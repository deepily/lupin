**Note on the shared key (B3b).** `notifications_filter_preference` is the one storage key both clients genuinely share, so far as this seat has read. The A0 note that "the two clients use different keys" holds for section visibility and accordion state; it does **not** hold here. Worth stating in the build, because a build that "gives the multiplexer its own key" would silently break a behaviour that currently works.

**A11 build items**: (1) the Queue Filter Settings section itself — admin-only, hidden for non-admins, header collapse, unpersisted disclosure; (2) its toolbar button `⚙️`; (3) the `Currently viewing: <mode>` status line and the long button labels; (4) clickable filter badges that reveal, save and scroll to the panel (closes A0 B6); (5) refuse a mode change at the setter for a non-admin, not only by hiding the control. Not owed: the mode, its storage key, the `user_filter` mapping, the refresh wiring and the doubled-load guard are all already there.
