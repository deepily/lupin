**Note on G2.** Legacy ships with debug logging permanently on and no way to turn it off from the page. The multiplexer has no such panel and no such flag, so the build has a genuine choice to make: reproduce the hard-on flag, or gate the panel behind something. That is a build decision, recorded here so it is not made by accident.

**Note on G8.** `addDebugMessage` distinguishes `info` from `error` in the DOM and the stylesheet never uses the distinction. An error line is visually identical to an ordinary one today, and only the `ERROR:` text prefix separates them. If the build styles the error class, that is a visible change from the lead — worth naming as such rather than shipping it as parity.

**A16 build items**: the whole section, specified by B1–B4, B6–B8, B10 and G1–G5 — open and visible by default, unpersisted, toolbar `🐛`, a plain "Debug Information" header with no controls; a 300 px scrollable monospace panel seeded with "System starting up..."; three writers (`log` gated on the debug flag, `error` prefixed `ERROR:`, `wsDiag` prefixed `WS-DIAG:`) each appending a `[HH:MM:SS] message` line via `textContent` with an `info`/`error` type class; **newest first**; capped at **20** lines by dropping the oldest. Decide G2 (the always-on debug flag) deliberately, and decide G8 (whether an error line looks different) deliberately — legacy does neither.
