# Decision record: one registry owns agent registration

**Source:** `src/rnd/v0.2.0/2026.08.15-agent-registration-single-source.md`, whole document (453 lines). Its own status line reads "DRAFT" at writing; the registry extension has since landed in `src/cosa/rest/v2/registry.py` (`CommandClass` and `resolve_agentic` exist).
**Status:** in force.

## What was decided

1. **One registry is the source of truth for agent registration.** Rick's ruling of 2026-08-15, as the source quotes it: "one registry is the source of truth; generate what can be generated, test what cannot." The source is explicit that this extends the registry in `src/cosa/rest/v2/registry.py`, which already existed, and is not a new build.
2. **Commands are classed in the registry** (`CommandClass`: conversational, agentic, control, none), and the old bucket names are derived from the class. The agentic commands become registry entries and `DEFERRED_COMMANDS` retires.
3. **`resolve()` stays scoped to conversational commands; agentic commands are read through a separate `resolve_agentic()`.** Registering them must not change what the router-facing lookup returns.
4. **The generated router prompt list comes from the registry, with its order held as registry data.** Order is declared, so that a byte comparison against the checked-in template stays an honest gate.
5. **The training corpus is reconciled by key, never generated.** Only the key set of the `agent-router-*.json` files is compared with the registry. The values are editorial (templates, placeholder sources, trigger phrases). The scoping rule is `agent-router-*.json`, because the `vox-cmd-*` files hold 23 browser commands that are not in the registry.
6. **The drift guard is class-aware and checks consistency, not voice reachability.** It requires every agentic command in the registry, prompt, training keys and factory, and every conversational command in the first three and in no factory branch. The confirmation-card list is a fifth surface, checked as a subset rule (a phantom arm and a dead-card arm). Every `cli_module` is checked by running `python -m <module> --help` and requiring return code 0.
7. **Exemptions carry a machine-checked reason and are scoped to a surface.** The count test `test_bucket_counts` is deleted in the commit that would invalidate it: it was neither to be hand-edited nor derived, because a derived count cannot fail.
8. **Retraining buys reliability, not reachability.** A command is reachable once the prompt lists it; the source's measurement was one invented command at n=10, so it does not establish that this generalizes. The source asks that this asymmetry be written beside the training generator.

## Not decided or left open in the source

- Whether the runtime router template equals the checked-in one (marked unverified by its reviewer).
- Whether the emitted command string always matches a registry key or alias for agentic commands.
- The five drifts, the three unrunnable `cli_module` values and the unset `started_at` were scheduled as phases 3 and 6. I did not check which of them have shipped.
