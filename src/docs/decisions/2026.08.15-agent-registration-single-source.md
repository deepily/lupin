# Decision record: one registry owns agent registration

**Sources:** `src/rnd/v0.2.0/2026.08.15-agent-registration-single-source.md` (the first design, 453 lines) and its follow-on `src/rnd/v0.2.0/2026.08.16-generate-router-prompt-and-corpus-from-registry.md` (185 lines). Both were read whole. The follow-on amends the first in three places, and this record states the current rule.

**Status:** in force as built. The registry, the generator and the lookup dispatch exist in the tree.

**Checked against:** `src/cosa/rest/v2/registry.py`, `src/cosa/rest/v2/router_prompt_generator.py`, `src/cosa/training/xml_prompt_generator.py`, `src/cosa/rest/agentic_job_factory.py`, `src/tests/unit/test_v2_registry_drift_guard.py`, and the `__main__.py` of the three `cli_module` packages.

## What is in force today

1. **One registry is the source of truth for agent registration.** The follow-on quotes Rick's ruling of `2026-08-15`. The router prompt list is generated from the registry, and so is the training corpus command list. The job factory dispatches by registry lookup. A completeness test catches whatever still drifts.
2. **Commands are classed in the registry.** `CommandClass` has four values: conversational, agentic, control and none. The template buckets are derived from the class: `ANSWER_COMMANDS`, `JOB_COMMANDS`, `CONTROL_COMMANDS` and `NO_MATCH`. `DEFERRED_COMMANDS` is gone. The names follow Rick's rename ruling of `2026-08-16`, as the follow-on cites it.
3. **`resolve()` serves conversational commands only, and it applies the CRUD fork.** Agentic commands are read through a separate `resolve_agentic()`, which reads `JOB_COMMANDS`. Registering agentic commands must not change what the router-facing lookup returns.
4. **`speakable` is a ratified field on the spec, not derived.** Which commands a person may say aloud is a human design judgement. No test can prove it right. The list is a checked-in decision, and a test pins the generated file to it.
5. **The router prompt is generated, and order is a fixed presentation order.** `render_router_prompt` emits the scaffolding and one `<command>` line per speakable command. The file stays checked in. `_SERVED_ORDER` fixes the sequence and is cross-checked against the speakable set, so a disagreement fails loudly. The first design's "order held as registry data" was overruled in code. The generator is a provable no-op on the served file. A better order is a separate measured change.
6. **The corpus command menu is generated; the phrasings are not.** `_compile_agent_router_commands` builds the menu from `speakable_commands()`. The three `agent-router-*.json` files supply example phrasings only, and the `vox-cmd-*` files are a separate browser vocabulary the registry does not own. The first design's "never generated" was wrong for the command list, and "not wholly generated" is the true rule.
7. **Factory dispatch is a registry lookup.** `create_agentic_job` reads `JOB_COMMANDS`, calls the spec's `job_factory` and returns `None` for an unknown command. A new agentic command needs a builder, a `JOB_BUILDERS` entry and a registry listing, and `test_1b2` fails if one is missing.
8. **The drift guard is class-aware and checks consistency, not voice reachability.** It requires every agentic command in the registry, prompt, training keys and factory. Conversational, control and none commands are checked against the surfaces that apply to them. The confirmation-card list is a fifth surface. It is checked as a subset, with a phantom arm and a dead-card arm. Each `cli_module` must answer `python -m <module> --help` with return code 0.
9. **Exemptions carry a reason and name a surface.** A machine-checked facility validates them, so a prompt-only exemption cannot silence the training guard.
10. **No count assertion and no tautological cross-check.** `test_bucket_counts` and the `cls`-versus-argument-table check were removed. A derived count cannot fail. A table built by iterating the other table always agrees with it.
11. **Each agentic command that has a `cli_module` answers `--help` from its registry entry.** Nine of the twelve agentic commands have one. `test fix expediter`, `test suite` and `mock job` have none, because they are invoked through the API. The three packages that had no entry point now carry a `__main__.py` that calls `run_help_for_module`. Cached help text can no longer be an import error.
12. **Reachability comes from the prompt line. Retraining buys reliability.** The follow-on records that a checked-in prompt line flipped emission from 0 of 5 to 5 of 5 with no retrain. It also records that the earlier 6 of 10 "router invents commands" claim did not reproduce. The probe document is not in the tree, so I could not read that evidence.

## Still open or not decided

- Whether the runtime router template always equals the checked-in one, which the first design's reviewer marked unverified.
- Whether the emitted command string always matches a registry key or alias for agentic commands.
- The follow-on's weakest claim, that generating the corpus list in one step is safe for rows already on disk and for key order. I did not find where it was closed.
- Whether the off-hours retrain was scheduled. The follow-on says not to schedule it before the generator lands.
