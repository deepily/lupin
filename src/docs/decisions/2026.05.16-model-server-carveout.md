## What is in force today

1. **A separate FastAPI app holds the three GPU models.** `src/lupin_model_server/main.py` loads Whisper, the code encoder and the prose encoder in its `lifespan`. It imports nothing from `cosa`. Its settings are environment variables read at import. The source's reason is that a compute container which loads no model does not start CUDA on a reload.
2. **The model server has six routes.** They are `/health`, `/transcribe`, `/embeddings/generate`, `/embeddings/batch`, `/embeddings/info` and `/admin/metrics`. The default port is 7998. `/admin/metrics` serves Prometheus text with the five metric names the source lists.
3. **`/health` reports readiness, not liveness.** It answers 200 when all three models are loaded and `load_errors` is empty, and 503 otherwise. It needs no key. The body differs from the source. It also carries `uptime_seconds`, `load_errors` and `api_key_fingerprint`, and it names the prose model `nomic_embed_text_v1_5`.
4. **Every other route checks an `X-API-Key` header.** `_install_api_key` reads the key file once at boot and stores a `bcrypt` hash of it. It then drops the in-memory string with `del`; the key file stays on disk. A file value that fails `_CK_LIVE_RE` is never hashed and becomes a load error. `require_api_key` first answers 503 when no hash was installed. With a hash installed it answers 401 for a missing header, a format mismatch or a failed `bcrypt.checkpw`. A `ck_internal_` key therefore gets 401 only when a key was loaded. This is the source's "Auth Refinement" section, which overrules its own earlier `ck_internal_*` choice.
5. **The model server no longer shares the notification key.** The source locked in the file `notification-api-claude-code-dev` for both uses. A later ruling of `2026-07-28` reversed that. `docker-compose.yml` now sets `LUPIN_MODEL_SERVER_API_KEY_NAME: model-server-api` on the model server and on both compute services. Both client helpers default to `model-server-api`. The model server's own code default is still `notification-api-claude-code-dev`. Other text in the tree still names the old key. It is in the `SpeechToTextProvider._transcribe_via_http` docstring and error text. It is in both `EmbeddingProvider` "no API key" messages. It is in the `require_api_key` docstring, the model server's module docstring and its `lifespan` comment. It is in the compose comment on the keys volume. The source deferred a dedicated key to "version-something later"; this is that key.
6. **One INI key switches the lifespan: `speech to text provider`.** Its values are `local` and `model-server`. An unset key reads as `local` in both readers. The two readers split on any other string. The lifespan treats every value except `model-server` as local and loads the models. `_should_use_local` needs the value to equal `local`. The provider therefore sends that same string to HTTP. The provider's docstring says an invalid value defaults to `local`. That holds for the lifespan only. The source's first draft key `model server local mode` was replaced in its reuse-pass section. No code file and no INI file names it. Three tracked documents still do. They are the source, the GCP provisioning plan and one `todo-history` file. That plan still lists setting it in the Production block as an unchecked item. In `model-server` mode the lifespan skips all three loads. It calls `SpeechToTextProvider.declare_remote_only()` and does not call `EmbeddingProvider.declare_in_process_engine_owner()`. In `local` mode it loads the three models and declares both owners.
7. **The shipped INI sets `model-server` under Development.** The source says the default is `local`, and the INI header comment still says so. The value is set once, under `[Lupin: Development]`, which inherits Baseline. `[Lupin: Testing]` and `[Lupin: Testing-GCS]` both inherit Development, so both take `model-server`. `[Lupin: Production]` inherits Baseline. Baseline sets neither key, so Baseline and Production take the code default `local`. A comment under `[Lupin: Testing-GCS]` places the key in Baseline; the tree does not.
8. **`SpeechToTextProvider` is built mostly as the source specified.** It is a singleton with the class flag `_is_in_process_owner`. `_should_use_local` is true only when the INI value is `local` and the flag is set. Any other case posts the file to `/transcribe`. Local mode needs the pipeline passed in, and retries once after a CUDA out-of-memory error. Two acceptance items are not built. The source asked for a lazy load on first call; the provider loads nothing and raises without a pipeline. The source asked for an awaited `transcribe( audio_bytes, content_type )`. The method is synchronous and takes `audio_path` and `whisper_pipeline`.
9. **The lifespan sets the owner flag only after Whisper has loaded.** `declare_in_process_owner()` is called inside the `try` that loads the pipeline. A failed load leaves `whisper_pipeline` as `None`, prints a warning, and the app keeps starting. This holds the source's risk about which process sets the flag.
10. **The speech routes take the provider as a dependency.** `/api/upload-and-transcribe-mp3` and `/api/upload-and-transcribe-wav` use `Depends( get_speech_provider )` and call `provider.transcribe`. They still take `Depends( get_whisper_pipeline )` too, which returns `None` in remote mode. The source said the first would replace the second. `/api/v2/ask-audio` and `/api/v2/transcribe` use the same dependency; the source did not list them.
11. **`_run_whisper_with_retry` is deprecated and still present.** Its docstring says it is "retained for one release cycle". In this tree only tests call it. No document found says when that cycle ends.
12. **Embeddings follow the owner flag, not a third provider value.** `EmbeddingProvider` branches on `openai`, then on `_is_in_process_engine_owner`, then falls to HTTP. No code compares `embedding provider` to `model-server`. The source's reuse-pass section proposed that third value. The splainer lists it, and `[Lupin: Testing-GCS]` sets it. It behaves as any non-`openai` value does.
13. **The model-server URL comes from the environment, then the INI.** `EmbeddingProvider._resolve_model_server_url` reads `LUPIN_MODEL_SERVER_URL`, then `model server url`, and otherwise returns `None`. `None` selects the app server's `/api/embeddings` routes. The INI step exists because `docker restart` does not re-read compose, which the source records as its second mid-flight bug. The speech resolver has the same order and ends on `http://lupin-model-server:7998`.
14. **The two providers do not share one retry helper.** The source's phase-three acceptance criteria asked for one `_call_with_retry` used by both. `SpeechToTextProvider._call_with_retry` makes up to three attempts and sleeps 2 then 4 seconds. `EmbeddingProvider._post_with_retry` is a separate helper, driven by the `embedding http` INI keys. It also retries a 429.
15. **The startup probe warns and continues.** The source's phase-three acceptance criteria asked for a 30 second poll that raises `RuntimeError`. The lifespan polls `/health` for a budget of 60 seconds by code default. On timeout it prints a message and startup continues. The key `model server startup probe timeout seconds` is read by the code and is absent from the INI.
16. **The compose service matches the source in most points.** `lupin-model-server` has `restart: unless-stopped`, port 7998 and `CUDA_VISIBLE_DEVICES: "0"`. It has a memory limit of 8G and a urllib healthcheck. It has no `cpus` limit, which the source asked for. It has no HuggingFace cache mount. The source's first mid-flight bug removed that mount, and the image carries the models.
17. **The GPU 0 pin is Rick's rule and it is built.** The source calls it a hard rule of `2026-05-16`. Compose sets `CUDA_VISIBLE_DEVICES: "0"` and `LUPIN_MODEL_SERVER_DEVICE: cuda:0`. The reservation is `count: all`. A compose comment says the device shown as index 0 depends on docker's enumeration.
18. **The model-server image is built lean and carries the models.** `docker/lupin-model-server/Dockerfile` downloads all three models at build time. It copies only `src/lupin_model_server`. Its header gives a target size under 15 GB. I did not measure the image.
19. **The GPU strip, the source's fourth phase, is planned and not carried out.** `lupin-rest-dev` and `lupin-rest-test` still hold a `deploy.resources.reservations.devices` block. Their `depends_on` names only `postgres`. `docker/lupin/Dockerfile` still downloads the three models. The source makes that phase wait for the smoke tests of the fifth. The folder's closure document lists the fourth phase as deferred.
20. **The source's "frozen" property is a deployment property.** The source means the container does not reload on code edits. The file itself has changed since. `git log` on its path shows five commits: one creates it and four change it. Compose runs image `lupin-model-server:0.1.1`, and its comment names a Whisper `return_timestamps` fix and key self-check work.
21. **The model server can also run on Cloud Run.** A later design of `2026-06-30` is marked approved by Rick. It moves the same app to a Cloud Run GPU service that scales to zero. It names this source as its origin. It says the app re-points by one URL value and the key. `cloud-run-model-server-deploy.sh` lists that design first as its design of record. The embedding timeouts in the INI are sized for that cold start.
