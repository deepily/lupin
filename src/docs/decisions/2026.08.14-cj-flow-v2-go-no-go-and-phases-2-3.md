# Decision record: the CJ Flow v2 go/no-go criteria and the queue, argument and new-agent designs

**Source:** `src/rnd/v0.2.0/2026.08.14-cj-flow-v2-phases-2-3-and-evaluation.md` (770 lines, read whole). Its status line reads "draft" and was not updated. The file holds its own later corrections: section 1.4b, a `2026-08-17` ruling on p95, section 4a and section 6.

**Status:** mostly not in force as written. The verdict the source exists to produce was not produced. The flow became the front door by a cutover instead. The queue design of section 2 was reversed. Sections 3 and 4 are partly built under later designs. Each rule below says how far.

**Who decided:** section 1.1 is headed with Rick's two metrics. The p95 ruling records votes by Cheech and María, with Mr Radio's vote pending. Section 1a records a ruling by Cheech on `extract()`. The source names no one who approved the document itself.

**Checked against:** `src/scripts/v2_eval.py`, `src/tests/integration/test_v2_eval_live.py`, `src/cosa/rest/v2/executor.py`, `src/cosa/rest/v2/flow.py`, `src/cosa/rest/v2/pending.py`, `src/cosa/rest/v2/registry.py`, `src/cosa/rest/routers/v2_ask.py`, `src/cosa/rest/routers/_retired_doors.py`, `src/cosa/agents/runtime_argument_expeditor/expeditor.py`, `src/cosa/rest/agentic_job_factory.py`, `src/cosa/rest/todo_fifo_queue.py`, `src/cosa/utils/util_code_runner.py`, `src/cosa/agents/io_models/xml_models.py`, `src/cosa/agents/test_suite/job.py` and `src/conf/lupin-app.ini`, at tree `d3d98a68a`.

## What is in force today

### The evaluation (source section 1)

1. **The eval harness runs one arm, the v2 flow, in two passes.** `main` in `v2_eval.py` raises `ValueError` unless `--passes` is 2. The cold pass runs first and the warm pass follows. The warm pass gives the cache-hit rate, as the source's section 1.1 asks.
2. **The harness does not decide the go/no-go question.** Every report starts with `NOT_GONOGO_BANNER`. It says no v1 baseline runs, so the numbers do not decide `INVEST`, `STOP` or `SPLIT`. The live test asserts that the report holds the words "NOT the go/no-go decision table".
3. **The go/no-go table of section 1.5 is not in the tree.** The source planned it. No tracked Python file holds `PENDING HUMAN` or an overall verdict line. No code computes the 20 percent bar, the floors as vetoes or the statement count. The harness does not use `ast`.
4. **No paired verdict was produced.** `TODO.md` holds a section whose heading carries the date `2026-08-20` and the words "REFUSE THE NUMBER". The heading credits Mr. Radio with the ruling and Tiberius with the finding. It closed the paired-run task on a refusal. The reason given is that the two arms were not scored by the same rules. Commit `75ad1bd8b` of `2026-08-26` then deleted `paired_eval.py` and `v1_eval_arm.py`. The words "Rick's ruling that V1 is deprecated and removed" appear in that commit's message and nowhere else I found. The decisions log in `TODO.md` holds two `2026-08-26` entries that quote Rick. In one he resumes the plan's order, which includes the V1 excision, subject to María's review. In the other he says her approval discharges the gate and tells the author to implement the plan.
5. **p95 is reported and gates nothing.** `compute_metrics` returns `p95_first_useful_ms` and `render_report` prints it. This matches the source's `2026-08-17` ruling. The other half of that ruling is a gate on the paired median delta. Its computation went with `paired_eval.py`. Its inputs are still built: `compute_metrics` returns `spans_by_utterance` and `main` writes `v2-arm-artifact.json`. A comment block above `guard_run_integrity` and the text of `NOT_GONOGO_BANNER` still point at the deleted harness.
6. **The sample is stratified by command and seeded.** `stratified_sample` draws per command from a sorted list with `random.Random( seed )`. The parser defaults are 60 per command and seed 1024. The report prints the seed and the requested size per command. Source section 1.4a declares 60 per command and a recorded seed.
7. **The live test runs a short sample by default.** `PROXY_LIMIT_PER_COMMAND` is 5. The test file's comment gives Rick's ruling of `2026-10-05`. `LUPIN_TEST_V2_EVAL_LIMIT` raises the cap, and `none` or `all` removes it. The test passes the cap as `--limit`, which `load_corpus` applies before sampling. So the 5 are the first 5 utterance lines of each command file. The report still prints the requested 60.
8. **The cold pass must start from an empty store.** Section 6.4 of the source asks for a clean starting state per arm. It names the `v2 snapshot table` key as the means. The tree isolates by database instead. The comment beside that key in `lupin-app.ini` gives Mr Radio's decision B of `2026-08-16`. `clean_v2_snapshot_store` truncates the snapshot and synonym tables after two guards pass. `guard_cold_start` raises when the cold pass shows a cache hit. `main` skips it under `--allow-warm-cold`. The live test's `cold_v2_store` fixture calls the clean step.
9. **A run that cannot be trusted raises instead of reporting.** `guard_run_integrity` checks three properties of the warm pass records. Every response was 200. Every trace is in the trace file. The router error rate is at or under a ceiling, 0.20 by default. The source does not design this guard. Its section 2 only warns that a broken read "fails as an all-zeros report rather than an error".
10. **Under the queued executor the harness waits for the terminal outcome.** The source says the harness must poll or read the trace file. Under `queued` the response holds no answer. The tree wraps each ask in `terminal_waiting_ask`, fed by a websocket listener. `--no-observe-terminal` turns that off. The deferred status is `waiting`; the source wrote `parked`.
11. **The harness is scheduled on the test server.** `v2_eval` is in `SUITE_SCRIPTS` in `job.py` and is absent from `ALL_SUITE_COMPONENTS`. The suite runs `src/tests/run-v2-eval.sh`. That runner calls `v2_eval.py` directly, not the pytest wrapper. The source does not state a venue. The harness docstring and the runner's header name it. The root `CLAUDE.md` does not name `v2_eval`; its "Testing venues" section holds the general rubric.
12. **Degraded paths carry distinct route reasons.** `AskFlow` emits `router_error`, `extract_error`, `replay_error` and `agent_error`. The harness holds them in `ROUTE_ERROR_REASONS`. The source's floor names `replay_failed`, and the tree's word is `replay_error`.

### Rulings made during the build (source section 1a)

13. **`extract()` and `collect()` take a required argument spec.** `RuntimeArgumentExpeditor.extract` and `collect` each take `spec` as a parameter with no default. `expedite` builds the spec itself with `ArgSpec.from_entry`, so its older callers pass no spec.
14. **Weather has no entry in the argument table.** `AskFlow._arg_spec_for` builds a spec at the call site when `JOB_ARG_CONTRACTS` has no entry. Its comment forbids adding a table entry. The source rejected a fake table entry for weather.

### The queued executor (source section 2)

15. **One INI key picks the executor.** `v2 executor` is read in `build_ask_flow` and passed to `make_executor`. The names are `inline` and `queued`, and any other name raises `ValueError`. The baseline value is `queued`. The INI comment dates that flip `2026-08-21`.
16. **Own queues for v2: planned in the source; reversed, see `executor.py`.** The source decided on four v2 queue instances. `QueuedExecutor.submit` pushes the job onto the existing todo queue. No queue class exists under `src/cosa/rest/v2/`. The INI comment gives the reason: six in-process callers need the existing queue.
17. **The parts that depended on own queues were not built.** `QueuedExecutor` does not mint a fresh job id. It scopes the job's existing `id_hash` through `register_scoped_job`. It marks `t_enqueue`, and `t_dequeue` appears in no code file. It answers `waiting`. I found no bounded done or dead ring and no v2 wall-clock watchdog.
18. **A request that needs input is parked in `PendingRequests`.** The source put the parked job in the v2 todo queue in the `PAUSED` state. `pending.py` holds an in-process store with a time limit, and `POST /api/v2/resume` answers it. `AskFlow._needs_input` calls `self.pending.put` when `interactive` is true, and then answers `parked`. Otherwise it stores nothing and answers `needs_input`. The `submit` docstring says "It never parks". No file under `src/cosa/rest/v2/` names `PAUSED`.
19. **`QueuedExecutor.submit` does not raise.** It catches an exception and returns `Outcome( status="failed" )`, as the source asked. `InlineExecutor.submit` catches a replay or agent failure the same way. It raises `ValueError` on a `work.kind` it does not know. `QueuedExecutor.__init__` raises `ValueError` when the queue is `None`.

### One argument interface (source section 3)

20. **One registry maps each command to its agent or job.** `REGISTRY` in `registry.py` is that table. `AgentSpec.required_args` reads a `declared_args()` classmethod first, then `JOB_ARG_CONTRACTS`, then a literal tuple. The module docstring says no agent declares its own arguments yet.
21. **The declaration module of the source was not built.** `src/cosa/agents/arg_spec.py`, `as_registry_entry`, `build_job` and `from_args` are not in the tree. `ArgSpec` is a class in `expeditor.py`. No agent package holds an `args.py`.
22. **`GET /api/v2/agents` lists each command and its arguments.** The route returns one `AgentOption` per registry command, with `required_args` and `arg_questions`. It has no `source` field, which the source's design named.
23. **`create_agentic_job` dispatches by registry lookup and still returns `None` on an unknown command.** It reads `JOB_COMMANDS` and calls the entry's `job_factory`. The source's typed exceptions were not adopted.
24. **Conversational agents are built by keyword.** `AskFlow._build_agent` passes each argument by name and passes no `routing_command`. The source asked for both.
25. **The three mode maps still exist.** `MODE_TO_AGENT`, `MODE_METADATA` and `AGENTIC_MODE_MAP` are defined in `todo_fifo_queue.py`. `routers/mode.py` imports `MODE_METADATA`. The source planned to collapse them into derived names.
26. **The error text fed to argument extraction was repaired.** The source found three agents whose cached help was a "No module named" error. `cli_help.py` now builds that help from the argument table. Its `Design:` line names the agent-registration record.

### A new agent (source sections 4, 4a and 6.3)

27. **`GenericQuestionAgent` and the promotion pipeline are not built.** No code file names the class. No `register_agent` function exists, which agrees with the source's rejection of runtime registration.
28. **Generated code runs from a file made for each run.** `assemble_and_run_solution` adds a random suffix to the configured path. Its comment cites Rick's ruling of `2026-08-19`, "fix the race only". The source asked for a per-job code file as a prerequisite.
29. **The other two hardenings were not found.** I found no static check of generated code in `util_code_runner.py`. I found no rule that a snapshot replays for its creator alone. `AskFlow._may_serve` is a different guard: it serves a row confirmed correct, with an exact hit exempt.
30. **A command the registry cannot resolve goes to the receptionist with a label.** `AgentRouterResponse.validate_command` still accepts an unknown command. `AskFlow._unresolved_route_reason` returns `user_picked_receptionist` for the command `agent router go to receptionist`. It returns `unknown_command` for every other command. The source's section 4a measured that the router emits commands found in no list.

### After the verdict (source section 5)

31. **The flow became the front door by cutover, not by a verdict.** The baseline section of `lupin-app.ini` sets `v2 flow enabled` true. Its comment dates the flip `2026-08-21`, in the commit that retired the other queue doors. `_retired_doors.py` answers 410 on those doors and names `2026-12-31` as their removal date.
32. **The staged cutover of the source was not followed.** I found no traffic-share setting. The source's rule "two flows in production is the failure state" has no code to check.
33. **`push_job` is still defined.** It is a method in `todo_fifo_queue.py`. A fixed-string search for `.push_job(` outside tests found one comment and no call. The source said to remove it when nothing calls it.
