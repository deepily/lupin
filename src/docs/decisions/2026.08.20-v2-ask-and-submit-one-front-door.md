## What is in force today

`[Lupin: Baseline]` sets `v2 executor = queued`. Under it the flow hands each job to the queue, and `RunningFifoQueue` runs it. Several rules below differ between the inline and the queued executor, and say so. Every statement about the queued path was read from the code. None was run.

1. **Two verbs put work on the queue: `ask` and `submit`.** Rick ruled the pair on `2026-08-21`. `AskFlow.ask` takes a question and decides what to do with it. `AskFlow.submit` takes work whose command is already decided. The routes are `POST /api/v2/ask` and `POST /api/v2/submit`. `submit` takes a named command with arguments, or a job the caller already built. It raises `ValueError` unless exactly one of the two is given.
2. **`submit` skips the head and does not park.** `AskFlow.submit` does no routing, no cache read in the flow and no argument extraction. Under the queued executor the built agent still passes `RunningFifoQueue._process_job`. That method looks up by `last_question_asked` and can serve an exact hit, as rule 8 states. Missing arguments come back as `status="needs_input"` with `args_missing` filled and no `pending_id`. The source's reason is that a service caller would not read a parked question. The source says "Only `ask` may reach needs-input", and the docstring of `ask` says the same.
3. **`/api/v2/resume` stays the second turn of a parked `ask`.** The source ruled it is not folded into `submit`. An unknown or expired `pending_id` answers `status="expired"` with `route_reason="pending_expired"`. A second resume that loses the claim answers `route_reason="already_resumed"`. Amended later: `v2_ask.py` now also serves `/api/v2/resume-job`, `/api/v2/ask-audio`, `/api/v2/transcribe` and `GET /api/v2/agents`. The source names none of those four.
4. **`ask` routes first and reads the cache second.** Rick ruled the order on `2026-08-20`: "route first and then check the cache". `ask` runs a fitness check, the router, `resolve`, the cache lookup, then arguments. A router answer of `unknown` goes to the receptionist as `router_error` before any cache read. A command with a CRUD factory skips the cache while the CRUD flag is on. That test is read from the registry and is not a list of command names.
5. **One resolver applies the CRUD fork.** `registry.resolve( command, crud_enabled )` is that resolver, and `crud_enabled` has no default. `resolve_voice` is deleted. A forked spec carries `snapshotable=False`. This is Rick's ruling of `2026-08-20` to pull the reporting pin out of routing.
6. **Agentic commands are reached through `resolve_agentic` on all three entries.** `ask`, `submit` and `resume` each call it when `resolve` returns `None`. The source's finding that `resolve_agentic` is "unreachable from the flow" is no longer true. The same file records the repair in a later manager ruling.
7. **A queued job answers `waiting`, and `waiting` counts as success.** `Outcome.status` is `done`, `waiting` or `failed`. `parked` is kept for a request that waits on a human. Rick ruled the word on `2026-08-20`. The class is `QueuedExecutor`; the source's `QueueExecutor` is its own stated typo. `SUCCESS_STATUSES` is used at both replay and agent gates. A `waiting` outcome speaks "New ... job..." once and is not written to the cache. `[Lupin: Baseline]` sets `v2 executor = queued`.
8. **The flow's lookup leads, and the queue keeps an exact-match stage.** Rick ruled the lead on `2026-08-20`. His words were that "the other caches get removed". That is carried out in part. Three things are deleted: the queue's accept-above-floor branch, `_process_fast_lane` and the two-turn confirmation. `RunningFifoQueue._process_job` still looks up a snapshot for an agent that is not a CRUD agent. At a score of 100 or more it serves the row if `_may_serve_cached( snapshot, "exact_hit" )` passes. `_format_cached_result` can still decline. It does so when re-running the stored code fails and the row is not confirmed `True`. The agent then runs.
9. **The flow's cache has a gist probe and a near-match ask.** `V2Cache._exact_probes` adds an exact match on the normalized gist. It runs after the verbatim and normalized probes. A blank gist does not match. `AskFlow._near_match_replay` handles a score at or above `similarity threshold confirmation`. It asks "Is that the same as: ...?". The timeout is 30 seconds and the default is no. It replays on a yes. With `similarity confirmation enabled` false it replays with no ask. A non-interactive caller is declined unasked. A score below 0 or above 100 is refused. Amended later: `quantities_differ` refuses a near match that names a different quantity.
10. **The read guard sits at the replay decision, and an exact hit is now exempt.** `AskFlow._may_serve` reads `answer_is_correct` on the hydrated snapshot. It returns `True` when the hit is exact and the verdict is not `False`. Otherwise it returns `True` only when the verdict is `True`. It is called in `ask` and in the near-match branch, not in the shared lookup. The source ruled that an unconfirmed row is "never served, not even once". The exact-hit exemption changed that. Its comment cites Rick, `2026-09-04`. The queue has a second guard, `RunningFifoQueue._may_serve_cached`, with the same two tests in its body. The comment in that body also cites `2026-09-04`. The comment at its call site in `_process_job` cites Rick, `2026-08-30`, for adding the guard. That call-site comment and the docstring of `_may_serve_cached` say only a confirmed row is served. Both are stale against the body. `_handle_solution_snapshot`, which runs a replay the flow queued, has no guard of its own. The source's claim that the guard has "EXACTLY ONE HOME" no longer holds. The end-of-run question also changed. `RunningFifoQueue._confirm_correctness` records the user's verdict when they answer. With no response it records `True`. The source said a timeout left the field at `None`. For a job whose lineage traces to a test-suite job it records `True` without asking. That comment cites Rick, `2026-10-02`. An exception is caught and printed, and no verdict is saved.
11. **The write guard refuses a row the router did not choose.** `AskFlow._write_guard` allows a write for the route reasons in `_ROUTER_CHOSE`: `args_none`, `args_complete` and `resumed`. `_maybe_write_back` writes when the result is snapshotable and `done`. So this guard governs the flow's own write, which happens under the inline executor. There, a `submit` result is not cached, with or without a question. There, a command with a CRUD factory is not cached under either flag state. Under the queued executor the guard decides nothing. `QueuedExecutor.submit` answers `waiting` or `failed` and does not read `work.snapshotable`. The queue then writes by rule 12. A `submit` of a conversational command is therefore written to the cache by the queue, unless its class is one of the three excluded. `_is_replayable` refuses a row with no code unless its class is in `CODELESS_AGENT_CLASSES`.
12. **Queued work is written back by the queue's existing path.** Rick ruled on `2026-08-20` to reuse it. `RunningFifoQueue._handle_base_agent` calls `snapshot_mgr.save_snapshot` at completion. It does not serialize `ReceptionistAgent`, `WeatherAgent` or `CrudForDataFramesAgent`. It does not ask who chose the agent. Outside `src/cosa/rest/v2` and `routers/v2_ask.py`, one non-test file reads `snapshotable`: `src/scripts/v2_eval.py`. `main.py` raises for a snapshot manager type other than `postgres`.
13. **A snapshot write needs an owner.** `V2Cache.snapshot_from_result` raises `ValueError` for an empty `user_id`. `_maybe_write_back` passes the caller's identity. The spoken door answers 401 for an agent request with no signed-in user. The source quotes Rick, `2026-08-20`: "cannot file without providing a valid user ID".
14. **A degrade lands on the receptionist with its own `route_reason`, with one exception.** The exception is a job builder that raises `SubmitRefused` in `_submit_agentic`. That emits `status="failed"` with the builder's route reason and runs no receptionist. The reasons in `flow.py` are `router_error`, `unknown_command`, `user_picked_receptionist`, `extract_error`, `replay_error`, `agent_error` and `agentic_build_error`. `_compose_error` keeps the first failure in the emitted `error` field. The replay, agent and build paths pass `primary_error`. The router and extraction paths do not. The source's heading reads "the failure must be SPOKEN". That refinement by Rick was planned in the source. I found no code that speaks it. `_speak` sends the receptionist's own answer.
