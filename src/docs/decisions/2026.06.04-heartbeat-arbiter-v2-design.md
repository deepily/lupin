## What is in force today

1. **The arbiter observes the hook's events and acts in a bounded way.**

   It tails the event files under `~/.claude/heartbeat-events/` from stored offsets and builds a fleet view. It does not write them; `test_iso1` pins that. It DMs managers and blockers, and it escalates to Rick. It also fires a bounded auto-poke at stuck live sessions. That poke is non-destructive. It goes by `send_to` or a host-side tmux inject. If the arbiter is down, every hook still pokes.
2. **The consumer is `ArbiterConsumerJob`, an `AgenticJobBase`, and it runs standalone.** The `:8001` service `lupin-arbiter-app` runs it inside `FleetArbiterLoop`. The loop starts a fresh job after each 12-hour cap. The in-process arbiter is gated by the ini key `arbiter in-process bootstrap enabled`, which ships false.
3. **A deadlock is a ring of `holding_on: peer:X` edges, and escalation needs a store-backed ring.** A ring built only from self-reported edges is not escalated. The ring must also persist for `deadlock_dwell_seconds`, default 300. The arbiter never breaks a deadlock. The false-escalation fix of June 2026 added both gates. `test_pc5b` pins the store gate.
4. **An auto-ping goes to the blocker and copies its owning manager.** It is throttled per `(holder, awaited, reason)` edge. The backoff schedule is 60, 300, 900 and 3600 seconds. The default global cap is 10 pings per 3600 seconds. `test_th1` to `test_th3` pin the backoff, the cap and the reset on resume.
5. **The idle roster is the union of a declared beacon and an inferred quiet.** The labels are `declared-available` and `quiet (inferred)`. The constructor refuses `quiet_threshold_seconds` at or above `alive_threshold_seconds`. The defaults are 300 and 600. `test_infer1` to `test_infer3` pin the inference, the shipped defaults and the refusal.
6. **The arbiter recommends reassignment and the manager acts. It never reaps.** `test_arbiter_redline.py` scans every `.py` file in `cosa/agents/heartbeat_arbiter/` and five named files of `lupin_arbiter_app`. The five are `fleet_arbiter_loop.py`, `arbiter_live_notify.py`, `health_watcher.py`, `app.py` and `local_snapshot_store.py`. It does not scan `context_pressure_writer.py`, and a new file in `lupin_arbiter_app` is not scanned until it is added to that list. It fails on a call named `reap`, `kill`, `dismiss`, `spawn`, `terminate` or `replace`. It allows two: `os.kill( pid, 0 )`, and any method call written `<expr>.replace(...)`. No test guards "never assigns". I did not trace every call site for it.
7. **Each session row has distinct age columns and one verdict.** `compute_liveness` returns the bridge, event, commons, idle-prompt, DM, hold and transcript ages and the freshest. The verdict is `LIVE`, `quiet <age>`, `stale <age>` or `offline`. State is a separate column.
8. **The bridge file's mtime is stamped by three call sites.** They are `PreToolUse`, `PostToolUse` and the MCP server's `BridgeLivenessMiddleware`. Each calls `touch_bridge_mtime`, a bare `os.utime`.
9. **A changed frame prints the table; an unchanged frame prints one tick line.** `render_tick` shows the time since the last change. A snapshot sink receives each published frame.
10. **`:7999` pulls the fleet state; `:8001` never pushes.** `GET /api/arbiter/fleet-state` reverse-proxies `:8001/state`. The legacy `GET` and `POST /api/arbiter/fleet-snapshot` pair stays until the cutover.
11. **The hook's work-owed source defaults to the transcript replay in code.** `DEFAULT_OWED_SOURCE_FROM_STORE` is false in `heartbeat_settings.py`. A store-count source exists behind `heartbeat.owed_source_from_store`. A comment in `post_tool_use.py` says the store-canonical cutover "is live".

## Planned in the source and changed

- **"Realize the arbiter by extending the existing agentic Heartbeat Poker" (`HeartbeatPokerJob`).** Carried differently. `ArbiterConsumerJob` extends `AgenticJobBase` and reuses the Poker's `Clock` and `SystemClock` only.
- **"The arbiter is a sensor + recommender, NOT an actuator" (section 6.3) and "Read-only on the Hook's plane" (section 7).** Narrowed. The later diagrams document says the redline moved from "never actuate" to "never destructively actuate". Poking is allowed. Reaping stays a recommendation. The job's module docstring still describes an arbiter that only reads files and posts messages.
- **"Liveness = ONE host-side bridge-file mtime ... do NOT fork a parallel last-seen store" (the source's section 10.1 and redline 3).** Reversed. The freshest of up to seven signals decides the verdict (rule 7). Hold and transcript mtimes join unconditionally; the source says event and transcript times "drop to optional/secondary".
- **"The arbiter pushes its latest fleet snapshot to lupin-rest" and "NO standalone arbiter HTTP" (section 10.4, redline 2).** Reversed. `:8001` serves `/state` and `:7999` pulls. The router docstring says "The old rule that there is no standalone arbiter HTTP server is retired". `arbiter_snapshot_store.py` still carries the old sentence in its module docstring.
- **Roster posted to a `fleet-idle-roster` commons topic and the manager DMed on change (section 6.2).** Dropped. A comment in `arbiter_job.py` says the per-tick roster broadcast is removed, and the roster is served from `/state`. `ROSTER_TOPIC` is `fleet-arbiter` and nothing posts to it.
- **A cycle in `peer:` edges is a deadlock to escalate (section 6.4).** Narrowed (rule 3). The same-file docstring says the ungated ring "false-escalated on every poll".
- **Parameter `idle_threshold_seconds`.** Renamed `quiet_threshold_seconds`. The invariant the source states is carried.
- **Work-owed from the session's own `Task*` state, replayed from its transcript (its section 5, headed "RESOLVED").** Still the hook's default in code. A later cutover to the task store is flag-gated and, by a code comment, live. See rule 11 and the open items.

## Still open or not decided

- Whether any host sets `heartbeat.owed_source_from_store` true. The default is false in code. I did not read a host's settings file.
- The source's open items "Cross-host fleet" and "Poll cadence + offset persistence". The constructor takes `offsets_state_path`, whose default `None` replays on restart. I did not read what production passes.
- Whether the arbiter's escalations reach a person. `test_arbiter_routing.py` pins the case-to-tier table cell for cell. Delivery to a person was not exercised.
- The source's statement that the idle beacon is "edge-triggered / de-duped". `stop.py` emits `EVENT_IDLE`; I did not trace the de-duplication.
