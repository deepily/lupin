## What is in force today

1. **Every session gets a persona at SessionStart, chosen at random.** The draw is uniform over the names not in use. The source says each session is "uniformly randomly assigned a voice/persona at SessionStart". `pick_unallocated_persona` calls `random.choice` over the free names. The aim is that a listener can tell parallel sessions apart.
2. **The pool is the INI key `cc session voice persona pool`.** It holds 14 names today. The source says 6 voices, with Sam reserved and kept out. The key now lists `sam` among the 14. The comment above it still says Sam is not in the pool. The loader reads the key, so the key governs. A name with no voice id is skipped.
3. **A full pool gives the overflow persona, then numbered "Extra N" personas.** The appended update replaced the source's hash-borrow rule with Sam as overflow. The overflow persona has since moved to the key `cc session voice persona overflow name`, set to `arnold`. A second overflow session gets "Extra N" with the lowest free N. It has a distinct color and shares the overflow voice and icon. Hash-borrow remains only when no overflow persona is configured.
4. **The random draw leaves out declared managers, and a spawn can request a named chain.** The source has neither. A manager roster from the environment is held out of the random draw. A chain is a strict ordered walk, and a `*` element means any free name. A chain used up without `*` answers 409 and leaves the session without a persona. A spawned headless worker with no chain gets the random draw.
5. **The bridge file is the single source of truth, and occupancy is a fresh scan.** `get_voice_persona` and `set_voice_persona` read and write the `voice_persona` field. `find_active_voice_persona_sessions` scans live bridges. The router holds one module lock around scan, pick and write. There is no in-memory registry and no sweeper.
6. **Stale bridges are pruned and aged out.** The source's update asks for both. `prune_dead_persona_bridges` runs at SessionStart on the host and nulls the field on any bridge whose process is dead. It does nothing inside a container. The occupancy scan also skips a bridge older than `cc session voice persona stale threshold seconds`, unless its process is proven alive. The value is 43200.
7. **A session keeps its persona across `/clear`, `/compact` and resume.** The source gates the carry-forward on `is_context_clear`. The code does not, because that flag is true only when the transient id changed, which a compaction need not do. `register_session.py` preserves any valid prior `voice_persona`. `session_end.py` releases the persona on every reason except `clear` and `compact`.
8. **A failed allocation leaves the session without a persona and does not block SessionStart.** The bridge then has no `voice_persona`. The speech router uses the configured default voice, which is Sam's, for a request with no `voice_id`. `get_session_info` returns `None` in that case.
9. **The server stamps the persona on each outbound notification, and the UI keeps a cache.** `_voice_persona_for_sender_id` stamps `voice_persona` by `sender_id`. The source says "No UI-side persona cache needed". The UI has a `senderPersonaMap`, filled from stamped envelopes and from the assigned and released events. It supplies the `voice_id` for TTS and the sender-card badge.
10. **The TTS request body key is `voice_id`.** The source's bundled bug fix is carried out. Both TTS calls in `notifications.js` set `ttsBody.voice_id` only when a voice is known.
11. **Personas are independent of speakerphone mode.** The source calls it conversation mode. `speakerphone.py` never touches `voice_persona`, and the router docstring states the independence. Every session gets a persona whatever its mode.
12. **Release is best effort and idempotent.** `POST /release` clears the field and pushes a `voice_persona_released` notification. A second call answers `released=False`.

## Added after the source

A worker's persona badge can carry its spawning manager's badge in the focus bar. `_resolve_manager_persona` reads the worker's `spawned_by`. The source says nothing on this.
