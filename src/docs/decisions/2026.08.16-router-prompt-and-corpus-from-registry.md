# Decision record: the router prompt list and the training menu come from the registry

**Source:** `src/rnd/v0.2.0/2026.08.16-generate-router-prompt-and-corpus-from-registry.md` (185 lines, read whole). Its status line reads "design, submitted for cascaded review. Not built." The tree has since built it, and amended it in three places.

**Status:** in force as built. Section 2.2's "generator owns order" was overruled in code. Section 7's test rewrite was not done. Both are stated below.

**Who decided:** the source quotes a ruling by Rick of `2026-08-15`, which is rule 1. The order ruling in rule 3 is Rachel's of `2026-08-16`, as the generator module's comment states it. The source names no one who approved the design itself.

**Checked against:** `src/cosa/rest/v2/router_prompt_generator.py`, `src/cosa/rest/v2/registry.py`, `src/cosa/training/xml_prompt_generator.py`, `src/cosa/training/xml_coordinator.py`, `src/cosa/agents/runtime_argument_expeditor/agent_registry.py`, and the tests named in the table.

This record builds on [One registry owns agent registration](2026.08.15-agent-registration-single-source.md), which cites this source as its follow-on. Rules 4 to 6 of that record overlap with rules 1 to 3 here and agree with them.

## What is in force today

1. **The router prompt's command list is generated from the registry.** The file stays checked in. The source quotes Rick: the prompt list is generated and a completeness test catches the rest. `render_router_prompt` builds the text and `write_router_prompt` writes it. The readers still load a file.
2. **The registry's `speakable` field says which commands the prompt lists.** The field is ratified and not derived. The prompt lists 18 entries: 17 commands plus `none`. A test pins that count. Two agentic commands are held out, each for a stated reason. `bug fix expediter` is reachable from a card only. `test fix expediter` is system-triggered, and its job id cannot be spoken. The source names only the second.
3. **Command order is a fixed presentation order, not generator-owned.** The source says "the generator owns command ORDER". The code reversed that. `_SERVED_ORDER` holds the sequence and `speakable_commands()` raises `ValueError` if it and the registry's set disagree in either direction. The generated file equals the served file byte for byte. A different order is a separate, measured change.
4. **The scaffolding is held verbatim and is not derived.** `_HEADER` and `_FOOTER` carry the instruction prose, the response-format block and the `{voice_command}` slot. The slot stays a literal, so the serve-time `str.format()` fills it. Only the list between the `<agent-routing-commands>` tags is generated.
5. **A test pins the checked-in file to the generator.** `test_on_disk_prompt_equals_generator` fails when someone hand-edits the file. The control `test_pin_detects_a_dropped_command` removes a line from the emitted text, not from the file. The source's section 3 asked for a hand-edit of the checked-in file and a restore. I found no test that does that.
6. **The training menu is read from the same list.** `_compile_agent_router_commands` returns one `<command>` line per `speakable_commands()` entry, in served order. The three `agent-router-*.json` files keep the example phrasings and no longer define what exists. The two `vox-cmd-*.json` files are a separate browser vocabulary, and the loader names each file by path.
7. **The corpus builder refuses a JSON roster that differs from the menu.** The source asked for two things. The corpus list comes from the registry, and a test pins the demotion. The tree goes further. `_assert_agent_router_json_commands_match_speakable` runs in the constructor and raises `ValueError` on a difference in either direction, before any row is built. A speakable command with no JSON key would train no rows. A JSON key that is not speakable would train a label the menu never offers.
8. **The commands in the generated rows equal the menu.** `test_training_rows_equal_the_menu` builds one-row frames from the real templates. `test_start_is_absent_from_both` checks that the `test fix expediter` start command trains no examples and is not on the menu.
9. **The simple-command builder trains under the agent-router wrapper.** It had used the browser wrapper. A comment in `xml_coordinator.py` records the fix, and `test_xml_coordinator_wrapper_regression.py` guards it. The `TODO.md` entry on the first retrain says the fix landed in code on `2026-08-16`. The corpus file on disk carried the old wrapper for two more days.
10. **`DEFERRED_COMMANDS` is retired and no `training_seed` field exists.** `SPEAKABLE_JOBS` is now a projection of the `speakable` field. `AgentSpec` has no seed field, as the source's own revision decided. A missing seed file is caught by `_test_command_paths`, which each JSON loader calls.
11. **Argument contracts and registry specs stay two tables.** `JOB_ARG_CONTRACTS` lives in `runtime_argument_expeditor/agent_registry.py` and `JOB_COMMANDS` in `registry.py`. Both exist today under the names the source gives as the renamed ones. The source warns that a rename sweep which collapses them destroys a real distinction.
12. **A listed command is reachable, and training buys reliability.** This is the source's section 1.2 and it is a measurement, not a code rule. The agent-registration record's rule 12 states it and its limits. I did not re-derive it here.

## Still open or not decided
