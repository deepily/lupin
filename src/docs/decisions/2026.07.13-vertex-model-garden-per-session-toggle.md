**Source:** `src/rnd/v0.1.9/2026.07.13-vertex-model-garden-toggle-search-and-logging.md`, revision 4. It is an R&D design document, not a ruling.

**Status:** in force for the toggle, the region rules, the guards and the logging harness. The pilot itself was parked on `2026-07-17`; see the later changes.

**Checked against:** `src/cosa/utils/vertex_env.py`, `vertex_logging.py`, `vertex_monitoring_oracle.py`, `vertex_spend_ceiling.py`, and `src/scripts/start-cc-with-tmux.sh`, each opened at the symbols named in the table at the end.

## What is in force today

### The toggle

1. **Vertex is a per-session opt-in, and Max stays the default.** The source quotes Rick's direction. He wanted to toggle between the Max plan and Model Garden "on an ad hoc basis", piloted on one session first. A global `env` block in `~/.claude/settings.json` was rejected. It would move the whole fleet onto metered billing.
2. **The mechanism is a `--vertex` flag on `start-cc-with-tmux.sh`.** There is no separate launcher script. The source marks this as a ruling of its design review and does not say that Rick made it.
3. **Composition and guards are Python.** `compose_vertex_env()` builds the three toggle variables and the model pins. The launcher refuses to start when it raises `VertexEnvError`. Python is used because the coverage mandate has no branch instrument for shell.

### The region

4. **The Vertex region is `global`, held in `LUPIN_VERTEX_REGION`, never in `LUPIN_GCP_REGION`.** The second is the container-deploy region, and the model cannot serve there.
5. **A region is certified once, by a `rawPredict` that returned 200, and is enforced by equality at launch.** The certified map is `VERTEX_REGION_CERTIFICATIONS`. The state recorded in `vertex_env.py` is:

| location | `rawPredict` | status |
|---|---|---|
| `global` | 200 | certified; serves and has working quota |
| `us-east5` | 429 | serves but is quota-starved; left out of the certified set |
| `us-central1` | 400 | not servable; the region the design first froze |
| `us` | 501 | an access-scope word, not a location |

6. **A region must name its proving instrument, which is checked at import.** `assert_region_oracle_is_admissible` refuses a certification whose evidence is region-blind. The MaaS OpenAI-compatible endpoint is such an instrument. It returned the same 200 for `global`, for `us-central1` and for a region that does not exist. The metadata endpoint is not admissible either. It returned 200 for a region that cannot serve.
7. **Traffic and logging config must sit at the same location.** The config is scoped to project, location and model. A mismatch runs, bills and logs nothing. `assert_traffic_config_coupling` asserts the match at run time.

### The guards

8. **Guards run before the first token, in the process that runs `claude`.** `pane_guard()` runs inside the pane after the unset and before `claude`. On the Max path it checks that every scrubbed key is gone. On the `--vertex` path it also checks three things. The toggle keys must be present and exact, the region must be certified, and the model pins must be exact.
9. **The tmux server is never born tainted.** The scrub rides `tmux new-session` on both paths. An existing server's environment is refused if it carries Vertex or hostile variables (`assert_server_env_is_vertex_free`). Vertex variables are never forwarded to spawned workers.
10. **Scrub what is hostile, and never what the same launch just forwarded.** The pane's unset set depends on the path (`pane_unset_keys( vertex_path )`). A scrub that ate the forwarded toggle variables once made `--vertex` run on Max under a metered-billing banner.
11. **Hostile variables are refused, or refused when they disagree.** Refused by name: `GOOGLE_APPLICATION_CREDENTIALS`, `ANTHROPIC_VERTEX_BASE_URL`, `CLAUDE_CODE_SKIP_VERTEX_AUTH` and the per-model region overrides. Refused only when they disagree with the resolved value: `GOOGLE_CLOUD_PROJECT`, `GCLOUD_PROJECT`, `ANTHROPIC_MODEL` and `ANTHROPIC_SMALL_FAST_MODEL`. An agreeing override is harmless, and a guard that fires on a valid configuration teaches people to disable guards. The pane unsets all of them outright. The region overrides are re-derived from the Claude Code binary by a test, not held as a number. The source counted 15, and the tuple holds 20 at the `2026-10-07` harvest.

### Logging

12. **The logging config is a complete-object write.** `setPublisherModelConfig` has no `updateMask`, so a partial write silently wipes the other half. `build_full_config_write_body` reads, merges and writes the whole object.
13. **The destination is dataset-level: `bq://{project}.vertex_logging`.** Vertex creates the table. A full table reference fails on the second write. BigQuery has no `global` location, so the dataset location cannot equal the Vertex region. `assert_bigquery_location_legal` rejects it.
14. **The certified location pairing is `global` with the `US` multi-region.** `CERTIFIED_LOCATION_PAIRINGS` records one observed write at `global` that completed with no error and read back. Every other pairing is open.
15. **A write is verified by polling its long-running operation to done with no error, then reading back.** HTTP 200 means accepted, not applied.
16. **Logging is asserted by row count, never by column.** The log schema is output-only and versioned. The sentinel search serializes the whole row, so no column is named.
17. **A negative verdict needs a canary.** The three verdicts are `PROVEN`, `REFUTED` and `INADMISSIBLE`. A canary must have landed in the same window before silence counts as `REFUTED`. A fixed wait is never specified, because Google declares no ingest delay.
18. **Search is reported as `INDETERMINATE`, not as failed, when logging is not proven.** `classify_ac_d5` returns that for an absent search block. "Search did not fire" and "we cannot see" are different claims.
19. **Retry-safety is a claim about the second write.** `assert_double_write_retry_safe` judges a set, a poll, a second set with the table existing, and an unchanged config. The tree holds the judge. It does not record that the double write was run.

### The acceptance oracle and the audit

20. **The oracle is Cloud Monitoring `PublisherModel`, which the serving path emits.** It shares no failure mode with logging. `vertex_monitoring_oracle.py` backs four checks. Two cover the region and model of served traffic: in the first the `location` label must equal the configured region. The third covers no leak into the default path, and the fourth covers derived spend. The source labels them with its acceptance-criteria numbers.
21. **A gap in the audit trail is accepted for trivial probes.** The source quotes Rick. A 2-cent query that cannot be audited is fine. The future billing export must be enabled.
22. **Vertex is a third cost path.** It is a considered exception to the prefer-bounded-Claude-Code rule, because bounded Claude Code is the Max path.

### Spend

23. **A rate cap was ruled, and only part of it was created.** The source says Rick ruled a Cloud Quotas rate cap on `2026-07-14`. It says he ratified a 30, 10 and 10 dollar daily split on `2026-07-15`. That bounds the worst case at 47.55 dollars a day. His ceiling was 50. At about 14:00 on `2026-07-15`, 9 of 12 quota preferences were created. The three bare-slug clamps, the Opus ones, were pending. The tree does not record their creation.
24. **The clamp arithmetic is `vertex_spend_ceiling.py`.** It converts a dollar budget to a tokens-per-minute number at the output price. By the capability page's account, it calls no quota API and no code reads it, so it clamps nothing by itself.
