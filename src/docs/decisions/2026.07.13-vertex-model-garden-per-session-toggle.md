# Decision record: Vertex / Model Garden per-session toggle

**Source:** `src/rnd/v0.1.9/2026.07.13-vertex-model-garden-toggle-search-and-logging.md`, revision 4 of `2026-07-15`. It is an R&D design document, not a ruling.

**Status:** in force for the toggle, region and guards.

**Landed:** the implementation has landed, and the source's status line names the two commits.

**Read from:** the sections on context, region, toggle, guards, acceptance, cost and review outcomes, plus the spend rows. The rest of its 1,900 lines is review history.

## What was decided

1. **Vertex is a per-session opt-in, and Max stays the default.** The source quotes Rick's direction of `2026-07-13`. He wanted to toggle between the Max plan and Model Garden "on an ad hoc basis", piloted on one session first. A global `env` block in `~/.claude/settings.json` was rejected. It would silently move the whole fleet onto metered billing.
2. **The mechanism is a `--vertex` flag on `start-cc-with-tmux.sh`, with no new launcher script.** The source marks this as a ruling of its design review. It does not say that Rick made it.
3. **The Vertex region is `global`.** It is held in `LUPIN_VERTEX_REGION`, never in `LUPIN_GCP_REGION`. The model `claude-opus-4-8` is not servable in `us-central1`: a `rawPredict` there returned 400. The word `us` is an access scope, not a location. Only a `rawPredict` may certify a region. A metadata 200 may not. This was measured, not ruled.
4. **Guards run before the first token, in the process that runs `claude`.** The in-pane guard `pane_guard()` does this inside the pane. The `--vertex` flag never creates the tmux server: it refuses, or creates one from a scrubbed environment. Vertex variables are never forwarded to spawned workers.
5. **The pilot's acceptance oracle is Cloud Monitoring.** It reads the `PublisherModel` metric, not a BigQuery log row. A log row cannot tell "the toggle never engaged" from "money was spent and nothing was logged". Criterion AC-D4b asserts that the `location` label equals the configured region.
6. **Spend is capped.** The source says Rick ruled a Cloud Quotas rate cap on `2026-07-14`. It says he ratified a split of 30, 10 and 10 dollars a day (Opus, DeepSeek, gpt-oss) on `2026-07-15`. The source puts the worst case at 47.55 dollars a day, against his ceiling of 50.
7. **A gap in the audit trail is accepted for trivial probes.** The source quotes Rick. A 2-cent query that cannot be audited is fine. The future billing export must be enabled, so that the work itself can be audited.
8. **Vertex is recorded as a third cost path.** It is a considered exception to the prefer-bounded-Claude-Code rule. Bounded Claude Code is the Max path, which is what this feature is an alternative to.

## Not decided in the source (as of `2026-07-15`)

- Whether paying real money for peak-hour Max headroom is worth it. This is Rick's gate, and it was still open.
- The data-retention opt-in `advancedAiEnabled`. It was held behind a data-sharing probe.
- The billing-export configuration. It is a console action that only Rick can take.
- Whether the follow-up edits to the cost-model page, the memory note and the root `CLAUDE.md` were made (decision 8). I did not check.
