## What is in force today

1. **The source of the stream is the seat's transcript JSONL file.** The source records this as the walk-through ruling on source. A raw terminal tee was left as an optional fourth phase and is not built. `git grep -l -F pipe-pane` over tracked `*.py` and `*.sh` files returns no file. The same search for `capture-pane` returns seven files, three of code and four of tests. So the search can find something.
2. **One poller serves each watched seat.** `_cc_transcript_tailers` in `routers/websocket.py` holds one `CcTranscriptTailer` per seat id. Every watcher of that seat shares it. `_start_watching_cc_transcript` creates a tailer on two conditions. The watcher is the seat's first, and the dict holds no entry for the seat. Nothing tails a seat that nobody watches, which is the walk-through ruling on sessions. The second condition hides a defect, listed under open items.
3. **The tailer stops in two ways, and only one of them waits.** An unwatch that empties a seat stops the tailer at once. The queue endpoint's cleanup also stops it at once, but only when the closing socket is still the active one for its session id. Every other path goes through the synchronous `disconnect()`, which drops the watch and cannot stop a tailer. Those paths are a superseded socket in `connect`, a send failure in `emit_to_session` or `async_emit`, and the audio endpoint. On those paths the tailer stops itself after `grace_seconds` with no watcher. The source said the tailer stops after the last watcher leaves "plus a grace period", without this split.
4. **The seat's file is resolved from the session bridge on every poll.** `resolve_transcript_path` reads the bridge by exact full id and makes no process-liveness check. It returns `transcript_path` as written, and returns an empty string when the file is missing. The path is never rejoined against a root. The source named `get_session_metadata` for this read. The code uses `find_session_by_id`, and its docstring says the first call answers only for the calling process.
5. **The tail primitive is new code in `cosa/utils/transcript_tail.py`.** The source proposed reusing `tail_session_file` and moving or re-exporting it. The tree wrote `tail_jsonl` instead. It returns rotation as a third value and withholds the replayed records. `read_tail_bytes`, `read_window_before` and `read_window_from` sit beside it.
6. **A changed bridge path is the `/clear` signal.** `poll_once` compares the resolved path with the one it holds. On a change it takes the new path, rebuilds the epoch, resets the offset to 0 and reports `rotated`. A shrunken file is the second detector. Blocks read from the old file and not yet sent are dropped. The loop then sends one `cc_transcript_state` frame with state `rotated`.
7. **`file_epoch` names the file, and two code paths compute it differently after a truncation.** `epoch_for_path` returns the transcript's base name without its extension. After an in-place truncation `poll_once` sets the tailer's epoch to that name, a `#` and the Unix time. Its frames carry that value. The watch handler and `read_backlog` still call `epoch_for_path` and get the bare name. This is read from the code and was not run. It is listed under open items.
8. **The mapper shows the record types it knows and skips the rest.** `DISPLAYABLE_RECORD_TYPES` holds `assistant` and `user`. A block's `kind` comes from the content block's type and not from the record's role. A bare-string `message.content` and a list are both handled. The four kinds are `text`, `thinking`, `tool_call` and `tool_result`. A recognised block with empty text is still emitted.
9. **A block is `{ ts, role, kind, text, truncated }`, sometimes with `name`.** The source's proposed shape put `offset` in each block. The built block has none, and offsets live on the frame. A `tool_call` carries its tool's `name`. A `tool_result` carries it only when its call was seen by the same index. Code comments cite two later tickets for the name field, which the source does not have.
10. **Each block has a byte budget, and 0 means unbounded.** `_block` measures UTF-8 bytes, cuts the text and sets `truncated` to true. The source also said the full text of a truncated block is served over REST. The REST route applies the same budget, and I found no request that returns the uncut text.
11. **The stream rides the existing `/ws/queue` socket with two new client verbs.** These are the walk-through rulings on transport and on read-only. The receive loop in `websocket_queue_endpoint` sends `cc_transcript_watch` and `cc_transcript_unwatch` to `handle_cc_transcript_verb`. No verb carries anything from a client to a seat.
12. **The watch that creates the tailer sets the starting offset.** `_start_watching_cc_transcript` passes `from_offset` to `tailer.start` only when it creates the tailer. A second watcher of the same seat joins the running stream. The source's rule "the server starts where the client asked" therefore holds only for the watch that creates the tailer.
13. **The watcher registry lives on `WebSocketManager`, and `disconnect()` sweeps it.** `cc_transcript_watchers` maps a seat id to a set of browser session ids. `drop_all_cc_transcript_watches` runs inside `disconnect()`. Frames go out through `emit_to_session` to each watcher, so the watcher set is the single filter.
14. **The console is admin only, through two different gates, with no redaction.** This is the walk-through ruling on access. The REST routes depend on `require_admin`. The socket verbs read `session_is_admin`, which `connect()` fills from the caller's roles. The source ruled that the positive admin arm is proved with a dependency override, because the fleet holds no admin password.
15. **A refused watch answers in the contract's own state frame.** A non-admin watch gets `cc_transcript_state` with state `refused` and reason `admin_only`. A seat with no resolvable transcript gets `refused` with reason `not_found`. Neither registers a watcher. The source's wire table lists four states and proposes `refused` only in its mobile section. A non-admin unwatch gets a generic `error` frame.
16. **A stale epoch is refused, and a null epoch is accepted.** The watch handler compares a non-null `file_epoch` with `epoch_for_path` of the current path. On a difference it sends state `epoch_mismatch` with that bare name and no blocks. A null epoch starts the watch. The seat check in rule 15 runs before the epoch check. After a truncation the tailer's own epoch has a suffix, as rule 7 says, so the two values differ.
17. **An append frame carries `{ cc_session_id, file_epoch, offset, next_offset, blocks, ts }`.** The byte offset is the only sequence number. A frame ends at the tailer's read position, so frames chain across records that map to no block. At most one append frame goes out per coalesce window, which is the walk-through ruling on latency. The first frame of a tailer is a `live` state frame.
18. **The four event names are registered in `websocket available events`.** The names are `cc_transcript_watch`, `cc_transcript_unwatch`, `cc_transcript_append` and `cc_transcript_state`. Ruling OSQ-6 set them and replaced the `transcript_*` names of the first walk-through. A unit test compares the configured set with a committed literal by set equality. That literal now also declares `task_store_changed`, added by a later row.
19. **The REST backlog reads in one of three directions.** `GET /api/cc-transcript/{cc_session_id}` takes `tail_bytes`, `before_offset` or `since_offset`, checked in that order. With none given it serves the configured tail, which is the walk-through ruling on backlog. A seat with no resolvable file answers 200 with empty blocks and `watchable: false`. The body adds `cc_session_id` and `watchable` to the source's four fields.
20. **The roster is a sibling route with its own admin gate.** `GET /api/cc-transcript-roster` calls the arbiter router's `get_fleet_state` handler and projects its sessions. An unreachable arbiter returns status `unreachable`, and an empty fleet returns status `ok`. Each seat row has the keys `session_id`, `persona`, `project`, `last_ts`, `transcript_watchable` and `file_epoch`. Rule 21 says which of them hold a value.
21. **The roster reads four fields that a fleet row does not carry.** `_project_seats` reads `stable_session_id`, `project`, `last_ts`, `last_seen` and `persona_name` from each fleet session. The fleet section is the output of `fleet_render.build_snapshot`, stored by the arbiter loop's `snapshot_sink`. A row there has `session_id`, `persona`, `state`, `holding_on`, `stuck`, `liveness`, `role` and `manager`. `carry_forward_lineage` can add `manager_retained`. So with a real fleet row the roster's `project` and `last_ts` are null, and its id is the row's `session_id`. Only the unit test's hand-written rows carry the other fields. `transcript_watchable` is true when that id resolves to a file. This is read from the code. I did not read a live response.
22. **Six dials are INI keys.** `load_settings` reads the poll interval, grace seconds, coalesce window, backlog tail bytes, block budget bytes and ring buffer bytes. Each has a default in the module. The source counted four dials. The INI comment says three values are rulings and three are implementer defaults. It names two rulings, the coalesce window and the backlog tail, and names no default. The source rules only those two, which leaves four dials unruled.
23. **Only the multiplexer carries the console in a pane.** It has `SessionTranscriptStore`, `SessionTranscriptRenderer` and `SessionTranscriptRoster`. The source's section 4 asked for a legacy panel with the full feature. The legacy client has none. A comment block in `notifications.js` says the legacy client gets no in-pane console and attributes that to a ruling by Rick of `2026-09-28`. `ccConsolePaintSenderCard` paints a sender-card button that opens `/app/console` in a new tab. That page, `console/consolePage.ts`, builds the multiplexer's store and renderer. The legacy stream and render functions have no caller outside tests: `ccConsoleBeginWatch`, `ccConsoleEndWatch`, `ccConsoleApplyChunk`, `ccConsoleApplyState`, `ccConsoleRenderPlanFor` and `ccConsoleCanWatch`. The legacy queue subscription list names the two server events, and no legacy code handles them.
24. **The multiplexer store follows the source's client rules.** Its header states them. A chunk that does not abut the last offset is dropped and one forward REST read repairs it. A new epoch, `epoch_mismatch` or `rotated` clears the buffer and re-reads the backlog. Nothing is sent before `auth_success`. The old seat is unwatched before the new one is watched. The ring is bounded in bytes. "Load earlier" pages back with `before_offset`.
25. **Prose and tool content do not share a renderer.** In the multiplexer `text` renders as markdown and every other kind as plain text. A kind the client does not know is shown, not dropped. The newest block is at the bottom, which is ruling OSQ-9. The legacy `ccConsoleRenderPlanFor` states the same split, but it has no production caller, so it renders nothing.
26. **The console is a second axis of the reading pane and is not persisted.** `ReadingPaneStore.getPaneContent` returns `reading` or `console`. Its header says the value is not persisted, so a reload returns to the reading view. `canGoBack` is false while the console shows.
27. **The console button sits on the sender card.** The walk-through ruling on the HTML pane had put it on the seat's session-strip chip. The header of `SenderCardConsoleButtons.ts` records a placement ruling by Rick of `2026-09-28`. It moved the button to the persona's title bar in the notification history. The button toggles the console.
28. **Bust-out opens the console on its own page.** The source disabled bust-out for the console in v1. Code comments record a ruling by Rick of `2026-09-28` that reverses this. The reading pane's bust-out opens `/app/console`, a page served by `routers/pages.py` with its own bundle entry.
29. **No client folds a thinking block today.** Ruling OSQ-7 said thinking is shown folded and expandable. A comment in `SessionTranscriptRenderer.ts` records a ruling by Rick of `2026-09-29`: text-bearing thinking is shown inline under a dim label. A thinking block with no text is a plain label. The legacy `CC_CONSOLE_FOLDED_KINDS` lists `thinking`, but nothing renders from it. The legacy comment attributes the fold to a ruling by Mr. Radio of `2026-09-27`. The source attributes it to Rick. I did not resolve that disagreement.
30. **A phone client is not checked in this record.** The source's section 5 plans a Live Console screen in the separate `lupin-mobile` repository. I saw file names there that match the plan, from one search, and read no file. Treat every statement about the phone as unchecked.
31. **The test fixture is a captured transcript.** `src/tests/fixtures/cc_transcript/` holds `primary.jsonl`, `breadth.jsonl` and `thinking.jsonl` with two manifests and the two capture scripts. The source's server row 2.8 asked for a captured fixture and not a hand-written one.
