# Decision record: Claude Code session selector strip and focus mode

**Source:** `src/rnd/v0.1.7/2026.04.30-cc-session-focus-mode/01-design.md`, whole document (220 lines).

**Status:** in force as amended. The source is marked "APPROVED" on `2026-04-30` and does not name the approver. Two later changes reverse or amend three of its rules, and this record states the current rule in each case.

**Checked against:** `src/lupin_app/static/js/notifications.js` (the functions named in the table below), `src/lupin_app/static/html/notifications.html`, and the later documents listed at the end.

## What is in force today

These rules describe the legacy notifications page, `notifications.js`. The multiplexer page has its own implementation in `src/lupin_app/static/js/multiplexer/render/SessionStripRenderer.ts`. It uses the same storage key, the same chronological sort and the same late re-apply, and its comments cite the legacy behaviour as the one to match. A port design exists in `src/rnd/v0.1.7/2026.05.02-notifications-ui-js-refactor/10-phase6c-persona-focus-recorder-design.md`, which I did not read.

1. **Two affordances, independent of conversation mode.** The strip is an always-on row above the notification list, with one icon per session that has a card. The focus pill, `#cc-strip-toggle`, shows only the focused session's card. Conversation mode and focus mode are separate axes.
2. **The strip is hidden until a Claude Code sender card exists.** It is shown when the first icon is added. It is hidden again when the last icon is removed.
3. **Strip order is chronological and never changes on activity.** Icons are sorted once after the initial load by `data-created-at` (the persona's `assigned_at`), oldest leftmost. A new session appends on the right. Planned in the source as "leftmost is most recently updated". Reversed on `2026-05-21` by the chronological-lock amendment; see the later documents.
4. **The strip keeps inactive sessions, and a pill hides them.** Any session that has a card has an icon. A session with no allocated voice persona renders as a slate-grey icon. The `Active` toggle sets `data-inactive-hidden` on those icons. It is stored under `notifications_cc_hide_inactive_strip`. The source planned "one icon per active session". The focus-tray design of `2026-05-02` amended it.
5. **Click behaviour.** In default mode a click smooth-scrolls to that session's card. In focus mode a click on a different icon switches focus, and a click on the focused icon does nothing. Turning the pill on enters focus on the leftmost icon, which is now the oldest session. The code reads the in-memory focused id first, but every exit has already cleared it, so that branch never runs. Turning the pill on flashes the focused card.
6. **Unread marks in focus mode.** A notification for an unfocused session sets `data-unread` on its icon and counts up. A managed worker keeps the pulse but never gets the numeric count. This was ruled by Rick on `2026-06-24`, as the code comment records. Focusing a session clears its mark, and leaving focus mode clears every mark.
7. **Every icon carries its conversation-mode state.** The icon has `data-conv-mode` set to `speakerphone` or `quiet`. A session with no recorded choice counts as `speakerphone`. The conversation-mode pin rule for cards is untouched.
8. **Focus state is client-only and persists under `notifications_cc_focus_state`.** The value is `{ enabled, focused_sender_id }`. There is no server state, no WebSocket event and no bridge field.
9. **A stored focus choice survives an absent session.** On reload with no card for the focused session, the UI shows the default view. The stored choice is kept. When the session's icon or card arrives late, `_maybeReapplyPersistedFocus` re-enters focus. The default view shows until then. The source planned "state is discarded". Two fixes reversed that. Preserving the intent on auto-exit was resolved on `2026-05-15`. The late re-apply, `_maybeReapplyPersistedFocus`, is dated `2026-06-17`.
10. **Removing the focused session's icon, or clearing every icon, exits focus mode in memory without clearing the stored choice.**
11. **Focus mode doubles the focused card's message lists.** While the pill is on, each date list of the focused card scrolls at 500 pixels instead of 250. A CSS rule keyed on the pill's `data-focus-active` attribute does it, with no JavaScript on the card. It was added on `2026-05-30`.

## Deferred in the source and still open

- Cross-device focus sync, which would need a bridge field and a WebSocket event.
- Per-card "anchor" pinning for the stacked view.
