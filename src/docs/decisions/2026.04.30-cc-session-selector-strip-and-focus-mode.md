# Decision record: Claude Code session selector strip and focus mode

**Source:** `src/rnd/v0.1.7/2026.04.30-cc-session-focus-mode/01-design.md`, whole document (220 lines).
**Status:** in force; the source is marked "APPROVED 2026-04-30" and does not name the approver. It credits "elicitation" answers from the user for the scope and ordering choices below.

## What was decided

1. **Two new affordances, both independent of conversation mode.** An always-on horizontal strip of one icon per active Claude Code session, above the notification list; and a toggleable exclusive focus mode that shows only the focused session's card. Conversation mode and focus mode are separate on/off axes, so any combination is legal.
2. **One ordering rule: the leftmost strip icon is the most recently updated session, in both modes.** Each notification arrival moves that session's icon to position 0. The source records that the user accepted the loss of stable icon positions in return for seeing which session is freshest (elicitation question 5).
3. **Peripheral awareness in focus mode.** A notification for an unfocused session moves its icon left and marks it unread with a count; the hidden card still receives the notification, so nothing is lost. Switching focus or leaving focus mode clears the mark.
4. **Focus state is per browser, stored in `localStorage` under `cc-focus-state`, and the feature is client-only.** There is no server state, no WebSocket event and no bridge field. The state is discarded on reload if the focused session no longer exists.
5. **Edge cases.** A focused session that ends or is deleted exits focus mode automatically; a new session arriving during focus appears leftmost but stays hidden; `/clear` inside the focused session leaves focus unchanged.
6. **The existing conversation-mode pin rule is untouched.**

## Deferred in the source (not decided)

- Cross-device focus sync (needs a bridge field and a WebSocket event); left until a use case exists.
- The strip's overflow strategy beyond `overflow-x: auto`.
- Per-card "anchor" pinning for the stacked view.
