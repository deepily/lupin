# Decision record: Claude Code session selector strip and focus mode

**Source:** `src/rnd/v0.1.7/2026.04.30-cc-session-focus-mode/01-design.md`, whole document (220 lines).
**Status:** in force. The source is marked "APPROVED" on `2026-04-30` and does not name the approver. It credits "elicitation" answers from the user for the scope and ordering choices below.

## What was decided

1. **Two new affordances, both independent of conversation mode.** The first is an always-on strip above the notification list. It has one icon per active Claude Code session. The second is a toggleable focus mode that shows only the focused session's card. Any combination of conversation mode and focus mode is legal.
2. **One ordering rule: the leftmost strip icon is the freshest session, in both modes.** Each notification arrival moves that session's icon to position 0. The source records that the user accepted unstable icon positions. In return the strip shows which session is freshest (elicitation question 5).
3. **Focus mode keeps peripheral awareness.** A notification for an unfocused session moves its icon left and marks it unread with a count. The hidden card still receives the notification, so nothing is lost. Switching focus or leaving focus mode clears the mark.
4. **The feature is client-only, and focus state is per browser.** It is stored in `localStorage` under `cc-focus-state`. There is no server state, no WebSocket event and no bridge field. The state is discarded on reload if the focused session no longer exists.
5. **Edge cases are settled.** A focused session that ends or is deleted exits focus mode automatically. A new session arriving during focus appears leftmost but stays hidden. A `/clear` inside the focused session leaves focus unchanged.
6. **The existing conversation-mode pin rule is untouched.**

## Deferred in the source (not decided)

- Cross-device focus sync, which needs a bridge field and a WebSocket event. It waits for a use case.
- The strip's overflow strategy beyond `overflow-x: auto`.
- Per-card "anchor" pinning for the stacked view.
