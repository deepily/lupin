## What is in force today

1. **TFE has one engine: the Claude Agent SDK `query`, called in process.** `TFEOrchestrator` calls `sdk_query` at four sites. They are the diagnosis Lead, the proposal Lead, the Coder and the verification call of the fix phase. Nothing in `orchestrator.py` or `config.py` branches on an engine name.
2. **The `tfe_to_cc` package holds prompt builders and parsers only.** It has `build_diagnosis_bundle_prompt`, `build_fix_bundle_prompt` and the parsers in `output_contract.py`. Nothing in `src/cosa` outside its own tests imports it. Two scripts in `src/scripts` and seven unit test files do.
3. **No INI key selects an engine.** The two keys the design names appear in no `.ini` file and in no code. The package docstring still calls them "future work". They are:

```
test fix expediter phase 1 engine = sdk | claude_code
test fix expediter phase 3 engine = sdk | claude_code
```
4. **Claude Code answers in two fenced JSON blocks.** They are `tfe-diagnosis` and `tfe-result`. The parsers extract the fence. The validators require `root_cause`, `error_category` and `confidence` for a diagnosis, and a `verdict` of `fixed`, `failed` or `unclear` for a result.
5. **A missing result block is rebuilt from the commits.** `parse_result_from_git_log` reads lines shaped `<sha> fix(tfe): C<id>`. A listed cluster with no such commit gets `unclear`. This follows the design's "commits are ground truth".
6. **A missing diagnosis block is recovered by pattern, and the recovery fails the package's own validator.** `parse_diagnosis_fallback` returns `error_category` `unknown` when it finds no category. `validate_diagnosis_payload` rejects `unknown`. I ran both on one input.
7. **The Max-subscription smoke test is retired, and its thesis with it.** The test is skipped, retired on 11 May 2026. The CLI reports a counterfactual `cost_usd` above zero on every `-p` call, whichever auth path paid. A zero `cost_usd` cannot gate anything.
8. **The REST door the design submits through is gone.** `/api/claude-code/queue/submit` answers 410. The route for a Claude Code job is `POST /api/v2/submit` with the command `agent router go to claude code`.
9. **The dispatcher still fixes its own tool list.** `_run_bounded` allows `converse`, `notify`, `ask_yes_no`, `Read`, `Write` and `Bash`. It has no `allowed_tools_override`, and no `Edit`, `Grep`, `Glob`, `ask_multiple_choice` or `ask_open_ended_batch`.

## Planned in the source and not carried, or reversed

- **A runtime fork, both engines permanent, selected by two INI flags.** Not built. The source says "The feature flag IS the steady-state architecture". The ledger entry for this source says "code still forks at runtime"; the tree does not.
- **`TFE_to_CC_Orchestrator` and `TFE_to_CC_Job` in `tfe_to_cc/orchestrator.py` and `job.py`.** Neither file exists.
- **`allowed_tools_override` on `dispatch()`, and a config field `phase_1_engine`.** Neither exists (rule 9, rule 3).
- **The Max-subscription test as "the blocking gate for everything else".** Retired (rule 7). The source's cost thesis, "$0.00 confirms Max subscription", has no replacement in the tree.
- **The diagnosis fallback "safe defaults (`confidence=0.5`, `error_category=\"unknown\"`)".** Carried as written; the validator then refuses it (rule 6).
- **The verdict set `fixed|failed|unclear`.** The parsers carry it. The live harness `tfe_to_cc_phase3_live.py` adds a fourth, `already_clean`, for a "fixed" verdict that has no commit. The package does not know it.

## Still open or not decided

- Whether to build the engine, or to retire the package. No later document I found rules on it. The redesign of May 2026 calls it "a prompt-builder package only, not a runtime CC consumer". It adds that the package "pre-stages prompts for a runtime integration that hasn't shipped".
- The source's own measurements stand as reported. I did not re-run them. The diagnosis phase took one call, 9 turns and 32 seconds. Across the live runs in log 21, the fix phase landed between 0 and 5 of 11 fixes. The SDK baseline was 0 of 11. Sonnet 4.6 beat Opus 4.7 on this input in the matrix. Treat those as one input set.
- The design's risks table promises a credential probe, `claude api user`, in the container preflight. A fixed-string search of `src/scripts` and `docker` finds none. I did not check the Dockerfile's CLI version pin or the message-cap telemetry.
