# Doc-lint gate

A pre-commit gate that lints docstrings, `#` comments and markdown on staged files. The commit hook runs it with `--blocking`, so a finding on a staged line refuses the commit.

## What it checks
- `gate.collect` reads each staged `.py` and `.md` file from the index. Python goes through `docstring_lint`, `comment_lint` and ruff; markdown goes through `md_lint` and markdownlint-cli2. Ruff reads the staged text and markdownlint-cli2 reads the working-tree file. A missing tool prints a "SKIPPED" warning. Markdownlint-cli2 exiting 1 with no finding read also refuses under `--blocking`, since the output format would have changed. Under `--blocking`, a tool that exits above 1 refuses the commit. So does a staged `.py` or `.md` file git treats as binary, since its diff names no touched line. That holds when the commit adds the file or changes its content. A warn-only file prints a warning instead, and so does a file whose blob is HEAD's or the merged commit's. A staged gitlink (a submodule entry) has no text and prints as not checked. A file that is not UTF-8 is held to the same rule as a binary one. A staged symlink is never linted as its target text and warns once. Under `--blocking` a link is refused when the commit adds it or changes its target, and it stands for source (`link_stands_for_source`). It stands for source when it is named like a swept `.py` or TypeScript file. It also does when it resolves outside the repo, to nothing the index holds, or to swept source files. A chain of tracked links is followed up to 8 hops, and a longer or looping one counts as source.
- `text_rules.lint_text` caps a summary at 90 characters, a sentence at 25 words and a preface at 6 lines. It also flags bare references, dates, banners and text addressed to a model. `docstring_lint` caps a docstring at 40 lines. `md_lint` caps a capability page at 40 lines, front matter included, and other `src/docs/` pages at 1500 words, except the `REFERENCE_SKIP` folders.
- `links.py` flags a relative markdown link whose target file is missing, and a `Design:` path inside the repo that does not exist. It skips web, mail, anchor-only and doc-viewer links, and never judges a `Design:` path outside the repo.

## Scope
- `cli.in_scope` drops a path with a `tests`, `.venv`, `node_modules`, `site-packages`, `__pycache__` or `rnd` directory segment. It also drops `test_*` files and `conftest.py`.
- Findings count only on lines the staged diff touched (`filter_findings`). The swept, counted and package refusals ignore this filter. File names are read from git apart at the NUL byte, so a name git would quote is linted. A name that is not UTF-8 prints with `\xNN` escapes, and its ruff findings and TypeScript count are kept. Markdownlint cannot be given such a name, so with that tool installed the file is refused. Page-level findings (`PAGE_LEVEL_RULES`: `reference-length`, `capability-length`, `runbook-template`) count when the commit edits the file, deletes lines from it, or moves it with no edit. Under `--blocking` one refuses only when the commit created it. That means the page is new, or the last commit's copy lacked the finding, or its measure rose (`gate.predating`). That copy is linted under the path it had then, so a move to a path with a limit creates the condition, edited or not. Otherwise it prints with `this condition predates the commit`.
- The swept scope (`swept_scope.is_swept`) is every tracked `.py` file that `in_scope` accepts, except paths under `src/lupin_mcp/`. Git lists the files, never a disk walk. A page moved unedited from an unjudged folder into a judged one counts as created, so its findings refuse.

## What makes it refuse
- `--blocking` refuses a commit with a finding on a staged line, from any linter the gate runs. Each prints as a `REFUSED` line. Every refusal exits 3, and the gate never exits 1. Without the flag these findings print and the gate exits 0. An internal crash prints `GATE CRASHED, commit allowed` and exits 0 either way. `gate.WARN_ONLY_PREFIXES` names two root folders that `--blocking` leaves in warn mode (`is_warn_only`): `history/` and `todo-history/`. That is a standing exception that Rick ruled, and `WARN_ONLY_PATHS` is empty. Their findings print with `(warn mode, commit allowed)`. The root `history.md`, `TODO.md` and `bug-fix-queue.md` (`gate.RECORD_PATHS`) block under rule set B, judged on added lines. Rule set B drops `iso-date`, `dated-banner`, a bare-ref of the row-id-or-sha kind, `caps` and `sentence-length` (`is_record_exempt`). Every other rule refuses. `caps` and `sentence-length` sit in one constant, `RECORD_RULES_OFF`, which is emptied when the writing rules are fixed. The same name at any other path is refused like any page, `src/cosa/history.md` and `src/cosa/history/` included. Waiving a line-level finding: ruff takes its own `# noqa: <code>`. A docstring finding takes the marker in the next bullet. A markdown finding or a `#` comment finding cannot be waived. While git holds `MERGE_HEAD` or `CHERRY_PICK_HEAD`, a finding on a line identical to its copy in any merged commit is not enforced (`gate.merged_in`). It prints with `came in with the merged or picked commit`. A line changed while resolving is enforced, and so is every finding when that file cannot be read. A Python file that holds a bare carriage return gets no such pass.
- Rule divergence: a tracked rule file that differs between index and working tree refuses a commit. This applies when the commit stages a Python file, a TypeScript or JavaScript file in the counted scope, or any count table. Rule files are the `doc_lint` package, the word list, `pre-commit-chain.sh`, `ts_doc_extract.mjs` and `ts_export_extract.mjs`. The swept and counted checks are then skipped.
- Swept scope: a staged swept file is refused when its docstring lint holds any finding on any line, touched or not. A waiver is a same-line marker, `doc-lint: waive <rule> -- <reason>`, that names the rule. Its reason needs a word of three or more letters, or it waives nothing.
- A staged swept file that does not parse, or is not UTF-8, is refused and cannot be waived. The commit gate drops a leading byte-order mark first. Elsewhere a non-UTF-8 file is skipped with a warning, and in the counted scope it counts as one finding.
- Counted scope: every other tracked `.py` file is counted. It is refused when its unwaived finding count exceeds its entry in `src/conf/doc-lint-counts.json`, which records one count per file. A new file starts at zero and a rename inherits its old entry.
- The count table may only fall. A staged table that raises an entry is refused, unless it carries a new rules stamp and equals a census of the index. A table cut under other rules refuses a commit that stages a counted file. With no table, the scope is reported as not checked. `python3 -m cosa.repo.doc_lint.counts --write` regenerates it.
- TypeScript and JavaScript scope: every tracked file `tsdoc_lint.in_scope` accepts (`.ts`, `.js`, `.mjs`) is counted, with no swept zero rule. A staged file is refused when its unwaived comment-finding count exceeds its entry in `src/conf/doc-lint-ts-counts.json`. The same rules as the Python table apply to new files, renames, waivers, a staged table and a stale stamp. `ts_counts` counts the staged text through the Node extractor, in one run for all staged files of the commit. A commit with none runs no extractor. `python3 -m cosa.repo.doc_lint.ts_counts --write` regenerates the table. `python3 -m cosa.repo.doc_lint.ts_doc_exists --list` prints each exported symbol that has no doc comment. The same files, less the R&D folders and the mobile bundle, are also held to a count of exported symbols with no doc comment. That table is `src/conf/doc-lint-ts-exports-counts.json`. `ts_doc_exists --write` regenerates it. A missing comment has no line to carry a waiver, so the refusal says to add one. `run-doclint-gate.sh` runs `ts_doc_exists --check` as its third step. Each run prints one count block per scope, four in all.
- `BLOCKING_PACKAGES` lists directory prefixes. A staged file inside one is refused for a mechanical finding on any line; the tuple is empty in this tree. Mechanical means `dated-banner`, `iso-date` or `agent-imperative`. It also means an eight-character id, bare or after `row`, `bug`, `task`, `ts`, `decision`, `job`, `pr` or `ticket` (`is_mechanical`).
- `pre-commit-chain.sh` runs the gate with `--blocking` after the secret scan and the R&D guard. It stops the commit only on exit 3. Any other non-zero exit is allowed with a line that says nothing was enforced. A tree whose `gate.py` predates blocking exits 1 on a finding and lands there. A ruff that fails on a blank file too is a version or configuration skew. It lets the commit through with one line saying ruff checked no file. A ruff that fails on one staged text still refuses. A `LUPIN_RUFF` program that prints no ruff report gets one such line as well. A staged Python file too deeply nested for the parser is refused as a parse error, and never crashes the gate. A count table too deeply nested to read counts as malformed, so a staged one is refused. A count table at HEAD that cannot be read refuses a commit that stages a counted file, unless the commit also stages a readable table. `range_gate` replays the commits of a range. It passes `--blocking` only to a commit whose parent descends from the sha in `src/conf/doc-gate-blocking-epoch.txt`. An empty file holds no commit to blocking, and a malformed one exits 2. A range is judged under the value its base records. A head that records another value, none or no file exits 2, and so does a working copy that differs from the head. So does an epoch that is not an ancestor of the head of the range, since nothing there can be told to predate it. When the base records none, the head's value is used. That range must hold one value throughout, so two values, or a value and then none, exits 2. The value must be a commit's own sha. The real gate runs from the code of each commit's parent, so a commit that edits `gate.py` is linted by the gate it replaces. A range whose base descends from the epoch holds every commit to blocking, including one merged in from a branch that forked before it. A merge commit is replayed with its other parents as the incoming commit. A concluded cherry-pick leaves no record, so it is replayed as an ordinary commit. `pre-push-chain.sh` is not installed by default; a person links it into the hooks directory. Once linked, it lints each pushed tip in a throwaway worktree through `src/tests/run-doclint-gate.sh`, which runs `scope_gate`. That gate exits 0 clean, 1 findings, 2 not checked. Any non-zero result refuses the push, but a tip that does not descend from the epoch commit is pushed with a warning.

## Calling it
- Hook: `python3 -m cosa.repo.doc_lint.gate --blocking --repo-root <root>`. Whole-corpus or diff reports: `python3 -m cosa.repo.doc_lint.md_lint` (or `docstring_lint`, `comment_lint`) with `--changed BASE`, `--staged`, `--strict` or `--json`, through `cli.run_linter`.
