# Post-game addendum: the final tip went red on six unit tests

- **Engagement**: Plan 1, the documentation rewrite.

- **Sources**: the full unit build on `e573d6698`, with its assertion lines read, and the commits named below.

## 1. What happened

- **Measured**: the full unit build on the final tip `e573d6698` ended with 6 failures. Re-run on that tip, the two files involved gave `6 failed, 63 passed`.
- **Why nobody saw it earlier**: author and reviewer ran the doc-lint gate, the census guards, the docs-only check and the existence check.
- **What they did not run**: the unit tier.
- **Why that matters**: a change made only of comments can still move a test that reads file bytes or counts a population. Those tests live in the unit tier.
- **Not known**: which commit first turned each test red. The build was not bisected.

## 2. The two causes and their fixes

| Cause | Tests | What was wrong | Fix |
|---|---|---|---|
| The sweep took undocumented exports to zero | 1, the real-repository census test | It asserted a count above zero, so a fully documented tree failed | `e0498aaa2` |
| The sweep changed the bytes of static JavaScript | 5, the cache-bust token tests | The `?v=` tokens in two files named the old bytes | `a8a80c5d0` |

- **Fix 1**: the real walk stays and accepts zero. A second test plants one undocumented export in a temporary file and shows the real extractor finds it.
- **Why the planted file**: a tree at zero says nothing about whether the check can detect. The plant is the positive control.
- **Fix 2**: `python -m lupin_app.asset_tokens --stamp` rewrote two files. No code changed.
- **After**: the two files pass with 39 and 35 tests. The census guards pass with 391 passed and 4 skipped.
