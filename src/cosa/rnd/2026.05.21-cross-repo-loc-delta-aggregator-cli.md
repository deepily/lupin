### 2.4 Library-shape plotter — vindicated

The pre-aggregated dict input contract Maria specified in her R&D doc §3.4 was a critical design choice. Without it the aggregator would have had to reimplement matplotlib rendering. With it:

```python
plot_summary(
    daily       = global_daily,           # {date_str -> {added, deleted, ..., by_repo: [...], by_file_type: [...]}}
    summary     = global_summary,
    output_path = path,
    group_by    = "repo",                 # ← swap from "file_type" to "repo"
    title_meta  = { "scope": "global", "repos": [...], "rev_window": "..." },
)
```

Same matplotlib code, different group key. Zero code duplication between per-branch and global use cases.

## 3. Schema v2 + sidecar JSON (recap; full design in Maria's doc §3.3)

### 3.1 CSV schema

```csv
date,repo,branch,file_type,added,deleted,files_touched,commits
2026-05-15,cosa,wip-v0.1.7-2026.04.23-tracking-lupin-work,python,521,73,2,1
2026-05-15,lupin,wip-v0.1.7-...,python,2553,5,7,3
```

### 3.2 Sidecar JSON `{csv_path}.meta.json`

```json
{
  "csv_schema_version": 2,
  "repo": "cosa",
  "branch": "wip-v0.1.7-2026.04.23-tracking-lupin-work",
  "rev_range": "main..wip-v0.1.7-...",
  "since": null,
  "until": null,
  "generated_at": "2026-05-21T21:11:38.770292Z"
}
```

### 3.3 Schema-v1 backward-compat path

When a legacy v1 CSV is encountered (no `repo` / `branch` columns, no sidecar):

1. `_load_csv_with_identity()` detects missing columns via `if "repo" not in df.columns`
2. Falls back to sidecar JSON if present (extracting `repo`, `branch` keys)
3. If sidecar also absent, derives from filename via `_repo_from_filename()` + `_branch_from_filename()`:
   - Filename pattern: `{repo}-{branch-slug}-loc-delta.csv` → split on first `-wip-` (the conventional branch-name prefix)
   - Fallback chain ensures any historical CSV remains aggregatable
4. Injects the derived values as new columns and reorders to canonical v2 layout

**Validated against**: `planning-is-prompting/io/git-loc-delta/planning-is-prompting-wip-v0.1.3-2026.02.16-continued-development-loc-delta.csv` (schema v1). The aggregator correctly extracted `repo="planning-is-prompting"`, `branch="wip-v0.1.3-2026.02.16-continued-development"` without a sidecar.

## 4. How the strawman resolved Maria's 5 open questions

These are **provisional resolutions** — to be ratified or overridden in the walk-through with Maria.

### Q §7.1 Repo discovery — Maria's lean: hybrid (INI + override)

**Strawman**: explicit `--repos PATH ...` only. INI auto-discovery NOT implemented.

**Rationale + Rick's directive (2026-05-21 voice)**:
- The Lupin INI's `external repos` paths are **container paths** (`/var/external-projects/...`), not host paths. The aggregator runs host-side; container paths don't resolve.
- A second INI key (host paths) would create dual sources-of-truth + drift risk.
- Rick voice: "I'm not certain where the INI would live. We don't really need it for now. We can defer indefinitely."

**Status**: **DEFERRED INDEFINITELY**. Phase 1 ships with explicit `--repos`. If a future use case forces auto-discovery, a fresh design pass decides INI-vs-env-vs-config-file.

### Q §7.2 Missing-CSV handling — Maria's lean: report-as-stale

**Strawman**: matches. When `_find_csv_in_repo()` returns None:
- Stderr line: `Warning: no CSV found for {path} (stale — no session-end ran here yet?)`
- Repo name added to `summary["stale_repos"]` list
- Console output appends a `Stale repos (no CSV found):` section listing the path basenames
- Aggregation proceeds with whatever CSVs WERE found
- Hard error only if zero CSVs total

**Status**: ✅ matches Maria's lean.

### Q §7.3 Branch-aware aggregation — Maria's lean: current-branch + `--all-branches` opt-in

**Strawman**: most-recently-modified CSV per repo, preferring branch-mode files (filename does NOT start with `YYYY-`).

**Mechanism** (`_find_csv_in_repo`):
1. Glob `{path}/io/git-loc-delta/*-loc-delta.csv`
2. If `--prefer-branch-csv` (default True): filter to filenames not starting with 4-digit year
3. Pick the most recently modified

**Status (2026-05-21 ratified by Maria via DM `1c7e222e`)**: ✅ **ACCEPTED my heuristic**. Maria's reply verbatim:
> "Rolling-overwrite means 'most-recent CSV' IS effectively 'current branch' in practice; the explicit-current-branch + `--all-branches` opt-in I proposed adds flag surface for a case that doesn't materially benefit users today. Defer that complexity until someone asks for cross-branch aggregation specifically."

`--all-branches` deferred to a future enhancement if a cross-branch aggregation use case emerges.

### Q §7.4 Default window — Maria's lean: today-only

**Strawman**: NO default window initially.

**Status (2026-05-21 ratified + implemented)**: ✅ **TODAY-DEFAULT at CLI level**. Maria DM `1c7e222e` leaned this way ("the slash command's natural mental model is 'what did I do today across all repos'"); I implemented it at the CLI layer (her offered location alternative) since the today-semantics is most naturally a CLI concern, not a wrapper concern.

**Semantics implemented**:

| Invocation | Effective filter |
|---|---|
| Bare `--repos PATH PATH ...` (no `--since` / `--until`) | `--since today --until today` |
| `--since YYYY-MM-DD` alone | until is open (any date ≥ since passes) |
| `--until YYYY-MM-DD` alone | since is open (any date ≤ until passes) |
| Both explicit | inclusive window as supplied |

**Note**: I diverged slightly from Maria's offered "since-as-today + --until alone" spec — implemented the natural mental model (open-on-the-other-side) since "since-as-today AND --until=2026-05-20" creates a nonsensical window for any user. Maria flagged this as "probably nonsense in practice" in her spec, so the divergence is in spirit.

**Verified live**: bare invocation against `--repos . src/cosa <pip-path>` correctly filters to 2026-05-21 only, returns lupin's +1,578 / -52, 14 commits as the single-repo single-day result.

### Q §7.5 Author filtering — Maria's lean: pass-through, default no-filter

**Strawman**: NOT IMPLEMENTED. No `--author EMAIL` flag yet.

**Status (2026-05-21 ratified by Maria via DM `1c7e222e`)**: ⏸ **DEFERRED to Phase 1.5**. Maria's reply verbatim:
> "Phase 1 doesn't need it; if Rick wants self-vs-others filtering later, surface as a Phase 1.5 enhancement. Documenting in the R&D doc's open-questions section as deferred."

**Implementation difficulty note** (preserved for future Phase 1.5 designer): aggregator reads pre-aggregated CSVs that already collapsed across authors. To honor `--author`, the design would need either:
- (a) Re-run the per-repo tool with `--author` and ingest fresh CSVs (slow, requires the per-repo branches accessible)
- (b) Restrict to CSVs that were themselves generated with `--author` filtering (requires the sidecar to carry author info — not in schema today)

Option (b) is cleaner but requires a schema bump or sidecar extension. Defer the design decision until Phase 1.5 is scheduled.
