## Context

Rick wants a per-day breakdown of lines added/deleted from the repo, broken down by file type, with two modes:

1. **Default (today)** — just today's commits: total added, total deleted, file-type breakdown.
2. **Branch range** — for every day Rick has been working on the current branch, show daily totals (added, deleted) + a per-day file-type summary.
3. **Bonus** — emit results as CSV so daily numbers can be tracked, pivoted, and graphed over time.

Why this exists: the existing `cosa/repo/branch_analyzer/` produces **branch-total** deltas via `git diff base...head`. It cannot bucket by date and cannot iterate per-commit. To answer "what did I do today" or "show me my daily velocity on this branch," we need a new entry point that walks `git log` and aggregates by commit date. The existing skill's classifiers and statistics helpers are reusable — only the orchestration and CSV writer are net-new.

## Approach

Build a new sibling under `cosa/repo/` that mirrors `branch_analyzer/`'s structure but is driven by `git log --numstat` (per-commit) instead of `git diff` (branch-total). This keeps separation of concerns clean — the existing `branch_analyzer` stays untouched and continues to answer "what did this whole branch change," while the new `git_loc_delta` answers "what changed when."

### Why a new package, not an extension of `branch_analyzer`

- `branch_analyzer` is hard-wired to three-dot `git diff base...head` and aggregates into a single bucket. Bolting per-commit iteration onto it would require restructuring `StatisticsCollector` to carry a `(date, file_type) → {added, deleted}` key shape, which would either break the existing public API or duplicate it conditionally. Cleaner to introduce a new package.
- Justified by the audit: the file/line classifiers and CSV-output gap are the only material reuse/build points; the rest of `branch_analyzer` is orthogonal to this use case.

## CLI Surface

```
python -m cosa.repo.run_git_loc_delta [OPTIONS]

  --repo-path PATH         Repo to analyze (default: cwd)

  Date range (mutually exclusive):
  --today                  (default) Commits since today 00:00 local
  --since YYYY-MM-DD       Inclusive lower bound
  --until YYYY-MM-DD       Inclusive upper bound (default: today)
  --branch [BRANCH]        Range = merge-base(main, BRANCH)..BRANCH
                           BRANCH defaults to current branch.
                           Base ref configurable via --base (default: main).
  --base REF               Base ref for --branch mode (default: main)

  Filters:
  --include-merges         Include merge commits (default: exclude)
  --author EMAIL           Filter by commit author email (default: all)

  Output:
  --output FORMAT          console | json | csv (default: console)
  --save-output PATH       Write to file. For --output csv, defaults to:
                           {project_root}/io/git-loc-delta/{YYYY-MM-DD}-loc-delta.csv

  -v, --verbose            Echo git commands and per-commit progress to stderr
  --debug                  Verbose + full tracebacks
```

**Exit codes**:
- `0` — success
- `1` — git failure (any `GitCommandError`: command not found, non-zero return code, timeout)
- `2` — argument-parse error (raised by `argparse` automatically on bad flags)

## Algorithm

1. **Resolve date range** — `--today` (default) → since=today 00:00, until=now. `--branch` → since=author-date of `git merge-base <base> <branch>`, until=HEAD author-date. Explicit `--since`/`--until` override.
2. **Shell out to git log** with the canonical pattern from `branch_analyzer/git_diff_parser.py:114-147` (`subprocess.run`, `capture_output=True`, `text=True`, timeout, custom `GitCommandError`):
   ```
   git log --numstat --no-merges --date=short \
           --pretty=format:'COMMIT|%H|%ad|%aE' \
           --since=<since> --until=<until> [<rev-range>]
   ```
3. **Parse stream** in `git_log_parser.py` — for each `COMMIT|...` line, set current `(sha, date, author)`; for each `\d+\t\d+\tpath` line, yield a `FileChange(date, sha, path, added, deleted)`. Binary files (`-\t-\t...`) → skip.
4. **Classify file type** via existing `FileTypeClassifier.classify(path)` → `python | javascript | markdown | other | …`. (Classifier is constructed with the branch_analyzer config loaded via `ConfigLoader().load()`.)
5. **Aggregate** in `daily_aggregator.py` to a single `dict[(date, file_type)] → {added, deleted, files_touched}` plus a `dict[date] → {added, deleted}` totals view.
6. **Emit** per `--output`:
   - **console** — two tables: per-day totals, then per (date × file_type) breakdown. Use `du.print_banner` for headers (matches COSA idiom).
   - **json** — `{ days: [{ date, total_added, total_deleted, by_file_type: [...] }], summary: {...} }`
   - **csv** — tidy-long shape (see below).

## CSV Output Shape (the bonus feature)

**Tidy-long**, pivot-friendly, fixed schema regardless of file-type cardinality:

```csv
date,file_type,added,deleted,files_touched,commits
2026-05-15,python,128,42,7,3
2026-05-15,markdown,300,15,2,3
2026-05-15,javascript,50,8,1,3
2026-05-16,python,80,20,5,2
```

Why long not wide: new file types over time would add columns in a wide format, breaking downstream consumers. Long is stable, pivotable in pandas with one line, and graphs cleanly in matplotlib/Excel.

Implementation: `pandas.DataFrame(rows).to_csv(path, index=False)` — matches the COSA CSV convention.

**Default save location** (when `--output csv` without `--save-output`) — **mode-aware** (post-ship enhancement 2026-05-16):

- `--branch` mode → `{cu.get_project_root()}/io/git-loc-delta/{repo}-{branch-slug}-loc-delta.csv`
  (stable per-branch filename; daily reruns overwrite in place until the branch lands)
- `--today` / `--since`/`--until` mode → `{cu.get_project_root()}/io/git-loc-delta/{YYYY-MM-DD}-loc-delta.csv`
  (date-stamped for archival snapshots)

Directory auto-created if missing. The mode-aware default replaces the original single-pattern default during the post-ship "documentation + filename-flip" iteration (Rick voice-approved 2026-05-16 via `ask_multiple_choice`).

> **Convention alignment (Pass 1 F1)**: `io/` is the established artifact-output convention across the project (`io/decision-proxies/`, `io/swe-team/reports/`, `io/deep-research/`, `io/commons/`). Aligning here avoids inventing a parallel top-level `reports/` tree.

## Edge Cases (Pass 1 F6)

| Edge case | Expected behavior | AC |
|---|---|---|
| **No commits in date range** (e.g. `--today` on a quiet weekend) | Print "No commits in range" banner, write zero-row CSV with just headers when `--output csv`, exit 0 | AC17 |
| **`--branch` on the base branch itself** (e.g. on `main` with `--base main`) | merge-base = HEAD → empty rev-range. Same handling as no-commits case. | AC17 |
| **Rename rows** (`git log --numstat` emits `R100\told\tnew` or `rename` lines depending on format) | With the chosen `--no-renames` flag NOT set: numstat emits the rename as separate add+delete entries with `added`/`deleted` counts of moved bytes. Default behavior keeps rename rows AS-IS (additive count). Documented in `git_log_parser.py` docstring. | AC18 |
| **Submodule paths** (e.g. running over Lupin with `src/cosa/` as a submodule) | `git log --numstat` on the parent does NOT descend into submodules by default. Submodule commits won't appear. Documented limitation. | (none — accept) |
| **Timezone for `--today`** | `--since "today 00:00"` uses git's interpretation, which respects local TZ. Documented in `--today` flag help. | (none — accept) |
| **Author filter as exact-match** | `--author EMAIL` is passed through to `git log --author=<value>` which matches as substring/regex. Document this in `--author` help. | (none — accept) |

### Design decisions

1. **Plot is additive (combines with `--output`)** not exclusive — `--branch --output csv --plot` produces all three artifacts in one pass. `--output console --plot` also works (console + plot but no CSV).
2. **Multi-day required** — `--today` single-day mode emits a stderr warning and skips plot generation (no time axis to plot).
3. **Library-shape plotter** with `group_by` parameter — bottom panel groups by `file_type` (default, per-branch use) or `repo` (forthcoming global aggregator use). María's `run_git_loc_delta_global` can call `plot_summary(global_daily, ..., group_by="repo")` directly without reimplementation.
4. **Library shape > CLI shape for rendering** — plotter takes pre-aggregated dicts (not CSV paths) so the global aggregator can build an equivalent `daily` dict from concat'd CSVs and reuse the same rendering.
5. **Schema v2 columns** (`repo`, `branch`) — explicit > filename-parsing heuristics for the global aggregator's `pd.concat + groupby(date)` flow.
6. **Sidecar JSON** instead of denormalized per-row metadata — `commit_sha_range` per row would waste bytes; sidecar keeps run metadata immutable + co-located.
7. **`csv_schema_version` integer in sidecar** — Maria's ask, accepted as structurally important for future schema bumps without column-presence inspection.
8. **No derived-state in sidecar** — declined to bake `total_added` / `csv_row_count` etc.: versioned-derived-state is a stale-bit hazard; aggregators compute totals from CSV in microseconds.
