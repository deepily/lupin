```python
# LanceDBSolutionManager now has:
def _resolve_db_path(self, config: Dict[str, Any]) -> str:
    """
    Resolves database path based on storage_backend config.

    Returns:
        - Local: /full/absolute/path/to/lupin.lancedb
        - GCS: gs://bucket-name/path/lupin.lancedb
    """
    backend = config.get("storage_backend", "local")

    if backend == "gcs":
        # Validate gs:// prefix, return GCS URI
        gcs_uri = config.get("gcs_uri")
        # ... validation logic
        return gcs_uri

    elif backend == "local":
        # Apply project root prefix, validate exists
        db_path = config.get("db_path")
        full_path = get_project_root() + db_path
        # ... validation logic
        return full_path
```

## Key Decisions Made

### Architecture Decisions
1. **Smart path detection in existing manager** (not separate GCS manager class)
   - Simpler, less code duplication
   - LanceDB handles both backends natively

2. **Explicit config key for backend selection** (`storage_backend=gcs|local`)
   - Clear and predictable
   - Works with existing config block pattern

3. **Path format detection as failsafe** (auto-detect `gs://` prefix)
   - Extra safety layer
   - Prevents misconfiguration errors

4. **Real GCS test bucket for integration tests**
   - Catches real-world issues mocks can't
   - Validates credentials and permissions

5. **Automated migration tooling with manual validation**
   - Backup script (local → GCS)
   - Restore script (GCS → local)
   - Migration utility (direct copy)
   - Warm-up routine (reduce cold-start latency)

### Configuration Decisions
1. **Production uses GCS, Development uses local**
2. **Testing has both options** (`[Lupin: Testing]` local, `[Lupin: Testing-GCS]` GCS)
3. **Warm-up enabled in Production only** (not needed for local filesystem)
4. **Backend defaults to "local"** if not specified (backward compatibility)
