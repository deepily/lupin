# Sender-Aware Notification System Implementation Plan

**Project**: Lupin (with COSA backend changes)
**Date**: 2025.12.29
**Prefix**: [LUPIN]
**Status**: Design Complete - Ready for Implementation

---

## Overview

Add sender identification to the notification system to enable:
- Grouping notifications by Claude Code project (LUPIN, COSA, PLAN, etc.)
- Chat-style UI with collapsible sender cards
- User responses displayed as outgoing messages
- Conversation history persistence across page reloads
- Multi-terminal workflow support

### Sender ID Format
```
claude.code@{project}.deepily.ai
```
Examples: `claude.code@lupin.deepily.ai`, `claude.code@cosa.deepily.ai`

### Hybrid Detection Strategy
1. If explicit `--sender-id` provided → use directly
2. If not → extract from `[PREFIX]` in message → construct email
3. Fallback → `claude.code@unknown.deepily.ai`

---

## Key Architectural Decisions

### 1. Persist ALL Notifications to PostgreSQL
- Fire-and-forget (async) notifications now also saved to PostgreSQL (NOT SQLite)
- Aligns with project's PostgreSQL migration strategy (auth tables already in PostgreSQL)
- Add `notifications` table to existing PostgreSQL schema
- Create `NotificationRepository` following existing repository pattern
- Enables full conversation history across page reloads

### 2. Activity-Anchored Window Loading
Load conversations relative to each sender's **last activity**, not current time:

```
LUPIN last activity: Friday 3pm
Window: 24 hours  →  Loads: Thu 3pm - Fri 3pm (even if today is Monday)
```

### 3. User-Configurable History Window
Dropdown control: `[Last 24h] [Last 2 days] [Last week] [Last month] [All]`
- Global setting applies to all sender cards
- Persisted in localStorage

### 4. Chat-Style Message Display
- Incoming notifications: left-aligned with ←
- User responses: right-aligned with → (for sync notifications)
- Chronological order within each sender card (oldest first)

```python
def extract_sender_from_message( message: str ) -> Optional[str]:
    """[LUPIN] msg -> claude.code@lupin.deepily.ai"""
    import re
    match = re.match( r'^\[([A-Z]+)\]', message )
    if match:
        project = match.group( 1 ).lower()
        return f"claude.code@{project}.deepily.ai"
    return None
```

2. Add `sender_id` field to `AsyncNotificationRequest` and `NotificationRequest`:

## Phase 4: Database - PostgreSQL + SQLAlchemy

### NEW Files to Create

**`cosa/rest/db/postgres_notification_model.py`** (SQLAlchemy ORM model)

```python
from sqlalchemy import Column, String, Text, Integer, Boolean, DateTime, ForeignKey
from sqlalchemy.dialects.postgresql import UUID, JSONB
from sqlalchemy.orm import relationship
from cosa.rest.db.database import Base
import uuid

class Notification( Base ):
    """SQLAlchemy ORM model for notifications table."""
    __tablename__ = "notifications"

    # Identity
    id               = Column( UUID(as_uuid=True), primary_key=True, default=uuid.uuid4 )

    # Routing - sender_id is the key field for grouping
    sender_id        = Column( String(255), nullable=False, index=True )  # claude.code@lupin.deepily.ai
    recipient_id     = Column( UUID(as_uuid=True), ForeignKey('users.id'), nullable=False, index=True )

    # Content
    title            = Column( String(255), nullable=False )
    message          = Column( Text, nullable=False )
    type             = Column( String(50), nullable=False )  # task, progress, alert, custom
    priority         = Column( String(50), nullable=False )  # urgent, high, medium, low

    # Timestamps
    created_at       = Column( DateTime(timezone=True), nullable=False )
    delivered_at     = Column( DateTime(timezone=True) )
    responded_at     = Column( DateTime(timezone=True) )
    expires_at       = Column( DateTime(timezone=True) )

    # Response handling
    response_requested = Column( Boolean, default=False )
    response_type      = Column( String(50) )  # yes_no, open_ended
    response_value     = Column( JSONB )       # Flexible response storage
    response_default   = Column( String(255) )
    timeout_seconds    = Column( Integer )

    # State machine
    state            = Column( String(50), nullable=False, default='created', index=True )

    # Relationship to User
    recipient        = relationship( "User", back_populates="notifications" )
```

**`cosa/rest/db/repositories/notification_repository.py`** (Repository pattern)

```python
class NotificationRepository:
    """Repository for notification CRUD operations following existing pattern."""

    def __init__( self, session ):
        self.session = session

    def create( self, notification: Notification ) -> Notification:
        """Create a new notification."""

    def get_by_id( self, notification_id: UUID ) -> Optional[Notification]:
        """Get notification by ID."""

    def get_sender_last_activities( self, recipient_id: UUID ) -> List[Dict]:
        """Get last activity timestamp per sender (for activity-anchored loading)."""

    def get_sender_conversation(
        self,
        sender_id: str,
        recipient_id: UUID,
        anchor: datetime,
        window_hours: int = 24
    ) -> List[Notification]:
        """Load conversation window relative to anchor."""

    def update_state( self, notification_id: UUID, new_state: str ) -> bool:
        """Update notification state."""

    def update_response( self, notification_id: UUID, response_value: dict ) -> bool:
        """Record user response."""
```

**`src/scripts/sql/notifications_schema.sql`** (Raw SQL for schema.sql addition)

```sql
-- Notifications table for sender-aware notification system
CREATE TABLE IF NOT EXISTS notifications (
    id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    sender_id           VARCHAR(255) NOT NULL,
    recipient_id        UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    title               VARCHAR(255) NOT NULL,
    message             TEXT NOT NULL,
    type                VARCHAR(50) NOT NULL,
    priority            VARCHAR(50) NOT NULL,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    delivered_at        TIMESTAMPTZ,
    responded_at        TIMESTAMPTZ,
    expires_at          TIMESTAMPTZ,
    response_requested  BOOLEAN DEFAULT FALSE,
    response_type       VARCHAR(50),
    response_value      JSONB,
    response_default    VARCHAR(255),
    timeout_seconds     INTEGER,
    state               VARCHAR(50) NOT NULL DEFAULT 'created'
);

-- Indexes for efficient querying
CREATE INDEX idx_notifications_sender_id ON notifications(sender_id);
CREATE INDEX idx_notifications_recipient_id ON notifications(recipient_id);
CREATE INDEX idx_notifications_state ON notifications(state);
CREATE INDEX idx_notifications_created_at ON notifications(created_at DESC);
CREATE INDEX idx_notifications_sender_recipient ON notifications(sender_id, recipient_id);
```
