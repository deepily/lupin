### Hypothesis 2: Separate Manager Instances

**Theory**: Admin creates NEW manager per request instead of using global singleton

**Data Flow**:

**Runtime Path** (Math Agent):
```
main.py:432 → Global snapshot_mgr created at startup
           ↓
RunningFifoQueue → Uses global manager
           ↓
add_snapshot() → Writes to DB + updates IN-MEMORY cache
```

**Admin Path**:
```
admin.py:486-498 → Creates NEW manager instance per request
           ↓
manager.initialize() → Loads from DB into NEW cache
           ↓
get_snapshot_by_id() → Reads from DB (bypasses cache)
           ↓
Returns stale data
```

**Alternative Solution** (NOT YET IMPLEMENTED):
- Share the global `snapshot_mgr` from main.py with admin router
- Eliminates fresh cache = stale data problem

## Architecture Notes

### DELETE Cache Key Bug (RESOLVED)

**Problem**: Cache stored verbatim questions but delete_snapshot normalized with `.lower()`

**Example**:
- Cache key: `"What's 2 + 2?"`
- Delete lookup: `"what's 2 + 2?"` (lowercased)
- Result: Key not found → return False → 500 error

**Fix**: Remove normalization, use verbatim for both cache storage and lookup

**Debug Output** (now visible with app_debug=true):
```
[DELETE-DEBUG] Looking up question: 'What's 2 + 2?'
[DELETE-DEBUG] Cache size: 1 questions
[DELETE-DEBUG] First 3 cache keys: ["What's 2 + 2?"]
[DELETE-DEBUG] Exact match found? True
```
