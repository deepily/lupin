**Sort Order Bug Resolution** (Session 24):
- **Root Cause**: Complex chain of transformations (DB DESC → JS `.reverse()` → CSS `column-reverse` → `appendChild`) cancelled each other out incorrectly for real-time vs initial load scenarios
- **Fix**: 4 coordinated changes:
  1. CSS `queue-fresh.css:793` - Changed `flex-direction: column-reverse` → `column`
  2. JS `queue-fresh.js:4169` - Removed `.reverse()` call
  3. JS `queue-fresh.js:3449` - Changed `appendChild` → `insertBefore(messageDiv, container.firstChild)`
  4. Python `notification_repository.py:220` - Changed `.desc()` → `.asc()`
- **How it works now**: Database returns oldest→newest (ASC), JS iterates with `insertBefore` prepending each message, newest ends up at top for both initial page load AND real-time WebSocket notifications

## Issues & Blockers

### Sort Order Display Bug (Session 23) - ✅ RESOLVED in Session 24
**Status**: ✅ RESOLVED
**Problem**: Notifications displayed oldest-first instead of newest-first.

**Root Cause**: Complex transformation chain (DB DESC → JS `.reverse()` → CSS `column-reverse` → `appendChild`) cancelled each other out incorrectly. Initial load and real-time had different behaviors, masking the bug.

**Resolution** (Session 24):
1. CSS: `flex-direction: column-reverse` → `column`
2. JS: Removed `.reverse()` call
3. JS: `appendChild` → `insertBefore(messageDiv, container.firstChild)`
4. Python: `.desc()` → `.asc()` in database query

**New Flow**: Database returns oldest→newest (ASC), JS prepends each message via `insertBefore`, result is newest at top for both initial load AND real-time notifications.
