## Track 1: Cloud Run Deployment (Priority)

### Phase 1.1: GCP Infrastructure Setup (30-60 minutes)

**Prerequisites**:
- [ ] GCP project exists and billing enabled
- [ ] gcloud CLI installed and configured (`gcloud auth login`)
- [ ] User has necessary IAM permissions (Cloud Run Admin, Secret Manager Admin)

**Tasks**:
- [ ] **Create GCP Secret for API Key**:
  ```bash
  # Read API key from local file
  cat src/conf/keys/notification-api-claude-code-dev

  # Create secret in GCP
  gcloud secrets create lupin-notification-api-key \
    --data-file=src/conf/keys/notification-api-claude-code-dev \
    --replication-policy="automatic"

  # Grant Cloud Run service account access
  gcloud secrets add-iam-policy-binding lupin-notification-api-key \
    --member="serviceAccount:PROJECT_NUMBER-compute@developer.gserviceaccount.com" \
    --role="roles/secretmanager.secretAccessor"
  ```

- [ ] **Verify secret created**:
  ```bash
  gcloud secrets describe lupin-notification-api-key
  gcloud secrets versions access latest --secret="lupin-notification-api-key"
  ```

- [ ] **Update ~/.notifications/config for production**:
  ```ini
  [production]
  global_notification_recipient = ricardo.felipe.ruiz@gmail.com
  api_key_file = /secrets/notification-api-key  # Cloud Run mount point
  api_url = https://lupin-XXXXX-uc.a.run.app  # Will be filled after first deployment
  ```

**Completion Criteria**: Secret exists in GCP, IAM policy set, local config updated

### Phase 1.2: Docker Build & Configuration (30-45 minutes)

**Tasks**:
- [ ] **Review/update Dockerfile** (should already exist at `docker/lupin/Dockerfile`):
  - Verify LUPIN_ROOT environment variable set
  - Verify entry point configured correctly
  - Add secret mount point: `/secrets/notification-api-key`
  - Verify port 7999 exposed

- [ ] **Build Docker image**:
  ```bash
  # From project root
  docker build -f docker/lupin/Dockerfile -t gcr.io/PROJECT_ID/lupin:latest .
  ```

- [ ] **Test Docker image locally** (optional but recommended):
  ```bash
  docker run -p 7999:7999 \
    -e LUPIN_ROOT=/app \
    -v $(pwd)/src/conf/keys:/app/src/conf/keys:ro \
    gcr.io/PROJECT_ID/lupin:latest

  # In another terminal, test health endpoint
  curl http://localhost:7999/health
  ```

- [ ] **Push to Google Container Registry**:
  ```bash
  docker push gcr.io/PROJECT_ID/lupin:latest
  ```

**Completion Criteria**: Docker image built, tested locally, pushed to GCR

### Phase 1.3: Cloud Run Deployment (30-45 minutes)

**Tasks**:
- [ ] **Deploy to Cloud Run with secret mounting**:
  ```bash
  gcloud run deploy lupin \
    --image gcr.io/PROJECT_ID/lupin:latest \
    --platform managed \
    --region us-central1 \
    --allow-unauthenticated \
    --port 7999 \
    --memory 2Gi \
    --cpu 1 \
    --timeout 300 \
    --set-secrets="/secrets/notification-api-key=lupin-notification-api-key:latest" \
    --set-env-vars="LUPIN_ROOT=/app,LUPIN_ENV=production"
  ```

- [ ] **Note the deployed URL** (will be in output):
  ```
  Service URL: https://lupin-XXXXX-uc.a.run.app
  ```

- [ ] **Update ~/.notifications/config with real URL**:
  ```ini
  [production]
  api_url = https://lupin-XXXXX-uc.a.run.app
  ```

- [ ] **Verify deployment health**:
  ```bash
  curl https://lupin-XXXXX-uc.a.run.app/health
  ```

**Completion Criteria**: Service deployed, URL obtained, health check passing

### Phase 1.4: Production Validation (30-45 minutes)

**End-to-End Testing**:

  ```bash
  curl -X POST https://lupin-XXXXX-uc.a.run.app/auth/register \
    -H "Content-Type: application/json" \
    -d '{"email":"test@example.com","password":"SecurePass123!","full_name":"Test User"}'
  ```

  ```bash
    --response_type=yes_no \
    --timeout_seconds=30 \
    --response_default=yes
  ```

- [ ] **Verify WebSocket connections work**:
  - Open Fresh Queue UI: https://lupin-XXXXX-uc.a.run.app/queue-fresh.html

- [ ] **Check Cloud Run logs for errors**:


- [ ] **Verify API key authentication in logs**:
  - Look for: `[API_KEY_AUTH] Authenticated service account: claude.code@deepily.ai`

**Completion Criteria**: All endpoints working, notifications deliver successfully, no auth errors

## Rollback Plan

**If deployment fails during Phase 1.3-1.4**:

1. **Quick rollback**:
   ```bash
   gcloud run services delete lupin --region us-central1
   ```

2. **Investigate logs**:
   ```bash
   gcloud run services logs read lupin --region us-central1 --limit 100
   ```

3. **Common issues and fixes**:
   - Secret not mounted: Check IAM policy on secret
   - Port mismatch: Verify Dockerfile exposes port 7999, Cloud Run --port matches
   - Database path issues: Verify LUPIN_ROOT set correctly
   - API key not found: Verify secret mount path matches config file path

4. **Iterate locally**:
   - Test Docker image locally with production-like config
   - Fix issues
   - Rebuild and redeploy

5. **Documentation continues regardless**: Track 2 can proceed even if Track 1 encounters issues

---

## Risk Mitigation

### Risk 1: Docker build fails
**Mitigation**: Test Dockerfile locally before pushing to GCR
**Impact**: Low - can iterate locally, doesn't block documentation

### Risk 2: Secret mounting doesn't work
**Mitigation**: Test IAM permissions early, verify secret accessor role set
**Impact**: Medium - blocks deployment validation, doesn't block docs
**Rollback**: Can revert to local testing while troubleshooting

### Risk 3: Production API key doesn't work
**Mitigation**: Validate API key locally first, check bcrypt hash in database
**Impact**: Medium - blocks notification testing
**Rollback**: Can test other endpoints (auth, queue) while fixing key

### Risk 4: WebSocket connections fail in Cloud Run
**Mitigation**: Check Cloud Run WebSocket support (timeout settings), verify SSL termination
**Impact**: Medium - blocks real-time features
**Rollback**: Can test REST endpoints, investigate WS config separately

### Risk 5: Documentation takes longer than estimated
**Mitigation**: Prioritize critical docs (README, API, CONFIGURATION), defer medium-priority
**Impact**: Low - doesn't block deployment
**Solution**: Continue docs work after deployment validated
