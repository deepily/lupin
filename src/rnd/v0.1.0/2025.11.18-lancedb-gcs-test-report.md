#### Root Cause Analysis

**Query/Retrieval Failures (Tests 1, 2, 4)**:

Three possible causes:
1. **GCS Consistency Delays**: 2-second delays may be insufficient for GCS data visibility
2. **Embedding Mismatch**: Insert and query using different embeddings/normalizations
3. **Index Building**: LanceDB may need time to build search indexes

**Evidence from Logs**:
```
Inserting new snapshot for: how do i use pythons fstrings
  ✓ Inserted new snapshot with id_hash: 7c529671...
Exact verbatim search: 'How do I use Python's f-strings?'
Exact verbatim search: 'How do I use Python's f-strings?' No match found in 7 ms
...
LEVEL 4: No exact matches found, falling back to similarity search...
Performing similarity search for: How do I use Python's f-strings?
Found 0 similar snapshots
```

**Observation**: The snapshot was inserted with normalized question "how do i use pythons fstrings" (no apostrophe), but query searched for "How do I use Python's f-strings?" (with apostrophe). Normalization appears to remove special characters during insert but query is using different normalization.

**Configuration Loading Failure (Test 3)**:

**Cause**: ConfigurationManager uses singleton pattern. Once initialized with one config block, subsequent initializations reuse the same instance.

**Solution**: Tests need to either:
- Reset singleton between tests
- Use separate environment variable names
- Accept that config loading test requires isolated process

## UPDATE: Root Cause Fixed - 100% Pass Rate Achieved

**Date**: 2025-11-18 (same session)
**Status**: ✅ **ALL TESTS PASSING**

### Root Cause Identified

The 50% test failure rate was caused by **normalization inconsistency**:

1. **SolutionSnapshot.__init__()** used deprecated `remove_non_alphanumerics()` method
2. **LanceDBSolutionManager.get_snapshots_by_question()** used `Normalizer.normalize()`
3. **Different normalization algorithms** produced different results for same input
4. **Cache lookup** checked un-normalized questions against normalized cache keys

**Example of the bug:**
```
Insert path: "How do I use Python's f-strings?" 
  → remove_non_alphanumerics() 
  → "how do i use pythons fstrings" (apostrophe removed)
  → Stored in cache

Query path: "How do I use Python's f-strings?"
  → Normalizer.normalize() 
  → "how do i use python 's f string" (apostrophe → space + 's)
  → Lookup in cache → NO MATCH ✗
```

### Fix Implementation

**Files Modified (4):**

1. **solution_snapshot.py** - Use Normalizer in __init__()
2. **solution_snapshot_mgr.py** - Replace remove_non_alphanumerics() with Normalizer
3. **file_based_solution_manager.py** - Replace remove_non_alphanumerics() with Normalizer
4. **lancedb_solution_manager.py** - Normalize question before cache lookup

**Key Changes:**
- Line 201: `self.question = self._normalizer.normalize( question )`
- Line 973-977: Normalize question before cache lookup
- Marked `remove_non_alphanumerics()` as DEPRECATED
