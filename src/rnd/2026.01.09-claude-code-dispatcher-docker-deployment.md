## Background

The Claude Code Dispatcher provides a UI card in the Notifications interface that allows users to:
- Select a project (lupin, cosa, plan)
- Enter a task prompt
- Choose between Option A (Bounded) or Option B (Interactive) execution
- View streaming responses in real-time
- Use MCP voice tools for interactive clarification

## Issues Fixed (Session 49)

### Issue 1: Wrong Output Format ✅ FIXED

**Problem**: Used `--output-format json` which only outputs a single final result after task completion.

**Solution**: Changed to `--output-format stream-json` for realtime streaming.

```python
# Before
"--output-format", "json",

# After
"--output-format", "stream-json",
```

**File**: `dispatcher.py` line 263

---

### Issue 2: Synchronous Subprocess ✅ FIXED

**Problem**: Used `subprocess.run()` which blocks until the entire Claude Code CLI process completes, preventing streaming.

**Solution**: Changed to `asyncio.create_subprocess_exec()` with line-by-line async reading.

```python
# Before
result = subprocess.run( cmd, capture_output=True, text=True, timeout=... )

# After
process = await asyncio.create_subprocess_exec(
    *cmd,
    stdout=asyncio.subprocess.PIPE,
    stderr=asyncio.subprocess.PIPE,
    ...
)
async for line in process.stdout:
    # Stream each line to WebSocket
    self.on_message( task.id, json.loads( line ) )
```

**File**: `dispatcher.py` lines 270-350

---

### Issue 3: Background Task Not Starting ✅ FIXED

**Problem**: Used `background_tasks.add_task()` which doesn't properly await async functions.

**Solution**: Changed to `asyncio.create_task()` for proper async scheduling.

```python
# Before
background_tasks.add_task( _run_dispatch, task_id )

# After
asyncio.create_task( _run_dispatch( task_id ) )
```

**File**: `claude_code.py` line 123

This is an environment/deployment issue, not a code issue.

## Deployment Options Trade-Off Matrix

| Option | Pros | Cons |
|--------|------|------|
| **1. Install Claude CLI in Docker** | Works in production | Complex setup: Node.js, npm, auth, MCP config, persistent ~/.claude/ |
| **2. Run FastAPI locally** | Simple, CLI already works | Not production-ready, can't test Docker deployment |
| **3. Use Anthropic SDK directly** | Works anywhere, no CLI needed | Loses MCP server integration (no voice tools) |
| **4. Hybrid: API proxy** | Docker calls local Claude instance | Complex architecture, needs network setup |

---

## Option Analysis

### Option 1: Install Claude CLI in Docker (Recommended for Production)

**What's Required**:
1. Node.js 20+ installed in container
2. Claude Code CLI installed globally via npm
3. Anthropic API key configured
4. MCP server configuration with correct container paths
5. Persistent storage for `~/.claude/` directory

**Dockerfile Changes**:
```dockerfile
# Install Node.js 20.x
RUN curl -fsSL https://deb.nodesource.com/setup_20.x | bash - \
    && apt-get install -y nodejs

# Install Claude Code CLI globally
RUN npm install -g @anthropic-ai/claude-code

# Create claude config directory
RUN mkdir -p /root/.claude

# Copy API key (or use environment variable)
# Option A: Copy file
COPY .claude/credentials.json /root/.claude/

# Option B: Use build arg
ARG ANTHROPIC_API_KEY
ENV ANTHROPIC_API_KEY=${ANTHROPIC_API_KEY}
```

**MCP Configuration Adjustment**:
The MCP config path needs to point to container paths:
```json
{
  "cosa-voice": {
    "command": "python",
    "args": ["/var/lupin/src/lupin_mcp/cosa_voice_mcp.py"],
    "env": {
      "LUPIN_ROOT": "/var/lupin",
      "LUPIN_APP_SERVER_URL": "http://localhost:7999"
    }
  }
}
```

**Pros**:
- Full feature parity with local development
- MCP voice tools work correctly
- Mirrors production deployment
- Can test end-to-end in Docker

**Cons**:
- Increases Docker image size (~200MB for Node.js)
- API key management complexity
- Need to handle Claude CLI updates
- MCP server paths need container adjustment

### Option 2: Run FastAPI Locally (Current Workaround)

**How It Works**:
- FastAPI runs on local filesystem where `claude` CLI is available
- PostgreSQL stays in Docker with port 5432 exposed
- Local FastAPI connects to Docker PostgreSQL

**Commands**:
```bash
# Ensure PostgreSQL Docker is running
docker-compose up -d postgres

# Run FastAPI locally
cd /mnt/DATA01/include/www.deepily.ai/projects/lupin
source src/cosa/.venv/bin/activate
PYTHONPATH="$PWD/src:$PYTHONPATH" LUPIN_ROOT="$PWD" python src/fastapi_app/main.py
```

**Database Connection**:
PostgreSQL in Docker exposes port 5432 to host - local FastAPI can connect at `localhost:5432`.

**Pros**:
- Works immediately, no setup needed
- Full feature testing possible
- Good for development iteration

**Cons**:
- Not representative of production
- Can't test Docker-specific issues
- Manual process, not automated

---

### Option 3: Use Anthropic SDK Directly

**How It Would Work**:
- Replace Claude CLI subprocess with direct Anthropic Python SDK calls
- Use `anthropic.Anthropic().messages.create()` with streaming
- Implement tool use manually

**Code Pattern**:
```python
from anthropic import Anthropic

client = Anthropic()

with client.messages.stream(
    model="claude-sonnet-4-20250514",
    max_tokens=4096,
    messages=[{"role": "user", "content": task.prompt}]
) as stream:
    for text in stream.text_stream:
        self.on_message( task.id, {"type": "text", "content": text} )
```

**Pros**:
- No CLI installation needed
- Works in any Python environment
- Simpler deployment

**Cons**:
- **Loses MCP server integration entirely**
- No voice tools (converse, notify, ask_yes_no)
- Would need to reimplement tool calling
- Different behavior than Claude Code CLI

---

### Option 4: Hybrid API Proxy

**How It Would Work**:
- Docker container exposes an endpoint that proxies to local Claude CLI
- Local "Claude proxy service" runs outside Docker
- Docker FastAPI calls the proxy for Claude operations

**Architecture**:
```
[Docker FastAPI] --HTTP--> [Local Claude Proxy] --subprocess--> [Claude CLI]
```

**Pros**:
- Docker deployment works
- CLI features preserved
- Separation of concerns

**Cons**:
- Complex multi-service architecture
- Network configuration needed
- Additional service to manage
- Latency overhead

---

## Recommendation

**For the Claude Code Dispatcher feature specifically, Option 1 (Install CLI in Docker) is the right long-term solution because:**

1. **Feature purpose**: The whole point is to dispatch Claude Code tasks
2. **MCP integration**: Voice tools require the CLI's MCP support
3. **Production parity**: Mirrors how it will run in production
4. **Testing fidelity**: Can test the exact deployment configuration

**Short-term**: Use Option 2 (Run FastAPI locally) for immediate testing and development iteration.

**Medium-term**: Implement Option 1 (Docker CLI installation) when ready for staging/production deployment.
