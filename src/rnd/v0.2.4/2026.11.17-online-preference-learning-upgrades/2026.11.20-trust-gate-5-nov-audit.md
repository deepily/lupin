# Audit of the 43 organic proxy_decisions rows of 5 Nov 2026

Phase 12 of the remediation plan asks for a read-only audit of the 43 organic rows of 5 Nov, with its output saved.
Run by Clayton on 20 Nov 2026 at about 13:35 EDT, against the dev database `lupin_db_dev` through `docker exec lupin-postgres psql`.
Every query ran inside `BEGIN TRANSACTION ISOLATION LEVEL REPEATABLE READ READ ONLY`, so none could write.

## What the audit found

| Finding | Count | Measured how |
|---|---|---|
| Organic rows created on 5 Nov (UTC day and New York day agree) | 43 | first query |
| Organic rows in the whole table, all of them on 5 Nov | 43 | by-day query |
| Rows with action `shadow` | 42 | by action |
| Rows with action `act` | 1 | by action |
| Rows with a stored forecast (`decision_value`) | 1 (the act row, "approved") | by decision_value |
| Rows whose stored human answer is true / false / absent | 33 / 9 / 1 | `metadata_json.user_answer` |
| Rows whose `notification_id` joins to a row of `notifications` | 0 of 43 | left join on `n.id::text = p.notification_id` |
| Distinct questions / distinct jobs | 4 / 1 | distinct counts |
| Rows in each ratification state | 43 `not_required` | by state |

Three readings follow from those counts, and each is a measured fact and not an inference about intent.

1. **A shadow row stores no forecast.** `log_shadow` hard-codes `decision_value = NULL`, so 42 of the 43 rows cannot show what the proxy forecast.
   The trust scoring does not read the stored row: it reads the forecast the proxy returned in memory, and a human approval of an "approved" forecast scores as success.
   The plan names `decision_value` as the shadow forecast, but for shadow rows nothing is stored there. Whether to store it is a question for Mr. Radio, and this phase does not change it.
2. **The one act row has no human answer.** It is the auto-approved "should we run the unit tests?" row at trust level 1, confidence 0.8, with `user_answer` absent. The orchestrator gives it no trust feedback.
3. **The human response cannot be joined.** The orchestrator mints a new UUID for each `notification_id`, and none of the 43 exists in `notifications`.
   So "joined by `notification_id`, never copied" holds for the design and not yet for these rows. The answer lives in `metadata_json.user_answer`.

The new `rule_agreement` column is NULL on every one of these 43 rows: 42 are shadow rows and one is unanswered.

## The queries

The three scripts below were piped to `psql -X -v ON_ERROR_STOP=1 -U lupin_dev -d lupin_db_dev`, in this order. Each selects only, inside a read-only transaction.
In the third script, the `\echo` line above the confidence query holds an unbalanced apostrophe, so psql printed `unterminated quoted string` in place of that heading. The select below it ran and printed its table, which is where the confidence and trust level readings come from.

### Script audit.sql

```sql
BEGIN TRANSACTION ISOLATION LEVEL REPEATABLE READ READ ONLY;
\echo == window: organic rows created on 2026-11-05 (UTC day) ==
SELECT count(*) AS organic_rows, min(created_at) AS first_at, max(created_at) AS last_at FROM proxy_decisions WHERE data_origin='organic' AND created_at >= '2026-11-05' AND created_at < '2026-11-06';
\echo == same window by America/New_York day ==
SELECT count(*) AS organic_rows_ny_day FROM proxy_decisions WHERE data_origin='organic' AND (created_at AT TIME ZONE 'America/New_York')::date = '2026-11-05';
\echo == all organic rows, by day ==
SELECT (created_at AT TIME ZONE 'America/New_York')::date AS day_ny, count(*) FROM proxy_decisions WHERE data_origin='organic' GROUP BY 1 ORDER BY 1;
```

### Script audit2.sql

```sql
BEGIN TRANSACTION ISOLATION LEVEL REPEATABLE READ READ ONLY;
\echo == by action ==
SELECT action, count(*) FROM proxy_decisions WHERE data_origin='organic' AND created_at>='2026-11-05' AND created_at<'2026-11-06' GROUP BY 1 ORDER BY 1;
\echo == by decision_value (the shadow or proxy forecast) ==
SELECT coalesce(decision_value,'<null>') AS decision_value, count(*) FROM proxy_decisions WHERE data_origin='organic' AND created_at>='2026-11-05' AND created_at<'2026-11-06' GROUP BY 1 ORDER BY 1;
\echo == by user_answer stored in metadata_json ==
SELECT coalesce(metadata_json->>'user_answer','<absent or null>') AS user_answer, count(*) FROM proxy_decisions WHERE data_origin='organic' AND created_at>='2026-11-05' AND created_at<'2026-11-06' GROUP BY 1 ORDER BY 1;
\echo == by ratification_state ==
SELECT ratification_state, count(*) FROM proxy_decisions WHERE data_origin='organic' AND created_at>='2026-11-05' AND created_at<'2026-11-06' GROUP BY 1 ORDER BY 1;
\echo == by domain and category ==
SELECT domain, category, count(*) FROM proxy_decisions WHERE data_origin='organic' AND created_at>='2026-11-05' AND created_at<'2026-11-06' GROUP BY 1,2 ORDER BY 3 DESC,1,2;
\echo == forecast against human answer (decision_value vs user_answer) ==
SELECT coalesce(decision_value,'<null>') AS decision_value, coalesce(metadata_json->>'user_answer','<none>') AS user_answer, count(*) FROM proxy_decisions WHERE data_origin='organic' AND created_at>='2026-11-05' AND created_at<'2026-11-06' GROUP BY 1,2 ORDER BY 1,2;
\echo == does a notification row exist for these notification_ids (join by notification_id) ==
SELECT count(*) AS rows, count(n.id) AS with_notification FROM proxy_decisions p LEFT JOIN notifications n ON n.id::text = p.notification_id WHERE p.data_origin='organic' AND p.created_at>='2026-11-05' AND p.created_at<'2026-11-06';
\echo == distinct questions ==
SELECT count(DISTINCT question) AS distinct_questions, count(DISTINCT metadata_json->>'job_id') AS distinct_jobs FROM proxy_decisions WHERE data_origin='organic' AND created_at>='2026-11-05' AND created_at<'2026-11-06';
COMMIT;
```

### Script audit3.sql

```sql
BEGIN TRANSACTION ISOLATION LEVEL REPEATABLE READ READ ONLY;
\echo == the four distinct questions, with action and answers ==
SELECT left(question,70) AS question_start, action, count(*) AS rows, count(*) FILTER (WHERE metadata_json->>'user_answer'='true') AS answered_true, count(*) FILTER (WHERE metadata_json->>'user_answer'='false') AS answered_false, count(*) FILTER (WHERE metadata_json->>'user_answer' IS NULL) AS unanswered FROM proxy_decisions WHERE data_origin='organic' AND created_at>='2026-11-05' AND created_at<'2026-11-06' GROUP BY 1,2 ORDER BY 3 DESC;
\echo == the same rows' confidence and trust_level ==
SELECT action, min(confidence) AS min_conf, max(confidence) AS max_conf, min(trust_level) AS min_level, max(trust_level) AS max_level FROM proxy_decisions WHERE data_origin='organic' AND created_at>='2026-11-05' AND created_at<'2026-11-06' GROUP BY 1;
\echo == all rows of the table by data_origin (population check) ==
SELECT data_origin, count(*) FROM proxy_decisions GROUP BY 1 ORDER BY 1;
COMMIT;
```

## What this does not show

- It reads the dev database only. The test database `:8000` was not queried.
- It counts the rows as stored. It does not say whether the 33 approvals were right.
- The one question "should we run the unit tests?" appears twice as shadow and once as act, so the same question took two dispositions.
