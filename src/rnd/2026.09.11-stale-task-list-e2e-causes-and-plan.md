## Fix plan

1. **A — both halves.** (i) The route handlers answer the holding-area query with holding rows only (empty by
   default), keyed on the query parameter the shared query module actually sends. Read it from the module before
   writing the handler, and assert in the handler that exactly two query shapes arrive. Scoping alone would hide
   the wrong half instead of removing it. (ii) Every locator in these files is scoped to the pane the test means
   (`multiplexer-task-list-container` / `#task-list-container`), because the Epic Board showing the same row is
   correct and permanent.
2. **B — one helper, `disclose_row( page, container, task_id )`**, in the e2e helpers: clicks
   `.task-disclose-button[data-task-id=…]`, waits for `tr[data-controls-for=…]` to lose `hidden`, and returns that
   controls row. Every B test locates its control inside the returned row. The order tests read the row's columns
   from line 1 and the controls row's disclosed fields from lines 2–3, pinned to literals copied from `ROW_SCHEMA`
   with a comment naming it. A TS unit test already pins the schema itself, so the E2E checks the DOM follows it.
   `test_actions_column_and_controls_render` becomes "the disclosed row carries the verb, priority and owner controls".
3. **C** — the order assertion becomes task list → holding area → epic board, read from `notifications.html` as a
   literal list.
4. **D** — the counter counts board queries only (the handler already sees the query string), and the test adds a
   second counter asserting exactly one holding-area query per tick, so "one clock, two fetches" is pinned rather
   than excused.
5. **E** — the live test asserts the window in the form the page renders it, computed by the page's own
   `_flowRatioWindowDays( window_hours )` from the live payload. The test's job is "the payload reached the DOM";
   the wording stays pinned in the mocked test and the TS tier, as its own comment says.

**Proof it discriminates**: before the fixes, the 27 fail on the causes above (this report). After, each file passes
on `:8000` (scheduled, `-k` on the four files). Mutation arms:

- **A(i) needs its own assertion (María's review).** Once every locator is scoped to its pane, the fake answering
  both queries with the same rows no longer reddens the id-cell tests or the counts — scoping hides it. So the
  fixture gains one test: the holding-area pane renders none of the board fixture's ids, and the handler saw one
  holding-shaped query. The arm that makes the fake answer both queries with the board's rows must redden that
  test, by name.
- `disclose_row` not clicking (B) reddens the B tests.
- The holding counter set to allow two (D) reddens the new assertion.

**Out of scope here, still owed on the row**: the 2px snapshot drift and the full-run e2e budget re-measure.
