# SWE Team UI Bug Fixes + Dry-Run Proxy Decision Generation

## Context

During the first hands-on UI testing of the SWE Team pipeline (Session 251), two categories of issues were discovered:

1. **Proxy admin pages are completely broken** — The Ratification Page and Trust Dashboard JS files are missing the `/api` prefix on all API calls, causing 404 errors. The WebSocket connection also fails due to wrong auth token key and invalid session ID format.

2. **Dry-run produces no proxy decisions** — The dry-run execution path bypasses the orchestrator entirely, so the Ratification Page and Trust Dashboard have nothing to display even after a successful dry-run. The user wants dry-run to generate mock proxy decisions for UI testing.

**Intended outcome**: Both proxy admin pages fully functional, and dry-run jobs produce realistic mock proxy decisions that populate the ratification and trust dashboard UIs.

## Part 1: Fix Proxy Admin Page Bugs (5 bugs across 3 files)

### Bug 1.1: Missing `/api` prefix in proxy-ratify.js

**File**: `src/fastapi_app/static/html/auth/admin/js/proxy-ratify.js`

The `apiCall()` function in `auth.js` (line 77) constructs URLs as `http://localhost:7999${endpoint}` — it does NOT prepend `/api`. The decision proxy router is mounted with prefix `/api/proxy` (see `decision_proxy.py:24`). So all JS calls must include `/api`.

| Line | Current | Fix |
|------|---------|-----|
| 56 | `/proxy/pending/${encodeURIComponent(userEmail)}` | `/api/proxy/pending/${encodeURIComponent(userEmail)}` |
| 94 | `/proxy/ratify/${id}?${params.toString()}` | `/api/proxy/ratify/${id}?${params.toString()}` |

### Bug 1.2: Missing `/api` prefix in proxy-dashboard.js

**File**: `src/fastapi_app/static/html/auth/admin/js/proxy-dashboard.js`

| Line | Current | Fix |
|------|---------|-----|
| 70 | `/proxy/trust/${encodeURIComponent(userEmail)}?domain=swe` | `/api/proxy/trust/${encodeURIComponent(userEmail)}?domain=swe` |
| 107 | `/proxy/decisions/swe/${encodeURIComponent(category)}?limit=${pageLimit}` | `/api/proxy/decisions/swe/${encodeURIComponent(category)}?limit=${pageLimit}` |
| 113 | `/proxy/decisions/swe/${cat.key}?limit=10` | `/api/proxy/decisions/swe/${cat.key}?limit=10` |
| 156 | `/proxy/mode` | `/api/proxy/mode` |
| 200 | `/proxy/mode` | `/api/proxy/mode` |

### Bug 1.3: Wrong localStorage key for WebSocket auth token

**File**: `src/fastapi_app/static/html/auth/admin/js/proxy-ratify.js`

Line 713 uses `localStorage.getItem("auth_token")` but `auth.js` stores the token under `"lupin_access_token"` (see `auth.js:16`).

| Line | Current | Fix |
|------|---------|-----|
| 713 | `localStorage.getItem( "auth_token" )` | `getAccessToken()` |

Use `getAccessToken()` from auth.js (already loaded on the page) for consistency.

### Bug 1.4: Invalid WebSocket session ID fallback format

**File**: `src/fastapi_app/static/html/auth/admin/js/proxy-ratify.js`

Line 706: The fallback `"proxy-ratify-" + Date.now()` produces an invalid session ID. The WebSocket endpoint validates against `adjective noun` format (two lowercase words separated by space).

| Line | Current | Fix |
|------|---------|-----|
| 706 | `localStorage.getItem( "session_id" ) \|\| "proxy-ratify-" + Date.now()` | `"proxy ratify"` (static known-good format) |

Use a simple static "adjective noun" format string. The proxy-ratify page only subscribes to `proxy_decision_new` events, so a dedicated session ID is fine. No need for localStorage lookup.

### Bug 1.5: Wrong ratification link URL in notifications.js

**File**: `src/fastapi_app/static/js/notifications.js`

Line 5272: The "Open Ratification" link in proxy summary notifications uses `/app/proxy-ratify` but the route is `/app/admin/proxy-ratify` (see `pages.py` router).

| Line | Current | Fix |
|------|---------|-----|
| 5272 | `window.open( '/app/proxy-ratify', 'lupin-proxy-ratify' )` | `window.open( '/app/admin/proxy-ratify', 'lupin-proxy-ratify' )` |

## Part 2: Dry-Run Mock Proxy Decision Generation

### Approach: Direct DB Insertion via ProxyDecisionRepository

Add mock `ProxyDecision` records at the end of `_execute_dry_run()` using the existing `ProxyDecisionRepository.log_decision()` method. This is the simplest path that:
- Requires no orchestrator instantiation
- Makes no Claude Agent SDK calls
- Uses existing DB infrastructure
- Produces realistic data for the Ratification and Trust Dashboard pages

### File: `src/cosa/agents/swe_team/job.py`

**Location**: End of `_execute_dry_run()` method, after the completion notification (around line 395), before the return statement.

**Mock decisions to insert** (3 representative categories):

```python
# Insert mock proxy decisions for UI testing
try:
    from cosa.rest.db.database import get_db
    from cosa.rest.db.repositories.proxy_decision_repository import ProxyDecisionRepository

    mock_decisions = [
        {
            "category"       : "testing",
            "question"       : "Run the test suite before merging? (dry-run mock)",
            "decision_value" : "approved",
            "confidence"     : 0.85,
            "trust_level"    : 2,
            "reason"         : "Dry-run mock: testing decisions are low-risk",
        },
        {
            "category"       : "deployment",
            "question"       : "Deploy changes to staging environment? (dry-run mock)",
            "decision_value" : "requires_review",
            "confidence"     : 0.62,
            "trust_level"    : 1,
            "reason"         : "Dry-run mock: deployment requires human review at L1",
        },
        {
            "category"       : "destructive",
            "question"       : "Delete old cache files from build directory? (dry-run mock)",
            "decision_value" : "requires_review",
            "confidence"     : 0.45,
            "trust_level"    : 1,
            "reason"         : "Dry-run mock: destructive ops always require review at L1",
        },
    ]

    with get_db() as db_session:
        repo = ProxyDecisionRepository( db_session )
        for mock in mock_decisions:
            repo.log_decision(
                notification_id      = str( uuid.uuid4() ),
                domain               = "swe",
                category             = mock[ "category" ],
                question             = mock[ "question" ],
                action               = "suggest",
                decision_value       = mock[ "decision_value" ],
                sender_id            = f"swe.lead@dry-run#{self.id_hash}",
                confidence           = mock[ "confidence" ],
                trust_level          = mock[ "trust_level" ],
                reason               = mock[ "reason" ],
                requires_ratification = True,
                metadata_json        = { "dry_run": True, "job_id": self.id_hash },
            )
        db_session.commit()

    if self.debug: print( f"[SweTeamJob] Inserted {len( mock_decisions )} mock proxy decisions for dry-run" )

except Exception as e:
    if self.debug: print( f"[SweTeamJob] Warning: Mock proxy decision insertion failed: {e}" )
```

**Import needed**: Add `import uuid` at top of `job.py` (check if already imported).

**Key details**:
- `action="suggest"` + `requires_ratification=True` → creates `ratification_state="pending"` records
- `sender_id` includes `dry-run` marker for traceability
- `metadata_json` includes `dry_run: True` flag so these can be filtered/identified later
- Wrapped in try/except — failure is non-fatal (dry-run still completes)
