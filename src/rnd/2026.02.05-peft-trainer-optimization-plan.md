## Executive Summary

Analysis of 8,508 training samples across 32 commands reveals that struggling commands (50-67% accuracy) share common patterns: **semantic ambiguity**, **alias fragmentation**, and **implicit context**.

This plan addresses each root cause through:
1. **Quality improvements** - Better keywords, disambiguation, structured negative examples
2. **Quantity increase** - Double sample size from 400 → 800 per command (~25,600 total samples)

Three implementation phases with measurable targets.

## Root Cause Analysis

### 1. "receptionist" (61.9%) - Alias Fragmentation

**Problem**: Training uses `RECEPTIONIST_TITLE` placeholder replaced with 30+ aliases:
- "Front Desk Clerk", "Administrative Assistant", "Concierge", "Information Clerk", etc.
- The word "receptionist" NEVER appears in training data!

**Evidence**: `src/ephemera/prompts/data/placeholders-receptionist-titles.txt` contains 30+ titles, none say "receptionist"

**Fix**: Add explicit "receptionist" keyword to 50% of training templates

### 2. "weather" (64.7%) - Implicit Context

**Problem**: Many templates omit "weather" keyword entirely:
```
"What will the temperature peak be today in GEOGRAPHIC_LOCATION?"
"Is GEOGRAPHIC_LOCATION expecting any hurricanes soon?"
"Forecast for this weekend in GEOGRAPHIC_LOCATION?"
```

**Evidence**: `src/ephemera/prompts/data/synthetic-data-agent-routing-weather.txt` - only ~30% of templates contain "weather"

**Fix**: Inject "weather" keyword into 50% of examples

### 3. "deep research" (53.3%) & "research to podcast" (50%) - Semantic Overlap

**Problem**: Both commands share "research" keyword:
- "deep research" templates: "research TOPIC thoroughly", "investigate TOPIC in depth"
- "research to podcast" templates: "turn this research into a podcast"

**Evidence**: Templates in `src/cosa/training/xml_coordinator.py:655-704` show overlap

**Fix**: Add contrastive disambiguators:
- deep research: "investigate", "analyze", "thorough", "in-depth study"
- research to podcast: "create audio", "generate podcast", "make episode"

### 4. "none" (61.9%) - Negative Learning Problem

**Problem**: Diverse unrelated requests without structure:
- "mute the TV" (home automation)
- "reboot the router" (IT)
- "open the garage" (home automation)
- General questions with no command intent

**Evidence**: grep of "none" examples shows random, unstructured negative examples

**Fix**: Create structured negative example categories (see Phase 2)

### 5. Sample Imbalance (Contributing Factor)

**Problem**: Unequal distribution
- "research to podcast": 182 samples (57% of 320 target)
- clipboard variants: 160 samples (50% of 320 target)

**Note**: Some 160-sample commands achieve 100% accuracy, so quality > quantity. However, imbalance still hurts.

### Phase 2: Disambiguation (Estimated: 3-4 hours)

**Goal**: Address semantic confusion between similar commands

#### 2.1 Create Contrastive Training Pairs

**File**: `src/cosa/training/xml_coordinator.py` method `build_agentic_job_training_prompts()`

**Change**: Update template patterns with stronger disambiguators:

```python
# deep research - emphasize investigation/analysis
"agent router go to deep research": {
    "template_patterns": [
        "investigate RESEARCH_TOPIC in depth",
        "analyze RESEARCH_TOPIC thoroughly",
        "conduct deep analysis on RESEARCH_TOPIC",
        "do a comprehensive study of RESEARCH_TOPIC",
        "I need a thorough investigation of RESEARCH_TOPIC",
        # AVOID: "research" alone without depth indicators
    ]
}

# research to podcast - emphasize audio/creation
"agent router go to research to podcast": {
    "template_patterns": [
        "create an audio podcast from the research",
        "generate a podcast episode about RESEARCH_TOPIC",
        "turn this into a podcast episode",
        "make an audio version of the research",
        "convert to podcast format",
        # AVOID: "research" without podcast/audio indicators
    ]
}
```

#### 2.2 Restructure "none" Examples

#### 2.3 Add Hard Negative Mining

**Implementation**: After initial training, collect misclassified examples and add them to training set with correct labels

**File**: Add new method to `xml_coordinator.py`:
```python
def extract_hard_negatives( self, validation_df: pd.DataFrame ) -> pd.DataFrame:
    """Extract misclassified examples for targeted retraining."""
    misclassified = validation_df[ validation_df[ 'is_correct' ] == False ]
    return misclassified[ [ 'input', 'expected_command', 'predicted_command' ] ]
```

#### 3.2 Add Validation Stratification

**File**: `src/cosa/training/xml_coordinator.py`

**Change**: Ensure validation set has equal representation per command:

```python
def get_stratified_validation_set( self, df: pd.DataFrame, samples_per_command: int=20 ):
    """Create balanced validation set with equal samples per command."""
    return df.groupby( 'command' ).apply(
        lambda x: x.sample( min( len( x ), samples_per_command ), random_state=42 )
    ).reset_index( drop=True )
```

#### 3.3 Implement Curriculum Learning

**Approach**: Train in stages:
1. **Stage 1**: Train on high-accuracy commands only (100% accuracy tier)
2. **Stage 2**: Add medium-accuracy commands (83-95% tier)
3. **Stage 3**: Add struggling commands with augmented data

**Implementation**: Add `--curriculum-stage` flag to PEFT trainer

## Risk Mitigation

1. **Regression Risk**: After each change, verify high-accuracy commands didn't degrade
2. **Overfitting Risk**: Use separate validation set, not test set
3. **Data Leakage**: Ensure train/test/validate splits are stratified and non-overlapping
