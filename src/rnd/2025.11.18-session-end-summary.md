### Phase 4: Root Cause Analysis & Fix ✅

**Problem Identified**: Normalization inconsistency between insert and query operations

**Root Cause**:
- `SolutionSnapshot.__init__()` used deprecated `remove_non_alphanumerics()` method
- `LanceDBSolutionManager.get_snapshots_by_question()` used `Normalizer.normalize()`
- Different algorithms → different normalized forms → cache mismatches

**Example Bug**:
```
Insert: "How do I use Python's f-strings?"
  → remove_non_alphanumerics()
  → "how do i use pythons fstrings" (apostrophe removed)

Query: "How do I use Python's f-strings?"
  → Normalizer.normalize()
  → "how do i use python 's f string" (apostrophe → space + 's)

Result: Cache lookup fails ✗
```

**Fix Implemented**:

Files Modified (4):
1. `src/cosa/memory/solution_snapshot.py` - Use Normalizer in `__init__()` (line 201)
2. `src/cosa/memory/solution_snapshot_mgr.py` - Replace `remove_non_alphanumerics()` with Normalizer (DEPRECATED file)
3. `src/cosa/memory/file_based_solution_manager.py` - Replace `remove_non_alphanumerics()` with Normalizer (DEPRECATED file)
4. `src/cosa/memory/lancedb_solution_manager.py` - Normalize question before cache lookup (lines 973-977)

**Verification**:
- Marked `remove_non_alphanumerics()` as DEPRECATED
- Created local backend isolation test to prove fix
- Re-ran all integration tests → 100% pass rate
