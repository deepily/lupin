## Item 28: the pid-alive probe

Five functions ask whether a pid exists with `os.kill( pid, 0 )`: `context_pressure._pid_alive`, `stale_buffer_janitor.is_pid_alive`, `register_session._is_live_cc_process`, `idle_waiter._is_pid_alive` and `session_bridge._is_pid_alive`. Four are hook code, and hooks cannot import cosa. No hook-library file is edited here. So the one cosa copy changes: `_pid_alive` now calls the hook library's `is_pid_alive`, keeps its not-an-int and any-other-OSError answers, and reads a non-positive pid as not alive.

PermissionError handling: there are two meanings in the tree and each caller picks one. "Exists" reads PermissionError as alive: `_pid_alive` (the arbiter leans toward alive), `is_pid_alive` and `_is_live_cc_process`. "Signalable, so it can be one of our seats" reads it as dead: `idle_waiter._is_pid_alive` and `session_bridge._is_pid_alive`, whose docstrings and tests say so. The second reading is correct at all twelve callers. Our seats, waiters and listeners run as one user, so a pid owned by another user is a recycled number. Reading it as alive would keep ghost bridges and a waiter slot held. An earlier version of this section called those two probes wrong; that was written before reading their callers, and is withdrawn. The caller-by-caller reading is in projects-data/lupin/cheech-tools/pid-probe-intent.txt. No hook-library file is edited.

One defect fixed: the old `_pid_alive( 0 )` and `_pid_alive( -1 )` returned True, because kill with pid 0 or -1 signals a process group. The janitor's probe returns False for them. A pid too large for the kernel now reads as not alive instead of raising OverflowError.

`test_arbiter_redline.py` expected one kill site in the arbiter folder. It now expects none, and the one kill behind the probe is pinned as signal 0 in `test_context_pressure_pid_alive.py`.
