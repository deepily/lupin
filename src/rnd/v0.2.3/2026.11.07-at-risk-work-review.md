## Finding (medium): landed now means "held on some remote", not "on the target"

`--remotes` excludes every commit reachable from any remote-tracking ref, so a branch pushed to `origin/<its own name>` and never merged anywhere counts zero commits at risk and reads landed. The janitor then files no row, and the archive ref is deleted 14 days later. The work survives only as long as that remote branch does; if it is deleted and pruned, nothing remains and nobody was asked.

| Receipt | Result |
|---|---|
| `test_a_pushed_line_that_never_reached_the_target_is_not_landed`: three commits pushed to `origin/old-line`, no squash, no merge | fails: `landed` is True |
| `test_the_squash_test_does_not_need_the_squash`: the commit's own "squash of a pushed line" scenario | passes: `at_risk_work` returns the same dict with and without the squash, so that test never exercises the squash |

For the 9 real refs this is the intended result: they sit on the pushed v0.2.2 line, which reached main. The defect is that the rule cannot tell that line from a pushed branch nobody merged.

Suggested narrowing, either one: count a remote-tracking ref only if it is reachable from `origin/main` or another named line (a config list), or ignore the remote-tracking ref that has the branch's own name. Add the failing test above as the negative control.
