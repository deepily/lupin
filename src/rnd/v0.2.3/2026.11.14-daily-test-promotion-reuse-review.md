# Reuse review: daily test promotion (row 586e23b0, commits 991c25c61 and 37fb3a42c)

Reviewed at commit 4ac63eb38, on top of f5b80394d (first written at 37fb3a42c). The reuse gate named 25 new definitions in `lupin_mcp/daily_test_promotion.py` with no outcome line: the run_command function, 9 methods of `Vm` and 15 module functions. The gate lists more on this base, in cron-jobs code and other files. They belong to other commits and are not ruled here.

## Method and limits

Each definition went through the logged MCP tools `fetch_similar` and then `record_search`, run by four helper agents so the 15,000-token replies stayed out of this document's author. I checked the receipt, symbol and search pairings of the first 27 lookups against the call log afterwards. `due` was looked up again on this tip, because its body changed. 9 of the 25 lookups came back with no cause and 16 with `LOW_CONFIDENCE`, which obliges a reading of the candidates.

A first attempt called the same functions from Python and ran out of model-call budget (`BUDGET_SPENT`). Those receipts were never written to the call log, because the log is written by the MCP wrapper, so the gate refused them. The review text was rebuilt on the logged receipts.

Beyond the shortlists I searched with fixed strings for `lupin-vm.sh`, `ZoneInfo(`, `update-ref`, `cat-file` and `fcntl.flock`, and read `reuse_harness.commands.run_command`, `job_cron.cron_last`, `job_health.covered`, `atomic_json.load_json_dict`, `duplicate_check_daily` (git, resolve_branch, branch_guard, run_lock), `duplicate_check_filing` (triage_payload, send_row), `source_at.full_sha`, `range_gate.require_commit` and `reader_rig_run.resolve_rev`. Most record_search candidates are unrelated task-store code that matched on words such as run, state and row; each has a line below.

## Two duplicates found, fixed in the rebase

- `latest_slot` equalled `cosa.rest.job_cron.cron_last( "0 18 * * *", now.astimezone( zone ) )`: 768 hourly instants across the 8 March and 1 November 2026 changes gave 0 differences. Clayton deleted it, and `due` now calls `job_cron.cron_last( SLOT_CRON, ... )`.
- `read_state` equalled `cosa.utils.atomic_json.load_json_dict`. Clayton deleted it, and `run` now calls `load_json_dict`.

Both were ruled `DUPLICATE` against the first commit. Neither definition exists on this tip, so neither needs an outcome line. The ruling for `due` is `DISTINCT` and stands on its own.

## Author's verdicts on the two near-twins (Clayton, 14 Nov 2026)

- `run_command`: kept local. `reuse_harness.commands.run_command` joins stderr into the output, which corrupts the last word of stdout (the instance state) or the first word (the deployed sha). A flag on the shared function remains a possible later change.
- `run`'s inline run lock: kept inline. `duplicate_check_daily.run_lock` is fixed to the duplicate-check folder through its `FOLDER` constant, so it cannot lock `io/jobs/test-promotion` without changing that module, which is outside this row's scope. Passing the folder in would let both jobs share it later.
