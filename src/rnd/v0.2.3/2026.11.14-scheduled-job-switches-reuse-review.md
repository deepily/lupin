# Reuse review: the scheduled-job switches (row c38a49bd)

The slice adds 16 Python definitions in three modules: `cosa.utils.cc_memory_watch` (5), `lupin_mcp.cron_switch_read` (9) and `lupin_mcp.notify_outbox` (2). Each has a logged `fetch_similar` receipt and a logged `record_search` id, both made on 14 Nov 2026 from the seat tree at f5b80394d. I matched each receipt to its symbol by the entry missing from its own shortlist, never by reply order.

Two modules are copies by design. `cc_memory_watch` runs as a lone file under the system python and cannot import `lupin_mcp`, so it carries its own parse rule, reader and gate. `test_cc_memory_watch_switch.py` pins the parse rule's source to the original and pins both readers to the same answers. The module already runs `python -m lupin_mcp.cron_switch_read` in a child process to write its failed summary, so the gate could in principle have read its switch the same way. It does not, because the gate reads the key on every sampling pass (the default interval is 15 seconds), and a child process per pass would run all day on the healthy path; the failed summary is written only when the key is unreadable. I label the originals `RELATED`, not `SAME_JOB`, because the code cannot call them from there. The reader should challenge that label: it is the one judgment call in this review (see the last section).

`fetch_similar` for `notify_outbox.run_flusher` answered with cause `BUDGET_SPENT`: 20 of the 120 entries it meant to check were not checked, so its shortlist covers 100.
