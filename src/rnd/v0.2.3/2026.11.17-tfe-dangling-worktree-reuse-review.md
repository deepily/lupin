# Reuse review: TFE job sandboxes whose git record is gone (row 438a8b49)

Commit b46acf17e added two definitions to `src/cosa/agents/shared/worktree_context.py` without outcome lines, and the reuse gate refused it on 17 Nov at 5061c59ed. This review writes the missing lines from the diff, so the PR gate can pass.

`has_dangling_git_link( path )` answers one question: does `<path>/.git` name a `gitdir:` target that no longer exists? The nearest existing code answers neighbouring questions. `_is_linked_checkout` and `kill_guard._tree_root_of` only ask whether `.git` is a file. `sender_id._dangling_gitlink_owner_basename` and `hook_credentials._main_checkout_name` parse the same `gitdir:` line, but return the main checkout's name and never check whether the target exists.

`WorktreeContext._remove_dangling_sandbox()` deletes the job's own folder only when that check is true. `worktree_reaper.drain_then_remove` is the normal removal path, and it refuses a folder whose git record is gone, which is the case this method exists for.
