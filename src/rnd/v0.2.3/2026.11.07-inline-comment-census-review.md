**Finding 1 (must fix): a git failure switches off every lint on the commit.** `dangling_path_findings` calls `ignored_paths`, which raises `RuntimeError` when `git check-ignore` exits above 1, and a missing git raises `FileNotFoundError`, which the docstring does not list. `tracked_paths` has the same property. Nothing in `comment_lint` catches either, so `gate.main` hits its crash handler, prints `GATE CRASHED, commit allowed` and exits 0. I forced the failure on a staged dangling path: the gate returned 0 and no other rule ran on that commit. Fix: catch both errors in `dangling_path_findings`, skip that one check, and add a warning line; add a test that forces each error and asserts the other comment rules still refuse.

**Finding 2 (low): trailing prose hides commented-out code.** `is_commented_out_code` accepts a comment only when the whole text parses as one Python statement. Any words after the code break the parse, so `# y = compute( 3 ) because` is not flagged (I staged it: exit 0, no finding), while `# y = compute( 3 )` is refused. The rule therefore undercounts dead code that carries a note, and the false-positive rate in the sample above says nothing about that side. A related trap: the waiver marker works only as `# code  # doc-lint: waive ...` with a second hash. Written with one hash, as `# code  doc-lint: waive ...`, the marker text itself breaks the parse; nothing is flagged, no waiver is counted, and a marker with no reason passes. Say so in the rule's refusal message, or strip a trailing waiver marker before parsing.

### Reuse outcome for the seven new comment_lint definitions (row 53f2a05a)

Reviewer: Rio, 7 November 2026. Tree: `5b17082d9`. Definitions: `tracked_paths`, `ignored_paths`, `take_path_failure`, `is_commented_out_code`, `line_pointer_findings`, `dangling_path_findings` and `commented_out_code_findings`, all in `cosa.repo.doc_lint.comment_lint`, written by Tiffany. I read the source of every candidate the seven searches returned that does a similar job. All seven rule DISTINCT. Two carry a note.

- **`tracked_paths`**: the git call is the same one `cli.tracked_files` makes (`ls-files -z`, names split at the NUL byte); `tracked_files( root, ( "", ), scoped=False )` returns the same paths. `tracked_paths` differs in what its caller needs: a cached `frozenset` for constant-time membership across thousands of comments, a 30-second limit, and a missing git or a timeout raised for the caller to catch. `cli.tracked_files` returns a sorted list, has no limit and lets a missing git escape. Follow-up, not a block: `tracked_paths` could call `cli.tracked_files` once that takes a timeout.
- **`ignored_paths`**: `planted_purposes.is_ignored` and `tree_path_refusal` ask about one path with `-q` and read any non-zero exit as "not ignored". That direction is unsafe in a gate, and neither takes a list. `ignored_paths` sends all paths through `--stdin -z` in one call, returns a set and raises when git exits above 1.
