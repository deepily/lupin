## Addition: how many of the 107 pointers dangle

I checked each `file:NNN` pointer for existence, resolving a bare name by basename. 103 resolve in range, 4 point past the end of the file found, and 6 name a file not tracked (some are examples such as `file.py:123`). So at least 4 to 10 of 107 (4% to 9%) are provably wrong by an existence test alone; the rest need a human read. This supports starting with the pointer rule. Basename matching can pick the wrong file, so read it as a bound.
