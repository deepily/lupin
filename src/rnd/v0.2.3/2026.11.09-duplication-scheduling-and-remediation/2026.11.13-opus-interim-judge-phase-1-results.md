## 3. Human labels: recall, precision, McNemar

The script scores both models against the labels and splits out the Opus work-alike stratum. It needs one input that the ledger cannot give: a map from each ruled pair to its label pair key.

- A ledger key holds hashes of the definition texts, not definition ids, so the judged (query) definition cannot be read back from the ledger.
- Joining on the candidate alone is ambiguous: of the 222 labelled pairs, many have a side that is a candidate in two to four ledger lines, and 33 labelled pairs have no side in any line.
- Rebuilding the map needs the pinned tree the proof ran from (`cheech-proof-pinned`), which no longer exists, and the 25 Oct run's commit was never recorded.

So the map has to come from whoever holds that tree or ran the Opus proof (Pocholo's run holds the same pool). Input: `--pair-map` is `{ "<definition key>|<candidate>": "<label pair key>" }`, `--labels` is `{ label pair key: bool }`, `--strata` is `{ label pair key: stratum }`. Recall is also checkable against record 2.json (found 72 of 80, correct 127 of 157), which validates the map before it is trusted.
