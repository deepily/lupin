# Reuse review: the cron run-time switch (row 94033d80)

The slice adds one definition to an indexed file: `lupin_mcp.job_run.switched_on`. It returns True for a registry job that names no `enabled_key`. Otherwise it reads that INI key as a required boolean.

The read itself is `ConfigurationManager.get_required` with `return_type="boolean"`. That call already refuses an absent or blank key, so `switched_on` adds only the registry opt-in. A job with no `enabled_key` has no switch and runs as before.

The nearest booleans read differently. `_as_bool_or_none` returns None for an unreadable value, so the caller falls to a fallback and a typo fails open. `librarian_tick.read_value` returns None for an absent key. A switch must refuse instead, so neither fits.
