## TL;DR

When a session the arbiter classifies as **stuck/dead is itself a MANAGER** (here: Tiberius),
the case-7 "manager tap" and case-13 reap-recommendation route the escalation to the
**owning manager** — and because a manager can't own itself, that resolves to the **other
LUPIN manager, Mr. Radio**. Result: Mr. Radio is repeatedly tapped on the shoulder about
Tiberius. A stuck/dead *manager* should escalate to **Rick only**, never to a peer manager.

The **confirmed** Tiberius-named misroute is the **case-13 reap-recommendation** ("Tiberius
stayed STUCK through 3 auto-pokes" → rick + Tiberius + Mr. Radio), from `_auto_poke` on a
**live + stuck MANAGER** subject — see Root Cause B.

Separately, an un-pruned corpse session (`9f133dd9`, dark since Jun 27) still carries
`role=manager, persona=Tiberius` alongside the **live** Tiberius (`eb4b105f`) — Root Cause A.
Per the correction below, the corpse's reach is **display/count**, NOT the manager-tap route,
so its fix is likely hygiene, not routing.

Two independent facets, two independent fixes (B = routing guard; A = prune/dedup + display
correctness). **Verify A's actual impact before scoping its RED.**

## Root cause B — case-7 "owning manager" resolution has no self/peer guard for a stuck MANAGER

Routing contract (`src/cosa/agents/heartbeat_arbiter/arbiter_routing.py`):

- `# 7  manager tap  (B) → owning manager  (the core actionable nudge)` → `TIER_OWNING_MANAGER`
  (line ~50 / `CASE_TIERS[7]`).
- `CASE_AUTO_POKE_REAP_REC = 13` → `TIER_RICK_AND_MANAGERS` (fans to Rick + **every** active manager).

Case 7 was designed for a stuck **worker**, whose owning manager should be nudged to act.
It has **no special case for when the stuck session is itself a manager**. "Owning manager"
then resolves to the *other* LUPIN declared manager (Mr. Radio), producing the inappropriate
peer shoulder-tap. Case 13 independently fans the reap-rec to all managers (incl. the peer).

**Design principle to encode:** managers answer to **Rick**, not to each other. A stuck/dead
*manager* is Rick's to actuate (reap/replace/re-staff) — route it Rick-only (mirroring the
Rick-only cases 1–3/10/15/18/19), and **exclude the subject manager AND peer managers** from
manager fan-out for a manager-subject escalation.

## Proposed fix (SWE team to design RED-first, then implement)

1. **Prune the phantom.** Ensure a corpse manager session past the max-age ceiling is dropped
   from the "stuck/dead" count + routing (not merely un-poked). Reconcile duplicate
   same-persona manager sessions to the freshest live one. (Coordinate with the host-side
   bridge-prune already specced in the 2026.05.16 stale-bridge doc.)
2. **Guard the routing.** When the subject of a case-7 tap (or a case-13 reap-rec) is itself a
   **manager**, route to **Rick only** — never to a peer/owning manager, never to the subject
   manager itself. Add the self/peer-exclusion to the owning-manager resolver and the
   `rick_and_managers` fan-out for manager-subject cases.

Both are **arbiter-only and freeze-safe** — same blast radius as today's `fb332fcd` fix
(`arbiter_job.py` + `fleet_render.py`, zero hook/mux/dist).
