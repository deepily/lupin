## 1. The class (what this bug IS — and is NOT)

**IS**: while a merge-gate sweep runs on `:8000`, **other fleet agentic jobs can be
writing to the shared `lupin_db_test` concurrently** — a *within-window* contamination.
The writes overlap a suite's OWN run, not the seam between suites.

**IS NOT** (`8bd20375`, already closed): cross-suite *residue* surviving the
`e2e→integration` seam. That is killed by the between-suites reset + per-test
`refresh_tokens` TRUNCATE. Between-suites isolation does **not** close THIS class —
the concurrent write lands mid-suite, after the seam reset already ran.

**Symptom**: `refresh_tokens` duplicate-jti PK violation → login 500
`"Token already exists"` → `KeyError: 'tokens'` cascade across every auth-dependent
test. `jti = uuid4()` per issuance means a collision is only producible by an
**identical token stored twice** — a same-jti double-store from a concurrent/retried
writer (schema.sql:26, `PRIMARY KEY (jti)`).

**Evidence**: during the failing `e2e→integration` window, `GET /api/queue/pool-status`
showed concurrent `inflight_agentic_jobs` on `:8000`.

## 2. Root-cause discovery (NEW — surfaced during this fix)

`monopolize=True` on `TestSuiteJob` is an **unenforced no-op placeholder**.
`src/cosa/rest/queue_consumer.py:125-129`:

```python
# Monopolize placeholder (no-op in serial mode)
# When Hybrid Fast Lane adds ThreadPoolExecutor, this will wait for
# running_queue to drain before processing the monopolize job.
if getattr( job, 'monopolize', False ) and todo_queue.debug:
    print( f"[CONSUMER] Monopolize job detected: {job.id_hash}" )
```

The ThreadPoolExecutor agentic pool **landed in v0.1.7**, but this monopolize hook
was never wired to drain/pause the pool. So nothing structurally prevents another
fleet agentic job (deep research, podcast, BFE/TFE, another submitted job) from
riding the same pool and writing `lupin_db_test` alongside the sweep. **This is the
mechanical root of the class.**

## 5. Design (option c)

**Layer 1 — queue classifier** (`RunningFifoQueue.get_non_test_inflight_agentic_jobs`):
enumerate `_agentic_futures` for inflight (submitted-but-not-done) futures whose
backing job is NOT `job_type == "test_suite"`, excluding the sweep's own `id_hash`.
A future whose job is absent from `queue_dict` is reported as `"unknown"` (fail-loud
on the unclassifiable — still a writer we cannot vouch for). Snapshot-under-lock,
mirroring the ghost-sweeper. Never raises.

**Layer 2 — sweep preflight** (`TestSuiteJob._preflight_assert_exclusive_test_db`):
called first inside `_execute` (after dry-run early-out, before the suite loop).
Reads the running-queue singleton (`lupin_app.main.jobs_run_queue`) in-process, calls
Layer 1, and **raises `RuntimeError` naming the offenders** if any. `do_all` catches
→ job FAILED + re-raise → the merge gate goes RED with a clear, diagnosable reason
(never a contaminated GREEN).

**Safety, mirroring `_reset_state_between_suites`**: gated to `lupin_db_test`. Off the
test DB (a sweep aimed at `:7999` dev, where coexisting fleet jobs are legitimate) →
logged NO-OP. Running-queue singleton unavailable/None (unit context) → logged NO-OP.
The ONLY raise is the loud-fail; classification itself never raises.
