## THE QUESTION

The survey ran `src/cosa/tests/**`: **8,799 ran, 8,771 passed.** A green test proves it
executed without raising. It does not prove it asserts anything. This row measures the gap.

## THE HEADLINE

`test_configuration_manager` is representative — on the failure path it does:
```python
return False, time.time() - start_time, "Default value retrieval failed"
```

**PROVEN, not inferred.** A fixture reproducing the shape:
```python
def test_returns_false_the_way_the_cosa_smoke_tests_do():
    success = False                      # the test DETECTED a failure
    return success, 0.0, "it failed"     # ...and reports it by returning

```

`pytest.ini` has **no `filterwarnings`**, so the warning never escalates. The detected failure
is discarded and the tier reports green.

⇒ This is `5bf28e07`'s thesis in its **running** form. That row says *"a suite that cannot go
red is indistinguishable from a suite that passes."* These 14 run, and still cannot go red.

## THE INSTRUMENT — and its two proven bugs

AST, never grep. A grep for `assert` matches a *description* of an assertion: docstrings,
comments, the word inside a string literal. Counted nodes: `ast.Assert`, calls whose name
starts with `assert` (verified against the real `unittest.TestCase` + `unittest.mock` surface —
all 34 distinct names in the tree are genuine; no typo'd no-op mock assertions), and
`pytest.raises`/`warns`/`fail`. Intra-module calls are followed transitively.

**A control fixture with per-function expected verdicts caught two bugs the code review did not:**

1. **builtins scored as unresolvable helpers.** `print(x)` made a test "a call I could not
   follow", pushing three known-floor cases into UNRESOLVED — i.e. making the tree look
   *healthier* than it is, the direction that flatters.
2. **blanket refusal to descend into nested defs.** Correct for a closure that is never
   referenced; wrong for `asyncio.run( inner() )`. Cost 54 tests, misfiled as unresolvable.

After both fixes the control matches **member by member**, not merely by count:
```
12 collected | ASSERTS 7 | NO ASSERT 4 | UNRESOLVED 1
```
including the docstring/comment/string decoys, a never-invoked closure, a local helper that
asserts (which body-only scanning gets wrong), and the two uncollectable-class cases.

### What it cannot see

- **Vacuous assertions** — `assert True`, `assertTrue(1)`. Checked separately: only **5** in the
  tree, and all 3 tests carrying them also hold real assertions (5, 1, 1). Not a live problem here.
- **Imported helpers.** The 185 could in principle be rescued by one. The sample says otherwise.
- Anything about whether a *real* assertion asserts the *right* thing. That needs mutation testing.
