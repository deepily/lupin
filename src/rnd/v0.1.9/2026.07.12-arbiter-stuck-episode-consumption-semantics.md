## 1. Defect

`fleet_data_model._count_stuck_episodes` consumes a prior `cap_reached` **only** when a later **`honored`** record appears. A session that recovers by going **`idle`** (`work_owed: false`) consumes **nothing** — so its `stuck` flag stays `True` until the events tail rolls off.

**Live evidence** — sam (session `84daa020`), verbatim from his events file:

| ts (UTC) | outcome | poke_count | work_owed |
|---|---|---|---|
| 01:00:11 | `cap_reached` | 3 | True |
| 01:08:13 | `cap_reached` | 3 | True |
| 01:15:19 | `cap_reached` | 3 | True |
| **01:27:32** | **`idle`** | 3 | **False** |

He recovered at 01:27. Yet at **21:49 EDT** — idle, zero owed work, bridge 0 seconds fresh — the arbiter still rendered him `LIVE STUCK` and tapped his manager. **Permanent LIVE-STUCK.**

### Why fix (B) at all, when (A) already suppresses the live FPs?

`3287ee1e`'s bridge-fresh veto (fix A) is an **announce-leg belt**: it suppresses a stuck-flagged session that is *demonstrably taking turns*. It does **not** cover a session that recovered via `idle` and then went **quiet** — a stale bridge means no veto, so a long-recovered session that stops taking turns is still announced as stuck. (B) fixes the flag **at source**, so the two compose rather than overlap:

- **(A)** catches: genuinely-capped, still-active. *Bridge fresh.*
- **(B)** catches: capped, then recovered, now quiet. *Bridge stale — (A) is blind to this.*

## 2. Consumer sweep (mandated by Mr. Radio before design)

`stuck` is produced in exactly one place — `fleet_data_model.py:438`, `_count_stuck_episodes( activity_recs ) >= STUCK_REPEAT_THRESHOLD` (threshold = 2) — and consumed in **ten** places.

**The safety property that governs every row below**: broadening the recovery class can only **consume more** caps, so the flag can only flip **`True` → `False`**, never `False` → `True`. The change is **monotone**. No consumer can see a *new* stuck session; every consumer can only see *fewer*.

| # | Consumer | File:line | What it does with `stuck` | Effect of the broadened rule |
|---|---|---|---|---|
| 1 | `_attention_workers()` | `arbiter_job.py:2454` | stuck leg of the attention roster | Fewer false roster entries. **Closes (A)'s residual gap**: a recovered-but-quiet session (stale bridge) stops being announced |
| 2 | `_tap_signature()` | `arbiter_job.py:2501` | tap-throttle change signature | Signature changes once on the transition poll → at most one extra tap evaluation; anti-storm throttle unaffected |
| 3 | `_format_manager_tap()` | `arbiter_job.py:2530` | splits members into `Stuck:` vs `Blocked:` lines | Fewer names on the `Stuck:` line (the visible bug) |
| 4 | `_fleet_progress_signature()` | `arbiter_job.py:3485` | fleet progress/liveness signature | Same one-time signature shift; benign |
| 5 | **`_pokeable_sessions()`** | `arbiter_job.py:3689` | **selects who gets POKED** — the actuating consumer | Fewer pokes at recovered sessions. **Safe by construction**: a wedged session *owes work* (`work_owed: True`), and `idle` is only written when `work_owed: false` — a wedged session cannot emit the beacon that would silence it |
| 6 | `_stuck_gate_why_not()` | `arbiter_job.py:4717` | poke-gate diagnostic vectors | `not_stuck` appears more often. Observability only |

**Nothing outside the arbiter + its UI consumes the flag.** No store rows, no notification routing, no test-suite path, no persistence.

## 3. Recovery-class ruling needed — the full writer-side outcome vocabulary

Constants live in `heartbeat_decision.py:43-53`. Counts are **empirical**, over every activity record in `~/.claude/heartbeat-events/` fleet-wide:

| Outcome | Fleet-wide count | Meaning | Recovery? |
|---|---|---|---|
| `honored` | 3062 | fresh declared hold → defended quiescence | ✅ **consumes today** |
| `poked` | 1160 | owed + under cap → self-poke | ❌ session still owes — *not* a recovery |
| **`idle`** | **705** | the explicit "nothing owed" beacon (`work_owed: false`), written only on the **transition** into idle | ✅ **ADD — this is the fix** |
| `cap_reached` | 94 | owed + at/over cap → stop nudging | ❌ this *is* the wedge evidence |
| `not_owed` | **0** | defined, but **never written** — the writer skips it and emits `idle` instead (`heartbeat_events.py:441`) | ➖ moot; excluded (no live consumer, no speculative shim) |
| `suppressed_stale_declared_owed` | **0** | Lever A (`4162e89d`) poke suppression | ➖ excluded — a *suppression* record, not a recovery beacon; recommend NOT speculating |

**Recommended recovery class: `{ honored, idle }`.** Exactly the two beacons that assert "this session is not wedged," both empirically live in the stream.

### A load-bearing detail that makes this work at all

The `idle`-outcome record carries **`kind: None`** — not `kind: "idle_prompt"`. `build_fleet_view` partitions records at `fleet_data_model.py:349`, excluding `idle_prompt` / `reaped` / `task_transition` from `activity_recs`. Had `idle` been an `idle_prompt`-kind record, it would be **invisible** to `_count_stuck_episodes` and the entire remedy would be **inert**. Verified against sam's file: his three `idle` records are `kind: None` ⇒ they *are* in `activity_recs` ⇒ the broadened rule will see them.

## 4. Proposed change (one function, pure)

In `_count_stuck_episodes`, generalize the recovery scan from a single outcome to a **recovery-class set**:

```python
RECOVERY_OUTCOMES = frozenset( { OUTCOME_HONORED, EVENT_IDLE } )   # bug 52b8ed6b
...
if isinstance( e, dict ) and e.get( "outcome" ) in RECOVERY_OUTCOMES:
    last_recovery = i
```

Order-respecting and deterministic, exactly as `5a1f17f8` designed it — no clock, no threshold knob, no new state. The `5a1f17f8` replay-robustness property is **strengthened**, not weakened: more recovery beacons consume more replayed history.

**The true positive is preserved**: a genuinely wedged session emits repeated `cap_reached` with `work_owed: True` and — by construction — never emits `idle` (which requires `work_owed: false`). Its caps are never consumed; it stays `stuck`; it is still poked and still announced.

## 6. Manager ruling (2026-07-12, thread 22f9aacf) — both APPROVED

Sweep accepted (spot-verified firsthand: one production call-site for the producer; arbiter-side reads match the table). Recovery class ratified as `{ honored, idle }`, **with both exclusions concurred** — and Mr. Radio sharpened the membership rule from my occurrence-count argument into a principle worth keeping:

> **A recovery outcome is a liveness beacon THE SESSION ITSELF EMITS.**

That classifies the exclusions cleanly and durably: `not_owed` is dead vocabulary (never written), and `suppressed_stale_declared_owed` is an **arbiter-side suppression marker**, not a session beacon — it fails the rule on principle, not merely on its zero count. The rule is recorded in the `RECOVERY_OUTCOMES` comment so the next vocabulary addition gets classified correctly.
