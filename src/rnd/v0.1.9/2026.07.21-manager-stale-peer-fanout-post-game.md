## 2. The two findings worth more than the fix

### 2a. A coverage gate cannot see a change to a data literal

`arbiter_routing.py`: **18/18 stmts, 0 branches, 100%** — and **not one of the 37 changed lines is in `executed_lines`.**

- `:164` (the table entry) is a **dict-literal continuation**, counted as one statement at `:150`. That statement executes on import **whatever value the line holds** — green for `TIER_RICK_ONLY`, for `TIER_RICK_AND_MANAGERS`, or for garbage.
- `:202-211` (the smoke assertions — consequential edit #1 in the plan) are **config-excluded** by `pyproject.toml:195-200`.

**Every table-driven routing / config / dispatch change in this repo is invisible to the fleet-wide 100% mandate.** Mutation is the only instrument that answers *"would a wrong value be caught."*

⚠️ **The manager's own AC-6 demanded "100% lines/branches/functions" because it is the house mandate.** It would have been reported green while proving nothing about the diff. **Writing the mandate into an acceptance criterion is not the same as the criterion being able to fail.**

### 2b. A peer-silence assertion keys on the RECIPIENT, never the MESSAGE

The reviewer's mutation B — revert the tier **and** rename `MANAGER-STALE:` → `MANAGER-QUIET:`, so peers *are* still being DM'd — found a brand-new assertion passing **vacuously**:

```python

[ s[0] for s in gw.sent ] == [ "Tiberius" ]                # the correct form
```

It survived only on a sibling Rick assertion that happened to share the same string literal. **This is María's F3 warning reappearing inside the fix that was written to satisfy F3.**
