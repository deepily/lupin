# The DM traffic corpus, and the experiment it exists for

**Design of record.** Written 2026-08-02 · María 🌸 (`3e328792`) · built by Krishna 🦚 (`55eae7a8`)
**Store rows**: `334569d6` (the sink) · `f5d6dc5e` (the test guard) · `f4bb1cdb` (faces, arm, thresholds) · `722fe4e9` (the Wednesday report)
**Status**: collecting. Instrumentation still landing — see §8 for what is not yet true.

---

## 1. Why this exists

Every DM the fleet sends is graded for length, directness and tone. Until today those grades were
**summed and discarded**: four running totals in a module-level dict, zeroed on every server restart.

That shape could not answer the only question anyone actually wanted answered — *how many DMs run
over 250 words?* **Totals cannot be un-summed.** And because auto-reload is off, every code change
requires a bounce, and every bounce wiped the counter. The instrument for measuring an intervention
was destroyed by the act of deploying one.

So the fix was not to persist the counter. It was to **stop throwing the rows away.**

---

## 2. What is collected

One JSON object per sent DM, appended to `src/tmp/dm_traffic.jsonl`. Append-only; never rewritten,
never read-modify-write.

| Field | Meaning |
|---|---|
| `ts` | write time, container clock (UTC) |
| `origin` | `"live"` for a real send, `"test"` for one written under pytest. **See §5.** |
| `arm` | which intervention was in force. **See §4.** |
| `from` / `from_session` / `from_project` | sender identity as resolved at the send path |
| `to` / `to_session` | recipient, after persona resolution |
| `words` / `chars` / `sentences` | measured on the body **as supplied**, before any timestamp framing |
| `body` | the full message text |
| `len_grade` `directness` `tone` `overall` | the judge's integer weights, `-2 … +2` |

### A null grade is a fact, not a hole

- `directness` / `tone` **null above 150 words** — the judge *declines* to grade the qualitative half.
  This is **a ruling, not a failure** (§6). Do not treat these as missing data or impute them.
- Any grade null with the judge unreachable — a genuine non-answer, deliberately distinguished from a
  real neutral `0`. Conflating those two was a real defect, corrected the same week: an unavailable
  judge used to return weight `0`, which *is* a grade on this scale.

---

## 3. Where it lives, and why there

`src/tmp/` inside the repo, which is bind-mounted read-write into the container.

- **Not in git** — the `tmp` pattern in `.gitignore` covers it (verified with `git check-ignore -v`;
  note the match is a bare `tmp`, broader than `src/tmp/`).
- **No compose change, no recreate, no migration, no new service.** The container already had a
  writable path to the host.
- **Visible from the operator's own shell** the instant a row is written.

⚠️ **This is only safe because auto-reload is off.** A server writing into a watched directory under
`src/` with `--reload` on would restart itself on every DM sent. If reload is ever re-enabled, this
sink must move first.

⚠️ **The corpus does not survive a fresh checkout**, by construction. It is data, not source. Anyone
who needs it preserved must copy it out.

## 4. The experiment

Two arms, comparing **feedback** against **refusal** as interventions on DM length.

| Arm | Intervention | State |
|---|---|---|
| **A — signal only** | The sender sees a length grade, and (once `f4bb1cdb` lands) a repeated emoji scaling with overage. Nothing is blocked. | **Running now** |
| **B — refusal** | An over-long DM is rejected outright at a hidden, randomized threshold. | **Not built.** Deliberately. |

Rick's sequencing: find out whether a signal alone shortens DMs before reaching for refusal.

### Why `arm` is stamped on every row

Arm A is running and arm B does not exist. If today's rows carried no arm label, then when B starts
the only way to separate the populations would be **by timestamp** — inferring the condition from
when a row was written.

That is the same inference that nearly poisoned this corpus on day one (§5), and it is worse here: a
bounce, a config flip or a mid-day ruling would put the boundary somewhere no timestamp reveals.
**One field today; impossible to retrofit later.**

The arm derives from a config boolean. **Absence or explicit false is arm A** — a missing key is a
valid state meaning "the reject path is not in force", not an error. True means errors are returned
on overage.

### If arm B is built later

Seed the threshold on a **hash of the message body**, not a fresh draw per attempt. Otherwise a
rejected DM retried unchanged succeeds about half the time, and the fleet learns that retrying beats
editing. And strip fenced code blocks from the word count, or the rule punishes the messages that
legitimately carry a stack trace.

## 5. Keeping test data out — three layers, and the honest limit

The corpus was contaminated within minutes of existing. Its first inspection found **34 rows of which
2 were real**; the other 32 were unit-test fixtures (*"does this still get through?"*, five times)
written to the production path because the tests call the same code from the same repo. Nothing
errored. Every row was valid JSON with plausible fields. **Averaged naively the file reported 4.9
words per DM** — which reads as *there is no verbosity problem*, the exact opposite of the truth.

It was caught by noticing **two clocks in one file**: test rows carried host-local timestamps, live
rows container UTC. That worked, and it was luck rather than design.

| Layer | What it does | What it misses |
|---|---|---|
| conftest autouse fixture | redirects every test to a throwaway path | a test written outside its reach |
| **writer self-guard** | refuses the production path outright when `PYTEST_CURRENT_TEST` is set | anything that is not pytest |
| `origin` stamp | records what wrote each row | nothing — but it only *records*, it does not prevent |

**The limit, stated rather than left to be discovered: a hand-run script that imports the module and
sends a DM is caught by neither guard.** That is exactly why the stamp still earns its place — a row
that says what it is beats a reader who has to be clever.

⚠️ The self-guard compares the live sink against a **separate immutable constant the fixture never
patches**. Comparing it against the patched variable would be a control comparing a value to itself:
it would pass every test and protect nothing.

## 6. Thresholds

| Threshold | Value | What it does |
|---|---|---|
| target | 60 words | the number every other grade is relative to |
| buckets | 60 / 90 / 150 / 250 | ⭐ 👍 🤷 👎 😞 |
| qualitative cap | 150 words | above this the judge stops grading directness and tone |
| emoji repetition | one face per 150 words | **derives from the qualitative cap**, not its own literal |

**The 150-word cap is a ruling, not a limitation.** Above it, how well a message is written is not
worth grading and fixing the grader for that case is not worth doing: if it is too long, it is out.
⇒ **length is a gate in front of the other two dimensions, not one dimension among three.** This is
also why the eventual lever is refusal rather than a better grader — a grade argues, a refusal does
not.

⚠️ **Before `f4bb1cdb`, these numbers existed twice.** `QUALITATIVE_WORD_LIMIT = 150` and
`LENGTH_TARGET_WORDS = 60` were named constants, and the bucket comparisons restated the same
literals inline — so changing a constant left the buckets where they were, silently. The migration to
config exists to make each number have **one definition**. If a threshold appears twice after that
lands, the migration did not do its job.

**Defaults must reproduce today's behaviour exactly.** The corpus is collecting; a threshold that
shifts mid-window changes what every stored grade means.

### ⚠️ Changing a threshold should not require a restart — and currently does (row `00600a75`)

The values are bound to **module-level constants at import**, so re-initialising the configuration
singleton leaves the judge reading its own frozen copies.

That is a property of this implementation, **not of the system**. `/api/init` already hot-reloads
configuration and flushes every registered cache — and the generic mechanism it uses exists precisely
because a cache-invalidation gap was filed against that endpoint once before, and the answer was for
each cache module to self-register an invalidator. **The judge is simply not a participant yet.**

Until it is, an INI edit is inert until a bounce. Open as a P1, because tuning a threshold with one
API call rather than a server restart is what anyone would want on a demo morning.

⚠️ Whoever fixes it must also fix the words: the INI comment block and the splainer entries currently
state that a bounce is required. **If that stops being true, those sentences become the next reader's
wrong answer.**

⚠️ And the fix has a trap of its own. The emoji-repetition interval deliberately *references* the
qualitative-cap value so the two share one definition. A reload path that re-resolves one and not the
other **reintroduces the duplicate-definition problem this section exists to close** — silently, and
only on reload. Any gate must prove the repetition interval moved too, not just the buckets.

## 7. Known biases — state them, do not bury them

- **The early sample is not the fleet.** The first hours are heavily one manager and one implementer
  running review gates, which run long by nature.
- **Fleet-wide, all projects.** The recorder fires on every DM regardless of origin project, so a
  per-project split is meaningful but the headline number belongs to nobody in particular.
- **The labels are a model's opinion.** `len_grade` is deterministic Python. `directness` and `tone`
  come from a local model whose directness half was rebuilt this same week. For training use, treat
  the qualitative pair as weak supervision until a human has spot-checked a sample.
- **Rows written before the stamps exist carry neither `origin` nor `arm`.** They predate the fields.
  They are **not contaminants** and must be handled explicitly rather than silently dropped or
  silently included.

## 8. What is not yet true

At the time of writing, `f4bb1cdb` is mid-build. **Not yet live**: the repeated emoji, the `arm`
stamp, and the config-backed thresholds. Rows written before it lands carry no `arm`.

**Open decision**: whether to truncate the corpus and restart the clock once that lands. The
recommendation on the table is to do it **once, at that moment** — archiving rather than deleting, so
the pre-instrumentation rows survive as a before-sample — because truncating earlier means truncating
twice, and because truncation removes the *record* of the early bias rather than the bias itself.

## 9. The report

Due **Wednesday evening 2026-08-05** (row `722fe4e9`), giving three days of collection before the
demo on the 6th.

It must answer: the **distribution** rather than the mean (the median is the honest number — a mean
can be a few outliers); **drift over time**, words per DM against hours-since-the-last-human-message,
which is the never-run test for whether inter-agent register degrades without a human in the loop;
**per-seat and per-project** concentration; and **whether the intervention worked**, split by reading
`arm` off the rows rather than inferring it from when they were written.

**Methodology, non-negotiable**: filter to `origin: "live"` before computing anything, handle the
pre-stamp rows explicitly and say which way you handled them, state the sample bias, and never quote
a number without its row count.
