## 1. The practice, first — because it is the only part that is executable

> **An assertion is not a guard until you have deleted the thing it guards and watched it go red.**

Everything below is commentary on that one line. Twelve assertions were written across two commits; **all twelve earned trust by reverting the thing they guard**. Four *other* checks were written the same day by both engineers, reviewed by both, agreed to by both — and **could not fail**. None of the four was caught by reading. Every one was caught by reverting.

The taxonomy in §2 is interesting. The sentence above is what someone can actually do on their next commit.

**Why review does not substitute.** A check that agrees with the code on the sampled input is *indistinguishable, in its output, from a passing test*. Green is green. There is no signal in the terminal that separates "this assertion holds because the code is right" from "this assertion holds because it cannot see the code." The only way to force the distinction is to break the code and watch.

The strongest available evidence for that claim is in §2.4: the fourth instance was written **immediately after both engineers had explicitly named the pattern to each other, in writing, in the same thread.** Naming it did not defend against it.

## 2. Four assertions that could not observe what they claimed to observe

### 2.1 A fixture margin wider than the bug (mine)

`_taskIsParked` normalizes a zone-less timestamp to UTC, mirroring the Python twin (`chase_ts.replace( tzinfo=utc )`); JS `Date.parse( "2026-07-22T14:00:00" )` reads **local**. Untreated, the twins disagree by the operator's UTC offset — silently, and only for zone-less rows.

The test placed fixtures at **±6h** from `now`. A 4h local offset cannot flip a 6h margin, so both assertions held under either reading.

**Receipt**: deleting the normalization outright left the suite **GREEN**. Re-cut with instants inside one offset, straddling in both directions so either sign flips exactly one assertion. The mutation then died.

> **María's rule, generalized from this**: *a fixture's margin must be SMALLER than the largest quantity that could mask the bug.* Fleet offsets reach 14h; the fixture allowed 6h of masking.

### 2.2 Two triggers, one shared dependency (María's catch, on my code)

The truncation banner fired on `has_more === true` **or** `count < total`. Two triggers reads as redundancy. Both key on `total`: a response omitting it makes `has_more` undefined *and* the comparison NaN-false, so a single missing field restores the exact silence the banner exists to remove.

**Fix**: a third trigger depending on neither — `count === limit` with no `total` ⇒ *completeness UNKNOWN*. The limit is **parsed from the shared query**, never hardcoded, so editing the query cannot leave a guard that silently stops matching.

### 2.3 A test asserting against its own fixture (mine)

The first Piece-1 test hand-built a muted state dict and asserted against **that**. It stayed RED after the production fix landed, because the fixed code never ran. It was testing its own construction.

**Fix**: drive the real `_resolve_owed_state` with patched settings.

### 2.4 A pin specified from the conclusion rather than the divergence (María's, on my code)

María asked for a pin that a muted session takes the neutral branch of `beacon_idle_message`. Written as specified, then checked by reverting the fix: it stayed **GREEN**.

A muted bundle carries `owed=False` **and** `owed_unknown=True`, and `beacon_idle_message` returns `idle_msg` on **both** the unknown branch and the not-owed fallthrough. The branches **coincide on exactly that input**, so the assertion could only ever agree.

**Re-cut** to the input where they diverge — `owed=True, owed_unknown=True → idle_msg`, i.e. **UNKNOWN outranks OWED**, which is the property the mute path actually depends on. Deleting the precedence line kills it.

In María's own words: *"I specified the assertion from the conclusion I wanted rather than from the input where the branches diverge."*

## 3. The finding neither of us would have reached by testing harder

**A guard keyed on COMMITTED state is structurally blind to a pre-commit run.**

`test_notifications_task_list_token_not_stale_vs_css` resolves `task-list.css`'s date from `git log`. Commit `4bec617b` edited that CSS without bumping the `?v=` token in `notifications.html`. The token was stale, so returning browsers would have served the cached sheet and **none of the new parked-dim or banner styles would have rendered** — a change that passes every test and reaches no user.

The guard was **green** on the pre-commit sweep and **red** on the very next one. Not because the sweep was sloppy: before the commit, `git log` had nothing to report. The guard's input did not exist yet.

**Consequence for how we speak about verification**: "I ran the suite before committing" is *not a claim about that guard at all*. This generalizes past cache tokens to anything asserting over committed state — migration heads, changelog freshness, tag/version alignment, file-date coupling. Those guards require a **post-commit** sweep, and their pre-commit green is uninformative rather than reassuring.

## 4. The parked overrule — the store settled it against both of us

The task-list panel needed to mark parked rows. Both engineers reasoned about the semantics fresh, and both got a term wrong.

- **María's ruling**: `park_reason` present ⇒ PARKED, including a null chase.
- **My draft**: `park_reason` present AND a future chase.
- **The store** (`task_store_owed.py:184`, canonical, with **three** existing readers): `park_is_active == status == "parked" AND next_chase_ts > now`.

Two terms neither of us had right:

1. **Keyed on `status`, not `park_reason`.** `parked` is a real status in `VALID_STATUSES`; the reason merely accompanies it.
2. **Null / unparseable / past chase is NOT park-active** — *"fail-loud-toward-owed: a malformed park is VISIBLE work."* `is_owed( "parked", None, now )` is `True`.

María's instinct — that parked-forever is the more alarming state to hide — was right; the store discharges it the other way. Its own docstring: an indefinite hold is a **contract violation** that belongs in `dropped`, *because dropping is visible*. So the loud treatment for a null-chase park is that it stays on the board as ordinary owed work, **not** that it gets dimmed. Under María's ruling the UI would have whispered *"deferred, ignore me"* over rows the store actively counts as owed.

**Lesson for the record**: where a canonical shared predicate exists, **mirror it term for term; do not rule fresh.** That module exists *because* divergence across its readers "has bitten this fleet repeatedly" — and the panel was about to become its fourth reader, which is precisely where the divergence it guards against would have entered.

**Second, smaller** (María's, self-reported): she recommended `park_reason_stale` as a shortcut for expiry. It answers a different question — whether the frozen quote has drifted from `updated_ts`. *"That was me recommending a field I hadn't read."*

## 5. What shipped, and the receipts

### `4bec617b` — the board was 57% invisible

The panel polled `/api/tasks?…&include_terminal=true`. Measured against the live store: **1,171 rows returned against a `limit` hard-capped at `le=500` — 671 dropped.** Ordering is newest-first, so the evicted rows were the **OPEN** ones the panel exists to display. Both call sites carried a comment promising the human's view was *"never silently truncated."*

**The number was never the defect; the silence was.** Dropping terminal rows takes the board to 139 — *headroom, not a guard,* and headroom expires without telling anyone.

| Trigger | Depends on |
|---|---|
| `has_more === true` | `total` |
| `count < total` | `total` |
| `count === limit` and no `total` ⇒ **UNKNOWN** | neither |

Also: server `warnings[]` rendered **verbatim** on their own line, never feeding the arithmetic (an unrecognized warning has no numbers; inventing them is worse than silence); `query_unavailable` as its own render state, because a missing static asset is a **deploy** defect and must not wear **transport**'s error state on a 60s poll; `tsconfig` widened to cover `static/js/shared` with `checkJs` — it was typechecked by **nobody**, and caught an undeclared `window` global on its first run.

### `b65191ec` — muting the poke reported a clean board nobody read

Two of three mute outcomes return `None` from `_run_heartbeat`, and `main()` falls through to the idle-announce, publishing **"Heartbeat: idle — nothing owed."** But the mute short-circuits *before* the hold read, transcript replay and store query — by design. `owed=False` was a **default standing in for a lookup that never ran**, and a muted fleet would report itself uniformly idle-and-clear.

`_announce_idle`'s own docstring names this conflation as what it was written to prevent: *"the whole-fleet false-idle that fired during the :7999 outage was exactly this."*

**Rick's ruling governs the shape** (verbatim, from when he ordered the beacon built): *"I also want the momentarily idle output pushed to me via notification API to reflect the contents of the default poke disabled message. I want to see what the workers see."* ⇒ **silence at the WORKER, honesty on the CARD.**

Deliberately **not** widened to `config_error` / heartbeat-disabled: both are long-standing pinned contracts and neither is a live-fleet switch. A discriminator test makes that narrowness a decision rather than an oversight.
