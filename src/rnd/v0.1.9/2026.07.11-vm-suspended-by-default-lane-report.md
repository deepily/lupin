### Reconciliation findings (verify-don't-assume)

1. **Real target = `lupin-host-test`**, NOT the top-level working tree's `micro-experimental-vm` (a stale scratch config, env=dev, e2-micro). The operative lane is a direct `terraform apply -var-file=vm.tfvars` in the `.vm-state/lupin-host-test/terraform` dir (GCS backend `gs://…/vm/lupin-host-test`).

2. **Gitignored-revert catch**: `.vm-state/` is gitignored (`.gitignore:16`). Rio's earlier "revert working tree to pristine" only restored git-*tracked* files, so the generated `vm.tfvars` came back as the original `enable_overnight_pause = true`. A first read had caught Rio's transient edit; a re-`grep` before editing revealed it had reverted — so the flip was genuinely mine to make. (This is exactly why the operative input must be verified, not taken on faith.)

3. **Audit "auto-starts daily 08:00" was a stale inference.** Live `describe` (read-only) showed the overnight-schedule policy was **not attached** to the instance — only `friday-eod-stop` was. The overnight-schedule existed as a **dangling, unattached resource policy** (from a prior `pause=true` apply), so removing it had zero runtime impact.

4. **`desired_status` cannot express SUSPENDED.** The google provider's `desired_status` supports only `RUNNING`/`TERMINATED`, so Terraform cannot declare a compute instance as created-suspended. The suspended steady state is reached **operationally** (`gcloud compute instances suspend`), not declaratively. No `compute.tf` edit for power state.

5. **lupin repo side confirmed already-paused (no edits)** — `lupin/src/terraform/envs/test/variables.tf`: `model_server_min_instances` default 0 (:55), `model_server_enable_scale_schedule` default false (:79), `vm_power_schedule_enable` default false (:95). Its own doc states this repo can only stop AUTO-resuming the VM; the actual power state lives in terraforming-vms.
