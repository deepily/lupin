## 0. TL;DR — the evidence reshapes the bug

María's headline was **"336 spurious pokes, 336/336 Mr. Radio, pure-idle, ~40 ms micro-burst signature."**
Re-reading the *same* logs by **session-id provenance** (an angle her writeup didn't report) splits that
population cleanly into **two distinct classes**:

| Class | Count | What it actually is | Real fleet poke? |
|---|---:|---|---|
| **1 — Test-log pollution** | **548 / 557** (98.4%) | `test_heartbeat_integration.py` emissions writing to the **production** `hook-events.jsonl` | **No** — nobody's session was poked |
| **2 — Genuine production FP** | **9 / 557** | A **stale, self-declared `work_owed:True` hold** poking via the DECLARED-owed path | **Yes** |

Consequences for the pre-ratified ruling:
- The **"Mr-Radio-only" signature is an artifact** of the test fixture (it monkeypatches the persona to
  `"Mr. Radio 🦉"`). The **real** FP class spans **six personas** (maria ×4, mr-radio ×2, Rachel, Tiffany, Rio).
- The **~40 ms micro-burst signature is the test**, not production. The 9 real FPs are **days apart** — so
  **(B) per-persona debounce does nothing for the real bug**; it only masks Class-1 log noise.
- **(A) structural gate** *does* kill the 9 real FPs by construction — it is the correct real-bug fix.
- The **dominant remediation is stopping the test-log pollution** — that alone deletes 98% of the "FP" rows
  and dissolves the false Mr-Radio/40 ms signature that framed this as urgent.

**Recommendation in one line:** fix the pollution (Class 1) + land the scoped (A) gate (Class 2); **de-scope
(B)** as inert against the real bug (or keep it as a cheap belt — Tiberius's call). Details in §4/§6.

  `sid` set (277).
- The `sidC*` rows fire in **bursts of 3 per pid** (~10 ms apart), each a fresh pid — the signature of one

**Source, pinned:** `src/tests/unit/test_heartbeat_integration.py`
- L5 author banner: *"Mr. Radio 🦉 (integration tester)"*.
- L279: `monkeypatch.setattr( stop, "get_voice_persona", lambda _sid: { "name": "Mr. Radio 🦉" } )` — the exact

- L494/518/562: scenarios drive `stop._run_heartbeat("sidC2"/"sidC3"/"sidC6b", …)`.

**Why it escapes the test's hermeticity:** the test patches `cu.get_project_root` (L277) and the hold/counter/
events dirs — but `hook_common.STREAM_LOG` (`hook_common.py:33-34`) is a **constant evaluated once at import**
against the real `LUPIN_ROOT`. Re-patching `get_project_root` afterward cannot rebind it. So every
`_run_heartbeat` → `log_to_stream(…, phase="heartbeat_oracle")` **appends to the real production log**,
regardless of test isolation. Nobody's session was poked — this is pure log contamination that inflated the
count and manufactured the false Mr-Radio/40 ms signature.

> Note: the once-per-minute cadence of some bursts (e.g. 2026-06-10 12:33→12:36) implies the emitting test was
> invoked repeatedly (a `/loop` or repro harness), not a single pytest run — but the *source of each row* is
> the same unpatchable `STREAM_LOG` write. Cadence ≠ root cause.

## 4. Fix design — reconciling the ruling with the evidence

### Lever P (Class 1 — DOMINANT): make the hook log target test-hermetic
`hook_common.py` should honor an env override for the log dir so tests write to their own tmp path, not
production. Preferred (prod code stays pytest-agnostic):
```python
# hook_common.py — resolve at call time, honor an override
def _logs_dir():
    override = os.environ.get( "LUPIN_HOOK_LOG_DIR" )
    return Path( override ) if override else Path( cu.get_project_root() ) / "io" / "claude_code_hooks" / "logs"
```
`log_to_stream`/`log_payload` call `_logs_dir()` instead of the module constant; the integration test (and any
test driving the emit path) sets `LUPIN_HOOK_LOG_DIR = tmp_path`. Kills 548/557 rows by construction and
dissolves the false Mr-Radio/40 ms signature. **Reversible** (env-gated; default unchanged).
*Alternative considered:* no-op emission under `PYTEST_CURRENT_TEST` — rejected (couples prod logging to pytest,
and would blind any legitimately-under-test emission assertion).

### Lever A (Class 2 — the REAL fix, = the ruling's (A)): structural poke gate
In `decide_heartbeat`, when the ONLY basis for poking is a **stale self-declared `work_owed:True` hold** AND the
oracle sees nothing owed AND no secondary trigger fired → **return `OUTCOME_NOT_OWED`** instead of poking.
This is ruling (A) — "emit poke only if oracle `work_owed` OR a secondary trigger is nonzero" — scoped precisely
to the declared-owed-but-idle case. It never touches honored holds (they already return at step 2) nor
oracle-owed pokes. Kills the 9 real FPs.
*Semantic caveat to flag:* this disables the "a stale `work_owed:True` hold keeps poking" behavior. For a session
whose `awaiting` is `user:*`/`peer:*`/`cadence:*` that is the **desired** outcome (it is blocked-waiting, not
idle-with-owed-work). *Alternative (more invasive, noted not chosen):* treat a stale hold with a
`user:/peer:/cadence:` await as still-blocked and re-honor a grace window rather than suppress. Recommend the
gate (simpler, reversible); defer the grace-rehold to a follow-up if Tiberius wants the softer semantics.

### Lever B (the ruling's (B)): per-persona <1 s debounce — RECOMMEND DE-SCOPE
Evidence: the real FPs are **days apart**, so a <1 s idempotency window is **inert** against Class 2. Its only
live effect is collapsing same-persona micro-bursts — which, once Lever P lands, **do not occur in production**
(they were the test). Keeping it adds a persistent per-persona timestamp store + a cross-session race surface
for **zero real-bug value**. **Recommend: drop (B).** If Tiberius wants a belt-and-suspenders anyway, I'll add a
minimal debounce on the emit — but flagged as symptom-masking, not a fix.

### Minor — `stale_inbound` never populated (0/12891): RECOMMEND PRUNE
The field is logged (`stop.py:1893`) and threaded but never takes a nonzero value. Wiring a stale-inbound
detector is unbuilt scope nobody has asked for. **Recommend: prune** the field from the oracle log + verdict
surface rather than wire it. Defer to Tiberius; not silently expanding scope.
