## 4. Method, and its stated blind spots

15 chunks by subdirectory, each `-q -p no:randomly -p no:cacheprovider --junitxml=<chunk>.xml`, run locally. Chunked deliberately: `pytest_direct` caps at 1200s and bug `8b93bcf5` makes a tier that blows its budget report `0 passed, 0 failed, 1 errors` — a single 8,799-test submission is a coin-flip on that lying zero. Per-chunk XML means a hang localizes instead of erasing the survey.

Counts are read from **junit XML attributes**, never a regex over pytest's terminal output — pytest pads its failure banner to terminal width, so a text splitter silently drops the longest test names and reports the survivors as the universe.

The run **waited 110s** for a peer's in-flight suite to clear before starting; concurrent suites false-RED each other.

**Blind spots, unresolved:**
- Whether a passing test **asserts anything** — the row's own blind spot (b). 8,771 green proves they run and do not raise; it does not prove they are load-bearing.
- Runtime measured on an **idle-ish shared box**; a contended runner will be slower.
- `HF_HOME`-class env gaps beyond the one found — this shell's environment is not the runner's.

## 5. 🔴 A live-store contact, and it was mine

`src/cosa/tests/unit/scripts_tests/test_check_schema_parity.py` connects to **`lupin_db_dev`** and `CREATE DATABASE`s a throwaway on the live dev Postgres.

**This survey executed it.** The junit XML records `TestCheckParityLive::test_in_parity_then_dropped_column_flagged` as **RAN**, not skipped — host `localhost:5432` is open, so `_pg_reachable()` returned true. Zero orphans afterwards, which Mr Radio ruled is the wrong measurement: *"your predicate was 'did it leave junk,' the rule's predicate is 'did it touch.'"* Rick, this morning: *"I absolutely do not want any test touching a live dev data store."*

⇒ **The gate is itself the contact.** `@unittest.skipUnless( _pg_reachable(), … )` opens a connection at **module import**, so *collection alone* touches the DB before a single test runs. **Deleting the test class is not sufficient — the reachability probe goes too.**

⇒ It fires on **any box where host 5432 is open**, which is every dev box. Not a latent edge.

I named this file as a hazard before launching and let it run anyway, having graded it "well-behaved." Escalated; the remedy is Tiffany's, not mine.
