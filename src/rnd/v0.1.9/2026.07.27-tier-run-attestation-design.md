# Durable tier-run attestation — design, and a correction to its own requirement

## 0. Verdict first, and it corrects the brief

The requirement was: *"a durable, recreate-surviving attestation, written somewhere the tests it reports on **cannot** write."*

**The second half is not achievable as stated, and believing it would be worse than knowing it isn't.** Measured:

```
src/cosa/agents/test_suite/job.py, the pytest Popen:
    env={ **os.environ, "LUPIN_ROOT": …, "LUPIN_TEST_PORT": …, … }
```

**The subprocess inherits the ENTIRE app environment.** The `_ENV_VAR_ALLOWED_PREFIXES = ( "TFE_", "BFE_", "LUPIN_TEST_" )` allowlist filters only the **caller-supplied** `env_vars` dict — it does not scrub inheritance. So the tests hold every credential the orchestrator holds, run as the same uid, in the same container, on the same filesystem.

⇒ **There is no store the suite *cannot* write.** A DB table is reachable with the app's own DSN; a bind-mounted directory is reachable with the app's own uid.

⇒ The achievable property is **TAMPER-EVIDENCE, not tamper-proofing**: the suite can still write, but it cannot do so *silently*. Designing to "cannot write" would ship a receipt store whose guarantee is a promise, and the whole point of this row is that we already trusted three instruments that could not deliver what they appeared to.

## 1. What the three blind instruments actually teach

| Instrument | Why blind | Requirement it generates |
|---|---|---|
| host `/tmp` | subprocess runs in the container; artifact lands container-side | the store must be on a **mount**, not a container path |
| container `/tmp` | wiped by every recreate — the most-recreated container on the box | the store must survive `docker rm` |
| `job_history` | `test_suite` was never a job_type; table dead since 2026-05-12 | the writer must be **on the tier's own path**, not a side-channel someone must remember to call |

And `fd0cd863` adds the fourth, which is the sharpest: **the artifact path is writable by the suite it reports on, and a fixture is sitting in it right now** (`line-1..line-6` in `/tmp/integration-latest.log`). Absence was my row; **presence-and-wrong is his**, and it is worse.

## 2. Design

### 2.1 Location — `io/test-suite/attestations/`
`docker inspect` confirms `/mnt/DATA01/…/lupin/io → /var/lupin/io rw=true` is a **bind mount on both containers**. It survives recreate; Krishna already rescued Lane B receipts into `io/test-suite/lane-b-receipts/`. This is the durable home, and it is the same one Rio offered — **one store, not a second parallel scheme.**

### 2.2 Shape — append-only JSONL with a hash chain
One line per tier run, appended by the orchestrator at the point it already computes the result dict:

```json
{ "seq": 412, "job_id": "ts-e69bfbbd", "suite": "integration",
  "started_at": "…", "finished_at": "…", "exit_code": 0,
  "passed": 263, "failed": 0, "errors": 0, "skipped": 4,
  "junit_path": "io/test-suite/artifacts/integration-….xml",
  "junit_sha256": "…", "stdout_sha256": "…",
  "prev_sha256": "<sha256 of the previous line>" }
```

**`prev_sha256` is the load-bearing field.** Anyone may append; nobody can rewrite or delete history without breaking the chain at the edit point. A verifier walks the file and reports the first index where the chain breaks. That converts "the suite could overwrite the receipts" from an undetectable risk into a **detectable event** — which is the honest version of the requirement.

### 2.3 The junit/stdout artifacts move too
`--junit-xml=/tmp/…` becomes `--junit-xml=<io>/test-suite/artifacts/…`, and the stdout log likewise. Otherwise the attestation cites paths that a recreate deletes — a receipt pointing at nothing.

### 2.4 The guard that generalizes `fd0cd863`
A static test asserting **no test module writes under the attestation or artifact roots**, scoped to behaviour (an AST scan for `open(...,'w'|'a')` / `Path.write_*` whose target derives from the artifact root), not a grep for the string. Krishna's defect is exactly this class: the symlink-rotation logic was exercised against the production path instead of a `tmp_path`. A guard here catches the next one at commit time rather than by someone opening the log during triage.

## 3. ⚠️ Its own coverage must not depend on a tier run

Mr Radio's constraint, and it shapes the code: **the writer and the verifier must be unit-testable with no tier, no container, no server.**

- The attestation writer takes a **result dict + a root path**, not a job. Tests call it with `tmp_path` and a hand-built dict.
- The verifier takes a **file path**. Tests build chains in `tmp_path`: valid, broken-at-N, truncated, empty, single-record.
- **Controls that must fail**: a chain with one line edited → verifier reports the exact index; a deleted middle line → reports the break; an empty store → reports "no records", *never* "valid" (an empty store must not read as a clean bill of health — that is this row's own trap).
- ⚠️ **And the 0→N proof stays owed.** Per this row's own hazard list, the instrument must be observed going from zero records to N on a real run before its zeros mean anything. That proof requires a tier run and is therefore **not** part of the unit coverage — it is a separate, explicitly-named acceptance step. Unit-green is not calibration.

---

## 4. What this does NOT do

- It does not make the store tamper-proof (§0). It makes tampering **detectable**.
- It does not answer *"did tier X run before 2026-07-27"* — that evidence is gone and this design cannot recover it. Forward-only.
- It does not fix `job_history`'s 2.5-month silence. Separate question, possibly bigger, deliberately not folded in.
- It does not clean the contaminated `/tmp` logs — that is `fd0cd863`, Krishna's, and it needs the isolation fix regardless of where receipts go next.

## 5. Coordination

`fd0cd863` and this row are two halves of one seam and must not be built twice:
- **Krishna's half**: stop the fixtures writing production paths (isolation, per `2b20a6d6` — no known-bad lists).

The overlap is §2.3 (where artifacts are written) and §2.4 (the guard). **Whoever lands the path change lands the guard with it** — a moved path without a guard re-arms the same defect at the new location, which is today's ordering lesson (`f3b5ecf3`) in a different coat.
