## Layered-pair framing (Tiberius rider)

Levers A and B are a **layered pair, not redundancy**. Lever A requires an **HONORED** hold (`is_honored`: fresh + reasoned). The common case — a Rick-parked manager holding a valid `awaiting:user:*` hold — never pokes at all, suppressed by Lever A from episode 1. But the **expired-hold class** (an `is_honored=False` hold — the exact shape today's HOOK-side 9-FP fix `4162e89d` targets, a stale self-declared hold) falls THROUGH Lever A (not honored → `_session_awaiting_user` returns False) and is instead governed by Lever B's cross-episode velocity: if such a session is nonetheless alive-on-a-cadence (last-signal advancing), Lever B suppresses it; if it's genuinely frozen, both levers correctly let the poke fire. Lever C is orthogonal (the peer-manager `-r2` duplicate, receipt-side).

## TL;DR

The arbiter's `_check_manager_staleness` (`src/cosa/agents/heartbeat_arbiter/arbiter_job.py:3746`) keys pokeability on wall-clock last-signal age alone. Three seams let a **legitimately-parked, alive-on-a-cadence** manager read as "stale/dark", producing false MANAGER-STALE pokes + Rick advisories and duplicate `-r2` peer-manager advisories. This is the ARBITER-side analog of today's HOOK-side Lever A (`4162e89d`, stale-declared-owed). The fix is **three narrow, independently-inert, OBSERVABLE suppressions** — each with a distinct log outcome (never silent), mirroring the Lever-A pattern María's watch audits.

Today's live evidence (Rick at an appointment, per broadcast `d9c84756`): mr radio false-poked across **four** episodes — 13:08 → 13:59 → 14:59 → 15:59 last-signals — every one benign, his last-signal **advancing every hour** while Rick-parked.

## Why the existing suppressions miss it

`_check_manager_staleness` already suppresses on FOUR signals: persona-twin (live_personas, `:3829`), bridge-mtime veto (`26dd3afb`, `:3880`), store-health degraded (`33949e83`, `:3951`), and owed_class `CLASS_BLOCKED_ON_USER` / `CLASS_DONE` (`:3918` / `:3932`). None catches the evidence:

- **owed_class BLOCKED_ON_USER reads the STORE, not the hold.** Per `_session_awaiting_user`'s own docstring (`:3469`), the `6929f4ac` open-gate override **reclassifies an awaiting-user session as `CLASS_ACTIVE`** in owed_class (it owes Rick a *re-ask*, so it must not go dark). So a manager parked awaiting Rick's gate answer is classified `CLASS_ACTIVE` → falls straight into the case-14 poke path (`:3946`). **This is episode 2 exactly** (mr radio parked awaiting Rick's gate answer, re-deferring on the defer_to_chase cadence).
- **bridge-mtime veto** only fires when the hooks-driven bridge mtime is *sub-threshold fresh*. A manager on a **45-min-slower wake-tick-park rhythm** (freshens hourly, then quiet ~45m) sits above the veto's freshness window at poke time — the veto can't see the hourly cadence.
- **persona-twin** only catches a live twin under a *different* sid — mr radio is the SAME sid, just quiet.

So the detector has no hold-side awaiting-user check, and no cross-episode velocity memory. Two gaps → two levers; a third lever fixes the coupled `-r2` duplicate.

## The three levers (Tiberius pre-ratified scope)

### Lever A — HOLD-GATING (honored awaiting-user hold ⇒ suppress case-14)

**Locus**: `_check_manager_staleness`, the eligible-row loop, in the ACTIVE/UNKNOWN path — a new guard placed AFTER the `CLASS_DONE` branch (`:3945`) and BEFORE the `store_read_degraded` gate (`:3951`), so a defended hold (ground-truth from the hold artifact) wins over an infra-degradation read.

**Mechanism**: reuse the existing, proven `_session_awaiting_user( sid, now )` (`:3459`) — True iff the session carries a **fresh honored hold** (`is_honored`) that EITHER declares `awaiting: user:*` OR holds ≥1 OPEN `pending_user_gate`. This is the SAME helper `_check_fleet_stall` already uses (`423f04a5`, `:3361`) — the hold-side dual of the store-side BLOCKED_ON_USER.

```python
# Lever A (item 285c0343): the HOLD-side analog of the owed_class BLOCKED_ON_USER
# branch above. owed_class reads the STORE, where the 6929f4ac open-gate override
# reclassifies an awaiting-user session as CLASS_ACTIVE (it owes Rick a re-ask) —
# so a manager parked awaiting Rick's gate answer reaches HERE classed ACTIVE and
# would draw the case-14 poke (episode-2 false positive). The awaiting-user truth
# lives ONLY in the hold artifact; read it. A fresh honored hold declaring
# awaiting:user:* (or holding an open user-gate) => defended quiescence, NOT stale.
# Emit AT MOST ONE case-16 advisory (SHARED _manager_blocked_advised set → cross-
# detector de-dupe, no Rick double-page) and suppress the repeating case-14 poke.
# Inert when the hold-reader seam is unwired (returns False → today's behavior).
if self._session_awaiting_user( sid, now ):
    # Q1 rider (Tiberius): the suppression log row carries the hold's awaiting string
    # AND (gates present) the soonest open-gate next_chase_ts — ONE outcome,
    # distinguishable post-hoc for María's audit, via a best-effort single-read helper.
    _facets = self._awaiting_user_hold_facets( sid )
    self._log( "arbiter_manager_stale_suppressed_awaiting_user_hold",
               session_id=sid, persona=persona, freshest_age_s=age,
               awaiting=_facets.get( "awaiting" ),
               soonest_next_chase_ts=_facets.get( "soonest_next_chase_ts" ) )
    if persona not in self._manager_blocked_advised:
        self._manager_blocked_advised.add( persona )
        self._mgr_stale_suppressed[ sid ] = ( CLASS_BLOCKED_ON_USER, persona )
        self._route( CASE_MANAGER_AWAITING_USER,
                     f"MANAGER-AWAITING-RICK (advisory, NOT manager-stale): {persona} is "
                     f"silent {_fmt_minutes( age )} but its honored hold declares it PARKED "
                     f"awaiting Rick — defended quiescence, not a stall. One-time notice, no poke.",
                     active_managers=active_managers, exclude_persona=persona )
    continue
```

- **Observability**: distinct log outcome `arbiter_manager_stale_suppressed_awaiting_user_hold` — never silent.
- **Re-arm**: reuses `_mgr_stale_suppressed[sid] = (CLASS_BLOCKED_ON_USER, persona)`, so the EXISTING re-arm loop (`:3902`) clears `_manager_blocked_advised` when the manager freshens below threshold → a future episode re-notifies once.
- **Cross-detector de-dupe**: the SHARED `_manager_blocked_advised` set is also consulted by `_check_manager_acks`, so a manager that is both tapped and awaiting-user is advised at most once (no Rick double-page).
- **next_chase_ts refinement (item scope 1b)**: `_session_awaiting_user` returns True for ANY open gate, which *already* covers the defer_to_chase case (a gate mid-chase is open). The `next_chase_ts` scheduled-chase cadence is thus honored transitively: an open gate on a future `next_chase_ts` is still an OPEN gate → awaiting-user → suppressed. No separate `is_chase_deferred` call is needed in the staleness path (it would narrow, not broaden, the suppression). We document this equivalence rather than add a redundant check. **← flag for Tiberius: confirm this is the intended read, or do you want an EXPLICIT `is_chase_deferred`-gated distinct outcome for observability?**

### Lever B — LAST-SIGNAL VELOCITY (N advancing episodes ⇒ alive-on-a-cadence ⇒ suppress)

**Locus**: `_check_manager_staleness`, at the episode-start branch (`:3955`, `if sid not in self._mgr_stale_since`). An "episode" begins each time an eligible manager re-crosses threshold after freshening (episode state is cleared on freshen by the `:3894` loop). The velocity signal must persist ACROSS episodes → new PERSONA-keyed state (survives the per-sid episode clear + re-spins), NOT cleared on freshen.

**New instance state** (init beside `_mgr_stale_since` at `:1060`):
```python
self._mgr_last_signal_seen  = { }   # persona -> last-signal datetime captured at the prior episode
self._mgr_velocity_streak   = { }   # persona -> count of consecutive episodes whose last-signal ADVANCED
```

**New constructor kwarg** (beside `manager_stale_poke_threshold_seconds`, `:603`): `manager_stale_velocity_suppress_streak : int = 2` — after this many consecutive advancing episodes, suppress. Default 2 applies live with **no factory/INI/splainer change** (the factory uses defaults for unspecified kwargs) → minimal blast radius on shared infra. `0` disables the lever (validated `>= 0`).

**Q2 rider (Tiberius) — INI promotion is the follow-on trigger**: this ships as a **ctor default, NOT an INI key day-one**. That deliberately differs from today's monopolize kill-switch (which got gate-time INI because it toggles BEHAVIOR): a numeric streak threshold is a **tunable, not a safety switch**. IF live tuning is ever wanted, the follow-on is the standard three-step — add the INI key, its splainer entry, and the `:8001` factory wiring — at which point the ctor default becomes the fallback. Recorded here so a future reader knows the promotion path exists and why it wasn't taken now.

**Mechanism** (evaluated at episode start, computing `last_seen = now - age`):
```python
if sid not in self._mgr_stale_since:
    self._mgr_stale_since[ sid ] = now
    self._mgr_poke_count[ sid ]  = 0
    # Lever B (item 285c0343): last-signal VELOCITY across episodes. A manager whose
    # last-signal ADVANCED since the prior episode is alive on a wake-tick-park rhythm
    # SLOWER than the 45m threshold (mr radio 13:08→13:59→14:59→15:59, four false
    # episodes, all advancing) — definitionally NOT stale. Track the streak of
    # consecutive advancing episodes; at >= the suppress threshold, this episode is
    # alive-on-a-cadence → suppress. A NON-advancing episode (last-signal frozen =
    # genuinely wedged) RESETS the streak → the real-stall true positive still pokes
    # (Tiberius: "an episode with a NON-advancing last-signal — that one would be real").
    last_seen = now - datetime.timedelta( seconds=age )
    prior     = self._mgr_last_signal_seen.get( persona )
    if prior is not None and last_seen > prior:
        self._mgr_velocity_streak[ persona ] = self._mgr_velocity_streak.get( persona, 0 ) + 1
    else:
        self._mgr_velocity_streak[ persona ] = 0
    self._mgr_last_signal_seen[ persona ] = last_seen
if ( self.manager_stale_velocity_suppress_streak > 0
     and self._mgr_velocity_streak.get( persona, 0 ) >= self.manager_stale_velocity_suppress_streak ):
    self._log( "arbiter_manager_stale_suppressed_velocity",
               session_id=sid, persona=persona, freshest_age_s=age,
               advancing_streak=self._mgr_velocity_streak.get( persona, 0 ) )
    continue
```

Placement: AFTER the episode-start bookkeeping (so the streak is updated every episode) but BEFORE the Rick advisory + poke emission (`:3958`), so a velocity-suppressed episode opens its episode counter (for re-arm symmetry) yet fires neither advisory nor poke.

- **Streak semantics vs the evidence**: ep1 (13:08) no prior → streak 0, poke fires (first episode is legitimately unknown). ep2 (13:59 > 13:08) → streak 1. ep3 (14:59 > 13:59) → streak 2 ⇒ suppressed. ep4 (15:59) → still suppressed. So the FIRST episode still nudges (correct — a manager that just went quiet once may genuinely need it); the hourly cadence is learned by episode 3. This is the "halve-rate → suppress" Tiberius asked for.
- **Observability**: distinct log `arbiter_manager_stale_suppressed_velocity` with `advancing_streak` — never silent.
- **Bounded state**: both dicts are persona-keyed (fleet-manager cardinality — tiny); a non-advancing/frozen episode resets the streak so a genuinely-stuck manager is never permanently muted.

**⚠ Ordering interaction with Lever A**: place Lever A's `continue` BEFORE Lever B's episode-start block, so an awaiting-user manager is suppressed by the more-specific hold signal (distinct log) and never perturbs the velocity streak. Lever B then only governs ACTIVE/UNKNOWN managers with no defended hold.

### Lever C — `-r2` RESEND ACK-BY-ACTIVITY (active peer manager ⇒ implicit ACK ⇒ no duplicate)

**Locus**: `_check_outreach_receipts` (`:1902`), the resend gate at `:1968`. The `-r2` is the arbiter's INTENTIONAL one-shot resend of an un-ACK'd manager-bound advisory (prior art: `src/rnd/v0.1.9/2026.06.30-arbiter-false-blocked-live-peer-and-r2-echo.md` — the resend is a milestone-must-land mechanism, **NOT a dup bug; do not delete it**). Today it fires whenever the recipient hasn't posted a *threaded reply* and isn't confirmed-offline. An **actively-building peer manager** posts no threaded reply → gets the duplicate.

**Fix**: make demonstrable recipient ACTIVITY since delivery count as an implicit ACK — the recipient clearly hasn't gone dark and needs no duplicate advisory. Signal = the SAME persona-keyed bridge-mtime map the MANAGER-STALE veto uses (`_read_manager_bridge_mtimes`, `:2640`), already computed each poll at `:1197` (`manager_bridge_mtimes`) and IN SCOPE at the receipts call site (`:1276`). All ack-tracked recipients are managers (every `expects_ack=True` route targets a manager — TIER_RICK_AND_MANAGERS / TIER_OWNING_MANAGER / the cc leg), so the manager-only bridge map covers them.

**Thread the map in** — call site `:1276`:
```python
outreach_acks = self._check_outreach_receipts(
    now, offline_personas=self._confirmed_offline_personas(),
    bridge_mtimes=manager_bridge_mtimes )
```

**New helper**:
```python
def _recipient_active_since( self, persona, sent_at, now, bridge_mtimes ):
    """Lever C (item 285c0343): did the recipient show ground-truth activity since we
    delivered? A fresh bridge mtime in [sent_at, now] means the peer manager took a
    turn (any hook fire — DM/task/hold write rides a turn) AFTER delivery → it is
    demonstrably active, not dark → an implicit ACK; the one-shot -r2 is redundant.
    Fail-SAFE: unwired seam (None), absent persona/mtime, or a future-skewed mtime
    outside [sent_at, now] → False → today's resend behavior (never drop a genuine
    escalation). Mirrors the 26dd3afb veto's [lower, upper] bound discipline."""
    if not bridge_mtimes or not persona:
        return False
    mt = bridge_mtimes.get( canonical_persona_key( persona ) )
    if mt is None:
        return False
    return sent_at.timestamp() <= mt <= now.timestamp()
```

**Wire it into the receipt loop** — inserted AFTER the ack-window check (`:1963`) and BEFORE the resend gate (`:1968`), so it only pre-empts the `-r2`, never the explicit-reply ACK above it:
```python
# Lever C: an active peer manager (fresh bridge mtime since delivery) has
# demonstrably ACKed via activity — close ACKED, distinct receipt outcome, and
# skip the redundant -r2. Distinct from the threaded-reply ACK above (explicit)
# and the offline suppression below (which closes UNACKED + queues a Rick note).
if self._recipient_active_since( state[ "persona" ], state[ "sent_at" ], now, bridge_mtimes ):
    latency = ( now - state[ "sent_at" ] ).total_seconds()
    self._log_outreach_receipt( outreach_id, state[ "kind" ], state[ "persona" ],
                                "acked_by_activity", latency_s=int( latency ) )
    del self._awaiting_ack[ outreach_id ]
    acked += 1
    continue
```

- **Signature change**: `_check_outreach_receipts( self, now, offline_personas=None, bridge_mtimes=None )` — the new kwarg defaults None → fully inert (byte-identical to today) when unwired; only the `:1276` call site passes it.
- **Observability**: NEW distinct receipt outcome `acked_by_activity` (vs `acked` explicit-reply, `unacked` offline/exhausted) — María's audit sees exactly why a `-r2` didn't fire.
- **Scope guard**: the resend MECHANISM (`_emit_dm -rN`), the Fix-3 offline suppression, and the milestone-must-land Rick note are all UNTOUCHED. This only adds a positive-ACK short-circuit; a genuinely-dark un-ACK'd advisory (no activity, not offline) still resends exactly once, then queues for Rick.
