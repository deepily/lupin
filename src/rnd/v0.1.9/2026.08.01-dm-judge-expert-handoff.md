## 0. TL;DR

We built a small LLM-as-judge that grades peer-to-peer agent messages on two subjective
dimensions (Directness, Tone) using a locally-served 24-billion-parameter quantized
Mistral. It does not grade. Across every prompt configuration we tried, it returns a
**near-constant** answer regardless of the message it is given — and in the original
configuration it returned the prompt's own example justification text verbatim for a
message that example did not describe. A rewritten few-shot prompt made it separate
"good" from "not good" and nothing further; it never reaches the negative half of a
five-level scale.

**Two disclosures belong at the top, before any number below is read:**

1. **Our measuring instrument was itself defective, and was still live while we reported
   findings from it.** When the judge cannot parse the model's output it falls back to a
   neutral result with **weight 0**. A real middling grade (`meh`) is **also weight 0**.
   Our probe compared weights only, so *every* measurement in this document may contain
   an unknown number of parse failures wearing the costume of a real neutral grade. A
   fix exists and is cheap (see §6.1) but has not been applied yet.
2. **We caused a second, separate defect and have not fixed it.** The rewritten prompt
   dropped a trailing structural example. The live model now sometimes emits malformed
   XML — it opens `<directness>` twice and never closes it — all three retries fail, and
   the dimension silently becomes the weight-0 fallback from disclosure #1. The two
   defects compound: the thing that makes measurements untrustworthy is now firing more
   often because of a change we made.

**What we are asking for**: a judgement on whether this task is achievable with a model
of this class and how, or whether we are attacking it the wrong way — see §7.

> ⚠️ **READ PART III FIRST IF YOU READ NOTHING ELSE.** After §0–§10 were written we
> restored the response-format machinery this prompt had been missing all along, and the
> picture changed materially: **the grades are honest; the envelope is what fails.** Part
> III also adds the single most useful fact in this document — **a smaller 8B model on the
> same machinery emits 100% compliant XML** — and reframes the question we are asking you
> from "can it grade?" to "what output format should we be using?"

## 2. Observable symptoms

### 2.1 Symptom A — constant output regardless of input (original prompt)

Two fixed messages, deliberately opposite on both axes, both kept under a 150-word
ceiling (past that ceiling the code skips the model entirely, so a longer probe would
have measured nothing). Three runs each, live model:

| run | body | directness | tone |
|---|---|---|---|
| 1 | GOOD (45 w) | `good` (1) | `needs_improvement` (−1) |
| 1 | BAD (78 w) | `good` (1) | `needs_improvement` (−1) |
| 2 | GOOD | `good` (1) | `needs_improvement` (−1) |
| 2 | BAD | `good` (1) | `needs_improvement` (−1) |
| 3 | GOOD | `good` (1) | `needs_improvement` (−1) |
| 3 | BAD | `good` (1) | `needs_improvement` (−1) |

Six for six identical. `(good, needs_improvement)` was exactly the label pair sitting in
the prompt's structural example.

### 2.2 Symptom B — the justification text is copied verbatim

Identical *grades* could be coincidence. Identical *justifications* cannot. Raw model
output for the **BAD** body (a rambling message with no verdict anywhere):

```
< directness > good < / directness >
< directness note > Leads with the verdict in the first sentence. < / directness note >
< tone > needs_improvem...
```

That sentence is the example's own note, byte-for-byte, describing a message that is not
the one being graded. Reproduced for the 45-word GOOD body, the 78-word BAD body, and
for the single word `yes`.

A fourth input — `"um so like anyway whatever i guess maybe it happened somehow you know"`
— did move, to `meh`, with the note *"The result is present but buried under a sentence
or two of setup."* That string is lifted verbatim from the **rubric's** `meh` anchor in
the same prompt file, and does not describe that input either. So the copying is not
specific to the example block; it copies whichever span of prompt text is nearest to
plausible.

### 2.3 Symptom C — malformed XML after our prompt rewrite (the defect we caused)

Raw output on some bodies under the current live prompt:

```
<response><directness>meah <directness>
```

The opening tag is emitted twice and never closed; the label is misspelled. All three
retries produce the same shape, the parse fails, and the dimension degrades to the
weight-0 "judge unavailable" fallback. Note also `meah` — the model does not reliably
reproduce the five label spellings even when the prompt lists them twice.

### 2.4 Symptom D — spaced labels (found and fixed, included for pattern)

The model emits `needs _ improvement` (spaces around the underscore). Our normalizer did
two sequential replaces, producing `needs___improvement`, which is not in the grade table,
so it silently degraded to the neutral fallback. Every occurrence of the most common
multi-word label in the scale was being discarded and published as a considered neutral.

Fixed by collapsing runs of whitespace/hyphen/underscore:

```python
key = re.sub( r"[\s_\-]+", "_", str( label ).strip().lower() ).strip( "_" )
```

This is included because it shows the model's *formatting* compliance is as shaky as its
*judgement*, and because the fallback that hid it is the same one in disclosure #1.

## 3. Evidence — code, verbatim

### 3.1 The fallback that makes measurement unreliable

`src/cosa/agents/dm_quality_judge/judge.py:339`

```python
def _fallback_dimension():
    """A safe neutral dimension result (meh/0) — used when the judge is unavailable."""
    return { "emoji": "🤷", "weight": 0, "detail": _JUDGE_UNAVAILABLE_DETAIL }
```

`_JUDGE_UNAVAILABLE_DETAIL = "judge unavailable"` (`judge.py:45`). A real `meh` grade is
also weight 0. The two are distinguishable **only** by the `detail` string, which our
probe ignored.

There are now three distinct weight-0-or-None non-answers, which is itself part of the
story:

| condition | emoji | weight | detail |
|---|---|---|---|
| parse/model failure | 🤷 | `0` | `"judge unavailable"` |
| body over 150 words | 🤷 | `0` | `"not judged: DM too long ... (277 words > 150)"` |
| feature switched off | 🚫 | `None` | qualitative-off marker |

Only the third was designed to be un-averageable. The first two sit in the same value
space as a real opinion.

### 3.2 The live prompt

`src/conf/prompts/dm-quality-judge.txt` — 92 lines. Structure: `### Instruction:` (role) →
`### Task:` (both rubrics, five anchors each) → `### Worked examples:` (two fully-graded
contrasting DMs) → `### Input:` (`{dm_body}`) → `### Response Format:` (six explicit
rules) → `### Response:`.

The two worked examples deliberately disagree with each other so neither can serve as
"the answer", and the first one scores **differently on the two dimensions**
(`exemplary` directness, `needs_improvement` tone) to teach that the axes are
independent. The Response Format block explicitly forbids the exact failure modes we
observed:

```
- No spaces inside the angle brackets: write `<directness>`, never `< directness >`.
- No spaces inside a label either: write `needs_improvement`, never `needs _ improvement`.
- Each grade is EXACTLY one of the five labels, spelled exactly: terrible, needs_improvement, meh, good, exemplary.
- Both notes must describe the DM in the Input section above — never either example.
- Grade Directness and Tone INDEPENDENTLY.
```

**The model violates every one of these instructions on some inputs.**

## 4. Things we ruled out by measurement (so the expert does not re-run them)

| Hypothesis | How it was killed |
|---|---|
| The template is not assembling — the DM never reaches the model | Dumped the final prompt string with a sentinel in place of the body. Substitution and injection both correct; the DM sits directly above the response block. |
| The instruction *"Copy this structure exactly"* is being obeyed literally | Rewrote that line alone to say the example is shape-only. Output unchanged, 3×3. Edit reverted. |
| It is the known long-input parroting bug, already contained by a 150-word gate | Probe bodies are 45 and 78 words. The gate never fired; the model was genuinely called every run. The containment was placed at the edge of the *observed evidence*, not the edge of the mechanism. |
| Changing the example fixes it | Three example variants tested at n=3: current pair → constant `(1,−1)`; implausible pair (`terrible`/`exemplary`) → a *different* constant `(0,+1)`; self-identifying notes → tone separates, directness does not. Changing the example moves **where** the constant sits, not **whether** there is one. |
| Splitting into one LLM call per dimension decouples them | Tested with examples held byte-identical across both arms: **6/9 doubled grades in both arms.** No effect. (An earlier run suggested it worked; that run changed the call structure *and* the examples together. Withdrawn.) |

## 5. What the current prompt measured — with the §0 caveat attached to every number

Live model, 3 runs per body, 2×2 sample (`{verdict leads, verdict buried}` ×
`{plain prose, jargon}`), each dimension scored only against the pair that varies it:

```
DIRECT_PLAIN    directness  1    tone  1
DIRECT_JARGON   directness  0    tone  0
BURIED_PLAIN    directness  0    tone  0
BURIED_JARGON   directness  0    tone  0
```

It recognizes exactly **one** of four cells: the message that is both direct and plainly
written. Hold the prose jargony and it cannot tell a leading verdict from a buried one;
bury the verdict and it cannot tell plain prose from jargon. Nothing reaches the negative
half of the scale — a five-level rubric collapsing to a two-level signal.

⚠️ **Every `0` in that table is ambiguous** between a real `meh` and a parse failure,
because of §3.1. Read it as *what the instrument said*, not as truth. The same asterisk
applies to all measurements in §2 and §4.

## 6. Candidate solutions, ranked

### 6.1 Fix the instrument first (not optional, and not a solution to the judge)

Make the probe compare `detail` strings, not just weights. A fallback names *itself*
(`"judge unavailable"`); a real grade names something *in the text* (*"Leans on an
aphorism instead of plain phrasing"*). The field already exists — today's raw
measurements can be re-classified rather than discarded. **Do this before trusting any
number in this document.** Cost: hours. Benefit: none to the judge; everything to our
ability to tell whether a later fix worked.

### 6.2 Option 1 — restore well-formedness without restoring the attractor

Put a **structural** example back in the last position before `### Response:` — tag shape
with obviously-non-answer placeholder content (e.g. `<directness>LABEL_HERE</directness>`)
rather than a filled, plausible grade.

- ✅ Directly targets the regression we caused; cheapest real fix.
- ✅ Testable in one probe run.
- ❌ May reintroduce copying in a new costume; we have already seen the model copy the
  *rubric* when the example was unattractive.
- ❌ Does nothing about the constant-output problem underneath.

### 6.3 Option 2 — constrained decoding / structured output

Force the five labels with a grammar or JSON-schema-constrained decode at the vLLM layer,
eliminating the XML and spelling failure classes entirely.

- ✅ Removes symptoms A-formatting, C and D by construction; no prompt wording can.
- ✅ vLLM supports guided decoding natively.
- ❌ Does **not** fix judgement quality — a constrained decoder will happily emit a
  well-formed constant.
- ❌ New dependency on serving-layer features; changes the response contract.

### 6.4 Option 3 — a bigger or different model

The hypothesis nobody has tested: a 24B GPTQ-quantized checkpoint may simply not do
subjective two-axis ordinal grading.

- ✅ Would settle whether this is a *task* problem or a *model* problem — currently the
  single largest unknown.
- ❌ We have not tested it. One attempt against a hosted external model was made and
  stopped by the project owner (billed external API, not authorized).
- ❌ If a larger model is needed, the cost/latency profile of grading every message
  changes the feature's viability.

### 6.5 Option 4 — fine-tune a small model on labelled examples

The fleet already runs fine-tuned LoRA adapters for routing, and the training pipeline
exists (`src/cosa/training/peft_trainer.py`). The judge prompt already matches the
Alpaca-style template the training data generator emits.

- ✅ Best long-term fit; the task is narrow and stable.
- ✅ Owner has explicitly claimed this as his own side project.
- ❌ **Gating unknown: nobody has counted how many labelled examples exist.** The
  pipeline is not the risk; the corpus is.
- ❌ Longest lead time.

### 6.6 Option 5 — do nothing / keep the qualitative half off (the status quo)

Keep the Python-computed Length grade, which is deterministic, has never been in doubt,
and is unaffected by all of the above. Drop Directness and Tone.

- ✅ Zero risk; already the shipped state; removes the entire defect class and the LLM call.
- ❌ Loses the signal the feature was built for. Length alone rewards short messages, not
  clear ones.
- **This is what happens if nothing else is decided**, so it is on the list honestly
  rather than as a straw man.

## 7. Questions for the expert

1. **Is two-axis, five-level subjective grading a reasonable ask of a 24B quantized
   instruct model at all?** If not, what is the smallest model class that does it
   reliably — and is the answer different for *ordinal* grading versus *binary* grading?
2. Every prompt variant we tried lands on a near-constant. Is that a known failure mode
   for a task shaped like this (one subjective judgement, few-shot, ordinal), and is the
   standard remedy to change the **task shape** (e.g. pairwise comparison instead of
   absolute grading) rather than the wording?
3. Would **pairwise ranking** ("which of these two is more direct?") work where absolute
   grading fails — and can a usable absolute score be reconstructed from pairwise
   judgements without an unreasonable number of calls?
4. Our worked examples contrast with each other and still get copied. Is there a
   positioning or formatting convention that reliably stops an instruct model from
   treating the last-shown answer as its own?
5. Would guided/constrained decoding be the right layer for the label-vocabulary problem,
   or does forcing the output shape tend to *mask* judgement failures by making a constant
   look well-formed?
6. `temperature = 0.0`: correct for a judge, or is some sampling actually necessary to
   break out of a copied-example attractor?
7. If fine-tuning is the answer — roughly how many labelled examples per dimension would
   you expect to need for a five-level ordinal judge of this kind?

# PART III — the response-format machinery was missing, and that reframes the question

*Added 2026-08-01, late afternoon, after §0–§10. Everything below was measured after
restoring a mechanism this prompt should have had from the start. It changes what we
think is wrong, and therefore what we are asking you.*

## 11. What we found: this repo already has a round-trip contract, and the judge wasn't using it

Every other LLM-driven agent in this codebase injects its expected response shape into
the prompt via a marker, `{{PYDANTIC_XML_EXAMPLE}}`, which is replaced at runtime by:

```python
# prompt_template_processor.py:91-92
example = model_class.get_example_for_template()
return example.to_xml()
```

**The same Pydantic model that parses the response generates the example.** The prompt's
example is therefore well-formed by construction and structurally identical to what the
parser accepts. Ten prompts in this repo use it. The judge's prompt did not — the marker
had been removed, leaving `### Response:` as the last line of the file with nothing after
it, and six English sentences describing the format in prose instead.

Two further details of the mechanism turned out to matter:

1. **A `</stop>` sentinel is appended to the injected example**
   (`prompt_template_processor.py:123`), and `</stop>` is a configured stop sequence in
   the model's sampling params. **The model learns where to terminate by seeing the
   terminator in the example.** With no example, the judge's model had no terminator to
   imitate — which is why it ran to `max_tokens` emitting the same clause ~30 times.

2. **The example content in working agents is placeholder prose, not a filled answer** —
   `<thoughts>Your thoughts</thoughts>`, `<idea1>Your first idea</idea1>`. The judge's
   version had been made *concrete* (`<directness>good</directness>` +
   `"Leads with the verdict in the first sentence."`) after an earlier attempt with a
   bracketed enum hint (`[one of: terrible, ...]`) was echoed verbatim as malformed XML.
   Both extremes fail, for different reasons: bracket-enum syntax is not prose, and a
   plausible grade is a usable answer. Descriptive prose is neither.

⇒ **§2.2's "it copies the example's note text" and §2.3's "it emits unclosed tags" were
the same omission seen from two sides.** With a filled example present, the model copied
it. With no example at all, the model lost well-formedness. Neither state ever had the
thing the other ten agents have.

## 12. What we changed, and what the model did

Prompt rebuilt to match the working precedent exactly: four Alpaca headers only
(`Instruction` / `Task` / `Input` / `Response`), the marker restored inside `### Input:`
under *"You MUST respond to the directives above using the following XML format:"*, the
DM restated after it, and the prose rules list deleted. `get_example_for_template()`
rewritten to return placeholders.

**The example now injected into the prompt:**

```xml
<?xml version="1.0" encoding="utf-8"?>
<response>
	<directness>Your directness grade</directness>
	<directness_note>Your one-sentence reason for the directness grade</directness_note>
	<tone>Your tone grade</tone>
	<tone_note>Your one-sentence reason for the tone grade</tone_note>
</response></stop>
```

**The complete, verbatim response** (45-word DM that leads with its verdict):

```
<?xml version="1.0" encoding "utf-8" ?>
< response >
	< directness > meah 100% of the message is a decision, but it is buried in a sentence of setup. </ directness > < tone > good 100% of the message is plain, but the last sentence is a flourish. </ tone > < / response >
```

| Behaviour | Before (no example) | After (round trip restored) |
|---|---|---|
| Ran to `max_tokens` | yes — 486 tokens, one clause repeated ~30× | **no, it terminated** |
| Closed its tags | no | **yes** |
| Copied the example's content | n/a (nothing to copy) | **no** |
| Emitted `<directness_note>` / `<tone_note>` | sometimes | **no — collapsed into the grade tag** |
| Spaces inside angle brackets | yes | yes |
| Label spelled correctly | `meah` | `meah` |
| XML declaration well-formed | n/a | **no — `encoding "utf-8"`, missing `=`** |

Two problems fixed, two new ones exposed, and one that has never moved.

**The collapse is the most informative failure.** Asked for four sibling elements, it
produced two, each containing a grade *and* its justification as one run of text. It did
that consistently. A plausible reading is that a grade and its reason are one thought to
the model, and a four-sibling schema fights that — but we have not tested a two-element
schema, so this is a hypothesis, not a finding.

**The dropped `=` in `encoding "utf-8"` is the tell we find hardest to explain away.**
That character is present in the example directly above it in the prompt. Producing
almost-correct-but-not-quite XML while copying from a correct sample in-context is not a
comprehension failure — it looks like a token-level fidelity problem.

## 13. The single most useful fact we can give you

**A smaller 8B model, on this same machinery, emits 100% compliant XML.**

Same repo, same `{{PYDANTIC_XML_EXAMPLE}}` round trip, same prompt-format family
(`instruction_completion`), same parsers. It just works there. The failing model is the
*larger* one — `Mistral-Small-3.2-24B-Instruct-2506-**GPTQ-AutoRound**`, a quantized
checkpoint.

That inverts the natural assumption. This is very likely **not** "the task is too hard for
a small model." A 24B that cannot reliably close a tag, spells `meah` for `meh`, and drops
the `=` from `encoding=` while a correct example sits in its context is exhibiting
**format fidelity** damage, not reasoning damage — and quantization is the obvious
suspect. We have not tested that hypothesis. We are naming it because it changes what
question is worth asking.

**Supporting evidence that judgment is intact.** On the runs that *do* parse, the grades
are honest and specific to the message:

> `directness: good` — *"The first sentence is 'Phase 1 is done and green. 89 unit tests
> pass, 100% lines and branches on the changed file.' The rest of the message is a
> decision, evidence, or a required action."*
> `tone: good` — *"'Not committed' is a minor flourish."*

That is a correct reading of the actual DM, not copied text. The model can do the job. It
cannot reliably produce the envelope.

## 14. So the question we are actually asking you has changed

§7 asked whether a 24B can do subjective ordinal grading. Part III suggests that was the
wrong question. The one we would rather you answer:

**Given a model that grades correctly but cannot reliably emit a structured envelope,
what is the right output format?** Three candidates, and we have no attachment to any of
them:

### 14.1 Stay on XML, fix the schema shape
Collapse to two elements (or make the note an attribute) to match what the model keeps
trying to do anyway.
- ✅ Cheapest; no infrastructure change; keeps every existing parser.
- ✅ Directly targets the observed collapse.
- ❌ Does nothing about spaced brackets, `meah`, or the dropped `=`.
- ❌ Would be our fifth prompt shape today. Each previous one failed differently.

### 14.2 Switch this agent to JSON
- ✅ JSON is far better represented in instruct-tuning data than XML; models of this class
  are generally more reliable at it.
- ✅ Strict, unambiguous, and a malformed JSON is *loudly* malformed rather than
  half-parseable.
- ✅ Composes with 14.3 — vLLM's guided decoding is strongest for JSON schema.
- ❌ Breaks this repo's XML convention for one agent; the `BaseXMLModel` round trip would
  need a JSON sibling.
- ❌ Untested here; the format-fidelity damage might follow it.

### 14.3 Constrained (guided) decoding at the serving layer
Enforce the shape in the sampler rather than requesting it in prose — see §15.
- ✅ Eliminates the entire malformed-output class **by construction**. Spaced brackets,
  unclosed tags, `meah`, and the dropped `=` all become impossible, not unlikely.
- ✅ Already supported by vLLM, which is what we serve on.
- ❌ **Does not improve judgment** — a constrained decoder will emit a well-formed
  constant just as happily. It fixes the envelope, not the grade.
- ❌ Small latency cost, and it can distort output if the grammar fights the model's
  natural phrasing.
- ⚠️ **It also masks the diagnostic.** Today the malformed XML is *how we know* something
  is wrong with this checkpoint. Constrain the output and that signal disappears while the
  underlying fidelity problem remains — which matters if the same model is doing other
  work in this fleet.

### 14.4 Change the model
Move this agent to the 8B that already emits compliant XML, or to a non-quantized 24B.
- ✅ The only option that tests the quantization hypothesis instead of working around it.
- ✅ If the 8B grades acceptably, the entire problem disappears with no code change.
- ❌ Unknown whether an 8B grades *well enough* — smaller models are typically worse at
  subjective judgment, which is the half we have not been able to measure cleanly.
- ❌ A non-quantized 24B costs more GPU memory.

## 15. What constrained generation actually is

For the reader who has not used it, since we are proposing it as an option.

An LLM generates one token at a time. At each step it produces a probability distribution
over the whole vocabulary (~32k–128k tokens) and samples one. **Nothing in that loop knows
what XML is.** "Emit well-formed XML" is a statistical tendency learned from training
data, competing at every step against every other continuation. `< directness >` is not an
error the model detected and let through — it is simply a sequence that scored well.

Constrained decoding — vLLM calls it *guided decoding* — inserts a filter between the
model and the sampler. At each step it asks a state machine which tokens are **legal
here**, sets the probability of every illegal token to zero, and renormalises. The model
still chooses; it just cannot choose anything that breaks the schema.

Concretely, with a JSON schema:

```json
{ "type": "object",
  "properties": {
    "directness"      : { "enum": [ "terrible", "needs_improvement", "meh", "good", "exemplary" ] },
    "directness_note" : { "type": "string" },
    "tone"            : { "enum": [ "terrible", "needs_improvement", "meh", "good", "exemplary" ] },
    "tone_note"       : { "type": "string" } },
  "required": [ "directness", "directness_note", "tone", "tone_note" ] }
```

After emitting `{"directness": "`, the state machine knows only five continuations are
legal. **`meah` is not among them, so it cannot be produced** — not "is unlikely to be",
cannot. Every one of today's failures dies the same way:

| Today's failure | Under constrained decoding |
|---|---|
| `< directness >` (spaced) | impossible — grammar admits no space there |
| tag opened twice, never closed | impossible — the machine tracks depth |
| `meah` | impossible — not in the enum |
| `_note` fields dropped | impossible — `required` forces all four |
| `encoding "utf-8"` missing `=` | impossible — no free-form declaration to malform |
| ran to `max_tokens` repeating | impossible — the object closes and generation ends |

vLLM supports this natively via `guided_json`, `guided_regex`, `guided_choice`, and
`guided_grammar` (EBNF) request parameters, backed by `outlines` or `xgrammar`. It applies
to the **request**, so it can be enabled per agent — the judge could be constrained while
everything else in the fleet stays as it is.

**Cost**: a small per-token overhead for the mask computation, usually a few percent.
`xgrammar` precompiles the grammar and is generally the faster backend.

**The honest caveat, restated because it is the thing an enthusiastic reader will skip**:
this makes the output *parseable*, not *correct*. If the model wants to say `meh` for
everything, constrained decoding gives you a perfectly well-formed `meh` every time. It
would solve the problem we have today, and it would do nothing for the problem in §5 —
and it would hide the evidence that led us to suspect the checkpoint.
