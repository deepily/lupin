## 1. The defect, in one line

A `mapped_column` can land in `postgres_models.py` before its migration exists. On `:7999` uvicorn runs with `--reload`, so **the model edit IS the deploy** — the ORM immediately SELECTs a column the DB lacks and every read of that table 500s fleet-wide.

**Measured incident (2026-07-19)**: `park_reason_captured_at`. **12 events, 18:52:56 → 18:55:24 EDT, 2m 28s.** Confirmed from two independent instruments — exception lines in the container log, and `/api/tasks` status codes across 9 days (30,522 × 200, **12 × 500**, all inside the window). Zero since.

**Why it matters beyond volume**: `/api/tasks` is the store — the owed-work oracle that the Stop-hook and the arbiter both read. A read outage there is fleet-wide, not local.

## 3. The fix — three halves, three tiers, deliberately

### Half 1 — hermetic AST diff (unit tier, `:7999`)

**New file**: `src/tests/unit/test_model_migration_drift.py` (does not exist; no collision)

AST-parse every file under `src/migrations/versions/`. Collect `op.add_column( "<table>", sa.Column( "<name>", … ) )` and `op.create_table` column lists into `{table: {columns}}`. Diff against every mapped class on `Base` (`postgres_models.py:31`, `class Base( DeclarativeBase )`) via `__table__.columns`. Any mapped column absent from the migration ops **fails**.

**No DB connection.** Pure static, runs in the real unit bucket.

**Rejected alternatives, both for the same reason:**
- **`information_schema` comparison** — needs a live DB, and queries the very database that auto-migrates under `--reload`. It would go green *because the window closed*, not because the defect can't recur. *(María's catch.)*
- **grep for the column name** — authoritative for *"this string occurs"*, adjacent to *"a migration adds this column to this table."* Passes on a docstring mention, a comment, a `downgrade()`, or an `add_column` against the **wrong table**. Measure **operations**, not text. *(Arnold's catch on María's draft.)*

**Named limit** (goes in the docstring): AST sees **literal calls only**. A column added via a loop, a helper, or a computed table name is invisible. Half 2 covers it.

### Half 2 — `compare_metadata()` empty-diff (unit/CI tier, `:7999`)

**REQUIRED CHANGE 2 (Mr. Radio)** — use the **API**, not the CLI:

```python
from alembic.autogenerate import compare_metadata   # verified importable
```

`alembic revision --autogenerate` **writes a revision file** — a mutation, and one that would litter `versions/` on every run. `compare_metadata()` returns the diff list and **writes nothing**.

⇒ With that swap Half 2 is **pure-read, fast, and `:7999`-eligible.** No scheduled monopoly window.

**Correcting my own §3 draft**: I wrote "merge gate is right" and then routed it to `:8000` — but the venue rubric is *mutation / >2 min / monopoly*, and a metadata-vs-schema comparison is **read-only**. I reached for the venue the writing-CLI implied. **Drop the CLI and the venue question dissolves.** Do not route to `:8000` by habit.

Catches everything Half 1's literal-only parsing misses, across all tables. Complete where Half 1 is partial. **Neither is sold as the other.**

### Half 3b — lifespan alarm, FAIL-OPEN (ratified by Rick)

At startup, **after** `run_migrations_to_head()` (`main.py:446`), compare `Base.metadata` against the DB's actual columns.

**REQUIRED CHANGE 1 (Mr. Radio) — SPLIT DETECTION FROM ROUTING. `notify()` MUST NOT be called in lifespan.**

⚠️ **Confirmed defect in my draft, verified at source**: `cosa_voice_mcp.py:107-109` — `LUPIN_APP_SERVER_URL` defaults to `http://localhost:7999`; `:1197` — *"Sends notification via HTTP POST to /api/notify."* **On `:7999` the alarm's transport IS the server that is still booting.** Pre-`yield` the app accepts no connections, so the POST hangs to timeout or fails. **An alarm that blocks boot is exactly what fail-open exists to prevent.**

| Step | When | Guarantee |
|---|---|---|
| **Detect** | synchronously in lifespan | DB already connected, comparison is cheap |
| **CRITICAL log** | synchronously | stderr has **no dependencies** — this is the **alarm of record** |
| **`notify()`** | **post-`yield` / startup-complete task** | short timeout, **exceptions swallowed** |

🔴 **NEVER `await` a network call in the pre-`yield` critical path.** The alarm path must be **structurally incapable** of raising or blocking.

On drift: **CRITICAL log naming model, column, and expected revision** — then **SERVE ANYWAY**.

**Fail-open is load-bearing.** My objection to a refused-boot variant was that a detector bug would take down the box carrying the MCP transport, the task store, and the owed-work oracle — turning a partial outage into a total one. Fail-open removes that: **worst case is a false alarm, which is the correct price.**

**Mr. Radio's constraint, carried**: the alarm must name model/column/expected-revision. *A startup alarm reading only "drift detected" reproduces the diagnosis cost it exists to remove.*

**Why a test tier alone is insufficient** — the reason this half exists: a pytest-tier detector only fires when someone runs pytest, which is **after** the store has already 500'd. Halves 1 and 2 are worth building and are **not sufficient**.

## 6. Reviewer rulings — all four answered (Mr. Radio 🦉, 2026-07-19)

### Q1 — Placement: **AFTER `run_migrations_to_head()`**. My worry was unfounded, for a checkable reason.

`upgrade head` **cannot fabricate a migration for a column that has none.** The target defect — a `mapped_column` with no migration anywhere — **survives auto-migrate untouched** and is fully visible afterwards.

What "after" masks is only *a migration that exists but hadn't been applied* — which auto-migrate has just legitimately fixed, and which **is not the bug**. "Before" would alarm on **every legitimately-pending migration**: a false alarm on every boot after any new migration lands, which is how a detector gets ignored into uselessness.

⇒ **Not the disconnected-4/4 shape.** It passes when there is no drift — not because it cannot see drift. The distinction is testable, and the PRIMARY control (`f68bc520`) proves which one we built.

### Q2 — Scope: **ALL tables. Decide noise from DATA, not fear.**

During implementation, run the comparison **once** and inventory existing drift:
- **Empty** ⇒ ship alarming on all tables. Done.
- **Non-empty** ⇒ fix each, or scope it out **with a stated reason per table**.

⚠️ **DO NOT ship a baseline/allowlist file of known drift.** That is a hand-maintained duplicate someone must remember to update — plan rule 19b, and **precisely what `test_portable_ddl_matches_orm_columns` already taught us in this same build.** Shipping an allowlist would rebuild the twin whose failure mode §2 cites as the reason this detector exists.

### Q3 — Venue: **`:7999` unit tier.** See REQUIRED CHANGE 2 in §3 — swapping the CLI for `compare_metadata()` makes it read-only, and the venue question dissolves.

### Q4 — **CONFIRMED DEFECT.** `notify()` cannot run in lifespan. See REQUIRED CHANGE 1 in §3. Verified independently at source before acceptance.
