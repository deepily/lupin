# Arbiter "free fleet-wide" Count — Staleness Filter

**Date**: 2026-06-24
**Author**: Cheech 🌿 (Mr. Radio's 🦉 crew)
**Status**: DESIGN — implementation pending Mr Radio gate
**Scope**: `src/cosa/agents/heartbeat_arbiter/idle_roster.py` (+ one call site in `arbiter_job.py`)

---

## Problem

The arbiter's manager-tap advisory reports e.g. **"176 free fleet-wide"** when only
~6–8 sessions are actually live. The count is:

```
arbiter_job.py:2152   free_n = len( roster )
arbiter_job.py:1098   roster = build_roster( fleet_view, now, self.quiet_threshold_seconds )
```

`build_roster` (leaf `idle_roster.py`) counts a session as "free" via `classify_idle`,
whose **DECLARED branch wins outright**:

```
idle_roster.py:65   if view.get( "last_outcome" ) == EVENT_IDLE:
                        return ( IDLE_SOURCE_DECLARED, TRUST_DECLARED )   # ← no liveness gate
```

The idle beacon (`EVENT_IDLE`) is **sticky-until-superseded**: a session that emitted
"idle" and then went dark keeps `last_outcome == "idle"` forever. So **stale/dead
sessions with a lingering idle beacon are counted as "free/idle"**, inflating the
number into the hundreds. The "pull a free worker" recommendation built on it
(`_format_manager_tap`, :2099/:2106) is therefore meaningless — "of no use to anybody
as it currently stands" (Rick, 2026-06-24).

(The INFERENCE branch already gates on `view["alive"]`, so it is not the main
culprit — but see Mechanism for why we filter uniformly anyway.)

## Mechanism

Reuse the **existing** predicate — the same one the ping-storm / persona-collapse /
edge fixes use — as the single source of truth for staleness:

```
dependency_graph.session_is_stale( view, now, alive_threshold_seconds )
  → True  iff  last_activity_ts is present, parseable, AND age > alive_threshold_seconds
  → False (fail-SAFE keep) for: non-dict view, missing now/threshold, missing/None/
           unparseable ts, or future/within-window ts
```

A roster entry counts as "free" only if **idle/quiet (classify_idle non-None) AND its
session is NOT stale** (`not session_is_stale(view, now, alive_threshold_seconds)`).
Applied **uniformly** to both the declared and inferred entries, per the explicit
ask — a sticky idle beacon on a 12h-dead session no longer inflates the count.

## Where filtered — INSIDE `build_roster` (recommended)

Thread a new optional `alive_threshold_seconds=None` parameter into `build_roster`;
apply `session_is_stale` to each candidate view inside the leaf loop. **Not** an
upstream `fleet_view` filter.

**Justification:**

1. **One source of truth** — reuse `session_is_stale`; no second staleness notion.
   Co-locates "is this idle session live?" with "is this session idle?" — one place.
2. **Single chokepoint, both consumers want it** — `build_roster` has exactly two
   downstream uses, both of which should reflect live capacity (see Consumers checked).
   Filtering the leaf fixes both with one change.
3. **Shared-`fleet_view` safety** — `fleet_view` feeds the graph, the deadlock
   escalation, and the published snapshot. Filtering it upstream would either mutate a
   shared structure or require a separate filtered copy at the call site (a second
   filtering notion). The leaf filter touches none of that — the `:1084`
   store-backed escalation feed stays **byte-identical**.
4. **Additive + fail-safe** — the new param defaults `None`. `session_is_stale`
   returns `False` when `alive_threshold_seconds is None` → **no gate** → behavior is
   byte-identical to today. Existing `build_roster` tests (which call the 3-arg form)
   stay green unmodified. The production call site passes `self.alive_threshold_seconds`.

## Consumers checked

`build_roster` is called in exactly ONE place (`arbiter_job.py:1098`,
grep-confirmed). Its output `roster` has TWO downstream uses:

| Site | Use | Wants filtered count? |
|---|---|---|
| `:1101→:2152` | `free_n = len( roster )` → `_format_manager_tap` → **"N free fleet-wide"** advisory | **YES** — this IS the bug |
| `:1152` | `summary["roster"] = len( roster )` → per-poll journal/observability counter | **YES** — the counter should reflect reality, not phantoms |

Both consumers want the live-idle subset. No consumer needs the unfiltered count.
The roster is **PULL-state** surfaced to managers (`:1099` note) — filtering is
strictly desirable there.

**NOT touched** (scope guard): the unfiltered store-backed deadlock escalation feed at
`:1084` (`escalation_cycles = find_deadlock_cycles( build_wait_edges( fleet_view ) )`)
and its `:1018`/`:1070` rationale — that path intentionally reads the UNFILTERED graph
so a real store-backed ring with a dead participant still escalates (Krishna A2). We
add a param to `build_roster` and pass it at `:1098` only; the escalation feed is
unchanged.

## Fail-safe

Missing / `None` / unparseable `last_activity_ts` → `session_is_stale` returns `False`
→ entry is **KEPT** (counted). We never under-report live capacity on bad/absent
data — identical bias-to-keep to the storm fixes (`session_is_stale`'s own contract).
