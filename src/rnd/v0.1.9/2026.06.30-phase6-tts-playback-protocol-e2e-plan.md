## 0. Why this plan exists

Phase-6 is the switchover-critical gap: until it lands, opening the mux **silences Rick's
spoken notifications** (`AudioStore.ts:19-25` is decode-only — no playback scheduling). The build
ports the legacy gapless 24kHz PCM scheduler (`notifications.js:playPCMChunk`) into
`AudioStore.onDecoded`, maps pause/resume/stop onto `AudioContext.suspend/resume`, and emits
`store_audio_ended` on utterance completion.

**The defect class we are guarding against — Manager's standing directive (2026-06-30):**
> *"decode ≠ playback was the whole bug."*

A test that asserts only "frames arrived / chunks decoded" would **false-pass** a mux that decodes
but never schedules a buffer source — i.e. stays silent. Therefore every "playback engaged"
assertion in this plan gates on **the scheduler actually scheduling buffer sources**
(`createBufferSource` + `source.start(when)`), never on frame arrival or decode events alone.

## 1. The three verification layers

| Layer | Venue / runner | Proves | When |
|---|---|---|---|
| **L1 — UNIT** (authoritative scheduler proof) | node `tsx --test`, no server (:7999-class, AI-discretionary) | The scheduler **actually scheduled**: injected `SchedulableAudioContext` stub records `createBufferSource`/`start(when)` calls, gapless start-time math, zero second-decode, pause/resume/stop on real ctx methods, completion-flag gating, `store_audio_ended` emitted exactly once, **zero `TtsQueueStore` calls**. `c8 --100` L/B/F. | Stage B, first |
| **L2 — PROTOCOL E2E** (server-push wire contract) | headless authed WS client (`websockets`/`requests`), :7999, AI-discretionary, ≤2 min, no persistent mutation | The **server half of the seam is live**: a triggered TTS streams binary PCM chunks **and** the `audio_streaming_complete` text frame over `/ws/audio` in order — i.e. the exact frames P6 subscribes to actually flow on the server-push path. | Stage B, second |
| **L3 — BROWSER E2E** (real-Chrome scheduler proof) | Playwright + `__multiplexerTestHook`, :8000 monopolize (scheduled) | The **real mux in real Chrome** schedules real audio: an `AudioContext`-wrap init-script records `createBufferSource`/`start` in the live browser; the real `eventBus` emits `store_audio_state_change→playing` then `store_audio_ended`. The only place "mux audibly scheduled" is headlessly observable end-to-end. | Stage B, third (optional/stretch — see §5) |

**Why L2 cannot replace L1 or L3:** the mux's `store_audio_state_change` / `store_audio_ended`
events are **internal browser EventBus** emissions — they never cross the wire. A headless WS
client sees only the **server's** frames, not the mux's reaction to them. So L2 proves the
frames arrive; L1 + L3 prove the mux *schedules* in response. All three are needed; none is
redundant.

## 2. L1 — Unit suite (authoritative "scheduler scheduled" proof)

**File**: `src/tests/unit/multiplexer/audio_store.test.ts` (EXTEND existing — 32 tests today, all
decode/state-machine; P6 adds the scheduler + completion-seam arm).
**Runner**: `npx tsx --test src/tests/unit/multiplexer/audio_store.test.ts`
**Coverage gate**: `c8 --100` lines/branches/functions on `AudioStore.ts` (+ any new module).
Scope explicitly includes the F-Sam-B1 (flag-reset multi-utterance) + F-Sam-B2 (drop-race)
branches (00c §P6-e AC). `boot.ts` is verify/deletion-only — OUT of c8 scope unless net-new
coverable logic lands there (00c F-Cheech-C1).

The existing fixture already injects `audioContextFactory` (test line 67) returning a
`StubAudioContext` (line 38) implementing `AudioContextLike` (decode-only: `createBuffer`). P6
widens this to the **`SchedulableAudioContext` superset** (00c COND-4 / F-Krishna-A4) adding
`createBufferSource`, `currentTime`, `destination`, `suspend()`, `resume()`. The stub records
every scheduler call.

**Assertions I verify the implementer's suite covers (gate on these, not decode):**
- **Scheduled, not just decoded**: each decoded chunk yields exactly one `createBufferSource` +
  one `source.start(when)`; a post-`stop()` chunk yields **zero** `createBufferSource` calls
  (F-Sam-A3 mux-side guard).
- **Gapless math**: first chunk `start()` === `ctx.currentTime` (because `nextStartTime` inits
  to `0` → `Math.max(0, currentTime) === currentTime`); consecutive chunks `start(when)` ===
  prior `start + duration` within ε; **never `start(NaN)`** (F-Sam-A1 load-bearing).
- **No second decode**: scheduler consumes the `AudioBuffer` from `pcm16ToAudioBuffer` — zero
  second `createBuffer`/decode.
- **Pause/resume/stop on real ctx**: `pause()`→`suspend()` recorded; `resume()`→`resume()`
  recorded; resume does **not** rebase `nextStartTime` (F-Sam-A2 no-fixup keeps gapless);
  `stop()` halts sources + resets `nextStartTime`→`0`; no-ops in guarded states.
- **Completion seam (signal-OUT only)**: `audio_streaming_complete` bus event sets the
  stream-complete flag; last-source `onended` AFTER the flag → `store_audio_ended` emitted
  **exactly once** + XState `ended`; an `onended` BEFORE the flag does **not** complete;
  mid-stream chunks do not trigger completion; **P6 makes zero calls into `TtsQueueStore`**
  (ownership-boundary assertion — assert via a `TtsQueueStore` spy or absence-of-import).
- **F-Sam-B1 multi-utterance**: flag inits `false` + resets on new-stream-start AND `stop()`;
  utterance 2's FIRST `onended` does NOT complete (no carry-over).
- **F-Sam-B2 drop-race**: flag set AFTER the last `onended` already fired (no active/pending
  source) STILL emits `store_audio_ended` exactly once (immediate symmetric check).
- **F-Sam-C1 autoplay-blocked arm**: rejection-capable stub `resume()`/`suspend()` exercises the
  `audiocontext-blocked` emission with a REAL test (no `# c8 ignore`).
- **F-Sam-C3 autoplay recovery**: first-gesture `resume()`; chunks queued while `suspended`
  survive and play.

**Type-registration verification (P6 net-new, F-Krishna-B1):** confirm the implementer registered
`audio_streaming_complete` in the `LupinEventType` union (`shared/types.ts:22-153` — today ABSENT;
only `store_audio_state_change`/`store_audio_chunk_decoded` are members). `store_audio_ended` is
ALREADY in the union (line 153, declared by F0) with `StoreAudioEndedPayload` (line 644) — P6
CONSUMES it, must not re-declare. A `tsc` clean run is part of the gate.

**F0-side already wired (no P6 action):** `TtsQueueStore` already subscribes to `store_audio_ended`
and self-advances (`TtsQueueStore.ts:168`). L1 asserts P6 *emits*; the F0 subscribe is F0's tested
surface.

## 3. L2 — Protocol E2E (server-push wire contract, :7999, AI-run)

**Goal**: prove that triggering a TTS notification causes the server to stream the exact frame
sequence P6 subscribes to, over `/ws/audio`, on the existing server-push path (no new server work
— roadmap reframe 2026-06-30). This is a **headless WS client**, NOT a browser.

**Runner**: a new pytest at `src/tests/smoke/` or `src/tests/websocket_smoke/` (route by the
§TESTING VENUES rubric — this one is :7999-eligible: no persistent mutation beyond the transient
TTS stream, ≤2 min, no monopoly). **CURL PROHIBITED** — use `requests` (auth) + a `websockets`
async client (frame observation), reusing the existing websocket_smoke connection/auth helpers.

**Auth (current, NOT legacy mock tokens — confirmed `websocket.py:277-296`):**
1. `POST /auth/login` `{email, password}` from `LUPIN_TEST_INTERACTIVE_MOCK_JOBS_*` →
   `tokens.access_token` (JWT). Memory's `mock_token_email_*` is LEGACY — JWT is the only mode.
2. Connect `ws://localhost:7999/ws/audio/{session_id}`; send `auth_request`
   `{type, token, session_id, subscribed_events:[…,"audio_streaming_complete","tts_error"]}` (the
   server strips an optional `Bearer ` prefix, `websocket.py:280-281`); await `auth_success`.
   `session_id` may be a programmatic `prefix-hash` form (e.g. `cc-clayton-<hash>`,
   `is_valid_session_id` `websocket.py:139-180`) — no browser "adjective noun" needed.
   Reuse helper `_open_audio_and_handshake()` from `test_multiplexer_transport.py:144+`.

**⚠️ Trigger correction (server-surface map, 2026-06-30):** the task's original framing ("submit
via `/api/push`, poll `/api/get-queue/done`") points at the **wrong path** — `/api/push` +
`/api/get-queue/*` are the **agent job queue** (calculator/deep-research pipeline) and **do not
touch TTS** (`queues.py:160-255` / `:388-500`). The real TTS-stream trigger is:

- **`POST /api/get-speech-elevenlabs`** (`speech.py:487-638`) — body `{session_id, text, ...}`,
  Bearer JWT, returns 200 immediately and spawns a background task that streams **PCM 24000**
  binary frames (`output_format=pcm_24000`, `speech.py:994`; `send_bytes`, `:1043`) +
  `audio_streaming_complete` (`:1115-1119`) over `/ws/audio/{session_id}`. **This is the correct
  provider** — its PCM 24kHz output is exactly what the mux's `AudioStore` decode path consumes.
- (`POST /api/get-speech` (OpenAI, `:362-485`) streams µ-law/mp3 — **wrong format for the PCM
  scheduler**; use ElevenLabs.)
- `notify()` itself does **not** server-push TTS — it queues a notification (`/api/notify` →
  `notification_queue.push_notification`); the PCM stream fires only when `/api/get-speech*` is
  called. The protocol E2E calls `/api/get-speech-elevenlabs` directly against the same
  `session_id` our `/ws/audio` client holds — a faithful exercise of the exact server-push path
  P6's `AudioStore` subscribes to (initiator-agnostic; whether the call is client- or
  server-initiated is the deferred `d1bdb7ca`/F0-d concern, NOT a P6-playback concern).

**Frame-sequence assertions (the wire contract):**
- An opening `audio_streaming_status` `{status:"loading", provider:"elevenlabs"}` text frame.
- ≥1 **binary** WS frame (raw PCM 24kHz chunk — `send_bytes`, binary frame, NOT base64-in-JSON).
- The `audio_streaming_complete` **text** frame (`speech.py:1115-1119`), flat shape
  `{"type":"audio_streaming_complete","status":"success","provider":"elevenlabs", ...}`.
- Ordering: `status(loading)` → binary chunk(s) → `audio_streaming_complete`.
- No `tts_error` frame (`:976-981`) on the happy path. (A negative test may set
  `debug_simulate_error:true` to assert the `tts_error` arm.)
- **Subscription note** (`websocket.py:242`): the audio WS filters outbound text events to
  `[audio_streaming_status, audio_streaming_complete, sys_ping]` by default; binary chunks are
  sent unconditionally via `send_bytes`. The `auth_request.subscribed_events` list governs text
  frames — include `audio_streaming_complete` (+ `tts_error` for the negative test).

**Explicitly NOT asserted at L2**: the mux's `store_audio_state_change` / `store_audio_ended`
(internal bus — not on the wire) and `createBufferSource` (browser-only). Those are L1 + L3.
L2's honest scope is *"the frames P6 listens for actually flow."*

## 4. L3 — Browser E2E (real-Chrome scheduler proof, :8000 scheduled, optional/stretch)

**Goal**: the one place "the real mux scheduled real audio in a real browser" is observable. Reuses
the established Playwright harness pattern from `test_multiplexer_tts_controls.py`.

**Harness (confirmed reusable):**
- Auth: `/auth/login` → seed `lupin_access_token`/`lupin_refresh_token` into `localStorage` via
  `page.context.add_init_script` → `page.goto(/app/multiplexer)`
  (`test_multiplexer_tts_controls.py:41-88`).
- Test hook: `window.__multiplexerTestHook` exposes `{ eventBus, stores }` (`boot.ts:635`) — so
  `page.evaluate` can subscribe to the **real** bus and read `stores.audio`.

**Two browser-only instruments:**
1. **AudioContext-wrap init-script** (added BEFORE boot via `add_init_script`): monkey-wrap
   `window.AudioContext` so `createBufferSource()` and each returned source's `start(when)` push
   to a `window.__audioSchedulerCalls` array. After triggering TTS, `page.evaluate` reads it and
   asserts ≥1 `createBufferSource` + `start` call with gapless `when` values — **the real-browser
   "scheduler scheduled" proof**.
2. **Real-bus event capture**: `page.evaluate` registers
   `__multiplexerTestHook.eventBus.on("store_audio_state_change", …)` +
   `…on("store_audio_ended", …)` into a collector, then asserts `playing` was reached and
   `store_audio_ended` fired exactly once.

**Trigger**: same server endpoint as L2 (TTS push to the page's session), or — if the harness
proves fiddly to route a live TTS into a Playwright session — inject synthetic binary PCM frames
through the test hook's transport. (Decide at Stage B from the L2 trigger findings; prefer the real
server push for honesty.)

**Venue**: `test_multiplexer_*` E2E batch on :8000, submitted via `POST /api/test-suite/submit`
(`test_types="e2e"`), bounce-if-idle + schedule-behind per §TESTING VENUES. **Never** side-door.

**Status**: stretch for the MVP gate. L1 (authoritative scheduler proof) + L2 (server wire
contract) are the **required** Stage-B legs; L3 hardens "real browser" and feeds the B5 visual
pass. If Stage-B time-boxes, L1+L2 ship and L3 is filed as a follow-up store item.
