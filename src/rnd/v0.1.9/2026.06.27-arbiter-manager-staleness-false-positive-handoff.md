## Hypotheses (ranked)

1. **Snapshot staleness / association miss for the manager row.** `_check_manager_staleness` reads `self._last_full_snapshot` — if the snapshot's per-row `liveness` is built once (or cached) and not recomputed against the freshest signal sources each poll, the row's `freshest_age_s` ages monotonically (exactly the +1m/poll symptom). **Verify**: does the snapshot rebuild `liveness` per poll, and does it read the `heartbeat-events/<full-id>.jsonl` mtime/last-ts?
2. **Persona/session-id association miss.** The freshest heartbeat event is `{"persona": null, "kind":"task_transition"}` (persona NOT stamped on transition events). If the detector binds liveness to the row by persona and drops null-persona events, my freshest signals don't associate. Earlier `honored` events DO carry `persona:"mr radio"` (~5 min old) — still well under threshold — so this alone shouldn't fully explain it, but it may compound. **Verify** `canonical_persona_key` matching + whether event-signal ingestion filters on persona.
3. **event_age / commons_age / dm_age simply not wired into the row's union** for this session shape (e.g. the manager row sources liveness from a different file than the live `heartbeat-events` jsonl).
