## 0. The ask (verbatim intent)

1. **Silence worker message-count badges on the focus bar.** Workers spun up and managed by *other* managers should NOT surface their new-message counts to Rick. Workers talk to Rick only *through* their managers. Apply in `notifications.js` first, then duplicate in the multiplexer.
2. **Per-card collapse toggle on every CC session card** inside the `section-notifications` accordion (multiplexer).
3. **Port the "broadcast to all CC sessions" compose control** — present in legacy, **entirely missing** in the multiplexer.

Deliverable sequence: **walk the DOM → gap list (this doc) → Rick rules on constraints → spin up SWE team → implement.**

## 1. The keystone finding — worker/manager is already known in the browser

A **worker** is exactly a sender whose `manager_persona` is **non-null**. A **root/top-level** session (one that talks to Rick directly) has `manager_persona == null`.

This signal is **already delivered to both clients** and needs **no backend change**:

| Client | Where the signal lives | Anchor |
|---|---|---|
| Legacy | `this.managerPersonaMap` (Map sender_id → {icon,color,name,initial}); stamped on **every** notification + `voice_persona_assigned` | `notifications.js:133-137`, `5684-5713` |
| Multiplexer | `StripSession.manager_persona?` on the strip store; `SenderRecord` does **not** carry it yet | `shared/types.ts:463-469`, `SessionStripStore.ts:205-262` |

Backend provenance (for reference, no change needed): `spawned_by` / `role` are written to the session bridge at spawn (`register_session.py:900-914`) and resolved into `manager_persona` by `voice_persona.py:_resolve_manager_persona` (`voice_persona.py:65-104`), then stamped live (`notification_fifo_queue.py:561`) and on cold-load hydration (`notifications.py:2577-2578`).

> **Consequence**: the silencing rule is a pure client-side predicate — `isWorker(sender) := managerPersona(sender) != null`. No new field, no schema bump, no migration.

> **One caveat for the multiplexer card path**: `SenderRecord` (what the section-notifications cards render from) does **not** currently carry `manager_persona` — only the *strip* store does. If we silence the per-card `.sender-new-count` badge in the mux (see Decision A option B/C), we must thread `manager_persona` (or a derived `is_worker` boolean) into `SenderRecord` from the same notification field the strip store already reads. This is a small client-side plumbing job, still no backend change.

## 2. Feature A — Silence worker badges on the focus bar

### 2.1 Legacy (`notifications.js`) — what exists

- **Focus-bar strip icon unread badge**: red counter via CSS `::after` on `.cc-strip-icon[data-unread="true"]` (`notifications.css:2186-2217`). Count tracked in `this.ccStripUnreadCounts` (`notifications.js:220`), incremented by `_markStripIconActivity()` (`notifications.js:10971-11001`) **only while focus mode is ON** and the sender is not the focused one. Cleared by `_clearStripUnreadFor()` (`11315-11321`).
- **Per-sender-card "N new" badge** (separate, in the section-notifications card header): `.sender-new-count` (`createSenderCard` line 13531; updated `updateSenderCardHeader` 14152-14161).

### 2.2 Multiplexer — what exists

- **Strip icon**: rendered by `SessionStripRenderer` / `sessionStripIcon.ts`. **No** per-icon unread-count badge exists (the legacy `data-unread-count` strip badge was never ported).
- **Per-sender-card "N new" badge**: `.sender-new-count` from `sender.unread_count` (`senderCard.ts:164-166`) — **this exists** and is the mux's only per-worker count surface.
- **Global missed badge**: one "N missed while away" count (`MissedStore.ts`, `missedBadge.ts`) — not per-persona; out of scope.

### 2.3 The silencing edit (pending Decision A scope)

- **Legacy**: in `_markStripIconActivity()`, early-return (skip the `data-unread`/`data-unread-count` write) when `this.managerPersonaMap.get(senderId)` is non-null. Optionally also gate the per-card `.sender-new-count` update in `updateSenderCardHeader()`.
- **Multiplexer**: gate the `.sender-new-count` render in `senderCard.ts` on `!isWorker(sender)` (requires threading `manager_persona`/`is_worker` into `SenderRecord`). The strip has no badge to silence.

## 6. Decisions — RULED by Rick (2026-06-24)

- **Decision A — Silencing target. ✅ RULED: suppress the count badge for managed workers, everywhere, in BOTH clients.** The exact predicate (Rick's words): *"only the workers who are being managed by a manager … have their notification count badges to not be rendered. So only unmanaged or manager instances display the notification count badge."* → `isWorker(sender) := managerPersona(sender) != null`. Workers ⇒ **no count badge**. Unmanaged / manager / root ⇒ **count badge rendered as today**. Applies to every count surface: legacy strip `data-unread-count`, legacy card `.sender-new-count`, and the mux card `.sender-new-count`.
- **Decision B — Silence semantics. ✅ RULED: keep a faint activity pulse, drop only the number.** Worker icons/cards keep a subtle sign-of-life pulse; the numeric count is suppressed. (Legacy: keep `data-unread` pulse, suppress the `::after` count via a `data-worker` carve; never write `data-unread-count` for workers.)
- **Decision C — Collapse toggle. ✅ RULED: verify the existing 2026-06-23 impl + rebuild dist if stale; session-only (legacy parity).** No reload-persistence.
- **Decision D — Broadcast port scope. ✅ RULED: full parity port** — compose card + 🎤 STT + live recipient chips + confirm modal + `POST /api/commons/broadcast-to-cc-sessions`.
