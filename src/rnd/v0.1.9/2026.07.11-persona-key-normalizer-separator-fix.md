## 1. Problem

`canonical_persona_key` is THE single normalizer every task-store seam agrees on
(create · reassign/patch · query · arbiter role-match). María filed a P1 with
`owner_persona="mr_radio"` (underscore — a near-canonical slug form). The store
canonicalized it **lossily** to `"mrradio"` (underscore deleted, no space
inserted), so every scoped query (`owner_persona="mr radio"`) missed it and the
P1 sat invisible until Rick eyeballed the raw board.

**Refutation of the original "divergent normalizer" hypothesis**: create and
reassign/query do NOT diverge — they all route through the SAME
`canonical_persona_key` (create `src/cosa/rest/routers/tasks.py:395-396`;
patch/reassign `tasks.py:633` → `task_store_rules.normalize_patch_fields:520`;
query `tasks.py:725-726`). The defect is in that shared **root**: its regex
`re.sub(r"[^a-z0-9 ]", "", ...)` **deleted** separator characters (`_`, `-`)
instead of treating them as word boundaries, fusing `"mr_radio"` → `"mrradio"`.
(Recorded on the bug as amendment #2, event 2287.)

## 2. Fix (primary)

`src/lupin_mcp/persona_normalization.py` — `canonical_persona_key`:

```python
# before
stripped = re.sub( r"[^a-z0-9 ]", "", ascii_only.lower() )   # deletes "_"/"-"
return re.sub( r"\s+", " ", stripped ).strip()
# after
spaced = re.sub( r"[^a-z0-9]+", " ", ascii_only.lower() )    # separators -> single space
return spaced.strip()
```

Every run of non-`[a-z0-9]` characters (punctuation, emoji, **and** separators)
collapses to a single space in one pass; `.strip()` trims the ends.
`"mr_radio"`/`"mr-radio"` → `"mr radio"` (not `"mrradio"`). One edit fixes
create + reassign + patch + query simultaneously (fix-at-source).

**Invariance** (verified): `normalize_for_match` (= key with spaces removed) and
`persona_slug` (= key with spaces → sep) outputs are unchanged; `persona_slug`'s
`sep`→space pre-substitution is now belt-and-suspenders. Docstrings for both
updated (nit N1).

## 4. Data-store straggler audit (nit N3) — board is NOT clean

scanned **662 rows → 13 stragglers**. Two sub-classes:

- **(a) Separator / display-case stragglers — HEALABLE by `--apply` post-fix.**
  e.g. `owner_persona`+`accountable_manager` `'mr_radio'→'mr radio'` (rows
  `82e4eaf0`, `c38e3134`), `'mr-radio'→'mr radio'` (`487dc704`),

  `'Mr Radio'→'mr radio'`, `'Krishna'`, `'Tiberius'`. These are **not** fixed
  points — the fix makes `canonical("mr_radio")="mr radio"`, so the backfill now
  computes the CORRECT healing target.
- **(b) Truly-fused rows — UNHEALABLE fixed points, need a MANUAL targeted UPDATE.**
  A value with no separator (e.g. María's original `"mrradio"`) satisfies
  `canonical("mrradio")=="mrradio"`, so it is invisible to the scan and cannot be
  auto-repaired. None appear in the 13 (consistent with being undetectable).

**Sequencing caveat**: the backfill only computes correct plans when it imports
the FIXED `canonical_persona_key`. Running `--apply` from the unfixed main tree
would MIS-heal (`"mr_radio"`→`"mrradio"`). Any `--apply` must therefore wait
until this fix lands.
