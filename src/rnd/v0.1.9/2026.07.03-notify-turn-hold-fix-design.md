## 1. Incident summary (proven, receipts on the bug)

Session `25c7441c` (Cheech) called `mcp__cosa-voice__notify` — a **fire-and-forget** verb — at
2026-07-03T01:52:53Z. The tool result returned only at **02:47:39Z** (`MCP error -32000: Connection
closed`, i.e. released by process death at reap): a **54m47s in-turn hang**. While the turn was
open, the Stop phase could not run, so tmux-injected messages (including Mr. Radio's 01:58:40Z
PREPARE-FOR-RE-SPIN tap — `queue-operation enqueue` in the transcript) sat queued and undrained;
bare Enter no-ops on an empty composer. The wedge forced a manager re-spin.

**Where the hang is NOT**: `:7999` received AND dispatched the notification (~01:53Z, docker-log
receipt), and the client HTTP leg is tightly bounded — `AsyncNotificationRequest.timeout` is
capped **1–30s** (`notification_models.py`, async model) and `notify_user_async` passes it to
`requests.post(..., timeout=request.timeout)` with a bounded retry schedule
(`notify_user_async.py:197-202`, `calculate_retry_intervals`).

**Where the hang therefore IS**: the cosa-voice **MCP server process's response leg** back to the
CC client — after (or around) the tool function's bounded work, the JSON-RPC response never reached
CC until the process died. Candidate internal mechanisms (not yet pinned): event-loop starvation by
a blocking call elsewhere in the server (sync `requests` on the async loop), a stalled stdio write,
or thread-pool exhaustion. Pinning the internal seam is follow-up work; **the levers below are
correct under all three**, which is what makes a bounded outer timeout the load-bearing fix.

## 2. Lever (i) — bound the tool call end-to-end (the structural fix)

### (i-a) CC-client bound: `MCP_TOOL_TIMEOUT` (config-only, INTERIM-capable) — **HONOR-CHECK VERIFIED ✅**

Claude Code honors the `MCP_TOOL_TIMEOUT` environment variable (milliseconds) as an upper bound on
MCP tool-call execution. Setting it in the fleet spawn path (`start-cc-with-tmux.sh` env, alongside
the existing roster env) bounds **every** MCP call — regardless of where the server stalls — and
converts a 55-minute wedge into a bounded tool-error the session simply recovers from (CC receives
a timeout error result; the turn proceeds; queued messages drain at turn end).

**Honor-check receipt (2026-07-03 ~07:04Z, evidence not hypothesis)**: scratch tmux pane, /tmp
scope, CC v2.1.199 launched with `MCP_TOOL_TIMEOUT=15000`; project `.mcp.json` registered a local
FastMCP server exposing `hang(seconds)` (`time.sleep`); the session called `hang(seconds=120)`.
The client aborted at exactly the bound — verbatim pane output:
`MCP server "hangmcp" tool "hang" timed out after 15s` — the turn then proceeded and ended
normally (the session itself reported "aborted by the client-side MCP timeout at 15 seconds").
A hung MCP tool call under this env is a bounded error, not a wedge. Probe applied per-pane only;
NO fleet-wide application (that is the fix itself, Rick-gated).

- **Cost/risk**: config-only, no code, per-session at spawn, trivially reversible. Must be sized
  ABOVE the longest legitimate blocking ask (`converse`/`ask_*` support `timeout_seconds` ≤ 600) —
  recommend **660_000 ms (11 min)**: comfortably above the 600s ask ceiling, an order of magnitude
  below the observed 55-min wedge.
- **Caveat**: bounds every server equally (blunt) — hence sizing above the blocking-ask ceiling.

### (i-b) Server-side: make notify structurally unable to block the response

Inside `cosa_voice_mcp.py`, `notify()` → `_notify_impl()` currently completes a synchronous chain
(sender-id wait ≤12s, spool check, bounded POST) before the MCP response is written. Harden to
**respond-then-work**: validate + enqueue to the existing durable outbox/spool (already built for
degraded windows — `_spool_failed_notify`, `_outbox_has_backlog`) and return immediately; let the
background flusher own delivery. A fire-and-forget verb's response then depends on ZERO I/O.

- **Cost/risk**: code change in live fleet comms (HIGH blast radius — every session's notify path);
  needs its own RED-first cycle + review + Rick's go. The spool machinery already existing makes
  this a rewiring, not new infrastructure.
- **Scope note**: blocking verbs (`ask_*`, `converse`) are exempt — they legitimately wait; their
  bound is (i-a).

## 3. Lever (ii) — generalized turn-age watchdog (detection, arbiter-side)

The arbiter already tails bridges/events and captures panes. Add a **turn-age detector**: a session
whose transcript's last `tool_use` has no matching `tool_result` for > N minutes (default 10) while
its pane shows no active stream = a held turn → operator advisory (same outreach rail as
manager-stale). This catches ALL variants of the wedge class (in-turn tool hang, stop-phase hold)
without touching fleet comms.

- **Cost/risk**: arbiter-only (LOW blast radius — `:8001` redeploy, manager authority), read-only
  signals, no false-wake risk (advisory tier, not poke).

## 4. Blast-radius comparison + minimal-effective recommendation

| Lever | Change surface | Blast radius | Bounded-wedge guarantee |
|---|---|---|---|
| (i-a) `MCP_TOOL_TIMEOUT` env | spawn script env | LOW (config, reversible) | YES — all MCP calls, all servers |
| (i-b) notify respond-then-work | cosa-voice server (live comms) | HIGH | YES — notify only |
| (ii) turn-age watchdog | arbiter | LOW | no (detects, doesn't prevent) |

**Recommendation (minimal-effective)**: land **(i-a) first** — config-only, fleet-wide guarantee,
reversible in one line — honor-check now VERIFIED (receipt in §2 i-a). Then **(ii)** for visibility (it would
have surfaced 25c7441c ~10 min in, instead of 55 min + a manager re-spin). Treat **(i-b)** as the
right long-term shape but sequence it behind Rick's ratification and a dedicated review cycle, since
it touches every session's comms path — and (i-a) already removes the unbounded failure mode.

## 5. Environmental caveat

The night of the incident had `:7999`/model-server turbulence (GPU model-server + cloud-run split
work, container swaps). The TTS/model-server coupling may have been the *trigger* for the server's
response-leg stall — i.e. this may not reproduce under a healthy stack, and the internal-seam pin
(§1 "candidate internal mechanisms") may require replaying a degraded `:7999`. The levers are
deliberately trigger-agnostic: they bound the failure whatever stalls the leg next time.

## 6. Interim operational detection + mitigation (live NOW, no ratification needed)

Also folded into the [unwedge runbook](2026.07.03-cc-stop-phase-pipe-hold-guard-and-runbook.md) §4:

- **Detect (turn-held variant)**: wedge signature at a pane + transcript tail shows a dangling
  `tool_use` (no result) — `tail` the session's `.jsonl` and look for the last `tool_use` id with
  no `tool_result`.
- **Mitigate**: **kill the session's cosa-voice MCP server process** (its `cosa_voice_mcp.py`
  python child under the CC pid) — NOT the CC process, NOT bare-Enter kicks. The MCP connection
  closes, CC receives the error tool_result, the turn ends, the queue drains. This is exactly the
  release observed at 02:47:39Z, minus the reap. The session survives with one errored tool call.

### Lever (i-a) — `MCP_TOOL_TIMEOUT=660000` in the fleet spawn env

- **Placement**: a static `-e "MCP_TOOL_TIMEOUT=660000"` in `start-cc-with-tmux.sh`'s
  `PERSONA_ENV_FLAGS` array — exactly parallel to the existing `CLAUDE_CODE_DISABLE_MOUSE=1`
  (always-on, forwarded across the tmux boundary so `claude` and every hook inherit it).
- **Fleet-wide coverage confirmed**: `session_spawner.py:162-186` builds
  `["bash", start-cc-with-tmux.sh, "--headless", …]`, so **headless spawns flow through the same
  script** and inherit the flag — a single line bounds both interactive and spawned sessions. No
  independent env-composition path to patch. The var is NOT placed in `fleet-roster.env`: the
  arbiter (`:8001`) runs no CC session, so the var is inert in its `EnvironmentFile=` drop-in →
  no drop-in change needed.
- **Sizing**: 660_000 ms (11 min) > the 600 s (600_000 ms) `converse`/`ask_*` blocking-ask ceiling
  (a legitimate wait is never severed) and an order of magnitude below the 55-min wedge. Verified
  by a test invariant.
- **CAVEATS (as steered by Mr. Radio)**:
  1. **Already-live sessions do NOT get the bound** — coverage arrives as sessions cycle; there is
     **no forced respawn**.
  2. **Bare-terminal sessions** not launched via `start-cc-with-tmux.sh` are **out of scope** (the
     `~/.bashrc` roster-source path documented in the roster template would be the manual add-on).

### Lever (ii) — arbiter turn-age watchdog (held-turn detector)

- **New module** `src/cosa/agents/heartbeat_arbiter/turn_age_watchdog.py` (`TurnAgeWatchdog`) —
  mirrors the eng#7 `FollowThroughEscalationWatcher` *shape* (INI-gate, `sweep_once`, one-shot
  markers, daemon lifecycle) but runs **standalone**: it has **no dependency on `ArbiterConsumerJob`**
  (it reads transcripts + panes directly), so it is started as its own daemon in `app.py` —
  **zero `arbiter_job.py` coupling**, which keeps it fully clear of María's arbiter poke-path lane
  (6fc8d78d) and Cheech's hooks/lib+stop.py lane (75f392c0).
- **Detection**: for each live CC session, `find_dangling_tool_use` finds the transcript's LAST
  `tool_use` with no matching `tool_result`; if its age > `arbiter turn age watchdog threshold
  seconds` (default 600) AND the pane shows no active stream → **one operator advisory**.
- **Flood-guard (fresh lesson from re-announce flood e1bbe011)**: advisory is **one-shot per
  unique `(session_id, tool_use_id)`**; the `_advised` marker set is intersect-cleared against the
  live dangling set each pass (`_advised &= live`, mirroring the arbiter's `_escalated &= live`), so
  a still-dangling turn never re-fires and only a genuinely NEW dangling `tool_use` advises again.
  **No fresh forensic row per sweep.**
- **Rail**: advisory routes through `make_escalation_notify_fn` (durable `fleet-escalations` post +
  best-effort live push) — the **same outreach rail as manager-stale**. Detection-only, **advisory
  tier (never a poke), no auto-kill → LOW blast radius**. The advisory body names the runbook §4
  mitigation (kill the session's `cosa_voice_mcp.py` child) rather than taking any action itself.
- **Config (never hardcoded)**: `arbiter turn age watchdog enabled` (default **false** — a
  defense-in-depth rollout gate sibling to `follow through escalation enabled`; `sweep_once` a
  no-op + `start()` refuses to spawn while off) and `arbiter turn age watchdog threshold seconds`
  (default 600). Both carry splainer entries. The daemon naps on `arbiter poll seconds`.
- **Activation**: flipping the enable flag + the `:8001` arbiter **restart** to load it are
  **manager/Rick territory** — everything here is commit-held and behavior-neutral until then.
