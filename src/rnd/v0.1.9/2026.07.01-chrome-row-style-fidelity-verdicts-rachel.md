## Systemic finding (read first — it frames every row)

The mux did **not** apply one uniform theme. It splits the surface:

- **Header cluster + top chrome = DARK theme** (mux-only idiom, deliberately OFF the shared sheet):
  `notifications-header.css` styles `.notifications-header-title` at `#e8e8ec` (light text) with
  translucent-white pills (`rgb(255,255,255,0.06)`) on the dark pane — its own header comment says
  *"Theme matches the mux dark-surface idiom (session-strip.css et al.) … these classes are mux-only, so
  nothing to single-source byte-faithful against the legacy monolith."* This is a CONSCIOUS divergence.
- **Content panels = LIGHT theme** (ported / legacy-aligned): AR `#e7f1ff`, PLY `#ecfdf5`/`#f9fafb`,
  broadcast `#fff`/`#f1f3f5` — all light.

Legacy is **uniformly light** (`.section-header` = `#e9ecef` bar, `#495057` text). So the mux introduced a
dark top-chrome band above light content — an internal inconsistency legacy does not have. **This is a design
call for Rick**, and it is the root cause behind the V2/V5 "style" verdicts below (they are not bugs — they are
a chosen reskin). It is the SAME class of decision as the AR/PLY palette: intentional, not accidental drift.

## Interpretation for the flip decision

- **V7 is genuinely at style-parity** — a faithful light-theme port with the one reported defect fixed. CLOSED.
- **V3/V4/V5 are all one decision**: the mux chose its own palette/theme (emerald TTS, blue-border AR without
  the filled header bar, dark header cluster) instead of byte-matching legacy. Each is *present, legible, and
  functional* — the spacing/legibility DEFECTS are fixed — but none is pixel-faithful. Per Mr. Radio these are
  **Rick DESIGN decisions, not bugs**; I have NOT repainted. If Rick wants strict legacy fidelity, the concrete
  edits are: AR border 2px→3px + add filled blue header bar; PLY emerald→Bootstrap-green + filled green header
  bar + border 1px→2px; header cluster dark→light (or accept the dark-band redesign).
- **V2 has a real OPEN sub-gap independent of theme**: the env-label + date + live-clock CONTENT does not exist
  in the mux header renderer. That is a missing feature, not a color choice — it should be built (or explicitly
  deferred) regardless of the theme decision.
