## 1. The mechanism (proven live, CC v2.1.199)

Claude Code's hook phase waits for hook-**stdout EOF**, not process exit. The default per-hook
timeout binds the hook *process* — a backgrounded grandchild that inherits the hook's stdout keeps
the pipe open after the hook exits, holding the Stop phase **indefinitely** (`sleep 300 & exit 0`
held it 1m8s+, past the 60s default timeout, in the controlled repro). While the phase is held:
input injected via tmux **enqueues** ("Press up to edit queued messages"), the queue drains only at
phase end, and bare Enter **no-ops** on an empty composer — the full 73d2b589 wedge signature.
Killing the pipe-holding child released the queue **instantly** in the repro.

## 3. The guard suite — `src/tests/unit/test_hook_spawn_stdout_discipline.py` (14 tests)

1. **AST sweep invariant**: every `subprocess.Popen` under `src/lupin_cli/claude_code/hooks/` must
   pass explicit `stdout=` AND `stderr=`. Call-node based — docstring examples can't false-positive.
   Hardened against the evasion routes adversarial self-review found in its own first draft:
   `from subprocess import Popen as <alias>` is tracked; `os.system` is banned outright (always
   inherits stdout, `cmd &` is the pipe-hold shape with no per-child redirect); the
   `asyncio.create_subprocess_*` twins are swept by the same keyword rule. Negative controls pin
   every detector (violation flagged, partial redirect flagged, alias flagged, os.system flagged,
   asyncio flagged, clean spawn accepted) so the guard can't silently go vacuous.
2. **Seam pins** on the four real spawn sites (table above): monkeypatched `Popen` captures the
   actual kwargs; each must be DEVNULL-or-file for both streams, never PIPE, `start_new_session=True`.
3. **Live demonstration pair**: `bash -c 'sleep 1.5 & exit 0'` with `stdout=PIPE` → parent exits
   instantly but EOF blocks ~1.5s (the wedge); with `stdout=DEVNULL` → returns at process exit (the
   discipline). Executable documentation of WHY the invariant exists.

Venue `:7999`/local, ~1.8s. No source files changed — tests + this doc only, so the 100% L/B/F gate
has no changed-source surface; the suite itself passes 11/11.

## 4. Fleet unwedge runbook (proven levers)

When a session shows queued-messages-at-idle ("Press up to edit queued messages", no turn starting):

1. **Do NOT bare-Enter kick** — proven useless (Enter no-ops on an empty composer; ×2 in repro, ×N
   in the 25c7441c incident).
2. **Find the pipe-holder**: `ps -ef --forest` under the CC pid — look for hook children or their
   orphaned grandchildren (long-lived `sleep`/waiter/one-shot helpers). Cross-check
   `ls -l /proc/<pid>/fd` for a pipe fd shared with the CC process.
3. **Kill the holder** (`kill <pid>`) — the Stop phase releases and the queue drains immediately
   (proven: instant drain in repro).
4. If no holder is found, the turn itself may still be open (in-flight tool/MCP call — see §5); a
   held phase and an open turn are indistinguishable from the pane alone.

**Detection** (for the arbiter/probe backlog, not built here): `tmux capture-pane` already runs in
the pane-idle probe — a `(running stop hooks… · <age>)` spinner line with age beyond ~2× the known
hook budget is the wedge signature; the probe currently classifies such panes "idle" because the
bottom shows the `❯` prompt + shortcuts bar (verified in repro).
