## 1. Defect

False **"Stuck: sam"** manager-tap advisories (2026-07-11, 21:12 / 21:49 EDT) while sam was demonstrably ACTIVE (pane-probed: plan mode, live subagents, tokens flowing) and the store held zero sam-owned rows.

## 2. Verify-first — both filed premises were REFUTED by primary evidence

The bug was filed suspecting **replayed cap-history** (the `92c7ab1d` axis). The evidence says otherwise:

**(a) `92c7ab1d` is not held — it is merged and live** (`5d4e7baa` → `59ba12e5`, arc closed-verified in `c52f20e6`). Its veto primitive `_session_bridge_fresh` therefore **already exists in the tree** and is *reused* here, not rebuilt.

**(b) The cap_reached records are GENUINE and FRESH, not replayed.** sam's events file (session `84daa020`):

| ts (UTC) | outcome | poke_count | work_owed |
|---|---|---|---|
| 01:00:11 | `cap_reached` | 3 | True |
| 01:08:13 | `cap_reached` | 3 | True |
| 01:15:19 | `cap_reached` | 3 | True |
| 01:27:32 | `idle` | 3 | False |

Two live caps with no intervening `honored` ⇒ `_count_stuck_episodes` = 2 ≥ `STUCK_REPEAT_THRESHOLD` ⇒ `stuck=True`. **The flag was computed correctly. The ADVISORY is what's wrong.** (Mr. Radio's `:8001` bounce that evening also produced zero stuck flags — the replay hypothesis is dead on both ends.)

## 3. Root cause — the arbiter contradicted itself on a single poll

Journal, poll **2026-07-11 21:12:20 EDT** — both lines, same poll:

```
arbiter_stuck_bridge_veto   persona=sam  bridge_age_s=8.6      ← "don't POKE sam — he's alive"
arbiter_outreach kind=tap → Mr. Radio: "1 stuck/dead"          ← "sam is STUCK"
render: sam  stuck  peer:rio  8s/4m  LIVE STUCK
```

The `92c7ab1d` bridge-fresh veto was wired into two consumers of the `stuck` signal — `_auto_poke` (every role) and, via `e5e33795`, the manager-**SUBJECT** advisory — but **never into the worker-subject roster leg** in `_attention_workers`. So the arbiter refused to poke sam *because he was demonstrably taking turns*, then told his manager he was wedged anyway.

`e5e33795` had explicitly pinned the veto as *"a MANAGER-SUBJECT guard only… a stuck WORKER is NEVER touched by the veto"*. **That exclusion was the defect** — and it left the advisory path disagreeing with the poke path, which has always vetoed every role.

> This is the same shape as `1ff7be20` (ping leg gated, roster leg not) and `cec10ef9`. A signal gets a correctness gate wired into one consumer and not its sibling. Third instance in the family.

## 4. Fix

Apply the **existing** `_session_bridge_fresh` veto to the stuck leg of `_attention_workers`, where it covers **every subject** (manager and worker alike). `bridge_mtimes` was already threaded into that method (`bf8c5cbb`) — **no new plumbing, no new mechanism, no store read.**

Store-corroboration is deliberately **not** the remedy shape here (Mr. Radio's ratified constraint): a genuinely wedged worker often *cannot* write store rows, so gating the stuck leg on store rows would hide real stalls.

The now-redundant `e5e33795` copy of the veto inside `_tap_managers` is **removed** — the upstream veto subsumes it byte-for-byte in outcome (a bridge-fresh stuck session never reaches that loop). Its semantics, journal event, and fail-safes are unchanged; only its worker-exclusion is retired. One rule, one owner.

### Fail-safe is ROSTER — the true positive is preserved

`_session_bridge_fresh` suppresses **only on positive liveness evidence**. Every uncertain direction keeps rostering: `bridge_mtimes` unwired/None · persona absent from the map · bridge **stale** · future-skewed mtime (clock skew, `097778b8`) · `now=None` · **deadlock-cycle member** (mutual stall stays load-bearing).

A genuinely wedged session stops emitting hook stamps — at poke-cap the self-poke nudge halts — so its bridge goes stale, it is never vetoed, and it is still announced.

## 5. Known adjacent defect — split to a separate item (NOT fixed here)

`_count_stuck_episodes` consumes a prior `cap_reached` **only** when a later **`honored`** record appears. sam recovered with an **`idle`** record, which consumes nothing — so his stuck flag became **permanent** (hence the 21:49 fire: idle, zero owed work, bridge 0s fresh, still `LIVE STUCK`).

Fixing that at source would change the semantics of `stuck`, a **shared** signal consumed by render, poke, snapshot, and the UI — a real blast radius requiring its own verify-first sweep across every consumer. Mr. Radio ruled it a **separate item** on his board (correctness debt, not hygiene). This fix kills both live false positives without touching it.
