# Runbook: Supervise & Instrument a Dying tmux Server (uid-scoped, systemd --user)

**Purpose.** A user's tmux server keeps dying (multiple times in two days), taking
several Claude Code sessions with it and orphaning the notification listeners that
inject voice commands into those panes. `loginctl enable-linger` is already set, so
logind session-reaping is **excluded** as the cause. This runbook (a) makes the tmux
server self-restarting under systemd, (b) instruments it so the **next** death is
fully attributed, and (c) reconciles the session-bridge file on every restart so the
listeners re-bind cleanly.

> **⚠️ FORENSIC UPDATE (2026-07-14, post-mortem of the 14:12 + 14:55 double death).**
> A live investigation refined three claims in this doc; read before executing.
>
> 1. **The OOM branch of §9's hypothesis is FALSIFIED with receipts.** At both deaths
>    the box had 188 GB free of 251 GB, `ulimit -c` was 0, and the kernel logged
>    **zero** OOM/kill/segfault events. tmux did not crash and was not OOM-killed. That
>    leaves the **userspace-signal** branch (a stray `pkill`/`kill-server` from a
>    teardown, cron, or shell) — which is exactly what §10's bpftrace tracer names. The
>    two deaths took whole cohorts across **three** projects (lupin,
>    planning-is-prompting, google-skills-distillation) simultaneously — proof it is the
>    shared tmux server, not anything project-specific.
> 2. **This runbook does NOT fix the stranded listeners; it was necessary but not
>    sufficient.** `reconcile-bridge.py` prunes stale bridge *entries*; it never signals
>    the orphaned listener *processes*, which are setsid'd to PPID 1 and reconnect
>    forever. That gap is now closed in code by an **owner-liveness watchdog** inside the
>    listener (`cc_notification_listener._watch_owner`, tests
>    `test_cc_listener_owner_watchdog.py`): the listener polls its owning `cc_pid` every
>    30 s (PID-reuse-safe via /proc start-time) and self-reaps when the session dies,
>    regardless of death mode. The two mechanisms are complementary — watchdog reaps the
>    process, reconciler cleans the bridge.
> 3b. **Two hardening fixes applied to the DEPLOYED units (2026-07-14 evening), after a
>    third death (20:04) went unattributed.** That death was NOT OOM (kmsg readable, zero
>    kernel OOM/kill events, 185 GB free) and left **no `Main process ... code=killed`
>    line** — because (i) `ExecStop=tmux kill-server` runs on a self-death when the server
>    is already gone, exits 1 ("no server running"), and its status **masked** the real
>    Main-process verdict in the journal; and (ii) the §B `tmux-watch` snapshot never
>    fired because its 15 s poll straddled the 2 s systemd auto-restart. Fixes now live:
>    - **`ExecStop=-/usr/bin/tmux -L default kill-server`** (leading `-` → systemd ignores
>      ExecStop's exit status), so the daemon's own `code=exited/killed status=N` surfaces
>      and a clean death is no longer flagged `failed`.
>    - **`Environment=WATCH_UP_INTERVAL=3` + `WATCH_DOWN_INTERVAL=3`** in `tmux-watch.service`
>      so the UP→DOWN edge (and its forensic snapshot) is caught on a ~2–4 s death window.
>      Cost: a heartbeat line every 3 s (~1 MB/day); widen back to 15 once the culprit is named.
>    The §10 killtrace was also installed + **proven** (a benign `kill -WINCH` logged a
>    `from=bash` line). The next death is now attributable three ways: killtrace sender +
>    un-masked journal exit class + 3 s watch snapshot. If the killtrace shows NO external
>    sender at that death, the `Type=forking` unit is self-killing via ExecStop — fix that next.
>
> 3. **§7/§12's bridge shape is WRONG as written.** The real bridge is NOT a single
>    `~/.claude/session-bridge.json` document. It is a **directory of per-session files**,
>    `~/.claude/sessions/cc-<HOST_PID>.json`, each a flat JSON object keyed by
>    `session_id`/`cc_pid`/`listener_pid` (NOT by tmux session name; `tmux_session` is
>    often `None` for bare-bones sessions). None of the four `BRIDGE_MODE`s model this,
>    and the default path does not exist — so the reconciler as shipped **no-ops forever**
>    (a guard that cannot fail). Rework the reconciler to walk the `cc-*.json` directory
>    and prune files whose `cc_pid` is dead (start-time-checked) before relying on it.

**Audience.** An assistant (a fresh Claude instance with no prior context) executing
this on the user's Ubuntu box, plus the user themselves. Read the whole file before
running anything.

## 0. Mental model (why the sessions "vanished")

Two persistence layers, opposite behaviours:

- **tmux sessions are in-memory only.** When the tmux *server* process dies, every
  session, pane, and scrollback buffer dies with it, atomically. There is no on-disk
  session image to reattach to. `no server running on /tmp/tmux-1001/default` means
  the server process is gone.
- **Claude Code transcripts are on disk.** CC writes the conversation to
  `~/.claude/projects/<hash-of-project-abs-path>/<session-uuid>.jsonl` on **every
  event**, so a crash loses no conversation. The lost artifact is the terminal
  *scrollback*, not the CC conversation.

Therefore: you cannot "restore" tmux sessions — you **recreate** them and **resume**
the CC conversations into the new panes.

---

## 1. Immediate recovery (do this first if sessions are currently down)

List the most recent on-disk CC sessions to see what to resume and in which project:

```bash
find ~/.claude/projects -name '*.jsonl' -printf '%T+ %p\n' | sort -r | head -20
```

The parent directory encodes the project's absolute path (`/` → `-`); the trailing
UUID is the session ID. Relaunch through the user's existing launcher, **reusing the
same tmux session names** so the SessionStart hook re-registers them and the
listeners re-bind:

```bash
# Continue the most recent CC session for a project's cwd:
cd "$LUPIN_ROOT" && ./start-cc-with-tmux.sh lupin --continue
# Or resume a specific session id (cwd-independent, unambiguous):
./start-cc-with-tmux.sh lupin --resume <session-uuid>
```

Flags (verified current): `--continue`/`-c` = most recent session in the current
directory; `--resume`/`-r` = interactive picker, or by session id/name. **Do not**
resume the same session id in two panes at once — the transcripts interleave.

## 2. What this runbook installs

| Component | Path | Role |
|---|---|---|
| `tmux-server.service` | `~/.config/systemd/user/` | Supervises the tmux server; auto-restarts on ANY death; records the kernel exit reason; runs the reconciler on each (re)start; OOM-biased. |
| `tmux-watch.service` | `~/.config/systemd/user/` | Independent watcher; heartbeats server RSS; captures a one-shot forensic snapshot on the UP→DOWN edge. Separate unit/cgroup so it survives the window it observes. |
| `reconcile-bridge.py` | `~/.local/bin/` | Prunes session-bridge entries whose tmux session is no longer live. Fail-safe: no-ops on any unrecognized schema. |
| `tmux-watch.sh` | `~/.local/bin/` | The watcher loop. |
| *(optional, root)* `tmux-killtrace.service` | `/etc/systemd/system/` | bpftrace signal tracer — names the *sender* of the fatal signal. |

All units bind the **same** socket the launcher uses (bare `tmux` ≡ `tmux -L default`
≡ `/tmp/tmux-<uid>/default`), so `tmux new-session -s NAME` attaches to the supervised
server with zero launcher changes.

## 4. Bootstrap — writes all four core files, templates the tmux path, installs, enables

Save as `bootstrap.sh`, then `bash bootstrap.sh`. Idempotent; safe to re-run.

```bash
#!/usr/bin/env bash
# Lay down + enable the supervised-tmux + observability bundle (systemd --user).
# Requires: tmux, python3, systemd --user. Run while the tmux server is DOWN.
set -euo pipefail

TMUX_BIN="$(command -v tmux || true)"; [[ -n "$TMUX_BIN" ]] || { echo "tmux not on PATH"; exit 1; }
command -v python3 >/dev/null || { echo "python3 not on PATH"; exit 1; }

# Refuse to steal a socket from a live, non-systemd server.
if "$TMUX_BIN" -L default has-session 2>/dev/null; then
  echo "A tmux server is already on socket 'default'."
  echo "For clean systemd ownership, install while it's DOWN, or (DESTROYS sessions):"
  echo "  $TMUX_BIN -L default kill-server"
  exit 1
fi

BIN="$HOME/.local/bin"; UNIT="$HOME/.config/systemd/user"
mkdir -p "$BIN" "$UNIT" "$HOME/tmux-logs"

# ---- reconcile-bridge.py (quoted heredoc: nothing expands) -------------------
cat > "$BIN/reconcile-bridge.py" <<'PYEOF'
#!/usr/bin/env python3
"""Prune stale entries from the session-bridge file.

Removes entries whose named tmux session is not currently live on the supervised
server. Wired to tmux-server.service:ExecStartPost. On a cold restart (only
_keepalive live) every pre-crash entry is pruned; the SessionStart hook then
re-registers real sessions as the launcher recreates them.

SAFETY CONTRACT: if the file can't be parsed under the configured mode, or a
record's session-name can't be located, NO changes are made and it exits 0. A
stale entry is self-healing (re-registration overwrites it); a mangled bridge is
not. A .bak is written before any change; writes are atomic (temp + rename).

CONFIG (env, set in the unit):
  LUPIN_SESSION_BRIDGE  path            [~/.claude/session-bridge.json] (absent -> no-op)
  BRIDGE_MODE           dict|list|jsonl|lines            [dict]
  BRIDGE_SESSION_FIELDS record keys holding the session name (list/jsonl)
  TMUX_BIN, TMUX_SOCKET tmux invocation                  [tmux, default]

dict mode assumes EVERY top-level key is a tmux session name. If sessions are
nested under a wrapper, use list/jsonl or adjust — dict mode would prune wrapper keys.
"""
import json, os, shutil, subprocess, sys, tempfile, time

BRIDGE = os.environ.get("LUPIN_SESSION_BRIDGE", os.path.expanduser("~/.claude/session-bridge.json"))
MODE   = os.environ.get("BRIDGE_MODE", "dict").strip().lower()
FIELDS = [f.strip() for f in os.environ.get("BRIDGE_SESSION_FIELDS",
          "tmux_session,session_name,session,name").split(",") if f.strip()]
TMUX   = os.environ.get("TMUX_BIN", "tmux")
SOCK   = os.environ.get("TMUX_SOCKET", "default")
KEEP   = {"_keepalive"}
LOGDIR = os.path.expanduser("~/tmux-logs"); LOGF = os.path.join(LOGDIR, "reconcile-bridge.log")

def log(msg):
    os.makedirs(LOGDIR, exist_ok=True)
    line = f"{time.strftime('%FT%T')} reconcile: {msg}"
    print(line)
    try:
        with open(LOGF, "a") as fh: fh.write(line + "\n")
    except OSError: pass

def live_sessions():
    try:
        r = subprocess.run([TMUX, "-L", SOCK, "list-sessions", "-F", "#{session_name}"],
                           capture_output=True, text=True, timeout=5)
    except Exception as e:
        log(f"tmux unreachable ({e!r}); live set = empty"); return set()
    if r.returncode != 0:
        return set()
    return {s for s in r.stdout.split() if s}

def field_name(rec):
    if isinstance(rec, str): return rec
    if isinstance(rec, dict):
        for f in FIELDS:
            v = rec.get(f)
            if isinstance(v, str) and v: return v
    return None

def atomic_write(path, text):
    shutil.copy2(path, path + ".bak")
    fd, tmp = tempfile.mkstemp(dir=os.path.dirname(path) or ".", prefix=".bridge.", suffix=".tmp")
    try:
        with os.fdopen(fd, "w") as fh: fh.write(text)
        os.replace(tmp, path)
    finally:
        if os.path.exists(tmp): os.unlink(tmp)

def main():
    if not os.path.exists(BRIDGE):
        log(f"{BRIDGE} absent; nothing to do"); return 0
    raw = open(BRIDGE, encoding="utf-8").read()
    if not raw.strip():
        log("bridge empty; nothing to do"); return 0
    ok = live_sessions() | KEEP
    try:
        if MODE == "dict":
            doc = json.loads(raw)
            if not isinstance(doc, dict): raise ValueError("mode=dict but top-level is not an object")
            stale = [k for k in doc if k not in ok]
            if not stale: log(f"dict: no stale keys (live={sorted(ok - KEEP)})"); return 0
            for k in stale: doc.pop(k)
            atomic_write(BRIDGE, json.dumps(doc, indent=2) + "\n")
            log(f"dict: pruned {stale}; kept {sorted(doc)}"); return 0
        if MODE == "list":
            doc = json.loads(raw)
            if not isinstance(doc, list): raise ValueError("mode=list but top-level is not an array")
            kept, dropped, unknown = [], [], 0
            for rec in doc:
                nm = field_name(rec)
                if nm is None: kept.append(rec); unknown += 1
                elif nm in ok: kept.append(rec)
                else: dropped.append(nm)
            if unknown: log(f"list: {unknown} record(s) had no session field in {FIELDS}; kept")
            if not dropped: log("list: no stale records"); return 0
            atomic_write(BRIDGE, json.dumps(kept, indent=2) + "\n")
            log(f"list: pruned {dropped}"); return 0
        if MODE == "jsonl":
            out, dropped, unknown = [], [], 0
            for ln in raw.splitlines():
                if not ln.strip(): continue
                try: rec = json.loads(ln)
                except json.JSONDecodeError: out.append(ln); continue
                nm = field_name(rec)
                if nm is None: out.append(ln); unknown += 1
                elif nm in ok: out.append(ln)
                else: dropped.append(nm)
            if unknown: log(f"jsonl: {unknown} line(s) lacked session field; kept")
            if not dropped: log("jsonl: no stale lines"); return 0
            atomic_write(BRIDGE, "\n".join(out) + "\n")
            log(f"jsonl: pruned {dropped}"); return 0
        if MODE == "lines":
            out, dropped = [], []
            for ln in raw.splitlines():
                tok = (ln.split() or [""])[0]
                if not tok: out.append(ln)
                elif tok in ok: out.append(ln)
                else: dropped.append(tok)
            if not dropped: log("lines: no stale lines"); return 0
            atomic_write(BRIDGE, "\n".join(out) + "\n")
            log(f"lines: pruned {dropped}"); return 0
        log(f"unknown BRIDGE_MODE={MODE!r}; no-op"); return 0
    except (json.JSONDecodeError, ValueError) as e:
        log(f"parse failed under mode={MODE} ({e}); NO CHANGES (fail-safe)"); return 0
    except Exception as e:
        log(f"unexpected {e!r}; NO CHANGES (fail-safe)"); return 0

if __name__ == "__main__":
    sys.exit(main())
PYEOF
chmod 0755 "$BIN/reconcile-bridge.py"

# ---- tmux-watch.sh (quoted heredoc) -----------------------------------------
cat > "$BIN/tmux-watch.sh" <<'WATCHEOF'
#!/usr/bin/env bash
# Edge-triggered tmux liveness + death-context logger.
# UP: heartbeat with server RSS (memory trajectory -> leak/OOM signal).
# UP->DOWN edge: ONE forensic snapshot (service exit line, PSI, free, top RSS,
#   kernel ring if readable). DOWN->UP: recovery line.
set -uo pipefail
TMUX="${TMUX_BIN:-tmux}"; SOCK="${TMUX_SOCKET:-default}"
DIR="$HOME/tmux-logs"; mkdir -p "$DIR"; LOG="$DIR/tmux-watch.log"
UP_INT="${WATCH_UP_INTERVAL:-15}"; DOWN_INT="${WATCH_DOWN_INTERVAL:-10}"
ts(){ date +%FT%T%z; }
say(){ printf '%s %s\n' "$(ts)" "$*" >>"$LOG"; }
spid(){ "$TMUX" -L "$SOCK" display-message -p '#{pid}' 2>/dev/null; }
rssk(){ awk '/^VmRSS:/{print $2}' "/proc/$1/status" 2>/dev/null; }
nsess(){ "$TMUX" -L "$SOCK" list-sessions 2>/dev/null | wc -l; }
snapshot(){
  { echo "==== tmux server DOWN $(ts) ===="
    echo "-- last known: pid=$LP rss=${LR:-?}kB sessions=${LN:-?}"
    echo "-- service exit (authoritative signal/class):"
    journalctl --user -u tmux-server.service -n 15 --no-pager 2>/dev/null \
      | grep -E 'Main process|Failed|Killed|Stopped|status=' || echo "   (journal unavailable)"
    echo "-- PSI /proc/pressure/memory:"; cat /proc/pressure/memory 2>/dev/null
    echo "-- free:"; free -h
    echo "-- top RSS:"; ps -eo pid,ppid,rss,comm --sort=-rss | head -12
    echo "-- kernel ring (OOM?), if permitted:"
    { journalctl -k -n 40 --no-pager 2>/dev/null || dmesg -T 2>/dev/null | tail -40; } \
      | grep -iE 'oom|kill|tmux' || echo "   (kernel log unreadable as this user)"
    echo "==== end snapshot ===="
  } >>"$LOG"
}
STATE=unknown; LP=; LR=; LN=
while :; do
  if pid="$(spid)" && [[ -n "$pid" ]]; then
    LP="$pid"; LR="$(rssk "$pid")"; LN="$(nsess)"
    [[ "$STATE" != up ]] && { say "server UP pid=$pid sessions=$LN"; STATE=up; }
    say "hb pid=$pid rss=${LR}kB sessions=$LN"
    sleep "$UP_INT"
  else
    [[ "$STATE" != down ]] && { say "server DOWN"; snapshot; STATE=down; }
    sleep "$DOWN_INT"
  fi
done
WATCHEOF
chmod 0755 "$BIN/tmux-watch.sh"

# ---- tmux-server.service (UNquoted heredoc: interpolates $TMUX_BIN only; the
#      units contain no other shell-special sequences. %h/%U are systemd
#      specifiers and are NOT touched by the shell) ---------------------------
cat > "$UNIT/tmux-server.service" <<UNITEOF
# Supervised, self-restarting tmux server. Decode the next death via:
#   journalctl --user -u tmux-server.service -n 30 --no-pager
#   status=9 SIGKILL -> OOM or kill -9   | status=15 SIGTERM -> teardown/pkill
#   status=1 SIGHUP  -> stray HUP        | dumped -> tmux crash (escalate -vv)
#   exited status=0  -> a clean tmux kill-server was issued somewhere
[Unit]
Description=Persistent tmux server (uid %U, socket "default")
After=default.target
StartLimitIntervalSec=60
StartLimitBurst=5

[Service]
Type=forking
ExecStart=$TMUX_BIN -L default new-session -d -s _keepalive
# ExecStartPost (not Pre): the reconciler needs a live socket for list-sessions
# to be authoritative; at Pre the old server is dead and it can't tell "empty"
# from "unreachable". At Post the fresh server reports only _keepalive, so a cold
# restart correctly classes every pre-crash entry as stale.
ExecStartPost=%h/.local/bin/reconcile-bridge.py
ExecStop=$TMUX_BIN -L default kill-server
Restart=always
RestartSec=2
# OOM-bias AWAY from this cgroup. NOTE: panes forked from the server inherit this
# score, so the kernel looks OUTSIDE this cgroup first (e.g. GPU inference).
# For per-pane degradation, raise the pane score in the launcher INNER (see runbook §8).
OOMScoreAdjust=-800
OOMPolicy=continue
Environment=TMUX_BIN=$TMUX_BIN
Environment=TMUX_SOCKET=default
# vvv EDIT: until this path EXISTS the reconciler no-ops (fail-safe). vvv
Environment=LUPIN_SESSION_BRIDGE=%h/.claude/session-bridge.json
Environment=BRIDGE_MODE=dict
Environment=BRIDGE_SESSION_FIELDS=tmux_session,session_name,session,name

[Install]
WantedBy=default.target
UNITEOF

# ---- tmux-watch.service (UNquoted heredoc: interpolates $TMUX_BIN) -----------
cat > "$UNIT/tmux-watch.service" <<UNITEOF
[Unit]
Description=tmux server death/health watcher
After=default.target

[Service]
Type=simple
ExecStart=%h/.local/bin/tmux-watch.sh
Restart=always
RestartSec=2
OOMScoreAdjust=-900
Nice=5
Environment=TMUX_BIN=$TMUX_BIN
Environment=TMUX_SOCKET=default

[Install]
WantedBy=default.target
UNITEOF

systemctl --user daemon-reload
systemctl --user enable --now tmux-server.service tmux-watch.service

echo
echo "Installed. Verify with:"
echo "  systemctl --user status tmux-server.service tmux-watch.service"
echo "  $TMUX_BIN -L default list-sessions        # expect: _keepalive"
echo "  tail -f ~/tmux-logs/tmux-watch.log"
echo
echo "NEXT: set the real bridge path + mode in ~/.config/systemd/user/tmux-server.service"
echo "then: systemctl --user daemon-reload && systemctl --user restart tmux-server.service"
```

## 5. Launcher interaction (no changes required)

The user's `start-cc-with-tmux.sh` calls `tmux new-session -s "$NAME" ...` with no
`-L`, i.e. the `default` socket — the same one systemd now owns. So sessions land on
the supervised server automatically, the `--vertex` `tmux start-server` becomes a
no-op (server already exists), and `tmux has-session` checks continue to work. The
`_keepalive` session is inert and can be ignored (the reconciler never prunes it).

## 7. Required config: point the reconciler at the real bridge (human input)

Edit `~/.config/systemd/user/tmux-server.service`:

```ini
Environment=LUPIN_SESSION_BRIDGE=/absolute/path/to/your/session-bridge
Environment=BRIDGE_MODE=dict          # choose per the file's shape:
# dict  -> top-level JSON object keyed by session name: {"lupin": {...}, "bar": {...}}
# list  -> JSON array of records; session name in BRIDGE_SESSION_FIELDS
# jsonl -> one JSON object per line;   session name in BRIDGE_SESSION_FIELDS
# lines -> plain text; session name is the first whitespace token per line
```

Then `systemctl --user daemon-reload && systemctl --user restart tmux-server.service`
and confirm `~/tmux-logs/reconcile-bridge.log`. A wrong `dict` guess on a wrapper-shaped
file is the one risky case — the reconciler writes a `.bak` first, but prefer to
confirm the shape (paste a redacted sample) before enabling on a nested bridge.

## 8. Optional: per-pane OOM graceful degradation (opt-in launcher edit)

`OOMScoreAdjust=-800` protects the whole cgroup, so under memory pressure the kernel
targets processes *outside* it first (e.g. the dual-4090 inference stack). To instead
let a single runaway **pane** be sacrificed while the server survives, add one line to
the launcher's `INNER` construction so each pane re-raises its own score:

```bash
INNER+="echo 200 >/proc/self/oom_score_adj 2>/dev/null; "
```

This is a deliberate tradeoff (protect the coding fleet vs. protect long-running
inference). Do not apply without the user's decision.

## 9. Debugging the next death (the whole point)

Two logs give the verdict:

1. **Signal class** — `journalctl --user -u tmux-server.service -n 30 --no-pager`:
   - `code=killed, status=9` (SIGKILL) → OOM killer or `kill -9`. Confirm OOM:
     `journalctl -k --since "10 min ago" | grep -iE 'out of memory|killed process|oom-kill'`.
   - `code=killed, status=15` (SIGTERM) → something asked politely: a teardown script,
     a broad `pkill -f`, or a scope stop.
   - `code=killed, status=1` (SIGHUP) → a stray HUP reached the server (relevant to any
     SIGHUP-triggered reload path — verify nothing HUPs the wrong process group).
   - `code=dumped` → tmux crashed. Escalate: add `-vv` to `ExecStart`
     (`$TMUX_BIN -vv -L default new-session ...`); a verbose `tmux-server-<pid>.log`
     lands in the working dir. Chatty — revert once captured.
   - `code=exited, status=0` → a clean `tmux kill-server`. Hunt it:
     `grep -rn 'kill-server' ~/.claude ~/bin ~/.config 2>/dev/null`.
2. **Memory trajectory + pressure** — `~/tmux-logs/tmux-watch.log`: the last few
   heartbeats before the DOWN line show whether server RSS was climbing (leak) or the
   box was under memory pressure (PSI + `free` + top-RSS in the snapshot).

If §9.1 says SIGKILL/SIGTERM but the sender is unclear, install the **optional root
tracer** (§10) to name it.

## 10. Optional root signal tracer (names the sender)

Requires `sudo` and `bpftrace` (`sudo apt install -y bpftrace`). Install only on request.

> **⚠️ CORRECTED 2026-07-14 (installed + proven on this box, bpftrace on Ubuntu / tmux 3.x).**
> The original single-line `-e` form in this section was **doubly broken** and never ran:
>
> 1. **`str(args->comm)` fails to compile.** On this bpftrace version `args->comm` is
>    already a fixed `string[16]`, and `str()` rejects it: *"str() expects an integer or
>    a pointer type as first argument (string[16] provided)."* Compare the string
>    **directly**: `/args->comm == "tmux: server"/`.
> 2. **systemd eats the `\n`.** Inside a unit `ExecStart=`, systemd expands `\n` into a
>    real newline, which splits the bpftrace program mid-string → *"unterminated string."*
>    (The `%%`→`%` escaping was fine; the `\n` was not.)
>
> Both traps vanish if you stop cramming the program into the unit line and put it in a
> standalone `.bt` file — no systemd re-interpretation, no `%%`, no `\n` escaping. Use
> the two-file form below. Also note `tmux kill-server` and a clean tmux self-exit send
> **no signal**, so they do NOT appear here — this tracer catches `kill()`-family signals
> (SIGKILL/SIGTERM/SIGHUP/…) only; cross-read with §9's journal line for clean exits.

**Step 1 — the bpftrace program, as its own file** `/etc/tmux-killtrace.bt`:

```
tracepoint:signal:signal_generate
/args->comm == "tmux: server"/
{
    printf("%s sig=%d target=%d from=%s pid=%d uid=%d\n",
           strftime("%H:%M:%S", nsecs), args->sig, args->pid, comm, pid, uid);
}
```

**Step 2 — the unit** `/etc/systemd/system/tmux-killtrace.service` (just points at the file):

```ini
[Unit]
Description=Trace signals sent to the tmux server
After=multi-user.target

[Service]
ExecStart=/usr/bin/bpftrace /etc/tmux-killtrace.bt
StandardOutput=append:/var/log/tmux-killtrace.log
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

**Step 3 — validate, install, PROVE:**

```bash
sudo bpftrace /etc/tmux-killtrace.bt          # must print "Attaching 1 probe..." with NO error; Ctrl-C
sudo systemctl daemon-reload && sudo systemctl enable --now tmux-killtrace.service
sudo systemctl status tmux-killtrace.service  # want: active (running), NOT auto-restart
# PROVE it captures (a null tracer is not evidence until proven): fire a benign signal
kill -WINCH "$(tmux -L default display-message -p '#{pid}')"
sudo tail -n 3 /var/log/tmux-killtrace.log     # expect a sig=28 line naming from=bash
# After the next real death:
sudo tail -n 20 /var/log/tmux-killtrace.log
```

In the output, `from`/`pid`/`uid` are the **sender**. A userspace killer (e.g. `pkill`)
shows its command; a kernel-origin OOM kill shows a `kworker`/kernel sender and is
cross-checked in `journalctl -k`. The comm string `"tmux: server"` (with the colon and
space) is the tmux server's `/proc/<pid>/comm` — verify with `cat /proc/<pid>/comm` if
the filter ever silently matches nothing.

Auditd alternative (no bpftrace):

```bash
sudo auditctl -a always,exit -F arch=b64 -S kill,tkill,tgkill -k tmuxkill
sudo ausearch -k tmuxkill --start recent
```
