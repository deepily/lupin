| | |

## 4. Cross-section ratification

### The reconciled contract — `answer_delivered_at`

**Three receipt-gated setters**, stated in §4.3, §4.4 and §4.5 in the same words:

| | Setter | Fires when |
|---|---|---|
| (a) | §4.3 live path | the SSE waiter is woken — the asking coroutine consumed the value |
| (b) | §4.4 pull path | the client's positive **ack of consumption** |
| (c) | §4.5 re-attach | a successful land — value returned to the caller — **acks on land** |

**Never a setter**: `listener_delivered` True · a successful `send_json` · an emit attempt · *serving* a row.
**One reader**: §4.4's owed query. **Fails toward re-delivery, never toward silence.**

### The design-level invariant (§3)

> `responded_at IS NOT NULL` is the **sole discriminator** between "a human answered" and "a default was manufactured."

Discovered **independently three times, in three sections, by two reviewers**. Stated once in §3; referenced from §4.1, §4.4 and §4.5. Anything deciding answered-ness on `state`, on `response_value` being non-null, or on a bespoke boolean is wrong by construction.

### The owed predicate — three terms, none redundant

```sql
response_requested AND responded_at IS NOT NULL AND answer_delivered_at IS NULL
```

| Term | Guards against |
|---|---|
| `response_requested` | it was an ask at all |
| `responded_at IS NOT NULL` | forged defaults **and** premature replay of still-pending live asks |
| `answer_delivered_at IS NULL` | answers already received |

Present in exactly three places — ORM index, concurrent migration, repo query — character-identical.

### The one reviewer disagreement, and how it was settled

**Rio vs Rachel, §4.3 step 4's durable gate.** Rio: the gate decides on a send signal, so it has the same disease as the setter. Rachel: leave it — step 5's owed-flag already covers the True-but-dropped case, and firing on True adds a *third* simultaneous copy plus a key mismatch (`job_id` carrier vs `notification_id` catch-up).

The reconciliation explicitly left this **for the author**, not for me — resolving a real disagreement by manager fiat would have buried the reasoning. **Tiberius settled it siding with Rachel**, with his reasoning stated in-doc, before seeing that Krishna independently leaned the same way on testability grounds.

I contributed one thing, so the losing side got an argument rather than an overrule: **`listener_delivered` is trustworthy in the FALSE direction only.** False means no socket or `send_json` threw — the frame definitely did not get through. True means only that it reached the buffer. Gating the durable carrier on the *informative* direction is sound (Rachel); reading True as a receipt is not (Rio). Both were right about different halves, and the asymmetry is what reconciles them. **Settled, not open.**
