## TL;DR

The live reap→prune mechanism is **complete and correct on paper**: `dismiss_sessions` →
`_default_emit_reap` → `POST /api/notify(type=session_reaped, sender_id, target_user)` → WS
`notification_queue_update` → `SessionStripStore.handleReaped(sender_id)` → `sessions.delete()`.
The card is pruned live **iff** that one WS frame is delivered. The bug is what happens when it
**isn't** (owner's WS briefly disconnected at reap time, or the best-effort emit fails silently):
**the reconnect re-hydrate does NOT prune the stale card, because `hydrate()` is additive-only.**
A full page refresh clears it only because refresh rebuilds the store **from empty** — an
*implicit* reconcile the reconnect path lacks. That asymmetry is the whole bug.

## Root cause — additive-only `hydrate`, no reconnect reconcile

`hydrate()` upserts every persona-carrying record and **never removes** a strip session absent-or-
null in the fresh snapshot — a deliberate invariant (gate condition (c) of the option-2 ruling:
"reuse the idempotent `hydrate()`, NO store surgery"). Tiffany's landed `StripReconnectRehydrator`
(`ff9aec9c`) re-runs that same additive `hydrate()` on the reconnect edge — which **refills missing
icons** (her bug) but **cannot prune stale ones** (this bug). The two are exact complements:

```
missed session_reaped (WS down at reap OR best-effort emit failed)
   → stale card stays in the Map (active=true, retains its assign-time M badge)
   → reconnect re-hydrate: additive merge → stale card SURVIVES
   → full page refresh: store rebuilt from empty → reaped row skipped (null persona) → card GONE
```

## Fix options (the fork for Mr. Radio)

All confine the change to the **reconnect** path (leave cold-boot `hydrate` additive so gate
condition (c) for boot is untouched); add a reconcile/prune pass invoked by
`StripReconnectRehydrator` after `hydrate`.

1. **Prune in-snapshot-null-persona (recommended, safest).** Remove a store session only when the
   server's snapshot INCLUDES its sender_id **with** a null/released persona (server authoritatively
   says "persona-less now"). A live-assigned-but-not-yet-persisted session is ABSENT from the
   snapshot → never pruned → the additive/live-event safety Tiffany preserved is kept.
   - **Covers**: the reported case (reaped rows ARE in senders-visible with null persona).
   - **Behavior change**: a *released-but-alive* session's inactive icon is also pruned on reconnect
     — but that already matches refresh behavior (refresh skips null-persona), so reconnect becomes
     consistent with refresh. Worth Mr. Radio's explicit nod.
   - **Gap**: a reaped worker that NEVER produced a senders-visible row (no notifications in
     retention) is ABSENT from the snapshot → not pruned. Narrow; persona-assign itself emits a
     notification, so most reaped workers have a row.
2. **Full rebuild on reconnect (clear-then-hydrate).** Make reconnect match refresh exactly.
   - **Covers**: everything, including the no-row reap.
   - **Cost**: reintroduces the live-assign race Tiffany's additive design avoided (a live
     `voice_persona_assigned` arriving between fetch and hydrate gets cleared). Needs a timestamp
     guard (only clear sessions whose `assigned_at` predates the fetch), which is the real cost.
3. **Server-side reliability only.** Harden `_default_emit_reap` routing/retry so the live frame is
   never missed. Doesn't help a genuinely-offline owner (can't deliver to a closed socket) → does
   NOT fully close the bug; the reconcile is still needed for the offline-at-reap window.

**Recommendation: option 1** — smallest surgery, preserves the live-event safety, closes the
reported case. Escalate to option 2 only if the no-row-reap gap matters.

## Implementation (option 1, ratified)

Confined to the **reconnect path**; cold-boot `hydrate` stays additive (gate condition (c)
honored). New `SessionStripStore.reconcile(records)` = the additive `hydrate` upsert PLUS a prune
of the sender_ids the snapshot reports as persona-less (null/released); `StripReconnectRehydrator`
calls `reconcile` for the strip (`senders` keeps `hydrate`). A shared private `upsertRecords`
returns the null-persona set so `hydrate`/`reconcile` share one loop with byte-identical upsert
behavior. Each pruned session emits a `"removed"` (only when it was actually tracked — `Map.delete`
truthiness), so the renderer's focus-auto-exit fires exactly as on a live reap; a final `"hydrated"`
drives the full DOM reconcile.

- `stores/SessionStripStore.ts`: `upsertRecords` helper + `reconcile()` + interface entry.
- `stores/StripReconnectRehydrator.ts`: `StripRehydrateStores.sessionStrip` typed to `reconcile`;
  the reconnect fetch calls `sessionStrip.reconcile(records)`.

### Documented residuals & behavior notes (ratified)

- **KNOWN-ACCEPTED — absent-from-snapshot reap.** A reaped worker that produced NO `senders-visible`
  row (no notifications in retention) is ABSENT from the snapshot, so `reconcile` does not prune it
  (pruning absent sessions would reintroduce the live-assign race option 1 avoids). It still clears
  on a full refresh (empty-rebuild). Narrow — persona-assign itself emits a notification, so most
  reaped workers have a row. Option 2 (timestamp-guarded full rebuild) is the escalation if this
  edge ever bites; not taken (more machinery for a rarer edge — Mr. Radio concurred).
- **Behavior change (accepted) — released-but-alive icon.** A persona-released-but-still-alive
  session has a null-persona snapshot row, so `reconcile` prunes its inactive icon on reconnect.
  This MATCHES full-refresh behavior (cold `hydrate` already skips null-persona), so reconnect
  becomes consistent with refresh — acceptable per Mr. Radio's ruling.
- **Secondary-wart refutation (row receipt).** The bug body's "null-persona rows still hydrate
  post-refresh" is REFUTED for the strip store: `SessionStripStore.ts:261` (`hydrate` skips
  null/released-persona records) means a refresh never re-adds a reaped card. Receipt accepted by
  Mr. Radio; noted on the store row at close.
