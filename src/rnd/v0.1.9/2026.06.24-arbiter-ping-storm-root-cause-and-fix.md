## The fixes (build these)

### Fix 1 — Reap clears the hold file (PRIMARY, highest value)
`dismiss_sessions` / the reap path must delete (or move-aside) the reaped session's `.heartbeat-hold-<sid>.json` at reap time — not just the bridge. Reuse `heartbeat_hold.clear_hold( session_id )`. Belt-and-suspenders: also tighten `prune_stale_hold_files` so a hold whose session is provably dead (no live tmux/bridge) is prunable sooner than TTL+6h — but ONLY on a positive dead reading (keep the bias-to-keep on any uncertainty; a live session can carry a stale hold — proven this session).

### Fix 2 — Staleness-gate hold-derived edges uniformly
Wherever the arbiter turns a hold's `awaiting=peer:X` into a wait edge, gate it through the SAME `dependency_graph.session_is_stale( view, now, alive_threshold_seconds )` predicate the bridge edge path already uses (37511bfb). A stale holder contributes ZERO edges. Fail-safe identical to 37511bfb: missing/unparseable ts → treat as NOT stale → keep the edge (never hide a live block).

### Fix 3 — De-dup the r2 double-fire
Find why each advisory emits twice (original + `-r2`). If it's a listener-layer re-delivery, collapse to one delivery per `outreach_id`. If `-r2` is an intentional retry, gate it on the original NOT having been ACK'd (don't re-fire an advisory whose `expects_ack=false`). Net goal: one user-visible ping per distinct advisory per poll.

### Fix 4 — (optional, low priority) Manager liveness during long interactive turns
A manager mid-`ask_*` walkthrough is alive but emits no hold-mtime refresh. Consider counting an in-flight blocking `ask_*`/recent tool activity as a manager liveness signal, OR documenting the "refresh your hold before a long walkthrough" discipline. Spec only if cheap; otherwise file as follow-up.
