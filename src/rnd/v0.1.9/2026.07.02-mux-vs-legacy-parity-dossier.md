## 4. Known-open items (by design — NOT regressions)

1. **TTS queue pane lands DARK (row 11).** Lane 1 (TTS-queue restore) merged the templates, header transport, and renderer wiring (`c2562b2e`), but the tts-pane deliberately stays `data-phase6-pending` until **WP5** wires it live. This is a staged-landing decision, not a parity break — the chrome is present and reviewed (Clayton PASS ×3); only the live activation is deferred. **Not a Rick-gate.**

2. **Abstract node divergence (row 12).** The mux renders no bare `.abstract` element; the "abstract visible" signal is carried by its structural equivalents — non-empty `#content-pane-body` for regular reading-pane content, and `.action-required-prompt` for the AR-widget context. The legacy↔mux `.abstract` selector map is **retired** (documented in `test_tier_horizontal.py` + `test_multiplexer_horizontal_pane_open_parity.py`). This is an implementation choice with equivalent user-visible content, **not a missing surface.**

3. **Absolute pane-width in horizontal pane-open is NOT compared** (row 9). Legacy uses a variable split ratio; the mux forces 50/50 while AR owns the pane. Per the same no-absolute-offset rule the vertical oracle uses (`test_tier2_tier3.py`), only structural presence + center-shift are asserted cross-client. A design difference, not a defect.

None of the three require code changes to unblock `ffecbcdf`; items 1 (WP5) is tracked separately on the TTS lane.

### Exact steps

1. Ensure the dev server is up on **:7999** (no bounce needed; read-only look).
2. Open the two surfaces in adjacent browser tabs/windows at a **≥1200px-wide** viewport (the horizontal-mode hint reads "Best at viewports ≥ 1200px wide"):
   - **Legacy**: `http://localhost:7999/app/notifications?classic=1`
   - **Mux**:    `http://localhost:7999/app/multiplexer`
3. **Vertical mode (default load)** — compare side by side:
   - top nav bar, sender cards, action-required panel, notifications header (with the cc-tts-fraction slider), broadcast card + ▼ toggle.
4. **Horizontal mode** — on each, toggle to horizontal (mux: click the `#layout-mode-toggle` ▭/⊞ control top-right; legacy: the `⇆` control), then compare:
   - the toolbar reflow (column→row), the 52px container clearance, and the centered content column.
5. **Horizontal pane-open** — trigger/await an action-required prompt on each; confirm the reader-pane split + the AR widget read equivalently.
