# Arbiter offset-reset hardening (bug 5a1f17f8)

**Date**: 2026.07.02 · **Owner**: Rio ⚡ · **Manager**: Tiberius 👑 · **Priority**: P2
**Follow-on to**: 92c7ab1d (bridge-mtime veto) + 8894e597 (one-way framing), merged `59ba12e5`.
**Evidence**: Mr Radio's preserved events file `8a92b253` (156 records) — frozen into the RED bench at `src/tests/unit/fixtures/arbiter_offset_reset_events.jsonl`.

## Root cause

The 2026-07-02 false-STUCK loop-poke (three ~60s fires after each of two `:8001`
restarts) traces to the events-tail offset lifecycle. `ArbiterConsumerJob` holds the
per-session byte offsets in memory (`self._offsets`) and passes them to
`events_tail.tail_fleet_events` each poll. On a **restart** the process starts with
`self._offsets = {}`, so `tail_fleet_events` re-reads **every** `~/.claude/heartbeat-events/*.jsonl`
from byte 0 and re-consumes **historical** `cap_reached` records as if fresh. Those
land in the 50-deep accumulated tail and re-trip `stuck` (`_count_stuck_episodes >= 2`),
even though the session recovered long ago (Mr Radio's file: last real `cap_reached`
21:27Z, followed by 5 `honored`/`poke_count=0`). The 92c7ab1d bridge-veto defends the
*active-session* case; this class is the *restart-replay* case it doesn't cover.

## Three-part fix (Mr Radio's a/b/c), all RED-first + 100% L/B/F

### (a) freshness-gate consumed `cap_reached` — `fleet_data_model._count_stuck_episodes`

A `cap_reached`+owed is now counted **only if no later `honored` recovery** appears in
the ordered (oldest→newest) tail — a `honored` after it means the session moved to
defended quiescence / resumed, so that wedge is *consumed*, not live. Deterministic, no
`now`/threshold knob. A genuinely wedged session emits repeated `cap_reached` with **no**
intervening `honored` → they all count → the true-positive is preserved.
**Real-fixture proof**: OLD count = 5 (false `stuck=True`, the loop) → NEW count = 0
(`stuck=False`). This alone makes any replayed/lingering record harmless.

### (b) durable event offsets across restarts — `events_tail` + `ArbiterConsumerJob`

New swallow-safe `save_offsets(path, offsets)` (atomic temp+replace) / `load_offsets(path)`
(missing/corrupt/non-dict → `{}`). `ArbiterConsumerJob` gains an injectable
`offsets_state_path`: **load on init** (resume, not byte-0) + **save after each poll**.
Inert when `None` (today's in-memory behavior). The `:8001` factory wires the real path
(`_offsets_state_path(cfg)` → `arbiter event offsets state path`, default
`/io/arbiter/event-offsets.json`), mirroring `_lineage_carry_path`. This stops the
re-read at the source — a bounce resumes where it left off, no replay. Rotation-safe:
a shrunk file self-corrects downstream (`tail_session_file`: offset > size → 0).

### (c) fire-throttle — `_auto_poke`

New `stuck_poke_min_interval_seconds` (INI `arbiter stuck poke min interval seconds`,
default **0 = disabled**). Where `poke_max_per_episode` bounds *how many* pokes an
episode gets, the throttle bounds their *rate*: a poll that would poke a session sooner
than the interval is **skipped without consuming the per-episode budget**; the throttle
re-arms when the episode ends. Belt against any residual storm. Ships disabled because
(a)+(b) already remove the specific restart-replay storm — it's defense-in-depth the
operator can turn on.

## Layering

(a) makes replayed records harmless · (b) prevents the replay · (c) rate-limits the
poke path regardless. (a) is the load-bearing symptom fix; (b) the root-cause
prevention; (c) an operator belt. Composes with 92c7ab1d (active-session bridge-veto).
