**Problem:** it lives INSIDE the `heartbeat_arbiter` package — not a neutral shared location. So the DM path can't cleanly reuse it, and reusing-by-importing-from-the-arbiter would be a bad dependency direction.

## The fix (3 steps)

### Step 1 — Extract the formatter to a central, neutral module (single source of truth)
Create e.g. `src/cosa/utils/edt_timestamp.py` (implementer picks the exact home; `cosa/utils/` is the natural neutral spot, importable by both the REST layer and the arbiter). It owns: `OUTREACH_TS_FORMAT`, `DEFAULT_TZ_NAME`, `resolve_tz()`, and a public `format_edt_timestamp(dt=None, tz_name=None) -> str` returning the bracketed prefix string `[YYYY.MM.DD at HH:MM:SS]` (decide: include the brackets in the helper, or return the inner string and let callers bracket — match the arbiter's actual output exactly). DST-aware, degrade-safe to UTC.

### Step 2 — Refactor the arbiter to import from the central module (DRY; behavior BYTE-IDENTICAL)

### Step 3 — Prefix every DM at the chokepoint

Applies to all directions (worker↔manager, manager↔manager). Confirm the prefix lands in the body the recipient actually sees (the inline `ai_to_ai` push body), and that threading/reply metadata is untouched.
