## 2. Leg 2 — AC-D7: the logging oracle is INADMISSIBLE until a canary row lands

**The problem AC-D7 must survive**: zero rows means BOTH "nothing ran" AND "it ran and we're blind." A test
that asserts on this table without first proving the table can speak is a formality that returns green.

**AC-D7 semantics (normative):**
1. **Fire a known-positive canary** — one prediction call through the logged publisher path (a Claude model —
   the PublisherModelConfig is the anthropic-publisher config; the clamped 500 out-TPM comfortably fits a
   tiny call) carrying a unique greppable sentinel (`lupin-acd7-canary-<epoch>`). EXECUTOR: Mr. Radio/Rick —
   it is spend, ~cents.
2. **Poll for the canary row** — partition-scoped to stay in the free tier:
   ```sql
   SELECT logging_time, model, api_method
   FROM `hello-world-foo-423219.vertex_logging.request_response_logging`
   WHERE logging_time >= TIMESTAMP_SUB( CURRENT_TIMESTAMP(), INTERVAL 2 HOUR )
     AND ( TO_JSON_STRING( full_request ) LIKE '%lupin-acd7-canary-%'
           OR EXISTS ( SELECT 1 FROM UNNEST( request_payload ) p WHERE p LIKE '%lupin-acd7-canary-%' ) )
   ```
   Poll cadence ~60s. **The elapsed time to first appearance IS the measured ingest latency for this run** —
   recorded, never assumed (no hardcoded wait; the AC-D8 canary-not-clock rule applies here verbatim).
3. **Verdict mapping**:
   - Canary row appears → **AC-D7 GREEN**, and only from that moment are claims about OTHER rows admissible
     (including negatives like "the Max session produced no row", window-scoped after the canary's landing).
   - Canary never appears within the run's budget (suggest 30 min — generous vs the ~2–3 min PublisherModel
     metric ingest measured earlier) → **AC-D7 INADMISSIBLE, NOT FAILING, NOT PASSING** — and simultaneously a
     REAL FINDING: the logging config read back `enabled=true` yet the sink does not receive; escalate as a
     config-attachment defect, do not re-run and hope.
4. **Bonus assertion once the canary lands**: inspect the canary row's `full_response` for reasoning-shaped
   content — closes 823be9cc's Claude-path half for free; the MaaS-publisher half still needs that bug's own
   sentinel probes.

**Canary role framing** (cited from clamp-prep doc §8, one concept, not forked): read-backs prove
*configured*; only a known-positive through the instrument proves *live*. The quota canary proves the brake
brakes (a 429 that MUST happen); this logging canary proves the oracle sees (a row that MUST land). Same
doctrine, two instruments.

## 3. Leg 3 — AC-D5 precedence: INDETERMINATE ≠ FAILED (closes F-D18)

AC-D5 (web-search precedence) necessarily rides this BQ log — it is the only place tool-use is visible.
**Normative rule**: AC-D5 evaluates ONLY when AC-D7 is GREEN in the same run.

| AC-D7 state | AC-D5 must report |
|---|---|
| GREEN (canary landed) | PASS / FAIL on the actual rows |
| INADMISSIBLE (canary never landed) | **INDETERMINATE** — "we cannot see" |
| Not yet run | INDETERMINATE |

"Search didn't fire" and "we cannot see" are different claims; a harness that conflates them converts
blindness into a green checkmark. The INDETERMINATE verdict is loud in reports — it blocks any AC-table row
that depends on it from reading as satisfied.
