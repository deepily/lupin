## 2. The two policy changes

### (1) Unknown-persona soft-flag
Persona fields (`owner_persona`, `accountable_manager`) on `task_create` / `task_reassign`
(server-side: the `POST /api/tasks` create path and the `PATCH /api/tasks/{id}` reassign
path) that canonicalize to a key matching **no known persona** get a **log-warn + an advisory**
— **NOT a hard 422**. New / cross-project personas are legitimately absent from any roster; a
hard gate would have blocked María's founding P1 filing. Hard-gating is only reconsiderable
if/when a *cross-project* roster accessor exists.

### (2) Class-scoped owner guard
`owner_persona` is required for the **owned-work classes** (`task` / `bug` / `review_request`)
but is **defaulted to the creator's persona on omission** (Krishna's refinement: forgiving,
never a hard 422 — María's NULL-owner filing 3a14292b was a simple omission). `decision` and
`gate` operator-queue rows stay **ownerless BY DESIGN** (Rick's court).

## 3. Decisions resolved with the manager

### D1 — roster-accessor location (CONFIRMED)
The task's premise "no roster accessor exists" came from a grep for a *roster* accessor. The
better finding: **`src/cosa/rest/voice_persona_helpers.py::load_persona_pool_from_config(config_mgr)`
already reads the `cc session voice persona *` INI keys** and returns the allocatable pool. We
reuse it — no new INI reader.

The roster is exposed to the pure-rules layer by mirroring the **existing `_get_default_scope_roots()`
precedent** already in `task_store_rules.py` (a lazy config-backed singleton that receipt
validation injects, tests overriding via a `scope_roots=` param). We add a twin
`_get_known_persona_keys()` lazy singleton + pure helpers with an **injectable `known_keys=`**
parameter — keeping `task_store_rules.py`'s purity model and 100%-unit-testability intact.

Roster set = pool-CSV names **∪** the overflow persona, each run through `canonical_persona_key`
(the pool INI keeps mixed case "Rachel"/"Tiberius"; the store key is accent/punct-stripped +
lowercased).

### D2 — advisory-field shape (COMPOSITE RULING)
Rejected: a new column (schema churn) and a **second** audit event (highest-churn "schema-free"
option — create's write is atomic `create_item` + exactly ONE `->queued` event, and the event
model has no advisory shape). The `title_guard` same-endpoint precedent
(`create_task` already returns `result["title_guard"]`) plus the atomic-create reality decided
it. Ruling:

- **PRIMARY**: a **response advisory field `persona_flag`** (mirrors `title_guard`; `None` when
  nothing is off-roster) + a **server log-warn** (`print`, mirroring the non-terse query WARN).
- **ALSO** (manager-sweep queryability at zero schema, zero new events): fold a **compact marker**
  into the `reason` of the **existing** event each path already writes —
  `[persona_flag: owner 'foo' off-roster]`.
  - **Patch path**: appended to the `patched` event's reason (preserving the caller reason / auto
    field-delta).
  - **Create path**: the `->queued` event. Kept (NOT dropped): `create_item` already delegates to
    `_append_event`, which already supports a `reason` — folding needs only a generic optional
    `flag_suffix` param on `create_item`, NOT new plumbing / a new event. Judgment relayed to the
    manager (his drop-if-costly fallback does not trigger).

Implementation keeps the repository **roster-agnostic**: `create_item` and `apply_patch` gain a
generic `flag_suffix: Optional[str] = None` they append to the event reason; **all** roster logic
lives in the pure rules helpers, and the router assembles the marker.

### D3 — owner-default mechanics (CONFIRMED)
`created_by` is contract-stamped `"<persona> <8-hex sid>"` (`task_store_tools.py:113`, e.g.
`"mr radio 372f9dc9"`). Pure helper `persona_from_created_by()`: `rsplit(" ", 1)`; if the tail
matches a session-id shape `^[0-9a-f]{6,}$` → persona = head, else the whole string; finish with
`canonical_persona_key`. On create, for `item_class ∈ DEFAULT_OWNER_CLASSES` with `owner_persona`
omitted (or blank → canonicalizes to `None`) → default to that derived persona. `decision` / `gate`
untouched. `DEFAULT_OWNER_CLASSES` stays a tuple constant.
