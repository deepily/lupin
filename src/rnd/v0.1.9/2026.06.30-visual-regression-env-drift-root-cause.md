## TL;DR

The `:8000` merge-gate visual regression suite is RED because **the container is missing
the `fonts-dejavu-core` package**. Lupin's CSS font stacks all terminate in the generic
`sans-serif`, and none of the named fonts before it (`-apple-system`, `Segoe UI`, `Roboto`,
`Helvetica Neue`) exist on Linux — so fontconfig falls through to the terminal generic.

- **Host** (where baselines were captured): `sans-serif` → **DejaVu Sans**
- **Container** (`lupin-rest-test`, where the merge-gate renders): `sans-serif` → **WenQuanYi Zen Hei** (a CJK font)

Every page with text renders in a **completely different typeface** between the two
environments → all git-tracked baselines mismatch, including the pages that link zero
B5-moved CSS. This is a **missing-font-package regression in the image**, NOT a
post-capture container drift, and NOT a real code regression.

**Chromium is identical (build 1208) on both sides — it is not a Chromium-version drift.**

So the container render env at capture time == the container render env now. If the baselines
had been captured **in-container**, a compare run would be GREEN. It is RED → **the baselines
were captured host-side** (DejaVu render), while the merge-gate renders in-container
(WenQuanYi render). Host-side `-k visual` dev runs pass (host vs host); the in-container
merge-gate fails (container vs host-captured baseline). Classic host-vs-container mismatch,
now traced to a specific missing package.

### 5. Existing determinism work and why it did not catch this

`src/tests/e2e_ui/conftest.py` already pins hinting/LCD/DPI/color (`browser_type_launch_args`)
and the 1280×720 viewport (`browser_context_args`), and forces visual-first ordering
(cold-cache parity). Those neutralize *config-level* and *cache-level* AA nondeterminism
**within one font stack**. They do **not** pin the **font SET** or the **rasterizer version**
across environments — so a missing font package that flips the generic fallback slips right
through. Prior art: `src/rnd/v0.1.6/2026.04.10-visual-regression-cold-warm-drift.md` (same
symptom page-list; solved the cold/warm axis, not the host/container font-set axis).

### a90cc63e — tts_chrome `wait_for_selector` timeout: it was a STALE SELECTOR, not contention

**Cheech's contention hypothesis is REFUTED.** `test_multiplexer_phase6b_tts_chrome_visual`
captures the TTS chrome's **idle** state (no audio flowing). `renderTtsChrome` is
STATE-driven: `opts.state === "idle"` returns `renderTtsEmpty()`
(`templates/ttsChrome.ts:115` → `:86-92`), which emits `.tts-chrome-empty` +
`.tts-queue-empty-state` and **no `.tts-controls`**. `.tts-controls` is emitted ONLY by the
playing/paused branch (`ttsChrome.ts:135`). The pre-fix gate
`page.wait_for_selector('#tts-pane .tts-controls', timeout=2000)` therefore waited for an
element the idle state **can never render** → a guaranteed 2000ms timeout, contention or not.

Timeline proof: the wait line dates to v0.1.7 (`26898e1e`, 2026-04-22); the state-driven
idle-empty render (`renderTtsEmpty`, no controls) landed LATER in `f48b0bf0` ("Mux L2 AR +
PLY colored panels + empty-states"). The selector went stale when L2 removed controls from
the idle render; the sanity gate was never updated. The committed baseline
(`multiplexer_phase6b_tts_chrome.png`, **960×76**) already depicts the idle empty panel —
correct + current — so no rebaseline is needed.

**FIX** (render-preserving; no rebaseline): wait for the idle observability handle the
template emits for EVERY state — `#tts-pane [data-testid="multiplexer-tts-chrome"][data-state="idle"]`
(`ttsChrome.ts:89-90`, `:121-122`; contract locked by unit test
`templates_tts_chrome.test.ts:48` + `:223`) — at a 15000ms timeout matching the test-hook
wait above. This is `src/tests/e2e_ui/test_multiplexer_phase6b_visual.py`. The
`data-testid`/`data-state` element is the sole child of `#tts-pane`
(`TtsChromeRenderer.renderNow` → `root.replaceChildren(chrome)`), so the descendant selector
resolves. RED-first proof lives in the existing TS unit tests (idle omits `.tts-controls`,
carries `data-state=idle`).

### 660d02b4 — task_editing ±1px height: HEIGHT-TOLERANT COMPARATOR (no rebaseline)

The stock comparator (`pytest_playwright_visual_snapshot`) is zero-tolerance on BOTH
dimensions AND pixel count — it raises `ValueError` the instant two images differ in size
(plugin.py:331-335), and requires **zero** mismatched pixels (plugin.py:329). So a benign
±1px sub-pixel row-height rounding (baseline 960×169 via `--update`; compare renders 960×170)
fails with no reconcilable rebaseline. The height source is the Actions-column form controls
(11px `<select>`/`<input>`/`<button>`, `css/multiplexer/task-list.css:393-428`) whose
`normal` line-height / intrinsic control height is fractional and rounds inconsistently
between two renders in the SAME container. (Note: the stock `ignore_size_diff` ini does NOT
help — it converts the crash into a normal FAILURE, it does not make a ±1px pass.)

**FIX** (test-infra; no feature-CSS touch; no rebaseline for the benign case): a
height-tolerant comparison core — `src/tests/e2e_ui/visual_height_tolerance.py` — plus a
conftest fixture `assert_snapshot_height_tolerant` (`src/tests/e2e_ui/conftest.py`), wired
into `test_task_editing_controls_visual`. The core forgives ONLY a benign bottom-edge ±N px
(default 1): same width required, height delta ≤ budget, then BOTH images are top-anchored
cropped to the shorter height and the overlap is compared with the ordinary zero-mismatch
pixelmatch at the same 0.1 threshold. It **cannot false-green a real regression** — a width
change, a delta > budget, OR a content SHIFT (top band diverges) all still fail. Worst case a
non-bottom-anchored flap stays RED (then escalates); it never hides one.

RED-first: `src/tests/unit/test_visual_height_tolerance.py` — 8 pure synthetic-image tests
(identical / width-mismatch / delta-beyond-budget / +1px benign / −1px symmetric / +1px
shifted-content / same-size pixels-differ / custom budget), **100% line + branch** on the
core (`--cov-fail-under=100` verified on the :7999 no-server venue).

**:8000 caveat (pending, coordinate with Tiberius):** the tolerant fix greens the compare
IFF the observed ±1px is bottom-anchored (last-row growth). If the coordinated :8000 window
shows the delta is instead a MID-content vertical shift, the overlap diverges and the test
stays RED — the documented fallback is then a deterministic-render change (pin integer
line-heights on the task-list controls) + a one-time rebaseline of the single PNG. Either
way, no false-green ships.
