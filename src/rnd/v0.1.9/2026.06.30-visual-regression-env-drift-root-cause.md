## TL;DR

The `:8000` merge-gate visual regression suite is RED because **the container is missing
the `fonts-dejavu-core` package**. Lupin's CSS font stacks all terminate in the generic
`sans-serif`, and none of the named fonts before it (`-apple-system`, `Segoe UI`, `Roboto`,
`Helvetica Neue`) exist on Linux — so fontconfig falls through to the terminal generic.

- **Host** (where baselines were captured): `sans-serif` → **DejaVu Sans**
- **Container** (`lupin-rest-test`, where the merge-gate renders): `sans-serif` → **WenQuanYi Zen Hei** (a CJK font)

Every page with text renders in a **completely different typeface** between the two
environments → all git-tracked baselines mismatch, including the pages that link zero
B5-moved CSS. This is a **missing-font-package regression in the image**, NOT a
post-capture container drift, and NOT a real code regression.

**Chromium is identical (build 1208) on both sides — it is not a Chromium-version drift.**

## Evidence

### 1. Render-env fingerprint: host vs `lupin-rest-test` container

| Axis | Host | Container | Verdict |
|---|---|---|---|
| Chromium (Playwright) build | 1208 | 1208 | **identical** — not the cause |
| fontconfig | 2.13.1 | 2.13.1 | identical |
| libfreetype6 | 2.11.1+dfsg-1ubuntu0.**2** | 2.11.1+dfsg-1ubuntu0.**3** | patch delta (minor AA axis) |
| Installed font count | **446** | **50** | large — the cause |
| `fonts-dejavu-core` | **present** (2.37-2build1) | **ABSENT** | **the cause** |

### 2. Generic-family fallback resolution (`fc-match`)

```
                    HOST                          CONTAINER
sans-serif   -> DejaVu Sans "Book"          -> WenQuanYi Zen Hei "Regular"
serif        -> DejaVu Serif "Book"         -> WenQuanYi Zen Hei "Regular"
monospace    -> DejaVu Sans Mono "Book"     -> WenQuanYi Zen Hei Mono "Regular"
Helvetica Neue -> DejaVu Sans               -> WenQuanYi Zen Hei
Roboto       -> DejaVu Sans                 -> WenQuanYi Zen Hei
Segoe UI     -> DejaVu Sans                 -> WenQuanYi Zen Hei
Arial        -> Liberation Sans             -> Liberation Sans   (identical — named font exists on both)
```

Named Latin fonts that exist on both (e.g. `Arial → Liberation Sans`) resolve identically.
Only the **generic terminal fallback** diverges — and that is exactly what Lupin's stacks
rely on. Confirmed CSS stacks (`src/lupin_app/static`):

```
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif
font-family: -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif
font-family: "Helvetica Neue", Helvetica, Arial, sans-serif
```

### 3. The regression is in the Dockerfile (WG-1, 2026-04-28)

`docker/lupin/Dockerfile:155-158` hardcodes the Playwright font list:

```
libfontconfig1 libfreetype6 xvfb \
fonts-noto-color-emoji fonts-unifont xfonts-cyrillic xfonts-scalable \
fonts-liberation fonts-ipafont-gothic fonts-wqy-zenhei \
fonts-tlwg-loma-otf fonts-freefont-ttf
```

The in-file comment admits it: *"WG-1, 2026-04-28: the original 3950d0a hardcoded list
omitted the fonts that `--with-deps` previously installed."* **`fonts-dejavu-core` is one
of those omitted fonts.** With DejaVu gone and `fonts-wqy-zenhei` present, WenQuanYi Zen Hei
wins the generic `sans-serif` fallback in the container.

### 4. The bug's "container drifted AFTER capture" guess is refuted

- Container `lupin-rest-test`: **Created 2026-06-10**, image `lupin:1.1.0` built **2026-06-03**.
- Baselines committed **2026-06-23** (`96204674` "rebaseline: regenerate visual baselines").
- The container has **not been recreated after 2026-06-23** (a `docker restart` preserves
  `Created`; only `rm -f`/`--force-recreate` resets it — it did not).

So the container render env at capture time == the container render env now. If the baselines
had been captured **in-container**, a compare run would be GREEN. It is RED → **the baselines
were captured host-side** (DejaVu render), while the merge-gate renders in-container
(WenQuanYi render). Host-side `-k visual` dev runs pass (host vs host); the in-container
merge-gate fails (container vs host-captured baseline). Classic host-vs-container mismatch,
now traced to a specific missing package.

### 5. Existing determinism work and why it did not catch this

`src/tests/e2e_ui/conftest.py` already pins hinting/LCD/DPI/color (`browser_type_launch_args`)
and the 1280×720 viewport (`browser_context_args`), and forces visual-first ordering
(cold-cache parity). Those neutralize *config-level* and *cache-level* AA nondeterminism
**within one font stack**. They do **not** pin the **font SET** or the **rasterizer version**
across environments — so a missing font package that flips the generic fallback slips right
through. Prior art: `src/rnd/v0.1.6/2026.04.10-visual-regression-cold-warm-drift.md` (same
symptom page-list; solved the cold/warm axis, not the host/container font-set axis).

## Remediation plan (Phase 2 — needs greenlight)

### Recommended — Option B: fix at source, then rebaseline in the merge-gate env

1. **Dockerfile fix** (`docker/lupin/Dockerfile:157`): add `fonts-dejavu-core fonts-dejavu-extra`
   to the font list. Restores what `--with-deps` used to provide; makes the container's
   `sans-serif → DejaVu Sans`, matching the host and every existing baseline.
2. **Render-env fingerprint guard test** (new, in `src/tests/e2e_ui/`): assert
   `fc-match sans-serif` → `DejaVu Sans`, plus freetype major + Chromium build, and FAIL LOUD
   on divergence. Satisfies the mandate "any new deterministic-font config gets a test +
   reasoned coverage." This turns the next silent font-env drift into an explicit, named failure.
3. **Rebuild image + recreate `lupin-rest-test`** — ⚠️ **Rick's gate** (shared merge-gate
   container / image rebuild; beyond STANDING authority; the bug anticipated "likely Rick
   input on the :8000 container env").
4. **Compare-first proof**: run `:8000 -k visual` COMPARE (no `--update-snapshots`) against
   the EXISTING host-captured baselines. Expectation: the ~34 non-B5 baselines go **green
   without any rebaseline** (container now renders DejaVu, matching the host capture). If that
   holds, it is decisive independent confirmation of the root cause. Residual reds expected:
   the ~3 B5-affected mux snapshots + possibly a few freetype-`.2/.3` AA stragglers.
5. **Deliberate rebaseline of the residual only**: `:8000 -k visual --update-snapshots`
   limited to the ~3 mux snapshots that legitimately reflect the B5 corner-button-hide
   (`multiplexer_phase5_notifications_pane`, `phase6c_section_d_*`) plus any AA stragglers.
   Baselines write to `io/test-suite/visual-baselines/` which is bind-mounted
   (`./io:/var/lupin/io`), so they land on the host filesystem for commit.
6. **Green gate**: `:8000 -k visual` COMPARE → 37/37 green. Commit rebaselined PNGs +
   Dockerfile + guard test (held for review; **push is Rick's word**).

### NOT recommended — Option A: rebaseline in-container as-is (WenQuanYi)

Fast (no image rebuild), but bakes an ugly Latin-in-CJK render, and **inverts** the problem:
host-side `-k visual` dev runs would then fail (host DejaVu vs container-captured WenQuanYi).
It also leaves the suite fragile to any future image font reshuffle. Rejected.

### :8000 protocol

Monopolize-mode. `list-pending` FIRST; a verified-idle `:8000` is bounce-then-schedule
SELF-AUTHORIZED. Submit ONLY via `POST /api/test-suite/submit` (schedule-tests skill) — never
a side-door. Killing a live in-flight job needs Rick.
