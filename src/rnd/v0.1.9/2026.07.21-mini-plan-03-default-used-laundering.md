## 1. The defect (unchanged from the row — restated for the builder)

`src/lupin_mcp/cosa_voice_mcp.py:1653`

```python
if response.is_timeout:
    if default is not None:
        return { "answers": default }
    return { "error": "timeout - no response received", "timeout": True }
```

The response object carries **both** `default_used` **and** `is_timeout`. This path branches on
`is_timeout` and then **discards both**, returning a bare `{"answers": default}` — byte-identical to a
real selection. The docstring states it as intended: *"same shape as a successful response."*

**The correct pattern is in the same file.** `converse` at `:1174`:
```python
prefix = "[default used] " if response.default_used else ""
```
The information is available, the pattern is established, and one of two sibling verbs throws it away.

## 3. Scope

- **D1 — the one-line fix, Rio's, additive.**
  ```python
  if response.is_timeout:
      if default is not None:
          return { "answers": default, "default_used": True }
  ```
  Callers ignoring the key are unaffected; callers checking it stop guessing.
- **D2 — READ THE SIBLINGS. They are LEADS, not findings — Rio explicitly did not verify them.**
  `ask_yes_no` (`:1419` takes a `default`) and `ask_open_ended_batch`. **My live instance above is
  `ask_yes_no`, so that one is now a finding, not a lead** — its return carried no `default_used` either.
  Read every verb that accepts a `default` and fix the whole family in one pass. **Do not fix only the verb
  named in the row title.**
- **D3 — the sibling that already works stays the reference.** `converse:1174` is the pattern. Make the
  family consistent with it rather than inventing a third convention.
- **D4 — symmetry check**: a real user selection must be explicitly distinguishable, not merely lacking the
  key. Prefer `default_used: False` on the real-answer path over an absent key, so a caller reading
  `.get("default_used")` gets `False` rather than `None` and cannot confuse "answered" with "old server".

## 4. Acceptance criteria

1. A timed-out `ask_multiple_choice` **with** a default returns `default_used: True` alongside `answers`.
2. A real selection returns `default_used: False` — **an explicit False, not an absent key** (D4).
3. A timed-out call **without** a default keeps its present shape exactly: `{"error": …, "timeout": True}`.
   That path is the control that already fires correctly; do not disturb it.
4. `ask_yes_no` and `ask_open_ended_batch`: **read them first, report what you find, then apply the same
   contract wherever a `default` can be returned.** If a sibling turns out not to share the pattern, say so
   with the file:line that proves it — a negative finding stated with a receipt is a result.
5. `converse`'s existing `[default used]` prefix behavior is unchanged.
6. Every changed verb's docstring stops claiming the timeout return is "the same shape as a successful
   response," because it deliberately no longer is.
7. **The test asserts the two shapes are DISTINGUISHABLE**, not merely that each is well-formed. A test that
   checks `answers == default` on both paths would pass today, against the defect.
8. 100% lines + branches + functions on every function touched.

## 5. Risk

**Low, and lower than it looks.** The change is additive — a new key on a dict. The one real hazard is a
caller doing an exact-shape comparison (`response == {"answers": X}`), which the added key would break.
Grep for consumers before landing; the MCP surface is the boundary, and agents read keys rather than
compare whole dicts.
