# Spatial AA-Comparator Feasibility Verdict — task_editing_controls_visual (bug 660d02b4 P3)

**Author**: Sam 🎙️ (session 2c323432) · **Manager**: Tiberius 👑 · **Task**: d90dcfc2 · **Date**: 2026-07-01

## TL;DR

A spatially-aware anti-aliasing comparator (connected-component area + morphological
erosion) was **built and proven** (28 tests, 100% line+branch, RED-first), but the
empirical measurement shows it **cannot safely restore exact-pixel coverage on
`test_task_editing_controls_visual`**. The card's real, matched-code, cross-process
glyph-AA jitter is **not** spatially-isolated single-pixel scatter — it forms
**2px-tall solid horizontal bars up to 145px** (four 145px, four 94px, five 74px
clusters; 98 clusters ≥10px; 41 px survive 3×3 erosion). Those benign clusters are
**geometrically indistinguishable** from plausible small real regressions (a thin
recolored row-border of the same 73×2 shape; a 12×12=144px recolored pill sits at
area 144 ≤ the benign max 145). **No floor/erosion operating point holds the
never-false-green line. Resolution D stands.** The stronger-lever + rebaseline path
(Oracle + Rick) remains the only route to pixel coverage here.

**Bonus finding (independent, actionable):** the committed baseline is **STALE** — it
predates the committed Detail-column move — and the pixel-blind gate silently shipped
that layout change with no rebaseline (see §4).

## 1. What was built (Phase 1 — DONE, proven)

`src/tests/e2e_ui/visual_height_tolerance.py` → `compare_pngs_aa_scatter_tolerant()`
(+ `AaScatterResult`). Width-strict, height-tolerant (reuses Krishna's crop
mechanism), then on the pixel-identical overlap:

- builds a content-independent diff mask via `pixelmatch(..., diff_mask=True)` (alpha>0);
- **connected-component labeling** (8-conn) → largest cluster area (primary contiguity signal);
- **3×3 morphological erosion** → survivors (independent solid-block tripwire);
- optional generous total-scatter ceiling (defense-in-depth; only ever stricter).

FAILs the instant `largest_cluster > floor` OR `erosion_survivors > 0` OR
`total > ceiling`. numpy/scipy are lazy-imported inside the function so the module
stays dependency-light for the other 36 visual tests.

### Proof (RED-first, :7999 no-server)

`src/tests/unit/test_visual_aa_scatter_tolerant.py` — 28 tests, **100% line + branch**
on the module. Mandatory matrix all green: (a) 20×20=400px contiguous block → FAIL;
(b) width/height change → FAIL; (c) content shift → FAIL; (d) pure isolated scatter → PASS.

**Never-false-green demonstration:** a naive count-budget = 600 (the budget needed to
pass a benign 500px isolated-scatter field) **FALSE-GREENS** a 400px contiguous block;
the spatial comparator passes the 500px scatter and correctly FAILS the 400px block.
The central test `test_scatter_passes_while_smaller_block_fails` encodes exactly this
(500px scatter PASS vs 400px block FAIL — opposite verdicts at inverted pixel counts).

## 3. Why it cannot be made safe (never-false-green analysis)

- **Area signal:** benign max cluster = 145px. A 12×12 = **144px** recolored pill is
  ≤145 → would false-green if the floor is raised to 145. No gap.
- **Erosion signal:** benign jitter leaves **41 survivors**; raising the survivor
  threshold above 41 lets a ~7×7 solid regression (survivors ~25) slip under.
- **Shape collision (decisive):** the benign clusters are 73×2 solid bars. A **real**
  regression of identical shape — a wrong-colored 2px row divider / row-background
  tint — is byte-for-byte the same geometry (area, thinness, 0 erosion survivors).
  **No area/erosion/shape feature separates them.**

At safe floors (2/4/8) the comparator correctly **FAILS** this benign jitter — i.e. to
"restore coverage" one would have to loosen it into the unsafe zone. The spatial
comparator is a genuine improvement over a raw count budget (§1), but this card's
benign jitter is genuinely **contiguous**, so the spatial premise ("isolated single-px
scatter") does not hold here. **Verdict: stay at resolution D.**
