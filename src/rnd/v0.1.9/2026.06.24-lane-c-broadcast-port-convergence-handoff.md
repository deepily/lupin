## Self-audit (Krishna, post-merge — for Rachel's adversarial review)

Edge cases traced through the code (receipts: file:line + the covering test).

| Case | Behavior | Where | Test |
|---|---|---|---|
| **Empty recipients** | `hydrate` → `[]` (missing/non-array `sessions`, or fetch failure clears cache + re-raises) → `renderChips` "list" with 0 → "no active sessions" pill → `updateSendButton` disables Send | `BroadcastStore.hydrate`, `renderChips`, `updateSendButton` | "empty active-session list…", "send button stays disabled with body but no recipients" |
| **0-session send** | Double-guarded: Send is `disabled` when 0 recipients (the `!sendBtn.disabled` click gate), AND `showConfirmModal` early-returns on `recipients.length === 0`. Server also returns `status:"no-active-sessions"`, `recipients:0` if somehow reached | `attachDelegation` send branch, `showConfirmModal` | "clicking a disabled send button does NOT open the modal" |
| **@Persona parse** | **Client does NOT parse @mentions** — chips inject the literal `@<name> ` / `@all ` token at the caret; the raw textarea body is POSTed; the SERVER (`broadcast_handler._parse_body`) does the `@Persona:` scope parse (legacy parity — legacy `injectMentionAtCursor` is also literal-insert-only). Nothing client-side to audit | `injectMentionAtCursor`, `buildChip`/`buildAtAllChip` | "clicking a recipient chip injects @persona…", "clicking @all injects @all" |
| **STT cancel (ESC)** | ⚠️ **Shared limitation, NOT a Lane-C regression.** `AudioRecorder.cancel()` → `_onStop` sees `cancelling=true` → returns WITHOUT firing `onComplete`/`onError`, so the renderer's `recording` flag + mic `.recording` class stay set until the next interaction. **This is identical to the existing `SenderCardRecorderRenderer`** (same `recordingManager` cancel-without-callback contract). A proper fix needs an `onCancel` hook on `recordingManager` — cross-cutting, touches the shared recorder + SenderCardRecorder, **out of Lane-C scope**. Flagged as a shared follow-on. | `AudioRecorder.cancel`/`_onStop:186`, `handleMicClick` | n/a (shared contract) |
| **Double-open modal** | HARDENED this pass: `showConfirmModal` calls `removeModal()` first so a second open can't orphan the first overlay in `document.body` (the full-screen overlay normally intercepts clicks, but defended anyway) | `showConfirmModal` | "opening the confirm modal twice leaves only one overlay (no leak)" |
| **XSS** | No `innerHTML` anywhere in the renderer — confirm-modal preview, chips, and status all use `textContent`; the template uses the auto-escaping `html` helper | `showConfirmModal` previewDiv, `chipButton`, `setStatus` | covered by render assertions |
