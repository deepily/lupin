## TL;DR

The arbiter's MANAGER-AWAITING-RICK advisory (case 16, "defended quiescence, not a stall — one-time notice, no poke") **re-fires every poll tick (~60s)** at each watching manager, on a fresh thread each time, for as long as the subject manager stays parked-awaiting-Rick. Mr. Radio ate 3 identical copies in 3 minutes (20:06:25 / 20:07:26 / 20:08:26, climbing minute count). A "no-poke" advisory that wakes every watcher every 60s is functionally a poke storm; severity-in-effect P2 while any manager parks >45m.

**Root cause — a cross-detector shared-flag ping-pong (not a thread-id dedup key).**

## Root cause (verified against the code)

`_poll_once` runs, in order, every tick:
1. `_check_manager_acks` (#9, `arbiter_job.py:1277`) — the tap-ACK / MANAGER-DOWN detector.
2. `_check_manager_staleness` (#F2, `:1284`) — the staleness / case-14 detector, which also emits the case-16/17 **advisories**.

Both share the persona-keyed one-shot flag `self._manager_blocked_advised` (and `_manager_done_advised`) — deliberately, for cross-detector de-dupe so Rick isn't double-paged.

The ping-pong:
- **`_check_manager_acks` re-arms (discards) the shared case-16/17 flag on ANY liveness activity** (`:3083-3086`): `if last_activity >= tapped_at: self._manager_blocked_advised.discard(manager)`. Its intent is to re-arm the MANAGER-DOWN escalation when a tapped manager shows it's alive — but it ALSO clears the BLOCKED/DONE *advisory* flags.
- **`_check_manager_staleness` re-fires case-16** whenever the union `freshest_age_s` reads stale and the persona is not in the advised set (`:4082-4093`).
- A manager **parked-awaiting-Rick is ALIVE** (its Stop-hook heartbeat self-pokes; it may post DMs) yet its **union `freshest_age_s` can read stale** — the documented **26dd3afb** bridge-vs-union divergence (the bridge/DM signal doesn't always reach the union). So each poll: acks sees "alive" → **discards** the advisory flag; staleness sees "union stale" → **re-fires** the advisory. Net: one case-16 per tick, climbing minute count. Exactly the forensic.

The existing `test_blocked_advisory_fires_once_then_silent` passes only because it re-polls a FIXED stale snapshot with **no acks-path activity** — it never models the acks-discard, so it never reproduces the ping-pong. That coverage blind-spot is fixed here too.

## Fix — a per-persona advisory cooldown (Tiberius ruling: option B)

Cap the case-16/17 advisory fire-rate with a **cooldown keyed on (detector-family, subject persona)**, independent of the flappy shared flag:

- New in-memory state `self._advisory_cooldown_until: dict[(family, persona), datetime]` (family ∈ {`blocked`, `done`}). **In-memory only — NO persistence** (Tiberius rider 1: a single extra advisory after an `:8001` restart is acceptable; do not build a durable store for it).
- New ctor kwarg + INI-promotable tunable `manager_advisory_cooldown_seconds` (default = `manager_stale_poke_threshold_seconds`, ~45m → at most one advisory per blocked-episode-window).
- At EACH case-16/17 emit site (the three: acks `:3092`, staleness owed-class `:4032`, staleness hold-gate `:4082`): before firing, additionally require the `(family, persona)` cooldown has expired. On fire, stamp `now + cooldown`.
- **Observability (Tiberius rider 2):** when the cooldown SUPPRESSES a would-be re-fire, emit a journal event `arbiter_advisory_suppressed_cooldown` carrying `persona`, `family`, and a running `suppressed_count` — same log pattern as the `742fe8dc` levers so soak-watches + the `285c0343` greps can see it working.
- Re-arm: the cooldown expires naturally; the existing freshen re-arm (`:4015`) + owed-class transitions still clear the shared flag for a genuine new episode, but the cooldown is the hard ceiling the ping-pong cannot bypass.

**Why cooldown over a surgical re-arm-split** (stop discarding blocked/done flags in `_check_manager_acks:3085`): the cooldown is the simplest reversible mechanism, robust against ALL liveness-divergence paths (bridge, DM, commons, event) without re-reasoning the delicate cross-detector re-arm that **MANAGER-DOWN depends on** — and tonight the arbiter just restarted with `285c0343` soaking on it, so we do not churn that path. It is additive (a tunable) and the MANAGER-DOWN re-arm flag is untouched. If the union-divergence family (26dd3afb) is ever properly fixed, the cooldown stays as belt-and-suspenders (Tiberius rider 3).

- **Cooldown expiry**: after the cooldown window elapses on a still-parked manager, exactly one MORE advisory is allowed (bounded re-notify, not silence-forever).
- **Legitimate first notice preserved**: the single first advisory still fires (`test_blocked_on_user_manager_suppressed_to_case16` stays green).
- **Genuine episode re-arm still works**: `test_blocked_then_freshens_rearms_case16` — a real freshen→re-block still re-advises once (verify cooldown does not block a genuine new episode beyond the window; may need the freshen re-arm to also clear the cooldown).
- **DONE twin**: same cooldown covers case-17 (`test_done_advisory_*`).
- **Regression**: `_check_manager_acks` MANAGER-DOWN re-arm on activity is UNCHANGED (the down flag is not cooldown-gated).
