## 🔴 FINDING — `verify-running-code.sh`: exit 0 claims more than the clock can prove

### The contract vs the predicate

The header states the exit contract:

```
#   0  the running process HAS the commit
#   1  the running process does NOT have it  (recreate required)
#   2  cannot determine
```

The predicate is a comparison of two clocks — host `git` commit time vs container
`.State.StartedAt` (plus `.State.Running`, which Rio correctly added after catching his
own first cut):

```python
print( 'HAS' if commit <= started else 'MISSING' )
```

**The two directions are not symmetric:**

| Direction | Claim | Sound? |
|---|---|---|
| commit **newer** than start → `MISSING` | the process cannot have code authored after it started | ✅ **unconditionally sound** |
| commit **older** than start → `HAS` | the process has this commit | ⚠️ **conditional on an unchecked precondition** |

`HAS` is sound only if **the container's code came from this repo tree**. The script
never verifies that. Its own on-screen text is honest — it prints *"the running process
started after this commit"* — but the documented exit-0 contract says *"HAS the commit"*,
and exit codes are what callers branch on.

### Why this is live, not theoretical — the VENUE half

Measured across the compose files:

| Venue | code source | clock verdict |
|---|---|---|
| `docker-compose.yml` (dev :7999, test :8000) | `./src:/var/lupin/src` (line 139, 273) | sound |
| `docker-compose.cloud-gpu.yml` | `./src:/var/lupin/src` (line 100) | sound |
| **`docker-compose.cloud-test.yml`** | **`image: ${LUPIN_IMAGE:-lupin:1.1.0}` — NO `./src` mount** | 🔴 **unsound** |

Verified: `grep -nE '\./src:/var/lupin/src' docker-compose.cloud-test.yml` returns **only
a comment** — line 127, *"if this service ever gains a `./src:/var/lupin/src` mount…"* —
confirming it does not have one. Code is **baked into the image**.

⇒ On `cloud-test`, a container started at time *T* reports **HAS** for every commit
authored before *T*, **regardless of which commit the image was built from**. The image
can be arbitrarily old. The verdict is a statement about *when the container started*,
not about *what code it contains*.

**And the container name is a free argument** (`verify-running-code.sh <container>`), so
nothing stops it being aimed at exactly the venue where it is unsound — which is the
deploy venue.

### Why this is the row's own thesis, one level up

The header already names this exact shape at lines 47–49:

> *"A start-clock alone answers 'did a process ever start after this commit' — a
> different question with the same shape, which is this row's entire thesis wearing the
> fix's clothes."*

Rio applied that reasoning to the `Running`/`StartedAt` gap and closed it. The same
sentence applies one level up, to the `HAS` verdict itself: **for a baked image, the
start-clock answers "did a process start after this commit" and the contract reads it as
"the process has this commit."**

Reinforced by two of today's sibling rows, which establish the precondition is violable
in this repo *right now*: `5f421be0` — *"a mount can be healthy in `docker inspect` and
serving June's bytes"* — and `28f125b1` — *"39 file binds, two failure modes, and dev has
been blind."*

### Suggested remedy (not applied — Rio's file, and the fix is a design call)

Either **narrow the name/contract** — exit 0 means *"no commit newer than the process
start"*, which is what it proves — or **add the missing precondition**: assert the
container's code path is bind-mounted from this tree, and return **exit 2
(CANNOT_DETERMINE)** where it is not. Exit 2 already exists and already carries "cannot
answer", which is the correct verdict class for a baked image; the third exit code Rio
built is exactly the right home for this, and using it costs no new vocabulary.

## ✅ CLEAR — the other three, with what I checked

### `test_timeout_marker_is_armed.py`

Name claims the marker is **armed**. The predicate proves it, in the strong direction:
plugin importable, **a cap actually kills an over-running test** (a 5s sleep under a 1s
cap must fail, and fail *with* `Timeout` in the output), and no global `--timeout` in
`addopts` so the blast radius stays the 18 opted-in tests.

**It carries the positive-control arm** row `ed4df64a` asks of every gate —
`test_the_probe_harness_can_also_report_a_PASS` exists precisely because `rc != 0` would
be satisfied by a harness that always fails. That is the arm most of today's gates lack,
present here before I asked for it.

Venue checked, hypothesis **rejected**: I suspected the caps might live in the
un-runnered `src/cosa/tests/**`. Measured — all 7 cap-bearing files are under
`src/tests/`, **zero** in `src/cosa/tests/`. No venue gap. Recorded because the
hypothesis was reasonable and the measurement killed it.

Confirms my own earlier finding is now **resolved**: I measured `pytest-timeout` MISSING
at ~14:00 and flagged the marker as registered-but-inert. It is now **installed (2.4.0)**
and pinned; this guard is what keeps it that way. My review's note on that point is stale
and superseded.

### `check_schema_at_head.py`

Name claims it checks the schema is at head. Predicate: reads the tree's head revision
and the DB's current revision and classifies. Name matches. It carries a genuine
**third exit code** (`CANNOT_DETERMINE`) rather than collapsing "no" into "cannot tell" —
the same discipline whose *absence* is the finding above, applied correctly here. The
docstring's `Ensures:` block explicitly enumerates the `( None, None, reason )` failure
path per source.

### `src/tests/conftest.py` guard

Two mechanisms, both scoped to what they claim. The config floor uses `setdefault`, not a
hard set, and the comment states why — an explicit export from CI, the container, or the
integration conftests still wins; it is a **floor**, and the name says floor. The venue
router delegates its logic to `tests/venue_routing.py` so it is unit-testable **in both
directions** without a container, and names deselected node-ids rather than counting them
— which I independently verified earlier in the day (`21745/21752 collected, 7 deselected,
zero errors`).
