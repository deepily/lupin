**Author**: Clayton 😎 (Implementer, María's crew) · **Date**: 2026-08-01
**Guards for**: §4.5 of `2026.08.01-late-answer-handback.md` (store row `7bb0a7df`)
**Why this doc exists**: María's instruction — design E's guards before E's code, so
each test is written against the contract the **server actually serves**, not one the
client half imagined. E is the section where a bad guard is easiest to write: the
client can pass against a fabricated contract. Every guard below names its **falsifier**
(what to delete/revert to make it go red) — an assertion nobody has watched fail is not
a guard.

## Contract under test (§4.5, verbatim intent)

| # | Surface | File (planned) | Contract |
|---|---|---|---|
| E-a | SSE **ack frame** | `notifications.py` ~`:1122`, before `await asyncio.wait_for` | yields `{"status":"ack","notification_id":<id>}` right after the WS push. Purely additive — `consume_sse_stream` already `continue`s on unrecognized status (`notify_user_sync.py:130/142/148`). |
| E-b | **GET** `/api/notifications/response/{notification_id}` | `notifications.py`, registered BEFORE `/{user_id}` | returns `{state, response_value, responded_at}`. **Pure read — no ack**, never sets `answer_delivered_at`. |

## The invariant E must not break

`responded_at IS NOT NULL` is the SOLE discriminator between "a human answered" and "a
default was manufactured." A row with a `response_value` but `responded_at` NULL is a
machine default — it maps to `ExpiredEvent(default_used=True)`, **never** `RespondedEvent`.
Deciding landed-ness on `state` moving or `response_value` being non-null is wrong by
construction.

## Guards — each with its falsifier

### E-a · the ack frame is additive and its id is captured
- **Test (unit, notify_user_sync)**: feed `consume_sse_stream` a stream whose first frame
  is `{"status":"ack","notification_id":"N"}` then a normal RespondedEvent → assert the
  returned event is unchanged AND the captured id == "N".
- **Test (unit, back-compat)**: feed a stream with the ack frame to the CURRENT (pre-E)
  parse path → assert it still `continue`s and yields the terminal event (no crash, no
  behavior change for a client that ignores the id).
- **Falsifier**: remove the `notification_id` capture in `consume_sse_stream` → the id is
  `None` → E-c's arming test (below) can only reach `reattach_unavailable`, never
  `reattach_armed` → E-b/E-c tests that need the id go red.
- **⚠️ imagined-contract risk**: the unit test *feeds* the ack frame — it does not prove the
  **server emits** it. The truth-proof is the **:8000 integration test (Rachel's tier)**:
  drive a real ask, assert the real SSE stream's first frame carries the id. A green unit
  E-a is NOT "the server acks."

### E-b · the response-by-id route is a pure read (never acks on serve)
- **Test (unit, router)**: GET `/response/{id}` returns `{state, response_value,
  responded_at}` for a mocked repo row; assert `repo.mark_answer_delivered` is **not**
  called (serving is not a receipt — same gate as D-V2).
- **Test (route order)**: assert `/response/{id}` is registered BEFORE `/{user_id}` (the
  static-shadow hazard, same as answers-owed).
- **Falsifier**: move a `mark_answer_delivered` call into the GET handler → the
  "serve-does-not-ack" assert goes red (a served-then-crashed poll would silently eat the
  answer).

### E-c · the client re-attach poll — landed predicate (E-V1)
- **Test (unit, notify_user_sync)**: on stream death, patch the poll to return
  `{response_value:{...}, responded_at:None}` → assert the result is
  `ExpiredEvent`-shaped (`status="expired"`, `default_used=True`, `is_timeout=True`) and
  **no** POST to `/answers-owed/ack` fired. Then patch the poll to return
  `{responded_at:"<ts>", response_value:{...}}` → assert `RespondedEvent`-shaped
  (`status="responded"`, `default_used=False`) AND an ack POST fired.
- **Falsifier**: change the landed test from `responded_at is not None` to
  `response_value is not None` (or `state != "delivered"`) → the NULL-responded default row
  now maps to `responded` → red. *This is the guard that protects the whole feature's
  reason for existing.*

### E-c · arming signal (E-V2)
- **Test (unit)**: on stream death **with** a captured id → assert a poll actually fires
  and the state signal reaches `reattach_armed` (assert the WIRING, not just that the id
  was parsed). On stream death with **no** captured id → assert `reattach_unavailable` is
  surfaced **loud** (a queryable/assertable field, not a bare log line).
- **Falsifier**: disconnect the poll-loop trigger from the `if not event:` branch → a poll
  never fires → `reattach_armed` is never reached → red.

### E-c · budget≤0 edge (E-V3)
- **Test (unit)**: stream dies exactly at budget exhaustion → assert **at least one**
  terminal poll still fires before returning, and the outcome is a terminal
  `ExpiredEvent(is_timeout=True)`, **not** the bare `status="stream_error"` that
  `:259` returns today.
- **Falsifier**: guard the final poll behind `budget > 0` (skip it at 0) → the dying
  stream returns bare `stream_error` → the "≥1 poll fired / not stream_error" assert red.

### E-c · ack ORDERING — the receipt must not precede the hand-off (E-V5, María 2026-08-01)

**The gap**: the poll RECEIVING the answer is not the caller USING it. If E acks on
poll-land and the process dies before the RespondedEvent reaches the model, the row is
marked delivered and the answer is gone — "ack on consume, never on serve" rebuilt one
level in, at smaller scale.

**Rule (fails toward re-delivery, never silence)**: E does **NOT** ack on poll-land. The
landed value is returned to the caller as the `RespondedEvent` — that return IS the
delivery. The row is left **OWED** (`answer_delivered_at` NULL). The genuine receipt (the
ack, setter (c)) is deferred to the next-turn catch-up surface, where the answer is
actually consumed as `additionalContext`. This makes the plan's already-declared-acceptable
double the steady state (bounded: a tool-return + one catch-up context line, never a
re-ask), and it forbids the one direction the whole feature exists to kill — silence.

*Adjustment to the plan-of-record*: §4.5 said "E acks immediately on land (setter c)."
This ordering analysis shows an eager ack risks silence, so setter (c) moves to the
catch-up consume point. The 3-setter contract stands (a=live SSE waiter, b/c=ack-on-consume
via `/answers-owed/ack`); only WHO fires (c) changes — catch-up, not the re-attach poll.
**Confirmed with María before baking in** (it touches the ratified contract).

- **Test (unit)**: on poll-land (responded_at NOT NULL), assert the RespondedEvent is
  returned AND **no** ack POST fired from `_send_sync_notification` (the row stays owed).
  Then assert a subsequent catch-up over that persona re-surfaces it (owed) and acks there.
- **Falsifier**: make `_send_sync_notification` ack on poll-land → simulate a death between
  ack and return → the answer is marked delivered but never surfaced → the "stays owed
  after land" assert goes red.

### E-c · ack-race steady state (E-V4)
- **Test (unit + repo)**: E lands and acks → a subsequent owed query for that persona
  **excludes** the row (dedupe-by-ack holds once the ack commits). This asserts the
  **post-ack** steady state is single; the doc DECLARES the pre-ack-commit context+tool
  double acceptable (bounded to the ack round-trip, never a re-ask) — it is not asserted
  away.
- **Falsifier**: skip E's ack-on-land → the owed query re-surfaces the row → red.

## A carry-over guard that must NOT stay trivially green (María/Rio, 2026-08-01)

`test_setter_a_not_marked_without_sse_waiter` (now in the committed router suite) passes
**trivially** while the setter-(a) call is unwired — "not marked" holds for free because
nothing marks. When the setter-(a) wiring lands, this test must be **re-checked as a real
negative**: revert-to-verify by making the mark fire unconditionally and confirming it
flips to RED. A green that never changed colour proves nothing. (Already red-proofed once
in the implementer session; re-run it at the wiring commit, not just at authoring time.)
