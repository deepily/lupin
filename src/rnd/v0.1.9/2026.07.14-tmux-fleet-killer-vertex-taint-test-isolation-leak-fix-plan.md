## 1. TL;DR

A single shared user-level tmux server (socket `default`, `/tmp/tmux-1001/default`, uid 1001) has died repeatedly over two days — today: 14:12, 14:55, 19:21, 20:04, 21:13 EDT — each death atomically destroying every session across three project trees.

**Per-death attribution (Stage-2 transcript forensics, §2.7):**
- **14:55, 20:04, 21:13 — positively attributed to this test** (a pytest invocation of it sits in a session transcript seconds before each death).
- **19:21 — deliberate acceptance kill** during the supervise-stack install (session 66f8b92c), not a bug event.
- **14:12 — unattributed, and provably NOT this file**: it predates the file's creation (14:55:04). Carved out to Open sub-question 6.

The root cause below claims the **three attributed deaths** — a stronger claim than the original blanket "5×", because it is positively receipted rather than inferred.

**Root cause — mechanism proven; instance positively attributed for 3 of 5 deaths (§2.7; pre-file residual carved to Open sub-question 6):** the smoke test `src/tests/smoke/test_vertex_launcher_server_taint.py` calls `tmux kill-server` in its fixture teardown (line 108). It *believes* it is isolated to a private `TMUX_TMPDIR` socket, but its helpers `_tmux()` and `_launch()` **inherit `$TMUX`** from the surrounding Claude pane (they strip only the vertex `TAINT` vars). On tmux 3.2a, **`$TMUX` takes precedence over `TMUX_TMPDIR`** for socket selection when no explicit `-L`/`-S` is given — so a bare `tmux` from inside a pane targets the **default** socket, not the private one. Every time this test ran from inside a Claude pane (i.e. every agent-driven dev run), its teardown `kill-server` nuked the shared fleet server.

**The claimed isolation was a false-green:** the file-history note "TMUX_TMPDIR beats $TMUX on 3.2a, isolated" was verified from a *non-tmux* shell (`$TMUX` empty), which never exercises the case the fleet actually runs in. The test's own docstring (lines 10–16) even warns about exactly this class of false-green — the guard-verifier fell into the guard's trap.

**Fix (proposed, for review):** strip `$TMUX`/`$TMUX_PANE` before any bare `tmux` invocation in smoke tests — primarily via a **suite-wide `conftest.py` guard** (fixes the whole class), secondarily via explicit per-helper stripping + an explicit private socket in the vertex test itself. Plus a small **instrumentation upgrade** so the next such death names its caller directly instead of by elimination.

## 2. Evidence (how we know)

> **Instrument of record:** the killtrace readings below come from the root bpftrace tracer specified in the tmux-supervise runbook §10 (`src/rnd/v0.1.9/2026.07.14-tmux-supervise-runbook.md`, ~L533–536).
> **Named contradiction — runbook rule overturned by this receipt:** runbook §10 asserts that `tmux kill-server` sends **no signal** and therefore "does NOT appear" in the killtrace. The 21:13 receipt (§2.1) refutes that: `kill-server` DOES generate a self-directed SIGTERM (sender pid == target pid == server pid), which is precisely how it was caught. This plan treats the §2.1 receipt as authoritative. The runbook amendment itself does **not** ride this plan — it is tracked separately as store task `e1ba0239` (post-cascade).

### 2.1 The killtrace (root bpftrace tracer, `/var/log/tmux-killtrace.log`)
At the 21:13 death:
```
21:13:28 sig=15 target=349437 from=tmux: server pid=349437 uid=1001
```
SIGTERM (15), and the **sender is the tmux server itself** (sender pid 349437 == target pid 349437). A self-directed SIGTERM where sender==target is the signature of `tmux kill-server` — tmux executes kill-server *inside* the server process, raising SIGTERM on its own pid. An external `pkill`/`killall`/`kill <pid>` would show `from=<that comm>`, so those are **ruled out** by this line.

### 2.2 Journal ordering (`journalctl --user -u tmux-server.service`)
The self-SIGTERM killed the daemon (pid 349437) **first**; only afterward did systemd's own `ExecStop` (`-tmux -L default kill-server`) run as a **new** pid 387424 and log `no server running on /tmp/tmux-1001/default`. So systemd's ExecStop did **not** cause the death — an **external-to-systemd** `kill-server` did, and systemd merely reacted (restart counter → 1, RestartSec=2).

### 2.3 Crash-vs-clean discriminator
- Clean stop (the 20:35 event) shows `Stopping/Stopped/Starting` — that is what `systemctl --user restart|stop tmux-server` produces.
- Crash pattern (20:04, 21:13) shows the daemon's MainPID vanish, then ExecStop finds "no server running", then restart. That is what a **direct `tmux -L default kill-server`** (bypassing systemctl) produces.
- **19:21 is dropped from the bug crash-pattern**: it shows the identical signature but was a **deliberate acceptance kill** during the supervise-stack install (session 66f8b92c, §2.7). Its signature-identity is itself informative — the discriminator distinguishes crash-vs-clean, **not intent**.
=> The 21:13 caller ran `tmux kill-server` **directly on the default socket, not via systemctl, unattended** (Rick was away).

### 2.4 Ruled out
- **NOT OOM:** 184 GB free of 251 GB, `/proc/pressure/memory` all zeros, server RSS flat at ~5 MB (no leak), zero kernel OOM/kill events.
- **NOT logind reaping:** `loginctl Linger=yes`.
- **NOT an external pkill/killall/kill:** killtrace names the server as self-sender (§2.1).
- **Signature limits (Stage 2):** systemd's own `ExecStop` (`tmux -L default kill-server`) produces the SAME self-SIGTERM signature when it fires — it is §2.2's journal *ordering* that rules it out here, not the signature itself. The killtrace signature answers WHAT (a kill-server ran) but not WHO issued it; naming the caller requires a second discriminator — §5.3 provides one.
- **NOT a tmux config self-exit:** the Workflow's tmux-internals lens confirmed no `exit-empty`/`destroy-unattached` config culprit, and `_keepalive` always holds ≥1 session (server never sees an empty state) and an empty-server exit emits no signal anyway.


## 3. Root cause (precise)

`src/tests/smoke/test_vertex_launcher_server_taint.py` (as it existed before quarantine):

- `_tmux()` (≈L58–62):
  ```python
  env = { key: value for key, value in os.environ.items() if key not in TAINT }   # inherits $TMUX
  env[ "TMUX_TMPDIR" ] = str( socket_dir )
  return subprocess.run( [ "tmux", *args ], ... env=env, ... )                     # bare tmux, no -L
  ```
- `_launch()` (≈L65–82):
  ```python
  env = dict( os.environ )              # inherits $TMUX wholesale
  env[ "TMUX_TMPDIR" ] = str( socket_dir )
  ...                                   # runs the real launcher, whose `tmux new-session` is bare (no -L)
  ```
- Fixture teardown `rig` (L108): `_tmux( socket_dir, "kill-server" )`.

Because `$TMUX` is inherited and wins over `TMUX_TMPDIR` (§2.5), both the launcher's `new-session` and the teardown's `kill-server` operate on `/tmp/tmux-1001/default`. The teardown therefore kills the shared server.

**Contributing latent hazard (class-level):** `pytest.ini` sets `python_files = test_*.py` but has **no `testpaths` and no `norecursedirs`**, and there is **no suite-wide guard** stripping `$TMUX`. Any smoke test that runs a bare `tmux <verb>` from inside a pane is a latent fleet-hazard. This test is the instance; the missing guard is the class.

## 5. Proposed changes (FOR REVIEW — not yet applied)

### 5.1 Fix the vertex-taint test (instance)
In `_tmux()` and `_launch()`, before setting `TMUX_TMPDIR`, drop the inherited pane context:
```python
env.pop( "TMUX", None )        # do NOT inherit the pane's server socket — else it wins over TMUX_TMPDIR
env.pop( "TMUX_PANE", None )
```
Rationale + proof: §2.5. With `$TMUX` absent, `TMUX_TMPDIR` wins (proven), so both the launcher and `_tmux` land on the private socket. This is the **minimal** fix and is sufficient on its own.

**Single-source rule:** the two strip keys are NOT restated in the test file — `_tmux()`/`_launch()` import `TMUX_ISOLATION_STRIP_KEYS` from the new helper module `src/tests/smoke/tmux_isolation.py` (§5.2), which defines it exactly once. See the anti-reuse warning in §5.2: this constant must never be folded into `MAX_PANE_UNSET_KEYS`.

**Defense-in-depth `-S`/`-L` — NOT ADOPTED (Open sub-question 4 CLOSED, Stage 2):** pinning an explicit private socket via `-S <tmp_path>/sock` (or `-L <unique>`) was considered and **declined by concurrence** — it requires the launcher to accept a socket override (invasive; §4 scope stays unamended), and the env-strip is sufficient on the proven precedence (§2.5). AC5's precedence unit test is the standing **canary**: if tmux socket-selection precedence ever changes, AC5 reddens first and reopens the question (recorded in OSQ-4's close).

### 5.2 Suite-wide guard (class fix) — **extend the existing** `src/tests/smoke/conftest.py`
`src/tests/smoke/conftest.py` **already exists** (it carries `pytest_addoption` for the scheduler flags plus the module-scoped autouse `_auto_proxy_for_module` fixture from the May-5 503-cascade design) — this change **extends** that file; it does not create a new one. The existing autouse-fixture precedent there part-answers Open sub-question 3's convention question. At smoke-suite session start, strip the ambient tmux context and pin a per-session private `TMUX_TMPDIR` so *any* bare `tmux` from *any* smoke test auto-isolates:
```python
# ADOPTED FORM (Open sub-question 3 CLOSED, Stage-2 ratified): pure logic in a NEW
# helper module + a THIN session-scoped autouse wrapper fixture in the EXISTING smoke
# conftest, borrowing the snapshot/pop/restore shape of the root conftest's
# `hermetic_config_module_boundary` ( src/tests/conftest.py:46-89 ).

# --- src/tests/smoke/tmux_isolation.py (NEW — pure, unit-testable; on AC3's coverage list) ---
TMUX_ISOLATION_STRIP_KEYS = ( "TMUX", "TMUX_PANE" )   # SINGLE SOURCE — §5.1 helpers import THIS

def strip_tmux_context( environ ):
    """Snapshot ( strip keys + TMUX_TMPDIR ), pop the strip keys; return the snapshot."""

def restore_tmux_context( environ, snapshot ):
    """Both branches: absent-at-snapshot -> pop; present -> restore to snapshot value."""

# --- src/tests/smoke/conftest.py (EXTEND existing — thin wrapper only) ---
@pytest.fixture( scope="session", autouse=True )
def tmux_fleet_socket_isolation( tmp_path_factory ):
    """
    Fixtures arm at first-test SETUP; import/collection-time tmux in smoke
    modules stays prohibited.  # <- ratified docstring rider, verbatim
    """
    snapshot = strip_tmux_context( os.environ )
    pinned   = tmp_path_factory.mktemp( "tmux-isolated" )
    os.environ[ "TMUX_TMPDIR" ] = str( pinned )

    yield pinned          # AC2's regression test requests this fixture BY NAME and asserts the pin

    restore_tmux_context( os.environ, snapshot )
```

The snapshot/restore arms resolve the process-global-mutation concern the same way `hermetic_config_module_boundary` does — with the mixed-run behavior stated precisely (Stage-2 corrected wording): the strip arms at first-test setup and stays live **through the end of the WHOLE pytest session** — in a mixed repo-root run, non-smoke tests executing after arm-time also see the stripped env (acceptable by design: no legitimate test may address the fleet socket) — and the prior environment is restored byte-for-byte at session teardown (absent keys end absent, present keys end at their snapshot value). The pure helper functions carry the unit-testability: both restore branches are driven directly via `monkeypatch` unit tests, no tmux involved.

> ⚠️ **Anti-reuse warning — do NOT fold `TMUX`/`TMUX_PANE` into `MAX_PANE_UNSET_KEYS`; it feeds the production launcher scrub.** The launcher's `SERVER_SCRUB` derives from `MAX_PANE_UNSET_KEYS` (`vertex_env`), and production panes legitimately carry `$TMUX` — widening that list would make the production launcher strip live pane context on the fleet server. The test-isolation strip is a SEPARATE, test-only constant (`TMUX_ISOLATION_STRIP_KEYS` above), defined once in `src/tests/smoke/tmux_isolation.py` and imported by the conftest wrapper and the §5.1 helpers — never restated, never merged into the vertex scrub set.

Guard-form disposition (Open sub-question 3, provisional): **session-scoped autouse fixture** — repo precedent favors it (existing autouse conftest guards incl. `hermetic_config_module_boundary` at `src/tests/conftest.py:46–89` and this conftest's own `_auto_proxy_for_module`; zero `pytest_configure`-based env mutators in the tree). **Pending Stage-2 ratification** on one residual: fixtures fire at run start, not collection — ratify that no smoke surface invokes tmux at collection/import time. ### 5.3 Instrumentation upgrade — **extend the runbook §10 killtrace stack** (name the caller next time)
The killtrace is structurally blind to the *client* that requested the kill (kill-server is self-directed; sender is always the server). Propose adding an execve-argv tracer as a **second probe in the existing runbook §10 killtrace stack** (`src/rnd/v0.1.9/2026.07.14-tmux-supervise-runbook.md`) — same delivery form as the first probe: standalone two-file `.bt` + systemd-unit pair, appending to the same append-only log, canary-verified after install. Sketch:
```
tracepoint:syscalls:sys_enter_execve /* argv contains "kill-server" */ {
    printf("KILLER comm=%s pid=%d ppid=%d cmd=%s\n", comm, pid, curtask->real_parent->pid, join(args->argv));
}
```
**Pre-adoption validation clause:** before adoption, validate this snippet against runbook §10's recorded bpftrace traps **on this box's bpftrace version** — (a) the `str(args->comm)` compile trap (`comm` is already `string[16]`; compare directly), and (b) the newline-in-unit-line trap (systemd expands `\n` inside `ExecStart=` → "unterminated string"; hence the standalone `.bt` file form). The sketch above uses bare `comm` and assumes the two-file form, but §10 earned those rules the hard way — re-verify, don't trust the sketch. **Executable HOW (Stage 2):** validation = `bpftrace` parse-only/dry-run of the `.bt` file on this box's bpftrace — **EXECUTOR: AI iff unprivileged parse works** (that privilege check is itself a named verify step); otherwise validation rides the HUMAN install session. **Pass criterion:** clean parse, then the AC6 canary line. The sketch's argv-match filter is explicitly **sketch-with-pass-criterion**: bpftrace cannot string-match across the argv array as written (per-index comparisons will be needed) — exactly what the dry-run will surface.

Alternatives, with the operational asymmetry stated eyes-open (Stage 2): running the supervised server with `tmux -vv` in `ExecStart` is **pre-designed prior art in the runbook itself** (unit-file comment at ~L358 "dumped -> tmux crash (escalate -vv)"; full escalation recipe at ~L499–500, including the chatty-revert caveat) — but its HUMAN leg is heavier than it looks: an `ExecStart` edit takes effect only via a `tmux-server.service` **restart = a fleet bounce** (every session dies; Rick must schedule it). The execve tracer **attaches without touching the running server** (one sudo, any time). auditd on `connect(2)` has **zero prior art** in the runbook. **Coverage caveat (stated, not hidden):** an execve tracer names only freshly-**exec'd** callers — a resident client/control-mode process sending `kill-server` over the socket evades it; `-vv` is server-side and catches every client command. For the known hazard class (exec'd bare `tmux` from test/agent shells), execve suffices — the choice is made knowing the gap.

**Disposition (Open sub-question 1 CLOSED in-plan — ratified by cascade concurrence; user-confirm rides the cascade-complete walkthrough):** ship §5.3 in the **execve-tracer form**, ordered **LAST** in §10 — never instrument-first. Forward-value rationale, cross-cited: §2.7's transcript forensics closed attribution for the three receipted deaths (the *backward* motivation is gone), but Open sub-question 6's unattributed population (14:12, "18:32", any day-1) proves an unnamed killer class existed and the current killtrace structurally cannot name callers — deferring entirely would re-run the 14:12 blindness on the next unattributed death. The HUMAN install leg stays offered-not-blocking per the install-only-on-request contract: the plan is complete if the install is declined; AC6 stays conditional.
