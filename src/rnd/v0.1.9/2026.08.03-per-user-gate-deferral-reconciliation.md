## 1. The defect, stated as mechanism

A pending user-gate (a direct `ask_*` to Rick) is represented in **two independent
places** with no key linking them:

| Representation | Written by | Deferral verb | On the MCP surface? |
|---|---|---|---|
| Store row (`blocked_by:[{kind:user}]` + `next_chase_ts`) | agent, via `task_transition` | `task_transition(blocked)` | **YES** — a seat can call it |
| Hold-file `pending_user_gates[]` row (own `next_chase_ts`) | agent, via `write_hold` | `defer_to_chase(...)` | **NO** — host-side only |

The Stop hook's re-ask/re-surface logic (`stop.py` ~1974) reads the **hold-file**
rows. Its relief valve (`is_chase_deferred`, fix 75f392c0) suppresses a gate only
when the **hold-file row's own** `next_chase_ts` is future.

When a seat follows the standing offline-user rule it defers in the **store**
(`task_transition -> blocked`). That never touches the hold-file row, and the seat
**cannot** touch it (`defer_to_chase` is off the MCP surface). So the hold-file
gate stays "due" → the Stop hook keeps naming it "re-ask now" / "operator-gate
re-surface overdue" every tick. There is no action a seat can take to clear it:
re-asking violates the offline rule; silence trips the re-surface check.

### What is NOT the defect (correction to the founding row)

The store owed-**count** already excludes `blocked` rows
(`task_repository.py`: "blocked / claimed / review are still not owed"). The store
deferral **did** drop the gate from the count. The nag is entirely the hold-file
re-surface path — a second source the store deferral cannot reach.

## 2. The reconciliation: per-USER, not per-gate

"Rick is unreachable until T" is **one fact about a person**, not a property of each
gate. So the store is authoritative, and the hold-file path *follows* it by asking a
per-user question at read time:

> Is this gate's user deferred right now?

- **Authoritative source**: the store's `blocked_by:[{kind:user}]` rows with a
  **future** `next_chase_ts`. The soonest such instant is `user_chase_until`.
- **Suppression rule**: while `now < user_chase_until`, **every** open hold-file gate
  for that session is suppressed (not pokeable, not due, not arbiter-resurfaced).
- **No correlation key needed**: gates inherit the deferral from the person, so a
  hold-file row never has to be matched to a store row.
- **Read-time expiry** (parked-row semantics): once `now >= user_chase_until`, the IO
  shell derives no future chase, and gates re-surface. No sweeper, no daemon.
- **Agent-reachable**: the deferral is *caused* by `task_transition(blocked, next_chase_ts)`
  — a verb a seat already has. That was half of why the bug was unfixable from where
  Mr. Radio sat.

## 3. Build

### 3a. Pure layer — `heartbeat_user_gates.py`
- `is_user_deferred( now_epoch, user_chase_until_epoch )` → `True` iff
  `user_chase_until_epoch is not None and now_epoch < user_chase_until_epoch`
  (strict `<`; boundary `==` is eligible, mirroring `is_chase_deferred`).
- `pokeable_gates`, `due_gates`, `aged_open_gates` gain an optional
  `user_chase_until_epoch=None`. When the user is deferred → return `[]`. Default
  `None` is byte-for-byte the old behavior (backward compatible).

### 3b. Client seam — `task_store_client.py`
- `query_blocked_user_rows( settings, api_key, owner_persona, timeout=None )`:
  `GET /api/tasks?owner_persona=X&status=blocked` (full rows via `_request`). Returns
  `( ok, rows )`. Same §C fail-safe: any not-ok read → `( False, [] )`, never raises.

### 3c. IO shell — `stop.py`
- **Only when `open_gates` is non-empty** (keep the common zero-gate Stop free of the
  extra round-trip): query blocked rows, derive `user_chase_until_epoch` = the minimum
  **future** `next_chase_ts` among rows whose `blocked_by` contains any `{kind:user}`.
- Feed it to `pokeable_gates` / `due_gates`. Fail-safe direction on a bad store read:
  `user_chase_until_epoch = None` → **do not suppress** (never silently bury an open
  user decision; a store outage is transient and the storm it resumes is bounded).
- Log the derived instant + suppressed count in the existing
  `heartbeat_gate_relief_valve` log phase for observability.

### 3d. Arbiter — `arbiter_job.py:4661` (INCLUDED per Mr. Radio, 2026-08-03)
The aged-resurface reads the same hold file and has the same blind spot; fixing the
seat but not the arbiter just moves the nag. The pure `aged_open_gates` gains the
param in 3a. The arbiter loop already reaches the store; it will derive the same
per-user `user_chase_until` for each dark session and pass it in. **If the arbiter
turns out to need a different shape than the same store call, STOP and raise it with
Mr. Radio rather than stretching the fix to cover both.** Do **not** bounce the
arbiter process (a full pyramid is live on :8000).
