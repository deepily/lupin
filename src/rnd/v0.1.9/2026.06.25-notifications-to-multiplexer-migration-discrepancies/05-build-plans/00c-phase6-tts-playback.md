## 5. Work breakdown

### P6-a — Port the gapless scheduler into AudioStore
**What**: After `CHUNK_DECODED` (`onDecoded`, `:302`), schedule the decoded `AudioBuffer`: create a buffer source, connect to destination, `start()` at `max(nextStartTime, ctx.currentTime)`, advance `nextStartTime`. Track the source for stop/completion.
**Files**: `AudioStore.ts` (new private `nextStartTime` **initialized to `0`** (F-Sam-A1, load-bearing), `activeSources[]`, `lastSource`; scheduler method called from `onDecoded`).
**ACs**:
- Functional: consecutive chunks play **gaplessly** (each starts exactly at prior end); first chunk starts at `ctx.currentTime` — **because `nextStartTime` inits to `0` so `Math.max(0, currentTime) === currentTime` (F-Sam-A1, load-bearing). An UNinitialized `nextStartTime` would give `Math.max(undefined, currentTime) === NaN` → `start(NaN)` silent-fail; a test asserts first-chunk `start()` === `currentTime`, never `NaN`.** Output is audible (asserted via injected AudioContext stub recording `start()` calls + scheduled times). **EXECUTOR: AI** (F-Cheech-A1 — the stub assertions [first `start()`===`currentTime`, gapless start times, never NaN] are Claude-executable; "audible" names the output the scheduler drives, NOT a human listen step).
- Structural: scheduler consumes the AudioBuffer already produced by `pcm16ToAudioBuffer` — no second decode. **EXECUTOR: AI** (assert the scheduler reuses the decoded `AudioBuffer`; zero second `createBuffer`/decode calls via the stub).
- Negative: a chunk arriving after `stop()` is not scheduled — **mux-side guard (F-Sam-A3): the scheduler early-returns when the XState snapshot is not a playing/active state (post-`stop()` the machine is `idle`), BEFORE `createBufferSource` — name this explicit condition, not just the legacy `4608-4612` anchor**. **EXECUTOR: AI** (assert a post-`stop()` chunk yields zero `createBufferSource` calls).

### P6-b — Pause / resume / stop on real audio
**What**: Back `AudioStore.pause()/resume()` with `AudioContext.suspend()/resume()`; `stop()` halts all tracked sources, **resets `nextStartTime` to `0`** + clears the source queue, returns the machine to idle (the STOP_REQUESTED transition already exists, `AudioStore.ts:83,90,97`). The `0` reset (not `undefined`) keeps a subsequent fresh burst's first chunk at `Math.max(0, currentTime) === currentTime` (F-Sam-A1).
**Files**: `AudioStore.ts:220-244`.
**ACs**: pause suspends audible output + holds the XState `paused` state; resume continues from the same point; **pause/resume PRESERVES the absolute schedule (F-Sam-A2) — `suspend()` freezes the AudioContext clock, so `currentTime` and every scheduled `start(when)` offset stay coherent; resume does NOT rebase/fix-up `nextStartTime` (an implementer must NOT recompute it on resume) — that no-fixup is exactly what keeps playback gapless across a pause**; stop silences immediately and resets scheduling (`nextStartTime`→`0`); all three are no-ops in their already-guarded states. **EXECUTOR: AI** (F-Cheech-A1 — every pause/resume/stop assertion runs against the injected AudioContext stub: `suspend()`/`resume()` call-recording, `nextStartTime`-reset, no-op guards; no human listen).

### P6-c — Completion-signal seam (signal-OUT only)
**What**: Subscribe AudioStore to the server's **`audio_streaming_complete`** bus event (already on the mux EventBus via `AudioTransport.ts:24`; source `speech.py:818-822`/`:1115-1119`) to set a **stream-complete flag**. Port the last-source `onended` gate (legacy 4645-4661): when the stream-complete flag is set AND this is the last scheduled source, fire the XState `ended` transition and **emit `store_audio_ended`**. **P6 does NOT call `TtsQueueStore.advance()` and does NOT clear/mutate the active-id** — it is a completion SIGNAL only. F0's `TtsQueueStore` subscribes to `store_audio_ended` and self-advances (rolls its own `current()`). The event-emit form structurally guarantees P6 never touches id state (COND-2 ownership boundary; firmed as the directed approach 2026-06-27). **F-Sam-B3 (subscription location):** the `audio_streaming_complete` subscription is registered **inside `AudioStore`** (NOT boot) for test self-containment — boot only mounts AudioStore; the bus-subscribe lives with the flag + handler it drives. **F-Sam-B1 (flag lifecycle):** the stream-complete flag **inits `false`** and is **RESET to `false` on new-stream-start AND on `stop()`** — AudioStore is persistent (idle↔playing↔ended), so a flag left `true` after utterance 1 would make utterance 2's FIRST `onended` complete prematurely, breaking every utterance after the first. **F-Sam-B2 (completion-drop race):** symmetric completion — when the flag is set, if there is **no active/pending source** (the last `onended` already fired for a short final chunk / a delayed frame), **emit `store_audio_ended` immediately** rather than waiting for an `onended` that already passed; else F0's `TtsQueueStore` would never self-advance and the queue would stall silently. (Manager-confirmed: stays on 00c-B's emit side — F0 unchanged, not escalated.)
**Files**: `AudioStore.ts` (bus subscription + stream-complete flag + `onended` handler + emit), `shared/types.ts` (**two edits**: the `store_audio_ended` payload AND — F-Krishna-B1 — registering `audio_streaming_complete` in the `LupinEventType` union, `:22-135`, so the P6-c subscribe is type-checked, not an `as LupinEventType` cast). **NOT** `TtsQueueStore.ts` — the F0-side subscription belongs to F0/00b, not P6.
**ACs**: end-of-utterance fires exactly once (not per-chunk); P6 **emits `store_audio_ended`** exactly once and mutates **no** id/queue state (assert P6 makes zero calls into `TtsQueueStore`); the stream-complete flag correctly gates `onended` (a last-source `onended` BEFORE the flag is set does NOT complete); mid-stream chunks do NOT trigger completion. **F-Sam-B1 (multi-utterance):** flag inits `false` + resets on new-stream-start AND `stop()`; a test asserts utterance 2's FIRST `onended` does NOT complete (no premature carry-over from utterance 1). **F-Sam-B2 (drop-race):** a test asserts that when the flag is set AFTER the last source's `onended` already fired (no active/pending source), `store_audio_ended` STILL emits exactly once (immediate symmetric check). **EXECUTOR: AI** (F-Cheech-A1 forward-sweep — every completion-seam assertion runs against the injected AudioContext stub + a bus-event injector; flag/emit/zero-`TtsQueueStore`-calls are Claude-observable).
