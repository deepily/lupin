## W3 — store-foundation design (do FIRST; W3+W4 depend on it)
Parametrize `hydrateHistory(api, opts?: HydrateHistoryOptions = {})`:
```ts
export interface HydrateHistoryOptions { days?: number; limit?: number; offset?: number; append?: boolean; }
```
- New state: `historyOffset` (rows loaded), `historyTotal` (server total for the window), `historyDays` (current window). Add getters (`historyLoadedCount()`/`historyTotalCount()` or expose via a small accessor) for W4's Load-More gate + count.
- Query build: `limit` (default **20** — legacy/W4 parity, NOT 100), `offset` (default 0), `days` (omit param when undefined; `"all"`→omit). Use URLSearchParams.
- **append=false (replace)** — window-change / initial / retry: CLEAR the history bucket + its `indexById` entries, reset offset=0, fetch, populate, set historyOffset=fetched, historyTotal=resp.total. (Plan-faithful: "changing the window clears the history bucket and refetches"; in-session removals within the window return from the server.)
- **append=true (load-more)** — fetch at offset=historyOffset, keyed-merge dedup by id (skip ids already present), append, historyOffset += fetched.
- **REMOVE the `historyHydrated` early-return guard** (append=false must refetch for retry + window-change); keep `isHistoryHydrated()` reporting "≥1 hydrate completed" (set true after first). 
- **BREAKS 2 existing tests** (rewrite them): `job_store.test.ts:251` "hydrateHistory is idempotent — second call is a no-op" (new semantic: second append=false REFETCHES) + `:267` asserts exact `/api/job-history?limit=100` (now `limit=20&offset=0`). Keep `:211`/`:230` (populate + in-session dedup) working. ADD tests: days param, offset/append load-more, replace-clears-then-refetches, historyTotal/offset tracking, "all"→no days param. 100% L/B/F.
- Backward-compat: `hydrateHistory(api)` with no opts still works (JobsPaneRenderer mount call unchanged) — defaults give a sane initial fetch (days=30 legacy default? confirm; limit=20, offset=0, replace).
