# Disk Cleanup: Remove Stale LoRA/Model Checkpoints from HF_HOME

## Context

`/mnt/DATA01` is at 95% used (95GB free of 1.8TB). `HF_HOME` (`/mnt/DATA01/include/www.deepily.ai/projects/models`) accounts for 1.4TB of that, and most of it is stale — old LoRA merge snapshots and raw training checkpoints from past fine-tuning runs, not the models actually in service today. This plan identifies exactly what's safe to delete and what must survive, verified against live processes and alias/env-var dependencies, not just directory names.

**Verified this session:**
- `svllmr` (alias, `~/.bash_aliases`) is **currently running** (confirmed via `pgrep`) serving `Ministral-8B-Instruct-2410.lora/merged-on-2026-02-20-at-21-10` on GPU0:3000 — this exact path is `$LUPIN_ROUTER_LORA_MINISTRAL_8B_PATH` per `~/.lora_env`. This one must survive.
- `svllmrq` (the Qwen3-4B-Base router alias) was raised as a possible dependency on `Qwen3-4B-Base.lora`, but Rick confirmed that alias is **irrelevant/mistakenly referenced** — no constraint there. Full directory removal is safe.
- `Mistral-7B-Instruct-v0.2` (93G, not the `.lora` variant) has no live process or env-var dependency — only a `cdpr` convenience alias that just `cd`s into a subdirectory of it (harmless if it 404s after deletion).
- `Llama-3.2-3B-Instruct.lora` (50G) has no alias or env-var reference anywhere.
- The port-collision concern raised earlier (new Mistral-Small-24B install vs. `svllmc`/`svllmcr` both on 3001) is a non-issue — GPU-exclusive scheduling means those two are never live simultaneously anyway. No change needed to the separate vLLM-install plan (`src/rnd/v0.1.9/2026.07.31-vllm-mistral-small-24b-install-plan.md`), which stays on port 3001.

## Approach

### Step 0 — Serialize this plan
Write this plan to `src/rnd/v0.1.9/2026.07.31-hf-home-disk-cleanup-plan.md` and link it from `src/rnd/README.md`, before any deletion command runs — same documentation-first pattern used for the vLLM install plan earlier this session.

### Step 1 — Back up the live `svllmr` checkpoint to DATA02 before touching anything

`/mnt/DATA02` already carries a mirrored skeleton of `/mnt/DATA01/include/www.deepily.ai/projects/models/` (same directory names, e.g. `Ministral-8B-Instruct-2410.lora/merged-on-2026-02-20-at-21-10/` already exists there — confirmed this session) but it's empty (3.3M total vs. 1.4TB on the source side) — a structure-only mirror, not an actual data backup. This matches the "dedicated backup drive" convention from prior sessions; using it for a pre-deletion safety copy of the one checkpoint Part 2 is about to make irreversible is exactly the right fit for that drive, independent of the still-open question about relocating the full active `HF_HOME` there.

```bash
rsync -avh --progress \
  /mnt/DATA01/include/www.deepily.ai/projects/models/Ministral-8B-Instruct-2410.lora/merged-on-2026-02-20-at-21-10/ \
  /mnt/DATA02/include/www.deepily.ai/projects/models/Ministral-8B-Instruct-2410.lora/merged-on-2026-02-20-at-21-10/
```

Verify before proceeding: `du -sh` both sides match (~24G), and spot-check file counts (`find ... | wc -l`) on source vs. destination agree. **No deletion — Part 1 or Part 2 — runs until this backup is confirmed complete and verified.** Part 1's three directories are unrelated to the checkpoint being backed up, but the backup still gates all of it: nothing gets deleted until Step 1 is done.

### Part 1 — Full removal of three stale directories (~206GB freed)

| Dir | Size | Dependency check | Verdict |
|---|---|---|---|
| `Mistral-7B-Instruct-v0.2` | 93G | `cdpr` alias only (cosmetic) | Full delete |
| `Qwen3-4B-Base.lora` | 63G | None (svllmrq confirmed irrelevant) | Full delete |
| `Llama-3.2-3B-Instruct.lora` | 50G | None found | Full delete |

```bash
rm -rf /mnt/DATA01/include/www.deepily.ai/projects/models/Mistral-7B-Instruct-v0.2

```

### Part 2 — `Ministral-8B-Instruct-2410.lora`: keep only the live `svllmr` checkpoint (~847GB freed)

Directory totals 871G across 44 `merged-on-*` snapshots and ~60 `training-*` raw-adapter checkpoints. Only `merged-on-2026-02-20-at-21-10` (24G) is live-served today.

```bash
cd /mnt/DATA01/include/www.deepily.ai/projects/models/Ministral-8B-Instruct-2410.lora
find . -mindepth 1 -maxdepth 1 ! -name "merged-on-2026-02-20-at-21-10" -exec rm -rf {} +
```

**This step is irreversible** and destroys all prior merge history and every raw training checkpoint for this model, keeping only what's currently being served. Re-merging with different settings or rolling back to an earlier checkpoint won't be possible after this runs.

### Net effect
~1.05TB freed. `/mnt/DATA01` goes from 95GB free (95% used) to **~1.14TB free (~37% used)**. This alone likely removes the need for the earlier-discussed DATA01→DATA02 `HF_HOME` relocation (that idea stays on hold, per Rick's instruction, and can be revisited only if still needed after this cleanup).
