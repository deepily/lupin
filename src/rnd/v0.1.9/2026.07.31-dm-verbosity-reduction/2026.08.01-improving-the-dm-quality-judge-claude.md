# DM Quality Judge — prompt recommendations

**Response to** `2026.08.01-dm-judge-expert-handoff.md` · Row `ca7a2cbf`

---

## 0. TL;DR

Stop asking the model to *judge* directness. Make it *locate* the verdict, then compute the
grade in Python. Everything else below is secondary to that.

---

## 1. What the existing data already constrains

Two things in §4 of the handoff narrow the hypothesis space more than the document claims.

### 1.1 Hypothesis 5 is largely falsified by evidence already in hand

§4.1 reports that the Tone justification for `BURIED_JARGON` *names the invented vocabulary
correctly*. The observation is therefore already being made explicitly, in a dedicated field,
in the same completion — and directness still fails.

The "recognition has nowhere to go and leaks into the other axis" story requires a
conservation law that does not exist in a transformer; there is no reservoir of unspent
observation. Adding a third dimension buys a redundant field and a new contamination pair, at
the cost of the cheapest experiment slot.

### 1.2 The failure is not local decoding difficulty

Look at where the jargon actually sits. `BURIED_JARGON`'s first sentence is:

> "So I wanted to circle back on the thing we were discussing earlier"

Plain English, zero jargon, unambiguously narration. The model had no comprehension problem at
the position that determines the grade. It failed because it never localised the decision to a
position at all: it graded the **document's register** rather than the **first sentence's
content**.

That also explains the directional asymmetry in question 4. With no positional anchor, the
fallback prior is *declarative + technical + assertive ⇒ this is a result*, which can only err
upward.

### 1.3 Consequence

The defect is **procedural, not attentional**. Directness is currently specified as a vibe with
prose anchors, and a vibe judgement degenerates to a register prior whenever the surface signal
(narrative first person, temporal connectives) is absent or masked.

`BURIED_PLAIN` passes because *"So I spent this morning going through..."* trips the narration
prior directly. Nothing about that case requires the model to know what a verdict is.

## 2. The change that matters

Replace the directness **grade** with an **extraction plus a lookup table**.

### 2.1 Instruction block

```
### Instruction
Grade one message on two independent axes.
DIRECTNESS is about POSITION only. TONE is about WORD CHOICE only.
A message can be unreadable and still perfectly direct.

### Task
Step 1. Copy sentence 1 of the body verbatim.
Step 2. Does sentence 1 state an outcome, a decision, a blocker, or a request
        of the reader? Answer yes or no. A sentence that announces intent,
        recounts effort, or merely names a topic is NOT an outcome, however
        technical it sounds. Treat any term you do not recognise as an opaque
        placeholder: unfamiliar vocabulary is evidence about TONE only and is
        never evidence about DIRECTNESS.
Step 3. If no, give the 1-based index of the first sentence that does state
        one. If no sentence does, give 0.
Step 4. Grade TONE on the 5-level scale, citing specific words.
```

### 2.2 Response schema

```xml
<judgement>
  <first_sentence>So I wanted to circle back on the thing we were discussing earlier.</first_sentence>
  <first_sentence_is_verdict>no</first_sentence_is_verdict>
  <verdict_sentence_index>0</verdict_sentence_index>
  <tone_evidence>owed oracle, aperture disclosure, re-park by induction</tone_evidence>
  <tone_grade>bad</tone_grade>
</judgement>
```

### 2.3 Scoring, in Python

```python
def directness_weight(idx: int) -> int:
    if idx == 1: return 2
    if idx == 2: return 1
    if idx == 3: return 0
    if idx == 0: return -2   # no verdict anywhere
    return -1                # buried behind 3+ sentences of narration
```

### 2.4 Why this is different in kind

1. **The extraction is falsifiable in Python.** Assert that `first_sentence` is a prefix
   substring of the body, and that `verdict_sentence_index <= len(sentences)`. A grade can
   never be validated; a quote can. This converts a silent wrong answer into a caught one.
2. **The jargon cannot reach the directness weight,** because the weight is no longer produced
   by the model. That is a stronger guarantee than any instruction to judge independently.
3. **It kills hypotheses 1–4 as a class.** None of their mechanisms have a path to an integer
   index that is checked against the source text.

### 2.5 Calibration note

This re-centres directness upward — a leading verdict now reaches `+2` where the model was
giving `+1`. Re-run the §2.3 worked example from the handoff before turning the blend back on,
or shift the table down one notch to preserve current behaviour.

## 3. Three cheaper fixes worth doing in the same pass

### 3.1 Field order is generation order

If the Pydantic model emits `grade` before `justification`, the justification is post-hoc
rationalisation of a token already committed — the model cannot use its own evidence. **Evidence
fields must precede grade fields in the schema.** This is close to free and, on a 4-bit 14B, is
frequently worth more than rubric rewording.

### 3.2 Check the prompt format against the model's chat template

The handoff describes Alpaca-style `### Instruction` sent to a completions endpoint, but Phi-4
was instruction-tuned on `<|im_start|>`-delimited turns. Bypassing the trained template
degrades instruction adherence for free — and shallow adherence is exactly the reported
symptom.

Move to `/v1/chat/completions` and let vLLM apply the tokenizer's template, or at minimum diff
the rendered prompt against `tokenizer.apply_chat_template`.

### 3.3 Raise `max_tokens`

Verbatim sentence quoting plus two justifications will crowd 512 on a long body. A truncated
XML tail becomes a parse failure or a silently missing field.

---

## 4. On questions 2 vs 2a

Do not test either as a *fix*. Run the split as a **three-call diagnostic** instead:
`BURIED_JARGON`, directness-only, current rubric otherwise unchanged.

- Still returns `good` → contamination is not the mechanism; **hypothesis 3 dies for the cost
  of three calls.**
- Returns `bad` → there is a real single-call interaction, and the extraction fix should be
  built **on top of** split calls rather than instead of them.

Either way this yields more than a week of building the jargon dimension.

---

## 5. Caution on few-shot exemplars

If exemplars are added to the prompt, **do not use the four probe bodies.** Paraphrase them
heavily or write new ones — otherwise the discrimination probe stops being a measurement.

---

## 6. Suggested order of work

1. Fix field order in the Pydantic schema (§3.1) and the chat template (§3.2) — both cheap,
   both possibly confounding every result so far.
2. Run the three-call directness-only diagnostic (§4).
3. Implement extraction + lookup table (§2), re-calibrate the blend (§2.5).
4. Re-run the 15-call probe. Expect `BURIED_JARGON` directness at `-2`, `REAL_527w` at `-1`
   or `-2`.
5. Revisit the 150-word gate only after the above — with directness computed deterministically
   from an index, long-body behaviour becomes a parsing question rather than a judgement one.
