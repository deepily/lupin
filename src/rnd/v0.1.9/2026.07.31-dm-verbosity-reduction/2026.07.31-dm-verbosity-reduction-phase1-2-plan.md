# DM Verbosity Reduction — Phase 1 (prompting) + Phase 2 (quality judge)

## Context

Rick's Max200 token burn is roughly half inter-agent DMs and half TTS/progressive-disclosure notify() payloads. The TTS side has already been shrunk (per-turn rider cut ~72%, see `src/rnd/v0.1.9/2026.06.27-cosa-voice-rider-slim.md` and `2026.07.19-brevity-mandate-injection-riders.md`). The DM side has not: a real sample (`~/dm-maria-raw.txt`) shows a 483-word DM body against the fleet's own stated 3-line target — aphorisms, self-narrated epistemic hedging, invented jargon, and multi-topic bundling, exactly the "neurotic," bot-not-human register Rick wants gone.

Root cause, confirmed by reading the code: the fleet already injects a brevity rider on every peer DM, but only on the **receiving** end, as a reminder for the recipient's *next reply* (`build_peer_dm_reminder()` in `hook_common.py`). Nothing shapes the **sender's** composition at the moment they call `dm_send` — the tool's own docstring carries zero style/tone instruction. That's the gap this plan closes.

Goal: cut DM token burn materially (target: roughly half) through prompting only — no local rewriter model, no reviewer/judge LLM. Those are explicitly deferred; the existing deep-research doc (`2026.07.31-verbosity-reduction-deep-research.md`, local Qwen3-30B rewriter + LLM-judge harness) is the natural seed for that later phase, not built now. This round must also be **toggleable**, so Rick can A/B a control session against a treatment session before committing.

Confirmed with Rick: toggle is a single INI key in `lupin-app.ini`, sequential A/B (flip between runs, not mid-session) — no env-var override for concurrent runs.

**Phase 2 (added this session)**: between the Phase 1 prompting fix and the eventual Phase 3 (a local LLM manually rewriting/truncating already-sent verbose DMs, per the deep-research doc), add a **quality judge**: `dm_send`'s own tool result carries back a graded quality judgment (Length, Directness, Tone — weighted emoji) so the sending LLM gets immediate feedback on its own DM, same turn, before ever seeing a reply. Confirmed with Rick: hybrid engine (deterministic rubric + a real judge-model call, latency not a concern — quality is), graded weights tallied per-persona over time, judge model is **Mistral Small 3.2 24B Instruct (2506) on vLLM** (a dedicated install is already planned separately — `src/rnd/v0.1.9/2026.07.31-vllm-mistral-small-24b-install-plan.md` — this plan consumes that endpoint, it does not redo that install work).

## Phase 1 Approach

### 1. New style tag + toggle getter

`hook_common.py` — add `DM_STYLE_TAG` next to the existing `BREVITY_TAG` (~line 605), folding in the ratified control-instruction language from `2026.07.31-anthropic-opus-4-8-checkpoints-and-language-reviews.md` line 158 ("lead with the result... no metaphors, aphorisms, punch lines... expand only when asked"), kept as a separate constant since `BREVITY_TAG`'s "Detail → abstract" clause doesn't apply to `dm_send` (no abstract param):

```python
DM_STYLE_TAG = (
    "[DM Style Contract — lead with the result; plain, literal sentences; "
    "decisions/evidence/risks/required actions only; NoAA WaHH; 3 lines / "
    "~60 words; longer ONLY WHEN ASKED.]"
)
```

`cosa/utils/util.py` — add `get_dm_style_contract_enabled()`, same shape as the existing `get_spoken_char_cap()`: reads `lupin-app.ini` key `dm style contract enabled` via `ConfigurationManager`, returns `False` (the safe/control default) on any missing-key or read error, never raises.

`lupin-app.ini` — add `dm style contract enabled = False` in `[Lupin: Baseline]` (after the existing `cosa voice enforce spoken char cap` line, ~883) so every block inherits it, defaulting OFF.

### 2. Send-side: MCP `instructions` payload + `dm_send` docstring

`cosa_voice_mcp.py` — read the toggle once at module load (`_DM_STYLE_CONTRACT_ENABLED = cu.get_dm_style_contract_enabled()`). Build a short `## DM Style Contract` section (~75 words, shorter than the existing `## Speakerphone TTS Contract` it sits beside), spliced into the `instructions=(...)` string right after `_TTS_CONTRACT_SECTION` (~line 646) — empty string when the toggle is off, zero byte cost when disabled. It explicitly states it governs **composing**, not just replying — that's the fix for the actual gap.

`dm_send`'s docstring gets a short style addendum appended (pointing back at the `instructions` section) only when the toggle is on — restructure the tool function so the doc mutation happens before `mcp.tool()` registration (define the function, append to `.__doc__`, decorate last), since FastMCP may snapshot the docstring at decoration time.

Both of these are read once per session (the MCP subprocess is spawned fresh per Claude Code session) — flipping the toggle takes effect on the **next fresh session**, not the current one. That's a non-issue for a sequential A/B: each arm is already a fresh session.

### 3. Reply-side: reinforce at reply-composition time, live (no restart)

`hook_common.py` — add `_peer_dm_reply_rider()`, a call-time resolver (reads the toggle fresh every call, matching the existing per-call `get_spoken_char_cap()` pattern):
- toggle OFF → returns `PEER_DM_BREVITY_RIDER` unchanged (today's shipped behavior — the control arm)
- toggle ON → returns `PEER_DM_BREVITY_RIDER` + `DM_STYLE_TAG`

`PEER_DM_BREVITY_RIDER` itself stays unchanged (it's asserted on directly by existing tests). In `build_peer_dm_reminder()`, swap the reply-affordance's last line from the raw constant to `_peer_dm_reply_rider()`. This one updates live within a running session — no MCP bounce needed for this half.

### 4. Measurement — so the A/B is a number, not a vibe

`cosa/rest/routers/dm.py` — add a `_dm_length_audit` counter dict, mirroring the already-shipped `_dm_project_audit` pattern (lines ~126-186): count, total_chars, total_words, since-timestamp. Add `_record_dm_length(body.body)` right after the existing `_record_dm_project(...)` call in `execute_dm_send` (~line 327) — measuring the caller-supplied body before any timestamp/frame prefix is added, so constant overhead doesn't pollute the delta. Add a `GET /api/dm/length-audit` endpoint mirroring the existing project-audit endpoint. Deliberately does not try to tag rows by experiment arm (fragile if sessions overlap) — Rick snapshots the endpoint before/after each arm's run instead.

## Phase 2 Approach — DM Quality Judge

Runs synchronously inside `execute_dm_send`, after the DM is accepted, before the tool call returns to the sender — latency is accepted, the sender should see its own grade in the same turn, not via a later round trip.

**1. Deterministic pre-check (fast, always runs, zero extra tokens):**
- Length: word/char count vs the Phase 1 ~60-word/3-line target.
- Directness: does the first sentence read as the verdict, or as a hedge-opener ("I think", "It's worth noting", "So,")? Keyword/position heuristic.
- Tone/jargon: blocklist scan seeded from the WaHH ❌ examples already in `cross-session-communication.md` and the NoAA-named aphorism patterns in `brevity-mandate.md`.

**2. LLM judge pass (real model, latency accepted, quality prioritized):** a fixed-rubric prompt sent to the Mistral Small 3.2 24B vLLM endpoint (host:port supplied once the separate install plan lands — new `lupin-app.ini` key, e.g. `dm judge vllm endpoint`), via the **existing** `LlmClientFactory`/`ChatClient` abstraction (`cosa/agents/llm_client_factory.py`, already supports a `vllm://host:port@model` descriptor — reuse, don't rebuild). Returns Length/Directness/Tone grades plus a one-line actionable note. **New build item, confirmed nothing like it exists today:** no `Judge`/`Grader`/rubric class exists anywhere in `cosa/`, `lupin_mcp/`, or `lupin_cli/` — this is net-new, as is JSON-schema-constrained output on the vLLM client path (today's `chat_client.py`/`completion_client.py` has no structured-output enforcement wired in; the deep-research doc flags xgrammar-enforced schema as the recommended approach, not something already built).

**3. Weighted emoji scale** (per dimension + one overall), carrying explicit numeric weight so it's not just decorative:
- ⭐ exemplary (+2) · 👍 meets the bar (+1) · 👎 needs improvement (−1)

**4. Return shape** — appended to `dm_send`'s existing tool result as a new `quality` field, e.g. `{"length": {"emoji": "👎", "weight": -1, "detail": "187 words, target ~60"}, "directness": {...}, "tone": {...}, "overall": {..., "note": "Cut to length next time — lead sentence was good."}}`.

**5. Per-persona tracking over time** — extend the same `_dm_length_audit` sibling-counter pattern from Phase 1 (`cosa/rest/routers/dm.py`) to also tally quality weights per sending persona (running average per dimension), exposed via a sibling endpoint (e.g. `GET /api/dm/quality-audit`) so Rick can watch whether a given persona's DMs actually improve over a session or a day.

**6. Own toggle**, independent of Phase 1's: `dm quality judgment enabled` in `lupin-app.ini`, default `False` — lets Phase 1 and Phase 2 be A/B'd separately or together.

**Explicit dependency**: Phase 2 cannot go live until the Mistral vLLM endpoint from `2026.07.31-vllm-mistral-small-24b-install-plan.md` is actually running (that doc's checkpoint choice is still open, per its own §"Open decision"). This plan does not duplicate that install work — it only wires a client to whatever endpoint it produces.

**Manual end-to-end A/B (the real test)**:
1. Confirm toggle is `False`. Snapshot `GET /api/dm/length-audit`.
2. Run the **control** session, send a few realistic peer DMs (similar topic to `~/dm-maria-raw.txt` so the arms are comparable). Snapshot the audit again → control delta.
3. Flip the toggle to `True`. Start a **fresh** session (required — new MCP subprocess) as the **treatment** arm, send comparable DMs. Snapshot again → treatment delta.
4. Compare avg_chars/avg_words per arm against the rough-half target, and read the raw bodies for register (no aphorisms/jargon), not just length.
5. Confirm the session-boundary behavior itself: a session started *before* the flip does not pick up the new instructions/docstring text; the reply-side rider updates immediately within a still-running session.
