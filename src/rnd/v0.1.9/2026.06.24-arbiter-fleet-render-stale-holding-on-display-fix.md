## TL;DR

The `/state` snapshot (and the arbiter's `fleet_arbiter_render` line) shows a **raw `holding_on` value (e.g. `peer:maria`) for a session whose last activity is STALE** — even though commit `37511bfb` now correctly drops that stale session's *edge* from inference. The harmful part (phantom taps/edges) is fixed; this is the remaining **cosmetic display inconsistency**: the rendered `holding_on` should agree with the edge logic — a stale session should not display an active `peer:X` hold.

## Background / why this is separate from `37511bfb`

`37511bfb` (bug `8a450183`) gated peer-EDGE inference on holder-SESSION freshness (`dependency_graph.session_is_stale`), so a beyond-alive-threshold session contributes **zero edges**. But the **display path** (`fleet_render.py`, which renders each row's `holding_on` for `/state` + the `fleet_arbiter_render` journal line) reads `holding_on` straight from the fleet-view row and shows it raw — it was NOT touched by the edge-inference fix (different code path). So a stale session still *displays* `peer:maria` until its `last_activity` refreshes.

## Fix direction (design it; confirm first)

**Sanitize the rendered `holding_on` against session-freshness, REUSING the shipped `session_is_stale`.** When `fleet_render` formats a row whose holder SESSION is stale (same beyond-alive-threshold predicate the edge gate uses), display a neutral value (recommend `none`, or a distinct `stale` marker — Manager will confirm wording) instead of the raw `peer:X`. The display then AGREES with the edge logic: a stale session shows no active hold.

- **Single source of truth:** reuse `dependency_graph.session_is_stale` (or the same now/threshold inputs) — do NOT re-implement a second freshness predicate.
- **Fail-safe / consistent with `37511bfb`:** missing/unparseable `last_activity` ts → treat as NOT stale → show the raw value (never hide a live hold).
- **Scope = DISPLAY ONLY.** `fleet_render` is rendering; do NOT alter `build_wait_edges`/`build_graph`/edge inference, and do NOT touch the `:1070` unfiltered deadlock escalation. This change must not affect any actionable decision — only what the human sees.
