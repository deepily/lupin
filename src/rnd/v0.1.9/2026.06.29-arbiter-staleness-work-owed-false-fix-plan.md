## TL;DR

A manager session that declares itself **done** (`work_owed: false` in its heartbeat hold)
keeps getting **manager-staleness pokes ~every 45 min**, wasting Rick's scarce weekly
tokens. The fix makes a **hold-declared `work_owed=false`** a first-class poke suppressor
(DONE-equivalent), independent of the store classification.

---

## Precise root cause (confirmed in code, supersedes the symptom-report *lead*)

The symptom report's lead pointed at `dependency_graph.py` `hold_is_stale` (L159/L575).
That predicate is real but feeds the **dependency-GRAPH edge-inference** path, **not** the
staleness-poke path. The actual poke decision is in:

- `src/cosa/agents/heartbeat_arbiter/arbiter_job.py` → `_check_manager_staleness()` (L2992).

It classifies each eligible manager via `owed_class = self._classify_owed(...)` (L2348),
which is **store-derived only**:

- `CLASS_DONE` ⇔ **zero non-terminal owed items in the STORE** → suppressed (case-17 advisory, no poke). ✅
- `CLASS_BLOCKED_ON_USER` ⇔ all owed items Rick-gated → suppressed (case-16 advisory). ✅
- `CLASS_ACTIVE` / `CLASS_UNKNOWN` → **case-14 poke fires.** ⚠️

**The gap**: `_check_manager_staleness` / `_classify_owed` **never read the heartbeat
hold's `work_owed` flag at all.** `declared_work_owed` is not even imported into
`arbiter_job.py` (it lives in `lupin_cli/.../heartbeat_hold.py`; only `get_pending_user_gates`
is imported). So a session that self-declares `work_owed=false` in its hold — but whose
STORE still shows ≥1 non-terminal item (or whose store read returns UNKNOWN) — classifies
**ACTIVE/UNKNOWN** and is poked every cycle.

**e02e22b9 cross-check verdict (preliminary — reviewer to confirm)**: e02e22b9's
"done-aware suppression" is **option (b)** from the report — it covered **store-DONE**
(zero non-terminal items) but **not** a hold-declared `work_owed=false`. Not a regression;
a genuine coverage gap in the same family.

---

## The fix (single, minimal, fold into the existing hold-read)

`_classify_owed` **already reads the hold once** in the 6929f4ac open-gate override loop
(L2406–2421, gated on `self._hold_reader_fn is not None`). Fold the work_owed axis into
that **same loop** — one hold read, two overrides, with **open-gate winning** (a session
with an open user-gate owes a re-ask and is NOT done, even if it sloppily set
`work_owed=false`):

```python
# inside the existing `if self._hold_reader_fn is not None and names:` loop,
# after reading `hold` for each persona's sid:
if declared_work_owed( hold ) is False:
    result[ persona ] = CLASS_DONE          # hold self-declares finished → DONE-equivalent
if open_gates( get_pending_user_gates( hold ) ):
    result[ persona ] = CLASS_ACTIVE        # 6929f4ac: open gate owes a re-ask → ACTIVE (wins)
```

- Import `declared_work_owed` from `lupin_cli.claude_code.hooks.lib.heartbeat_hold`.
- **Order matters**: apply `work_owed=false → DONE` BEFORE the open-gate `→ ACTIVE`, so an
  open gate re-promotes (preserves 6929f4ac).
- **Fail-safe preserved**: unwired seam / raising reader → `hold = None` →
  `declared_work_owed(None) is None` (not `False`) → no override → today's behavior. A
  `work_owed` field that is absent/non-bool → `None` → no suppression (never silences a
  real escalation).

This feeds the detectors that consume `owed_class` — the consolidated "signal-of-life"
direction, narrowed to the `work_owed` axis for this bug.

> **CORRECTION (Cheech 🌿 review, file:line-verified by Tiberius 👑)**: the override is
> NOT uniform across all three consumers. It IS honored by **#9 (acks)** and **#F2
> (staleness)** — both gate on `cls == CLASS_DONE`. It is **NOT** honored by **#11
> (fleet-stall)**: `_has_live_owed_work` (arbiter_job.py L2806) hand-rolls its exclusion
> and excludes ONLY `CLASS_BLOCKED_ON_USER`, never `CLASS_DONE` — even though the pure
> predicate `owed_class_suppresses` (L214, `NOT_OWED_CLASSES` L191) treats DONE as
> suppressing and its docstring (L200-201) names #11 a consumer. So the feared exposure —
> a wedged self-declared-done session silencing the STALL detector — **does NOT
> materialize**. This #11 drift is **PRE-EXISTING** (not introduced by this fix; arbiter_job.py
> had zero `declared_work_owed` refs before) and is filed as a **separate follow-on**
> (whether it is a bug or intentional turns on done-but-alive-non-progressing fleet
> false-stall semantics — out of scope for this focused staleness-poke fix).

The only NEW #11 interaction from this fix: a session previously `BLOCKED_ON_USER`
(stall-excluded) that ALSO sets `work_owed=false` → re-labeled DONE → newly *included* in
the live-owed set (DONE not excluded by #11). Opposite direction (less suppression),
low-impact, arguably more-correct. Accepted.

**Out of scope for this task** (note + defer, do NOT build): the full consolidated
signal-of-life suppressor over {fresh hold, recent DM, recent task-transition} — those
axes are already partly covered by the 5-signal ack path; folding them into ONE source is
a follow-on, not this fix.
