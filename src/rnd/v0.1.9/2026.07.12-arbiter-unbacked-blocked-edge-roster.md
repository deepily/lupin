## 1. Defect

The heartbeat arbiter emitted false **"Blocked: X"** manager-tap advisories for workers with **ZERO store-backed blocked rows** — three live occurrences across two personas, the last (`maria`, 2026-07-12 00:28:48 EDT) on **fully-patched code** (both `ad0f6199` L1 dedup and `cec10ef9` L2 designed-hold suppression live), empirically proving the path survives both by design.

Verify-first was satisfied by the live evidence set; the remaining leg — reproducing the edge-derivation mechanics in the unit harness — is `src/tests/unit/test_arbiter_unbacked_blocked_edge.py`.

## 2. Root cause (journal ground truth, not hypothesis)

`build_fleet_view` mints a view's `holding_on` **straight from the session's most-recent heartbeat activity record** (`fleet_data_model.py:437`):

```python
"holding_on" : ( last_activity.get( "awaiting" ) or "none" ) if last_activity else "none",
```

`awaiting` is a **free-form** field, and it is **STICKY**: it persists on the freshest activity record until a later record overwrites it. maria's records (`~/.claude/heartbeat-events/6ecfb4e7….jsonl`):

| record ts (UTC) | `awaiting` | `work_owed` |
|---|---|---|
| 2026-07-11T22:13:42 | `peer:sam-and-reviewers` | True |
| 2026-07-12T00:42:01 | `peer:sam-and-reviewers` | **False** |
| 2026-07-12T04:27:56 | `peer:sam-and-reviewers` | **False** |

At the 04:28:48Z poll her view therefore carried a peer edge to **`sam-and-reviewers` — a prose label, not a fleet persona**. The awaited "peer" is absent from the fleet ⇒ not alive ⇒ the `bbce7e2f` dead-peer **fail-safe KEEPS the holder** ⇒ she was rostered "blocked" and tapped to her manager — while the store held **zero** non-terminal rows for her and her bridge was **53s fresh** (demonstrably active).

**Bridge activity does not age the edge out.** The edge was ~6h stale on a live session. That is the "how do `holding_on` edges age out vs bridge activity" question answered: *they don't.*

### The real finding — an ASYMMETRY, not a missing feature

The same poll's journal line:

```json
{"event": "arbiter_poll_activity", "edges": 1, "cycles": 0, "pings_fired": 0, "roster": 1, "taps_fired": 1}
```

- The **PING leg** (`"You're blocking worker Y"`) is **already store-corroborated** — `edge_is_store_backed` over `build_store_wait_edges`, bug `d44b7068` (`arbiter_job.py:1285`) — and correctly fired **zero** pings off that edge.
- The **ROSTER/advisory leg** (`_attention_workers` → `_format_manager_tap`) consulted **no store at all** and fired the false advisory off the **same edge**.

`d44b7068` fixed one leg and not its sibling. That gap *is* the bug.

## 3. Fix

Thread the **already-computed** per-poll authoritative store wait-graph (`store_edges = build_store_wait_edges( owed_items )`, `arbiter_job.py:1244` — **no new query**) into `_tap_managers` → `_attention_workers` as `store_edges=None`. In the **blocked-edge leg only**: a derived edge with no store `blocked_by` backing does not roster its holder, and the suppression is journaled as `arbiter_unbacked_edge_suppressed` (carrying `persona` + `awaited`).

```python
awaited = graph[ "edges" ].get( persona )
if ( store_edges is not None and persona not in cycle_personas
     and not edge_is_store_backed( persona, awaited, store_edges ) ):
    self._log( "arbiter_unbacked_edge_suppressed", persona=persona, awaited=awaited )
    continue
```

### Fail-safe direction is ROSTER (never hide a real stall) — three carve-outs

1. **Store read failed / seam unwired** (`owed_items is None` ⇒ `store_edges=None`) → **no filtering**, today's behavior. A store outage must never silence a genuine block. Mirrors `ping_edges`' fail-safe branch exactly.
2. **Deadlock-cycle member** → always kept; a mutual stall stays load-bearing.
3. **Canonical persona keying on both sides** (`edge_is_store_backed`) → a spelling/casing difference can never fake an "unbacked" verdict.

### Scope fence (Mr. Radio, ratified)

- `_item_is_user_gated` (Rick-gate) — **untouched**.
- `ce13b134` dedup key/cooldown — **untouched**.
- `cec10ef9` designed-hold suppression semantics — **untouched** (a composition test pins both gates coexisting on one poll).
- **The `stuck` leg — untouched.** The sibling false **"Stuck: sam"** advisories entered the roster via the view's `stuck` FLAG (`fleet_data_model._count_stuck_episodes` over `cap_reached` records — the `5a1f17f8`/`92c7ab1d` replay axis), *not* via a `holding_on` edge (journal: those advisories read `1 stuck/dead · 0 blocked`). That is a **DISTINCT root**, filed separately by Mr. Radio. Gating the stuck leg on store rows would hide a genuinely wedged worker — the wrong fail-safe direction. Two tests pin this fence.
