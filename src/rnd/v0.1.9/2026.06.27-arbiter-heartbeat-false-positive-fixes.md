## B1 — Stop-hook ignores a well-formed hold

### Diagnosis (empirical)

The decision flow is sound *in structure*: `heartbeat_decision.decide_heartbeat()` calls `is_honored(hold)` and returns `OUTCOME_HONORED` (no poke) for a fresh, reasoned hold — **before** consulting owed work. So María's hypothesis that "`work_owed:true` always nags and the hold only suppresses the literal no-hold branch" is **disproven by the code**: a plain `todo_in_progress` owed signal does NOT override an honored hold (only `needs_verification` / `outstanding_user_gate` do, via the 6929f4ac obligation-override).

Therefore the hold must have failed `is_honored()` → which is `is_fresh()` AND non-empty reason. `is_fresh()`:

```
elapsed = now − held_at          # held_at is SUPPLIED BY THE AGENT
return elapsed < ttl_seconds
```

**Root cause**: `held_at` is agent-authored, but **agents have no reliable wall-clock**. The no-reliable-clock rule forces an agent to anchor `held_at` to a *past* receipt (the latest timestamp it can see — a DM, an arbiter heartbeat). If that receipt is older than the agent assumes, the hold is **born already-stale or near-stale**, fails freshness, and the session is poked — then re-writes the hold (again anchored to a stale receipt), and is poked again. Empirically: **"nagged 4 consecutive Stops despite a hold present each time."**

Confirming evidence: María's on-disk hold carries `held_at` `19:04:00Z`, but the **host-real file mtime is `19:05:44Z`** — the mtime trails `held_at`, i.e. the host knows the true write time and the agent's `held_at` does not. The Stop hook ignores mtime; the **arbiter already uses hold mtime** as a liveness signal (`_default_hold_mtime_fn`, task `70be69f2`). That inconsistency *is* the bug.

### Fix (decided: mtime anchor)

In `heartbeat_hold.py`, compute freshness against the **file's mtime** (host truth of when the hold was last written), falling back to `held_at` only when the mtime is unavailable. `held_at` becomes advisory metadata. An agent that re-declares its hold each turn refreshes the mtime → always honored. Removes the agent's unreliable clock from the freshness path entirely.

- `is_fresh(hold, now, mtime=None)` — when `mtime` is provided, freshness = `(now − mtime) < ttl`; else legacy `held_at` path (back-compat for callers/tests that pass no mtime).
- The reader threads the actual file mtime: `read_hold` / `read_hold_resilient` know the path they read, so they can stat it and attach `_mtime` (or the Stop-hook shell stats it). Design choice in implementation: prefer attaching the resolved mtime at read time so `is_fresh`/`is_honored` stay pure over the passed value.
- **Bias-to-keep-alive**: if neither mtime nor a parseable `held_at` is available, fall back to current behavior (never *more* likely to poke than today).

### Tests
- mtime within ttl → fresh/honored even when `held_at` is ancient.
- mtime expired but file just rewritten → fresh (the core repro).
- no mtime (path absent) → legacy `held_at` behavior preserved.
- 100% line/branch/function on `heartbeat_hold.py`.

## B3 — "X blocking Y" with no backing obligation

### Diagnosis (demonstrated live)

While walking Rick through this very fix, the arbiter poked María "you're blocking Tiberius." Reality: *Tiberius* held `awaiting: peer:maria` for her writeup; she **delivered** it; the obligation was discharged — but the arbiter kept minting the edge off the now-stale one-sided `awaiting`. Same class as the postmortem's "Krishna blocked on Mr Radio" recurring ~23 min for a delivered-and-parked worker.

**Root cause**: the wait-edge derivation mints "X blocking Y" from a one-sided signal (Y's `awaiting: peer:X`, or a DM-wait graph) **without checking whether X actually owes Y anything**.

### Fix (decided: backing-obligation gate)
Only mint "X blocking Y" when X has a **live owed obligation** toward Y — cross-check Y's `awaiting` against X's real board/delivery state; suppress the edge when X has delivered or owns nothing for Y. Makes the edge truthful at the source rather than damping the symptom.

Files (confirm at implementation): `dependency_graph.py` (`build_wait_edges`, `build_store_wait_edges`, `hold_contradicts_peer_edge`) + the `arbiter_job.py` edge-advisory path.

### Tests
- Y awaits X, X has an open item owed to Y → edge fires (true positive preserved).
- Y awaits X, X delivered / owns nothing → edge suppressed (the repro).
- 100% coverage on touched modules.
