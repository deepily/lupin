## Task 1: Create `templates/themes/default.yaml`

**Path**: `/mnt/DATA01/include/www.deepily.ai/projects/lupin/src/cosa/agents/presentation_generator/templates/themes/default.yaml`

This YAML file defines theme configuration that the orchestrator loads and passes to the renderer. It is NOT Marp frontmatter itself — it is a config file that drives frontmatter generation.

### Structure

```yaml
# Theme: default — clean, professional presentation theme
name: default

# Marp frontmatter directives (injected verbatim into ---/--- block)
frontmatter:
  marp: true
  paginate: true
  size: "16:9"

# Header/footer templates — {title}, {speaker}, {date} are interpolated
header_template: "{title}"
footer_template: "{speaker} | {date}"

# CSS style block — injected into frontmatter `style:` key
style: |
  section {
    font-family: 'Segoe UI', Tahoma, Geneva, Verdana, sans-serif;
    padding: 40px;
  }
  h1 {
    color: #2d3748;
    border-bottom: 2px solid #4299e1;
    padding-bottom: 10px;
  }
  h2 {
    color: #4a5568;
  }
  ul {
    font-size: 0.95em;
    line-height: 1.6;
  }
  section.title-slide {
    text-align: center;
    display: flex;
    flex-direction: column;
    justify-content: center;
  }
```

### Design Rationale

- Separating theme config from renderer makes themes swappable without code changes.
- The `header_template` / `footer_template` use simple `str.format_map()` interpolation with presentation metadata.
- The `style` block is raw CSS passed through to Marp's `style:` frontmatter key.
- Future themes (e.g., `corporate.yaml`, `academic.yaml`) follow the same schema.

## Task 2: Create `renderers/marp_text_renderer.py`

**Path**: `/mnt/DATA01/include/www.deepily.ai/projects/lupin/src/cosa/agents/presentation_generator/renderers/marp_text_renderer.py`

### Class: `MarpTextRenderer`

A stateless renderer. Single public method `render()` — pure function, no side effects.

```python
class MarpTextRenderer:
    """
    Render a PresentationModel to Marp Markdown.

    Pure text transformer: PresentationModel in, Marp markdown string out.
    No file I/O, no async, no LLM calls.

    Requires:
        - presentation is a valid PresentationModel with at least one slide
        - theme_config is a dict with keys: frontmatter, header_template,
          footer_template, style

    Ensures:
        - Returns a complete Marp Markdown string
        - Slide count in output matches presentation.total_slides
        - All presenter notes wrapped in HTML comment blocks
        - YAML frontmatter includes theme directives
    """
```

### Public API

```python
@staticmethod
def render( presentation: PresentationModel, theme_config: dict, debug: bool = False ) -> str:
```

### Internal Methods (all `@staticmethod`, all private)

| Method | Responsibility |
|--------|---------------|
| `_render_frontmatter( presentation, theme_config )` | Build YAML frontmatter block |
| `_render_slide( slide, is_first )` | Dispatch to type-specific renderer |
| `_render_title_slide( slide )` | Title slide: `# Title`, `## Subtitle`, speaker/date |
| `_render_content_slide( slide )` | Content slide: `# Title`, bullet list |
| `_render_section_divider_slide( slide )` | Section divider: centered `# Title`, optional subtitle |
| `_render_conclusion_slide( slide )` | Conclusion: `# Title`, bullets, call-to-action feel |
| `_render_presenter_notes( notes: PresenterNotes )` | HTML comment block with structured notes |

### Frontmatter Generation Logic

The `_render_frontmatter` method:
1. Starts with `---\n`
2. Writes `marp: true` (always)
3. Writes each key from `theme_config["frontmatter"]` (e.g., `paginate: true`, `size: "16:9"`)
4. Interpolates `header_template` and `footer_template` with `{ "title": presentation.title, "speaker": presentation.speaker, "date": presentation.date }`
5. Writes `header:` and `footer:` directives
6. Writes `style: |` followed by indented CSS from `theme_config["style"]`
7. Ends with `---\n`

### Slide Rendering Logic

Each slide renderer returns a string (no leading `---`). The `render()` method joins slides with `\n---\n\n`. The first slide gets no separator prefix; subsequent slides do.

**Title slide** (`_render_title_slide`):
```markdown
# {slide.title}
## {slide.subtitle}
{presentation.speaker} | {presentation.date}
```

**Content slide** (`_render_content_slide`):
```markdown
# {slide.title}

- {bullet 1}
- {bullet 2}
- {bullet 3}
```

**Section divider** (`_render_section_divider_slide`):
```markdown
<!-- _class: section-divider -->

# {slide.title}
```
(Uses Marp local directive for class-based styling)

**Conclusion slide** (`_render_conclusion_slide`):
Same structure as content slide — bullets for takeaways. The distinction is semantic (for future CSS differentiation), not structural.

### Presenter Notes Format

All slide types get presenter notes appended if the `PresenterNotes` object has any content:

```markdown
<!--
Transition: {notes.transition}
Talking points:
- {point 1}
- {point 2}
Timing: {notes.timing_seconds}s
Emphasis: {notes.emphasis}
-->
```

Omit lines where the value is `None` or empty. If all fields are empty/None, omit the entire comment block.

### Edge Cases

- **Empty `content_bullets`**: Render slide with title only, no bullet list.
- **`None` subtitle**: Skip subtitle line entirely.
- **`None` transition / emphasis**: Omit those lines from presenter notes.
- **Empty `talking_points`**: Omit the "Talking points:" section.
- **Unknown slide type**: Fall back to `_render_content_slide` with a debug warning.

### Code Style Notes

- Spaces inside parens/brackets per CLAUDE.md: `def render( presentation, theme_config, debug=False ):`
- Vertically aligned assignments
- DbC docstrings on all methods
- Use `"\n".join( lines )` pattern for building slide content (list of lines, join at end)

```python
@staticmethod
def _write_marp( marp_path: str, marp_content: str ) -> None:
    """
    Write Marp Markdown content to disk, creating directories as needed.

    Requires:
        - marp_path is an absolute file path
        - marp_content is a non-empty string

    Ensures:
        - Parent directory exists
        - File is written with UTF-8 encoding
    """
    os.makedirs( os.path.dirname( marp_path ), exist_ok=True )
    with open( marp_path, "w", encoding="utf-8" ) as f:
        f.write( marp_content )
```

**3. Add static method** `_load_theme_config` for loading the YAML theme file:
```python
@staticmethod
def _load_theme_config( theme_path: str ) -> dict:
    """
    Load theme configuration from a YAML file.

    Requires:
        - theme_path is an absolute path to a YAML file

    Ensures:
        - Returns dict with keys: frontmatter, header_template,
          footer_template, style
        - Falls back to minimal defaults if file not found

    Returns:
        dict: Theme configuration
    """
    import yaml

    if not os.path.exists( theme_path ):
        logger.warning( f"Theme file not found: {theme_path}, using fallback" )
        return {
            "frontmatter"     : { "marp": True, "paginate": True },
            "header_template" : "{title}",
            "footer_template" : "{speaker} | {date}",
            "style"           : "",
        }

    with open( theme_path, "r", encoding="utf-8" ) as f:
        return yaml.safe_load( f )
```

**4. Replace `_render_text_async` stub** (lines 995-1002):

```python
async def _render_text_async( self, presentation: Optional[ PresentationModel ] ) -> None:
    """
    Phase 6: Render PresentationModel to Marp Markdown.

    Loads theme config, calls MarpTextRenderer, writes .md file to disk.

    Requires:
        - presentation is a valid PresentationModel (or None to skip)

    Ensures:
        - Writes Marp Markdown file to config-defined output path
        - Stores marp_path in _presentation_state for job to read
        - Logs file path and size when debug is enabled
    """
    if presentation is None:
        if self.debug: print( "[Orchestrator] Phase 6: Skipped (no presentation)" )
        return

    if self.debug: print( "[Orchestrator] Phase 6: Render Text — generating Marp Markdown" )

    try:
        # Resolve theme path
        import cosa.utils.util as cu
        theme_path = cu.get_project_root() + self.config.templates_path + self.config.default_theme + ".yaml"

        # Load theme config (sync — small file, fast read)
        theme_config = self._load_theme_config( theme_path )

        # Render Marp Markdown (pure function — no I/O)
        marp_content = MarpTextRenderer.render( presentation, theme_config, debug=self.debug )

        # Get output path (same dir as YAML, but .md extension)
        user_id   = self._presentation_state.get( "user_id", "unknown" )
        marp_path = self.config.get_output_path( user_id, presentation.title, file_type="md" )

        # Write to disk in thread pool (non-blocking)
        loop = asyncio.get_event_loop()
        await loop.run_in_executor( None, self._write_marp, marp_path, marp_content )

        # Store path for job to read
        self._presentation_state[ "marp_path" ] = marp_path

        if self.debug:
            print( f"[Orchestrator] Marp written: {marp_path}" )
            print( f"[Orchestrator] Marp size: {len( marp_content )} chars" )

        await voice_io.notify(
            f"Marp rendered: {presentation.total_slides} slides → {os.path.basename( marp_path )}",
            priority="low"
        )

    except Exception as e:
        logger.error( f"Marp rendering failed: {e}" )
        if self.debug:
            import traceback
            traceback.print_exc()
        await voice_io.notify( f"Marp rendering error: {str( e )[ :80 ]}", priority="urgent" )
```

### Key Pattern Observations from Phase 5 `_serialize_async`

- Uses `loop.run_in_executor( None, ... )` for file writes (thread pool, non-blocking).
- Stores path in `self._presentation_state[...]` for job to read.
- Uses `voice_io.notify()` for progress breadcrumbs.
- Wraps in try/except with `logger.error()` and traceback on debug.
- Phase 6 follows this exact pattern.

## Risks and Mitigations

| Risk | Mitigation |
|------|-----------|
| Theme YAML schema mismatch | `_load_theme_config` has hardcoded fallback dict; tests validate against known schema |
| Marp frontmatter syntax errors | Tests verify exact `---` boundaries and `marp: true` presence |
| Special characters in bullets (YAML/Markdown escaping) | Bullets come from LLM via Pydantic model — already strings. No re-escaping needed for Marp Markdown. |
| `get_output_path` timestamp race (YAML and Marp get different timestamps) | Acceptable — files live in same directory, names differ only by extension and seconds. Alternatively, could cache the timestamp, but this matches existing Phase 5 pattern. |
| `templates_path` is relative to project root with leading `/` | Matches existing pattern: `cu.get_project_root() + self.config.templates_path` — the leading `/` in the config value acts as a path separator. |
