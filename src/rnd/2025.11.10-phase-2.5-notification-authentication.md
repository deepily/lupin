## Overview

Phase 2.5 adds authentication to notification endpoints to enable secure production deployment to Google Cloud Run. This phase implements API key authentication for service-to-service communication between Claude Code CLI and the Lupin FastAPI server.

**Context**: Phase 2.4 (Async Refactoring) completed the notification system with both async (fire-and-forget) and sync (response-required) modes. However, notification endpoints currently have no authentication, which blocks production deployment.

**Goal**: Implement secure API key authentication with multi-environment support (dev, staging, production) to enable Cloud Run deployment.

### API Key Security Requirements

#### Generation Requirements

**Algorithm**: `secrets.token_urlsafe(48)` (Python standard library)
- Produces 64-character base64url-encoded string
- Cryptographically secure random generation
- No special characters that require URL encoding

**Format**: `ck_live_{random_string}`
- **Prefix**: `ck_live_` (6 characters)
- **Random portion**: 64 characters (base64url)
- **Total length**: 70 characters minimum
- **Example**: `ck_live_9x7Kp3mN8vQ2jR5wT6yL4hC1aZ0dE3fG8bS5nU2mV7xP9kJ4qW6rT8yH3cA1zL0`

**Prefix Rationale**:
- `ck_` = "Claude Key" (clear identifier)
- `live_` = Production key (vs. `test_` for testing)
- Follows Stripe API key convention (recognizable pattern)
- Enables key detection in logs/code (security scanning)

**Generation Process**:
1. Generate random bytes: `secrets.token_urlsafe(48)` → 64 chars
2. Add prefix: `ck_live_{random}` → 70 chars total
3. Display plaintext key to user ONCE
4. Hash with bcrypt (cost factor 12)
5. Store only hash in database
6. Write plaintext to key file (environment-specific)

#### Storage Requirements

**Database Storage** (hashed):
- Table: `api_keys`
- Field: `key_hash` (TEXT, bcrypt hash)
- Algorithm: bcrypt with cost factor 12
- Salt: Automatic (bcrypt handles salting)
- Never store plaintext keys in database

**File Storage** (plaintext):
- **Development**: `/path/to/project/src/conf/keys/notification-api-claude-code-dev`
- **Production**: `/home/user/.lupin/keys/notification-api-claude-code-prod`
- **Staging**: `/home/user/.lupin/keys/notification-api-claude-code-staging`
- **Permissions**: 600 (read/write owner only)
- **Git**: Excluded via `.gitignore` (keys never committed)

#### Key Lifecycle

**Creation**:
- CLI utility: `python src/scripts/create_service_account.py --env=dev`
- Interactive prompts for email, description
- Generates key, displays once, stores hash

**Usage**:
- CLI commands read key from file
- Send in `X-API-Key` header
- Server validates against bcrypt hash
- Update `last_used_at` timestamp on success

**Revocation**:
- Set `is_active = 0` in database
- Key immediately invalid
- No need to delete (audit trail preserved)

**Rotation**:
- Generate new key for same service account
- Deploy new key to CLI config
- Mark old key inactive
- Grace period: Support both keys during rollout (optional)

#### Security Properties

**Confidentiality**:
- ✅ Keys hashed with bcrypt (irreversible)
- ✅ Plaintext only in file storage (not database)
- ✅ File permissions restrict access (600)
- ✅ Keys never logged or displayed after creation

**Integrity**:
- ✅ Bcrypt comparison prevents tampering
- ✅ Key format validation (prefix + length)
- ✅ Database foreign key ensures valid user_id

**Availability**:
- ✅ Key lookup indexed (fast validation)
- ✅ Multiple keys per user (rotation without downtime)
- ✅ Revocation immediate (set inactive flag)

**Auditability**:
- ✅ `created_at` timestamp (when generated)
- ✅ `last_used_at` timestamp (authentication tracking)
- ✅ `description` field (key purpose documentation)
- ✅ Inactive keys retained (audit history)

### Multi-Environment Configuration Requirements

#### Problem Statement

Claude Code CLI must authenticate to different Lupin server instances:
- **Development**: `http://localhost:7999` (local development)
- **Staging**: `https://lupin-staging-xyz789.run.app` (pre-production testing)
- **Production**: `https://lupin-production-abc123.run.app` (live deployment)

Each environment requires:
- Different server URL
- Different API key (separate service accounts per environment)
- Easy switching between environments
- Sensible defaults (localhost for dev)

#### Configuration File: `~/.lupin/config`

**Location**: `~/.lupin/config` (user home directory)

**Format**: INI (matches `lupin-app.ini` convention)

**Structure**:
```ini

[environments]
```

**Required Fields Per Environment**:
- `api_url`: Full URL to Lupin server (with protocol and port)
- `api_key_file`: Absolute path to API key file

**Optional Fields Per Environment**:
- `description`: Human-readable description
- Future: `timeout_seconds`, `retry_count`, `verify_ssl`

**Validation**:
- `api_url` must be valid URL (http:// or https://)
- `api_key_file` must be absolute path
- File at `api_key_file` must exist and be readable
- API key must match format: `ck_live_*` (70+ characters)

#### Configuration Precedence

**Lookup Order** (highest to lowest priority):

1. **Environment Variables** (highest priority)
   - `LUPIN_API_URL`: Override server URL
   - `LUPIN_API_KEY_FILE`: Override key file path
   - `LUPIN_ENV`: Select environment from config file
   - Use case: Temporary overrides, CI/CD, testing

2. **Config File** (`~/.lupin/config`)
   - Persistent user configuration
   - Multiple environment profiles
   - Use case: Normal development/production usage

3. **Hardcoded Default** (lowest priority)
   - `api_url`: `http://localhost:7999`
   - `api_key_file`: `{project_root}/src/conf/keys/notification-api-claude-code-dev`
   - Use case: First-time setup, local development

**Examples**:

```bash

# → Uses [local] from ~/.lupin/config

# Scenario 2: Switch environment via LUPIN_ENV

```

## Phase 2.5.2: Design & Technical Planning

### Database Schema Design

#### Table: `api_keys`

**Purpose**: Store API key hashes for service account authentication

**Schema**:
```sql
CREATE TABLE IF NOT EXISTS api_keys (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    key_hash TEXT NOT NULL,
    description TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    last_used_at TIMESTAMP,
    is_active BOOLEAN DEFAULT 1,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);
```

**Indexes** (for performance):
```sql
-- Fast lookup by key hash (authentication path)
CREATE INDEX IF NOT EXISTS idx_api_keys_key_hash ON api_keys(key_hash);

-- Fast lookup by user (list keys for user)
CREATE INDEX IF NOT EXISTS idx_api_keys_user_id ON api_keys(user_id);

-- Filter active keys (revocation check)
CREATE INDEX IF NOT EXISTS idx_api_keys_is_active ON api_keys(is_active);

-- Composite index for active key lookup
CREATE INDEX IF NOT EXISTS idx_api_keys_user_active ON api_keys(user_id, is_active);
```

**Field Specifications**:

| Field | Type | Constraints | Purpose |
|-------|------|-------------|---------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | Unique identifier |
| `user_id` | INTEGER | NOT NULL, FOREIGN KEY | Links to service account user |
| `key_hash` | TEXT | NOT NULL | Bcrypt hash of API key |
| `description` | TEXT | NULL | Human-readable key purpose |
| `created_at` | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP | Key creation timestamp |
| `last_used_at` | TIMESTAMP | NULL | Last successful authentication |
| `is_active` | BOOLEAN | DEFAULT 1 | Revocation flag (1=active, 0=revoked) |

**Field Details**:

**`user_id`**:
- Links to `users.id` (existing users table)
- ON DELETE CASCADE: Deleting user deletes all keys
- Service account user has role = 'service_account'
- One user can have multiple API keys (rotation support)

**`key_hash`**:
- Bcrypt hash of full API key (including `ck_live_` prefix)
- Cost factor: 12 (default)
- Never store plaintext keys in database
- Hash format: `$2b$12${salt}{hash}` (60 characters)

**`description`**:
- Optional human-readable description
- Examples: "Production Claude Code CLI", "Staging environment", "CI/CD pipeline"
- Helps identify keys during audits
- Max length: 255 characters (enforced at application layer)

**`created_at`**:
- Automatically set on INSERT
- Immutable (never updated)
- Used for audit trail and key age reporting

**`last_used_at`**:
- Updated on every successful authentication
- NULL initially (not used yet)
- Used for identifying stale keys (security audit)
- Updated via: `UPDATE api_keys SET last_used_at = CURRENT_TIMESTAMP WHERE id = ?`

**`is_active`**:
- Boolean flag (SQLite stores as INTEGER: 0 or 1)
- 1 = Active (default)
- 0 = Revoked (authentication fails)
- Soft delete pattern (preserves audit trail)
- Revocation is immediate (no caching)

**Relationships**:

```
users (1) ──→ (N) api_keys
  ↑
  │ user_id FK
  │
role = 'service_account'
email = 'claude.code@deepily.ai'
```

**Example Data**:


### API Key Generation Design

#### Algorithm: `secrets.token_urlsafe(48)`

**Why This Algorithm**:
- ✅ Cryptographically secure (uses `os.urandom()`)
- ✅ URL-safe base64 encoding (no special characters)
- ✅ Standard library (no external dependencies)
- ✅ Generates 64 characters from 48 bytes input

**Generation Process**:

```python
import secrets

def generate_api_key() -> str:
    """
    Generate a secure API key with format: ck_live_{random}

    Returns:
        API key string (70 characters)
        Example: ck_live_9x7Kp3mN8vQ2jR5wT6yL4hC1aZ0dE3fG8bS5nU2mV7xP9kJ4qW6rT8yH3cA1zL0
    """
    random_part = secrets.token_urlsafe(48)  # 64 chars base64url
    api_key = f"ck_live_{random_part}"
    return api_key
```

**Key Format Breakdown**:
- **Prefix**: `ck_live_` (6 characters)
- **Random**: 64 characters (base64url: A-Z, a-z, 0-9, -, _)
- **Total**: 70 characters minimum
- **Entropy**: 288 bits (48 bytes × 8 bits/byte)

**Format Validation**:

```python
import re

def validate_api_key_format(key: str) -> bool:
    """
    Validate API key format.

    Requires:
        - key is a string

    Ensures:
        - returns True if format valid
        - returns False if format invalid

    Format: ck_live_{64+ base64url chars}
    """
    pattern = r'^ck_live_[A-Za-z0-9_-]{64,}$'
    return re.match(pattern, key) is not None
```

**Hashing Process**:

```python
import bcrypt

def hash_api_key(api_key: str) -> str:
    """
    Hash API key with bcrypt (cost factor 12).

    Requires:
        - api_key is a valid API key string

    Ensures:
        - returns bcrypt hash (60 chars)
        - hash can be verified with bcrypt.checkpw()
    """
    key_bytes = api_key.encode('utf-8')
    salt = bcrypt.gensalt(rounds=12)  # Cost factor 12
    key_hash = bcrypt.hashpw(key_bytes, salt)
    return key_hash.decode('utf-8')  # Store as string
```

**Verification Process**:

```python
def verify_api_key(api_key: str, key_hash: str) -> bool:
    """
    Verify API key against stored hash.

    Requires:
        - api_key is plaintext key from client
        - key_hash is bcrypt hash from database

    Ensures:
        - returns True if key matches hash
        - returns False if key doesn't match
        - timing-safe comparison (bcrypt built-in)
    """
    key_bytes = api_key.encode('utf-8')
    hash_bytes = key_hash.encode('utf-8')
    return bcrypt.checkpw(key_bytes, hash_bytes)
```

**Security Properties**:

**Entropy**: 288 bits (extremely high)
- Brute force infeasible (2^288 possibilities)
- Birthday attack infeasible
- Collision probability negligible

**Uniqueness**: Virtually guaranteed
- Probability of collision: 2^-288 (astronomically low)
- No database uniqueness constraint needed (wasteful)

**Timing Safety**: Bcrypt comparison
- `bcrypt.checkpw()` is timing-safe
- Prevents timing attack on key verification
- No early-exit on mismatch

**Cost Factor**: 12 (balanced)
- Fast enough for API usage (~100-200ms)
- Slow enough to mitigate brute force
- Can increase if needed (backward compatible)

### Config Loading Mechanism Design

#### Module: `src/cosa/utils/config_loader.py`

**Purpose**: Load Lupin CLI configuration with precedence: env vars > config file > defaults

**Core Function**:

```python
from pathlib import Path
from typing import Dict, Optional
import os
from configparser import ConfigParser

def get_api_config(env: Optional[str] = None) -> Dict[str, str]:
    """
    Load Lupin API configuration with precedence order.

    Requires:
        - env is optional environment name (overrides default)

    Ensures:
        - returns dict with 'api_url' and 'api_key_file' keys
        - precedence: env vars > config file > hardcoded defaults
        - raises ValueError if config invalid or missing

    Precedence Order:
        1. Environment variables (LUPIN_API_URL, LUPIN_API_KEY_FILE)
        2. Config file (~/.lupin/config) with LUPIN_ENV or 'env' parameter
        3. Hardcoded defaults (localhost:7999, dev key)

    Args:
        env: Optional environment name to use (overrides LUPIN_ENV and config default)

    Returns:
        dict: {'api_url': str, 'api_key_file': str}

    Raises:
        ValueError: If config invalid (malformed URL, missing key file, etc.)
    """
    # Priority 1: Check environment variables (highest)
    api_url = os.getenv('LUPIN_API_URL')
    api_key_file = os.getenv('LUPIN_API_KEY_FILE')

    if api_url and api_key_file:
        # Both env vars set - use them
        return {
            'api_url': api_url,
            'api_key_file': api_key_file
        }

    # Priority 2: Check config file
    config_path = Path.home() / '.lupin' / 'config'
    if config_path.exists():
        config = _load_config_file(config_path)

        # Determine which environment to use
        if env:
            # Explicit env parameter (highest)
            env_name = env
        elif os.getenv('LUPIN_ENV'):
            # LUPIN_ENV environment variable
            env_name = os.getenv('LUPIN_ENV')
        else:
            # Default from config file
            env_name = config.get('environments', 'default', fallback='local')

        # Get environment config
        if env_name not in config:
            raise ValueError(f"Environment '{env_name}' not found in {config_path}")

        env_config = config[env_name]
        return {
            'api_url': env_config['api_url'],
            'api_key_file': env_config['api_key_file']
        }

    # Priority 3: Hardcoded defaults (local development)
    import cosa.utils.util as cu
    project_root = cu.get_project_root()

    return {
        'api_url': 'http://localhost:7999',
        'api_key_file': f"{project_root}/src/conf/keys/notification-api-claude-code-dev"
    }
```

**Config File Loader**:

```python
def _load_config_file(config_path: Path) -> ConfigParser:
    """
    Load and parse INI config file.

    Requires:
        - config_path is valid Path to config file

    Ensures:
        - returns ConfigParser with loaded config
        - raises ValueError if file malformed or invalid

    Validates:
        - File is readable
        - INI format is valid
        - Required fields present
    """
    config = ConfigParser()

    try:
        config.read(config_path)
    except Exception as e:
        raise ValueError(f"Failed to read config file {config_path}: {e}")

    # Validate config structure
    if 'environments' not in config:
        raise ValueError(f"Config file missing [environments] section: {config_path}")

    return config
```

**Validation Function**:

```python
def validate_api_config(config: Dict[str, str]) -> None:
    """
    Validate API configuration.

    Requires:
        - config is dict with api_url and api_key_file keys

    Ensures:
        - raises ValueError if config invalid
        - returns None if config valid

    Validates:
        - api_url is valid URL (http:// or https://)
        - api_key_file path exists and is readable
        - api_key file contains valid key format
    """
    import re
    from pathlib import Path

    # Validate URL format
    url = config['api_url']
    if not re.match(r'^https?://.+', url):
        raise ValueError(f"Invalid API URL format: {url}")

    # Validate key file exists
    key_file = Path(config['api_key_file'])
    if not key_file.exists():
        raise ValueError(f"API key file not found: {key_file}")

    if not key_file.is_file():
        raise ValueError(f"API key file is not a file: {key_file}")

    # Validate key file readable
    try:
        with open(key_file, 'r') as f:
            api_key = f.read().strip()
    except Exception as e:
        raise ValueError(f"Cannot read API key file {key_file}: {e}")

    # Validate key format (ck_live_*)
    if not re.match(r'^ck_live_[A-Za-z0-9_-]{64,}$', api_key):
        raise ValueError(f"Invalid API key format in {key_file}")
```

### Middleware Architecture Design

#### Module: `src/cosa/rest/middleware/api_key_auth.py`

**Purpose**: FastAPI middleware for API key authentication

**Core Components**:

1. **API Key Validation Function** - Verify key against database
2. **Dependency Function** - FastAPI dependency for route protection
3. **Decorator** (optional) - Simplified route protection

#### API Key Validation Function

```python
from typing import Optional
import bcrypt
from cosa.rest.database import get_database_connection

async def validate_api_key(api_key: str) -> Optional[int]:
    """
    Validate API key and return user_id if valid.

    Requires:
        - api_key is string from X-API-Key header

    Ensures:
        - returns user_id (int) if key valid and active
        - returns None if key invalid or inactive
        - updates last_used_at timestamp on success
        - timing-safe comparison (bcrypt)

    Args:
        api_key: API key from request header

    Returns:
        int: user_id if valid
        None: if invalid or inactive
    """
    # Query all active keys (indexed lookup)
    conn = get_database_connection()
    cursor = conn.execute('''
        SELECT id, user_id, key_hash
        FROM api_keys
        WHERE is_active = 1
    ''')

    rows = cursor.fetchall()

    # Check each key (timing-safe bcrypt comparison)
    for row in rows:
        key_id, user_id, key_hash = row

        if bcrypt.checkpw(api_key.encode('utf-8'), key_hash.encode('utf-8')):
            # Valid key found - update last_used_at
            conn.execute('''
                UPDATE api_keys
                SET last_used_at = CURRENT_TIMESTAMP
                WHERE id = ?
            ''', (key_id,))
            conn.commit()

            return user_id

    # No matching key found
    return None
```

#### FastAPI Dependency Function

```python
from fastapi import Header, HTTPException, status
from typing import Annotated

async def require_api_key(
    x_api_key: Annotated[str | None, Header()] = None
) -> int:
    """
    FastAPI dependency for API key authentication.

    Requires:
        - x_api_key from X-API-Key header

    Ensures:
        - returns user_id if authentication successful
        - raises HTTPException 401 if authentication fails

    Usage:
        @app.post("/api/notify")
        async def notify(user_id: Annotated[int, Depends(require_api_key)]):
            # user_id is authenticated user
            ...

    Raises:
        HTTPException: 401 if key missing, invalid, or inactive
    """
    if not x_api_key:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Missing API key. Include X-API-Key header.",
            headers={"WWW-Authenticate": "API-Key"}
        )

    # Validate key format before database lookup
    import re
    if not re.match(r'^ck_live_[A-Za-z0-9_-]{64,}$', x_api_key):
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Invalid API key format",
            headers={"WWW-Authenticate": "API-Key"}
        )

    # Validate against database
    user_id = await validate_api_key(x_api_key)

    if user_id is None:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Invalid or inactive API key",
            headers={"WWW-Authenticate": "API-Key"}
        )

    return user_id
```

### Endpoint Updates Plan

#### Endpoints Requiring API Key Authentication

**Notification Endpoints** (Phase 2 async/sync):

1. **`POST /api/notify`** - Async (fire-and-forget) notifications
   - Current: No authentication
   - Update: Add `Depends(require_api_key)`
   - Impact: All CLI async notifications

2. **`GET /api/notify/sync`** - SSE sync notifications (response-required)
   - Current: No authentication
   - Update: Add `Depends(require_api_key)`
   - Impact: All CLI sync notifications

**Endpoints Explicitly Excluded** (keep existing auth):

1. **WebSocket** (`/ws/queue/{session_id}`, `/ws/audio/{session_id}`)
   - Keep JWT authentication (existing)
   - Reason: User-facing connections, not service-to-service

2. **User Auth Endpoints** (`/auth/login`, `/auth/register`, etc.)
   - Keep existing authentication logic
   - Reason: Different auth flow (JWT-based)

3. **Admin Endpoints** (user management, etc.)
   - Keep JWT authentication with admin role check
   - Reason: Not for service accounts
