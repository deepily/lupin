# Everyday Calculator Agent — Implementation Plan

**Project**: [LUPIN] Everyday Calculator with Voice I/O
**Pattern**: Pattern 3 (Feature Development) — well-scoped, single routing command, follows proven CRUD pattern
**Timeline**: ~1-2 weeks (3 capability modules + shared framework)
**Status**: IN PROGRESS (Phases 1-4 COMPLETE, Phase 5 partial, Phase 6 partial — Testing Ladder)

---

## Context

The Lupin voice assistant currently handles math via the `MathAgent`, which generates Python code through an LLM for every question. This works but introduces hallucination risk and latency for calculations that are purely deterministic (unit conversions, price comparisons, mortgage math).

The CRUD-for-DataFrames system demonstrates a better pattern for structured operations: **LLM extracts intent into a typed XML model, then pure Python functions execute the operation**. No code generation, no sandbox — just dispatch.

This plan applies the CRUD intent-extraction pattern to build an **Everyday Calculator** agent that handles three capability domains via a single routing command:

1. **Unit Conversions** — km<>miles, inches<>mm, F<>C, liters<>gallons, etc.
2. **Unit Price Comparison** — normalize dissimilar product sizes/prices to a common unit (cost-per-ounce, cost-per-liter) and determine which is cheaper
3. **Mortgage Calculator** — monthly payment, total interest, amortization basics

All three are deterministic arithmetic — zero LLM involvement in the calculation itself.

---

## Architecture: CRUD-Style Intent Extraction + Dispatch

```
Voice: "How many miles is 10 kilometers?"
       |
[Existing Router] -> "agent router go to calculator"
       |
[CalculatorAgent.run_prompt()]
  +-- LLM extracts intent -> CalcIntent XML model
  +-- Fields: operation=convert, from_unit=km, to_unit=miles, value=10
       |
[CalculatorAgent.run_code()]
  +-- dispatcher.dispatch( intent ) -> calc_operations.convert(...)
       |
  Pure Python: 10 * 1.60934 = 16.0934
       |
[CalculatorAgent.run_formatter()]
  +-- format_result_for_voice() -> "10 kilometers is about 16.09 miles."
```

### Why This Pattern (Not Code Generation)

| Concern | MathAgent (code gen) | Calculator (dispatch) |
|---------|---------------------|-----------------------|
| Accuracy | LLM may hallucinate conversion factors | Hardcoded factors, 100% correct |
| Speed | ~2-5s (LLM + sandbox) | ~0.5s (LLM intent only, no sandbox) |
| Extensibility | Every query re-derives the math | Add a conversion factor to a dict |
| Testability | Must test generated code | Unit test pure functions directly |
| Fallback | No fallback | MathAgent fallback for exotic queries |

## Detailed Design

### 1. CalcIntent XML Model (`xml_models.py`)

Follows the `CRUDIntent` pattern exactly:

```xml
<calc_intent>
    <operation>convert</operation>
    <value>10</value>
    <value_2></value_2>
    <from_unit>kilometers</from_unit>
    <to_unit>miles</to_unit>
    <items></items>
    <principal></principal>
    <annual_rate></annual_rate>
    <term_years></term_years>
    <down_payment></down_payment>
    <confidence>0.95</confidence>
    <raw_query>how many miles is 10 kilometers</raw_query>
</calc_intent>
```

**Operations enum** (3 domains):
- `convert` — unit conversion
- `compare_prices` — unit price normalization + comparison
- `mortgage` — mortgage calculation

**Field usage by operation**:

| Field | convert | compare_prices | mortgage |
|-------|---------|----------------|----------|
| `value` | Amount to convert | -- | -- |
| `from_unit` | Source unit | -- | -- |
| `to_unit` | Target unit | -- | -- |
| `items` | -- | JSON array of `{name, price, quantity, unit}` | -- |
| `principal` | -- | -- | Loan amount |
| `annual_rate` | -- | -- | Interest rate (%) |
| `term_years` | -- | -- | Loan term |
| `down_payment` | -- | -- | Down payment amount |

### 2. Conversion Tables (`conversion_tables.py`)

Dict-based, no external libraries. Hub-and-spoke model where each unit category normalizes to a base unit:

```python
# Length: base unit = meters
LENGTH = {
    "meter": 1.0, "km": 1000.0, "mile": 1609.344,
    "foot": 0.3048, "inch": 0.0254, "yard": 0.9144, "cm": 0.01, "mm": 0.001,
}

# Weight/Mass: base unit = grams
MASS = {
    "gram": 1.0, "kg": 1000.0, "pound": 453.592, "ounce": 28.3495,
    "mg": 0.001, "ton": 907185.0,
}

# Volume: base unit = liters
VOLUME = {
    "liter": 1.0, "gallon": 3.78541, "quart": 0.946353,
    "pint": 0.473176, "cup": 0.236588, "fl_oz": 0.0295735, "ml": 0.001,
}

# Temperature: special (not ratio-based)
# Handled via explicit formulas in calc_operations.py
```

**Unit alias resolution**: `"kilometers" -> "km"`, `"miles" -> "mile"`, `"ounces" -> "ounce"`, etc.
Stored as a flat `ALIASES` dict in the same file.

### 3. Calculator Operations (`calc_operations.py`)

Three pure functions, no LLM, no I/O:

**`convert( value, from_unit, to_unit )`**
- Resolve aliases -> find category -> normalize to base -> convert to target
- Temperature handled specially (F<>C<>K formulas)
- Returns `{ "status": "ok", "result": 16.09, "from_value": 10, "from_unit": "km", "to_unit": "miles" }`

**`compare_prices( items )`**
- Input: list of `{ name, price, quantity, unit }` dicts
- Normalize all to common base unit (e.g., cost per ounce for weight, cost per fl_oz for volume)
- Sort by unit price ascending
- Returns `{ "status": "ok", "items": [...sorted with unit_price...], "cheapest": "Brand A", "common_unit": "ounce" }`

**`mortgage( principal, annual_rate, term_years, down_payment=0 )`**
- Standard amortization formula: `M = P[r(1+r)^n] / [(1+r)^n - 1]`
- Returns `{ "status": "ok", "monthly_payment": 1264.14, "total_paid": 455090.40, "total_interest": 155090.40, "loan_amount": 300000 }`

### 4. Dispatcher (`dispatcher.py`)

Mirrors `crud_for_dataframes/dispatcher.py`:

```python
def dispatch( intent, debug=False ):
    op = intent.operation.strip().lower()
    if op == "convert":
        return calc_operations.convert(...)
    elif op == "compare_prices":
        return calc_operations.compare_prices(...)
    elif op == "mortgage":
        return calc_operations.mortgage(...)
    else:
        raise ValueError(f"Unknown calc operation: {op}")

def format_result_for_voice( result, operation ):
    # TTS-friendly formatting per operation type
```

### 5. CalculatorAgent (`agent.py`)

Subclass of `AgentBase`, overrides `run_prompt()`, `run_code()`, `run_formatter()` — same pattern as `CrudForDataFramesAgent`:

- `run_prompt()`: Call LLM, extract `<calc_intent>` XML, parse into `CalcIntent`
- `run_code()`: Call `dispatch( self.calc_intent )` — pure Python, no sandbox
- `run_formatter()`: Call `format_result_for_voice()` — no LLM formatter call

**Fallback**: If intent extraction fails or operation is unrecognized, delegate to `MathAgent` for code-generation fallback (exotic calculations the dispatch tables don't cover).
