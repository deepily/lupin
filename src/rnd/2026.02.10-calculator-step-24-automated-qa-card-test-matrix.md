## Part 1: Add job_id to /api/push Response

### Why

`/api/push` currently returns `{"status": "queued", "result": "Job added to queue. Queue size [3]"}` — no job_id. This forces consumers to match jobs by question text in the done queue, which is fragile. Both code paths already have `job.id_hash` available at return time.

### Changes

**File 1: `src/cosa/rest/todo_fifo_queue.py`** (CoSA submodule)

Change `push_job()` to return a dict instead of a string.

Two return sites to update:

1. **Agent creation path** (line ~722):
   ```python
   # Before:
   return msg
   # After:
   return { "message": msg, "job_id": agent.id_hash if agent else None }
   ```

2. **`_queue_best_snapshot`** (line ~839):
   ```python
   # Before:
   return f'Job added to queue. Queue size [{self.size()}]'
   # After:
   msg = f'Job added to queue. Queue size [{self.size()}]'
   return { "message": msg, "job_id": job.id_hash }
   ```

3. **Rejection path** (line ~378):
   ```python
   # Before:
   return f"Job rejected: {reason}"
   # After:
   return { "message": f"Job rejected: {reason}", "job_id": None }
   ```

4. **Any other return paths** in `push_job` — search for all `return` statements and ensure they all return dicts.

**File 2: `src/cosa/rest/routers/queues.py`** (Lupin repo)

Update the push endpoint response (lines 196-210):
```python
# Before:
result = todo_queue.push_job( question, websocket_id, user_id, user_email )
return { "status": "queued", "websocket_id": websocket_id, "user_id": user_id, "result": result }

# After:
result = todo_queue.push_job( question, websocket_id, user_id, user_email )
return {
    "status"       : "queued",
    "websocket_id" : websocket_id,
    "user_id"      : user_id,
    "job_id"       : result.get( "job_id" ),
    "result"       : result.get( "message", str( result ) )
}
```

**Backward compatibility**: The `result` field still contains the message string. `job_id` is additive — existing consumers are unaffected.

## Part 2: Automated Test Script

### Script: `src/tests/smoke/test_calculator_live_pipeline.py`

Following the existing pattern from `test_expeditor_mock_job_smoke.py`:

1. **Auth**: Login via `/auth/login`, get JWT token
2. **Session**: Get WebSocket session ID via `/api/debug/websocket-state`
3. **Set mode**: `POST /api/mode/current` with `{"mode": "calculator"}`
4. **For each of 6 queries**:
   - Submit via `POST /api/push`
   - Extract `job_id` from response
   - Poll `GET /api/get-queue/done` every 2s, match by `job_id`
   - Validate answer contains expected keywords
5. **Reset mode**: `POST /api/mode/current` with `{"mode": null}` (not DELETE)
6. **Print summary table**

### Test Matrix

| # | Query | Expected Op | Expected Keywords in Answer |
|---|-------|------------|----------------------------|
| 1 | "How many miles is 10 kilometers?" | convert | "6.21" or "6.2" |
| 2 | "Convert 72 Fahrenheit to Celsius" | convert | "22.2" or "22.22" |
| 3 | "500 grams in pounds" | convert | "1.1" or "1.10" |
| 4 | "Compare 12 oz at $3.49 vs 24 oz at $5.99" | compare_prices | "cheaper" or "better" |
| 5 | "Monthly payment on $300k mortgage at 6.5% for 30 years" | mortgage | "1,896" or "1896" |
| 6 | "What's 500 ml in cups?" | convert | "2.1" or "2.11" |

### Polling Pattern

```python
def _submit_and_wait( question, headers, ws_id, timeout=60 ):
    resp = requests.post( f"{BASE_URL}/api/push",
        json={ "question": question, "websocket_id": ws_id },
        headers={ **headers, "X-Session-ID": ws_id },
        timeout=30
    )
    job_id = resp.json().get( "job_id" )

    # Poll done queue by job_id
    elapsed = 0
    while elapsed < timeout:
        done = requests.get( f"{BASE_URL}/api/get-queue/done", headers=headers, timeout=30 )
        for job in done.json().get( "done_jobs_metadata", [] ):
            if job.get( "job_id" ) == job_id:
                return job
        time.sleep( 2 )
        elapsed += 2
    return None
```
