## 5. Open questions / risks

- **Service user**: unit runs as the enabling user (`admin_rickruiz_altostrat_com`). It must (a) be in `docker`
  (Phase 1.2), and (b) read the UID-1001-owned checkout + write `io/` (mementos, `arbiter.log`). If `io/` isn't
  group/world-writable by that user, the arbiter's writes fail — verify in Phase 1.4; may need a group grant on `io/`.
- **`systemd --user` over IAP `--command`**: non-interactive SSH may lack a user D-Bus session; `systemctl --user`
  needs the user manager (linger provides it). Phase 2 (Rick, interactive or post-linger) is the reliable path.
- **usermod is reversible** (`gpasswd -d`), non-destructive. Re-login required before the group takes effect.
