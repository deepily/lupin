# Lupin/CoSA Skills Encyclopedia — Master Plan

**Created**: 2026-03-05
**Status**: Draft — awaiting review and priority feedback
**Purpose**: Eliminate Claude Code pattern reinvention by encoding canonical implementations as auto-activating skills

---

## The Problem

Claude Code repeatedly reinvents patterns that already exist in this codebase:

- Creates ad-hoc configuration management instead of using `ConfigurationManager`
- Builds custom XML parsing instead of using `BaseXMLModel` with proper None coercion
- Reinvents notification authentication flows instead of following the documented token dance
- Creates new queue job types without following the `QueueableJob` protocol
- Constructs fragile `Path(__file__).parent.parent` chains instead of `cu.get_project_root()`

Each reinvention wastes time on backtracking corrections and risks introducing subtle bugs that the canonical patterns already handle.

## The Solution

Two deliverables:

1. **Documentation Catalogue** — A persistent index of all ~200+ documentation files across Lupin + CoSA, organized by category with a quick-reference table mapping common tasks to their documentation
2. **10-11 New Skills** — Claude Code skills that auto-activate when relevant work begins, providing canonical patterns instead of letting Claude reinvent them

Combined with the 5 existing skills, this brings the total to **15-16 skills** covering all major Lupin/CoSA development patterns.

#### Skill 1: `configuration-manager`

| Aspect | Detail |

| | `src/conf/lupin-app.ini`, `src/conf/lupin-app-splainer.ini` |

**Key patterns to encode**:
- Singleton instantiation: `ConfigurationManager( env_var_name="LUPIN_CONFIG_MGR_CLI_ARGS" )`
- The `get()` API with all 7 return types: `boolean`, `int`, `float`, `string`, `list-string`, `json`, `dict`
- MANDATORY: Every new config key requires a matching splainer entry
- Config block inheritance chains (default -> Baseline -> Development/Production)
- Testing: `_reset_singleton=True` atomic reset
- Anti-patterns: zero-argument constructor, conflicting init parameters

## Key Design Decisions

| Decision | Choice | Why |
|----------|--------|-----|
| **Skill location** | Global (`~/.claude/skills/`) | Consistency with existing 5 skills; works from both Lupin and CoSA directories |
| **Catalogue location** | `src/rnd/` standalone `.md` | Too large for a skill (~1000+ lines); serves human reference purpose |
| **Granularity** | One skill per conceptual domain | Groups related patterns (e.g., both agent hierarchies in `agent-creation`) |
| **Cross-cutting concerns** | "Related Skills" links | Each consuming skill links to `configuration-manager` rather than duplicating it |
| **CLAUDE.md extraction** | Generally no | Already loaded at session start; only `nested-git-repos` warrants extraction for commit-time safety |
| **Pace** | 2-3 skills/session | Quality over speed; each requires 500-3000 lines of source reading |
