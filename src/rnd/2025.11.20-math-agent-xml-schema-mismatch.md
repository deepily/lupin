# Math Agent XML Schema Mismatch Investigation

**Date**: 2025-11-20
**Status**: In Progress - Requires Further Investigation
**Context**: Testing "What's 2+2?" query after pydantic_ai API migration

## Executive Summary

After successfully fixing pydantic_ai ModelSettings API compatibility issues, the "What's 2+2?" query now progresses through the agent pipeline but fails at the XML parsing stage. The system shows a **schema mismatch** where the formatter's simple `<rephrased-answer>` XML is being validated against the code generation stage's complex `CodeBrainstormResponse` schema.

The query now reaches the math agent pipeline but fails with XML validation errors and reports: "There was an error executing the code, so I couldn't calculate 2+2."

## The Two-Stage XML Pipeline

### Stage 1: Code Generation (CodeBrainstormResponse)
**Location**: `src/cosa/agents/math_agent.py` - `run_prompt()` method
**Schema**: `src/cosa/agents/io_models/xml_models.py:1181-1572`

**Expected XML Structure**:
```xml
<response>
    <thoughts>Your thoughts</thoughts>
    <brainstorm>
        <idea1>Your first idea</idea1>
        <idea2>Your second idea</idea2>
        <idea3>Your third idea</idea3>
    </brainstorm>
    <evaluation>Your evaluation</evaluation>
    <code>
        <line>All imports here</line>
        <line></line>
        <line>def your_function_name_here( optional_arguments ):</line>
        <line>    ...</line>
        <line>    return solution</line>
    </code>
    <returns>Object type of the variable `solution`</returns>
    <example>solution = your_function_name_here( optional_arguments )</example>
    <explanation>Explanation of how the code works</explanation>
</response>
```

**Required Fields**:
- `thoughts` (str)
- `brainstorm` (nested object with idea1, idea2, idea3)
- `evaluation` (str)
- `code` (list of strings)
- `returns` (str)
- `example` (str)
- `explanation` (str)

**Prompt Template**: `src/conf/prompts/agents/math.txt`

### Stage 2: Formatting (RephraseResponse)
**Location**: `src/cosa/agents/raw_output_formatter.py` - `run_formatter()` method
**Schema**: Simple rephrasing format

**Expected XML Structure**:
```xml
<response>
    <rephrased-answer>The user-friendly rephrased answer</rephrased-answer>
</response>
```

**Purpose**: Takes raw code execution output and converts it to conversational format

**Prompt Template**: `src/conf/prompts/formatters/math.txt`

**Configuration**:
- `formatter_model_name_for_math = Deepily/kaitchup/Phi-4-AutoRound-GPTQ-4bit`
- `formatter_prompt_for_math_terse = True` (when True, skips formatter entirely)

## Observed Error

### Logs Show:
```
Created structured_v2 strategy for agent: agent router go to math
Parsing XML response using structured_v2 strategy
  Pydantic parsing failed: Data validation failed: 7 validation errors for CodeBrainstormResponse
thoughts
  Field required [type=missing, input_value={'rephrased-answer': "The....", '#text': '\n    \n'}, input_type=dict]
  ...
[6 more similar errors]

XML: <response>
    <rephrased-answer>There was an error executing the code, so I couldn't calculate 2+2.</rephrased-answer>
</response>
```

### Problem Analysis:
1. **XML Structure**: The actual XML is the formatter's `<rephrased-answer>` format (CORRECT for Stage 2)
2. **Schema Applied**: pydantic validation is using `CodeBrainstormResponse` (WRONG - should be Stage 1 schema)
3. **Result**: 7 validation errors because the simple XML doesn't have the complex fields

### Root Cause Hypotheses:

**Hypothesis 1: Schema Inheritance Issue**
- The formatter may be inheriting the wrong XML schema from the parent agent
- The "structured_v2 strategy" might not distinguish between generation vs formatting stages

**Hypothesis 2: Pipeline Stage Confusion**
- pydantic_ai might be getting called at the wrong point in the pipeline
- The formatter's output is being re-parsed with the code generation schema

**Hypothesis 3: Configuration Routing Error**
- The routing command "agent router go to math" maps to `CodeBrainstormResponse`
- This mapping might be incorrectly applied to the formatter stage

**Hypothesis 4: Code Execution Failure Cascading**
- Code generation succeeded but execution failed (return_code != 0)
- The error was passed to the formatter
- The formatter correctly generated `<rephrased-answer>` error message
- But something is trying to validate this with the wrong schema

## Code Flow Analysis

### Normal Success Path:
```
User Query: "What's 2+2?"
    ↓
AgentRouter → identifies as math query
    ↓
MathAgent.run_prompt() → generates code using CodeBrainstormResponse XML
    ↓ (parses XML into solution_dict)
MathAgent.run_code() → executes generated Python code
    ↓ (code_response_dict with return_code, output)
MathAgent.run_formatter() → rephrases output conversationally
    ↓ (uses RephraseResponse XML)
Return: answer_conversational to user
```

### Suspected Failure Point:
The logs suggest failure at the **formatter stage**, where:
1. Code execution failed (error in code_response_dict["output"])
2. Formatter LLM generated error message in correct `<rephrased-answer>` format
3. **Something is re-parsing this XML with CodeBrainstormResponse schema**
