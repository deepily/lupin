# Plan: Notification Proxy Integration Tests for CRUD, Calculator, and Expediter

## Context

The notification proxy agent auto-responds to notifications from agentic activities so the user doesn't have to interact manually during testing. We need an integration test that exercises the proxy with three different agent types:

1. **Calculator** — needs `similarity_confirmation_enabled=false` to avoid "Is that the same as X?" prompts
2. **CRUD** — needs proxy to auto-confirm destructive operations (delete/update)
3. **Runtime Argument Expediter** — needs proxy to auto-answer missing arg questions for Deep Research, Podcast Generator, Research-to-Podcast

The existing test infrastructure (`LivePipelineTestBase` → `InteractiveSmokeTest`) already supports `--auto-proxy`, `--no-confirm`, mode switching, and submit-and-poll patterns. The integration test builds on this.

## Files to Create

### 1. `src/tests/smoke/test_proxy_integration.py` (new)

Master integration test combining all three agent types. Extends `InteractiveSmokeTest`.

**12 scenarios across 3 groups:**

| # | ID | Group | Query | Proxy Needed |
|---|-----|-------|-------|-------------|
| 0 | CALC_CONVERT_KM | calculator | "How many miles is 10 kilometers?" | No |
| 1 | CALC_MORTGAGE | calculator | "Monthly payment on $300k mortgage at 6.5% for 30 years" | No |
| 2 | CALC_COMPARE | calculator | "Compare 12 oz at $3.49 vs 24 oz at $5.99" | No |
| 3 | CRUD_ADD_TODO | crud | "add buy milk to my grocery list" | No |
| 4 | CRUD_ADD_TODO_2 | crud | "add buy bread to my grocery list" | No |
| 5 | CRUD_QUERY | crud | "what's on my grocery list?" | No |
| 6 | CRUD_DELETE | crud | "delete buy bread from my grocery list" | Yes (YES_NO confirm) |
| 7 | CRUD_ADD_CAL | crud | "add dentist appointment on March 15 at 2pm" | No |
| 8 | EXP_DR_HAPPY | expediter | "do deep research on quantum computing" | Yes (confirmation) |
| 9 | EXP_DR_MISSING | expediter | "do some deep research" | Yes (missing args + confirm) |
| 10 | EXP_PG_MISSING | expediter | "make me a podcast" | Yes (missing args + confirm) |
| 11 | EXP_RTP_HAPPY | expediter | "research quantum gravity and turn it into a podcast" | Yes (confirmation) |

**Key design decisions:**
- `--group` flag: `calculator`, `crud`, `expediter`, or `all` (default)
- Calculator scenarios use `/api/push` with `get_mode_for_scenario()` returning `"calculator"`
- CRUD scenarios use `/api/push` with `get_mode_for_scenario()` returning `"todo"` or `"calendar"`
- Expediter scenarios override `_submit_and_wait()` to use `/api/mock-job/submit` (synchronous, no polling)
- `pre_run_hook()` starts proxy AND disables similarity confirmation
- `post_run_hook()` stops proxy (similarity confirmation restored in `finally` block by base class)

**Credential pattern:** Override `_get_credentials()` to match the expeditor smoke test pattern (lines 266-289 of `test_expeditor_mock_job_smoke.py`):
- When `LUPIN_INTERACTIVE_TESTS=true`: use `LUPIN_TEST_INTERACTIVE_MOCK_JOBS_EMAIL` / `PASSWORD` (i.e., `interactive.job.tester@lupin.deepily.ai`)
- Fallback: `LUPIN_TEST_EMAIL` / `PASSWORD`
- This account is used for ALL scenarios (calculator, CRUD, and expediter), ensuring consistent user context

**Pattern to follow:** `test_crud_live_pipeline.py` (213 lines) and `test_expeditor_mock_job_smoke.py` (703 lines) — the integration test combines both submission patterns.
