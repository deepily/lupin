`planning-is-prompting/workflow/scripts/orphaned_head_sweep.py` — María 🌸, 2026-09-05. It

not exist, and exited 2. Worth knowing before anyone wires it into anything.

**No new script is needed.** This document is only about whether it should *fire on a schedule*.

## 2. Why it never fires today — TWO INDEPENDENT CAUSES, either sufficient alone

Both measured 2026-09-06. Neither is a bug in the script.

### Cause 1 — it is tied to a ritual, not to a scheduler

It is wired into `session-end.md` §8.2 as a real bash block with documented exit codes, and pinned
by `test_the_ritual_invokes_the_orphaned_sweep.py`. **Nothing schedules it.**

```
crontab           10 live entries · 5 of them context-pressure-tick · ZERO name the sweep
systemd --user    0 timers
```

**Positive control**: the same grep returns **10** for `context-pressure`, so the instrument
demonstrably reaches. The zero is the tree's, not the search's.

⇒ It fires only when a human runs session-end, and only in a repo where it resolves — which is
Cause 2.

### Cause 2 — in lupin it resolves to a path that does not exist

§8.2 resolves the script **repo-relative**, deliberately, so the ritual works in any repo that
installs the workflow:

```bash
sweep="$repo_root/workflow/scripts/orphaned_head_sweep.py"
if [ -f "$sweep" ]; then "$py" "$sweep" ...; else echo "skipped — no sweep installed"; fi
```

**lupin has no `workflow/` directory.** Its workflow content lives at `src/workflow/`. Measured
across three roots:

| repo_root | resolves? |
|---|---|
| `lupin` | **ABSENT → SKIP branch** |
| `lupin-wt-cc-author-cheech-1` | **ABSENT → SKIP branch** |
| `planning-is-prompting` | RESOLVES → runs |

⇒ The sweep runs **only when session-end is run inside planning-is-prompting** — not where the
fleet works, and not where the 70 branches are.

🔴 **And the skip is quiet.** It prints `orphaned-sweep: skipped — no sweep installed in lupin` and
the ritual moves on, exit 0. That is CLAUDE.md § *A CLEAN EXIT IS NOT EVIDENCE THE WORK HAPPENED*:
the skip line and a genuinely clean sweep are indistinguishable to anyone not hunting for the
difference.

⚠️ **The two causes are independent and either alone is sufficient.** Fixing the path without
adding a timer leaves it firing only at session-end; adding a timer without fixing the path leaves
it firing into the skip branch. **A ruling that closes only one closes nothing.**

> the column. It is a **LIST a human reads once at session-end**, and it is ordered so the top of it

She **built the alert version, measured it, and killed it** — and the sharpener failed instructively
too: filtering on "the owning seat is alive" only cut 23 → 13, because it keyed on the PERSONA NAME
and **a persona outlives its seats**.

⇒ So "deliver, not print" is **already true of (i)** — which she allows to be loud, and which is
**0 today** — and **deliberately false of (ii)**. A timer that pushes (ii) reverses a ruling made
with numbers. A timer that pushes only (i) does not.

## 4. The options

| | what fires | volume | reverses a ruling? |
|---|---|---|---|
| **A** | **fix the path only** — no timer. The sweep runs at every lupin session-end | 70-line list, read by the seat ending its session | **no** — this is the surface María designed for |
| **B** | **A, plus a timer that delivers category (i) only** | 0 today; loud when non-zero, which is the point — (i) is *imminent loss* | **no** — she allows (i) to be loud |
| **C** | A, plus a timer that delivers **(ii)** as well | ~70 items | 🔴 **yes** — this is the wall she measured and refused |

**My recommendation: B.** It closes both causes, and it delivers exactly the category whose
false-positive cost is zero and whose failure mode is permanent loss. (ii) stays a list on the
surface it was designed for.

read the resolution rule and measured which roots satisfy it; I did not ask why it was written that
way, and that is the workflow repo's owner's answer, not mine. Option A's "fix" may therefore mean
*install the workflow scripts into lupin* rather than *change the path in session-end.md*, and those
are different changes with different blast radii.

⚠️ **And one number is not mine**: the 70 is a census at one moment on one tree. Re-derive it before
quoting — it moves as branches land.

## 6. The two branch counts RECONCILE — closing design §2.2

Cheech's design left this open: *"I have not explained the difference and I am not claiming
he was wrong."* It is now explained, and **both measurements were correct**.

The mistake available here is comparing counts taken at different moments. Computed instead
as **one snapshot, both predicates** — main checkout, sha `cf579b4c`, 2026-09-06 13:20:14 EDT,
target `wip-v0.2.1-2026.08.29-cjflow-v2-followup`:

| | predicate | count |
|---|---|---|
| **A** | every branch ahead of the working line | **74** |
| **B** | A, minus refs a **live tmux seat** has checked out | **70** |
| | difference | **4** |

**B is `orphaned_head_sweep`'s predicate, and 70 is exactly what the sweep printed when run
by hand 40 minutes earlier.** The two instruments agree completely; they answer two questions.

The four dropped are all held by live seats: `krishna-s3-accordion-css`,
`krishna-seven-onto-live`, `wt-john-accordion-carbon-copy-plan`, `wt-rachel-land-slot-audit`.

⚠️ **The held set is FIVE, not four — do not compute `74 − 5`.** `wt-tiffany-epic-css-linkage`
is held by a live seat but is `ahead=0`, so it never entered A. The subtraction is over the
**intersection** of held-and-ahead, not over held. Checked rather than assumed: `74 − 5 = 69`
would have read as a one-off discrepancy and sent the next reader hunting for a defect.

**And 72 → 74 is drift, not error.** Cheech measured at `1c9a7ea6` at 12:55; the line moved
between (John's accordion merge among others). The population grows as seats commit and
shrinks as work lands. ⇒ **Re-derive, never quote — including the 74 above.**

### 6.1 Which predicate is right depends on the question

| predicate | the question it answers |
|---|---|
| **A** (Cheech) | *what work exists that the line does not have* — the **backlog**. Wider. |
| **B** (the sweep) | *…and nobody is sitting behind it right now* — the **unowned subset**. |

A is the right net for the standing-backlog question, because **a registered-but-dead worktree
still holds a branch** and `_checked_out_refs` only sees paths belonging to a live tmux session.
B is the right net for a session-end list, because naming a branch someone is actively working
in is noise a reader learns to skip.

⇒ **Neither is a correction of the other.** A document that had simply replaced one number with
the other would have made the next reader think they had found a new defect — which is this
repo's own rule that two counts get *reconciled*, not adjudicated.
