# Slices 4 + 5: Open-Ended and Open-Ended Batch Prediction (LLM Synthesis)

**Status**: IN-PROGRESS
**Date**: 2026-03-02
**Context**: Completing the PredictionEngine with open-ended response types

---

## Overview

Two-tier prediction strategy for free-text responses:

1. **Tier 1 — Exact match retrieval** (`STRATEGY_CBR_RETRIEVAL`): If the top similar case's question exactly matches (normalized), return that answer directly
2. **Tier 2 — LLM synthesis** (`STRATEGY_LLM_SYNTHESIS`): Retrieve top K similar cases, have Phi-4 14B synthesize a best-guess answer from patterns

## Key Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Prediction strategy | Two-tier (retrieval + LLM synthesis) | Free-text can't be voted on like binary/MC |
| LLM model | Phi-4 14B (local) | Existing infrastructure, ~500-2000ms acceptable |
| XML model pattern | BaseXMLModel subclass | Matches CalcIntent, ExpeditorResponse patterns |
| Accuracy comparison | Embedding cosine similarity | Semantic comparison for free text |
| Batch handling | Same two-tier approach | JSON-formatted compound answers |
