# SWE Team Proxy: Data Origin Tracking + Workload Generator

**Date**: 2026-02-25
**Session**: 268
**Status**: Implemented

## Context

Sessions 258–267 completed Phases 0–3 of preference learning for the SWE Team Proxy (CBR, embeddings, BLR + Thompson Sampling, Conformal + ICRL). Session 265 seeded 50 synthetic proxy decisions into PostgreSQL + LanceDB. These synthetic decisions bootstrap trust proxy training but will eventually be superseded by organic production data. We need: (a) a clean way to distinguish and purge synthetic data, and (b) a workload generator that exercises the full SWE team pipeline to produce higher-quality synthetic data and serve as the foundation for a comprehensive integration test.

### Dry-Run Enhancement

Previously: 3 hardcoded mock decisions (testing, deployment, destructive) with fixed confidence values.

Now: 6 phase-specific questions run through the real `EngineeringClassifier` pipeline:
- Phase 2: "Create a new API endpoint?" → architecture
- Phase 3: "Refactor the existing module?" → architecture
- Phase 4: "Install pydantic-settings?" → deps
- Phase 5: "Run unit tests?" → testing
- Phase 6: "Delete old build artifacts?" → destructive
- Phase 9: "Deploy to staging?" → deployment

Each classified with real confidence scores, tagged `data_origin=synthetic_generated`.

### Capture Harness

```
swe_workload_runner.py
├── login() via LUPIN_TEST_INTERACTIVE_MOCK_JOBS_* env vars
├── submit_task() → POST /api/swe-team/submit
├── poll_done_queue() → GET /api/get-queue/done
├── capture_decisions_for_job() → SQL query on metadata_json->>'job_id'
└── Writes JSONL manifest to io/decision_proxies/ per-run
```
