### ⚠️ **CRITICAL ISSUES (Remaining 15%)**

#### 1. Job ID Mismatch Problem (HIGH PRIORITY)

**Root Cause Analysis:**
```javascript
// Cache Storage (during job completion)
const textHash = await this.generateCacheKey(text);  // SHA-256 of TTS text
await this.jobCompletionCache.store(textHash, ...);

// Cache Retrieval (during replay)  
const cachedJob = await this.jobCompletionCache.get(jobId);  // Uses SolutionSnapshot.id_hash
```

**Impact:**
- Cache lookups fail ~90% of the time
- System falls back to SolutionSnapshot text instead of actual TTS response
- Users hear wrong audio during replay (metadata vs actual spoken response)

**Evidence:**
- Code comments: `"This is the actual TTS response like 'It's 6:27 PM.'" vs fallback`
- Implementation uses different key schemes for store vs retrieve operations

**Resolution Strategy:**
1. **Investigate ID Sources**: Map WebSocket event IDs → SolutionSnapshot IDs → Cache keys
2. **Align Key Strategy**: Choose consistent ID scheme across all systems
3. **Options**: 
   - Modify cache to store by SolutionSnapshot.id_hash
   - OR modify cache retrieval to use text-based hash lookup
   - OR create bidirectional ID mapping system

#### 2. WebSocket Queue Event Validation (MEDIUM PRIORITY)

**Issue Description:**
- Longer-running jobs (>30 seconds) may experience WebSocket event sequence issues
- Queue state transitions may not fire in correct order: `todo` → `running` → `done`
- History mentions "WebSocket queue event validation with longer-running jobs"

**Potential Impacts:**
- Job completion events may arrive before queue transition events
- Done queue may not update properly for long-running jobs
- Replay functionality depends on proper queue state management

**Testing Requirements:**
1. **Submit Long Jobs**: Create jobs that take 30+ seconds to complete
2. **Monitor Event Sequence**: Verify `queue_todo_update` → `queue_running_update` → `queue_done_update`
3. **Validate Timing**: Ensure `tts_job_request` aligns with `queue_done_update`

#### 3. Response Text Accuracy (MEDIUM PRIORITY)

**Issue Analysis:**
- JobCompletionCache should capture exact TTS text from `tts_job_request` WebSocket events
- Current implementation may use SolutionSnapshot response text as fallback
- Replayed audio should match exactly what was originally spoken to user

**Verification Needed:**
```javascript
// Current implementation in handleJobCompletion()
const actualText = envelope?.text || envelope?.audio_text || "Job completed";
await this.jobCompletionCache.store(jobId, actualText, ...);
```

**Validation Steps:**
1. **Audit Text Capture**: Verify WebSocket event contains exact TTS response
2. **Compare Sources**: TTS request text vs SolutionSnapshot response text  
3. **Test Accuracy**: Original audio vs replayed audio should be identical
