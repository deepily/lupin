## A. Preconditions — checked before I read a single outcome

Fail any of these and the run is void, not caveated.

1. **One frozen snapshot, and the report names it** — `snapshot_sha256` in the run header matches the
   committed manifest, and the row count matches. Two runs quoting different digests are two studies.
2. **Both arms walked the same bodies.** After the join-key fix, `pair_records` must join on
   `frozen_index`. My acceptance test: two draws of the same size with different seeds must RAISE.
   Until that fix lands, no paired number is acceptable regardless of how good it looks.
3. **Every row measurable** — no row with `tutor_enabled` or `tutor_fired` not True reached the
   record set (`assert_row_is_measurable`). A run containing `disabled` rows is void.
4. **`model_failed` under its pre-stated ceiling on BOTH arms**, checked on the pre-flight prefix
   before the full spend. An arm above the ceiling is a broken arm, not a cautious model.
5. **The Flash-Lite arm proved to be Flash-Lite** — all four Vertex markers by name, and the local arm
   proved NOT to be a Vertex client. Two arms resolving the same model produce a perfect study of one
   model against itself.
6. **Environment recorded** — scipy version read at run time, `google-genai` version, resolved GCP
   project, and the freeze's git sha.

## B. What counts as a REPORTABLE result

7. **b + c ≥ F.** Below it: report `b`, `c`, the snapshot row count, and the words **INCONCLUSIVE**.
   No point estimate as a headline with a caveat underneath — that is how an underpowered run becomes
   a cited number.
8. **McNemar exact**, `binomtest( min(b,c), b+c, 0.5 )`. No chi-square, no continuity correction.
9. **Wilson interval on b/(b+c) reported ALWAYS** — including when p clears. An interval spanning 0.5
   means the direction is not established, whatever the point estimate says.
10. **Direction stated only if the Wilson interval excludes 0.5.** p < 0.05 with an interval straddling
    0.5 is reported as "no established direction".

## C. What I will NOT accept as a headline

11. **"Flash-Lite hallucinates less"** — the guard measures what our detector catches. Without item 5
    (hand-labelling a sample of each arm's delivered output) the honest claim is **detectability**, not
    honesty. This is Rick's item and its absence caps the claim; it does not void the run.
12. **Any claim about human-facing DMs.** The corpus is 100% fleet-to-fleet (§4b). Permitted claim:
    *"which model better rewrites agent-to-agent fleet chatter."*
13. **A cost or latency win reported without all-in cost for BOTH arms.** A prior arm published −30.4%
    and became +7.0% once paid inference was counted.
14. **A number whose denominator differs between the arms**, or differs from the D fixed before arm 1.

## D. Reproducibility — the run must be re-derivable by someone who was not here

15. Header carries: snapshot path + sha256 + row count, selection mode, and — when sampled —
    `sample_size`, `seed`, and `drawn_frozen_indices`. Seed alone is insufficient: I verified the same
    seed against a different population draws different rows, so the digest is load-bearing.
16. A `first_n_corpus_order` run carries its **TIME-WINDOW** caveat into the report, or is not used.
17. The frozen snapshot has a named retention — it is real message bodies on disk outside the repo.

Rick ruled four things after the criteria above were written. Three bind symbols to values; the
fourth is a NEW decision rule and is therefore an amendment, not a binding.

| symbol | bound to |
|---|---|
| **D** — fabrication denominator | **narrow** |
| **F** — operational discordant floor | **10** (≥ the arithmetic bound of 6 ✅) |
| title/scope | narrower: fleet-to-fleet |

**New rule — LATENCY IS A TIEBREAKER.** Rick: *"even if they disagreed or fabricated at an equal
rate, if one is ten times faster than the other then I'm going to go with it."*

## A1.1 — The one conflict, and it is the dangerous one

**Criterion 7 says a run with `b + c < 10` is INCONCLUSIVE.** A naive reading of the tiebreaker turns
that into a decision: "no significant difference was found" reads as "they fabricate at an equal
rate", and the tiebreaker then hands the call to latency.

**Those are not the same thing.** An underpowered run is *absence of evidence*, not *evidence of
equality*. At `b + c = 4` we would have learned nothing about honesty, and a 10× latency win would
carry a decision the honesty data never supported.

⇒ **The tiebreaker fires only on a POWERED tie.** Concretely: `b + c ≥ 10` AND the Wilson interval on
`b/(b+c)` includes 0.5. Below the floor, the honest output is INCONCLUSIVE and the decision waits —
latency does not rescue it. Nothing else in the seventeen conflicts; criterion 13 (all-in cost, both
arms) reinforces it.

## A1.2 — Is latency measured cleanly enough to carry a decision? Partly. Ran it.

**Measured**: `elapsed_seconds` per row, `time.monotonic()`, `replay_harness.py:459-461`. Same
machine, same process, same batching (one row at a time, both arms). That much is clean.

**Three qualifications, in order of how much they threaten a decision:**

1. 🔴 **The arms run SEQUENTIALLY, phi_4 always first** (`:701`, `[ARM_PHI4, ARM_FLASH_LITE]`), and the
   local box is shared with the router and other agents (plan §2.4). So each arm sees a *different
   slice of fleet load*. If the fleet was busy during one block and quiet during the other, the ratio
   measures load, not the model — and nothing in the run would show it.
   **Fix, cheap and total: interleave per row** (A, B, A, B) instead of running arm blocks. The rows
   are already in memory; this removes time-varying load as a confound entirely. **I would not accept
   a 1.5× tiebreaker from block-sequential timing. A 10× one survives it** — but say which you have.
2. **`elapsed` wraps the whole `_apply_dm_tutor` call**, not just the model call — claim counting,
   pointer restoration, fabrication and rescope checks, ID-label repair. Both arms pay the same local
   overhead, so the measured ratio is **diluted toward 1.0**. That is conservative for a 10× claim
   (the model-only ratio would be *larger*), so it cannot manufacture a tiebreaker win. It must not be
   reported as "per-rewrite model latency" — it is per-rewrite *tutor-path* latency.
3. **No warm-up row is discarded.** Row 0 of each arm carries that arm's first-call cost — lazy Vertex
   client init plus ADC token fetch on flash_lite, connection setup on vLLM. Each arm pays its own, so
   it is not one-sided; at 400 rows it is ~0.25% and irrelevant to a 10× claim. Discard row 0 per arm,
   or report median and p90 (criterion: §2.4 asks for median, p90, p99 anyway — the tail is what a
   blocked DM sender feels, and medians are immune to a single cold row).

## A1.3 — Added criteria

18. **The tiebreaker requires a POWERED tie**: `b + c ≥ 10` and the Wilson interval spans 0.5.
    INCONCLUSIVE is never a tie.
19. **A latency ratio used for a decision must come from interleaved timing**, or the report states
    that it is block-sequential and that fleet load is an unmeasured confound.
20. **Report median, p90 and p99 per arm**, not a mean — and name the measurement as tutor-path
    latency, not model latency.
21. **The tiebreaker does not survive a fabrication LOSS.** Rick's rule is conditioned on an equal
    rate; a faster model that fabricates measurably more is not a tie, and criterion 10 governs.

## A1.4 — LAN vs public internet: NOT a confound, and the criteria do not treat it as one

Raised by Sam, relayed by the Manager: phi_4 answers over the LAN, flash_lite over the public
internet, so interleaving cannot equalise them. True, and structural — but it is **not a defect in
the measurement**, because it is the thing being decided.

Rick's question is operational: which model goes into the DM tutor. **Production phi_4 already answers
over that same LAN hop** — `src/conf/lupin-app.ini:227` points the live spec key at
`vllm://192.168.1.21:3001@kaitchup/Phi-4-AutoRound-GPTQ-4bit` — and production flash_lite would answer
over the public internet. The round trip to Google is part of what he would be buying. Removing it
would measure a deployment nobody is proposing.

It *would* be a confound for the question "which model is intrinsically faster." That is not the
question, and the report must not answer it.

⇒ **22. Frame the latency result as DEPLOYED latency, not model latency**, and say so in the wording:
*"the tutor served by Phi-4 on the LAN vs the tutor served by Flash-Lite over the internet."*
⇒ **23. Report p90 and p99 per arm, not a median alone.** The internet leg is variable in a way the
LAN leg is not, so the tail carries information the centre hides — and the tail is what a blocked DM
sender actually experiences (plan §2.4 asks for median, p90 and p99 for exactly this reason).
⇒ **24. State the measurement's reach**: one network, one day, our vantage point (plan §2.4's second
confound). That caveat belongs next to the number, not in a footnote — but it caps the claim, it does
not void the tiebreaker.

**The latency rule is therefore NOT conditional on removing the network difference.** If a condition
is wanted from Rick, the useful one is narrower: confirm he means *deployed* speed rather than *model*
speed, and that one network on one day is enough to act on.

## A1.6 — What `fabrication_blocked` measures, and one criterion of mine that got it wrong

Raised by the Manager (rows `d18b13d3`, `e03dfba8`). I went to the detector rather than reasoning
about it: `_fabricated_facts`, `src/cosa/rest/routers/dm.py:814`.

**Mechanically, a block asserts**: the rewrite contains a **number, hex id, path, or capitalised
token** absent from the original. A **surface-novelty test over four token classes** — not a test of
whether the model invented anything. Two limits the code states about itself:

- **False positives, measured**: it blocked 1 of 27 real pairs, and that one replaced
  *"Force-recreated"* with *"Deployed"* — a meaning change, not an invented fact.
- **A stated blind spot**: it *"cannot see a fabricated COMMON NOUN. 'the reviewer' is lowercase and
  passes untouched"* — the very incident the guard was built for.

⇒ In the ABSOLUTE sense, a block is not a fabrication and a non-block is not clean.

**The Manager's narrower statement is correct and I agree with it**: the same guard, at the same
threshold, judged both arms over the same frozen bodies, so the model is the only variable. Internal
validity holds. The claim the study supports is *"which model's output this guard flags less, under a
fixed judge."*

**What I would add to it**: the judge is fixed as *code*, but its sensitivity is a function of output
*style* — `_FAB_CAP` matches capitalised tokens, so a model writing in title case trips it more often
than one paraphrasing into lowercase common nouns, at equal honesty. That does not break the
comparison; it is why the claim has to stay "flagged less by this guard" rather than "fabricates
less". And it is measurable rather than merely stateable — see criterion 28.

### My own error, corrected here rather than edited above

**Criterion 21 said "a faster model that fabricates measurably more is not a tie."** It should read
**"is BLOCKED measurably more often."** That is the one place in the seventeen that assumed a block
equals a fabrication in the absolute sense. Criterion 11 already had it right — it refuses
"hallucinates less" and names the measurement detectability. No other criterion assumes it.

### The honest framing

> **Which model, serving the DM tutor behind the same prompt and the same guard, has its rewrites
> flagged less often by the production fabrication guard — on fleet-to-fleet traffic — and at what
> latency and all-in cost?**

Both what is measured and the operational question worth asking, **because the guard is what ships**:
a rewrite that guard refuses never reaches a recipient, whatever the truth about the model's honesty.
What the study cannot answer is which model hallucinates less — item 5 (blind hand-labelling) is the
only thing that touches that.

### Added criteria

26. **The headline names the guard, not the models' honesty.** "Flagged less often by the fabrication
    guard", never "fabricates less" / "hallucinates less" / "is more honest".
27. **Report the instrument's limits beside the number**: the measured 1-in-27 false-positive rate and
    the common-noun blind spot. A proxy reported without its error characteristics reads as a direct
    measurement.
28. 🆕 **Measure the instrument for arm bias — cheap, and it turns a caveat into a number.** Count the
    checkable-class tokens (capitalised words, numbers, hex ids, paths) each arm emits per rewrite. If
    the arms differ materially, part of any gap is the instrument rather than the model. Computable
    from the records already banked, with no extra spend.
