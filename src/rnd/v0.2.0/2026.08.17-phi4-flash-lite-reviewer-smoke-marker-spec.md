## Marker 2 — resolved model id, READ BACK

| | |
|---|---|
| Assert | `response.model_version` starts with `gemini-3.1-flash-lite` |
| Verified | `types.GenerateContentResponse` carries `model_version` as a real field |
| **Fails when** | Vertex serves a different or aliased model than the descriptor named |

🔴 **Do NOT assert `client.model_name`.** That attribute is set from the descriptor at
`gemini_vertex_client.py:103` — asserting it compares our own input to itself and cannot fail for any
reason the marker is meant to catch. The handoff's wording is *"read back from the client"*, and
`model_version` off the response is the only read-back that qualifies. This is the same class as the
`tutor_fabricated` truthiness trap in plan §2.3: a value that matches today by construction.

## Marker 4 — no API key read

| | |
|---|---|
| Assert | `ac.api_key is None` |
| Measured | `None` |
| **Fails when** | any api-key construction path returns |

**Add the process-global belt**, which `ac.api_key` alone does not cover. Per the §5 fold bundle,
`chat_client.py:69`/`:71` and `completion_client.py:83`/`:84` set `OPENAI_API_KEY` / `OPENAI_BASE_URL`
**process-global for every vendor**. So capture both env vars before the arm and assert they are
unchanged after it — that catches a fall-through that already happened, which an assertion on the
Vertex client object cannot see.

## Three things the implementer will otherwise get wrong

1. **Venue.** This smoke makes a **live, paid Vertex call**. Under §TESTING VENUES that is persistent
   state (LLM API spend) ⇒ **`:8000`, submitted via `POST /api/test-suite/submit`**, not `:7999`.
   Markers 1, 3 and 4 need no call and belong in a `:7999` unit test; only marker 2 needs the spend.
   Split them, and the cheap three run on every commit.
2. **Private attributes.** `_api_client` and `_http_options` are internal to `google-genai`. That is
   acceptable here — no public accessor exposes the resolved endpoint — but it means the smoke is
   pinned to **1.73.1**, and the version must be recorded next to the result the way §3.1 requires for
   scipy. State it at the call site.
3. **The entry point.** Assert through `get_client( "dm_tutor/flash_lite" )`. A raw
   `get_client( "vertex://global@…" )` raises `Unsupported vendor: vertex` by design (plan §2.1a) —
   passing that would be testing a rejection, not the arm.
