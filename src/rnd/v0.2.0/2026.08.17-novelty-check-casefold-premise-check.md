## What is actually blocking

The tokens flagged as invented "names" are overwhelmingly **ordinary English words that happen to be
capitalised** — a sentence opener, a bullet head, an imperative. `_FAB_NOT_NAMES` already excludes
function words (`the`, `and`, `if`); it does not exclude content words, so `Verify` and `Ensure` are
read as invented entities.

## The trade Rick has to rule on, stated before anyone sees a p-value

V3 means **a capitalised common word can no longer be flagged as a fabricated name.** That includes
the one real catch this guard is credited with: it blocked a rewrite that replaced "Force-recreated"
with "Deployed" — a meaning change worth refusing. `Deployed` is a dictionary word, so under V3 that
rewrite ships.

The guard's docstring already concedes it cannot see a fabricated *common noun* ("the reviewer").
V3 widens that hole from lowercase to any case. That is a deliberate loosening in exchange for a
~69% cut in Flash-Lite's rejections — Rick's stated goal — and it is his call, not mine.

## What this does to the study's pre-registered acceptance

Flagging it rather than adjusting it, per the row.

- The caveat in `2026.08.17-phi4-vs-flash-lite-WHERE-WE-STAND.md` — *"76% of Flash-Lite's blocks are
  capitalised-token novelty alone; drop that class and p goes 2.7e-07 → 0.42"* — is **arithmetically
  correct**: 99 of 130 flash_lite blocks (76.2%) are name-only. Only its *name* misleads, by implying
  capitalisation caused them. Phi-4's share is 64.4% (47 of 73), which the caveat never stated.
- Removing the class entirely (Tiffany's sensitivity check) is **not** the same intervention as V3.
  V3 keeps the class and narrows it: 29 vs 40 blocks still stand, so the re-run is a genuine test, not
  the degenerate "delete the disagreement" case.
- A dictionary-backed rule needs a word list that exists **inside the server container**, not just on
  this host (`/usr/share/dict/american-english`). A vendored list is the safe form.
