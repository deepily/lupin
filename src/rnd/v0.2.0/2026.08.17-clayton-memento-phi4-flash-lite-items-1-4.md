## 9. Retro deposit — how I came to know each thing

**Where I asserted instead of checked.**
- I called the guard "hardened" after a realpath comparison. It was not — only writing the
  hard-link test made me see that realpath compares two bind-mounted names as *unequal*, so
  the container-mount case walks straight through. Tiffany's F5 pointed at `(st_dev, st_ino)`;
  I understood *why* only after writing the test that fails without it.
- I DM'd the manager "item 1 green" while all three files were **untracked**. Tiffany then
  reviewed a copy that had moved under her, so two of her four blockers were already closed
  before her DM landed. That wasted her findings and made my "already fixed" unfalsifiable.
  The rule that fixes it is mechanical, not attitudinal: **commit, then claim, and hand over
  a sha.** I was told this; I did not derive it.
- I nearly reported a regression I had manufactured myself — two red tests in a fresh
  worktree, cause was the gitignored `cloud-run.env` being absent, not the code.

**What the brief/spec misled me on.**
- The handoff's §7 item 1 says the harness must raise if "the snapshot path equals the live
  path". Implemented literally, that check **cannot fire**: the snapshot is always
  `dm_replay_frozen.jsonl` and the live file always `dm_traffic.jsonl`, so the basenames can
  never match. My own replay test found it (I aimed the loader at the live *directory*,
  expected a refusal, got `FileNotFoundError`); Tiffany filed the same thing as B1 minutes
  later. The reachable guard is the **directory-level** one. I had mutation-tested the file
  guard and would still have shipped something unreachable from its own call path.
- The handoff hardcodes the fabrication denominator that the input plan deliberately leaves
  as `DENOMINATOR-TBD`. Reading "THIS ONE DOC" as authoritative would have closed Rick's
  decision. The reviewer caught this before I built it.

**Self-corrections.**
- `test_freeze_refuses_to_write_over_the_live_corpus` passed only because it *told the
  function the live corpus was named after the snapshot*. Its own comment admitted it.
  Deleted rather than defended, replaced with the real shape.
- Asserted Wilson's lower bound `== 0.0` at 0/6. It is `2.8e-17` — a difference of two
  nearly-equal floats. My test was wrong, not the code; fixed the assertion and said so in a
  comment so the next reader does not re-derive it.
- Shipped `--limit` as the only way to bound a run. Sam pointed out the frozen set is in
  corpus order, so the first N rows are a *time-window* sample. Folded a seeded draw into
  the harness and deleted his workaround driver rather than keeping both.

**What surprised me in this codebase.**
- `_apply_dm_tutor` is **contractually incapable of raising**. Every failure becomes a
  recorded `meta` field, and a field is not an alarm. Three distinct ways a run can look
  clean and measure nothing all trace back to that one property.
- The corpus moved **4 rows between my counting it and freezing it** (8,006 → 8,010, about
  four minutes). The drift the freeze exists to stop is visible on that timescale.
- A git worktree carries tracked files only. Obvious in hindsight; it cost me a false red.
- `EXCLUDED_PATH_PARTS` in the gate-reachability census is matched against the **absolute**
  path, and `.claude` is on the list — so the census silently sees zero test files inside the
  repo's own sanctioned worktree location. I found it only because I refused to accept
  "5 failed" without separating pre-existing from mine, which meant checking the base commit
  out into a throwaway worktree and re-running the same five.

**The one habit that paid.** Every time I wrote a test that tried to make a guard fire in the
shape production actually calls it, the guard turned out to be weaker than I thought. Twice.
