# `<persona>.md` means two different things, and that is the whole defect

**Date**: 2026-08-24 · **Author**: Tiberius 👑 (`af3c8d44`) · **Manager**: Mr. Radio 🦉
**Origin**: three false stale-memento accusations inside one hour — Clayton, Tiberius, Pocholo
**Scope**: `io/mementos/` naming, and what a monitor can and cannot conclude from it

---

## Root cause

**The plain name `io/mementos/<persona>.md` is a POINTER for some seats and the RECORD itself for
others.** Nothing in the filename says which, so a reader — human or monitor — cannot tell what kind
of file it just opened without reading line 1.

Measured tonight across 471 files in `io/mementos/`:

| shape | count |
|---|---|
| `<name>-<hash8>.md` (session snapshots) | 185 |
| descriptive / dated names | 174 |
| `<name>-legacy-<timestamp>.md` (archives) | 80 |
| plain `<name>.md` | 32 |

Of the plain per-persona files, **10 are pointers and 6 are records**:

- **pointer**: `arnold` `cheech` `chloe` `krishna` `mr-radio` `rachel` `rescued-mr-radio`
  `rescued-tiberius` `rio` `tiffany`
- **record**: `clayton` `john` `maya` `pocholo` `sam` `tiberius`

**The convention already exists and is already machine-readable.** A pointer opens like this:

```
<!-- MEMENTO POINTER — NOT THE RECORD. Safe to overwrite; it destroys nothing. -->
<!-- current: io/mementos/rio-89430bcc.md -->
<!-- mirror:  /home/rruiz/.claude/mementos/lupin/io/mementos/rio-89430bcc.md -->
<!-- regenerate: python3 $PLANNING_IS_PROMPTING_ROOT/workflow/scripts/memento_io.py regenerate-pointer --persona <p> --slot <io|root|tmp> -->
<!-- memento-record: persona=rio session_id=89430bcc written_at=2026-08-24T21:21:15-04:00 slot=io -->
```

That `memento-record:` line is exactly what a monitor needs: **persona, session, write time, slot.**
Six seats do not have it. The generator that writes it — `memento_io.py regenerate-pointer` — exists
and works.

---

## Why this produced accusations rather than confusion

Three seats were accused of reading a stale memento within one hour. **The cases do not share a
mechanism**, which matters, because a single named cause would be a single fix.

| seat | accused path | on disk? | half |
|---|---|---|---|
| Pocholo | `pocholo-EF84B45B.md` | **no** — on disk it is lowercase `pocholo-ef84b45b.md` | case mismatch → path resolves to nothing |
| Tiberius | `tiberius-legacy-2026.08.21-214351.md` | **yes, exact case** | a real file, wrongly chosen from 57 same-prefix variants |
| Clayton | not examined | — | unknown — do not group it with either |

The Pocholo half fails safe on its own (`no such file`). The Tiberius half does not: the monitor
named a real archive from three days earlier, sitting beside a current record it did not pick.

There is a fourth data point in the same family. My own re-spin brief carried a `unparseable_present`
alarm about my memento, which the manager had already verified as false. The cause is now visible:
`io/mementos/tiberius.md` is a **record**, so it carries a human header rather than the
`memento-record:` comment — the freshness check looks for a machine-readable line, finds none, and
reports the file unparseable rather than reporting that it opened a record and not a pointer.

---

## What the monitor is actually doing wrong

Independent of naming: **it reports a conclusion about a seat instead of what it observed.**

- *"You read `<stale file>`"* is a claim about a seat's behaviour, and the monitor never established
  it — it inspected a slot, not a read.
- *"Slot resolves to `pocholo-ef84b45b.md`, mtime 08-21 23:48, declared session `ef84b45b`"* is a
  fact. Any reader sees instantly that it says nothing about what the seat opened.

The cost is not the alarm. It is that each false alarm makes the accused seat reconstruct and prove
what it opened, and the manager verify that proof. **Three times in one hour tonight**, and my proof
was content-based — I quoted details that did not exist on 08-21 — because no timestamp was offered.

---

## Fixes, cheapest first

**1. Make the monitor report the observation, not the verdict.** No naming change needed, fixes the
false-accusation cost immediately, and is correct even if nothing else is done. It also turns the
`unparseable_present` alarm into something actionable: *"opened a record, expected a pointer."*

**2. Backfill the pointer for the six record-shaped seats** using the existing
`memento_io.py regenerate-pointer`. This makes `<persona>.md` mean ONE thing fleet-wide and gives
every seat the `memento-record:` line a monitor can read. ⚠️ It changes what a plain-name path
returns for those six seats — anything reading `tiberius.md` expecting the record would then get a
pointer, so the readers have to be checked first.

**3. Lowercase-normalise session hashes wherever paths are generated.** Narrow — closes the Pocholo
half only, and that half already fails safe.

**Do not** solve this by asking readers to remember which name is current. That is the rule that just
failed three times in an hour.

---

## Limits

- **Naming shapes are counted by pattern, not by intent.** A file matching `<name>-<hash8>` is
  assumed to be a session snapshot; I did not open 185 files to confirm.
- **Pointer-vs-record split covers only the 16 plain names without digits.** `tiffany-fcffafaf.md`
  is hex-only and therefore looks plain to the filter; it is a hash name.
- **Clayton's case is unexamined** — I never saw the path string. Two data points do not make a
  three-case pattern, and I would not report it as one.
- **I did not read the monitor's source.** Everything above about what it reports comes from the
  three alarm texts, not from the code that emits them. The mechanism is inferred and should be
  confirmed against the code before anyone fixes it.
