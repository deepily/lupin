## Verdict

**Output size is NOT where a 60-slide deck breaks.** A 60-slide outline is ~3–4K output tokens against claude-opus-5's **128K** output ceiling — a ~30× margin. The 15-slide "proven ceiling" is proven only because duration defaulted to 15 (`15 min × 1.0 slides/min`), **not** because 15 is near any size limit. The truncation → fail-loud → dead-job mechanism is real, but its numerical trigger is far above 60 slides.

## The two inputs to the arithmetic

1. **The ceiling.** The outline runs on `content_model = claude-opus-5` (`lupin-app.ini:1663`) via the bounded-CC path. `api_client.call_for_outline` passes `max_tokens=4096` (`api_client.py:267`) — but that is a **PHANTOM**: `_call_api` builds `ClaudeAgentOptions(model, system_prompt, tools, permission_mode, max_turns)` at `api_client.py:413-419` with **no `max_tokens`**, and the docstring confirms it — *"Retained for signature parity (unused on the bounded path)"* (`api_client.py:402`). So the real ceiling is the model's own output limit: **claude-opus-5 = 128,000 output tokens** (Anthropic model card). Even a conservative Agent-SDK default (≥8K) leaves 60 slides safe.

2. **The per-slide cost.** `parse_outline_response` expects 6 fields per entry (`prompts/outline.py:296-303`): `number` (int), `arc_position` (short enum), `type` (short enum), `title` (assertion sentence, ~8–12 words), `visual_type` (short enum), `source_hint` (short phrase). With JSON keys + punctuation + whitespace, one entry ≈ **50–70 output tokens**.

## The estimate

| Slides | Duration @ 1.0 s/min | Est. outline output tokens (×50–70) | vs 128K ceiling | vs phantom 4096 |
|---|---|---|---|---|
| 15 (today's default) | 15 min | ~750–1,050 | 0.8% | ~20% |
| 25 | 25 min | ~1,250–1,750 | 1.4% | ~34% |
| 40 | 40 min | ~2,000–2,800 | 2.2% | ~59% |
| **60** (Rick's talk) | **60 min** | **~3,000–4,200** | **~3.3%** | **~73–103%** |

**Read this two ways.** Against the *real* ceiling (128K), 60 slides is trivially safe — the outline won't truncate on size until ~1,800+ slides. Against the *phantom* 4096 (if it were ever wired in), 60 slides sits right at the edge and a verbose deck would truncate — a latent trap worth noting, but not live today because the cap never reaches the SDK.

## What could still bite a 60-min deck (not the outline output)

Named for María's benefit, from the P0-2 recon:
- **Source truncation** — `narrative.py:178-180` clips the source doc to 30,000 chars before analysis. A 60-min talk's source is analyzed from a fraction of itself. This is the real 60-min risk, not the outline call.
- **Elaboration** is safe by construction — chunked fallback at `batch_size=6` (`orchestrator.py:1097`).

## Cheapest path to a *measured* number (if the estimate isn't enough)

The estimate rests on two things I did NOT run: the ~50–70 tokens/entry figure, and the assumption that the Agent-SDK subprocess applies no output cap below 128K. One cheap measurement settles both: **a single outline-only call at `target_duration_minutes=60`**, reading `output_tokens` off the `ResultMessage` (`api_client.py:440`) — the code already records it.
