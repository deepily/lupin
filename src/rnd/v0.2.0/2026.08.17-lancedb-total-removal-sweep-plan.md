## Why deletion, not lazy imports

The obvious cheap fix is to move `import lancedb` inside the `else` branch so the package stops loading. **Rejected** — under a total-removal ruling that is work we would immediately undo, and it leaves a dead path that reads as supported. One wrinkle worth knowing if anyone revisits it: several modules annotate `def _get_schema( self ) -> pa.Schema:`, which evaluates `pa` at class-definition time, so lazy imports would also need `from __future__ import annotations`. Deleting the schema builders removes that problem instead of working around it.

## Lanes

File ownership is disjoint so three sessions can run at once without stepping on each other. Every lane: **suites green + 100% lines/branches on every module it touches**, commit locally, **never push**.

### Lane A — the six cache-layer modules
Delete the LanceDB branch from each: the `lancedb.connect(...)` arm, the `pa.schema(...)` builders that only that arm calls, the `-> pa.Schema` annotations, and the module-level `import lancedb` / `import pyarrow as pa`. Keep the Postgres path exactly as it is. Where a module's `__init__` reduces to a single path, delete `self._use_postgres` and the branch rather than leaving a constant-true flag. Update each module's tests: the LanceDB-path tests are testing deleted code — delete them, don't skip them, and hold coverage at 100%.
**Receipt**: the 55 → 0 measurement, re-run with the same `MetaPathFinder` probe.

### Lane B — the snapshot manager and the factory
Delete `cosa/memory/lancedb_solution_manager.py` (2,182 lines) and `ManagerType.LANCEDB` with its `_create_lancedb_manager`. Repoint any caller of the LanceDB class at `PostgresSolutionManager` (Phase 1 already shipped it). Sweep `snapshot_manager_interface.py`, `two_tier_question_search.py`, and `solution_manager_factory.py` for LanceDB naming in docstrings and comments — the words are now wrong, not just stale. **Do not touch `lupin-app.ini:15`.**
**Receipt**: `create_from_config_manager` builds `PostgresSolutionManager` in every non-prod section; factory tests at 100%.

### Lane C — the flag, the dependency, the config
Make Postgres unconditional: `vector_store_backend.py` and its `is_postgres_backend()` / `resolve_lancedb_path()` seam exist only to choose between two backends, and there is one backend now. Remove the `vector store backend` key and the `solution snapshots lancedb *` keys from both INI files (splainer entries included — the splainer mandate cuts both ways). Drop `lancedb` from `src/cosa/requirements.txt`. Sweep the remaining comment/docstring references outside the hands-off list.
**Receipt**: a fresh interpreter importing the app has no `lancedb` in `sys.modules`; `pip check` clean; full unit suites green.
