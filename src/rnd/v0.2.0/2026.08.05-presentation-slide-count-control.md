## Why 12 — the two sources of pressure

**1. The count is a formula, not a setting — and the two prompts contradict each other.**

`slide_budget = int( target_duration_minutes × slides_per_minute )` — `orchestrator.py:801`
(duplicated verbatim at `:739` and `:1779`). Defaults `15 × 1.0 = 15` (`config.py:43-44`,
`lupin-app.ini:1666-1667`).

`prompts/narrative.py:156` then computes `content_slide_budget = slide_budget − 3` and interpolates it
at `:188` and `:200` — *"The total proposed slides for content sections should be close to 12."*
So **12 is causal-by-construction in the prompt target**, not a numeric coincidence.

But the final count is **not** code-forced to 12. The outline prompt is internally contradictory:
`prompts/outline.py:235` says *"Create exactly {slide_budget} slides"* (15), `:225` reports
*"Narrative analysis proposed {total_proposed}"* (≈12), and `:236` says *"respecting their proposed
counts."* Nothing caps the list. **The subtraction biases the run toward budget−3; the contradictory
outline instructions let the model land anywhere in [budget−3, budget]. Last night it resolved to 12.**

Neither the formula nor the subtraction has any unit-test coverage; nothing would fail today if either
changed.

*(Mechanism confirmed by Rachel 🕊️ on a refute-first pass. Her correction — that this biases rather
than determines — is why the fix below is worth making regardless: removing a contradiction is right
whether the outcome is deterministic or probabilistic.)*

**2. The source document is clipped to 30,000 characters — a bare literal in two places.**
`prompts/narrative.py:178` and `prompts/elaboration.py:171`, plus a third copy in the podcast
generator (Rachel). Against the 77,621-byte file Rick actually fed it, **the clip throws away 61%
before the model reads a line.** The narrative analysis cannot propose slides for content it never
saw. That's ~19k tokens against opus-5's 1M context — it fits about fifty times over. No config key
exists for it.

**Already plumbed, so not a problem:** `target_duration_minutes` reaches config from all three entry
points (CLI `__main__.py:183`, REST `rest/routers/presentation_generator.py:36`, voice
`agents/runtime_argument_expeditor/agent_registry.py:140-142` → `job.py:249-250`). It defaulted to 15
last night only because no number was said.

**Not a ceiling, despite appearances:** `max_tokens` on the outline and elaboration calls
(`api_client.py:267`, `:281`) is dead code on this path — `_call_api`'s own docstring says
*"Retained for signature parity (unused on the bounded path)"* (`:402`) and `ClaudeAgentOptions`
(`:413-419`) sets model, system prompt, tools, permission mode and max_turns, and nothing else.
Raising it would change nothing. My first read called it a ceiling; Clayton and Mr. Radio each caught
it independently and I verified before this doc was written.

**Two more bugs found in passing:**
- **`audience_context` is collected and then dropped.** `job.py:106` stores it; `job.py:249-256`
  copies duration, audience, theme and content_model to config but **not** this; `config.py` has no
  such field, so `getattr( self.config, "audience_context", None )` (`:693`, `:809`, `:977`) is always
  `None`. Rick's dictated "presenting to forward-deployed engineers at Google" went nowhere.
  *(In flight with Clayton.)*
- **Gate 1's revise is inert** (above).

### T1 — an explicit slide count that overrides the formula

Add `target_slide_count : Optional[int] = None` to `PresentationConfig` (`config.py:43`), read from a
new INI key `presentation generator target slide count` (`config.py:94`, `lupin-app.ini:1666`).

Collapse the three duplicated formula sites (`orchestrator.py:739`, `:801`, `:1779`) into one helper:

```python
def _slide_budget( self ):
    if self.config.target_slide_count is not None: return self.config.target_slide_count
    return int( self.config.target_duration_minutes * self.config.slides_per_minute )
```

Plumb it by copying the chain `target_duration_minutes` already travels, file for file:
- `job.py:58` ctor param + `job.py:249-250` config override
- `__main__.py:183` CLI flag `--target-slide-count`, added to `USER_VISIBLE_ARGS` (`:24`)
- `rest/routers/presentation_generator.py:36` request field + `:188` forward
- `rest/agentic_job_factory.py:224` pass-through — **⚠️ there are TWO sites, not one.** `:224` is the
  direct presentation job; **`:244` is `research_to_presentation`.** An earlier draft of this list
  named only `:224`. See the scope ruling below.
- `agents/runtime_argument_expeditor/agent_registry.py:140` voice aliases ("slides", "slide count")
  + fallback question

Duration stays as-is and keeps driving per-slide timing. **Verified safe by Rachel:**
`prompts/elaboration.py:135-137` computes `total_slides = len( slide_outlines )` and
`avg_seconds_per_slide = total_seconds // max( 1, total_slides )` — timing derives from the *actual
produced* slide count, not the budget formula, so 40 slides in 60 minutes self-corrects to 90s/slide
with no further change.

### T2 — remove the contradiction between the two prompts

`prompts/narrative.py:153-156` recomputes its own budget and subtracts 3. Pass the resolved budget in
instead, and state one coherent split ("N total = 3 structural + N−3 content"). Leave
`outline.py:235` alone — **once T1 lands, `slide_budget` IS the resolved count, so narrative and
outline agree by construction.**

> **The seam Rachel will grep for**: T2 only works if **both** prompts receive the **same** resolved
> budget from `_slide_budget()` (`orchestrator.py:801`) — narrative getting `resolved − 3` for its
> content split, and `outline.py:235`'s "exactly {slide_budget}" getting `resolved`. **If either
> prompt still computes its own number, the contradiction survives and the bias is back.** That is the
> single check that decides whether this fix is real.

### T2b — soft target, warn on drift (Rick's ruling)

After the outline returns, compare `len( outlines )` against the requested budget. If they differ,
`notify()` the user with both numbers. **Do not fail the job and do not retry** — sections stay
coherent, the user just learns that 40 came back as 38. This matters *because* the target is a prompt
instruction the model can miss, not a hard constraint. Natural home: alongside the existing structural
validation at `orchestrator.py:872-888`.
