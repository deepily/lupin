## 2. The delta — nine items in the files that are NOT in the fold

Ordered by how much they change the design.

### 2.1 🔴 §6 is misnamed: it is a drift guard, not a completeness test — R3 follow-up 1

arnold's answer to "can a command be right everywhere the test looks and still be unreachable by voice?" is **yes**, by three mechanisms:

1. **No retrain.** The test reads training-JSON keys on disk; the deployed router emits from LoRA weights. A new key with no retrain is **green in the test and mute in production**. §5.4 states this asymmetry — the *test* does not encode it, so assertion 1 uses "in the training keys" as a reachability proxy that §5.4 itself says it is not.
2. **Runtime template ≠ checked-in template.** The test reads the checked-in file; if the running router loads a different or differently-rendered one, membership ≠ what the router is told. **Marked UNVERIFIED by the reviewer** — flagged as the load-bearing assumption, not a confirmed defect.
3. **Emitted string ≠ registry key, no alias wired.** Set-membership tests that the same *string* is in four lists; never that the string the router emits at runtime matches a registry key or alias. `resolve()` handles V2 aliases (`registry.py:143`); whether `resolve_agentic()` will is a phase-1 open.

**Required action**: rename it a **drift guard**, and state the three reachability gaps as out-of-scope-by-design. The honest scope is four-list drift consistency — real and worth having, but the §6 header overclaims.

### 2.2 🔴 Phase 3's anti-relaxation gate is not mechanically enforceable — R3 follow-up 2

Nothing stops a builder reaching green by weakening the test: loosen an assertion, add to an "intentional exemption" set, or bump the hard-coded counts `6 / 7 / 1 / 2` and the `16` total at `test_v2_registry.py:75-80`.

The sharp part: §5.1.2 already concedes those counts must be hand-updated in the same commit — but **a count updated to the new true value is, in a diff, indistinguishable from a count updated to silence a failure.** Both are one-line number changes turning red to green. The falsifiability demos §6 requires are themselves ordinary tests and can be edited too.

**Required action** (if the gate is to be structural rather than intentional): **derive the expected counts from the registry at test time** so there is no magic number to edit, and require any exemption to carry a **machine-checked reason field** rather than silent set membership.

### 2.3 🟠 A new §6 assertion the design's own choice makes necessary — R1 item 2

§5.1.1 keeps `ArgSpec.from_entry( AGENTIC_AGENTS[cmd] )` reading `AGENTIC_AGENTS`. If that table survives migration, then `cls == AGENTIC` and `AGENTIC_AGENTS` membership become **two sources for the same fact** — the exact drift this design exists to remove.

**Required action**: assert the two agree — every `cls == AGENTIC` command is in `AGENTIC_AGENTS` and vice versa. Cheap; closes a seam the design itself opens.

### 2.4 🟠 Assertion 3 needs both-directions set equality — R3

"Appears in prompt + training **only**" catches a *missing* membership but not an *extra* one, unless it also asserts absence from registry + factory. Write it as set-equality both ways, the way assertion 4 already does (`test_v2_registry.py:68`).

### 2.5 🟠 §5.4's real limitation is statistical power, not the 60% — R1 item 1

The whole asymmetry rests on **n=10, one invented command (`agent router go to recipe finder`), one topic**. 10/10 at n=10 carries a wide confidence interval (~69% lower bound) and there is **no evidence it generalizes across all agentic commands**.

María's fold labels both arms — correct — but the caveat to carry forward is this one. If the fast-path reachability story is ever challenged, this is the gap, **not** the control-arm percentage.

### 2.6 🟡 §5.1's justification should be softened — R1 item 2

§5.1 sells `cls` on "agentic appear in all four sources, conversational in two." That split is **already derivable** from `AGENTIC_AGENTS` membership, so it does not need a new field. `cls`'s real job is the finer **CONVERSATIONAL / CONTROL / NONE** split, which no agentic signal can produce, plus turning a fragile derived-negative ("absence from `AGENTIC_AGENTS`") into an explicit positive label.

Worth stating plainly: **`cls` is not a fifth list.** §5.1.2 derives all four bucket constants from it — net **4 hand-maintained frozensets → 1 field per spec**.

### 2.7 🟡 `none` is shared across both namespaces — the scoping fix is necessary, not cosmetic — R2

Of the 23 vox-cmd keys, **exactly one overlaps** the router's space: `none`, appearing in `vox-cmd-simple-commands.json:12`, `agent-router-simple-commands.json:6`, and the registry (`RECEPTIONIST_OR_NONE`, `registry.py:116`).

So a directory-glob reconcile would **accept `none` and orphan the other 22** — a partial-looking failure that is harder to diagnose than a clean one.

### 2.8 🟡 §5.3's "all ten corpora" wording — R2

The object-valued shape is **one file**, `agent-router-agentic-commands.json` (10 entries). The other four carry **bare path strings**. María's §9 worry that compound/simple don't share the agentic shape is **confirmed** — but her stated rationale ("values are editorial: which template, which placeholders, which triggers") holds only for the agentic file. The **conclusion** (key-only reconcile) is sound regardless: `json.load(f).keys()` extracts whatever the value shape.

### 2.9 🟡 Tiffany's *preferred* ordering fix is stronger than the folded one

María folded "set-equality + a declared ordering rule" — Tiffany's **fallback**. Her **preferred** fix: **make order registry-owned data** — declare an explicit ordered command list in the registry and generate from it. Order stops being editorial, and byte-compare becomes an honest gate rather than one that must be abandoned.

Worth a deliberate choice rather than inheriting the weaker option by accident.
