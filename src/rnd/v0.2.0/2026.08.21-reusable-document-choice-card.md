# The document choice card, made reusable

**Row**: `a1420538` (widened by Rick's ruling 2026-08-21 ~15:12 EDT) · **Author**: Clayton (implementer) · **Reviewer**: María · **Merge**: Mr Radio

## What Rick asked for

> "We're going to have to disambiguate file names in the future; create a reusable approach."

and, 15:17:

> "The old file chooser dialogue was ugly and did not leverage the flexible ask component of the MCP server connected to the notification API; make sure we leverage that."

## Where we actually are

The card is **already** a thin wrapper over the notification API's exclusive single-select ask.
`RuntimeArgumentExpeditor._ask_choice_for_arg` builds one `NotificationRequest` with
`response_type=MULTIPLE_CHOICE`, a single question, `multi_select: False`, and `options` =
candidate basenames plus the two escapes. There is no bespoke dialog to replace. So the second
constraint is **"keep it that shape and stop reinventing it per agent"**, not "rebuild it".

What is *not* reusable today is everything around the card:

| Piece | Today | Problem |
|---|---|---|
| Which args get a card | `special_handlers[arg] == "fuzzy_file_match"` in `agent_registry.py` | A string tag spelled per agent; nothing declares the *search roots*, which are read from a config key derived from the display name with a **podcast fallback** |
| Card identity | none — the card is identified by its **question prose** | Prose is the join key between code and the proxy answer files. A wording change silently unanswers the card |
| Proxy answer | one entry **per agent**, `question_pattern` byte-identical to the derived question | Agent #3 gets no card answer until someone remembers to add a twelfth JSON entry |
| Answer validation | only sentinel-shaped answers are checked | Any strategy may submit prose the card never offered |

And there is a live generality hole: `expeditor.py:1664`, the **second** call site (post-describe
ambiguity), still calls `_choose_document_from_matches( matches, docs_map, user_email )` with no
`arg_name` / `agent_display_name`. It falls back to `"research"` and "for the podcast" — the exact
defect commit `63ca8976` fixed on the first-turn card and never reached here. A presentation user
who describes their document and stays ambiguous gets a card titled **"Missing: research"**. This
is the case the contract test has to catch, because a hand-listed test would have listed the call
site that was already fixed.

## The four pieces

**(1) Declare file-typed args once.** `JOB_ARG_CONTRACTS` entries gain a typed `file_args`
declaration: `{ arg_name: { "kind": "file", "search_roots": [...] } }`, carried onto `ArgSpec` and
surfaced by `AgentSpec`. The expeditor's dispatch and `_handle_fuzzy_file_match` key off
`kind == "file"` and read roots from the declaration — never off `command`, never off a config key
derived from the display name with a podcast fallback. `special_handlers` stays as the
compatibility spelling so nothing has to move in one commit.

**(2) Give the card a stable identity.** `response_options` is an opaque dict that round-trips
through the API untouched, so `card_id: "document_choice"` rides there beside `questions` — no new
model field, no endpoint change. The question stays derived from `arg_name` / display name exactly
as `63ca8976` does. The proxy answer files then carry **one generic entry** keyed on `card_id`,
matched deterministically before the LLM sees anything, replacing the two per-agent
`question_pattern` entries. Prose stops being a join key.

**(3) Validate every multiple-choice answer, whatever produced it.** In `responder.py`, after the
strategy chain and after sentinel resolution, a `multiple_choice` answer must be one of
`option_labels( notification )` or it is a counted, printed skip. Today only sentinel-shaped
answers are checked; script-matcher, rules and cloud-LLM answers go straight to
`_submit_response`. This closes the leftover this row was filed on — a CBR `prediction_hint` still
carrying the retired prose at **confidence 0.9 against a threshold of 0.9**. The boundary matters
and gets stated: the gate is `confidence < floor → reject`, so **equal passes**; the test feeds
0.9 against 0.9, not 0.95.

**(4) A contract test derived from the registry.** Iterate every `kind="file"` arg across every
registered agent and assert, per arg: the card is reachable (every call site passes the caller's
`arg_name` and display name), and a proxy entry answers it. Derived, not hand-listed — that is
what makes it catch `expeditor.py:1664` and the not-yet-written third agent.

## A second instance, named but not touched today

The open-ended **describe-it** ask has the same hole one surface over. Five entries across
`all-agents`, `proxy-integration-test`, `expeditor-smoke`, `minimal` and `podcast` key
"Which research document should I use…?" on prose and answer with a file path — and they
have **diverged**, not merely multiplied: two answer `latest`, three a mock path, and
podcast's carries an extra trailing sentence. Same shape, same fix (an id), out of scope
for this row. (María first read those five as choice-card entries; they are
`response_types: ["open_ended", "open_ended_batch"]`, a different surface — which is why
the straggler guard in the contract test is scoped to `multiple_choice` and does not
false-accuse them.)

## Order and receipts

(3) first — smallest, and it is the live risk. Then (2), (1), (4). Red-on-revert captured per
behaviour; `:7999` unit/smoke only.

**Both sides of the 0.9 boundary are literals**, in the fixture and in the assertion. If
either were computed, float arithmetic could move the comparison and the test would stop
pinning the thing it exists to pin.
