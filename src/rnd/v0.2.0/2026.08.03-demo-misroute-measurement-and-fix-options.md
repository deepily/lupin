## 2. Correction to the row's two-case framing

The row asked to separate "a low-confidence confirmation firing (90% floor)" from "a
confident wrong pick (training data)." The measurement shows it is **neither, cleanly**:

- The **agentic confirmation is NOT confidence-gated** — it fires unconditionally for
  every LLM-routed agentic command (`todo_fifo_queue.py:754-764`). So "the confirmation
  exists to catch a low-confidence pick" does not describe this path.
- The **90% floor is a different mechanism** — the snapshot-cache confirmation
  (`push_job` "Top-1 + confirm", lines 500-644), which gates replaying a *cached prior
  answer*. It was not involved in this route.
- The router pick **was** confident (no hesitation, no ambiguity signal).

## 3. The real trap: the label lies

`PRODUCT_NAMES["agent router go to research to podcast"]` = **"Doc-to-Pod (convert
existing research to podcast)"** (`todo_fifo_queue.py:1006`). That description is
*exactly* what Rick asked for — convert his existing document. So a Rick hearing the
confirmation would say **yes** and be routed to `DeepResearchToPodcastJob`, whose
documented behavior is *"1. Deep Research: Web search, synthesis, report generation"*
from a `query` topic — it **web-researches the topic from scratch and never opens his
file**. A *working* confirmation still misroutes him, because the label affirmatively
describes a capability the agent does not have.

And there is **no document→podcast agent at all**: the only podcast paths are `podcast`
("create a podcast from a topic") and `research_to_podcast` (deep-research a topic). Both
generate from a topic; neither reads a provided document.
