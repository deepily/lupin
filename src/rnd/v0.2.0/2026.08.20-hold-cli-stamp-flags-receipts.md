## The zone ruling (Cheech, 2026-08-20)

The first cut normalized a zone-less timestamp to UTC. That picks a timezone the
caller did not give, and a wrong guess is not rejected and not obviously bad — it
is off by the host offset, which reads as a plausible timestamp and debounces the
wrong way. **A zone-less stamp is now refused at exit 2 with nothing written**,
the same as an undatable one.

Measured, not argued: `2026-06-22T12:00:00` dates **14400 s apart** depending on
which reader asks — `_parse_iso` assumes UTC, `_iso_age_seconds` calls
`.timestamp()` on the naive datetime and Python resolves it LOCAL. Four hours on
this box, most of a debounce window.
`test_the_two_readers_really_do_disagree_by_the_host_offset` asserts that gap
equals the host offset **at the stamp's own date** (DST-safe), so the guard's
justification is executed rather than only written down.

House format, measured: `write_hold` builds `held_at` through `_now()`, so it is
offset-bearing UTC — a live write produced `2026-08-21T02:38:08+00:00`. `"now"`
resolves to exactly that shape, so this introduces no second convention.

Accepted: `"now"`; any offset-bearing stamp, offset **preserved** rather than
re-zoned (`2026-06-22T08:00:00-04:00` lands verbatim); a trailing `Z` treated as
the offset it is. One `fromisoformat` call answers both the datable and the offset
question, so the two guards cannot drift apart.
