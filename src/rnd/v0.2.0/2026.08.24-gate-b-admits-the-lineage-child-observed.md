## ⚠️ The window was narrow — stated because it bears on repeatability

Of 168 samples at 2 s intervals, only **three** caught the monopoly held by this run, and only
**one** of those three also had a child in flight. Two showed the hold with
`inflight_agentic_jobs: 0`.

That is a qualifying observation, not a comfortable one: the admission window is roughly
**six seconds** wide, and a 2 s poll caught it once. A slower poll, or a slightly different
render duration, plausibly misses it — and per this row a miss is a **FAIL, not
inconclusive**. Anyone repeating this should poll faster than 2 s, or instrument the
admission at the seam instead of sampling for it. **The PASS is real; the method is lucky.**

Zero samples showed a foreign monopolizer during the watch, so clause 3 never had to reject
anything here. It stays load-bearing for a busier box.

## Method, and where it departs from the row

- **Substitution, approved and recorded.** The row names `test_presentation_live_smoke.py`;
  this ran `test_presentation_render_only_smoke.py`. Same routing command, same top-level
  `parent_id_hash` read from `LUPIN_TEST_MONOPOLIZE_PARENT_ID`, same lineage probe — so the
  same agentic job on the same path carrying the same tag, and Gate B does not care what the
  child computes. The live file has exactly one scenario and its floor is real LLM spend on
  output nobody reads; render-only skips content generation at ~$0.
- Submitted only via `POST /api/test-suite/submit`, `auto_fix_on_failure=False`. No side door.
- **No re-submit.** A 2-minute shell timeout killed the first watcher; a `--watch-only` mode
  was added to resume against the existing job id rather than start a second monopolizer and
  measure the wrong one. The 60 samples that watcher had taken survived, which is what the
  fsync-per-sample discipline was for.

## Two defects the rig found in itself before it could lie

1. **`monopolize_id` is `ts-<id>::<user-uuid>`, not the documented `ts-{uuid8}`**
   (`src/cosa/rest/routers/test_suite.py:48` is wrong). Clause 3 written as a plain `==`
   against the documented shape never matches → NO QUALIFYING SAMPLE → **FAIL**, condemning a
   Gate B that was working perfectly, on the one row whose whole subject is an instrument that
   cannot see. Fixed to compare the `ts-` half exactly; pinned with six cases including
   somebody else's monopolizer, a hold with no child, and a child with no hold.
2. **`check_idle` read monopoly state and called it emptiness.** It reported `idle: True` on a
   box with `todo total_jobs=7`, `run total_jobs=1`. `AgentBase`/`SolutionSnapshot` jobs run
   inline on the consumer thread, so every pool field stays legitimately zero while the
   consumer is saturated. And the obvious fix is itself blind: `/api/get-queue/*` returns a
   **user-filtered** view carrying `filtered_by` and `is_admin_view: false`, so a non-admin
   zero means "none of mine", not "none at all". Fix spec sent to Cheech, who owns
   `gate-status.py` and the filing.
