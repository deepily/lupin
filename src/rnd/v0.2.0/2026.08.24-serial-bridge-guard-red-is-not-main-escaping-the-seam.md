## Verdict

`register_session.main()` **never writes into the operator's real bridge directory when the seam is set.**
The guard's red is a peer write that the whole-directory fingerprint cannot attribute — the exact
failure mode row `e2ae4102` split the guard into two tiers for.

**The gate is passable.** Three independent lines, none of which is a re-run.

## 1. Instrumented: 40 driven `main()` calls, zero escapes

A `sys.addaudithook` watches every `open`-for-write, `os.rename`, `os.replace` and `os.mkdir`. Any path
under `~/.claude/sessions` is **recorded and raised on**, so a proven escape is blocked rather than
allowed to mutate a colleague.

```
runs=40  completed=40
ESCAPE ATTEMPTS INTO /home/rruiz/.claude/sessions: 0
```

### 1a. The instrument has teeth — falsified, not assumed

A clean result from a blind instrument is worth nothing, so the instrument was made to fail on purpose:
drive `main()` with the seam **unset** and `HOME` pointing at the real home — what a hardcoded-path
regression looks like.

```
FALSIFIER escapes caught+blocked: 1
    /home/rruiz/.claude/sessions/cc-stable-1346801.id
VERDICT: instrument HAS TEETH
```

It caught the escape on the first write and blocked it. The 40-run clean result is therefore meaningful.

## 2. The null control: the guard goes red with the test REMOVED

Run the guard's **own** `real_dir_fingerprint()` twice with **nothing in between** — no `main()`, no test,
only a sleep of the same wall-clock a real test occupies. Any delta is peer noise by construction.

| gap | dirty |
|---|---|
| 2.0 s | **8 / 30 (26%)** |
| 10.0 s | **5 / 6 (83%)** |

and the deltas print the *identical* sentence a real red prints:

```
CHANGED (merged into a live seat): ['cc-1231268.json', 'cc-8845.json', 'cc-listener-b98b9c38.log']
CHANGED (merged into a live seat): ['cc-memory-samples.log']
```

⇒ **A red is reachable with no test in the room at all.** At a 2-second test, roughly one run in four is
expected to go red from peer traffic alone.

### What this does to the row's central argument

The row rests on: *"I hashed `cc-737317.json`, idled 10 seconds with NO test running, and re-hashed.
Identical. ⇒ the write correlates with `main()`, not with the passage of time."*

That control is **one sample of a process that is 83% dirty at that gap**, and it watched **one file**
rather than the directory the guard actually fingerprints. A single clean 10-second window is the
expected outcome for any *individual* file whose owner happened to be quiet; it is not evidence about
the directory. The inference does not survive its own control being run more than once.

## 3. Structural: an escape would name the RUNNER'S OWN bridge, never a peer's

Letting `main()` write into a temp seam and listing what it produces:

```
cc-1346801.json          ← the RUNNING SEAT's cc_pid, not the python pid (1765518)
cc-stable-1346801.id
cc-listener-seam-pro.spawn-lock / .stderr
cc-listeners.log
```

`main()` derives the bridge name from the Claude Code process ancestry — **its own seat**. So a genuine
seam escape deposits `cc-<the runner's own pid>.json`. That is exactly what row `5a68c92c` recorded when
run 1 went red on `cc-16114.json`, *the manager's own bridge*.

`5641d306`'s red named **`cc-737317.json`, which the row itself identifies as Mr. Radio's** — a seat that
was not running the test. **`main()` has no code path that writes a peer's bridge filename.** The named
file was never attributable to `main()`, whatever the timing looked like.
