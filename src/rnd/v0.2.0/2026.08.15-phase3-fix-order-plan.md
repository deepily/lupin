# Phase 3 — fix-order sketch (green the drift guard BY FIXING)

**Author**: Tiberius 👑 · **Date**: 2026-08-15 · **Manager**: Rachel 🕊️
**Gate (§7)**: the guard goes green *by the fixes*, never by loosening. An intentional
drift gets an **explicit exemption carrying a machine-checked `reason` field** — not a
relaxed assertion. So phase 3 has exactly two honest tools: **align the sources**, or
**exempt with a reason**.

The red names 4 failing methods over 5 commands. They are THREE different kinds of fix,
in rising blast radius. Adding a command to the prompt is the only one that changes what
the router can emit — it goes last.

---

## The commands, grounded

- **test fix expediter** (factory + training) vs **test fix expediter resume** (registry +
  training): the factory builds `TestFixExpediterJob` under `test fix expediter`; the
  registry/arg-spec knows it as `…resume`; TFE has a real resume path
  (`resume_resolver.py`). ⇒ **one agent under two names across the four lists** — a
  one-name-everywhere violation, not four separate defects.
- **heartbeat poker** (factory only): builds a fleet-ops job with `RecipientSpec`
  recipients. Not user-voice-facing on its face.
- **bug fix expediter**, **test suite**: owned + factory, but absent from the prompt.

---

## Fix order (low blast radius → high)

**0. Add an exemption-with-reason facility to the guard.** §7 mandates it: a
`{command: reason}` map the assertions consult, with a test asserting every exemption's
reason is non-empty. This is explicit + reasoned, NOT a loosening — it is the sanctioned
way an intentional non-reachable command greens the guard. Needed before steps 3–4 can
land honestly.

**1. KIND 1 — mechanical, NO router-emit change: make the 3 cli_modules runnable.**
Add a runnable `__main__.py` (or correct the `cli_module` path) to `claude_code`,
`bug_fix_expediter`, `test_fix_expediter`. Greens **5′** and kills the §4 defect where
`get_cli_help` caches `"No module named …__main__"` and feeds it to the extraction
prompt. Self-contained, no voice behaviour change. ⚠️ **§7 currently files this as
phase 6** — but 5′ is a phase-2 assertion and stays red until it lands. **Decision D4**:
pull it into phase 3, or accept 5′ stays red until phase 6.

**2. KIND 2a — internal alignment, NO new capability: canonicalize the TFE name.**
Pick ONE name and align registry · factory · training · prompt (one-name-everywhere).
Greens the `test fix expediter` halves of **1b** and **1c**. **Decision D2**: canonical
name, and whether `resume` is a separate command or a mode-arg of one command.

**3. KIND 2b — heartbeat poker: exempt or remove.** Not voice-facing. Either **exempt
with reason** ("internal fleet-ops job, never router-emitted") or **remove its factory
branch** if it is dead from the voice path. Greens the `heartbeat poker` half of **1b**.
**Decision D3**.

**4. KIND 3 — LAST, the only emit-changing step: prompt reachability.**
For each of `bug fix expediter`, `test fix expediter[resume]`, `test suite`, decide
per-command: **voice-reachable → add to the router prompt + training corpus** (this
CHANGES what the router can emit; per §5.4 it is reachable the moment the prompt lists it,
retrain lags for reliability), **or internal → exempt with a reason**. Greens **1a** and
the registry-side halves of 1b/1c. Do this last and per-command because it is the only
change with router-emit blast radius. **Decision D1** (Rick's domain: which are meant to
be user-voice-invocable).
