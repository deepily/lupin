## The defect

`memento_io.pointer_rel_path` returns a **persona-keyed** pointer for the `io` slot and a
**single repo-wide** pointer for the `root` slot:

| slot | record | pointer |
|---|---|---|
| `io` | `io/mementos/<persona>-<sid8>.md` | `io/mementos/<persona>.md` — one per persona |
| `root` | `.claude-memento-<persona>-<sid8>.md` | `.claude-memento.md` — **one for the whole repo** |

So `resolve_record( repo, "root", persona )` never uses `persona` at all. Measured on a
constructed tree holding only Clayton's root record:

```
resolve_record(root, "root", 'clayton') -> .claude-memento-clayton-8002a94e.md
resolve_record(root, "root", 'cheech' ) -> .claude-memento-clayton-8002a94e.md
resolve_record(root, "root", 'rachel' ) -> .claude-memento-clayton-8002a94e.md
resolve_record(root, "root", 'nobody' ) -> .claude-memento-clayton-8002a94e.md
```

`nobody` is a persona that has never existed. **The resolver fails open.**

## Correction to the row's evidence

The row states that asking for `(root, Cheech)` **today** hands you Clayton's record. Run
against the live lupin repo, `resolve_record` returns `None` for **every** persona, Clayton
included. The pointer's `current:` names `.claude-memento-clayton-8002a94e.md`, which does not
exist at the repo root — it is mirror-only — so `target.exists()` is False and the
newest-by-mtime fallback finds no root records at all.

Rachel 50362a46 read the pointer's two header lines and inferred the resolution; she did not
run the resolver. **The defect is real in code; the demonstration does not reproduce through
that door.**

## The harm is reachable without the resolver

`.claude-memento.md` is **13,354 bytes**. It is not a stub that names a record — `pointer_text`
copies the record's whole body into it. Its first content line today is:

```
# Memento — Clayton 😎 · session 8002a94e · 2026-08-23 evening
**Role**: adversarial reviewer for Cheech 🌿 (manager 626cd9c3)
```

So a spawn brief saying *"read `.claude-memento.md`"*, an inherited instruction, a `cat`, or a
`seed_memento` pointed at that name **hands the reader Clayton's entire memento right now**,
with no resolver involved and nothing to fail closed. Fixing `resolve_record` alone would leave
that path exactly as it is. That is why the fix here sits at the **reader**, not at the pointer.

## Why it wore a green

The re-spin wake check (row `b0570b67`) reads a boot receipt naming the file the successor
actually opened. Its ladder: `DEAD_NO_WAKE` → `SEED_NOT_CONSUMED` → `STALE_SLOT` →
`STALE_MEMENTO` → `RETURNED`.

Walk the Clayton case through it. It booted. It resolved a memento. `root` is a live slot. The
record was written inside the freshness window. ⇒ **RETURNED. No alarm.**

**Every rung asks about the FILE — is it live, is it current. None asks about the READER.** So
the one failure where a successor is confidently and coherently wrong is the one that passes,
and a manager who reads RETURNED stops looking. A silent gap invites a look; a green forbids one.

## What shipped (lupin only)

1. **The receipt carries the record's own claim.** `build_receipt_dict` / `write_boot_receipt`
   gain `memento_persona` — who the FILE says it belongs to, beside `persona`, who the SEAT is.
   `register_session._build_memento_block` fills it from `_persona_of( path, header )`, the same
   header-then-filename rule the resolver used to pick that file, so the receipt cannot disagree
   with the decision it records.
2. **`WRONG_PERSONA`**, asked in `classify_wake` **before** the slot and age questions — a record
   can be live and current and still be somebody else's, and identity is the finding the manager
   needs first. The shape is borrowed from `reap_memento.verify_seat_memento`, which already
   refuses *"a prior holder's memento in this slot"*; this is the same question, moved to where
   the reader is.
3. **`persona_slugs` returns a SET, and a mismatch means DISJOINT.** The two writers in this
   fleet disagree about accents: `memento_io.slugify` turns "María" into `mar-a`,
   `register_session._persona_slugs` folds first and gets `maria`. Both spellings exist on disk
   (18 records under `maria`, one under `mar-a`). Reducing each side to one canonical slug would
   have reported a live roster persona as an impostor every time she re-spun. **This was caught
   in my own first cut and corrected before it shipped.**
4. Unknown is never an alarm. A record that does not say whose it is, a seat with no allocated
   persona, an emoji-only name — none can be *proven* crossed, and inventing an alarm out of an
   absent measurement is how a check earns its way into being ignored.

## What is NOT fixed, and belongs to whoever owns `memento_io.py`

- `resolve_record` still ignores `persona_slug` for the root slot. Untouched per Cheech's
  ruling — that file is shared by every project.
- The root pointer is still one file for a repo whose records are persona-keyed (the row's
  option 1, which costs a migration and every reader of the fixed name).
- **A plain `cat .claude-memento.md` is still unguarded.** Nothing in code can refuse a human
  read. The `WRONG_PERSONA` verdict catches the successor *after* it has rehydrated; it does not
  stop the read. That gap is the argument for option 1.
