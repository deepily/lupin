## Things a successor will get wrong without being told

**`is_bare_identifier` and `is_bare_row_id` are not interchangeable, and the difference is a
precondition.** `is_bare_identifier( token )` means "no slash and no dot" and is only sound on a
token **already matched by `_POINTER_TOKEN`** — given one, that test can only be the 8-hex shape.
I called it on the raw path slot value, where it degenerates into exactly that test and eats
`Makefile`, `README`, `LICENSE`, `Dockerfile`, `src`, `io` — three of which are tracked files here.
María caught it. **Borrowing a filter across the line where its precondition holds is how a narrow
guard silently becomes a wide one.** Raw strings use `is_bare_row_id`, which is anchored and asks
the question directly.

**`pointer_tokens` must NOT be narrowed in place.** It is also the body of the whole-line structure
rule `_ATTACHMENT`, so narrowing it moves the *sentence counter* — a delivered id line would start
counting as a claim and a repaired message could re-trigger the tutor. The restore path gets its
own narrower selector (`restorable_pointers`); the counter keeps seeing all four pointer shapes.
**Widening `_ATTACHMENT` is the safe direction** (it adds a structure shape); narrowing
`pointer_tokens` is not.

**A "measured" claim about a big suite means a set-diff, not a resemblance.** `befeba88`'s receipt
is 23 failed / 25058 passed on the branch against 23 failed / 25047 on a detached baseline at the
same parent, with `comm` on the sorted FAILED lists empty **in both directions**; the +11 passes are
exactly the new tests. The 23 are environment-shaped — bounce-script (12), vertex/`cloud-run.env`
(9), gate census (1), terraform (1). Do not re-litigate them.

**Failure counts are per-selection and two honest numbers can disagree.** I reported 4 env failures
over `tests/unit/*dm*.py` + `dm_compression`; María reported 5 over a wider set reaching the phi4
and flash-lite marker files. Neither was wrong. Say which selection produced a number.

**Background pytest runs get killed by the harness (exit 144).** Two full sweeps died that way with
no partial output. What worked: `nohup python -m pytest … > logfile 2>&1 &` — detached, writing
progressively, so a kill leaves evidence.

## Facts about mock auth worth not re-deriving

- `verify_mock_token` now returns a **uuid5 minted from the RESOLVED email** as `uid`/`user_id`/`sub`
  (`email_to_user_uuid`, fixed namespace constant, no table). The **system id is unchanged** and is
  still what `get_user_info` is keyed on.
- **`email_to_system_id` is not a round trip** — it appends its own 4-hex suffix. So
  `…_8e32@generated.local` resolves to system id `…_8e32_7cf9`, and the legacy `mock_token_<id>` and
  email `mock_token_email_<addr>` forms reach **different users**. Pre-existing; the test asserts it.
- Only `AUTH_MODE=mock` was ever affected — the v1 baseline arm's launcher. `:7999` and `:8000` run
  JWT, where the user id is already a UUID (Tiberius verified this on the row).

## Working practices that earned their keep again

- **Red-on-revert, actually run, with the observed text in the commit message.** Every behaviour
  claim this sitting names its arm and its failure string.
- **The inverse control is the one that catches over-reach.** The suppression tests would have
  stayed green through every widening; `Makefile` in the delivered set is what went red.
- **A test that does not bite is not a test.** `test_a_two_path_restored_line_is_still_STRUCTURE`
  first asserted `claims_out <= trigger` — with 3 claims under a trigger of 4, a line that *did*
  count still slipped under. Tightened to `assertEqual( claims_out, count_sentences( rewrite ) )`.
- **Name the residue instead of quietly leaving it.** I excluded hyphen/underscore from the strip
  set and said so; María ruled it wrong on a better argument (a real name carrying either has an
  extension, so it can never reach the anchored pattern) and I took the ruling. Disclosure is what
  made that a two-minute exchange instead of a later bug.
