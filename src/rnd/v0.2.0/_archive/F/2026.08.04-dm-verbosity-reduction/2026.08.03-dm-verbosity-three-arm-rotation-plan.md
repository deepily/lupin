## 2. The three arms

Nothing modifies a message. No truncation, no summarisation, no rewriting.

| Arm | Judge runs | Sender is told | Delivered |
|---|---|---|---|
| **graded** | yes | grade rides back on the send result | yes |
| **blind** | yes | nothing; `quality` key absent | yes |
| **rejecting** | yes | descriptive over-length error | **no** |

The judge runs in all three — blind withholds the result rather than skipping the
measurement, so instrumentation is identical everywhere and only feedback varies.

## 3. Assignment: the clock decides, nothing is stored

```python
ARMS       = ( "graded", "blind", "rejecting" )
EPOCH_DATE = date( 2026, 8, 3 )

def current_arm( now=None ):
    """
    Resolve the live experiment arm from wall-clock time alone.

    Requires:
        - now is a datetime, or None to read the system clock

    Ensures:
        - returns exactly one of ARMS
        - identical across every process at the same instant, with no shared state
        - rotates hourly; the daily offset makes each arm visit every hour of the
          clock across a three-day cycle
    """
    now       = now or datetime.now()
    day_index = ( now.date() - EPOCH_DATE ).days
    return ARMS[ ( now.hour + day_index ) % 3 ]
```

**Why stateless**: `:7999` went through 24 boots on 2026-08-03 alone. Any in-memory
rotation counter resets on every bounce. A clock-derived arm is correct the instant
a process starts and needs no coordination between the REST app, the arbiter, and
the MCP server.

**Why the daily offset**: 24 ÷ 3 = 8 exactly, so a plain `hour % 3` pins each arm to
the same eight hours forever — perfectly confounding arm with time of day, which is
the thing rotation exists to prevent.

| Hour | Mon | Tue | Wed |
|---|---|---|---|
| 14:00 | graded | blind | rejecting |
| 15:00 | blind | rejecting | graded |
| 16:00 | rejecting | graded | blind |

## 4. ⚠️ The unit of randomization is the HOUR, not the message

The arm is server-wide: every session in a given hour is in the same condition, and
messages inside an hour share workload, participants, and circumstance. **They are
not independent observations.**

| | Naive | Correct |
|---|---|---|
| Effective n per arm | ~530 messages | **~20 hours** |
| Detectable difference in median length | 10 words (~2.9σ) | **~15 words (~2.4σ)** |

The analysis must cluster standard errors by hour, or use the hour-median as the
observation. Treating messages as independent produces confident-looking
significance that isn't there.

**Within-hour tests keep message-level power** — the exposed-vs-unexposed comparison
in §7 lives inside a single hour, so it isn't affected by this.

## 5. Labelling: a row declares what it is

Classification must never depend on a timestamp cutoff. A deploy that slips, a
bounce that delays, or an override flipped for a demo would silently misfile rows.

| Era | `arm` | `experiment` |
|---|---|---|
| Pre-flag (36 rows) | *absent* | absent |
| Baseline (740 rows) | `signal_only` | absent |
| Rotation | `graded` \| `blind` \| `rejecting` | `three-arm-v1` |

The three new words appear nowhere in the existing corpus, so the vocabularies are
disjoint and classification is a lookup:

```python
def classify( row ):
    """
    Ensures:
        - a row's own fields determine its bucket; no timestamp arithmetic
        - anything without a rotation label is baseline, whenever it was written
        - a missing `outcome` reads as `accepted` — true by construction, since the
          writer only ever ran post-delivery and no reject path existed
    """
    arm = row.get( "arm" )
    if row.get( "experiment" ) == "three-arm-v1" and arm in ARMS:
        return arm, row.get( "outcome", "accepted" )
    return "baseline", "accepted"
```

### The existing 776 rows

**Do not backfill.** Absence of `outcome` is not missing data — the writer sat after
delivery and no reject path existed, so every existing row *is* an accepted
delivery. Defaulting at read time is factually correct; rewriting would destroy
provenance (a stamped and an inferred value look identical afterwards) and risks
losing rows to a concurrent append, since the file is live.

Those rows are **baseline, not a fourth arm**. Use them for the reference length
distribution, the predicted-refusal-rate maths, and the "before we did anything"
story. Never pooled with rotation hours.

## 6. Log the attempt, not the send

Today the corpus writer sits *after* delivery. A refused message would never reach
it — so the rejecting arm would record only messages short enough to pass, and its
average would fall for reasons having nothing to do with restraint. Survivorship
bias: measuring the bombers that came home.

**The row is written before the length check**, carrying `outcome` of `accepted` or
`rejected`. Two honest numbers per hour: attempted, and delivered.

No attempt is linked to any follow-up send. If a sender chooses to shorten and
resend, that is ordinary fleet behaviour and appears as its own row.

### Row schema additions

```json
{ "arm": "rejecting", "experiment": "three-arm-v1",
  "reject_threshold": 150, "outcome": "rejected", "words": 187, ... }
```

`reject_threshold` is written on **every** row including graded and blind ones,
recording the threshold that *would* have applied. Without it the dose-response
curve isn't reconstructable, and predicted-vs-observed refusal rate can't be
computed for the non-rejecting arms.

## 7. Measuring the effect

### 7.1 Primary outcome (pre-registered)

**Median attempted words per hour, compared across the three arms.** One number.
Everything below is exploratory and labelled as such.

### 7.2 Adaptation within a rejecting hour

Since rejections aren't linked to retries, "% accepted first try" is *mechanically*
1 − refusal rate — arithmetic, not a result.

**The interpretable version: observed refusal rate vs. the rate the baseline
distribution predicts.** At 150 words the baseline predicts 15.4% refused. If the
hour comes in at 15%, nobody adapted. At 9%, sessions shortened inside the hour —
and that gap is the effect, needing no retry tracking.

### 7.3 Carryover — difference-in-differences on session exposure

In the hour *after* a rejecting hour, split senders by whether they were refused:

| | Hour N (rejecting) | Hour N+1 |
|---|---|---|
| **Exposed** (≥1 refusal) | A | B |
| **Unexposed** | C | D |

Effect = **(B − A) − (D − C)**.

Exposed sessions are by definition the long writers, so comparing B to D directly
would confound "was refused" with "writes long anyway." Comparing each group's
*change* removes it — unexposed sessions absorb whatever else shifted.

### 7.4 Event study

Align each session's messages on its first refusal; plot mean length at −3, −2, −1,
+1, +2, +3, +5, +10. Gives the **half-life** of the lesson. *"The effect lasts about
four messages"* is a more useful sentence than *"there was an effect."*

### 7.5 Re-spin as a natural eraser

A re-spun session reappears under a **new session id** with no memory. Compare a
persona's last messages under the old id against its first under the new one. If
length reverts exactly at the boundary, the effect is carried by context memory
rather than anything environmental.

Churn measured from the corpus — this population exists:

| | |
|---|---|
| Distinct sessions | 24 |
| Median session span | 149 min |
| Sessions spanning >60 min | 19 of 24 (**79%**) |
| Sessions with ≥5 messages | 19 |

### 7.6 Null-result guard

| Finding | Means |
|---|---|
| No shortening even *within* the rejecting hour | treatment never landed — check per-session refusal counts |
| Shortened during, reverted after | real but transient |
| Shortened during and stayed short | durable learning |

These are only separable if the within-hour measure is taken as well as the after.

## 8. Dose-response ladder

Stepping the threshold in 25-word increments turns one data point into a curve.
Exposure per dose, from the baseline distribution (busy hour ≈ 81 DMs, ~5.9 active
seats, ~14 DMs per seat per hour):

| Threshold | Refused | Rejections/hr | Per seat/hr | **Seats hitting ≥1** |
|---:|---:|---:|---:|---:|
| 250 | 2.7% | 2.2 | 0.37 | **32%** |
| 225 | 4.1% | 3.3 | 0.57 | 44% |
| 200 | 5.9% | 4.8 | 0.82 | 57% |
| 175 | 9.0% | 7.3 | 1.24 | 73% |
| **150** | **15.4%** | 12.5 | 2.11 | **90%** |
| 125 | 26.5% | 21.5 | 3.64 | 99% |
| 100 | 45.3% | 36.7 | 6.24 | 100% |

**The last column decides where to start.** At 250, two thirds of seats never see a
refusal in their hour — the treatment wasn't administered, so a null tells you
nothing. **Recommended sequence: 150 · 125 · 175 · 200 · 100**, anchored where the
treatment lands, reaching up to confirm the curve flattens and down to find where it
breaks.

**Shuffle the order.** A monotonic walk downward confounds dose with elapsed time,
and the fleet is also accumulating experience over those same days. Repeat at least
one dose late that also ran early; if the repeat matches, time isn't driving it.

**Not the current mean (101 words)**: 44% refusal, ~37 rejections per seat per day.
That jams coordination during rejecting hours and spills the disruption into
neighbouring hours, which are the other two arms. That spillover is a genuine
confound. It also makes the design data-dependent — threshold derived from the very
outcome being measured — which hurts replication.

## 9. Threshold disclosure

**Reject with direction, not a number**: *"DM refused: too long. Cut it
substantially and resend."*

Publishing "150 words" invites 149-word messages — the number becomes the target
instead of the ceiling. But a rule with no signal leaves a sender unable to judge
how much to cut, so it guesses, and guessing costs tokens. Directional wording gives
something actionable without handing over a number to hug.

Configurable via `dm reject disclose threshold` so it can be revisited without a
code change.

## 10. Known limitations — state these on Thursday, don't wait to be asked

1. **Context clears are invisible.** Session ids survive `/clear` by design ("stable
   session IDs survive context clears via write-once atomic lockfile"). A cleared
   session looks identical to a remembering one, so it counts as "exposed, didn't
   learn" when it remembers nothing. **The error has a known direction: it can only
   pull measured carryover toward zero.** A positive carryover finding is therefore
   trustworthy — it survived the dilution. A null one is ambiguous and must be
   reported as "lower bound, unknown dilution," never as "no learning."
   *Cheap fix if it can land*: the SessionStart hook already fires on a clear —
   append a marker row (`event: "context_cleared"`), and exposure can be invalidated
   at the first clear after a refusal.
2. **The graded arm's feedback is barely informative.** `len_grade` correlates
   −0.957 with word count and matches the config buckets exactly on all 776 rows —
   it is a lookup table, not a judgment, and `overall` inherits that at −0.748. If
   graded shows no effect, the rival explanation is that *this* feedback carried no
   information the sender didn't already have. Improving the judge is separate work.
3. **The fleet isn't blind.** Sessions read CLAUDE.md, broadcasts, and this very
   document. Contamination applies equally to all three arms so it can't manufacture
   an effect, but it limits what the numbers say about ordinary operation.
4. **One hour may be too short.** A seat sends ~14 DMs per hour and, at 150 words,
   meets ~2 refusals. Enough to notice, probably not enough to change habits. *"One
   hour of refusals doesn't change behaviour"* is not the same claim as *"refusals
   don't work."*
5. **Workload mix.** Every seat is the same model, but a session writing revision
   handoffs writes long and one doing coordination writes short. Hourly rotation
   spreads that across arms; per-sender medians within arm are the check.
6. **One fleet, one operator.** External validity unknown.

### Predictions on record (before the data lands)

- Rejecting shows a visible **within-hour** dip
- Graded shows little or nothing
- Carryover into the following hour is weak and decays within a few messages

## 11. Safety valve

A refused DM is a **dropped coordination message**. If a bounce warning, a hold
order, or a stop-work instruction runs long during a rejecting hour, it silently
does not arrive.

**Recommendation: exempt broadcasts and manager-seat messages from rejection.** The
messages most likely to be both long and critical are exactly the coordination ones.
Alternative is a bypass token the sender sets, but that invites routine use.

## 12. Configuration

```ini
# Three-arm DM verbosity rotation (2026-08-03). Empty = rotate hourly by clock;
# set to graded|blind|rejecting to PIN one arm — for demos, where a live talk
# should not be at the mercy of whatever hour it happens to be.
dm experiment arm override         =

# Word count at or above which a send is refused in the rejecting arm. Separate
# from the GRADING thresholds on purpose: the point at which we refuse need not
# be the point at which we mark a message verbose.
dm reject threshold words          = 150

# False = refusal says "too long, cut it substantially" with no number.
# True = the refusal names the threshold. See §9 for the trade-off.
dm reject disclose threshold       = False

# Exempt broadcasts and manager-seat sends from rejection (§11 safety valve).
dm reject exempt coordination      = True
```

`dm reject on overage` becomes redundant — the arm decides. Leave it in place,
ignored, with a comment pointing here.
