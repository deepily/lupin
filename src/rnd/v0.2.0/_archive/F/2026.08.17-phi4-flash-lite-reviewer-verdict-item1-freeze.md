## B1 — BLOCKING. The guard inside `freeze()` cannot fire in the real shape, and the test that appears to cover it feeds a fabricated live path.

`freeze()` calls `assert_snapshot_is_not_live( snapshot_path, live_path=source )` at
`freeze_corpus.py:364`, where `snapshot_path` is always `<out_dir>/dm_replay_frozen.jsonl`
(`:360`) and the live corpus is always `<dir>/dm_traffic.jsonl` (`CORPUS_FILENAME`, `:46`,
`:76`). **The two basenames can never be equal**, so the comparison at `:98` can never be true.

Ran it, in the production shape — a directory holding `dm_traffic.jsonl`, with `--out-dir` aimed at
that same directory:

```
live dir contents BEFORE: ['dm_traffic.jsonl']
!! freeze() did NOT raise — guard did not fire
live dir contents AFTER : ['dm_replay_frozen.jsonl', 'dm_traffic.jsonl', 'manifest.json']
```

The snapshot and manifest were written **into the live corpus directory**. The guard did nothing.

`test_freeze_refuses_to_write_over_the_live_corpus` (`:109`) passes anyway, because it hands
`freeze()` a `live_path` of `live_dir/dm_replay_frozen.jsonl` — it tells the function the live corpus
is named after the snapshot. Its own comment says so out loud: *"The snapshot name differs from the
live name, so this is NOT the case the guard catches."* A test that has to misstate the input to go
green is not covering the behaviour in its name.

**Ask**: the guard that §7 item 1 demands is on the **read** side — the replay harness must refuse a
live-path input. Wire `assert_snapshot_is_not_live` into the harness's corpus argument (item 2), and
either give `freeze()` a real write-side check (refuse when `out_dir` resolves to the live corpus's
directory) or drop the call and stop implying it protects something.

## B2 — BLOCKING. R2 says compare `(st_dev, st_ino)`; the code compares realpath strings, and the bind-mount R2 was written for is live in this repo.

`freeze_corpus.py:95-98` compares `os.path.realpath` **text**. Plan §1.2a R2 is explicit: *"Normalise
with `os.path.realpath` and compare `(st_dev, st_ino)`, not text. A symlink, a relative path, a
trailing slash, or a bind-mount alias all defeat a string compare while pointing at the same growing
file."*

Symlink and `..` are covered by realpath, and the tests prove those two. **The bind-mount alias is
not**, and it is not hypothetical: `docker-compose.yml:163` mounts
`/mnt/DATA01/…/projects-data/lupin/dm-corpus` at `/var/lupin/dm-corpus`. The same file has two names
that no amount of `realpath` will reconcile, because each is already canonical in its own namespace.
Anything running in the container, or any caller who passes the container path, walks straight past
this guard and reads the growing corpus.

**Ask**: `os.stat( … ).st_dev, st_ino` on both sides, as written. Handle the not-yet-existing snapshot
path (stat raises) explicitly rather than by falling back to a string compare.

## B3 — BLOCKING. A zero-row freeze succeeds, and `--verify` calls it OK.

Nothing in `freeze()` requires the frozen set to be non-empty. Ran it on 500 rows that are all under
the trigger:

```
source_row_count  : 500
snapshot_row_count: 0
freeze raised?    : no — it returned a manifest for an EMPTY replay set
verify_snapshot   : True | snapshot matches manifest
```

The paths into this are real, not contrived. `count_claims` (`:198-202`) catches bare `Exception` and
returns 0, so any breakage in the claim counter marks **every** row ineligible; `eligible_only`
defaults to True (`:340`); `select_eligible` then returns `[]`. The study's input becomes an empty
file, the manifest records it as a clean freeze, and the verifier agrees.

**Ask**: `freeze()` raises when `len( rows ) == 0`, and `verify_snapshot` fails a zero-row snapshot.
A pre-stated minimum row count in the manifest would be better still — the discordant floor (§3.1)
implies one.

## B4 — BLOCKING. Coverage is not measurable for this module, so Convention 6 cannot be evidenced.

The module lives in a **dashed directory** (`src/scripts/phi4-flash-lite-study/`), which is not an
importable package, and the test loads it through `importlib.util.spec_from_file_location`
(`test_phi4_flash_lite_freeze.py:25-31`). Coverage never sees it. Both ways of asking:

```

coverage run --branch -m pytest … ; coverage report               → No data to report.
```

Convention 6 is 100% lines AND branches AND functions on new code. Right now the number is
unobtainable, and the `# pragma: no cover` markers at `:33`, `:36`, `:416`, `:442` are decorative —
nothing measures what they exclude. `main()` in particular takes `argv=None` **specifically so it can
be tested**, then excludes itself.

**Ask**: put the module where it can be imported (underscored package under `src/cosa/` or
`src/scripts/phi4_flash_lite_study/`), import it normally in the test, and show the coverage number.

## Nits — not blocking

- **N1** — `count_claims` (`:198`) re-implements the router's `_count_claims` (`dm.py:1097`) rather
  than importing it. The module's own docstring makes exactly this argument for the resolver twelve
  lines earlier: *"a copy is a thing that drifts, and a drifted copy is a guard that stops guarding."*
  Same reasoning, same file, one function later. Import it.
- **N2** — `source_sha256` is computed at `:366` and the rows are read at `:367`. On a file growing
  ~5 rows/min (§1.2) the digest need not describe the bytes that were actually read. Read once, derive
  both — or checksum again afterwards and refuse on a mismatch.
