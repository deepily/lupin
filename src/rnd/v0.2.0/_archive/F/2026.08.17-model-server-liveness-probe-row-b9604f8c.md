# A dead model server now refuses the run at second one, naming the port

**Row**: `b9604f8c` (P2) · **Found**: 2026-08-17 the hard way · **Fixed**: 2026-08-17 by John 🏄🏽
**Manager**: Mr. Radio 🦉 (`e251aa88`) · **Sibling row**: `73c6819d` (the same defect in a different coat)

---

## Verdict

The outage was fixed the same day; the DETECTION was not. A run would start against a dead
dependency, spend hours, and fail with a message three layers from the cause. It now probes
every model-server port the configuration names — before the first question, and again
between the passes — and refuses naming the port that did not answer.

---

## 1. What happened

The Ministral-8B router at `192.168.1.21:3000` went down. Port `3001` (Phi-4) stayed up, so
the box answered any casual check and looked alive. The paired run kept calling and failing,
and the outage surfaced only when a **three-hour job died on it**.

**Half-alive read as alive.** That is the mechanism, and it is why "probe the model server"
is not the fix — "probe EVERY port the run will dial" is.

## 2. The probe

`src/cosa/utils/model_server_liveness.py`.

| Function | What it does |
|---|---|
| `discover_vllm_endpoints( config_mgr )` | sweeps the config for every `vllm://host:port@model` spec and returns the distinct set — a new endpoint in `lupin-app.ini` is probed without anyone updating a list here |
| `probe_endpoint( endpoint )` | `GET /v1/models`; never raises; returns what the endpoint did **in words** |
| `require_live( … )` | refuses unless every endpoint answered, naming the dead ones first and the live ones after |

**Every failure shape gets its own wording**, because "port closed" misses every way a
server stays up and stops working:

| What the endpoint did | What the probe says |
|---|---|
| nothing listening | `did not answer at … (Connection refused)` |
| accepted, then silence | `did not answer at … (timed out)` |
| HTTP 503 (or any error status) | `answered HTTP 503 at …` |
| 204 / a non-200 that is not an error | `answered HTTP 204 at …` |
| something that is not vLLM | `answered at … but not with a model list` |
| serving | `serving ['kaitchup/Phi-4-…']` |

When some ports answer and some do not, the refusal **says so explicitly** — the live ones
are listed under the dead ones, with a line naming the half-alive trap. A reader who sees
only "the model server is down" goes looking for a box that is, in fact, mostly up.

## 3. Where it fires — and the mid-run question the row asked me to decide

**Run start AND once between the passes.** A three-hour run can outlive its dependency: the
box can die at minute ten as easily as before minute zero. The pass boundary is the cheapest
point where a mid-run death is still catchable, and it protects the expensive half.

| Call site | When |
|---|---|
| `v2_eval.main` | before the cold pass — injected as `probe_models_fn`, so the unit tier never opens a socket |
| `v2_eval.main` | again between the cold and warm passes |
| `test_v2_paired_live.py` | precondition 2b, beside the isolation and pinned-tree guards, via the module-level `_require_model_servers_live` seam |

Not wired into per-request paths: a probe on every call is a second failure mode, and the
run-level guard is where the hours are.

## 4. Receipts

**14 tests** in `src/tests/unit/test_model_server_liveness.py`, on **real sockets** — live
arms run actual HTTP servers on ephemeral ports; dead arms point at a port bound-then-released
so nothing is listening. **100% lines and branches** (64 statements, 18 branches).

| Arm | Result |
|---|---|
| a port genuinely not listening | refuses, names it |
| **half-alive pair (the incident)** | refuses, blames only the dead port, reports the live one, warns about half-alive |
| a live pair | **proceeds**, reporting which models answered |
| accept-then-silence | named as a timeout, not as "closed" |
| HTTP 503 · HTTP 204 · a non-vLLM responder | each named distinctly, none counted alive |
| two dead ports | both named — it does not stop at the first |
| nothing to probe | refuses; an empty list cannot prove a live dependency |

**4 call-site tests**: `v2_eval` refuses **before a single question is asked** (the control
asserts zero questions went out), probes twice in the right order, and the paired bridge
refuses before either arm measures anything and is handed the run's own config object.

## 5. Collateral found by the frozen-tree tier, and fixed

Five tests in `src/tests/unit/test_v2_eval.py` injected a client but not the git-sha reader,
so a **unit** test dialled the real `:8000` over the network. They passed whenever that
server was free and went red for ten seconds of socket timeout whenever it was busy — it
was busy, holding a monopolize-mode paired run. The verdict had nothing to do with the code
under test.

The reader is now injected. The accidental network call **was** the only thing exercising
the sha path in that file, so it was replaced deliberately rather than deleted: the reported
sha must reach the provenance record, and a server that cannot identify itself must stop the
run. Same shape as this row — a test that reports on something it is not measuring.

## 6. What this does NOT do

- **It does not check that the right MODEL is loaded**, only that the endpoint is serving
  and says what it serves. A probe that can fail several ways needs diagnosing itself.
- **It does not probe the lupin-model-server** (embeddings, STT) — a different dependency
  with a different URL, worth its own row if it ever costs an hour.
- **It cannot catch a death between the last probe and the end of the warm pass.** The
  window is bounded, not closed; closing it entirely means probing per request, which buys
  a new failure mode for a shrinking gain.
- **The second defect the row records** — that a worker cannot file a `blocked` row without
  a manager round-trip — is untouched here. It is a store-permissions design question, not
  this fix.
