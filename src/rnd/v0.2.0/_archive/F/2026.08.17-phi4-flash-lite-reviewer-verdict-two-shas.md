### 🔴 NEW FINDING — the doc-viewer blocklist does not block the ADC filename

`.docview.yml` allows **anything under `src/`** (`allowed_prefixes: - src/`), and `.json` is a
served type. The universal floor blocklist is supposed to be the backstop. It is not, for this file.
Ran `_is_secrets_path` directly:

| path | result |
|---|---|
| `credentials.json` | **BLOCKED** |
| `application_default_credentials.json` | **SERVED** |
| `.config/gcloud/application_default_credentials.json` | **SERVED** |
| `src/conf/keys/application_default_credentials.json` | **SERVED** |
| `service-account.json` | **SERVED** |
| `sa_key.json` | **SERVED** |

**Why**: the pattern is `\bcredentials?\b` (`_scope_registry.py:81`). In
`application_default_credentials.json` the character before `credentials` is `_`, which is a word
character — so there is no word boundary and the pattern does not match. The bare name matches; the
real ADC filename does not. `.aws`, `.ssh`, `.kube`, `.docker` are blocked as directory segments;
**`.config` and `gcloud` are not**.

**Two things follow, and only the first is about Sam's change:**

1. **Mount the ADC file OUTSIDE `src/`** — `/root/.config/gcloud/application_default_credentials.json`
   is where the SDK looks anyway, and nothing under `/root` is in a served scope. Mounting it under
   `src/conf/keys/` (an existing credential mount point, `docker-compose.yml:81`) would put a live
   Google credential inside a path the doc viewer serves.
2. **Independently, add the missing patterns to the floor blocklist** — `application_default_credentials`,
   `service[-_]account`, `\.config$`, `gcloud`. This is pre-existing and not Clayton's or Sam's doing;
   `src/conf/keys/gemini` is already SERVED by the same gap. Worth its own row.

### Four more criteria for the mount, when the diff arrives

- **Blast radius**: `:8000` runs *every* scheduled suite. ADC there gives all of them the ability to
  spend on Vertex, not just this study. Name what stops an unrelated suite from billing.
- **Read-only** (`:ro`) and a named teardown — plan §3.2 requires owner + teardown for anything
  permanent, and this is a credential on a shared box.
- **`restart` ≠ `--force-recreate`**: mounts resolve at container CREATE. A plain restart applies this
  silently-not-at-all, and the arm would fail for a reason nobody would look for.
- **Project confirmation**: `resolve_gcp_project_id()` returns `hello-world-foo-423219` **with
  `LUPIN_GCP_PROJECT_ID` unset in the shell** — it fell back to the gitignored
  `src/scripts/cloud-run.env`. A container that does not inherit that file resolves differently or
