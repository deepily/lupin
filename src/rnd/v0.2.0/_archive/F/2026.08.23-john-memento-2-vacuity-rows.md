## The single most useful thing I learned today

**"Is it collected?" belongs in any test-hygiene sweep from the start, next to "does it exist?"**

`beffcddd` was filed at 51 items on my number. Six of them run. My detector checked that a
function was named `test_*` in a file named `test_*.py` — it never checked that pytest could
**collect** it. That is an 8× overcount, and it would have sent the next person to fix 45
things that cannot bite.

Fixed in `927076a4`: the tool now runs `--collect-only` per file, splits **ACTIONABLE** from
**NOT RUN BY PYTEST**, and exits non-zero only on ACTIONABLE.

⇒ 🔴 **AND THAT FIX CREATED THE TRAP THAT `9d5fd628` IS BUILT AROUND.** "Not collected by
pytest" is **not** the same question as "does not run". The 36 de-poison functions are dead by
both measures. The 9 in `9d5fd628` are dead by one and **alive** by the other — they execute
through `run-lupin-smoke-tests.sh`, which invokes each file as a script and reads its exit
code. My own detector will park them in its NOT-RUN section and stay green. **Do not let a
clean detector run talk you out of that row.**

## The method, and why it is not optional

**Mutate + assert-the-edit-landed + run must be ONE command.** Two steps, and a *failed edit*
produces a green that reads as "the test does not bite" when nothing was ever mutated.

Tally across both rows, one day:
- Pocholo: 5 false greens on the parent row.
- Me: 1 (mutation G — my *test* was blind, not the code).
- **Cheech: 4** — a `_audio_group_id` typo, an anchor matching two sites, a check run against
  the wrong module, and on `beffcddd` a first mutation aimed at the **ExpatError** arm when the
  six ride the **ValidationError** arm. That last one would have had him report my six as
  blunt. He volunteered all four unprompted.

⇒ **A green mutation usually means a broken mutation, not a blunt test.** Verify the mutation
landed before believing what the run tells you.

## The pattern that paid four times

**A weak test sitting beside a justification that does not survive being checked.**

| Excuse | Reality |
|---|---|
| "to avoid mocking the full FastAPI endpoint" (TFE dead-queue pair) | the endpoint takes its four queues as ordinary arguments |
| "inspection rather than a full live push/poll because in-memory dead queue state is wiped on every uvicorn reload" | same endpoint, same non-problem |
| "We can't easily test this without mocking" (`_patch_code_in_response_dict`) | reads two file helpers and indexes a list; two patches and it drives |
| `assert False, "should have raised"` + `except Exception: pass` | reads as rigour, catches its own assertion |

⇒ **When a test explains why it is weak, check the explanation.** Expect this in `9d5fd628`.

  bring it to Cheech. It is a finding with its own row.
- **Venue matters.** These run against a live server. Route by the CLAUDE.md rubric, not the
  folder name — anything mutating persistent state or over 2 minutes goes to `:8000` via
  `/api/test-suite/submit`, never `:7999`.
- The runner is `src/tests/run-lupin-smoke-tests.sh`. Each module's `main()` returns a bool
  and `sys.exit( 0 if result else 1 )` carries it. That exit code is the seam a mutation has
  to move.
- **Narrow your exception types.** On `beffcddd` I replaced `assert False` / `except Exception`
  with `pytest.raises( XMLParsingError )`, not `raises( Exception )` — a bare `Exception`
  passes on a `TypeError` from a bad signature, going green while proving the parser was never
  reached. Replacing a weak test with another weak test is the live failure mode.
