## The recipe

### Before you start — 3 checks, one minute

```bash
docker exec lupin-rest-dev claude -p PONG          # expect PONG. no PONG = no podcast, stop here
docker inspect -f '{{.State.StartedAt}}' lupin-rest-dev   # must be AFTER the bounce
```

Then **hard refresh the browser** — `Ctrl+Shift+R`, not F5 — and **log in as yourself**, not a test
account. The approval prompt routes to whoever authenticated; a service account has no browser and the job
stalls waiting for an answer that can't arrive.

### The run

| # | Do | Expect |
|---|---|---|
| 1 | Q&A card, Agent Mode left at **System (Auto-Route)**, click 🎤 | — |
| 2 | Say **"make me a podcast"** — nothing after it | Routes to the file reader. **Do not name the topic here** — that is what breaks it |
| 3 | Confirm menu | Pick **"Doc-to-Pod (create a podcast from an existing document)"** |
| 4 | It asks **"which document?"** | This prompt appearing is the demo *working* |
| 5 | Say **KISS** | Resolves to your explainer. Proven |
| 6 | Language question | Should now pre-fill **`en`**. **Accept it — do not say "Spanish"**, which would override it |
| 7 | Approval gate → render | ~7 min. Click **Play Here** |

### The one deviation worth considering

**Set Agent Mode → Podcast Generator instead of speaking step 2.** That bypasses the router entirely and
goes straight to the file reader — deterministic, no classification.

It does **not** help with the script-generation failure, which is where the risk actually lives. The
routing half is already proven 3-of-3 plus a live run. So this only removes a risk you don't have.
**Mentioned for completeness; not recommended** — it costs you the pure-voice story for no real gain.

## When it fails — and it may

**What you'll see**: *"the AI service returned an error while writing the podcast script. Please try again
in a few minutes."*

⚠️ **That message is misleading and you should know it before you're standing in front of people.** It is a
catch-all: parse failure, rate limit, and network error all produce that identical sentence. The real cause
is logged but never shown. *"Try again in a few minutes"* is written to sound transient — **it fooled two
of my engineers today.** Waiting will not help if it's the parse failure.

**What to do**: retry once, immediately, not in a few minutes. If it fails the same way twice, it is the
parse failure and a third attempt is unlikely to differ.
