## 2. Standing rules that bear on THIS plan

These are the ones a reviewer of this particular design will actually collide with.

### 2.1 The user is never a tester — Layer 1

The human is the designer and the user. Not the tester, not the bug-filer. Any step that reads *"verify"*, *"confirm"*, *"check the output"*, or *"Manual E2E"* without an `EXECUTOR:` tag is an ownership gap. *"Manual E2E"* in this project means **not yet automated** — it never means a human does it.

### 2.2 The 100% coverage mandate is ACTIVE — so Convention 6 is live

Lupin requires 100% of lines **and** branches **and** functions. A verification step tagged `EXECUTOR: AI — tests pass` is therefore **incomplete** here: it must name the coverage-assertion shape, or name why coverage does not apply to that layer. This is the Stage-3 Ownership reviewer's Convention 6, and it is active because this project has the mandate — it is dormant only in projects that don't.

### 2.3 Testing venue routing — Layer 2

Two servers, and the choice is by rubric, not by habit.

- **`:7999` (dev)** — only if all three hold: no persistent-state mutation, ≤2 minutes, no need for server monopoly.
- **`:8000` (test)** — anything that mutates state, spends real LLM money, exceeds 2 minutes, or needs monopoly. Submitted **only** through `POST /api/test-suite/submit`. Never curl, never a direct queue push.

**This plan will hit that boundary.** A 995-row replay against a paid model is real spend and well over two minutes. If a section routes it to `:7999`, that is a finding. A folder named `smoke/` is not a venue marker.

### 2.4 Cost path — Layer 2

Two LLM cost paths exist, and which one a feature lands on is a design-time question:

- **Bounded Claude Code jobs** — covered by the Max subscription, no per-token cost.
- **Direct SDK calls with `ANTHROPIC_API_KEY_FIREWALLED`** — billed per token.

Gemini is neither: it is a third path with its own key and its own bill. A migration is a **cost shift, not a saving** — never describe one as free.

### 2.5 No defensive fallbacks — Layer 1

No `getattr()` chains with silent defaults. Objects arrive fully constructed; a missing attribute should fail loudly at the source, not resolve quietly at the consumer. If a section proposes a fallback, ask what it is hiding.

### 2.6 Code style, if the plan specifies code

4-space indent, `snake_case` functions, `PascalCase` classes, spaces inside brackets — `foo( bar )` and `items[ 0 ]` — double quotes, vertically aligned assignments and dictionary colons, Design-by-Contract docstrings with Requires / Ensures / Raises.

## 4. Persona and comms conventions

- **Sign with your own persona icon.** It is how Rick tells voices apart in chorus mode.
- **Reply to a DM in its thread** — carry `reply_to` and `thread_id`. An untied DM can land on a subagent rather than the seat you meant, arrive context-stripped, and be correctly refused as spoofed.
- **Brevity is a hard rule, not a style note.** Verdict first, three lines or less, plain English. No coined vocabulary — if a competent engineer who joined this week would need a glossary, rewrite it. Detail goes in the `abstract`, never in speech.
- **State the defect, the fix, the receipt.** No stakes clauses, no counterfactual catastrophes. A finding stated as mechanism holds at any severity; one stated as catastrophe gets discounted the moment the stakes turn out lower.
- **Deposit as you go.** The moment you catch yourself wrong, nearly miss a finding, hit a misleading instruction, or pass a gate — post 1–3 sentences to the `post-game` topic. Do not bank it. Your seat may be reaped before any retrospective reaches you, and what survives a reap is only what was already written down. Include **how you came to know it**: did you *run* it or *read* it, and would something cheaper have sufficed?
