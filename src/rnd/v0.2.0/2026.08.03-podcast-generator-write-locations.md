# Podcast Generator — Where Iteration Scripts Land

**Date:** 2026-08-03 · **Author:** Rio ⚡ (session 001b6922) · **Store row:** 190c5627 · **For:** Mr. Radio 🦉 → Rick
**Question (Rick, by voice):** where does the podcast generator stash the scripts across successive iterations, and can a stale one poison a later run?

## Verdict

**All podcast output lands in `io/podcasts/<user_email>/`.** The runtime-argument fuzzy file matcher never scans that directory, so run N's output **cannot** poison run N+1's source selection. Confirmed independently by Mr. Radio: the matcher's search loop walks `project_root + "/src"` (expeditor.py:1059-1064), and `io/` is a *sibling* of `src/`, never a descendant — `io/podcasts` is unreachable **by construction**, not merely by absence.

## Q1 — Every on-disk write location

| Artifact | Directory | Filename convention | Receipt |
|---|---|---|---|
| Script (first save) | `io/podcasts/<email>/` | `{ts}-{topic}-script.md` | config.py:297,298 + orchestrator.py:1441,1456-1459 |
| Script (revision, same run) | same | `{ts}-{topic}-script-v{n}.md` | orchestrator.py:1424-1432 |
| Script (translated) | same | `{ts}-{topic}-script-<lang>.md` | config.py:386-387; orchestrator.py:1411-1421 |
| Audio | same | `{ts}-{topic}.mp3` (+`-<lang>`) | config.py:299,394-395; orchestrator.py:1767-1772 |

- Directory template: `io/podcasts/{user}` — config.py:297
- Timestamp: `datetime.now().strftime("%Y.%m.%d-%H%M%S")` — per-second — config.py:364
- Dir assembled as `get_project_root() + "/" + "io/podcasts/<email>"` — config.py:373-374
- **No outline / metadata / state file is written to disk.** All run state lives in the in-memory `self._podcast_state` dict. The `io/podcasts/.../dry-run-...` paths at job.py:427-428 are dry-run stubs only.

## Q2 — Collision behavior across successive runs of the SAME source

- Each run = fresh orchestrator, fresh `podcast_id` (orchestrator.py:143); `get_output_path` stamps a NEW per-second timestamp into the filename.
- Run 2, 3, 5 → **new timestamped sibling file each time. No overwrite.**
- Revisions WITHIN one run add `-v{n}` on that run's own base file only (orchestrator.py:1431-1432).
- Cross-run collision only if two runs hit the identical second AND identical 50-char topic slug — effectively never for interactive use.

## Q3 — Retention

- **Nothing is cleaned up.** Files accumulate forever.
- The only delete is `_delete_draft_script` (orchestrator.py:1473-1487), fired ONLY when the user cancels a draft.
- Live evidence: `io/podcasts/ricardo.felipe.ruiz@gmail.com/` holds scripts + mp3s dating Jan→Apr 2026, none swept.

## Q4 — The poison trap (the one that matters)

`_handle_fuzzy_file_match` scans exactly three sources (expeditor.py:1000-1070):
1. `io/deep-research/<email>` — non-recursive, `.md/.yaml/.yml/.txt` (line 1034)
2. `io/presentations/<email>` — non-recursive, `.yaml/.yml` only (line 1042)
3. Config `podcast generator source search paths` = **`/src`** (lupin-app.ini:1398), walked recursively (line 1064)

Podcasts write to `io/podcasts/` — not deep-research, not presentations, outside `/src`. A podcast script is invisible to the matcher. **Proven by code + live disk, not inferred from the directory name.**

### The real Thursday risk (NOT a podcast bug)

The already-bitten failure was a **deep-research** run writing into `io/deep-research/<email>` — which IS scanned. That dir currently holds ONE KISS file: `2026.07.25-the-kiss-protocol-how-a-brevity-mandate-got-built.md` (67KB). If a new deep-research run (or an extra drop) leaves a second KISS-ish `.md` there, the matcher can pick the wrong one again. **Operational rule (relayed to Rick): keep exactly one intended source file in `io/deep-research/<email>/` and the pick is safe.**

## Plain-English answer: "Run it 5× Thursday — what's on disk, can it poison run 6?"

Each run drops one new timestamped script `.md` (plus one `.mp3` if audio is made) into `io/podcasts/ricardo.felipe.ruiz@gmail.com/`. Five runs = five distinct files, never overwriting, never cleaned up. **None can poison run 6** — the file-picker never looks in `io/podcasts/`. The only thing that can poison a run is a stale or wrong `.md` in `io/deep-research/<email>` (Maria's drop folder); keep one intended file there and it's safe.
