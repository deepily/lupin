## What phase 5 is

`create_agentic_job()` in `src/cosa/rest/agentic_job_factory.py` is **301 lines carrying
eleven live `if`/`elif` branches**, one per agentic command. The v2 registry already
carries the field meant to replace it:

```python
# src/cosa/rest/v2/registry.py:86
job_factory : Optional[ Callable[ ..., Any ] ] = None   # agentic: builds the Job (wired in phase 5)
```

It is `None` for every command. Phase 5 wires it, and the `if`/`elif` goes away.

## Why this matters beyond tidiness

Today, **adding a new agent requires a code edit here**. Tiberius's pass-2 document nearly
told crews the opposite — its first draft said to add no branch at all, which would have
left a new agent unbuildable, and it was caught by grepping the factory rather than
trusting the design note.

The distinction that draft missed is load-bearing and survives phase 5:

- **Routing** goes through the registry. Three v1 mechanisms were collapsed into it and
  `test_v2_registry_drift_guard.py` stops them returning.
- **Construction** — resolved command plus arguments into a `Job` — was never included.

⇒ Phase 5's prize is that **adding an agent stops touching this file at all.**

## Rick's two rulings (2026-08-25, `ask_multiple_choice`, `answered:true`)

### 1. Shape — *"One builder per command, then simplify"*

Two passes, not one.

**Pass A.** Every branch body becomes a module-level builder function with an identical
signature. Each command's registry entry points at its builder. `create_agentic_job()`
becomes a lookup plus a call. **The eleven bodies move; they do not change.**

**Pass B, later and separately.** With eleven small functions side by side, collapse the
ones that turn out to be near-identical into a declarative mapping, keeping a callable
override for the ones that genuinely need code.

**Why not go straight to a table.** The branches are not uniform, so a table needs an
escape hatch on day one — and we would be designing that hatch while simultaneously
moving all eleven. Pass A tells us for free which are uniform, instead of us guessing.

### 2. Behaviour — *"Pure refactor, no behaviour change"*

Every command must build **exactly the job it builds today**, proven command by command.
Anything that looks like a bug on the way gets **its own row** and does not ride along.

⇒ This is what makes the phase gateable by comparison rather than by a reviewer reading
eleven bodies and forming an opinion.

## The gate: eleven equivalence tests

The whole phase rests on one falsifiable claim — *same command, same args, identical
`Job`* — so the test is a direct comparison, old path against new.

```python
@pytest.mark.parametrize( "command,args", ELEVEN_CASES )
def test_new_path_builds_what_the_old_path_built( command, args ):
    old = _legacy_create_agentic_job( command, args, **FIXED_CONTEXT )   # kept, temporarily
    new = create_agentic_job(         command, args, **FIXED_CONTEXT )
    assert _comparable( new ) == _comparable( old )
```

**Keep the old function under a private name for the duration of pass A**, delete it in the
commit that turns the last branch green. A refactor that deletes its own reference on the
first commit cannot be compared against anything.

### Three things this test must get right

**`_comparable()` must not compare identity or timestamps.** Two `Job` objects are never
`==` by default and will carry different `id_hash` / creation times. Compare the
constructor-visible attribute set with those fields excluded — and **name the exclusions
explicitly** rather than filtering by type, or a genuinely-changed field slips out with
them.

**The argument cases must exercise the branch bodies, not just their happy path.** For the
two that parse `languages`, include **both** a real list and a comma-separated string; for
test suite, whatever its 39 lines actually discriminate on. A case set that only sends
well-formed input proves the lookup works and says nothing about the bodies.

**Prove the test can fail.** Before wiring anything: change one builder's default and
confirm exactly that command reddens. A green equivalence suite that would stay green
under a real change is worth nothing — and this is the same trap the notification row was
just bitten by, where a 200 carrying `user_not_available` read as success for months
because the assertion never inspected the discriminating field.

## Two hazards specific to this file

### The queue directives are not agent arguments

`scheduled_at`, `monopolize`, `spawned_by_id_hash` are parameters, deliberately, and the
docstring already explains why: they instruct the **queue**, not the agent, and `args_dict`
is validated against `JOB_ARG_CONTRACTS`, so smuggling them through it would mean faking
them into an agent's contract to survive the trip. As the v1 doors retired into
`/api/v2/submit`, the stamping moved *into* this factory.

⚠️ **The failure mode is silent**: `create_agentic_job` reads arguments **by name** and does
not name these, so a left-in `scheduled_at` is **dropped without a word and the job runs
immediately**, while the caller believes it is scheduled. Whatever shape `job_factory`
takes, these three must stay outside the per-command argument path — and one equivalence
case should carry a `scheduled_at` and assert it survives.

### `None` for an unrecognised command is contract, not an accident

The docstring promises it. A lookup that raises `KeyError` on a miss is a behaviour change
and violates ruling 2. Preserve the `None`, and pin it with a test.

## Suggested commit sequence

Each commit green and reviewed before the next.

1. **Extract with no dispatch change.** Eleven builders + the equivalence suite; the
   `if`/`elif` still runs and now just calls them. Falsifier proven at this point.
2. **Wire the registry.** `job_factory` populated for all eleven; dispatch by lookup;
   `if`/`elif` deleted along with `_legacy_create_agentic_job`.
3. **Guard the gap.** Extend `test_v2_registry_drift_guard.py` so a command registered
   without a `job_factory`, or a construction `if command ==` reappearing in this file,
   goes red. *Without this, phase 5 can silently un-happen.*

### Step 3 is a different gate from the equivalence tests — do not conflate them

Mr Radio asked whether the equivalence suite covers the whole gate. **It does not, and the
distinction is worth stating plainly:**

The equivalence tests are a **one-time migration proof**. They show the eleven bodies moved
unchanged — and the moment step 2 deletes the legacy function they can no longer prove
anything at all. **Nothing in them notices a twelfth command arriving next month with a
fresh construction branch bolted into this file.**

That is step 3's job, and it needs **two** assertions, because they catch different things:

| assertion | catches |
|---|---|
| every registry command has a non-`None` `job_factory` | a new agent registered without a builder — which today returns `None` and reads to a user as *"the router did not understand me"* |
| no `if command ==` / `elif command ==` construction branch in `agentic_job_factory.py` | somebody adding the twelfth **the old way** — the habit this file has taught for a year |

**Neither alone is sufficient.** A new agent could carry a `job_factory` *and* a legacy
branch, and the branch would win by running first. Equally, deleting the branches does not
make anyone populate the field. They are a pair.

Put them in `test_v2_registry_drift_guard.py` rather than a new file: that guard exists
because three v1 **routing** mechanisms drifted apart and came back. Construction is the
fourth. Same failure, same home.

⚠️ **Falsify step 3 the way you falsify the rest** — register a throwaway command with
`job_factory=None` and watch the first assertion redden; paste a fake `elif command ==`
into the factory and watch the second. *A drift guard nobody falsified is a comment with a
test-shaped wrapper.*

⚠️ **Do not land step 3 in the same commit as step 2.** Get the lookup green first, then
guard it. If they ride together and the guard is wrong, you cannot tell which half broke.

**Pass B is a separate row and a separate design.** Do not start it in the same branch.

## Pass A inventory — what the eleven actually do

*Added 2026-08-25 21:25 EDT at `c1019639` by Clayton 😎, on Mr Radio 🦉's ask. Read from
the tree with `ast`, not by eye. **This is an inventory, not a proposal**; pass B is a
separate row and a separate branch per Rick's ruling.*

Rick rejected going straight to a declarative table because nobody knew which of the eleven
would collapse. They now have been counted, and the answer is **six collapse cleanly, two
collapse into one shared helper, two look collapsible and are not, and one is genuinely
singular.** The interesting finding is not the six — it is the pair that a reasonable person
would merge on sight and must not.

| # | builder | beyond ctor + `_finish` | verdict |
|---|---|---|---|
| 1 | `_build_deep_research` | nothing. 1 literal default (`no_confirm=True`) | **collapse** |
| 2 | `_build_claude_code` | nothing | **collapse** |
| 3 | `_build_presentation_generator` | nothing (15 kwargs, the widest) | **collapse** |
| 4 | `_build_research_to_presentation` | nothing | **collapse** |
| 5 | `_build_swe_team` | nothing | **collapse** |
| 6 | `_build_bug_fix_expediter` | nothing; 3 kwargs use the `get(x) or None` idiom | **collapse** |
| 7 | `_build_podcast_generator` | languages splitter | **shared helper** |
| 8 | `_build_research_to_podcast` | languages splitter — **byte-identical to #7** | **shared helper** |
| 9 | `_build_test_suite` | `test_types` + `pytest_args`, `shlex`, `_SEMANTIC_NONE`, raises | **override** |
| 10 | `_build_test_fix_expediter` | `original_test_types` + `original_pytest_args` | **override — NOT the same as #9** |
| 11 | `_build_test_fix_expediter_resume` | no constructor, no `_finish`, early `return None` | **singular, leave alone** |

**The six pass-throughs are pass-through in the strict sense**: zero statements between the
deferred imports and the constructor call. Every kwarg is one of four shapes — a context name
(`user_id`/`user_email`/`session_id`/`debug`/`verbose`, identical across all eleven), a plain
`args_dict.get( "x" )`, a `_parse_*( args_dict.get( "x" ) )`, or the `args_dict.get( "x" ) or
None` idiom. A table of `(kwarg → source, parser)` expresses all six with no code.

**#7 and #8 are the same code, verified rather than eyeballed** — `ast.unparse` of both
pre-constructor blocks compares **equal**. One helper, called twice.

🔴 **#9 and #10 are the trap, and the whole reason pass A ran before pass B.** Both parse a
comma-ish list plus an args string; the resemblance ends there.

| | `_build_test_suite` (#9) | `_build_test_fix_expediter` (#10) |
|---|---|---|
| list key | `test_types` | `original_test_types` |
| list default | `"integration,e2e"` | `[]` |
| args key | `pytest_args` | `original_pytest_args` |
| args split | **`shlex.split`** | **`.split( " " )`** |
| `_SEMANTIC_NONE` | honoured | **not consulted** |
| malformed input | **raises `ValueError`** | cannot raise |

Merging these into one parser gives #10 `shlex` quoting, semantic-none handling and a raising
path it does not have today — three behaviour changes under a refactor's name, and the kind
ruling 2 forbids. They need **two separate overrides**, or one helper explicitly parameterised
on all six differences, which is not obviously smaller than the code it replaces.

**#11 is not a builder in the shape the other ten are.** It resolves a resume target, returns
`None` when there is no single match, builds no job of its own, and calls
`_stamp_queue_directives` directly — it is the sole `FINISH_EXEMPT` entry, because falling
through to `_finish` would overwrite the resumed job's original `routing_command`/args with
the resume args. A declarative table cannot express it and should not try.

### One thing pass B should fix that is not about collapsing

**All ten non-resume builders carry the same ten-line deferred import block, and each uses
exactly one of those ten classes** (`ast` finds two distinct blocks across the eleven: ten
builders share one of 10 imports, `_resume` has 11). That is **111 import statements doing the
work of 11**. It was correct for pass A — the block moved verbatim with the bodies, preserving
import *timing* along with behaviour, which is what made the move provable — but nothing
requires it to stay. Each builder needs its own one line.

⇒ **Shape pass B should probably take**: a table for the six, one shared languages helper for
the pair, a `callable` override column used by exactly #9, #10 and #11, and each builder's
import narrowed to the class it builds. **Six of eleven is a real reduction and four of eleven
is a real floor** — the escape hatch Rick predicted would be needed on day one is needed on
day one, and now it is measured rather than assumed.
