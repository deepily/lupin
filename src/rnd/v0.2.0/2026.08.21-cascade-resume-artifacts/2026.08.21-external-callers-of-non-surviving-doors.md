## Door 8 is the sharp one

`POST /api/upload-and-transcribe-mp3` has **three external callers across two separately-managed
repos** (mobile `http_service.dart:215`, plugin `recorder.js:500`, plus mobile's constant at
`app_constants.dart:56`) — and its in-repo `push_job` call raises `TypeError` on every agent-mode
request (`routers/speech.py:338`, one argument where four are required).

So the most externally-depended-on door on the list is also the one already broken. Whoever rules on
its disposition should know both facts at once: fixing it and deleting it are both live options, and
the callers are in repos this one cannot edit.

## Sweep scope, stated so the gaps are visible

**Searched**: `src/lupin-mobile`, `src/lupin-plugin-firefox`, `src/scripts`, `src/docs`,
`src/lupin_app/static`, `src/conf`, and the user crontab (8 lines, no matches). Excluded
`node_modules`, build output and lockfiles.

**NOT searched, and each is a real blind spot**: anything outside this filesystem — other machines,
a deployed mobile build already in someone's hands, saved Postman/Bruno collections, browser
bookmarklets, a peer's private scripts, or any service calling in over the network. **A grep of this
repo cannot prove a door has no callers; it can only prove which callers this repo knows about.**
For a 410 ruling, the honest complement is server-side: log every hit on these sixteen paths for a
period before any of them starts returning 410, and let the traffic name the callers the grep cannot
see.
