# Cancel now reaches a job that has not started yet

**Row**: `4b87fe61-cac7-4e6e-9563-dfebaeaf6e49` (P3) · **Author**: Krishna 🦚 · **Date**: 2026-08-24

## The defect

`POST /api/jobs/{job_id}/cancel` looked the job up in the RUNNING queue only:

```python
job = running_queue.get_by_id_hash( job_id )    # queues.py, pre-change
except KeyError: raise HTTPException( 404, f"Job not found or not running: {job_id}" )
```

So a job sitting in the todo queue — the cheap, safe, no-work-lost moment you most want to
cancel at — was the one moment the endpoint refused, and it refused with a message that reads
as "there is no such job". A caller who believed that 404 would watch the job start anyway.

## What changed

`cancel_job` now consults the running queue first, then the todo queue.

| State | Before | After |
|---|---|---|
| running, agentic | `cancel_requested` | `cancel_requested` (unchanged) |
| running, non-agentic | 400 "Only agentic jobs support cancellation" | 400 that also names `DELETE /api/queue/run/{id}` |
| queued in todo | **404** | **`cancelled`** — removed from todo, `job_removed` emitted |
| scheduled for later | **404** | **`cancelled`** — see below |
| unknown id | 404 "not found or not running" | 404 naming both states searched |

`_emit_job_removed()` was extracted from `delete_queue_job` and is now shared by both paths, so a
cancelled card disappears from the UI exactly the way a deleted one does.

## The "other pre-running states" question, settled from source

The row asked whether the same gap existed for scheduled-but-not-queued and deferred jobs.
**There is no separate queue for them.** `FifoQueue.get_next_eligible_job` (`fifo_queue.py:155`)
reads a `scheduled_at` attribute off jobs already sitting in the todo queue and skips the ones
whose time has not come. A scheduled job IS a todo job. One todo lookup covers every pre-running
state, and no third queue needs consulting.

## 🔴 Correction to the row's own amendment — checked, not assumed

The 2026-08-21 amendment states:

> A test_suite job is not an `AgenticJobBase`. So for test-suite jobs the endpoint has NO
> REACHABLE SUCCESS PATH AT ALL: 404 before it starts, 400 once it is running.

**That is not true, and was not true when it was written.** `src/cosa/agents/test_suite/job.py:173`
reads `class TestSuiteJob( AgenticJobBase ):`, and `git log -L` on that line shows it has said so
since the file was created in commit `53fef419` (2026-05-29) — it has never been anything else.
Verified by MRO at runtime: `TestSuiteJob → AgenticJobBase → ABC → object`.

So the 400 arm never fired for a test-suite job. The observed failure was entirely the 404 on the
queued job, which is real and is what this change fixes. Once a test-suite job is RUNNING, cancel
worked before this change and works after it.

Two consequences worth carrying forward:

- The amendment's conclusion that "the in-container process kill was the ONLY lever" does not
  follow. Cancel on a *running* test-suite job was available the whole time.
- The amendment's own method note — "maya read the handler and got it right in one pass; two
  probes would not have found the 400" — holds, with the caveat that reading one handler is not
  the same as reading the class it tests against.

## Falsification

`TestCancelJobReachesQueuedJobs` (10 tests) was written before the fix and all 10 were red. The
central one asserts a queued job comes back `cancelled` and that `delete_by_id_hash` was really
called with the job id — the same instrument maya's failing call would have used.

Six mutations, each proven to have landed before its run:

| # | Mutation | Result |
|---|---|---|
| N1 | revert the fix — cancel consults running only | killed — 13 failed |
| N2 | skip the ownership check on the queued path | killed — 1 failed |
| N3 | report success even when the delete did not take | killed — 2 failed |
| N4 | drop the `job_removed` emit on the queued path | killed — 1 failed |
| N5 | check todo before running, so a running job gets yanked | killed — 5 failed |
| N6 | let a websocket failure escape and fail the cancel | killed — 2 failed |

Harness: `scratchpad/mutate2.sh`.
