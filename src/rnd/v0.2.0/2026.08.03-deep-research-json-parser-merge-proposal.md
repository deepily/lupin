# Proposal: fold deep_research's JSON parser into the shared helper

**Date:** 2026-08-03 · **Author:** Rio ⚡ · **Row:** d923ceb2 · **Status:** investigate-and-propose (do NOT land without Mr. Radio's word)
**Predecessor:** Rachel's consumer sweep `src/rnd/v0.2.0/2026.08.03-json-parser-last-brace-consumer-sweep.md` (commit 52cde456)

## Verdict

Adopt the shared helper's existing contract — **the parser returns `None` and never raises; each consumer owns its failure posture.** Deep research keeps its raise via a 3-line wrapper; BFE folds trivially. **One genuine behaviour change needs scrutiny before landing: deep_research selects the FIRST balanced brace span, the shared helper selects the LAST.** Everything else is structural or a strict improvement.

## Recommended merged contract

**Parser recovers only; posture lives in the caller** (the shared helper's deliberate design, and the pattern set by the fuzzy-prefilter helper e651bc76). Rationale: policy in the caller means one parser can serve a raiser, a None-propagator, and a fallback-returner without any of them inheriting a posture they did not choose. It is also the anti-silence design — `recover_json_object` logs the full raw body at ERROR on failure, which is exactly the observability whose absence let the podcast copy discard good output for five months.

Concretely:
- **deep_research** — replace its private `extract_json_object` with a thin wrapper that preserves its RAISE boundary:
  ```python
  def extract_json_object( text ) -> dict:
      if text is None or not text.strip():
          raise ValueError( "Cannot extract JSON from empty/blank response" )
      obj = recover_json_object( text )
      if obj is None:
          raise ValueError( "Response did not contain a recoverable JSON object" )
      return obj
  ```
  Its one real caller (`api_client.py:449`) and consumers see the SAME raise-on-failure behaviour.
- **BFE** — replace `_extract_last_json_object` with the shared `extract_json_object` (pure extractor). Bodies are byte-identical → zero behaviour change; caller at `:511` keeps its fence-split + `_fallback_diagnosis` posture.

## Behaviour changes to flag (NOT just structure)

1. **FIRST → LAST brace selection (the one that matters).** deep_research picks the first balanced span that parses; the shared helper picks the last. On a completion with multiple top-level brace spans (a prose example object before the real one, or the real object followed by brace-bearing trailing prose), the two pick **different objects**. The direct-`json.loads` fast path masks this for clean single-object responses (both identical); divergence only bites on the fallback path with multiple spans. **Before landing:** capture 5–10 real deep-research completions and confirm LAST-brace + fence-cut returns the same object FIRST-brace does. If any diverge, that is the risk to weigh.
2. **Fence handling gains the P0 fix.** The shared `recover_json_object` drops everything after the CLOSING ``` fence (P0 4317efd1); deep_research only trims a trailing ``` when the content ends with it. Folding **adds** the trailing-prose-after-fence fix to deep research — an improvement, but a change.
3. **Loud ERROR logging appears.** `recover_json_object` logs the full (bounded) raw body at ERROR on unrecoverable input; deep_research currently raises with no body log. Folding adds that observability — an improvement, but new log output.
4. **Return-type nuance.** deep_research is hinted `-> dict`; `recover_json_object` returns `Any`. A top-level JSON array/scalar would pass through where a dict is expected. If strict dict-ness matters, the wrapper should `assert isinstance( obj, dict )` — decide explicitly.
