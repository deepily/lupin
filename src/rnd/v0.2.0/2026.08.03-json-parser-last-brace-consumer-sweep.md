## What this means for each of Mr Radio's three break-points

1. **"Prefer the fenced block over the last balanced brace."**
   Both lenient copies strip a fence **only when it is at the very start** of the content (podcast `script_generation.py:422`; presentation `json_recovery.py:71`). A fenced ```json block that follows leading prose is never preferred — the code falls straight through to `rfind("}")`. If the model emits *real JSON, then trailing commentary containing braces*, last-brace grabs the small trailing object and drops the large real one — the 5,533-token-drop shape. **Fix #1 must change fence DETECTION (find a fence anywhere, prefer its contents), and it must land in BOTH lenient copies**, not just podcast.

2. **"Make the silent None branch loud."**
   Podcast returns `None` silently and then `parse_script_response` **injects `segments=[]`** (`script_generation.py:496–511`) — the silence Mr Radio wants killed. Presentation deliberately returns `None` and documents *"the STRICT failure posture (raise on None) is the CALLER's responsibility"* (`json_recovery.py:59`). **So if Clayton makes the parser itself raise, he changes presentation's contract** — all four presentation callers (api_client, outline, elaboration, narrative) must be checked so the new raise isn't double-handled or swallowed. Deep research already raises; leave it.

3. **"Move the no-segments floor AHEAD of the human approval gate."**
   Podcast `parse_script_response` docstring is explicit: a zero-segment recovery yields an empty-segment script and *"the downstream audio phase enforces the no-segments floor (orchestrator Phase 5 guards)"* — i.e. AFTER the human approval gate. The move-ahead target is the three `parse_script_response` call sites (`orchestrator.py:1288/1352/1602`) relative to where the approval gate sits. **Check presentation's `narrative.parse_analysis_response` for an analogous empty floor** — pptx rendering treats an empty deck as a real defect (`json_recovery.py:10`), so it likely needs the same early floor.
