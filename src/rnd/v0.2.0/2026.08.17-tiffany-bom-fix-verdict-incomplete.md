## Candidate fix — closes 24/24, measured

Replace the position-0 strip with one closed-ended helper, and route the narrowing through it too:

```python
def _strip_leadin_noise( text: str ) -> str:
    """
    Drop every leading character a reader cannot see, in ANY order, until a visible
    one appears. Closed-ended by CONSTRUCTION: whitespace plus Unicode category Cf
    (format) — which is what U+FEFF, U+200B, U+2060 and the direction marks are —
    rather than a hand-kept list the next invisible codepoint reopens.
    """
    i = 0
    while i < len( text ) and ( text[ i ].isspace() or unicodedata.category( text[ i ] ) == "Cf" ):
        i += 1
    return text[ i: ]
```

- `:302` → `prefix = _strip_leadin_noise( prefix )`
- `:319` → `if not _strip_leadin_noise( prefix ).startswith( "{" ):`
- add `import unicodedata`

Category `Cf` verified to cover `U+FEFF`, `U+200B`, `U+2060`, `U+200E`; `U+00A0` is `Zs` and caught by
`isspace()`. **Two strips in a fixed order can never handle interleaving** — that is why this is a loop
over a character *class*, not a longer `lstrip` argument.

Test table should be extended with the reverse order and a non-BOM invisible:
`[ " ﻿", "\n﻿", "\t﻿", "​", "﻿ ﻿" ]`.

## Standing concern, not a blocker

The narrowing is whitelist-shaped on a security floor: "block only if it starts with a brace" means
every lead-in is a candidate bypass forever, and this is the second one found in two commits. The
candidate makes the class closed-ended, which is as far as this shape goes. If the false-positive
pressure returns, the durable answer is to key the decision on the *payload* (a parsed object carrying
a credential field) and accept blocking documents that embed a whole literal credential — not to keep
widening what may precede the brace.
