## Techniques worth keeping

- **The kernel's OOM task dump is a full inventory nobody reads.** `journalctl` → the
  `Out of memory: Killed process` line plus the task table gives per-process RSS at death. Parse
  it by stripping the `[ pid]` brackets first — variable bracket spacing shifts awk's columns and
  will silently hand you `total_vm` where you wanted `rss`.
- **`comm` can carry a whole command line.** `npm exec tsx --` is what identified the invocation.
  Read the **entire trailing name field**, not the first token.
- **Test the procedure you are about to document.** The identify-the-writer step for the bridge
  guard works on `cc-<pid>.json` and returns `?` on the bare `<pid>.json` harness files — a reader
  could mistake that `?` for evidence. Found only by running it.
- **Mutation-test against an isolated tree copy, never in place.** In-place backup/restore on a
  shared file silently reverts a peer's write with nothing to show for it. Standing rule now.
