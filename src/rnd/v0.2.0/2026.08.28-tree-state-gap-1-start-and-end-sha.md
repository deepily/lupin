# Gap 1 — a run states the tree it STARTED on as well as the one it ended on

**Row**: `11253df9` (gap 1 of three; gap 3 closed at `58f707ab`, gap 2 still open and deliberately untouched here)
**Date**: 2026-08-28 · **Author**: Mr. Radio 🦉
**Predecessor**: `src/rnd/v0.2.0/2026.08.26-every-green-states-its-tree.md` (§6b for why the line lives in a module)

Design written and committed **before** the code, per the process correction john recorded on the row.

---

## 1. The gap, in the row's own words

> *"the probe reports at the END of a run. A commit landing mid-run is not detected, so a long tier can still be a hair stale. The unit tier runs ~13 minutes and peers commit inside that window routinely — measured tonight, the branch moved 20+ commits during my session."*

And the second motivation, added when gap 3 closed:

> *"THE TWO PATHS THEREFORE DIFFER IN WHEN, NOT IN WHAT: pytest reports the tree at the END of a run, the node tiers at the START. Closing GAP 1 would unify them."*

So there are two claims to fix, and they are not the same claim:

1. **A run's end sha is not the sha it started on**, and nothing says so.
2. **The pytest and node surfaces disagree about *when* they measure**, so two greens quoting a sha may mean different things.

---

## 2. What is NOT being done, and why

**A second full probe.** The row itself named the reason gap 1 was left open: *"the second probe's cost was not obviously worth it."* The current line costs at worst 9 git calls at `timeout=5` = 45 s, pinned by a test. Running the whole probe twice doubles that ceiling to 90 s for a diagnostic.

**One git call is enough.** The gap is about *commits landing mid-run* — a **sha** question. `branch`, `behind`, `ahead`, `fetched` and `tracked-dirty` at start would answer questions nobody asked, at 8× the cost of the one that was.

⇒ **Start capture is exactly `git rev-parse --short HEAD`.** Worst case moves 45 s → 50 s, not 45 s → 90 s.

**Gap 2 stays open.** Which *files* moved is a separate instrument with a separate cost, and nobody has asked for it.

---

## 3. The shape of the line

The existing line is unchanged, and one field is appended:

| Case | Field | Meaning |
|---|---|---|
| start sha == end sha | `run-span=unmoved` | the tree held still for the whole run |
| start sha != end sha | `run-span=<start>..<end> ⚠️ TREE MOVED MID-RUN` | a commit landed while the run was in flight |
| start sha unreadable | `run-span=UNKNOWN — the start sha could not be read` | measured and failed, as distinct from not measured |
| no start captured | *(field absent)* | this line IS the start — a point-in-time report, no span to state |

**Why the span is stated even when nothing moved.** The module's own contract already says it: *"returns a single line, always … never '' and never None. A silent instrument reads as 'nothing to report'."* A missing `run-span` on a pytest line would be indistinguishable from a probe that never ran. `unmoved` is a measurement; silence is not.

**Why `unmoved` does not repeat the sha.** `sha=` already carries the end sha, which by definition equals the start sha in that case. Repeating it buys nothing and costs a token on every line.

**Why absence is the right encoding for the node runners.** They emit *before* the run. A line emitted at the start has no span to describe, and inventing `run-span=unmoved` there would assert a fact about a run that has not happened yet. Absence there is not a silent instrument — the whole line is the start report.

---

## 4. Where the start sha comes from

`src/conftest.py`, at module import — the earliest point the conftest reaches, and the same point `_COVERAGE_FILE_AT_START` is already captured at. That precedent is deliberate: a "state at start" value is captured at start, and both live beside each other so a reader finds them together.

The value is threaded into `tree_state_line` as an **explicit parameter**, defaulting to `None`. Not a module global: the module is imported by two callers with different needs, and a global would make the node path's behaviour depend on whether the pytest path happened to have run first.

---

## 5. Why the two surfaces still differ, stated rather than smoothed over

⚠️ **Gap 1 does NOT fully unify pytest and the node tiers, and claiming it did would be false.**

`jstest_slice_exec` **replaces the shell** (`exec`, `src/scripts/lib/jstest-slice.sh:201`). Nothing after it in `run-typescript-tests.sh` or `run-js-tests-capped.sh` executes at all. So an end-of-run emit on the node side is not a cost decision — it is **impossible by construction** without restructuring those runners around the exec.

What this change actually achieves:

- **pytest** gains the span, so its line now describes an interval rather than a moment. The mid-run window — the thing gap 1 was filed about — is closed for every pytest tier.
- **node/c8** keeps a point-in-time start report, correctly labelled by the absence of `run-span`.

⇒ The surfaces now differ in *what they can observe*, which is a property of `exec`, rather than in *when someone chose to look*, which was an unforced difference. That is the honest half of the unification, and the remaining half is written here rather than left for the next reader to discover.

## 6. Acceptance criteria

100% lines/branches/functions on everything touched, per the standing mandate.

| # | Criterion |
|---|---|
| AC1 | `tree_state_line` accepts an optional start sha and renders the four cases in §3 exactly |
| AC2 | Called with no start sha, the line is **byte-identical** to today's — the node runners must not change output |
| AC3 | The conftest captures the start sha at import, via one `rev-parse`, and passes it to the terminal-summary call |
| AC4 | A start-capture failure yields the UNKNOWN span, never an exception and never a missing field |
| AC5 | The single-implementation property still holds — the conftest imports, it does not re-derive |
| AC6 | Cost is pinned: the start capture is one git call, asserted on the injected reader's call log |

**Mutations that must go red**: dropping the field when the shas differ · rendering `unmoved` when they differ · emitting a span on the node path · swallowing a start-capture failure as `unmoved` · the conftest re-growing a local start capture instead of using the module's.
