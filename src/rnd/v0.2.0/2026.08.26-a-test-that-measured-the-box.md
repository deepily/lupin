## The verdict, in six lines

1. A unit test failed on one machine and passed on every other, with **identical code**. It cost an evening to source.
2. **Fixed by Rio at `6f75b227`** (2026-08-26 11:48, hours before this investigation). The *mechanism* — why it failed on one box and passed on every other — was established separately, later the same day. With speakerphone ON, `_notify_impl` rewrote *any* priority outside `("high","urgent")` to `"high"` — including an **invalid** one, so by the time `NotificationPriority(priority)` ran the bad value no longer existed. The call shipped `HIGH` and reported *"Notification sent (delivered)"*. **A priority nobody chose, delivered silently.**
3. **Why it hid**: the test read speakerphone state **live from the session bridge** and never pinned it. In **chorus** the absent-flag default is **ON** — the failing side.
4. **The fix to the test is not the interesting part.** The OFF-arm tests stay green against the live defect *even after pinning*. Only a **speakerphone-ON** case exercises the lifting path at all.
5. **The sweep written to find siblings then repeated the same mistake at one level up**: it reported 29 exposed tests, and the true number is **3**. Every drop was a false positive found by *reading*, never by the tool.
6. ⇒ Both halves of this are the same error, and it is the sentence to keep:

> **An instrument that reads ambient state and reports the reading as a fact about the code.**

   The test did it about `_notify_impl`. The sweep did it about the test suite. Neither was lying; both were answering a question about their own machine and captioning it as a question about the code.

## 1. The defect (MEASURED, then fixed by Rio)

`src/lupin_mcp/cosa_voice_mcp.py:1524`, before:

```python
if priority not in ( "high", "urgent" ):
    priority = "high"
```

A typo'd `priority="urgnet"` was rewritten to `"high"` alongside every valid low/medium. Validation below could not reject what no longer existed. Fixed to lift only *recognised* values, so an unrecognised one falls through and is **reported**.

**The failure text, verbatim**, from the run that found it:

```
E   AssertionError: an invalid request must never reach the transport
src/tests/unit/lupin_mcp/test_converse_and_notify_paths.py:170
```

with the dumped local showing the request **constructed** with a bad priority — i.e. validation never saw it.

## 2. Why one box and not another

`_notify_impl`'s Phase-3 gate reads live state on every non-internal call:

```python
active = get_speakerphone( sid ) if sid else False
```

`get_speakerphone` returns `False` when no bridge file exists, but when a bridge **exists without the field** the default is **mode-aware — False in solo, TRUE in chorus**.

⇒ The same test, same code, takes the lift branch on a chorus box holding a fieldless bridge and not elsewhere. That is the whole intermittency.

## 3. What the guard needed (`12c0de8c`)

Pinned `get_speakerphone` False in both OFF-arm tests, and added `test_speakerphone_on_does_not_launder_an_unrecognised_priority`. It **captures** the request rather than raising on contact, so it asserts on **what shipped**, not on the returned string.

**Falsified, not assumed** — reverting to the old predicate:

```
1 failed, 29 passed
AssertionError: an unrecognised priority was laundered into a valid one and shipped as 'high'
```

🔴 **The other 29 stayed GREEN against the live defect, both pinned OFF-arm tests included.** That is the finding: the OFF arm *cannot* see this, so pinning alone would have produced a tidy test file that still caught nothing.

## 4. The sweep, and the count that would not sit still

`src/scripts/bridge_pin_sweep.py`. Its number moved **29 → 15 → 13 → 10 → 4 → 3**, and **every** drop was a false positive found by reading the tests:

⚠️ **The error ran in the direction that creates work.** Acting on "15" would have sent someone to pin code that was already correct.

## 5. The control travels with the detector (`6ea5f7ea`)

Mr Radio's objection: *"0 of 41" measured on the tree it was tuned against is fitted to the data.* A sweep that has quietly stopped detecting prints the **same 0** as a clean tree.

So `classify()` was split out of `sweep()` and the controls run on synthetic sources: one **negative control** that must be flagged, one sample per isolator that must stay quiet. **Falsified both ways:**

- **Blind the driver list** → `NEGATIVE CONTROL FAILED` — *while the sweep still printed `0 do NOT pin get_speakerphone`.* The silent failure, reproduced. That 0 is byte-identical to a healthy 0.
- **Forget one isolator** → `FALSE POSITIVE: isolator no longer recognised`, count jumps 0 → 5. It starts inventing work.

## 6. Exit codes, and the line that audited its author (`3dd5bc95`)

`0` CLEAN · `1` WORK · `2` BROKEN, with BROKEN taking precedence and saying in words that the count is not evidence. A forgotten isolator also exits `2` — **a detector that invents work is broken, not working.** All three provoked against real conditions; the `1` by stripping **both** pins off a live test (removing only one leaves `_get_cc_metadata`, which isolates on its own).

Per-driver counts replaced a remembered total, and **caught two errors in the driver list on their first run**:

- `_converse_impl` **does not exist** — the function is `converse` (`:1337`) and never reaches the gate. It matched nothing while making the sweep look twice as broad as it was.
- `_flip_speakerphone` does **not read** the flag — it *writes* it via `set_speakerphone`.

`get_speakerphone` has exactly **one** call site: `:1515`, inside `_notify_impl`. ⇒ **The honest denominator is 33, not the 41 quoted for most of the evening.**

## 7. Limits, stated

- The sweep **reports only** and cannot see a test isolating in a way it has not been taught. A future `0` means *"none of the five known shapes"* — never *"provably hermetic"*.
- `_get_cc_metadata` isolates **only** because a fake sid misses the bridge lookup. For a **real** sid whose bridge lacks the field, the default is mode-aware and TRUE in chorus — it would not isolate at all.
- Bridge **writes** are a real but separate hazard, deliberately out of scope.
- **Method note** (Mr Radio): mutation testing here was done on scratch copies for the detector, but the exit-`1` proof mutated the live test file and restored it with `git checkout`. A scratch copy is the better habit; a restore that is forgotten is a committed lie.
