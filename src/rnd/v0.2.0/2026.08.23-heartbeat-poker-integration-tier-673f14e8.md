### The control on my own test

M8 is an off-by-one: with `>` the switch fires on the third silent tick instead of the
second. **Exactly one assertion catches it** — the one pinning the streak length in the
escalation message, which was added after noticing the first draft would not have.

Proven both ways: the same M8 mutation is **🟢 GREEN against the test without that
assertion** and **🔴 RED with it**. Firing count and tick count are identical in both.
A test that asserts an escalation happened, but not *when*, is one edit from vacuous.

## The instrument hazard worth keeping: a stale `.pyc` faked a red

After the mutation sweep, a **pre-existing unit test I never touched** —
`test_send_to_logs_413_response` — failed, asserting stderr was empty when the source
plainly logs. `git status` showed the product tree clean, and it was.

**Cause**: CPython validates a cached `.pyc` on the source's **mtime in seconds and its
size**. Mutation M3 changed `>= 400` to `>= 600` — **the same number of bytes** — and the
mutate/restore cycle completed inside one second. The interpreter reused the *mutant's*
bytecode against restored source.

⇒ **The running code was not the code on disk, and nothing in the tooling said so.** It
presented as a real red in an unrelated file. Purging `__pycache__` restored 61/61 green;
the source had never been wrong.

The harness now purges bytecode before every run, and M3 was re-run clean to confirm its
red was genuine rather than an echo of its own prior mutant.

⇒ **Same-size mutations are the dangerous ones.** A single-character swap that preserves
length — `400`→`600`, `>=`→`> `, `True`→`Fals` — is exactly the shape most likely to be
silently cached, and exactly the shape a careful mutation tester reaches for first.

"mutates persistent state". As written it does not: the store is on `tmp_path`, the clock

stale prose told this row three live tests were being suppressed when they were empty.

`/api/dm/send` best-effort. Asserting live delivery would manufacture flakiness for a leg
the product deliberately does not guarantee. What is asserted instead is what the code
promises: a 413 refusal loses no poke and is logged once per poke.
