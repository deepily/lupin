# A pytest collection error is silence — and it was being read two different wrong ways

**Row**: `bc83f2df` (P1) · **Found**: 2026-08-17 by Cheech 🌿, two incidents in one afternoon
**Fixed**: 2026-08-17 by Sam 🎙️ (`4fa58ddc`) · **Manager**: Mr. Radio 🦉 (`e251aa88`)

---

## Verdict

It is not one behavior, it is **two**, and they differ by *where* the error lands. A
collection error in a test module was reported as **FAILED** — byte-identical to a genuine
red, for a suite that never ran. A collection error in a conftest fired **no pytest hook at
all** and wrote no junit, so nothing in-process could see it.

A plugin would have fixed the loud half and stayed silent on the half that cost the time.

---

## 1. What was measured

Both shapes built deliberately and run for real. Nothing here is inferred from reading code.

| | Shape A — error in a TEST module | Shape B — error in a CONFTEST |
|---|---|---|
| pytest exit code | `2` | `4` |
| junit XML | written, `tests=1 errors=1` | **absent** |
| pytest hooks | `collectreport`, `collection_finish`, `sessionfinish`, `cmdline_main` all fire | **none fire** — not even in the outermost `src/conftest.py` |
| parsed counts | `p0 f0 e1` | `p0 f0 e0` |
| **gate verdict BEFORE** | **`FAILED`** | `NOT EXECUTED` |
| **gate verdict AFTER** | **`COLLECTION ERROR`** | **`COLLECTION ERROR`** |
| cause named AFTER | orphaned import | signature change ahead of its callers |
| where named AFTER | `test module` | `conftest` |

Both wrong readings cost something different:

- **Shape A read as a red.** `_classify_outcome(0, 0, errors=1, 0)` returned `"FAILED"`, the
  same string as `_classify_outcome(5, failed=1, 0, 0)`. Someone reading it hunts a
  regression that does not exist. Worse: the measured directory held **3 tests across 2
  files** and the junit accounted for exactly **1**. The other two never ran and appear
  nowhere, so the report understates its own blast radius while sounding precise.
- **Shape B read as nothing.** It reached `NOT EXECUTED` by accident — every count is zero
  because nothing could be parsed — and carried no diagnosis whatsoever. This is the one
  Cheech described as silence, and it is the harder one: **no hook fires**, so a conftest
  plugin cannot catch it. Only the exit code, seen from outside the process, can.

That asymmetry is the whole design constraint. A fix living only inside pytest handles the
case that was already loud.

## 2. The fix

`src/cosa/utils/pytest_collection_diagnosis.py` — a shared module that reads an exit code
plus captured output and returns a description. It decides nothing; both callers render the
same diagnosis.

| Surface | Catches | How |
|---|---|---|
| `src/conftest.py` hook | shape A | `pytest_collectreport` + `pytest_sessionfinish`, printing the block on a plain `pytest` run |
| `src/cosa/agents/test_suite/job.py` | **both** | exit code from the subprocess — the only signal that survives shape B |

New state `COLLECTION ERROR`, added to `_classify_outcome` and to **both** strict lookup
maps (`_OUTCOME_ICON` and the overall-status map) — a state missing from either raises
`KeyError` while the run writes its own report.

The diagnosis names the **cause class**, not just the symptom: `ModuleNotFoundError` →
orphaned import (subject retired, test left behind); `TypeError: … missing N required
positional argument` → a signature change that landed ahead of its callers. An unrecognised
shape is reported as unrecognised rather than guessed — a confident wrong cause costs more
than an honest admission.

**The uncommitted case is called out explicitly.** One of the two incidents was a required
parameter added in a file that was never committed: `git log` showed nothing, so it was
invisible to everyone but its author. The block lists uncommitted `.py` files and says why
they are listed.

## 3. Receipts

**17 unit tests** in `src/tests/unit/test_pytest_collection_diagnosis.py`. Every one builds a
real cause shape on disk and runs a real pytest subprocess — synthetic strings would only
prove the regexes match strings I wrote.

Per the row's bar, each shape has a `test_current_tooling_*` counterpart asserting what the
**existing** classifier does. Those are the "before", and they will start failing the day
someone changes that classifier — which is the correct time for them to fail.

**Controls, which are what make the rest evidence:**

| Control | Result |
|---|---|
| a genuine failing test | still `FAILED` — the new state does not swallow real reds |
| a clean pass | still `PASSED`, and prints no block |
| nothing collected (exit 5) | flagged, because zero tests is not a pass either |
| `where_hint` on exit 0/1 | still `None` — the hint states *where*, never *whether* |

`job.py`'s own suites: **228 passed**.

## 4. A bug I put in and had to find by running it

`diagnose()` originally required the `"Interrupted: N errors during collection"` banner to
corroborate exit 2. That banner is written by pytest's **terminal reporter** — it is not
carried in a collect report. So the in-process hook, the one surface that can catch shape A
at all, passed a traceback that never matched and silently got `None` back. **The diagnostic
was fully wired in and reported nothing.**

My tests did not catch it because they fed full terminal output. It surfaced only when I ran
the hook for real inside the repo and no block appeared. Fixed with an explicit `where_hint`
— a caller that already knows collection failed states it, rather than re-deriving it from a
string it does not have — and a regression test that feeds traceback text alone.

The shape is worth keeping: **a test that supplies richer input than the real caller does
will pass while the real caller gets nothing.**

## 5. What this does NOT do

- **A bare `pytest` run on shape B still gets no diagnosis block.** No hook fires, so nothing
  in-process can print one. A developer sees pytest's own `ImportError while loading
  conftest` traceback and no cause class, and no uncommitted-file list. Closing that needs
  the sanctioned runner scripts to call the module on exit — worth doing, not done here.
- **Cause classes cover the two measured shapes plus two near neighbours.** Anything else
  reports as `unrecognised import-time failure`. That is deliberate, but it means the
  catalogue grows only as real incidents arrive.
- **No `:8000` run exercised this.** The gate wiring is proven by driving `_classify_outcome`
  and the parsers directly, not by a scheduled suite that actually hit a collection error.
