**Author**: Sam 🎙️ (tester, session `1fe241ea`) · 2026-08-17
**Problem it solves**: the paired replay's Flash-Lite arm cannot run on `:8000`.

---

## 1. The failure, measured

Inside `lupin-rest-test`, today:

```
project in container: hello-world-foo-423219          # resolves fine — src/scripts/cloud-run.env is bind-mounted
constructed OK; vertexai=True api_key=None base=https://aiplatform.googleapis.com/
LIVE CALL FAILED: DefaultCredentialsError
```

`docker-compose.yml` carries **zero** `gcloud` / `GOOGLE` / `GCP` references, and neither
container mounts `~/.config/gcloud`. The project id resolves; the *credential* does not exist.

The trap worth naming: **construction succeeds without credentials** (the SDK resolves them
lazily, at call time). So a harness that only builds the client — or a marker check that only
reads construction-time fields — looks perfectly healthy in that container and fails at the
first body.

## 2. Option A (recommended) — mount ADC read-only into the test container

```yaml
  lupin-rest-test:
    volumes:
      # ... existing mounts ...
      # Vertex credentials for the phi4-vs-flash-lite study's Flash-Lite arm. The
      # google-genai SDK in Vertex mode authenticates with Application Default
      # Credentials — there is no API key by design — and without this mount the arm
      # dies with DefaultCredentialsError at the first body, AFTER constructing cleanly.
      # Read-only: nothing in here ever refreshes the credential, and a writable mount
      # would let a test invalidate the host's login.
      - ~/.config/gcloud:/home/rruiz/.config/gcloud:ro
    environment:
      # ... existing env ...
      # Explicit rather than relying on $HOME resolution: /home/rruiz/.claude is already
      # shadowed by the claude-creds-test volume, so "the SDK will find the well-known
      # path" is an assumption this container has already broken once.
      GOOGLE_APPLICATION_CREDENTIALS: /home/rruiz/.config/gcloud/application_default_credentials.json
```

**Apply with a RECREATE, never a restart** — mounts and env resolve at container CREATE:

```bash
docker compose up -d --force-recreate lupin-rest-test
```

**Verify it landed** (this is the exact probe that fails today):

```bash
docker exec lupin-rest-test python3 -c "
import sys; sys.path.insert( 0, '/var/lupin/src' )
from cosa.agents.gemini_vertex_client import GeminiVertexClient
c = GeminiVertexClient( model_name='gemini-3.1-flash-lite', location='global' )
print( c.run( 'Reply with the two letters OK and nothing else.' ) )"
```

### Two things this change drags with it

1. **The parity test will go red without a declaration.**
   `src/tests/unit/deploy/test_compose_service_parity.py` fails any mount or env key present
   on one of `lupin-rest-{dev,test}` and not the other unless it carries a dated
   `KNOWN_DIVERGENT_MOUNTS` / `KNOWN_DIVERGENT_ENV` entry. Either add both entries, or mount
   into **dev as well** — which needs its own `--force-recreate` and therefore takes `:7999`
   down for the fleet for the length of a recreate.

2. **What is actually being handed over.** The host ADC is an `authorized_user` credential —
   Rick's own Google account refresh token, quota project `hello-world-foo-423219`, file mode
   600 — not a scoped service account. Mounting it gives everything running in that container
   Rick's user-level Google access, not Vertex-only access. The container already holds a
   Claude OAuth grant and `~/.lupin`, so this is not a new *class* of secret there, but it is
   a broader one. **A Vertex-only service-account key would be the tighter fit** if we are
   willing to create one; that is a Rick decision, not a crew decision.

## 3. Option B — run the paired replay host-side

The replay does not need the server: `_apply_dm_tutor` is a pure function and the harness
calls it in-process, so the whole study runs from the host where ADC already works. What is
lost is the `:8000` submit protocol — no scheduling, no queue-order coordination, no monopoly
guarantee, and no record of the run in the test-suite reports.

Cheaper today, worse afterwards: the run stops being reproducible by anyone who did not watch
it happen. Recommend A.

## 4. What does NOT need this change

- Everything in `src/tests/unit/test_flash_lite_arm_vertex_markers.py` except the live test:

  credential-free container exactly as they do on the host.
- The phi_4 arm: local vLLM over HTTP, no Google credential involved.
