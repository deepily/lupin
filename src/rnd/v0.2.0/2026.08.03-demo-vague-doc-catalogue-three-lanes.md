## Root cause — three distinct mechanisms (corrected 2026-08-03)

There is **not one root cause. There are three distinct failure mechanisms**, and the original "the system can't see his document" story was only ever true for one lane as measured.

- **Lane 1 — routing.** The LLM router sends the request to *research*-to-podcast (which researches a topic from scratch), so his existing file is never even looked for. No resolver is reached.
- **Lane 2 — context overflow (as measured), scope (post-fix).** The expeditor's fuzzy handler had **no keyword pre-filter**, so it sent all ~1958 `/src` markdown files to phi-4's 8k context → **HTTP 400**, caught at `expeditor.py:1172` → *"Matching failed."* It **never judged the description, never reached scope.** Rio's shared pre-filter (commit `e651bc76`) removes the overflow; **post-fix, Lane 2 reaches the judgment and then hits the scope wall** (below).
- **Lane 3 — scope.** Its resolver (`match_research_docs`) already had the pre-filter, so it reached the judgment, found no in-scope candidate, and returned **HTTP 404**. This is the genuine "can't see his document" case: `brevity-mandate.md` is in `/var/external-projects/planning-is-prompting/`, outside `/src` + `io/deep-research/<email>`.

**Scope is the shared wall for Lanes 2 (post-fix) and 3 — but it was NOT what Lane 2 hit when measured.** The overflow crash masked it. Two failures wore the same *"Matching failed"* wording only because the expeditor's `except` branch reuses that string regardless of cause. Lane 1 is a separate routing problem that scope changes do not touch.

## The fix — and why it is NOT a one-line config change

The obvious move is "add the doc's directory to `podcast generator source search paths`." **That does not work as pure config.** Two code barriers confine resolution to the project root:

1. `match_research_docs()` (`podcast_generator.py:230`): `abs_search_dir = project_root + search_dir`. The config value is concatenated onto `/var/lupin`, so an absolute `/var/external-projects/...` mis-joins to `/var/lupin/var/external-projects/...` → does not exist → skipped. It can only ever walk directories **under** the root.
2. `validate_source_path()` (`podcast_generator.py:508, 643`): prepends the root to ANY path (even one starting with `/`) and exists to block directory traversal. An out-of-root document is rejected by design; widening it is a **security-boundary** change, not a config tweak.

**A symlink does NOT get around this — it must be a real copy.** `validate_source_path` resolves the path with `os.path.realpath` (`podcast_generator.py:176`), which *follows symlinks to their real location*. A link placed in the user's deep-research dir but pointing at `planning-is-prompting` resolves back OUTSIDE the project root, and the traversal guard then rejects it (proven by Mr Radio, 2026-08-03). Copy the bytes; do not link.

**Two honest options for Rick:**

- **(A) Code change** — teach `match_research_docs` + `validate_source_path` to accept a whitelisted external root (e.g. the `planning-is-prompting` mount). Real work; touches a traversal guard; needs review.
- **(B) No code, same-day** — **copy** (not symlink — see above) the KISS/brevity explainer into a directory the resolver already scans (`/src` or the user's `io/deep-research/<email>`). Then **Lane 2 and Lane 3 resolve the vague description** and Rick gets his podcast without a code change. (Lane 1 still routes to research-to-podcast; making Lane 1 work is the separate auto-submit / routing decision.)
  - ⚠️ *Correction dependency (2026-08-03):* Option B makes **Lane 2** work **only because the overflow crash is now fixed** (commit `e651bc76`). Before that fix, copying the doc into `/src` would NOT have rescued Lane 2 — the resolver still shipped all ~1958 files to phi-4 and 400'd before judging, so the copy would never have been considered. Post-fix, the pre-filter narrows to the copied doc's keywords and it resolves. **Lane 3 was always copy-fixable** (it had the pre-filter already).

Recommendation for Thursday: **Option B (a real copy)** — it is the lowest-risk path to a working live demo, and it is reversible.
