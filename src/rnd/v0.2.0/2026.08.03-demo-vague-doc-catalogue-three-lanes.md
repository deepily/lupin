## The single root cause

Every lane fails Rick's goal for the same reason: **the system cannot see his document.** The lone resolver that maps a description to a file — the phi-4 fuzzy matcher — searches only `/src` and `io/deep-research/<email>`. `brevity-mandate.md` is in `/var/external-projects/planning-is-prompting/`, outside that set.

- **Lanes 2 and 3** invoke a resolver and it returns no candidate → "Matching failed" / 404.
- **Lane 1** never reaches the resolver at all: the LLM router sends the request to *research*-to-podcast (which researches a topic from scratch), so his existing file is never even looked for.

The differences between the lanes are in *how far each gets* before the same wall (or a route that avoids the resolver entirely); the wall itself is one thing.

---

## The fix — and why it is NOT a one-line config change

The obvious move is "add the doc's directory to `podcast generator source search paths`." **That does not work as pure config.** Two code barriers confine resolution to the project root:

1. `match_research_docs()` (`podcast_generator.py:230`): `abs_search_dir = project_root + search_dir`. The config value is concatenated onto `/var/lupin`, so an absolute `/var/external-projects/...` mis-joins to `/var/lupin/var/external-projects/...` → does not exist → skipped. It can only ever walk directories **under** the root.
2. `validate_source_path()` (`podcast_generator.py:508, 643`): prepends the root to ANY path (even one starting with `/`) and exists to block directory traversal. An out-of-root document is rejected by design; widening it is a **security-boundary** change, not a config tweak.

**Two honest options for Rick:**

- **(A) Code change** — teach `match_research_docs` + `validate_source_path` to accept a whitelisted external root (e.g. the `planning-is-prompting` mount). Real work; touches a traversal guard; needs review.
- **(B) No code, same-day** — place or symlink the KISS/brevity explainer under a directory the resolver already scans (`/src` or the user's `io/deep-research/<email>`). Then **Lane 2 and Lane 3 resolve the vague description** and Rick gets his podcast without a code change. (Lane 1 still routes to research-to-podcast; making Lane 1 work is the separate auto-submit / routing decision.)

Recommendation for Thursday: **Option B** — it is the lowest-risk path to a working live demo, and it is reversible.
