## 1. It shipped

The gate exists and is real code, not a plan. `routers/dm.py:1925` states the contract:
*"length gate: `rejecting` + over threshold + not exempt → HTTP 413 with a body that states
the action WITHOUT naming the threshold (undisclosed)."* The undisclosed-refusal wording is
implemented (`:2005-2008`), the exempt-sender list is implemented, and the corpus row is
written in a `finally` so a crash still persists an honest outcome.

## 2. It is switched off, deliberately and safely

`is_suspended()` (`src/cosa/rest/dm_experiment.py:250`) reads the flag, and
`load_default_policy()` short-circuits to `make_inactive_policy()` when it is true — so
`assignment_at()` returns `None` for every instant and **no DM is gated at all**.

Two design choices there are worth keeping and are NOT defects:

- **It suspends at policy construction, not at the call site.** Every reader — the gate, the
  corpus stamp, the pool-status view — agrees the pilot is off, instead of one branch
  believing it is still running.
- **A config-read failure returns `True`**, i.e. stays suspended. That is the safe direction:
  an experiment that silently resumed on a failed read would gate live traffic on an arm
  nobody chose.

The reason for the suspension is sound and stands (Rick, 2026-08-13): the DM tutor is the
live treatment, and a rejecting hour would refuse the very messages the tutor exists to
shorten, so no row could say which mechanism did the work.

## 3. The property Rick asked for is missing

Rick's proposal (recorded in `5c78f7f9`, 2026-08-01) was: *do not publish the limit, and draw
it randomly between 150 and 250 so it cannot be gamed.* **The unguessability IS the
anti-gaming mechanism** — the refusal text is deliberately undisclosed, which only buys
anything if the number behind it is not a constant.

What is implemented is a single fixed integer, read once at startup into the policy object
(`dm_experiment.py:122`, config at `lupin-app.ini:1129`).

⇒ **Mr. Radio's own engineering note on this row is not implemented, and the failure he
predicted is worse than he described it.** He wrote that as drafted, *"a rejected DM retried
unchanged succeeds about half the time, which teaches retry-beats-editing."* Against a fixed
threshold, an unchanged retry does not succeed half the time — **it fails 100% of the time,
deterministically.**

That is better on the retry axis and worse on his actual concern. The gaming vector is not
retry; it is that **one probe reveals the constant to everyone, permanently.** A sender who
learns 150 can sit at 150 forever, which is precisely the outcome the randomization was
specified to prevent. Hash-seeding the threshold on the body (his fix) would restore both
properties at once: unguessable across senders, and stable for a given text so a rejection
sticks until the words actually change.

## What this means for the row

The row asks to be closed as superseded or revived. Neither is available:

- **Superseded** would require the reject to be doing the work the rewriter was for. It is
  not doing any work.
- **Revived** requires the row's own stated condition — *"if the hard reject ships and DMs are
  still long, i.e. authors route around it by splitting one long message into three."* That
  condition is **untestable while the gate is off.** You cannot observe authors routing around
  a refusal that never fires.

So the honest state is: **the rewriter is parked behind a decision nobody can make yet**, and
the cost question the 2026-08-02 amendment sharpened ("an API rewriter is metered against a
real bill; measure the net saving before believing it") remains open and unmeasured.

## What is NOT recommended here

**Do not flip `dm experiment suspended`.** That is Rick's, and the suspension has a live
reason (the tutor). This document changes nothing; it records what is true so the next
reader does not re-derive it.

If and when the flag is flipped, the threshold should be hash-seeded first — otherwise the
mechanism is gameable on day one, and the first sender to probe it hands the constant to
everyone.
