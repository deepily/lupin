# P0-2 Recon — target_duration_minutes → slide-count, and what a 60-min deck hits

**Author**: Clayton 😎 (Implementer, Mr. Radio's SWE crew) · **Date**: 2026-08-05
**Status**: RECON ONLY — no code authorized. María owns the architecture; this is the measured ground.
**Every claim below carries a file:line. Nothing is reconstructed from the spec.**

---

## TL;DR

The slide count is a **derived soft target**: `slide_budget = int( target_duration_minutes × slides_per_minute )`, computed identically in 4 places, and handed to the model as the prompt line *"Create exactly {slide_budget} slides."* No hard cap exists anywhere. `slides_per_minute` defaults to **1.0** (INI), so 15 min → 15 slides — that is the `budget: 15` Rick saw. A 60-min deck (→ 60 slides) hits **two real ceilings**: the outline phase is a **single un-chunked API call** that will truncate-and-fail-loud, and the source doc is **truncated to 30 000 chars** before narrative analysis.

## The five questions

### Q1 — Where does `target_duration_minutes` go once collected?

Full trace, expeditor → the thing that sizes the deck:

| Step | Location | What happens |
|---|---|---|
| Arg map | `agent_registry.py:140-142` | `target_duration_minutes` / `duration` / `minutes` → `target_duration_minutes` |
| Job param | `presentation_generator/job.py:58` | ctor kwarg `target_duration_minutes` |
| Job field | `job.py:106` | `self.target_duration_minutes = target_duration_minutes` |
| Into config | `job.py:249-250` | `if self.target_duration_minutes is not None: config.target_duration_minutes = …` |
| **Sizes the deck** | `orchestrator.py:739, 801` (and `narrative.py:153`) | `slide_budget = int( config.target_duration_minutes × config.slides_per_minute )` |

So the terminal consumer is the `slide_budget` arithmetic in the narrative + outline phases.

### Q2 — What decides the slide count today? **Name the line.**

**A derived value, then a prompt instruction — not a constant, not a model judgement.**

- The number: `slide_budget = int( target_duration * slides_per_minute )` — `narrative.py:153`, echoed at `orchestrator.py:739` (narrative), `orchestrator.py:801` (outline), `orchestrator.py:1779` (Gate 1 summary).
- The two inputs are INI keys (`config.py:94-95`): `presentation generator target duration minutes = 15` (`lupin-app.ini:1666`) and `presentation generator slides per minute = 1.0` (`lupin-app.ini:1667`).
- How it becomes slides — **it is a prompt instruction to the model**, quoted:
  - `outline.py:235`: *"1. Create exactly {slide_budget} slides following the structural formula"*
  - `outline.py:221-224`: budget split into `opening_count=2` (`outline.py:179`), `closing_count=3` (`outline.py:180`), body = the remainder (`outline.py:181`).
  - `narrative.py:200`: *"The total proposed slides for content sections should be close to {content_slide_budget}."*

So `15 = 15 min × 1.0 slides/min`. The `budget: 15` in both of last night's runs = the default duration untouched, times the default pace.

### Q3 — Is there a ceiling a 60-min deck would hit?

**No hard cap on slide count / duration** — `config.py` has no max, `__main__.py` arg parser has no `type=`/bound on duration (`__main__.py:96-97`, `114`). But two soft ceilings bite at 60 slides:

1. **Outline phase is one un-chunked call** — `orchestrator.py:848` `call_for_outline(...)` produces ALL slides in a single response, and unlike elaboration there is **no `_outline_chunked` fallback**. A ~60-slide outline risks a truncated/unparseable response, and `_outline_async` is **D6-STRICT fail-loud** — on parse failure it re-raises → job FAILED (`orchestrator.py:892-900`). **This is the hardest ceiling.**
2. **Source truncated to 30 000 chars** — `narrative.py:178-180` clips the source doc before analysis. A 60-min talk's source material is analyzed from only its first 30k chars.
3. Elaboration is **safe** — it has a chunked fallback at `batch_size = 6` (`orchestrator.py:1097`, triggered `1008-1012`), so per-slide content generation scales fine.

### Q4 — What would "specify the slides to be included" attach to?

An existing per-section structure already exists to name into:

- **Narrative sections** carry a per-section `proposed_slide_count` — `narrative.py:261`, validated `narrative.py:270-274`; surfaced to the user at Gate 1 (`orchestrator.py:1778-1784`).
- **Outline entries** (`SlideOutline`) carry `source_hint` tracing each slide to its narrative section — `orchestrator.py:869`, `outline.py:239`.

There is **no existing "include only these slides/sections" filter** — no allow-list, no per-slide toggle. A user selection would need a NEW filter layer, but it can attach to the section headings / arc positions that already exist (no new identity scheme needed).

### Q5 — What is already user-controllable but not exposed?

- **`slides_per_minute`** — the direct lever on deck density — is INI-only. It is NOT in `arg_mapping` (`agent_registry.py:134-148`), so the Q&A path cannot set it. Exposing it is the smallest change that lets a user say "denser/sparser."
- **`title_style`** (`config.py:45`) and **`max_revisions`** (`config.py:46`) — INI-only, not mapped.
- **Already exposed** via the expeditor Q&A path: `source`, `target_duration_minutes`, `audience`, `audience_context`, `theme` (`agent_registry.py:134-155`). Duration IS already collectable — last night defaulted because it wasn't spoken, falling to `fallback_defaults ... "default"` (`agent_registry.py:157`).

## Note for María's architecture

- A 60-min deck is **not** a config-value change alone — it needs the **outline phase chunked** (mirror elaboration's `batch_size` pattern) and the **30k source truncation** revisited, or the deck fails at outline / analyzes a fraction of the source.
- "Specify slides to include" has a **home** (narrative sections / arc positions) but **no mechanism** — it's a new filter, not a new data model.
- The `fallback_defaults` duration is the string `"default"` (`agent_registry.py:157`), not an int — worth a glance that it resolves cleanly before it reaches `int( … )` at `orchestrator.py:739`.
