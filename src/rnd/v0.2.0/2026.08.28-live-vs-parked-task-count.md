# The task-list header counted deferred work as remaining work

**2026-08-28 · María 🌸 (`124bd1de`) · planning-is-prompting seat, lupin change**
**Scope ruled by Rick**: notifications client only (multiplexer card and epic board unchanged, deliberately)

## The defect

The notifications Task List header printed **one number**: every open row.

Rick, this morning: *"Right now I see we have 8 tasks listed total. But that's not actually true because 5 of them are parked."* A board of 3 workable rows and 5 deliberately-deferred ones read as **8**, so every conversation about driving the board to zero started from a figure that was 60% rows nobody intended to touch.

**One line**, `notifications.js:9650`:

```js
if ( countEl ) countEl.textContent = String( openTasks.length );
```

## What parked actually means — and the wrinkle worth knowing

Parked = a human ruled the row **not-now**. Approved, blocked on nothing, carrying a `park_reason` (a quote of the row's own decisive sentence) and a `next_chase_ts`. Bounded and self-expiring; an indefinite hold is `dropped`, because dropping is visible.

🔴 **Parked is a status PLUS a live clock, not a flag.** The canonical rule — `park_is_active()`, `cosa/rest/task_store_owed.py:184`:

> `status == "parked"` **AND** `next_chase_ts > now`

So a parked row whose chase time has **passed** is no longer parked. It rejoins the owed count at **read time** — nothing sweeps it, no daemon, no human action. Same for a null or unparseable chase, which the store calls *fail-loud-toward-owed*: a malformed park is visible work.

⇒ **Live = open rows MINUS park-active rows.** Not "minus rows whose status says parked." A "Parked: 5" that becomes "Parked: 4" at 09:00 with no row touched is **correct behavior, not drift**.

## The change

**`src/lupin_app/static/js/notifications.js`** — two new pure helpers plus three call-site lines:

| Function | Does |
|---|---|
| `_formatTaskListCount( live, parked )` | `Live: 3 · Parked: 5 · Total: 8`; **bare `3` when parked is 0** — the split is a disclosure that only earns its space when there is something to disclose |
| `_taskListCountText( openTasks, now )` | Counts the parked side through the existing `_taskIsParked()`, so the header and the row dimming can never disagree |

Call sites: the fresh-fetch render, and the **outage replay** of last-known rows — that second one matters, because a header that kept printing a raw length there would silently change meaning the moment the store blinked.

**No markup change.** The `#task-list-count` span carries the whole string.

**Not touched**: no store change, no endpoint change, no new task rows (moratorium in force). Data already on the wire; presentation only.

## Tests — 145 pass, and the one that matters was falsified

`src/tests/unit/notifications_js/task_list_panel.test.ts`, 11 new cases.

**The falsifying case**: two rows identical except their chase time — one future, one past — must read `Live: 1 · Parked: 1 · Total: 2`. Replacing the predicate with `t.status === "parked"` reports `Live: 0 · Parked: 2` and **goes red**. Measured:

```
MUTANT: const parked = rows.filter( t => t && t.status === "parked" ).length;
  not ok 125 - 🔴 _taskListCountText: an EXPIRED park counts LIVE, not parked
  not ok 126 - _taskListCountText: a null chase counts LIVE (fail-loud-toward-owed)
  # pass 143  # fail 2
REVERTED: # pass 145  # fail 0
```

**One existing assertion changed meaning, deliberately.** `task_list_panel.test.ts` used to assert a single parked row counts `"1"`; it now asserts `"Live: 0 · Parked: 1 · Total: 1"`. That edit is the visible record that the number's meaning moved.

**e2e is unaffected and that is checked, not assumed**: `test_task_list_card.py` seeds no parked rows, so its `str( OPEN_COUNT )` assertions still meet a bare number.
