## The defect

`marp --pptx` rasterizes every slide to a PNG (`orchestrator.py:1753`). Finished decks
carry **zero selectable text** on the slides — measured 0 `<a:t>` runs across slide parts
on both 2026-08-05 builds. Speaker notes are real text and are fine (8,235 words in one
deck); the defect is the *slides* only.

## Verdict: renderer switch, not structural

Confirmed by Cheech 🌿 (owns the orchestrator) and by the code. `PresentationModel`
(title / subtitle / content_bullets / speaker / date / presenter_notes per slide) is passed
intact to the Phase 8.5 export call `_export_pptx_async( presentation )`
(`orchestrator.py:1718`). The structured text survives to the export boundary; Marp is the
only thing that discards it. So the fix is a new export path, not a pipeline rewrite.

## Text REPLACES the image — it is not an overlay

Each slide is built from scratch in python-pptx: native text frames (title / subtitle /
bullets) plus the slide's real notes slide. The Marp full-slide PNG is **not reused**. Only
genuine *content* images (charts, diagrams) are embedded as separate pictures alongside the
text. The text is real PowerPoint `<a:t>` runs — selectable, copyable, screen-reader-visible.
The look changes precisely because we own layout now; that is the trade Rick accepted, not a
cost that could have been avoided by overlaying text on the old rendering.

## Design

### New: `renderers/pptx_deck_renderer.py`

`PptxDeckRenderer.build( presentation, theme_config, visuals_dir, output_path )` — pure
build from the model, no LLM, no async. Slide-type dispatch mirrors `MarpTextRenderer`:

- **title** → centered title + subtitle + `speaker | date` line.
- **content / key_point / evidence / hook / agenda** → title, optional subtitle, bulleted body.
- **section_divider** → centered title + subtitle.
- **conclusion / summary / cta / qa** → same as content.

For a non-`text_only` slide, locate its raster file in `visuals_dir` by placeholder index +
renderer prefix; if found, place it beside/below the text. Speaker notes → the slide's real
notes slide via `slide.notes_slide.notes_text_frame`.

Layout uses `python-pptx` primitives (`Presentation`, blank layout, `add_textbox`,
`shapes.add_picture`). Theme colors come from `theme_config` (same dict Marp uses). The look
**will differ** from Marp — accepted by Rick; not a regression.

### `deck_verdict.py` — text-layer assertion

Add `_count_slide_text_runs( zf )`: count `<a:t>` elements across `ppt/slides/slideN.xml`
parts **only** (never `ppt/notesSlides/*`). Add a `min_text_runs=1` parameter to
`verify_presentation_deck`; a deck below the floor is a hard `False` with a specific reason.
Today's all-image decks fail this; a v1-built deck passes it.

### Orchestrator wiring — `_export_pptx_async`

Replace the `marp --pptx` subprocess with a call to `PptxDeckRenderer.build(...)`, sourcing
`presentation`, the theme config, and `visuals_dir` (`os.path.dirname(marp_path)/visuals`).
Keep the non-fatal contract: on failure, MD + YAML still deliver. `pptx_export_enabled` and
`dry_run` guards unchanged.
