## CORRECTION — the mechanism is DEMOTION, not exclusion (Cheech, 22:40 EDT)

I wrote "the resolver SKIPS your current memento." **That is wrong, and I had repeated it
from the DM rather than reading the code.** Cheech caught it. Read the code:
`register_session.py`, `_memento_candidates`.

**What actually happens.** Every candidate gets a sort key:

```python
if stamp: sort_key = ( 1, stamp )                      # has a memento-record header
else:     sort_key = ( 0, str( os.path.getmtime(path) ) )   # headerless
...
return sorted( out, key=lambda row: row[2], reverse=True )
```

A headerless file is **a candidate, and is never dropped** — the function's own docstring
says so: *"A record with neither still appears — it ranks last, but it is never silently
dropped."* `_persona_of` even falls back to the FILENAME for persona matching precisely so
headerless records stay reachable. Keeping them was deliberate design.

⇒ **The defect is that the tuple's first element makes the demotion UNCONDITIONAL.**
Tier 1 beats tier 0 on the first comparison, so `written_at` and `mtime` are never even
reached across tiers. **No amount of freshness rescues a headerless file.** A headered
record from any date outranks a headerless one from today.

**Why the outcome looked identical to a skip**: with one headered file present, demotion to
last place and exclusion select the same winner every time. My measurement was right —
`john-d4eed929.md`, Aug 17, seven days stale — and my explanation of it was wrong. The
observable was real; the mechanism I attached to it was borrowed, not derived.

⇒ **The general shape, worth keeping**: a correct measurement does not validate the story
you tell about it. I reproduced the symptom live and then narrated a cause I had not read.
Read the ranking function before describing a ranking bug.

**Nothing about the remedy changes.** Regenerating the slot as a pointer with a
`memento-record` header on line 1 promotes it to tier 1, where the `written_at` comparison
finally applies and the newest genuinely wins. `resolve --persona john --slot io` now
