## THE ANSWER, in six lines with none of our code in them

```js
import assert from "node:assert/strict";
import { GlobalRegistrator } from "@happy-dom/global-registrator";
GlobalRegistrator.register();
const el = document.createElement("div");
document.body.appendChild(el);
assert.equal(el, null);        // dies here, ~2.5 GB/s, until the kernel intervenes
```

`node:assert` builds its failure diff by deep-inspecting the ACTUAL value; on a happy-dom
element that walk goes element then `ownerDocument` then `defaultView` then the whole `Window`
graph, and never terminates.

**Needs all three at once** (3 runs per cell): happy-dom registered, a DOM node as the actual
value, and **the assertion FAILS**. Remove any one and it survives at ~86 MB.

**A CUSTOM MESSAGE DOES NOT SAVE YOU** — measured 22:08, and the opposite of what I expected.
`assert.equal(el, null)` killed; `assert.equal(el, null, "custom message")` **also killed**;
`assert.ok(el === null, "msg")` survives, msglen 14, rss unchanged.
So the trigger is the DOM node being the actual value, **not** the rendering of a visible diff.
Rule text must say: *"a custom message does NOT make it safe."*

## THE CHEAP RIG CHECK — runnable cold, by whoever reads this next

The 2 GB ceiling rides on ONE unmeasured quantity: what four DIFFERENT workers cost when
resident at once. Everything measured so far is one file.

```bash
source src/scripts/lib/jstest-slice.sh
JSTEST_RSS_MAX_MB=100000 JSTEST_POLL_SECS=0.05 jstest_watchdog_exec \
  node --test-concurrency=4 --import tsx --test <4 to 8 DIFFERENT *.test.ts files>
```

Read the `peak RSS` line. The ceiling is deliberately absurd so the run MEASURES instead of
killing. It takes seconds.

**What it settles**: whether per-worker cost stacks. If four files land near 800 MB, the margin
is **2.5x, not 10x** — which makes the cap **merely adequate** rather than generous, and that is
worth knowing BEFORE the 119-file run rather than after.

🔴 **IT IS NOT THE SUITE MEASUREMENT AND MUST NOT BE REPORTED AS ONE.** It bounds the per-worker
question only. The 119-file peak still needs the real run, and **that run IS the first
measurement — an experiment, not a gate.** If it goes red, read the number; do not re-condemn
the tier.

⚠️ **Both halves of the 2 GB number's provenance, so it is never quoted bare**: 196 MB
single-file on a full process tree and 205 MB at concurrency 4 are **the same one file run two
ways**, not four different workers. Anyone quoting a margin from them is quoting one that was
