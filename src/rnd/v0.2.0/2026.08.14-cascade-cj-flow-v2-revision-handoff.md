## 3. Per-section revision summary

### 3.A — Module layout, registry, endpoint contract (§1, §3, §3a, §8) — **CLOSED**

13 findings (Rachel 6, Tiberius 5, Rio 2). None foundational. One re-litigation round.

**R-A1 · Registry keys on the full routing string.** `AgentSpec.command` is the full string (`"agent router go to weather"`); short forms go in `aliases`. **Why it matters**: the §9 registry-guard test could not be written *at all* until the key form was pinned — and that test is the plan's own named defence against the three-mechanism drift reappearing.

*Correction found by verifying the proposal*: two of three sources use the full string, not three. `MODE_TO_AGENT` keys on short forms (`math`, `calendar`, `weather`) while the router template and `AGENTIC_AGENTS` use the full string. **That disagreement is the drift the registry exists to kill** — an argument for the split, not against it.

**R-A2 · The guard needs a fourth bucket.** The router template (`src/conf/prompts/agent-router-template-completion.txt`) carries **fifteen** commands including `agent router go to automatic`, which the plan never mentions — a set-equality guard fails on its first run. `automatic` is a **mode-control command**, not an agent: it clears the user's mode and returns early (`todo_fifo_queue.py:739-747`). Buckets: registry entry · deferred set · receptionist-or-none · **`CONTROL_COMMANDS`**. Same bucket settles `receptionist`.

**R-A3 · "One factory serves all six" is a constraint, not a note.** The registry pins the **non-CRUD** classes and must not copy the v1 constructor block — that block forks calendar and todo to CRUD agents (never snapshotted, so those two report 0% cache-hit forever and it will read as a v2 bug) and passes `MathAgent` a different first argument. A single `factory` field cannot express the fork.

**R-A4 · The stats surface owes two more rates.** Degrading an agent failure to the receptionist with `route_reason="agent_error"` is correct — a failure should never 500 or abort an eval run. But **there is no `agent_error_rate`**, so an agent failing on *every* request produces a run that looks like healthy receptionist traffic and the eval reports success. Add `agent_error_rate` and `replay_failure_rate`. *This is the plan's own risk-6 lesson — "a dead model server masquerades as success" — applied to the router and not to the agent.*

**R-A5 (cluster, see R-D10)** · the registry-guard test carries no `EXECUTOR:` tag and names no coverage assertion.

**Documented, not revised**: `v2/registry.py` collides by name with `runtime_argument_expeditor/agent_registry.py`; a reader grepping "registry" hits two. Suggested `command_registry.py` — author's call.

### 3.B — Executor seam, argument chain, never-block contract (§2, §4, §5, weather) — **CLOSED**

15 findings (Rachel 8, Tiberius 5, Rio 2). None escalated. Two re-litigation rounds. **A Stage-1 ruling was reversed at Stage 2** — the pipeline working as designed.

**R-B1 · Unit B is a lift with the spec passed in, not a verbatim lift.** The plan says both: the work breakdown calls unit B *"verbatim lift, no logic edits"* while its own weather section requires `extract()` to serve a command **not** in `AGENTIC_AGENTS`. The weather section is the correct half.

**R-B2 · The spec is REQUIRED — no fallback to the table.** The plan had `extract()` fall back when no spec is passed; that is the silent-fallback anti-pattern Lupin's fail-loudly rule names. **Layer 1, not a judgment call.** The author extended the rule to `collect()` unprompted, having found the symmetric case in her own plan.

**R-B3 · The spec is a typed `ArgSpec` carrying every field — this reversed R-B1's first form.** `extract()` reads **six** fields off the agent entry — `arg_mapping`, `fallback_defaults`, `fallback_questions`, `required_user_args`, `special_handlers`, `system_provided` — and `collect()` reads `display_name` and `fallback_questions`. Seven distinct. **A spec carrying only `required_args` cannot feed either, and the concrete failure is that "what's the weather" never parks and runs location-less — the exact case the demo exists to prove, silently succeeding.**

Chosen over passing the raw entry because the untyped dict is what the design exists to retire, while **a typed spec is the north-star queryable interface** — the same trade the plan already made for its resolution order, paid early on the cheapest agent. `expedite()` constructs the `ArgSpec` from the table, so v1 callers stay byte-identical.

**Attached requirement**: `extract()` must source `user_visible` from the spec's `fallback_questions` when present, or it shells out to `get_cli_help` for a CLI weather does not have.

**R-B4 · Weather proves the GATE, not the consumption.** The weather agent has no `location` parameter; it web-searches the raw question string (`weather_agent.py:84`). v2 therefore **composes** the question from the extracted location rather than passing a kwarg — needing **zero changes to any v1 agent**, cheaper than the plan implies. But the agent then re-parses the location out of the recomposed question, so the extracted value is validated as a `needs_input` **gate** and never **consumed** as an argument.

⇒ **Phase-1 definition of done: "proves extract-and-park, zero v1 behavior change."** *"Agent consumes the arg"* is a phase-2 claim gated on `declared_args()`. This does not contradict Rick — he deferred the north star himself; it contradicts the plan's own prose.

**R-B5 · The never-blocks guarantee needs a test.** The whole contract rests on `interactive=false` and nothing pins it. A bug that parks anyway returns a clean-looking 200 while leaking a thread, and the eval cannot see it.

*Manager ruling on the residual*: the `needs_input` resume **ships** in phase 1; the definition of done stays extract-and-park. Those conflict only if *built* and *proven* are conflated — the resume is real code that ships, but the eval runs `interactive=false` and never exercises it. **Phase 1 builds resume and proves park**, which is precisely why the test is owed.

*Second ruling — two owed items, not one.* **(a)** The never-blocks/park test: `interactive=false` → `PendingRequests` stays empty and no background thread spawns. **(b)** The resume path ships in phase 1 but its only output is TTS-to-human, so it needs an **AI-observable completion seam** — the resume thread writes a trace line on completion and updates a pollable `PendingRequests` status — tagged `EXECUTOR: AI`. Absent that seam, tag the resume verification `EXECUTOR: HUMAN <reason>`; **it may not be left implicit.**

**R-B6 · The split-guard test is behavioural and must be proven able to fail.** Patch `AGENTIC_AGENTS` to empty, call `extract()` with a passed spec, assert it still works — **not** a grep of the source, which passes for the wrong reasons and dies on a rename. Then reinstate the lookup, run the guard, **paste the actual red line**, and revert. A claim that it fails is not the red.

### 3.C — Cache and storage (§6, §6a) — **CLOSED**, one ruling parked

9 findings. One escalated (§4); four closed in-group.

**R-C1 · Don't float-compare for the headline number.** If replay fires only at exactly `100.0`, a warm-pass self-match at `99.9999` routes instead — **understating the cache-hit rate the entire experiment exists to measure**. The fix removes the bug class rather than adding an epsilon: a warm-pass repeat is a **tier-1 exact hit** via `question_normalized` string equality (`find_exact_normalized`), deterministic and lossless. Make that the replay signal; reserve the ANN float score for the *similar* tier only.

**R-C2 · The "would-be-wrong" column gets an automated oracle.** The corpus already carries the expected command per line as its JSON key. A replay is would-be-wrong when the matched snapshot's `routing_command` ≠ that utterance's expected command — automated, free, same source as routing accuracy. **Caveat to keep verbatim**: command-match is a *lower bound* (same command, different location still scores right), so it under-counts; a semantic oracle is phase 2. A column nobody can fill gets filled by hand or left blank, and either way stops being evidence.

**R-C3 · Wire the embedding cache — and it is the VERBATIM-keyed one, not the normalized one.** §6 treats embedding as always-computed; the warm pass replays the identical corpus, so an exact repeat can get its vector back with no model call. **Corrected 2026-08-14 (Mr. Radio 🦉, re-verified before writing)**: the original text named `EmbeddingCacheRepository.get_cached_embedding(normalized_text)` (`embedding_cache_repository.py:50`), which is the wrong cache for this column. **The principle: the cache must be keyed by the exact text that produced the ANN vectors.** Those vectors are `question_embedding`, generated from the snapshot's **own raw `question`** (`solution_snapshot.py:318-319`) — `question_normalized_embedding` is a separate field — and `question_embedding` is what the ANN index searches (`solution_snapshot_repository.py:6,107`, HNSW dot via `vector_search.py:95`). The matching cache is therefore **`QuestionEmbeddingRepository`, which keys on the exact question string** (`question_embedding_repository.py:35-51`, `QuestionEmbedding.question == question`). **Risk to assert, not assume**: key parity — a normalized-keyed lookup cannot serve a verbatim-keyed column, so wiring the wrong one misses every time and "free" evaporates silently. *Provenance: code-read, not run.*

**R-C4 · The storage guard proves a narrower thing than its name claims.** The no-LanceDB guard walks only **v2's own source** for direct imports. **Under the manager's own recommended option in §4 — a delegating shim — LanceDB could be transitively in the path while the guard stays green.** Ruled: the guard walks the **transitive import graph**. Decision row `29e98243` amended so the recommendation is not read as cost-free.

**Verified true** — two of the plan's four self-flagged second-hand claims: the mutable-default hazard on `SolutionSnapshot.__init__` (`solution_snapshot.py:176-184`), and `runtime_stats` as a `Text` column so the JSON version tag round-trips with no schema change.

## 6. Workflow-guidance candidates

1. **A handoff DM is a lossy channel.** DMs are condensed in transit, and *a pointer to where the real content lives is exactly the sentence a condenser drops* — the payload survives, the address does not. A Stage-2 reviewer held twelve minutes for a summary already on disk. **Fixed mid-run**: post the upstream summary to the section topic *before* the handoff DM, and tell reviewers to read the topic and never wait on a relay. Deposited to `post-game`.
2. **A reviewer's default reading is the instruction's problem.** The same reviewer apologized for the miss; it was a handoff-design failure, not a reading failure.
3. **Stage 2 reversing a closed Stage-1 ruling is the pipeline working.** R-B3 reversed R-B1 and prevented a silently-broken demo. Worth stating in the playbook so a manager does not treat it as process failure.
4. **A Layer 1 question is not votable.** A vote was offered in good faith on the fallback rule; accepting it would have implied the group can outvote a standing rule. It resolved when the author reversed independently, on reasoning she reached alone.
5. **Enumeration is not enforcement.** The manager ruled "a test at full scope" and then supplied a list of fields; the reviewer pointed out that a list is the same gap wearing a test's clothes. Guards assert a **property**, never walk an inventory.
6. **Build alongside review, hold the merge.** Units A and B were built in a worktree during the review and merged the minute both sections closed. Two defects — the by-reference mutation and the true seven-field contract — were found *by building*, not by reading, and neither would have surfaced in a review-then-build sequence.
