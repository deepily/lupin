## 🔴 Headline — one mechanism, found twice, that overturns phase 3's premise

Two reviewers arrived at the same thing from opposite directions: **the router never says "I don't
know."**

### María's probe — the vocabulary is not closed

Run in memory against a **copy** of the template, so the shared prompt file was never touched.

- A fake command **listed in the prompt** was emitted **10 of 10**.
- The **control arm** — the same fake command absent from **both** the prompt and the trained
  vocabulary — still came back **6 of 10**.

**What this changes**: the plan's *"a new command costs a three-to-four-hour retrain"* is **wrong as
written**. A retrain buys **reliability**, not **reachability**.

### Tiberius's §4 finding — the capability-gap detector cannot fire

A frozen-vocabulary router with **no confidence signal** confidently **misroutes** a novel request to
a trained command rather than returning *"unresolved."* So the capability gap is **invisible to its
own predicate** — and this holds regardless of how the probe came out.

### The live defect that falls out of both — row `d9ecd69e`

The response validator **never rejects an unknown command**, so an invented one falls through v1's
`else` and **silently web-searches the user's question**. v1 behavior today, not a phase-3 concern.

## Rachel 🕊️ — §1 (go/no-go criteria), §1a (rulings), §1.5 (harness output)

**Verdict**: the criteria are pre-registered but **not machine-decidable**. §1.5's harness cannot
actually settle a STOP, and the 20% bar is defended against noise while p95 and the sampling rule
quietly reopen it. **8 findings, 3 HIGH.**

### 1 (HIGH) — the harness cannot print the floor it promises to print

§1.5 claims *"verdicts filled in by the harness, not whoever reads it"* (line 129), but the
replay-correctness floor (lines 55, 137) is *"hand-checked, zero answers to a materially different
question"* — a **human semantic judgment**. A machine cannot print PASS on that row.

**Failure**: the harness emits a FLOOR PASS that was never computed, or leaves it blank and the whole
STOP hinges on the one unfilled row.

### 2 (HIGH) — no STOP row, and floors are not marked as vetoes

§1.5 prints 9 input rows but **no row for the STOP itself** (§1.4 lines 82-84 = not-faster AND
not-smaller), and does not mark the floors as vetoes (§1.2 line 49, *"any one failing ends it"*).

**Failure**: a v2 that is faster **and** smaller but fails the replay-correctness floor reads **GO**
from the top of the table — precisely the *"a criterion only a human remembers gets skipped"* failure
§1 opens with (line 29).

### 3 (HIGH) — p95 from n=60, and the pairing is thrown away

§1.1 puts **p95** in the bar (lines 43-45) while §1.4a samples **n=60 per command** (line 113); a p95
from 60 points is roughly the 3rd-worst observation, dominated by a single tail outlier on the resume
path. Line 35 also compares aggregate **p50-vs-p50 unpaired**, though v1 and v2 run the *identical*
utterances — discarding the pairing that would beat LLM variance.

**Failure**: GO/STOP flips on tail noise. Unpaired, 20% may be too small to detect a real win — or
large enough to reject one.

### 4 (MED-HIGH) — one sampling scheme serving two incompatible jobs

§1.4a's equal-n stratification (lines 113, 119) makes the headline cache-hit and latency numbers a
per-command **macro average**, which is not the frequency-weighted rate a user actually feels
(calculator 561 vs datetime 127, line 99). Per-command diagnosis and system-wide go/no-go need
different weightings.

**Failure**: v2 passes the macro bar while being slower on the command people actually use.

### 5 (MED) — the replay floor may be unmeasurable on the default run

§1.4a's n=60 sample vs the replay floor's **n≥30 hits** (line 55): a sampled run may not yield 30
cache-hittable utterances, so the floor is only measurable via the full-corpus flag — which line 116
treats as **optional**.

### 6 (MED) — the size criterion is double-defined

§1.3's hard **≤200 statements** (line 75, printed at §1.5 line 140) vs §1.4's fuzzy *"meaningfully
smaller"* (line 83). At 210 lines the two disagree, so the STOP conjunction is ill-defined at the
boundary.

### 7 (MED) — cold or warm pass is never stated

§1.1 line 35 never says whether latency is measured on the **cold** or **warm** pass. v2's tier-2
embedding is on the hot path when cold; the replay-formatter LLM dominates when warm. A 20% delta
could be an artifact of cache warmth rather than control logic.

### 8 (LOW) — cost estimate likely understated ~2×

§1.4a line 116's *"~960 for the cold/warm pair"* appears to count **v2 only**; the v1 arm of the
latency comparison doubles it.

### Clean

**§1a is clean** — the required-spec ruling and its rationale are sound. No findings.
