# Trust-criteria pins vs. the shipped harness — two pins now compute a false clean

**Row `2ebe4ccb`** · Krishna 🦚 · 2026-08-25 · **no `:8000` run required — this reads artifacts and code**

---

## The finding in one line

Two of §10a's eight pinned denominators, applied to the artifact that exists today,
compute **0.0** on a pass where **99 of 100 requests never finished** — the same
false clean that row `2ec6ad9c` just removed from the harness, now living in the
checklist's own rules.

## Why this is checkable now

`2ebe4ccb` waits on a clean paired run, and that wait is real. But §10d already
established the principle this doc follows: **the repair does not wait.** A pin that
would mis-read an artifact will mis-read a clean one the same way, and the whole point
of pinning denominators before a number exists is that they cannot be chosen after
seeing what they produce.

What changed since §10a was written (2026-08-21 ~20:05 EDT) is that the v2 agent path
became **asynchronous**. `/api/v2/ask` now enqueues and returns `status="waiting"`, so a
response can be a perfectly good HTTP 200 that reports **no outcome at all**. §10a
predates that state and has no line for it.

## The measurement

Against `io/v2-flow/eval-2026-08-25-16-53-36/records.jsonl`, warm pass, n=100:

| quantity | value |
|---|---|
| responses that returned HTTP 200 | 100 |
| responses reporting a **terminal** outcome | **1** (a `needs_input`) |
| responses still `status="waiting"` | **99** |
| responses carrying a `similarity` | **0** |
| replays | **0** |

### Pin #1 — cache-hit rate, denominator `n_ok`

    checklist rule:  hits / n_ok  =  0 / 100  =  0.0000
    shipped harness: 0.0 (n=1)    — observed AND cacheable, and it prints the n

A reader applying the pin gets a decisive-looking **0.0 over a hundred requests**. The
cache was never observed at all. Note the pin was **already** out of step with the
harness before `2ec6ad9c`: the cacheable exclusion (a command whose spec says
`snapshotable=False` can never replay) has not been `n_ok` for some time. The async
change widened an existing gap rather than opening a new one.

### Pin #4 — failure rate, `ok == False / n`, in each arm's own `ok` predicate

    checklist rule:  0 / 100  =  0.0000  failure rate

v2's `ok` predicate is **HTTP 200**. Every one of the 99 unfinished requests satisfies
it, so a pass in which essentially nothing completed reports a **flawless** failure
rate. This is the sharper of the two: pin #1 at least sits next to a cache the reader
might question, whereas a 0% failure rate is the number a reader uses to decide the run
is trustworthy enough to read the rest of.

## The checklist already contains the right doctrine — it was never applied here

§10a pin #3, verbatim:

> A path with **zero observations is `UNDETERMINED`, never `PASS`**: "never exercised"
> and "exercised and clean" are different findings and only one of them is evidence.

That is exactly the rule `2ec6ad9c` implemented for the cache metrics. The checklist
stated the principle for degradation paths and did not carry it across to the two rates
that now need it most. So this is not a new idea to ratify — it is an existing ruling
with two more places to apply.

## Proposed — for María (doc owner) and Mr Radio, not applied by me

**A ninth pin: the observation state.** Three states, not two:

| state | meaning | how it must be counted |
|---|---|---|
| **observed, succeeded** | terminal outcome, no error | numerator-eligible |
| **observed, failed** | terminal outcome, reported an error | in the denominator, not the numerator |
| **NOT observed** | 200 returned, `status="waiting"`, no outcome yet | **excluded from both, and its count published** |

And the consequence for the two pins:

- **Pin #1** — denominator becomes *observed* cacheable rows. Where **no** row was
  observed, the rate is **UNMEASURABLE**, never 0.0 (matching pin #3's own doctrine).
- **Pin #4** — a failure rate must publish `n_unobserved` beside it, or state that the
  arm's `ok` predicate cannot distinguish "succeeded" from "has not finished". v2's
  predicate cannot.

⚠️ **This is a v2-side change only.** v1's `ok` predicate is "a span was measurable",
which already implies both transitions were seen — v1 has no unobserved state, and §10a
pin #4's per-arm framing is what makes that expressible. The asymmetry is real and
should be stated rather than smoothed.

## What this does NOT establish

- It does **not** re-open `2ebe4ccb`'s wait on the clean run. Every item needing a
  **value** still waits (§10c).
- It does **not** claim the two pins were wrong when written. They were written against
  a synchronous v2; the path changed underneath them.
- The 08-25 artifact is **v2-only**. No `v2 ≥ v1` item is touched here, and no verdict
  is computable — §10c's table still answers that question, not a number.
- Whether any of this moves a **clean** run's figures is **unmeasured**. If the clean
  run polls to terminal, `n_unobserved` is 0 and every pin behaves exactly as written.
  This matters when it is **not** zero, and nothing today says which that will be.
