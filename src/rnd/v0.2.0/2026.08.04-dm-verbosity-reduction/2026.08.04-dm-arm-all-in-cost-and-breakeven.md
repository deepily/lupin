## 1. The finding: `est_tokens/delivered` treats a refused draft as free

`analyze_arms.py:384` computes:

```python
"mean_est_tokens_delivered" : _mean( [ r[ "est_tokens" ] for r in delivered ] ),
```

It averages over **delivered rows only**. Every token spent composing a draft that the
length gate refused is absent from the number. In the `rejecting` arm that is not a
rounding detail — it is 29,244 tokens across 109 refused drafts.

Divide *total* tokens by messages that actually landed and the comparison reverses:

| | blind | rejecting |
|---|---|---|
| attempts | 235 | 544 |
| delivered | 235 | 435 |
| gate-refused | 0 | **109** |
| tokens, all attempts | 47,752 | 97,693 |
| tokens burned on refused drafts | 0 | **29,244** |
| **published** per delivered | 203.2 | **157.7** → *looks 22% cheaper* |
| **all-in** per delivered | 203.2 | **225.1** → *11% more expensive* |

### Verified, not assumed

The cross-tab is clean — every `not_attempted` row is a length-gate refusal, no crashes
mixed in:

```
blind      passed    delivered      235
rejecting  passed    delivered      435
rejecting  rejected  not_attempted  109
```

And the tokens were genuinely spent: `est_tokens = len( body.body ) // 4` is stamped on
the draft that was composed and sent over the wire (`dm.py:869`) before the gate returns
413. The sender paid for it.

### The mechanism that sharpens it

Refused drafts average **268.3** tokens against **204.5** for a blind message. The gate
selects for the *longest* drafts by construction, so each refusal discards an
above-average message and then pays again for the rewrite.

---

## 2. The structural fact: a refusal can never pay for itself

For the message it refuses:

| | cost |
|---|---|
| under `blind` | D — the draft lands |
| under `rejecting` | D (burned) + R (the rewrite) |

Extra = R, always positive. **The draft is sunk the instant it is refused; no rewrite
recovers it.** So the arm cannot win on the message it acts upon. It can only win the
way Rick framed it — by future messages arriving shorter *without* needing a refusal.

That reframes the whole evaluation: this is not a per-message efficiency, it is an
investment with a payback period.

---

## 3. Break-even

| | |
|---|---|
| tokens spent on rewrites (the unrecoverable extra) | 16,115 |
| first-try messages available to repay it | 352 |
| each must be shorter by | **45.8 tokens = 22.4%** |
| **observed** first-try gap vs blind | **54.7 tokens = 26.8%** |

Blind averages 204.5 tokens/message; `rejecting` first tries average 149.8. Tuesday sits
**just above break-even** — roughly a 3% net saving.

### The margin is thin and rests on one assumption

Everything depends on whether the 26.8% gap is **caused** by the arm, or is just
different senders in different hours.

| Credit given to the arm | Tuesday result |
|---|---|
| all of it | **−3,147 tokens** (saving) |
| none of it | **+16,115 tokens** (loss) |

Those are bounds, not estimates. Reality is between them. A 4.4-point error in the causal
assumption flips the sign.

> The earlier "11% more expensive" figure reported to Rick is the **no-credit bound** — a
> per-delivered rate comparison that gives the arm nothing for its shorter first tries.
> Accurate as a bound; not the whole answer.

## 4. What settles it

**Co-primary B — "first attempts only"** — is the designed test for exactly this question:
it isolates restraint from retries. It currently reports `n_pairs=0`, because the
comparison matches Tuesday against Wednesday at the same clock hour and Wednesday has not
run. That is expected, not a defect.

Rick's 2026-08-04 ruling to extend collection through Wednesday is what makes it

## 6. Recommendation

Report **both** numbers side by side rather than replacing one with the other. The
published per-delivered figure answers "how long is a message that lands?"; the all-in
figure answers "what did a landed message cost?" Both are legitimate questions and they
have different answers — publishing only the first invites reading a 22% saving that the
retry has already spent.

Not implemented here: this is a measurement-definition change to a live experiment's
analysis, and changing how the corpus is scored mid-flight deserves a deliberate call
rather than a quiet edit. The corpus itself is untouched and append-only, so both numbers
remain computable from it at any time.
