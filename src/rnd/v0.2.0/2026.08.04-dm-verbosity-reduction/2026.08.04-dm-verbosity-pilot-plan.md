## Context

776 graded DMs show that returning a quality grade to the sender changed nothing
measurable: length flat across 24h (ρ=+0.036, t=+0.92), median 91 words against a
60-word target, 78% over target. All of them sat in one condition, so "nothing
happened" and "nothing was detectable" cannot be told apart.

Two review passes have since reshaped the design:

- **Expert review** (`2026.08.03-dm-verbosity-experiment-design-review.md`) — seven
  changes, all accepted. Two were my errors: a fixed `(hour+day)%3` rotation makes
  rejecting *always* precede graded, so carryover lands in the comparison arm; and
  five dose thresholds across ~20 rejecting hours gives four observations each,
  contradicting my own hour-as-unit-of-randomization argument.
- **Two-day recommendation** (`2026.08.03-dm-two-day-verbosity-pilot-recommendation.md`)
  — the real window is 28 hour-blocks, not ~60. Three arms would leave 9–10 blocks
  each. **Two arms give 14 each and permit a matched-clock crossover.**

**This plan implements the two-day recommendation.** Graded is dropped from the pilot
and restored next week.

**Intended outcome**: a defensible directional result — *"across 14 matched clock-hour
pairs, attempted excess words were X lower under rejection than under blind"* — not a
dose-response curve, not a causal claim about learning.

⚠️ **Hard deadline: Tuesday 09:00 America/New_York.** That is when the first slot
opens. Everything below must be live before it, or Tuesday's seven blocks are lost
and the matched design collapses to one day.

## The design

| | |
|---|---|
| **Window** | Tue 2026-08-04 and Wed 2026-08-05, **09:00–23:00 America/New_York** |
| **Blocks** | 28 hourly slots, 14 per day |
| **Arms** | `blind` · `rejecting` (150 words) — **graded deferred** |
| **Allocation** | 7 of each per day; Wednesday is Tuesday's mirror at every clock hour |
| **Constraint** | no run of the same arm longer than 2 hours |
| **Outside the window** | `assignment_at()` returns `None` — ordinary non-experimental behaviour |

Both arms withhold the grade, so the `quality` key is **absent in both** (not null,
not `""` — a present-but-empty key tells the sender it is being measured, which is
itself a treatment).

Wednesday-mirrors-Tuesday is what buys the power: every clock hour is observed under
both conditions, so time-of-day and workload rhythm difference out of the comparison.

## Implementation

### 1. Shared word count (unblocks E)

`dm_word_count( text )` in a shared module, imported by `dm.py` and both judges,
replacing the four inline copies. Only then does `word_count_version: 1` mean
anything.

### 2. Schedule generation

`src/scripts/dm-experiment/generate_schedule.py` writes an immutable, git-tracked
`src/conf/dm-experiment-schedule.json` from a **recorded seed — `20260804`**:

```python
tuesday   = randomize_with_max_run( [ "blind" ] * 7 + [ "rejecting" ] * 7, max_run=2 )
wednesday = [ "rejecting" if arm == "blind" else "blind" for arm in tuesday ]
```

28 explicit slots, each with `slot_id`, local hour, UTC instant, and arm. Timezone
handling via `zoneinfo` — slots are declared in America/New_York and stored with
their UTC equivalents, because rows record `assigned_at_utc`.

Generator asserts before writing: 14 per arm, 7 per arm per day, mirrored at every
clock hour, no run > 2.

### 3. Runtime policy object

Loaded **once at application startup**, not per request — `get_dm_feedback_arm()`
currently builds a `ConfigurationManager` per DM (`dm.py:488-505`); do not copy that.
Path follows the `_DM_TRAFFIC_JSONL` / `_DM_TRAFFIC_PRODUCTION_PATH` pattern
(`dm.py:351-357`) so tests redirect without blinding a self-guard.

```python
def assignment_at( arrival_utc ):
    """
    Resolve the experiment slot covering an instant.

    Requires:
        - arrival_utc is a timezone-aware UTC datetime

    Ensures:
        - returns a slot dict inside a declared active interval
        - returns None outside every interval — the experiment is inactive and
          ordinary non-experimental behaviour applies
        - never re-reads the clock
    """
```

**Resolve once, from the request-arrival timestamp**, and thread that assignment
through instrumentation, gate, logging, and response. A send may cross an hour
boundary; re-reading the clock mid-operation would split one message across two arms.

**The server is authoritative.** The MCP client forwards the server's response and
never computes the arm itself.

### 4. Corpus row

Written **before** the length gate, at the position the `sender_project` 422 occupies:

`schedule_id` · `slot_id` · `scheduled_arm` · `effective_arm` · `assigned_at_utc` ·
`reject_threshold` · `eligible_for_rejection` · `exemption_reason` · `length_gate`
(`passed|rejected|exempt`) · `delivery_outcome` (`delivered|failed|not_attempted`) ·
`follows_rejection` · `chars` · `est_tokens` · `word_count_version` ·
`override_reason` · `experiment: "two-arm-v1"`

`length_gate` and `delivery_outcome` stay separate — a row written pre-delivery
cannot honestly claim "accepted."

**`delivery_outcome` is initialized to `not_attempted` at row-write and never left
null** (Mr Radio, 2026-08-03). A crash between a passed gate and delivery must leave
an honest value, not an absent one a later reader treats as success.

**`follows_rejection`** is a boolean stamped at write time: was this sender's
immediately previous attempt **within the same hour-block** rejected? A per-sender
last-outcome lookup — not a retry chain — and it is what makes the first-attempt
co-primary in §7 computable without linking intents.

⚠️ **Scoped to the block, not to the sender's history** (Mr Radio, 2026-08-03).
Stamping from the previous attempt *full stop* would let the first message of a
rejecting hour inherit a flag from the blind hour before it — leaking treatment
across the very boundary the mirrored schedule exists to protect. **The lookup resets
at every slot boundary**; the first attempt a sender makes in a new block is always
`follows_rejection: false`.

**`est_tokens`**: Rick's target is token burn; excess-words-over-60 is a proxy for it.
`chars` is already measured, so record it explicitly and carry `est_tokens ≈ chars/4`.
Label it an estimate everywhere it is reported. If a real tokenizer is cheaply
reachable server-side, use it and bump `word_count_version`.

The existing 776 rows carry `arm: signal_only`, disjoint from the new vocabulary, so
classification is a lookup. **Never backfilled, never pooled into an arm** — they are
an observational baseline collected under a third condition.

**Inside the window the legacy `arm` field is ABSENT** (Cheech's question, answered
2026-08-03). Not `signal_only`. A row carrying both `arm: signal_only` and
`effective_arm: rejecting` asserts two contradictory things, and the point of the
disjoint-vocabulary rule is that **no row ever carries both**. Outside the window
nothing changes — `get_dm_feedback_arm()` keeps writing `arm: signal_only` exactly as
today.

Classifier: `experiment == "two-arm-v1"` → use `effective_arm`; otherwise baseline.

**The `dm reject disclose threshold` key is dropped.** §5 settles that the refusal
never names the threshold, so a switch for something we have decided never to do is
dead config that invites someone to flip it mid-experiment.

### 5. Arm behaviour

- `blind` → judge runs, audit tallies, `quality` key **absent**
- `rejecting` → gate at 150 words → **413** (not 422: the client already maps 422 to
  `recipient_unresolved`, `cosa_voice_mcp.py:3370`), body undisclosed:
  *"DM refused: too long. Cut it substantially and resend."*
- `None` (outside window) → today's behaviour, no experiment fields

**Exemption: the arbiter sender only — under any of its known ids.** Every exemption
is logged with `exemption_reason`.

**Amended 2026-08-03 (María's ruling, Cheech's question).** "The arbiter sender only"
scopes **who** is exempt, not **how many strings spell it**. The arbiter's
`sender_session_id` is not stably knowable from the tree — three names are live in
different places, so the key is a **comma-separated list** and all three are set:

| Id | Where it comes from |
|---|---|
| `arbiter-runner` | `run-heartbeat-arbiter.py:77` — the live `:8001` service path |
| `heartbeat-arbiter` | `arbiter_bootstrap.py:130` + `:152` — the in-process rollback path (gated off) |
| `lupin-arbiter-app-8001` | live `sender_session_id` in `test_arbiter_live_notify.py:277`; also the commons roster identity |

The asymmetry decides it: **over-listing cannot exempt a participant** (all three are
arbiter-only names, no fleet seat answers to them), while **under-listing silently
drops pokes** for the whole window. The empirical check was run and came back
inconclusive — the live corpus holds **zero** arbiter rows, so data could not settle it.

⚠️ **Condition on the ruling — log every exemption HIT with the id that matched.**
This converts the hedge into an instrument. If **zero** exemptions fire on Tuesday,
the arbiter's real id is a **fourth** string and its pokes have been rejected silently
all along — which is precisely the failure the exemption exists to prevent. Without
that log, **a working exemption and a completely missed one look identical.**

Rick's ruling, 2026-08-03: managers are *not* exempt. A refused manager sees the
error — *"too long, resubmit a shorter version"* — and can act on it immediately, so
the failure is loud and self-correcting. The arbiter's is not: its poker discards
every exception (`heartbeat_poker_commons_gateway.py:155-176`), so a refused poke
vanishes with no log, no retry, and no signal, and a stalled session could sit
unpoked for a full hour.

This also settles the disclosure question consistently — the refusal states the
problem and the required action without naming the threshold.

### 6. Client and hook

MCP client gains a 413 branch → `{"status":"error","reason":"dm_too_long","detail":…}`.
`register_session.py` reads `payload.get("source")` and emits a `context_cleared`
marker.

### 7. Analysis script

`src/scripts/dm-experiment/analyze_arms.py`. **The unit of evidence is 14 matched
clock-hour pairs, not the thousands of messages** — messages are correlated within
session and hour.

**Two co-primaries, and they must agree** (Mr Radio, 2026-08-03):

| | Measure |
|---|---|
| **Co-primary A** — all attempts | hour-level `mean( max( words − 60, 0 ) )` per eligible attempt |
| **Co-primary B** — first attempts only | the same statistic over rows where `follows_rejection` is false |

Both computed as rejecting-minus-blind across the 14 matched pairs, with a
randomization interval.

⚠️ **Why B is mandatory.** A alone falls *mechanically* under rejection with zero
behaviour change: one 200-word intent becomes a 200-word refusal plus a 90-word
resend, and the mean of the two is 145. Intention-to-treat over the hour does not
rescue it — the extra attempt is inside the hour. So:

- **Both move** → sessions genuinely wrote shorter
- **Only A moves** → we measured retries, not restraint
- **Neither moves** → no effect at this dose in one hour

Secondary: % ≥150 · attempts per successful delivery · delivery delay · repeated
rejection loops · bunching just below 150 · **mean `est_tokens` per attempt and per
delivered message** (the number the intervention exists to move).

**Order-effect secondary, pre-declared**: compare blind-first pairs against
rejecting-first pairs. Tuesday's sequence is randomized, so order is randomized
*between* pairs even though fixed within one — which turns carryover from an
assumption into a measurement.

Intention-to-treat: the whole assigned hour, never only post-refusal messages.

Pin to `blind` if: rejection rate >35% in an hour · any session rejected ≥5 times
consecutively · attempts-per-delivery >2.0 fleet-wide · ~~**any arbiter poke fails to
send**~~ **← DROPPED 2026-08-03, see below**. Each trip logged with timestamp and trigger.

## Scope and honesty

**Deferred to next week**: the graded arm, the dose ladder (2–3 randomized
thresholds), rejection-to-retry linkage, sequence numbers, and the sequential
randomized design (warning+delivery vs warning+rejection) that is the only clean way
to isolate individual learning.

**This pilot will not claim**: an optimal threshold · that refusal caused sessions to
learn · a learning half-life · that no carryover exists · that context clearing biases
only toward zero.

**Known limitations**: the fleet is not blind to the experiment · one hour is short
for adaptation · a session sends ~14 DMs/hour and meets ~2 refusals at 150 words ·
context clears are under-detected until the `source` fix lands · one fleet, one
operator.

**Predictions on record before data lands**: rejecting shows a visible within-hour
reduction in excess words; carryover into the following hour is weak.

**Settled 2026-08-03**: exemption is the arbiter sender only. Managers stay in the
experiment — they see the error and can resubmit shorter.
