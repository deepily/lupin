## 2. Why the earlier envelope attempts failed

Not the XML I/O layer — our prompts. They were hand-rolled and never told the model to emit
`</stop>`, while `lupin-app.ini:219` had the server configured to stop on it. A stop list
catches; it never instructs. So generation ran past the closing tag and the response came back
truncated or buried in garbage.

| arm | words | secs | text after `</response>` |
|---|---|---|---|
| no sentinel requested | 3,004 | 56.2 | 2,633 words of garbage |
| `</stop>` requested | **114** | **3.2** | **0** |

`AgentBase` never had this problem: `prompt_template_processor.py:129` appends `</stop>` to the
injected XML example on every call. Going through the standard path fixes it by construction.

### ⚠️ Correction to my own evidence (María, after Mr Radio's first live agent call)

I described tonight's `dm.txt` run as *"4 of 4 clean, envelope plus sentinel."* **The sentinel
half is wrong.** `dm_txt_run.py` substituted its XML example bare, so that run had **no
sentinel** — and it pulled slots with `re.search`, which is forgiving of malformed XML.

Under the agent's **strict** parse the very first live call **failed**, on a `thoughts` block
containing `git show HEAD:<file>` — `xmltodict` read it as an unclosed tag. Fixed the way the
sibling arm already does it (`dm-compression.txt:34`): the prompt instructs CDATA.

So "4 of 4 clean" means *a forgiving parser found five slots*, not *the envelope survives strict
parsing with a sentinel*. Those are different claims and I stated the stronger one. Mr Radio's
`--both` flag prices the sentinel half instead of assuming it.

## 3. What gets built

### 3.1 `DmTutorResponse` — `src/cosa/agents/dm_tutor/xml_models.py`

`BaseXMLModel` subclass, following `dm_compression/xml_models.py`. Five fields, the same slots
`dm.txt` ships today:

| field | tag | required |
|---|---|---|
| `thoughts` | `<thoughts>` | yes |
| `declaration_or_question` | `<declaration-or-question>` | yes |
| `supporting_1st` | `<supporting-statement-1st>` | yes |
| `supporting_2nd` | `<supporting-statement-2nd>` | yes |
| `file_path_or_url` | `<file-path-or-url-if-present>` | no — empty when the DM has none |

Two behaviours inherited from the sibling model, both already paid for: **CDATA wrapping**, and
the **`from_xml` ampersand override** (the base class re-escapes `&` inside CDATA, and 88 corpus
bodies carry a bare `&`).

`get_example_for_template()` returns an **instance**, not a string — the processor calls
`.to_xml()` on it.

### 3.2 `DmTutorAgent` — `src/cosa/agents/dm_tutor/agent.py`

`ROUTING_COMMAND = "dm tutor rewrite"`. Shaped after `DmCompressionAgent`. Substitutes the DM
body with `.replace()`, never `.format()` — DM bodies carry literal braces.

### 3.3 Prompt — `src/conf/prompts/agents/dm-tutor.txt`

`dm.txt` as it stands after tonight's edits, with `{{PYDANTIC_XML_EXAMPLE}}` and the `### Input:`
marker. No wording changes; this is the prompt that worked.

### 3.4 Registration — four places, all required

A miss in any one ships a silently broken prompt rather than an error.

| # | file / key | value |
|---|---|---|
| 1 | `prompt_template_processor.py` `MODEL_MAPPING` | `'dm tutor rewrite' : DmTutorResponse` |
| 2 | `xml_parser_factory.py` `agent_model_map` | `"dm tutor rewrite": DmTutorResponse` |
| 3 | INI `prompt template for dm tutor rewrite` | `/src/conf/prompts/agents/dm-tutor.txt` |
| 4 | INI `llm spec key for dm tutor rewrite` | `dm_tutor/phi_4` |

Plus the model spec, mirroring `lupin-app.ini:218-219`:

```ini
dm_tutor/phi_4        = vllm://192.168.1.21:3001@kaitchup/Phi-4-AutoRound-GPTQ-4bit
dm_tutor/phi_4_params = { "prompt_format": "instruction_completion",
                          "model_name": "Phi-4-AutoRound-GPTQ-4bit", "temperature": 0.0,
                          "max_tokens": 4096, "stop": [ "</s>", "</stop>" ], "stream": False }
```

### 3.5 The 200-run

`tutor_sample_run.py` already samples by stride, shows failures in place, and takes
`N_PER_BAND` on the command line. It gets pointed at the agent and run with `N_PER_BAND=50`
across the four bands. Document to `/tmp`, as before.
