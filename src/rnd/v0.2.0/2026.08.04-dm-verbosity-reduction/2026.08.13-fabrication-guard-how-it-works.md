**Shipped**: commit `a28c24b6`

---

## The short answer to "how are you prompting for it?"

**I am not prompting for it at all.** No model is asked whether the rewrite is faithful. There is no second LLM call, no judge, no self-check, no "verify your output" instruction.

The guard is **twenty lines of set arithmetic over regular expressions**, running after the rewrite comes back and before it is delivered. It costs microseconds and it cannot be talked out of its answer.

That is the whole design idea, and it is Rick's own rule generalised — *LLMs do not count well*. Extended: **do not ask a model to guarantee something you can check yourself.** A prompt instruction is a request. A post-check is a guarantee.

The prompt does contain one relevant line (`src/conf/prompts/agents/dm-tutor.txt:18`):

```
Requirement: You MUST return string literals verbatim.
```

That line was in force on 2026-08-13 when the tutor invented a person who does not exist. **The instruction was already there and the model broke it anyway.** That is the argument for the guard in one sentence.

---

## What the failure was

The tutor turned a message about a task-store row into three sentences about *"the reviewer"* wanting documentation. **There was no reviewer.**

Cheech framed the severity better than I did: a **dropped** path is visibly missing, so he asked about it. An **invented** one reads as signal — his first instinct was to work out which reviewer and which change. Only the rest of the message being incoherent stopped him acting on it.

Two properties make this a different class of failure from compression loss:

1. **It is invisible by construction.** A gap announces itself; an invention does not.
2. **It is unbounded.** A rewriter that can add one fact can add any fact. No trigger threshold bounds that — raising the trigger changes how often the dice are rolled, not what happens when they land wrong.

## The logic, in full

```python
def _fabricated_facts( original, rewritten ):
    try:
        def classes( text ):
            return {
                "number" : set( _FAB_NUM.findall( text ) ),
                "hex_id" : set( _FAB_HEX.findall( text ) ),
                "path"   : set( _FAB_PATH.findall( text ) ),
            }
        before, after = classes( original ), classes( rewritten )
        found = { k: sorted( after[ k ] - before[ k ] ) for k in before if after[ k ] - before[ k ] }

        original_words = { w.lower() for w in _FAB_WORD.findall( original ) }
        new_names      = sorted( { c for c in _FAB_CAP.findall( rewritten )
                                   if c.lower() not in original_words
                                   and c.lower() not in _FAB_NOT_NAMES } )
        if new_names: found[ "name" ] = new_names
        return found
    except Exception:
        # A guard that raises must not take the send path with it.
        return {}
```

Read it as one sentence: **extract the hard facts from both texts; anything in the rewrite that is not in the original is an invention.**

If the returned dict is non-empty, `_apply_dm_tutor` refuses the entire rewrite and delivers the **sender's original body** instead. It does not try to repair the rewrite — a text that invented one fact has not earned trust about the rest.

## The four classes, and why each is drawn that way

| Class | Pattern | Catches |
|---|---|---|
| `number` | `\b\d[\d,.]*\b` | Any figure — counts, percentages, ports, line numbers, versions |
| `hex_id` | `\b[0-9a-f]{7,40}\b` | Git shas and task-store row ids, 7 to 40 chars |
| `path` | `(?:[A-Za-z][\w+.-]*://\S+\|(?:[\w.@%+-]+/)+[\w.@%+-]*)` | URLs (scheme form) and anything with a `/` in it |
| `name` | `\b([A-Z][A-Za-z'’-]{2,})\b` | Capitalised words ≥3 chars — the proper-noun proxy |

**Numbers, hex ids and paths are compared as plain set differences.** They are self-delimiting tokens, so exact set membership is the right test — a sha either appears in the original or it does not.

**Names need a different comparison, and that difference is the one interesting part of the code.** The other three classes are compared class-to-class: paths in the rewrite against paths in the original. A name in the rewrite is instead compared against **every word of the original, case-folded** — `_FAB_WORD` matches all alphabetic words, not just capitalised ones.

Why: a faithful rewrite legitimately capitalises a word the sender wrote in lower case, because it moved the word to the start of a sentence. Comparing capitals to capitals would flag that as an invention. Comparing against *every* word means only a token that appears **nowhere at all** in the original counts as new.

### The near-miss that a control caught

An earlier version excluded sentence-initial words to cut false positives — and thereby missed a fabricated name in **the commonest position of all**, the start of a sentence. A planted control caught that before it shipped. The current version matches names position-independently for exactly that reason.

### The stopword set

`_FAB_NOT_NAMES` holds ~120 capitalised words that are never entities:

```
the a an and but or nor so then than that this these those there here it its they
them their we our us you your i my me he she his her him if when while where what
...
```

Without it, a rewrite that opened a sentence with *"The"* was refused for **fabricating the word "The"** — a false positive cheap enough to delete that leaving it in would have cost real compression for no safety.

## Measured, not assumed

Validated against **27 real rewrite pairs** from the live corpus:

- ✅ Fires on a planted fabricated sha, number, path and name.
- ✅ Silent on a faithful rewrite and on a faithful reordering.
- ✅ Blocks **1 of 27** real pairs — and that one had replaced *"Force-recreated"* with *"Deployed"*, a meaning change worth refusing anyway.

## The stated limit

**It cannot see an invented common noun.** *"the reviewer"* is lowercase and passes untouched — meaning the guard would **not** have caught the original incident by that phrase alone. It catches the class the incident belongs to (invented entities), not that exact wording.

The obvious alternative — flag any content word in the rewrite that is not in the original — was **measured on the same 27 pairs and rejected**: it would have blocked **23 of 27**, because paraphrasing is the entire point of the tutor. A guard that refuses 85% of good work is not a guard.

Closing that class needs a fail-first prompt regression suite, which is not built.

## Where it sits in the pipeline

```
sender writes body
      │
      ├─ claims ≤ 4 ────────────────────────────► deliver unchanged
      │
      └─ claims > 4 ──► local Phi-4 rewrite
                              │
                              ├─ empty/failed ──► deliver original
                              │
                              ▼
                     restore dropped pointers
                              │
                              ▼
                     FABRICATION CHECK  ◄── this document
                              │
                    ┌─────────┴─────────┐
                 invented            clean
                    │                   │
            deliver original      deliver rewrite
                                  + attribution footer
```

Two ordering decisions are load-bearing:

1. **The pointer restore runs first**, so a path the restore put back is not itself read as fabricated.
2. **The fabrication check runs before the output gate**, so a fabricating rewrite is refused on the stronger of the two grounds.

Both the guard and the restore are wrapped so that **an exception inside them cannot take the send path down**. An unreadable comparison returns "nothing proven fabricated", leaving the tutor exactly as safe as it was before the check existed — fail-open on the guard, because the DM bus must not go down over a check.

---

## The transferable idea

The tutor cannot be trusted to preserve facts, and no amount of prompt tightening changes that — the instruction was already there when it invented a person. So:

> **Take the checkable thing out of the model's reach and check it in code.**

Same shape as the pointer restore beside it, and the same shape as the claim counter, which is a deterministic sentence counter rather than a model asked to count. Three guards, one principle: **the model does the writing; code holds the receipts.**
