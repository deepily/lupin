# Expert Review: Silent DM Compression and Literal Freezing

**Reviewed:** 2026-08-06  
**Source plan:** *Arm 4 — silent DM compression*  
**Review focus:** Extracting high-value literals before compressing agent DMs through summarization

## Overall assessment

The core idea is strong: **extract → placehold → compress → validate → restore** turns literal corruption from a probabilistic problem into a mostly deterministic one. Phase 1—the extractor, placeholder system, validator, restorer, and test suite—is worth prototyping.

The plan is not ready for live delivery, however. It currently treats literal fidelity as if it implied message fidelity. It does not. The freeze protocol can guarantee exact preservation of selected byte spans, but a separate semantic-preservation layer is needed to ensure those spans remain attached to the correct claims and that the claims themselves retain their meaning.

## Main issues to resolve

### 1. Define the semantic-preservation contract

A compression can preserve every literal while reversing or weakening the claim containing it:

- “The bug may be at `judge.py:572`” → “The bug is at `judge.py:572`.”
- “Do not deploy `d256e25a`” → “Deploy `d256e25a`.”
- “Alice found the issue; Bob fixed it” → “Alice fixed the issue.”

In particular, “strip hedging” is unsafe unless the system distinguishes social ceremony from epistemic qualification. Words such as *perhaps*, *likely*, *observed*, *inferred*, *may*, and *not* carry meaning.

The compression contract should explicitly preserve:

- negation, uncertainty, and modality;
- actor/action/object relationships;
- status: proposed, observed, completed, or blocked;
- conditions, comparisons, causality, and temporal order;
- requests, deadlines, and ownership; and
- every actionable proposition, unless specific boilerplate classes are declared removable.

This contract should be defined before model evaluation, because it determines what counts as a correct compression.

### 2. The corpus does not generate its own extraction ground truth

The corpus supplies ground truth only for literals the current regexes already detect. It cannot reveal missing literal classes or incorrect match boundaries. Extraction recall therefore needs a manually labeled, stratified sample in addition to corpus-scale testing.

Likely missing classes include:

- URLs, email addresses, and user mentions;
- issue, ticket, and pull-request identifiers;
- branch names, tags, package versions, and version constraints;
- IP addresses, hostnames, and database identifiers;
- timestamps, time zones, durations, and commit-relative references;
- decimals, signed values, percentages, ranges, currency, and scientific notation;
- CLI flags, function and class names, and JSON/YAML keys;
- fenced code, commands, error messages, and log excerpts;
- Windows paths and paths containing spaces;
- model names and other exact product identifiers; and
- credentials, API tokens, and other high-entropy secrets.

Deterministic overlap rules are also required. A quoted span containing backticks containing a SHA should become one non-overlapping extracted span, not three nested substitutions. A lexer or explicit span-priority system will be safer than a sequence of independent replacements.

### 3. SOFT-extraction false positives are not nearly free

Freezing a long quoted sentence can prevent most useful compression. Freezing an acronym or coined term may preserve exactly the jargon the rewriter is supposed to remove. False positives can therefore reduce compression, preserve noise, and increase token cost.

Measure extraction precision and frozen proportion across the distribution, especially in the tail, rather than relying only on corpus averages. A message should bypass rewriting when:

- its frozen proportion exceeds a chosen threshold;
- too little compressible text remains;
- the theoretical minimum output cannot meet the target; or
- it consists primarily of code, logs, quotations, or exact instructions.

### 4. Use unique placeholders per occurrence

The proposed “same literal → same placeholder” rule loses provenance. Two identical values in different claims can both survive while becoming attached to the wrong claims.

Prefer occurrence-unique placeholders while retaining a separate equivalence group in metadata:

```text
⟦S02_PATH00⟧ → judge.py:572
⟦S05_PATH01⟧ → judge.py:572
```

The sentence or clause prefix makes cross-claim movement detectable. Typed placeholders may also help the model preserve grammar, although their token cost should be benchmarked.

### 5. Validate the placeholder scheme empirically

`⟦L00⟧` is plausible, but character length says nothing about token cost. It should be tested with every candidate model’s actual tokenizer and API behavior, including:

- Unicode normalization;
- JSON serialization and escaping;
- stop sequences and truncation;
- visually similar brackets and characters;
- zero-width and bidirectional Unicode characters; and
- messages containing more than 99 placeholders.

A per-message namespace or nonce is preferable to merely escaping collisions. The original bytes should remain unchanged locally, and restoration should use an exact placeholder parser rather than general string replacement.

### 6. Separate the three fidelity risks

The plan currently conflates:

1. the model’s raw placeholder failure rate;
2. the validator’s false-negative rate; and
3. semantic corruption after structural validation.

At roughly 6,142 literals per day, 99.9% raw literal fidelity means approximately 6.1 literal failures. If validation detects those failures and sends the original, they are bypasses affecting yield and latency—not delivered corruptions.

The hard structural invariant should be:

> Zero known placeholder violations are delivered.

Raw model fidelity determines effective compression yield and cost. Validator false negatives and semantic errors are the actual safety risks.

The phrase “round-trip byte equality after restoration” should also be narrowed. The rewritten message cannot be byte-equal to the original. Use two separate tests:

- **Extractor/restorer test:** placehold and immediately restore without rewriting; require exact whole-input byte equality.
- **Rewriter-path test:** after rewriting and restoration, require exact equality of every mapped literal and occurrence.

Semantic preservation must be evaluated separately.

### 7. Twenty human reviews per week cannot validate semantic safety

At a 1% semantic-error rate, 20 reviews have only about an 18% chance of finding even one error. Twenty reviews may be reasonable for steady-state monitoring after validation, but launch evaluation needs hundreds of stratified, blinded comparisons plus targeted review of every risk flag.

Useful automated proxies for relocation include:

- clause-local rewriting with source clause identifiers;
- prohibiting placeholders from moving between clauses;
- comparing actor, action, negation, and modality around each placeholder;
- bidirectional entailment checks per clause; and
- question-answer consistency between the source and compressed form.

Order monotonicity is useful telemetry, but it is too weak to serve as a safety check.

## Answers to the plan’s reviewer questions

### Placeholder format

Do not commit to `⟦L00⟧` until it has been tested against the actual candidate tokenizers and APIs. Prefer occurrence-unique, optionally typed and clause-scoped placeholders with a collision-free per-message namespace.

### Extraction recall

Expand the taxonomy, establish explicit overlap precedence, and manually label a representative corpus sample. Add property-based fuzzing for arbitrary Unicode, overlapping spans, adjacent literals, repetitions, delimiter injection, and large placeholder counts.

### Retry behavior

Begin with no synchronous retry. If validation fails, deliver the original immediately and retry offline for diagnosis. Temperature zero is not a correctness guarantee, and a retry doubles tail latency while creating another opportunity for semantic drift. A synchronous retry can be reconsidered later if bypass frequency materially damages the economics.

### Relocation detection

Clause confinement is the cheapest meaningful improvement. Combine it with local semantic-role or entailment checks. Do not rely on placeholder ordering alone.

### The 99.9% fidelity gate

Treat 99.9% as a raw-yield objective, not a delivered-safety threshold. Rank models by effective tokens saved after detected failures, bypasses, and retries. The safety requirement remains zero detected structural violations delivered, with semantic error measured independently.

## Test-suite improvements

The negative control is valuable but insufficient. Disabling freezing may not reliably break every assertion because models naturally preserve many literals. Add mutation tests that deliberately:

- omit each placeholder;
- duplicate it;
- alter each delimiter and identifier character;
- join it to neighboring text;
- invent an in-namespace and out-of-namespace placeholder;
- move it between clauses;
- truncate the output at every placeholder boundary; and
- insert visually similar Unicode characters.

Each mutation should demonstrate that the intended validator check fails. Also test the extractor and restorer with property-based generation, not only a hand-written adversarial set.

## Operational requirements

Original-message retrieval and auditability should precede live rewriting rather than arrive in a later phase. Each transformed delivery should retain:

- the immutable original message;
- the delivered derivative;
- the placeholder map or a suitably protected reference to it;
- model, tokenizer, and prompt versions;
- validator results;
- the fallback reason, when applicable; and
- timing, cost, and achieved compression.

The compressor should first run in shadow mode, producing and evaluating rewrites without delivering them. Live rollout should then use a small canary population and an immediate rollback switch.

Covertness should not be load-bearing. Since the stated scope is mechanical compression, the delivered text should be identifiable as a derived representation and the original should remain recoverable. Secret rewriting makes debugging, accountability, and trust substantially worse.

External model use also requires an explicit privacy review. Replacing recognized literals protects only the values the extractor finds; unrecognized secrets and sensitive prose still leave the system. Provider retention, training, data residency, and access policies belong in the sourcing gate.

## Economics to recompute

The projected savings should be recalculated using:

- actual provider tokenization;
- system-prompt and placeholder overhead;
- short-message skips;
- high-frozen-density bypasses;
- structural validation failures;
- semantic-risk bypasses;
- recipient fan-out;
- actual cache behavior; and
- effective savings after fallbacks and retries.

The increase from 84,234 source DM tokens per day to 223,734 rewriter input tokens per day should be derived explicitly. Cash cost, delivery latency, context-window savings, and downstream inference savings should be reported separately.

## Recommended build order

1. Define the semantic-preservation and removable-boilerplate contract.
2. Build the deterministic extractor, non-overlapping span resolver, occurrence-level placeholder map, validator, and exact restorer.
3. Validate extraction recall against a manually labeled corpus sample.
4. Add mutation testing, property-based fuzzing, and the adversarial suite.
5. Benchmark placeholder formats against exact candidate tokenizers.
6. Run candidate models in shadow mode on a held-out, stratified corpus.
7. Evaluate structural yield, semantic preservation, effective compression, latency, privacy, and cost separately.
8. Put original retrieval, provenance, monitoring, and rollback in place.
9. Conduct a limited canary before broader rollout.

## Recommendation

Proceed with the freeze-protocol prototype, but narrow its claim to:

> Exact preservation of selected byte spans through a lossy rewrite.

Do not describe the overall system as meaning-preserving until it has a defined semantic contract, clause-level relocation controls, meaningful human evaluation, and a recoverable original-message path. Literal freezing is an excellent safety kernel; it is not, by itself, a complete message-integrity system.
