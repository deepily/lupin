## 2. 🔴 The promotion changed TWO things, not one

This is the finding that matters most, because it governs what any number in this file may be
compared against. **Both were found by running the code, not by reading it.**

### 2.1 Strict XML instead of regex — this one bit on the first live call

The 2026-08-11 evening run pulled its slots out with `re.search`. A regular expression does not
care that the model wrote `git show HEAD:<file>` inside its reasoning. `xmltodict` does: it reads
`<file>` as an opening tag that is never closed, and the entire response fails to parse.

The first live call through the agent died exactly this way:

```
XMLParsingError: Invalid XML format: mismatched tag: line 4, column 4
```

The agent's fail-closed contract held — `rewrite()` returned `None`, nothing escaped into the
caller — but a tutor that fails on any message containing an angle bracket is not usable in this
fleet's traffic.

**The fix, and it is a departure from the plan's §6 "no prompt rewording":** one requirement line
added to `dm-tutor.txt`, copied near-verbatim from the sibling arm's established practice at
`dm-compression.txt:34`:

> Requirement: Put the contents of each slot inside `<![CDATA[` and `]]>` exactly as shown in the
> format below. Everything between those two markers is copied literally, so you do not need to
> escape anything inside them.

**The argument for making the change**: this is format plumbing for the standard path — the same
category as the `{{PYDANTIC_XML_EXAMPLE}}` marker itself — not a change to what the model is asked
to *say*. **The argument against**: it is still a prompt edit, and the plan said no prompt edits.
**Flagged to Rick explicitly rather than buried**; his to keep or veto. If vetoed, the prompt
cannot ride the standard path, and that becomes the finding.

### 2.2 The stop sentinel

`AgentBase` appends `</stop>` to the injected example by construction
(`prompt_template_processor.py:130`). The evening run had none: `dm.txt` contains zero mentions of
`stop`, and the harness substituted its example bare.

**So the sentinel is NOT what made that run work.** The five-slot scaffold is. The sentinel is a
separate, independently measured win — María's `stop_probe.py` clocked a 250+ message at
3,004 words / 56.2s without it against 114 words / 3.2s with it.

### 2.3 The consequence for the record

The plan's §4 step 2 reads *"tonight's four messages should produce the same output through the
agent as they did through the script"* — written as a null check. **It is not one.** Two variables
moved. The `--both` flag exists so the sentinel half can be priced instead of assumed; the parser
half cannot be unmoved without abandoning the standard path.

### 3.1 The fail-closed contract — the design point, not a detail

`rewrite_dm( body )` returns the distilled lines, or `None`. **`None` always means "deliver the
original."** Never a partial rewrite, never an exception into the sender's call stack.

It is a free function rather than a method for one reason: **construction failures must fail closed
too.** A missing INI key or an unregistered routing command has to deliver the original message,
and a caller in the send path should not need to know that `DmTutorAgent.__init__` can raise.

Why this matters more than it looks: a tutor that occasionally mangles a message is worse than no
tutor at all, because the recipient cannot tell which kind of message they are holding.

### 3.2 The four registrations, and why each is load-bearing

A miss in any one ships a **silently broken prompt** rather than an error.

| # | site | what a miss does |
|---|---|---|
| 1 | `MODEL_MAPPING` (`prompt_template_processor.py`) | `get_example_for_agent` returns None → the marker is left literal in the prompt **and no `</stop>` is appended** |
| 2 | `agent_model_map` (`xml_parser_factory.py`) | `ValueError` at parse time — the loud one |
| 3 | INI `prompt template for dm tutor rewrite` | `KeyError` at construction |
| 4 | INI `llm spec key for dm tutor rewrite` | `KeyError` at construction |

There is a **third road to the same broken prompt**, documented at `xml_models.py:225` and now
covered by a test: if `get_example_for_template()` returns a *string* instead of an instance,
`PromptTemplateProcessor` raises `AttributeError`, `AgentBase` swallows it in a bare `except`
(`agent_base.py:161`), and the template ships unprocessed with nothing raised anywhere.

**The construction smoke test asserts against all of them** — six checks, each guarding a failure
that is invisible without it.

## 5. The 200-run

**In flight**: `--n-per-band 50 --both` = 200 messages × 2 arms = **400 calls**.

Results land in §5.1 when it completes. What it can answer: whether the sentinel changes delivery
rate or compression at a sample size that can carry a claim, and what the failure modes are across
real traffic rather than four hand-checked messages.

What it **cannot** answer: whether any rewrite is *faithful*. Every automated check here is
structural — slots present, pointer verbatim in the body, word counts. Whether a rewrite quietly
reverses a meaning is Rick's read, and it stays owed.

### 5.1 Results — 200 messages × 2 arms = 400 calls, 24 minutes of model time

**387 of 400 delivered (96.8%).** Every one of the 13 failures fail-closed: the original message
would have been sent unchanged, and none raised into a caller.

| band | arm | n | ok | delivered/in | p50 secs | path ok |
|---|---|---|---|---|---|---|
| `<80` | sentinel | 50 | 49 | 76% | 3.1 | 49 |
| `<80` | control | 50 | 47 | 76% | 3.2 | 49 |
| `80-150` | sentinel | 50 | 50 | 41% | 3.6 | 50 |
| `80-150` | control | 50 | 49 | 42% | 3.6 | 50 |
| `150-250` | sentinel | 50 | 49 | 30% | 3.7 | 48 |
| `150-250` | control | 50 | 48 | 31% | 3.7 | 48 |
| `250+` | sentinel | 50 | 47 | **17%** | 4.0 | 47 |
| `250+` | control | 50 | 48 | **16%** | 3.9 | 48 |

#### The sentinel bought nothing measurable

**Sentinel arm 195/200 (97.5%) · control arm 192/200 (96.0%) — a gap of 3 messages.** The noise
floor pre-registered for this corpus is ±2, with 4+ needed to call a winner. **A 3-message gap does
not clear it.** Compression is identical to within a point in every band.

#### Reconciling this with `stop_probe.py` — María asked for it in the record, and she is right to

Her probe measured one 250+ message at 3,004 words / 56.2s without the sentinel against 114 / 3.2s
with it, and that result was carried into the plan as *the* explanation for the envelope failures.
**At n=200 it does not hold.**

**Her words**: *"I sold the stop sentinel as the fix off one 250+ message… CDATA was in your run and
not in mine, so the sentinel was confounded with the real fix."*

**One correction to that, because the record should be exact.** Her probe was not confounded — it
varied the sentinel cleanly, with no CDATA in either arm, and its result is real *for that prompt*.
What the n=200 run shows is an **interaction, not a confound**: the sentinel and the CDATA
instruction guard against the same failure — generation that runs past the closing tag and comes
back unparseable — and **once CDATA is in place the sentinel has nothing left to catch.**

So the sentinel is not "the fix", and it is not nothing either. It is a backstop for a condition the
shipped agent no longer operates in. It costs seven characters and it is what the standard path does
anyway, so it stays.

The generalisable part is smaller and duller than either headline: **one message cannot tell you
which of two overlapping guards did the work.**

#### Compression scales with length, steeply

76% → 41% → 30% → **17%**. A 250+ word DM comes back as **one sixth of its length**. Short messages
barely move, which is correct behaviour — a 60-word message has little to remove, and squeezing it
would cost meaning for nothing.

This is the number that matters against arm 4's failure: **arm 4 shipped 3.0% where 38% was
needed.** The tutor delivers 83% on the long messages that hold most of the token mass. Different
mechanism — arm 4 preserved every message and rewrote conservatively; the tutor throws away
everything that is not the point.

#### The 13 failures

| kind | n | what happened |
|---|---|---|
| `XMLParsingError` | 9 | malformed XML despite the CDATA instruction |
| `ValidationError` | 4 | the model returned an empty required slot |

By arm: **control 8, sentinel 5.** By band: `250+` 5, `<80` 4, `150-250` 3, `80-150` 1 — no clean
length relationship.

The `ValidationError` cases are the validator doing exactly its job: a dropped supporting statement
is a two-line delivery masquerading as a three-line one, and it fails closed rather than shipping.

#### 🔴 The path checker's 9 "misses" are formatting, NOT fabrication — read the records, not the count

296 slots correctly empty · 78 found a real path the message carried · **9 flagged `NOT IN DM`**.

At face value that reads as a 2.3% hallucination rate. **It is not one.** Reading all nine:

| flagged value | what it actually is |
|---|---|
| `commit 32e659f1` ×2 | the sha **is** in the corpus — verified verbatim in **7 bodies** (`"do this before 32e659f1"`). The model added the word `commit`. |
| `:669/:804-830` ×2 | two real line ranges merged into one shorthand |
| `podcast_generator/orchestrator.py:1646; presentati…` | two real paths, semicolon-joined |
| `…orchestrator.py:634, …orchestrator.py:655, …` | three real paths, comma-joined and ellipsis-abbreviated |
| `narrative.py:156, outline.py:235, outline.py:225, …` | four real paths, comma-joined |
| `mcp:3372, dm.py:493, dm.py:768` | three real pointers, comma-joined |
| `lupin-app.ini:1267, notifications.js:1130, system.…` | three real pointers, comma-joined |

**Zero fabrications.** Every one is either a real literal with a label word attached, or several real
pointers packed into a slot that holds one. All nine come from the two long bands (`150-250` and
`250+`) — long DMs carry several paths, the prompt asks for "the most relevant" singular, and the
model declines to choose.

**So the defect is mine, in two places**, and neither is the model:

1. **The checker is too strict.** `pointer in body` cannot pass a value the model legitimately
   composed. It should test each comma/semicolon-separated element, and strip a leading label word.
2. **The prompt does not say "exactly one".** It says "the most relevant", which a model can read as
   "the relevant ones".

Neither is fixed here — both are named in §6 rather than patched at 11pm on numbers that would then
need re-running.

## 6. Still open

- **Rick's ruling on the CDATA line** (§2.1) — the one decision this build made that the plan said not to make.
- **Rick's read of the rewrites** — the fidelity question no harness can answer. Every check here is structural: slots present, pointer verbatim, word counts. Whether a rewrite quietly reverses a meaning, and whether the one technical detail in nine that survives is the RIGHT one, is his and stays owed.
- **The path checker is too strict** (§5.1) — `pointer in body` cannot pass a legitimately composed multi-path value. Should test each comma/semicolon-separated element and strip a leading label word. Until then its `NOT IN DM` count reads as a hallucination rate and is not one.
- **The prompt does not say "exactly one" pointer** (§5.1) — "the most relevant" is read by the model as "the relevant ones" on long messages. A one-word fix, but it is a prompt edit and §2.1's ruling should land first.
- **The `<80` band barely compresses** (76% delivered). Worth asking whether the tutor should run on short messages at all — 3.1s of latency to remove a quarter of a 60-word message may not be worth it.
- The tutor's older inline-prompt path (`dm_tutor/tutor.py`, `PROMPT_BASE` at l.83) is now superseded by `dm-tutor.txt` for the agent path, but the file is untouched — `sentences.py` and `tutor.py` were both out of scope.
- **Integration into the DM send path is NOT done** — `rewrite_dm()` exists and is the seam Rick asked for, but nothing calls it yet. That is the "greater experiment" and it was not in this cut.
