## 0. The setup, in one paragraph

A DM body goes out to a rewriter with its immutable bits replaced by opaque
tags. The rewriter shortens the prose. What comes back has to be checked before
the tags are swapped back for the real values. All four algorithms below exist
to answer one question: **is what came back safe to restore?**

A tag looks like this:

```
[[L07]]              plain form
[[a3f1_L07]]         namespaced form (rare — see §1.2)
```

---

## 1. Minting unique tags

### 1.1 The ordinal is the identity

Literals are located, overlaps resolved, and the surviving spans sorted by
position. Then the tag is simply the span's **index in that list**:

```python
for ordinal, span in enumerate( spans ):
    token = f"{OPEN_DELIM}{namespace}L{ordinal:02d}{CLOSE_DELIM}"
```

Three properties fall out of that, and each is load-bearing:

| Property | Why it matters |
|---|---|
| **Occurrence-unique, not value-unique** | The same sha appearing twice gets `[[L03]]` and `[[L09]]`, not one shared tag. Collapsing them would destroy provenance — two copies in two different claims could swap places and nothing could tell |
| **Sequential from 00, no gaps** | A missing ordinal is detectable without comparing any content. The numbering *is* the checksum |
| **Carries nothing else** | No type, no clause. Those live in the `Placeholder` record, which holds strictly more than the tag ever could |

That last one was a deliberate reversal. The expert review proposed typed,
clause-scoped tags (`⟦S02_PATH00⟧`) so the model could see structure. Two facts
killed it: **the type label is not trustworthy** — the port pattern fires on
line numbers, so a tag labelled `PORT` frequently is not one — and every extra
character is paid on every tag across all traffic.

Equivalence between identical literals is not lost; it is recorded as
`group_id` in the map, which is where the review wanted it anyway.

### 1.2 The namespace, and why it is usually empty

A tag must not collide with text the author actually wrote. The obvious
defence is a per-message random prefix on every tag. That is correct and
expensive: 2–3 extra tokens on every tag, on all traffic, to defend against
something that almost never happens.

So the namespace is **empty by default** and appears only when the message
could actually collide:

```python
collides = (
    OPEN_DELIM in text
    or _loose_token_pattern( "" ).search( text ) is not None
    or _naked_token_pattern( "" ).search( text ) is not None
)
if not collides: return ""
```

🔑 **The collision test uses the validator's own matchers, not the exact
delimiter.** That is the subtle part. Our corpus contains `(L207)` and `(L345)`
written as ordinary line references. Those are not tags, but the *loose* matcher
in §4 reads them as mangled tags and the validator rejects the message. Testing
only for `[[` would have missed them entirely.

When a namespace is needed it is derived from the SHA-256 of the body, widening
until it provably does not occur in the text. Deterministic — the same body
always yields the same namespace, so nothing has to be stored alongside the
message.

## 2. Proving each tag appears exactly once

Two checks, deliberately separate, because they fail differently.

### Check 1 — set equality

```python
expected_set = set( expected )                       # what we sent
found_set    = set( found_tokens )                   # what came back

missing = expected_set - found_set                   # omission
extra   = found_set - expected_set                   # confabulation
```

Catches a tag that vanished, and a tag that materialised. Set arithmetic, no
content comparison anywhere.

### Check 2 — multiplicity

```python
for token in expected:
    want = 1                          # occurrence-unique by construction
    got  = found_tokens.count( token )
    if got != want: fail(...)
```

Set equality alone would pass a message where `[[L03]]` came back **twice** —
the set is unchanged. The multiplicity check is what makes "exactly once" mean
exactly once.

The `want = 1` is not an assumption; it is guaranteed by §1.1. Because tags are
minted per-occurrence rather than per-value, every tag is sent precisely once,
so the expected count is always 1 and duplication is unambiguous.

### Why "exactly once" is a stronger claim than it looks

Restoration is a single pass with an exact parser. If a tag appeared twice, one
literal would be written into two places. If zero times, a literal silently
disappears. Both are corruptions that read as perfectly fluent text — which is
the entire failure mode this system exists to prevent.

## 3. Detecting ordering

Two signals, both **warnings**, neither gating delivery.

### 3.1 Sequence monotonicity

```python
sequence = [ expected[ t ].occurrence_index for t in found_tokens if t in expected ]
if sequence != sorted( sequence ):
    warn( "order", "placeholder order changed — possible relocation" )
```

Tags were minted in document order, so their ordinals ascend in the text as
sent. If they come back out of ascending order, something was moved.

### 3.2 Clause confinement

Each tag records the clause it started in. After the rewrite the body is
re-segmented and each tag's landing clause is compared to its origin. A tag that
changed clause is a tag that may have been re-attached to a different claim.

```python
if len( rewritten_clauses ) != len( frozen_msg.clause_spans ):
    warn( "clause_confinement_unavailable", ... )       # cannot be evaluated
else:
    for each tag: compare landed clause vs origin clause
```

That first branch matters more than it looks. When the rewrite changes the
clause structure, origin and landing indices are **not comparable** and the check
cannot be performed. It used to be skipped silently, which **inverted the
signal**: real compression reshapes clauses, so the check went quiet exactly
when it was most needed and spoke up only about rewrites that had barely
changed anything. It now says "could not be checked" — silence and *not
checkable* are different answers.

### 🔴 3.3 The honest limit — read this before trusting a clean result

**Neither signal catches the case that matters most.** A rewrite can swap which
claim each tag belongs to while leaving the tags in ascending order inside a
single clause:

```
sent      The bug is in [[L00]] and the fix is in [[L01]] today
returned  Fix in [[L00]] and bug in [[L01]] today
```

Ordinals still ascend. Nothing left its clause. `ok=True`, zero warnings — and
the meaning is inverted. This is called **relocation**, and it is not a tuning
problem: the information needed to detect it is not present in the structure.

There is a test asserting this is *not* caught, so that nobody later reads a
green run as meaning the tags are attached to the right claims. Catching it
needs a semantic check or a human, and neither exists yet.

## 4. Detecting invented tags

The naive version — flag anything bracket-shaped that we did not send — was
written first and was wrong. `[done]` and `[dropped]` are ordinary status
markers in this traffic, and a rule that broad rejects real messages wholesale.

The working version anchors on **our own tag shape**, via a deliberately sloppy
matcher:

```python
def _loose_token_pattern( namespace ):
    return re.compile(
        "[" + _LOOKALIKE_OPEN  + "]{1,2}"     # [ ( { ⟦ 〚 【 「 … one or two
        r"\s*" + namespace + r"_?\s*"
        r"[Ll]\s*\d+\s*"                      # the L-ordinal body
        "[" + _LOOKALIKE_CLOSE + "]{1,2}"
    )
```

It matches things that were *meant* to be tags: wrong brackets, single instead
of double, unicode lookalikes, stray whitespace. Then:

```python
for m in loose_pattern.finditer( rewritten ):
    if m.group( 0 ) not in expected_set:
        fail( "no_invented", f"placeholder-shaped text not sent: {m.group(0)!r}" )
```

Anything tag-shaped that is not **exactly** one of ours is a violation. That
covers both an in-namespace ordinal we never issued (`[[L99]]` when we sent
L00–L05) and an out-of-namespace invention.

### 4.1 The same matcher does double duty

Comparing the loose count against the exact count is also how **mangling** is
detected:

```python
loose_hits = len( loose_pattern.findall( rewritten ) )
if loose_hits != len( found_tokens ):
    fail( "boundary_integrity", ... )
```

Any split, truncation, dropped bracket or substituted delimiter changes one
count and not the other. That turns "the model mangled a tag" from *a list of
shapes to enumerate* into **one comparison**. A third matcher catches tags whose
delimiters were stripped entirely (`L03` bare in the text).

### 4.2 Why prose does not trip it

`(L207)` in a real message *does* match the loose pattern. It is not treated as
an invented tag because such a message gets a namespace (§1.2), and the matcher
then requires that namespace — putting the prose out of reach. The collision
test and the invention check use the same instrument, on purpose.

## 5. The four algorithms, side by side

| # | Question | Mechanism | Gates delivery? |
|---|---|---|---|
| 1 | Are the tags unique? | Ordinal per resolved span, sequential from 00 | by construction |
| 2 | Does each appear exactly once? | Set equality + per-token count against `want = 1` | ✅ yes |
| 3 | Did anything move? | Ordinal monotonicity + clause confinement | ⚠️ warning only |
| 4 | Did the model invent one? | Loose tag-shape matcher, membership test against the sent set | ✅ yes |

Everything in columns 2 and 4 is **structural** — no content is compared, no
model is consulted, and the checks run in microseconds. That is the whole design
bet: turn "did the model transcribe this 40-character hash correctly" into "did
the model leave an opaque 7-character token alone", because the second question
is cheaply and exactly answerable and the first is not.

Column 3 is where honesty lives. It is the one question this design cannot
answer, and it says so rather than implying otherwise.
