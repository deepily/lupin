### 1.1 The coupling that makes an unattended retrain unsafe

The corpus does not merely carry labels. **Every generated row interpolates the command menu into its instruction** — `xml_coordinator.py:387`, `:634`, `:805`. So the LoRA learns *the menu*, not only the mapping.

⇒ A retrain against a hand-typed prompt **bakes today's 18-vs-19 disagreement into the weights**, and the first symptom is an emission probe weeks later.

### 1.2 What generation does NOT buy — stated so nobody over-claims

Regenerating the corpus does not make a new command reachable. **Reachability comes from the prompt line**, measured: Tiffany's A/B flipped emission **0/5 → 5/5** by adding one checked-in line, with no retrain and no bounce (`2026.08.15-router-emission-probe.md`). Training alone never emitted — the trained-but-unlisted arm scored **0/5**.

The retrain buys **reliability**, not reachability, and is allowed to lag. Any claim stronger than that is unsupported.

## 2. The design

### 2.1 `AgentSpec` grows ONE field

```python
speakable : bool = False   # belongs in the router prompt
```

Declared once, on the spec. **This is what retires `DEFERRED_COMMANDS`**: "speakable" stops being a hand-kept frozenset of 9 that must equal `JOB_COMMANDS ∩ template`, and becomes a property each command carries.

> **REVISED 2026-08-16 after cascade §A — `training_seed` DROPPED. Maya was right and the concession is on evidence.**
> I originally proposed a second field pointing at each command's phrasing seeds. It is redundant: **all three JSONs already map the command string to its seed path** — `agent-router-simple-commands.json` and `-compound-` map straight to a path (`"agent router go to todo": "/src/ephemera/prompts/data/synthetic-data-agent-routing-todo-lists.txt"`), and `-agentic-` maps to a dict whose `template_file` is the path. Since §2.4 deliberately keeps seed ownership in the JSONs, a field on the spec is a **second copy of a mapping that already exists**.
> ⇒ It would have introduced the exact duplication this row exists to remove, inside the design meant to remove it.
> **The real need behind it survives, and belongs elsewhere**: a `speakable` command with no seed file is currently undetectable. That is a **guard assertion** over the existing keying, not a new field.

⚠️ `DEFERRED_COMMANDS` is currently the last hand-written list inside the registry — the exact shape row `30483697` exists to eliminate. Retiring it is a deliverable here, not a side effect.

### 2.1a Where `speakable`'s values come from — the RATIFIED LIST

**Added after cascade §B. Krishna's finding, and it is the best of the run.**

`speakable` **cannot be generated** (trap 3 forbids deriving it from today's template) **and cannot be tested** — no oracle can prove the list *right*, because which commands a person should be able to say out loud is a human design judgement. It therefore falls between the two halves of Rick's ruling, *generate what can be generated, test what cannot*.

⇒ **A third disposition**: the list is a **ratified, checked-in decision**, and the test pins the generated file **to that list** — proving **no drift**, never pretending to prove correctness. A test claiming to prove the list right would be the fourth tautology on this row.

**The ratified list is the prompt's current 18 commands**, measured. That is a starting point with provenance, not a derivation — and changing it is a decision someone makes and records, which is exactly the property we want.

### 2.2 One generator writes the prompt file

A module emits `agent-router-template-completion.txt`: the fixed scaffolding, plus one `<command>` line per `speakable` command, plus `none`.

**The file stays checked in and human-readable.** Serving is unchanged — the readers keep reading a file. What changes is *who is allowed to write it*.

**The generator owns command ORDER** (Clayton, cascade §B). Order is part of the generated artifact, so a one-time **regenerate step** brings the checked-in file into line with the generator — **never the reverse**. Tuning the generator until it happens to reproduce today's byte order would make §2.3's test true by construction; that is trap 3 wearing a different hat.

### 2.3 A test pins the file to the generator

Assert the on-disk file equals what the generator would emit right now. Hand-edit the prompt and it goes red.

**This is the step that converts the guard from a detector into a preventer**, and it is the point of the exercise.

### 2.4 The corpus builder reads the same list

Point `_compile_agent_router_commands()` at the generated list instead of concatenating the three JSONs. The 18-vs-19 disagreement then cannot recur by construction.

The three JSONs **stay** and keep the example phrasings. They shed only their second job: being a competing definition of what exists.

⚠️ **§5.3 of the parent design still stands — the corpus is RECONCILED, not wholly generated.** The phrasing seeds are human-authored and must remain so. Only the *command list* is generated.

**New test required (Krishna, cascade §B)**: nothing currently proves the corpus **stopped defining the command set on purpose**. After this change the JSONs still hold keys that look authoritative, and a future reader — or a future edit — could restore them to that role without anything going red. Assert that the corpus's command list comes from the registry and **not** from the JSON keys, so the demotion is pinned rather than merely intended.

## 5. The traps — what I would get wrong if I were building this

Named deliberately. I have been wrong twice today by reasoning from a nearby example instead of reading the source, so treat these as claims to check, not facts to inherit.

1. **`JOB_ARG_CONTRACTS` (today `AGENTIC_AGENTS`, 12) and `JOB_COMMANDS` (today `AGENTIC_COMMANDS`, 12) hold the same commands and are NOT the same thing** — argument contracts versus registry specs. A rename sweep that collapses them destroys a real distinction and **nothing would fail**.

2. **The prompt's failure mode is silent.** A generated prompt that is well-formed but *different* — reordered commands, changed whitespace, a dropped trailing line — passes every assertion in the guard and changes live routing. This is why this piece earns a cascade and the rename does not.

3. **Do not derive `speakable` from membership in the current template.** That makes the generator reproduce today's file by construction and §2.3's test a tautology — the third one on this row.

4. **The three `cli_module` values naming packages with no `__main__.py`** (`claude_code`, `bug_fix_expediter`, `test_fix_expediter`) are real; `deep_research.cli` **looks** broken to a naive check and is not — it is module-style with a guard at `cli.py:1253`.

5. **`src/conf/training/` is five files in two namespaces.** `agent-router-*` is the routing corpus; `vox-cmd-*` is **23 browser commands**. A glob of `training/*.json` false-orphans all 23. The scoping rule is `agent-router-*.json`.
