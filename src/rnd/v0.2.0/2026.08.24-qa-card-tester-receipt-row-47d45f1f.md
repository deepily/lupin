### Why the existing gate cannot see it

`test_v2_agents_endpoint.py` says so itself, in a comment above the assertion:

> *USER_INITIABLE_COMMANDS is DERIVED from REGISTRY, so it proves the ENDPOINT matches the TABLE …
> and nothing about whether the table is RIGHT. Clear one spec's user_initiable and both sides move
> together; measured, that mutation leaves this assertion green.*

That is accurate and I confirmed it rather than trusting it. The comment then says the table's
content is pinned by **named per-command assertions** — receptionist, both expediters, TFE resume,
`none`, `automatic`. **`math` is not among the named commands, and neither are the other five
conversational agents.** So the protection the comment describes is real but does not extend to the
commands a user actually picks from the dropdown.

**This is not a defect in the implementer's work.** The endpoint is a faithful projection; the gate
is honest about what it proves. The gap is that no assertion pins the six conversational agents as
user-initiable.
