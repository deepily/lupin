## Wall 1 — the fuzzy matcher overflowed phi-4 (stage 3), now fixed two ways

**First run (config = `/src`):** the matcher threw **before judging anything**:

```
[Expeditor] Fuzzy match error: ... maximum context length is 8192 tokens.
However, you requested 203873 tokens (199777 in the messages...)  → HTTP 400
```

**Root cause:** `expeditor.py:_handle_fuzzy_file_match` builds `docs_map` from the user's deep-research + presentations dirs **plus an `os.walk` of every path in `podcast generator source search paths` = `/src`**, then (`:1104-05`) dumps the **entire** candidate path list into the phi-4 prompt with **no keyword pre-filter**. The router's twin (`podcast_generator.py:match_research_docs`) already had that pre-filter; the expeditor path did not. So *every* description got "Matching failed", regardless of scope or match quality — the overflow precedes the judgment. This **supersedes** the morning catalogue's "out of scope" story: my seed was **in scope** and still failed.

**Candidate count, reconciled (corrected 2026-08-03):** the **expeditor** — the failing path — scans **four** extensions, `.md/.yaml/.yml/.txt` (`expeditor.py:1031`, `source_extensions`), not `.md` alone. Its candidate set under `/var/lupin/src` is **6,676** files (reproduced host and container) — that is what overflowed phi-4, and it matches the logged **199,777** tokens. An earlier **md-only** figure of **1,964** answers a *narrower* question — the **router**'s `match_research_docs`, which filters `.md` only (and already had the pre-filter, so it never overflowed). Both stand, each for its own path: **6,676** (expeditor, four extensions) is the overflow count; **1,964** (router, md-only) is the narrower resolver. Token math settles it — 1,964 md paths ≈ 37k tokens cannot produce 199,777, the four-extension set does. *(Correction on the record: I first reported the md-only 1,964 as authoritative; Rio's ~6,670 was right for the failing path.)*

**The two fixes (both landed):**
- **Config mitigation** (commit `7e29bcfe`, Tiffany): `podcast generator source search paths` `/src` → **empty**, so only the user's always-scanned deep-research + presentations dirs remain — a handful of files, no overflow. Live without a bounce (the expeditor builds a fresh `ConfigurationManager` per call, re-reading the bind-mounted ini). Splainer rewritten so the empty value reads as a deliberate exit condition, not an oversight.
- **Durable code fix** (commit `e651bc76`, Rio): extracted the router's keyword pre-filter into a shared helper `cosa/agents/io_models/utils/fuzzy_file_prefilter.py` and routed **both** paths through it — one behaviour, not two copies that can drift.

**Verified:** re-run with the mitigation, the vague description *"the explainer about automating the old lighthouse so it minds itself"* **resolved to the seeded doc** (confirm summary: `research=/var/lupin/io/deep-research/…/2026.08.03-verdigris-lighthouse-automation-explainer.md`). **Stage 3 passes.**

## Wall 2 — the script parser drops everything on a brace (stages 4-5)

With stage 3 fixed, the job created and ran — then produced a **136-byte, zero-segment "Untitled Podcast"** artifact. **This is not dry-run and not a matcher problem.** On job `pg-c24936c8`: analysis ran, `script_generation` returned **5,533 tokens**, then `parse_script_response` fell to its default fallback (`title="Untitled Podcast"`, `segments=[]`, `0.0 min`) because `lenient_json_loads(response.content)` returned `None`.

**Trigger (Clayton, deterministic three-way control):** a **brace in the model's trailing prose** after the closing ```` ``` ```` fence. Clean fenced JSON → 2 segments; the same JSON followed by an `### Explanation` line containing any `{` → 0 segments; the same trailing prose with no brace → 2 segments. **The job did not error** — it completed and asked a human to approve an empty script. There is no guard between "produced nothing" and "ready for sign-off". Owned by Clayton (P0 `4317efd1`); scope widened — the parser is copied three times and the **presentation generator has the identical bug**, being de-duped onto one helper.

Rio's shared pre-filter drops any candidate sharing **zero** keyword tokens with the description — a silent-failure risk if a demo sentence has no word in common with the document's path. **Measured against Rick's real pair** (his sentence about the KISS protocol and saving tokens, vs the real filename `2026.07.25-the-kiss-protocol-how-a-brevity-mandate-got-built.md`): with narrowing forced (201 files → 1), **his doc is the sole survivor** on its `kiss`+`protocol` overlap. The zero-overlap drop **is** real (reproduced: a description with no path-token overlap drops its target), but it does **not** bite Rick — (a) his sentence overlaps his filename, and (b) post-mitigation his candidate map is under the 50-file narrowing threshold, so the pre-filter returns it unchanged. The risk returns only if `/src` is restored to the search key.
