**Every arm kills exactly one test.** No arm is decorative, and none is covered only by another's assertion. This is the shape the plan asked for and did not have.

The `ORACLE EMPTY` arm in particular earns its place: it is the one thing standing between this gate and the empty-vs-empty trap, where an emptied HTML file and a broken endpoint agree at `set() == set()` and the suite reports green.

## 🔴 The blocking gap — Auto-Route makes the live guard permanently red

`AUTO_ROUTE_SENTINEL = "__auto_route__"` is declared in the module and **used nowhere in the predicate**. It appears only in the control's *clean* case, where the caller happens to put it on **both** sides.

That works synthetically and fails live. After phase 3, `expected` is the registry's `USER_INITIABLE_COMMANDS`, and the sentinel is **deliberately not a registry command** — that was the entire point of choosing a sentinel over an exemption. The rendered DOM must still carry Auto-Route. So the two sides disagree by exactly one element, forever.

Executed, not reasoned:

```
expected = { "agent router go to math", "agent router go to weather" }
rendered = [ "__auto_route__", "agent router go to math", "agent router go to weather" ]

  → PHANTOM: '__auto_route__' was rendered but is not in the expected set
```

**Recommended fix: drop the sentinel inside the predicate, not in each caller.** One stated exception, in the shared function, where the control can exercise it — rather than a `| { AUTO_ROUTE_SENTINEL }` that every future caller must remember to write and one eventually will not.

And it needs **two** control arms, not one:

1. the sentinel present in `rendered` and absent from `expected` is **clean**;
2. a *second* unrecognised value alongside it is still **PHANTOM**.

Without the second arm the fix is a hole the exact width of "anything the render feels like adding", which is the widening we removed the exemption to avoid.

## Two smaller notes, neither blocking

**The predicate cannot police its own oracle's correctness, only its emptiness.** `ORACLE EMPTY` catches a *missing* oracle; it cannot catch a *wrong* one. If phase 3 repoints `expected` at, say, all 20 registry commands instead of the `user_initiable` subset, every arm stays green while the gate checks the wrong set — which is the original gate-3 defect wearing a new coat. That belongs in the caller's own assertion, and it is worth one line in the phase-3 test saying which column it read.

**`rendered_list = [ v for v in rendered ]`** is `list( rendered )`. Harmless; mentioned only so nobody reads intent into it later.
