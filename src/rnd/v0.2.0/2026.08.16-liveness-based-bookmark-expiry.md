### 1.2 The existing janitor is the pattern to copy — it is nearly generic already

`dm_inbox_hwm_janitor.classify_hwm_file` already:
- keys on the **filename** session fragment (an HWM body has no `session_id`), and
- gates on the **live set FIRST** (bias-to-keep: `live_session_ids is None` keeps

- compares **`[:8]` prefixes** (`_live_prefixes`): the truncation over-matches, and
  over-match is the safe direction (keeps MORE). The lossy key is load-bearing —
  widening to full ids would make truncated filenames miss every live id.

The `[:8]`-prefix comparison generalizes cleanly to the full-id families
(`ask-answer`, `task-store-map`, `heartbeat-acked` all carry the FULL id in the
name; an `[:8]` prefix of a full id still matches an `[:8]` live prefix).

## 2. The design

### 2.1 Generalize the janitor to be family-parameterized

Extract the classify/report/sweep trio into one family-parameterized module
(candidate: `bookmark_janitor.py`), parameterized by `(glob, prefix, suffix)`.
`dm_inbox_hwm_janitor` becomes a thin binding (or is folded), so its proven
semantics — live-gate-first, bias-to-keep, prefix compare, negative-age = not-provable
= KEEP — are inherited unchanged, not re-implemented.

### 2.2 Register the three uncovered families in the arbiter sweep

Add `ask-answer-hwm`, `task-store-map`, `heartbeat-acked` next to the existing
dm-inbox sweep in `fleet_arbiter_loop`, fed the SAME `find_active_sessions` live set,
under the same `enable_hold_deletion` gate.

### 2.3 Two per-family carve-outs that MUST be preserved

- **`.heartbeat-hold-*` is NOT in scope** — those move to `/tmp` in Phase 1
  elsewhere. The glob must not catch them. `heartbeat-acked` ≠ `heartbeat-hold`;
  scope precisely.
- **Unparseable names are SKIP/KEEP.** `.dm-inbox-hwm-stable-s.json` (no parseable
  id) and `.heartbeat-acked-unknown.json` (empty-id fallback) must never be reaped —
  same typed `KEEP_UNPARSEABLE` outcome the dm-inbox janitor already emits.

### 2.4 Falsifiability (same standard as any live guard)

Each family's classify rule gets a must-fail control: a real filename with its
session id **withheld** from the live set → PRUNABLE; with it present → KEEP. Prove
the live-gate fires by deleting the gate and watching the control go red. The
report/sweep pairing (dry-run count == delete count under one clock + one live set)
carries over from the dm-inbox janitor.

## 5. The traps — what I would get wrong

1. **Widening the `[:8]` prefix key to full ids** would make every truncated
   filename miss every live id and start reaping live sessions' cursors. The lossy
   key is load-bearing; do not "fix" it.
2. **An empty live set reading as "nothing is alive."** `None` (unknown) keeps
   everything; an empty-but-authoritative set is different from a failed enumeration.
   Only pass a non-None set when sessions were genuinely enumerated.
3. **Catching `.heartbeat-hold-*` in a loose glob.** Scope to `heartbeat-acked`
   exactly; the hold family is someone else's Phase-1 move to `/tmp`.
4. **Reaping `unknown` / `stable-s`.** No parseable id = KEEP, typed.
