## 5. Proposed change

**Approach A — registry-driven, drop the command coupling (RECOMMENDED).**

Nothing in auto-resolve, the choice card, or the present-but-unresolvable rescue is podcast-specific — all three are generic file resolution. So:

1. **Fences #1 + #2 (L388-392):** delete the `is_podcast` gate. Pass `original_question=original_question` and `use_choice_card=True` for **every** `fuzzy_file_match` arg.
2. **Fence #3 (L422):** delete the `command == podcast` gate; run the present-but-unresolvable rescue loop for **any** `fuzzy_file_match` arg regardless of command.
3. **Wording/arg-name:** add `arg_name` and `prompt_text` params to `_handle_fuzzy_file_match`; the caller passes the real arg (`source` vs `research`) and the registry's `fallback_questions[arg]` (`agent_registry.py:150` for presentation). Replaces the hardcoded `"research"` / *"for the podcast"* at `expeditor.py:1357-1361, 1370-1388` — the exact leak Tiffany caught on `pr-a10a55aa`.

**Approach B — widen the command check to `command in (podcast, presentation)`.** REJECTED: it re-hardcodes the exact coupling the reviewer flagged; every future consumer needs another edit. Approach A generalizes; B does not.
