**Reviewer**: Clayton 😎 (`b36934bf`) · **Date**: 2026-08-22 · **Under review**: `a82bb155`, `src/rnd/v0.2.0/2026.08.22-qa-card-phase-4-observation-method.md`
**Verdict**: **His claim is CORRECT, and I verified it through the code rather than from the doc. The review over-generalised. One residual finding.**

## The claim, and the attack

Sam's claim: the review called phase 4's drain unobservable on `:8000` by citing `ce29cd20`, but that xfail is on `/api/v2/ask` — a door with no `parent_id_hash` — while phase 4's agentic path uses `/api/v2/submit`, which has one and which Gate B admits through the monopolize hold.

**I traced it end to end rather than reading his summary:**

1. `queue_consumer.py:118` — Gate B's admission predicate is
   `getattr( j, "spawned_by_id_hash", None ) == parent and not getattr( j, "monopolize", False )`.
   So lineage is keyed on **`spawned_by_id_hash`**, not on `parent_id_hash` — which is the substitution that could have broken his claim.
2. `flow.py:595` — `_submit_agentic` passes **`spawned_by_id_hash = parent_id_hash`**. The two fields are the same value under different names, so the substitution holds.
3. `running_fifo_queue.py:461` — the hold's own comment agrees: a monopolizer *"defers foreign intake (**admitting lineage children**) until it clears."*

**So a `/api/v2/submit` carrying the running sweep's `id_hash` as `parent_id_hash` is admitted while the hold is live, and its drain IS observable.** The claim stands.

**And the review's citation does not transfer.** `ce29cd20`'s xfail sits on `/api/v2/ask`, whose signature carries no `parent_id_hash` at all — so its agentic jobs are stamped with `spawned_by_id_hash=None`, never match `parent`, and are deferred every time. That is exactly why the xfail is where it is. **The blocker generalised from one door to both, and only one of them has the field.** Sam's doc is careful to say this does *not* retire `ce29cd20`, which is the right scoping: the ask-door round trip stays unobservable for the reason its own docstring gives.

His observable is also correctly built. The conjunction — `monopolize_inflight` true **AND** `monopolize_id` names *my* sweep **AND** `inflight_agentic_jobs >= 1` — closes the hole where the gate passes because monopolize was simply **off**: with the kill-switch disabled `_monopolize_active` is never set, everything drains, and a weaker observable would go green having proven nothing about lineage.

## 🔴 The residual — the lineage tag is dropped on a falsy value, silently

`agentic_job_factory.py:135`:

```python
if spawned_by_id_hash: job.spawned_by_id_hash = spawned_by_id_hash
```

A **truthiness** guard. If `LUPIN_TEST_MONOPOLIZE_PARENT_ID` is unset, empty, or read into an empty string, the tag is not stamped, no error is raised, and the job is simply **foreign**. Gate B then defers it — and the phase-4 gate does not fail with "you forgot the tag", it **hangs until the sweep finishes**, up to `cj flow monopolize drain timeout seconds` (default **300**).

Sam's own §108 requires the tag be read *in code, not in a comment* — Tiberius hardened that at `00cd8a70` after his own control failed to fail. That rule ensures the tag is **read**; nothing yet ensures it is **non-empty**.

**Fix, one precondition in the phase-4 smoke**: assert `LUPIN_TEST_MONOPOLIZE_PARENT_ID` is non-empty *before* submitting, so a missing tag fails in a second with its own name on it rather than as a five-minute timeout that reads like a queue problem.

**This is the third instance today of one shape** — a truthiness guard that silently drops instead of refusing:

| site | falsy value | consequence |
|---|---|---|
| `isAutoRoute` (`agent-select.js`) | blank sentinel | every pick silently auto-routes |
| `option_value_drift` oracle | empty expected set | `set() == set()` passes — caught by `ORACLE EMPTY` |
| `_stamp_queue_directives` | empty parent id | job goes foreign; gate hangs 300s |

Two of the three are already guarded. This is the one that is not.

## Not a finding, worth keeping

Phase 4's gate must use an **agentic** command. Only `_submit_agentic` stamps lineage; a conversational command runs inline on the request thread, where there is no queue hand-off to observe at all. The doc's path is agentic throughout, so this is a note for whoever writes the test, not a correction.
