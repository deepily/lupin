## Step 1 — code parity (covers 569 commits)

```bash
export LUPIN_GCP_PROJECT_ID=hello-world-foo-423219
src/scripts/lupin-vm.sh deploy wip-v0.2.0-2026.08.03-present-and-demo
```

The verb already does the whole safe sequence: preflight `--phase pre` (aborts on blocking) → `push-bundle --reset` (forces the tree to the branch, preserves untracked data/env/keys) → `up -d --no-deps --force-recreate lupin-rest` → arbiter restart → `/health` gate on `:7999` (up to ~144 s, it is a slow boot) and `:8001` → preflight `--phase post`.

`--no-deps` is load-bearing and already present (bug `70794d58`): without it compose re-runs `cloudsql-socket-init`, whose `rm -f /cloudsql/*/.s.PGSQL.5432` deletes the live socket the running proxy owns — the app then crash-loops while `docker ps` still reads *healthy*.

This works because `lupin-rest-cloud-gpu` **does** bind `/mnt/lupin-data/lupin/src → /var/lupin/src` (verified by `docker inspect`), so synced code is live after the restart. `reload` is off on the VM, hence the force-recreate.

## Two defects found while measuring

### 1. The provenance stamp is five weeks stale — "what is running?" answers wrong

| Source | Says | Reality |
|---|---|---|
| `.deployed-ref` | `df611aa7`, 2026-07-13 | ❌ stale by 5 weeks |
| actual git tree | `24f8d88f`, 2026-08-17 | ✅ this is what runs |

Cause: `lupin-vm.sh push-bundle` (the verb actually used on 2026-08-17) moves the tree but **never writes `.deployed-ref`**; only `deploy-cloud-test.sh` stamps it. The design doc promised "what's running is one `cat`, not a code-grep" — today that `cat` returns a five-week-old lie, which is worse than no stamp, because a stale stamp is trusted.

**Fix**: have `do_push_bundle` write the stamp. Small change, kills a whole class of "which code is up there?" confusion.

### 2. `deploy-cloud-test.sh` points at a container this VM does not run

It is hardcoded to `REST_CONTAINER=lupin-rest-cloud-test` / `docker-compose.cloud-test.yml`. The VM runs **`lupin-rest-cloud-gpu`** / `docker-compose.cloud-gpu.yml`. Its AXIS-A path also aborts by design ("the `./src` mount was removed 2026-07-07"), which is true of cloud-*test* but **not** of cloud-gpu, where the mount is present.

**Use `lupin-vm.sh deploy`**, not `deploy-cloud-test.sh`, for this VM.
