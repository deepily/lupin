# `lupin-vm.sh push-bundle` — a silently-swallowed mode arg and a `--dry-run` that touches the VM

**Date**: 2026-08-24 · **Author**: Tiberius 👑 (`cb30ffac`) · **Manager**: Mr. Radio 🦉
**Found while**: probing row `c41ec7e6` (the `.deployed-ref` stamp) on `lupin-host-test`
**Status**: findings only — nothing changed in the script. §3 amended 2026-08-24 20:40 with the
hardware receipt: `c41ec7e6` is **proven fixed**; `5f1532d1` remains **unproven**.

---

## Verdict

Two defects in `src/scripts/lupin-vm.sh`, both measured, neither previously recorded:

1. **`push-bundle <branch> checkout` silently degrades to fetch-only.** The mode is a *flag*
   (`--checkout`); a positional `checkout` is swallowed by the arg loop and the run exits **0**
   having moved nothing.
2. **`--dry-run push-bundle … --checkout` SSHes to the VM** and runs the post-checkout preflight
   for real. Read-only, so nothing is damaged — but a dry run that contacts the box misstates its
   own contract, and `deploy` guards the identical call while this one does not.

A third claim I made in-flight — *"`reset` mode is implemented but no CLI flag can reach it"* — is
**RETRACTED**. See §4.

---

## 1. The mode argument is a flag, and the positional form fails silently

`push-bundle`'s parser (`src/scripts/lupin-vm.sh:534-543`):

```bash
DO_CHECKOUT=""
BRANCH=""
for a in "$@"; do
    case "$a" in
        --checkout) DO_CHECKOUT="checkout" ;;
        --*)        die "push-bundle: unknown flag $a" ;;
        *)          [ -z "$BRANCH" ] && BRANCH="$a" ;;
    esac
done
do_push_bundle "$BRANCH" "$DO_CHECKOUT"
```

The first positional becomes `BRANCH`. **Every later positional hits the same `*)` arm, finds
`BRANCH` non-empty, and is discarded** — no warning, no non-zero exit.

`--*` is rejected loudly via `die`. A bare word is not. So the two ways to get the mode wrong have
opposite outcomes: a typo'd flag aborts, a plausible-looking positional runs and does nothing.

### Measured

Minimal repro of the parser, `set -euo pipefail` as in the real script:

```
$ bash repro.sh mybranch checkout
BRANCH=[mybranch] DO_CHECKOUT=[]
exit=0

$ bash repro.sh mybranch --checkout
BRANCH=[mybranch] DO_CHECKOUT=[checkout]
exit=0
```

Note the exit status: **0 in both cases.** `set -e` does not fire on the failing
`[ -z "$BRANCH" ] && BRANCH="$a"` list, so the caller gets a success it did not earn.

### What it looked like live

This is how I first invoked it, believing I was moving the tree:

```
$ ./src/scripts/lupin-vm.sh --dry-run push-bundle wip-v0.2.0-2026.08.03-present-and-demo checkout
[lupin-vm] bundling branch 'wip-v0.2.0-2026.08.03-present-and-demo' from …
[lupin-vm] (dry-run) git bundle create <tmp>; scp -> VM:/tmp; cp -> …; sudo git fetch origin …; chown 1001 .git
```

The line ends at `chown 1001 .git`. It should continue with the checkout, the `__pycache__` purge,
and the `.deployed-ref` stamp — `do_push_bundle` builds exactly that text into `$move_desc` and
appends it (`lupin-vm.sh:239-246`). **The absent tail is the only evidence the mode was dropped**,
and it is visible solely on a dry run. A live run with the same mistake prints a normal-looking
fetch and leaves the tree where it was.

That is the sharp end: the failure is silent in the mode where it costs something. An operator who
believes new code is on the box, and whose `.deployed-ref` therefore never moves, has been handed
the exact wrong answer that row `c41ec7e6` exists to prevent.

### Fix shape (not applied)

Reject unrecognised positionals instead of dropping them:

```bash
*) if [ -z "$BRANCH" ]; then BRANCH="$a"
   else die "push-bundle: unexpected argument '$a' (mode is a flag: --checkout)"
   fi ;;
```

The `die` message should name the flag — the mistake is reaching for a word the usage text and the
internal `case` labels both spell as `checkout`.

## 2. `--dry-run` contacts the VM

`do_push_bundle` honours the flag correctly (`lupin-vm.sh:244-247`): on `DRY_RUN=1` it logs the plan
and returns before building a bundle or opening a connection.

The **post-checkout preflight arm sits outside that function**, at subcommand level
(`lupin-vm.sh:561-571`), guarded only on `DO_CHECKOUT`:

```bash
if [ -n "$DO_CHECKOUT" ] && [ "${LUPIN_SKIP_PREFLIGHT:-0}" != "1" ]; then
    log "POST-checkout preflight (--phase post) — the tree moved without a restart"
    gcloud compute ssh "$VM_NAME" … --command "cd $VM_ROOT && bash src/scripts/preflight-vm.sh --phase post"
fi
```

No `DRY_RUN` test. So `--dry-run … --checkout` opens an IAP tunnel and runs 59 assertions against
the live VM.

### Measured

```
$ ./src/scripts/lupin-vm.sh --dry-run push-bundle wip-v0.2.0-2026.08.03-present-and-demo --checkout
…
== Summary ==
phase=post   passed=59   warnings=5   blocking=0   layers-skipped=0
PREFLIGHT PASSED (5 warning(s), non-blocking)
```

Those 59 assertions ran on `lupin-host-test`. The tree had not moved — nothing had — so the log
line above them ("the tree moved without a restart") is also false on this path.

### Why it is worth fixing even though it is read-only

`deploy` guards the structurally identical remote call (`lupin-vm.sh:642-650`): `DRY_RUN=1` prints
`RESTART_CMD` instead of SSHing. **The two sibling subcommands disagree about what `--dry-run`
promises**, and the one that disagrees is the one an operator reaches for to check a flag before
committing to a deploy.

The concrete cost: a dry run is the cheap thing you do when you are unsure. This one takes an IAP
tunnel and ~30s of VM assertions, and reports a "post-checkout" state for a checkout that never
happened. Nobody is harmed; the reader is misinformed.

### Fix shape (not applied)

Mirror `deploy` — either skip the arm under `DRY_RUN`, or print the command it would run:

```bash
if [ -n "$DO_CHECKOUT" ] && [ "$DRY_RUN" -eq 1 ]; then
    log "(dry-run) POST-checkout preflight on VM: bash src/scripts/preflight-vm.sh --phase post"
elif [ -n "$DO_CHECKOUT" ] && [ "${LUPIN_SKIP_PREFLIGHT:-0}" != "1" ]; then
    …
fi
```

**Provenance, stated plainly**: I did not re-measure the VM myself. The push was executed by Rick

### `dctl_detect_axis` — the payoff, now demonstrated

Earlier in this document I recorded that correcting the stamp did **not** flip the routing, because
at that moment both the stale stamp and the VM's true head routed `deps`. With the stamp corrected
to the shipped tree, it does. Measured locally against tip `3c62f7c8` (pure `git diff` over
`DCTL_DEP_PATHS` = `pyproject.toml uv.lock`; no VM involved, deterministic):

| `prev_sha` | routes to |
|---|---|
| `d04152cf` — the corrected stamp | **`code`** |
| `df611aa7` — the old stale stamp | `deps` |
| `1959ed18` — the VM's pre-push head | `deps` |

`git diff --stat d04152cf HEAD -- pyproject.toml uv.lock` is empty, which is why the first row
routes `code`.

**So the mechanism is now visible end to end**: a stale stamp made the detector claim a dependency
delivery was needed when only source had moved. The three-row table is the whole argument — the
same detector, the same target, three different `prev_sha` values, and only the honest one routes
`code`.

⚠️ **Do not read the earlier "does not flip the routing" line as refuted-and-deleted.** It was
true of the state it described: a stamp corrected to a tree that still lags on dep files would
still route `deps`. What makes this `code` is that the VM was moved level with the dev box *and*
stamped. The fix delivers the payoff **only in combination with an actual deploy** — which is
exactly the condition under which anyone reads `.deployed-ref`.

## 4. Retraction

While probing I told Mr. Radio that `do_push_bundle`'s `reset` mode was **unreachable** — that no
CLI flag could select it. **That is wrong.** `deploy` calls it directly:

```
lupin-vm.sh:608:        do_push_bundle "$DEPLOY_BRANCH" "reset"
```

`reset` is the deploy semantic (drift-proof: force the tracked tree to the branch tip), and
`push-bundle` deliberately offers only the non-discarding `checkout`. The split is by design, not
an oversight. I read the `push-bundle` parser, found no `--reset`, and concluded the mode was dead
without checking its other caller — a filtered look reported as a fact about the whole file.
