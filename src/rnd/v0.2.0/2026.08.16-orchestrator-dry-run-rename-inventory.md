## 1. The problem, restated

One token, `dry_run`, names two opposite behaviours in the presentation generator:

| layer | meaning | evidence |
|---|---|---|
| **JOB** `PresentationGeneratorJob.dry_run` | writes **NOTHING** — mock paths, `slide_count=0`, early return. Fleet-wide convention. | `job.py:236-237` → `_execute_dry_run` |
| **ORCHESTRATOR** `PresentationOrchestratorAgent.dry_run` | does **REAL ingest** and writes **REAL YAML** to disk (offline / mock-LLM mode for offline tests). | `orchestrator.py:147-156` docstring says so verbatim |

**The fix**: rename the ORCHESTRATOR parameter `dry_run` → **`offline_mode`**. The JOB flag keeps `dry_run` (it obeys the fleet convention). The two behaviours stop sharing a word.

**The trap** (Arnold): both spellings live `=True` inside the SAME test files. A mechanical/global replace silently repoints a test from one layer to the other — it still passes, asserting the wrong thing. Hence: **site by site, NO sed.**

## 4. The seam that makes this dangerous — `job.py:287`

The JOB's `dry_run=True` **early-returns** at `job.py:236` before the orchestrator is ever built, so line 287 always passes `False` in practice. But it is the one line where the two layers physically touch: the JOB flag (`self.dry_run`) is the VALUE fed to the ORCHESTRATOR keyword. After the rename the line reads `offline_mode = self.dry_run` — keyword renamed, value unchanged. Renaming the RHS here would be the exact cross-layer error this row exists to prevent.
