## Assertion 3 — why both-directions (Arnold's sharpest point)

A one-directional "`automatic` appears in prompt+training" check catches a **missing** membership (drop it from the prompt → red) but NOT an **extra** one: if `automatic` were *also* registered as a resolvable agent, the one-way check stays green because it only asks "is it in prompt+training?", never "is it ONLY there?". The fix is set-equality both ways — control/none commands equal `prompt ∩ training` AND are absent from `registry-agents ∪ factory` — exactly the shape assertion 4 already uses. The mutation above (`automatic` → CONVERSATIONAL) is the extra-membership a one-way check would miss and a two-way check catches.

### 🔴 FINDING A — assertion 3 does not catch a control→conversational migration

Assertion 3's residue is `residue = (prompt ∩ training) − V2_AGENTS − AGENTIC_COMMANDS`, compared to `cn = CONTROL ∪ NONE`. When `automatic` moves from `CONTROL` into the conversational bucket, it leaves `cn` AND is subtracted out of `residue` (now in V2_AGENTS) — both sides lose it symmetrically, equality holds, green. So the exact extra-membership case Arnold's both-directions requirement was meant to close is still invisible. This is a real behaviour drift (a mode-control command silently becomes a resolvable agent) that no drift-guard assertion fires on. **Fix**: add an assertion that `CONTROL ∪ NONE` is disjoint from `V2_AGENTS ∪ AGENTIC_COMMANDS`, or that `resolve()` returns `None` for every control/none command.

### 🔴 FINDING B — assertion 4 (partition) is green by construction; the REAL defect is a SILENT OVERWRITE

`V2_AGENTS / AGENTIC_COMMANDS / CONTROL_COMMANDS / RECEPTIONIST_OR_NONE` are all derived by filtering `REGISTRY`, a dict keyed by command with exactly one `cls` per entry. So the buckets are disjoint by construction; test_4 can never go red on real data — same pathology as the count/cls tautologies already deleted this cascade. Its `TestFalsifiability` demo uses synthetic sets, hiding that the REAL predicate cannot fire.

**The risk it should have caught (Rachel) is not an overlap — it is a SILENT OVERWRITE.** `REGISTRY = { spec.command: spec for spec in ( *_CONVERSATIONAL, *_AGENTIC, *_CONTROL, *_NONE ) }` (registry.py:183): a command duplicated across the pre-dedup tuples is dropped, last-one-wins, **no error**. Demonstrated:

| tree | pre_dedup_specs | len(REGISTRY) | silently_dropped | `math`.cls |
|---|:---:|:---:|:---:|---|
| clean | 19 | 19 | 0 | conversational |
| dup `math` injected into `_NONE` | **20** | **19** | **1** | **none** (silently flipped, no exception) |

So a duplicate silently drops a spec AND silently reclassifies the command's `cls` — exactly the drift this design exists to remove, introduced with zero signal. test_4 stays green throughout.

**Fix**: guard the PRE-DEDUP tuples, and name it for the defect:
```python
def test_no_command_is_silently_overwritten_across_class_tuples( self ):
    pre = len( _CONVERSATIONAL ) + len( _AGENTIC ) + len( _CONTROL ) + len( _NONE )
    self.assertEqual( len( REGISTRY ), pre,
        "a command string is duplicated across the class tuples — the REGISTRY dict "
        "comprehension silently dropped one (last wins), reclassifying it with no error" )
```
The partition check (test_4) is the by-construction shadow of this; this is the assertion that can actually fire.

**Why this is a LIVE HAZARD, not a test-shape argument (Rachel).** The demonstration shows `math` flipping `conversational → none` with **no exception at import**. In production that means a registered agent can change class and **become unreachable** — `resolve()` would return `None` for it, routing it to the receptionist — and nothing anywhere raises, logs, or asserts. The silent-overwrite guard is the only thing that would surface it.

**Why this count is legitimate when the two we deleted today were not.** The rule this cascade set was never "no counts" — it was *a check must not read its own source on both sides* (`[[feedback_a_derived_check_must_not_read_its_own_source]]`). The deleted `test_bucket_counts` and `test_cls_agentic_matches_agentic_agents` compared a value to the same source it was derived from (tautology). This assertion compares **two genuinely different things**: the pre-dedup tuple length (the authored specs) against the post-dedup dict length (what survived). They are equal only when no command was silently dropped, so the check CAN go red — which is the whole point.
