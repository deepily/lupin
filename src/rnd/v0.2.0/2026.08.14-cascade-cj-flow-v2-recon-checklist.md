## 1. What this cascade is reviewing

A **plan**, not code. Nothing has been built. The plan proposes a parallel "v2" request-handling flow beside the existing CJ Flow (v1), living in a new `src/cosa/rest/v2/` package plus one new FastAPI router. Purpose is evaluation: build it small, measure latency-to-first-useful-response and cache-hit rate, then decide whether more is worth adding.

Your job is to find what is wrong, missing, or unbuildable **in the plan**, before a crew spends a day on it.

## 3. Standing Lupin rules that bind every finding (Layer 1 — non-negotiable)

- **The user is never a tester.** Any verification step that lands work on Rick is a finding. "Manual E2E" means "not yet automated", never "a human does it".
- **100% coverage — lines AND branches AND functions.** A plan AC that says "tests pass" without naming the coverage shape is a finding (Convention 6). `# pragma: no cover` needs a same-line reason.
- **No curl for API testing.** `TestClient` / `requests` / `urllib.request` only.
- **Testing venues**: `:7999` (dev) is for fast, read-only, non-mutating, under-2-minute work. Anything that mutates persistent state, spends LLM money, or needs the server to itself goes to `:8000` via `POST /api/test-suite/submit`. A plan that runs an eval corpus against `:7999` is a finding.
- **No backward-compat shims, no migration code, no defensive `getattr()` chains.** Fix at the source; fail loudly.
- **Paths** resolve through `cu.get_project_root()`, never `Path(__file__).parent` chains.
- **Cost model**: an LLM-driven agent should answer "can this be a bounded Claude Code job?" A plan that reaches for the firewalled Anthropic SDK without naming which guardrail rules out bounded CC is a finding.
- **Code style**: spaces inside brackets/parens, aligned `=` and dict colons, double quotes, snake_case functions, Design-by-Contract docstrings.
