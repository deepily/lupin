## The one-line version

Every held commit removes a credential fallback. A fallback removal is safe **only after**
the value it replaces is provisioned where the process can see it. Provisioning is not
done. Landing early converts a public-repo hygiene fix into a boot failure.

## Landing procedure

```bash
# 1. provision, then prove — in that order
docker compose up -d --force-recreate lupin-rest-dev

# 2. read the PROCESS, not the config
docker exec lupin-rest-dev sh -c 'tr "\0" "\n" < /proc/1/environ | grep JWT_SECRET_KEY'

# 3. only then
git cherry-pick 3ff9820f b26088de
```

Expect the recreate to **refuse to start** if `.env` is missing or the variable is blank.
That is the guard working, not a new fault.

## Three instrument failures from tonight, worth more than the fixes

These cost real time and each looked exactly like a working check.

**1. `docker exec printenv` is not the process.** It spawns a new process from stored
config and never runs the entrypoint. Where an entrypoint sources an env file, `printenv`
reports the compose value while PID 1 holds something else. Read `/proc/1/environ`.
*(Mr Radio's finding; it cost a 48-minute run.)*

**2. `git checkout -- <file>` restores from the INDEX.** Run a revert control after
`git add` and it hands back your own fix, so the guard "passes against the broken
version". Use `git checkout HEAD -- <file>`. My first control on `586e8376` was a false
receipt for exactly this reason.

**3. A worktree carries no untracked files.** I reported 39 unit failures from a worktree;
38 were `src/scripts/cloud-run.env` being absent. One was real. A red in a worktree is not
evidence about the repository until it is re-run in a checkout that has the untracked
files.

The common shape: **each check described a state that was real, but not the state in
use.** A derived reading and a live reading are different claims.

## Two more, about writing guards

**A guard that cannot fail is a comment.** My first argv guard called the command builder
with no credentials and asserted the flags were absent — which passes against the very
implementation it names. Drive the real entry point, with the real inputs.

**Never compare a credential with a bare `==`.** pytest rewrites it and prints both sides
on failure; when one side comes from the ambient environment, the guard publishes the
password. This happened to me at ~18:15 and is a second exposure on row 4996e41c.
Collapse to a bool first:

```python
matched = env.get( "..." ) == expected
assert matched, "value withheld deliberately"
```

## Scanner notes (`src/scripts/secret_scan.py`)

It judges shape, not intent, which is what makes it useful — it correctly flagged a decoy
of mine that read as obviously fake to a human. Shape test fixtures as `<angle-bracket>`
placeholders so they cannot trip it.

Three false positives found, all one root: the placeholder and reference rules require the
extracted value to be *exactly* that form, so a trailing token defeats them — a dict's
closing brace on the same line, a quote-plus-newline inside an embedded `.env` line, and
an `x or y()` expression. Reshape the code; do not reach for `--no-verify`, because that
habit costs more than the lines do. Raised with Chloé.
