## The centrepiece: CJ Flow v2 — the brain, and the doors

Rick named this himself as the thing to document. The build ran as epic `f7b57d88` — thirteen
steps, two implementation lanes, a per-step gate of *red-on-revert* plus both test tiers green
plus an independent reviewer PASS before any step merged.

### What it replaced

Before this branch, a question entering Lupin was handled by `TodoFifoQueue.push_job()` — a
440-line method that did fitness checking, cache lookup, near-match confirmation, LLM routing,
agent construction and the queue push, all inline. **Eighteen HTTP routes put work on the
queue**, each with its own contract, and routing logic had drifted into *three* places: an
`if`/`elif` chain reached from `push_job()`, a `MODE_TO_AGENT` map, and a command `if`/`elif`
in the job factory.

### What exists now

**Two doors, plus resume.** Verified against the live `:7999` OpenAPI document at 18:36 EDT
— the server has 158 paths and exactly these under `/api/v2`:

| path | method |
|---|---|
| `/api/v2/ask` | POST |
| `/api/v2/submit` | POST |
| `/api/v2/resume` | POST |
| `/api/v2/agents` | GET |

`ask` takes a question. `submit` takes work whose command the caller already chose. `resume`
answers a question the flow asked back. The split is the design: `submit` deliberately refuses
to hold a conversation, which is why the podcast door — whose description path fuzzy-matches
documents and asks which one you meant — retired into **`ask`** and not `submit`.

**One brain behind them.** `AskFlow` (`src/cosa/rest/v2/flow.py`, 84,648 bytes) resolves the
command against the registry, runs the argument expeditor, asks the user when an argument is
missing, and hands the built job to the queue. It is constructed **once** in the app lifespan
(`src/cosa/rest/routers/v2_ask.py:227`) and served to both the HTTP routes and the in-process
callers as the same object — one flow means one guarded write-back path.

**The v1 path is dead, and a test enforces it.** `push_job()` still exists but carries a
`🔴 DEAD AS OF STEP 6c` banner naming its replacement, and
`src/tests/unit/test_6c_push_job_has_no_production_caller.py` fails if any production module
calls it again. The deadness was made *legible* rather than merely true, because the branch's
own step 0 closed a trap where `grep "def save_snapshot"` led a reader into a deprecated manager
nobody runs.

**410 and not 404 is deliberate.** A deleted route is invisible and nothing stops someone
re-adding it next year; a tombstone says the path existed, was retired on purpose, and names its
replacement — so a caller reading the failure learns the fix instead of filing a bug. The removal
date lives in the *message*, not only in a comment, because the callers that still hit these
paths live in two separately-managed repos whose owners will never open the file. And the
tombstones carry **no auth dependency**, so an unauthenticated stale client learns the same thing
an authenticated one does rather than getting a 401 that reads like a credentials problem.

**Three doors stayed out, each for a stated reason** — this is the part that shows the cut was
made by reading handlers rather than route names:

  accepts base64 MP3, transcribes with Whisper, and queues only on the `munger.is_agent()`
  branch. Retiring it would have taken browser dictation and the multiplexer's insert-at-cursor
  down and offered them nothing. Its queueing *tail* now hands the transcription to the v2 ask
  flow in-process (door 8) — Rick's framing: there are two ways to ask, type it or say it, and
  both end at the same flow.
- `/api/mock-job/submit` stayed because `submit` genuinely **cannot build** a mock job — no
  entry in `JOB_ARG_CONTRACTS`, no branch in `create_agentic_job`. A tombstone pointing at a door
  that refuses back teaches less than the handler it replaced.
- `/api/test-suite/submit` stayed because it is how the gate rig schedules a `:8000` run, and it
  was ordered to land **after** that gate was green. The gate went green 2026-08-25; **this door

### The registry as the single source

`src/cosa/rest/v2/registry.py` holds **20 commands** — 11 agentic, 6 conversational, 1 control,
2 none — read out of the module tonight. The agentic set is not a hand-written list; it is a
comprehension over the argument-contract table:

```python
_AGENTIC = tuple( _agentic_spec( command, entry ) for command, entry in JOB_ARG_CONTRACTS.items() )
```

`JOB_ARG_CONTRACTS` carries **11 entries**, and the two counts agree because one is derived from
the other. Display name, CLI module and CLI style come off the same entry, so there is no second
list to drift from the first. `src/tests/unit/test_v2_registry_drift_guard.py` (24 tests) exists
to stop the three retired routing mechanisms coming back.

⚠️ **"No `if`/`elif`" is true of ROUTING and false of CONSTRUCTION, and the distinction is
load-bearing.** Turning an already-resolved command plus arguments into a Job object still
dispatches by branch. Counted in the tree tonight: **11 branches, live**, at
`src/cosa/rest/agentic_job_factory.py:189–400`. The registry carries a `job_factory` field for
exactly this and it is `None` — the phase that wires factory dispatch by lookup has not landed.
A new agent today **does** add a branch there. Pass 2 of the voice-workflow document nearly told
crews the opposite, which would have left a new agent unbuildable; it was caught by grepping the
factory instead of trusting the design note.

## Making a new agent reachable by voice

Rick asked a plain question during this branch: **can a SWE team register a newly built agent so
that it runs by voice?** The honest answer used to be *"yes, if they find all four places."* It is
now *"one contract entry, two one-line opt-ins, and one construction branch that is on its way
out."*

The `agentic-voice-workflow` skill had drifted far enough from the code that following it produced
an agent that was **callable by API and mute by voice**. The repair split into two passes, and the
split was deliberate:

| | **Pass 1** — what the checklist was MISSING | **Pass 2** — what the checklist got WRONG |
|---|---|---|
| landed | 2026-08-15/16 (`ec29deff`, `21f230df`) | 2026-08-25 |
| shape | *widening* — same world, more of it | *correcting* — different world |
| problem | two registration surfaces were absent, so an agent could satisfy every listed item and still be unreachable | the system underneath was rebuilt; the checklist still described the old one |

**Pass 2 was deliberately gated through four attempts to start it**, on Rachel's reasoning:
*"Writing it earlier documents a system that does not exist yet, which is how this skill became a
CAUSE of drift in the first place."* Its gate had two halves — the registration consolidation and
the brain integration — and both had to land first. Twice the row *looked* workable because the
store can only express one blocker and half a gate reads as clear.

Full write-up: `src/rnd/v0.2.0/2026.08.25-agentic-voice-workflow-pass-1-and-2.md`. Two rules from
it that are cheap to get wrong:

- **Queue directives are not agent arguments.** `scheduled_at` and `monopolize` arrive in the same
  dictionary as real arguments and are popped out before the job is built. `create_agentic_job`
  reads arguments **by name** and does not name these, so a left-in `scheduled_at` is dropped in
  silence and the job runs immediately while the caller believes it is scheduled.
- **Ship in `shadow` first.** Trust mode is per agent in the INI
  (`disabled` / `shadow` / `suggest` / `active`). Default `shadow` computes and logs the decision
  without executing it, so you get a real trace on real traffic before the command can act.
  **A green pipeline test does not mean voice-reachable** — those are different claims and the
  pipeline test cannot make the second one.

### 2. The OOM cap is built, measured, and deliberately not lifted

Three Claude Code sessions were killed by `systemd-oomd` on 2026-08-23. The allocator is now
**named** rather than suspected (row `32c58572`): `node:assert` builds its failure diff by deep
-inspecting the actual value, and on a happy-dom element that walk reaches
`element → ownerDocument → defaultView → the entire Window graph` and does not terminate.

**It needs three things at once** — happy-dom registered × a DOM node as an assertion operand ×
the assertion **failing**. Controls, three runs per cell: the conjunction died 3/3; a passing
assert on the same node, a plain object with a failing assert, and a failing assert without
happy-dom all survived at ~86 MB.

⇒ **The hazard is a failing assertion holding a DOM node, not "the TypeScript tier"** — which is
precisely the state a *fix cycle* is in, and why green runs never showed it.

when it cannot cap, and is wired into `npm test` — `npm run test:uncapped` answers with a refusal
naming the incident. Containment was watched independently during a capped run: **three kills in 68

## The stamping convention — every number carries `run_at` + `head`

**Added 2026-08-25 by Krishna 🦚 (session `4550bc37`) on Mr Radio's adoption, so it lives in the
document it governs rather than in the DM thread that produced it.** A convention that exists only
in a message is the same defect this branch kept finding: a rule nobody can read at the point of use.

### The rule

> **Every measured figure in this document carries the `run_at` timestamp and the `head` sha it was
> taken at. Two figures reconcile ONLY at the same sha. A figure without both is not comparable to
> anything — it is a number with no referent.**

### Why — the receipt, not the argument

Three people measured this branch's topology inside fourteen minutes and got three different
answers. **Nobody miscounted.**

| who | run_at (EDT) | head | ahead | files | insertions |
|---|---|---|---|---:|---:|
| Clayton 😎 | 18:35 | `56a7ed22` | 1,419 | 1,380 | +315,661 |
| Krishna 🦚 | 18:26 | `dfc84ddb` | 1,420 | 1,381 | +315,698 |
| Krishna 🦚 | 18:47:51 | `6e5cb95e` | 1,422 | 1,382 | +315,934 |
| Mr Radio 🦉 | 18:48:23 | `a9bdc3ef` | 1,423 | 1,382 | +315,990 |

Four commits landed in that window — `dfc84ddb` 18:36:17, `480d4e8f` 18:45:02, `6e5cb95e` 18:46:59,
`a9bdc3ef` 18:48:14. Every row above is correct **at its own sha**. Strip the sha column and the
table reads as four people disagreeing about one number.

### 🔴 The clause the receipt actually forced: capture the sha MECHANICALLY

The first version of this rule said "stamp the sha." That is not enough, and this document proved it
on itself. The table above originally read **"Measured 2026-08-25 18:35 EDT, at `dfc84ddb`"** — but
`dfc84ddb` was committed at **18:36:17**, a minute *after* that measurement. The sha named a commit
that did not yet exist when the numbers were taken.

The figures were never wrong. Re-derived at the sha one commit earlier:

```
$ git rev-list --count main..dfc84ddb^          -> 1419
$ git diff --shortstat main...dfc84ddb^         -> 1380 files changed, 315661 insertions(+), 35236 deletions(-)
```

Exact match on all four. **Clayton measured at `56a7ed22` and the label said `dfc84ddb`** — a
hand-written stamp applied after the fact, off by one commit.

⇒ **A WRONG STAMP IS WORSE THAN NO STAMP.** With no sha, a disagreement is merely unreadable. With a
wrong sha, honest drift is converted into an apparent miscount, and the next reader goes looking for
an arithmetic error that was never there. That is strictly more expensive than the ambiguity the
stamp was added to remove.

### How to take a figure so the stamp cannot drift

Capture the sha in the **same invocation** as the number. Never type it in afterwards:

```bash
SHA=$( git rev-parse HEAD )                 # resolve ONCE — this is the referent
MB=$( git merge-base main "$SHA" )
STAMP="run_at=$(date -Iseconds) head=$(git rev-parse --short "$SHA")"

echo "$STAMP  ahead=$( git rev-list --count main.."$SHA" )"
echo "$STAMP  $( git diff --shortstat "$MB".."$SHA" )"
```

🔴 **COUNT AGAINST `$SHA`, NEVER AGAINST `HEAD`.** The first version of this snippet stamped
`git rev-parse HEAD` and then counted `git rev-list --count main..HEAD` — **two separate
resolutions of a moving reference.** A commit landing between them produces a stamp and a count
that describe different trees, which is the very failure this rule exists to prevent, reintroduced
inside the fix for it. Resolving the sha once and measuring against that variable makes the stamp
and the number describe one tree by construction, not by luck of timing.

### Scope

Applies to every quantity in this document that was counted rather than reasoned: commit and file
counts, insertions/deletions, test counts, door counts, coverage percentages, corpus sizes. It does
**not** apply to a figure quoted from a named historical artifact — those carry the artifact's own
identity instead, which is the same principle one level up.

**Companion rule already in force**: `history.md`'s header carries provenance only and no health
figure, for the same reason — a stamped number that nothing re-derives goes stale silently, and was
quoted into a commit message as a health claim on 2026-07-27.
