# The collection diagnosis now reaches a human at a terminal

## Verdict

Sam's module was wired into the scheduled suite job and into the in-process pytest hook.
Neither of those is what a person types. Anyone running a sanctioned runner script still
got pytest's bare traceback, because every runner ended in `exec pytest` — and `exec`
replaces the shell, so nothing was left alive to read the one signal a conftest collection
error produces.

---

## 1. Why the exit code, and only the exit code

Unchanged from the finding this row descends from, and it is the whole design constraint:

| | error in a TEST module | error in a CONFTEST |
|---|---|---|
| exit code | `2` | `4` |
| junit XML | written | **absent** |
| pytest hooks | fire | **none fire, anywhere** |
| reachable from inside pytest | yes | **no** |

A conftest takes the directory down before pytest has a session. No plugin, no hook, not
even the outermost `src/conftest.py` runs. The exit code, read by the shell after pytest
returns, is the only thing that survives — so the fix has to live in the shell.

## 2. What changed

**New**: `src/scripts/lib/pytest-with-diagnosis.sh` — one sourced function,
`run_pytest_with_diagnosis`, used in place of `exec pytest`. It tees the run, reads
`PIPESTATUS[0]`, and on any code that is not 0 or 1 asks the diagnosis module about it.
The module answers with silence for codes that are not collection errors (3, 124, 130).

**The exit code is the product.** The wrapper re-raises pytest's status verbatim and
discards the diagnoser's own — a wrapper that swallowed a non-zero status would turn every
failure into the same silence it was built to end.

| Runner | Before | After |
|---|---|---|
| `run-unit-tests.sh` | `exec pytest` | wrapper |
| `run-cosa-tests.sh` | `exec pytest` | wrapper |
| `run-smoke-tests.sh` | `exec pytest` | wrapper |
| `run-pytest-direct.sh` | `exec pytest` | wrapper |
| `run-serial-bridge-guard.sh` | `exec pytest` | wrapper |
| `run-integration-tests.sh` | captured `$?` already | wrapper (its own reporting untouched) |
| `run-e2e-ui-tests.sh` | captured `$?` already | wrapper (its own reporting untouched) |
| `run-presentation-regression.sh` | 3-way tier classification | calls the module in its NOT-EXECUTED branch |
| `run-all-tests.sh` | delegates to the above | inherits |
| `run-websocket-smoke-tests.sh`, `run-smoke-direct.sh`, `run-typescript-tests.sh` | — | **out of scope: not pytest** |

**Module additions** (`cosa/utils/pytest_collection_diagnosis.py`): a `main()` CLI so a
shell can call it, `_read_tail` (a 256KB cap so pointing it at a 200MB suite log is cheap),
and `_strip_ansi`. The last one is the wrapper's own side effect handled: `tee` makes stdout
a pipe, pytest drops colour on a pipe, so the wrapper asks for colour back with `PY_COLORS`
— and a coloured `E   ModuleNotFoundError` does not match a pattern written for the plain
string. Stripping first is what keeps the fix from silencing itself.

The CLI **always exits 0**. Its status says whether the DIAGNOSER ran, never whether the
suite passed; a non-zero there would be read by the next `$?` as the run's verdict.

## 3. Receipts

**Measured before, on the real runner script** (`run-pytest-direct.sh`, a real broken
conftest): exit 4, pytest's `ImportError while loading conftest` traceback, **no diagnosis
block**. After: exit 4, same traceback, then the block naming `conftest`, "signature change
ahead of its callers", `make_provenance`, and the uncommitted-file list.

**26 tests** in `src/tests/unit/test_runner_collection_diagnosis.py`. Every one writes a
real cause shape and runs a real runner script as a subprocess.

| Check | Result |
|---|---|
| broken conftest via runner | block printed, exit **4** preserved |
| broken test module via runner | block printed, exit **2** preserved |
| `-k` matching nothing | block printed, exit **5** preserved |
| a passing run | silent, exit **0** |
| a genuine failing test | silent, exit **1** |
| plain `pytest`, no wrapper | still silent — **the "before", kept alive as a control** |
| Ctrl-C (SIGINT to the process group) | exit **130**, no block invented |
| timeout kill | exit **124**, no block invented |
| diagnosis module missing | exit **4** still arrives, no block, no error |
| colourised output | still classified — escape codes stripped |
| census: 7 pytest runners | each sources and calls the wrapper, none `exec`s pytest |

**7 more tests** on the module's new CLI and 6 closing pre-existing gaps in it. The file now
reads **100% lines and branches** (99 statements, 36 branches, 33 tests in
`test_pytest_collection_diagnosis.py`) — it was 93% before, with the git-unavailable path,
the removed-symbol cause class, and the truncated-suspect-list branch untested.

## 4. What dropping `exec` changed, measured rather than assumed

`exec` handed the terminal's signals straight to pytest; now a shell sits in between. Both
observables were checked rather than reasoned about: **Ctrl-C still ends the run with 130**,
and **a timeout kill still reports 124**.

The PID-file guards (`run-integration-tests.sh`, `run-e2e-ui-tests.sh`) are **unaffected, and
that is a receipt, not a non-event**: both record `$$` — the runner shell's own PID, never
pytest's — and neither script ever used `exec`, so the wrapper cannot have moved what they
record. A test drives the pattern live: with a real pytest running under the wrapper, the
recorded PID is the runner shell and `kill -0` finds it alive.

## 5. What this does NOT do

- **A literal bare `pytest` typed by hand is still silent on the conftest shape.** Nothing
  can change that from inside pytest — no hook fires. This closes the sanctioned runner
  scripts, which is where the row aimed it; someone invoking pytest directly is outside any
  wrapper by definition.
- **The suite job now sees the block twice** — once in the captured log the wrapper printed
  it into, once through its own `diagnose()` call. Harmless duplication, named here so the
  next reader does not file it as a bug.
- **The cause catalogue is unchanged.** It covers the two measured shapes plus two
  neighbours; anything else still reports as unrecognised rather than guessed.
- **No `:8000` run has hit a real collection error yet.** Same gap Sam named. This row adds
  runner-level proof by construction, not a live scheduled suite tripping over one.
