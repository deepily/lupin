### The trap to design around

`pointer_tokens` is used **two ways that must not disagree** (its own docstring says so):
as the body of the whole-line structure rule `_ATTACHMENT`, so a restored line counts as
STRUCTURE rather than as a claim and repairing a message cannot push it back over the
trigger — *and* as the thing the restore lifts out of the model's reach.

⇒ **Do not narrow `pointer_tokens` itself.** Narrowing it changes the sentence counter.
Add a separate, narrower selector for the restore path only.

### The design I had settled on (not yet written)

- `sentences.py`: new `is_bare_identifier( token )` — true when the token has no `/` and
  no `.`, which by construction of `_POINTER_TOKEN` means the bare 8-hex row-id shape.
  URLs, slashed paths and `filename.ext` all carry one or the other, and each tells a
  reader *where to look*; a bare id tells them nothing actionable once the sentence that
  gave it meaning is gone.
- `sentences.py`: new `restorable_pointers( text )` = `pointer_tokens` minus that shape.
  `pointer_tokens` UNCHANGED.
- `dm.py`: `_restore_dropped_pointers` calls `restorable_pointers` and appends **at most
  one** line.
- `dm-tutor.txt`: **line 13** is the offender — *"Your output MUST contain any and all
  commit hashes, path specifiers, and/or other IMMUTABLE string literals…"*. Replace with
  a prohibition: an identifier may appear only inside the sentence that uses it; never on
  a line of its own; never as a list; if a hash does not belong in one of the three
  sentences, leave it out. Lines 18–19 already cover "return literals verbatim", so that
  half of line 13 need not be restated. Lines 16–17 (the path slot) stay untouched.

**ONE OPEN CHOICE, decide it explicitly rather than by accident** — when the rewrite drops

## What the rows actually were

The first three were one defect wearing three costumes: **a card or ask was identified by its PROSE**, and the prose is derived per calling agent. That made the wording a join key between code and the proxy answer files, so every new agent needed a byte-identical copy and a wording change silently unanswered the card with no error anywhere.

The remedy each time: give the surface a **stable id** in `response_options` (which the API carries through as an opaque dict — no model field, no endpoint change), match it exactly **before any model call**, and let the entry carry no prose at all. `document_choice` for the multiple-choice card, `document_describe` for the open-ended ask.

Alongside it, three smaller things worth remembering:

- **`file_args` in `JOB_ARG_CONTRACTS`** now declares each file-typed argument once (`kind="file"`, `search_roots`, `search_paths_key`). It killed a derivation where the extra-search-paths config key was built from the display name and **fell back to the podcast's key** — so an agent with no key of its own searched wherever the podcast was configured to look.
- **Strategy-agnostic validation** in `responder.py`: every `multiple_choice` answer is checked against the card's own options, exact-after-stripping, because that is the expeditor's own acceptance rule.
- **`option_sentinels`** now knows `__all__` as well as `__first_option__` / `__last_option__`.

The fourth row, `adf5c1a1`, is the one the other three created: that validation originally **skipped every multi-select card**, because the multi-select encoding was pinned nowhere and any rejection would have been a guess. `054207ce` pinned it, which retired the reason — so the skip came out, and answers are now checked one pick at a time, plus a separate check that the answer is keyed under a header the card actually asked.

## Things a successor will get wrong without being told

**Profiles do not inherit.** Each proxy script file carries its own copy of a generic entry. The id buys a VERBATIM copy, not a shared one. I overclaimed this and had to correct it in `861012b9`.

**The straggler guards are scoped by response type, and must stay that way.** The choice-card guard is scoped to `multiple_choice`, the describe guard to `open_ended`. Each would false-accuse the other's entries if widened. Both María and Mr Radio initially read the six open-ended describe entries as choice-card entries; I refuted it with `response_types` read out of the records, and they withdrew. **Read the records, don't grep the prose** — that mistake was made three separate times on these rows by three different people, including me.

**The `agents` tag is a second discriminator, not decoration.** María found that `_entry_for_card_id` returned before `_filter_entries_by_agent` ran and iterated the unfiltered list, so the tag was silently ignored on the id path. Live in the merged card path and harmless only because no `card_id` entry was tagged. Fixed in `b2228d79`; the lookup now searches the filtered list and narrows by `arg_name` too.

**A bare label string does not answer a multi-select card.** It gets wrapped under the header `"response"`, the card's real header reads as ABSENT, and the agent concludes the user selected nothing — silent, and identical to a human declining. `__all__` must submit `{"answers": {"<header>": [labels…]}}`. `", ".join( labels )` would pass review and apply zero fixes. This is why `054207ce` said "pin the encoding first"; it was the load-bearing step.

**A carve-out outlives the reason that justified it.** `unoffered_values` skipped every
multi-select card because the encoding was "pinned nowhere" — true when written, false
eight commits later once `encode_multi_select` pinned it. María caught it; the reason had
expired but still read as sound, and it sat in a different part of the file from the
change that retired it. **When you pin something, go looking for whatever was justified
by it not being pinned.** My own first instinct was to correct the stale docstring, which
would have left the unguarded path in place wearing a fresher excuse.

**Some defects are structurally out of reach of the obvious fix.** Element-wise label
comparison cannot catch `{"answers": {"Wrong": ["a valid label"]}}` — the label is real,
the KEY is wrong. That needed its own function (`unasked_headers`) and its own commit. A
wrong header is not a wrong answer: upstream it reads as NO answer, the reader falls to
its default, and the agent reports the user chose nothing.
