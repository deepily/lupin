# Thursday demo — the one page (podcast from a spoken sentence)

**For Rick, Thursday 2026-08-06. Read standing up.** The path: pick "Podcast Generator,"
say a plain sentence about a document, and it builds a podcast you can play on the spot.

---

## 1. What you do — in order

1. Open the app (the notifications page).
2. Choose **Podcast Generator** from the request dropdown.
3. Type or say a plain sentence describing the document you want — e.g.
   *"the explainer about the KISS protocol and saving tokens."* You don't need the filename.
4. **Uncheck "Dry Run."** Dry Run plays a canned sample; unchecking it makes the real podcast.
5. Send it. A job card appears and starts working.
6. When the card asks you to **approve the script**, approve it. (It also asks out loud.)
7. When it finishes, click **Play Here** on the card. The podcast plays in a small
   floating player right there — no new tab, no download.

---

## 2. What's proven — one line each

- **Your sentence finds the right document.** Ten different plain-English descriptions
  were tried; all ten resolved to the correct file.
- **Play Here actually plays.** An automated browser test clicks the real button and
  confirms the audio starts and advances — not just that a player appears.
- **The approval prompt can't hang the demo.** If it isn't answered, the job now
  releases itself after ten minutes instead of freezing.
- **You'll hear the approval ask.** The "approve this script" request is spoken aloud,
  so it reaches you even while you're presenting.
- **The two things that kept the player silent for weeks are fixed and live.** The
  player can now fetch the audio using your login, and it's allowed to show inside the
  page. Both confirmed working on the live servers.
- **Dry Run is now a real end-to-end check.** Dry Run plays a genuine sample podcast
  (two hosts explaining what Dry Run does), so the whole player path gets exercised at
  zero cost every time anyone runs one.

---

## 3. What is NOT proven — read this before you present

- **Nobody has run the full "card → approve → play" flow as you.** No one can log in as
  you, so every proof above was done as the test user or with the committed sample.
  The pieces are proven; the exact sequence under your own account has not been walked.
- **Keep your browser tab open through the approval step.** If the tab drops at the
  moment the approval prompt fires, delivery of that prompt isn't guaranteed — it can
  fall back to the operator instead of reaching you. Staying on the tab avoids it.
- **Off-peak is safer for a live build.** The real (non–Dry Run) build calls the model;
  during peak hours it can hit a rate limit and need a short retry. If it stalls at
  "script generation," wait a moment and resend.
