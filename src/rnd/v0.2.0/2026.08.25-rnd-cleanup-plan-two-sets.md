## 🔴 The risk that makes this more than `git mv`

**29 of the 33 are referenced from somewhere else in the repo.** A bare move silently breaks every one of those links, and a broken doc-viewer link is invisible until somebody clicks it.

Most-referenced: `2026.06.23-gcp-code-sync-to-runtime-design.md` (**8** inbound), `2026.07.08-cpu-vm-app-restore-runbook.md` (5), `2026.04.05-test-suite-agentic-job-comprehensive-expansion.md` (4), `2026.04.10-test-fix-expediter-plan.md` (4), `2026.07.12-gcp-bind-mount-revert-plan.md` (4).

## Proposed procedure

1. **Freeze the inventory** — write the 33 → destination map to a manifest file, so the plan is auditable after the fact rather than reconstructed from `git log`.
2. **`git mv` each file** (preserves history; never `mv` + `git add`).
3. **Rewrite every inbound reference** — for each moved basename, rewrite `src/rnd/<name>` → `src/rnd/<version>/<name>` across `*.md`, `*.py`, `*.sh`, `*.ini`. Bare-basename mentions with no path need no edit.
4. **Update `src/rnd/README.md`** — per-version file counts change; the table currently states counts that the move invalidates.
5. **Verify, and make the verification able to fail**: assert `src/rnd/*.md` contains only `README.md`; assert **zero** occurrences of `src/rnd/<moved-name>` remain anywhere; assert every moved file exists at its new path; `git log --follow` on a sample to prove history survived.
6. **One commit**, explicit paths only.

**Reversibility**: total. `git mv` is tracked; a revert restores every path.

# Set 2 — the `v0.2.0` rubric

## The size of the problem

**221 documents** in `v0.2.0`, covering Aug 3 – Aug 25 — **23 days**. For scale, `v0.1.7` holds 68 documents across 35 days. `v0.2.0` is running at roughly **five times** the documents-per-day of the release before last.

Median document is **7.3 KB**; the largest is 189 KB. Zero are mis-dated — every file's date falls inside the v0.2.0 window, so nothing here belongs in another version directory.

There is already a `mementos/` **subdirectory** in `v0.2.0` — the segregation pattern exists and was simply not followed. **20 documents with `memento` in the name sit loose at the top level anyway.**

## Two signals I measured, and what each is worth

**Durable citation** — is the document named from `history.md`, `CLAUDE.md`, `src/docs/`, `.claude/skills/`, or source code? **25 of 221 are. 196 are not.**

⚠️ **This is a KEEP signal only. It is not a DELETE signal, and using it as one would be the defect.** Plenty of genuine research is simply never linked from CLAUDE.md. An uncited document is *unproven*, not *worthless*.

⚠️ I first ran this census unrestricted and got **138 cited**, which looked decisive and was not: it counted citations from `io/mementos/`, which are themselves ephemeral. **A memento citing a document proves nothing about that document's durability.** The 25 figure excludes them.

**Name shape** — **35 documents** carry a session-scoped word in the filename: `memento` (20), `handoff` (5), `-brief` (4), `walkthrough` (3), `recon-checklist` (2), `rehearsal` (2), and one each of `go-no-go`, `preflight`, `draft`, `where-we-stand`, `interim`, `ledger`, `run-card`. This is a strong prior, **never a verdict** — a document named `walkthrough` can carry the only record of a real measurement.

## The rubric

**One question decides it**: *would a competent engineer who joins this project next month need this document to understand why the code, the tests, or the standing rules are the way they are?*

### KEEP — Class A: Mechanism, measurement, or root cause
States **how something actually works or actually failed**, with evidence a reader can re-derive: numbers, commands, controls, a named failure mode. Survives its session because the mechanism does.
*Examples*: `2026.08.24-oom-allocator-named-happy-dom-assertion-diff.md` · `2026.08.24-typescript-suite-memory-measured.md` · `2026.08.24-monopolize-as-idleness-caller-audit.md`

### KEEP — Class B: Decision record
Captures a ruling **and the reasoning behind it**, so a later reader can date, scope, and challenge it. This is the class whose absence the history-gap row was filed about.
*Examples*: `2026.08.17-phi4-flash-lite-rick-ruling-four-decisions.md` · `2026.08.20-brain-integration-cascade-review-plan.md`

### KEEP — Class C: Origin of a standing rule
The **sole surviving record** of why a rule that constrains future sessions exists. **Never archived, regardless of every other signal.**
*Examples*: `2026.08.23-typescript-test-runner-oom-hazard.md` · `2026.08.24-stash-guard-prefix-position-bypasses.md`

### ARCHIVE — Class D: Session artifact
State written **for one session or one seat**, at one hour: mementos, handoffs, briefs, resume artifacts, "where we stand". Needs a glossary of session ids and persona names to parse. `v0.2.0/mementos/` already exists for exactly these.

### ARCHIVE — Class E: Tactical run card
A **short-lived operational instruction** — rehearsal cards, preflight checklists, drafts, recon checklists, go/no-go sheets. Its job ended when the run ended.

### ARCHIVE — Class F: Superseded
A **later document covers the same subject more completely**, and this one adds no evidence the successor lacks. The successor must be **named in the manifest**, not asserted.

## 🔴 Disposition: archive, never delete

Rick said *"segregating and removing"*. My recommendation is **`git mv` into `v0.2.0/_archive/<class>/`** — segregated out of the working index, still on disk, still in git, still doc-viewer-reachable.

**Why not delete**: the cost of wrongly archiving is one `git mv` back. The cost of wrongly deleting is a lost root cause that nobody knows to look for — and this rubric will be applied to **221 documents by judgment**, so it *will* be wrong somewhere. Deletion converts a recoverable error into an unrecoverable one for **zero** additional benefit: git already keeps the bytes either way, so deleting does not reclaim anything a move does not.

If Rick wants them gone from the tree entirely, that is a second, separate commit **after** he has seen the classified manifest — not bundled into this one.

## Guardrails, each able to fail

| # | Guardrail |
|---|---|
| 1 | **No document cited by a durable surface is archived** until its citation is rewritten in the same commit. |
| 2 | **No Class C document is archived, ever** — even if uncited and named `-brief`. |
| 3 | **Every classification carries a one-line justification** naming the deciding evidence. No bare verdicts. |
| 4 | **Class F must name its successor.** "Superseded" without a named successor is a guess. |
| 5 | **Name shape never decides alone** — it selects candidates; the content decides. |
| 6 | The archive keeps flat filenames, so `git log --follow` and every doc-viewer link keep working. |

## Proposed procedure

1. **Classify all 221** — one line of justification each, into a manifest doc. This is the deliverable Rick reviews; **no file moves yet.**
2. **Rick spot-checks** the manifest — ideally the borderline calls rather than the obvious ones.
3. On approval: `git mv` into `_archive/<class>/`, rewrite affected citations, run the guardrail checks.
4. **Add the convention to `src/rnd/README.md`** so the drift does not recur — and honestly, so the next session writing a memento knows where it goes without asking.

## ⚠️ What I cannot promise

The classification is **judgment applied to 221 documents**, most of them written by other personas about work I did not do. I will be wrong on some. Guardrail 3 exists so that every call is **checkable** rather than trusted, and archive-not-delete exists so being wrong is cheap.

**Estimated cost of step 1**: reading 221 documents is the bulk of the work. I would do it solo unless Rick lifts this morning's skeleton-crew instruction, in which case it fans out cleanly — the classes are independent per document.
