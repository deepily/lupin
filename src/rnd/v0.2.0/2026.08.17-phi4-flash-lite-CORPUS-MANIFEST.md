# Phi-4 vs Flash-Lite — frozen replay-set manifest

**The snapshot itself is deliberately NOT in git.** It is 9.6 MB of real DM bodies
carrying named colleagues, unreleased defect discussion, and live paths. Committing
it to make the numbers auditable would trade a reproducibility problem for a
disclosure one — the same call the arm-4 crew made
(`src/rnd/v0.2.0/2026.08.04-dm-verbosity-reduction/CORPUS-MANIFEST.md`).

What is committed is everything needed to **verify you hold the same file** and to
**re-derive the same replay set** from the same source. That is the auditable part;
the bodies are not.

> The snapshot lives OUTSIDE the repo, in the fleet data root — not under
> `src/tmp/`. Arm 4's manifest records why that matters: `src/tmp/` is gitignored
> at `.gitignore:5`, so every arm-4 number was pinned to a file nobody else could
> obtain. Outside the checkout is also where `git clean -xdf` cannot reach.

## Selection — how 8,010 became 4,942

| parameter | value | why |
|---|---|---|
| `eligible_only` | `true` | only bodies that actually put the tutor OVER its trigger; an under-trigger row returns `under_trigger` and calls no model, so it measures nothing about either arm |
| `trigger_claims` | `4` | read from the live config at freeze time (`dm tutor trigger claims`) |
| claim counter | `dm.py:1097` `_count_claims` | the ROUTER'S OWN counter, imported not copied — the study's "eligible" and the tutor's "fires" must be the same function |
| `sample_size` | `null` | the whole eligible set is frozen; sampling is a cost decision for the run, not the freeze |
| `seed` | `20260817` | recorded even when unused, so a later sampled re-freeze is reproducible |
| `minimum_rows` | `1` | a zero-row freeze RAISES rather than recording an empty study input as a clean run |

## Why the freeze exists at all

The corpus is append-only and the fleet is still writing to it — it held 6,938 rows
at cascade review, 8,006 when this harness was being built, and 8,010 four minutes
later at the freeze. Two arms replayed against a moving file are not paired: arm 2
sees rows arm 1 never saw, and every per-body comparison silently becomes a
comparison of two different datasets.

## Scope limit, carried forward — this is Rick's call, not the crew's

The corpus has **zero human traffic**: 100% of fired rows are fleet-to-fleet and
~35% is self-reference (reviewers of this study feeding its own corpus). Evidence:
`src/rnd/v0.2.0/2026.08.17-corpus-human-vs-fleet-split.md`.

Internal validity is untouched — the pairing holds — but the study can honestly
claim only *"which model better rewrites agent-to-agent fleet chatter"*, never
anything about the human-facing DMs the tutor's stated job names. **No filter has
been written and none should be**; excluding fleet traffic, taken literally, empties
the corpus. This is a scope question for Rick.
