# Plausible and wrong: eight ways a test can pass without testing, and four ways a record can read true without being true

> The filename still says `seven` because rows cite it by path; the count in the title is the
> honest one. A heading that reads "seven" over a list of eight is the third record shape below,
> committed in the survey of itself.

**Rows**: `122f07a1` · `beffcddd` · `9d5fd628` · `673f14e8` · `990934d9` · `e5e964f4` · `ead5137f`

## The one sentence

Everything found today shares a shape: **the artefact looks healthy from outside and is not.**
A green test that cannot fail and a current-looking record that is stale are the same defect
wearing different clothes — and no detector we have looks in most of these places.

## Seven vacuity shapes

A test can be present, collected, executed, and green while proving nothing.

| # | Shape | Detector? | Found in |
|---|---|---|---|
| 1 | Assertion swallowed by `except Exception` — `AssertionError` IS an `Exception` | ✅ the detector | `beffcddd`, `9d5fd628` |
| 2 | Grep-shaped over `inspect.getsource` — asserts TEXT, not BEHAVIOUR | ❌ | `122f07a1` |
| 3 | Non-strict `xfail` — passes whether it fails OR unexpectedly succeeds | ❌ | `122f07a1` |
| 4 | An `or`/`in` whose satisfied branch is always true — `assert status in [200, 401]` accepts **both** answers to the question it asks | ❌ | `9d5fd628` |
| 5 | Tautological `assert True` — a no-op that never calls the method it names | ❌ | `beffcddd` |
| 6 | Assertion reached through a **helper** — `assert_response_ok()` wraps `assert`, so a statement-counting detector cannot see it | ❌ | `9d5fd628` |
| 7 | Assertion **never reached** — the endpoint 404s, every loop iteration hits `continue` | ❌ | `9d5fd628` |

**Shape 7 is the nastiest.** The code is present, collected, and passing. From outside that is
indistinguishable from healthy coverage. Proven, not argued: `assert False` planted past the
`continue`, edit confirmed on disk (+84 bytes), test still passed.

⇒ **The detector covers one of seven.** A clean run guards against one known defect. It is
never a certificate that the suite is honest, and no row should close as if it were.

## An eighth shape, and it is not test-shaped — it is RUNNER-shaped

The seven above are all things a test does. This one is something a **runner** does, and no
amount of reading the test file will find it.

| # | Shape | Detector? | Found in |
|---|---|---|---|
| 8 | **The file contributes nothing and the run says nothing** — pytest collects zero tests from a script-shaped file, exits clean, and prints a duration | ❌ | `e5e964f4` |

`pytest src/tests/lupin_smoke/test_queue_workflow.py` reported **"4 warnings in 0.07s"** and exited 0.
That is not a pass and not a failure; it is an absence wearing a pass's clothes. Three of the four
files in that directory did it at once, while the shell runner named those three and never named the
fourth — **two doors over one directory with an empty intersection**, each reporting success over a
directory neither of them checked whole.

⇒ **The artefact here is the ABSENCE of a test rather than a test that cannot bite**, which is why
none of shapes 1–7 can see it: there is no assertion to inspect. The tell is the clock. `0.07s` was
too fast to be real, and that is the only reason anyone looked.

⇒ **And a sibling of the same shape**: a suite that cannot be found being papered over with a
generated stub, so a missing suite reports green (`6ba22c29`). Same defect, opposite direction —
one runner says nothing about a file, the other invents a file to say something about.

**The corollary for credentials.** A test that needs a credential it does not have must **skip
loudly, naming the missing variable**. It must not pass and it must not vanish: a
credentials-missing path that yields green is shape 8 with a login screen. Applied in `ead5137f`,
where three admin tests now name `LUPIN_TEST_ADMIN_EMAIL` / `LUPIN_TEST_ADMIN_PASSWORD` in their
skip reason rather than quietly disappearing.

## And three ways a RECORD does the same thing

Found in one evening, two of them the manager's own:

| Shape | What it looks like | What it is |
|---|---|---|
| **Enumerated gap reading as silent** | "no detector sees this" | 89-entry allowlist, both files enumerated with dates and rows, and a census riding the unit gate |
| **Answer parked outside HEAD** | an open question | answered in an uncommitted docstring, credited by name, one `git checkout` from gone |
| **Snapshot reading as live** | the current record | frozen copy, stale by two minutes, contradicting the live one |
| **A collection count recorded as a result** | "10 tests collected" | ten tests that had never executed — every one of them errored at setup |

The fourth was filed the same night, by the manager, into the row that exists to catch exactly it:
`--collect-only -q` returned `10 tests collected`, and that number was written down as though the
tests had passed. Run properly, the same file gave **10 errors in 0.10s** — a fixture name colliding
with an installed plugin, so not one test body had ever run (`ead5137f`).

⇒ **Numeric and specific is not the same as measured.** A collection count answers "can pytest see
these?", never "do they work?", and it is seductive precisely because it looks like evidence.

## The checks that actually catch these

Each earned by getting it wrong first.

1. **Mutate + assert-the-edit-landed + run must be ONE command.** Ten times across three seats a
   red or green turned out to be the *instrument*, not the code. **A green mutation usually means a
   broken mutation, not a blunt test** — verifying `beffcddd`, a mutation aimed one branch off
   reddened a single unrelated test and read exactly like six blunt tests.
2. **Run the OLD shape verbatim on the same broken build.** The strongest receipt produced all day:
   old shape 14 passed GREEN while the new shape reddened, on an identically broken parser.
3. **Ask "is it collected?" next to "does it exist?"** A detector found 51 items; 6 were ever
   collected. The row was filed at ~8× its actionable size.
4. **Then ask "does any runner select the path it lives in?"** — and **"does some OTHER runner run it?"**
   "Not collected by pytest" is not "does not run".
5. **When a test explains why it is weak, check the explanation.** Six instances, two rows, not one
   justification survived contact. The sharpest was a **code comment** — `# No auth header` — that a
   helper three frames down contradicted by re-attaching the token.
6. **Before claiming something is unmonitored, grep for an allowlist or a census.** A deliberate,
   dated exemption is the likeliest explanation for an obvious gap.
7. **A brief is a hypothesis, not an instruction.** Three briefs written today were wrong; the worker
   who moved nothing while the scope was wrong was right every time.
8. **Read the clock.** `0.07s`, `0.10s`, `0` collected — a duration far too small for the work
   claimed is the cheapest tell there is, and it is the one that caught shape 8 twice.
9. **A file that has never run is not a file that works.** When something executes for the first
   time, expect real findings and budget for them. `ead5137f` turned up five defects the moment its
   ten tests could run, two of them wrong since the day the file was added in 2025.

## What a close is worth

`beffcddd` closed with **no product defect found** — five assertions that had never been reported on
could finally fail, and none of them found a bug. That is a real result, stated plainly.
`9d5fd628` closed **6 of 9 green, 3 honestly red** on a 410 tombstone: *a red that names a dead
endpoint is worth more than a green that hides one.*

`ead5137f` closed a file that had **never executed** — 10 errors, 0 tests run — at 8 passed with 3
loud skips, or 11 passed with credentials. Five defects found, none of them in product code, and
every green earned by 15 one-at-a-time mutations that all went red. *A green is worth what it cost
to break.*
