## Enforcement — the row's chase IS the ramp (there is no automated gate)
`fail_under` is applied MANUALLY via CLI — there is no automated merge gate. So each step date is set
as the row's `next_chase_ts`: on chase, re-measure, raise `fail_under` to the step, assign the
coverage work, set the next chase. Without this the ramp is a number nobody re-runs.

## Design calls (Tiffany, the ramp owner's judgment)
1. **cosa keeps its own high floor, separate from the global number.** A single global 96 floor lets
   cosa's 99.4% silently regress while the global stays green — cosa retains its dedicated gate so
   the widened frame's ramp cannot mask a cosa backslide.
2. **lupin_app's 27.2% is not a test-writing gap — it is a measurement-scope gap.** Its runtime is
   exercised by :8000 integration/e2e, which this baseline does not include. Step 1 resolves scope
   (measure it under the tier that exercises it, or account for it) rather than demanding redundant
   unit tests.
3. **lib stays IN the frame — no omit-to-dodge.** These are 524 lines of standalone client
   entrypoints, plausibly omittable like `__main__.py` glue — but omitting 524 lines the moment we
   were told to "measure the truth" is the narrow-the-wording option Rick rejected wearing a
   disguise. Covering the clients, OR a scoped Rick-ruling to omit true entrypoints with a stated
   reason, is a ramp STEP — not a unilateral tonight edit.
