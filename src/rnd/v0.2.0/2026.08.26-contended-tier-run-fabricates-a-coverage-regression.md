# A contended tier run fabricates a coverage regression

**Row**: `e2099400` (coverage frame → 100%)
**Written**: 2026-08-26, Mr Radio 🦉 (session `08e47ef3`)
**Branch**: `wip-v0.2.0-2026.08.03-present-and-demo`

---

## The claim

**A `pytest --cov` tier run that shares the box with another test suite reports
a coverage number that is materially, silently wrong — low by five points here —
and the loss is concentrated in modules exercised through spawned subprocesses.**

It does not crash, does not warn, and does not change the pass/skip/xfail counts.
It looks exactly like a regression you just caused.

## What happened

Five full unit-tier runs on the same day, same command, same isolated
`COVERAGE_FILE`, measuring `--cov=lupin_cli`. Runs 1–4 had the box to
themselves. Run 5 overlapped a `run-cosa-tests.sh` invocation.

| run | tests passed | missing stmts | cover | alone? |
|---|---|---|---|---|
| 1 | 18,628 | 1107 | 86% | yes |
| 2 | 18,670 | 1016 | 87% | yes |
| 3 | 18,697 | 999 | 87% | yes |
| 4 | 18,744 | 967 | 87% | yes |
| **5** | **18,912** | **1320** | **82%** | **NO — cosa tier concurrent** |
| **6** | **18,957** | **853** | **89%** | yes — *clean re-run of the same tree* |

**Run 6 is the control, and it settles it.** Same tree, same command, run alone
minutes later: **853 missing, 89%** — the best number of the day, on the run
immediately after the one that reported the worst. Run 5's 1320 was not a
property of the code.

Run 5 has **168 more passing tests than run 4 and 353 more missing statements.**
Read at face value it is a five-point regression caused by the very commits that
added those tests.

## Where the loss sits

Every degraded file is a module reached through a **spawned subprocess**. Every
file that had tests added that day *improved* in the same run.

| file | run 4 | run 5 | direction |
|---|---|---|---|
| `hooks/lib/cc_notification_listener.py` | **0 missing (100%)** | 155 missing (60%) | 🔴 |
| `hooks/register_session.py` | 84 | 191 | 🔴 |
| `hooks/lib/hook_common.py` | 34 | 136 | 🔴 |
| `hooks/session_end.py` | 12 | 55 | 🔴 |
| `notifications/notification_models.py` | 33 | 4 | ✅ (tests added) |
| `hooks/lib/session_bridge.py` | 86 | 47 | ✅ (tests added) |
| `notifications/notify_user_async.py` | 20 | 10 | ✅ (tests added) |

Branch-partials also jumped, 144 → 300 — consistent with code entering a
function and not finishing it.

## The discriminating measurement

The worst-hit file, measured **alone**, nothing else on the box:

```
$ COVERAGE_FILE=<isolated> ./src/tests/run-unit-tests.sh -q \
    --cov=lupin_cli.claude_code.hooks.lib.cc_notification_listener --cov-report=term \
    -k "cc_notification_listener or cc_listener"

src/lupin_cli/claude_code/hooks/lib/cc_notification_listener.py  530  0  148  3  99%
165 passed, 18821 deselected in 17.05s
```

**0 missing.** Run 5 said 155. The file did not change between them.

And the full clean re-run (run 6) restores every one of the four:

| file | run 4 (alone) | run 5 (contended) | run 6 (alone) |
|---|---|---|---|
| `cc_notification_listener.py` | 0 | **155** | **0** |
| `hook_common.py` | 34 | **136** | **12** |
| `register_session.py` | 84 | **191** | **66** |
| `session_end.py` | 12 | **55** | **12** |

Branch-partials likewise: 144 → **300** → **96**.

⇒ **Run 5 is not a usable measurement.** The trend is runs 1–4 and 6:
**1107 → 1016 → 999 → 967 → (discard) → 853.**

## What this does NOT establish

⚠️ **The mechanism is a suspect, not a finding.** Contention is the obvious
difference between run 5 and its four predecessors, and subprocess-timed
coverage is the plausible victim — a child that is descheduled, slow to start,
or reaped before it flushes writes no coverage data, and its parent's tests
still pass because they assert on behaviour rather than on the child's exit.
**I did not prove that chain.** What is measured is the correlation and the
scoped contradiction, not the causal path.

Specifically NOT claimed:
- that CPU contention is the only condition that produces this
- that every subprocess-exercised module is affected, or affected equally
- that a *non-*subprocess module can never lose coverage this way
- that the loss is deterministic — run 5 is one sample of the contended case

**The honest floor**: a tier coverage number taken while another suite was
running cannot be compared against one taken alone, in either direction.

## Why it matters more than it looks

The failure is **directionally hostile**. It makes coverage look *worse*, so the
natural response is to go write more tests for files that are already covered —
spending the day on a hole that is not there. That is the same shape as the
41%-vs-99% incident recorded in this session's memento, which cost an hour, and
the same shape as the shared-`.coverage` defect (row `aa41fa66`) that made a
tier read **96.59% green and false**.

Those three have a common core: **coverage tooling reports a number under every
condition, including the conditions where it cannot measure.** There is no
"unmeasurable" state in a `--cov` summary line the way Krishna's ninth pin gave
the eval harness one.

## Possible connection to an open puzzle

The memento records an unresolved case: `lupin_mcp/cosa_voice_mcp.py` read
**41%** in one full-tier run and **99%** in a confirmation run plus three scoped
runs, with 1,594 → 1,137 total missing (458 − 1 = 457, exactly one file moving).
Cause recorded as *"Mechanism unknown — recorded, not diagnosed."*

That is the same shape as this: one file, one full-tier run, a large single-file
delta, contradicted by scoped runs. **This is a lead worth checking, not an
explanation** — nobody recorded whether that run shared the box, so the
hypothesis is currently untestable against it. If it recurs, record what else
was running.

## What to do

1. **Do not take a tier coverage measurement while another suite is running.**
   Check first: `pgrep -fa pytest`.
2. **Corroborate any per-file number with a scoped run before acting on it** —
   the existing rule, and this is the second incident it would have caught.
3. **When a coverage number moves the wrong way, suspect the instrument before
   the tree.** The pass count moving *up* while coverage moves *down* is a
   contradiction, not a regression.
4. Record what else was on the box beside any tier coverage figure, so the next
   anomaly is diagnosable rather than merely noted.
