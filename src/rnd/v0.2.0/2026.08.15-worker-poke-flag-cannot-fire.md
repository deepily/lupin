# The worker-poke flag is on and cannot fire

**Date**: 2026-08-15
**Found by**: Mr. Radio 🦉 (session `5b7da733`)
**Status**: verified from the running process + the source; **not filed as a row** — Rick's
board-down push tonight says add no new tasks. File it the moment that lifts.

---

## Verdict

Rick enabled `arbiter auto poke workers enabled = true` at 20:56 EDT to stop worker
sessions stalling unnoticed. **The flag genuinely took effect, and no worker can be poked
anyway.** Zero pokes have been sent in the hour since, while five sessions sat stale for
20–53 minutes.

The flag unlocks a door that workers have no path to.

---

## Evidence

### 1. The config landed — this is not a config problem

The running arbiter logged its own audience resolution at startup:

```json
{"ts_local": "2026-08-15-at-20-56-51-(EDT)", "event": "arbiter_poke_audience_config",
 "master": true, "workers": true, "managers": true, "operator": true,
 "note": "master ON — each audience answers for itself"}
```

Read from the process's own boot log, not from the ini file. The knob is on.

### 2. Zero pokes sent

Over the hour from 20:50 to 21:53, the journal carries **52 `arbiter_poke_gate` events and
0 pokes sent** — no `poke_sent`, no `poke_dispatch`, nothing. Meanwhile the fleet render
showed, simultaneously:

| persona | verdict |
|---|---|
| sam | stale 53m |
| extra 1 | stale 38m |
| Clayton | stale 26m |
| maria | stale 31m |
| arnold | stale 31m |

### 3. Why — there are two tiers and workers can reach neither

`arbiter_job.py` gates a poke through two independent predicates.

**Stuck tier** (`_stuck_gate_why_not`, :4854) — open to both roles, requires
`view["stuck"] is True`. Across the window, **30 of 30 worker evaluations returned
`not_stuck`**:

```
     24 "stuck_why_not": ["not_alive", "not_stuck"]
      5 "stuck_why_not": ["not_stuck"]
      1 "stuck_why_not": ["audience_disabled", "not_stuck"]
```

**Stale tier** (`_stale_gate_why_not`, :4887) — refuses any non-manager outright:

```python
if not isinstance( row, dict ) or row.get( "role" ) != "manager":
    why.append( "not_manager" )
```

Observed verbatim for worker Tiffany: `stale_why_not: ["not_manager"]`.

### 4. Why `stuck` is never true

`stuck` is not "has gone quiet". It is defined in `fleet_data_model.py:53` as
**"REPEATED cap_reached + work_owed"** — `_count_stuck_episodes( activity_recs ) >=
STUCK_REPEAT_THRESHOLD` (:471). It requires a session to have repeatedly hit its poke cap
while owing work.

**A worker that simply stops taking turns never becomes `stuck` by that definition.** So:

- stuck tier → needs `stuck`, which quiet workers never earn
- stale tier → manager-only by construction

⇒ **a quiet worker has no poke path at all**, whatever the worker audience flag says.

## Secondary finding — the liveness signals disagree

24 of the 30 worker evaluations also returned **`not_alive`** for sessions that
`list_spawned_sessions()` reported as `alive: true, status: live` at the same moment. The
fleet view's `alive` and the tmux-probed roster do not agree.

Related: every row in every render carried `state: unknown`, and the event half of the
`live(bridge/event)` column was `—` for all 12 sessions across the whole window. That is
consistent with the activity-record feed being empty — which would also explain why
`_count_stuck_episodes` never reaches its threshold.

**Stated as observation, not diagnosis**: I have not traced why the activity records are
empty. The `stuck`/`stale` gap above stands on its own regardless — it is structural, and
visible in the source.

## A caution about how this reads

The flag is on, so a dashboard, an ini grep, and the boot log all say worker pokes are
enabled. The only thing that says otherwise is the absence of pokes — and absence is
exactly what nobody notices. This is the shape where a fix gets marked done and the
original symptom keeps happening, with everyone believing it was addressed.

The symptom Rick was fixing — four of my seats stalling 31–46 minutes this afternoon — is
unchanged tonight.

---

## What would close it

1. Give the stale tier a worker path, or give workers their own quiet-tier threshold.
   The manager-only restriction looks deliberate for the manager-staleness advisory; a
   worker wake-nudge is a different purpose riding the same gate.
2. Separately, reconcile the fleet view's `alive` with the tmux roster, since `not_alive`
   would block the stuck tier too even after (1).
3. A test that would have caught this: assert that a worker whose freshest signal exceeds
   the stall threshold produces an empty gate vector on **some** tier. Today no test asks
   whether a quiet worker is reachable at all.
