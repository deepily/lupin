## The seven checks

### 1. Is the login token alive? — the one that silently expires

Script generation runs through Claude Code inside the container, on an OAuth token that **expires and is
refreshed by the host roughly three times a day.** It was alive on 08-03 and 08-04; that says nothing about
Thursday.

```bash
docker exec lupin-rest-dev claude -p PONG
```

Expect `PONG`. **If it fails, no podcast can be generated at all** — this is the single highest-value check
on the card, and the one nobody notices until the demo is running.

### 2. Is the server actually serving the committed code?

Auto-reload is **off**. A saved file is not a served file, and a Python change needs a bounce.

```bash
docker inspect -f 'started={{.State.StartedAt}}' lupin-rest-dev
git log -1 --format=%cd --date=iso -- src/cosa/ src/lupin_app/
```

**The container start time must be LATER than the last commit touching served code.** If it isn't, bounce:

```bash
./src/scripts/bounce-dev-server.sh
```

That script refuses if a job is in flight, warns the fleet, and waits for acknowledgement — let it.

### 3. Hard refresh the browser — `Ctrl+Shift+R` — ⏰ **WITHIN 20 MINUTES OF PRESENTING**

Not F5. A plain reload serves cached JavaScript from a tab that has been open for hours.

⏰ **The timing is now load-bearing, not hygiene.** Do this shortly before you present — **not the night
before, not first thing in the morning.** A hard refresh re-authenticates and **resets the 30-minute token
clock**; that clock is what the audio player depends on.

**Why** (Sam 🎙️, 2026-08-04, code-read): the access token lasts **30 minutes**
(`lupin-app.ini:1267`). Every authenticated call on the notifications page refreshes the token before firing
— **except the audio player.** It is a separate standalone page that reads the token straight out of
local storage (`audio-player.html:148`), fires a raw request with no refresh wrapper, and on a 401 just
prints *"Could not load audio"* with **no retry** (`:235`). It is the single authenticated call in the whole
demo that bypasses the refresh path.

Worse, the *proactive* refresh is dormant: the monitor ticks every 10 minutes and only refreshes an
**already-expired** token, so the 5-minute early-refresh threshold can never fire (ticks land at +10/+20/+30,
never inside the +25→+30 window). Refresh is therefore **reactive only**.

**The bite**: clicking Play Here right around the 30-minute mark, before the reactive tick rewrites the
token. On an active foreground tab that window is sub-second. **On a backgrounded tab — you, on your slides —
browser throttling widens it to minutes**, and a 401 there is a hard failure needing a manual reload in front
of the room.

**Occurrence is LOW and entirely self-inflicted**: it cannot happen if the token is younger than 30 minutes
when you click. One well-timed refresh removes it completely. No code change needed.

### 4. Log in as Rick's own account

Every prompt routes to whoever authenticated. A service account has no browser, so the approval prompt goes
nowhere and the job stalls waiting for an answer that cannot arrive.

⚠️ **"Keep the tab open" — with a reload right before you start.** A long-open tab is exactly what ages the
token past 30 minutes and arms the audio-player failure in step 3. Open is fine; **stale is not**.

behind them; if any monopolizing job is in flight, intake holds yours until it drains. Check the queue is
quiet and stand the fleet down for the demo window. *(Sam 🎙️, 2026-08-04.)*

## If something goes wrong on stage

| Symptom | What it is | What to do |
|---|---|---|
| *"the AI service returned an error… try again in a few minutes"* | Rate limit. Measured cooldown ~3.5 minutes | Say "it's rate-limited, give it a minute" and carry on. It fails loudly, it does not produce a broken podcast |
| Routes to the wrong agent | The utterance named a topic too early | Re-say the bare line. Or set Agent Mode → *Podcast Generator*, which bypasses routing entirely |
| A file-not-found error naming a topic word | The old defect — the topic went into the document slot | The bare line avoids it. The dropdown avoids it deterministically |
| Prompt never arrives | Wrong account, or the tab lost its connection | Check #4 |

**The deterministic escape hatch**: setting **Agent Mode → Podcast Generator** skips the router completely
and goes straight to the file-reading agent. Rick has chosen not to use it, and that is his call — but it
is there, it works, and on stage it is one click.
