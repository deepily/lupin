# Filtered test-suite run reports as a full-suite pass (row f3beb6d5, P1)

**Date**: 2026-08-15
**Owner**: Mr. Radio 🦉 · **Builder**: Rio · **Reviewer**: Krishna · **Found by**: Mr. Radio, filed by Cheech 🌿

## The defect

`io/test-suite/2026.08.15-at-16:57-EDT-e2e-results.md` reports:

```
# Test Suite Report — ALL PASSED
**Suites**: e2e
**Total**: 5 passed, 0 failed, 0 errors, 0 skipped
```

Its own embedded pytest log says:

```
collected 692 items / 687 deselected / 5 selected
====================== 5 passed, 687 deselected in 23.08s ======================
```

The run was a deliberate `-k` slice of one file. The five passes are real. What is
wrong is the **reporting**: `cost_summary` carries `total_not_executed = 0` while 687
tests were not executed, and `all_passed = true` — which is what the dashboard and the
test-suite completion watchdog read. A 5-test slice is indistinguishable from a
full-suite green until a human opens the raw pytest log. Cheech read the same report
from the outside and concluded the harness was broken; both readings are the same
defect.

## Why the obvious fix is wrong

The first proposed remedy was to route the deselect count into `not_executed`.
`_classify_outcome` (`src/cosa/agents/test_suite/job.py:394`) returns `NOT EXECUTED`
whenever nothing failed and `not_executed > 0`:

```python
if ( failed + errors ) > 0:    return "FAILED"
if not_executed > 0:           return "NOT EXECUTED"
return "PASSED"
```

Every filtered run would therefore report `NOT EXECUTED` with `all_passed = false` —
including TFE landing and confirm runs, which are filtered **by design**. The remedy
would red the exact runs it was meant to protect. Ratified against this shape instead
(Cheech agreed 2026-08-15 17:04 after checking `job.py:394` himself; the row was
amended so the wrong instruction does not outlive the conversation).

## Ratified shape

1. **Parse `deselected` from stdout.** The junit-xml carries no deselect information —
   its `tests` attribute counts only what was selected. Parse both pytest forms:
   `collected N items / M deselected / K selected` and the trailer
   `K passed, M deselected in Xs`. Add `"deselected"` to the parsed result dict,
   defaulting to `0`.
2. **`not_executed` keeps its meaning** — a tier that never ran (bug `89bfcc8f`).
   Deselection is intentional scoping, not non-execution, and must not reach
   `_classify_outcome`.
3. **`cost_summary` gains `total_deselected` and `filtered`** (bool, true when
   `total_deselected > 0`). `all_passed` keeps its meaning for what actually ran.
4. **The report header names the scope when filtered** — e.g.
   `FILTERED — 5 of 692 selected` — so no reader, dashboard, or watchdog can mistake a
   slice for a full-suite gate. The per-suite metrics table gains a `Deselected` row.
