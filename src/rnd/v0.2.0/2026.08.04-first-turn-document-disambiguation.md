## What's wrong today

You say *"make a podcast based on the KISS protocol"*, two files match, and you get a **blank question**:

> Which document should I use for the podcast? Describe it or say the filename.

The system already knows both candidates at that exact moment — it just throws them away, because the
auto-resolve step only accepts a result when it lands on **exactly one** file. The numbered list you'd want
does exist, but it only appears if your *second* answer is also ambiguous. Three turns to reach a menu the
system could have shown on turn one.

## What it becomes

The same card you already click for the routing confirm — *"I think you want PodMaker. Is that right?"* —
appears instead, listing the real candidates:

> **Which document?**
> • `2026.07.25-the-kiss-protocol-how-a-brevity-mandate-got-built.md` — deep research, Jul 25
> • `2026.08.04-kiss-protocol-brevity-token-savings-explainer.md` — deep research, Aug 4
> • Let me describe it instead
> • Cancel

You click one. One turn, no typing, and the demo shows the system **knowing** both files and asking you to
choose — which reads as intelligence rather than confusion.

## Maximum reuse — this is not a new UI

| Piece | Where it already exists | We write |
|---|---|---|
| The choice card itself | `ResponseType.MULTIPLE_CHOICE` + `response_options={"questions":[…]}` | nothing |
| The renderer | the same notification component that draws the routing confirm | nothing |
| The exact request shape | `todo_fifo_queue.py:1040-1054` (routing confirm) | copy it |
| JSON answer parsing (`{"answers": {...}}`) | `todo_fifo_queue.py:1069-1077` | copy it |
| Timeout / cancel / default handling | `_ask_for_arg` in the expediter | reuse |

**New code is one helper** — `_ask_choice_for_arg()` — sitting beside the existing `_ask_for_arg()`, same
signature plus an options list. Nothing about the card, the transport, or the UI is invented.

## The change, precisely

One file: `src/cosa/agents/runtime_argument_expeditor/expeditor.py`.

1. **New helper** `_ask_choice_for_arg( arg_name, question, options, user_email, abstract=None )` —
   `MULTIPLE_CHOICE` request built exactly like the routing confirm; returns the chosen label, `None` on
   cancel, and a sentinel when the user picks *"Let me describe it instead"*.
2. **Call it at the 2+ auto-resolve branch** (`:1158-1166`) instead of discarding `auto_matches`.
   Options = one per candidate (label = filename, description = folder + date), plus the two escapes.
3. **Replace the numbered-string prompt** at `:1208-1213` with the same helper — but **gated to the podcast
   caller**, see the correction below.
4. **Option cap** — more than **five** candidates falls through to today's open ask. This is a **UX
   judgment, not a technical limit**: Sam measured that the same card already renders eleven options for the
   routing confirm, so a bigger list is renderable. Five is where a list stops being a choice and starts
   being a wall of text; nothing breaks at six. Stated as taste, so nobody later quotes it as a constraint.
5. **Termination** — "Let me describe it instead" returns to the open ask, and if *that* answer is ambiguous
   again the path falls to the **exact-path ask**, not back to the card. Without this the loop
   card → describe → card → describe only exits on Cancel. The sentinel-to-open-ask wiring gets a real
   assertion, not a docstring claim (Sam, Q3).

**Unchanged**: no-match, `too_broad`, and `error` still ask for an exact filename.

### ⚠️ Correction — Sam's review, before a line was written

My first draft claimed the presentation generator's `source` arg was untouched because it never receives
`original_question`. **That is only half true, and the half that's false is item 3.**

The command fence at `:373` does gate the *auto-resolve pre-step* (item 2) to podcast — so that part of the
claim holds. But item 3 changes `:1207`, which lives **inside `_handle_fuzzy_file_match`**, and presentation's
`source` calls that same function at `:374`. A described answer with 2+ matches reaches `:1207` on the
presentation path too. Card-ifying it there would change presentation's UX — two days before a demo that
includes a presentation item.

**Ruling: gate item 3 as well.** The helper is opted into by the *caller*, not decided inside the function —
`_handle_fuzzy_file_match` takes a `use_choice_card` flag that only the podcast call site passes. Podcast gets
the card at both ambiguity points; presentation keeps today's exact behaviour, structurally, not by retest.

Worth naming plainly: the claim was mine, it was written in the same paragraph that congratulated itself for
being careful about scope, and it took a reviewer running the call graph to catch it. *A fence you inherited
is not a fence you checked.*

## What this also kills

`expeditor.py:1230` — today, if your spoken answer at the numbered pick matches neither a number nor a
filename, it **silently returns the first match**. An unrecognized answer looks like a confident pick of the
wrong file. With a choice card there is no free text to mis-parse on this path, so the silent fallback
becomes unreachable rather than merely unlikely.
