1. **Cache-hit denominator**: n_ok (0.459) vs n (0.277) vs n_answered (0.278); and whether the 126 `replay_error` rows (similarity=100 matched, replay failed) count as "replay branch taken" for the plan's *"hit = replay taken AND produced an answer"*.
2. **Routing-accuracy denominator**: mappable-eligible (0.836/0.718) vs all ok (0.497/0.337) vs all n; and whether expected `none` ≡ `agent router go to receptionist` and what `automatic` should map to (0/60 both passes either way).
3. **Degradation-path names**: checklist/plan say `replay_failed`, code emits `replay_error`; plan §1.5 says "all 6 present", §1.2 lists 4; zero `router_error`/`extract_error` — PASS (none seen) or UNDETERMINED (never exercised)?
4. **"Failure rate" (D10)**: ok==False/n (39.7%) vs HTTP≠200 (0.3%); harness key `n_http_error` = n − n_ok (131) is completion failures, not HTTP.
5. **Latency instrument**: `t_first_useful` (server) vs `client_span_ms` (client, what the paired gate uses) vs `t_complete`; over ok only (harness) or all answered.
6. **D1 "declared n"**: 480 (plan, 8 commands) vs 300 (this run, 5 commands).
7. **D6 `n_shared`**: v1∩v2 warm (needs v1) vs v2 cold∩warm (180).
8. **D10 "clustered"**: block width (50 vs 30 vs category) changes the block table; the corpus here is category-ordered so seq-block and category readings overlap but differ (block 0–49: 49/50 vs todo: 59/60).
9. **R-C2 pre-filter**: 23 math-expected hits replayed a calculator snapshot — mechanical rule says FAIL; whether math↔calculator is "materially different" (the same 23 utterances were routed to calculator in the cold pass too) is a labelling question.
10. **§2b "v2 ≥ v1" literal at n=60 (Q2)** — one utterance flips it.
