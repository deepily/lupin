# The TypeScript coverage gate reports 100% while `shared/` sits outside its denominator

**Date**: 2026-08-24 · **Author**: Tiberius 👑 (`cb30ffac`) · **Manager**: Mr. Radio 🦉
**Found while**: closing item 2 of row `47d45f1f` (100% lines+branches on everything the
implementer touched)
**Status**: analysis only — **no config changed**. Widening the gate is explicitly NOT proposed
here; see §5.

---

## Verdict

`run-typescript-tests.sh` enforces `--check-coverage` at 100/100/100/100 over **three** `--include`
trees. `src/lupin_app/static/js/shared/` is not one of them.

The tests for `shared/` **do** run inside the gate — the runner's test glob is
`src/tests/**/*.test.ts`, which reaches `src/tests/unit/shared/agent_select.test.ts`. So those
tests contribute **pass/fail** to the gate while the source they exercise contributes **nothing to
the coverage number**.

That is the blind-instrument shape: **the gate can report 100% with an entire directory absent from
the denominator**, and nothing in its output says so.

---

## 1. The exact configuration

`src/tests/run-typescript-tests.sh:169-171`:

```bash
    --include='src/lupin_app/static/js/multiplexer/**/*.ts' \
    --include='src/lupin_app/static/js/nav/**/*.ts' \
    --include='src/lupin_app/static/js/diagnostic/**/*.ts' \
```

and the test selection, `:179`:

```bash
         --test "src/tests/**/*.test.ts" "${PASSTHROUGH_ARGS[@]}"
```

Two globs with different reach. The **test** glob is tree-wide. The **coverage** globs name three
directories. Every source file outside those three is invisible to the threshold.

Note also that all three `--include` patterns end in `*.ts`. `shared/` holds `.js` files, so it
would remain outside the denominator **even if the directory were added with the same pattern
shape** — a detail that matters to anyone who later tries the one-line fix.

## 3. The measurement that makes it concrete

`agent-select.js` is **not** in the un-instrumentable class. It is a real ESM import in its test —
unlike `notifications.js`, which the runner's own §comment explains is loaded through
`vm.runInThisContext` and therefore reports an ad-hoc 0/0 no matter what `--include` says.

Measured directly, under Cheech's capped lane (`jstest-slice.sh`, `MemoryMax=6G`,
`MemorySwapMax=0`):

```
File             | % Stmts | % Branch | % Funcs | % Lines | Uncovered Line #s
-----------------|---------|----------|---------|---------|------------------
 agent-select.js |     100 |      100 |     100 |     100 |
```

`# tests 32  # pass 32  # fail 0`

**So the file is at 100% on all four axes.** Nothing is wrong with the implementer's coverage —
which is precisely what makes this worth writing down. The number was obtainable and good, and the
standing gate would never have produced it. A future file in `shared/` at 40% would produce the
same gate output as this one at 100%.

### Capped-lane receipt

The run was performed inside the lane, not around it:

```
Elapsed (wall clock): 0:00.81
Maximum resident set size: 159,748 KB  (~156 MB)
Exit status: 0
```

**~156 MB against a 6 GB ceiling.** No kill, no cap hit. Consistent with the named mechanism: the
hazard needs *happy-dom registered × a DOM node as an assertion operand × the assertion FAILS*, and
here all 32 assertions pass. This file registers happy-dom and makes 45 assertions — it is loaded
ammunition that simply is not firing today.

⚠️ **Forced deviation from the greenlit procedure**: `--test-isolation=none` does not exist in
node **v22.15.0** (`bad option`). Pocholo recorded this on row `32c58572`; I confirmed the flag is
rejected before running. It was dropped and nothing else changed. Per his note, default per-file
child isolation can only *mask* an accumulation, so its absence does not weaken a survival result.

## 5. Explicitly NOT proposed: widening the gate tonight

Adding `shared/` to `--include` could turn the whole tier red — `arg-interview.js` and
`task-list-query.js` have never been measured against a 100% threshold, and `arg_interview`'s test
is currently `arg_interview.quarantined.ts`, deliberately renamed out of the `*.test.ts` glob, so
its source would enter the denominator **with its test still excluded**. That is a guaranteed red
with no owner.

Mr. Radio's ruling, 2026-08-24 21:02: *do not widen the gate scope — that could turn the whole tier
red and it is not a call to make at nine at night.*

**The finding is the hole, not a patch for it.** Whoever takes the decision needs three facts, all
above: the `.ts`-only pattern shape (§1), the quarantined-test interaction (this section), and the
fact that at least one file in the directory is already at 100% and would enter green (§3).

## 6. What is proven and what is not

- ✅ `shared/` is outside the coverage denominator — read from the config, `:169-171`.
- ✅ Its tests nonetheless run in the gate — the test glob at `:179` is tree-wide.
- ✅ `agent-select.js` is at 100/100/100/100, measured, 32/32 passing, ~156 MB peak in the capped
  lane.
- ❌ **Not measured**: `arg-interview.js` and `task-list-query.js` coverage. I did not run them.
  Nothing here should be read as a claim about their state — that is exactly the mistake this
  document is about.
