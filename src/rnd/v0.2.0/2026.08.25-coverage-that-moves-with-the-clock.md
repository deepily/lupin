## Verdict

**The same 333 tests report 15% or 18% coverage of one file depending on how long the suite takes
to run.** Nothing about the tests changes — no assertion, no fixture, no code. **41 statements are

## Q3 — the structural control, and the trap that is now measured

The row warned that a daemon suppressed under test is a daemon whose behaviour is then untested.
It is worse than that, and this is measured rather than argued:

**Suppressing the daemon kills the pytest process.** A plugin that no-ops `Thread.start` for
`name == "session-id-watcher"` and nothing else takes the run from `EXIT=0, 333 passed` to
**`EXIT=1` with no traceback and no summary**, dying inside
`test_get_session_info_defaults_to_chorus_when_the_mode_cannot_be_read`. The mechanism is in the
source: `_wait_for_sender_id` (`cosa_voice_mcp.py:566`) blocks on `_session_ready` and calls
`_die_no_session_id()` on failure, which ends in **`os._exit( 1 )`** (`:564`) — a hard exit no
pytest hook can report.

⇒ **The daemon is load-bearing, not a bystander.** It is the only `threading.Thread` constructed in
the module, and it is what resolves the session id. Any proposal of the form *"don't start it under
test"* must first answer what sets `_session_ready`, or it converts a coverage defect into a
silently-truncated suite — a strictly worse failure, because `os._exit` produces no report at all.

**What a real control has to do**, stated as constraints rather than a design:
1. Start the daemon **deliberately**, in a test that owns it, so its lines are earned rather than
   accrued.
2. Keep coverage **independent of session duration** — the gate must not read differently on a
   faster box.
3. Never weaken the gate. Missing lines want real tests, or a pragma with a stated reason.

## Q3 — the structural control, proposed with its mechanism and its cost

The row asked for a proposal, not an implementation, and this stays a proposal deliberately: the
change lands in a module every seat's MCP server imports and needs a `:7999` bounce before anyone
sees it.

**The daemon does TWO separable jobs, and only one of them is load-bearing.**

| phase | what it does | load-bearing? | credits coverage? |
|---|---|---|---|
| **1 — resolve** (`:452-475`) | one-shot `wait_for_session_id`, then `_session_ready.set()` in a `finally` | **yes** — this is what `_wait_for_sender_id` blocks on, and why suppressing the thread hard-exits the suite | no — it runs once and stops |
| **2 — watch** (`:477-521`) | forever loop, `time.sleep( 2.0 )`, re-reads the bridge on mtime change | **no** — nothing blocks on it | **yes — the entire defect**; all 34 credited lines in the `commons` scope live here |

⇒ **Split them.** Phase 1 keeps running at import exactly as today, so nothing that depends on
`_session_ready` changes and the hard-exit path is never reached. Phase 2 becomes an ordinary
function — `_watch_bridge_for_changes( stop_event, poll_interval )` — started only when a predicate
says to.

**Why this satisfies the constraint the row placed on any such proposal** ("a daemon suppressed
under test is a daemon whose own behaviour is then untested"): once phase 2 takes a stop event, a
test can start it **deliberately**, drive a bridge-file change, assert the session id updated, and
set the event — precisely the shape already proven **earned** in this repo by
`CommonsArchiver.test_run_loop_swallows_exceptions_and_continues`. The coverage stops being accrued
and starts being asserted. That is the point of the split, not a side effect.

**The predicate must be an explicit flag, not environment sniffing.** Reading `PYTEST_CURRENT_TEST`
inside product code makes the product behave differently under test for a reason the product cannot
state; an INI/env flag defaulting ON, which `conftest` turns off, keeps the decision greppable.

**A second, separable change — stop a library `os._exit` being reachable in a test process.** This
is the bar the stderr fix raised rather than cleared. `_die_no_session_id` keeps its notification
and logging, then either `os._exit( 1 )` **when the process is the MCP server** or raises a named
exception otherwise, with server-ness set explicitly at the entry point rather than guessed. A test
then gets a normal failure in the run's own summary.

**Cost, stated so it can be refused**: two edits to a module every seat imports; a `:7999` bounce
before the effect is visible; one new flag; and phase 2's behaviour must be re-covered by real
tests rather than by the daemon that currently covers it — which will show up, correctly, as a
coverage **drop** on first landing. That drop is the true figure appearing, not a regression.
