## THE ONE VERDICT RACHEL ASKED FOR

**UPDATED after the A/B (§ below): §5.4's "prompt-listing ⇒ reachable" is SUPPORTED — with training held constant.** Adding one prompt line for `test fix expediter resume` (commit 9bdbe127), with NO retrain and NO server bounce, flipped its emission from **0/5** (main tree, not prompt-listed → routed to `swe team`) to **5/5** (worktree, prompt-listed → the correct command). Only the prompt differed; the model and training were identical (production adapter merged-2026-02-20, and TFE-resume was in the training set in BOTH arms). So a checked-in prompt line alone makes the command emittable — the reachability half of §5.4 holds, and the no-retrain part holds.

**The one residual — cannot be isolated with the current tree:** both A/B arms had the command TRAINED, so this shows prompt-listing is sufficient *given* training. It does NOT isolate prompt-listing *without* training (§5.4's strongest form), which needs a command that is prompt-listed but was never trained — no such command exists in the tree.

**Earlier "NOT TESTED" is superseded** (it was correct when only the live :7999 prompt was available, which lists neither TFE command). The worktree + `LUPIN_ROOT` pointed at it gave the prompt-listed arm with no merge and no bounce.

**Separate observation (not the claim):** §5.4's *supporting evidence* — a command in **neither** prompt nor training emitted 6/10 ("the router invents commands") — did **not** reproduce. My BFE arm (neither) emitted the target **0/5** (routed to `claude code`). Contradicted on this adapter; that is the evidence, not the claim.

## The A/B — prompt line ON vs OFF, training constant (run 2, 14s, :7999)

Ran in an isolated worktree at **9bdbe127** (`wt-phase2-drift-guard`, adds `<command>agent router go to test fix expediter resume</command>` to the prompt) with **`LUPIN_ROOT` exported to the worktree** so the router reads the worktree's template, not the dirty main tree (per Rachel — otherwise a false red). Same production adapter (PID1-sourced), same gen params. Control datetime = 3/3 in the worktree (harness valid).

| command / phrase | prompt-listed? | trained? | n | raw emitted | match |
|---|:--:|:--:|:--:|---|:--:|
| `test fix expediter resume` — "resume the test fix expediter job from job xyz9" | **NO** (main tree) | yes | 5 | `swe team ×5` | **0/5** |
| `test fix expediter resume` — same phrase | **YES** (9bdbe127 worktree) | yes | 5 | `test fix expediter resume ×5` | **5/5** |
| `test fix expediter` (plain) — "fix the failing tests…" | NO (still unlisted) | yes | 5 | `test fix expediter resume ×5` | 0/5 (routed to the now-listed sibling) |

**Reading:** the ONLY variable that changed between rows 1 and 2 is the prompt line (model + training identical). Emission flipped 0/5 → 5/5. That is the causal demonstration: prompt-listing drives emission, no retrain needed. The router routes an unlisted phrase to the nearest *listed* neighbor (`swe team`, then once TFE-resume is listed, to it) — so listing the right command captures the phrase.
