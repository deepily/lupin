### 3.1 🔴 Is the difference real? — the test, the interval, and the floor

**This section exists because it was missing.** Reviewer finding, 2026-08-16, accepted by me without qualification: the plan built the discordant 2×2 above and then never tested it. A grep of all 548 lines for `mcnemar`, `confidence interval`, `wilson`, `significan`, `discordant`, `power`, `minimum detectable` returned **zero matches**. Every other fix on the review list could land and the run could still report noise as a result. Naming the off-diagonal cells "the finding" and stopping is the setup for a significance test with the test left out.

Write `b` for **Phi-4 clean / Flash Lite fabricated** and `c` for **Phi-4 fabricated / Flash Lite clean**. The concordant cells carry no information about *which* model is better and must not enter the test.

**1. The test — McNemar's EXACT test on the discordant pairs.** Under the null "the two models fabricate at the same rate", each discordant pair is a coin flip, so `b ~ Binomial( b + c, 0.5 )`. Report the two-sided exact binomial p-value. **Exact, not the chi-square approximation** — the approximation is unreliable at exactly the small `b + c` this run is likely to produce, which is the regime where the answer matters most.

**2. The interval — Wilson score interval on `b / (b + c)`.** Report it alongside the point estimate, always, including when the p-value clears. Wilson rather than the normal-approximation ("Wald") interval, which misbehaves near 0 and 1 and can produce bounds outside `[0, 1]` — again exactly where a small discordant count lands. An interval spanning 0.5 means the direction is not established, whatever the point estimate looks like.

**3. The floor — PRE-STATED, and the reason it must be.** Declare a minimum `b + c` **before the run**, in this document, and if the run comes in under it the result is **INCONCLUSIVE and is not reported as a comparison**. A floor chosen after seeing the numbers is not a floor; it is a rationalisation with a threshold attached.

**The arithmetic lower bound is 6, and it is not a matter of taste.** With a two-sided exact binomial at α = 0.05, the most extreme possible split at `b + c = 6` gives `2 × 0.5⁶ = 0.031` — just significant. At `b + c = 5` the most extreme split gives `2 × 0.5⁵ = 0.063`, which **cannot** reach significance no matter how lopsided the result. ⇒ **A floor below 6 is arithmetically incapable of producing a significant finding, so a run reporting fewer than 6 discordant pairs is reporting nothing.**

⚠️ **6 is the bound on POSSIBILITY, not a recommendation.** At 6 pairs only a perfect 6–0 split clears, and the Wilson interval is nearly the whole unit interval — technically significant, practically uninformative. A usable floor is higher; **the crew must pre-state the actual number here before the first arm runs.** I am deliberately not inventing one: the right value depends on the effect size worth acting on, which is Rick's call, not a number I can derive. What is NOT negotiable is that a number gets written down first.

**4. If the floor is not met.** Report `b`, `c`, and the frozen snapshot's row count, state INCONCLUSIVE, and say what sample would have been needed. Do **not** report the point estimate as a headline with a caveat underneath — that is how an underpowered run becomes a cited number.

#### 3.1.1 The test — exact call signature, scipy only

```python
from scipy.stats import binomtest
p = binomtest( min( b, c ), b + c, 0.5, alternative="two-sided" ).pvalue
```

**scipy ONLY — do not reach for statsmodels.** Verified on this box: `scipy 1.17.1` imports, `statsmodels` is **not installed** (`ModuleNotFoundError`). Declared at **`src/cosa/requirements.txt:210`** as `scipy==1.15.2`. ⚠️ Note the pin (1.15.2) and the installed build (1.17.1) differ — not blocking, `binomtest` predates both, but the run should record which it used.

**`binomtest` has no chi-square or continuity-correction option**, so the approximation §3.1 forbids cannot slip in through a default. That is the real reason to prefer it over a library whose defaults you must remember to override.

**Verified against the floor arithmetic independently** — the call reproduces the bound rather than being asserted to:

| b | c | n | p |
|---|---|---|---|
| 6 | 0 | 6 | **0.03125** ✅ = 2 × 0.5⁶ |
| 0 | 6 | 6 | **0.03125** — `min()` makes it symmetric, as McNemar requires |
| 5 | 0 | 5 | **0.06250** ✅ cannot reach 0.05 |
| 4 | 2 | 6 | 0.68750 |

#### 3.1.2 The interval — Wilson, closed form, scipy only

```python
from scipy.stats import norm
import math

def wilson( k, n, alpha=0.05 ):
    z      = norm.ppf( 1 - alpha / 2 )
    p      = k / n
    d      = 1 + z * z / n
    center = ( p + z * z / ( 2 * n ) ) / d
    half   = ( z * math.sqrt( p * ( 1 - p ) / n + z * z / ( 4 * n * n ) ) ) / d
    return ( center - half, center + half )     # k = b, n = b + c
```

🔴 **NEVER `statsmodels.proportion_confint` without naming the method.** Its **default is `method='normal'` — the Wald interval this section forbids.** If statsmodels is ever added, the call must read `proportion_confint( b, b + c, alpha=0.05, method="wilson" )`, and whoever adds it must state in the code that the default is Wald. A silent default is how a forbidden method ships under an approved name.

**Why it matters, measured** — at the floor itself the two disagree completely:

| k / n | Wilson | Wald |
|---|---|---|
| 6 / 6 | **(0.6097, 1.0000)** | (1.0000, 1.0000) — **degenerate**: zero width, claims certainty from six observations |
| 20 / 25 | (0.6087, 0.9114) | — |

⇒ **The must-fail control writes itself**: flip the interval to Wald and the lower bound moves `0.6097 → 1.0`. Pocholo verified that test goes red on exactly that value. A degenerate interval at the smallest reportable sample is the precise failure Wilson exists to prevent, so testing it there is testing it where it counts.
