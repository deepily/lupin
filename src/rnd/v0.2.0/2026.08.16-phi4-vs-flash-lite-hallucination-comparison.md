**Why this task and not a benchmark**: it already has a **hallucination detector in production**, and that detector has been firing.

Counts below are stamped with the moment they were taken and **will not match a fresh read** — that is expected, not an error. ### 1.2 🔴 FREEZE THE REPLAY SET FIRST — the corpus is a LIVE append-only log

**Rachel's finding, and it invalidates §3's whole claim if ignored.** `dm_traffic.jsonl` is appended to by **every DM the fleet sends, continuously** — including the DMs this cascade is generating right now. Between the two arms' runs it grows.

⇒ **Naming a fixed body count is false the moment it is written down.** Read the corpus at the start of arm A and again at the start of arm B and you get **different sets** — so the comparison is **unpaired**, which is precisely the property §3 exists to guarantee. Every per-body cell in the disagreement matrix would be comparing two different populations.

**And the drift is not small today — it is measured, and it has a rate.** Fired rows went **995 → 1,044 → 1,138** across one afternoon; the last two readings are ~20 minutes apart, so roughly **5 new rewrites per minute** while a cascade runs.

⇒ **A two-arm replay taking an hour would see its input set grow by about a quarter underneath it.** Sam independently read 1,131 between my last two figures — the same file at a third moment, not a discrepancy. Confirming it *wasn't* a second corpus is why the inode was checked (§1.1).

**Required, before either arm runs:**

1. **Snapshot the corpus to a pinned file** — copy, with the byte count and a checksum recorded.
2. **Both arms read the pinned file**, never `dm_traffic.jsonl` directly.
3. **Record the snapshot's provenance** in the report: source path, timestamp, row count, checksum. A paired claim whose input cannot be reproduced is not a paired claim.
4. **Assert it**: the harness should refuse to run against the live path. A convention that says "use the snapshot" gets forgotten under time pressure — exactly the failure mode §3 of the sibling design is about.

⇒ This is the same class as the in-memory audit counter zeroing on a bounce: **a measurement is only as durable as the thing it reads.**

## 4. What this CANNOT settle — stated up front

1. **The guard is not ground truth.** `fabrication_blocked` counts what our detector caught. A model that hallucinates in ways the guard does not recognise scores *better* while being *worse*. ⇒ **Hand-label a sample of each arm's delivered output.** Without it we are comparing detectability, not honesty.
2. **Cost is asymmetric, and the corpus already knows it.** Local vLLM is sunk GPU; Flash Lite is paid per call. A prior arm on this work published −30.4% and came out **+7.0% all-in** once paid inference was counted (`2026.08.04-dm-arm-all-in-cost-and-breakeven.md`). Report all-in or do not report cost.
3. **Prompt fairness.** The tutor prompt was written against Phi-4 and iterated on Phi-4. A fair comparison says so. An *unfair* one is still informative — it answers "would swapping help today", which is the operational question.
4. **Temperature 0.0 is not determinism** on a hosted API. Repeat a subsample to size run-to-run variance before attributing any difference to the model.
