## Context

Rick's directive, 2026-08-14: the current CJ Flow ("COSA Jobs Flow") request pipeline is buggy and
misses his most important use case. He wants a **parallel v2** — non-destructive, standing beside v1 —
with the least control logic that makes three branches work:

1. **Speak → replay a cached solution if one exists.** First in the chain, before anything else.
2. **Otherwise the LoRA intent router** ascertains intent and strips out the user's arguments →
   run a pre-existing agent. (Creating *new* agents is deferred to phase 2/3.)
3. **Else → the receptionist.**

Purpose is **evaluation**: build it small, test it rigorously, then decide whether the bells and
whistles are worth adding. Success is measured on **latency to first useful response** and
**cache-hit rate**.

### What the survey found

All four stages already exist. The defect is that they are **tangled**, not missing:

| Stage | Where it lives today |
|---|---|
| Cache lookup | `src/cosa/rest/todo_fifo_queue.py:508` → **Postgres + pgvector** (see §6) |
| LoRA router | `todo_fifo_queue.py:945`; model `deepily/ministral_8b_2410_ft_lora` on `:3000` |
| Argument extraction | `src/cosa/agents/runtime_argument_expeditor/expeditor.py:190` |
| Receptionist as the else | `todo_fifo_queue.py:745` (`receptionist` or `none`) |

They sit inside one ~700-line `push_job` with **three command→agent mechanisms that disagree**
(`todo_fifo_queue.py:697-777`, `agent_registry.py:22`, `agentic_job_factory.py:103`), the **cache
checked twice** (`todo_fifo_queue.py:508` and `running_fifo_queue.py:277`), salutations stripped then
re-attached (`:416` then `:625`), and a whole-queue block to read a yes/no (`:451-486`).

**So v2 is a thin orchestrator over parts that already work** — which is what makes "minimal control
logic" a real target rather than a wish.

### Rick's rulings

| Fork | Ruling |
|---|---|
| Execution | **Inline, no queues** for phase 1 — prove the control logic. Phase 2 extends to todo/running/done/dead "with less bugginess and fewer ad-hoc bolt-ons." |
| Missing arguments | **Two-stage extraction, not a fork**: router → if args incomplete, hand the **raw utterance** to the expeditor's phi4 pass → whatever is still missing goes to the **interactive** expeditor. The receptionist is the else for **unascertainable intent only**. |
| Cache write-back | **Shared snapshot store, tagged v2.** |
| Endpoint | Its own module, its own endpoint under `/api/v2/…`, **reusing the existing TTS**. |
| New agents | **Deferred** to phase 2/3. |
| Proving the arg chain | **Weather is the argument case** — start simple. |
| Storage | 🔴 **LanceDB is OUT — "do not use in any way shape or form."** Postgres + embeddings, full stop. v2 talks to the Postgres repository **directly** and never imports `lancedb_solution_manager`. |
| North star | **One argument-extraction machine for every agent**, old and new: each runnable agent implements a queryable interface exposing its required and optional arguments, so the expeditor can interrogate any agent and **one dispatch path serves all of them**. Phase 2/3 — *"just not the first step."* |

## The design

### 2. The executor seam — inline now, queues later without a rewrite

```python
@dataclass( frozen=True )
class Work:
    kind         : Literal[ "replay", "agent", "receptionist" ]
    job          : Any          # SolutionSnapshot | AgentBase subclass
    user_id      : str
    user_email   : str
    session_id   : str
    snapshotable : bool

@dataclass
class Outcome:
    status     : Literal[ "done", "parked", "failed" ]
    answer     : Optional[ str ]
    answer_raw : Optional[ str ]
    job_id     : Optional[ str ]
    error      : Optional[ str ]

class Executor( Protocol ):
    def submit( self, work: Work, trace: StageTrace ) -> Outcome: ...
```

- `InlineExecutor.submit()` — ~25 lines. Replay: `run_code()` / `run_formatter()`
  (`src/cosa/memory/solution_snapshot.py:847`, `:915`). Agents: `do_all()`
  (`src/cosa/agents/agent_base.py:498`). Returns `status="done"`.
- `QueuedExecutor.submit()` — phase 2. Pushes to the queue, returns `status="parked"` with `job_id`;
  the answer arrives over the existing websocket path.

**Why this makes phase 2 a swap**: the HTTP contract already carries `job_id` and `status`. Changing
executors flips `status` from `done` to `parked` and leaves every line of `flow.py` untouched.
Selected by INI `v2 executor`, default `inline`.

⚠️ **Phase-2 trap, flagged now**: `RunningFifoQueue` does its own second cache lookup at
`running_fifo_queue.py:277`. A `QueuedExecutor` that hands work to the existing running queue would
have its cache verdict silently re-decided downstream, making the cache-hit metric fiction. Phase 2
must target a v2-owned running path or an explicitly cache-suppressed one.

Concurrency: `asyncio.to_thread( flow.run, ... )` in the handler, mirroring `queues.py:238`.

### 3. One registry, replacing three

`src/cosa/rest/v2/registry.py` replaces the if/elif chain (`todo_fifo_queue.py:697-777`),
`MODE_TO_AGENT` (`:58`), and the second if/elif in `agentic_job_factory.py:103`.

```python
@dataclass( frozen=True )
class AgentSpec:
    command       : str
    factory       : Callable[ ..., Any ]
    aliases       : tuple[ str, ... ] = ()
    snapshotable  : bool = True
    _required_args: Optional[ tuple[ str, ... ] ] = None

    @property
    def required_args( self ) -> tuple[ str, ... ]:
        # Resolution order is the MIGRATION PATH, not a fallback chain (see §3a):
        #   1. the agent declares its own args  ← the destination
        #   2. AGENTIC_AGENTS table             ← today, for the ten agentic commands
        #   3. this spec's literal tuple        ← today, for the conversational agents
        if hasattr( self.factory, "declared_args" ):
            return self.factory.declared_args().required
        entry = AGENTIC_AGENTS.get( self.command )
        if entry: return tuple( entry[ "required_user_args" ] )
        return self._required_args or ()
```

#### 3a. Shaped for the north star, from the first line

Rick's phase-2/3 requirement — *every agent, old and new, uses the same argument-extraction machinery,
queryable for what it requires and what is optional, with one dispatch path* — changes how phase 1
should be **shaped**, even though none of it gets built now.

The concrete consequence is the resolution order above. `required_args` asks the **agent** first, and
only falls back to the tables. In phase 1 no agent answers, so every lookup lands on a table exactly as
it does today. In phase 2, agents adopt a small declaration protocol:

```python
@dataclass( frozen=True )
class DeclaredArgs:
    required: tuple[ str, ... ]
    optional: tuple[ str, ... ]

class DeclaresArgs( Protocol ):
    @classmethod
    def declared_args( cls ) -> DeclaredArgs: ...
```

**Migration is then per-agent, not a cutover** — an agent that implements `declared_args()` is served
by the new path the moment it does; every other agent keeps working off the table. When the last one
migrates, `AGENTIC_AGENTS`'s arg half and `AgentSpec._required_args` both become dead and get deleted.
The expeditor's `AGENTIC_AGENTS` gate (`expeditor.py:222-226`) — the very thing that blocks weather
today — disappears at the same time, because there is no longer a list to be off.

The cost of shaping it this way in phase 1 is **four lines and a comment**. The cost of not doing it is
that phase 2 reopens the registry, the expeditor gate, and the dispatch path together.

**Phase 1 wires six**: math, calculator, datetime, todo, calendar, weather. All six share the
identical 11-kwarg constructor signature (verified across `todo_fifo_queue.py:697-777`), so one
factory call site serves all of them. Weather is `snapshotable=False` (v1 excludes it,
`running_fifo_queue.py:1566`).

`receptionist` and `none` are deliberately **not** registry entries — they are the else.
Everything else goes in an explicit `DEFERRED_COMMANDS` set.

⚠️ **Pin to the non-CRUD agents.** V1 routes todo/calendar to CRUD agents when
`crud for dataframes agents enabled` is true (`todo_fifo_queue.py:987`), and CRUD agents are never
snapshotted (`running_fifo_queue.py:1563`). Inheriting that flag makes those two commands report 0%
cache-hit forever, which will read as a v2 bug.

### 4. The two-stage argument chain

**Verified firsthand**: the phi4 raw-utterance extraction pass **already exists**. `expedite()`
steps 3–6 (`expeditor.py:246-300`) build a prompt with `voice_command = original_question` — the raw
utterance — run it on `kaitchup/phi_4_14b` (`lupin-app.ini:325` → `:164`, `:3001@Phi-4-AutoRound-GPTQ-4bit`),
and merge what it finds with the router's regex-parsed args.

**What is genuinely new**: a seam. `expedite()` runs extraction straight into the interactive block
at `:327` with no way to say "extract only, tell me what's still missing." The fix is a pure
extract-method split, public signature unchanged:

```python
def extract( self, command, raw_args, original_question ) -> Optional[ Extraction ]:
    # verbatim lift of expedite() lines 219-326

def collect( self, extraction, user_email, session_id, user_id, job_id=None, bearer_token=None ):
    # verbatim lift of expedite() lines 328-457

def expedite( self, ... ):        # unchanged — delegates to both
```

**The v2 chain**:

1. Router → `(command, raw_args)`.
2. `resolve(command)` is `None` → **receptionist** (`route_reason="unknown_command"`). The only
   arg-independent else.
3. `required_args` empty → straight to the executor.
4. Otherwise `expeditor.extract(...)` — the phi4 pass over the raw utterance.
5. `missing` empty → executor.
6. `missing` non-empty → **interactive stage**, parked. **Never the receptionist.**

⚠️ `expedite()` returns `None` for any command outside `AGENTIC_AGENTS` (`expeditor.py:222-226`).
See the Open Fork.

### 5. Blocking interaction inside an inline executor — the sharp edge

`collect()` blocks on a human for **minutes** (30s timeouts, 30→60→120s backoff). An inline HTTP
handler cannot hold that: it pins a worker, blows past client timeouts, and records human think-time
as flow latency — destroying the primary metric.

**Ruling: the endpoint never waits for a human. It returns the question.**

Four terminal outcomes, not three:

| `path` | meaning |
|---|---|
| `replay` | cached solution replayed; answer in the response |
| `agent` | agent ran; answer in the response |
| `receptionist` | intent unascertainable; answer in the response |
| `needs_input` | args incomplete; **the first question** is in the response |

`needs_input` parks the `Extraction` in an in-process `PendingRequests` dict, returns 200 immediately,
and runs `collect()` on a background thread. When the human answers, that thread builds the job, runs
the executor, and delivers through the same TTS path. **Nothing in the expeditor changes** — it
already runs on a worker thread today, and its human round trip goes over `/api/notify`, not over the
open request.

Two consequences, both good: `latency_first_useful_ms` never contains human think-time (it is recorded
separately as `human_wait_ms`), and park-and-resume is exactly what a queued executor does natively —
so the seam is honored.

**Eval harness flag**: `interactive=false` makes `needs_input` terminal — never ask, never park.
This is the harness default, so a corpus run never blocks on a human.

The repository's ANN entry point takes an **embedding**, not a question string, which is what makes

| Tier | How | Cost |
|---|---|---|
| **1 — exact** | plain SQL equality on `question`, then `question_normalized` | one indexed lookup, **no embedding** |

⚠️ **Check before assuming it's expensive**: `embedding_cache_repository.py` and
`question_embedding_repository.py` exist in the same package. If repeated questions hit a cached
embedding, tier 2 is far cheaper than it looks. **The crew measures this; the plan does not assume it.**

#### Write-back — shared table, tagged

An isolated table starts empty, reports ~0% for weeks, and measures a different population than the one
v1 has been filling. It answers the wrong question.

**Where the tag lives, with no schema change**: `runtime_stats` is a plain `Text` column
(`vector_store_models.py:299`) holding a JSON string, so extra keys round-trip intact.

```python
snap.runtime_stats = { **snap.runtime_stats,
                       "flow_version": "v2", "created_by": "v2.ask", "created_at": iso_ts }
```

⚠️ Note `{**...}` — **not** in-place mutation. `SolutionSnapshot.__init__` has `runtime_stats` as a
**mutable default argument** (`solution_snapshot.py:179`), shared across every default-constructed
snapshot in the process; in-place mutation tags all of them. Same hazard on `synonymous_questions`,
`non_synonymous_questions`, `code`.

**How a query filters on it**: `runtime_stats` is Text, not `jsonb`, so Postgres cannot index into it
without a cast. Two options, both fine because the table is small — a Python-side filter after
`SELECT id_hash, runtime_stats`, or (authoritative) the v2 trace JSONL, which records `id_hash` on
every write-back. The trace is the enumeration source for "delete everything v2 created" — an id list,
no scan.

**Kill switch**: `v2 snapshot writeback enabled = false` stops write-back entirely. No second-table
escape hatch is proposed: a separate table would need its own migration and its own HNSW index for
what the tag already buys.

**Gist moves off the hot path.** V1 computes gist + embeddings before the cache lookup
(`todo_fifo_queue.py:419-436`) — pure added latency on every request. V2 computes the gist lazily,
on the write-back path only, via `GistNormalizer.get_normalized_gist` (`gist_normalizer.py:81`).

### 6a. The 90-99 band, and choosing the floor from data instead of guessing

V1 has three tiers: `>= 100` auto-accept, `>= 90` **ask the user "is that the same as…?"**, `< 90` route
(`todo_fifo_queue.py:518-597`, verified firsthand). That middle tier blocks the queue on a human with
30→60→120s backoff.

Note that on the Postgres path the floor is applied **server-side** — `get_snapshots_by_question`
passes `threshold_pct` into the query (`solution_snapshot_repository.py:117-121`), so anything below it
never comes back. To build the threshold table below, **v2 queries at a low floor (say 70) and applies
its own decision floor in Python**, keeping the scores it rejected.

**V2 phase 1 drops the ask.** But that leaves a real question the metric is highly sensitive to: what
happens between the floor and a perfect match?

**Ruling: below a perfect match, route.** Replaying an unconfirmed 92% match risks answering a
different question than the one asked, and the conservative direction is the cheap one — worst case is
doing work instead of replaying.

**But record the score on every single request anyway.** `best_score` goes into the trace line whether
or not the branch was taken. Then the eval computes **cache-hit rate as a function of threshold**,
post-hoc, from one run:

```
floor   hit-rate   would-be-wrong (spot-checked)
100.0     18%        —
 98.0     24%        …
 95.0     31%        …
 90.0     39%        …
```

That turns "what should the floor be?" from an argument into a table, and it costs one extra field.
Without it, picking a floor means re-running the corpus once per candidate value.

### 7. Instrumentation

`StageTrace` marks with `time.perf_counter_ns()`, started **inside the handler after auth**:
`t_recv`, `t_cache_exact`, `t_embed`, `t_cache_ann`, `t_router`, `t_extract`, `t_replay_code`,
`t_replay_format`, `t_agent`, `t_first_useful`, `t_tts_dispatch`, `t_writeback`.

The cache is **three** marks, not one — exact-tier lookup, embedding, ANN probe — because the whole
question of whether Postgres retrieval is fast enough turns on which of the three dominates, and a
single `t_cache_lookup` would hide it.

- **"First useful response"** = the instant `answer_conversational` exists (or, for `needs_input`,
  the instant the question text exists) — immediately before TTS dispatch.
- **"Cache hit"** = the replay branch was taken **and** replay produced an answer. `cache_candidate`
  (a snapshot came back above floor) is tracked separately, so a replay that throws cannot inflate
  the numerator.

**Two sinks**: `QueryLogTable.log_query` (`query_log_table.py:205`) with `input_type="v2"` (v1 uses
`"api"`, so one predicate separates them, zero schema change), and
`io/v2-flow/trace-YYYY-MM-DD.jsonl` — the authoritative metric source.

⚠️ **Do not use `get_cache_hit_stats` (`query_log_table.py:350`)** for this metric.
`cache_hit_verbatim`/`cache_hit_normalized` mean the *embedding* cache, not the *solution* cache. It
will read 0% for v2 and mean nothing.

**Query surface**: `GET /api/v2/ask/stats?window=24h`, ~30 lines aggregating the JSONL — `n`,
`cache_hit_rate`, `cache_candidate_rate`, `replay_failure_rate`, `p50`/`p95_first_useful_ms`,
`by_path`, `router_error_rate`, `extract_error_rate`.

### 8. The endpoint contract

```
POST /api/v2/ask        Depends( get_current_user )      # same as /api/push, queues.py:165
```

**Request**: `{ question, websocket_id, speak: true, interactive: true }`.
`speak=false` runs the whole flow, skips TTS dispatch, keeps timings — that is what makes the control
logic testable at the endpoint.

**Response 200** carries: `path`, `status`, `route_reason`, `answer`, `answer_raw`, `command`,
`args_known`, `args_missing`, `pending_id`, `job_id`, `snapshot_id`, `similarity`, `wrote_snapshot`,
`timings_ms{}`, `trace_id`, `spoke`.

**Errors**: 400 for empty/oversized question (mirror `queues.py:210-231`). **Never 500 for an agent
or replay failure** — it degrades to the receptionist with `route_reason="agent_error"`, because
falling to the receptionist *is* the specified else and a 500 aborts an eval run.

**TTS reuse**: the exact `notify_user_async( AsyncNotificationRequest( ... ) )` call
`FifoQueue._notify` makes (`fifo_queue.py:663-679`). It POSTs to `/api/notify` with retries, so it is
**not** free — stamp `t_tts_dispatch` after it returns and keep it outside `first_useful`.

### 10. Phasing

**Phase 1 delivers**: the four branches · six read-only agents, **weather carrying `location` as its
required argument so the extraction stage and the `needs_input` gate run for real** · `InlineExecutor`
behind the `Executor` protocol · the expeditor extract/collect split, with **both halves taking a typed
`ArgSpec` as a required parameter** · the registry's agent-first resolution order (§3a) · shared-store
write-back tagged
`flow_version="v2"` · TTS reuse · trace + stats endpoint · the five test tiers · the two-pass eval
harness and its report.

**Deliberately deferred**: creating new agents · agentic/long-running commands · the queued executor ·
mode short-circuit · blocking `ConfirmationDialogue` · salutation handling · hot-path gist/embedding
precompute · job cards and websocket UI · search-and-summarize fallback · CRUD agents · the 90-99
similarity confirmation band.

**Phase 2** (decided by the numbers): `QueuedExecutor` + todo/running/done/dead, cache-suppressed
downstream · agentic commands wired · job cards · **the `DeclaresArgs` protocol lands and agents begin
migrating onto it one at a time** (§3a).
**Phase 3**: creating new agents · the last agent migrates, `AGENTIC_AGENTS`'s arg half and the
expeditor's command gate are deleted, and **one dispatch path serves every agent**.

### 11. Risks and sharp edges

1. **Similarity can exceed 100%** — bug 78f21b1b: non-unit-vector query embeddings produced 1024% for
   a true cosine of 0.517, landing in the perfect-match branch and making routing unreachable in 0 ms
   *while reading as success* (`todo_fifo_queue.py:518-543`, verified firsthand, reasoning in-comment).
   **Keep the `[0,100]` guard in v2 anyway**, with an honest note on why the risk is now lower rather
   than gone: the Postgres path asks `dot_topk` for `metric="cosine"`
   (`solution_snapshot_repository.py:120`), which normalizes, so the specific 1024% mechanism should
   not recur. The guard costs two lines and the failure mode it catches is silent — that asymmetry is
   the whole argument for keeping it.
2. **Replay is not free and can throw.** `run_code` raises on empty code for non-Calculator agents
   (`solution_snapshot.py:892-894`), and `run_formatter` calls an LLM for most agents (`:983-990`) —
   so cache-hit latency is dominated by a formatter LLM call, not by the lookup. Instrument
   `t_replay_code` and `t_replay_format` separately; **caching `answer_conversational` and skipping
   the formatter on replay is probably the single largest latency win available**, and the eval should
   surface it as a phase-2 candidate.
3. **Copy before replay** — `run_code` writes `self.answer`, `run_formatter` writes
   `self.answer_conversational`. Use `for_current_user()` (`solution_snapshot.py:821`, shallow and

4. **The Postgres floor is applied in the query, not after it.** `threshold_pct` goes into

5. **Get the session and repository the way the rest of the app does.** v2 constructs

   **not** through `dependencies/config.py:41 get_snapshot_manager()`, which builds a manager with no
   config and imports a different module than `main.py` uses. Session lifetime inside a background
   resume thread (the `needs_input` path, §5) is a real question the crew must answer explicitly: a
   session opened in the request must not be reused after the response returns.
6. **A dead model server masquerades as success.** Cold `:3000` → router returns `"unknown"` →
   everything falls to the receptionist, so cache-hit looks fine while routing is 0%. Same for `:3001`
   and extraction. Record `router_error` and `extract_error` as **distinct** trace outcomes.
   ⚠️ `lupin-app.ini:173-174` records that `:3001` serves one model at a time — if anyone re-points it,

7. **`get_cli_help` shells out** via subprocess, cached per-process (`agent_registry.py:320`) — first

8. **`_get_routing_command` is trapped on `TodoFifoQueue`** (`:945`), whose construction drags in

## Weather is the argument case — how the chain gets proven

**The problem it solves**: as originally scoped the two-stage chain would be built and never executed.
All six phase-1 agents take zero arguments, and `expedite()` returns `None` for any command outside
`AGENTIC_AGENTS` (`expeditor.py:222-226`). All ten agentic commands are heavy (deep research, podcast,
SWE team, Claude Code); the only one with no required args is the test suite, which defeats the purpose.

**Weather declares `location` as its one required argument in the v2 registry.** One utterance pair
exercises the entire chain on every eval pass:

| utterance | what it proves |
|---|---|
| *"what's the weather in Tokyo"* | router gets the intent → phi4 pulls `location` from the raw utterance → **extraction succeeded, so no gate fires** and the agent runs |
| *"what's the weather"* | router gets the intent → phi4 finds nothing → **`needs_input`**, and the question comes back **in the response** rather than blocking |

It costs seconds per run, not minutes, and it uses an agent that already exists.

🔴 **What weather proves, stated exactly — cascade ruling R-B4.** It proves **the gate, not the
consumption.** The weather agent has no `location` parameter; it web-searches the raw question
(`weather_agent.py:84`), so v2 **composes** the question from the extracted location and the agent then
**re-parses the location back out of it.** The extracted value is therefore validated as a
`needs_input` gate and **never consumed as an argument**.

⇒ **Phase-1 definition of done: "proves extract-and-park, with zero v1 behavior change."** *"The agent
consumes the argument"* is a **phase-2** claim, gated on `declared_args()`. This does not contradict
Rick — he deferred the north star himself. It contradicts this document's own earlier prose, which
claimed more than the design delivers.

**The generalization required**: `extract()` must serve a command that is not in `AGENTIC_AGENTS`. It
takes a typed `ArgSpec` as a **required** parameter — **no fallback to the table** — and the
`AGENTIC_AGENTS` gate relocates into the `expedite()` shim, which builds the spec from the entry so v1
callers stay byte-identical. Silent fallback is the anti-pattern Lupin's fail-loudly rule names.

⚠️ **The spec must carry every field, not just `required_args`.** `extract()` reads six off the entry
(`arg_mapping`, `fallback_defaults`, `fallback_questions`, `required_user_args`, `special_handlers`,
`system_provided`) and `collect()` reads two more — seven distinct. **A spec carrying only
`required_args` fails concretely: "what's the weather" never parks and runs location-less — the exact
case this demonstration exists to prove, silently succeeding.** And `extract()` must source
`user_visible` from the spec's `fallback_questions` when present, or it shells out for a CLI weather
does not have.

This is the **same seam the north star needs** (§3a), paid early on the cheapest agent.

⚠️ **Honest note**: today the weather agent reads the location out of the raw utterance itself.
Declaring `location` as a required argument is a real design change, not a description of current
behavior — v1's weather path is untouched, and only v2 treats it as an argument.

## Cascade revisions — ratified 2026-08-14 13:43, folded in

Cheech's cast closed all four sections across three stages; ten rulings. The three that changed the
document's own prose are folded above (definition of done, unit A's key form and guard buckets, unit
B's "not a verbatim lift"). The rest are recorded here, each changing what a builder builds. Full
record: `2026.08.14-cascade-cj-flow-v2-revision-handoff.md`.

**The replay signal is a tier-1 exact match, not a float comparison.** If replay fires only at exactly
`100.0`, a warm-pass self-match landing at `99.9999` routes instead — **understating the very
cache-hit rate this experiment exists to measure.** The fix removes the bug class rather than adding an
epsilon: a warm-pass repeat is a tier-1 exact hit via `question_normalized` string equality, which is
deterministic and lossless. **Reserve the ANN float score for the *similar* tier only.**

**The stats surface owes two more rates: `agent_error_rate` and `replay_failure_rate`.** Degrading an
agent failure to the receptionist is right — a failure should never 500 or abort an eval run — but with
no rate for it, **an agent failing on every single request produces a run that looks like healthy
receptionist traffic**, and the eval reports success. This is §11 risk 6's own lesson ("a dead model
server masquerades as success") applied to the router and not to the agent.

**Wire the embedding cache.** `get_cached_embedding(normalized)` is an exact btree lookup returning the
stored 768-float vector with **no model call**. The warm pass replays the identical corpus, so an exact
normalized repeat gets its embedding free — §6 treats embedding as always-computed. ⚠️ **Assert, don't
assume, normalization parity**: if v2 normalizes differently from whatever populated that cache, the
match misses and "free" evaporates. (Provenance: code-read, not run.)

**The would-be-wrong column gets an automated oracle.** The corpus already carries the expected command
per line as its JSON key, so a replay is would-be-wrong when the matched snapshot's `routing_command`
differs from it — free, and from the same source as routing accuracy. ⚠️ **Keep the caveat verbatim**:
command-match is a **lower bound** (same command, different city still scores as right), so it
under-counts; a semantic oracle is phase 2. *A column nobody can fill gets filled by hand or left
blank, and either way stops being evidence.*

**Two mutable-default guards, and they are different bugs.** Prose is not a control — §6 named the
hazard and then gave it no acceptance criterion, no risk entry and no test.

1. **Structural, by property rather than by list**: introspect `SolutionSnapshot.__init__`'s
   `__defaults__` / `__kwdefaults__` and assert none is a `dict`/`list`/`set`/`OrderedDict`. That fails
   the moment anyone adds a mutable default — catching all four known instances **and the fifth nobody
   has written yet**. *An enumerated field list is the same enforcement gap wearing a test's clothes.*
2. **Copy before mutating**, at the `from_entry` boundary — one choke point rather than every caller
   remembering — with an assertion that two `extract()` calls do not grow the entry's dict.

Unit C2 gets the acceptance criterion *"write-back rebinds the tagged field with `{**...}`, never
mutates in place"*, or the fix is a comment the crew can skip. **Both guards are already built and
merged.**

**One factory field cannot serve all six conversational agents** — the v1 constructor block forks
calendar and todo to CRUD agents (never snapshotted, so those two would report 0% cache-hit forever and
it *will* read as a v2 bug) and passes `MathAgent` a different first argument. The registry pins the
**non-CRUD** classes explicitly; it must not copy that block.

**Confirm the parquet sink is outside the banned path, or drop it.** §7's first sink writes to a
pyarrow table in the `memory/` layer, co-located with the LanceDB-era store. `input_type="v2"`
round-trips fine, but the plan already calls the JSONL "the authoritative metric source" — **so
dropping it costs zero metric.**
