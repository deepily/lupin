## 1. Problem (recap)

`monopolize=True` is an **unenforced no-op placeholder**. `queue_consumer.py:125-129`:

```python
# Monopolize placeholder (no-op in serial mode)
# When Hybrid Fast Lane adds ThreadPoolExecutor, this will wait for
# running_queue to drain before processing the monopolize job.
if getattr( job, 'monopolize', False ) and todo_queue.debug:
    print( f"[CONSUMER] Monopolize job detected: {job.id_hash}" )
```

The agentic `ThreadPoolExecutor` landed in v0.1.7, but this drain/hold hook was
never wired. Consequence: a monopolize-mode sweep does NOT get exclusive use of the
shared `lupin_db_test` — other fleet agentic jobs ride the same pool and write
concurrently (the `caf58f71` contamination class). Option (c) makes that fail LOUD
at sweep start (detection); option (a) is the durable PREVENTION.

## 2. Design — two gates in the consumer

Both gates live in `consumer_worker` (`queue_consumer.py`), reusing the `caf58f71`
classifier `RunningFifoQueue.get_non_test_inflight_agentic_jobs()` as the oracle.
This is TODO-wiring at the existing placeholder, not new architecture.

### Gate A — drain-before-dispatch (the placeholder's original promise)

When a `monopolize` job is popped, BEFORE `running_queue.push(job)` /
`_process_job(job)` (currently line ~150), block until the agentic pool has drained
of **non-test inflight jobs** — i.e. `get_non_test_inflight_agentic_jobs(exclude_id_hash=job.id_hash) == []`.
Poll on a short interval; tick `_tick_heartbeat()` each iteration so a healthy wait
never trips `consumer_stalled`.

### Gate B — hold-foreign-intake-during-monopolize (the missing half)

While a monopolize agentic job is inflight, the consumer must not dispatch ANOTHER
agentic job into the pool. Mechanism:

- `RunningFifoQueue` gains a `_monopolize_active` flag (id_hash of the active
  monopolize job, or None), set under lock when a monopolize job is dispatched and
  cleared in `_on_agentic_complete` (the same callback that pops `_agentic_futures`).
- The consumer, having popped a NON-monopolize **agentic** job while `_monopolize_active`
  is set, **defers** it (re-enqueues / leaves it in the todo queue for the next tick)
  rather than dispatching. Fast-lane `AgentBase` / `SolutionSnapshot` jobs are NOT
  agentic-pool jobs — see D3.

Gate A closes the "leftover inflight foreign writer at sweep start" path (what the
evidence shows); Gate B closes the "new foreign job dispatched mid-sweep" path that
option (c) cannot see.

## 3. Decisions (Tiberius rulings folded)

**D1 — Gate-A timeout / anti-deadlock. RATIFIED.** Bound the drain-wait via
`cj flow monopolize drain timeout seconds` (default 300s, `[Lupin: Baseline]` +
splainer). On timeout → **fail loud**: dead-letter the sweep with a reason that
NAMES the offenders (classifier output verbatim). Never silent-proceed — a
contaminated gate must never run. Option (c)'s preflight is the belt.

**D2 — Scope of the hold. OVERRULED → WIDEN to ALL intake.** My "hold agentic
only" was too narrow: fast-lane `AgentBase`/`SolutionSnapshot` jobs also write
persistent state (`solution_snapshots`, `notifications`) into `lupin_db_test` and
can contaminate row-count/state expectations. Monopoly means monopoly — while
`_monopolize_active` is set, Gate B defers **EVERYTHING**. (Gate A's drain oracle
stays agentic-only — correct: fast-lane runs ON the consumer thread, so by
construction none is mid-flight when the consumer sits at Gate A.)

**D3 — Deferral mechanism. RATIFIED (i) peek-and-skip.** The consumer does not
pop while the hold is set → todo queue stays FIFO-intact → the deferred head
dispatches first when the hold clears. Riders: the skip path ticks
`_tick_heartbeat()` + bounded `condition.wait` (no busy-loop); FIFO-first ordering
asserted in a test.

**D4 — Trigger. RATIFIED generic `job.monopolize`.** Not `job_type == "test_suite"`.
Rider: back-to-back monopolize jobs serialize (the 2nd defers at Gate B until the
1st clears), not deadlock — asserted in a test.

## 5. Kill-switch (Tiberius rider) — `cj flow monopolize enabled`

The pre-existing `cj flow monopolize enabled` INI flag was documented but never
read (a dead key whose splainer already promised this exact behavior). Option (a)
fulfils it as the master kill-switch — a deploy-free escape hatch for the
deadlock/starvation risk (simplest-reversible-mechanism doctrine).

Tiberius's two riders, both built:
1. **Read at GATE-time, not cached at __init__** — `RunningFifoQueue._is_monopolize_enabled()`
   reads config fresh each call, so an INI-only flip takes effect via hot config
   reload without a bounce. (The drain *timeout* stays cached at __init__ — a tuning
   duration, not a safety gate; matches the stall-threshold pattern.)
2. **Gates all three surfaces atomically** — the `_submit_agentic_job` SET, Gate A,
   AND Gate B all consult `_is_monopolize_enabled()`. No half-state (hold set while
   gates disabled, or vice versa) is possible by construction. Tested end-to-end
   (`flag=false → _monopolize_active stays None through a full submit`).

## 6. Added hazard (Tiberius) — hold lifecycle on ABNORMAL exit

`_on_agentic_complete` covers done/exception/stalled/failed. But a monopolize job
dead-lettered by the **ghost-job sweeper** (`_ghost_job_sweep`) exits by a DIFFERENT
path — if the hold weren't cleared there too, a wedged sweep would freeze ALL intake
permanently. `_release_monopolize_hold(id_hash)` (clears iff owner-match; idempotent)
is called from EVERY terminal pop site: `_on_agentic_complete` and both
`_ghost_job_sweep` arcs (dead-letter + already-transitioned cleanup). RED test:
ghost-swept monopolize job → flag cleared → intake resumes.
