## The answer in one block

Six lines, **no Lupin code at all**, kill a 4 GB cgroup every time:

```js
import { GlobalRegistrator } from "@happy-dom/global-registrator";
GlobalRegistrator.register();
const assert = (await import("node:assert/strict")).default;
const el = document.createElement("div");
document.body.appendChild(el);
assert.equal(el, null);          // ← dies HERE, constructing the AssertionError message
```

**The allocator is `node:assert`'s failure-message construction**, which deep-inspects the
actual value to build its diff. When that value is a happy-dom element, the walk reaches the
element's `ownerDocument` → `defaultView` → the whole `Window` graph, and the serialization
does not terminate within any memory the box can offer.

⇒ It is not the TypeScript runner, not `tsx`, not the worktree, and not any Lupin source file.
It is **(happy-dom registered) × (a DOM node as an assertion operand) × (the assertion FAILS)**.
Remove any one of the three and it is harmless.

## How this was reached, including the thing that nearly went in the report wrong

The row's procedure pointed at the banked `arg_interview.test.ts` from the condemned worktree.
It reproduced immediately — SIGKILL at 4.98 s — and it kept reproducing after both confounds
Cheech raised were eliminated (byte-identical file at its real `../../../lupin_app/...` path:
5.04 s).

**Then the banked source turned out to carry a left-over mutation.** The banked
`arg-interview.js` (blob `295259ce`) differs from the repo copy (blob `e391891e`, un-mutated by
commit `e5b0077a`) by exactly one line:

```js
-    return result.path === "needs_input";                                              // banked, MUTATED
+    return result.path === "needs_input" && Boolean( result.pending_id ) && Boolean( result.answer );  // repo
```

Reverting **that single line** turns a 6 GB SIGKILL into **19/19 passing in 1.44 s**. The
mutation makes `renderArgQuestion` return an element where the test expects `null`, so
`assert.equal( el, null )` fails — and the failing assertion is the allocator.

⚠️ **A single sample lied to me on the way here, in the direction of a false negative.** In a
one-shot per-test sweep, the culprit test reported a clean `pass 0 / fail 1`. Re-run five
times under a fixed cap it is **5/5 SIGKILL**. Every count in this document is from **at least
three runs**; the determinism rule from row `5a68c92c` is not a bridge-guard rule, it applies to
any check whose failure mode is nondeterministic.

## What this does and does not settle

- ✅ **The condemned worktree is CLEARED.** It reproduces in a clean `/tmp` lab with freshly
  installed `node_modules`. The blast radius does not collapse to one tree, and quarantining
  that worktree would have fixed nothing.
- ✅ **The 08-23 pair is explained**: a fix cycle runs tests that FAIL, which is exactly the
  condition. That is why it bit during remediation rather than on a green run.
- 🔴 **08-22: I ARGUED THIS WAS A DIFFERENT MECHANISM AND I WAS WRONG. Measured, it matches.**
  My objection was that 08-22 held 229 GB with `inactive_anon` 217 GB — allocated once and
  never re-touched — whereas this is continuous per-tick growth "touched the whole way." The
  second half was an assumption I never measured. Sampling `memory.stat` inside the repro's own
  cgroup, every megabyte of it is **inactive**:

  ```
  inactive_anon=1897 MB  active_anon=0 MB
  inactive_anon=3749 MB  active_anon=0 MB
  inactive_anon=5524 MB  active_anon=0 MB   → SIGKILL
  ```

  ~100% inactive against 08-22's ~95%. That is the same signature, not a different one, and it
  is what you would expect from a serializer writing strings it immediately abandons: allocated,
  never re-read. **Rachel's amendment on this row is right and my push-back does not survive its
  own test.** The remaining differences — 6 GB vs 229 GB, `CONSTRAINT_MEMCG` vs global — are
  explained by the cap being present in one case and absent in the other, not by mechanism.

  What still stands from the objection is only the narrow wording point: **"external memory" is
  a location, not a mechanism**, so the two should be joined on the measured signature, which
  now exists, rather than on the shared word, which was never enough.
- ❌ **This does not re-open the TypeScript tier.** The ban stands at all four doors. What
  changes is that the hazard is now specific enough to be engineered against rather than only
  avoided — that decision is Rick's, not this document's.
