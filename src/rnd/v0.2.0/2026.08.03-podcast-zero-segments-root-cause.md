# P0 4317efd1 — Podcast script generates ZERO segments: root cause

**Investigator**: Clayton 😎 (session ee92a5fd) · **Date**: 2026-08-03 · **Manager**: Mr. Radio 🦉
**Status**: root cause PROVEN. No fix applied (per brief: "DO NOT fix before you report the cause").

## Verdict

Not a generation failure — a **silent parser failure**. The model produced a full ~5,533-token script; `parse_script_response` failed to recover any JSON from it and returned its **empty fallback**, which the pipeline treated as a successful (if empty) result and sent to the human approval gate.

## The four questions, answered with receipts

### 1. Where do segments come from, and what makes the list empty?

Path: `orchestrator._generate_script_async` → `api_client.call_for_script(...)` → `parse_script_response( response.content )` → builds `PodcastScript(segments=[...])`.

- The source **was** read (log: "Loaded research doc: 1419 chars") and analysis **succeeded** (real content: Cordelia Fenwick, Marrow Point, 62%).
- Script generation **returned output** — 1768 in / 5533 OUT tokens, $0.1846 — so the model did NOT return nothing.
- `parse_script_response` (`prompts/script_generation.py:484`) calls `lenient_json_loads( response.content )`. When that returns `None`, the function returns the fallback at **lines 517-522** with `segments: []`. `_generate_script_async` then builds a `PodcastScript` from `result.get("segments", [])` → **0 segments**, and does **not** raise (its loud `except` only fires on a thrown exception, and no exception was thrown).

**Why `lenient_json_loads` returned `None`** (`script_generation.py:403-442`): its recovery is (1) strip a leading/trailing ` ``` ` fence — but the trailing-fence strip only fires `if content.endswith("```")`; (2) `json.loads`; (3) `extract_json_object`, which takes the **last** balanced `{...}` by scanning back from the final `}`. When the model appends explanatory prose **after** its closing fence (e.g. `### Explanation: each segment is a {speaker, role, text} object`), the content no longer ends with a fence, `json.loads` fails, and `extract_json_object` grabs a brace group **inside the prose** — not the script — which is not valid JSON → `None` → empty fallback.

### 2. "Untitled Podcast" and 0.0 minutes are defaults — which layer applied them?

The parser's own fallback dict, verbatim (`script_generation.py:517-522`):
```python
return {
    "title"                      : "Untitled Podcast",
    "segments"                   : [],
    "key_topics"                 : [],
    "estimated_duration_minutes" : 0,
}
```
Nothing upstream failed — analysis produced real content. The defaults applied purely because the **parse** step silently fell through to this fallback.

### 3. Why is there no guard?

There is one — in the **wrong phase**. `parse_script_response`'s docstring says the "no segments → real failure" floor is enforced by "orchestrator Phase 5 guards" (audio). But the empty script passes the **Phase 4 review/approval gate** (human sign-off) **before** Phase 5 runs. So the floor sits *downstream* of the human prompt — the empty script reaches Rick first. **The check belongs before the review gate** (reject a 0-segment script the moment the script phase returns).

### 4. Is this the same failure Rick saw last night? How long has it happened?

Yes — recurring. Disk scan of `io/podcasts/**` for tiny/zero-segment scripts:
- **2026-03-03 / 03-07** — three 140-byte `research-topic` scripts (`ricardo.felipe.ruiz`).
- **2026-07-31** — four 143-byte `research-topic` scripts (v1/v2/v3, `interactive.job.tester`).
- **2026-08-03** — the 136-byte P0 artifact.

So empty scripts have been produced intermittently since **at least 2026-03-03**. The parse fallback pre-dates the 2026-06-18 bounded-CC migration in spirit (defaults are old); bounded-CC models that add trailing prose make the trigger more frequent.

## Deterministic repro (dev :7999, `parse_script_response`)

| Input shape | Result |
|---|---|
| Clean fenced JSON (real Verdigris script) | title correct, **2 segments** |
| + trailing `### Explanation` prose containing a brace | **"Untitled Podcast", 0 segments** (exact artifact) |
| + trailing prose with NO brace | title correct, **2 segments** |

`extract_json_object` returned the literal fragment `'{speaker, role, text}'` from the prose. Trigger = **any brace in the model's trailing prose after the closing fence.**

## Forensic gap

The orchestrator's script-parse path logs nothing on the `None` branch (only `api_client.py:355` logs `Raw content:` on a *different* parse). So the actual malformed response was never captured. A one-off dump on the `None` branch + one re-run would catch the exact bytes if wanted (mechanism is already proven without them).

## Fix options (proposed, not applied)

- **A — Harden the parser (root fix).** In `lenient_json_loads`: strip a closing fence wherever it appears (not only at string end), and/or make `extract_json_object` prefer the **first/outermost** balanced object from the first `{`, not the last `}`. Add unit cases for "JSON + trailing prose with braces." Small, targeted, covered by the repro above.
- **B — Move the no-segments floor before the review gate (safety net).** Reject a 0-segment `PodcastScript` at the end of the script phase, before any human approval prompt. This kills the human-facing symptom regardless of parser robustness — arguably the more important fix given the brief ("empty generation treated as success").
- **C — Prompt tightening (secondary).** Instruct the model to emit only the JSON, no trailing prose. Reduces trigger frequency; not a guarantee for bounded-CC.

**Recommendation:** A + B together (root fix + the gate that should have existed). C as a cheap add-on. Owner/sequencing is Mr. Radio's call; the fix itself is a candidate for the SWE crew.
