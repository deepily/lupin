## 2. Doctrine reconciliation — is a backfill "migration code"?

`feedback_no_migration_code` forbids **in-app** backward-compat migration code and says *drop+recreate for local
stores*. This utility is **NOT** in-app: it is a one-time **offline** export/import run at cutover (design §5/§8-P4
explicitly carve it out — "NOT in-app migration code"). It honors drop+recreate by loading into freshly-created
(alembic-built, empty) Postgres tables and offering **truncate-then-load** re-run semantics (idempotent: same final
state every run) rather than upsert/merge reconciliation.

## 3. Architecture — pure core + pragma'd IO boundary (persona_key_backfill pattern)

```
src/cosa/rest/db/vector_store_backfill.py
├─ BACKFILL_SPECS                      # registry: (source_table, target_model, transform, label)  — pure data
├─ _to_vec( value )                    # numpy/list/None/NaN → list[float] | None                  — pure
├─ _clean_scalar( value )             # NaN/NaT/numpy-scalar → python scalar | None                — pure
├─ _to_datetime( value )              # ms-timestamp / datetime64 / datetime / None → datetime|None — pure
├─ _row_to_io_kwargs( row )           # input_and_output_tbl dict → InputAndOutput kwargs           — pure
├─ _row_to_synonym_kwargs( row )      # canonical_synonyms dict   → CanonicalSynonym kwargs          — pure
├─ _row_to_snapshot_kwargs( row )     # solution_snapshots dict   → SolutionSnapshot kwargs          — pure
├─ backfill_table( session, model, source_rows, transform, *, apply=False,
│                  truncate=False, batch_size=1000 )                                                — DB via injected session
│     → { "source_count", "existing_before", "purged", "inserted" }
│     · existing_before = count(target)
│     · apply & truncate            → DELETE all target rows first (purged = existing_before)
│     · apply & existing_before>0 & not truncate → raise ValueError (fail-loud; refuse silent double-load)
│     · stream source_rows, transform each, session.add, flush every batch_size (caller commits)
│     · apply=False (dry-run)       → count source only, ZERO writes, inserted=0
└─ IO boundary (# pragma: no cover — LanceDB / DB-session / CLI):
   ├─ _iter_lancedb_rows( store_uri, table_name, batch_size )   # lancedb.connect → to_lance().to_batches → dicts
   ├─ _run( apply, truncate, only )                             # opens store + get_db(), wires source→backfill_table, prints report
   └─ __main__                                                   # argv: --apply / --truncate / --only=<label>
```

**Read side** (boundary): `lancedb.connect( get_project_root() + "/src/conf/long-term-memory/lupin.lancedb" )`,
`db.open_table( name ).to_lance().to_batches( batch_size )` → each pyarrow `RecordBatch.to_pylist()` yields row dicts.
Memory-safe streaming (never materializes all 190k rows). Vector columns arrive as numpy arrays → `_to_vec`.

**Write side**: direct model construction via the injected SQLAlchemy `session` (the Lane B models own the schema;
`session.add` + periodic `flush`), mirroring `persona_key_backfill.backfill_persona_keys( session, apply )`.

**Metric/vector fidelity**: vectors are copied **verbatim** (no re-embedding, no normalization) — the keystone stays
unnormalized (P0 norm ≈22); the dot (`<#>`) equivalence the Lane B repos serve depends on byte-faithful vectors.

## 4. Idempotency & safety

- **Dry-run by default** (`apply=False`): reports source/target counts, writes nothing. Safe to run any time.
- **Fail-loud on non-empty target** without `--truncate`: refuses to double-load (no silent duplicate rows on the
  synthetic-PK `input_and_output`).
- **`--truncate`**: DELETE-all-then-load → re-runnable to a deterministic final state (drop+recreate doctrine).
- **`--only=<label>`**: run a single table (e.g. `--only=canonical_synonyms`) for the small synonym heal without
  re-loading 190k rows.
- **Transaction**: the boundary commits once per `_run`; a mid-load failure rolls the whole run back (all-or-nothing,
  same as `migrate-sqlite-to-postgres.py`).
