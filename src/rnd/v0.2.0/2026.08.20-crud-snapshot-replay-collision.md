## The headline

**A plainly non-CRUD question replays a CRUD-classed snapshot on a tier-1 EXACT hit at 100.0.** No
threshold is involved, so route-first cannot prevent it, and the guard has to key on the **retrieved**
snapshot rather than the incoming question. Everything below is either that finding, its provenance,
or the plan-level findings gathered on the way to it.

## 1. PROVEN — the collision, on the real lookup path

Run through `TwoTierQuestionSearch.lookup` against `lupin_db_test` — the real path, not a hand-rolled cosine:

| non-CRUD utterance | tier | replay? | score | matched snapshot's agent |
|---|---|---|---|---|
| "What is the best way to paint a room evenly?" | `exact_verbatim` | **True** | 100.0 | **TodoListAgent** |
| "What is the purpose of version control in software development?" | `exact_verbatim` | **True** | 100.0 | **TodoListAgent** |
| "Show me yoga poses for relaxation." | `exact_verbatim` | **True** | 100.0 | **TodoListAgent** |

Tier 1 fires before the ANN tier, so **there is no floor to tune**. Eight of the 27 TodoListAgent rows
are general-knowledge questions — also party games, turning off notifications, a vegetable garden,
art therapy, sourdough bread.

⇒ **Route-first helps on neither side.** The question routes non-CRUD; the cache still hands back a
CRUD-classed snapshot. `running_fifo_queue`'s `isinstance` check on `CrudForDataFramesAgent` protects
the **execution** path, not the **replay** path.

⇒ **The durable design finding**: the cache replays a snapshot without checking its class.

### Reproduce it — Postgres only, no model server needed (tier 1 never embeds)

```python
# PYTHONPATH=src, db_scope bound to lupin_db_test
search = TwoTierQuestionSearch( db_scope=<scope for lupin_db_test>, debug=False )
r = search.lookup( "What is the purpose of version control in software development?" )
# r.tier == "exact_verbatim"; r.is_replay_hit is True; r.best_score == 100.0
# → the matched row carries agent_class_name = "TodoListAgent"
```

### Provenance — the rows are a fixture, the mechanism is production

All 27 `TodoListAgent` rows were created **2026-08-20, 21:44:45 → 22:13:58 EDT**, at a steady
~60–70 s cadence, `user_id` **empty on every row** — a machine walking a scripted list, almost
certainly a `:8000` suite running during this review. **So 44.4% is fixture data, not production evidence.**

But `routing_command = "agent router go to todo"` on all 27, *including* the general-knowledge ones.
That is **mode routing working as designed** (`todo_fifo_queue.py:705ff`), **not** a mislabelling: a
user in todo mode asking *"what is the purpose of version control?"* **is** correctly sent to the todo
agent, and the snapshot is honestly labelled.

⇒ **Worse, not better.** Mode is a shipped feature, so production manufactures rows like these by
design. Later, a different user — or the same one out of todo mode — asks that question verbatim and
tier 1 replays a CRUD-classed snapshot at 100.0.

**Two extras from the same read**: `user_id` is empty on all 27, so nothing binds a snapshot to who
asked — a cross-user replay has no guard to trip. And many answers are raw XML documents or empty
strings, so replaying one is wrong twice over.

## 4. Live bug on main — stage 2 replays an answer the user DECLINED

`f014dd40`'s message says stage 2's accept *"is safe only because the upstream ask happens."* It is not.

When Rick says **no** — or the ask times out and the "no" default applies — stage 1 sets
`needs_llm_routing`, the job becomes an `AgentBase`, and stage 2 re-runs its **own** lookup on the same
question (`running_fifo_queue.py:302`, `:946`), finds the same 90–99% match, and replays it anyway
(`:313`, `:953`). **The declined answer comes back.**

Accurate framing: *stage 2 accepts on an assumption `push_job` cannot honour — it may have asked and
been told no.*

⚠️ **Control-flow reading, not an executed repro.** Stage 1 searches `parsed_question` **with** the
gist; stage 2 searches `last_question_asked` (salutation-plus-question) — different strings, so the two
scores can differ. Likely, not certain. Worth one runtime log line before filing as confirmed.

## 5. §Sequence — a mid-way break, and how to split step 6

red-on-revert ⇒ a real window in which the live voice path has **no cache at all**. *(The author has

revert that restores the old path outright. As one commit, the revert that fixes a misbehaving ask

behaviour changes broke what Rick hears.

## 9. The near-match ask branch is not specified precisely enough to build

- **Range** — no numbers, and two floors compete: `DEFAULT_QUERY_FLOOR` (the ANN query floor) vs
  `similarity threshold confirmation = 90.0` (the decision floor). Name which gates the ask, and say
  whether 100.0 still auto-accepts silently as today (`todo_fifo_queue.py:610`).
- **Synchrony** — today synchronous: `notify_user_sync`, 30 s timeout, 3 attempts, backoff 2.0, default
  "no" (`:640-655`). `AskFlow`'s own ask is the asynchronous `_needs_input` → `PendingRequests` →
  `resume`, which the plan withdrew earlier. Pick one; it changes what `push_job`'s caller returns.
- **Each answer** — yes → replay with `last_question_asked` rebound to the **new** wording (stage 1 does
  this at `:621`, easy to drop); no → route; **no answer** → today the safe default is "no". None stated.
- **Free win, unstated** — a confirmed "yes" could register a canonical synonym, making the next repeat
  a tier-1 hit. Today it is discarded.
