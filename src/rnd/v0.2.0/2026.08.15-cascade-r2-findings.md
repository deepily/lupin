## Findings

### [MEDIUM] §5.3 / §6 under-scope "the training corpus" — the folder holds a second namespace the doc never names

`src/conf/training/` is not three files; it is five, in two namespaces. The doc counts and reasons about the 19 agent-router keys only. The two `vox-cmd-*` files hold **23** browser/search keys (`go to current tab`, `search kagi new tab`, `search perplexity using clipboard new tab`, …) that match nothing in the registry, and they are loaded as training data alongside the agent-router files.

**Consequence**: a §6 reconcile that globs `training/*.json` (the natural reading of "the training corpus") false-orphans **22** of those 23 keys — a new cry-wolf failure class on top of the nine intentional-absence cases §3 already accounts for. This is the exact "guard that cries wolf gets deleted" failure §8 warns against.

**Fix**: scope the reconcile explicitly to `agent-router-*.json`, stated in both the doc and the test. Do not glob the directory.

**Answer to Rachel's follow-up #1 — do any vox-cmd keys overlap the router's space?**
One does: **`none`**. It appears in `vox-cmd-simple-commands.json:12`, in `agent-router-simple-commands.json:6`, and in the registry (`RECEPTIONIST_OR_NONE`, `registry.py:116`). So **22 of the 23 vox-cmd keys are a genuinely separate command space; `none` is shared** across both namespaces and the registry. A directory-glob reconcile would accept `none` and orphan the other 22 — which makes the scoping fix above necessary, not cosmetic.

### [LOW / wording] §5.3 "all ten corpora … values are objects" is true for one file only

The object-valued shape (`template_file` + `placeholders` + `conditional_args`) is `agent-router-agentic-commands.json:2-150` — **one** corpus, 10 entries. The other four files carry **bare path strings** (`agent-router-compound:2-5`, `agent-router-simple:2-6`, both vox-cmd files). So "ten corpora" reads as ten files but means ten entries in one file.

María's §9#2 worry is **confirmed**: compound/simple do **not** share the agentic object shape. But her stated rationale — "values are editorial content no registry can derive (which template, which placeholders, which triggers)" — holds only for the agentic file. For compound/simple the value is a single bare template path; no placeholders, no triggers. The claim's **conclusion** (key-only reconcile) is sound; its **generalization** across files is loose. Key-only reconcile is unaffected either way: `json.load(f).keys()` extracts regardless of value shape.

### [MEDIUM] §5.2 + §7 phase-4 gate — command ORDER is editorial and not registry-derivable

The 16 `<command>` lines (`agent-router-template-completion.txt:11-26`) are **derivable** as a set from the registry (16 = 6+7+1+2). The file's static `[INST]`/Task/Requirements skeleton is editorial but it is a template, not a per-command list — spliced, not generated — so that part is fine.

The problem is **order**. The template sequence is:

```
datetime, weather, calendar, receptionist,        # = agent-router-compound order
todo, math,                                        # from simple
deep research, podcast generator, research to podcast,   # from agentic
calculator,                                        # back to simple
claude code, swe team, presentation generator, research to presentation,  # agentic
automatic, none                                    # simple
```

**Answer to Rachel's follow-up #2 — name the ordering rule, or say none exists.**
**No mechanical rule over the registry reproduces this sequence.** It is not alphabetical, not registry bucket/declaration order (`V2_AGENTS` declares math, calculator, datetime, todo, calendar, weather at `registry.py:85-91` — a different order), and not any single file's order or a concatenation of the three files: it **interleaves** simple and agentic entries (todo/math → three agentic → calculator → four agentic → automatic/none). It reads as hand-curated by semantic grouping.

Therefore §7 phase-4's gate — *"generated file byte-compared to the hand-maintained one before switching"* — **cannot pass honestly** as written. Two ways out:
- **Preferred**: make order registry-owned data — declare an explicit ordered command list in the registry and generate from it. Order stops being editorial; byte-compare becomes honest.
- **Otherwise**: replace the byte-compare gate with a **set-equality** check plus a deliberate, separately-owned ordering. Byte-equality is the wrong gate for a hand-curated sequence.

Either is a small change, but the gate as phrased is a trap: it will go red on ordering and invite someone to "fix" it by relaxing the assertion — the §7 phase-3 failure mode.

## Bottom line

Both of María's reviewed design claims are correct. Key-only reconcile is the right call and avoids the orphan trap by construction. Ship with three refinements: (1) scope the reconcile to `agent-router-*.json` so the 22 non-shared vox-cmd keys don't false-fail; (2) tighten the §5.3 wording (object values = one file); (3) make command order registry-owned data, or swap the phase-4 byte-compare for a set-equality gate.
