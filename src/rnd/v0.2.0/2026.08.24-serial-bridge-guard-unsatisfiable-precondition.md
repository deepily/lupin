## 1. The precondition cannot be satisfied — and asking peers to pause will not create it

`CLAUDE.md` said to run the guard *"on a quiescent box"*; the row-level guidance said *"run it when
you are the only session writing bridges."*

🔴 **The last row is the point.** The seat that runs the guard is itself one of the writers: it
writes its own bridge and its own listener files *while the guard executes*. So the precondition is
not merely hard to arrange on a busy box — **it is unachievable by any amount of coordination**,
because the one session you cannot ask to hold still is the one running the check.

That is why the original row is titled the way it is, and it is why the fix had to be a **wording**
fix. A doc that asks for an impossible state gives a reader no way to interpret the result, and the
sanctioned response to the resulting red — *"re-run"* — is behaviourally identical to weakening a
gate.

## 2. The rule that separates a real red from noise

Rachel's rule, now in `CLAUDE.md` rather than in a DM:

> **Real contact is DETERMINISTIC; peer noise is NOT.**

1. **Re-run and compare the NAMED file.** The same filename every run = contact. A different file
   each run, or none = peer noise.
2. **Identify the writer** — the stronger form. Read the named file's `session_id` / `cc_pid`, then
   `ls /proc/<cc_pid>`. A live seat that is not the test is noise. This is exactly the query that
   produced the table in §1, so it is known to work on the `cc-*.json` shape.

⚠️ **Caveat on step 2, measured:** the directory holds **two unrelated schemas**. Lupin bridges are
`cc-<pid>.json` and carry `session_id` / `cc_pid` / `voice_persona`. The bare `<pid>.json` files are
**Claude Code's own session registry** — different keys entirely (`sessionId`, `peerProtocol`,
`messagingSocketPath`), written by the harness, nothing to do with Lupin. Step 2's field names work
on the first shape only. A reader who applies it blindly to a bare `<pid>.json` gets `?` and should
not conclude anything from that.

## 4. 🔴 THE SCOPING QUESTION — for Rick, with the numbers attached

**Do not "fix" this by narrowing the glob.** `fingerprint_dir` globs `*` and not `cc-*.json`
because row `877794ed` **widened it on purpose**: the narrow form MISSED real
`cc-listener-*.stderr` and `.spawn-lock` writes. That was a correct decision that caught a genuine
hazard. Narrowing it back re-opens exactly what widening found.

The measured cost of that correct decision:

| | count |
|---|---|
| entries the guard fingerprints (`glob("*")`) | **6,498** |
| bytes sha256'd — **twice per test**, before and after | **154 MB** |
| Lupin bridges among them (the thing being protected) | **5** |
| `.log` + `.stderr` files present | **4,676** |
| names on the `UNATTRIBUTABLE` exclusion list | **2** |

Breakdown of the 6,498: `2,397 .log`, `2,279 .stderr`, `1,403 .spawn-lock`, `322 .lock`,
`42 .jsonl`, `36 .json`, `11 .id`, `4 .key`.

⇒ **The noise surface is roughly 1,300× the signal surface**, and the exclusion list covers 2 of
~4,676 log-ish files.

**Both horns are real, which is why this is a decision and not a cleanup:**

- **Keep the wide glob** — hazard coverage stays complete; the gate stays noisy, slow (154 MB × 2
  hashes per test), and needs §2's procedure on every red, forever.
- **Scope the fingerprint** — the gate becomes quiet and fast; **the `877794ed` hazard class
  returns unless the narrower set explicitly includes listener-stderr and spawn-lock names.**

A middle option exists and is **not evaluated here**: keep the wide glob but grow `UNATTRIBUTABLE`,
or key on `.log`/`.stderr`/`.lock` suffixes rather than two literal names. That trades a hazard
class nobody has measured for noise everybody has, so it needs its own analysis before anyone
reaches for it.
