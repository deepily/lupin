## Live reading, taken during this audit

```
:8000 -- UNKNOWN                                    (exit 2)
  . todo_queue_size could not be read
  . monopolize_inflight could not be read
  signals: run_queue_size=0, todo_queue_size=None, inflight_agentic_jobs=0, monopolize_inflight=None
  UNKNOWN IS NOT IDLE -- do not recreate, do not submit.
```

Two of four signals are unreadable, so the honest answer is UNKNOWN, and UNKNOWN is not idle.
Note that a reader glancing at `run_queue_size=0, inflight_agentic_jobs=0` would call this
idle — which is the same mistake in a new costume, one layer down from `monopolize_id`.

⚠️ **A measurement error of my own, recorded because it nearly became the finding.** My first
run piped the checker into `tail` and read `$?` — which is `tail`'s status, not the checker's.
It printed `EXIT=0`, i.e. **IDLE**, for a run whose own text said UNKNOWN. Re-run without the
pipe, the true exit is **2**. A pipeline silently replaces the exit code you meant to read; on
a check whose entire contract is *"read the exit code"*, that turns the sanctioned instrument
into a false green.
