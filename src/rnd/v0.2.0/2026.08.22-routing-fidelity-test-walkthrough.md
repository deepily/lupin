# Routing-fidelity tests — what guards `/api/v2/ask` and `/api/v2/submit`, and what each one is actually for

**Written**: 2026-08-22 · **Author**: Mr. Radio 🦉 (session `dc0137ba`) · **For**: Rick, morning walkthrough

## The one-paragraph answer

There are **~520 test functions across 33 files** guarding routing fidelity, and they are not one suite — they are **six layers, each answering a question the layer below it cannot**. Layer 1 pins the *registry* as the single source of truth. Layer 2 stops the four downstream consumers of a command name from drifting apart. Layer 3 pins what the *router prompt* and the *training corpus* say, so a retrain cannot teach a menu the server does not serve. Layer 4 tests the two endpoints themselves. Layer 5 proves the **old doors are dead and the new door can do what they did**. Layer 6 goes over HTTP against a running server, because everything above it runs in-process and can be green while the shipped app is broken.

The recurring design idea, visible in almost every file: **a guard that cannot be observed failing is not a guard.** Most of these files contain an explicit "prove it can fail" test alongside the real assertion.

---

## Layer 1 — The registry is the source of truth

`src/cosa/rest/v2/registry.py` (385 lines) holds the command→agent mapping as **data**. Before this, `todo_fifo_queue.push_job` ran the routed command down a hand-written if/elif ladder of ~10 branches naming agent classes, while the registry held the same mapping and only the HTTP route asked it. Two sources, one truth, guaranteed drift.

| File | Tests | What it is for |
|---|---:|---|
| `test_v2_registry.py` | 18 | `resolve()`'s hit/alias/miss arms, `required_args`' three arms, and the **four-bucket partition**: every command the router can emit sits in exactly one of {v2 agent, deferred, mode-control, receptionist}. 100% lines+branches on `registry.py`. |
| `test_v2_registry_resolve_scope_guard.py` | 3 | The sharpest hazard, named as such in the design: `resolve()` must stay scoped to **conversational** commands, and agentic commands must be served only by `resolve_agentic()`. A naive `REGISTRY.get()` inside `resolve()` would silently start returning specs for agentic commands — changing live routing as a side effect of a bookkeeping change. |
| `test_registry_voice_binding.py` | 14 | The if/elif ladder is gone; these pins stop it growing back. Every v1 ladder command still resolves, every one has a voice binding, the label matches what v1 said, and **a new command needs no queue edit**. Every test here was watched failing before it was kept. |

**Why the scope guard matters more than it looks**: it is the only test in the set that guards against a *correct-looking* change. Everything else catches an omission; this one catches a refactor that reads as tidy-up.

## Layer 2 — Four consumers, one command name, no drift

`test_v2_registry_drift_guard.py` — **24 tests**, the class-aware drift guard.

Four things consume a routing command name: the **registry** (owner), the **router prompt template**, the **training corpus keys**, and the **job factory's branches**. This file asserts all four agree, in both directions:

- `test_1a` every owned agentic command is router-listed
- `test_1b` factory branches **equal** the owned agentic set (equality, not subset)
- `test_1c` training agentic keys **equal** the owned agentic set
- `test_1d` the card surface agrees with the owned agentic set
- `test_4` no command lives in two class buckets
- `test_5` every agentic CLI module actually runs

It also carries six `test_demo_*` tests whose whole job is to prove the guard fires — membership gaps, both-direction inequality, partition overlap, an unrunnable CLI module, a class mislabel.

**Read the honesty in this file's docstring.** It names two reachability gaps it deliberately does **not** close, so nobody reads its name as a reachability proof: (1) training keys on disk vs LoRA weights, and (3) emitted string ≠ registry key. A third gap — runtime template ≠ checked-in template — is marked **verified closed** (Tiffany, 2026-08-15) because the live router loads the template fresh from disk.

That last point is the one to carry into today's training run: **the drift guard does not prove the model was retrained.**

## Layer 3 — What the router is told, and what the model was taught

This is the layer that decides routing fidelity *before any request arrives*.

| File | Tests | What it is for |
|---|---:|---|
| `test_v2_router_prompt_generator.py` | 16 | **The pin.** The checked-in router prompt must equal what `render_router_prompt()` emits right now. Hand-edit the prompt and it goes red — that is what converts the drift guard from a *detector* into a *preventer*. Also pins the ratified **eighteen** commands, the emission order, the header/footer prose against an independent golden, and that a hand-edit of the prose is detected. |
| `test_v2_router_client.py` | 4 | Routing goes through the decoupled module-level `get_routing_command` with the client's **own** config and factory — never by constructing a `TodoFifoQueue`. That is risk 8 in test form. |
| `test_agent_router_prompt_template.py` | 6 | Guards a real defect from 2026-08-02: the template carried an unsubstituted `{{PYDANTIC_XML_EXAMPLE}}`, and `.format()` collapses `{{X}}` to `{X}` rather than calling the processor. The model was shown a literal `{PYDANTIC_XML_EXAMPLE}` where the response example belongs, invented its own tag, the parser rejected it, the router said "unknown", and the push fell through to web search. These tests render the template exactly as the router does. |
| `test_v2_training_corpus_registry_source.py` | 9 | The training **row set** and each row's **label** come from the registry, not from the three agent-router JSONs. The menu was already single-sourced; *which commands got rows* was not — so a JSON could contribute a command the menu inside those very rows never offers, and the model would learn both halves. |
| `test_agent_router_corpus_roster.py` (cosa) | 4 | The generated rows equal the generated menu, by construction. Closes the 18-vs-19 disagreement. `START` is absent from both — it is system-triggered with a non-speakable job-id argument, so a retrain must stop being taught to emit it. |
| `test_router_corpus_consistency.py` *(wip)* | 25 | Capability gate on the training data, both directions: no MATH line asks for something `CalculatorAgent` implements; no CALCULATOR line is symbolic work the calculator has no operation for. Plus a duplicate-group ceiling — the bar is "adds none", not "zero". |
| `test_router_label_audit.py` *(wip)* | 34 | Tests for the audit script itself: the bucket classifier, both destination rules, the duplicate check, the cold-pass recount, and that `--dry-run` touches no files. |

🔴 **The two `wip` files are not on the integration branch, and the integration files are not on wip.** Whichever way the merge goes, the combined set only exists after it. Worth confirming before this afternoon's training run.

## Layer 5 — The old doors are dead, and the new door can do their work

This is where the "high fidelity" claim is actually earned. Retiring a door is only safe if the successor does the job.

| File | Tests | What it is for |
|---|---:|---|
| `test_retired_queue_doors_410.py` | 10 | Twelve doors answer **410 Gone**, each refusal naming its replacement and saying REMOVE BY 2026-12-31 out loud. Includes `test_no_refusal_names_a_door_that_does_not_exist_yet` — Cheech's rule: *"a 410 that names a door that does not exist yet is a refusal pointing at nothing."* That is why the submit-shaped doors could not retire until `/api/v2/submit` existed. |
| `test_every_retired_door_names_the_right_successor.py` | 5 | **Found by attack, not by reading** (Pocholo, 2026-08-21). Flip `/api/podcast-generator/submit` from `/api/v2/ask` to `/api/v2/submit` in the table and **63 tests stayed green** — every existing guard checked *consistency*, not *correctness*. The count test checks how many, the set test checks which, the sentence test checks the wording matches whatever the table names. Flip the target and the sentence flips with it: internally consistent, factually wrong. This file freezes the expected successor per door. |
| `test_retired_doors_through_the_real_app.py` | 4 | The tombstones refuse through the app **`main.py` really builds**. The 410 suite mounts routers onto a FastAPI it builds itself — every assertion in it is true of the *routers* and none of it is true of the *server*. If `main.py` stopped including `queues.router`, that suite stays green while `/api/push` is live again. |
| `test_step12_internal_callers_use_flow_submit.py` | 5 | Six internal callers have no endpoint to disable — they push work onto the queue from inside the process. They must reach `flow.submit()` too. `job_persistence:830`, the boot-time catch-up restore, is ruled in by you precisely because it is *"the caller least likely to be noticed misbehaving: startup, unattended, re-enqueueing work an interruption left behind."* |
| `test_6c_push_job_has_no_production_caller.py` | 4 | The sweep: no production module calls `push_job`; the spoken door reaches the flow, not the queue. Includes `test_the_sweep_can_actually_fail` and `test_a_comment_naming_push_job_is_not_a_caller`. |
| `test_push_job_entry_coverage.py` (cosa) | 8 | Entry pins for the two branches step 6c would silently drop: `AskFlow.run()` reads no user mode, and `resolve()` is conversational-scoped so an agentic command resolves to nothing there. The pin is an **absence** assertion — the LLM router was never called. |
| `test_door8_agentic_transcription.py` | 4 | The one that caught a live bug (`b7fe8941`, raised by María). The existing door-8 tests hand the door a **MagicMock** flow and assert `ask` was called with the transcription — which proves the transcription *reaches* the flow, not that the flow can do anything with it. Behind the mock, `ask` resolved every agentic command to None and answered *"I do not understand"*, so **"do a deep research on the state of AI" was unanswerable by voice while door 8's own suite stayed green.** |
| `test_write_back_lands_before_the_job_is_done.py` | 3 | Driven, not read: the queue saves the snapshot **before** it pushes the job onto the done queue. That ordering is what makes the cold→warm round trip a fair test rather than a race. |

## Layer 6 — Over HTTP, against a running server

Everything above runs in-process. These do not.

| File | Tests | Venue | What it is for |
|---|---:|---|---|
| `test_v2_ask_roundtrip.py` | 2 | `:8000` | Two POSTs over HTTP: a snapshotable answer is written back and the next identical request replays from cache. The isolated cache control proves `V2Cache` composes with itself; it does **not** prove the shipped app turns write-back on. |
| `test_v2_resume_live.py` | 2 | `:8000` | ask → park → resume driven to terminal `done` over HTTP. The unit tier proves resume closes the loop against the real `PendingRequests` — but with a fake executor and router. |
| `test_v2_eval_live.py` | 1 | `:8000` | Thin wrapper so the standalone two-pass eval harness can be **scheduled** via `POST /api/test-suite/submit`, which only runs registered pytest suites. |
| `test_v2_paired_live.py` | 1 | `:8000` | The v1-vs-v2 paired median-Δ go/no-go, over an identical seeded utterance list with pairing preserved. All gate logic lives in `paired_eval.main`; this bridge re-implements none of it. |
| `test_v2_ask_voice_path_live.py` | script | `:8000` | A spoken todo, math and weather question against the real API. **Read its venue note**: the first version claimed `:7999`-legality on a read-shaped todo. Wrong — `flow._maybe_write_back` writes when `snapshotable and status == "done"`, and `snapshotable` defaults True on the registry entry. **Every ask writes a snapshot row whatever the question was.** Shaping the question to avoid a mutation cannot work when the mutation belongs to the flow, not the agent. |

`test_v2_eval.py` (**109 tests**) is the harness's own unit tier: metric core, injectable live-client seam, and a dedicated prove-it-can-fail block for every property the run-integrity guard asserts — including that a **200 reporting a route error is not a success**, that the routing denominator excludes unmappable utterances, and that a cold pass aborts early on the first replayed answer rather than after the whole corpus.

Three files guard the paired run's preconditions rather than its result: `test_v2_paired_allowlist_config.py` (5), `test_v2_paired_bridge_reachability.py` (17), `test_v2_paired_live_precondition.py` (3).

## Three things worth knowing before this afternoon's training run

1. **Nothing here proves the model was retrained.** The drift guard says so in its own docstring — "no-retrain (training keys on disk vs LoRA weights)" is explicitly out of scope. The corpus tests prove the *training data* agrees with the registry; the pin proves the *prompt* agrees with the generator. The weights are unguarded by construction.
2. **The corpus tests and the endpoint tests are on different branches right now.** `test_router_corpus_consistency.py` and `test_router_label_audit.py` are on `wip`; the whole v2 submit cluster is on the integration branch. The complete guard set exists only after the merge.
3. **The most valuable file in the set is the smallest.** `test_every_retired_door_names_the_right_successor.py` is 5 tests, and it exists because 63 green tests were consistent with a wrong answer. That is the shape of defect worth looking for in the next surface, not just this one.
