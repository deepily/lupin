# Nine assertions that could not fail, and the two things hiding underneath them

**Row** `9d5fd628` · **Owner** John 🏄🏽 · **Manager** Cheech 🌿 · **2026-08-23**
Split out of `beffcddd` (closed `54f2e987`). Predecessor mementos: `54324b69`, `76f29be7`.

---

## Verdict

Nine assertions in `src/tests/lupin_smoke/` sat inside a `try` whose `except Exception`
only logged. `AssertionError` is an `Exception`, so a failed check was caught and the test
passed anyway. All nine are replaced. The control is the receipt: **on the same build, the
old shape passes green where the new shape fails by name.**

Un-swallowing them exposed four things nothing had ever reported, listed below. **None is a
product defect.** Product auth is correctly enforced; the retired endpoint was retired on
purpose. Every defect found is test-side.

## Four things that were hiding underneath

### 1. `/api/push` has been dead, and one test was already saying so in public

The endpoint answers `410`: *"Every question now enters through `/api/v2/ask`. This route is
a tombstone."* Three swallowed tests were sitting on it.

⚠️ **This was not discovered here.** `test_job_submission` (line 123, not in this row, not
touched) is **already red today** with the identical `410`. The smoke runner has been
reporting this file as failing on its own. What this row adds is that three *more* tests sat
on the same dead door reporting green.

⇒ **A standing red nobody chases is no better off than a swallowed assertion — it just fails
in public.** Migration filed as `a2184fa4`; deliberately **not** done here. A red that names
a dead endpoint is worth more than a green that hides one.

### 2. Three "unauthenticated" tests had never once sent an unauthenticated request

`LupinTestClient.http_request` re-attaches the bearer token whenever the caller supplies no
`Authorization` key — and `headers = {}` has none, so the helper puts one back:

```python
headers = kwargs.get('headers', {})
if 'Authorization' not in headers:
    headers['Authorization'] = self.auth_token
```

The comment said `# No auth header`. The call path three frames down said otherwise.

**And the assertion underneath was worse than vacuous**: `assert status_code in [200, 401]`,
commented *"Should either require auth or allow without auth"* — it accepts **both answers to
the question it claims to ask**. Two independent defects stacked: the request was never
unauthenticated, *and* the check would have passed either way.

Fixed with an explicit `authenticate` parameter, and the expectation tightened to `== 401`.
Probed first: with genuinely no header, all three endpoints return `401`. **Product is fine.**

### 3. A test that could not read the stream it subscribed to

`test_audio_streaming_events` fed binary WebSocket frames straight to `json.loads` and died
on `'utf-8' codec can't decode byte 0xff in position 0` — `0xff` being an MP3 frame header.
The audio path was working; the test could not read it. It had been passing for as long as
that handler existed.

### 4. A test whose assertions are unreachable — swallowing was not why it could not fail

`test_queue_contents_access` targets `/api/queue/{type}`, which returns `404` for all four
queue types. Every iteration takes the `if response.status_code == 404: continue` branch, so
**no assertion in the loop body ever executes.**

Proven rather than argued: `assert False` planted just past the `continue`, edit verified on
disk (+83 bytes), test still **🟢 GREEN**.

⇒ Un-swallowing it is still correct, but it does **not** make it bite. Reported as green-and-
vacuous rather than green-and-fixed.

## Two blind spots now named in the detector

`src/rnd/v0.2.0/2026.08.23-swallowed-assertion-detector.py` counts `assert` **statements**.

- **Shape 6 — an assertion reached through a helper.** `TestValidator.assert_response_ok`,
  `assert_json_contains` and `assert_websocket_event` (`utilities.py:344/:350/:356`) are plain
  functions wrapping `assert`. They raise `AssertionError` identically and are swallowed
  identically, and the tool cannot see them. Sites 7 and 8 exist only because of this.
- **Shape 7 — an assertion that is never reached**, per finding 4 above. A collect-only
  report and a swallow-detector both call that test healthy.

Combined with the five shapes named on `beffcddd`, the tool covers **one of seven**.
A clean run guards against one known defect. It is not a certificate that the suite is honest.

## Method notes worth keeping

- **Mutate + prove-the-edit-landed + run must be one command.** The harness refuses to run if
  the anchor is missing, ambiguous, or the file is byte-identical afterwards. It caught one
  ambiguous anchor during this row — two matches for the same three lines — which would have
  mutated the wrong site and produced a confident wrong answer.
- **A probe can be broken too.** The first reachability probe here queried
  `/api/get-queue-contents/{q}` and got four `404`s. The helper actually calls
  `/api/queue/{q}`. Both are 404, so the *conclusion* survived — but it survived by luck, and
  a wrong instrument that agrees with you is the hardest kind to notice.
- **When a test explains why it is weak, check the explanation.** Six for six across three
  rows now. The sharpest instance is here: the explanation was a **code comment** asserting a
  fact the call path contradicts. **The comment is not evidence; the call path is.**
- **"Not collected by pytest" is not "does not run."** These nine are invisible to pytest and
  execute every time `run-lupin-smoke-tests.sh` runs. The detector stayed green through this
  entire row, by design.
