# doc_lint precision and recall, measured by reading

This report measures how often the doc_lint rules agree with a human reading of the same text. Plan section 4.3 asks for it, and Rick sets the pass floor at the Phase 3 sign-off from these figures. Every label below was typed by one reader (Tiberius) after reading each item in full, with no regex pre-filter and the labels frozen by sha before the linter ran. The one exception is the S2 draw, which used the labeller's own grep to find candidates (section 6).

## 2. How to read the tables

- Precision is TP over TP plus FP; recall is TP over TP plus FN, both against the reader's labels. An item the reader labelled positive and the linter did not flag is an FN.
- Intervals are Clopper-Pearson. S1 uses a two-sided 90% interval, which gives the one-sided 95% lower and upper bounds. S2, S3 and S4 use a two-sided 95% interval. Each table says which.
- A rule with fewer than 10 positives prints "insufficient positives" and no recall figure, as the plan requires.
- Units differ: S1 and S2 score one docstring, S4 one block, S3 one page (a page is positive when it holds at least one violation, which is lenient).
- Recall is of what the reader found in a sample drawn for the purpose. It is not the rate across the whole repository, and S2's quota draw cannot estimate prevalence.

## 8. Four boundary calls the plan text leaves open

These are disagreements between two careful readers, so they need a ruling in the plan, not more samples.

1. R3 at exactly 25 words: is "under 25" strict? (Dart block D106.)
2. R5 on a short phrase against an aphorism (D097, "never a vanishing spinner").

## 9. Caveats

- Not blind to the linter on S3 and S4: the reader had seen the linter's results on both samples before relabelling by reading. S1 was labelled before any linter output, and S5 is the blind check where it exists.
- Tuning history: the earlier 214-docstring tuning set and the 105-docstring held-out batch 1 were labelled by reading. Held-out batch 2 (R1 and R3 only) was labelled by the reader's own script, so its figures are code against code and are not used here.
- Those three earlier lists are gone from the labeller's scratchpad. S1 excluded the 424 burned ids, but S2 could only exclude the 200 S1 ids. The injection rule was tuned on 4 positives in the 214 set, and the overlap with S2 is unknown.
- One labeller on S1, S2, S3 and S4. The labeller did not write or run the linters.
- S3 has 20 pages, so most per-rule figures there are wide or insufficient.
- Positives under 10 print no recall, as the plan requires. R2, the bold part of R4, the rhetoric part of R5 and "not X but Y" are not scored here; they belong to the prose judge.

## 10. Defects and leads found while measuring

- `md_lint` raises `FileNotFoundError` for `src/conf/dm-tutor-lowercase-words.txt` when the repo root is the lupin-mobile tree, because the word list resolves against that root. The mobile gate must pass lupin's word list (row `ec1854b7`).
- The date rule matches hyphenated ISO dates only. The dotted `YYYY.MM.DD` form this repo uses in file names and headers is invisible to it (filed by Cheech as a bug row).
- The injection rule fires only on "you must" and "you should". The exemption by tool registration still has to be built and tested.
