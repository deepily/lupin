# Lupin AF documentation rewrite plan

Sep 29, 2026 · @Richard P Ruiz

Rewrite what agents read, freeze what they don't, and prove no rewrite loses a claim. That turns about 500k lines of prose across Lupin and Lupin-mobile into a bounded job.

## Scope

Two repos are in scope: `deepily/lupin`, the platform (FastAPI server, vanilla JS clients, and CoSA at `src/cosa`), and `deepily/lupin-mobile`, the Flutter client that talks to that server. Together they hold about 555k lines of prose.

**Branch targets.** Lupin-mobile's `main` hasn't changed since 2026-04-16; current work is on `wip-v0.1.6-2026.04.16-tracking-lupin-work`, last updated 2026-09-29. Lupin's `main` was measured at 2026-09-13, and some of its branches are newer. The rewrite runs on the working branches, not a stale `main`.

## What is wrong

The length of each document is mostly stable. The problems are the density of rhetorical markers, references nobody can follow, and history mixed into current instructions. The markers started appearing in early 2026 and rose through August.

The volume grew too. Lupin's R&D output went from 27 docs in eight months (v0.0.5) to 317 in four weeks (v0.2.0).

The six patterns, each with an example from the repos:

1. **Aphorism instead of a statement.** "This predicate is the red." "Silence is recoverable here; a crying wolf is not." Memorable, but nothing a reader can act on or check.
2. **Incident history inside contracts.** Bug IDs, "MEASURED, 2026-07-25", and rejected alternatives sit inside the docstring. `park_reason_is_stale` runs to 113 lines. In Lupin, 813 docstrings (16%) have more than six lines before the contract, and the 98 docstrings over 40 lines hold 8.5% of all docstring lines.
3. **Rulings and conversation quoted in code.** Mobile's `groupByFiler` opens with "🔴 THE GROUPING KEY IS THE PERSONA … RICK'S RULING R1=B, 2026-09-22", followed by three quoted exchanges. The decision matters; its transcript doesn't belong in the function.
4. **Palimpsest documents.** The tmux runbook opens with a "⚠️ FORENSIC UPDATE" block, items 1 through 3b, so the current procedure is buried under its own history.
5. **References nobody can follow.** "§4.3 setters b/c", "ruling 2", "the §0 #2 invariant", "AC5", "row aa543525": pointers into documents the reader doesn't have, with no path.
6. **Typographic shouting.** ALL-CAPS sentences, bold, ⚠️, 🔴 and ⇒ used for emphasis. Mobile doc comments are the loudest corpus measured: 34.7 CAPS words per 1,000.

What is healthy: first lines. None of the Lupin docstring or Mobile `///` first lines is over 100 characters, and 89% of Lupin summaries fit on one line. Lupin's Requires / Ensures blocks (3,331 / 3,938) are tight and checkable. The rewrite removes what surrounds the contracts and leaves the contracts intact.

## The standard

Eight rules, each one checkable by a linter or a judge. Your KISS protocol is the base, and PEP 257 and Effective Dart already require the first two.

1. **Lead with the claim.** The first sentence says what the thing does or decides. In code it is one line of at most 90 characters, followed by a blank line. PEP 257 says the summary line "may be used by automatic indexing tools", and Jev's symbol index depends on exactly that.
2. **Say only what the signature doesn't.** Effective Dart: "focus on explaining what the reader doesn't already know."
3. **One idea per sentence**, under 25 words.
4. **No typographic emphasis.** No ALL-CAPS words, ⚠️, 🔴 or ⇒. In docs, bold is only for a term's first definition; in code comments, never.
5. **No rhetoric.** No aphorisms, no "not X but Y" setups, and none of *deliberately / by construction / load-bearing / the point*. State the constraint and its consequence.
6. **Every reference resolves.** A path, plus an anchor if needed, or no reference at all. No bare §, row, ruling or step IDs.
7. **Current state only.** History goes to the commit message, `history.md`, or the R&D doc the `Design:` line points to. No dated UPDATE banners and no quoted conversations in code. A ruling becomes a one-line decision record in `docs/decisions/`, and the code links to it.
8. **Fit the template.** Runbook: prerequisites, steps, verify, rollback. Reference page: at most 1,500 words. Capability page: at most 40 lines.

The design-by-contract docstring keeps its shape. What changes is the text around the contract. Rewriting `park_reason_is_stale` to these rules takes it from 113 lines to 20:

```python
def park_reason_is_stale( status, park_reason_captured_at, body_changed_ts ) -> bool:
    """
    True if a parked row's body changed after its park reason was quoted.

    Compares two DB-clock stamps already on the row; reads no clock. Advisory:
    every ambiguous input returns False, so False means "body unchanged since
    capture", not "reason still true". Reasons invalidated by outside events
    are caught by the chase (next_chase_ts), not here.
    Design: src/rnd/v0.1.9/2026.07.19-park-reason-staleness-detection.md §3

    Requires:
        - both timestamps: ISO-8601 str, datetime, or None; both from the DB clock; naive = UTC

    Ensures:
        - status != PARK_STATUS               -> False
        - either timestamp None or unparseable -> False
        - body_changed_ts >  captured_at       -> True
        - body_changed_ts <= captured_at       -> False
        - never raises
    """
```

In Dart the same shape applies: a `///` summary sentence, a blank `///`, at most four lines of why, a `Design:` path, then Requires / Ensures where behavior isn't obvious. Today only about 10% of Mobile's doc blocks carry a contract (275 `Ensures:` in 2,719 blocks). Whether that coverage should grow is an open question below.

The standard is enforced in three places: a docstring and doc-comment linter (Python `ast`; Dart `///` blocks), a markdown linter with marker thresholds, and the reuse-reviewer skill, which rejects a diff that fails either linter.

Triaging the R&D archive is cheap. Jev classifies each doc as *still in force*, *superseded* or *history*. At about 4.6M input tokens for Lupin and 0.3M for Mobile, that's roughly $0.20 at $0.042 per million. Uncertain calls go to Opus, and anything still marked in force comes to you. Every doc gets an `archived:` frontmatter line, and the directory is excluded from agent context.

## Verification

A terse rewrite is accepted only when three checks pass: the code is unchanged, every claim survives, and the metrics improved.

1. **Code unchanged (mechanical).** Python: the AST with docstrings stripped must be identical before and after. `#` comments aren't in the AST, so comment edits pass too. Dart: every changed line in the diff must be a `//` or `///` line, or blank.
2. **No claim lost (cascade).** An extractor lists the atomic claims in the old text. For each claim, Jev answers one yes/no: "Does the new text, or the doc its `Design:` line points to, state this claim?" Confident yes answers pass. Uncertain ones go to Opus. Any claim dropped as history has to be labeled that way in the pull request.
3. **Contract clauses preserved.** The count of Requires / Ensures / Raises items may drop only when items are merged, and every merge is listed.
4. **Metrics improved.** A before/after dashboard of tokens and the marker rates in the table above, per package.
5. **Reader test (pilot only).** A fresh agent answers the same questions from the old text and the new. The new text must score at least as well.

The mechanical check for Python, tested:

```python
import ast

def strip_docs(src: str) -> str:
    t = ast.parse(src)
    for n in ast.walk(t):
        if isinstance(n, (ast.Module, ast.ClassDef, ast.FunctionDef, ast.AsyncFunctionDef)) and n.body \
           and isinstance(n.body[0], ast.Expr) and isinstance(n.body[0].value, ast.Constant) \
           and isinstance(n.body[0].value.value, str):
            n.body = n.body[1:] or [ast.Pass()]
    return ast.dump(t)

assert strip_docs(old_src) == strip_docs(new_src)   # docs-only diff, or reject
```

For Dart:

```bash
git diff -U0 -- '*.dart' | grep -E '^[+-][^+-]' | grep -vE '^[+-]\s*(//|$)' && exit 1 || exit 0
```

## Decisions and open questions

Decided:

- `lupin/src/cosa` is canonical; `deepily/cosa` gets archived (see Scope).
- The design-by-contract docstring stays; the rewrite targets the prose around it.
- The R&D archives are frozen and triaged, not rewritten.
- The docs rewrite and the code-wiki bootstrap are one piece of work: reference pages become capability pages.

Open:

- [ ] Should Dart adopt Requires / Ensures across the public API in `lib/`, or only where behavior isn't obvious? About 10% of blocks have a contract today.
- [ ] Where does history live: commit messages, `history.md`, or the linked R&D doc? The rule needs one answer.
- [ ] Decision records: is `docs/decisions/` in each repo the right home for rulings like R1=B?
- [ ] Linter thresholds: set them from pilot data, not in advance.
- [ ] Merge Mobile's `wip-v0.1.6` branch into `main` before the sweep, or run the sweep on the branch?
- [ ] Sign-off: you approve the spec and the pilot; after that, the adversarial reviewer approves each package.
