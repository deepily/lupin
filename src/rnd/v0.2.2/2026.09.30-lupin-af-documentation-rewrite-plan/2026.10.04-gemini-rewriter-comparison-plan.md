# Rerunning the rewriter trial with Gemini: plan for the comparison

## 1. What this plan is for

On 2026-10-04 a trial of the faster docstring rewriter ran here with Claude models: 130 docstrings were rewritten and then checked for lost claims. Rick has free use of AGY, his employer's command-line coding tool, on a work development server. This plan lets him run the same trial there with a Gemini model in every role, and lay the two results side by side for time, cost and accuracy.

The planning is finished on 2026-10-04. The Gemini run happens on the work server on 2026-10-05 or later. Nothing in this plan has been run against a Gemini model.

**The finding that shapes this plan.** The same evening the fast settings were run over the earlier pilot (78 docstrings), where two real losses are known. On the development half of the labelled set (70 pairs with planted removals) the fast judge caught 28 of 28. So a judge can score perfectly on planted removals and still miss the real ones, and the reasoning setting of the judge decided the outcome. The Gemini run must record the reasoning setting of every model call, and its judge must be tested on the two known losses before its verdicts on the 130 are believed (section 8, step 2).

## 4. The roles and what fills them

The harness names four roles. The Gemini run fills each with a Gemini model. The model identifiers are whatever AGY offers on the work server; they are recorded in the run log, not chosen here.

| Role | In the Claude run | In the Gemini run | Note |
|---|---|---|---|
| Writer | Sonnet 5.5, one seat | the strongest general Gemini model on offer | rewrites docstrings from the writer's brief |
| Extractor | Sonnet 5.5 | the same model as the writer | lists the claims of the old text, each with an exact quote |
| Judge | Haiku 4.5 | a smaller, faster Gemini model | says present, absent or uncertain for each claim |
| Second opinion | Opus 5.5 | a strong Gemini model that is **not** the writer's model | settles the judge's uncertain verdicts |

The harness refuses to start when the judge or the second-opinion model is the same as the writer model (`check_models` in `harness_runner.py`): a model must not grade its own rewrite. So the Gemini run needs three distinct model identifiers at least: one for writer and extractor, one for the judge, one for the second opinion. If only two Gemini models are on offer, use the judge's model for the second opinion and say so in the run log; do not get past the check by passing a false writer label.

Run the judge with its reasoning on, three runs, as the reference. A reasoning-off arm may be added as a second run on a copy of the ledger; it costs little and shows whether Gemini's judge has the weakness found here.

## 5. Step 0 at work: a ten-minute probe that chooses Set A or Set B

Before anything else, find out what AGY can do from a script.

1. Start AGY from a shell script with a one-line prompt and no person at the keyboard. Confirm it prints the answer and exits.
2. Confirm it can be told which model to use, and to use no tools.
3. Time ten such calls one after another. Then start eight at once and confirm all eight answer.
4. Note whether AGY reports the tokens each call used.

**The rule, fixed on 2026-10-04 before any Gemini figure existed:** if AGY runs unattended, eight at once work, and a one-line call takes under 20 seconds, use Set A. Otherwise use Set B.

For scale: one pass of the check is about 550 calls (151 extractor, 390 judge, about 10 second opinions, by the Claude run's counts), and the plan runs it twice, on Claude's rewrite and on Gemini's. With the writing that is 1,100 to 1,200 calls. At 20 seconds of start-up each, that adds about 7 hours one at a time, or about 55 minutes at 8 wide.

**The work server's setup.** Not tested on a clean machine; this is read from the imports.

| Need | Detail |
|---|---|
| Python | 3.13 (the Claude run used 3.13.7), in a virtual environment named `.venv` at the repository root |
| Packages | `pip install -r src/cosa/requirements.txt`. The harness itself needs `scipy` and whatever `cosa.utils.util` imports |
| Two environment variables, set to the clone's root | `export LUPIN_ROOT="$PWD" PYTHONPATH="$PWD/src"`, from the repository root. Every command in this plan assumes both |

## 6. Set A: the harness calls AGY once per prompt

This keeps the prompts, the ledger, the scoring and the report identical to the Claude run. Only the model behind each call differs.

**What must be built first, at work: a command door in `src/cosa/repo/doc_lint/model_transport.py`.** It does not exist as of this plan. The bundle's `run-fast.sh` is the Claude command with this machine's paths; it is a model to copy, not something to run. Today `complete( model, system_prompt, user_prompt, ... )` starts the Claude tool. The door is a second way to answer the same call:

| Requirement | Reason |
|---|---|
| Chosen by a setting on the command line, for example `--transport command --command-template "<the AGY command>"` | the Claude path stays the default and unchanged |
| The template names where the model, the system prompt and the user prompt go; prompts are passed by file or standard input, never on the command line | prompts hold quotes and newlines, and some are long |
| The answer is the command's standard output, unmodified | the harness parses the text itself |
| A non-zero exit or a timeout raises `ModelCallError` | the harness already retries and records these |
| The ledger binds the template and the tool's version string | a ledger from one tool must never resume under another |
| `claude_agent_sdk` is imported only when the Claude path is used | the module imports it at the top today, and the work server will not have it |
| The reasoning setting is passed through, and written to the ledger key as `--judge-thinking` is | section 3's finding |
| Tests use a stand-in command that echoes a canned answer; 100% lines, branches and functions | project rule |

**Then the run**, from the repository root on the work server, with the bundle unpacked beside it:

1. Check the pairs file: `sha256sum trial-pairs.json` must print the checksum in section 3. Both runs must judge the same text.
2. Checker on Claude's rewrite. Run `harness_cli` over `trial-pairs.json` with Gemini in the extractor, judge and second-opinion roles: `--extractor-lists 1 --judge-runs 3 --parallel 8`, reasoning on. This scores Gemini as a checker on exactly the text the Claude check saw.
3. Writer. Give the writer's brief (in the bundle) to the Gemini writer over the same 27 files at commit `7ac117348`. Record wall clock. Run `docstring_lint` and `docs_only_diff` as the brief says. Commit the result on a branch.
4. Checker on Gemini's rewrite. Build a second pairs file with `build_pairs.py` (old `7ac117348`, new the Gemini commit) and run `harness_cli` over it with the same settings as step 2.
5. Bring back: the two ledgers, the two reports, the run logs, and the Gemini rewrite as a branch or a patch.

## 7. Set B: AGY does the job as an agent

Use this only if the probe rules out Set A. AGY is handed written instructions and plans its own calls. The timings then compare two agents, and the call counts may not be knowable. Accuracy stays comparable only if AGY writes its results in the file formats below, so the same scoring script reads them.

Instructions to give AGY, in this order. The order matters: a judge that reads the old and new text together tends to judge by impression.

1. **Write.** Follow the writer's brief in the bundle over the 27 files. Commit. Record start and end time.
2. **Extract, from the old text only.** For each of the 130 docstrings in `trial-set.json`, read the old docstring at commit `7ac117348` and nothing else. List every claim it makes: what the code does, requires, guarantees, raises, and why a design choice is as it is. For each claim give the exact words of the old text that state it. Write `claims.json`: a list of `{ "id", "claims": [ { "text", "quote" } ] }`. Do not open the new text during this step.
3. **Judge.** For each claim, read the new text of the same docstring and answer `present`, `absent` or `uncertain`. For `present`, copy the exact words of the new text that state the claim. Do this three separate times, each without looking at the earlier answers. Write `verdicts.json`: a list of `{ "id", "claim_index", "run", "verdict", "quote_in_new" }`.
4. **Record.** Model identifiers, reasoning settings, start and end time of each step, and the tokens used if AGY reports them.

Do steps 2 and 3 twice: once with the new text taken from `trial-pairs.json` (Claude's rewrite), once with AGY's own rewrite.

## 8. How the comparison is scored

| Measure | Claude side | Gemini side | Where it is scored |
|---|---|---|---|
| Writer time | 13 min 13 s, one seat | wall clock of the writing step | from the logs |
| Writer quality | alarms the reference check raises on Claude's rewrite, sorted by a reader | alarms the same Claude reference check raises on Gemini's rewrite, sorted by the same rules | at home, after the branch comes back. One referee for both writers |
| Checker time | section 3's table | the same stages from the Gemini ledger | from the ledgers |
| Checker accuracy | the reader's sort of the alarms on Claude's rewrite is the answer key | Gemini's verdicts on the same pairs, scored against that key: real losses caught, real losses missed, false alarms | at home or at work; the key is in the bundle |
| Cost | tokens per stage times list price | tokens per stage times list price | both are notional: neither side is billed per token |

Three checks keep the comparison honest:

1. **Same text.** The pairs checksum of section 3 is confirmed before the Gemini checker runs.
2. **Known losses first.** Before the 130, run the Gemini check over the two pilot docstrings whose losses are known (`known-losses-pairs.json` in the bundle), with five judge runs. Report two things separately, because the Gemini extractor runs first and a claim it never extracts cannot be judged: (a) for each of the two known-lost claims, whether the extractor produced a claim whose quote overlaps the quote given in the file; (b) of the verdicts on those claims, how many say absent. The Claude figures are for (b) only, on claims the Claude extractor had produced: 8 of 10 with thinking on, 1 of 10 with it off.
3. **Like with like.** A Gemini judge run with reasoning on is compared with the Claude reference judge, and a reasoning-off run with the Claude fast judge. Never across. Compare call time per stage, not wall clock: the Claude reference run's 11 minutes 7 seconds reused its claim lists and so contains no extractor time.

**The scoring script and its rule.** `score_against_key.py` in the bundle reads either a list of claims a checker called absent (the harness path, made by `replay_fast.py`) or Set B's `claims.json` and `verdicts.json`, and scores it against the reader's key. Two claims are the same claim when they belong to the same docstring and their quotes from the old text overlap by at least half of the longer quote; a quote that cannot be found in the old text is reported and never guessed. Half of the longer, because under a shorter-quote rule one claim quoting a whole docstring would be credited with every real loss in it; fed exactly that, the script credits none and prints the claim as a partial match for a person to read. `replay_fast.py` takes the run's model identifiers, list count, judge runs and thinking setting as arguments, since the ledger's keys contain them. Run on the Claude results it gives 2 of 2 real losses for the reference judge and 0 of 2 for the fast judge, which is the table in section 3.

**Cost has a gap on the Claude side.** The harness records calls and seconds, not tokens. The Claude run therefore has no token counts, and the cost row above can be filled for Claude only by estimating from the length of the prompts and replies. If AGY reports tokens, record them; the comparison of cost is then Gemini's measured tokens against a Claude estimate, and must be labelled so.

## 10. What this comparison cannot tell you

- One trial set, one run per side. A difference of a few alarms is noise.
- The answer key is one reader's sort, made with exact-quote checks, of alarms raised by Claude judges. A real loss that neither Claude judge raised is in nobody's key.
- Two known losses are a small test of a judge.
- The Claude writer was a seat with tools, working file by file. A Gemini writer driven per prompt through a command door is a different way of working, and Set B's agent is different again.
- Time on the work server includes that server's network and AGY's start-up. Report call time and wall clock separately, as section 3 does.
- That AGY is free for Rick to use is his statement of 2026-10-04; nothing here checked it.
