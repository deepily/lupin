## What the user sees when it is done

After a podcast finishes, a folder `Lupin Podcasts/<timestamp>-<topic>/` in Rick's own Drive holds the
mp3 for each language, the original source document and, if switched on, the scripts. The completion
card carries a Drive link for each language and one for the folder. If the upload fails the podcast
still completes, and the card says why the upload failed.

## Phase 1: the publisher, with no Google call in the tests

**New file** `src/cosa/utils/drive_publisher.py`:

| Symbol | Contract |
|---|---|
| `DrivePublisher( token_path, folder_name, service=None, debug=False )` | builds the Drive service from the token only when `service` is not injected |
| `ensure_folder( name, parent_id=None ) -> str` | finds a folder the app created by name or creates it; returns its id. The top folder's id is cached in `src/conf/keys/google-drive-folder-id.json` and re-checked on each run (María's fix 2) |
| `upload( local_path, mime_type, parent_id ) -> dict` | resumable upload; returns `{ "file_id", "web_view_link" }` |
| `publish_job( job_folder_name, files ) -> dict` | makes the job subfolder, uploads each `( path, mime )`, returns the folder link and per-file results; one failed file does not stop the rest |
| `DrivePublishError` | raised for a missing token, a token that cannot be refreshed, and API errors, with the file name in the message |

Before writing it, run the reuse lookup (`check_exists`) for "upload a file to Google Drive" and "find
or create a Drive folder", and record the result in the row.

**New script** `src/scripts/google-drive-authorize.py`: runs the installed-app OAuth flow with scope
`drive.file`, reads `src/conf/keys/google-drive-oauth-client.json`, writes
`src/conf/keys/google-drive-oauth-token.json` with mode 600, then makes one test call that lists the
app's own files and prints the account email. It follows the bootstrap-exception path rule.

**Dependencies**: add `google-api-python-client`, `google-auth` and `google-auth-oauthlib` to the
`dependencies` list in the root `pyproject.toml`, run `uv lock` so `uv.lock` matches, and commit both
files. The containers install with `uv sync --locked` at image **build** (`docker/lupin/Dockerfile`), so
`:7999` and `:8000` need an image rebuild plus `--force-recreate`, not a bounce, before any run inside a
container can import the new module (John's review). Rebuilding `:8000` comes before the integration
run; rebuilding `:7999` comes before the live check.

## Phase 3: the hook in BOTH podcast jobs

Two jobs produce podcasts (John's review, 2026-10-31): `PodcastGeneratorJob`
(`src/cosa/agents/podcast_generator/job.py`) and `DeepResearchToPodcastJob`
(`src/cosa/agents/deep_research_to_podcast/job.py`). Both already build `audio_by_lang` and
`script_by_lang` the same way. So the hook is **one shared function**, `publish_podcast_to_drive(
audio_by_lang, script_by_lang, source_path, job_folder_name, config )` in
`src/cosa/agents/podcast_generator/drive_hook.py`. It returns the extra abstract lines and the folder
link, and both jobs call it. The source document is the resolved `full_path` in `PodcastGeneratorJob`, and
the resolved `result.research_path` (the generated research report) in `DeepResearchToPodcastJob`.

In each job, after `audio_by_lang` and `script_by_lang` are filled and before the abstract is built:

1. If the publish flag is off, do nothing. The flag is read **before** `drive_publisher` is imported.
2. Collect the files: the mp3 for each language, the script for each language when its flag is on, and
   the source document once when its flag is on. Use the **resolved** `full_path` that `_execute`
   already computes when it checks that the research document exists, not `self.research_path`, which
   may be relative (María's fix 1). Keep `full_path` in a local variable for the hook; do not resolve
   the path a second time.
3. Call `publish_job` in a worker thread (`asyncio.to_thread`) so the upload does not block the event
   loop.
   The shared hook's outer boundary catches **every** `Exception`, not only `DrivePublishError`, and
   turns it into the failure line, with the exception's type in the reason (John's review). This is the
   one deliberate broad catch, and it carries a same-line comment saying why: an upload must never fail
   the podcast. `DrivePublisher` itself still raises specific errors.
4. Success: each language line gains `[☁️ Drive](<link>)`, and one `**Drive folder**` line is added.
   Failure: one line `**Drive**: upload failed (<reason>)`; the job still returns success.
5. Store the folder link in `self.artifacts[ "drive_folder_link" ]` so the done card and the mobile app
   can read it.
6. The dry-run path never uploads.

## Risks

| Risk | Handling |
|---|---|
| A refresh token for an app in "testing" mode in Google Cloud expires after 7 days | publish the OAuth consent screen to "in production" (single user, no review needed for `drive.file`), or re-run the authorize script; the setup page says so |
| Under the `drive.file` scope the app cannot see a folder Rick makes by hand, so it would create a second "Lupin Podcasts" | the setup page says to let the app create the folder; the cached folder id stops repeat duplicates (María's fix 2) |
| The token file is a secret | lives under `src/conf/keys/`, never committed, never linked into worktrees |
| A large mp3 times out | resumable upload in chunks; the failure line names the file |
| The two halves disagree on the card's links | only `drive_folder_link` is added; the existing audio links are unchanged. Tiffany's row `3469e9db` is told the field name |
