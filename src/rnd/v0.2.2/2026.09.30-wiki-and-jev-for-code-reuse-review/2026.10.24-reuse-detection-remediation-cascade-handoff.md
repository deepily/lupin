## 3. Per-section summary

### 3.A Retire NEW, recorded search, exit gate
- The checker never answers DISTINCT. The old NEW becomes UNCERTAIN with cause `NO_MATCH`, and DISTINCT is an agent's ruling that needs a `record_search` record (Rick confirmed this reading, parking item P1).
- `record_search` (new `src/lupin_mcp/reuse_search.py`) derives 3 to 6 terms with `split_identifier`, refreshes the index, runs `git grep --untracked`, and maps hits through extractor spans. Each candidate gets a ruling of SAME_JOB, RELATED or UNRELATED plus a reason, in a record written once and named by its id.
- The exit gate fails closed. A DISTINCT row with no search, an uncited search, unruled candidates or an empty search without a `none` line is refused. The INDEX_STALE race has an injectable seam.

### 3.B Index fixes and the rebuild during a run
- **Language is a required argument on both tools, with no default** (Rick's revision of D6, P3). A missing value raises `LANGUAGE_REQUIRED` and a bad one `LANGUAGE_INVALID`, both checked in the implementation behind an Optional argument at the FastMCP wrapper. Language and `include_tests` are part of the receipt id.
- Private and protected methods are indexed with their class named; tests are a separate scope that goes through the sweep-only route. The replay snapshot holds the set that was actually judged, and there is one shared file-suffix constant.
- The rebuild probe uses a fake embedder whose vector depends on the text, golden files captured from `d0bd4f604`, and a measured, committed refresh bound.

### 3.C Semantic duplicate checker (Phase 2)
- It reuses `extract_python`, `shapes()` behind a flag, a factored `run_parallel` and `need_input`'s forbidden list. The blindness scrub covers strings unique to the reuse tools only, with a census test.
- The proof pool runs at real size, with the server and client definitions as distractors. Found-rates are reported per stratum, but the 80/80/90 bar is unchanged. The 90% self-agreement count has its own hand-worked test.
- A run that cannot be scored is reported as `unscorable` with its cause, never dropped. Estimate: 6 to 9 days (P7).

### 3.D Tooling for the 400-need diagnostic set (Phase 3)
- Work-alike keys come by two routes, a vector route and a sampled route (word overlap, directory, random), each with its own miss rate, so the search is not graded on matches it picked itself. A find on a symbol outside the key goes to review as `ALT_MATCH`.
- The TypeScript leak check ignores type words. The probe keeps a ledger and can resume. Seed replacements are reported. The needs set has a committed status file that reads `pending` until Rick changes it to `final`.
