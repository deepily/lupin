## 3. Phase W-A: Jev client

1. Move `reuse_check.py`'s call into a client module (`src/cosa/agents/jev_client.py`, or a vendor entry in `llm_client_factory.py` if TypeSafe's API is OpenAI-compatible). Endpoint URL, auth header, request shape and model name are checked against TypeSafe's API reference. The key lives in the key file `src/conf/keys/typesafe-api-key` (provisioned by Rick with E2), loaded through `du.get_api_key` from the data root (see section 4; keys are never linked into worktrees), not from an environment variable: the cosa-voice STDIO subprocess inherits only its seat's environment. A missing or unreadable key is diagnosed in the style of `src/lupin_mcp/outbound_api_key.py`, and the verdict is UNCERTAIN_READ_SOURCE with the cause KEY_UNREADABLE, never an empty NEW.
2. Keep the pinned model in config. The client refuses a `-latest` model name.
3. Send only what the spec allows: signatures, first docstring lines and L0 lines. An exclusion list in config removes sensitive modules from the index before anything is sent; the implementer drafts it and Rick approves it inside E2. A unit test captures every outbound payload in the fake and asserts that only allowlisted fields go out, each line within a maximum length, and that no excluded module's text appears, with a positive control (an excluded fixture module that must be absent, and a non-excluded one that must be present). This is a deliberate narrowing of spec 2 line 128 ("docstrings"); E2 approval covers the narrow set only.
4. Treat a failed call as a failed question: if any call in a sweep fails after retries, the verdict is UNCERTAIN_READ_SOURCE, never NEW.
5. Measure: calls, latency and cost per `check_exists` on the real index. The Stage 2 review measured about 5,700 entries at `dfc2743be` (5,013 public Python definitions plus 669 found by regex in JS and TS), so a sweep is about 5,700 calls, about 178 rounds at 32 concurrent; at an assumed 1 to 3 seconds per call that is 3 to 9 minutes per question, and a diff with 10 new definitions is about 57,000 calls. The gate has a budget: at most 60 seconds of wall clock per `check_exists` (the author's starting value), and a cost ceiling that Rick sets with the E2 approval. The fallback order is fixed in advance and chosen by the measured number: if the sweep is over budget by up to 10 times, add the spec's L0 step (Jev picks L1 pages first) and re-measure; if it is still over budget, or over by more than 10 times, go to E13 (an embedding pre-filter). The L0 step is added and re-measured when the sweep is over budget, while keeping the spec's rule that the L2 sweep is not pruned for the areas selected. A local embedding shortlist in front of Jev was not adopted: the spec rules embeddings out on purpose (spec line 24: "no embeddings and no vector store to go stale"), even though lupin already has a pgvector cache (`src/cosa/memory/embedding_cache_table.py`, `/api/embeddings`). Decision E13 asks whether to revisit that.

Plan 1's claim judge does not use this client by default: it needs yes/no answers on full text, which is more than this plan sends to TypeSafe (plan 1, D3).

Tests: unit tests against a fake keyed on the request hash that asserts the request body, so a client that builds the request wrongly fails; one fixture in it is captured from a real Jev call once E2 allows (a hand-written response is tidier than the real one); partial failure included; 100% line, branch and function coverage, with `# pragma: no cover` and a reason only on the live-only line; one live test behind a new registered pytest marker, excluded by default like the existing `embedding_cost_live`, checking repeat agreement. "Identical" means the same verdict and the same shortlist entries above 0.5. Spec 2's evidence is 96 of 96 identical decisions, which still allows a true flip rate near 3% (95% bound), and a sweep makes thousands of calls, so a few flips are expected and one at the 0.9 threshold changes a verdict. The live test therefore measures the flip rate over repeated sweeps of a fixed set of at least 30 needs, including seeded known-duplicate and known-distinct ones, written by a seat that has not seen Jev's output, each run at least 5 times. The flip rate is the fraction of needs whose verdict differs between any two repeats. The pass rule is a flip rate at or below 5% (the author's starting value until W-A measures it), reported with its upper bound. A 5% flip rate means roughly one review in twenty could get a different verdict, which E10 must take into account. The test makes real API calls, so it runs on `:8000` as a scheduled suite, like the other real-spend suites, within the spend ceiling Rick sets with E2. If Rick sets no ceiling, the live test does not run and this gate stays open (EXECUTOR: HUMAN, design authority). Replay at frozen inputs reads the cached answers and is deterministic regardless.

Exit gate (EXECUTOR: AI, once the handoff above is done): a live call works against the pinned model; the measured flip rate is within the pass rule; the per-question cost and latency are reported and within the budget in step 5, or the fallback order in step 5 has been applied and re-measured.

## 4. Phase W-B: index, duplicates and wiki lint

Harden `symindex.py` and `wiki_lint.py` into an importable package at `src/cosa/repo/symindex/`, next to the existing repo analyzers, with the CLI beside the package (`python -m cosa.repo.symindex build`), as `run_branch_analyzer.py` sits beside the analyzers in `src/cosa/repo/`. The location is decided here so the MCP tools in W-C can import it without the `sys.path` insertion lupin's path rule forbids.

- Routes: the prototype keeps only the first argument of each route decorator, so a route on a prefixed router loses its prefix (for example `@router.post( "/notify" )` on `APIRouter( prefix="/api" )` would be indexed as `/notify`, not `/api/notify`). The index reads the `prefix=` literal on each `APIRouter( )` construction (18 of 38 in `src/cosa/rest/routers/` set one, measured 2026-09-30, and `main.py`'s `include_router` calls carry none) plus any `include_router( x, prefix= )`, by AST. It does not read the app's route table, because that would mean importing `lupin_app.main` inside the cosa-voice server, which is heavy and has import side effects.
- Generated files: `.gitignore` gets an entry for `src/docs/index/` (not for `src/docs/wiki/`, which is committed); no such rule exists today, so the first `build` would dirty every seat's tree.
- Two roots. The index root is the git toplevel of the server's working directory (or a `root` tool argument), not `LUPIN_ROOT`: it is the code being asked about. This is a recorded exception to lupin's path rule, for this server only, because cosa-voice is registered at user scope with `LUPIN_ROOT` and the interpreter pointing at the main checkout, and it serves every repo, so `cu.get_project_root()` would make a worktree seat index main and a seat in another repo get lupin's index. A working tree that is not lupin returns the cause NOT_LUPIN_TREE. The data root is `LUPIN_ROOT` (through `cu.get_project_root()`): the key file, receipts, snapshots, the response cache and the call log live under it, because keys are never linked into worktrees and a reap deletes a worktree together with anything written there. No path uses `__file__` chains. Tests: a worktree seat's `index_sha` differs from main's, and a receipt written by a worktree seat is readable from main. A lupin-mobile index (W-H) is a different index root.
- Concurrent writers: each seat runs its own server, and two seats on the main checkout share one `src/docs/index/`. `build` writes to a temporary file and then `os.replace`s it, under an `flock` around the rebuild, so a reader never sees a half-written index and `index_sha` is never taken over a torn file. The call log is an `O_APPEND` JSONL file under the data root, one line per call. Receipts are written by temporary file and rename, and are content-addressed, so a duplicate write is harmless. Tests: two processes rebuilding at once, with a read that must never see a partial file.
- Freshness: the check uses the same file population as `build` (one shared `_files()`, with the same skip list for `.venv`, tests and `src/rnd`) and compares a manifest (a hash of the path and mtime set). That also catches added and deleted files, which the prototype's check misses, and it stops an edit under `src/rnd` or in a test from triggering a rebuild.
- TypeScript and JavaScript through a real parser, chosen by the E3 comparison (py-tree-sitter or the TypeScript compiler already in the repo), with JSDoc first lines and pins, so JS pages can be linted.
- `dups`: keep the exact structural pass; add a near pass (token shingles) and report both.
- `diff`: public symbols added, removed or changed between two index snapshots. `diff --all` lists every definition, including `_private` and nested helpers, which the public-symbol index skips; W-F uses it.
- `grimp` import-graph grouping as the fallback for W-D when package prefixes do not match capabilities, as the spec suggests.
- `wiki_lint.py` moves here from the spec's librarian phase, because W-D's exit gate needs it. Orphans are reported per package with a count, not per symbol, until a package has at least one capability page.

Tests: a prefixed-router fixture whose indexed route must include the full prefix, built from a real router and from `src/cosa/rest/v2` as well as an invented one; fixtures with an exact clone, a renamed clone and a distinct look-alike; pin stability under docstring and whitespace edits; pin change under a one-token code edit; TypeScript fixtures with class methods, typed arrow functions and generics; a fixture wiki with one seeded finding per `wiki_lint.py` check (stale, dangling, orphan, unindexed), each asserted to fire; 100% line, branch and function coverage.

Exit gate (EXECUTOR: AI): the index lists every public symbol in the fixture repo, and at the pinned lupin HEAD it matches an independent count on a random sample of at least 30 modules (chosen by a seat, seed recorded, counted by a different route, such as `inspect` or the compiler API over the same files, or a grep-and-read by a seat that has not seen the index; pass means an exact per-module match, with mismatches listed); `wiki_lint.py` fires on every seeded finding, and the run on an empty wiki is kept only as a no-crash check. The duplicate report is saved with its provenance stated: it holds structural clones only, so it is not the evaluation set by itself. Before W-E uses it, a separate set of hand-found near-duplicates is built by a seat that has not seen the tool's output, and the near-pass threshold and how its precision is measured are stated.

## 5. Phase W-C: reuse tools in cosa-voice

Per Rick's ruling, the tools are mounted on the existing server, in the shape `task_store_tools.py` already sets: thin `@mcp.tool` wrappers in `cosa_voice_mcp.py` over `*_impl` functions in a sibling module (`src/lupin_mcp/reuse_tools.py`), which imports the index from `src/cosa/repo/symindex/` (section 4). The wrappers import that module lazily, so a reuse failure cannot stop the voice tools from loading. The prototype's `register( mcp )` hook is not used as written; its tool logic moves into the `*_impl` functions.

The index build and the freshness check do blocking file and AST work. They run in a thread executor, never directly inside an async tool, because one blocked verb starves every other verb in the seat's single STDIO process (`test_the_human_waiting_asks_do_not_starve_the_loop.py` proves this for the existing tools). The reuse tools get the same heartbeat-shaped test.

| Tool | Behaviour |
| --- | --- |
| `check_exists(need)` | Verdict REUSE, EXTEND, NEW or UNCERTAIN_READ_SOURCE, a shortlist, and a receipt ID. UNCERTAIN_READ_SOURCE always carries a `cause` field beside the verdict, stored in the receipt: LOW_CONFIDENCE (any confidence below 0.9), CALL_FAILED (any failed call), KEY_UNREADABLE, DEPENDENCY_MISSING, NOT_LUPIN_TREE or INDEX_STALE |
| `fetch_similar(entry)` | Shortlist for a new definition, excluding the definition itself by symbol ID, not by splitting text |
| `read_capability(names)` | L1 pages; no Jev call |
| `replay(receipt_id)` | The stored result, a re-run against the frozen inputs, and a re-run at HEAD, with the differences |

Receipts and replay:

- `index_sha` covers everything `check_exists` reads: `symbols.md` and the L0 `INDEX.md` lines. Otherwise a librarian edit to L0 changes the answer that "replay at the frozen index" gives.
- Jev responses are cached by request hash, so replay at frozen inputs returns the cached answer, and the re-run tests only whether the model still agrees.
- The receipt ID is a hash of tool, query, `index_sha`, model and threshold, as the spec defines. Two callers asking the same question against the same inputs share a receipt, which keeps a list of callers and times.
- Snapshots and receipts are content-addressed, compressed and stored outside git (E4), under one shared data directory, below the data root from section 4, that every seat's server writes to (named in E4). Content-addressed files are written by temporary file and atomic rename, so concurrent writers cannot corrupt one another.
- Dependencies: the cosa-voice server runs in a light venv built from `CC_VENV_REQS` in `src/scripts/install-cosa-voice.sh` (today `fastmcp requests pydantic regex pytz`, with the note that everything else is stdlib or in-repo), and `tree_sitter` and `grimp` are not in it. W-C adds whatever packages the chosen parser (E3) and the `grimp` fallback need to `CC_VENV_REQS` and `pyproject.toml`; a Node-based parser (E3 option 1) needs `node` on the host instead. When a dependency is missing, the tool returns UNCERTAIN_READ_SOURCE with the cause DEPENDENCY_MISSING, never an empty NEW, and a test runs against a clean venv closure. The lazy import keeps the voice tools alive, but without this the reuse tools would be silently dead and a fresh host would never get them.
- The freshness check is the manifest comparison in section 4, so it catches deleted and added files, not only newer ones. A stale index that cannot be rebuilt returns the cause INDEX_STALE.
- Every call is logged server-side (tool, caller, receipt ID, time), so coverage does not rest on the caller's own logging (E7). The hook is a second FastMCP middleware added beside `BridgeLivenessMiddleware` (`mcp.add_middleware( ... )` in `cosa_voice_mcp.py`), so no tool writes its own log. Each seat runs its own STDIO server process, so there are as many servers as seats: each server appends to its own per-session JSONL file under the shared data directory (E4), and the W-F gate script merges those files at read time. One log file per server, read alone, would show only that seat's calls and report false gaps.

A fix to these tools reaches a seat only when its MCP server restarts; a `/clear` does not reload it. Merge announcements say so.

Tests: unit tests per tool with the request-keyed fake Jev from section 3; replay determinism; each UNCERTAIN path (low confidence, partial failure, missing key, missing dependency, non-lupin tree, stale index), each asserting its `cause` and not only the verdict, since a test that checks only the verdict passes on any of the six; an L0 edit changing `index_sha`; the missing-dependency UNCERTAIN path against a clean closure; two servers writing receipts and log lines at once; a negative test that makes the reuse import raise and asserts cosa-voice still starts and a voice tool answers; an integration test that starts cosa-voice over STDIO and calls each reuse tool alongside an existing voice tool.

Tests that write receipts, logs or snapshots use a temporary data directory injected through config, so they are `:7999`-eligible and leave no persistent state; 100% line, branch and function coverage.

Exit gate (EXECUTOR: AI): (i) a stored result is byte-equal after a process restart; (ii) the receipt ID recomputed from tool, query, `index_sha`, model and threshold equals the stored ID; (iii) a corrupted cache entry and a missing entry each return a named error rather than a verdict; and the voice tools still pass their existing tests. Checks (ii) and (iii) are proved by mutation: edit one input, or corrupt the entry, and name the test that reddens.

## 6. Phase W-D: wiki bootstrap (= plan 1, Phase 4)

1. Group `symbols.md` by package prefix and route prefix; use `grimp` where those do not match capabilities.
2. The librarian proposes, per group: slug, one-line purpose, covered symbols, canonical entry point.
3. Rick approves or renames the slugs. This is the only human step in W-D (EXECUTOR: HUMAN, design authority).
4. The librarian writes `src/docs/wiki/capabilities/<slug>.md` for the worst areas first (from the duplicate report), puts the `symbol@hash` pins in the page's frontmatter (where `wiki_lint.py` reads them), and adds the line to `src/docs/wiki/INDEX.md`.
5. Every public symbol without a first docstring line gets one, to plan 1's standard. Split with plan 1's Phase 5 sweep: this step only adds missing first lines, and never rewrites an existing docstring (that is the sweep's job). Both use the lock in plan 1, section 8 (a task-store row per package, backed by a branch per package, checked with `task_query` before touching it), so one of them owns a package at a time; if the sweep reaches the package first, it adds the missing lines in the same pull request and this step skips it.
6. Existing `src/docs` reference pages become capability pages where they describe a capability. This phase converts them; plan 1's Phase 4 owns the pages that are not capability pages, and the CLAUDE.md template (plan 1, section 7).

`src/docs/wiki/INDEX.md` is linked from `src/docs/README.md`, which stays the index of record for every doc in `src/docs` and its verification dates.

Page format: the spec's L1 fields (intent, canonical entry point, how to extend, "don't" rules, invariants, `covers:` pins) within plan 1's 40-line capability template.

Exit gate: slugs approved (EXECUTOR: HUMAN, design authority); every package that holds a member of a cluster in the duplicate report has a capability page, or the gap is listed (the report lists function clusters, so this is the mapping from cluster to page); `wiki_lint.py` reports no stale, dangling or unindexed pages; and the checks below (EXECUTOR: AI), together with the full unit tier green on the changed tree (plan 1, section 7). `wiki_lint.py` proves pins and links, not content, so a second seat that is not the librarian and has not seen the author's output samples at least 20 pages against the source, and the pass rule is zero false invariants or "don't" rules, with every finding listed. Step 5 is gated by the index: public symbols without a first docstring line are zero in every package this phase touched (195 of 5,013 lacked one at the Stage 2 measurement).

## 7. Phase W-E: baseline recall

The evaluation set is the structural-clone report from W-B plus the separately built set of hand-found near-duplicates, since clones the AST finder cannot see (same behaviour, different vocabulary) would otherwise be missing from the denominator. For each duplicate cluster, a seat that has not seen the other members (or the target's docstring) describes one member as a need, so the need does not borrow the target's vocabulary; exact-clone clusters share names too, so easy hits would otherwise dominate the headline. `check_exists` is called from the tree under test (the tools index the git toplevel of the server's working directory, section 4), and recall is measured at K = 10: how often the other members appear in the top 10 of the shortlist. Recall is reported separately for the structural clones and for the hand-found set, each with a 95% interval, overall and per package, with the misses listed. Before the first measurement the clusters are split into a repair set and a held-out set; the librarian repair below only touches the repair set, and Rick's E10 decision rests on the held-out recall alone, so repairing the failed clusters cannot raise the number by construction.

Cost: W-E makes one `check_exists` per cluster member, so its call budget is the number of members times the per-question calls measured in W-A (an unpruned sweep is about 5,700 calls and 3 to 9 minutes per question, which is hours of wall clock for a full run). W-E therefore runs after the W-A fallback decision (the L0 step, or E13), not before it, and states its call count and wall-clock estimate before it starts. The live spend is within the ceiling Rick sets with the E2 approval.

Exit gate: the held-out recall at K = 10, with its interval and the repair-set figure, is reported (EXECUTOR: AI). Rick decides whether the held-out number is high enough to wire the tools into review (E10) (EXECUTOR: HUMAN, design authority). If not, the repair-set misses go through the librarian repair (W-G, run by hand) and the test repeats on the held-out set.

## 8. Phase W-F: review integration

1. Reuse-reviewer skill (`.claude/skills/reuse-reviewer/`): for each new definition in a diff, calls `fetch_similar`, reads the capability pages on the shortlist, reads source only for shortlisted or uncertain candidates, and rules DUPLICATE, EXTEND `<symbol>` or DISTINCT `<why>`, citing a receipt. The skill holds the one table that maps the three vocabularies in use, so a receipt cited in a plan's prior-art table needs no translation:

| `check_exists` verdict | `plan-review.md` section 4 prior-art label | Reuse-reviewer ruling |
| --- | --- | --- |
| REUSE | reuse-as-is | DUPLICATE |
| EXTEND | extend-existing | EXTEND `<symbol>` |
| NEW | genuinely-new | DISTINCT `<why>`, only after the reviewer has read the shortlist's source; a NEW verdict does not rule DISTINCT by itself |
| UNCERTAIN_READ_SOURCE | none yet: read the source first | the reviewer rules only after reading the candidates |

The skill also runs plan 1's linters and `prose_judge.py`, and rejects a diff that fails them. Whether a failure blocks is set by one config flag, `reuse review gating` (default `false` until E10 is decided), which the skill reads; while it is false the skill reports findings and does not reject, and a test flips the flag and asserts both behaviours.
2. Implementer rule: plans record `reuses:`, `extends:` or `rejected: <symbol> because <reason>`, each with `reuse-receipt: <id>`, and call `check_exists` again when an unplanned helper appears during the build. Private and nested helpers are in scope: the unplanned helper is usually a `_private` function, which the public-symbol index skips, so the diff side of the gate uses `symindex diff --all` (section 4).
3. Plan review: the reuse pre-pass in `planning-is-prompting/workflow/plan-review.md` section 4 requires receipts. That change is made in the planning-is-prompting repo.
4. Counter-reviewer (E8, either as a new optional role or as a second Reviewer instance with a replay brief): runs `replay` on the reviewer's receipts and reads the source of any candidate the reviewer dismissed.
5. Citation rule: an assertion without a receipt is challenged, and the gate script below is the enforcer.

Exit gate (EXECUTOR: AI): on the first two real crew runs with the skill, which together contain at least 10 new definitions (so a near-empty diff cannot pass), a script compares the merged per-session call logs (section 5) and the review documents with the new definitions in each diff (from `symindex.py diff --all`). Each new definition must have a `fetch_similar( entry )` call keyed on its symbol ID and a ruling in the review document that cites that receipt. A matched log line proves a call happened; the cited ruling proves the reviewer used it.

## 9. Phase W-G: librarian loop

- Queue: lint findings and misses become task-store rows (E6). The librarian is a role, not a persona name: the manager assigns it to a pool persona at spawn, and that persona is the rows' `owner_persona`. The store rejects a create whose `correlation_key` does not start with `epic:` (`src/cosa/rest/task_store_rules.py`), so all librarian rows share one key, `epic:wiki-librarian`, and per-page and per-package deduplication is done on the row title or body (orphans are batched per package). The crew confirms the key rule against the live API before building the queue. The store also runs a closed-versus-new ratio gate (`task flow ratio enforcement active = True` in `lupin-app.ini`; 24-hour window, fleet-wide, only `done` counts as closed, P0 exempt), which can refuse new rows on a day the fleet has closed fewer than it created. So row creation is bounded. A miss gets its own row (misses are few and valuable), and lint findings are batched into one rollup row per package, updated with `task_amend` rather than re-created; the E11 consolidation tickets are subject to the same gate and follow the same refusal handling. On a ratio refusal the finding goes to a pending file under the data root (section 4), which is retried on every tick, so a process restart loses nothing; the refusal is written to `librarian.log` under the data root and raised with `notify()` to the owning manager, which is the place a person reads. The test feeds a 422 refusal, restarts the process, and asserts that the finding survives and is created on the next tick. Rollup rows never reach `done` by themselves; the librarian closes a package's rollup when the package's findings are cleared.
- Miss record: the task-store row is the record (receipt ID, symbol that should have matched, who caught it, repaired or not), carried in a machine-parseable block (a fenced JSON block) in the row body, so a miss is never folded into a rollup. `src/docs/wiki/misses.jsonl` is exported from the store by the daily tick from those blocks, so seats never write the file concurrently.
- Repair check: after rewriting a summary, the librarian replays the original receipt at HEAD. Because a live replay goes through Jev, where the flip rate (E10) can put the symbol on the shortlist with no repair at all, the before and after states are each replayed R times (R = 5): the repair is done when the missed symbol is absent from the shortlist in all R runs before the rewrite and present in all R after it. Each repaired miss becomes a regression case, but it runs in the scheduled live tick, not the unit tier: a unit test can only replay the cached post-repair answer, which never reads the current wiki, so a later wiki edit that re-breaks the match would leave it green. The unit tier covers the harness only.
- Cadence: a daily lint from a real crontab entry, plus on-demand runs from a manager. The host is usually off between 11 PM and 10 AM EDT (`CLAUDE.md` off-peak rule), so the tick is set inside the 10 AM to 1 PM window, or has a catch-up run on the first tick after boot. The entry is installed in the shape of `planning-is-prompting/workflow/scripts/install_context_pressure_tick.py` and through `crontab_lock.py`, since two installers raced on the crontab once (lost update, 2026-09-23) and a hand-rolled `crontab -` edit would reopen that. The fleet's ticks were paused by broadcast on 2026-09-06, so the installer copies how the existing ticks honor that pause; a new tick that ignores it is a defect. So while the fleet pause is in force the new tick is paused too, by design.
- Clone check: lupin has no CI (no `.github/workflows`), and its merge gate is the pyramid, whose membership is guarded in four places (`ALL_SUITE_COMPONENTS` in `test_suite/job.py`, the `CLAUDE.md` gate table, the marker, and `test_typescript_suite_gate`). So `symindex.py dups` runs as part of the daily tick, not as a per-merge gate. A new clone whose receipt said NEW is recorded as a miss and gets a consolidation ticket (E11); the tick finds the receipt by looking the new definition's symbol ID up in the receipt store (E4) and the call log. Alternative: a named pyramid component with all four places updated.

Exit gate (EXECUTOR: AI): one observed scheduled run of the tick (a log line with the time and exit 0), not just a crontab entry; if the fleet pause is still in force the gate is met by an on-demand manager run and the scheduled run stays recorded as pending until the pause is lifted (EXECUTOR: HUMAN, the pause is Rick's). One known miss is seeded to prove the loop end to end (inject, detect, repair, verify by the R-fold replay above), so the gate does not pass vacuously when W-E and W-F produced none. Real misses are then repaired and verified the same way, and their regression cases run in the scheduled live tick.

## 12. Risks and guardrails

| Risk | Mitigation |
| --- | --- |
| Signatures and docstrings leave the machine | Only signatures, first docstring lines and L0 lines are sent; exclusion list; Rick approves the egress (E2) |
| A full sweep is too slow or costly per question | Measured in W-A; the L0 selection step if needed |
| A partly failed sweep reads as NEW | Any failed call makes the verdict UNCERTAIN |
| Jev judges equivalence poorly | Jev only builds shortlists; every DUPLICATE or DISTINCT ruling comes from a reviewer reading source, including a NEW verdict, which does not rule DISTINCT until the shortlist's source is read (section 8 table) |
| Prompt injection through agent-written docstrings | The reviewer keeps the final say; plan 1's `docstring_lint.py` has a rule that flags imperative text addressed to a model (plan 1, section 4.1) |
| Replay drifts after wiki edits | L0 included in `index_sha`; cached Jev answers |
| A reuse bug stops cosa-voice loading | Lazy import; reuse failures are caught at registration; a negative test makes the reuse import raise and asserts that cosa-voice still starts and a voice tool answers |
| Worktree seats index the wrong tree | Index root is the git toplevel of the server's working directory, not `LUPIN_ROOT` (section 4); a test checks it |
| The orphan list floods the queue | Orphans batched per package |
