# Bug Investigation: Math Agent TTS Not Working

**Document**: Research & Root Cause Analysis
**Session**: 108 (2026.01.29)
**Author**: Claude Code + User Investigation
**Status**: Root cause identified, fix designed

---

## 1. Executive Summary

Math jobs complete successfully but produce no TTS audio. Mock jobs DO produce TTS. Investigation revealed two distinct issues:

1. **Race Condition** (Fixed): `associate_job_with_user()` called after `push()` - consumer thread could grab job before user mapping existed
2. **Missing user_email Attribute** (Root Cause): Math agents lack `user_email` attribute that mock jobs have, causing TTS to route to wrong user

---

## 2. Problem Description

### 2.1 Symptoms

- Math questions (e.g., "What is 2+2?") complete successfully with correct answers
- Job state transitions work: `pending → todo → run → done`
- Response text shows in UI: `response_text: '4'`
- **NO TTS audio plays**

### 2.2 What Works

- Mock jobs produce TTS audio correctly
- WebSocket events fire correctly
- Job cards appear and transition correctly
- Answers are computed and returned

### 2.3 Reproduction Steps

1. Log in as any user
2. Submit math question via UI or CURL
3. Observe: job completes, answer shown, NO TTS

## 3. Investigation Process

### 3.1 Initial Theory: Race Condition

**Hypothesis**: Consumer thread grabs job before `associate_job_with_user()` is called, so `_notify()` can't find user mapping.

**Code pattern identified** (4 locations):
```python
# PROBLEMATIC PATTERN
todo_queue.push( job )  # Consumer may grab NOW
user_job_tracker.associate_job_with_user( job.id_hash, user_id )  # TOO LATE!
```

**Timeline of race condition**:
```
Thread 1 (API)                    Thread 2 (Consumer)
─────────────────                 ─────────────────
push( job )
                                  job = todo_queue.pop()
                                  running_queue.push( job )
associate_job_with_user()         _handle_solution_snapshot()
(tracker now has mapping)         _notify() → tracker lookup FAILS
```

**Fix implemented**: Move association BEFORE push in all 4 locations.

**Result**: Race condition fixed, but TTS still not working.

### 3.3 Tracing the Notification Flow

**Call chain for TTS**:
```
Job completion
  ↓
RunningFifoQueue._handle_solution_snapshot() or _handle_base_agent()
  ↓
self._notify( msg, job=running_job )  [running_fifo_queue.py:462,264,585]
  ↓
_notify() creates AsyncNotificationRequest  [fifo_queue.py:513-563]
  ↓
target_user = self._get_target_user_email( job )  [fifo_queue.py:552]
  ↓
notify_user_async( request )  [fifo_queue.py:556]
```

**The critical function** (`_get_target_user_email()` at `fifo_queue.py:465-511`):
```python
def _get_target_user_email( self, job: Any ) -> str:
    if job:
        # PATH 1: Check for email stored directly on job
        if hasattr( job, 'user_email' ) and job.user_email:
            return job.user_email  # ← MOCK JOBS RETURN HERE

        # PATH 2: Check for email in metadata dict
        if hasattr( job, 'metadata' ) and isinstance( job.metadata, dict ):
            if 'user_email' in job.metadata:
                return job.metadata[ 'user_email' ]

        # PATH 3: Try to resolve email from user_job_tracker (legacy path)
        if hasattr( job, 'id_hash' ):
            user_id = self.user_job_tracker.get_user_for_job( job.id_hash )
            if user_id:
                try:
                    from cosa.rest.user_service import get_user_by_id
                    user_data = get_user_by_id( user_id )
                    if user_data and user_data.get( "email" ):
                        email = user_data[ "email" ]
                        print( f"[NOTIFY] Resolved email from user_id: {email}" )
                        return email
                    else:
                        print( f"[NOTIFY] user_service returned no email for user_id={user_id}" )
                except Exception as e:
                    print( f"[NOTIFY] Failed to look up email for user_id={user_id}: {e}" )

    # PATH 4: Fallback to default email (WRONG USER!)
    return "ricardo.felipe.ruiz@gmail.com"
```

### 3.4 Root Cause Identified

**For mock jobs**: Path 1 succeeds → `job.user_email` exists → TTS routes to correct user

**For math jobs**:
1. Path 1 fails → no `user_email` attribute
2. Path 2 fails → no `metadata` dict with email
3. Path 3 may fail → tracker lookup or user service lookup
4. Path 4 returns default → TTS routes to `ricardo.felipe.ruiz@gmail.com` (wrong user!)

**Why Path 3 might fail**:
- Even with race condition fixed, the job passed to `_notify()` might not be the original agent
- For cache hits (SolutionSnapshot), the id_hash might differ from what was associated
- The `get_user_by_id()` might fail or return no email

## 5. The Fix

### 5.1 Design Principle

Set `user_email` attribute on agents at creation time, matching how mock jobs do it.

### 5.2 Implementation Plan

#### Step 1: Look up user_email in push_job()

**Location**: `src/cosa/rest/todo_fifo_queue.py`, after line 330 (start of `push_job()`)

```python

    user_email = None
    try:
        from cosa.rest.user_service import get_user_by_id

## 9. Related Background

### 9.1 TTS Migration (Session 97-98)

The notification system was migrated from `_emit_speech()` callback to `_notify()` using `notify_user_async()`. The new system:
- Uses `AsyncNotificationRequest` model
- Calls `/api/notify` endpoint
- Supports job_id routing to job cards
- Supports suppress_ding for conversational flow

### 9.2 Compound Hash (Session 108)

Job id_hash now includes user_id for user-scoped identification:
- Same user, same question = same hash (idempotent)
- Different users = different hashes (no collision)
- Database can extract base hash for persistence

### A.3 _get_target_user_email() Full Implementation

# src/cosa/rest/fifo_queue.py:465-511
def _get_target_user_email( self, job: Any ) -> str:
    """
    Get target user email from job metadata for notification routing.
    """
    if job:
        # Check for email stored directly on job (set during push)
        if hasattr( job, 'user_email' ) and job.user_email:
            return job.user_email

        # Check for email in metadata dict
        if hasattr( job, 'metadata' ) and isinstance( job.metadata, dict ):
            if 'user_email' in job.metadata:
                return job.metadata[ 'user_email' ]

        # Try to resolve email from user_job_tracker (legacy path)
        if hasattr( job, 'id_hash' ):
            user_id = self.user_job_tracker.get_user_for_job( job.id_hash )
            if user_id:
                try:
                    from cosa.rest.user_service import get_user_by_id
                    user_data = get_user_by_id( user_id )
                    if user_data and user_data.get( "email" ):
                        email = user_data[ "email" ]
                        print( f"[NOTIFY] Resolved email from user_id: {email}" )
                        return email
                    else:
                        print( f"[NOTIFY] user_service returned no email for user_id={user_id}" )
                except Exception as e:
                    print( f"[NOTIFY] Failed to look up email for user_id={user_id}: {e}" )

    # Fallback to default email
    return "ricardo.felipe.ruiz@gmail.com"
```
