# Runtime Argument Expeditor - Design Document

**Date**: 2026-02-04
**Status**: READY TO IMPLEMENT
**Project**: [LUPIN]

---

## Goal

Create a runtime argument expeditor that sits between LORA intent classification and agentic job creation. When a user says something like "make me a podcast", the LORA model identifies the command (`agent router go to podcast generator`) but may not capture all required arguments. The expeditor detects missing args by comparing the user's input against each agent's `--help` output via an LLM, then asks the user for missing information via synchronous voice notifications before creating the job.

**Scope**: Deep Research, Podcast Generator, Research-to-Podcast (3 agents only).

---

## Architecture

```
Voice Input -> LORA Router -> (command, args)
                                  |
                          Is it agentic? --No--> existing elif chain (unchanged)
                                  |
                                 Yes
                                  |
                    RuntimeArgumentExpeditor.expedite()
                                  |
                     +-------------+-------------+
                     | 1. Run --help on target   |
                     | 2. LLM gap analysis       |
                     | 3. Ask user for missing   |
                     |    args (sync notify)     |
                     | 4. Return complete args   |
                     +-------------+-------------+
                                  |
                    Create Job -> Push to Queue
```

---

## Key Design Decisions

1. **`--help` captured at runtime** via subprocess, cached per-process-lifetime (dict). Stays current as CLIs evolve. 10s timeout with fallback to static registry.

2. **Synchronous flow** - `push_job()` in `todo_fifo_queue.py` is synchronous. The disambiguation agent uses `notify_user_sync` (SSE-blocking) for user interaction, same pattern as existing sync notifications in the queue.

3. **LLM does gap analysis only** - determines which required args are present/missing. The actual questions to ask come from a static registry (deterministic, not hallucinated).

4. **Podcast file path** uses existing fuzzy file matching (`FuzzyFileMatchResponse` + `fuzzy-file-matching.txt` prompt) already built for the podcast generator description mode.

5. **Config flag** to enable/disable (`runtime argument expeditor enabled = true`).

6. **System-provided args** (user_email, session_id, user_id, no_confirm) are injected from the HTTP context, never asked for.

## Phase 2: LLM Response Model

### New file: `src/cosa/agents/runtime_argument_expeditor/xml_models.py`

A `ExpeditorResponse` Pydantic XML model (extending `BaseXMLModel` from `src/cosa/agents/io_models/xml_models.py`):

```xml
<response>
    <all_required_met>false</all_required_met>
    <args_present>query=biodiversity loss</args_present>
    <args_missing>budget</args_missing>
</response>
```

Fields: `all_required_met` (str "true"/"false"), `args_present` (str), `args_missing` (str, comma-separated).

The LLM determines which required args are satisfied. The static registry provides the questions to ask for any missing ones.

## Phase 3: Core Expeditor

### New file: `src/cosa/agents/runtime_argument_expeditor/expeditor.py`

**Class**: `RuntimeArgumentExpeditor`

**Constructor**: Takes `config_mgr`, `debug`, `verbose`. Creates `LlmClientFactory`.

**Main method**: `expedite( command, raw_args, user_email, session_id, user_id, original_question )`

Flow:
1. Look up `command` in `AGENTIC_AGENTS` registry
2. Call `get_cli_help( command )` to capture `--help` output
3. Parse LORA raw_args string into dict (e.g., `topic="foo"` -> `{"topic": "foo"}`)
4. Map LORA arg names to CLI arg names via `arg_mapping`
5. Build LLM prompt: `--help` output + original voice command + mapped args + system-provided list
6. Call LLM (spec key from config: `llm spec key for runtime argument expeditor`)
7. Parse `ExpeditorResponse` from LLM output
8. If `all_required_met == "true"` -> return mapped args dict with original voice values
9. If args are missing -> for each missing arg:
   - If `special_handlers` has a handler for this arg (e.g., `fuzzy_file_match`) -> run that
   - Otherwise -> call `notify_user_sync` with the `fallback_questions[arg]` question, `response_type="open_ended"`
   - Store user's response in args dict
10. Return complete args dict (or `None` if user cancels/times out)

**Helper methods**:
- `_parse_lora_args( raw_args_str )` - regex parser for `key="value"` and `key=value` patterns
- `_ask_for_arg( arg_name, question, user_email )` - wrapper around `notify_user_sync`
- `_handle_fuzzy_file_match( user_email )` - reuses `FuzzyFileMatchResponse` + fuzzy matching prompt to match user description to research doc files on disk

**Smoke test**: `quick_smoke_test()` at bottom testing imports, arg parsing, registry lookup, help capture.

## Phase 7: Integration into TodoFifoQueue

### Modify: `src/cosa/rest/todo_fifo_queue.py`

**Minimal changes** (3 additions):

1. **New imports** (top of file):
```python
from cosa.agents.runtime_argument_expeditor.agent_registry import AGENTIC_AGENTS

```

2. **New elif branch** inserted before the `else` on line 643:
```python
elif command in AGENTIC_AGENTS:
    msg = self._handle_agentic_command(
        command, args, user_id, user_email, websocket_id, salutation_plus_question
    )
```

3. **Two new methods** added to `TodoFifoQueue`:

`_handle_agentic_command( self, command, raw_args, user_id, user_email, session_id, original_question )`:
- Checks if expeditor is enabled (config flag)
- Creates `RuntimeArgumentExpeditor` instance
- Calls `expedite()` -> gets complete args dict or None
- If None -> notify cancellation, return
- Calls `_create_agentic_job()` to build the right Job object
- Associates job with user via `user_job_tracker`
- Pushes job to queue
- Notifies user of submission

`_create_agentic_job( self, command, args_dict, user_id, user_email, session_id )`:
- Factory method with 3 branches matching the 3 commands
- Creates `DeepResearchJob`, `PodcastGeneratorJob`, or `DeepResearchToPodcastJob`
- Passes system-provided args (user_id, user_email, session_id, no_confirm=True)
- Passes user-provided args from expeditor

## Risks & Mitigations

| Risk | Mitigation |
|------|-----------|
| LORA doesn't recognize new commands yet | LLM fallback router handles them from updated prompt template |
| `--help` subprocess hangs | 10s timeout, fallback to static `required_user_args` from registry |
| Sync notification blocks push_job thread | Each question has a timeout (configurable, ~60s default). Timeout -> cancel job |
| LLM hallucinates arg analysis | LLM only determines present/missing. Questions come from static registry (deterministic) |
| Podcast fuzzy file match fails | Falls back to asking user for exact path |
