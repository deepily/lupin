|---|---|---|
| **A. New deterministic `comment_lint` rules** (commented-out code, `file:NNN` pointers, TODO without owner) | Free to run, fits the existing gate and its counted-scope table, no model spend. | **B. A judged pass, like the docstring claim judge** | The only way to find stale comments and to rank restating by how little it adds | Unproven payoff: one stale comment in 120, so a pass over 33,363 lines pays to confirm a rate near 1%. **Recommendation: A, in a reduced form.** Start with `file:NNN` pointers and commented-out code (the two with a measured harm: a wrong pointer misleads, and dead code reads as live), plus unowned TODO if Rick wants it (32 hits, tiny). Leave restating alone: the label comments are noise, not error, and a rule would produce hundreds of findings with no reader harm. Reconsider B only if a larger staleness sample (a few hundred blocks, checked against their code) finds a rate near 5% or more.

## Limits

- The staleness check was a read against adjacent code, plus targeted greps for the pointers and names a comment cites (six checks). It cannot see a comment made false by a change elsewhere. The stale rate (0.8% unweighted, 1.0% weighted) is a floor.
- One classifier (this seat) judged all 120. No second reader and no mutation-style check of the labels.
- The line-weighted sample favours long comments; a per-block rate would show more restating, since restating comments are one line each.
- `comment_lint` finding counts were run with `LUPIN_ROOT` pinned to this tree. The population is the swept scope at `6a0054f79`, held `src/lupin_mcp/` excluded as the scope defines.

### How each comment was judged

I read each draw with its block and the code under it. For every comment that cites a file, a line number, a function or constant, a document, a config key or a test, I looked the cited thing up with `grep` or `git ls-files` and compared what the comment says with what the code does. I also ran a script over both samples that extracts every cited file path and checks it against `git ls-files`; it found the six dangling documents below. **That script checks that a path exists, not what sits at a cited line, and it only saw the part of each block I had printed (the draw's block, capped at 15 lines), so it could not catch a moved line pointer further up a long block.** A reviewer (Rio, `src/rnd/v0.2.3/2026.11.07-staleness-pass-review.md`) then checked every `file.ext:NNN` pointer in the full blocks of the unflagged draws and found five stale ones my hand pass had passed; I re-checked all five and they are class A below. She did not re-judge the roughly 285 unflagged draws that cite no such pointer, and neither have I. Three kinds of comment were **not** checkable and count as not stale: measurements ("907,074 files", "n=143"), design intent, and row or commit ids.

The verdict has three classes:

| Class | Meaning |
|---|---|
| **A: wrong** | the comment states something the code contradicts, or points at a file or line that holds something else |
| **B: drifted** | a `file:NNN` pointer that is off by five lines or fewer; the target is still easy to find |
| **C: dangling** | the comment is otherwise accurate but cites a document that is no longer in the tree (still recoverable from git) |

**Stale** below means A plus B. C is reported beside it, because those comments still mislead less than an A: the claim holds, only the place to read more is gone.
