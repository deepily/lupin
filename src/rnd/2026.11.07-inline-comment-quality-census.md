# Inline `#` comment quality: census and recommendation

Row `53f2a05a`, asked by Rick on 6 Nov 2026. Measured on 7 Nov 2026 at `6a0054f79`. A measurement and a recommendation; no lint rule was changed.

## Verdict

Of 120 sampled comments, **66% are accurate and useful, 25% restate the code**, and the rest are separators, commented-out code, tool pragmas and one stale pointer. No TODO or FIXME turned up without an owner, and no comment was only a row id or date. The defect worth a rule is narrow (commented-out code, `file.py:NNN` pointers, unowned TODOs); the widest defect, restating, is cosmetic. **Recommendation: add a few deterministic rules to `comment_lint`; do not build a judged pass now.**

## Sample

- **Seed 20261107**, `random.Random( seed ).sample` within each stratum, 120 comment lines (the target was about 100).
- Strata: every area above 400 comment lines, allocated in proportion to size with a floor of 5, plus one stratum for everything smaller (5 lines).
- The classifier read each sampled line with three lines of context before and four after, and judged the whole comment block the line sits in.
- Because the unit is a line, long comment blocks are drawn in proportion to their length. The rates are rates **per comment line**.
- The sample and the classification are kept outside the tree, in the seat's scratchpad.

**Overlay: history carried inside an otherwise useful comment.** 27 of the 120 (22.5%) name a row id, a date, a persona or a "my first pass" story while also explaining something. **Where restating sits.** All 30 restating comments are one-line labels over the next statement; none sits in a multi-line block. The notable cluster is `# Test N:` narration inside in-file smoke tests (8 of the 30). The long comments, which are most of the lines, are mostly accurate.

## Options

| Option | Pros | Cons |
|---|---|---|
| **A. New deterministic `comment_lint` rules** (commented-out code, `file:NNN` pointers, TODO without owner) | Free to run, fits the existing gate and its counted-scope table, no model spend. Targets the three classes that are mechanical to detect. TypeScript already recognises commented-out code, so there is precedent | Catches about 3% of lines (floor 0.7%, sample 2.5%). Commented-out detection by `ast.parse` has false positives on prose such as `# for example x = 1`. Cannot see staleness or restating |
| **B. A judged pass, like the docstring claim judge** | The only way to find stale comments and to rank restating by how little it adds | Unproven payoff: one stale comment in 120, so a pass over 33,363 lines pays to confirm a rate near 1%. Model cost on every changed block, and the docstring judge's labelled-pair machinery would need building for comments. A judge would also flag a quarter of all lines as restating, mostly harmless one-line labels |
| **C. Nothing** | No work. 66% of sampled lines are useful and the defects found are mild | The 107 line-number pointers keep going stale, and commented-out code keeps growing. 21.7% of lines already breach today's style rules, so the corpus is not at zero anyway |

**Recommendation: A, in a reduced form.** Start with `file:NNN` pointers and commented-out code (the two with a measured harm: a wrong pointer misleads, and dead code reads as live), plus unowned TODO if Rick wants it (32 hits, tiny). Leave restating alone: the label comments are noise, not error, and a rule would produce hundreds of findings with no reader harm. Reconsider B only if a larger staleness sample (a few hundred blocks, checked against their code) finds a rate near 5% or more.

## Limits

- The staleness check was a read against adjacent code, plus targeted greps for the pointers and names a comment cites (six checks). It cannot see a comment made false by a change elsewhere. The 0.8% is a floor.
- One classifier (this seat) judged all 120. No second reader and no mutation-style check of the labels.
- The line-weighted sample favours long comments; a per-block rate would show more restating, since restating comments are one line each.
- `comment_lint` finding counts were run with `LUPIN_ROOT` pinned to this tree. The population is the swept scope at `6a0054f79`, held `src/lupin_mcp/` excluded as the scope defines.
