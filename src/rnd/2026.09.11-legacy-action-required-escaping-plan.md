# 2026.09.11 — Legacy action-required card: escape every sender-supplied string

**Row**: `6ce9f4a1` (P1) · **Author**: Mr. Radio 🦉 · **Reviewer**: María 🌸 · **Measured**: 2026-09-11 ~13:40 EDT at `1e0028dd`
**Scope**: `src/lupin_app/static/js/notifications.js` only. The multiplexer twin
(`multiplexer/render/templates/actionRequiredInteractive.ts`) writes through the `html` tagged template and
`.textContent` / `.value`, so it is not in scope.

## What is wrong

`renderActionRequiredNotification` and `renderMultipleChoiceUI` build the card with `innerHTML` from a
template string. The row names two unescaped sender strings. Counting every interpolation in both
renderers finds **seven**:

| # | where (anchor text) | value | context |
|---|---|---|---|
| 1 | `<div class="action-required-title">` | `notification.title \|\| notification.message` | element text |
| 2 | `class="response-text-input" id="response-input-` | `notification.response_default` | `value="…"` attribute |
| 3 | `<div class="mc-question-text">` | `question.question` | element text |
| 4 | `class="mc-input" data-idx=` (the line above it) | `opt.label` | `value="…"` attribute |
| 5 | `<span class="mc-option-label">` | `opt.label` | element text |
| 6 | `<span class="mc-option-desc">` | `opt.description` | element text |
| 7 | `class="mc-other-input"` | `otherText` (the saved custom answer) | `value="…"` attribute |

Safe as they stand, and staying that way: `notification.id` (server-stamped), the project badge
(`getProjectFromSenderId` only returns a regex-matched `[a-z0-9-]` segment upper-cased, or `UNKNOWN`), the
yes/no class names (fixed literals), `message` and `abstract` (through `renderMarkdown`), and all of
`renderOpenEndedBatchUI`, which already escapes every field — it is the pattern to copy.

A `<img src=x onerror=…>` in a question, or a `"` in an option label, runs script or breaks the attribute
on the operator's page. Senders are fleet seats and agents, so this is not an anonymous-attacker path —
but by reading the markup, a `"` in an ordinary label would end row 4's attribute early with no malice
needed (read from the code, not driven in a browser; the round-trip test below drives it).

## The change

Wrap all seven in the existing `this.escapeHtml( … )`, which escapes `& < > " '` and so is correct for both
element text and double-quoted attributes. Nothing else changes.

The one thing to prove rather than assume: **an escaped attribute must still round-trip as the answer.**
`getCurrentQuestionAnswer` reads `.mc-input:checked` `.value`, and the browser decodes entities when it
parses the attribute, so `value="a &quot;b&quot;"` reads back as `a "b"`, the label the sender sent. The
`allLabels.includes( savedAnswer )` comparison then still matches. A test pins this.

## The row's own "done means" (carried in, not re-decided)

Row `6ce9f4a1` sets three conditions beyond the two named sites, and this plan adopts all three:

1. **A real-browser test**: Playwright `page.set_content`, no server — happy-dom is not a browser's parser.
2. **A revert arm per site** that reddens a named test.
3. **A file-wide sweep** of `notifications.js` for other sender fields interpolated into `innerHTML`
   templates, **with the count stated**. The seven above cover two renderers only; the sweep is build step 1,
   its method (every `innerHTML` / `insertAdjacentHTML` assignment, then each `${…}` inside it classified
   as escaped / sanitized / server-constant / sender-supplied) and count go into this doc before any edit,
   and any sender-supplied site it finds outside the card becomes its own row unless it is a one-line
   `escapeHtml` wrap.

## Tests (as built)

**Unit** — `src/tests/unit/notifications_js/sender_text_is_escaped_in_the_legacy_page.test.ts`, 16 tests:
one per fixed site (14), a round-trip test (a label carrying `"` and `&` is the value read back and re-ticks
on re-render), and a positive control (the pre-fix markup in the same harness DOES parse into an `<img>`
and an attribute break-out). Every assertion compares a boolean or a string, never a DOM node: a failing
assert holding a happy-dom node blew the jstest lane's 2 GB RSS ceiling on the first revert arm.

**Revert arms** — `src/rnd/assets/2026.09.11-legacy-escaping-sweep/revert_arms.py`, one arm per wrap:
14/14 killed, each run 16 tests, restore verified by sha256 before and after every arm. Arm 7 (option label
in `value="…"`) reddens two tests, its own and the round-trip test — both guard that site.

**Real browser** — `src/tests/e2e_ui/test_sender_text_cannot_run_script_on_the_legacy_page.py`: the same 14
sites rendered in Chromium via `set_content` (no server), every rendered input focused, 400 ms for image
errors to fire, then a counter the payload would bump must read 0. Its control writes both payload shapes
raw into the same page and must read 2. Runs on `:8000` with the E2E tier.

**Coverage**: `notifications.js` is a documented exemption from the c8 gate (`run-typescript-tests.sh`,
"legacy notifications.js is NOT in this gate, ON PURPOSE"), so there is no coverage figure to move.
