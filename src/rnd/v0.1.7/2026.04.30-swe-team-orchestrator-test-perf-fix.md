# Fix `test_swe_team_orchestrator.py::TestDryRunRegression` — 196s → ms

## Context

This morning's full-suite regression run (Session b195a160, 2026-04-30) flagged
`test_swe_team_orchestrator.py::TestDryRunRegression::test_dry_run_completes`
as failed. Standalone re-run shows the test PASSES — but takes **196 seconds**.

That number is wrong by orders of magnitude. The test is in `src/tests/unit/`,
where the venue contract is "milliseconds per test." Three sibling tests in
`TestDryRunRegression` follow the same pattern, so the cluster-cost is
3 × 196s = 9-10 minutes of every full-suite run when conditions are right —
and **it flips to a hard FAIL when system load is high enough** to trip whatever
implicit timeout the dispatcher imposes (full-suite ran 17:53 yesterday under
load; that's where the 1 fail / 3802 pass came from).

The user's ask: orient on what the test actually does, then fix it to be fast,
and consider rewriting from scratch into smaller pieces.

## Diagnosis — why 196s

**Surface explanation (wrong)**: `MockAgentSDKSession` in
`src/cosa/agents/swe_team/mock_clients.py:51-90` defines 6 dry-run phases with
`asyncio.sleep` delays summing to 3.4s. That's the "expected" test duration.

**Real explanation (50× the surface)**: the test instantiates
`SweTeamOrchestrator` **without a mocked `team_io`** (lines 661-668 of
`test_swe_team_orchestrator.py`):

```python
def test_dry_run_completes( self ):
    config = SweTeamConfig( dry_run=True )
    orch = SweTeamOrchestrator(
        task_description = "Add health check",
        config           = config,
    )
    result = asyncio.run( orch.run() )       # ← real run, real notify path
```

The test file DOES define a `mock_team_io` fixture (line 56-65) but
`TestDryRunRegression` doesn't take it. So `orch.run()` calls the **real**
`cosa_interface.notify_progress` (in `src/cosa/agents/swe_team/cosa_interface.py:97-128`)
which calls `_dispatcher.notify_progress` (in
`src/cosa/agents/utils/agent_notification_dispatcher.py:260-303`) which does:

```python
await asyncio.to_thread( _notify_user_async, request )    # ← real IPC / HTTP
```

Every breadcrumb fires a real notification through the dispatcher's thread pool
into whatever endpoint `_notify_user_async` hits. Under load, each call can
sit on a socket for tens of seconds. With 6 mock-client phases + multiple state
transitions, total wall-clock balloons to 196s+.

**This isn't a unit test.** It's a covert end-to-end test wearing a unit-test
costume. The fix is to make it actually a unit test (or move it to the right
venue with proper labeling).

## Recommended Approach — two-tier rewrite

Replace the existing `TestDryRunRegression` (4 tests, all hitting the real
notify path) with a **two-tier structure**:

### Tier 1 — fast unit tests in `src/tests/unit/test_swe_team_orchestrator.py`

Multiple small tests that each verify ONE invariant of dry-run behavior
in isolation. **Target: < 50ms per test.** Achieved by:

1. **Mock the entire `team_io` boundary** via a fixture that patches
   `cosa.agents.swe_team.cosa_interface.notify_progress` (and the other
   3 entry-point functions) to `AsyncMock`. Reuse the existing
   `mock_team_io` fixture pattern OR write a class-level autouse fixture
   that ALL `TestDryRunRegression` tests get for free.

2. **Zero out `MockAgentSDKSession` per-phase sleeps** so the legitimate 3.4s
   of mock-client time also goes to zero in unit-test context. Add a class-level
   constant `MockAgentSDKSession.DELAY_MULTIPLIER = 1.0` that callers can
   monkeypatch to `0.0` in tests. Default behavior unchanged.

3. **Break apart the mega-tests**. The current 4 tests are:
   | Test | What it covers |
   |---|---|
   | `test_dry_run_completes` | result returned, "Dry-run complete" string, COMPLETED state |
   | `test_dry_run_with_job_id` | job_id constructor pass-through |
   | `test_dry_run_with_state_callback` | 3+ state transitions emitted |
   | `test_dry_run_get_state_includes_new_fields` | get_state() shape (already fast — no run() call) |

   Replace with smaller, more focused tests:
   - `test_dry_run_returns_summary_string` — assert result shape only
   - `test_dry_run_state_is_completed` — assert final state
   - `test_dry_run_emits_messages_via_team_io` — assert AsyncMock call count
   - `test_dry_run_state_transitions_pass_through_callback` — callback fires
   - `test_dry_run_passes_job_id_through_to_notify` — assert job_id forwarded
   - `test_dry_run_get_state_shape` — keep as-is (already fast)
   - `test_dry_run_completes_within_50ms` — guard against re-introducing real I/O

   Each test ~milliseconds. Total ~6 tests × 50ms = 300ms vs. 4 tests × 196s = 784s today.

### Tier 2 — one end-to-end check in `src/tests/smoke/test_swe_team_dry_run_e2e.py` (NEW)

Keep ONE end-to-end test that exercises the real notify path, since SOME
coverage of "the wires are still connected" is valuable. **Target: 5-10s.**
This is the legitimate "regression test" the original docstring claimed to be:
"Ensure dry-run still works after all changes."

Lives in `src/tests/smoke/` per Lupin's testing-venues contract:
- :7999-eligible (no persistent state mutation, < 2 minutes runtime, no monopoly).
- AI-discretionary; runs in scheduled all-suites.
- Has its own `quick_smoke_test()` entry point following the
  `cosa-voice-notifications` skill convention.

This test does NOT mock anything. It calls `orch.run()` against the real
dispatcher with a real running `:7999` server. If the dispatcher is healthy,
test passes in ~5s. If the dispatcher is hung, this is the right venue to
catch it loudly.

## Patterns / Utilities to Reuse

- **Existing `mock_team_io` fixture** in `test_swe_team_orchestrator.py:56-65`
  already mocks all 4 cosa_interface functions. Refactor as a module-level
  helper or autouse fixture so `TestDryRunRegression` gets it for free.
- **`unittest.mock.patch` over `cosa.agents.swe_team.cosa_interface.notify_progress`**
  is the lowest-disruption mock site (it's a module-level coroutine, easy to
  patch, won't affect other tests via session-level state since each test
  patch is scoped).
- **`pytest.MonkeyPatch.setattr( MockAgentSDKSession, "DELAY_MULTIPLIER", 0.0 )`**
  is the idiomatic way to zero the mock-client sleeps per-test.
- **Smoke test base class** — see `src/tests/smoke/utilities/live_pipeline_base.py`
  (`LivePipelineTestBase`) for the standard shape; the Tier-2 file should
  inherit from it OR follow `test_calculator_live_pipeline.py:1-80` as a
  simpler template.

## Risk Assessment

- **Low risk on Tier-1 rewrite**: pure test edits in parent Lupin. If the
  AsyncMock patches miss something, tests fail loudly at runtime, not in prod.
- **Low risk on `mock_clients.py` change**: additive class constant with default
  preserving existing behavior. Affects only test paths that explicitly
  monkeypatch.
- **Low-to-medium risk on Tier-2 new file**: depends on whether `:7999` is
  reliably available during scheduled runs. Mitigated by following the
  `LivePipelineTestBase` pattern that's already proven.
- **One known sharp edge**: `_resolve_target_user()` and the per-task
  ContextVar plumbing in the dispatcher (`agent_notification_dispatcher.py:113-180`)
  may have side effects across tests if patches don't reset correctly between
  tests. The autouse fixture should be CLASS-scoped not session-scoped to
  avoid leak.
