## TL;DR

The 2026-05-15 doc-viewer scope unification (Q-R2 retired the `?scope=` query param in favor of path-prefix routing) updated the backend `/api/docs/file` endpoint, the scope registry, and the documentation — **but the frontend SPA dispatcher was never touched**. As a result every `/app/docs?path=lupin/<rel>` URL the new doc-link mandate produces was being routed to `/api/io/file` and returning 404. While in there, a latent `NameError: ALLOWED_FILES` in `/api/docs/health` (the legacy whitelist constants were removed in unification but the health handler still referenced them) also surfaced and was patched.

http://localhost:7999/app/docs?path=lupin/src/rnd/v0.1.7/2026.05.16-voice-persona-stale-bridge-and-sam-overflow.md

## Root Cause

### Bug 1 — SPA dispatcher

`src/fastapi_app/static/html/document-viewer.html` (pre-fix, lines 235-258) implemented scope-based dispatch from the pre-unification model:

```js
const scope   = params.get( 'scope' ) || 'io';                         // ← defaults to 'io'
const apiPath = scope === 'io' ? '/api/io/file' : '/api/docs/file';
let fetchUrl  = apiPath + '?path=' + encodeURIComponent( path );
```

For the new-form URL `?path=lupin/src/...` (no `?scope=` param):
1. `scope` defaulted to `'io'`
2. `apiPath` became `/api/io/file`
3. Fetch became `/api/io/file?path=lupin/src/...` — the IO endpoint can't find a Lupin source path under the `io/` directory and correctly returned **HTTP 404**.

The backend `/api/docs/file?path=lupin/src/...` was returning **HTTP 200, 16,159 bytes** when called directly — the bug was entirely on the SPA side.

### Bug 2 — Health endpoint NameError

`src/cosa/rest/routers/docs_files.py` (pre-fix, lines 345-374) `docs_files_health()` referenced `ALLOWED_FILES` and `ALLOWED_PREFIXES`. These were the legacy narrow whitelist constants for the retired `docs` scope. The unification removed them but missed updating the health handler:

```python
file_status = {
    name: os.path.isfile( os.path.join( project_root, name ) )
    for name in sorted( ALLOWED_FILES )   # ← undefined
}
```

Result: every `GET /api/docs/health` → **HTTP 500** with `NameError: name 'ALLOWED_FILES' is not defined`.

## Fix

### Production code (3 files)

| File | Change |
|------|--------|
| `src/fastapi_app/static/html/document-viewer.html` | Replaced legacy scope-defaulting dispatcher with first-segment path-prefix routing. New rules: (1) `io/<rel>` → `/api/io/file?path=<rel>`, (2) `<known-project>/<rel>` → `/api/docs/file?path=<full>` where `<known-project>` is in a hardcoded `KNOWN_PROJECTS` Set, (3) anything else falls through to `/api/io/file?path=<full>` for backwards-compat with bare io-relative paths from `notifications.js` and persisted job metadata. Also updated the directory-listing breadcrumb generator to emit the new URL form. |
| `src/cosa/rest/routers/docs_files.py` | Rewrote `docs_files_health` to iterate `_get_scope_registry()` instead of the retired constants. New response shape: `{status, project_root, io: {root, exists}, scopes: {name: {root, exists, allowed_prefixes, manifest}}, media_types}`. |
| `src/cosa/rest/routers/_dir_listing.py` | `_build_view_url` now emits path-prefix URLs (`/app/docs?path=<scope>/<rel>`) retiring the legacy `?scope=` form. IO binary routes (audio/pdf/image/pptx) unchanged since they hit `/api/io/file` / `/app/audio` directly. Updated header docstring + function docstring to reflect the new routing table. |

## Why this slipped through May 15

The 2026-05-15 unification's Phase 5 walked through the backend (`docs_files.py` path-prefix split), the scope registry, and the docs. There was no equivalent Phase walking through the frontend SPA. The `document-viewer.html` dispatcher and the `_dir_listing.py::_build_view_url` helper both kept emitting / accepting the legacy form, and no E2E test caught it because the e2e_ui tests (see below) also still ran against the legacy URLs.

The pattern (per `feedback_sweep_for_pattern_offenders`): the May 15 milestone fixed one of N sites but didn't sweep the others. This fix sweeps:
- ✅ Dispatcher
- ✅ Breadcrumb generator
- ✅ `_build_view_url`
- ✅ Health handler (different bug, same root cause class — retired-constant references)
- ⚠️ E2E UI tests still on legacy URL form — parked, see below

## Backwards Compatibility

The new dispatcher keeps a **legacy fallback** branch for `/app/docs?path=<bare-io-relative>` URLs emitted by:

- `notifications.js` `renderReportLinkSection` (lines 7110, 7112, 7374, 7379, 7387)
- `podcast_generator/job.py` (line 335 — `[📝 View Script](/app/docs?path={script_rel})`)
- `presentation_generator/job.py` (similar pattern)
- Persisted job metadata in completed/dead queues from before this fix

These all use bare `<io-relative>/<file>.md` paths (e.g. `podcasts/user/script.md`). The dispatcher detects "first segment is neither `io` nor a known project name" and routes to `/api/io/file?path=<full-path>` — preserving the old behavior.
