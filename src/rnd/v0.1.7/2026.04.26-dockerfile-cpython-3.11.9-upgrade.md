# Dockerfile: CPython 3.11.5 → 3.11.9 Upgrade

**Date**: 2026-04-26
**Author**: Claude (Lupin parent context)
**Audience**: Docker / build-engineering specialist
**Branch context**: `wip-v0.1.7-2026.04.22-spit-and-polish-for-cjflow-tfe-and-bfe`
**Severity**: HIGH — currently blocks all `e2e` + `integration` test-suite validation on the `:8000` test container, masking real failures behind a CPython interpreter crash.

---

## TL;DR for the Docker expert

Three lines in `docker/lupin/Dockerfile` build CPython **3.11.5** from source. Python 3.11.5 contains CPython regression **bpo/#97382** — `ast.parse()` invoked while the interpreter is deep in C frames leaves the `c_recursion_remaining` counter permanently unbalanced. The bug was fixed in **3.11.6** and is present in every later 3.11.x release.

The crash surfaces inside pytest's traceback formatter on the `:8000` test container during `e2e`/`integration` runs and reads:

```
SystemError: AST constructor recursion depth mismatch (before=126, after=144)
```

Because the crash happens INSIDE pytest's own error reporter, **all real test failures in the same run are masked** — the run reports "0 failed, 1 error" with no actionable signal.

**Required change**: bump 3.11.5 → 3.11.9 (or any 3.11.x ≥ 3.11.6) in the Dockerfile, then rebuild + replace the `lupin-rest-test` container.

That is the entire fix. No code, test, or config changes are needed.

## Background

### Why we build CPython from source instead of using `python:3.11-slim`

The base image is `nvidia/cuda:12.2.2-base-ubuntu22.04` so the container has CUDA 12.2 access for inference workloads. Ubuntu 22.04's apt repository ships Python 3.10.12 (see commented-out `FROM python:3.10.12` at line 2 of the Dockerfile), and the project pins to 3.11.x for typing/asyncio behaviour we depend on. So we layer a from-source 3.11 install on top of the CUDA base. The decision pre-dates this plan and is not under review here — we are only asking for a patch-level bump.

### How we discovered the bug

**Job ID**: `tfe-99595e2c` (Test Fix Expediter, completed 2026-04-24 18:30 EDT)
**Source**: `ts-4139484f::50c73ba7-...` — a scheduled `e2e,integration` test-suite run on `:8000`
**Artifacts**:
- Remediation snapshot: `io/test-suite/2026.04.24-at-18:17-EDT-e2e-integration-remediation.json`
- TFE report: `io/swe-team/reports/interactive.job.tester@lupin.deepily.ai/2026.04.24-at-18:30-EST-ts-4139484f-stalled-test_fix_expediter-report.md`

The TFE auto-clustered the single error into one cluster (`C1`), proposed three remediations, and stalled at its voice gate awaiting operator selection. The TFE's analysis is the source for this plan.

### The trace (verbatim, abbreviated)

```
File "/usr/local/lib/python3.11/site-packages/_pytest/_code/source.py", line 191,
  in getstatementrange_ast
    astnode = ast.parse(content, "source", "exec")
File "/usr/local/lib/python3.11/ast.py", line 50, in parse
    return compile(source, filename, mode, flags, ...)
SystemError: AST constructor recursion depth mismatch (before=126, after=144)
```

`getstatementrange_ast` is called by pytest while formatting a traceback for ANY test failure (or any non-passing collection event). On 3.11.5 this can corrupt `c_recursion_remaining` and crash the interpreter mid-report. Once it crashes, the run aborts and pytest writes summary `total_passed=464, total_failed=0, total_errors=1` — the lone "error" is the internal crash; whatever real failures triggered the formatter are lost.

### Why this didn't show up before now

The `unit` test suite (3600 tests, last green pass on 2026-04-25 16:07 EDT under job `ts-32ce6bda`) does not exercise the same C-frame depth path. The bug surfaces preferentially under the deeper stacks produced by `e2e`/`integration` runs (Playwright + FastAPI TestClient + pytest-playwright-visual + extensive fixture chains). The `pytest.ini` `addopts = -m "not manual" --showlocals` line increases the stack depth further by forcing `repr()` on every local during traceback formatting, which reduces the headroom in `c_recursion_remaining`.

## Why 3.11.9 specifically

- **Minimum required**: 3.11.6 (first release containing the fix for #97382).
- **Recommended**: 3.11.9 — latest 3.11.x patch as of the TFE's analysis date (2026-04-24). Pulls in additional security fixes since 3.11.6 with no API-level changes.
- **Optional alternative**: pin to whichever 3.11.x is current on `python.org/ftp/python/` at build time. Any 3.11.x ≥ 3.11.6 closes the bug. We are not pinning to a specific patch as a matter of policy elsewhere — 3.11.9 just happens to be what the TFE proposal cited.

We do NOT recommend jumping to 3.12.x in this patch. That is a minor-version bump and out of scope for fixing the regression.

## Apply procedure

### 1. Edit the Dockerfile

5 lines, all already enumerated above. Use a literal find-and-replace from `3.11.5` → `3.11.9` scoped to `docker/lupin/Dockerfile`.

### 2. Rebuild and replace the test container

The test container is `lupin-rest-test`, defined in `/mnt/DATA01/include/www.deepily.ai/projects/lupin/docker-compose.yml`.

```bash
cd /mnt/DATA01/include/www.deepily.ai/projects/lupin

# Rebuild from scratch (Python source-build is the only step that takes real time;
# expect ~10–15 min on the host's hardware due to ./configure --enable-optimizations)
docker compose build --no-cache lupin-rest-test

# Replace the running container (do NOT use `docker restart` — it does not pick up
# rebuilt images or compose.yml mount changes)
docker rm -f lupin-rest-test
docker compose up -d lupin-rest-test
```

### 3. Verify the interpreter version inside the new container

```bash
docker exec lupin-rest-test python3.11 --version
# Expected: Python 3.11.9
```

### 4. Confirm the FastAPI server is up on `:8000`

```bash
curl -sS http://localhost:8000/api/health
# Expected: 200 OK
```

`docker compose up -d` should bring the service up automatically; if `/api/health` does not respond within ~60s, check `docker logs lupin-rest-test` for a startup error unrelated to this change.

### 5. Run the project preflight to confirm bind-mounts are intact

```bash
bash src/scripts/preflight-test-container.sh
```

This catches docker-compose.yml drift / mount mismatches that `docker restart` would silently mask. It must pass before any further test-suite submission to `:8000`.

## Risks + rollback

### Risks (low)

1. **Build cache invalidation** — `--no-cache` rebuild costs ~10–15 minutes. This is a one-time cost; subsequent builds will cache-hit until the next bump.
2. **Newer `make altinstall` behaviour** — none expected. 3.11.x patch releases do not introduce ABI breaks. `pip` / `setuptools` versions installed by `ensurepip` may shift slightly; pip is bumped immediately afterward via `pip install -U pip` (line 67) so any drift is irrelevant.
3. **Native extensions compiled against 3.11.5** — none. All Python deps in this image are pure-Python or wheel-installed during the same build; nothing is built against the interpreter at host level.

### Rollback

Trivial. Revert the 5 lines, rebuild, replace the container.

```bash
git checkout HEAD -- docker/lupin/Dockerfile
docker compose build --no-cache lupin-rest-test
docker rm -f lupin-rest-test
docker compose up -d lupin-rest-test
```

The dev container `lupin-rest-dev` (port 7999) is untouched by this plan but uses the SAME Dockerfile via the same compose service definition. After rebuild, both containers will run 3.11.9. If the dev container is currently running and the project owner does not want it bounced, gate the rollout — but in practice both containers should run identical Python versions to keep `:7999` representative of `:8000`.

## Out of scope (do NOT do these as part of this plan)

The TFE produced two additional proposals. Both are workarounds for the masked-failure symptom, not the dependency root cause. **Do not apply either** — they only complicate the eventual rollback once 3.11.9 is in place.

| TFE proposal | Why we are NOT doing it |
|--------------|--------------------------|
| Monkey-patch `_pytest._code.source.getstatementrange_ast` in `src/tests/conftest.py` to swallow `SystemError` | Hides the bug instead of fixing it. Requires a follow-up PR to remove once the upgrade lands. |
| Remove `--showlocals` from `pytest.ini` `addopts` | Only reduces the bug's likelihood, does not eliminate it. Also reduces traceback debuggability for the project owner. |

The `--showlocals` flag stays as-is. The conftest is not patched.
