## Summary

When Claude Code is launched from within a nested git repo under Lupin (`src/cosa/`, `src/lupin-mobile/`, `src/lupin-plugin-firefox/`), the cosa-voice MCP server collapses their identities to `project == "lupin"` and routes all notifications under `claude.code@lupin.deepily.ai`. Root cause is substring-matching in `detect_project()` at `src/cosa/agents/utils/sender_id.py:21-56`.

## Bug Demonstration

```json
// cwd = /…/lupin/src/cosa   → reported by get_session_info():
{ "project": "lupin", "project_source": "known", "sender_id": "claude.code@lupin.deepily.ai#52a71953" }
```

Failure table:

| cwd | Current result | Correct result |
| --- | --- | --- |
| `/…/lupin/src/cosa/` | `"lupin"` | `"cosa"` |
| `/…/lupin/src/lupin-mobile/` | `"lupin"` | `"lupin-mobile"` |
| `/…/lupin/src/lupin-plugin-firefox/` | `"lupin"` | `"lupin-plugin-firefox"` |
| `/…/lupin/` | `"lupin"` ✓ | `"lupin"` |

## Root Cause

`detect_project()` does substring matching on `os.getcwd().lower()`. When cwd contains both `/lupin` and `/cosa`, the first check's `and "/lupin" not in cwd` short-circuits to False, falling through to the `/lupin` catch-all. `/lupin-mobile` and `/lupin-plugin-firefox` trivially match `/lupin` — classic substring-greediness.

## Fix Strategy

Replace substring matching with **git-repo-boundary walk-up**: from `cwd`, walk up until a directory containing `.git` (file or dir — handles worktrees and submodule gitlinks) is found; its basename becomes the project name. Fallback to `cwd.name.lower()` if no `.git` ancestor.

Also extend `KNOWN_PROJECTS` in `src/cosa/utils/notification_utils.py` to include `lupin-mobile` and `lupin-plugin-firefox`, so `_PROJECT_SOURCE` reports `"known"` instead of `"basename"` for these repos.

## Files Modified

All inside the **CoSA submodule** (`src/cosa/`). Per project `CLAUDE.md` and memory `feedback_lupin_only_never_cosa.md`, no git operations are run against CoSA from the parent Lupin context. User commits CoSA changes from a CoSA-context session.

1. `src/cosa/agents/utils/sender_id.py` — `detect_project()` rewrite + smoke-test extension with mocked-cwd cases for each nested repo.
2. `src/cosa/utils/notification_utils.py` — `KNOWN_PROJECTS` extended to include `lupin-mobile`, `lupin-plugin-firefox`; `is_known_project` smoke-test extended to cover them.

## Risks Flagged

- On first Claude Code launch from a newly-recognised nested repo, `_validate_repo_account()` will log an `urgent` validation notification if `~/.lupin/config` has no matching section. This is the *intended* behaviour for the account-validation subsystem — just a flag for the user to add config sections (`[lupin-mobile]`, `[cosa]`, `[lupin-plugin-firefox]`) when they want routine use from those repos.
- `_resolve_canonical_project()` with no `~/.lupin/config` mapping simply returns the detected name unchanged — so `sender_id` becomes `claude.code@lupin-mobile.deepily.ai` etc. If the user wants a different canonical identity, they add a config section.

## Out of Scope

- `~/.lupin/config` updates (user-specific).
- MCP re-registration (server is already user-scope; Claude Code restart reloads module).
- Committing to CoSA (handled by user from a CoSA-context session).
