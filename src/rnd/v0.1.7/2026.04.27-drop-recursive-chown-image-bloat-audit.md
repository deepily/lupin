## Context

`lupin:1.0.0` (the Tier 0+1 hygiene-pass image we just shipped) is **72.1 GB**. That's down from `lupin:0.9.0`'s 130 GB — a meaningful win — but still big enough that pushes to a registry are slow and disk usage on the build host is uncomfortable. An audit pinpointed one structural waste responsible for **~31.5 GB** of the total: the final `chown -R rruiz:rruiz /home/rruiz /var/lupin /opt/python /opt/venv` step, which creates a new image layer that re-stores virtually every file with rruiz ownership (Docker's copy-on-write tracks inode metadata at file granularity, so a recursive chown effectively duplicates the entire affected tree into a new layer).

Other large costs (HF models baked into the image, cuda-toolkit-12-4 needed only at build time, etc.) are deferred to a future rainy-day Tier 2/3 PR. This iteration is scoped narrowly to **eliminating the recursive chown**, then rebuild + verify.

A related architectural question was answered as part of the audit: *if we eventually externalize the LanceDB (currently bind-mounted from the host via `./src:/var/lupin/src` already, but planned for GCS-FUSE in production), does the INI need to change inside the image?* Short answer captured below: **no**.

## LanceDB config question (definitive answer)

**No INI change needed when LanceDB lives outside the image.** The existing config is already path-relative:

| Layer | Resolved value |
|---|---|
| INI key (`src/conf/lupin-app.ini:340`, `[Lupin: Development]`) | `solution snapshots lancedb path = /src/conf/long-term-memory/lupin.lancedb` |
| Runtime resolver (`src/cosa/memory/lancedb_solution_manager.py:200-201`) | `if db_path.startswith("/src/"): full_path = du.get_project_root() + db_path` |
| `du.get_project_root()` inside container | `/var/lupin` |
| Computed path inside container | `/var/lupin/src/conf/long-term-memory/lupin.lancedb` |
| docker-compose bind mount (`docker-compose.yml:41` + `:101`) | `./src:/var/lupin/src` |
| → effective on-disk path | `<host>/src/conf/long-term-memory/lupin.lancedb` (host filesystem) |

So LanceDB is **already** runtime-mounted; the COPY we removed in `lupin:1.0.0` was always redundant. For a future GCS-FUSE setup (production / Cloud Run, no docker-compose bind mount), the change is **only** in the orchestrator's volume-mount spec — the INI value stays exactly as is, and `lancedb_solution_manager.py` doesn't need to know whether the underlying path is a bind mount, a GCS-FUSE mount, or a regular directory. The only requirement: the mount point must land at `/var/lupin/src/conf/long-term-memory/lupin.lancedb` inside the container.

The splainer entry in `src/conf/lupin-app-splainer.ini` already documents this (Default: `/src/conf/long-term-memory/lupin.lancedb`).

## This iteration: drop the recursive chown

### Strategy

Switch to `USER rruiz` early in the Dockerfile so subsequent RUN steps create files with rruiz ownership at write time, instead of fixing ownership retroactively. Use `--chown=rruiz:rruiz` on every COPY that lands files in rruiz-owned paths. Front-load all root-needed work into a single block before the USER switch. Keep one transient `USER root` only for the items that genuinely require it (claude.ai/install.sh writes to /usr/local/bin via wrapper, MARP CLI to /usr/local/bin, GitHub CLI apt repo).

### Critical files to modify

| File | Why |
|---|---|
| `docker/lupin/Dockerfile` | All restructuring lives here. No app-code changes. |

NOT touched: `pyproject.toml`, `uv.lock`, `.dockerignore`, `docker/lupin/scripts/patch-pytest-playwright-visual-snapshot.py`, app source code.

### Restructured Dockerfile shape

1. **Root block — system deps**
   - `FROM nvidia/cuda:12.4.1-base-ubuntu22.04`, `ENV DEBIAN_FRONTEND/TZ`
   - Purge `cuda-compat-12-4` (existing step, unchanged)
   - BuildKit cache hygiene (`apt.conf.d/keep-cache`)
   - Single `RUN --mount=type=cache apt-get install` for: existing system deps **PLUS playwright's chromium runtime deps** (hardcoded list — `libnss3 libnspr4 libdbus-1-3 libatk1.0-0 libatk-bridge2.0-0 libcups2 libdrm2 libxkbcommon0 libxcomposite1 libxdamage1 libxfixes3 libxrandr2 libgbm1 libpango-1.0-0 libcairo2 libasound2`) so we can drop `--with-deps` in the user-space playwright step. Comment notes derivation from `playwright install-deps chromium --dry-run`.
   - `useradd rruiz` (existing)
   - **NEW**: `mkdir -p /opt/python /opt/venv /var/lupin/io /home/rruiz/.claude && chown rruiz:rruiz /opt/python /opt/venv /var/lupin /home/rruiz` — directory ownership prep so subsequent rruiz writes succeed.
   - `COPY --from=ghcr.io/astral-sh/uv:0.8 /uv /uvx /usr/local/bin/`
   - GitHub CLI apt repo + install
   - MARP CLI wget+tar to `/usr/local/bin`

2. **`USER rruiz`** ← single switch.

3. **Rruiz block — user-space installs**
   - `uv python install 3.13` → `/opt/python` (rruiz-owned)
   - `WORKDIR /app`, `COPY --chown=rruiz:rruiz pyproject.toml uv.lock ./`
   - `uv venv --seed /opt/venv && uv sync --locked --no-install-project`
   - `python -m spacy download en_core_web_sm`
   - HF model downloads (3 lines, write to /home/rruiz/.cache/huggingface)
   - `python -m playwright install chromium` (no `--with-deps` — system deps already in root block)
   - `COPY --chown=rruiz:rruiz docker/lupin/scripts/patch-pytest-playwright-visual-snapshot.py /tmp/` then `RUN python /tmp/patch-pytest-playwright-visual-snapshot.py`
   - `curl https://d2lang.com/install.sh | sh` → `/home/rruiz/.local/bin/d2`
   - `curl https://claude.ai/install.sh | bash` (verify writes to user dir; `USER root`/`USER rruiz` sandwich if needed)
   - All app-code COPYs with `--chown=rruiz:rruiz`
   - `COPY --chown=rruiz:rruiz docker/lupin/claude-config/{settings.json,mcp.json}` to `/home/rruiz/.claude/`
   - `WORKDIR /var/lupin/src`

4. **Final**
   - **REMOVE**: the recursive `chown -R rruiz:rruiz /home/rruiz /var/lupin /opt/python /opt/venv` ← this is the entire 31.5 GB layer we're killing
   - **REMOVE**: the `if [ -d /root/.cache ]; then ... cp -an /root/.cache/. /home/rruiz/.cache/ ... fi` block ← no longer needed
   - **Adjust** `--mount=type=cache,target=/root/.cache/uv` → `--mount=type=cache,target=/home/rruiz/.cache/uv,uid=1001,gid=1001`
   - Keep `CMD [ "/bin/bash", "/var/lupin/src/scripts/run-fastapi-lupin.sh" ]`

### Edge cases

| Edge case | Action |
|---|---|
| `python -m playwright install chromium` requires playwright-the-package installed in venv | Order this AFTER `uv sync`. Verify playwright is in main deps or that `dev` group is auto-included. uv default behaviour as of 0.8: dev group included unless `--no-dev` passed. |
| Claude Code installer | Verify writes to `~/.local/bin`. If it surprises us by needing root, wrap in `USER root` ... `USER rruiz`. |
| pytest-playwright-visual-snapshot patcher | After uv sync, /opt/venv files are rruiz-owned. Patcher run by rruiz can modify them. ✅ |
| BuildKit cache mount as USER rruiz | Change to `target=/home/rruiz/.cache/uv,uid=1001,gid=1001`. Apt mounts (`/var/cache/apt`, `/var/lib/apt`) stay root-only. |
| GitHub CLI apt repo setup | Stays in root block, no change. |

### Reused patterns

- Non-root user creation (Dockerfile:18-19) — existing pattern, reuse as-is.
- `cu.get_project_root()` resolver (`src/cosa/utils/util.py`) — canonical path resolver. NOT modified.
- `playwright install-deps chromium --dry-run` — gives canonical apt list. Capture output once and bake the list into the Dockerfile with a comment noting last refresh date.
