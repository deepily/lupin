## 5. JS — sentence splitter

Added `_splitIntoSentences(text)` helper to the notifications UI class (right before `addToTTSQueue`).

- Primary algorithm: regex match on terminal punctuation followed by whitespace + capital letter or end-of-string.
- The terminal-character class respects `this.ttsPreviewIncludeSemicolons` — defaults to `.!?` only.
- Fallback: if regex produces a single chunk but the text has >12 words, splits at the word-count midpoint.

## 6. JS — preview/remainder computation

Added `_computeTTSPreview(item)` method. Mutates the item in-place with `previewText`, `remainderText`, `stage`. Opt-out paths (stage="full", no remainder) when:

- `this.ttsPreviewEnabled` is false
- `item.type === 'action-required'` (full context needed for response)
- `item.ttsText.length < this.ttsPreviewMinChars`
- Sentence splitter produces ≤ preview_count sentences

Telemetry: logs `[TTS-COST] Preview: X/Y chars (saved Z). Session: A/B (C%)` on each successful preview cut. Per Q10.

## 7. JS — addToTTSQueue evolution

Modified `addToTTSQueue` (~line 13064 post-edit) to call `this._computeTTSPreview(item)` BEFORE the existing queue-insertion logic. All downstream paths (action-required priority insert, fire-and-forget append, focus mode, etc.) continue to work — the only added field-set happens up-front.

## 8. JS — activateNextTTS routing by stage

Modified `activateNextTTS` (~line 13170 post-edit). Replaces the bare `this.playTTS(item.ttsText, ...)` with stage-aware routing:

- `stage === "remainder"` → play `item.remainderText`
- `stage === "preview"` → play `item.previewText`
- `stage === "full"` (or unset) → play `item.ttsText` (legacy fallback)

## 9. JS — onTTSPlaybackComplete auto-pause

Modified `onTTSPlaybackComplete` (~line 13519 post-edit). Added a top-of-function guard: if the just-finished active item has `stage === 'preview'` AND a non-empty `remainderText`:

- Flip `activeTTSItem.stage` to `"remainder"`
- Set `_ttsPausedAfterPreview = true` + `isTTSPaused = true`
- Stop the pulsing indicator (preview chunk no longer playing)
- Persist state via `saveTTSQueueState`
- Return early — do NOT advance queue

User now resumes via the existing play button (which routes to `resumeTTS`).

## 10. JS — resumeTTS remainder routing

Modified `resumeTTS` (~line 13773 post-edit). Added a top-of-function branch: if `_ttsPausedAfterPreview` is set AND `activeTTSItem.stage === 'remainder'` AND `remainderText` non-empty:

- Telemetry: log `[TTS-COST] Remainder resumed: +X chars` and update session counters (resuming the remainder CANCELS the savings for that message — accounted for by subtracting from `ttsCostSavings.saved`).
- Clear `_ttsPausedAfterPreview` + `isTTSPaused`.
- Resolve the voice_id from the active item's persona (same as initial preview playback).
- Call `playTTS(item.remainderText, ...)` — a NEW TTS request to the provider for the remainder text.
- On error, force advance via `onTTSPlaybackComplete`.
- Return without falling through to the audio-context resume path (no audio is suspended).

The existing audio-context / HTML-audio resume path stays unchanged for non-preview pauses.

## 11. JS — stopTTSAndAdvance drops remainder

Modified `stopTTSAndAdvance` (~line 13611 post-edit). Added a guard before `stopAudio` + `onTTSPlaybackComplete`:

- If `_ttsPausedAfterPreview` is set AND there's an active item: zero out `remainderText`, clear the flag, clear `isTTSPaused` (so `onTTSPlaybackComplete` doesn't short-circuit on the manual-pause guard).
- Fall through to the existing stop-and-advance behavior.

User pressing stop after a preview now correctly skips to the next item's preview rather than getting stuck on the paused remainder.

## 12. JS — localStorage persistence

Modified `saveTTSQueueState` (~line 13895 post-edit) and `restoreTTSQueueState`:

- **Save**: when `_ttsPausedAfterPreview` is true AND active item exists, include `previewPausedItem` (snapshot of `activeTTSItem`) and `ttsPausedAfterPreview` flag in the persisted JSON.
- **Restore**: if persisted state has both flags, re-hydrate `this.activeTTSItem` from the snapshot, set `_ttsPausedAfterPreview = true` and `isTTSPaused = true`. Otherwise fall through to the existing "audio context lost on reload" path that clears pause state.

After page reload, the paused remainder survives and the user can click play to resume.
