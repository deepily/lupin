## Context

The 2026-05-13 preview-and-pause feature shipped with an aggressive default — auto-pause the entire TTS queue after every preview slice played, forcing the user to click resume per message. Today's decouple fix (commit `efbcae3`) kept the visible notification list from stalling, but the AUDIO side is still annoying: pause-after-preview is the wrong default for a multi-session listener who'd rather just hear a snippet of each message and move on.

**Rick's directive (2026-05-14 evening voice message):**

1. **Stop instead of pause** — when the preview slice finishes, **advance the queue** to the next notification. Drop the remainder. No more `isTTSPaused=true` between turns, no more `resumeTTS` for remainder playback, no more "paused after preview" bubble state.

2. **Runtime percentage slider** — add a slider widget in the Claude Code accordion bar (`#cc-session-strip`) with five stops at **0% / 25% / 50% / 75% / 100%** that controls the per-arrival TTS preview fraction at runtime. Persists to localStorage. Seeded from INI `tts preview fraction` default on first load.

**Why this is the right shape:**
- 25% (current default) becomes a *bite-sized* announcement, not a *prefix-with-stall*
- 0% = silent watch mode — notifications appear in the list (via the decouple fix) but no audio at all
- 100% = full-message playback (the pre-preview-feature behavior; useful when the user wants every word)
- The slider is per-listener, per-browser-tab — no server round-trip on change, no MCP coordination needed

**What stays intact:**
- The decouple fix from this afternoon (immediate list render on WS arrival)
- The abbreviation pre-mask in `_splitIntoSentences()`
- The `ceil`-based math in `_computeTTSPreview()`
- The INI keys `tts preview fraction`, `tts preview min chars`, `tts preview enabled`, `tts preview include semicolons` (`tts preview fraction` becomes the seed default for the slider; the others still gate behavior)
- The `[TTS-COST]` telemetry (just reworded — "preview played" instead of "auto-pausing")

### 1g. Strict FIFO ordering invariant in `addToTTSQueue`

**Rick's directive (2026-05-14 evening, post-plan)**: oldest messages at the top of the queue; new messages always go to the END. When the user returns to a backlog of ten messages, they should hear the oldest first in arrival order so the audio narrative reads chronologically.

**Current** (`notifications.js:13205-13220` approximately):

```javascript
addToTTSQueue( item ) {
    this._computeTTSPreview( item );
    if ( item.type === 'action-required' ) {
        // Priority: Insert at front (but after other action-required items)
        const insertIndex = this.ttsQueue.findIndex( q => q.type !== 'action-required' );
        if ( insertIndex === -1 ) {
            this.ttsQueue.push( item );
        } else {
            this.ttsQueue.splice( insertIndex, 0, item );
        }
        this.log( `TTS queue: Added action-required item at priority position, queue length: ${this.ttsQueue.length}` );
    } else {
        this.ttsQueue.push( item );
        this.log( `TTS queue: Added fire-and-forget item at back, queue length: ${this.ttsQueue.length}` );
    }
}
```

**Issue**: action-required notifications JUMP the queue (insert before the first fire-and-forget). With the preview-and-pause now superseded by preview-and-advance, action-required items aren't more urgent for audio purposes — they all play their preview slice and move on. The priority displacement breaks Rick's "hear them in arrival order" mental model.

**After**: strict FIFO regardless of type. Every incoming item pushes to the back.

```javascript
addToTTSQueue( item ) {
    this._computeTTSPreview( item );
    this.ttsQueue.push( item );
    this.log( `TTS queue: Added ${item.type} item to back, queue length: ${this.ttsQueue.length}` );

    // If nothing currently playing AND not in focus mode, kick off playback
    if ( !this.activeTTSItem && !this.ttsFocusModeActive ) {
        this.activateNextTTS();
    }
}
```

**What changes for action-required UX**: the visible action-required CARD still appears in the action-required SECTION immediately on WS arrival (separate render path — already-immediate before this fix). The buttons are clickable from the moment the card lands. Only the TTS AUDIO order is reshuffled — the user hears their action-required prompt in chronological order rather than out-of-band.

**Invariant going forward**: `ttsQueue` is strict FIFO. Head (index 0) plays next; new arrivals append. No splice-to-front, no priority class, no per-type displacement.

### 2b. `activateNextTTS` honors `stage='skip'`

```javascript
} else if ( item.stage === 'skip' ) {
    this.log( `TTS queue: Skipping audio dispatch for ${item.id} (slider at 0%)` );
    const panel = document.querySelector( `.audio-control-panel[data-notification-id="${item.id}"]` );
    if ( panel ) {
        const listItem = panel.closest( 'li' );
        if ( listItem ) {
            listItem.classList.remove( 'is-tts-pending' );
        }
    }
    this.activeTTSItem = null;
    setTimeout( () => this.activateNextTTS(), 50 );
    return;
}
```

50ms `setTimeout` prevents synchronous infinite-loop if entire queue is `stage='skip'`.

### 4b. Restore-on-init

```javascript
const userOverride = localStorage.getItem( this.TTS_FRACTION_PREF_KEY );
if ( userOverride !== null && userOverride !== '' ) {
    const parsed = parseFloat( userOverride );
    if ( !isNaN( parsed ) && parsed >= 0 && parsed <= 1 ) {
        this.ttsPreviewFraction = parsed;
    }

```

### 4c. Slider event listener

In `setupEventListeners()`:

```javascript
const fractionSlider = document.getElementById( 'cc-tts-fraction-slider' );
const fractionLabel  = document.getElementById( 'cc-tts-fraction-value' );
if ( fractionSlider && fractionLabel ) {
    const percent = Math.round( this.ttsPreviewFraction * 100 );
    fractionSlider.value = String( percent );
    fractionLabel.textContent = `${percent}%`;
    fractionSlider.addEventListener( 'input', ( e ) => {
        const pct = parseInt( e.target.value, 10 );
        const fraction = pct / 100;
        this.ttsPreviewFraction = fraction;
        fractionLabel.textContent = `${pct}%`;
        localStorage.setItem( this.TTS_FRACTION_PREF_KEY, String( fraction ) );
        this.log( `[TTS-PREVIEW] User set runtime fraction to ${pct}% (${fraction})` );
    } );
}
```

### 4d. Strip-unhide trigger
