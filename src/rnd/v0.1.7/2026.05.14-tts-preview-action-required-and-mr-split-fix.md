## Context

Two separate bugs in the TTS preview-and-pause feature (introduced 2026-05-13 per the parent design doc). Both live in `src/fastapi_app/static/js/notifications.js`.

### Bug A (URGENT — TTS cost burn)

`_computeTTSPreview()` at line 13025 opts action-required notifications OUT of preview-and-pause:

```javascript
if ( !this.ttsPreviewEnabled || item.type === 'action-required' || text.length < this.ttsPreviewMinChars ) {
    item.previewText   = text;
    item.stage         = 'full';
    return item;
}
```

This was design-doc decision Q5(b) — rationale: "full context needed for response." But every long action-required ask (multi-option questions, batch open-ended, voice-mode prompts) now plays in full, burning TTS tokens.

Rick's example message ran verbatim through TTS: an 8-sentence ~700-char "Layered. The doctrine lives in your global Claude file..." prompt. With the fix, preview would have been ~2 sentences (~150 chars), saving ~78% of TTS spend on that one message.

Rick has explicitly overridden Q5(b) based on production cost telemetry: action-required messages MUST get preview-and-pause like every other notification. The UX trade-off (user may click a button without hearing remainder) is accepted.

### Bug B (correctness — Mister-Radio split)

`_splitIntoSentences()` at line 12986 uses regex:

```javascript
const boundaryRegex = new RegExp(
    `[^${terminalChars.replace( /[.!?;]/g, c => '\\' + c )}]+(?:[${terminalChars.replace( /[.!?;]/g, c => '\\' + c )}]+(?=\\s+[A-Z]|\\s*$)|$)`,
    'g'
);
```

This treats `Mr.` as a sentence boundary: the period is followed by ` R` (space + capital), which matches the `(?=\s+[A-Z]|\s*$)` lookahead. The parent design doc at line 87 falsely claims `"Mr. Smith said hi. Then he left."` is handled correctly — the implementation diverged from the spec.

For Rick's session-end "Mr. Radio here..." message (9 real sentences):
- Splitter produces 10 entries (extra entry for false-split "Mr.")
- `Math.floor(10 * 0.25) = 2`
- Preview = `"Mr. Radio here."` (16 chars of 580 = 2.7% of message)

A related latent bug: when the regex lookahead fails (e.g., `"3.14"`), the `match()` engine SKIPS characters instead of treating them as part of the current sentence. `"3.14 is pi. Foo."` produces `["14 is pi.", "Foo."]` — the `"3."` prefix is dropped entirely.

### Secondary issue (math tuning)

`Math.floor(N * 0.25)` undersizes preview for medium-N messages. For N=9, floor=2 (~22% of sentences); for N=5-7, floor=1 (~14-20%). Recommend switching to `Math.ceil`. For Rick's 9-sentence message this gives 3-sentence preview (~118 chars = 20% by characters) instead of 2-sentence (~48 chars = 8%).

## Phase 2 — Abbreviation pre-mask + algorithm swap (correctness)

**File**: `src/fastapi_app/static/js/notifications.js`, lines 12980-13003.

Rewrite `_splitIntoSentences()`. Two changes:

### 2a. Pre-mask common abbreviations

Before regex application, replace abbreviation periods with a placeholder (`` — SOH control char, never appears in real TTS text):

```javascript
const ABBREVIATIONS = [
    // Personal titles
    'Mr.', 'Mrs.', 'Ms.', 'Mx.', 'Dr.', 'Prof.', 'Sr.', 'Jr.', 'Rev.',
    // Geographic
    'St.', 'Mt.', 'Ft.', 'Ave.', 'Blvd.', 'Rd.',
    // Discourse
    'vs.', 'e.g.', 'i.e.', 'etc.', 'viz.', 'cf.', 'No.',
    // Time
    'a.m.', 'p.m.', 'A.M.', 'P.M.'
];
const ABBR_MASK = '';

let masked = text;
ABBREVIATIONS.forEach( abbr => {
    const placeholder = abbr.replace( /\./g, ABBR_MASK );
    masked = masked.split( abbr ).join( placeholder );
} );
```

### 2b. Switch from `match()` to `split()` with lookbehind+lookahead

Current `match()`-based approach has a latent flaw: when the lookahead fails, the regex engine SKIPS the unmatched prefix instead of including it in the current sentence (root cause of the "3.14 is pi." → ["14 is pi."] bug).

Replace with `split()` using a zero-width boundary:

```javascript
const terminalChars = this.ttsPreviewIncludeSemicolons ? '.!?;' : '.!?';
const escaped       = terminalChars.replace( /[.!?;]/g, c => '\\' + c );
const splitRegex    = new RegExp( `(?<=[${escaped}])\\s+(?=[A-Z])`, 'g' );

let parts = masked.split( splitRegex )
    .map( p => p.replace( new RegExp( ABBR_MASK, 'g' ), '.' ).trim() )
    .filter( p => p.length > 0 );

if ( parts.length > 1 ) return parts;
```

Why `split()` wins: the lookbehind `(?<=[.!?])` requires a terminal punct BEFORE the split point, and the lookahead `(?=[A-Z])` requires a capital AFTER. `split()` includes ALL inter-boundary content in the resulting parts — nothing is dropped.

### 2c. Preserve the word-count fallback (no change)

Lines 12996-13002 word-count fallback for long single-sentence text stays as-is.

## Trade-off Rick accepted

By removing the action-required opt-out (Phase 1a), the UX for long action-required prompts changes: user hears ~25% of context, audio auto-pauses, then they either:
- Click resume to hear full context, then answer; OR
- Answer directly from the partial context they heard

Risk: user answers incorrectly because they didn't hear the full options. Mitigation: rider already mandates "TTS body is headline + takeaway only — detail goes in abstract" — long context-rich asks should already be short in the spoken body per `feedback_tts_body_headline_and_takeaway_only`. The bug Rick is reporting (whole "Layered..." paragraph spoken aloud) suggests the rider directive is being violated by senders; the preview-truncation safety net catches the violation at the receiver.
