## What changed

### 1. Focus-bar strip-icon initial → persona-first, project-fallback

- **File**: `src/fastapi_app/static/js/notifications.js`, around line 8967
- **Function**: `_addStripIcon( senderId, projectName, persona, sessionId, insertAtTop )`
- **Before**: `const initial = ( projectName || "?" ).charAt( 0 ).toUpperCase();`
- **After**: `const initial = ( persona?.display_name || persona?.name || projectName || "?" ).charAt( 0 ).toUpperCase();`
- **Why**: Rick has four parallel Lupin sessions in chorus mode; the focus strip was showing four identical "L" pills. Now it shows T / R / A / etc.
- **Impact on speakerphone code**: minimal — persona was already a function param; only the initial char is computed differently. Color, tooltip, click dispatch unchanged.

### 2. TTS queue pauses synchronously BEFORE the mic engages, resumes 750 ms AFTER recording stops

This is the meatier change. Three new pieces on `recordingManager` (~line 3398 onward):

- **`TTS_RESUME_DELAY_MS` constant** (line 3406) — `750`. Tunable.
- **State flags** (lines 3414-3415):
  - `_ttsPausedByRecording` — true when WE caused the current pause (state-preserving: a user-initiated manual pause is never auto-resumed).
  - `_resumeTimeoutHandle` — pending `setTimeout` handle for the delayed resume.
- **`_scheduleTTSResume` helper** (around line 3608) — replaces any pending resume timeout, schedules a new one 750 ms out, kicks `activateNextTTS()` on resume if the queue has backlog but no active item.

**Three hook points modified**:

- `startRecording` (~line 3428) — added a synchronous pre-mic pause block AFTER the auto-cancel-previous step but BEFORE the `new AudioRecorder(...)` construction. Clears any pending resume timeout (chained-recording flicker prevention), then calls `pauseTTS()` and force-sets `isTTSPaused = true`.
- `onRecordingStop` (~line 3486) — appended a call to `self._scheduleTTSResume()`.
- `cancelRecording` (~line 3571) — appended a call to `this._scheduleTTSResume()` (ESC-cancel path doesn't fire `onRecordingStop`).

### 3. Barge-in queue-gate fix (added during testing)

Live testing surfaced a bug: when the user presses record BEFORE any TTS is playing, the original `pauseTTS()` early-returns (because `!activeTTSItem`) and leaves `isTTSPaused = false`. Then `activateNextTTS()` (line 12950) sees the flag false and lets fresh TTS arrivals barge through during recording.

Fix:

- After `pauseTTS()` in `startRecording`, **force `self.ui.isTTSPaused = true`** regardless of whether `pauseTTS` actually did anything. This closes the queue-advance gate.
- Inside `_scheduleTTSResume` after `resumeTTS()`, **if `activeTTSItem` is null but `ttsQueue.length > 0`, manually call `activateNextTTS()`** to drain messages that accumulated during the recording window. Without this kick, the queue stalls forever (no playback-completion event will fire).

## Semantic changes that affect speakerphone code

If you're touching any of these symbols, **double-check** the new behavior:

| Symbol | Old behavior | New behavior | Watch out |
|---|---|---|---|
| `isTTSPaused` | Set by `pauseTTS()` only when an item is actively playing | Can now be force-set true by `recordingManager` even when no item is active | If your code reads `isTTSPaused` to mean "something is paused", be aware it can now mean "queue gate is closed" without any audio actually paused. |
| `activateNextTTS()` | Called from `addToTTSQueue` (new arrival) and playback-completion handlers | Same callers, PLUS manually kicked by `_scheduleTTSResume` after resumeTTS | If you add a new caller, be aware the gate at line 12950 (`if isTTSPaused: return`) is now load-bearing. |
| `pauseTTS()` / `resumeTTS()` | Designed for the user pause/play buttons | Now also called by `recordingManager` for mic-engagement | If you change the early-return guards (lines 13501, 13535), check `recordingManager._scheduleTTSResume` still drains queue correctly on no-active-item resume. |
| `recordingManager.cancelRecording` | UI teardown only | UI teardown + schedule TTS resume | The auto-cancel-previous chain in `startRecording` calls this; the new `startRecording` clears the pending timeout so chained recordings don't flicker. |
| Strip-icon initial | First letter of project name | First letter of persona display_name (with project as fallback) | If you're rendering similar pill-style elements elsewhere, you may want the same semantic shift. |
