### Step 4 — Render module: orchestrator + barrel

**New files**:
- `render/NotificationsListRenderer.ts`:
  - Lifecycle (per **D-I** plural keys matching `StoreSet`):
    ```typescript
    interface NotificationsListRenderer {
      mount( root: HTMLElement, deps: { eventBus, stores: { notifications, senders, actionRequired } } ): void;
      unmount(): void;  // unsubscribes ALL EventBus listeners + clears root
    }
    ```
  - Hybrid render strategy (Q-B): hydrate=full, add/update/expire=keyed (via `keyedListMerge` on `data-id-hash`), `tick`=text-node only on `.action-required-countdown` (no parent-tree mutation).
  - Mount routing per **D-L**: action-required widgets → `#action-required-section`; sender cards → `#sender-cards-container`.
  - Empty-state (Q-K): paint `<div data-testid="multiplexer-empty-state">No notifications yet.</div>` when `notificationStore.list()` empty.
  - Subscription pattern reuses Phase 4's `unsubscribers: Array<() => void>` lifecycle (RE-6 — collect unsubscribe closures from `eventBus.on()`; `unmount()` runs each).
  - Per **F18**: 4 explicit empty-state transitions covered by tests — (a) hydrate-with-zero, (b) hydrate-with-N, (c) post-expired reducing to zero, (d) post-added from zero.
- `render/index.ts`:
  - `createNotificationsListRenderer({eventBus, stores})` factory (RE-12 — matches Phase 4 `createStores` + Phase 3 `createTransports` factory shape).

**New unit test**: `render/notifications_list_renderer.test.ts` floor ≥16 with these mandatory cases:
- Hydrate / add / update / expire / mount / unmount / no leaked listeners
- **Tick invariant** per **AC4** + **F5** + **A13**: set sentinel `data-test-canary="<uuid>"` on the `.action-required-widget` parent before tick burst; emit 10 `eventBus.emit("store_action_required_changed", { changeKind: "tick", id_hash, countdownMs })` calls at 100ms intervals; assert canary unchanged AND only `.action-required-countdown` `textContent` differs
- 4 empty-state transitions (per F18)
- Progress-group lazy-cache: hydrate → expand → simulate updated event → collapse → expand → newest entry visible (per F14)
