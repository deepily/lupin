## Context

This morning Rick spawned 5 fresh Claude Code sessions and got **3 × Rio + 2 × Mr. Radio**, with 4 of the 5 personas carrying `borrowed=true` (dashed-border badge in the UI). At day-start, with zero supposedly-live sessions and a 6-voice pool, this is impossible — unless the allocator believes prior allocations are still occupying slots.

Rick's intuition was correct: **stale persona allocations from prior days are not being cleared, and the pool reads as effectively exhausted from the moment the first session of the day starts.** This plan documents the root cause, fixes it, and folds in two related requests:

1. **Bug fix (primary)** — make the in-container occupancy scan actually prune dead-PID bridges.
2. **Feature** — replace the deterministic hash-borrow fallback with **Sam as the overflow persona**: multiple Sams are allowed, multiples of other personas are not.
3. **Log-only bug** — duplicate notification fan-out (5 × system broadcast + 4 × Mr. Radio "completed" / 1 × Rio "completed"). Add a TODO entry for follow-up; do not fix in this work.

**Reconstruction of the morning sequence**:

## Root Cause

`find_active_voice_persona_sessions()` in `src/lupin_cli/claude_code/hooks/lib/session_bridge.py:1249-1306` honors a conditional dead-PID filter:

```python
trust_host_pids = _can_trust_host_pids()  # False when /.dockerenv exists
...
if trust_host_pids:
    file_pid = _extract_pid_from_filename( path.name )
    if file_pid is not None and not _is_pid_alive( file_pid ):
        continue
```

`_can_trust_host_pids()` (`session_bridge.py:83-104`) returns `False` when running inside a container — because host PIDs are invisible from the container's PID namespace, and naive `kill(host_pid, 0)` would discard *every* bridge as dead, which is the OPPOSITE failure. The bypass exists for a real reason.

**The Lupin FastAPI server runs inside the `lupin-rest-dev` container.** Every call to `/api/cosa-voice/voice-persona/.../allocate` therefore hits the bypass path and counts every bridge with a non-null persona as occupied — including every leftover from yesterday.

The fix cannot simply delete the bypass; we need a liveness signal that works across the host-vs-container namespace boundary.

## Solution Design

### Layer 1 — Host-side housekeeper at SessionStart (primary fix)

The SessionStart hook (`src/lupin_cli/claude_code/hooks/register_session.py`) runs on the host, where host PIDs are trustworthy. Add a sweeper that runs before `/allocate` and nullifies the `voice_persona` field on any bridge whose PPID is dead.

```python
# New helper in session_bridge.py:
def prune_dead_persona_bridges() -> int:
    """
    Walk cc-*.json, null the voice_persona field on any bridge whose
    file PID is dead. Returns count of bridges pruned.

    Host-side only — relies on _is_pid_alive being meaningful.
    Safe to call from a SessionStart hook on every invocation.

    Ensures:
        - Stale bridges from prior days are scrubbed before the new
          session's /allocate POST runs
        - Bridges with isinstance(voice_persona, dict)=False are untouched
        - Returns 0 (not error) if SESSION_DIR doesn't exist
    """
```

Called once near the top of `register_session.py` (before line 868 where `_allocate_voice_persona_via_http` fires). Cost: tiny — one bridge directory scan per session start.

**This fixes the "first session of the day" case completely**, because the very first SessionStart hook of the day scrubs yesterday's leftovers before any allocation runs.

### Layer 2 — In-container TTL guard (belt-and-suspenders)

For the residual case where a host-side prune doesn't fire (e.g., user makes no fresh sessions all day but the server is bounced for an unrelated reason), add a TTL freshness check to `find_active_voice_persona_sessions` that runs **even when `trust_host_pids=False`**:

```python
# After the trust_host_pids block, before reading the file:
stale_threshold_seconds = config_value("cc session voice persona stale threshold seconds", default=43200)  # 12h
mtime_age = time.time() - path.stat().st_mtime
if mtime_age > stale_threshold_seconds:
    continue  # stale — treat as free
```

Use bridge file `mtime` (not `assigned_at`) because the cc-notification-listener heartbeat updates `mtime` periodically, giving us a free liveness signal that survives the namespace gap. Default threshold 12 hours — covers a normal workday with margin. Configurable via INI for sessions that legitimately run longer.

### Layer 3 — Sam-as-overflow allocation

Replace `borrowed_persona_for_sid` with Sam allocation when the pool is exhausted. Sam stays the system-default for any `voice_id`-less TTS request (unchanged). The only new behavior: when `pool − occupied` is empty, return Sam with `overflow=True` instead of hash-borrowing an in-use pool persona.

**INI additions** (`src/conf/lupin-app.ini`):

```ini

cc session voice persona sam icon         = 🎙️
cc session voice persona sam color        = #00BCD4
cc session voice persona sam profile      = System default voice (overflow)
cc session voice persona sam display name = Sam
# Sam's voice_id is the SAME as elevenlabs tts default voice id — single source of truth
# Sam is intentionally NOT in `cc session voice persona pool` — he is appended
# only when the main pool is fully occupied.

cc session voice persona stale threshold seconds = 43200
```

**Helper change** (`src/cosa/rest/voice_persona_helpers.py`):

```python
def load_overflow_persona_from_config( config_mgr ) -> Optional[ PoolPersona ]:
    """Load Sam — reads sam_* keys + elevenlabs tts default voice id."""
    voice_id = config_mgr.get( "elevenlabs tts default voice id", default="" )
    if not voice_id:
        return None
    return {
        "name"         : "sam",
        "display_name" : config_mgr.get( "cc session voice persona sam display name", default="Sam" ),
        "voice_id"     : voice_id,
        "icon"         : config_mgr.get( "cc session voice persona sam icon",         default="🎙️" ),
        "color"        : config_mgr.get( "cc session voice persona sam color",        default="#00BCD4" ),
        "profile"      : config_mgr.get( "cc session voice persona sam profile",      default="System default voice" ),
        "overflow"     : True
    }

def pick_unallocated_persona( pool, occupied_names, stable_session_id, overflow_persona=None ):
    if not pool:
        return None
    free = [ p for p in pool if p[ "name" ] not in occupied_names ]
    if not free:
        if overflow_persona is not None:
            return dict( overflow_persona, borrowed=False )  # overflow=True preserved
        return borrowed_persona_for_sid( pool, stable_session_id )  # legacy fallback only if Sam unconfigured
    chosen = random.choice( free )
    return { **chosen, "borrowed": False }
```

`allocate_persona_for_session` passes the overflow persona through.

## Risks / Gotchas

1. **Host-side prune races with concurrent allocations.** Two simultaneous SessionStart hooks could both prune + allocate. The router's `asyncio.Lock` serializes the in-process critical section, so the worst case is one prune scrubs slightly-stale state before the second prune runs — idempotent. No data corruption.
2. **TTL false-positives for long-running sessions.** A session running >12h gets falsely pruned. Mitigation: the cc-notification-listener already updates the bridge `mtime` on every heartbeat (verify in Phase 3), so an active session keeps its mtime fresh. If verification shows the listener doesn't update mtime, we'll add an explicit touch.
3. **Sam overflow flips a UI contract.** The old `borrowed=true` cue (dashed border + "↻") had specific semantics ("you're using someone else's voice"). Sam's `overflow=true` is semantically different ("the pool spilled to the default voice"). The CSS variant must be visually distinct so the user can tell at a glance.
4. **`borrowed_persona_for_sid` becomes legacy.** Keep it as a defensive fallback for the case where Sam config is missing — but flag it with a deprecation comment pointing to overflow.
5. **Mobile dart model is a separate sub-repo.** Per nested-repo rules, this plan's edit to `voice_persona.dart` only modifies the file; commits in `src/lupin-mobile/` happen in a separate sub-project context.
