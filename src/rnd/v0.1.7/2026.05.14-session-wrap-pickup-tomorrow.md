## What we shipped today (committed)

### 🌅 Morning — TTS preview action-required + Mr.-split fix (commit `d87e0d7`)

Two bugs in the 2026-05-13 TTS preview-and-pause feature:

- **Bug A (URGENT cost burn)**: action-required notifications opted OUT of preview-and-pause. Every long `ask_yes_no` / `ask_multiple_choice` / `converse` played full TTS verbatim.
- **Bug B (correctness)**: `_splitIntoSentences()` regex falsely split `Mr.` as a sentence boundary, previewing only "Mr." (~16 chars) for session-end style messages.
- **Latent bug found in flight**: `match()`-based splitter silently dropped prefix text when its lookahead failed (`"3.14 is pi."` → `["14 is pi.", "Foo."]`).

Fix: removed action-required opt-out, swapped response handler to `stopTTSAndAdvance()` for auto-pause stall, rewrote `_splitIntoSentences()` with 25-abbreviation pre-mask + `match()` → `split()` lookbehind+lookahead swap, `Math.floor` → `Math.ceil` for previewCount, inline `_tts_quick_self_test()` with 9 cases.

### 🌞 Afternoon — Notification-list / TTS-queue decouple (commit `efbcae3`)

The morning's preview-and-pause shipment exposed a downstream bug: high/urgent fire-and-forget notifications had a DEFERRED render path. `addNotificationToSenderGroup()` was called from inside `activateNextTTS()`, gated by `if ( this.isTTSPaused ) return;`. When the queue auto-paused after preview, subsequent notifications were invisible — Rick reported a 20+ item backlog stranded behind a paused TTS queue.

Fix: render to visible list IMMEDIATELY on WS arrival in `handleNotificationUpdate` high/urgent branch. Mirrored the low/medium pattern. Added `.is-tts-pending` CSS class — amber stripe + ⏳ corner glyph — to mark cards queued for TTS but not yet playing.

### 🌙 Evening — TTS preview-and-advance + runtime slider + strict FIFO (commit `5836a6f`)

Two more shape changes after Rick lived with the morning + afternoon fixes:

1. **Stop instead of pause** — removed `_ttsPausedAfterPreview` field entirely, `onTTSPlaybackComplete` preview-pause early-return deleted, `resumeTTS` preview-remainder branch deleted, `stopTTSAndAdvance` special case deleted, dropped `remainderText` from item shape.
2. **Runtime percentage slider** — 5-stop control (0/25/50/75/100) in `#cc-session-strip` (later moved to accordion header). 0% adds new `stage='skip'` that bypasses audio dispatch while keeping the notification in the visible list. Strict FIFO in `addToTTSQueue` — every item pushes to back regardless of type (action-required no longer jumps the queue).
3. Persisted via `notifications_tts_preview_fraction_runtime` localStorage key; seeded from INI `tts preview fraction` default on first load.

Live-tested at 25% / 50% / 100% / 0% — Rick confirmed: "this is the U-X I was looking for, basically a global verbosity filter."
