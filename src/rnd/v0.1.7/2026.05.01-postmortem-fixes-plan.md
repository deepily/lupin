## Phase 2 — Cluster D: `test_suite` mode HTTP 500 (real product bug) ★ HIGH PRIORITY

**Bug**: `src/cosa/rest/todo_fifo_queue.py:634-647` — branch ordering checks `MODE_TO_AGENT` before `AGENTIC_MODE_MAP`; for modes present in BOTH dicts (`test_suite`, `presentation`, `deep_research`, `podcast`, `research_to_podcast`, `claude_code`, `swe_team`, `research_to_presentation`), the wrong branch fires and produces a malformed command (underscore instead of space). Falls through to "TO DO: Implement else case" → downstream `.split()` on `None` → HTTP 500.

**Fix** (one-shot, ~5 line change):

```python
# CURRENT (todo_fifo_queue.py:634-647)
if user_mode and user_mode in MODE_TO_AGENT:
    command = f"agent router go to {user_mode}"
elif user_mode and user_mode in AGENTIC_MODE_MAP:
    command = AGENTIC_MODE_MAP[ user_mode ]
else:
    # LLM routing
    ...

# PROPOSED (re-order)
if user_mode and user_mode in AGENTIC_MODE_MAP:
    # Agentic modes (test_suite, deep_research, podcast, ...) — use canonical command string
    command = AGENTIC_MODE_MAP[ user_mode ]
    args = ""
elif user_mode and user_mode in MODE_TO_AGENT:
    # Direct-routed modes (calculator, todo, calendar, ...) — synthesize from user_mode
    command = f"agent router go to {user_mode}"
    args = ""
else:
    # LLM routing
    ...
```

**Why this works**: `AGENTIC_MODE_MAP` keys are the strict subset of agentic modes that need their underscore→space transformation; for non-agentic direct-routed modes (`calculator`, `todo`, `calendar`, `weather`, `datetime`), the f-string synthesis is correct because those keys don't have multi-word forms.

## Phase 4 — Cluster F: `notify_user_sync` connect-timeout bug ★ MEDIUM-HIGH PRIORITY

**Discovery from Explore agent (Phase 1 of this plan)**: The bug is NOT in `idle_waiter.py` itself but in the shared `notify_user_sync` library it depends on.

**Bug**: `src/lupin_cli/notifications/notify_user_sync.py:225` — `requests.post(..., timeout = request.timeout_seconds + 10)` uses a single total-timeout. When the URL is unreachable (test sets `LUPIN_API_URL=<unreachable>`), the OS-level TCP SYN retry can dominate the 70s budget, exceeding the test's 15s window. The waiter subprocess survives 15s and gets SIGKILL'd.

**Fix** (one-line, surgical):

```python
# CURRENT (notify_user_sync.py:225)
timeout = request.timeout_seconds + 10  # +10s for network overhead

# PROPOSED — split into (connect, read)
timeout = ( 3, request.timeout_seconds + 10 )  # ( connect_timeout, read_timeout )
```

**Why 3s connect**: Plenty for any localhost or LAN target, fails fast on unreachable URLs. The read budget is unchanged, so legitimate long-running notifications (180s confirmation prompts) continue to work.

**Cross-cutting impact**: This `notify_user_sync` is the SAME path the expeditor uses for Cluster A (the 503 cascade). Fixing the connect-timeout doesn't directly fix Cluster A (503 is an HTTP-level response, not a timeout), but it improves resilience whenever the notification target is partially-reachable.

**Files to edit**:
- `src/lupin_cli/notifications/notify_user_sync.py:225` (parent Lupin repo — I edit, user commits in Lupin session)

**Tests to add**:
- `src/tests/unit/test_notify_user_sync_timeout.py` (new) — mock `requests.post` and assert it's called with `timeout=(3, ...)`. One test, ~15 lines.
- The existing `src/tests/smoke/test_idle_waiter_smoke.py::test_waiter_lifecycle_state_transitions` becomes the smoke regression — should go red→green.

**Verification**:

- Smoke regression on `:7999`: `pytest src/tests/smoke/test_idle_waiter_smoke.py -v`

## Phase 6 — Cluster B: Scheduler `--auto-proxy` propagation ★ DESIGN DECISION REQUIRED

**Discovery from Explore agent (Phase 1 of this plan)**:
- Endpoint: `src/cosa/rest/routers/test_suite.py:70-169` accepts `pytest_args: str` in the request body.
- Job class: `src/cosa/agents/test_suite/job.py:136, 184` stores it; `_run_suite()` at line 718 builds `cmd = ["bash", script_path] + sanitized_args`.

- INI key exists but unused by endpoint: `test suite default pytest args = ` (empty) at `src/conf/lupin-app.ini:1039-1040`.

**Three options** — user decision required before implementation:

### Option A — Per-test-file map in `job.py` (simplest, hardcoded)

Add to `src/cosa/agents/test_suite/job.py` near the top (next to `SUITE_SCRIPTS`):

    "src/tests/smoke/test_presentation_live_smoke.py",
    "src/tests/smoke/test_research_to_presentation_live_smoke.py",
})

In `_run_suite()` (line ~718), if the suite is `smoke` AND any LIVE_SMOKE file exists in the resolved test path, append `PYTEST_ARGS_FOR_LIVE_TESTS`.

**Pros**: One-file change, no schema change. **Cons**: Hardcoded list; cost cap not per-test tunable.

### Option B — INI-driven per-suite config

Add to `src/conf/lupin-app.ini` `[Lupin: Baseline]`:

Refactor `_expand_all()` to split smoke into "smoke-fast" and "smoke-live" buckets. Schedule them as two pytest invocations with different args.
