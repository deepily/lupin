## Context

The voice-persona allocator has a **latent collision bug**. When the named pool
(`maria, mr radio, Rachel, Tiberius, Rio, Tiffany, Krishna, sam`, with `arnold` configured as the
single overflow via `cc session voice persona overflow name`) is exhausted,
`pick_unallocated_persona` hands *every* further session the **identical** overflow dict — same
`name` ("arnold"), same `voice_id`, same 🪨 icon, same color, `overflow=True`. One overflow renders
fine; **two or more concurrent overflows are visually indistinguishable** in the chorus UI.

The trigger is a forthcoming **cascade-review workflow** that can spin up 7-8 concurrent reviewer
sessions — right at or past the named-pool ceiling. Rick wants overflow sessions to stay *visually*
distinct even though they share one voice. Separately, Rick is acquiring 1-2 more ElevenLabs voices
to widen the named pool, so the Extra-N tier is a **rare deep-overflow fallback**, not the common
path.

### Decision (locked)

Via `ask_multiple_choice` (2026-05-28), Rick selected **Option A — "Arnold first, then Extra N"**:

- **1st overflow session** → stays **"Arnold"** (🪨, his real color) — exactly as today. Zero
  behavior change for the common single-overflow case.
- **2nd, 3rd… concurrent overflow** → **"Extra 1", "Extra 2"…** — distinct names + distinct colors,
  all speaking in the configured overflow voice (Arnold's `voice_id`).

Rejected Option B ("all overflows are Extra N") because it erases Arnold's name from the badge UI
even for a single overflow.

### Outcome & honest limitation

Never run out of allocable *identities*; the today-collision bug is fixed; Arnold remains a
recognizable named character for the typical case. **Extra-N disambiguates the eye, not the ear** —
all Extras share Arnold's voice. This is acceptable: Rick is buying real voices for true audio
distinction, and cascade-review output is *written* (review docs), not listened-to live.

### Explicitly out of scope (shelved during the design discussion)

Headless `tmux` + Claude-Code session spawning + teardown. The fork "do cascade reviewers need to be
voiced chorus peers, or just parallel review compute?" resolved to **compute** — reviewers ride the
existing **Workflow tool / bounded `ClaudeCodeJob` / CJ-Flow** path, which already does
fan-out → verify → synthesize. No new spawn machinery is built.

## Design

All logic lives in the pure-functional helper `src/cosa/rest/voice_persona_helpers.py`. The bridge
file remains the single source of truth — occupancy is computed by the existing live scan
(`find_active_voice_persona_sessions`), so a dead session frees its identity (Arnold *or* Extra-N)
automatically, no counter, no registry, no sweeper.

**No frontend work.** The UI badge path (`broadcast-panel.js`,
`multiplexer/render/templates/personaModal.ts`, `focusTray.ts`) renders
`name`/`display_name`/`icon`/`color` generically; the old `.persona-badge.overflow` styling is
already retired. The router voice-id acceptance (`routers/voice_persona.py:537-541`) already adds the
overflow `voice_id` to `pool_ids`, and Extras share that same `voice_id`, so request-persona
validation needs no change either.

### Allocation algorithm

In `pick_unallocated_persona`, the exhausted-pool + overflow branch becomes:

```python
if not free:
    if overflow_persona is not None:
        if overflow_persona[ "name" ] not in occupied_names:   # "arnold" still free
            return dict( overflow_persona, borrowed=False )      # ← today's behavior, unchanged
        n = _lowest_free_extra_n( occupied_names )               # 1, 2, 3… lowest unused "extra N"
        return _make_extra_persona( overflow_persona, n, extra_colors )
    return borrowed_persona_for_sid( pool, stable_session_id )   # legacy fallback, unchanged
```

- `_lowest_free_extra_n( occupied_names )` → `n = 1; while f"extra {n}" in occupied_names: n += 1`.
  Stateless, self-freeing, **gap-reusing** (Extra 2 dies → next allocation reuses "extra 2", does not
  skip to "extra 3").
- `_make_extra_persona( base_overflow, n, extra_colors )` → fresh dict:
  - `name`         = `f"extra {n}"` (lowercase key form, space-separated — same convention as "mr radio")
  - `display_name` = `display_name_for( f"extra {n}" )` → "Extra 1"
  - `voice_id`     = `base_overflow["voice_id"]` (Arnold's voice)
  - `icon`         = `base_overflow["icon"]` (🪨; the number lives in `display_name`)
  - `color`        = `extra_colors[ (n - 1) % len(extra_colors) ]`, falling back to
    `base_overflow["color"]` when the palette is empty
  - `overflow`     = `True`, `borrowed` = `False`

### Plumbing changes

- `pick_unallocated_persona( pool, occupied_names, stable_session_id, overflow_persona=None, extra_colors=None )`
  — add the optional `extra_colors` param (list of hex strings).
- `allocate_persona_for_session( config_mgr, stable_session_id )` — read the palette and pass it
  through:
  ```python
  extra_colors = [
      c.strip()
      for c in config_mgr.get( "cc session voice persona extra colors", default="", silent=True ).split( "," )
      if c.strip()
  ]
  ```

### Config

Add to `[Lupin: Baseline]` in `src/conf/lupin-app.ini` (with a matching `lupin-app-splainer.ini`
entry — mandate):

```
cc session voice persona extra colors = #4527A0, #6A1B9A, #9C27B0, #AD1457, #C2185B, #7B1FA2
```

Starter palette is **green-rule compliant** (per `feedback_no_green_in_persona_pool`: green RGB
component < 30% AND green *strictly the lowest* of the three channels — never in the top two): a
purple→magenta family — indigo `#4527A0`, purple `#6A1B9A`, orchid `#9C27B0`, magenta `#AD1457`,
rose `#C2185B`, violet `#7B1FA2`. Cycles by `(n-1) % len`. The "Extra" display prefix is hardcoded
in `_make_extra_persona` (trivially promotable to a config key later if needed).

> **Implementation note:** my first-draft palette (slate/brown/indigo/deep-orange) was 4/6
> green-rule **non-compliant** — caught by the `TestExtraColorsGreenRule` invariant test before any
> run. The shipped palette above passes all six (green strictly lowest channel, all < 16%).
