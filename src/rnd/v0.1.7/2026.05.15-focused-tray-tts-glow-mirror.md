## TL;DR

When a notification bubble is being read aloud via TTS, mirror the same pulsing-yellow drop-shadow glow onto the subscript speaker icon (`.cc-strip-icon::before`) of the persona currently speaking, in the focused tray. Re-paint the subscript icon's background as a two-tone green: lighter green when idle, darker green when that persona is the current TTS source. Both signals (darker green AND pulsing glow) fire together on TTS start and clear together on TTS end.

**Outcome for Mr. Rick**: at-a-glance "who is speaking right now" in the strip, without having to scroll the notification feed.

---

## Visual State Matrix

| Persona Strip Icon State          | Subscript-Icon Background           | Drop-Shadow Animation               |
|-----------------------------------|-------------------------------------|-------------------------------------|
| **Idle** (no TTS for this persona)| `rgba( 25, 135, 84, 0.25 )` (light) | none                                |
| **TTS rendering for this persona**| `rgba( 25, 135, 84, 0.95 )` (dark)  | `ttsPulseGlow` 1s ease-in-out infinite |
| TTS finished                      | reverts to light green              | animation cleared                   |

The **lighter green** matches `.sender-conversation-mode-btn.is-active` background (`notifications.css:1821`). The **darker green** is the existing strip-icon speakerphone color (`notifications.css:2191`). The **yellow glow** reuses the existing `@keyframes ttsPulseGlow` (`notifications.css:2778-2787`) — no new keyframes required.

## Affected Surfaces

### CSS — `src/fastapi_app/static/css/notifications.css`

1. **Lighten idle background** (modify line ~2191):
   - Current: `background: rgba( 25, 135, 84, 0.95 );` on `.cc-strip-icon[data-conv-mode="speakerphone"]::before`
   - New: `background: rgba( 25, 135, 84, 0.25 );` (idle = light)

2. **Add active-speaker rule** (new rule, near line 2197):
   ```css
   .cc-strip-icon[data-tts-active="true"]::before {
       background: rgba( 25, 135, 84, 0.95 );
       animation: ttsPulseGlow 1s ease-in-out infinite;
   }
   ```

3. **Optional small-radius variant** (risk mitigation, see §Risks below): if the existing 5-15px box-shadow bleeds too far on an 18px subscript icon, add `@keyframes ttsPulseGlowSmall` with 2-6px values and reference it in the new rule.

### JS — `src/fastapi_app/static/js/notifications.js`

1. **TTS-start hook** (in or adjacent to `activateNextTTS()` at line ~13711, or wherever `.tts-playing` is added to `.sender-message` at lines ~4904/4922):
   - Resolve `sender_id` of the bubble whose TTS just started.
   - Apply: `document.querySelectorAll( \`.cc-strip-icon[data-sender-id="${sender_id}"]\` ).forEach( el => el.dataset.ttsActive = "true" );`

2. **TTS-end hook** (matching teardown — wherever `.tts-playing` is removed):
   - Resolve same `sender_id`.
   - Clear: `document.querySelectorAll( \`.cc-strip-icon[data-sender-id="${sender_id}"]\` ).forEach( el => delete el.dataset.ttsActive );`

3. **Defensive cleanup** on TTS-cancel / page-unload / WS-disconnect: clear `data-tts-active` on ALL strip icons to prevent stuck-on glow.

## Phase 1 + 2 Implementation Log (2026-05-15)

**CSS** (`src/fastapi_app/static/css/notifications.css:2172-2218`):
- Added `transition: background 500ms ease-in-out;` to the shared base rule for both speakerphone and quiet variants (no-op for quiet since its background never changes).
- Lightened speakerphone idle background from `rgba( 25, 135, 84, 0.95 )` → **solid `#d1e7dd`** (Bootstrap `success-bg-subtle`).
  - **First attempt was `rgba( 25, 135, 84, 0.25 )`** — verbatim copy of the `.sender-conversation-mode-btn.is-active` value. Mr. Rick caught this on first refresh: the toggle's 25%-alpha works because it sits on a light sender-card, but the strip-badge sits on a *persona-colored* circle, so alpha-blending read as washed-out / transparent instead of pale green. Fixed by picking a solid perceptual-equivalent shade.
- Added `.cc-strip-icon[data-conv-mode="speakerphone"][data-tts-active="true"]::before` rule: re-asserts darker `0.95` green and applies `ttsPulseGlowSmall` animation. Selector explicitly excludes `data-conv-mode="quiet"` so 🤭 amber badges stay untouched.
- Added `@keyframes ttsPulseGlowSmall`: peak `box-shadow: 0 0 6px 2px` + `outline: 1px`; rest `box-shadow: 0 0 2px 1px` + `outline: 1px` — sized for 18px badge, no spillover into adjacent strip icons.

**JS** (`src/fastapi_app/static/js/notifications.js:4895-4960` area):
- Hooked `startTTSPlayingIndicator()` and `stopTTSPlayingIndicator()` to call new `_mirrorTTSStateToStripIcons( notificationElement, active )` helper.
- Helper walks up to nearest `.sender-card` to resolve `data-sender-id`, then toggles `data-tts-active="true"` (or `delete`) on every matching `.cc-strip-icon[data-sender-id="..."]` in the DOM. Multi-instance safe.
- `node --check` passes; CSS sanity (balanced braces, all 4 rules present) verified via Python script.

**Not done**:
- TTS-cancel / WS-disconnect cleanup paths — pre-existing concern, not introduced by this change. If `stopTTSPlayingIndicator()` is bypassed by an abrupt cancel, the strip icon would stay green-glowing until next start/stop cycle. Out of scope for this tweak.

## Risks & Open Questions

1. **Glow blast-radius on tiny element** — `ttsPulseGlow` uses `box-shadow: 0 0 15px 5px` at peak; on an 18px badge offset `bottom: -6px right: -6px`, the spread may overlap adjacent strip icons. **Mitigation**: introduce `ttsPulseGlowSmall` keyframes with 4-8px peak, sized for badge. Will judge during Phase 1.

2. **Multi-window strip icons** — every focused-tray instance with the same `data-sender-id` should glow. The `querySelectorAll` form above handles this; confirm no shadow-DOM/iframe surfaces exist that would isolate matches.

3. **Quiet-mode (🤭 amber badge) behavior** — the user's request only addresses the speakerphone (🔊) variant. **Default**: leave `data-conv-mode="quiet"` icons untouched (they don't render TTS by definition). If Mr. Rick wants the glow to fire on quiet-mode personas too, we'll need a follow-up gate.

4. **Active-speaker vs. recently-spoke decay** — request says "once TTS is finished, pulsing goes away". Reading literally: the darker green also reverts immediately to light. **Alternative**: brief fade-out (e.g., 500ms transition on background) so the change isn't a hard pop. Default to hard switch unless Mr. Rick wants a fade.

5. **Coverage** — `notifications.js` and `notifications.css` live OUTSIDE `src/fastapi_app/static/js/multiplexer/`, so the 100% c8 mandate does NOT apply. Manual visual check on `:7999` + Playwright visual regression on `:8000` is the proportionate test bar.

## Decisions (Mr. Rick — 2026-05-15 voice reply)

1. **Glow size** — ✅ Scale down. Introduce `@keyframes ttsPulseGlowSmall` sized for the 18px badge (peak ~6px box-shadow, ~1px outline; rest ~2px box-shadow, ~1px outline).
2. **Fade on TTS-end** — ✅ 500ms fade-out preferred over hard switch. Implement via `transition: background 500ms ease-in-out;` on the `::before` base rule.
3. **Quiet-mode (🤭) badge** — ✅ Leave untouched. No green/glow applied to `data-conv-mode="quiet"` icons.
4. **Recently-spoke decay** — ✅ No persistent "recently spoke" state. TTS-end → revert immediately to idle (with the 500ms fade for polish, not a separate timer).
5. **Visual-regression scheduling** — ⏳ Open. Will re-ask after Phase 3 manual `:7999` check passes.

## Implementation Notes (post-decision)

**JS sender_id resolution**: `startTTSPlayingIndicator(notificationId)` and `stopTTSPlayingIndicator(notificationId)` (lines 4895 / 4917) only know the notification element's ID. Walk up to nearest `.sender-card` to resolve `data-sender-id`:

```js
const senderCard = notificationElement.closest( '.sender-card' );
const senderId   = senderCard?.getAttribute( 'data-sender-id' );
if ( senderId ) {
    document.querySelectorAll( `.cc-strip-icon[data-sender-id="${ senderId }"]` )
        .forEach( el => el.dataset.ttsActive = "true" );  // or `delete el.dataset.ttsActive`
}
```

This pattern handles multi-instance strip icons (one per visible focused-tray surface).
