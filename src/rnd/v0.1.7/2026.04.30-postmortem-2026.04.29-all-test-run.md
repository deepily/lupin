**Files**: `src/tests/unit/test_swe_team_job.py` (parent Lupin — safe to edit in this session).

**Risk**: Near-zero. Test-only change. Identical to fixes already shipped for other agents.

### Cluster B — `auto_round` import not gated → `test_lora_env_update_smoke` cascades (3 smoke failures) ★ EASY

- `test_update_preserves_other_models`
- `test_prefers_8bit_over_4bit`

The container intentionally omits `auto_round` because it's only used at training time on a GPU host, not in the test/dev container. Mirror the pattern. The test only exercises `_update_lora_env()` which doesn't need the AutoRound class.

**Files**: `src/cosa/training/quantizer.py` (CoSA submodule — **edit allowed per `feedback_cosa_edit_vs_manage_git`, but DO NOT git-manage. Surface as user-side commit when they return.**)

**Fix path**: Need to instrument `:8000` to capture the full traceback (the user-facing error swallows the `traceback.print_exc()` output to container stdout per `queues.py:246`). Could also be reproduced locally via a unit test that calls `TestSuiteJob.factory_from_config(...)` with a fake config_mgr that returns `None` for both keys.

## 7. Process Note (for future runs)

The `all-remediation.json` schema is excellent for this kind of postmortem — having `failures[]` with `traceback`, `suite`, `time`, and `classname` per failure reduced the cluster-finding work from ~1 hour of grep to ~10 minutes. The fact that it surfaces every sub-failure even when the pytest entry point is `quick_smoke_test()` returning False is critical — without that the smoke tests look like 9 opaque "F"s.

One observation: `test_proxy_integration.py` and `test_expeditor_mock_job_smoke.py` show structured per-scenario PASS/FAIL/CANCEL tables in stdout, but the JSON only captures the entry-point-level FAIL. If we want the structured table to be programmatically queryable across runs, the entry point should aggregate per-scenario into a JUnit `<testsuite>` and rely on pytest's machinery rather than asserting on the aggregate boolean. That's a future R&D thread, not a fix.
