## Determined architecture (forced by the host/container boundary)

Exploration nailed the one constraint that decides everything:

| Component | Runs where | tmux access |
|---|---|---|
| cosa-voice **MCP server** (`src/lupin_mcp/cosa_voice_mcp.py`) | **HOST** (stdio subprocess of `claude`, registered via `install-cosa-voice.sh` → `claude mcp add --transport stdio`) | ✅ can run `tmux`/scripts |
| Lupin **FastAPI** (`:7999`/`:8000`) | **container** | ❌ no tmux, no host PIDs |
| `start-cc-with-tmux.sh`, SessionStart hook, cc-notification-listener | **HOST** | ✅ |

→ **The spawn trigger MUST be a cosa-voice MCP tool (host-side), NOT a container REST endpoint.** A
container endpoint physically cannot create a host tmux session. This is the load-bearing decision.

### The shared contract (Track T builds it; Track M documents against it)

**New MCP tools** in `src/lupin_mcp/cosa_voice_mcp.py` (`@mcp.tool` pattern; precedent =
`_request_persona`, lines 1776-1888). Signatures reconciled with María's runbook needs:

```
spawn_sessions(
    count,                       # int ≥ 1 (capped by INI)
    manager_persona,             # slugified for the collection topic + reviewer names (dm-tiberius)
    task_prompt,                 # str; supports template tokens {role} {section}
                                 #   {scope_sentence} {cascade_name} {parent_topic}
                                 #   {manager_session_id} — templates live in workflow/ for portability
    project        = "lupin",    # sets cwd + which CLAUDE.md loads
    role           = "reviewer", # enum: reviewer | author | observer | manager
    persona_preference = None,   # str | list[str]; if any requested persona is unavailable the
                                 #   spawn FAILS PREDICTABLY rather than silently re-allocating
                                 #   (keeps Cast Manifests stable across cascades)
    seed_memento       = None    # optional path/ref to a prior memento; APPENDED after the rendered
                                 #   task as a trailing "Prior context" reference appendix (task
                                 #   leads; a large memento never buries the directive). Pairs with
                                 #   write_memento on dismiss. (Rick 2026-05-28: full continuity loop
                                 #   in v1; APPEND not prepend.)
) -> dict
    # Host-side: runs the headless spawn script `count`× with unique tmux names; each child
    # starts as `claude "<rendered task_prompt>"`, allocated headless=True (below).
    # Returns { spawned: [ {session_id, persona_name, persona_icon, persona_color,
    #           tmux_session_name, requested_role, status}, ... ],
    #           manager_persona, collection_topic }.
    # Tags each child bridge spawned_by=<manager session_id> for lineage/reaping.

dismiss_sessions(
    session_ids   = None,   # default: all sessions I spawned (via spawned_by tag)
    reason        = "",     # recorded; surfaced to the reviewer before teardown
    write_memento = True    # give the child a chance to write a memento (per
                            #   workflow/memento-management.md 7-element contract) BEFORE
                            #   tmux kill, so persona specialization survives re-spawn
) -> dict
    # tmux kill-session for each + nullify its persona bridge so the Extra-N/pool slot frees
    # immediately (reuse the prune primitive in session_bridge.py, not the 12h mtime TTL).

list_spawned_sessions() -> dict   # what this manager spawned + liveness
```

**`headless=True` persona allocation (per María; refined by Rick 2026-05-28):** spawned reviewers
are allocated with a `headless` marker. The broadcast/TTS layer must distinguish **two axes**:
- **Spoken TTS: OFF by default**, but **individually un-mutable on demand** — the user or manager can
  un-mute any ONE reviewer to "tap it on the shoulder" (per-session TTS-enable toggle). Avoids a
  serialized chorus of identical-voiced Extra-N reviewers burying the manager's voice.
- **Text broadcasts: ON** — user broadcasts still inject as text to headless reviewers so Rick can
  halt/steer the running pack. Their own asks route as blocking peer DMs to the manager.

**Lifecycle signals (v1 = commons-post; richer push deferred to v1.1):** v1 — each child posts
`ready, [role]` to `dm-{manager}` on startup (manager's existing poll/push sees it; satisfies
María's §3 worked example) and posts a `died`/error notice on crash. v1.1 — optional
`on_spawn_complete` / `on_session_died` push hooks via the existing commons-question-watcher infra
(flagged, not v1-blocking).

**Task delivery:** initial `claude "<task_prompt>"` arg (simplest; child reads its brief on
startup). The manager templates the prompt to include role + "post findings to `dm-{manager}` via
`commons_post`/`commons_send_to` with `in_reply_to`". **No new result-collection code** — reuse the
existing commons DM-threading the cascaded-review workflow already runs on
(`src/lupin_mcp/commons_store.py`, `commons_read(topic="dm-{manager}", since=...)`).

**Headless spawn:** add a `--headless` (detach-only) path to `src/scripts/start-cc-with-tmux.sh`
that skips the blocking `tmux attach` and accepts an initial-prompt arg — keeps the persona env-flags
DRY rather than forking a second script.

### Decisions (RESOLVED — Rick, voice 2026-05-28)

1. **Generic `spawn_sessions`** (not cascade-specific) — the pattern will repeat. ✅
2. **Task delivery = initial `claude "<prompt>"` arg** (not send-keys). ✅
3. **Teardown = explicit `dismiss_sessions` + idle-TTL auto-reap backstop in v1** — a crashed/
   forgotten manager never strands reviewers burning OAuth. ✅
4. **Lifecycle signals = commons-post in v1** (child posts "ready"; death covered by the auto-reaper
   + ready-ack timeout). Push hooks (`on_spawn_complete`/`on_session_died`) deferred to v1.1. ✅
5. **Reviewer TTS = silent by default, individually un-mutable on demand** — clean audio channel
   (no chorus of identical Arnolds burying the manager's voice), but the user/manager can un-mute
   any ONE reviewer to "tap it on the shoulder." Reviewers remain **text-broadcastable** (user
   broadcasts inject as text so Rick can halt/steer the pack). ✅
   **MECHANISM RESOLVED DURING BUILD (no new code path):** this maps ONTO THE EXISTING speakerphone
   primitive — do NOT build a parallel `tts_muted` flag / broadcast-panel two-axis / new un-mute
   toggle. Evidence (Explore trace 2026-05-28): (a) per-session spoken TTS is already gated by
   `speakerphone_on` → browser `conversationModes[sid]` (a session that isn't speakerphone-on is not
   spoken); (b) reviewers communicate findings via **commons text**, not `notify()`-TTS, so they're
   silent by their comms path anyway; (c) user **text broadcasts reach sessions independently** of
   `speakerphone_on` (injected via the listener) — text-broadcastable is already true; (d) **un-mute
   = the existing `POST /api/cosa-voice/speakerphone/{sid}` / `enable_speakerphone` targeting that
   reviewer** (already per-session, already broadcasts `speakerphone_changed`). The ONLY residual
   hardening is belt-and-suspenders against a *stray* reviewer `notify()`: have a headless reviewer
   self-register `speakerphone_on=False` in its SessionStart so the browser pre-mutes it (the
   `conversationModes[sid] === false` strict check otherwise leaves an unknown session un-muted).
   That single change lives in the high-risk `register_session.py` bootstrap hook → done in a
   focused, carefully-verified pass, not bundled. ✅ semantics; ⏳ stray-notify hardening.
6. **Author narrative continuity = full loop in v1** — `persona_preference` (same voice across
   rounds) + `seed_memento` on spawn (restores prior context) + `write_memento` on dismiss. The
   author returns as the same persona *and* remembers authoring the plan. ✅
   **Memento archive convention = Option B (per-persona-per-cycle archive)** — on
   `write_memento=True`, the child writes to `io/mementos/<persona-slug>-<YYYY.MM.DD-at-HHMM>.md`
   (archived, no clobber, so parallel personas keep independent continuity threads). On re-spawn the
   Manager selects the archived path and passes it as `seed_memento`. (If `workflow/memento-management.md`
   dictates a canonical dir, adopt that.) Decided with María 2026-05-28.

**Cost/throttle (standing constraint):** N concurrent reviewers share Rick's Max-plan rolling
window → live cascade runs obey the **off-peak rule** (post-midnight); flagged in María's runbook.

**Voice-continuity caveat:** Extra-N reviewers share Arnold's voice, so voice-continuity is most
meaningful for *named-pool* personas (the author should ideally be a stable named persona) — another
reason the "buy more ElevenLabs voices" track matters.
