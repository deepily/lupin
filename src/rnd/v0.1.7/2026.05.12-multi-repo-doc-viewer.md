# Multi-Repo Browsing for the Lupin Doc Viewer

## 1. Context

The Lupin doc viewer (built earlier today — see [`2026.05.12-doc-viewer-directory-listing.md`](2026.05.12-doc-viewer-directory-listing.md)) currently serves files from a single repo (the Lupin parent) under a narrow whitelist (`src/docs/`, `src/rnd/`, `src/workflow/`, plus a handful of root `*.md` files). Rick owns and develops in multiple repos and wants to browse code/docs across them via the same UI without context-switching.

**Trigger**: Rick hit a `404` while typing the path `src/rnd/2026.05.12-hello-bq-world-decision-reconciliation.md` and assumed it was a whitelist bug. Investigation showed the file simply doesn't exist in the Lupin repo — it belongs to a different repo entirely. The episode crystallized the broader UX gap: the viewer should be able to browse files in any of Rick's repos.

**Goal**: Extend the viewer to support N named "scopes", each a separately configured repo root with its own whitelist. Cross-repo browsing in the same UI; per-scope security boundaries preserved.

**Out of scope for this design**:
- Cross-repo SEARCH (grep across all scopes) — could be a follow-on
- Writing to external repos — viewer is read-only by definition
- Syntax highlighting (deferred to future Phase 2.5 per Rick's Q2 amendment)

## 3. Architecture

### 3a. Scope registry — INI config shape

New keys under `[Lupin: Baseline]` in `src/conf/lupin-app.ini` (with matching splainer entries in `src/conf/lupin-app-splainer.ini`):

```ini
# Multi-repo doc viewer (2026-05-12) — see
# src/rnd/v0.1.7/2026.05.12-multi-repo-doc-viewer.md
external repos = lupin, cosa-voice, planning-is-prompting, lupin-mobile, lookml, par-pacific, claude-plans

external repo lupin path = /var/lupin
external repo lupin allowed prefixes = src/

external repo cosa-voice path = /var/external-projects/cosa-voice
external repo cosa-voice allowed prefixes = src/

external repo planning-is-prompting path = /var/external-projects/planning-is-prompting
external repo planning-is-prompting allowed prefixes = src/, workflow/, docs/

external repo lupin-mobile path = /var/lupin/src/lupin-mobile
external repo lupin-mobile allowed prefixes =

external repo lookml path = /var/external-projects/google/lookml
external repo lookml allowed prefixes = src/

external repo par-pacific path = /var/external-projects/google/par-pacific-financials-er-442109
external repo par-pacific allowed prefixes = src/

external repo claude-plans path = /var/external-claude/plans
external repo claude-plans allowed prefixes =
```

**Semantics**:
- `external repos` is a comma-and-space separated list of scope names (`name1, name2, name3`). Parsed via `ConfigurationManager.get( "external repos", return_type="list-string" )` (built-in splitter at `src/cosa/config/configuration_manager.py:832` — splits on `", "`). The INI format MUST use `, ` as the delimiter (comma + single space) for the splitter to behave as expected.
- For each name, `external repo <name> path` MUST resolve to an existing directory at startup (validated; if missing, the scope is skipped with a warning rather than aborting boot — supports environment-by-environment configurability).
- `external repo <name> allowed prefixes` is a comma-and-space separated list of path prefixes (relative to the scope root), parsed via the same `return_type="list-string"`. **Empty value means "all paths under the scope root are reachable"** (subject to `MEDIA_TYPES` and the secrets blocklist; not "all files everywhere").
- Each scope name MUST NOT collide with reserved built-ins: `docs`, `io`.

**`ScopeConfig` shape (Python)**:

```python
@dataclass( frozen=True )
class ScopeConfig:
    name             : str
    root             : str           # absolute in-container path
    allowed_prefixes : tuple[ str, ... ]  # empty = wildcard
```

**Registry build (startup-only)**:

A new helper `cosa.rest.routers._scope_registry.build_scope_registry()` reads the INI block and returns `dict[str, ScopeConfig]`. Called once at FastAPI startup; the dict is module-level for the rest of the process lifetime.

```python
def build_scope_registry( config_mgr ) -> dict[str, ScopeConfig]:
    names = config_mgr.get( "external repos", default=[], return_type="list-string" )
    registry = {}
    for name in names:
        name = name.strip()  # belt-and-suspenders trim
        if not name:
            continue
        if name in ( "docs", "io" ):
            log.warning( f"external repo name {name!r} collides with built-in scope; skipping" )
            continue
        root = config_mgr.get( f"external repo {name} path", default=None, silent=True )
        if not root or not os.path.isdir( root ):
            log.warning( f"external repo {name!r}: path {root!r} does not exist; skipping" )
            continue
        prefixes = config_mgr.get(
            f"external repo {name} allowed prefixes",
            default=[],
            return_type="list-string",
            silent=True,
        )
        registry[ name ] = ScopeConfig(
            name             = name,
            root             = root,
            allowed_prefixes = tuple( p.strip() for p in prefixes if p.strip() ),
        )
    log.info( f"scope registry: registered {len( registry )} external scope(s): {list( registry )}" )
    return registry
```

Uses the `ConfigurationManager` built-in splitter — no hand-rolled parsing.

**Built-in scopes** (`docs`, `io`) stay hardcoded — they predate the registry, and refactoring them in now adds churn without benefit. They live alongside the registered external scopes; the lookup tries the registry first, then falls through to built-in handling.

### 3b. Endpoint surface — `/api/docs/file` accepts `?scope=`

Today's frontend dispatch:
```js
const apiPath = scope === 'docs' ? '/api/docs/file' : '/api/io/file';
```

Tomorrow:
```js
const apiPath = scope === 'io' ? '/api/io/file' : '/api/docs/file';
const fetchUrl = apiPath + '?path=' + encodeURIComponent( path )
                 + ( scope !== 'docs' && scope !== 'io' ? '&scope=' + encodeURIComponent( scope ) : '' );
```

Backend on `GET /api/docs/file`:
```python
async def get_docs_file(
    path  : str = Query( ..., description="..." ),
    scope : str = Query( "docs", description="Scope name (default 'docs' for back-compat)" )
):
    # If scope == "docs", use legacy whitelist + project root (existing behavior).
    # Else, look up scope in SCOPE_REGISTRY; resolve root + allowed_prefixes; serve.
```

This keeps every existing `/api/docs/file?path=...` URL (notifications, podcast generator output links, etc.) working unchanged because `scope` defaults to `"docs"`.

`/api/io/file` stays special-purpose for binary content (mp3/pdf/png) — not scope-aware.

### 3c. Path resolution + traversal safety per scope

Per-scope resolution mirrors today's logic but parameterized:

```python
def _resolve_in_scope( scope_cfg: ScopeConfig, decoded_path: str ) -> str:
    """
    Resolve `decoded_path` against scope_cfg.root, blocking traversal.

    Raises HTTPException(400) if the resolved path escapes the scope root.
    """
    full_path = os.path.normpath( os.path.join( scope_cfg.root, decoded_path ) )
    if not full_path.startswith( scope_cfg.root + os.sep ) and full_path != scope_cfg.root:
        raise HTTPException( 400, "Invalid path: must be within scope root" )
    return full_path


def _is_whitelisted_in_scope( scope_cfg: ScopeConfig, relative_path: str ) -> bool:
    """
    Empty allowed_prefixes → wildcard (all paths reachable subject to ext/blocklist).
    Non-empty → relative_path must match (startswith OR equal-bare-root) one prefix.
    """
    if not scope_cfg.allowed_prefixes:
        return True
    for prefix in scope_cfg.allowed_prefixes:
        if relative_path.startswith( prefix ):
            return True
        if relative_path == prefix.rstrip( "/" ):
            return True
    return False
```

Cross-scope traversal (`?scope=cosa-voice&path=../../lupin/something`) is blocked by `_resolve_in_scope` — the resolved path must start with the SCOPE's root, not the project root. Same defense, parameterized.

### 3d. MEDIA_TYPES expansion

Current `MEDIA_TYPES` in `docs_files.py`:

```python
MEDIA_TYPES = {

    ".txt"  : "text/plain; charset=utf-8",
    ".json" : "application/json",
    ".yaml" : "text/yaml; charset=utf-8",
    ".yml"  : "text/yaml; charset=utf-8",
}
```

Expanded:

```python
MEDIA_TYPES = {
    # Existing — markdown-renderable text
    ".md"   : "text/markdown; charset=utf-8",
    ".txt"  : "text/plain; charset=utf-8",
    ".json" : "application/json",
    ".yaml" : "text/yaml; charset=utf-8",
    ".yml"  : "text/yaml; charset=utf-8",

    # NEW — source code (rendered as plain pre in the frontend)
    ".py"   : "text/x-python; charset=utf-8",
    ".ts"   : "text/typescript; charset=utf-8",
    ".tsx"  : "text/typescript; charset=utf-8",
    ".js"   : "text/javascript; charset=utf-8",
    ".jsx"  : "text/javascript; charset=utf-8",
    ".css"  : "text/css; charset=utf-8",
    ".html" : "text/html; charset=utf-8",
    ".sh"   : "text/x-shellscript; charset=utf-8",
    ".sql"  : "text/x-sql; charset=utf-8",
    ".toml" : "text/x-toml; charset=utf-8",
    ".ini"  : "text/plain; charset=utf-8",
    ".cfg"  : "text/plain; charset=utf-8",
    ".xml"  : "text/xml; charset=utf-8",
}
```

**Note**: `.html` is whitelisted as TEXT to view — not served as `text/html` to be rendered as a page. The viewer's frontend dispatch is on whether to treat the response as markdown or plain `<pre>`; HTML content shown in `<pre>` is benign.

### 3e. Secrets blocklist (Phase-1 hard requirement)

Even though `MEDIA_TYPES` doesn't include `.env`, `.pem`, `.key`, etc. as recognized extensions, the EXISTENCE of broader source-code reach means we want defense-in-depth against accidental whitelisting drift. Pattern-based filename blocklist:

```python
SECRETS_BLOCKLIST_PATTERNS = (
    # Dotfiles known to carry secrets
    re.compile( r"^\.env(\.|$)" ),
    re.compile( r"^\.netrc$" ),
    re.compile( r"^\.pgpass$" ),

    # Common credential-bearing names
    re.compile( r"credentials?", re.IGNORECASE ),
    re.compile( r"secrets?", re.IGNORECASE ),
    re.compile( r"\.pem$" ),
    re.compile( r"\.key$" ),
    re.compile( r"\.pfx$" ),
    re.compile( r"\.p12$" ),
    re.compile( r"id_rsa", re.IGNORECASE ),
    re.compile( r"id_ed25519", re.IGNORECASE ),
)

def _is_secrets_path( relative_path: str ) -> bool:
    """Match the basename AND any path segment against blocklist patterns."""
    parts = relative_path.split( "/" )
    for part in parts:
        for pattern in SECRETS_BLOCKLIST_PATTERNS:
            if pattern.search( part ):
                return True
    return False
```

Applied in BOTH:
- File-serve path: 400 with "Path matches secrets blocklist" before reading the file.
- Directory-listing path: filter out matching entries from the listing so they don't surface at all.

The blocklist applies to ALL scopes (built-in `docs`/`io` + external). It runs AFTER the per-scope whitelist (defense-in-depth).

### 3f. JWT auth gate

Both endpoints get `Depends( get_current_user )`:

```python
from cosa.rest.dependencies.auth import get_current_user

@router.get( "/api/docs/file", ... )
async def get_docs_file(
    path        : str = Query( ... ),
    scope       : str = Query( "docs" ),
    current_user: User = Depends( get_current_user ),    # NEW
):
    ...
```

Frontend in `document-viewer.html`:

```javascript
// At top of the IIFE — pull the JWT from wherever the rest of the app stores it.
// Lupin's convention: localStorage 'access_token' (per src/lib/clients/auth-client).
const token = localStorage.getItem( 'access_token' );
const headers = token ? { 'Authorization': `Bearer ${ token }` } : {};

// In every fetch:
const response = await fetch( fetchUrl, { headers } );
```

**404 → 401**: if the user is not logged in, the request returns 401 Unauthorized. Frontend should detect 401 and redirect to `/app/login?next=<current-url>` so the user logs in and comes back to the same view.

**Notifications path is safe**: the notifications page already requires authentication; clicking a doc link there opens `/app/docs?path=...` which loads `document-viewer.html`, which fetches with the local-storage token. No anonymous-link breakage.

### 3g. Frontend Content-Type dispatch

Today the dispatch is:
```js
if (content-type includes 'application/json') → renderDirectoryListing
else → renderMarkdown (marked.js + DOMPurify)
```

Tomorrow:
```js
if (content-type includes 'application/json') → renderDirectoryListing
else if (content-type starts with 'text/markdown') → renderMarkdown (existing)
else if (content-type starts with 'text/') → renderPlainText  // NEW
else → error / unsupported
```

`renderPlainText` is small — sanitize the raw text (HTML entities) and put it in `<pre class="doc-code-content">`. Plus matching CSS for monospace + scrolling.

Future Phase 2.5: replace `renderPlainText` with a syntax-highlighting version that uses extension to pick a Prism (or highlight.js) language and applies highlighting.
