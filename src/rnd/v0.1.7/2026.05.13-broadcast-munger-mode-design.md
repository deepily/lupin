## 1. Context

Rick is shipping a broadcast feature where messages use `@mention` syntax (`@you`, `@me`, `@foo`). The notifications-UI recorder pipeline strips characters that are load-bearing for that syntax — most prominently `.` (periods), which are killed unconditionally by `multimodal_munger.py:757`.

Investigation traced the full pipeline and cataloged every existing munger mode. No existing mode is a clean fit for the broadcast use case, so a new mode is defined.

## 3. Decisions (settled with Rick 2026-05-13 PM)

| Q | Decision | Rationale |
|---|---|---|
| Q1 — map contents | `period`, `dot`, `underscore`, `hash`, `hashtag` work as single tokens. Multi-token `at sign`, `dot dot`, `hash tag`, `dot dot dot` do NOT match per-token lookup (tokenizer: `re.findall(r"[\w']+\|[ ]+\|[^\w\s']", text)`) | Need phrase preprocessing |
| Q2 — `at` conversion | **Verbose** — only literal `"at sign"` → `"@"` | Preserves "look at this", "we'll meet at noon"; user dictation discipline acceptable |
| Q3 — mode signaling | **UI context** — JS sends `prompt_key="broadcast"` | Server stateless; precise scoping |

### 4.2 New method `munge_text_broadcast` — body sketch

Mirrors `munge_text_punctuation` (lines 658-767) with two changes: **add** a phrase-preprocess pass for `at sign`, **omit** the line-757 `[,.]` strip.

```python
def munge_text_broadcast( self, raw_transcription: str, mode: str ) -> tuple[str, str]:
    """
    Process broadcast-context speech transcriptions while preserving @-mentions, dots, underscores.

    Requires:
        - raw_transcription is a string
        - mode is a valid mode string
        - Punctuation and number dictionaries are loaded

    Ensures:
        - Returns tuple of (prose, mode)
        - Phrase-preprocesses literal "at sign" → "@" (case-insensitive, word-boundaried)
        - Applies the same tokenize + lookup pipeline as munge_text_punctuation for single-token
          punctuation/number/domain conversions
        - DOES NOT strip commas or periods (line 757 of munge_text_punctuation is omitted)
        - Preserves @, _, ., # literally regardless of Whisper output form
        - Removes spaces around punctuation and dashed-spellings (m-a-y → may)
    """
    prose = raw_transcription

    # Phrase-preprocess: literal "at sign" → "@" (Q2 Verbose decision)
    prose = re.sub( r'\bat sign\b', '@', prose, flags=re.IGNORECASE )

    # Remove URL protocols (mirror munge_text_punctuation behavior)
    prose = self._remove_protocols( prose )

    # Build case-insensitive lookup dictionaries
    domain_lookup = { k.strip().lower(): v for k, v in self.domain_names.items() if k.strip() }
    punct_lookup  = { k.strip().lower(): v for k, v in self.punctuation.items() if k.strip() }
    number_lookup = { k.strip().lower(): v for k, v in self.numbers.items() if k.strip() }

    # Tokenize and per-token replace
    tokens = self._tokenize( prose )
    result = []
    for token in tokens:
        token_lower = token.lower()
        if token_lower in domain_lookup:
            result.append( domain_lookup[ token_lower ] )
        elif token_lower in punct_lookup:
            result.append( punct_lookup[ token_lower ] )
        elif token_lower in number_lookup:
            result.append( number_lookup[ token_lower ] )
        else:
            result.append( token )

    prose = ''.join( result )

    # NB: line 757 [,.] strip is OMITTED — broadcast preserves periods and commas

    prose = self._remove_spaces_around_punctuation( prose )
    prose = self._remove_dashed_spellings( prose )

    return prose, mode
```

### 4.3 Server-side threading (verify, no change expected)

**Clarification 2026-05-13 PM**: server-side routing uses `prefix`, NOT `prompt_key`, to select the munger method.

- `speech.py:172` accepts `prefix: Optional[str] = Query(None)` as a query parameter
- `speech.py:256` passes `prefix=prefix if prefix else ""` into `MultiModalMunger`
- `MultiModalMunger.__init__` stores it as `self.prefix`
- `parse()` (lines 257-281) routes to a munger method when `self.prefix in modes_to_methods_dict`. Specifically at line 274-279: `if self.prefix in self.modes_to_methods_dict: method_name = self.modes_to_methods_dict[ self.prefix ]`

So to route to `munge_text_broadcast`, the recorder must send the query parameter `prefix=multimodal+text+broadcast` (URL-encoded). The `prompt_key` parameter is a SEPARATE concern — it selects a prompt template at line 97 (`prompt_dictionary.get( prompt_key, "generic" )`) and falls back to "generic" if unknown.

**This supersedes the Q3 decision wording** ("JS sends `prompt_key="broadcast"`"). The intent stays the same (UI-context-driven mode selection); only the parameter name changes from `prompt_key` to `prefix` because `prefix` is the actual routing key in the existing implementation.

No `speech.py` code changes are needed — the `prefix` parameter is already accepted and threaded through.

### 4.4 JS-side threading (`notifications.js`)

`recordingManager.startRecording(field, recordingMode="generic")` accepts a new `recordingMode` parameter. When `recordingMode === "broadcast"`, the `AudioRecorder` upload-and-transcribe-mp3 POST appends `prefix=multimodal+text+broadcast` to the query string (URL-encoded). When `recordingMode === "generic"` (the default), no `prefix` is sent — the server-side default routing (`munge_text_punctuation`) fires.

**Exact call-site contract** is left to broadcast-UI integrators. This PR plumbs the path but doesn't yet have a broadcast composer to call from. Once the broadcast UI lands (separate work tracked in Inter-Session Commons or the upcoming broadcast-accordion edit by María), it will invoke `startRecording(field, "broadcast")`.
