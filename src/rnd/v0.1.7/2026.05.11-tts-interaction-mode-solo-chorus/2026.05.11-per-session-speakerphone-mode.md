## ⚠️ Post-serialization addendum (2026-05-11) — Preserve monopoly path as fallback

**User clarification, immediately after this plan was serialized**:

> "I don't know as of yet if I want to throw away all of the plumbing used to create monopoly mode. We might want to think of having a separate parallel implementation that allows us to restore monopoly mode in case this experiment does not turn out the way I imagined it."

This **overrides** the original plan's "hard cut, no migration code" stance in one specific respect: the **monopoly enforcement plumbing must not be deleted**. Instead, the per-session speakerphone implementation lands **alongside** the monopoly path as a parallel implementation, gated by a runtime flag.

### Reconciliation with the rest of the plan

| Plan element | Original (hard-cut) | Revised (parallel) |
|---|---|---|
| Naming rename (`conversation_mode_active` → `speakerphone_on` etc.) | ✓ Apply | ✓ Still apply — for clarity, rename old to its proper-new-name |
| Delete `find_active_conversation_sessions` helper | Delete | **Keep.** Still used by monopoly branch. |
| Delete `_conversation_mode_lock` (asyncio.Lock) | Delete | **Keep.** Still used by monopoly branch. |
| Delete the displace + activate loop in router | Delete | **Keep**, wrap in `if mode == "monopoly":` |
| Default new sessions to `speakerphone_on = true` | Apply | Apply WHEN mode is `per-session`; preserve old default WHEN mode is `monopoly` |
| Server rider content (speaker-on vs phone) | Static fork | Mode-aware fork (rider reads BOTH `speakerphone_on` AND `mode`) |
| UI toggle (bell↔phone → phone↔speaker) | Replace | Mode-aware: render the monopoly green-pin OR the per-session toggle based on flag |
| CLAUDE.md migration | Move into server rider | Same — but rider has both code paths |
| Cross-talk leak cue removal | Delete | **Keep when mode=monopoly**, remove when mode=per-session |

### Runtime flag

Proposed key (in `src/conf/lupin-app.ini` under `[Lupin: Baseline]`):

```ini
cosa-voice speakerphone mode = per-session
; values: per-session | monopoly
; per-session: multi-session speakerphone, no displacement (the new experiment)
; monopoly: single-session conversation mode (pre-2026-05-11 behavior, kept as fallback)
```

Paired explanation in `lupin-app-splainer.ini`.

### Test obligations under the parallel model

Per `feedback_feature_flag_preserves_old_path.md` ("Feature-flagged forks preserve both paths permanently"):

- **Both paths stay first-class and maintained forever.** Tests must cover BOTH the per-session and monopoly modes at every layer (unit, smoke, integration).
- No "we'll retire the loser" planning — assume both modes are permanent.
- The plan's existing test inventory must double: every assertion that depends on mode must run twice (once per mode), parameterized via `pytest.mark.parametrize` or equivalent.

### Implementation implications

- **Phase 2 (server router cleanup)**: instead of removing the displacement loop, gate it on the flag. Keep both branches reviewable.
- **Phase 3 (MCP `_notify_impl` cleanup)**: cross-talk leak cue removal becomes mode-conditional, not unconditional.
- **Phase 4 (hook rider content split)**: `_system_reminder_body` reads the mode flag and emits monopoly-flavored or per-session-flavored rider. Effectively four rider variants now: speaker-on×monopoly, speaker-on×per-session, phone×monopoly, phone×per-session — though some collapse to identical text.
- **Phase 6 (multiplexer UI)**: bell-vs-phone toggle stays available behind the monopoly mode; phone-vs-speaker toggle is the per-session mode UI. Frontend reads the mode flag and renders the appropriate toggle. The "green mic monopoly pin" lives on (gated to monopoly mode); it does NOT need a new semantic, freeing the persona color pool's green-reservation rule to remain unchanged when mode=monopoly. Reservation only needs revisiting if mode=per-session.

### Why this matters

The user is contemplating, not committing. Monopoly mode might genuinely be the right design after living with the per-session experiment for a while. Throwing the plumbing away forecloses revert. Parallel preservation costs slightly more test + maintenance time forever, but buys reversibility — which is exactly what an experiment in early-stage thinking needs.

## Context

Today the cosa-voice MCP server has a **conversation mode** concept with two coupled semantics:

1. **A render-mode signal**: when "active," Claude re-crafts replies for TTS and rides the `notify()` rail at the end of each turn. The system-reminder + `<voice-message>` envelope is what reliably keeps Claude on that rail.
2. **A mic-monopoly enforcement**: server-side displacement logic (asyncio.Lock + scan + atomic displace + activate in `src/cosa/rest/routers/conversation_mode.py:164-225`) guarantees only one session at a time has conversation mode active. The UI surfaces this as a green "mic monopoly pin."

The user wants to **decouple and reshape** this:

- **At-distance becomes the default interaction mode**, not an opt-in. The user is rarely at the CLI; cosa-voice notify() rendering is the primary feedback channel.
- The toggle is purely about **how Claude renders outbound to the user**: text-only (phone mode) vs text + TTS (speakerphone mode). Per-session, independent, **N can be on simultaneously**. The cosa-voice TTS queue already serializes playback at the user's ear; each persona has its own voice for disambiguation.
- **Monopoly is dead**. The "one at a time" enforcement was a vestigial coupling between render-mode and mic-routing. Mic-routing is parked as a separate axis and out of scope for this refactor.
- **The MCP server becomes the prompt-injection authority**. Speakerphone-conditional rules currently sprinkled across CLAUDE.md migrate into the per-turn rider that the hook builds dynamically based on per-session bridge state. CLAUDE.md slims to always-on notification rules only.
- The `<voice-message>` + `<system-reminder>` micro-prompt mechanism is **preserved and load-bearing** — it's what makes Claude reliably ride the `notify()` rail. The rider's *content* varies by speakerphone state; the wrapping mechanism itself is unchanged.

Outcome: multiple Claude Code sessions can all speak through Mr. Radio / María / their persona simultaneously; the user can hand work off across sessions by voice; phone mode becomes the deliberate "quiet this session" gesture rather than the default.

## Recommended approach

### Naming convention

| Old name | New name |
|---|---|
| `conversation_mode_active` (bridge field) | `speakerphone_on` |
| `enter_conversation_mode` (MCP tool) | `enable_speakerphone` |
| `exit_conversation_mode` (MCP tool) | `disable_speakerphone` |
| `/api/cosa-voice/conversation-mode/{sid}` (HTTP) | `/api/cosa-voice/speakerphone/{sid}` |
| `conversation_mode_changed` (WS event) | `speakerphone_changed` |
| `action:exit_conversation_mode` (listener action) | `action:disable_speakerphone` |
| `conv_mode_wrap` / `conv_mode_reminder_block` / `conv_mode_exit_reminder` | `speakerphone_wrap` / `speakerphone_reminder_block` / `speakerphone_exit_reminder` |
| `get_conversation_mode` / `set_conversation_mode` | `get_speakerphone` / `set_speakerphone` |
| `find_active_conversation_sessions` | **delete** (no monopoly = no displacement scan needed) |
| `/conversation-mode-on` / `/conversation-mode-off` (slash commands) | `/speakerphone-on` / `/speakerphone-off` |
| `conversation-mode-on` / `conversation-mode-off` / `conversation-mode-guardrails` (skills) | `speakerphone-on` / `speakerphone-off`; **retire** the guardrails skill (rule lives in tool docstrings + server rider) |

Per the user's "no migration code" preference, this is a **hard cut**. No aliases for old tool/endpoint/event names. Existing bridge files get regenerated on next session start.

### Default state

- New sessions: `speakerphone_on = true` (at-distance is default).
- Persists across `/clear` (joins persona in the survive-clear set).

### Server changes

**`src/cosa/rest/routers/conversation_mode.py` → rename file to `speakerphone.py`**

- Drop the `asyncio.Lock()` (line 50) — no more atomic displace needed.
- Drop the displacement branch (lines 164–222): the scan, the per-other-session set + notify + action push.
- Activate path simplifies to: `set_speakerphone(sid, true)` + WebSocket broadcast.
- Deactivate path unchanged in shape: `set_speakerphone(sid, false)` + WebSocket broadcast + self-exit listener action push (preserved — Claude in that session still needs the "stop calling notify on close" reminder when toggled to phone).
- `displaced_sessions` field removed from response.

**`src/lupin_mcp/cosa_voice_mcp.py`**

- Tools renamed (signatures unchanged): `enable_speakerphone` / `disable_speakerphone`. USER-ONLY initiation hard rule preserved in docstrings.
- `_flip_conversation_mode` → `_flip_speakerphone`. HTTP-first, direct-bridge fallback preserved.
- `get_session_info()` return shape: rename `conversation_mode_active` → `speakerphone_on`.
- **`_notify_impl()` (lines 723–834)**:
  - speakerphone_on=true branch: keep (force `suppress_ding=True`, force `priority="high"`, strip fenced code blocks).
  - speakerphone_on=false branch: **passthrough.** Remove the cross-talk leak cue (lines 805–811) that today inverts `suppress_ding` for CC senders in non-conv-mode. Rationale: in the new world, phone mode is a deliberate quiet state; `suppress_ding=True` from Claude is a legitimate "quiet notification" pattern (UI card without ding or TTS), not a leak symptom. The old inversion was a safety net for the monopoly model and is now wrong-shaped.

**`src/lupin_cli/claude_code/hooks/lib/session_bridge.py`**

- Rename `get_conversation_mode` / `set_conversation_mode` → `get_speakerphone` / `set_speakerphone`.
- Delete `find_active_conversation_sessions` (no callers after the displace loop is removed).
- Bridge schema: `conversation_mode_active` → `speakerphone_on`, default `true`.
- Bump bridge file format version. On read, if version is old → discard and recreate with new defaults (no migration code).

**`src/lupin_cli/claude_code/hooks/lib/hook_common.py`**

- Rename `conv_mode_wrap` / `conv_mode_reminder_block` / `conv_mode_exit_reminder` / `_system_reminder_body` to the `speakerphone_*` analogues.
- **Rider content split**, driven by per-session `speakerphone_on`:

  **Speaker-on rider (rich, current behavior + content migrated from CLAUDE.md):**
  - Source-aware preamble (voice / terminal-typed / hook-idle-prompt / hook-permission-prompt) — unchanged.
  - "Session is in speakerphone mode. After your response, call `notify(message=<full text of your reply>, suppress_ding=True, priority='high')`."
  - Brevity rules (migrated from `CONVERSATION MODE & TTS RESPONSE BREVITY MANDATE`): strip TTS-hostile syntax from the spoken `message`, re-craft prose, length cap (~60 words routine / ~80–120 substantive), keep `abstract` rich for written record, ack-before-tool-work obligation.
  - Routing reminder (migrated from `INTERACTIVE TOOL ROUTING`): prefer cosa-voice `ask_*` over `AskUserQuestion`.

  **Speaker-off rider (new, short):**
  - Source-aware preamble (unchanged).
  - "Session is in phone mode (text-only render). No closing `notify()` required."
  - "You may still call `notify()` for milestones, errors, blocking questions — those produce UI notification cards regardless of TTS state. `ask_*` blocking tools also remain available."

- **`speakerphone_exit_reminder()`** (the transition-injection delivered via tmux when a session flips from speaker to phone): keep mechanism, update body to reflect the new naming and the fact that notify() is still allowed for milestones/errors in phone mode.

- `<voice-message>` envelope wrapping stays universal — fires whenever a voice-recognized input arrives, regardless of speakerphone state. The rider that follows it varies by state.

**`src/lupin_cli/claude_code/hooks/user_prompt_submit.py`**

- Update call-site names for the renamed `speakerphone_reminder_block`. No semantic change at this layer — it always asks the helper, which returns the appropriate rider for the session's current state (or empty if the session lookup fails, fail-closed).

### UI changes (multiplexer TypeScript)

`src/fastapi_app/static/js/multiplexer/` — three categories of change:

1. **Event rename**: every listener for `conversation_mode_changed` → `speakerphone_changed`.
2. **Per-session toggle**: replace the bell-vs-phone two-state toggle with a phone-vs-speaker two-state toggle. Phone icon = text-only render; speaker icon = text + TTS. Both states are valid steady-states; the toggle is bidirectional.
3. **Drop monopoly affordances**: remove "displaced" event-handling code and the visual signal that previously fired when another session claimed mic ownership.

**100% c8 coverage mandate applies** — every touched file in `src/fastapi_app/static/js/multiplexer/` plus its tests in `src/tests/unit/multiplexer/` must land at `c8 --100`. This is a hard gate per the mandate ratified 2026-05-06.

### Open UX decisions — deferred, not blocking

**Persona-color / "green pin" semantic**: today the persona color pool excludes green because green-on-success is reserved for the conversation-mode mic-monopoly pin (feedback memory `feedback_no_green_in_persona_pool.md`). With monopoly dead, that reservation no longer has a use-case. Three candidates for the new visual semantic:

| Option | Meaning | Tradeoff |
|---|---|---|
| (a) Green = speaker-on | Most cards green (default state) | Default-green dilution; signal weak |
| (b) Green = phone-mode | Phone-mode card highlighted as the deliberate exception | Inverts intuition (green ≠ "on") |
| (c) Drop green reservation; toggle uses icon shape only | Phone glyph vs speaker glyph; color free for personas | Frees the color pool; cleanest |

Plan **does not decide this**. The backend refactor and the UI toggle change can land first; the color/glyph treatment becomes a follow-up UX gate (single AC, single PR). Plan recommends (c) but defers.

### Explicitly out of scope

- **Inbound mic-routing semantics** — the user parked this. Plan does not change who receives voice-recognized input or how the `<voice-message>` envelope's session-target is decided. That's a separate axis that may or may not need its own refactor later.
- **Persona color pool expansion** — separate decision; plan only sets up the question.
- **Backwards-compatible aliases** for old tool/endpoint/event names — explicitly NOT included per the no-migration-code preference.

## Phased landing (if/when revisited)

1. **Phase 0 — R&D doc serialization.** (This document.)
2. **Phase 1 — Bridge field rename + defaults.** `session_bridge.py` field + getter/setter renames; bridge format version bump; new-session default `speakerphone_on=true`.

## Risks / blast radius

- **Coordinated rename across nested repos**: parent Lupin + `src/cosa/` both touched. The CoSA-side change (HTTP router) and Lupin-side changes (hooks, MCP server, multiplexer) must land in a coordinated commit pair.
- **Static doc loses content**: CLAUDE.md no longer self-describes the speakerphone rules. Source of truth migrates to server code. Auditability of behaviors becomes "read the hook + server" rather than "read CLAUDE.md."
- **Per-turn rider weight**: speaker-on rider gains migrated content. Measure per-turn token cost before/after to verify we haven't ballooned context.
- **No backward-compat aliases**: any tool or workflow that still says `enter_conversation_mode` / `exit_conversation_mode` will break post-merge. Sweep parent + submodules for both names before landing.
- **100% c8 coverage hard gate**: any multiplexer TS change without paired test work is a blocker.
- **The cross-talk leak cue removal** is a real behavioral change. Today the inversion catches "CC tries to notify-silently while not in conv-mode" mistakes. In the new world, that pattern is legit. If we discover an unforeseen use of the inversion as a safety net, we'll need to re-add a narrower version.
