## TL;DR

Add a global INI switch — `tts interaction mode = solo | chorus` — that selects between two **permanently maintained** TTS interaction models:

| Value | Behavior | Today's name |
|---|---|---|
| `solo` | One session at a time speaks via TTS. Activating speakerphone on a new session **displaces** the prior holder (asyncio.Lock + scan + atomic transition). UI surfaces a green mic-monopoly pin on the active session. | "Conversation mode" — today's behavior, preserved exactly |
| `chorus` | N sessions can be in speakerphone mode simultaneously. No displacement, no Lock. Each session's persona voice disambiguates at the listener's ear; the cosa-voice TTS queue already serializes playback. | The new experiment |

**Solo preserves today's behavior pixel-perfect.** Chorus is the experiment. Both branches are first-class and permanent — every test parameterizes over both modes. If chorus doesn't feel right after living with it, the INI flag flips back to solo and nothing breaks. The naming pair (`solo`, `chorus`) leaves the door open for additional values later — `duet`, `trio`, `quartet` — if pair- or small-group-routing become interesting. Plan does not commit to those.

The doc that follows is the refactor plan to **introduce the switch** — land the chorus branch alongside the solo branch, both gated by the new INI key.

## Context

Today the cosa-voice MCP server has a **conversation mode** concept with two coupled semantics:

1. **A render-mode signal**: when "active," Claude re-crafts replies for TTS and rides the `notify()` rail at the end of each turn. The system-reminder + `<voice-message>` envelope is what reliably keeps Claude on that rail.
2. **A mic-monopoly enforcement**: server-side displacement logic (asyncio.Lock + scan + atomic displace + activate in `src/cosa/rest/routers/conversation_mode.py:164-225`) guarantees only one session at a time has conversation mode active. The UI surfaces this as a green "mic monopoly pin."

These two were originally bundled because the assumption was "one user, one mic, one Claude voice at a time." Rick is contemplating a different default — at-distance becomes the default interaction mode, and multiple Claude sessions can all speak through their own personas simultaneously.

The proposal: **don't replace** the current model, **add** the new model alongside it, gate them via the global `tts interaction mode` INI key, and let Rick experiment with chorus while keeping solo as a known-good revert target.

- Under chorus: multiple Claude Code sessions can all speak through Rio / María / Mr. Radio simultaneously; Rick can hand work off across sessions by voice; phone mode becomes the deliberate "quiet this session" gesture rather than the default.
- Under solo: identical to today.

The `<voice-message>` + `<system-reminder>` micro-prompt mechanism is **preserved and load-bearing** in both modes — it's what makes Claude reliably ride the `notify()` rail. The rider's *content* varies by mode and per-session speakerphone state; the wrapping mechanism itself is unchanged.

## The switch

**INI key (in `src/conf/lupin-app.ini` under `[Lupin: Baseline]`):**

```ini
tts interaction mode = chorus
; values: solo | chorus
; chorus (default): N sessions simultaneously; no displacement; persona voices disambiguate at the listener's ear
; solo: one session at a time speaks via TTS; activating displaces prior holder; green mic-monopoly pin in UI
```

Paired explanation in `lupin-app-splainer.ini`.

**Default**: `chorus` per 2026-05-12 execution-kickoff override (see `90-decisions-log.md`) — the experiment IS the work; set to `solo` in the INI to invoke today's monopoly-mode fallback. Reversibility intact via the parallel-preserved solo branch.

**Read sites**: `ConfigurationManager.get_config_value( "tts interaction mode" )`. Cache in-process where hot (router, hook common). One central helper `get_tts_interaction_mode()` to avoid scattered config lookups.

## Recommended approach

### Naming convention

The per-session render-mode field is renamed regardless of which `tts interaction mode` is active. The field describes *this session's TTS render state*; the mode is what arbitrates across sessions.

| Old name | New name | Notes |
|---|---|---|
| `conversation_mode_active` (bridge field) | `speakerphone_on` | per-session render state |
| `enter_conversation_mode` (MCP tool) | `enable_speakerphone` | |
| `exit_conversation_mode` (MCP tool) | `disable_speakerphone` | |
| `/api/cosa-voice/conversation-mode/{sid}` (HTTP) | `/api/cosa-voice/speakerphone/{sid}` | |
| `conversation_mode_changed` (WS event) | `speakerphone_changed` | |
| `action:exit_conversation_mode` (listener action) | `action:disable_speakerphone` | |
| `conv_mode_wrap` / `conv_mode_reminder_block` / `conv_mode_exit_reminder` | `speakerphone_wrap` / `speakerphone_reminder_block` / `speakerphone_exit_reminder` | |
| `get_conversation_mode` / `set_conversation_mode` | `get_speakerphone` / `set_speakerphone` | |
| `find_active_conversation_sessions` | `find_active_speakerphone_sessions` | **kept** — still used by the solo branch's displacement scan |
| `/conversation-mode-on` / `/conversation-mode-off` (slash commands) | `/speakerphone-on` / `/speakerphone-off` | |
| `conversation-mode-on` / `conversation-mode-off` / `conversation-mode-guardrails` (skills) | `speakerphone-on` / `speakerphone-off`; **retire** the guardrails skill (rule lives in tool docstrings + server rider) | |

Per Rick's "no migration code" preference, this is a **hard cut on naming**. No aliases for old tool/endpoint/event names. Existing bridge files get regenerated on next session start.

### Default per-session state

- **Solo mode**: New sessions default `speakerphone_on = false` (matches today's behavior — sessions opt in to TTS render).
- **Chorus mode**: New sessions default `speakerphone_on = true` (at-distance is default).
- `/clear` persistence: speakerphone state persists across `/clear` in both modes (joins persona in the survive-clear set).

### Server changes

**`src/cosa/rest/routers/conversation_mode.py` → rename file to `speakerphone.py`**

The activate path branches on `tts interaction mode`:

- **Solo branch** (preserves today's behavior exactly):
  - `asyncio.Lock()` held during activate/deactivate.
  - Displacement scan: find other sessions with `speakerphone_on = true`, atomically flip them off, broadcast `speakerphone_changed` for each, push `action:disable_speakerphone` to each.
  - Activate self: `set_speakerphone(sid, true)` + broadcast.
  - Response includes `displaced_sessions` list.

- **Chorus branch** (new):
  - No Lock.
  - No scan.
  - Activate self: `set_speakerphone(sid, true)` + broadcast.
  - Response includes `displaced_sessions = []` (always empty, kept in schema for response-shape stability).

Deactivate path is mode-independent: `set_speakerphone(sid, false)` + broadcast + self-exit listener action push.

**`src/lupin_mcp/cosa_voice_mcp.py`**

- Tools renamed (signatures unchanged): `enable_speakerphone` / `disable_speakerphone`. USER-ONLY initiation hard rule preserved in docstrings.
- `_flip_conversation_mode` → `_flip_speakerphone`. HTTP-first, direct-bridge fallback preserved.
- `get_session_info()` return shape: rename `conversation_mode_active` → `speakerphone_on`. Add `tts_interaction_mode` to the response so frontends know which UI to render.
- **`_notify_impl()` (lines 723–834)**:
  - `speakerphone_on=true` branch: unchanged (force `suppress_ding=True`, force `priority="high"`, strip fenced code blocks).
  - `speakerphone_on=false` branch is **mode-conditional**:
    - Solo: keep cross-talk leak cue (today's behavior — inverts `suppress_ding` for CC senders when not in conversation mode, as a safety net for the monopoly model).
    - Chorus: passthrough — no inversion. In chorus, `suppress_ding=True` from Claude is a legitimate "quiet notification" pattern, not a leak symptom.

- **Rider content matrix** — driven by per-session `speakerphone_on` AND global `tts interaction mode`. Four variants total, though some collapse to identical text:

|  | solo + speaker-on | solo + phone | chorus + speaker-on | chorus + phone |

### Open UX decisions — deferred, not blocking

**Persona-color "green pin" reservation**: today the persona color pool excludes green because green-on-success is reserved for the mic-monopoly pin (feedback memory `feedback_no_green_in_persona_pool.md`).

- Under solo mode, the reservation continues to make sense — green-pin is live.
- Under chorus mode, the reservation has no use case — no monopoly to signal.

Three candidates for chorus-mode visual treatment:

| Option | Meaning | Tradeoff |
|---|---|---|
| (a) Green = speaker-on | Most cards green (default state in chorus) | Default-green dilution; signal weak |
| (b) Green = phone-mode | Phone-mode card highlighted as the deliberate exception | Inverts intuition (green ≠ "on") |
| (c) Drop green reservation in chorus; toggle uses icon shape only | Phone glyph vs speaker glyph; color free for personas | Frees the color pool; cleanest |

Plan **does not decide this**. The backend mode-switch and the UI plumbing can land first; the chorus-mode color/glyph treatment becomes a follow-up UX gate (single AC, single PR). Plan recommends (c) but defers. Solo-mode color reservation is untouched regardless.

### Explicitly out of scope

- **Inbound mic-routing semantics** — parked. Plan does not change who receives voice-recognized input or how the `<voice-message>` envelope's session-target is decided. That's a separate axis that may or may not need its own refactor later.
- **Persona color pool expansion** — separate decision; plan only sets up the question.
- **Backwards-compatible aliases** for old tool/endpoint/event names — explicitly NOT included per the no-migration-code preference.
- **Retiring solo mode** — explicitly NOT planned. Both modes are permanent. If chorus turns out to be the right design after long-term use, retiring solo can be a separate decision later.

8. **Phase 7 — Multiplexer UI + tests.** Event listener rename; mode-aware toggle (solo: bell↔phone; chorus: phone↔speaker); mode-aware monopoly affordances; restore 100% c8 coverage with both modes parameterized.
