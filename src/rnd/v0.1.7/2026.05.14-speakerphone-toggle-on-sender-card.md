## Context

Each Claude Code sender card in the notifications UI currently renders `sender-conversation-mode-btn`, the legacy toggle for "conversation mode" (the solo/monopolize concept). This is broken in two ways:

1. **Stale paradigm**: Project default flipped to `tts_interaction_mode = chorus` on 2026-05-12. The solo/monopolize semantic no longer applies to most workflows. The right per-session knob in chorus mode is `speakerphone_on` — does THIS session's TTS play audibly, or is the session silent (user reads terminal)?

2. **Dead endpoint**: The button's click handler at `notifications.js:9673` POSTs to `/api/cosa-voice/conversation-mode/{session_id}`, which **does not exist on the server**. The canonical endpoint that writes the bridge + broadcasts the WS event is `/api/cosa-voice/speakerphone/{session_id}` (used by the cosa-voice MCP's `enable_speakerphone()` / `disable_speakerphone()` tools). The legacy UI button has been silently 404-ing.

**Goal**: Rewire the per-sender toggle to read `tts_interaction_mode` from the config endpoint at load time, render the correct variant for the current mode (chorus → speakerphone icon/label; solo → conversation-mode icon/label per `feedback_feature_flag_preserves_old_path`), call the canonical `/speakerphone/` endpoint, and stay in sync with the bridge via the existing WebSocket broadcast.

**Hook-rider sub-question answered up front**: Rick asked whether the per-turn rider instructions need to change. **They do not.** The 4-variant rider at `hook_common.py:1085-1164` already adapts to `(mode, speakerphone_on)`. When the toggle flips speakerphone off in chorus mode, the next user-prompt rider already says "no notify() required; terminal-only output." See Phase 5 below.

### 2b. Render mode-aware button in `createSenderCard()` (replaces lines 10384-10387)

```javascript
const speakerphoneOn = this.speakerphoneState[ sessionId ] || false;
const isSolo = this.ttsInteractionMode === 'solo';

const icon = isSolo
    ? ( speakerphoneOn ? '📞' : '🔔' )       // solo: conversation / notification
    : ( speakerphoneOn ? '🔊' : '🔕' );      // chorus: speakerphone / private phone

const title = isSolo
    ? ( speakerphoneOn
        ? 'Conversation mode ON — this session monopolizes TTS (click to release)'
        : 'Notification mode — no monopoly (click to claim TTS)' )
    : ( speakerphoneOn
        ? "Speakerphone ON — this session's TTS plays audibly (click to mute)"
        : "Private phone — this session's TTS is muted (click to enable speakerphone)" );
```

Keep the CSS class `sender-conversation-mode-btn` unchanged (zero CSS edits — `.is-active` rule at `notifications.css:1767-1799` works for both icon sets).

### 2c. Seed initial state from bridge on render

When a sender card is created, fire `GET /api/cosa-voice/speakerphone/{sessionId}` (returns `{session_id, on}` per `speakerphone.py:103-136`) to populate `this.speakerphoneState[sessionId]` and re-render the button reactively.
