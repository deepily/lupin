## Part A — Recent Activity Filter Strip

### Filter Model — Three Axes, Intersected

| Axis | Options | Mutex? | Default |
|------|---------|--------|---------|
| **Direction** | Sender · Recipient | yes (at most one active) | none active |
| **Kind** | All · Heartbeats · Personas · Broadcasts | yes (exactly one active) | All |
| **Persona** | one chip per active session persona | yes (at most one active) | none active |

**Kind axis semantics (4-option per Rick's 2026-05-21 walkthrough amendment):**

- **All** — no kind constraint; everything renders (heartbeats + conversational DMs + broadcasts + acks + reserved-topic entries).
- **Heartbeats** — only entries where `metadata.kind === "heartbeat"`. Heartbeats ride `dm-<persona>` topics so Direction (Sender / Recipient) interacts normally.
- **Personas** — only persona-to-persona conversational DMs. Tightened from earlier draft to specifically require `topic.startsWith("dm-")` AND `metadata.kind !== "heartbeat"` — so reserved-topic entries (presence pings, system events, broadcasts) do NOT sweep in.
- **Broadcasts** — only broadcast traffic. Matches entries where `topic === "broadcasts"` OR `topic === "broadcast-acks"`. The two reserved broadcast topics are unified under this single filter (broadcast originating messages + their ack responses both surface together).

**Direction × Kind interaction (4-option amendment):**

- Direction works normally for Kind ∈ {All, Heartbeats, Personas} — all three of those Kind values live on `dm-<persona>` topics, so Recipient=`dm-X` matches and Sender=`persona_name===X` matches.
- **Kind=Broadcasts + Direction=Recipient is a silent no-op** — broadcasts fan out to all recipients, so no `dm-<persona>` topic exists to match against. The filter behaves as if Direction were at the default (no constraint) for broadcast entries. Direction=Sender still filters broadcasts by originator (`persona_name === selectedPersona`).

**Predicate composition** (boolean AND across active axes):

```
direction = "sender"     → entry.persona_name.toLowerCase() === selectedPersona
direction = "recipient"  → entry.topic === "dm-" + selectedPersona
                            (no-op when kind === "broadcasts" — broadcasts fan out)
direction = null         → no direction constraint

kind = "all"             → no kind constraint
kind = "heartbeats"      → entry.metadata?.kind === "heartbeat"
kind = "personas"        → entry.topic?.startsWith("dm-")
                            && entry.metadata?.kind !== "heartbeat"
kind = "broadcasts"      → entry.topic === "broadcasts"
                            || entry.topic === "broadcast-acks"

persona = null           → direction axis becomes a no-op (cannot filter direction without a target)
```

**Example resolutions:**

| Query | Direction | Kind | Persona | Predicate |
|-------|-----------|------|---------|-----------|
| "All DMs received by Tiberius" | Recipient | Personas | Tiberius | `entry.topic === "dm-tiberius" && entry.metadata.kind !== "heartbeat"` |
| "All heartbeats sent to María" | Recipient | Heartbeats | María | `entry.topic === "dm-maria" && entry.metadata.kind === "heartbeat"` |
| "Everything Tiberius said" | Sender | All | Tiberius | `entry.persona_name.toLowerCase() === "tiberius"` |
| "Heartbeats Tiberius emitted" | Sender | Heartbeats | Tiberius | `entry.persona_name === "tiberius" && entry.metadata.kind === "heartbeat"` |
| "Conversational DMs Tiberius sent" | Sender | Personas | Tiberius | `entry.persona_name === "tiberius" && entry.topic.startsWith("dm-") && entry.metadata.kind !== "heartbeat"` |
| "Broadcasts from María" (new) | Sender | Broadcasts | María | `(entry.topic === "broadcasts" \|\| entry.topic === "broadcast-acks") && entry.persona_name === "maria"` |
| "All broadcast traffic" (new) | — | Broadcasts | — | `entry.topic === "broadcasts" \|\| entry.topic === "broadcast-acks"` |

## Part B — Focus-Bar Chronological Lock

### Current Behavior (MRU-Driven)

Two mechanisms enforce most-recently-updated ordering:

1. `_addStripIcon(insertAtTop=true)` at `notifications.js:9257-9261` — runtime adds prepend → newest leftmost.
2. `_promoteStripIcon()` at `notifications.js:9353-9380` — invoked from `moveSenderCardToTop()` at line 17172 on every sender-card update, moving the icon back to leftmost.

### Target Behavior (Creation-Chronological)

| Event | Today | After change |
|-------|-------|--------------|
| Initial page load | Icons in API order (newest-first) → leftmost = newest active | Sorted by `assigned_at` ascending → leftmost = oldest assigned |
| Runtime new-session add | Prepend → newest leftmost | Append → newest rightmost |
| Activity on existing session | `_promoteStripIcon` repositions to leftmost | Position UNCHANGED; unread-badge pulse intact |
| Session removed | Icon disappears; rest re-flow | Same — remaining icons retain chronological positions |
| Persona color/icon update | In-place attribute mutation | Same |
| Focus mode / unread pulse | Orthogonal (`data-focused` / `data-unread`) | Same — focus visuals unchanged |

### Creation-Time Source

Voice-persona allocation stamps `assigned_at` (ISO-8601) when a persona is allocated. Visible in `mcp__cosa-voice__get_session_info` payload as `voice_persona.assigned_at`. This is the canonical "persona creation time."

**Plumbing check at implementation time**: confirm the `persona` object passed into `_addStripIcon(senderId, projectName, persona, sessionId, …)` includes `assigned_at`. The `/api/cosa-voice/voice-persona/pool` endpoint already exposes it; the senders router and the WS new-session event must also include it.

**Fallback**: if `assigned_at` is missing for an icon at insertion time, stamp `data-created-at` with `new Date().toISOString()` so ordering is deterministic within the session.
