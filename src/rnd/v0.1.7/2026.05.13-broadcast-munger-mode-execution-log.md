### 7a. Intermediate finding — joining semantics needed

First test run revealed cases 5-7 failed because the existing `_remove_spaces_around_punctuation` only strips leading-space-before-punctuation (line 434: `prose.replace(" .", ".")`) and NOT trailing-space-after. The lookup-converted `"dot"` → `"."` produced patterns like `"file_name. py"` instead of `"file_name.py"`.

**Resolution**: added explicit joining semantics inside the token-replacement loop — when a token's lookup result is in `{".", "_", "#"}` (identifier-glue chars), pop the trailing space from `result` and skip the following space in `tokens`. Domain replacements (e.g., `.com`) also join.

This change is scoped to `munge_text_broadcast` and does NOT affect `munge_text_punctuation` or any other existing mode.

prose = re.sub( r"\bquestion mark\b",     "?", prose, flags=re.IGNORECASE )

The existing `_remove_spaces_around_punctuation` helper collapses any " ?" / " !" leading-space gap after substitution, so output is naturally formatted (e.g., `"How are you ?" → "How are you?"`).

Single-token entries (`comma`, `colon`, `semicolon`, `bang`) flow through the existing per-token lookup branch and emerge with natural spacing handled by `_remove_spaces_around_punctuation`.

## 16. Follow-up — gratuitous-punctuation cleanup rules

**Requested by Rick (voice, 2026-05-13 PM)**: Whisper sometimes emits gratuitous comma runs and stacked punctuation around emphatic dictation. Three specific patterns called out as objectively redundant and worth cleaning post-munge:

1. **Multiple commas in a row** — `",,,"` or `",,"` → `","`
2. **Comma immediately before `!`** — `",!"` → `"!"`
3. **Period immediately after `!`** — `"!."` → `"!"`

**Edits applied** to `munge_text_broadcast` body, after `_remove_spaces_around_punctuation` + `_remove_dashed_spellings`:

```python
prose = re.sub( r",+", ",", prose )      # collapse comma runs
prose = prose.replace( ",!", "!" )       # drop comma before bang
prose = prose.replace( "!.", "!" )       # drop period after bang
```

Order is significant — collapse first, then the symbol-specific drops, so cascades like `",,!"` resolve through `",!"` to `"!"` in one pass.

**Why scoped to broadcast and NOT pushed into `_remove_spaces_around_punctuation`**: the shared helper is used by `munge_text_punctuation`, `munge_text_email`, `munge_python_punctuation`, `munge_sql_punctuation`, and others. Rick scoped the cleanup as a broadcast-specific concern — adding to broadcast only keeps blast radius minimal. If the same cleanup turns out to be desirable everywhere, it can be hoisted later in a separate ticket.
