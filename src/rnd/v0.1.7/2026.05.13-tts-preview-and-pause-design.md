## Context

Rick reports "an incredible spike in TTS service costs" because so much of what's arriving as TTS in chorus mode is replayed verbatim. Goal: synthesize only the first ~25% of each TTS message and auto-pause; user resumes via existing pause/play/stop UI.

## Critical cost-model finding (drives the design)

ElevenLabs and OpenAI both charge **at request-time, not per-byte streamed**. Stream-abort saves bandwidth but NOT dollars (`speech.py:879` logs full char count at generation start). To actually save money, the split MUST happen **client-side** before the API call.

## Core mechanic

1. **At `addToTTSQueue`** — if `tts preview enabled` AND `type !== 'action-required'` AND `text.length >= tts preview min chars`:
   - Split `ttsText` into sentences via `_splitIntoSentences`
   - Compute `preview_count = max(1, floor(N * tts preview fraction))`
   - Slice into `previewText` (first `preview_count` sentences) + `remainderText` (rest)
   - If `remainderText` is empty, set `stage = "full"` (no pause needed)
   - Otherwise `stage = "preview"`

2. **Queue item shape evolves**:
   ```
   { id, type, notification, addedAt,
     previewText,    // text to send for current playback
     remainderText,  // text to send on resume (empty string if no remainder)
     stage,          // "full" | "preview" | "remainder"
     ttsText         // legacy field — kept for backward compat
   }
   ```

3. **`activateNextTTS`** routes by stage:
   - `stage === "full"` → send `previewText` (= original `ttsText`), advance on completion (current behavior)
   - `stage === "preview"` → send `previewText`, ON COMPLETION transition to `stage === "remainder"` + auto-pause
   - `stage === "remainder"` → send `remainderText`, advance on completion

4. **`onTTSPlaybackComplete`**:
   - If item.stage === "preview" AND remainderText non-empty: set `_ttsPausedAfterPreview = true`, set `isTTSPaused = true`, update item.stage = "remainder", do NOT advance queue
   - Otherwise: advance as today

5. **`resumeTTS` (user hits play)**:
   - If `_ttsPausedAfterPreview` true AND active item has `stage === "remainder"`: clear flag, send remainder via TTS, advance on completion
   - Otherwise: standard resume (continue paused audio)

6. **`stopTTSAndAdvance`** — drops remainder + advances unconditionally (preserves existing semantics)

## Sentence-splitting algorithm

```javascript
_splitIntoSentences( text ) {
    if ( !text || typeof text !== 'string' ) return [];
    // Primary: split on terminal punctuation followed by space + capital letter (or EOS)
    const parts = text.match( /[^.!?]+(?:[.!?]+(?=\s+[A-Z]|\s*$)|$)/g ) || [];
    if ( parts.length > 1 ) return parts.map( p => p.trim() ).filter( p => p );
    // Fallback: if regex produced a single chunk for clearly-long text, word-count split
    const words = text.trim().split( /\s+/ );
    if ( words.length > 12 ) {
        const mid = Math.floor( words.length / 2 );
        return [ words.slice( 0, mid ).join( ' ' ), words.slice( mid ).join( ' ' ) ];
    }
    return [ text.trim() ];
}
```

Handles:
- ✅ `"Hello. World."` → ["Hello.", "World."]
- ✅ `"Mr. Smith said hi. Then he left."` → ["Mr. Smith said hi.", "Then he left."]
- ✅ `"3.14 is pi. Cool fact!"` → ["3.14 is pi.", "Cool fact!"]
- ✅ `"www.example.com is a URL. Visit it."` → ["www.example.com is a URL.", "Visit it."]
- ✅ Long single-sentence text → falls back to word-count split

## Cost-tracking telemetry

```javascript
// At every split point
if ( previewLen < originalLen ) {
    this.ttsCostSavings = this.ttsCostSavings || { saved: 0, total: 0 };
    this.ttsCostSavings.total += originalLen;
    this.ttsCostSavings.saved += ( originalLen - previewLen );
    this.log( `[TTS-COST] Saved ${originalLen - previewLen} chars (preview: ${previewLen} of ${originalLen} total). Session total saved: ${this.ttsCostSavings.saved} of ${this.ttsCostSavings.total} (${(100*this.ttsCostSavings.saved/this.ttsCostSavings.total).toFixed(1)}%)` );
}
```

When user resumes a remainder, log `[TTS-COST] Remainder resumed: +${remainderLen} chars (cancels saved chars for this message)`.
