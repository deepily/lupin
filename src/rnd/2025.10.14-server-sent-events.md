# FastAPI Server-Sent Events (SSE) Implementation Guide

## Conceptual Overview

Server-Sent Events (SSE) operates over a unidirectional HTTP connection where the server maintains an open response stream. The client initiates a standard HTTP request, and the server responds with `Content-Type: text/event-stream`, keeping the connection alive while pushing events. Each event follows the format:

```
data: <payload>\n\n
```

### Architecture

Your implementation involves three layers:

1. **FastAPI endpoint**: Accepts POST, simulates async work, emits heartbeats every 5s, returns final result
2. **Python SSE client**: Maintains connection, handles events, implements 2-minute timeout
3. **Bash wrapper**: Orchestrates execution and captures output

## Implementation

### 1. FastAPI Server (`server.py`)

```python
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
import asyncio
import json
from datetime import datetime
import random

app = FastAPI()

async def event_generator(message: str, heartbeat_interval: int = 5):
    """
    Generator that yields SSE events: heartbeats and final result.
    Simulates processing time between 2-120 seconds.
    """
    processing_time = random.uniform(2, 120)
    start_time = asyncio.get_event_loop().time()
    
    # Send initial acknowledgment
    yield f"data: {json.dumps({'type': 'ack', 'message': 'Request received', 'timestamp': datetime.utcnow().isoformat()})}\n\n"
    
    # Simulate async processing with heartbeats
    elapsed = 0
    while elapsed < processing_time:
        await asyncio.sleep(heartbeat_interval)
        elapsed = asyncio.get_event_loop().time() - start_time
        
        # Send heartbeat
        yield f"data: {json.dumps({'type': 'heartbeat', 'elapsed': round(elapsed, 2)})}\n\n"
    
    # Send final result
    result = f"Processed: {message} (took {round(processing_time, 2)}s)"
    yield f"data: {json.dumps({'type': 'result', 'data': result, 'timestamp': datetime.utcnow().isoformat()})}\n\n"

@app.post("/process")
async def process_message(payload: dict):
    """
    SSE endpoint that streams events back to client.
    Expects JSON: {"message": "your message", "heartbeat_interval": 5}
    """
    message = payload.get("message", "")
    heartbeat_interval = payload.get("heartbeat_interval", 5)
    
    return StreamingResponse(
        event_generator(message, heartbeat_interval),
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "X-Accel-Buffering": "no"  # Disable nginx buffering
        }
    )

if __name__ == "__main__":
    import uvicorn
    uvicorn.run(app, host="0.0.0.0", port=8000)
```

### 2. Python SSE Client (`client.py`)

```python
import requests
import json
import sys
from datetime import datetime, timedelta

def consume_sse(url: str, message: str, heartbeat_interval: int = 5, timeout_seconds: int = 120):
    """
    Consumes SSE stream with timeout handling.
    Returns the final result string or None on timeout.
    """
    payload = {"message": message, "heartbeat_interval": heartbeat_interval}
    
    try:
        start_time = datetime.now()
        
        with requests.post(
            url,
            json=payload,
            stream=True,
            timeout=(10, timeout_seconds)  # (connect timeout, read timeout)
        ) as response:
            response.raise_for_status()
            
            for line in response.iter_lines():
                # Check timeout
                if (datetime.now() - start_time).total_seconds() > timeout_seconds:
                    print(f"ERROR: Timeout after {timeout_seconds}s", file=sys.stderr)
                    return None
                
                if line:
                    decoded = line.decode('utf-8')
                    
                    # SSE format: "data: "
                    if decoded.startswith('data: '):
                        data_str = decoded[6:]  # Remove "data: " prefix
                        
                        try:
                            event = json.loads(data_str)
                            event_type = event.get('type')
                            
                            if event_type == 'ack':
                                print(f"[ACK] {event.get('message')}", file=sys.stderr)
                            
                            elif event_type == 'heartbeat':
                                print(f"[HEARTBEAT] Elapsed: {event.get('elapsed')}s", file=sys.stderr)
                            
                            elif event_type == 'result':
                                # Final result - return it
                                return event.get('data')
                        
                        except json.JSONDecodeError as e:
                            print(f"ERROR: Failed to parse event: {e}", file=sys.stderr)
            
            # Stream ended without result
            print("ERROR: Stream ended without result", file=sys.stderr)
            return None
            
    except requests.exceptions.Timeout:
        print(f"ERROR: Request timeout after {timeout_seconds}s", file=sys.stderr)
        return None
    except requests.exceptions.RequestException as e:
        print(f"ERROR: Request failed: {e}", file=sys.stderr)
        return None

if __name__ == "__main__":
    if len(sys.argv) < 2:
        print("Usage: python client.py  [heartbeat_interval] [timeout]", file=sys.stderr)
        sys.exit(1)
    
    message = sys.argv[1]
    heartbeat_interval = int(sys.argv[2]) if len(sys.argv) > 2 else 5
    timeout = int(sys.argv[3]) if len(sys.argv) > 3 else 120
    
    url = "http://localhost:8000/process"
    result = consume_sse(url, message, heartbeat_interval, timeout)
    
    if result:
        print(result)  # stdout for the result
        sys.exit(0)
    else:
        sys.exit(1)
```

### 3. Bash Wrapper (`process.sh`)

```bash
#!/bin/bash

# Configuration
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
PYTHON_CLIENT="${SCRIPT_DIR}/client.py"
MESSAGE="${1:-Default message}"
HEARTBEAT_INTERVAL="${2:-5}"
TIMEOUT="${3:-120}"

# Validate Python client exists
if [[ ! -f "$PYTHON_CLIENT" ]]; then
    echo "ERROR: Python client not found at $PYTHON_CLIENT" >&2
    exit 1
fi

# Execute Python client and capture result
result=$(python3 "$PYTHON_CLIENT" "$MESSAGE" "$HEARTBEAT_INTERVAL" "$TIMEOUT")
exit_code=$?

if [[ $exit_code -eq 0 ]] && [[ -n "$result" ]]; then
    echo "SUCCESS: $result"
    exit 0
else
    echo "FAILED: No result received or error occurred" >&2
    exit 1
fi
```

## Key Design Decisions

### 1. Async Generator Pattern
FastAPI's `StreamingResponse` with async generators provides backpressure handling and clean resource management. The generator pattern allows the server to yield events incrementally without buffering the entire response.

### 2. JSON-Structured Events
Each SSE event carries typed payloads, enabling extensibility. The event schema includes:
- `type`: Event classification (ack, heartbeat, result)
- `data`: Event-specific payload
- `timestamp`: UTC timestamp for tracking

### 3. Stream Multiplexing
Diagnostics (heartbeats, acknowledgments) route to stderr, while final results go to stdout. This separation allows bash scripts to cleanly capture results while monitoring progress.

### 4. Dual Timeout Strategy
The implementation uses:
- `requests` timeout tuple: `(connect_timeout, read_timeout)`
- Explicit elapsed time checking in the event loop

This ensures robustness against both network-level timeouts and application-level hanging.

### 5. Exit Code Propagation
Proper exit code handling enables bash error handling patterns:
- `0`: Success with result
- `1`: Timeout or error

## Error Handling

### Client-Side Errors

**Timeout:**
```
ERROR: Timeout after 120s
Exit code: 1
```

**Connection Failure:**
```
ERROR: Request failed: Connection refused
Exit code: 1
```

**Parse Error:**
```
ERROR: Failed to parse event: Expecting value: line 1 column 1 (char 0)
```

### Server-Side Considerations

- **Connection drops**: Client handles via `requests.exceptions.RequestException`
- **Malformed JSON**: Client catches `JSONDecodeError` and continues processing
- **Nginx buffering**: Disabled via `X-Accel-Buffering: no` header

## Extensions & Modifications

### Adding Progress Percentages

Modify the generator to include progress:

```python
yield f"data: {json.dumps({'type': 'progress', 'percent': 50, 'elapsed': elapsed})}\n\n"
```

### Error Event Type

Add error handling in the generator:

```python
try:
    # processing logic
except Exception as e:
    yield f"data: {json.dumps({'type': 'error', 'message': str(e)})}\n\n"
```

### Custom Result Serialization

For complex results:

```python
result_obj = {
    "status": "completed",
    "data": processed_data,
    "metadata": {"duration": processing_time}
}
yield f"data: {json.dumps({'type': 'result', 'data': result_obj})}\n\n"
```

Async generators yield events incrementally, avoiding memory accumulation for long-running streams.

## Troubleshooting

### Issue: No Events Received

**Cause:** Buffering by intermediate proxies  
**Solution:** Ensure `X-Accel-Buffering: no` header is set

### Issue: Timeout Despite Heartbeats

**Cause:** `requests` read timeout too aggressive  
**Solution:** Increase read timeout or use `None` for infinite

### Issue: Connection Hangs

**Cause:** Generator not yielding or blocking I/O  
**Solution:** Use `asyncio.sleep()` instead of `time.sleep()` in async context
