## Executive Summary

This document describes the implementation of a storage backend factory pattern for LanceDB solution snapshot manager, enabling seamless switching between local filesystem storage (development/testing) and Google Cloud Storage (production/Cloud Run deployment).

**Key Features**:
- Smart path detection in existing `LanceDBSolutionManager`
- Configuration-driven backend selection (`storage_backend=local|gcs`)
- Backward compatible with existing local-only deployments
- Automated warm-up routine for GCS cold-start mitigation
- Complete migration tooling (backup, restore, local↔GCS)

## Architecture Overview

### Storage Backend Options

| Backend | Use Case | Configuration | Path Format | Persistence |
|---------|----------|---------------|-------------|-------------|
| **Local** | Development, Testing | `storage_backend=local` | `/src/conf/.../*.lancedb` | Ephemeral (container) |
| **GCS** | Production (Cloud Run) | `storage_backend=gcs` | `gs://bucket-name/path` | Persistent (cloud) |

### Configuration Blocks

```ini
[Lupin: Development]
storage_backend                   = local
solution snapshots lancedb path      = /src/conf/long-term-memory/lupin.lancedb
solution snapshots lancedb table     = solution_snapshots
```

## Path Resolution Logic

### Design Principles

1. **Explicit Configuration**: Backend selection via `storage_backend` config key
2. **Smart Path Detection**: Auto-detect GCS if path starts with `gs://` (failsafe)
3. **Validation First**: Validate paths before attempting connection
4. **Error Messages**: Clear, actionable error messages for misconfiguration

### Algorithm Pseudocode

```
function _resolve_db_path(config):
    backend = config.get("storage_backend", "local")

    if backend == "gcs":
        gcs_uri = config.get("gcs_uri")

        # Validation
        if gcs_uri is None:
            raise ValueError("storage_backend=gcs requires gcs_uri config")

        if not gcs_uri.startswith("gs://"):
            raise ValueError("GCS URI must start with gs://, got: {gcs_uri}")

        return gcs_uri

    elif backend == "local":
        db_path = config.get("db_path")

        # Validation
        if db_path is None:
            raise ValueError("storage_backend=local requires db_path config")

        # Apply project root prefix if path is relative
        if db_path.startswith("/src/"):
            full_path = get_project_root() + db_path
        else:
            full_path = db_path

        # Path existence validation (local only)
        if not os.path.exists(full_path):
            raise ValueError("Local database path does not exist: {full_path}")

        return full_path

    else:
        raise ValueError("Unknown storage_backend: {backend}. Must be 'local' or 'gcs'")
```

### Validation Rules

**GCS Backend**:
- ✅ `gcs_uri` config key must be present
- ✅ GCS URI must start with `gs://`
- ✅ URI format: `gs://<bucket-name>/<path>/<db-name>.lancedb`
- ❌ Do NOT validate GCS bucket existence (requires network call)

**Local Backend**:
- ✅ `db_path` config key must be present
- ✅ Path must exist on filesystem (or be creatable)
- ✅ Apply `get_project_root()` prefix for relative paths
- ✅ Absolute paths used as-is

### 2. New _resolve_db_path() Method

**File**: `src/cosa/memory/lancedb_solution_manager.py`

**Location**: After `__init__()`, before `_get_schema()`

```python
def _resolve_db_path( self, config: Dict[str, Any] ) -> str:
    """
    Resolve database path based on storage backend configuration.

    Requires:
        - config["storage_backend"] is "local" or "gcs"
        - If backend=gcs: config["gcs_uri"] must be valid GCS URI
        - If backend=local: config["db_path"] must exist or be creatable

    Ensures:
        - Returns fully qualified database path for lancedb.connect()
        - Local paths have project root prefix applied
        - GCS URIs validated for correct format
        - Clear error messages for misconfiguration

    Args:
        config: Configuration dictionary with backend and path settings

    Returns:
        str: Resolved database path (local absolute path or GCS URI)

    Raises:
        ValueError: If backend unknown, required keys missing, or validation fails
    """
    backend = config.get( "storage_backend", "local" )

    if backend == "gcs":
        # GCS backend - use cloud storage URI
        gcs_uri = config.get( "gcs_uri" )

        if not gcs_uri:
            raise ValueError(
                "storage_backend=gcs requires 'gcs_uri' config key. "
                "Example: solution snapshots lancedb gcs uri = gs://bucket/path/db.lancedb"
            )

        if not gcs_uri.startswith( "gs://" ):
            raise ValueError(
                f"GCS URI must start with 'gs://', got: {gcs_uri}. "
                f"Example: gs://lupin-lancedb-prod/lupin.lancedb"
            )

        if self.debug:
            print( f"[GCS Backend] Using GCS URI: {gcs_uri}" )

        return gcs_uri

    elif backend == "local":
        # Local backend - use filesystem path
        db_path = config.get( "db_path" )

        if not db_path:
            raise ValueError(
                "storage_backend=local requires 'db_path' config key. "
                "Example: solution snapshots lancedb path = /src/conf/long-term-memory/lupin.lancedb"
            )

        # Apply project root prefix if path is relative
        if db_path.startswith( "/src/" ):
            full_path = du.get_project_root() + db_path
        else:
            full_path = db_path

        # Validate path exists (or parent directory exists for creation)
        if not os.path.exists( full_path ):
            parent_dir = os.path.dirname( full_path )
            if not os.path.exists( parent_dir ):
                raise ValueError(
                    f"Local database path parent directory does not exist: {parent_dir}. "
                    f"Full path: {full_path}"
                )

        if self.debug:
            print( f"[Local Backend] Using local path: {full_path}" )

        return full_path

    else:
        raise ValueError(
            f"Unknown storage_backend: '{backend}'. Must be 'local' or 'gcs'. "
            f"Check your configuration file [config_block] section."
        )
```

## GCS Credentials Strategy

### Cloud Run (Production)

**Authentication Method**: Application Default Credentials (ADC)

**Setup**:
1. Cloud Run service account automatically has ADC
2. Grant service account GCS permissions:
   ```bash
   gcloud projects add-iam-policy-binding PROJECT_ID \
       --member=serviceAccount:SERVICE_ACCOUNT_EMAIL \
       --role=roles/storage.objectAdmin
   ```
3. Or grant bucket-specific permissions:
   ```bash
   gsutil iam ch serviceAccount:SERVICE_ACCOUNT_EMAIL:roles/storage.objectAdmin \
       gs://lupin-lancedb-prod
   ```

**No Code Changes**: LanceDB Python library automatically uses ADC when connecting to `gs://` URIs

### Local Development

**Option 1: gcloud ADC** (Recommended for local testing with GCS)
```bash
gcloud auth application-default login
```

**Option 2: Service Account Key** (For CI/CD)
```bash
export GOOGLE_APPLICATION_CREDENTIALS="/path/to/service-account-key.json"
```

**Option 3: Skip GCS Locally** (Use local backend only)
- Use `[Lupin: Development]` config block (storage_backend=local)
- No GCS credentials needed

### Testing

**Test Environment Setup**:
1. Create test bucket: `gs://lupin-lancedb-test/`
2. Set lifecycle rule: Auto-delete objects >7 days
3. Use separate service account with limited permissions
4. Test fixtures use `[Lupin: Testing-GCS]` config block

## Warm-Up Routine Design

### Purpose

Mitigate GCS cold-start latency penalty by pre-loading frequently accessed fragments into memory/cache during application startup.

### Implementation Location

**File**: `src/fastapi_app/main.py`

**Insertion Point**: After manager initialization (around line 415)

### Pseudocode

```python
def warmup_lancedb_cache( snapshot_mgr: SolutionSnapshotManagerInterface ) -> None:
    """
    Pre-load GCS fragments into memory/cache on startup.

    Requires:
        - snapshot_mgr is initialized and connected
        - Database contains at least one record (or handles empty gracefully)

    Ensures:
        - Runs 3-5 representative semantic searches
        - Completes in <30 seconds
        - Logs warm-up duration and stats
        - Does not crash if database empty

    Args:
        snapshot_mgr: Initialized solution snapshot manager

    Returns:
        None
    """
    if not config_mgr.get( "enable_lancedb_warmup", default=False, return_type="bool" ):
        if debug:
            print( "[Warm-up] Skipped (enable_lancedb_warmup=false)" )
        return

    start_time = time.time()

    try:
        # Get sample queries (representative of common searches)
        sample_queries = [
            "calculate fibonacci sequence",
            "format date and time",
            "mathematical computation",
            "parse user input",
            "validate data structure"
        ]

        queries_executed = 0
        total_results = 0

        for query in sample_queries:
            try:
                results = snapshot_mgr.semantic_search( query, top_k=5 )
                queries_executed += 1
                total_results += len( results )
            except Exception as e:
                # Graceful degradation - continue warm-up even if query fails
                if debug:
                    print( f"[Warm-up] Query failed (non-fatal): {e}" )

        duration = time.time() - start_time

        print( f"[Warm-up] Complete: {queries_executed} queries, {total_results} results, {duration:.2f}s" )

    except Exception as e:
        # Non-fatal - warm-up failure should not crash application
        print( f"[Warm-up] Failed (non-fatal): {e}" )
        if debug:
            import traceback
            traceback.print_exc()
```

### Expected Performance

**Targets** (based on research doc):
- **Cold start without warm-up**: 100-300ms p95 latency
- **After warm-up**: <50ms p95 latency (ideally <30ms)
- **Warm-up duration**: <30 seconds total

### Configuration

```ini
[Lupin: Production]
enable_lancedb_warmup = true

[Lupin: Development]
# Warmup not needed for local filesystem
enable_lancedb_warmup = false

[Lupin: Testing-GCS]
# Disable for faster test execution
enable_lancedb_warmup = false
```

## Migration Tooling Design

### 1. Backup Script (Local → GCS)

**File**: `src/scripts/lancedb-backup-to-gcs.sh`

**Purpose**: Upload local LanceDB to GCS bucket for Cloud Run deployment or disaster recovery

**Usage**:
```bash
./src/scripts/lancedb-backup-to-gcs.sh [bucket-name] [local-path]

# Example:
./src/scripts/lancedb-backup-to-gcs.sh lupin-lancedb-prod /src/conf/long-term-memory/lupin.lancedb
```

**Algorithm**:
1. Validate inputs (bucket exists, local path exists)
2. Create timestamped backup: `backup-YYYYMMDD-HHMMSS.tar.gz`
3. Compress local LanceDB directory
4. Upload to `gs://bucket-name/backups/backup-YYYYMMDD-HHMMSS.tar.gz`
5. Validate upload success (checksum comparison)
6. Log results

### 2. Restore Script (GCS → Local)

**File**: `src/scripts/lancedb-restore-from-gcs.sh`

**Purpose**: Download GCS backup to local filesystem for debugging or recovery

**Usage**:
```bash
./src/scripts/lancedb-restore-from-gcs.sh [bucket-name] [backup-filename] [local-path]

# Example (latest backup):
./src/scripts/lancedb-restore-from-gcs.sh lupin-lancedb-prod latest /src/conf/long-term-memory/lupin.lancedb

# Example (specific backup):
./src/scripts/lancedb-restore-from-gcs.sh lupin-lancedb-prod backup-20251113-143000.tar.gz /tmp/lupin.lancedb
```

**Algorithm**:
1. Validate inputs
2. If "latest": Find most recent backup in bucket
3. Download backup from GCS
4. Extract to local path (with safety checks - prompt if path exists)
5. Validate data integrity
6. Log results

### 3. Migration Utility (Local ↔ GCS)

**File**: `src/scripts/migrate-lancedb-local-to-gcs.py`

**Purpose**: Direct data copy between local and GCS LanceDB instances (no intermediate tar.gz)

**Usage**:
```python
python src/scripts/migrate-lancedb-local-to-gcs.py \
    --source-backend local \
    --source-path /src/conf/long-term-memory/lupin.lancedb \
    --dest-backend gcs \
    --dest-uri gs://lupin-lancedb-prod/lupin.lancedb \
    --table-name solution_snapshots
```

**Algorithm**:
1. Open source LanceDB connection
2. Open destination LanceDB connection
3. Read all records from source table
4. Write records to destination table (batched for efficiency)
5. Validate record counts match
6. Display progress bar for large datasets

## Risk Mitigation

### Risk 1: GCS Latency Too High

**Symptom**: Warm queries >500ms p95

**Mitigation**:
- Warm-up routine pre-loads cache
- Performance benchmarks validate early

**Contingency**:
- Add local SSD caching layer (ephemeral but fast)
- Consider hybrid approach (local cache + GCS persistence)

### Risk 2: GCS Credentials Issues

**Symptom**: `PermissionDenied` or `401 Unauthorized` errors

**Mitigation**:
- Test with real GCS bucket during integration testing
- Document IAM setup steps clearly
- Validate service account permissions before deployment

**Contingency**:
- Rollback to local backend (`storage_backend=local`)
- Use Dockerfile with `[Lupin: Development]` block temporarily

### Risk 3: Data Migration Corruption

**Symptom**: Missing records or corrupted data after migration

**Mitigation**:
- Backup scripts with validation (checksum, record count)
- Round-trip testing (local → GCS → local)
- Keep local backups until GCS proven stable (1 week)

**Contingency**:
- Restore from local backup
- Re-run migration with verbose logging

### Risk 4: Breaking Changes to Existing Code

**Symptom**: Local development broken after factory implementation

**Mitigation**:
- Backward compatibility testing (local backend must work unchanged)
- Default to `storage_backend=local` if not specified
- Comprehensive unit tests for path resolution

**Contingency**:
- Feature flag to disable GCS backend
- Git revert if issues discovered post-merge
