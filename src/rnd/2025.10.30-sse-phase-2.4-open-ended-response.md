# SSE Phase 2.4: Open-Ended Response Implementation

**Date**: 2025-10-30
**Status**: Planning
**Related**: [2025.10.30-sse-phase-2.2-ux-improvements.md](./2025.10.30-sse-phase-2.2-ux-improvements.md)

## Overview

Implement open-ended (free-text) response type for SSE notifications, allowing users to provide custom text responses instead of binary Yes/No choices. Includes voice input via Web Speech API.

## Current State

### ✅ Already Working
1. **Frontend UI scaffold** exists:
   - Text input field
   - Microphone button 🎤
   - Submit button
   - Enter key support

2. **Backend support** exists:
   - `response_type=open_ended` is accepted
   - Response submission endpoint handles arbitrary text
   - Database stores text responses

3. **Event flow** works:
   - User types text → Submit → Response sent to backend
   - SSE stream completes with user's text

### ❌ Missing Pieces
1. **Voice input (STT)** - Mic button shows placeholder alert
2. **Input validation** - No length limits, XSS protection, or sanitization
3. **Default value handling** - Unclear how `response_default` works for open-ended
4. **Visual feedback** - No character counter, no validation errors shown

### Task 2: Voice Input (Web Speech API)
**Priority**: MEDIUM (nice-to-have, not critical)

**Approach**: Use browser's built-in Web Speech API (Speech Recognition)
- **Pros**: No server-side STT needed, works offline, free
- **Cons**: Limited browser support (Chrome/Edge only), English-biased

**Implementation**:
```javascript
async startVoiceInput( notificationId ) {
    // Check browser support
    if ( !('webkitSpeechRecognition' in window) && !('SpeechRecognition' in window) ) {
        alert( "Voice input not supported in this browser. Please use Chrome or Edge." );
        return;
    }

    const SpeechRecognition = window.SpeechRecognition || window.webkitSpeechRecognition;
    const recognition = new SpeechRecognition();

    recognition.lang = 'en-US';
    recognition.interimResults = false;
    recognition.maxAlternatives = 1;

    const micButton = document.querySelector( `[data-notification-id="${notificationId}"].response-mic-button` );
    const textInput = document.getElementById( `response-input-${notificationId}` );

    // Visual feedback: Change button color while recording
    micButton.classList.add( 'recording' );
    micButton.textContent = '🔴';  // Red circle

    recognition.onresult = ( event ) => {
        const transcript = event.results[0][0].transcript;
        textInput.value = transcript;  // Fill input with transcription
        textInput.focus();
        this.log( `Voice input transcribed: ${transcript}` );
    };

    recognition.onerror = ( event ) => {
        this.error( `Voice input error: ${event.error}` );
        alert( `Voice input failed: ${event.error}` );
    };

    recognition.onend = () => {
        micButton.classList.remove( 'recording' );
        micButton.textContent = '🎤';  // Back to microphone
    };

    recognition.start();
}
```

### Task 3: Default Value Handling for Open-Ended
**Priority**: MEDIUM (completes feature parity with yes/no)

**Design decision needed**: What should `response_default` mean for open-ended?

**Option A: Pre-filled text** (Recommended)
- `response_default="No comment"` → Input field pre-filled with "No comment"
- User can edit or submit as-is
- On timeout: Submit the pre-filled value

**Option B: Placeholder suggestion**
- `response_default="e.g., I approve"` → Shows as placeholder, not submitted
- On timeout: Submit empty string (or error?)

**Option C: Conditional behavior**
- If `response_default` provided → Pre-fill (Option A)
- If null → Required (no default, must respond or timeout fails)

**Recommendation**: Use Option A for consistency with yes/no behavior.

**Implementation** (assuming Option A):
```javascript

```

@router.post("/notify/response")
async def submit_notification_response(
    request_body: Dict[str, Any] = Body(...),
    notification_db: NotificationsDatabase = Depends(get_notifications_database),
    ws_manager: WebSocketManager = Depends(get_websocket_manager)
):
    notification_id = request_body.get( "notification_id" )
    response_value  = request_body.get( "response_value" )

    # Validation: Check response value
    if not response_value or not isinstance( response_value, str ):
        raise HTTPException( status_code=400, detail="response_value must be a non-empty string" )

    # Sanitize: Remove HTML tags (prevent XSS)
    import re
    response_value = re.sub( r'<[^>]+>', '', response_value )

    # Length validation
    if len( response_value ) > 500:
        raise HTTPException( status_code=400, detail="Response too long (max 500 characters)" )

    if len( response_value.strip() ) == 0:
        raise HTTPException( status_code=400, detail="Response cannot be empty" )
