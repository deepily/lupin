## Addendum, 2026-09-15 ~20:35 EDT — how the snapshot suite stabilizes, and a retraction

Added at Mr. Radio 🦉's instruction after a census question exposed a defect in how this
author was counting. File existence below verified with `git ls-files`, not from memory.

### RETRACTION, stated as a retraction

**I claimed `src/tests/e2e_ui/test_dm_recent_activity.py` "pins nothing by any mechanism I
searched for". That is FALSE and is withdrawn.** It stabilizes thoroughly: lines 162-168 clear
the live commons feed with `innerHTML = ""`, inject one deterministic entry whose `ts` is frozen
at `2026-05-15T12:00:00.000Z`, tag the injected row with a `data-testid` of its own, and wait on
that testid before capturing.

The claim failed twice over, and both failures are in the *predicate*, not the tree:

1. I searched the fixed string `textContent =`, which can never match `innerHTML`.
2. I was looking for text-**pinning** when this file's mechanism is **clear-and-inject**.

⇒ **A predicate shaped like one remedy cannot see a different one.** The search was not merely
narrow; it encoded an assumption about what a fix looks like, and then reported the absence of
that shape as the absence of any fix.

### "Seven stabilizers" was a lower bound of a lower bound

| layer | population | what it is |
|---|---|---|
| `^_STABILIZE[A-Z_]*_JS` | **7 constants / 6 files** | one naming convention |
| all module-level `*_JS` constants | **~50 names / 25 files** | the real namespace |
| stabilizing **behaviours** | **3 shapes** | below |

The original figure counted one naming convention inside one of three behaviours. It was correct
for its predicate and useless without it — which is why the predicate now travels with it:

```
grep -rlE '^_STABILIZE[A-Z_]*_JS' src/tests/e2e_ui/*.py     # Mr. Radio's
git grep -lE '^_STABILIZE[A-Z_]*_JS' -- src/tests/e2e_ui/   # mine
```

Both return the same 6 files today. They agree **because both blind spots are empty**, not because
either is complete: the glob cannot see subdirectories (0 tracked `.py` there now), `git grep`
cannot see untracked or ignored files (0 now). Either becomes wrong the moment that changes.

### The three stabilization shapes

| shape | example | what it does |
|---|---|---|
| **pin text** | `_STABILIZE_*_JS`, `NORMALIZE_SPECS` | overwrite a drifting string with a fixed one |
| **hook the source** | `test_multiplexer_task_editing.py` (12 `page.route` / `add_init_script`) | stop the varying data arriving |
| **clear-and-inject** | `test_dm_recent_activity.py:162-168` | empty a live container, append a frozen row |

A census of the third shape is **not** offered here. One file of it has been read.

### 🔴 The Group A remedy already exists in this repo

`test_dm_recent_activity.py` is the correct handling of the live commons feed — **the exact defect
V10/V11/V12 have.** Those three capture `#sender-cards-container` with the feed live inside it,
which is the unbounded-height mechanism recorded earlier in this document. `dm_recent_activity`
empties that feed and injects one frozen row before it captures.

**Whoever fixes Group A should copy this file, not invent a mechanism.** This is read, not
inferred — the lines are quoted above.

### `test_commons_recent_activity.py` — the evidence that the convention under-reports

This file is **not** a population member and was never offered as one. It is the **specimen**:
concrete proof that enumerating by naming convention misses real instances of the behaviour.

| property | value | why it matters |
|---|---|---|
| clears a live container | `innerHTML = ''` at line 104 | the clear-and-inject behaviour, unmistakably |
| matches `^_STABILIZE[A-Z_]*_JS` | **no** | so the convention-based count never saw it |
| matches the fixed string `textContent =` | **no** | so this author's widened-but-still-wrong search never saw it either |
| asserts a snapshot | **no** (`assert_snapshot` count = 0) | so it is outside the snapshot population |

⇒ Read the last two rows together. A file can exhibit the behaviour, be invisible to **both**
predicates used in this investigation, and still be correctly excluded from the final count — for a
reason that has nothing to do with why the predicates missed it. **A count that lands on the right
number by a wrong route is not a census**, and nothing in the number itself tells you which you have.

That is the whole argument for shipping the predicate beside the figure, made with a real file
rather than in the abstract.

### ⚠️ A note on how these findings travelled

Every correction in this addendum crossed between sessions through a summarizing channel, and **a
summariser drops a negation before it drops anything else**. Measured in this investigation, twice:

- A path error (`src/tests/visual/…` for `src/tests/e2e_ui/…`) survived condensation while the
  finding it carried stayed intact — the wrong half travelled cleanly.
- A "not a population member, recorded as evidence" qualification arrived at the other end as
  "add it to the record", which reads as the opposite instruction.

⇒ **Durable artifacts carry qualifications; messages carry claims.** When a retraction or a
limit matters, it belongs in a committed file — this one — not in a DM that will be summarised on
arrival. That is why this section exists in the doc at all rather than in the thread where it
was argued.
