## What the debug-file ramp taught, so the next seat does not rediscover it

Six `src/scripts/debug/` files went 0% → 100% today (`ba1d71bb`, `51e78249`). The technique
transfers to the list above, but **the shape has to be checked per file first** — the assumption
that an import-and-smoke moves these cheaply was wrong in both directions:

| shape | what it means | how to cover it |
|---|---|---|
| **No functions, no `__main__` guard** | **importing IS running** — straight into network calls and real clients | install every stand-in **before** the import, on the **source module** (`from … import …` copies the reference at import time, so patching the script afterwards is too late), then `importlib.import_module` from a clean `sys.modules` |
| **Main guard + one big function** | importing is safe and covers almost **nothing** | reach the function through the **module object** and drive it with scripted inputs |
| **Reads `sys.argv` at module level** | dies under pytest's own argv | `monkeypatch.setattr( sys, "argv", … )` before the import |

⚠️ **Entry points named `test_*` are a trap.** Several of these scripts define `test_something()`.
Importing that name into a test module hands pytest a function matching `python_functions` and it
gets **collected as a test** — one that opens real sockets or HTTP connections. Reach it through the
module object, never by name.

⚠️ **And read the DATA, not just the return value.** Two fixture defects on this ramp were caught by
tests failing against *correct* code: a script that mutates one payload dict between two calls (so
recording by reference made both reads identical), and a "not a dict" branch that a list fixture can
never reach because an earlier step calls `.keys()` on it. Both were fixed in the **fixture** — never
by relaxing the assertion.
