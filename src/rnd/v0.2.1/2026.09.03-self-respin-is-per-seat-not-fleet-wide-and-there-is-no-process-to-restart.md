## 4. Reconciling with `988bcdae` — the rule holds, and it does not overturn this table

Tiberius established: **a process serves the code it imported FIRST, not the code that was
newest when it started**, because `sys.modules` is sticky and `session_spawner` is imported
*inside* the tool function. Start time genuinely does not predict which spawner a seat serves.

**That rule is correct and it applies to a different import kind than this one.** Measured,
one line each:

| module | import site | column | when it binds |
|---|---|---|---|
| `session_spawner` | `cosa_voice_mcp.py:3222` | **indented** — inside the tool function | first `spawn_sessions` call — **minutes to hours after start** |
| `session_bridge` | `cosa_voice_mcp.py:82` | **column 0** — no enclosing `def`/`class`/`try`/`if` | **server startup** |

⇒ For `session_bridge`, **first-import time collapses onto process start time**, so the
19:31:57 split is valid for *this* module and would be invalid for the spawner. His warning
is exactly the trap I would otherwise have walked into; the check that clears it is one
`cat -A` of two lines, and it is recorded here so nobody has to take it on my word.

**Two surfaces, two import kinds, one process** — which is why the same seat can be stale for
both and needs two different arguments to prove it.

## 5. María's second ask — is a restart actually the only fix?

**Three candidate refresh paths. Two are refuted by measurement, one is confirmed.**

| path | verdict |
|---|---|
| the process reloads the module some other way | 🔴 **no such mechanism** — zero hits for `importlib.reload` / autoreload / watchdog anywhere in `src/lupin_mcp/` |
| the MCP child restarts independently of its session | 🔴 **never observed** — across all 7 live processes the child is **0–1 s** younger than its `claude` parent. Over 11 hours and 7 seats, **not one** has ever been replaced in-session |
| a new session gets a new subprocess | ✅ **confirmed** — the three post-19:31 processes, one of which is mine, and whose `self_respin` demonstrably works |

⇒ **A seat's MCP module set is fixed when that seat launches and never changes for its
lifetime.** A `/clear` cannot refresh it either: `self_respin` clears *into the same pane and
the same session id* by design, so the parent process — and its child — survive.

⚠️ **Measured vs. read**: the 0–1 s deltas are mine, measured across the live population. That
a `/clear` preserves the process is **read from the design** (same seat, same session id,
same lineage), not separately measured tonight. Stated apart so nobody inherits it as a
measurement.

**There is no shared process to restart.** The documented workaround *is* the fix:

```

```

**Receipt: this seat.** I was reaped and respawned at ~20:06 tonight; my subprocess is
post-19:31 and the verb works. Managers already hold this authority — it needs nobody's word.

## 7. The procedure, for when it is wanted

**Nothing here needs Rick.** It is inside standing manager authority. Written as one command
per step so it is not re-derived under pressure.

**Step 0 — list the stale seats.** The split is at the moment the symbol reached disk:

```bash
CUT=$(date -d '2026-09-03 19:31:57' +%s)
ps -eo pid,ppid,lstart,args --no-headers | grep '[c]osa_voice_mcp.py' | while read -r pid ppid rest; do
  st=$(date -d "$(ps -o lstart= -p "$pid")" +%s)
  if [ "$st" -lt "$CUT" ]; then echo "STALE mcp=$pid claude=$ppid cwd=$(readlink /proc/$ppid/cwd)"; fi
done
```

⚠️ **The `if` is not styling.** Written as `[ … ] && echo`, the loop's exit status is the last
test's, so a run that correctly finds nothing stale **exits 1** and reads as a failure — this
file's own § *THE LINE YOU ADD TO REPORT THE EXIT CODE*. Verified: the `&&` form exits 1 while
printing all four seats. **Read the printed rows, not the status.**

**Run as written it prints the four stale seats.** Positive control: moving the cutoff later
makes the same loop print all seven, so an empty result would mean *none are stale* rather
than *the loop cannot see them*.

**Step 1 — reap and respawn each stale seat**, one at a time, from its own manager:

```
dismiss_sessions( write_memento=True, respin_personas=["<name>"] )
spawn_sessions(   persona_preference=["<name>"], seed_memento=<path> )
```

⚠️ **The trap Tiberius named, unchanged**: if the worker already wrote to the **root** slot
for a `self_respin` it can no longer fire, pass `write_memento=False` and hand the **root
record** as `seed_memento`. The reap only proves the **io** slot.

**Step 2 — confirm it worked.** Two independent confirmations; take both.

| surface | stale answer | fixed answer |
|---|---|---|
| the new seat's own `self_respin` on a bogus memento path | `cannot import name 'get_claude_session_id_with_source'` | `aborted … not a proven 'over_budget' reading` |
| that seat's MCP process start time vs `19:31:57` | earlier | later |

**How to tell it did NOT work**: the new subprocess still predates the split (⇒ you respawned
into an existing session rather than a new one), or the probe still raises `ImportError`
(⇒ the seat is serving a `session_bridge` from a tree that lacks `13014bd1` — check that
seat's `PYTHONPATH`, not its start time).
