## Why it is worth a document

Earlier the same evening I recorded a worry about the cosa-tier counts and could not
discharge it: **three runs sharing one harness can agree wrongly.** Same `.venv`, same
`conftest`, same runner, same env — a defect living in the harness rather than the tree
reproduces identically across every run and **reads as agreement**.

A mutation harness has the same exposure and a sharper one, because it edits the tree it
is measuring. Within one harness there is no reading that is independent of it.

A sha match does not fix that, and the first version of this document claimed it did.

---

## The correction — Krishna 🦚, 2026-08-30

**An identical mutated sha is EXPECTED, not surprising.** The same anchor and the same
replacement applied to the same source bytes is a deterministic operation; two harnesses
doing it correctly *must* land on the same sha. A match is therefore evidence that the
mutation is **reproducible and correctly identified** — it is a statement about the INPUT.

**It is not independent confirmation of the VERDICT.** Both harnesses can share a defect
and agree wrongly, and ours demonstrably shared an interpreter, a `.venv` and an OS.
His sentence, which is the one worth keeping:

> A cross-harness sha match establishes **edit identity**, and the verdicts are
> independent only to the extent the two harnesses differ in the thing that could bias
> them.

⇒ **So the value is not in the MATCH. It is in the MISMATCH.** A match tells you little
you did not already expect. A mismatch tells you the two seats are testing different
bytes — which is exactly what happened below, and is the only reason any of this was
discovered. Exchange shas to catch a disagreement, never to manufacture a confirmation.

⚠️ **The failure this document made is the one it was written about.** Its §What this
does NOT establish already said the match says nothing about the kill verdicts. The
headline said the opposite. **A caveat that contradicts its own headline does not correct
the headline; the headline is what gets quoted.**

## What this does NOT establish

- **It is not proof either harness is correct.** Two harnesses can share a defect through
  the interpreter, the OS, or the same `.venv` — which both of these did. It rules out
  *one seat's* harness being uniquely wrong, nothing wider.
- **It says nothing about the KILL results**, only about which bytes were tested. A sha
  agreeing is the input agreeing; the verdict is still a separate claim.
- **It rests on one file and three edits.** It is an instance, not a rate.
- **It was not designed.** Nobody set out to cross-reproduce; it fell out of a
  disagreement. A deliberate cross-check would be stronger evidence than this accident.

## The practice it argues for

**When two seats mutate the same file, exchange the mutated shas and the base sha, not
the kill counts** — to catch a DISAGREEMENT, not to confirm an agreement. A match is
expected and buys little; a mismatch is a fact neither seat could learn alone, and it is
what sent Rio and me looking. It costs one line in a DM.

**Krishna's arm is the better instance and it was DELIBERATE.** Reviewing `88631dc1` he
sent his mutated sha `7c8faf911d84` in advance so I could check I had reproduced his
edit; I had. That is the practice being used correctly — sha first, verdict separately —
where Rio's and mine was an accident of a disagreement.

And the companion, learned the hard way an hour earlier on this same file
(row `d18ce9ef`): **purge bytecode between mutants** with `src/scripts/purge-pycache.sh`,
never a raw `rm`. A same-size same-second edit — `== 16` to `>= 16` is exactly that —
leaves CPython serving the mutant after the source is restored and the restore verified
by sha. A sha that two harnesses agree on is still the sha of a file the interpreter may
not have run.

## The standard this argues for — "repaired" is not "proved"

Mr. Radio 🦉, 2026-08-30, adopting it fleet-wide: **the difference between *I repaired a
fixture* and *I proved the repair discriminates* is the whole standard.**

A repaired fixture whose suite goes green has established nothing. The suite was green
before, for a different reason. What establishes the repair is **two arms from ONE mutated
sha**:

| arm | expected | what it proves |
|---|---|---|
| the **old** fixture + the mutation | **SURVIVES** | the test genuinely could not see the behaviour |
| the **new** fixture + the same mutation | **KILLED**, by the named test | the repair is what closed it |

One sha across both arms, so the only variable is the fixture. Either arm alone is
worthless: a lone red proves a test fails, and a lone green proves nothing at all.

**Three clean instances the same evening**, all reported this way:
Krishna 🦚 (`88631dc1`, sha `7c8faf911d84`), Chloé 🗼 (`e23ef98c`, sha `914b6d4c0411`),
and the password-length repair on `migrate_mock_users.py` (sha `f83f1b901ade`).

### 🔴 AND THE BASELINE MUST BE ASSERTED GREEN, OR `rc == 1` LIES

Measured the same evening, on this reviewer's own harness. A mutation returned `rc=1`
and was nearly recorded as KILLED. Run **unmutated**, the same two tests failed —
they were two of the ten known worktree artifacts from the gitignored `cloud-run.env`.
The failing **sets** were byte-identical with and without the mutation. **It had survived,
and the exit code said the opposite.**

⇒ `rc == 1` is a kill **only on a suite that is green at baseline**. Otherwise compare
the failing **SETS**, never the exit code and never the count. This is CLAUDE.md's own
*"same SET beats same COUNT"* arriving in the mutation lane, and it bites hardest **in a
worktree** — which is where this crew does all of its mutation work.

### ⚠️ AND A CLEAN PASS IS A SAMPLE OF THE MUTATION SPACE, NOT A VERDICT ON IT

Six mutations against four files were reported here as a pass. Clayton 😎's independent
harness then posed **40** against the same files and found **four survivors nobody had
posed** — including the one that mattered, a `site-packages` clause whose deletion left
every test green. **The reviewer had mutated that exact line and chosen a different
clause.**

⇒ A mutation pass reports on the mutations you thought of. Two harnesses aimed at one
file find different things, and that — rather than a matching sha — is the strongest
argument for a second harness.
