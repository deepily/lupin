## 🔴 FINDING 1 (blocking) — with `LUPIN_ROOT` unset the startup hook has UNBOUNDED scope, and the CLI in the same module refuses exactly that

`_default_roots()` returns `()` when `LUPIN_ROOT` is unset, and `_in_scope` documents `()` as
**"empty = every path is in scope"**. `src/sitecustomize.py` calls a bare `install()`, so an
interpreter that starts with `src/` on the path and no `LUPIN_ROOT` patches itself to rewrite
**every pyc it writes anywhere on the filesystem**.

**Measured, one variable, both directions** — a package in a scratch dir with no relation to this repo:

| arm | `LUPIN_ROOT` | result |
|---|---|---|
| A | set to the worktree | `installed=True  mode=timestamp    converted=0` |
| B | **unset** | `installed=True  mode=checked-hash  converted=2` |

Blast radius is real but bounded — `site-packages`, `.venv`, `node_modules`, `.git` are excluded, so
third-party trees are safe. **Stdlib is not**: `_in_scope('/usr/lib/python3.13/json/decoder.py', ())`
returns `True`. On this box those files are root-owned so the write fails and fails open; on a
user-owned pyenv/conda interpreter it would convert them.

**This is new with this branch.** `_default_roots` and `_in_scope` are unchanged; what changed is that
something now calls `install()` at *every* interpreter startup. A latent property became a live one.

**The argument that this is not a matter of taste** — the same module already takes the opposite
position at its other door:

```
main()      line 473-475   if not roots: print( "no roots to scan — pass directories or set LUPIN_ROOT" ); return 1
install()   line 243       scope = tuple( ... roots if roots is not None else _default_roots() )   # () means EVERYTHING
```

The CLI refuses to scan the world with no roots, and there is a test pinning that
(`test_main_refuses_rather_than_scanning_the_world_with_no_roots`). The startup hook does it instead.

**Suggested fix — in `sitecustomize.py`, not in `install()`.** `install( roots=[] )` meaning
"no restriction" is deliberate and three tests rely on it, so the guard belongs at the auto-install
site: skip the install when `_default_roots()` is empty. An explicit caller can still ask for
unbounded; the thing that runs unasked at every startup cannot. Author's call on the spelling.
