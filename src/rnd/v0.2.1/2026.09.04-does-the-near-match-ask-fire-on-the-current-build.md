## 🔴 This retires a framing, and the framing was load-bearing

Tiffany reported "`near_match_confirmed` fired **ONCE, ever**, against 286 asks that cleared the 90.0
bar." Both halves are true and the join is not: **that single firing IS the single post-landing
opportunity.** The other 285 were scored by a build with no near-match path to send them down.

⇒ The rate is **1 of 1**, not 1 of 286. The feature is not failing to fire; it had one chance and took
it.

## ⚠️ Rick's 84.85 case is here, and it is a DIFFERENT question

The 2026-09-04 record at **84.85** is Rick's case. It is **below the 90.0 bar**, so it never entered
the near-match band at all — it was routed to the agent, correctly, by the threshold.

⇒ **That is a threshold question, not an "ask never fires" question.** This row asked whether the ask
fires and the answer is yes. Whether 90.0 is the right bar is a separate, still-open debate, and
**Rick ratified 90.0** — explicitly out of scope here.

## What this does NOT establish

1. **n = 1.** One success is not a reliability claim. "It fired on its only opportunity" ≠ "it fires
   reliably." Re-check as traffic accrues.
2. **The deploy date is unestablished.** `8bf71a64` is the bulk WIP *merge*, so `-S` gives when the
   change reached this branch — not when it was authored, and **not when it reached the running
   `:7999` container**. A trace record is written by whatever code was actually *running*, so
   **2026-08-29 is a lower bound**. If the deploy was later, even the 98.37 record could in principle
   predate it — though it is dated 09-01, three days after, which makes that unlikely rather than
   impossible.
3. **Nothing about the declined/auto-accepted paths.** `near_match_declined`,
   `near_match_auto_accepted`, `near_match_declined_non_interactive` and `similarity_out_of_range`
   appear **zero** times post-landing — but with one in-band ask that is expected, not evidence. An
   empty population and a broken path print the same zero.

## Method note

The pre/post split, the positive control, and the four-record dump were all computed in one pass over
the corpus, read-only, from a worktree. The corpus is gitignored and lives only in the main checkout —
a worktree has zero trace files, which is the documented gitignored-artifact pattern and would have
produced a confident, empty, wrong answer to every question above.
