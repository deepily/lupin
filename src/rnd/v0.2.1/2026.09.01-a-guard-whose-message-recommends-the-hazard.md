# A guard whose own message recommends the hazard it exists to prevent

**Rio ⚡ and Tiberius 👑 · 2026-09-01 · written at Mr. Radio 🦉's direction, to sit
alongside Krishna 🦚's measurements from the same evening.**

Two of this repo's four hook guards shipped this defect. Neither of us found the other's;
we found our own, about an hour apart, and only recognised it as one shape when the
manager put them side by side. That is the reason it is written as a class.

## The two instances

| sha | guard | what the message told the reader |
|---|---|---|
| `30ba7976` | `stash_guard` | `git checkout <sha> -- <path>` "touches nothing shared, races nothing" — **false** |
| `92445956` | `stash_guard` | Tiberius correcting his own correction: his replacement implied `cp` from your own backup was the safe form |
| `9350649d` | `commit_scope_guard` | "`git commit -F <file>` parses cleanly and gets reviewed" — **true of the flag alone, and incomplete** |

## Why this text is worse than a stale comment

🔴 **A guard's message is read by whoever JUST hit the failure and is hunting for a way
through.** A doc is read once, by someone browsing, in a calm moment. This sentence is
read at the exact instant a seat has been refused and wants a substitute — so wrong
advice there is not merely believed, it is *acted on immediately*.

⇒ Both of ours were **the most load-bearing sentence in the file**, and neither had a
test.

## The two failure modes are different, and one does not imply the other

**Both remedies were perfectly legal commands.** Legality is not the predicate, and this
is the part that took two people to see.

| | the remedy | the defect |
|---|---|---|
| **Rio's** | `git commit -F msg.txt -- <paths> <<'EOF'` | it **does not work** — still unreviewed with the heredoc attached |
| **Tiberius's** | `git checkout <sha> -- <path>` | it **works fine** — the sentence around it was false |

⇒ A remedy can be *readable* and dishonest, or *honest* and unreadable. **Asserting one
says nothing about the other.**

⚠️ Rio's first pattern caught only his own case and he offered it as the shared fix.
Tiberius asked whether it caught his, the answer was **no**, and that question is what
turned one predicate into two. *A helper that fits the case you found is not yet a
helper for the class.*

## The shared check

`src/tests/helpers/guard_remedy.py` (`035cf18a`):

| predicate | asserts | catches |
|---|---|---|
| `remedy_is_readable` | put the recommended command back through **the guard's own parser** | a remedy the guard cannot act on |
| `remedy_carries_its_caveat` | a command naming a hazardous operation carries that hazard's warning **nearby** | a legal command with a false sentence around it |

Measured across both guards, including the cross-check that earns the second predicate:

```
commit_scope_guard, current text              readable OK          · caveats OK
a remedy that does not parse                  readable CAUGHT
stash-shaped text, legal cmd + false line     readable CANNOT SEE  · caveats CAUGHT
the same text with its caveat restored                             · caveats OK
stash_guard's REAL corrected text @ 92445956                       · caveats OK
that same real text with its caveats stripped                      · caveats CAUGHT
```

The third row is the whole argument for two predicates. The last two are a live
cross-check: the helper was written against **Rio's** guard and it passes **Tiberius's**
corrected text while catching its stripped form.

⚠️ **The hazard table is a FLOOR, not a definition.** It lists operations this fleet has
been burned by, with the words that make them honest. It cannot know a hazard nobody has
hit yet, so a green means *"carries the caveats we know to demand"* — never *"this advice
is safe."*

### 🔴 AND THE FIRST CUT OF THE CAVEAT CHECK HAD A FALSE POSITIVE MODE — NAMED, MEASURED, FIXED

Mr. Radio 🦉 read the helper and found it: the caveat search ran over the **whole
message**, so a caveat word occurring *anywhere* passed that row. **A green therefore
said "these words are present somewhere", not "this command is qualified".**

Worse, it was written down as *deliberate* — the docstring argued that a caveat one line
below its command still reaches the reader, which is true and does not license searching
three paragraphs away.

**Measured on a constructed case** whose `git checkout` remedy was entirely unqualified,
with the word *overwrite* appearing well above it about an unrelated queue:

```
caveat three paragraphs away, hazard unqualified   PASSED  -> now CAUGHT
the same hazard, caveat on the NEXT line           passes (correct, unchanged)
stash_guard's REAL text @ 92445956                 passes (correct, no false alarm)
commit_scope_guard's REAL notice                   passes (correct, no false alarm)
```

The fix is a **proximity window** — `window` lines either side of the match, default 2 —
so a caveat on the following line still counts and one across the message does not. Both
real guards still pass, which is what shows the tightening did not buy a false refusal.

⚠️ **A window is a heuristic, not a proof of association.** It can still be fooled by a
caveat that happens to sit near an unrelated hazard. It narrows the false positive; it
does not close it, and the docstring says so rather than letting a green be read as more
than it is.

⇒ **The instrument had the same defect as the thing it measures.** It reported a
property it had not established — which is this evening's other recurring finding, now
arriving inside the tool written to catch it.

## The arm for this class is the REVERT

The defect lives in a sentence, so **put the old sentence back** — do not mutate the
parser. Rio's: revert the notice wording → **2 failed, both new tests, each named**;
restore → **17 passed**.

## What it corrected downstream, which is the reason to read this twice

Tiberius's `92445956` corrects his own `30ba7976`, **and it corrects standing advice Rio
had been giving all evening and had written into a memento**: *"end a mutation arm with
`cp` from your own backup, never `git checkout`."*

🔴 **That is not the safe form.** The `cp` fixes only WHICH BYTES come back; **the write
is identical**, so it still overwrites a peer's edit made since your backup. `git
checkout` restores HEAD and `cp` restores your snapshot — both are a blind write into a
shared working tree.

⇒ **Only a detached worktree of your own closes that window**, which is what
`stash_guard`'s corrected message now says.

⇒ And note the shape of the propagation: a wrong sentence in a guard's message became a
seat's standing habit, then that seat's memento, then its advice to two peers, inside one
evening. **The message is upstream of the doctrine, which is why it is worth a test.**
