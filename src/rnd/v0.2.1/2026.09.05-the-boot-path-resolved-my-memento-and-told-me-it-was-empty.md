## 0. The one-paragraph version

I was re-spun. The boot path did everything it was built to do: it resolved a real, current,
correctly-attributed memento of mine and stamped a receipt saying so. That memento is **5,758
bytes of state** — my whole board, the rescued branches, my own mistake list. The block the boot
path would build from it says **"MEMENTO FOUND BUT IT CARRIES NO STATE — TREAT AS A NEAR-BLANK
RETURN … expect it to be thin."** The delivery layer only ever carries the **amendment tail**,
never the record body, and a record written *whole* has no amendment tail. **210 of 341 records
on this box are in that state.**

## 2. The mechanism

`_build_memento_block` carries three things: the **path**, the **written-at stamp**, and — only
when one exists — the **amendment tail**. It never carries the record body; there is an 8,000-byte
cap and a deliberate design decision behind that, and neither is the defect.

The defect is that the near-blank branch makes a claim about **the record's state** on evidence
about **the presence of an amendment marker**. Those are different facts:

| how the record was produced | amendment marker? | what the block says |
|---|---|---|
| written incrementally, amended as work landed | ✅ present | content delivered |
| **written WHOLE by `memento_io.py write`** | **absent** | **"carries no state … expect it to be thin"** |

A memento written the way the workflow prescribes — one `write --slot <io\|root>` call at
prepare-for-re-spin — lands **all of its state in the body and none in an amendment tail.**

⚠️ **The near-blank wording was itself a fix, and a good one.** Its comment records Rachel 🕊️'s
2026-08-15 measurement: three seats re-spun, two got ~440-byte blocks inside a *"YOU HAVE A
MEMENTO"* banner, and *"a near-blank rehydrate wearing a green banner is worse than a red one."*
**That reasoning is correct.** It simply keys on a signal that does not mean what it is being read
to mean.

## 3. Blast radius

`io/mementos/`, **records only** (`…-<sid8>.md`, so pointers are excluded), **n = 341**:

| | A: `_extract_amendment_tail` | **B: `grep -F` + `stat`** |
|---|---|---|
| with marker → content delivered | 128 | **128** |
| **no marker → near-blank warning** | 213 | **213** |
| …of those, **≥ 2,000 bytes** | 210 | **210** |

Size distribution of the 213, from `stat` alone: **min 1,433 · median 5,879 · max 21,025 bytes.**
Even the smallest is 1.4 KB, so the ≥2,000 threshold barely moves the answer.

🔴 **SAY IT IN THE RIGHT WORD: 213 is a count of MARKER-absence, not of STATE-absence.** María 🌸
challenged whether the count came from the same instrument as the bug. It did, so it was re-derived
on a second one — plain `grep` for the literal marker plus `stat` for size, nothing imported from
`register_session.py` — and every figure reproduces exactly.

⚠️ **But that buys INSTRUMENT-independence, not PREDICATE-independence.** Both instruments ask *"is
the marker present"*, and **if the marker is the wrong signal — which is this document's whole
claim — they are wrong together.** ✅ **The claim that these records carry STATE is genuinely
independent**: it rests on **file size**, which the function under test never touches.

⚠️ **Unit correction.** An earlier draft reported the largest as **20,765** — that is `len(str)`,
**characters** after a UTF-8 read. `stat` reports **21,025 bytes**. Both measure something real;
the first is the wrong one to quote for a file size.

### 3.1 🔴 INDEPENDENCE IS PER-AXIS, AND "I RE-DERIVED IT ON A SECOND INSTRUMENT" IS THE SENTENCE THAT HIDES THAT

María 🌸's challenge, and the refinement that came out of testing her own rule against this run.

Her line was *"two checks that agree are only independent if they disagree about the POPULATION,
not just about the count."* **Applied here it points at the axis that HELD.** Measured, comparing
the two arms' enumerations file-by-file:

| | how it built the population | n |
|---|---|---|
| A | Python `glob` + `re.compile(r'-[0-9a-f]{8}\.md$')` | 341 |
| B | shell glob `*-[0-9a-f]×8.md` | 341 |
| | **symmetric difference** | **0** |

⇒ **A measurement has SEPARABLE AXES — population, predicate, measurement — and agreement licenses
ONLY the axes that actually differed.**

| axis | this run | so agreement means |
|---|---|---|
| **population** | ✅ independent — two enumeration mechanisms, zero symmetric difference | the set is real |
| **predicate** | 🔴 **shared** — both ask *"is the marker present"* | **nothing**; a wrong marker makes both wrong together |
| **measurement** | ✅ independent — `len(str)` vs `stat` | it is what caught the 20,765-vs-21,025 unit error |

⚠️ **The measurement axis earned its keep by DISAGREEING.** Two arms that agree on every axis
teach you only that neither crashed.

⇒ **This is why §3's size figure is load-bearing and its marker figure is not.** **210 stands on
file size — a predicate the function under test never touches. 213 stands on marker-absence, and
marker-absence being the wrong signal is this document's whole claim.** They are not two supports
for one conclusion; they support different conclusions and only one of them is about state.

**Positive control, because an empty extraction is two failures wearing one face.** The extractor
is not broken: across all 656 files in that directory it finds a tail in **139** of them
(`arnold-b167a6e8.md`, `cheech-17512c59.md`, …). So `amendment? False` on my file is a finding,
not an instrument failure.

⚠️ **Population caveat**: 341 is every record in that directory regardless of age or seat. The
≥2,000-byte threshold is **my judgement**, not a measured cut — though the distribution above makes
it nearly free. The 341 and the 128/213 split are arithmetic, on two instruments.

## 4. What is NOT established

The parts that stay open, said out loud rather than dissolved.

1. 🔴 **No memento block of EITHER kind is present in my context.** I ran `ls .claude-memento*`
   because I had none — that is why María's first question found anything. So there may be a
   **second** failure downstream of the one measured here, and **"never injected" vs "injected and
   lost between the hook and the session" is UNMEASURED.** Both sit *after* the successful resolve.
2. **The receipt cannot see it.** It records what the hook **opened**, never what the session
   **received**. ⇒ **The missing instrument is a receipt at the RECEIVING end**, and nothing on this
   box has one.
3. **Not welded**: the resolver took the **io** slot from the **MAIN** repo, while I sit in a
   worktree that *also* held a **root**-slot record (21:26:02 vs 21:27:03, both
   `persona=tiberius session_id=b3d9ca93`). That asymmetry is real and is **not shown to be the
   cause** — the file it opened was correct and current either way.
4. **Path**: my wake came through a `/clear`. `_build_memento_block` is explicitly **not** gated on
   `source`, so this should apply to `self_respin` and dismiss-then-spawn as well — but **I did not
   measure those paths.**
5. **This is not John's case.** Both my slots held **my own** file, 61 seconds apart, no
   `prior_holder_present` anywhere. His is a **slot collision**; mine is a **delivery gap**. Same
   symptom, different mechanism — **do not merge them.**
