## 1. What was measured

**Max concurrent = 12, at 2026-09-04 11:48:03 EDT.**

Method — sweep-line over `[first notification, last notification]` per session:

```sql
SELECT split_part(sender_id,'#',2), min(created_at), max(created_at), max(sender_persona)
FROM notifications
WHERE created_at >= '2026-09-04 00:00-04' AND created_at < '2026-09-05 08:00-04'
  AND sender_id LIKE 'claude.code@%'
  AND split_part(sender_id,'#',2) ~ '^[0-9a-f]{8}$'
GROUP BY 1;
```

**Population**: `lupin_db_dev.notifications`, 31 sessions. The `~ '^[0-9a-f]{8}$'` filter drops
four non-session senders that would otherwise inflate the count — `fallback`,
`context-pressure-tick`, `ctx-tick`, and one empty.

The 12 at the peak: three managers (Tiffany, maria, mr radio) booted 11:07–11:09 and running to
~23:45, plus nine workers spawned 11:34–11:48.

> ⚠️ **NAME THE POPULATION.** The interval is first-to-last **notification**, so a seat that ran
> silently is **undercounted**. **12 is a floor, not a ceiling**, and every occupancy figure below
> inherits that caveat.

⚠️ **The hourly `count(DISTINCT session)` is NOT this number** and reads higher (12–16 all day). It
counts sessions that *overlapped anywhere in the hour*, so a `/clear` — same seat, new id — is
counted twice. It is the wrong instrument for a concurrency question and is recorded here only so
the next reader does not reach for it.

## 3. Cause 2 — the enforcement code is frozen at seat boot

cosa-voice is registered **stdio**, so every seat runs **its own** MCP subprocess, started at seat
boot, importing from the checkout, with **no reload path**.

```
$ ps -eo pid,lstart,args | grep cosa_voice_mcp
9385  Sat Sep  5 09:43:37 2026  .../.venv/bin/python .../src/lupin_mcp/cosa_voice_mcp.py
```

One per seat, started at the seat's own session start. So the three managers that booted at
11:07–11:09 were running **pre-gate code for their whole twelve-hour life**, including every spawn
they made after the 14:13 merge.

🔴 **THE ASYMMETRY IS THE DEFECT.** `6883a349` had already made the cap's **value** survive a stale
process, by re-reading the INI from disk — precisely because `ConfigurationManager` is a
process-lifetime singleton with no reload. The **value** was fresh and the **code** was not.

> A rule that can only reach the fleet by every seat re-booting is not installed. It is announced.

⚠️ **And it is dormant this morning for a reason that is not reassuring.** Tiberius 👑 measured that
every live subprocess today imports post-`23bb0124` code — true, and it is true because the box
goes down ~11pm and **the whole fleet is new each morning**. That is a fact about 10am on a Friday,
not a property of the system. It goes live again the moment anyone merges a policy change at midday
into a fleet that has been up since 9am — which is yesterday's shape exactly.

## 5. The fix

`src/lupin_mcp/fleet_cap_admission.py`, invoked from `src/scripts/start-cc-with-tmux.sh`.

**Why the launcher**: it is a **fresh bash process per launch** that shells out to `python3`. Policy
evaluated there is, by construction, the policy on disk at the moment of the spawn — no bounce, no
re-boot, no dependence on which manager's interpreter asked.

| property | mechanism |
|---|---|
| survives a stale caller | evaluated in the launcher, not the MCP |
| closes the mid-boot race | a launch **reserves** a seat under `flock`; occupancy = live bridges + unmaterialised reservations |
| never double-counts | a reservation is retired when the child's **bridge appears**, not by a timer |
| counts persona-less seats | census uses `require_persona=False` |
| reaps nothing | Rick's 09-03 ruling, unchanged |
| fails open, loudly | only exit 3 refuses; everything else allows and says why on stderr |

**It does not replace the MCP gate and must not.** That one refuses *early*, before a tmux session
exists, and can speak about a batch (*"4 requested, 2 fit"*). This one sees one child at a time and
fires after the caller has committed. Two gates, two jobs: the first is the good error message, the
second is the one that binds.

**The reservation is not over-building.** `list_spawned_sessions` already documents and measures the
window: a healthy child goes `unknown_no_bridge → none → allocated` in about one second. Two
launches inside that window both read the same headroom. The TTL (120s) is **garbage collection for
a launch that died**, never the mechanism of correctness.

### The property that answers the P0

A stale manager's MCP still runs the **old** gate; that gate allows; it shells out to the launcher;
**the launcher refuses**. Verified by reading `session_spawner.py:1038` and `:1090`: a runner
returning non-zero sets `ok = False`, the row is recorded `status: "failed"` **without raising**, and
only `status == "spawned"` rows are appended to the manifest. **No seat is created, no exception, no
manifest row.** Yesterday's exact shape cannot recur through an eleven-hour-old interpreter.

## 6. Verification — a controlled pair, one variable

At the layer the incident entered: the **real launcher**, not the module.

| cap | occupancy | flags | result |
|---|---|---|---|
| **5** | 5 | `--headless` | **exit 1**, refusal on stderr, **no tmux session created** |
| **6** | 5 | `--headless` | **exit 0**, no refusal, reached the `has-session` branch |

**The second arm is not optional.** *"The guard fires"* and *"the guard fires WHEN IT SHOULD"* are
different claims, and a guard that refused everything would satisfy the first. The allow-arm reused
an **existing** tmux session name so it created nothing; the INI was restored and `cmp`-verified
byte-identical against a pre-arm backup.

### The first run found a real defect in my own wiring

Written as a bare call followed by `if [[ $? -eq 3 ]]`, the script exited **3** and that `if`
**never executed** — `set -euo pipefail` had already aborted. The refusal still happened, so the arm
**looked like a pass** while the branch meant to distinguish a refusal from a crash was dead.

⚠️ **And the dead branch was not cosmetic.** Under `set -e` **any** non-zero exit kills the launch, so
an argparse usage error (exit 2) would have refused **every spawn on the box** — turning a guard
designed to fail *open* into one that fails *closed* fleet-wide. Now `|| _fleet_rc=$?`, and only
exit 3 refuses. Pinned by `test_the_guard_invocation_survives_set_e`.

⇒ This is § *A CLEAN EXIT IS NOT EVIDENCE THE WORK HAPPENED* from the other side: the **outcome** was
right for the **wrong reason**, and only reading the exit code caught it.

## 7. What Tiberius's audit changed

- **It killed a design before I built it.** Persona allocation is **fail-soft**: refusing at
  `/allocate` does **not** stop a session — it produces a running, **persona-less** one, invisible to
  the cap's own denominator. I was one step from building that chokepoint. It would have
  *manufactured* more uncountable seats. **Not built.**
- **It bounded the fix.** Every tmux session goes through `start-cc-with-tmux.sh`, and no cron job or
  systemd unit launches one. So the guard covers **every agent spawn**.
- **The one door it does not cover**: a human typing `claude` directly. Deliberately
  **warned, not refused** — a cap that locks the operator out of his own terminal removes the ability
  to undo it. Interactive sessions still **count** toward occupancy, so they squeeze agents out,
  which is the correct direction.
- **Two gates, two denominators.** Each refusal now names its own population inline, because a reader
  holding two refusals with two numbers and no stated population cannot tell a disagreement from a
  bug. ⚠️ **That makes a disagreement legible, not absent.** The real fix is one denominator —
  John's `7c36ad4f`, which flips the gate's census. Not duplicated here on purpose.
