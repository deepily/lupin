# A narrow character class truncates where an anchored one refuses

**Date**: 2026-09-02 · **Author**: Pocholo 📣 (session `aceca488`) · **Origin**: Tiberius 👑
**Commits**: `1136e0a7` · `d743079d` · `eb590633` · `e926ed3b`

## The rule

🔴 **NARROWED BY ITS OWN AUTHOR, 2026-09-02, and the wide form below is kept only to show
what was withdrawn.** The first cut of this doc led with:

> ~~A lowercase-only character class goes blind exactly on the values that carry
> information — a digit, a capital, a delimiter — while matching cleanly on the quiet
> default.~~

**Tiberius 👑 refused that as wider than his experience supports** when asked, during this
run's post-game, whether it was the rule he would put in a doc. His narrower claim, which is
the one to carry:

> Where a field's quiet default is lowercase and its informative values carry shas, digits
> or capitals, a lowercase-only class silently prefers the default. — Tiberius 👑,
> 2026-09-02

⇒ **It is a property of THE FIELD, not of the character class.** And his argument for the
narrowing is this document's own yield, turned against its own headline: **26 anchored
validators correct by design against 1 real extractor** is a result that argues *against*
the wide reading, not for it. A class is not a hazard; a class paired with a field whose
interesting values leave its alphabet is.

⚠️ **The sweep was still the right ACTION** — his words. What was too wide was the sentence
at the top, not the decision to go looking.

**This is the post-game's cheapest mechanism working exactly as specified**
(`workflow/post-game.md` §3.3 ①: cross-examine the source before graduating any rule —
FREE, and load-bearing). It cost one question and it caught an overclaim **in a doc that was
already committed**, from the only person who could refute it.

## How it was found

Tiberius read a field off a real 21,666-test unit tier with:

```bash
grep -o 'run-span=[a-z-]*'
```

and got an empty value, which he reported — correctly, on what he could see — as the
tree-state module failing silently. The field was present. The class stopped at the `0` of
`0768a8b2`.

| case | `[a-z-]*` | `[^ ]*` |
|---|---|---|
| tree moved | `run-span=` | `run-span=0768a8b2..ec0bf947` |
| tree still | `run-span=unmoved` | `run-span=unmoved` |

**The asymmetry is the whole hazard.** Three of the four values `run-span` can take are
lowercase words; the fourth is `<sha>..<sha>`. A pattern written and checked while the tree
is still reads `unmoved` perfectly and forever, then goes blind at precisely the moment the
field has something to report. Documented at `_run_span`'s docstring in
`src/cosa/utils/tree_state.py` (`1136e0a7`) — where the value space is *defined*, so a
reader writing a parse meets it.

## The distinction that decides whether you have a defect

> A regex that **can** drop a key and one that **did** are different findings. Only the
> latter has a victim. — Tiberius 👑

Applied to every candidate below as a **did-drop test**: run the narrow and wide classes
over the *real* corpus and diff the sets. A `can` gets fixed and labelled latent; a `did`
gets fixed and gets its consequence measured.

## The sweep

**Ship the command, not the number** — a population is a measurement and needs re-deriving:

```bash
git grep -n -E '\[a-z[^]]*\]\s*\*|\[a-z[^]]*\]\+' -- 'src/*.py' 'src/*.sh' 'src/*.ts'
```

⚠️ **Tracked files only.** `git grep` cannot see untracked ones, so that is the population
this covers and no other. Positive control at the time of writing: 44 files contain `[a-z`,
so a zero from this search would have meant something.

⚠️ **The count moves.** 45 lines when first run, **47** an hour later — my own commits added
comment lines *about* the pattern. Re-derive; do not quote.

### Classify by SHAPE, never by name

| shape | behaviour on an out-of-class value | hazard |
|---|---|---|
| **anchored validator** `^[a-z_]+$` | **REJECTS**, loudly | none — this is correct by design |
| **unanchored extractor** `findall` / `search` / `grep -o` | **TRUNCATES**, silently | the whole problem |

Of 47: **26 anchored**, 10 extractor-shaped (2 of those being this work's own comments).

🔴 **My first pass filtered candidates by TEXT** — excluding lines mentioning
`slug|kebab|lower|ident|persona|snake|email|hex|uuid`. That is name-based narrowing, the
exact move that hides cases, and **it hid 6 of 45 unexamined — one of them an instance.**
No keyword tells you which shape you have. Only the shape does.

## The one that had a victim

`_SUITE_SCRIPT_RE` matched `"[a-z_]+"` for a SUITE_SCRIPTS **key**. The literal holds `e2e`
and `v2_eval`.

```
.sh entries in the literal        13
returned by read_suite_scripts    11   ← e2e, v2_eval dropped for a digit
```

**Consequence, measured by flipping only the character class:**

```
find_gate_targets             11 -> 12   recovers src/scripts/v2_eval.py
find_unreferenced_test_files  50 -> 50   no test file's verdict moved
```

⚠️ **The two keys behaved differently and my first note gave them one sentence.**
`find_gate_targets` follows `.sh` references, and `run-all-tests.sh` names the e2e runner at
its line 94 — so `src/tests/e2e_ui` returned to the target set by a second route. **Nothing
names `run-v2-eval.sh`**; that one was not masked at all. I had measured `e2e` and *reasoned*
about `v2_eval`. Corrected in `eb590633`.

⇒ **The target population really was short by one; the census verdict was not affected**,
because the recovered path is a script and reachability verdicts are about test files. Both
halves belong in the record — "latent" and "actively wrong" are different claims and the
only way to tell which you have is to run it both ways.

## The repair that mattered was the FIXTURE

Every key in the synthetic tree `test_gate_reachability_census.py` builds was lowercase —
`unit`, `all`, `gone` — so a narrow key class and a correct one produced **byte-identical
output**. The assertions were right and unfalsifiable.

Two changes, and the second is the durable one:

1. the synthetic literal now carries an `e2e` key;
2. `test_every_shell_entry_of_the_real_literal_is_extracted` counts the **real** literal and
   asserts the extracted set equals it — **it cannot go blind on a fixture, because the
   fixture is what went blind.**

Red arm: reverting only the class reddens both and nothing else (2 failed, 31 passed).

## The other rule this run produced — from Rio ⚡, and it is cheaper than mine

Asked in the post-game what made the overclaim easy for him to see and hard for me to see in
my own work, he gave a mechanical answer rather than a temperamental one:

> `same-tree` is a RELATIONAL word. *Same*, *matched*, *consistent* — each requires two
> operands. I asked what the second one was; you read it as a check with a name.

⇒ **A relational word in a verdict declares an arity. Count the operands you actually had.**
`same-tree` off one located module is a two-operand word over a one-operand measurement — and
so is `coherent but NOT $LUPIN_ROOT`, which is why the same fix had to be made twice in the
same field (`39df9f9a`). It costs one question, needs no tooling, and is checkable by reading
the verdict string alone.

⚠️ **This is the same defect as the narrow character class, one level up.** Both are a
DESCRIPTION that promises more than the MEASUREMENT delivers: the class promises to match a
field whose alphabet is wider than it admits; the relational word promises a comparison the
sample cannot support. Neither is caught by re-reading the code, and both are caught by
asking what the words commit you to.

## What to carry forward

- **Anchored validator vs unanchored extractor is the only classification that matters.**
  One rejects loudly; the other truncates silently.
- **Ask did-drop, not can-drop**, and measure it over the real corpus.
- **A probe returning `0 = 0` is not a result** until a positive control says the search
  could have found something.
- **Never filter a sweep by keyword.** It hides the cases whose names sound benign.
- **A population is a measurement.** Ship the command; the count moved by two inside an hour.
- **A relational word declares an arity** — *same*, *matched*, *consistent*. Count the
  operands you actually had before using one (Rio ⚡).
- **Cross-examine the source before graduating a rule.** It is free, and here it caught an
  overclaim in this very document after it was committed.
