## WHY THIS EXISTS

The gate script **had only ever been seen to pass.** Every run since it was written
came back green, which is exactly the evidence a gate cannot supply about itself: a
script that checks nothing and a script that checks a clean tree print the same thing
and exit the same way.

This is the arm that was designed in the session that wrote the script and never run
before the seat cleared.

⇒ **An assertion nobody has watched fail is a comment with a semicolon.** The same
applies to a gate.

## WHAT THIS ESTABLISHES, AND WHAT IT DOES NOT

✅ The gate **reddens on a real type error**, exits **1**, and reports the failure in
the summary shape it claims to.

✅ It **discriminates rather than merely reddening.** A script that turned all three
projects red on a single-file error would satisfy a naive "does it fail?" check and
fails this one. The single-project attribution is what makes the arm worth running.

🔴 It says **nothing** about whether the gate is wired into anything. It is deliberately
wired into nothing — see below.

🔴 It is **one** error shape (TS2322) in **one** project. It does not establish behaviour
on a syntax error, a missing tsconfig at runtime, or a `tsc` that dies partway.

## ⚠️ READ `Failed: 1` AS ONE PROJECT, NOT ONE TYPE ERROR

The script's own comment says the three "tests" are the three **projects**. Here both
readings happen to give 1 — one project red, holding one error — which is precisely how
a count whose unit is unstated gets quoted later as something it never measured.
