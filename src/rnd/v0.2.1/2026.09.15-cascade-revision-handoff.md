## §6 — Workflow-guidance candidates

**Required section.** Five candidates, each with what was measured. These belong in a `planning-is-prompting` redline, not here.

1. 🔴 **The store refuses to mint the cascade's own mandated ledger.** The workflow mandates a step-tier and section-tier ledger; the store will not accept `in_progress` at create, and a create may name a live status only for a P0. Every ledger row a Manager mints at P1 lands in the holding area. **The workflow mandates an artifact the store forbids the mandated author to create.** This cascade's ledger rode on row amendments instead — which is why §2's grid has three empty cells. *The gap produced a measurable loss of telemetry, not just friction.*

2. 🔴 **Nothing in the flow required a second pair of eyes on a plan.** The review gate exists for code. The author wrote a build plan, merged it unreviewed, and only learned it was unreviewed when the operator asked. The whole cascade is the remedy for one missing gate. Candidate: an author-merged planning document is subject to the same pre-merge review as code, or Stage 0 becomes a checkable precondition rather than a rubric nobody is obliged to run.

3. **A summary is not a source.** Both of this cascade's two largest findings — 80 missing behaviours and three dropped ordering edges — trace to one habit: generating a derived document from an upstream document's *roll-up* instead of its body. Candidate: when a plan derives from an inventory, it cites the inventory's atomic blocks, and a mechanical regeneration is the check. Human-shaped review found symptoms for three stages; the regeneration found the cause in one pass.

4. **A number written before its tally exists will be inherited as measured.** "48 findings" sat in a merged plan, sourced to nothing, and would have propagated into this document had it not been checked against the ledger. Candidate: a count in a summary carries its source, or it is written as an estimate and marked.

5. **Raw control bytes make a document invisible to `grep` while `git` still reads it as text.** The spec carried five NUL bytes, the first at byte 9461; git's binary heuristic stops at 8 KB, so the file diffed and reviewed normally, while `grep` classified it as binary and returned **zero hits for every term in it**, silently, exit 1. A reviewer grepping this spec would have measured "not present" for content that is present — and a Stage 2 brief had explicitly warned reviewers against exactly that inference. Candidate: documents escape control characters; and any "zero hits" result is confirmed against a positive control on the same file before it becomes a finding.
