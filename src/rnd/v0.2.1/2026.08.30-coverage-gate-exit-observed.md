| arm | exit | what the gate printed |

## Why this was worth doing at all

Before it, the exit was **evidenced from two directions and watched from none**:

- Tiberius's revert control — the case and live-declaration tests fail with the walk fix
  reverted, while the control and omit tests keep passing.
- My live-tree census — `undeclared` moves `[]` → `['src/cosa/2026.09.01-new-prototype.py']`.

Both are strong. Neither is a process returning a non-zero status. The distinction matters here
more than usual, because **this entire epic has been about instruments that answer a question
nobody asked** — and "the branch is covered by a test" is itself a claim an instrument makes.

The alternative was two full tier runs. Priced honestly: **one exit code, at the cost of taking
the box off four peers**, on a machine where the contention guard had already refused both arms
every minute from 16:16. Mr. Radio ruled no, and asked for a targeted control or an explicit
"unobserved" record. This is the control.

## What the fixture is, and what it therefore proves

Located at `projects/scratchpad/d5818089/gate-fixture` — a per-session subdirectory of the
**registered** scratch project.

**Real**: `run-coverage-gate.sh`, `check-floor-not-lowered.sh`, `tier-measured.sh`,
`resolve-venv-pytest.sh`, and `cosa/utils/coverage_frame.py` — all verbatim copies from the
worktree at `1d7f4846`.

**Synthetic**: the frame only — two source entries (`src/mini`, `src/cosa/rnd`), one covered
file, `fail_under = 0`.

⇒ **It observes the gate's exit path over a synthetic frame. It says nothing about the real
repository's frame**, and must not be read as a coverage verdict on anything.

`fail_under = 0` is deliberate: it takes the floor out of the experiment entirely, so the only
thing that can move the exit code is the frame check. Both arms print `floor_exit=0`.

**No tiers were run.** Without `--run-tiers` the gate reads an existing `COVERAGE_FILE`; the
fixture's was produced by one `coverage run` over a two-statement module, about a second.

## The first control failed, and that is a result

The fixture's **first** control arm exited **1**, and it was not a bug in the gate — it was
Tiberius's newest guard firing exactly as designed:

```
DECLARED UNSEEABLE BUT NEVER REACHED — these KNOWN_UNSEEABLE entries name
paths this census did not find, so each is a receipt for a check that did
not happen.
    src/cosa/rnd/2026.05.21-git-loc-delta-plot-prototype.py
```

`KNOWN_UNSEEABLE` names a real-repository path that a two-directory mini frame cannot reach, so
the declaration was a receipt for a check that never ran. **The fixture was reshaped to make
that path reachable — the guard was not suppressed.** So the control that passes is one where
the declaration check is *live*, not switched off. A fixture built by silencing the guard would
have proved the opposite of what it claimed.

## Notes for whoever runs it next

- **Drive it from your worktree, never with the fixture as your cwd.** It has its own `.git`,
  so from inside it the nearest `.git` ancestor is `gate-fixture` — a name no credentials
  section knows. A shell script running against it is fine; a session or any MCP-calling
  process standing in it is not.
- **The own-`.git` is a requirement, not a convenience**: `check-floor-not-lowered.sh` resolves
  `git show HEAD:pyproject.toml` from the **repo root**. Under the enclosing scratchpad repo it
  would look for a pyproject at *that* root, find none, and refuse `exit 2 CANNOT TELL`. The
  only alternative is a `pyproject.toml` at the scratchpad root, which would change a shared
  repo for every other session.
- The fixture is disposable and age-swept. Rebuild it rather than trusting one left lying
  around: a fixture is an instrument, and an instrument nobody re-derived is a rumour.
