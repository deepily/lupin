## 🔴 The one file, and a mechanism I got wrong before I got it right

**`src/cosa/rnd/2026.05.21-git-loc-delta-plot-prototype.py`** — tracked, 6,466 bytes, on disk, sitting
under the `src/cosa` source prefix, matched by no `omit` pattern, and **not in coverage's frame.**

**My first mechanism was WRONG and a one-variable arm killed it.** I saw that `src/cosa/rnd/` has no
`__init__.py`, read coverage's *"To be importable, the files have to be in a directory with a
`__init__.py`"*, and concluded that was the cause. The discriminating arm — add `src/cosa/rnd` as its
**own** `source` entry, change nothing else — predicts the file appears, because that same docstring
exempts the walk root. **It did not appear. Frame stayed at 724, delta empty.** The mechanism was dead.

**The real cause is the next clause down**, `coverage/files.py:579`:

```python
if re.match(r"^[^.#~!$@%^&*()+=,]+\.pyw?$", filename):
```

The character class **excludes a dot**, so any filename with a dot in its *stem* is skipped as
*"strange characters … probably editor junk"*. Proven with a controlled pair whose only variable is one
character:

| filename | |
|---|---|
| `2026.05.21-git-loc-delta-plot-prototype.py` | 🔴 **SKIPPED** |
| `2026-05-21-git-loc-delta-plot-prototype.py` | ✅ accepted |
| `git_loc_delta_plot_prototype.py` | ✅ accepted |

⇒ **It is the DOTS, not the package check.** Had I published the first mechanism it would have sent the
next reader to add `__init__.py` files that fix nothing — § *A WRONG MECHANISM SENDS THE NEXT READER AT
INNOCENT CODE*, and the arm is the only reason it did not.
