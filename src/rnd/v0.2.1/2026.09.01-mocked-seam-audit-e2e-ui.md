**Trigger**: `GET /api/tasks/flow-ratio` answered 422 in production for its entire life. Three tests

## The instrument, and its positive control

Playwright glob matching was **measured**, not read off the pattern, using the exact function
`page.route` calls — `playwright._impl._helper.url_matches`, playwright **1.58.0**:

```
"**/api/tasks*"   vs /api/tasks/flow-ratio    -> False
"**/api/tasks*"   vs /api/tasks?status=open   -> True     <- positive control
"**/api/tasks/*"  vs /api/tasks/flow-ratio    -> True     <- positive control
"**/api/tasks/*"  vs /api/tasks/events        -> True
"**/api/tasks?*"  vs /api/tasks/flow-ratio    -> False
```

`*` compiles to `[^/]*`, so a trailing star **stops at the slash**. The probe returns positives on
the same corpus, so every `False` above is a measurement rather than a broken extractor.

Precedence was read from the source, not assumed: `_page.py:676` does `self._routes.insert( 0, ... )`
— **the last-registered handler is checked first.**

## Finding 1 — the repair landed tonight is a dead branch built on a false premise (LIVE)

`src/tests/e2e_ui/test_task_list_card.py` carried:

> ⚠️ THE GLOB `**/api/tasks*` ALSO MATCHES /api/tasks/flow-ratio.

**It does not.** The flow-ratio body was placed behind an `if` *inside* the `**/api/tasks*` handler,
where nothing could reach it. The seed never applied, so the two header tests were sending fixture
numbers (`0.77`, an em dash) at a **live board**.

**Fixed**: a second `page.route` on the literal path, registered **last** so it wins. Re-measured —
the two globs are now disjoint, each matching only its own target.

> This is the audit's own lesson landing on the audit's own subject: the first attempt to close the
> flow-ratio hole reproduced its shape one layer up. The claim was plausible, written in good faith,
> and wrong — and nothing in a green run would have said so, because the tests had not been run yet.

## Finding 2 — `**/api/tasks/*` swallows both literal siblings (LATENT)

`src/tests/e2e_ui/test_multiplexer_task_editing.py`'s `TASKS_PATCH_ROUTE` cannot distinguish a task
id from a literal sibling route. An unguarded `_record_patch` would answer `GET /api/tasks/flow-ratio`
with `{"ok": true}` **200** *and* push it into `recorded["patch"]` — faking a live endpoint and
corrupting a wire assertion in one move.

**Latent today, verified with a positive control**: the multiplexer fetches neither path.
`git grep flow-ratio -- src/lupin_app/static/js/multiplexer/` is empty, against **5** `api/tasks`
hits in the same corpus.

**Hardened**: the handler now **refuses** a literal sibling with a 501 naming the path, per
CLAUDE.md — a step that cannot do the job declines and says what it did not do, rather than
returning something the caller reads as success.

## Finding 3 — every other mock is endpoint-as-fixture, and says so

The remaining 17 files stub an endpoint to drive a **renderer** deterministically. Their docstrings
are honest about it ("the endpoint is STUBBED via `page.route` so each render state is driven
deterministically"). The subject is the render path; the endpoint is data supply. **Legitimate — but
it does mean no E2E covers those endpoints' own reachability.** `**/api/notify**`,
`**/api/jobs/**`, `**/api/epic-stories*` and the rest were each measured against the literal
siblings above and swallow none of them.

## The one real end-to-end check

`TestTaskListHeaderFlowRatioLive` in `src/tests/e2e_ui/test_task_list_card.py` — **no route mock**.

The client hides this failure **by design**: `fetchFlowRatio` returns `null` on any non-2xx and
`_renderFlowRatio` writes an empty string, so a broken endpoint and a quiet board render
identically. Nothing short of the real wire can separate them.

1. **`test_the_app_s_own_fetch_of_the_real_flow_ratio_answers_200`** — watches the **app's own**
   request on the wire. Asserts a request was issued at all (an absent one fails loudly rather than
   passing vacuously), then that every response is 200. **A 401 is called out separately**, so an
   auth failure cannot masquerade as the 422 routing defect — the trap that made Mr. Radio's first
   guard read the auth layer and report on the route table.
2. **`test_the_real_payload_reaches_the_rendered_header`** — asserts the live payload's
   `window_hours` reaches the DOM. It checks the **window and the shape, never the digits**: the
   ratio is live state and moves while the suite runs, so an exact number would be flaky for a
   reason unrelated to the defect.

### Two arms at one sha

| arm | change | result |
|---|---|---|
| **broken** | `/tasks/flow-ratio` registration physically moved **below** `/tasks/{task_id}`; caches purged | **422 Unprocessable Entity** through the real ASGI stack |
| **restored** | `cp` from backup — **not** `git checkout`, which would have destroyed uncommitted work in the same tree | empty `git diff`, **16 passed** |

The broken arm establishes that `status == 200` discriminates. Under the reverted order the app's
own fetch observes 422 and the guard reddens naming exactly that.

## What the browser leg actually found — a REAL stale deploy, first run

The two live tests were scheduled on verified-idle `:8000` as `ts-186f09f9`. **They failed, with
exactly the assertion they were built to make:**

```
AssertionError: expected every /api/tasks/flow-ratio response to be 200, got [422].
422 is the registration-order defect: the literal path parked below
/api/tasks/{task_id} and was swallowed by it.
```

**This was not a synthetic mutation. The endpoint really was answering 422 on the test venue.**
Measured on both venues at 17:56 EDT, through each server's own HTTP surface:

| venue | `GET /api/tasks/flow-ratio` | container started | fix commit `8eca08f7` |
|---|---|---|---|
| `:7999` dev | **200** `{created:5, closed:20, ratio:0.25}` | 17:27 EDT | 17:44 EDT |
| `:8000` test | **422** `"task reference 'flow-ratio' is neither a UUID nor a hex id prefix"` | **10:34 EDT** | 17:44 EDT |

The container's **on-disk** file was already correct — bind-mounted, `flow-ratio` at line 1820 above
`{task_id}` at 1909. The **running process** was not: it imported the module at 10:34, seven hours
before the fix, and `uvicorn --reload` is off. **A saved file is not a served file** (CLAUDE.md,
2026-08-01). Bouncing the idle `:8000` moved the endpoint to 200.

⇒ The guard's first real run caught a genuine defect nobody was looking for.

**Both browser arms are now measured**, same sha, same four selected tests, the only variable being
which build `:8000` had loaded:

| job | build on `:8000` | result |
|---|---|---|
| `ts-186f09f9` | started 10:34, pre-fix | **2 passed, 2 failed** — both live tests red, `got [422]` |
| `ts-9cfdbb82` | bounced 17:57, post-fix | **4 passed, 0 failed** |

⚠️ **The two that passed in BOTH runs are the mocked pair**, `TestTaskListHeaderFlowRatio`. They were
green while the endpoint they are named for was answering 422 three feet away. **That is the finding
of this whole audit in one line**, and it is why the live class had to exist rather than the mocked
one being tightened.

⚠️ **And the green arm exercises the em-dash branch, not the numeric one** — the test DB has no rows
in the window, so the live payload is `ratio: null`. That is the harder of the two render paths and
the reason the assertion accepts `—` *or* a 2dp number rather than demanding digits.

## What this does not establish

- The live pair is proven to discriminate on THIS defect (route registration order). It is not a
  general guard on the endpoint's correctness: it checks status, the window, and the render shape,
  never the counts.
- The refusal branch added in Finding 2 is **unreachable today** by construction. It is a guard
  against a future fetch, not a currently-exercised path — stated plainly here because an
  unreachable branch nobody flags is precisely Finding 1.
- ~~The sweep covers `src/tests/e2e_ui/` only.~~ **CLOSED 2026-09-01, same session.** The rest of
  the tree was swept too: `git grep -ln "page.route\|route.fulfill"` outside `e2e_ui` returns three
  real files (the rest are markdown), against a positive control of the same search inside `e2e_ui`
  returning the known 19. **None of the three fakes its own subject:**

  | file | mocks | subject | verdict |
  |---|---|---|---|
  | `parity_oracle/ab_visual_report.py` | senders-visible, conversation-by-date | render parity | fixture — fine |
  | `parity_oracle/test_golden_capture.py` | same two | golden capture | fixture — fine |
  | `smoke/multiplexer_auth.py` | senders-visible, job-history | **auth** | fine, and it is the model |

  `multiplexer_auth.py` is worth naming as the pattern to copy rather than merely clearing: it mocks
  the two hydration calls that would otherwise add noise and drives its ACTUAL subject — auth — for
  real. Mocking the neighbours to isolate the subject is the opposite of mocking the subject, even
  though both read as "this test uses page.route".
