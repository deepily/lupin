Not cascade output. Project rules an implementer must already be operating under, listed because §7.2 staffs
three surfaces and two of them sit under rules that differ from the third.

   `projects/lupin-mobile/`, not under `lupin/src/`, it has its own git history and its own merge gate, and
   **it is never committed from the Lupin context**. §7.2 staffs Tiffany on §5; that work lands in a
   different repository from §1–§4's. This is the most consequential single line in this document for
   whoever picks up mobile.
2. **The 100% coverage mandate's scope is SPLIT three ways, and applying one rule uniformly gets it wrong in
   two directions.** Active for §1–§4 — 100% lines, branches and functions, `pytest --cov
   --cov-fail-under=100` for Python and `c8 --100` for TS. **`lupin-mobile` is excluded from the Lupin-wide
   mandate by name.** And **`notifications.js` is a named exclusion inside the active zone**, for the
   measured reason in B4.10b: it cannot be c8-instrumented at all.
3. **`:8000` is submit-only**, via `POST /api/test-suite/submit` — never an ad-hoc curl, a direct queue push
   or an in-process instantiation, because a side door collides with scheduled runs and poisons both. Every
   E2E row in every section depends on this, including C5.20. A verified-idle `:8000` is
   bounce-then-schedule self-authorized; the only user gate is killing a live in-flight job.
4. **Never auto-commit and never push.** Push stays gated on the user's direct word. The plan and this
   document are both **untracked and uncommitted** by instruction.
5. **The merge pyramid is ordered and typecheck is gate #1** — ~3s of static analysis ahead of a ~25min TS
   tier, so a type-red branch fails cheaply. Integration is the final gate. Full order is in the project
   guide; B4.12 leans on typecheck being first.

**The four revisions that changed the design rather than the wording:**

1. 🔴 **A `/clear` swaps the transcript path; it never shrinks the file** (P1). The plan's only epoch
   detector was a shrink check inherited from `events_tail.tail_session_file`. Measured on a live bridge:
   `register_session.py` runs at every SessionStart, `/clear` fires SessionStart, and the hook rewrites the
   bridge with a **new** `transcript_path` while preserving `stable_session_id`. So the old file stops
   growing and a different file appears elsewhere — a shrink-only tailer sits on the dead file forever and
   **the pane silently freezes at every clear**, the exact failure `file_epoch` was added to prevent. The
   tailer now re-resolves the bridge each poll and treats a changed path as the primary signal, with shrink
   demoted to secondary for genuine truncation. **A2.3 has two arms, and a shrink-only tailer must fail
   arm (a).**
2. **The roster endpoint the plan said did not exist, existed — and then the wrong one was chosen** (T1,
   then Pocholo). §3 originally asserted "No roster endpoint. Nothing lists the live seats a viewer could
   watch." Three prior arts existed. The projection first targeted `/arbiter/fleet-snapshot`; that is
   **superseded by `/arbiter/fleet-state`**, which says so in its own endpoint description and which all
   three clients already poll. Two things found in verification that neither reviewer raised: fleet-state
   is gated `require_api_key_or_jwt` — **authenticated but not admin**, so the projection carries its own
   `require_admin` or ruling Q5 is widened by accident (A3.4); and it answers `{status: "unreachable"}` as
   **HTTP 200** when `:8001` is down, so the roster must tell "no live seats" from "the arbiter is down"
   (A3.7).
3. **The block mapper was specified for about a third of the records** (P2). Census of 8,115 records across
   four recent transcripts: `user` + `assistant` are 34%, across thirteen record types, and the type set is
   **not closed**. The mapper now skips unrecognised types **by default rather than by enumeration**, takes
   `kind` from the content block's type and never the record's role — 760 of 1,026 `user` records carry
   tool_results, which a role-based mapping would render as fake human turns — and handles
   `message.content` as both a bare string and a list.
4. **The watcher registry had no home and no teardown** (P3). It now lives on `WebSocketManager` beside the
   five per-session maps `disconnect()` already sweeps, as an explicit **sixth** entry. Without it a closed
   tab never unwatches, the tailer polls forever, and `emit_to_session` early-returns into a dead session —
   no error anywhere. **A2.5 gained a socket-drop arm; omitting the sweep must redden it while the unwatch
   arm stays green**, which is how the leak would have shipped.

**Also folded:** the `/ws/queue` receive loop handles exactly two verbs and `update_subscriptions` cannot
absorb a third (F1, T2); the server must honour `from_offset` or the gap between REST and watch is silent
(F3); `file_epoch` on every frame, nullable on watch, with a **stale non-null epoch refused via
`epoch_mismatch` rather than silently rebased** (F2, T15); per-block budget with `truncated: true`, adopting
`tasks.py`'s existing `budget == 0 means unbounded` semantic rather than inventing a `cap` that reads the
opposite way (F5, T7); the carrier named as `emit_to_session`, which applies **no** subscription filter, so
the watcher set is deliberately the only place a frame can be dropped (T2); the four event names into
`websocket available events`, because a name absent there validates away **while auth reports success**
(T3); reuse roles split — `tail_session_file` for offsets, `iter_tool_uses` as the walk *shape* only since
it yields tool_uses alone, `read_transcript` excluded as offsetless (T4); Q6's backlog gaining `tail_bytes`
and `before_offset`, because a forward-only read returns the **first** 64 KB when Q6 wants the last (P4);
the ring byte-bounded, since `FleetEventAccumulator` is 50 **records** and a record ring cannot answer a
byte-offset question (T6 as corrected by P7); `ended` given a producer in the `SessionEnd` hook (P6); id
width pinned to the full `stable_session_id` with the roster **normalising** rather than assuming, because
the snapshot matches "prefix-tolerantly" (Tiffany, P5); the four documentation artifacts made Phase 0
(T13); and every citation anchored on symbols rather than line numbers (T14).

**Stage 3 reopened two Stage-2 closures — the one round this cascade used.** María's Stage-2 record closed
P1 and P3 as `revised` on a check of the prose; the acceptance-table halves had not landed. Clayton found
both. Her own correction is on the record, and it names the mechanism better than I could: *"My verification
was of the wrong artifact."* Five of Clayton's ten findings were that same shape. **This is the most
transferable thing the cascade produced** — see §6.

**Clayton's Stage 3 additions:** positive arms on both admin criteria, because a refusal-only assertion is
satisfiable by a gate that refuses everyone (A3); a coverage obligation naming the new Python modules at
100%, with fact- and doc-checks excluded **by name** rather than silently (A4); tier and venue headers on

- **Clayton B3 asked for the legacy client to be held "under the same coverage gate". That gate physically
  cannot measure it.** Every test under `src/tests/unit/notifications_js/` loads `notifications.js` by
  slicing its source string through `vm.runInThisContext`, which is outside c8's require/import graph, so
  **c8 reports an ad-hoc 0/0 even when the file is forced into `--include`** — measured 2026-08-03 and
  recorded in `run-typescript-tests.sh`, which also notes the file is in no tsconfig and never enters that
  gate's denominator. A plan instructing someone to c8 it would have sent them chasing a 0/0 and calling it
  covered. **B4.10b is therefore a named exclusion with its reason and its real gate** — the behavioural
  tests in that directory plus the E2E arms B4.7/B4.8 — which is the shape the existing note says was
  wanted: *the defect was the silence, not the uncovered lines.* Ratified by Mr. Radio, who checked both
  the census test and the exemption note himself.
  - **A count disagreement inside this finding resolved cleanly, and the resolution is itself the lesson.** My
    measurement said 46 files, Clayton's gate said 45. **Neither was wrong — we measured different trees**:
    his worktree at `0783051fa` has 45, main at `ba0a9b4e9` has 46, and the single file between them is
    `tts_silent_when_the_slider_is_at_zero.test.ts`, which landed on main *after* his worktree's base commit.
    Five predicates agree within each tree. ⇒ **The figure is 46 on main at `ba0a9b4e9`**, written with its

    carries a timestamp whether you write one or not.
- **Clayton B1's parity remedy needed its fixture named, not just its form.** He was right that B4.11 held
  thirteen multiplexer behaviours with a hand list of two twins, and right that the remedy is the
  predicate-derived census of
  `src/tests/unit/notifications_js/both_clients_issue_the_same_request_for_every_control.test.ts`, whose
  header states the principle: *"a hand list is right about everything its author thought of and silently
  wrong about the rest."* But that file teaches a second lesson its own header records — **the fixture is
  the whole measurement.** Asserting a URL with the id `t1` made an encoded and an unencoded client
  byte-identical, so the test measured nothing in either direction. The console's equivalent trap is **id
  width**: with one seat in the fixture roster, a client resolving by full `stable_session_id` and one
  matching on the chip's 8-hex prefix return the same answer. **B4.4c therefore requires a fixture roster
  holding two seats that share their first 8 characters**, or the test cannot discriminate.

**Pocholo's Q1 forced an explicit design choice.** §4 had stated two incompatible designs in one paragraph.
**Design (b) was chosen and ratified**: the console is a separate `paneContent` axis, **not** a third
`ContentPaneEntry` type. Three things decided it — the entry union is closed with a string payload and a
live console has no payload; `handleBustOut()` is an `if/else` with **no default arm**, so a third type
falls into the abstract branch and would render the seat id as markdown into a new window; and the history
stack is depth-capped at 10 with `back()` popping, so a stack could hold several consoles, silently breaking
"one console per tab" **while B4.4 stayed green**, since it asserted only the seat-switch path. All four
exits are now named in a table, and **bust-out is disabled for the console in v1, explicitly.**

⚠️ **One ratified decision was superseded by a later finding, with the owner's agreement.** Tiberius's B9
had Mr. Radio's ratification to persist `paneContent` via `ReadingPaneStore`'s envelope, and separately not
to persist the watched seat. Pocholo's Q5 showed **those two halves do not compose**: persisting the axis
without the seat restores a console with nothing in it. `paneContent` is now **not persisted**, a reload
returns the pane to the reading view, and Mr. Radio ratified the reversal.

**Also folded:** the auth gate is the `auth_success` **EventBus** event, not the transport's `authReady`,
which is `protected` and unreachable from a store (B5); two render paths, markdown for prose and plain text
for tool content, because the hazard is **mangling and not injection** (B6); the five-edit boot checklist,

## §6 Workflow-guidance candidates

Five candidates, in the order I would rank them. The first is the one I would push hardest.

⚠️ **These five are the SEED for the post-game, not the post-game itself.** That is a separate artifact under
a separate `doc_kind`, and deposits for it are already accumulating on commons topic `post-game` — this
document is `doc_kind: review`, the cascade's review record. The label matters because
one-document-per-initiative-per-kind means a later retrospective filed as `post-game` would otherwise have to
append to this file rather than stand on its own.

1. 🔴 **"Verify the closure against the artifact the finding names, not the prose."** Section A's single
   round happened because two Stage-2 closures were checked by reading the narrative while the acceptance
   halves never landed — and **both missing halves guarded the primary mechanism of their finding**, so the
   closure record read complete while the defect stayed unwatched. María's own phrasing is the rule:
   *verification of the wrong artifact.* Five of Clayton's ten section-A findings were this shape. Candidate
   rule: **a finding that names an acceptance criterion is closed only when that criterion is re-read**, and
   the manager's check is the table, not the paragraph.
   - 🔴 **AND IT HAS A CONTROL GROUP, which is what lifts it above an anecdote.** Sections B and C were
     reviewed *after* María began checking acceptance tables rather than prose, and Clayton traced **every**
     upstream fix in both to a row: **11 of 11 in B, 7 of 7 in C, zero prose-only closures.** Same author
     pool, same rubric, same reviewer, three sections — a measured before-and-after in which the intervention
     cleared the defect completely, not a lesson drawn from a single failure.
   - **Plus the cheap mechanism, or the rule depends on remembering**: when a finding requires an
     acceptance-criterion change, **the re-litigation DM should carry the replacement row text**, so folding
     it is a paste rather than a second act of authorship. That is the difference between a rule and a tool
     that refuses.
2. 🔴 **An acceptance criterion built on an unverified claim is worse than the claim alone**, because it
   converts a wrong belief into a green test. Two of mine did exactly that (B4.9, B4.6). Candidate rule:
   when a finding corrects a claim, revise the claim **and** its criterion in the same pass, then sweep for
   other criteria leaning on it.
3. **A reviewer can be right about the defect and wrong about the remedy.** Two of Clayton's three
   substantive B findings inverted once checked against the tree — the coverage gate could not measure the
   file it was pointed at, and the parity remedy needed its fixture named or it would have measured nothing.
   Candidate rule: **verify a finding before folding it**, and record the divergence rather than silently
   substituting your own remedy.
4. **An absence claim is the expensive kind of error**, because it manufactures work nobody reviews out. Four
   in this cascade: no roster endpoint (three existed), no boot test (twelve existed), no lifecycle observer
   (one existed, asserted absent by two of us independently), no transport send path (it existed). Candidate
   rule: **grep for the capability, not for the filename you expect it to live in** — and treat "this needs
   to be built" as a claim requiring the same evidence as any other.
5. **Reusing a found artifact is not free.** `/arbiter/fleet-snapshot` was superseded; `/arbiter/fleet-state`

   a reuse verdict lands, **check the artifact's gate, its units and its failure envelope**, not just its
