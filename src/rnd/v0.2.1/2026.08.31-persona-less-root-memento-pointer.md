## Verdict

`memento_io`'s **root** slot gives every persona in a repo **one** pointer file,
`.claude-memento.md`. `memento_slot.verify_memento_at_slot` **LEG 2** runs the reap's proof
against that derived pointer and requires its header `session_id` to be **this** seat's.

⇒ **Whoever wrote the root slot last owns the pointer, and every other seat's `self_respin` is
refused** — with a message naming the winner's session id rather than the shared file.

The **io** slot does not have this shape: its pointer is `io/mementos/<slug>.md`, per-persona.

## Why it was not caught by ruling `8068c65e`

Mr Radio's scope point, and it is the sharper framing: **`8068c65e` routed the REAP around the
shared pointer. It never touched `self_respin`'s LEG 2**, which was left pointed straight at the
one file every persona shares.

## Why this is not cosmetic

`self_respin` is the **first** rung a manager at the context ceiling takes (CLAUDE.md § MANAGER
CONTEXT MONITORING). Refusing it pushes the seat down to succession or a fresh spawn — the worse
rungs — for a reason it did not cause and cannot see from the message.

## The patch

Two production lines. Applied to **copies** for the runs above; the sources are untouched.

### 1. Writer — `planning-is-prompting/workflow/scripts/memento_io.py`, `pointer_rel_path`

```diff
-    if slot == "root": return Path( ".claude-memento.md" )
+    if slot == "root":
+        _refuse_if_record_shaped_pointer( persona_slug, f".claude-memento-{persona_slug}.md" )
+        return Path( f".claude-memento-{persona_slug}.md" )
```

Its docstring `Ensures` block still claims *"slot='root' cannot collide by construction: its
pointer is the fixed name"* — that sentence becomes false with this change and must be rewritten
in the same commit.

### 2. Reader — `lupin/src/lupin_mcp/memento_slot.py`, `slot_pointer_path`

```diff
-    if slot == SLOT_ROOT: return root / ".claude-memento.md"
+    if slot == SLOT_ROOT: return root / f".claude-memento-{persona_slug( persona )}.md"
```

Its `Ensures` line naming the root pointer *"PERSONA-LESS by memento_io's own layout"*, and the
module docstring paragraph built on that fact, both need rewriting in the same commit.

### 3. The collision guard is MANDATORY, not optional

Without it this change **reintroduces F-1** (Rio, 2026-07-21 — record destruction). Measured
against the guard's own classifier: `.claude-memento-arnold-20260721.md` is `record=True`, and it

**Verified firing on the patched writer**, with the victim intact afterwards:

## 🔴 THE CROSS-REPO DECISION — Rick's call

The writer lives in **planning-is-prompting**, the reader in **lupin**. They must agree on the
pointer's name or LEG 2 looks for a file the writer never wrote. Two ways to sequence it:

### Option 1 — FLAG DAY: both repos change together

Land the writer and reader as one coordinated pair; no fallback anywhere.

| | |
|---|---|
| ✅ | One shape in the tree at all times. Nothing to remove later — no second cleanup that gets forgotten |
| ✅ | Smaller diff, and LEG 2 keeps its full strength with no branch that can be reasoned around |
| ❌ | **A real transition window.** Between the two merges, seats run a writer and reader that disagree, and `self_respin` fails for everyone until both land |
| ❌ | A seat whose memento predates the change has no `.claude-memento-<slug>.md`. Its LEG 2 fails on a **missing** pointer until it rewrites |

### Option 2 — READER-TOLERANT: writer switches now, reader accepts either

Reader prefers `.claude-memento-<slug>.md`; falls back to `.claude-memento.md` **only when the
per-persona file is absent**, and only while the legacy pointer's header names this seat.

| | |
|---|---|
| ✅ | **No transition window.** Merge order stops mattering; a pre-change memento keeps working |
| ✅ | Safe to land the repos hours or days apart, which matters when one is on Rick's push gate |
| ❌ | Carries a fallback branch that **must later be removed**, and a removal scheduled for "later" is a rule that depends on remembering |
| ❌ | While the fallback lives, the last-writer-wins refusal is still reachable for any seat that has not yet rewritten — the defect is narrowed, not closed |

### MEASUREMENT — the pointer changed hands four times in 37 minutes, and locked out this doc's own author

**Method.** Two independent derivations per record, so neither rests on the other: the file's
filesystem `mtime`, and the `written_at` stamped inside its own `memento-record` header. They agree
on all four. The holder is read from the **pointer's own header**, not inferred from which file is
newest.

| written_at (header) | mtime | record | holds the pointer? |
|---|---|---|---|
| 2026-08-31T01:17:10 | 01:17 | `.claude-memento-mr-radio-93a8751c.md` | lost it |
| 2026-08-31T01:20:33 | 01:20 | `.claude-memento-tiberius-ec3cdc52.md` | lost it |
| 2026-08-31T01:39:19 | 01:39 | `.claude-memento-maya-9278edec.md` | lost it |
| 2026-08-31T01:54:24 | 01:54 | `.claude-memento-clayton-80d429df.md` | **yes** |

Pointer header, read directly:

```
<!-- current: .claude-memento-clayton-80d429df.md -->
<!-- memento-record: persona=clayton session_id=80d429df written_at=2026-08-31T01:54:24-04:00 slot=root -->
```

🔴 **THE CONSEQUENCE, RE-MEASURED FIFTEEN MINUTES AFTER THE FIRST TABLE IN THIS DOC.** Earlier in
this document, `maya` is the seat that PASSES. Re-run now, same seat, same record, untouched:

```

  memento header session_id (80d429df) != seat (9278edec) — a prior holder's memento in this slot
```

**The author of this document was locked out of `self_respin` while writing it**, by a peer doing
nothing wrong — Clayton was sent to re-spin by his manager. No action of maya's was involved and no
file of maya's changed.

⇒ **Read the two tables together: they are the same seat, fifteen minutes apart, with opposite
verdicts.** That is the defect stated as a measurement rather than an argument.

**What this establishes for Option 2**: a seat becomes immune the first time it writes a memento
after the change, because it then owns a per-persona pointer and never consults the fallback. At
four re-spins in 37 minutes, the fallback is dead code within hours of landing.

⚠️ **What it does NOT establish**: that cadence is one busy night on one repo. It is an argument
that the fallback retires FAST, never a licence to delete it on a schedule — which is why row
`21792c5d` retires on a checkable condition instead.

⚠️ **Retire it on a CONDITION, never a timer**: every persona holding a root record has one whose
`written_at` postdates the merge. That is checkable over the record headers. Row `21792c5d` carries
it, opened in this same sitting rather than promised.

**My recommendation: Option 2**, then the follow-up row above to delete the fallback. The transition
window in Option 1 is not theoretical — the two repos are on **different branches with different
gates**, and lupin's commits are already parked behind Rick's push gate. Option 1 asks for a
simultaneity the current gate structure cannot supply.

⚠️ **Recommending Option 2 means owning its named cost.** The fallback removal must be a store row
opened in the same sitting, not a sentence in this doc.
