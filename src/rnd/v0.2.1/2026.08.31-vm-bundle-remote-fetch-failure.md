# The VM's "origin" is a stale bundle FILE — what pointing it at our branch actually costs

**Measured 2026-08-31 by Tiberius 👑.** Nothing was sent to the VM; every VM command was read-only,
and the replacement bundle was built into a scratchpad, never copied.

## 1. Why the fetch failed

`git remote -v` on the VM (`/mnt/lupin-data/lupin`):

```
origin  /mnt/lupin-data/lupin-wip.bundle (fetch)
origin  /mnt/lupin-data/lupin-wip.bundle (push)
```

**"origin" is a file, not a server.** Written **Aug 25 00:38**, 55 MB, holding **exactly one ref**:

```
d04152cfa1d70f0cefb526a108dbd23c9687a27b refs/heads/wip-v0.2.0-2026.08.03-present-and-demo
```

Not corruption — `git bundle verify` reports *"is okay … records a complete history."*

Reproduced on the VM with a positive control, so the empty answer is evidence rather than silence:

| arm | result |
|---|---|
| fetch `wip-v0.2.1-2026.08.29-cjflow-v2-followup` | `fatal: couldn't find remote ref` · **exit 128** |
| **positive control** — fetch `wip-v0.2.0-2026.08.03-present-and-demo` | `-> FETCH_HEAD` · **exit 0** |

⇒ A branch switch on the VM delivers nothing. The ref is simply not in the file it fetches from.

## 2. The replacement bundle — built locally, verified, NOT sent

```
git bundle create <scratchpad>/lupin-wip.bundle wip-v0.2.1-2026.08.29-cjflow-v2-followup
```

* build time **1.16s**, size **56,411,556 bytes (54 MB)**
* `git bundle verify` → *"is okay … records a complete history"*
* `git bundle list-heads` — **one ref, and it is the one we want**:

```
b67fd52b01d5ce9a99d53a6e378af45218547842 refs/heads/wip-v0.2.1-2026.08.29-cjflow-v2-followup
```

⚠️ It carries **only** that ref. `wip-v0.2.0-2026.08.03-present-and-demo` — the branch the VM is
deployed on — is **not** in the new bundle. The VM keeps it as a local branch, but it stops being
fetchable from `origin` the moment the file is overwritten.

## 3. What the tree move would cost

The VM sits at `d04152cf` (**2026-08-24**); our branch tips at `b67fd52b` (**2026-08-31**). They are
**parallel lines from a common Aug-3 base** (`1fa05b16`), not stale-vs-fresh — `d04152cf` is **not**
an ancestor of our HEAD.

🔴 **Do not read the commit counts as the cost.** `rev-list --left-right --count` gives **1280 / 546**,
which looks like the VM is 1,280 commits of work ahead. **It is not**: spot-checked
`src/lupin_cli/claude_code/hooks/lib/stash_guard.py`, landed by a VM-side commit, and it is
**present on both** lines. The work re-landed across the two branches, so the counts overstate the
divergence. **The file diff is the honest measure.**

| scope | delta `d04152cf` → `b67fd52b` |
|---|---|
| whole tree | 838 files, +103,491 / −28,825 |
| of which `src/tests` + `src/rnd` | **617 files** — tests and R&D docs, not deployed code |
| **deployed code** (`src/cosa`, `src/lupin_app`, `src/conf`, `docker*`) | **95 files, +10,837 / −815** |

**Deploy-critical files in that delta:**

```
M  docker-compose.cloud-gpu.yml      <- the compose file lupin-vm.sh actually uses
D  docker-compose.cloud-test.yml     <- DELETED on our branch
M  src/conf/lupin-app.ini
M  src/scripts/preflight-vm.sh
```

### 🔴 The named risk: the VM has uncommitted edits to two of those same files

`git status` on the VM shows tracked modifications to **`docker-compose.cloud-gpu.yml`** and
**`src/conf/lupin-app.ini`** — and both are **Modified in the incoming delta**. Those are live deploy
edits that exist nowhere else.

Two facts, stated separately rather than welded: *(a)* both files are locally modified on the VM;
*(b)* both files change in the incoming delta. What `checkout -B` does when those collide is git's
documented refuse-to-clobber behaviour — **predicted, not measured here**, because measuring it means
touching the VM.

## 4. The exact sequence — and the safe step is a DIFFERENT subcommand from the costly one

Both run **from the dev box**, where the checkout lives.

**Step 1 — fixes the fetch failure, does NOT move the VM's tree:**

```bash
set -a; source src/scripts/cloud-run.env; set +a
src/scripts/lupin-vm.sh push-bundle wip-v0.2.1-2026.08.29-cjflow-v2-followup
```

Dry-run output, verbatim:

```
git bundle create <tmp> wip-v0.2.1-2026.08.29-cjflow-v2-followup
scp -> VM:/tmp
cp  -> /mnt/lupin-data/lupin-wip.bundle
sudo git fetch origin wip-v0.2.1-2026.08.29-cjflow-v2-followup
chown 1001 .git
```

Refs update; **working tree UNCHANGED**; no `.deployed-ref` stamp (nothing moved). This is the
reversible half — it only overwrites the bundle file.

**Step 2 — this is the one that costs, add `--checkout`:**

```bash
src/scripts/lupin-vm.sh push-bundle wip-v0.2.1-2026.08.29-cjflow-v2-followup --checkout
```

Adds, on the VM: `git checkout -B <branch> FETCH_HEAD` → purge `__pycache__` + `*.pyc` → `chown 1001`
the tree → stamp `.deployed-ref` with `<vm HEAD sha> <utc ts> push-bundle-checkout`.

**Neither step restarts anything.** `lupin-vm.sh deploy` is the one that additionally
force-recreates `:7999` and restarts the `:8001` arbiter.
