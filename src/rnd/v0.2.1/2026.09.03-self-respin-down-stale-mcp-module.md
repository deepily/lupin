# `self_respin` is down fleet-wide: the MCP process serves a module older than the commit that added the symbol

**Date**: 2026-09-03 ~20:01 EDT · **Found by**: Tiberius 👑 · **Verified independently by**: Mr. Radio 🦉
**Status**: OPEN. Asked Rick 20:02, he was offline (`[default used] no`). Chase 2026-09-04 10:00 EDT.
**Why this doc exists**: the ticket gate refused the row (13 created / 32 closed, ratio 0.41, opens
below 0.40 — one more close needed). Rather than inflate the priority to P0 to route past the gate,
the finding is parked here where it cannot be lost. It gets a row the moment the gate opens.

## The failure

```
Error calling tool 'self_respin': cannot import name 'get_claude_session_id_with_source'
from lupin_cli.claude_code.hooks.lib.session_bridge
```

Hit twice, either side of the `:7999` bounce at 20:00 — **so it is not the bounce**.

## Diagnosed, not guessed

Each leg checked separately, because a mechanism that is easy to picture is not thereby one that
has been checked:

| check | result |
|---|---|
| symbol present on disk | ✅ `src/lupin_cli/claude_code/hooks/lib/session_bridge.py:454` |
| commit that added it | `13014bd1` — two commits back from HEAD at the time |
| a fresh interpreter imports it | ✅ yes |
| the running MCP process imports it | 🔴 **no** |

⇒ **The running cosa-voice MCP process holds a module older than `13014bd1`.** A saved file is not a
served file. This is a stale *served* module, not a code defect — **no code change fixes it, and
retrying is pointless.** The remedy is a restart of that process, which is fleet comms and outside
the standing "anybody may bounce `:7999`" grant.

## Why it is worse than one seat

- Every seat over the context ceiling must now be **reaped by its manager** rather than clearing itself.
- 🔴 **A manager over the ceiling has no rung at all.** Rung one (`self_respin`) is broken. Rung two
  (`dismiss_sessions`) cannot reach its own seat, because a manager's own session is not in its own
  lineage. Only rung three remains — a full board handover to a peer manager, which only works
  **while the dying manager can still act**.

⚠️ **Degraded, not stopped**, and said plainly so nobody reads this as an outage it is not.
Manager-reaping works: Tiberius was reaped with `respin_personas=["Tiberius"]` and respawned from his
verified memento the same tick, `retained_unmatched: []`, no rows landed silently on the manager's board.

## The workaround, with the trap in it

```
dismiss_sessions( write_memento=True, respin_personas=["<name>"] )   # then respawn from the memento
```

⚠️ **If the worker already wrote a memento to the ROOT slot** for a `self_respin` they can no longer
fire, pass `write_memento=False` and hand the **root record** as `seed_memento`. The reap only proves
the **io** slot (the two doors read different slots, by design), so asking it to prove a memento will
DM an over-budget seat and make it spend the context the reap exists to reclaim.

## What is NOT established

- **Why the process is stale** — how long it has been running, and whether it predates other commits
  too, was never measured. Only that it predates `13014bd1`.
- **Whether anything else it serves is also stale.** One broken import was found because one verb was
  called. Nothing surveyed the rest of its surface.
