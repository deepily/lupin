## The six survivors, read four ways

**Five were the FOURTH reading — a fixture that cannot discriminate.** Not one was a weak

### 1. `site-packages` exclusion dropped — `914b6d4c0411` — **fixture** ⭐ highest value

`_tracer` rejects on `PREFIX not in fn or "/tests/" in fn or "site-packages" in fn`. The
fixture's third-party path is `/usr/lib/python3.13/site-packages/pytest/__init__.py`, which
carries **no `/src/`** — so the *first* clause rejects it and the `site-packages` clause never
does any work. Deleting that clause leaves every existing test green.

**It is load-bearing in this repo specifically**: `src/cosa/.venv` is a vendored 3.11
virtualenv of ~29,000 files whose paths contain **both** `/src/` and `site-packages`
(CLAUDE.md § "THERE IS A SECOND VIRTUALENV *INSIDE* `src/`"). Without the clause the tracer
would attribute lines across the whole vendored tree.

Fix: a path that carries both — `/src/cosa/.venv/lib/python3.11/site-packages/urllib3/connection.py`.

### 2. `sorted( ls )` → `list( ls )` — `b8fce4692d7a` — **fixture**

The test records lines `(30, 10, 20)`. A small CPython int set iterates by slot, and 10/20/30
land in ascending slots, so `list( ls )` and `sorted( ls )` return the **identical list**:

```
(30, 10, 20) -> list [10, 20, 30] == sorted   # agrees — the sort is invisible
(100, 3, 50) -> list [50, 3, 100] != sorted   # discriminates
```

Fix: line numbers `(100, 3, 50)`.

### 3. `sort_keys=True` → `False` — `3b94bec67e1c` — **fixture**

Invisible with one file per thread — the sorted and unsorted renderings are byte-identical.
Fix: record two files `z` then `a`, and assert on the **raw text**, since the parsed dict
compares equal either way and would hide exactly what is being tested.

### 4. default `OUT` path changed — `6ae7f41de7c7` — **fixture**

Every test monkeypatches `OUT`, so the default is executed at import (hence 100%) and then
never asserted. Fix: clear the environment, `importlib.reload`, assert the default. The same
test also kills the `PREFIX` default mutation `5f1eeb8c1296`.

### 5. `returned_len == sent_len` → `>=` — `a7bce7f3cc32` — **fixture**

`_FakeStore` can only **truncate** (`cap`) or **refuse** (`raise_at`) — every fixture returns a
body no *longer* than the one sent, and on those `==` and `>=` agree on every row. Only a store
that hands back **more** than it was given separates them; a probe calling that a survival would
report a clean round-trip while the store was concatenating entries.

Fix: a `_PaddingStore` that appends to the body.

> This is the same shape as the `assert len( password ) == 16` → `>= 16` survivor on
> `migrate_mock_users` earlier the same evening. **An equality whose fixtures only ever
> approach it from one side is not being tested as an equality.**

### 6. `store.read( ..., limit=1 )` → `limit=2` — `262fc37cb0ae` — **EQUIVALENT, no test**

`read` returns `list( reversed( entries ) )[ :limit ]` — newest-first — and the caller takes
`entries[ 0 ]`. The extra record is fetched and discarded; `entries[ 0 ]` is identical either
way, under the fake and under any newest-first store. **Writing a test for this would be
writing a test to kill something that was never a defect.**
