### 3.2 THE DISCHARGE — the two-independent-readings pattern (Maya 🌻)

**Graduated at Tiberius 👑's request, seconded by Mr Radio 🦉 (2026-08-30 16:10): this is the
concrete discharge for R1 / `masked-invariant`, and it earns a named section rather than a table
cell.** §3.1 says never let an instrument certify itself. **This is what doing that looks like in
code**, and it is already in the tree — `aab06b9c` (ancestor of HEAD), `src/tests/unit/test_secret_scan.py`.

**The problem it solves**: a test that polices a record *through the helper that expresses the
record* cannot fail. A dead helper — one returning `[]` or `( set(), [] )` for any input — makes
the assertion pass **vacuously**, and a vacuous pass is indistinguishable from a real one.

**Three moves, and all three are required:**

1. **Read the live record DIRECTLY**, not through the thing under test.
   ```python
   direct = [ row for row, reason in recorded[ "branch_accepted" ].items()
              if reason == GRANDFATHER_REASON ]
   ```
2. **Cross-check the helper against that read**, so a broken helper **reddens instead of certifying**.
   ```python
   assert sorted( riding ) == sorted( direct ), (
       f"amnesty_rows disagrees with a direct read of the record: helper says "
       f"{len( riding )}, the file says {len( direct )}. The helper is wrong, or the "
       "record's shape changed under it — either way the bound below means nothing." )
   ```
3. **Assert the record is NON-EMPTY**, so the test cannot pass on nothing.
   ```python
   assert direct, ( "NO row rides the amnesty. Either every row was individually re-triaged — "
                    "worth saying out loud and re-pinning AMNESTY_ROWS to 0 — or this test is "
                    "reading an empty record and would pass on anything." )
   ```

🔴 **MOVE 3 IS THE QUIET LOAD-BEARER, AND HERE IS PLAINLY WHY: WITHOUT IT, THE CROSS-CHECK PASSES
ON NOTHING — WHICH IS THE SAME DEFECT ONE LEVEL UP.**

Moves 1 and 2 build a control: two readings that must agree. **On an empty record they agree
perfectly.** So a cross-check without move 3 is itself an instrument that cannot fail — it reports
"the helper is honest" in exactly the case where it has checked nothing at all. **The control you
just built to escape §3.1 has walked straight back into §3.1.**

That recursion is the whole reason this move is not optional garnish. `assert direct` is what
converts *"the helper agrees with the record"* into *"the helper agrees with the record, and the
record exists"* — and only the second of those is evidence. The companion assertion in the same file
says it outright: *"the record holds no accepted rows at all — this test would pass on anything."*

⇒ **Generalised, and worth carrying past this file: any two-reading control needs a third assertion
that there was something to read.** A comparison is not a measurement until you know both sides are
non-empty.

**Note what the failure messages do**, because it is the standard Tiberius set at the start of the
day and this meets it: each one names **which** reading disagreed, **by how much**, and **what
follows** — *"either way the bound below means nothing."* A reader who has never seen the file can
act on that sentence.

**Provenance**: written by **Maya 🌻**; forced by **Tiberius 👑** reviewing `177c3542`, whose comment
states the principle in one line — *"Policing the amnesty with the very helper the amnesty is
expressed in means a DEAD helper makes this test pass vacuously. **The instrument cannot be its own
control.**"* That sentence predates Maya's frame by hours and says the same thing; §3.1's framing and
this discharge were arrived at independently, from opposite ends — a reviewer's comment and a
retro's synthesis. **That convergence is the argument for graduating it.**

**A SECOND WORKED EXAMPLE, AND IT IS THE CLEANEST ONE IN THE TREE** — flagged by Maya 🌻 (relayed
16:14). The heartbeat hold verb, `heartbeat_hold_io.py:472`, does all three moves and adds a fourth:

```python
hold      = write_hold( ... )
read_back = read_hold( args.session_id, base_dir=args.base_dir )   # 1. independent read
if not is_honored( read_back ):                                     # 2. cross-check
    path.write_bytes( prior_bytes )                                 # 4. ROLL BACK on failure
    os.utime( path, prior_times )
    return EXIT_NOT_HONORED
print( "honored  yes (read back through the reader the hook uses)" )
```

**The load-bearing phrase is in its own success line**: *read back through the reader the hook uses.*
Not a re-read of what it just wrote, and not its own parser — **the consumer's reader**. A write
that verifies with its own reader proves the bytes round-trip, which is the thing least in doubt.

**The fourth move is one this retro did not have and should**: on a failed verify it **restores the
previous hold, bytes and mtime**, and exits non-zero. So the control does not merely detect — it
**refuses to leave a worse state behind than it found**. A verify that reports failure and leaves
the broken artifact in place has told the truth and still done harm.

⚠️ **This is the CURE, not a case of the disease — file it that way.** Maya's correction, and she is
right: it is the pattern §3.2 prescribes, already implemented, and it should be cited as the
reference implementation rather than mistaken for an instance in §3.1.

⚠️ **THE BOUNDARY IS LOAD-BEARING, NOT A CAVEAT — KEEP IT** (Mr Radio 🦉, 16:12). This pattern
applies **only where an independent second reading actually exists.** `masked-invariant` (§6) is
precisely where none does: two agreeing sites, no second record to read — annotation-and-review is
the fallback there, and this section is not a claim that every masked line is fixable.

**Why the limit is the important half**: *a rule that claims to apply everywhere becomes a ritual.*
Stated without the boundary, this one would be satisfied by **manufacturing a second reading** —
deriving the "independent" read from the same helper, or from a source that shares its assumption —
which produces the ceremony of a control and none of its force. **A fake second reading is worse
than no second reading, because it also reports success.**

**And the same test governs the graduation**: convergence is evidence when two readings genuinely
arrive independently — Tiberius on one file, this retro across nine instances. **One reading
repeated is not convergence**, however many times it is restated. Today produced both, which is why
the distinction is written down rather than assumed.

## 6. Lessons for the failure-mode catalog

**`masked-invariant`** — *a fact stated twice on one path, where every test that observes a return
value sees the two sites agree, so neither can be independently proved.*

> **This entry was written three times and refuted twice, both times by Tiberius 👑, both times
> because a claim was checked instead of accepted.** Recorded in full because the retraction path is
> the finding:
>
> 1. **Rachel's draft** — *"a test can assert the mechanism and still be unable to fail if the fact
>    is stated in two places."* **Refuted**: it condemns a healthy arrangement. `fcb0fd8d` carries
>    direct unit tests on both sites *plus* the path-level one.
> 2. **Tiberius's first correction, published ~15:33** — *"pin each site DIRECTLY with its own unit
>    test."* **He then reproduced it and refuted his own fix**: the outer site's "direct" test still
>    resolves through the inner one, so it observes the same output. **Measured at `a35ce8ef` by
>    Rachel before republishing**: neuter the wrapper's `""` branch → **127 passed**, including
>    `test_an_unreadable_live_comm_refuses_rather_than_passes`, which asserts that exact function.
>    **Independent pinning of the outer site is not achievable while the inner site agrees.**
> 3. **The third version is below. RULED 15:39 and SPLIT** — adopted for this crew immediately,
>    escalated to Rick for fleet doctrine. Mr Radio stopped the revision loop at 15:38 and took the
>    ruling himself; the measurement is what made it decidable rather than a matter of taste.
>
> **The rule is already in the code it came from**: `03b90812` replaced Tiberius's earlier
> annotation — which claimed both sites were "pinned independently, so the duplication is checked,
> not merely asserted" — with one that states the price: *"this line is MASKED: no test can fail on
> it while the delegate agrees… the redundancy is deliberate AND unfalsifiable, so it is defended by
> this comment and by review, not by the harness. Do NOT 'fix' the masking by deleting this line —
> the redundancy is the point; the missing proof is the cost."* **A rule that ships as an annotation
> in the file it was derived from is installed; one that ships only as a retro line is not.**

- **Trigger**: deliberate defence-in-depth. A caller handles a boundary case AND the callee handles
  it. **Direction of the danger: the redundancy is usually there ON PURPOSE.**
- **Symptom**: mutating the outer site leaves the whole suite green — *including a unit test written
  against that very function*, because it delegates to a site that returns the same answer.
- **The obligation — one of two**: drop the second statement, **or** keep it and **state the price
  in the comment**, so the line is defended by **review** rather than by the harness.
- 🔴 **THE ANTI-PATTERN THIS EXISTS TO PREVENT: deleting the line because a mutation harness reports
  it dead.** It *is* dead to the harness. It is not dead to the contract — here, folding it would
  make a fail-closed gate depend on the predicate agreeing, which is the two-contracts-not-meeting
  shape the module was written to fix.
- **Where a second reading EXISTS, the discharge is §3.2** — the two-independent-readings pattern
  (read the record directly · cross-check the helper · assert non-empty). Reach for that first; the
  annotation fallback below is only for the case where no independent reading is possible.
- **What discharge is NOT**: arguing the path-level test is good enough. **What it is**: an
  annotation that names the cost, reviewed by a human, on a line everyone now knows the harness
  cannot defend.

**`rule-instead-of-mechanism`** (recurrence — already in the catalog via `011f1f90`) — three fresh
instances in one day: misplaced mementos after the row was filed (§3.3), checked-hash drift after
