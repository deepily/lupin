## 1. The parity rule (Rick, 2026-09-15, Phase 1 §8)

Parity means the multiplexer **contains** every behaviour the legacy client has. Anything the multiplexer does *beyond* legacy is allowed and stays. So every finding here gets one of three verdicts:

| Verdict | Meaning | Owed? |
|---|---|---|
| **MATCH** | Both clients behave the same | no |
| **OWED** | Legacy has the behaviour and the multiplexer lacks it, or does it differently | **yes** — goes to the build list |
| **EXTRA** | The multiplexer has a behaviour legacy lacks | no — keep it, do not back-port |

A behaviour that *conflicts* with a legacy behaviour (for example, the multiplexer auto-expands where legacy stays collapsed) is **OWED**, not EXTRA: the lead's behaviour wins.

## 2. Method

Each accordion is inventoried on both sides against the same fixed list of behaviours, so a missing row is visible rather than silently skipped.

| # | Behaviour | The question asked of both clients |
|---|---|---|
| B1 | **Default disclosure** | Expanded or collapsed on a first load with no saved state? |
| B2 | **Toggle trigger** | What opens and closes it: header click, chevron only, keyboard? |
| B3 | **Persistence** | Is the open/closed state saved? Under which storage key? Restored on reload? |
| B4 | **Toolbar show/hide** | Does the toolbar button hide the whole section? Is that saved? |
| B5 | **Collapse/expand-all** | Does a global or per-section `⊟`/`⊞` act on it or on its children? |
| B6 | **Auto-reveal** | Does an event (new item, a focus request) un-hide or expand it by itself? |
| B7 | **Live header** | Do the title, count or "updated …" text change while the page is open? |
| B8 | **Refresh control** | What does `⟳` (or equivalent) refetch, and what does it do to disclosure state? |
| B9 | **Nested accordions** | Each child accordion's default, trigger and persistence (B1–B3 again, one level down) |
| B10 | **Empty state** | What renders when there is nothing to show? |
| B11 | **Layout mode** | Does the horizontal (reading-pane) layout move or change it? |

**Evidence standard.** Every cell cites source as `file:line` on both sides. A behaviour read from source is marked **(source)**. Where it has also been watched in a browser it is marked **(observed)**. Nothing is inferred from a missing search hit: an absent behaviour is stated with the search that found nothing.

**Browser confirmation — constraint.** Clicking a toggle writes persisted UI state that the operator's own tabs share. Browser confirmation therefore waits for a method that does not disturb his state, such as a separate browser profile. Until then, cells are **(source)**.
