## 🔴 DISTRUST ANY STRAGGLER LIST BUILT FROM `git grep`, INCLUDING BOTH OF MINE

I ran two grep censuses an hour apart and got **22** and **33** stragglers. Both wrong, and
they fail in **opposite directions**:

| pass | what it did wrong | error |
|---|---|---|
| loose | counted a script **mentioned in a test comment** as tested | too few stragglers (22) |
| strict | missed a **dashed-name** import | too many stragglers (33) |

**The receipt.** `watch-hook-events.py` has a dedicated suite that loads it as

```python
whe = importlib.import_module( "watch-hook-events" )    # the DASHED filename
```

My strict regex searched the *underscored* module name `watch_hook_events`, found nothing,
and reported a well-tested file as untested. Same trap swallowed `capture-bounce-resubmit.py`
and `migrate-sqlite-to-postgres.py`.

⇒ **A grep for a module name cannot answer "is this covered."** The instrument is a coverage
run. Publishing either list would have sent three seats to write second suites for files that
already have them — wasted work that looks like progress.

### The one grep result that IS sound, and the asymmetry is the whole point

```bash
git grep -l -- "<stem>" -- src/tests src/cosa/tests
```

- **EMPTY is conclusive** — nothing named cannot be loaded. Use the **dashed stem**, as on disk.
- **A HIT proves nothing** — it may be a comment, a docstring, or a rename-consistency check.

Checked for the thing that would break even that: a test loading scripts generically by
`glob`/`listdir` with no name in its source. Only **enumerators** exist, and enumerating a
filename does not execute it, so no coverage comes from them.

### The three retirements, and the proof they needed

Clayton 😎 pushed back that *"a test file exists"* is not proof the tests **execute** the
module, and he was right to — I had asserted it for two of these from the filename alone.
Checked properly, by opening each test file and finding the load line:

| script | loaded by | how | tests |
|---|---|---|---|
| `watch-hook-events.py` | `test_watch_hook_events.py` | `importlib.import_module( "watch-hook-events" )` | — |
| `migrate-sqlite-to-postgres.py` | `test_migrate_sqlite_to_postgres.py` | `importlib.util.spec_from_file_location( "migrate_sqlite_to_postgres", … )` | 42 |
| `capture-bounce-resubmit.py` | `test_capture_bounce_resubmit.py` | `importlib.util.spec_from_file_location( "capture_bounce_resubmit", … )` | 14 |

⇒ **His objection was right in principle and wrong on these three.** All three genuinely load
and run the module. The retirements stand — but they stood on evidence only after he asked,
and for two of them I had been one filename away from saying so without checking.

⚠️ Note the load mechanism differs per file — `import_module` on a dashed name in one,
`spec_from_file_location` in the other two. That variety is exactly why a single grep pattern
cannot survey this, and why the coverage run is the instrument.
