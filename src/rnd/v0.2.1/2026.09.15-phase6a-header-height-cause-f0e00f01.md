# The phase6a −6px is the chevron becoming a button, and nothing below the header moved

**Row**: `f0e00f01` · **Seat**: Pocholo 📣, author for Mr. Radio 🦉 · **Written**: 2026-09-15
**Ruling this answers**: Mr. Radio, 2026-09-15 21:58 EDT — *"Rebaselining is not appropriate
without a clear cause for the −7px displacement."* The cause is named below, measured with a
two-arm test that moves in both directions.

---

## Verdict

`test_multiplexer_phase6a_jobs_pane_visual` fails on height because commit **`97ab72a2`
(2026-09-06)** changed the section-header chevron from a `<span>` to a `<button>`, on Rick's
divergence-#5 keyboard-access ruling. A `<span class="toggle-button">` measures **35px**; the
`<button>` measures **29px**. That 6px comes straight off `.section-header`, which is
`max(child heights) + 30px padding + 1px border` — **66px in the golden, 60px today**.

**Nothing below the header changed position relative to the header.** The whole image delta is
the header band.

⚠️ **It is −6, not −7.** The pane's box is **396.5px**, so the screenshot rounds to 397 or 398
between runs. The golden is 404. The structural delta is **−6**; the extra −1 in some runs is the
sub-pixel flap that `assert_snapshot_height_tolerant` already exists to forgive (bug `660d02b4`).
Quoting −7 folds a real 6px cause together with a known ±1px rounding artifact.

## The measurement

One capture on `:7999` from the test's own `_INJECT_JOB_FIXTURES_JS` and `_STABILIZE_DOM_JS`
(lifted from the test file by regex, so the fixture cannot drift from the test), `timezone_id="UTC"`
pinned, compared against the surviving committed golden.

### 1. The offset is a step function with exactly two steps

Every golden row that is unique *within golden* and matches exactly one current row, plotted as
`offset = current_y − golden_y`:

| golden y | offset becomes |
|---|---|
| 1 | `+0` |
| 22 | `−3` |
| 75 | `−6` |
| …through y=394 | stays `−6` |

Guarded per the blank-window trap: of 315 contentful golden rows, **62 uniquely matched**,
**152 ambiguous (duplicated rows, discarded)**, **101 matched nothing**. A scan that skipped the
uniqueness guard would have reported a single clean displacement and been wrong.

### 2. The two 3px steps are one 6px header

Vertical colour runs at `x=500`, a column clear of all text:

| | golden | current |
|---|---|---|
| header band `#e9ecef` | y1..65 (**65px**) | y1..59 (**59px**) |
| header bottom border `#dee2e6` | y66 | y60 |
| gap, then first bucket | y67.. | y61.. |

Header **66 → 60**. The h3 is centred in the header (`align-items: center`), so it takes half the
loss (3px, step one) and the rest appears below it (3px, step two). Two steps, one cause.

### 3. No child got smaller — every glyph is byte-identical in size

Ink extents inside the header band:

| element | golden | current | height |
|---|---|---|---|
| emoji 📝 | y22..42 | y19..39 | 21px **both** |
| text "Jobs" | y26..38 | y23..35 | 13px **both** |
| chevron ▼ | y28..39 | y25..36 | 12px **both** |

All three shift up by exactly 3px and none changes size. So the *line box* shrank, not the content
— which is what sent the search to the box model rather than to fonts or CSS sizes.

### 4. Two-arm test, and it moves both ways

In the live page, the chevron is swapped for a `<span>` carrying the identical class and text, then
back:

| arm | tag | `.toggle-button` | `.section-header` |
|---|---|---|---|
| as shipped | `BUTTON` | 29px | **60px** |
| chevron restored to a span | `SPAN` | 35px | **66px** ← the golden |
| swapped back | `BUTTON` | 29px | **60px** |

The span arm reproduces the golden's header height **exactly**. The third arm is the restore
control: the instrument moves in both directions, so the 66 is not an artifact of mutating the DOM.

### Hypotheses killed along the way

- **The toolbar commits** (`c4f8e39c` / `5a3e57f0` / `0839b3ff`). `0839b3ff` removes the accordion
  pair from `#section-toolbar`, which is **outside** `#jobs-pane` — it cannot move this header. My
  memento recorded the 1px coincidence as unproven; it is now disproven. The 1px was the 396.5
  rounding.
- **`.section-header` padding.** `git log -L` on the rule: `padding: 15px 20px` since the file was
  created, never edited. Both definitions of the selector in the tree carry 15px.
- **The emoji's font metrics.** Stripping the 📝 from the h3's text node leaves `h3` at **28.078125px**,
  unchanged, and the emoji's line box probes at 22px under all eight font stacks tried. The emoji
  contributes nothing to the header height.

separate questions from the −6px — they are bucket-header controls and label text, at unchanged y.

⚠️ **Stated as a gap, not bridged**: this doc measures *that* those bands differ. It does **not**
measure which commit changed each one, and the live-count band cannot be fixed by a rebaseline at
all — a golden that captures a live database tally goes stale again the next day.

## What this does and does not authorise

- **Does**: name the cause of the height delta, which is what the ruling asked for. The change is
  intentional and ratified (keyboard access; a `<span role="button">` with no `tabindex` cannot be
  focused), so the golden is the stale side.
- **Does not**: authorise a rebaseline on its own. A rebaseline also bakes in the live-count band at
  `x761-789`, which is uncontrolled — it would go red again without anyone changing code. That band
  wants a pin or a stubbed route first. **Mr. Radio's call.**
