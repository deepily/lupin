## 1. Phase A — fixes to panes that already exist

### A-1. The one theme, in three mechanisms

**The multiplexer repaints and forgets.** Legacy protects an operator's in-progress state across its repaints; the multiplexer replaces its DOM wholesale and loses it. That is one *theme* across **six** rows below — but it is **three different mechanisms**, and building them as one would force the wrong shape onto at least one of them.

| # | What is lost | Where | Legacy's answer | Mechanism |
|---|---|---|---|---|
| 1 | A half-typed reason, the chosen verb, the open disclosures, the focused control | Task List, every 60 s poll | `_captureOperatorState` / `_restoreOperatorState` (`notifications.js:13231-13435`) | **A-1a** |
| 2 | A click whose press and release straddle a repaint | Task List | press-hold guard: `mousedown` holds the repaint, `mouseup`/`mouseleave`/`blur` replays it (`:14274-14283`) | **A-1b** |
| 3 | The batch-reason box and disclosures | Holding Area | same capture/restore (A9 H13) | **A-1a** |
| 4 | Disclosed rows and group state | Epic Board | A10 E11 | **A-1a** |
| 5 | An opened queue bucket, and an expanded job card, on every job event | Jobs pane | `lupin_queue_expand_state` (`:15429-15460`), restored on load | **A-1c** |
| 6 | A pending Action Required prompt, its active id, pause state and half-answered stepper | Action Required, on reload | `notifications_action_required` (`:21332-21519`) | **A-1c** |

**A-1a — capture and restore across a repaint** (rows 1, 3, 4). **This already exists in the multiplexer**: `NotificationsListRenderer.ts:1296-1344` has the `captureCardFocus` / `restoreCardFocus` pair, keyed capture restored onto the replacement node. A-1a **generalises that pair**; it does not invent one. Two partial mechanisms are also already in place: `HoldingAreaRenderer.ts:163-178` (`batchesInFlight` / `batchReports`, built for exactly this failure) and `EpicBoardRenderer.ts:265-268`, which states the persisted-choice-is-truth invariant row 4 needs.

**A-1b — defer the repaint while a gesture is mid-flight** (row 2). **The one row reuse cannot help**, and legacy says why at `notifications.js:14277-14280`: by the time the release arrives the node itself is gone, so the only answer is to hold the paint. **A-1b lands before or with A-1a** — bundle it into the capture work and the build will treat a gesture as a capture case, which it is not.

**A-1c — persist to storage and restore on load** (rows 5, 6). 🔴 **Name the persistence idiom before writing either key.** Four competing idioms are in the tree today: `shared/StorageService.ts:2-5,41-45` declares the DC2 "no raw localStorage" invariant, while `taskListCollapse.ts:17`, `epicBoardCollapse.ts:26` (inverted polarity) and `FinishedTasksRenderer.ts:83-91` each deviate from it. `finishedTasksModel.ts:81-87` carries an in-tree warning that copying either inverts a user's saved state and fails invisibly. A-1c adds one key and A-2 #6 adds another; pick the idiom once, up front.

**The test idiom already exists too**: `task_controls_survive_the_disclosure.test.ts:1-40` assembles the renderer, emits a store change, and asserts the control both survives **and** still reaches the store. `testkit/accordionHarness.ts:176-202` already mounts the three panes A-1 touches.

**Done means**: an operator can type a reason, press a button, open a bucket or answer half a prompt, and a poll, a job event or a reload does not take it away. A test per surface that mutates state mid-repaint and asserts survival. *(This is A-1's acceptance criterion. It does not replace the finish bar in §5, which applies to every item.)*

## 5. How a Phase A or Phase B item is finished

> Revision 1's finish bar paraphrased five standing rules and **weakened every one of them**. Each clause below now cites the rule it enforces, so a reader can check the bar against its source instead of trusting the paraphrase. This bar governs; an item's own "done means" line is its acceptance criterion, not a substitute.

1. **Tests at every applicable tier** — a unit test for the changed unit, an integration test for the affected surface, and an E2E test for the user-observable behaviour. Results reported in a table, pass/fail per tier. A test that genuinely cannot be automated is named **with its specific reason**; silent omission is not available. *(`~/.claude/CLAUDE.md` § Test Ownership Mandate.)* One of those tests must fail against today's code — the **negative control** of `workflow/neutral-execution.md`.
2. **The mechanism, not the symptom** — especially A-1, which is three mechanisms across six surfaces. See §1.
3. **Adversarial peer review, unconditionally, and it binds at COMMIT** — not at merge, and not only "where state or timing is involved". *(`workflow/swe-team-roles.md`, `workflow/manager-autonomy.md`.)*
4. **100% coverage — lines AND branches AND functions**, via `c8 --100`. Write it that way in every AC; never ≥90% or ≥95%. `c8 ignore` only for a genuinely-unreachable defensive branch, with a same-line reason. *(lupin `CLAUDE.md` § 100% coverage mandate — a Lupin-wide hard gate.)*
5. **The merge pyramid, by name and in order**: typecheck → unit → cosa → coverage → typescript → smoke → serial bridge guard → websocket smoke → e2e_a → e2e_b → integration (the final gate), each at 100%, at the venues named in lupin `CLAUDE.md` § TESTING. "Green suite" names nothing a reader can execute. Typecheck runs first and costs ~3 s; note that its summary counts **projects**, not tests.
6. **A saved file is not a served file — and for the multiplexer that means the bundle.** `static/js/multiplexer/**` reaches the page only through `npm run build` (manifest → `boot.<hash>.js`); legacy needs its immutable `?v=` token bumped. **Whoever merges the item verifies the running code**, by reading the served manifest hash — not the source file. A new pane additionally owes the `boot.ts:295-320` mount handshake and its AC9 console line, or `the_hand_lists_are_checked_against_what_boot_reaches.test.ts` reddens.
7. **Close the row with a receipt** — `receipt_refs` on the transition to `done`, per `workflow/task-store-discipline.md`. Keep the Phase 2 row id in the commit message for readability; the id is not the receipt.
