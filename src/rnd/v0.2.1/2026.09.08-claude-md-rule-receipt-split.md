## 1. What "split the rule from the receipt" means

Every one of those 49 sections has the same anatomy:

| part | example | verdict |
|---|---|---|
| **the RULE** | *"⇒ QUIET means zero pytest AND zero UNKNOWN"* | 🟢 **stays inline** — a seat acts on it |
| **the COMMAND** | the `ps -eo comm,args` block | 🟢 **stays inline** — a seat copies it |
| **the DISCRIMINATING TABLE** | which pattern reported what | 🟢 **stays inline** — it is how you use the rule |
| **the RECEIPT** | *"Tiffany 💍, 2026-09-05, on her own misreading… 28 samples, 24 answered ONE"* | 🔵 **moves** — it is why the rule is believed |
| **the RECONCILIATION** | four seats' counts, the retracted draft, who corrected whom | 🔵 **moves** |
| **the SCOPE LIMIT** | *"the both-unreadable path was exercised with synthetic input only"* | 🟡 **judgement call — see §4** |

**Destination**: `src/docs/doctrine/<topic>.md`, one file per host section, each moved receipt
under a heading the inline pointer names. Nothing is deleted; everything stays in git and stays
reachable by one link.

**Every inline entry keeps a pointer**, so a seat that wants the evidence is one click away:

```
[receipts → doctrine/testing-venues.md § another-suite-running]
```

## 2. Sample A — an OPERATIONAL section. Most of it stays.

`### 🔴 "IS ANOTHER SUITE RUNNING?" — MATCH comm, NEVER THE COMMAND LINE` · **5,431 chars**

### BEFORE (structure, abridged)

- 1 opening line of context
- ✅ the correct `ps -eo comm,args` command block
- ✅ the three-pattern reported-vs-truth table
- 2 numbered paragraphs on the two failure modes, naming three seats by name
- ⇒ the `comm`-vs-command-line ruling
- 🔴 Tiffany's count-instability finding: attribution, 28-sample table, "on her own misreading"
- 🔴 Mr. Radio's correctness-vs-diligence framing paragraph
- ⇒ the ownership ruling
- ✅ the MINE / PEER / UNKNOWN script block
- ⚠️ the environ-unreadable warning + ruling
- ⚠️ "the receipt for why this is worth a section" — four minutes, her own coverage run
- 🔴 the tagger-without-gate ruling
- ⚠️ the synthetic-input limit

### AFTER (proposed, ~1,450 chars — 3.7:1)

> ### 🔴 "IS ANOTHER SUITE RUNNING?" — ASK OWNERSHIP, NEVER A COUNT
>
> Two ways to get the process match wrong, pointing opposite directions:
>
> | pattern | reported | truth |
> |---|---|---|
> | `pgrep -f "\-m pytest"` | 0 | missed a live run — the script form has no `-m pytest` |
> | `pgrep -af "pytest"` | 5 | four spurious — **a seat's spawn briefing IS its command line** |
> | `comm`-based (below) | 1 | ✅ |
>
> ```bash
> ps -eo comm,args --no-headers | awk '$1=="pytest" || ($1 ~ /^python/ && $0 ~ / -m pytest/)'
> ```
>
> `comm` answers *what this process is*; the command line answers *what someone wrote about it*.
>
> 🔴 **And a COUNT is unstable even off the correct command.** Over one unchanging run, 28 samples
> returned **1** twenty-four times and **2** four times — the coverage gate spawns transient
> children. `… | wc -l` then `-eq 0` cannot be made reliable by being careful.
>
> ⇒ **Ask ownership: is any pytest here NOT mine?** Emit MINE / PEER / UNKNOWN per process, keyed
> on `/proc/<pid>/environ`'s `LUPIN_ROOT` **or** `readlink /proc/<pid>/cwd` — print which you used,
> and emit **UNKNOWN** when neither is readable rather than PEER.
> ⇒ **QUIET means zero PEER *and* zero UNKNOWN.** *"I could not tell whose this is"* must never
> resolve to *"go ahead"*.
>
> ⚠️ The both-unreadable branch is proven as logic, **never observed live**.
> [full tagger script + receipts → doctrine/testing-venues.md § another-suite-running]

**What moved**: the seat attributions, the two-failure-mode prose, the correctness-vs-diligence
paragraph, the four-minute anecdote, and the full 8-line tagger loop.
**What stayed**: both commands (one inline, one pointed at), the table, all three ⇒ rulings, and
the scope limit — because a reader deciding whether to trust UNKNOWN needs it at the point of use.

## 3. Sample B — a MEASUREMENT-HEAVY section. The table stays, the history goes.

`### 🔴 A TIER RUN FROM A WORKTREE REPORTS 10 OR 11 FAILURES…` · **10,678 chars**

### BEFORE

The operative content is a **conditional artifact table** and a **three-variable pin command**.
Around it sit: five separate reconciliation passes (2026-08-29 `3d01df71`, 08-30 Rio `cc336880`,
08-30 Maya `a4fd4551`, 09-04 Cheech `dc96a65b`, 09-05 Tiffany `d74f5851`), each with its own
arm tables, its own scope note, and a paragraph reconciling it against the previous one; plus
two corrections where an author narrowed his own claim.

### AFTER (proposed, ~2,100 chars — 5:1)

> ### 🔴 A TIER RUN FROM A WORKTREE REPORTS FAILURES THE MAIN TREE DOES NOT HAVE
>
> **Pin all three, every time — the first is inherited from your shell and silently wrong:**
>
> ```bash
> cd <worktree> && LUPIN_ROOT="$PWD" PYTHONPATH="$PWD/src" .venv/bin/python -m pytest src/tests/unit/ -q
> ```
>
> `LUPIN_ROOT` decides which tree paths RESOLVE against; `PYTHONPATH` decides which tree modules
> are IMPORTED from. Pin one and not the other and your run's modules come from **two checkouts —
> a tree that exists nowhere on disk**, and a mutation that never lands reads as a guard that holds.
>
> **Then subtract the environment artifacts — do not chase them. `ls` first; the file is the
> coordinate and the count is derived from it:**
>
> | missing | check | failures |
> |---|---|---|
> | `src/scripts/cloud-run.env` (gitignored) | `ls src/scripts/cloud-run.env` | **9** absent · **0** present |
> | `src/terraform/envs/test/.terraform/providers` | — | 1 |
> | `.venv` | `ls .venv/bin/python` | **33** |
> | `LUPIN_ROOT` unpinned | — | 1 |
>
> ⚠️ Provisioning runs in the PYTHON spawn path only — a hand-typed `git worktree add` gets
> nothing and sees all of them.
> ⚠️ **A failure that passes in the main tree has TWO explanations**: a worktree artifact, or a fix
> you do not have yet. `git log --oneline <your-sha>..<main-HEAD> -- <test path>` names the commit;
> ancestry alone only narrows the suspects.
>
> [five reconciliation passes, arm tables and scope notes → doctrine/worktree-tiers.md]

**What moved**: every dated measurement narrative and its reconciliation.
**What stayed**: the command, the conditional table with its `ls` discriminator, and the
two-explanations warning — which is a rule you apply while reading a red.

## 9. One defect in this work, and how it was caught

The first splitter treated a `# comment` inside a bash fence as a level-1 heading, so it captured **half**
a section, left the remainder orphaned inline, and **reported a plausible char count** — `OK 12284 chars`
against a true 24,650.

It was caught by a size table that showed `# Find all nested .git directories` owning 118,394 chars, not by
the tool. The file was restored from git and the splitter rebuilt to refuse rather than guess: it now
declines unless the anchor matches exactly once **and** the captured section has balanced fences, and both
refusals were exercised alongside a positive control proving they still allow a valid split.

⇒ Exactly the shape § *a clean exit is not evidence the work happened* describes — **the failure and the
success printed the same thing.**
