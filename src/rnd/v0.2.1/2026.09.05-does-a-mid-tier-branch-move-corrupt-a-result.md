## The design — four arms, one variable

All arms run in a **dedicated detached worktree** (`lupin-wt-tiberius-moveprobe`), never a shared
tree, by one script (`arm.sh`) under identical pins.

| arm | sha | what it does | answers |
|---|---|---|---|
| **A** | `35590594` | full unit tier, no move | `S_A` |
| **B** | `be1d58b2` | full unit tier, no move | precondition — does the pair have RANGE? |
| **A2** | `35590594` | repeat of A | determinism control; **mismatch HALTS before C** |
| **C** | `35590594` → `be1d58b2` | real `git checkout` **120s in, mid-execution** | `S_C` |

**The discriminator.** `S_C` equal to `S_A` or `S_B` ⇒ a mid-tier move hands you *some real tree's*
answer: a **DISCOMFORT**. `S_C` containing members in neither ⇒ a set **no tree on this branch
produces**: a **DEFECT**.

### Why this move pair

`35590594 → be1d58b2` is a real first-parent move from the same day, 10 Python files. It was chosen
as the strongest available case because it changes `src/tests/unit/conftest.py` (+99 lines,
**collection-time**) **and** adds four new test files (21 tests, 6/6/3/6 by `def test_` count).

## 🔴 ONE NUMBER DOING THREE JOBS — which tree, that collection was missed, and therefore what the arm may claim

**C collected 22527 — BASE's exact count, not POST's 22548.** That single figure does three separate
things, and for most of the evening it was being spent on only the first:

1. **WHICH TREE C REPORTED.** 22527/22452 is BASE's pair, to the test. C returned the base tree's
   answer, entire — not a hybrid.
2. **THAT THE MOVE MISSED COLLECTION.** A move landing mid-collection would have produced a
   *mixture* of the two counts. It produced neither mixture nor POST's number. So collection
   **completed at BASE before the move** — proven by the count itself, not assumed from the 120s
   placement.
3. **THEREFORE WHAT THE ARM MAY CLAIM.** Because collection was already finished, this arm tests a
   **post-collection** move and nothing else.

⇒ **So "what a tier measures is fixed at COLLECTION" is closer to a DESCRIPTION OF WHAT WAS TESTED
than to a finding.** A post-collection move changes nothing — that is shown. **A mid-collection move
being safe is NOT shown**, and that is the leading caveat on this whole document, not a footnote.

⚠️ **A gap in the harness that the data cannot close:** no collection-end timestamp was recorded. It
can be proven that collection **finished at BASE**; it cannot be said **by how much it beat the
move**. Those are different strengths of claim. Stamp collection-end next time — pytest's own header
carries it.

### 🔴 An anchor error CANCELS in a difference and SURVIVES in an absolute

Two seats disagreed by 44 seconds about when Rachel joined. The cause: one clock was **reconstructed
from elapsed readings**, the other **read directly** (`date -Is` at each event). The reconstructed
absolutes were off; **the interval computed from them was right**, because the same offset sits in
both ends of a subtraction and drops out.

⇒ **When your clock is reconstructed rather than read, quote DIFFERENCES, not INSTANTS — and say
which kind you have, because the two print identically.**

⇒ And note which claim this makes safest: *"C was alone at the move"* rests on **neither** an
absolute nor an interval. It is two **bracketing samples within one instrument**, so a shared anchor
error moves both together and cannot separate them from the move. **It survives any anchor error in
either observer.** The mirror of *a coordinate is not a reference*: there a coordinate goes stale
where a content-name does not; here an absolute inherits its anchor's error where an interval does
not.

## 🔴 A FOOTNOTE THAT BECAME A FINDING — and a false premise I put in front of the user

While committing this document the repo's own secret scanner refused it, flagging **two lines that
are pytest node ids**. The reflex reading is "false positive, bypass it." Both halves of that were
wrong, and the way they were wrong is this document's own subject.

### What actually fires, measured through the scanner's own `scan_text`

| line | fires? | scanner output |
|---|---|---|
| `test_secret_scan.py::test_a_detector_change_forces_a_full_rescan …` | 🔴 **YES** | `len=80  sha256:78612a902f84` |
| `test_secret_scan.py::test_the_recorded_counts_are_derived_from_the_same_scan …` | 🔴 **YES** | `len=64  sha256:0341b56f08cc` |
| the same two names as a **markdown table row** | ✅ no | `[]` |
| `test_terraform_invariants.py::test_terraform_provider_cache_is_present …` — **same `::` shape** | ✅ no | `[]` |

The sha256 prefixes match the ones the commit hook printed, so this is the same instrument reaching
the same finding, not a lookalike. **The fourth row is the discriminating arm**: an identical `::`
shape does *not* fire, so the trigger is not the punctuation — it is that `::` parses as a
`key: value` assignment whose **key contains the word `secret`** (`_CHEAP_HINTS` at
`secret_scan.py:125`, then `_FIELD` against the key). The scanner is behaving exactly as designed.

⇒ **The fix is therefore a real fix, not a dodge**: split the node id into `file` and `test` columns.
Every character of every name is preserved, the `::` is gone, and the scanner passes **unbypassed**.

produced a fix that needs no bypass at all.
