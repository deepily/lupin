## 1. The ordering rule, and why it shaped everything

**The writer lands after the reader.** Not a preference — a receipt. On 2026-08-31 commit `072ef7e`
landed an instruction naming a file no code created, and `d4f6c29` reverted it; the round trip cost

⇒ So Phase 4 is the **smallest diff in the plan and the last thing landed**, and it ships `False`.

## 2. The asymmetry between the two new words

The part easiest to get subtly wrong, because the obvious shortcut works.

| | `wont_fix` | `not_approved` |
|---|---|---|
| in `VALID_STATUSES` | yes | yes |
| in `TERMINAL_STATUSES` | **yes** | **no — never** |
| hidden from the board | via terminality | via `BOARD_INVISIBLE_STATUSES` |
| mintable at create | no | **yes** |
| out-edges | none (append-only) | every status |

**Terminal membership is not a convenience for `wont_fix`** — it does three things at once: hides
the row from both `notin_( … )` filters in one edit, gives it no out-edges through the *derived*
`LEGAL_TRANSITIONS` graph, and keeps `blocker_is_terminal` honest, since a row blocked on a
won't-fix row genuinely **is** unblocked. Nothing further is coming.

🔴 **And that is exactly why `not_approved` must not borrow it.** Terminality would tell
`blocker_is_terminal` that a row waiting on an unapproved row may proceed — the opposite of the
truth. An unapproved row's whole point is that it is *waiting for movement*. It gets its own
`BOARD_INVISIBLE_STATUSES` instead, **named separately so no future reader mistakes "hidden from the
board" for "finished"**.

### Why `not_approved` is mintable where `parked` is not

Parking is a human ruling **existing** work not-now, so it requires a `park_reason` quoting a row
that already exists. A holding-area row has no history to quote — being unexamined is its whole
content. **It is the state a row is BORN in, not one it is moved to.**

## 3. Decisions taken beyond the design spec

### 3a. `wont_fix` requires a non-blank reason

Added for the same reason `dropped` has it. The receipt gate fires only on `->done`, so a won't-fix
cites **no commit** — the reason is the only thing standing behind it. **A refusal whose
justification is not written down is indistinguishable from the work being forgotten.**

⚠️ This has a client cost that should have been named when the call was made: it turns a one-click
control into a form. María absorbed it into Phase 2 slice 2.

### 3b. The won't-fix gate keys on `to_status` alone — from EVERY source

🔴 **The load-bearing half of Phase 3.** María found, and Rick confirmed (planning-is-prompting
`a1f2697`), that **`wont_fix` COUNTS toward the create/close ratio** while `dropped` does not. So a
seat able to close rows that way holds *both halves* of a mint-by-deletion loop: close to raise the
closed count, then create against the headroom it just manufactured. Approver-only is what shuts it.

⇒ Gating only `not_approved -> wont_fix` would have left the loop **open from `queued`**, which is
where a worker's own rows actually sit. It would have looked implemented and closed nothing.
Tested across all six source statuses, with `dropped` as the **negative control** proving it stays
open to everyone — without that arm, a gate refusing every close would pass the whole section.

⚠️ A UI-only restriction hands every worker that loop. **The button must not be the control.**

### 3c. The gate is a pure function, not inline in the router

It started inline. Inline, the only way to watch it refuse is to stand up a database, mint a row in
the holding area and drive a `PATCH` — so the cheap tests would have asserted on `is_approver` and
**called that the control**. A correct predicate wired to nothing passes every such test.

⇒ As `refusal_for_admission( from_status, to_status, actor )`, all four clauses are observable
directly and a separate test proves the router calls it.

### 3d. Configuration read at CALL time, never a field default

A Pydantic `Field( default=… )` is evaluated at **import**, so the flag would freeze at boot and an
operator's flip would need a restart. That is precisely the asymmetry Rick objected to on the ratio
gate the same day: *the dials he could turn were the ones that changed nothing, and the switch that
mattered was the one he could not reach.*

### 3e. `model_fields_set`, so explicit intent survives the default

An explicit `status="queued"` and an omitted `status` **arrive as the same string** — the field
default makes them identical by value. Without `model_fields_set` a caller who deliberately asked
for a queued mint would be silently redirected, with no way to say what they meant. A test asserts
this on the model itself, so a future Pydantic change reddens *there*, naming the cause.

### 3f. No new mount

A new bind mount resolves at container **CREATE**, so it would need
`docker compose up -d --force-recreate` on both servers before a single approval could work — and a
plain `restart` would apply it silently-not-at-all. The allowlist reuses the already-mounted
flow-ratio directory. ⚠️ The env var's name says flow-ratio and this is not flow-ratio; that
mismatch is deliberate and cheap to fix later. Paying a force-recreate today to avoid a misleading
name is the expensive half of the trade.

## 4. The honest limit, written into the code

🔴 **This is a POLICY control, not a security boundary.** The actor is `payload.actor`, which the
**caller declares**; `require_api_key_or_jwt` proves only that the caller holds a fleet credential,
and every seat holds the same one.

⇒ It refuses an honest caller who is not an approver. It does **not** stop a dishonest one from
typing an approver's name. The authenticated user id is recorded alongside, so a false claim is
**attributable after the fact** — accountability, not prevention. Calling it authorization would
overclaim, and the difference decides what may be concluded from it.

## 6. Cross-lane findings worth keeping

**From María, and sharper than anything on my side today:**

1. **A test that reads source text cannot tell an implementation from an explanation of one** — and
   it fails in the *flattering* direction, because well-commented code is the most likely to satisfy
   a search for what the comment describes. 5 of her 12 guards passed against broken code.
2. **Two of those never ran at all**, because the break string was not unique. ⇒ *A falsification
   pass that does not check its own anchors reports a false green exactly as loudly as a real one.*
3. **A suite that reads a file as text can be entirely green about an application that does not
   start.** She proved it: a stray brace in the actions cell leaves every searched-for string
   intact, so 34 of her tests passed while the browser would fail to parse the script. Fixed at
   `f42c083e`.
4. **The doc is the spec for HOW; the order is the spec for WHAT.** Her Phase 2 bullets listed two
   panes; Rick's words named three. Following the doc would have shipped the gap and called the
   phase done.

**From the re-spin dispute** (row `db56ac6d`), because the instrument generalises:

> A successful rehydration looks exactly like never having cleared, **from the inside**, with a full
> context of recent work. So *"do I remember this session"* is answered confidently and wrongly by
> the one seat best placed to answer it. The instrument that works is the mirror image: **"is there
> work attributed to me that I do not remember?"** — an ABSENCE, which a rehydrated seat can detect
> and a continuous one cannot fake.

⇒ Same family as this repo's standing rule that *an empty result is two failures wearing one face*.
Here a **full** result — complete recall — is two states wearing one face, and in both directions
the only thing that separates them is **asking about the gap rather than about the content**.

## 7. RULED: the holding area is self-expiring

🔨 **Rick, 2026-09-02, by voice**: *"Yes they are self-expiring… like a chase on a parked row."*

⚠️ **He had already answered this once and the answer never arrived.** María asked three times; all
three timed out. **Three timeouts are data about a channel, not about a question** — read as three
refusals they would have looked like a decision to defer, and the feature would have been built on
a default nobody chose.

`holding_is_active( status, next_chase_ts, now )` mirrors `park_is_active` deliberately: expiry
computed at **read** time, never written back. **A sweeper that stops running leaves rows buried
forever, silently; a predicate that stops running returns nothing at all, loudly.**

| arm | behaviour |
|---|---|
| chase in the future | hides — the silence the chase buys |
| **chase come due** | **stops hiding itself** |
| chase absent / unparseable | **surfaces** — fail-loud-toward-visible |
| non-holding status | untouched; status checked first |
| boundary `chase == now` | asserted **EQUAL to** `park_is_active`, not to a literal `False` |

That last row is the one worth defending: he said *like a parked chase*, so if the parked boundary
is ever re-cut the test reddens rather than the two silently drifting apart.

### 🔴 The judgment call: expiry makes a row VISIBLE, not OWED

A parked row rejoins the **owed** count because it provably came from `queued`/`in_progress` — that
subset relation is the restoration proof, asserted at import. A `not_approved` row was **never owed
by anyone**. Re-admitting it to the owed set would poke every seat about work nobody approved —
exactly what that assert forbids.

⇒ The chase does what the ruling asks by returning the row to the **board**, where a human sees an
untriaged pile that stopped hiding. **The thing that must not be silent is the row, not the fleet's
pokes.** Flagged to Rick as a call he can overrule.

### ⚠️ The gap the ruling opened — PROVEN, not asserted

Nothing sets a chase at mint. Measured against the live predicate:

```
freshly minted holding row, chase = None
  holding_is_active   : False
  ~holding_is_active  : True    <- the second OR arm of the board filter
  => shown on main board : True     🔴 BACKWARDS

same row WITH a 72h triage chase
  holding_is_active   : True
  => shown on main board : False    ✅
```

⇒ **A holding row with no chase lands on the main board** — the opposite of what the holding area is
for, and it makes `BOARD_INVISIBLE_STATUSES` inert for that status.

**The fix is a default triage window at mint, not a change to the None handling.** Inverting None to
"hide indefinitely" would reintroduce the unbounded silence the ruling exists to remove. Giving
every holding row a chase makes the ruling *coherent* — expiry then always eventually fires — and
leaves fail-loud-toward-visible as what it should be: an anomaly path for a row minted wrong.

⇒ **María reached the same null-handling independently, from the client side** (`b38d2843`): demote
now requires a triage-by date and stamps a real `next_chase_ts`, and her argument for a null chase
is *"copy park's fail-loud rather than treat a missing chase as infinite silence, since the failure
mode this whole feature exists to stop is a row resting in a bin nobody opens."* Two lanes, one
answer, neither derived from the other.

⚠️ **So the predicate meets a MIXED population**: demoted rows carry a chase, minted ones do not,
until the triage window lands. That is a transient the read-time design absorbs — but it is the
reason the null arm had to be *decided* rather than inherited.

**Verified viable against the live schema** before building on it: the two chase-related CHECK
constraints *require* a chase for `parked` and `blocked`; **none forbids one on any other status**.

### 🔴 And a third instance of the same test defect, from her side

Her new guard asserted the error **message** was present rather than the **condition** that produces
it — so breaking the requirement to `if(false)` left the message sitting in a dead branch and the
test stayed green. **Third instance today**, and she wrote this one *after* building the
comment-stripper fixture specifically to stop it.

⇒ *Knowing the lesson is not the same as applying it while writing.* Which is the argument for
falsifying **every** guard rather than trusting an author who has just learned better — including
when that author is you, an hour later.
