## Context

1001 SWE Team dry-run notification artifacts (`st-*` sender IDs) pollute the user's personal notification feed. The `global_notification_recipient` in `~/.lupin/config` points to `ricardo.felipe.ruiz@gmail.com`, so all test/dry-run notifications land in the personal account.

## Plan

### Phase 1: Create `admin@lupin.deepily.ai` user

The user wants to create this manually (to set their own easy password). The registration endpoint is:

```bash
curl -X POST http://localhost:7999/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email": "admin@lupin.deepily.ai", "password": "YOUR_PASSWORD", "roles": ["admin", "user"]}'
```

**Password requirements**: 8+ chars, 3 of 4 character types (lower, upper, digit, special). No common passwords.

After creation, update `~/.lupin/config`:
```ini
global_notification_recipient = admin@lupin.deepily.ai
```

### Phase 2: Add "Not Mine" filter mode to Notifications UI

Currently: `own` (My Jobs) and `all` (All Users' Jobs)
Add: `others` (Not My Jobs — everything except the logged-in user)

#### Files to modify

**`src/fastapi_app/templates/notifications.html`** (~line 404):
- Add third button: `🚫 Not My Jobs` with id `filter-others-jobs`

**`src/fastapi_app/static/js/notifications.js`**:
- `setFilterMode()` (~line 4987): Handle `'others'` mode, update button states for 3 buttons
- `initializeFilterUI()` (~line 5008): Handle `'others'` in saved preference restore
- Queue fetch URL construction (~line 4901): Pass `?user_filter=!self` or `?user_filter=others` for the new mode
- Button event listener (~line 1390): Add click handler for `filter-others-jobs`

**`src/cosa/rest/routers/queues.py`** (or wherever `/api/get-queue/{name}` lives):
- Handle `user_filter=others` — return jobs where `user_id != current_user_id`

**Notification conversation history** — the filter also needs to apply to the notification sender cards:
- `loadConversationHistory()`: When mode is `others`, only show sender cards NOT associated with the current user
- When mode is `own`, only show sender cards associated with the current user (current behavior)
- When mode is `all`, show everything (current behavior)

### Phase 3: Batch delete for filtered notifications

The "Clear All Notifications" button already exists. When the `others` filter is active, it should only delete the visible (filtered) notifications — not everything.

**`src/fastapi_app/static/js/notifications.js`**:
- The clear/delete function should respect the current filter mode
- When `others` is active and user clicks "Clear All": only delete notifications from senders that are NOT the current user

**`src/cosa/rest/routers/notifications.py`**:
- May need a new endpoint or parameter: `DELETE /api/notifications/clear?scope=others` or `?exclude_user=current`

### Phase 4: Reassign existing 1001 st-* notifications

After creating `admin@lupin.deepily.ai`, bulk-reassign the 1001 SWE Team dry-run notifications from `ricardo.felipe.ruiz@gmail.com` to the new admin account. This is a one-time database operation:

```sql
UPDATE notifications
SET user_id = (SELECT id FROM users WHERE email = 'admin@lupin.deepily.ai')
WHERE sender_id LIKE 'st-%'
AND user_id = (SELECT id FROM users WHERE email = 'ricardo.felipe.ruiz@gmail.com');
```

Or alternatively, just delete them since they're test artifacts.
