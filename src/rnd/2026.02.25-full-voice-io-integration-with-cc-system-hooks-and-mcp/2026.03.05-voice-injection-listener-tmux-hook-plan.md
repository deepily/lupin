# Voice Injection into Claude Code via Notification Listener + tmux + UserPromptSubmit Hook

## Context

Lupin's voice I/O integration (Phases 0-6) built a bidirectional voice channel where Claude Code hooks drain buffered voice messages at tool-call boundaries (Pre/PostToolUse, Stop). However, this **only works when Claude is actively working** — calling tools or finishing a task. When Claude is **idle at the prompt**, there's no hook boundary to trigger message delivery.

This plan implements the missing piece: **direct voice injection into idle Claude Code sessions**. The existing notification pipeline (`POST /api/notify` -> WebSocket -> `CCNotificationListener` -> JSONL buffer) already delivers text to a session-keyed buffer. The new work adds: (1) tmux session discovery so the listener knows which tmux pane to target, (2) a tmux `Enter` keystroke trigger after buffering so Claude wakes up, and (3) a `UserPromptSubmit` hook that drains the buffer and injects content as invisible `additionalContext`.

**Research doc**: `2026.03.05-voice-injection-tmux-buffer-hook-design.md` (same directory)

---

## Architecture: Unified Notification Pipeline

```
User (browser/voice/API)
  |
  +-- POST /api/notify (type=user_initiated_message)     <-- ALREADY EXISTS
  |
  +-- WebSocket push -> CCNotificationListener            <-- ALREADY EXISTS
  |
  +-- Listener writes JSONL buffer                        <-- ALREADY EXISTS
  |     ~/.claude/sessions/cc-buffer-{hash}.jsonl
  |
  +-- Listener sends: tmux send-keys -t {session} Enter   <-- NEW (Phase 2)
  |     (resolves tmux_session from session bridge file)
  |
  +-- UserPromptSubmit hook fires (empty prompt)           <-- NEW (Phase 3)
        +-- drain_voice_buffer() (existing JSONL drain)
        +-- format + enrich voice context
        +-- emit additionalContext -> Claude processes
```

No new FastAPI endpoint needed. No separate `.txt` buffer format. The existing notification -> listener -> JSONL buffer pipeline is reused end-to-end.

---

## Design Decisions

| ID | Decision | Rationale |
|----|----------|-----------|
| D1 | Reuse existing JSONL buffer (no new `.txt` format) | Single buffer format for all voice delivery. Listener already writes JSONL; hooks already drain it. |
| D2 | Listener triggers tmux Enter after buffering (no new API endpoint) | Keeps the delivery pipeline unified: notify -> WS -> listener -> buffer -> tmux -> hook. No new server-side code. |
| D3 | Scan `~/.claude/sessions/cc-*.json` for session lookup (no index) | Typically <10 files. O(1) in practice. |
| D4 | Add tmux discovery to `register_session.py` | Production hook currently does NOT write `tmux_session`. Prerequisite for the listener to know where to send Enter. |
| D5 | Hooks registered globally in `~/.claude/settings.json` | All existing hooks are registered there (verified). Per-project `.claude/settings.local.json` only has permissions. |
| D6 | `start-cc-with-tmux.sh` as the tmux launcher name | Clear, descriptive name matching project script conventions. |

## Listener Event Handling -- Order of Operations

When a user sends a message (e.g., from browser voice input or API call), this is the exact sequence:

```
1. POST /api/notify (type=user_initiated_message, job_id={session_hash})
      |
2. Server creates NotificationItem, pushes via WebSocket to all user sessions
      |
3. CCNotificationListener._handle_event( "notification_queue_update", event_data )
   |  a. Check event_type == "notification_queue_update"
   |  b. Extract notification dict from event_data
   |  c. Check notif_type == "user_initiated_message"
   |  d. Check job_id == self.session_id_hash
   |  e. -> Match! Proceed to buffer + respond
      |
4. _buffer_message( notification )
   |  a. Build entry dict (message, priority, job_id, sender_id, timestamp)
   |  b. Append JSONL line to ~/.claude/sessions/cc-buffer-{hash}.jsonl
   |  c. flush() immediately
      |
5. _send_gist_response( notification )
   |  a. Gister generates 3-5 word summary
   |  b. Sends "Received: {gist}" notification back to browser user
      |
6. _trigger_tmux_enter()                                    <-- NEW
   |  a. Resolve tmux_session from session bridge file (cached)
   |  b. subprocess: tmux send-keys -t {session} Enter
   |  c. Claude Code receives empty prompt submission
      |
7. UserPromptSubmit hook fires                              <-- NEW
   |  a. drain_voice_buffer() atomically consumes JSONL buffer
   |  b. format_voice_context() -> "[Voice]: user message"
   |  c. enrich_voice_context() -> appends "IMPORTANT: acknowledge..." reminder
   |  d. emit additionalContext -> Claude processes the voice command
```

## Phase 2: Listener tmux Trigger

### 2.1 Add tmux Enter trigger to `cc_notification_listener.py`

**File**: `src/lupin_cli/claude_code/hooks/lib/cc_notification_listener.py`

After `_buffer_message()` writes to the JSONL file, add a call to trigger tmux:

```python
def _trigger_tmux_enter( self ):
    """Send bare Enter to the CC session's tmux pane to wake the UserPromptSubmit hook."""
    tmux_session = self._resolve_tmux_session()
    if not tmux_session:
        self._log( f"{self.LOG_PREFIX} No tmux session found -- skipping Enter trigger" )
        return
    try:
        subprocess.run(
            [ "tmux", "send-keys", "-t", tmux_session, "Enter" ],
            capture_output=True, timeout=2
        )
        self._log( f"{self.LOG_PREFIX} Sent Enter to tmux session '{tmux_session}'" )
    except ( subprocess.TimeoutExpired, FileNotFoundError, subprocess.CalledProcessError ) as e:
        self._log( f"{self.LOG_PREFIX} tmux Enter failed: {e}" )
```

`_resolve_tmux_session()` reads `~/.claude/sessions/cc-*.json` matching `self.session_id_hash` and extracts the `tmux_session` field. Cache the result after first resolution.

Call `_trigger_tmux_enter()` at the end of `_buffer_message()`, after the JSONL write + flush.

### 2.2 Add `--tmux-session` CLI arg (optional override)

Allow explicit tmux session name as CLI argument (for testing/debugging):
```bash
python -m lupin_cli.claude_code.hooks.lib.cc_notification_listener \
    --session-id abc12345 --tmux-session my-project
```

If not provided, auto-resolves from session bridge file.

## Phase 3: UserPromptSubmit Hook

**File**: `src/lupin_cli/claude_code/hooks/user_prompt_submit.py` (NEW)

Core logic:
1. `read_hook_input()` -- parse payload from stdin
2. Resolve `session_id` from payload (or `get_claude_session_id()` fallback)
3. `drain_and_acknowledge( session_id )` -- drain the existing JSONL buffer
4. `format_voice_context( messages )` -- format as `[Voice]: ...` strings
5. If content: `emit_json( build_additional_context( enrich_voice_context( ctx ) ) )`
6. If no content: `emit_json( {} )` -- normal prompt flow (user typed something manually)

**Reuses entirely from `hook_common.py`**: `drain_and_acknowledge`, `format_voice_context`, `enrich_voice_context`, `build_additional_context`, `read_hook_input`, `emit_json`, `log_payload`, `send_tts`.

**No new functions needed in hook_common.py** -- the JSONL drain path is already complete.

**Design constraints**:
- Must be lightweight (CC hook timeout ~10s default)
- No network I/O in critical path (`send_tts` is fire-and-forget)
- Follows exact same bootstrap + import pattern as `pre_tool_use.py`
