## Context

The Claude Code hook system has 7 working hooks prefixed with `test_` from Phase 0 validation. Three hooks (SessionStart, PermissionRequest, SessionEnd) are already production-quality with full voice buffer drain, listener lifecycle management, and blocking sync notifications. Four hooks (PostToolUse, PreToolUse, Stop, Notification) are observation-only passthroughs that log + send TTS + emit `{}`.

**Goal**: Rename all 7 hooks (drop `test_` prefix), add voice buffer drain + acknowledge to the 4 passthrough hooks, and enhance the Notification hook to include CC message content in TTS. **No context injection into CC's execution flow** — hooks drain the buffer and acknowledge via TTS, then emit `{}` passthrough.

**Bonus**: Include a manual testing guide for running `cc_notification_listener.py` in a standalone shell.

## Step 8: Enhance Notification Hook

**File**: `src/lupin_cli/claude_code/hooks/notification.py`

Include the `message` field content in TTS for all notification types, especially `permission_prompt`:

```python
# Current (generic):
tts_msg = f"Hook fired: Notification — type {notification_type}"

# Enhanced (includes message content):
if notification_type == "permission_prompt":
    tts_msg = f"Permission prompt: {message}" if message else "Permission prompt"
elif notification_type == "idle_prompt":
    tts_msg = f"Idle: {message}" if message else "Claude is waiting for input"
else:
    tts_msg = f"Notification ({notification_type}): {message[:80]}" if message else f"Notification: {notification_type}"
```

Note: CC currently sends `"Claude Code needs your attention"` for permission_prompt — generic, but at least the user hears it. If CC enriches the payload in the future, it'll flow through automatically.

## Appendix: Manual Listener Testing Guide

### Running the listener in a standalone shell

```bash
# Terminal 1: Start the listener with debug output
cd /mnt/DATA01/include/www.deepily.ai/projects/lupin
export PYTHONPATH="$PWD/src:$PYTHONPATH"

python -m lupin_cli.claude_code.hooks.lib.cc_notification_listener \
    --session-id test1234 \
    --debug
```

The listener will:
1. Read credentials from `~/.claude/notification-hooks-credentials.ini` `[lupin]` section
2. Authenticate via JWT against the FastAPI server (port 7999)
3. Connect via WebSocket and subscribe to `notification_queue_update`
4. Filter for `user_initiated_message` notifications where `job_id == "test1234"`
5. Buffer matches to `~/.claude/sessions/cc-buffer-test1234.jsonl`

### Sending a test message (Terminal 2)

First get a JWT token, then POST a notification:

```bash
# Get JWT token
TOKEN=$(curl -s -X POST http://localhost:7999/api/login \
    -H "Content-Type: application/json" \
    -d '{"email":"claude.code@lupin.deepily.ai","password":"YOUR_PASSWORD"}' \
    | python3 -c "import sys,json; print(json.load(sys.stdin)['access_token'])")

# Send a user_initiated_message targeting session "test1234"
curl -X POST http://localhost:7999/api/notify \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer $TOKEN" \
    -d '{
        "message": "Hello from voice input test!",
        "type": "user_initiated_message",
        "sender_id": "manual-test",
        "target_user": "YOUR_EMAIL",
        "job_id": "test1234",
        "priority": "normal"
    }'
```

### Watching the buffer (Terminal 3)

```bash
# Watch the buffer file grow
tail -f ~/.claude/sessions/cc-buffer-test1234.jsonl

# Or manually drain it (simulates what hooks do)
python3 -c "
import sys
sys.path.insert(0, '$PWD/src')
from lupin_cli.claude_code.hooks.lib.hook_common import drain_voice_buffer
msgs = drain_voice_buffer('test1234')
for m in msgs:
    print(f'Drained: {m[\"message\"]}')
print(f'Total: {len(msgs)} messages')
"
```

### Shutting down

Send SIGTERM to the listener:
```bash
kill $(pgrep -f "cc_notification_listener.*test1234")
```

The listener will print session statistics (messages buffered, buffer state) before exiting.
