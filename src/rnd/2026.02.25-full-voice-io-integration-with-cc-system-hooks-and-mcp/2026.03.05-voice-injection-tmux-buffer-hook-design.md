# Voice Command Injection via tmux + Buffer File + UserPromptSubmit Hook

## System Overview

This system enables hands-free voice command injection into running Claude Code
sessions. Voice-transcribed text is written to a session-keyed buffer file, then
a bare `Enter` keystroke is sent to the correct tmux session. Claude Code's
`UserPromptSubmit` hook reads the buffer and injects the text as invisible
system context. Claude processes the command without anything appearing in the
prompt input field.

### End-to-End Flow

```
1. Voice transcription written to ~/.claude/voice_buffers/{SESSION_ID}.txt
2. tmux send-keys -t {TMUX_SESSION} Enter        (empty prompt submitted)
3. UserPromptSubmit hook fires                    (Claude Code calls hook)
4. Hook reads buffer file                         (voice text loaded)
5. Hook deletes buffer file                       (consumed, single-use)
6. Hook returns JSON with additionalContext        (stdout → Claude Code)
7. Claude receives the voice command invisibly     (system-level context)
8. Claude processes the command                    (as if instructed directly)
```

The CLI text box stays empty. No text is typed into the prompt. The voice
command arrives as `additionalContext` — system context attached to an empty
prompt — invisible to the user but fully actionable by Claude.

## Component 1: Launch Script

Spawns a Claude Code instance inside a named tmux session. The tmux session
name becomes the deterministic handle used to target `send-keys` later.

### `launch_claude.sh`

```bash
#!/bin/bash
# ──────────────────────────────────────────────────────────────
# launch_claude.sh — Spawn Claude Code in a named tmux session
#
# Usage:
#   ./launch_claude.sh my-project          # named session
#   ./launch_claude.sh my-project --init   # with init hook
#   ./launch_claude.sh                     # auto-generated name
#
# The tmux session name is the key that links everything:
#   - SessionStart hook discovers it via pane PID lookup
#   - Lupin resolves session_id → tmux name for send-keys
#   - You attach/detach freely from any SSH session
# ──────────────────────────────────────────────────────────────

NAME="${1:-cc-$(date +%s | md5sum | cut -c1-8)}"
EXTRA_ARGS="${@:2}"

# Check if session already exists
if tmux has-session -t "$NAME" 2>/dev/null; then
    echo "Session '$NAME' already exists. Attaching..."
    tmux attach -t "$NAME"
    exit 0
fi

# Launch Claude Code inside tmux
# 'read' at the end prevents pane from closing on exit
tmux new-session -d -s "$NAME" \
    "claude $EXTRA_ARGS; echo ''; read -p 'Session ended. Press Enter to close.'"

echo "Launched: $NAME"
echo "Attach:   tmux attach -t $NAME"
echo "Send cmd: tmux send-keys -t $NAME Enter"
```

### Session management commands

```bash
# List all running Claude Code sessions
tmux list-sessions

# Attach to a session (from any SSH connection)
tmux attach -t my-project

# Detach from current session (back to shell)
# Ctrl+b then d

# Kill a session
tmux kill-session -t my-project
```

## Component 2: SessionStart Hook — Register tmux Mapping

When Claude Code starts, this hook captures the `session_id` from stdin JSON,
discovers which tmux session owns the process, and writes both to a session
file. This is the bridge between Claude Code's internal session_id and tmux's
external addressing.

### `~/.claude/hooks/register_session.py`

```python
#!/usr/bin/env python3
"""
SessionStart hook: register session_id → tmux session mapping.

Writes to:
  ~/.claude/sessions/cc-{PPID}.json

Also exports CLAUDE_SESSION_ID via CLAUDE_ENV_FILE so Bash
tool commands can reference $CLAUDE_SESSION_ID.
"""
import json
import os
import subprocess
import sys
from pathlib import Path


SESSION_DIR = Path.home() / ".claude" / "sessions"


def find_tmux_session(ppid: int) -> str | None:
    """Discover which tmux session owns our parent process."""
    try:
        result = subprocess.run(
            ["tmux", "list-panes", "-a", "-F",
             "#{session_name} #{pane_pid}"],
            capture_output=True, text=True, timeout=2
        )
        if result.returncode != 0:
            return None

        for line in result.stdout.strip().splitlines():
            parts = line.rsplit(" ", 1)
            if len(parts) == 2 and int(parts[1]) == ppid:
                return parts[0]

        # Claude Code's direct parent may be a shell; check grandparent
        try:
            with open(f"/proc/{ppid}/stat") as f:
                gppid = int(f.read().split()[3])
            for line in result.stdout.strip().splitlines():
                parts = line.rsplit(" ", 1)
                if len(parts) == 2 and int(parts[1]) == gppid:
                    return parts[0]
        except (FileNotFoundError, IndexError, ValueError):
            pass

    except (subprocess.TimeoutExpired, FileNotFoundError):
        pass

    return None


def main():
    try:
        data = json.load(sys.stdin)
    except (json.JSONDecodeError, EOFError):
        sys.exit(0)

    session_id      = data.get("session_id", "")
    transcript_path = data.get("transcript_path", "")
    cwd             = data.get("cwd", "")

    if not session_id:
        sys.exit(0)

    ppid = os.getppid()
    tmux_session = find_tmux_session(ppid)

    # ── Write session file ───────────────────────────────────
    SESSION_DIR.mkdir(parents=True, exist_ok=True)
    session_file = SESSION_DIR / f"cc-{ppid}.json"

    session_data = {
        "session_id":      session_id,
        "transcript_path": transcript_path,
        "cwd":             cwd,
        "ppid":            ppid,
        "tmux_session":    tmux_session,
    }

    session_file.write_text(json.dumps(session_data, indent=2))

    # ── Export to CLAUDE_ENV_FILE ─────────────────────────────
    env_file = os.getenv("CLAUDE_ENV_FILE")
    if env_file:
        with open(env_file, "a") as f:
            f.write(f"export CLAUDE_SESSION_ID='{session_id}'\n")
            f.write(f"export CLAUDE_TMUX_SESSION='{tmux_session or ''}'\n")

    # ── Inject context so Claude knows its session_id ─────────
    output = {
        "hookSpecificOutput": {
            "hookEventName":    "SessionStart",
            "additionalContext": f"Session ID: {session_id}"
        }
    }
    print(json.dumps(output))
    sys.exit(0)


if __name__ == "__main__":
    main()
```

## Component 3: UserPromptSubmit Hook — Voice Injection

This is the core mechanism. It reads a session-keyed buffer file on every
prompt submission. If a file exists, its contents are injected as
`additionalContext` and the file is deleted. If no file exists, the hook
exits cleanly and the prompt proceeds normally.

### `~/.claude/hooks/voice_inject_hook.py`

```python
#!/usr/bin/env python3
"""
UserPromptSubmit hook: inject buffered voice commands.

On every prompt submission (including empty Enter):
  1. Check for buffer file keyed by session_id
  2. If found: read text, delete file, inject as additionalContext
  3. If not found: exit 0, normal prompt flow

The buffer file is written by an external process (voice daemon,
Lupin server, or manual testing via voice_send.sh).
"""
import json
import sys
from pathlib import Path


BUFFER_DIR = Path.home() / ".claude" / "voice_buffers"


def main():
    try:
        data = json.load(sys.stdin)
    except (json.JSONDecodeError, EOFError):
        sys.exit(0)

    session_id = data.get("session_id", "default")
    buffer_file = BUFFER_DIR / f"{session_id}.txt"

    # No buffer → normal prompt flow
    if not buffer_file.exists():
        sys.exit(0)

    # Read and consume the buffer
    try:
        voice_text = buffer_file.read_text().strip()
        buffer_file.unlink()
    except OSError:
        sys.exit(0)

    if not voice_text:
        sys.exit(0)

    # Inject as invisible system context
    output = {
        "hookSpecificOutput": {
            "hookEventName": "UserPromptSubmit",
            "additionalContext": f"[Voice command]: {voice_text}"
        }
    }
    print(json.dumps(output))
    sys.exit(0)


if __name__ == "__main__":
    main()
```

## Component 4: Voice Send Utility

The external trigger. Writes the voice text to the buffer file, then sends
a bare Enter to the target tmux session. This is what Lupin (or a manual
test) calls to inject a voice command.

### `voice_send.sh`

```bash
#!/bin/bash
# ──────────────────────────────────────────────────────────────
# voice_send.sh — Write voice text to buffer + trigger Enter
#
# Usage:
#   ./voice_send.sh <session_id> <tmux_session> "your command"
#
# Example:
#   ./voice_send.sh a1b2c3d4 my-project "run the test suite"
# ──────────────────────────────────────────────────────────────

SESSION_ID="$1"
TMUX_SESSION="$2"
TEXT="${@:3}"

if [ -z "$SESSION_ID" ] || [ -z "$TMUX_SESSION" ] || [ -z "$TEXT" ]; then
    echo "Usage: $0 <session_id> <tmux_session> \"command text\""
    exit 1
fi

BUFFER_DIR="$HOME/.claude/voice_buffers"
mkdir -p "$BUFFER_DIR"

# Step 1: Write to buffer
echo "$TEXT" > "$BUFFER_DIR/$SESSION_ID.txt"

# Step 2: Send bare Enter to trigger the hook
tmux send-keys -t "$TMUX_SESSION" Enter

echo "Sent: '$TEXT' → session $SESSION_ID via tmux $TMUX_SESSION"
```

### Python equivalent for Lupin integration

```python
import subprocess
from pathlib import Path

def send_voice_command(session_id: str, tmux_session: str, text: str):
    """Write buffer + trigger Enter in the correct tmux session."""
    buffer_dir = Path.home() / ".claude" / "voice_buffers"
    buffer_dir.mkdir(parents=True, exist_ok=True)

    # Write buffer
    (buffer_dir / f"{session_id}.txt").write_text(text)

    # Trigger hook via bare Enter
    subprocess.run(
        ["tmux", "send-keys", "-t", tmux_session, "Enter"],
        check=True
    )
```

## Component 5: Hook Configuration

Register both hooks in `~/.claude/settings.json`:

```json
{
  "hooks": {
    "SessionStart": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "python3 ~/.claude/hooks/register_session.py"
          }
        ]
      }
    ],
    "UserPromptSubmit": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "python3 ~/.claude/hooks/voice_inject_hook.py"
          }
        ]
      }
    ]
  }
}
```

After editing, restart Claude Code. Hooks are snapshotted at startup.

```bash

# Claude Code is now at the prompt

# Terminal B: Check the session file for session_id
cat ~/.claude/sessions/cc-*.json

# Terminal B: Send a voice command
```


## How It Connects to CoSA/Lupin

In the full production architecture, `voice_send.sh` is replaced by Lupin's
FastAPI endpoint:

```
Microphone → STT pipeline → Lupin /api/voice-command/{session_id}
    → Lupin resolves session_id → tmux_session (from session file)
    → Lupin writes buffer file
    → Lupin calls: tmux send-keys -t {tmux_session} Enter
    → UserPromptSubmit hook fires → Claude processes voice command
```

The Stop hook (see companion design doc) handles the reverse case: draining
buffered voice commands that arrived while Claude was working, and asking the
user via `notify_user_sync` if they want to continue.

Together, the two hooks create a bidirectional voice channel:

```
Voice IN  → buffer file + Enter → UserPromptSubmit hook → Claude works
Voice OUT ← notify_user_sync   ← Stop hook             ← Claude finishes
```
