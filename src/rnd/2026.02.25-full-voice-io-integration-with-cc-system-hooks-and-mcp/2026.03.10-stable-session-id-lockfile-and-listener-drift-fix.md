# Stable Session ID Persistence Across CC Lifecycle

**Date**: 2026-03-10
**Session**: 335
**Status**: Implementation Plan (Review-Revised)
**Review**: All 5 issues from code review incorporated. See `-review.md` for original findings.

## Context

Claude Code generates a new UUID v4 session ID on **every lifecycle event** (start, resume, `/clear`, context compaction). The Lupin voice I/O system depends on a stable session identity for notification routing between the MCP server, CC Notification Listener, and browser UI. Two problems exist:

1. **Listener drift bug** (Session 334): After context clears, the listener filters by the transient hash but the MCP server and browser route notifications using the stable hash — causing voice messages from the browser to be rejected by the listener.

2. **Fragile stable ID chain**: The `stable_session_id` is currently preserved by reading the old bridge file before overwriting it. If that read fails (race condition, corruption, file missing), the stable ID is lost. The MCP server stores it in-memory, but the MCP server can crash/restart at any time.

## Approach: Write-Once Lockfile + Listener Fix

### Phase 1: Write-Once Stable ID Lockfile

**File**: `src/lupin_cli/claude_code/hooks/register_session.py`

Create `~/.claude/sessions/cc-stable-{ppid}.id` — a plain text file containing just the stable session ID. Written once on first SessionStart for a given CC PID, never overwritten. This replaces the fragile "read old bridge file to carry forward stable ID" chain.

**Replace lines 404-421** (context clear detection block) with:

```python
# ── Context clear detection ──────────────────────────────────
# Write-once lockfile is the source of truth for stable ID.
# Uses open('x') (O_CREAT|O_EXCL) for atomic creation — safe against
# the documented double-fire on `--continue` (two concurrent SessionStart hooks).
stable_lockfile = os.path.join( session_dir, f"cc-stable-{cc_pid}.id" )
try:
    # Attempt atomic create — succeeds only for the first SessionStart of this PID
    with open( stable_lockfile, "x" ) as f:
        stable_session_id = session_id
        f.write( stable_session_id )
except FileExistsError:
    # Lockfile already exists — this is a subsequent lifecycle event (clear, compact, resume)
    # or the second concurrent hook on --continue. Read the winner's stable ID.
    try:
        with open( stable_lockfile ) as f:
            stable_session_id = f.read().strip()
    except OSError as e:
        # Lockfile exists but unreadable (corruption, permission denied).
        # Log to stderr (hooks emit to stderr without polluting Claude's context),
        # then establish a new stable anchor rather than silently diverging.
        print( f"[register_session] WARNING: failed to read lockfile {stable_lockfile}: {e}",
               file=sys.stderr )
        stable_session_id = session_id
        try:
            with open( stable_lockfile, "w" ) as f:
                f.write( stable_session_id )
        except OSError:
            pass  # Best-effort recovery

    # Detect context clear by comparing transient IDs in the bridge file
    if os.path.exists( session_file ):
        try:
            with open( session_file ) as f:
                old_data = json.load( f )
            old_session_id = old_data.get( "session_id", "" )
            if old_session_id and old_session_id != session_id:
                is_context_clear = True
                _cleanup_old_listener( old_data, session_id )  # session_id = new transient UUID, keep its listener alive
        except ( json.JSONDecodeError, OSError ):
            pass
except OSError as e:
    # Cannot create lockfile at all (permissions, disk full).
    # Fall back to transient session_id — stability guarantee lost for this session.
    print( f"[register_session] WARNING: failed to create lockfile {stable_lockfile}: {e}",
           file=sys.stderr )
    stable_session_id = session_id
```

**Review fixes incorporated**:
- **Issue #1 (TOCTOU race)**: Replaced `exists()` + `open('w')` with atomic `open('x')` + `FileExistsError` handler
- **Issue #2 (OSError fallback)**: Logs to stderr and overwrites corrupted lockfile instead of silently diverging
- **Issue #4 (argument naming)**: Added inline comment at `_cleanup_old_listener` call site

### Phase 2: Pass Stable ID to Listener (The Drift Fix)

**File**: `src/lupin_cli/claude_code/hooks/register_session.py` — line 476

Change:
```python
listener_pid = _spawn_listener( session_id, session_data if session_id else None, session_file )
```
To:
```python
listener_pid = _spawn_listener( stable_session_id, session_data if session_id else None, session_file )
```

This makes the listener filter on the **same hash** that the MCP server uses for `sender_id` and the browser uses for `job_id`. After context clear, the new listener still matches browser notifications because both use the stable hash.

### Phase 3: Listener `accepted_ids` Set (Hardening)

To:
```python

```

**File**: `src/lupin_cli/claude_code/hooks/register_session.py` — `_spawn_listener()`

Pass both stable and transient hashes:
```python

# On subsequent lifecycle events (compact, clear), they diverge and both are needed.

```

This ensures the listener accepts notifications routed by either hash, covering edge cases where some component hasn't caught up to the stable hash convention.

### Phase 4: Stale Lockfile Cleanup

**File**: `src/lupin_cli/claude_code/hooks/register_session.py` — lines 454-462

Extend the stale file purge to also clean up `cc-stable-*.id` files:

```python
if entry.startswith( "cc-" ) and ( entry.endswith( ".json" ) or entry.endswith( ".id" ) ):
```

And exclude the current lockfile from cleanup:
```python
if fpath != session_file and fpath != stable_lockfile:
```

Add PID liveness check before purging lockfiles to guard against PID reuse:

```python
def _is_live_cc_process( pid_str ):
    """Check if a PID corresponds to a live process (not necessarily CC, but alive)."""
    try:
        pid = int( pid_str )
        os.kill( pid, 0 )  # signal 0 = existence check, no signal sent
        return True
    except ( ProcessLookupError, ValueError ):
        return False
    except PermissionError:
        return True  # Process exists but we can't signal it — don't purge

# In the cleanup loop for .id files:
match = re.match( r"cc-stable-(\d+)\.id", entry )
if match and not _is_live_cc_process( match.group( 1 ) ):
    os.remove( fpath )
```

**Review fix incorporated**:
- **Issue #3 (PID reuse)**: Added `os.kill(pid, 0)` liveness check before purging stale lockfiles

### Phase 5: MCP Server Recovery (Low Priority)

**File**: `src/lupin_mcp/cosa_voice_mcp.py`

The MCP server already reads `stable_session_id` from the bridge file via `_read_session_file()`. On restart, it re-reads the bridge file (Phase 1 of the watcher thread). Since Phase 1 of this plan guarantees the bridge file's `stable_session_id` is always correct (sourced from lockfile), no MCP changes are strictly needed.

Optional: add lockfile as a fallback read path in the watcher's initial resolution, for the edge case where the bridge file is missing but the lockfile exists.
