## Tier 2: Smoke Tests

**File**: `src/tests/smoke/test_expeditor_mock_job_smoke.py`

Follows exact pattern from `test_deep_research_dry_run_smoke.py`: Login -> Submit -> Verify -> Poll -> Verify results. Uses `/api/mock-job/submit` endpoint.

### Test Structure

```
quick_smoke_test():
  Test 1: Login & get token (env vars)
  Test 2: Health check - GET /api/mock-job/health
  Test 3: Standard mock job (no voice_command) - verify baseline works
  Test 4: Expeditor test - POST with voice_command="do deep research on quantum computing"
          -> Verify command matching, args_resolved in config, dry_run=True
  Test 5: Verify dry-run job completes in done queue ($0.00 cost)
```

**Important constraints for Tests 4-5:**
- The expeditor calls LLM for gap analysis (real inference cost)
- The expeditor calls `notify_user_sync()` for missing args (blocks for user response)
- Tests 4-5 need: `LUPIN_INTERACTIVE_TESTS=true` env var AND user present to answer prompts
- Skip mechanism: env var check in `quick_smoke_test()` with early return after test 3

**Smoke Test Total: 5 tests** (3 automated, 2 interactive)

## Mocking Strategy

| Component | Mock Target | How |
|-----------|-------------|-----|
| `subprocess.run` | `agent_registry.subprocess.run` | `@patch` with MagicMock |
| `_help_cache` | `agent_registry._help_cache` | `.clear()` in setUp |
| Job classes | `cosa.agents.*.job.*Job` (source modules) | `@patch` returning MagicMock |
| No mocks needed | `ExpeditorResponse`, `_parse_lora_args` | Pure functions |
