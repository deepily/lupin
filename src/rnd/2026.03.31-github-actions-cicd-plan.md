# Plan: GitHub Actions CI/CD for Lupin

## Context

The Lupin repo has zero CI/CD today — no `.github/workflows/` at the project root. The project has 2,691 unit tests across 99 files, all heavily mocked and self-contained. There are also integration, WebSocket, and E2E UI test suites, but those require a running server and database.

This plan adds CI/CD in two phases: Phase 1 is free (pytest + ruff), Phase 2 adds paid Claude Code-powered PR review.

---

## Current Testing Infrastructure

| Item | Detail |
|------|--------|
| Python version | 3.11 |
| Test framework | pytest 8.4.2 |
| Unit tests | 2,691 tests in 99 files (`src/tests/unit/`) |
| Unit test speed | ~5s collection, fast execution (mocked deps) |
| Required env var | `LUPIN_ROOT` (conftest.py bootstrap) |
| pytest config | `pytest.ini` at project root |
| Main requirements | `src/cosa/requirements.txt` (265 packages, includes torch, spacy, transformers) |
| Test requirements | `requirements-test.txt` (pytest, pytest-asyncio, pytest-cov) |
| Linting tools | None configured (no ruff, flake8, pylint, or pyproject.toml) |
| Existing CI | None at Lupin root |

### CI Challenge: Heavy Dependencies

The full `requirements.txt` includes PyTorch (~2 GB), spacy, transformers, flash-attn, lancedb, etc. Installing everything on every push would take 5-10 minutes and consume significant GitHub Actions minutes.

**Mitigation strategy**: Cache the pip install between runs using `actions/cache`. First run is slow (~8 min), subsequent runs with cache hit take ~30-60s for install.

# PHASE 1: Free Tier (Unit Tests + Ruff Linting)

## New Files to Create

### 1. `.github/workflows/ci.yml`

Single workflow with two jobs running in parallel:

```yaml
name: CI

on:
  push:
    branches: [ main, 'wip-*' ]
    paths-ignore:
      - '*.md'
      - 'history/**'
      - 'src/rnd/**'
      - 'src/docs/**'
  pull_request:
    branches: [ main ]

jobs:
  unit-tests:
    runs-on: ubuntu-latest
    timeout-minutes: 15

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: '3.11'

      - name: Cache pip packages
        uses: actions/cache@v4
        with:
          path: ~/.cache/pip
          key: ${{ runner.os }}-pip-${{ hashFiles('src/cosa/requirements.txt', 'requirements-test.txt') }}
          restore-keys: ${{ runner.os }}-pip-

      - name: Install dependencies
        run: |
          pip install --upgrade pip
          pip install -r src/cosa/requirements.txt
          pip install -r requirements-test.txt

      - name: Run unit tests
        env:
          LUPIN_ROOT: ${{ github.workspace }}
        run: pytest src/tests/unit/ -v --tb=short

  lint:
    runs-on: ubuntu-latest
    timeout-minutes: 5

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: '3.11'

      - name: Install ruff
        run: pip install ruff

      - name: Run ruff (bugs only)
        run: ruff check src/cosa/ src/fastapi_app/
```

**Key design decisions**:
- **Triggers**: Push to `main` and `wip-*` branches (matching your branch naming convention), plus PRs to `main`
- **Path ignoring**: Skip CI for markdown-only changes (history, docs, rnd)
- **Parallel jobs**: Lint runs in ~10s on a separate runner while tests install deps
- **Cache**: Pip cache keyed on requirements file hashes — dramatically speeds up repeat runs
- **flash-attn**: This package requires CUDA to install. If it fails in CI (no GPU), we may need to add `--no-deps` or exclude it. Unit tests mock GPU code, so it's only needed for importability. Fallback: install everything except flash-attn and torch GPU extensions.

### 2. `ruff.toml`

Configured to catch **bugs and bad practices only**, respecting your custom style:

```toml
# Ruff configuration for Lupin project
# Bug-catching only — custom style rules are enforced by CLAUDE.md conventions

target-version = "py311"

[lint]
# Only enable rules that catch real bugs, not style
select = [
    "F",      # Pyflakes — unused imports, undefined names, redefined unused
    "E9",     # Runtime errors — syntax errors, IO errors
    "W6",     # Deprecated features
    "B",      # Bugbear — common Python pitfalls (mutable defaults, assert, etc.)
    "S",      # Bandit — security issues (hardcoded passwords, SQL injection, etc.)
    "UP",     # pyupgrade — deprecated Python patterns
    "RUF",    # Ruff-specific rules
]

# Explicitly ignore ALL style/formatting rules
ignore = [
    # Whitespace rules (conflict with spaces-inside-parens preference)
    "E1", "E2", "E3",
    # Import ordering (handled by convention, not enforced)
    "I",
    # Line length (not enforced)
    "E501",
    # Bandit rules that are too noisy for this project
    "S101",   # assert usage (used extensively in tests)
    "S603",   # subprocess calls (needed for GPU management)
    "S607",   # partial executable path
]

# Exclude nested repos and generated files
[lint.per-file-ignores]
"src/lupin-mobile/**" = ["ALL"]
"src/lupin-plugin-firefox/**" = ["ALL"]
"src/tests/**" = ["S", "B"]  # Skip security/bugbear in tests
".venv/**" = ["ALL"]

exclude = [
    ".venv",
    "src/lupin-mobile",
    "src/lupin-plugin-firefox",
    "__pycache__",
    "*.pyc",
]
```

**What ruff catches** (the valuable stuff):
- Unused imports and undefined names (`F`)
- Unreachable code, redefined variables (`F`)
- Mutable default arguments (`B006`)
- Bare `except:` clauses (`B001`, `E722`)
- Security anti-patterns: hardcoded passwords, SQL injection, weak crypto (`S`)
- Deprecated Python patterns (`UP`)

**What ruff ignores** (respecting your style):
- All whitespace rules (E1xx, E2xx, E3xx) — your spaces-inside-parens, dict alignment, etc.
- Import ordering — you group by convention
- Line length — not enforced

### 3. Potential Issue: `flash-attn` in CI

`flash-attn` requires CUDA headers to install and will fail on a CPU-only GitHub runner. Options:

| Option | Trade-off |
|--------|-----------|
| **A. Install with `--ignore-installed` and catch ImportError** | Tests that mock CUDA code still work; flash-attn just isn't importable |
| **B. Create `requirements-ci.txt`** | Curated subset excluding GPU-only packages. More maintenance. |
| **C. Use `pip install --no-deps flash-attn`** | Skips build, installs metadata only. May not work. |
| **D. Comment out flash-attn for CI** | Simplest but diverges from production deps |

**Recommendation**: Option B — create a `requirements-ci.txt` that references the main requirements but excludes `flash-attn` and installs CPU-only torch. This keeps CI fast and clean.

### New File: `requirements-ci.txt`
```
# CI-specific requirements — CPU-only, no CUDA
--find-links https://download.pytorch.org/whl/cpu
torch==2.6.0+cpu

# Everything else from main requirements (minus flash-attn)
-r src/cosa/requirements.txt
```

With a corresponding filter step in the workflow:
```bash
grep -v 'flash.attn' src/cosa/requirements.txt > /tmp/requirements-filtered.txt
pip install --find-links https://download.pytorch.org/whl/cpu -r /tmp/requirements-filtered.txt
```

# PHASE 2: Paid Services (Claude Code PR Review)

**Prerequisite**: Phase 1 working. Anthropic API key available.

## Setup

Run `/install-github-app` from Claude Code terminal to:
1. Install the Claude GitHub App on the Lupin repo
2. Configure `ANTHROPIC_API_KEY` as a repository secret
3. Generate a starter workflow

## New File: `.github/workflows/claude-review.yml`

```yaml
name: Claude Code Review

on:
  pull_request:
    types: [opened, synchronize]

jobs:
  review:
    runs-on: ubuntu-latest
    timeout-minutes: 10

    steps:
      - uses: actions/checkout@v4

      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          prompt: |
            Review this PR for:
            1. Logic errors and potential bugs
            2. Security vulnerabilities
            3. Adherence to the project's CLAUDE.md code style conventions
            4. Design by Contract docstring completeness
            5. Prohibited patterns (defensive getattr chains, fragile path manipulation)
            Post inline comments on specific lines where issues are found.
```

**What Claude reviews against your actual conventions**:
- Spaces inside parentheses and brackets
- Vertically aligned `=` signs and dict colons
- Design by Contract docstrings on new functions
- No `getattr()` chains with fallbacks
- `cu.get_project_root()` instead of `Path(__file__).parent` chains
- Double quotes for string delimiters
- One-line conditionals for simple checks

### Optional: Claude Code Security Review

```yaml
      - uses: anthropics/claude-code-security-review@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
```

Specialized security scanner — catches OWASP Top 10 patterns in diffs.
