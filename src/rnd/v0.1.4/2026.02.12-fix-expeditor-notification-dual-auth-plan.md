# Plan: Fix Expeditor Notification Delivery via Dual-Auth + voice_io.py

## Context

After fixing the `emit_to_user()` envelope nesting (previous plan — implemented), the live proxy test still fails: the expeditor's notification never reaches the proxy, causing "User cancelled unexpectedly."

**Symptom chain**:
1. Smoke test POSTs to `/api/mock-job/submit` (JWT auth as `interactive.job.tester@lupin.deepily.ai`)
2. Expeditor finds `query` missing → `_ask_for_arg()` → `notify_user_sync()` → POSTs to `/api/notify`
3. `/api/notify` requires `X-API-Key` header (bcrypt validated) → **401** (key not registered in DB)
4. `_ask_for_arg()` returns None → `expedite()` returns None → mock job returns `"cancelled"`
5. Smoke test reports "User cancelled unexpectedly" — no failure reason shown

**Root cause**: `/api/notify` only supports API key auth. The expeditor runs inside the server process (via `asyncio.to_thread`) where the user is already JWT-authenticated, but `notify_user_sync()` can't use that JWT — it must load an API key from a config file, and that key's bcrypt hash isn't in the `api_keys` table.

**Fix**: Add dual-auth (`X-API-Key` or `Bearer JWT`) to `/api/notify`, thread the JWT through the expeditor chain, and fix `voice_io.py`.

## Changes

### Change 1: Create `require_api_key_or_jwt()` dependency

**File**: `src/cosa/rest/middleware/api_key_auth.py`

Add a new dependency that accepts EITHER authentication method:

```python
async def require_api_key_or_jwt(
    x_api_key: Annotated[str | None, Header()] = None,
    authorization: Annotated[str | None, Header()] = None
) -> str:
    """
    Dual-auth: accepts X-API-Key header OR Authorization: Bearer <jwt>.
    Returns user_id (UUID string) on success, raises 401 on failure.
    """
    # Option 1: API key
    if x_api_key:
        if not re.match( r'^ck_live_[A-Za-z0-9_-]{64,}$', x_api_key ):
            raise HTTPException( status_code=401, detail="Invalid API key format" )
        user_id = await validate_api_key( x_api_key )
        if user_id:
            return user_id
        raise HTTPException( status_code=401, detail="Invalid or inactive API key" )

    # Option 2: Bearer JWT
    if authorization and authorization.startswith( "Bearer " ):
        token = authorization[ 7: ]
        from cosa.rest.auth import verify_token
        user_info = await verify_token( token )
        return user_info[ "uid" ]

    raise HTTPException(
        status_code=401,
        detail="Missing auth. Provide X-API-Key or Authorization: Bearer <jwt>",
        headers={ "WWW-Authenticate": "API-Key, Bearer" }
    )
```
