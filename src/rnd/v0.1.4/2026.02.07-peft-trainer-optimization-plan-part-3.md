## Executive Summary

After Parts 1-2 of the optimization series (results dashboard, explicit routing, quantization strengthening, skip_empty/skip_comments fix), training data generation reveals that 4 "simple" agent-routing commands are drastically under-sampled:

| Command | Current | Target | Gap |
|---------|---------|--------|-----|
| automatic routing mode | 60 | 1500 | 96% |
| none | 214 | 1500 | 86% |
| math | 450 | 1500 | 70% |
| todo list | 443 | 1500 | 71% |

All other commands hit 1500. The root cause is architectural: **compound commands** (weather, date-and-time, calendar, receptionist) multiply template lines by placeholder values (e.g., 100 templates × 199 cities = 19,900 raw → 1500 sampled), while **simple commands** generate exactly 1 sample per template line with no multiplication.

---

## Root Cause Analysis

### Simple vs. Compound Command Architecture

**Compound commands** (`build_compound_agent_router_training_prompts()` at `xml_coordinator.py:336`):
```
for raw_line in raw_lines[ 0:100 ]:        # up to 100 templates
    for args in arguments:                  # 199 placeholder values
        voice_command = raw_line.replace( placeholder, args )  # genuine semantic variation
```
Result: 100 × 199 = 19,900 raw samples → 1500 after sampling.

**Simple commands** (`build_simple_agent_router_training_prompts()` at `xml_coordinator.py:595`):
```
for raw_line in raw_lines:                  # N template lines
    insert_interjection( random.choice() )  # 1 random interjection
    prepend_salutation( random.choice() )   # 1 random salutation
```
Result: N raw samples. No multiplication loop.

The `_prune_duplicates_and_sample()` method takes `min(target, available)` per command — so if a command only produces 450 samples, that's the ceiling.

### Why Not Just Increase the Augmentation Factor?

At 25x for automatic-routing (60 lines), 96% of training data would share one of only 60 core semantic patterns. The LORA model would learn to ignore salutations/interjections rather than learn intent boundaries. This is a known issue in LORA fine-tuning: repetitive patterns with superficial variation cause the adapter to memorize surface patterns.

---

## Strategy: Hybrid (Template Expansion + Controlled Augmentation)

**Principle**: Templates provide semantic diversity (heavy lifting). A controlled augmentation factor provides the final boost to reach 1500. Keep the factor low (3-8x) to avoid training on near-duplicates.

### Per-Command Plan

| Command | Current Lines | Expand To | Aug Factor | Raw Output | Post-Dedup Est. |
|---------|--------------|-----------|------------|------------|-----------------|
| automatic routing mode | 60 | ~200 | 8x | 1600 | ~1520 |
| none | 214 | ~500 | 3x | 1500 | ~1480 |
| math | 450 | ~500 | 3x | 1500 | ~1480 |
| todo list | 443 | ~500 | 3x | 1500 | ~1480 |

## Part 1: Template Expansion (4 files)

### `synthetic-data-agent-routing-automatic-routing-mode.txt` (60 → ~200)

Current 60 lines are all imperative ("Switch back to automatic"). Add ~140 more in these categories:
- **Conversational**: "I think I'd like to go back to automatic now", "Actually, just let the system decide"
- **Questioning**: "Can you switch me back to auto mode?", "How do I get back to normal routing?"
- **Indirect/contextual**: "I don't need the math agent anymore", "I'm done with direct mode"
- **Polite/casual**: "Thanks, you can go back to picking the right agent", "Never mind the direct mode"
- **Negative framing**: "Stop using the calendar agent", "Cancel this mode", "Exit agent mode"

Augmentation factor of 8x is justified here because:
- The semantic space is genuinely narrow (all mean "go back to auto")
- What the model needs to learn is recognizing this intent DESPITE conversational wrapping
- "Hey Carla, um, can you switch back?" teaches looking past decorations

## Part 2: Code Change — Augmentation Factor in Simple Builder

### File: `src/cosa/training/xml_coordinator.py`

**Modify `build_simple_agent_router_training_prompts()`** (line ~595) to accept an `augmentation_config` dict that specifies per-command factors. Default to factor=1 (preserving current behavior).


Pass the config when calling:
