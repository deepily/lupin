## Part 1: Confirmation Loop Design

### Flow (inserted after arg collection, before job creation)

```
expedite() existing flow:
  1. Registry lookup
  2. Capture CLI help
  3. Parse LORA args
  4. Map LORA → CLI names
  5. LLM gap analysis
  6. If complete → collect present args
  7. If incomplete → ask for each missing arg
  8. Inject system args

NEW step 9: _confirm_and_iterate()
  ┌─────────────────────────────────────────────────────────────┐
  │ Build human-readable summary (user-facing args only):      │
  │                                                             │
  │   "Here's what I have for your deep research job:          │
  │    • Topic: quantum computing                              │
  │    • Audience: beginner                                    │
  │    • Budget: no limit                                      │
  │                                                             │
  │    Does this look right? Say 'yes' to proceed,             │
  │    'cancel' to abort, or tell me what to change."          │
  └─────────────────────────────────────────────────────────────┘
                            │
                    User responds via voice
                            │
              ┌─────────────┼─────────────┐
              │             │             │
         "yes/go/ok"    "cancel"    "change budget to 50"
              │             │             │
         Return args    Return None   LLM parses intent
                                         │
                                  ArgConfirmationResponse:
                                    action="modify"
                                    arg_name="budget"
                                    new_value="50"
                                         │
                                  Update args_dict
                                         │
                                  Re-present summary
                                         │
                                  ← Loop back to prompt
```

### New XML Model: `ArgConfirmationResponse`

Added to `src/cosa/agents/runtime_argument_expeditor/xml_models.py`:

```python
class ArgConfirmationResponse( BaseXMLModel ):
    """
    Parses user intent during argument confirmation loop.

    <response>
        <action>modify</action>
        <arg_name>budget</arg_name>
        <new_value>50</new_value>
    </response>
    """
    action    : str = Field( ..., description="User intent: 'approve', 'modify', or 'cancel'" )
    arg_name  : str = Field( ..., description="Argument to modify (empty if approve/cancel)" )
    new_value : str = Field( ..., description="New value for the argument (empty if approve/cancel)" )

    def is_approval( self ):
        return self.action.strip().lower() in ( "approve", "yes", "ok" )

    def is_cancel( self ):
        return self.action.strip().lower() in ( "cancel", "stop", "quit" )

    def is_modify( self ):
        return self.action.strip().lower() == "modify"

    @classmethod
    def get_example_for_template( cls ):
        return cls( action="modify", arg_name="budget", new_value="50" )
```

Registered in `MODEL_MAPPING` (prompt_template_processor.py):
```python
'argument confirmation' : ArgConfirmationResponse,
```

## Part 3: Expanded Smoke Test (9 Scenarios)

### Scenario Matrix

| # | ID | Voice Command | Agent | Key Arg | Missing? | User Action |
|---|-----|---------------|-------|---------|----------|-------------|
| 1 | `DR_HAPPY` | `"do deep research on quantum computing"` | deep research | `query` | No | Confirm summary |
| 2 | `DR_MISSING` | `"do some deep research"` | deep research | `query` | Yes | Provide topic → confirm |
| 3 | `DR_BUDGET` | `"do deep research on climate change with a budget of 5 dollars"` | deep research | `query` | No | Confirm summary |
| 4 | `DR_AUDIENCE` | `"do deep research on machine learning for a beginner audience"` | deep research | `query` | No | Confirm (audience extracted) |
| 5 | `PG_MISSING` | `"make me a podcast"` | podcast gen | `research` | Yes | Pick file → confirm |
| 6 | `PG_AUDIENCE` | `"make me a podcast for an expert audience"` | podcast gen | `research` | Yes | Pick file → confirm |
| 7 | `RTP_HAPPY` | `"research quantum gravity and turn it into a podcast"` | res-to-pod | `query` | No | Confirm summary |
| 8 | `RTP_MISSING` | `"I want research to podcast"` | res-to-pod | `query` | Yes | Provide topic → confirm |

Every non-cancel scenario includes the confirmation step. The user must say "yes" (or similar) after seeing the argument summary before the job is submitted.
