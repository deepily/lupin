# TTS Mode Switching Design

**Date**: 2025.07.12  
**Purpose**: Add dynamic switching between OpenAI batch TTS and ElevenLabs streaming TTS  
**Status**: Design Phase  
**Priority**: Medium - Enhancement to existing speech system
**Related**: Builds on `2025.07.12-audio-to-speech-renaming-design.md`

## Executive Summary

### Problem Statement
Currently, the speech synthesis system uses a single TTS approach, but users have different preferences for speech response timing:
- Some users prefer **immediate feedback** (streaming) even if it builds up over time
- Other users prefer **reliable delivery** (batch) with consistent, complete audio
- Current system doesn't provide choice between these fundamentally different user experiences

### Solution Overview
**Core Principle**: Provide meaningful user choice between two distinct TTS philosophies

Add dynamic mode switching:
- **"Instant" Mode**: ElevenLabs streaming TTS for immediate gratification
- **"Reliable" Mode**: OpenAI batch TTS for consistent, complete audio
- **User preference storage** with intelligent fallback strategies

### Implementation Benefits
1. **User Choice**: Optimize experience for individual preferences (speed vs reliability)
2. **Enhanced Responsiveness**: Sub-second speech initiation for urgent notifications
3. **Resilient Architecture**: Multiple TTS providers increase overall system reliability
4. **Future Foundation**: Groundwork for advanced context-aware audio features

## User Experience Philosophy Analysis

### The Fundamental Experience Difference

This isn't simply about "two TTS providers" - it represents **two completely different user experience philosophies**:

#### "Batch Processing" Philosophy (OpenAI)
- **Optimizes for**: Reliability, consistency, audio quality
- **User mindset**: "I can wait a moment for a perfect response"
- **Best for**: Important notifications, business contexts, unreliable networks
- **Latency profile**: Higher initial delay (2-3s), but guaranteed complete playback
- **Trade-off**: Longer wait time for more polished result

#### "Real-Time Streaming" Philosophy (ElevenLabs)  
- **Optimizes for**: Immediate gratification, perceived responsiveness
- **User mindset**: "I want to hear something RIGHT NOW, even if it builds up"
- **Best for**: Casual interactions, real-time conversations, impatient users
- **Latency profile**: Starts almost immediately (~0.5s), but can have streaming hiccups
- **Trade-off**: Immediate response with potential for incomplete delivery

### Real-World User Scenarios

#### Scenario A: Power User Developer
- **Need**: Immediate feedback during coding sessions
- **Choice**: "Instant" mode
- **Willing to trade**: Occasional streaming glitches for immediate response
- **Benefit**: Notification feels like real-time conversation

#### Scenario B: Business Professional  
- **Need**: Reliable delivery of important notifications
- **Choice**: "Reliable" mode
- **Priority**: Never miss a notification due to streaming failure
- **Benefit**: Consistent, polished audio experience

#### Scenario C: Context-Aware User (Future Enhancement)
- **Need**: Best of both worlds
- **Choice**: "Smart" mode
- **Behavior**: 
  - High priority alerts → Stream instantly
  - Long notifications → Batch process
  - Normal alerts → User preference

## Technical Architecture Design

### Current Flow (Post-Speech Migration)
```
speech_update event → handleSpeechUpdate() → hybridTTS.speak() → /api/get-speech
```

### Enhanced Flow with Dynamic Switching
```
speech_update event → handleSpeechUpdate() → 
  ↓
  Check TTS Mode Preference
  ↓
  ┌─ Mode: "instant" → ElevenLabs Streaming → /api/get-speech-elevenlabs
  └─ Mode: "reliable" → OpenAI Batch → /api/get-speech
```

### Architecture Components

#### 1. Enhanced HybridTTS Class
```javascript
class EnhancedHybridTTS {
  constructor(options = {}) {
    this.mode = localStorage.getItem('tts-mode') || 'reliable';
    this.fallbackEnabled = true;
    this.apiUrlBatch = '/api/get-speech';
    this.apiUrlStreaming = '/api/get-speech-elevenlabs';
  }
  
  async speak(text, options = {}) {
    const mode = options.mode || this.mode;
    
    try {
      switch(mode) {
        case 'instant':
          return await this.streamingSpeak(text, options);
        case 'reliable':
          return await this.batchSpeak(text, options);
        default:
          throw new Error(`Unknown TTS mode: ${mode}`);
      }
    } catch (error) {
      if (this.fallbackEnabled) {
        return await this.fallbackSpeak(text, options, mode);
      }
      throw error;
    }
  }
  
  async streamingSpeak(text, options) {

    // Connect to WebSocket, stream audio chunks
  }
  
  async batchSpeak(text, options) {

    // Wait for complete audio before playback

}
```

#### 3. Intelligent Fallback Strategy
```javascript
async fallbackSpeak(text, options, failedMode) {
  console.warn(`TTS mode '${failedMode}' failed, attempting fallback`);
  
  // If streaming failed, try batch
  if (failedMode === 'instant') {
    this.showUserFeedback('Switching to reliable mode...');
    return await this.batchSpeak(text, options);
  }
  
  // If batch failed, try streaming
  if (failedMode === 'reliable') {
    this.showUserFeedback('Trying instant mode...');
    return await this.streamingSpeak(text, options);
  }
}
```
