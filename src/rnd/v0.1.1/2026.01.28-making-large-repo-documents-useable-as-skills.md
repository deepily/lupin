# Making large repository documentation AI-accessible: The 2026 practitioner's guide

The shift from "prompt engineering" to **context engineering** represents the most significant evolution in AI-assisted development. Successful teams obsessively manage context through SKILL.md files, MCP servers, and strategic documentation placement—because context degradation is the primary failure mode in AI coding assistants. The emerging consensus favors **static files with LLM-based search** over traditional RAG for code-adjacent documentation, while MCP servers handle real-time external data. This report synthesizes practical implementations from late 2024 through January 2026.

## The Claude Code Skills architecture powers contextual knowledge delivery

Claude Code Skills represent a modular, open-standard architecture (agentskills.io) now adopted across Claude Code, GitHub Copilot, and Claude Agent SDK. Every skill requires a **SKILL.md file** with YAML frontmatter and Markdown content:

```markdown
---
name: testing-patterns
description: Jest testing patterns for this project. Use when writing tests, creating mocks, or following TDD workflow.
---

# Testing Patterns

## When to Use
- Writing new tests
- Creating mock functions
- Following TDD workflow

## Test Type Selection

### Smoke Tests (Quick Validation)
**Use when:** Verifying basic functionality after deployment, CI/CD quick checks
**Caveats:** Don't rely on for comprehensive coverage; keep under 5 minutes

### Integration Tests
**Use when:** Testing component interactions, verifying API contracts
**Caveats:** Requires test database setup; budget ~30s per test; may have flaky tests

## Anti-Patterns
- ❌ Testing implementation details
- ❌ Shared mutable state between tests
```

The **description field is critical for discovery**—Claude's system prompt loads only metadata (~100 tokens) at startup, then pulls full instructions (<5k tokens) when triggered. Practitioners encode conditional knowledge through decision trees: "Creating new content? → Follow Creation workflow. Editing existing? → Follow Editing workflow." The official Anthropic skills repository at github.com/anthropics/skills contains production examples for PDF processing, document editing, and a meta-skill for creating other skills.

The standard directory structure places skills in `.claude/skills/` for project-scoped, team-shared knowledge:

```
.claude/
├── skills/
│   ├── testing-patterns/
│   │   └── SKILL.md
│   ├── api-conventions/
│   │   └── SKILL.md
│   │   └── references/
│   │       └── endpoints.md
```

Progressive disclosure is the dominant pattern—keep SKILL.md under **500 lines** and reference detailed documentation in separate files. From Anthropic's official guidance: "Write trigger-rich descriptions that include both WHAT the skill does AND WHEN to use it."

## MCP servers enable dynamic documentation injection based on intent

The Model Context Protocol, donated to the Linux Foundation's Agentic AI Foundation in December 2025, has become the de-facto standard for connecting AI agents to external tools. Three MCP server architectures dominate documentation retrieval:

**Context7** (43k GitHub stars) automatically injects library-specific documentation. When a user asks "Create a Next.js middleware for JWT auth," Context7 detects the intent, resolves "Next.js" to its library ID, and retrieves version-specific documentation—eliminating hallucinations from outdated training data:

```json
{
  "mcpServers": {
    "context7": {
      "url": "https://mcp.context7.com/mcp",
      "headers": { "CONTEXT7_API_KEY": "YOUR_KEY" }
    }
  }
}
```

**GitMCP** (6.9k stars) transforms any GitHub repository into a documentation hub. Configure it as `gitmcp.io/{owner}/{repo}` to expose `fetch_documentation`, `search_documentation`, and `search_code` tools that Claude can call when working with that repo.

**docs-mcp-server** provides self-hosted documentation indexing with semantic search. It scrapes websites, GitHub, npm, and PyPI, then chunks documentation while preserving code blocks and tables:

```python
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("documentation-server")

@mcp.tool()
async def search_docs(query: str, library: str) -> str:
    """Search documentation for a library.
    
    Args:
        query: Search query describing what to find
        library: Name of library (e.g., react, nextjs)
    """
    results = await vector_search(library, query)
    return format_results(results)
```

Intent detection works through tool descriptions. The LLM analyzes user prompts, matches intent against available tool schemas (loaded via `tools/list`), extracts parameters from natural language, and invokes the appropriate documentation retrieval function. The "progressive disclosure" pattern—loading tool metadata first, full schemas only when selected—reduces token overhead significantly.

## Static files beat traditional RAG for code-adjacent documentation

Community consensus strongly favors static files with LLM-based search over traditional RAG. From a synthesis of 12 practitioner sources: "RAG introduces hidden failure modes: What similarity function? What reranker? How to chunk code? LLM Search looks at 10 lines to understand structure, looks at 10 more if needed—just like humans."

| Approach | Best For | Community Rationale |
|----------|----------|-------------------|
| **Static files (CLAUDE.md)** | Project conventions, build commands, universal rules | Always-on context, version controlled, team-shareable |
| **Skills (on-demand)** | Domain-specific workflows, conditional instructions | Loaded when needed, preserves token budget |
| **MCP servers** | Real-time external data, API references | Dynamic retrieval for constantly-changing content |
| **Traditional RAG** | Large doc bases, rapidly changing content | Noted: 87% of enterprise RAG deployments fail ROI expectations |

The emerging **hybrid pattern** uses CLAUDE.md for universal context (<100 lines), Skills for domain-specific instructions (loaded contextually), and MCP for external documentation and APIs. A practitioner warning from extensive Claude Code usage: "If you're using more than **20k tokens of MCPs**, you're crippling Claude. That only gives you 20k tokens left for actual work before context is cooked."

When RAG is necessary—for very large documentation bases—Anthropic's **Contextual Retrieval** approach reduces failed retrievals by up to 67%. It prepends chunk-specific context before embedding: transforming "The company's revenue grew by 3%" into "This chunk is from an SEC filing on ACME Corp's Q2 2023 performance; previous quarter revenue was $314M. The company's revenue grew by 3%." Hybrid search combining semantic embeddings with BM25 keyword matching consistently outperforms single-method approaches by **5-10 percentage points**.

## Large codebases demand aggressive context window management

With Claude Code consuming ~20k tokens baseline for system prompts and tools, context engineering becomes critical at scale. Cursor 2.0's Composer addressed this by training with codebase-wide semantic search built directly into the model. Claude Code users rely on several strategies:

**The dev docs system** (cited across 4+ sources) structures working memory:
```
~/dev/active/[task-name]/
├── [task-name]-plan.md      # Accepted plan
├── [task-name]-context.md   # Key files, decisions
└── [task-name]-tasks.md     # Work checklist
```

**Token-conscious session management** includes aggressive use of `/clear` between unrelated tasks, `/catchup` to read changed files after context reset, and monitoring via `/context` command. Fresh sessions in monorepos consume ~10% of context window just for baseline orientation.

Chunking strategies vary by content type. **Semantic chunking** (grouping sentences by embedding similarity) provides context-aware boundaries but at higher computational cost. **Document structure-based chunking** using headers and sections works well for structured documentation. Code requires language-specific splitters to avoid breaking functions. Snowflake's research recommends **300 tokens per chunk with 20% overlap** for optimal retrieval.

The **"lost in the middle" problem** persists even with 200k context windows—relevant information buried in long documents gets missed. Practitioners address this through careful context curation rather than dumping entire files. One practitioner's rule: "If Claude struggles to understand your codebase, your cognitive load is too high—both for the AI and for developers maintaining the code."

## Community discourse reveals clear patterns and anti-patterns

The developer community across GitHub, Reddit (430k+ members on r/ClaudeAI), and Discord has converged on several key insights.

**CLAUDE.md authoring guidance**: Keep it under **300 lines** (HumanLayer: "Our root CLAUDE.md is less than sixty lines"). Claude's system prompt includes a reminder that context "may or may not be relevant"—meaning it may ignore overly long content. Focus on what Claude gets wrong, not general best practices. From How_I_Use_Every_Feature: "❌ Don't: Write comprehensive manual. ✅ Do: Document what Claude gets wrong."

**Critical anti-patterns** identified across multiple sources:

- **Kitchen sink sessions**: Starting one task, switching to unrelated work, polluting context. Fix: `/clear` between unrelated tasks.
- **Over-correcting loops**: Claude wrong → correct → still wrong → correct again. Fix: After 2 failed corrections, `/clear` and write a better initial prompt.
- **Over-specified CLAUDE.md**: Too long, Claude ignores half. Fix: If Claude does it correctly without the instruction, delete it.
- **Auto-formatting hooks**: Can consume 160k tokens in 3 rounds. Fix: Run formatters manually between sessions.

**Planning before coding is non-negotiable** for production work—unanimous across 8+ sources. Anthropic's official guidance: "Steps #1-#2 are crucial—without them, Claude tends to jump straight to coding a solution." Use "think", "think hard", or "ultrathink" for deeper analysis phases.

**Cursor-specific insight** from Elementor Engineers: "After a few messages, rules are being ignored. My educated guess is it's due to built-in context window optimization where recency wins. You have to maintain periodic rule reinforcement—explicitly add 'remember the rules' after conversation."

## Conclusion

The trajectory from late 2024 through January 2026 shows a maturing ecosystem where **context engineering—not prompt engineering—determines success**. Static SKILL.md files with progressive disclosure handle project-specific knowledge; MCP servers like Context7 and GitMCP dynamically inject external documentation; and aggressive context management through `/clear` and token monitoring prevents degradation.

The counterintuitive finding: traditional RAG often fails for code-adjacent documentation. LLM-based file search, where Claude uses ripgrep and find commands to explore as needed, produces more reliable results. When RAG is necessary, Contextual Retrieval with hybrid search (BM25 + embeddings) and reranking achieves 67% improvement over naive approaches.

Practitioners should start with minimal CLAUDE.md files documenting what the AI gets wrong, implement Skills for conditional workflows like "smoke vs integration test caveats," add MCP servers only for genuinely dynamic external data (keeping total MCP tokens under 20k), and plan before coding—always. The community wisdom is clear: less configuration produces better results, because the primary failure mode isn't missing instructions—it's context pollution and degradation.
