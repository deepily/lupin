# Design: Semantic Session Names for Notifications UI

**Project**: LUPIN
**Date**: 2026.01.14
**Session**: 57
**Status**: Ready for implementation

## Summary

Enhance the notification UI's session identification by adding:
1. **Smarter auto-naming** - Extract action verbs + key nouns instead of first 4 words
2. **localStorage persistence** - Session names survive page refresh
3. **Inline edit capability** - Click to rename sessions manually
4. **Generate Gist button** - LLM-powered summary from conversation history

---

## Current State

Session 56 introduced conversation identity with:
- **Session ID format**: `claude.code@{project}.deepily.ai#{session_id}` (e.g., `#a1b2c3d4`)
- **Auto-naming**: `generateSessionName()` extracts first 4 words from first message
- **Display**: `LUPIN #a1b2c3d4 Session Name` in sender card header

**Current `generateSessionName()` (line 4572):**
```javascript
generateSessionName( firstMessage ) {
    if ( !firstMessage ) return 'Session';
    const cleaned = firstMessage.replace( /^\[[A-Z]+\]\s*/, '' );  // Remove [LUPIN] prefix
    const words = cleaned.split( /\s+/ ).slice( 0, 4 );            // First 4 words
    const name = words.join( ' ' );
    return name.length > 30 ? name.substring( 0, 27 ) + '...' : name;
}
```

**Current limitations:**
1. **Not persisted** - Regenerated on each `createSenderCard()` call
2. **Not editable** - Users can't rename sessions
3. **First 4 words may be generic** - "Hello, I need help..." vs "JWT token bug"

## Design Space

### Dimension 1: Name Generation Strategy

| Strategy | Pros | Cons |
|----------|------|------|
| **A. First N words** (current) | Simple, fast, deterministic | May not capture essence |
| **B. Keyword extraction** (TF-IDF) | More representative | Requires all messages, complex |
| **C. LLM summarization** | Best quality | API cost, latency, backend changes |
| **D. User-provided only** | Most accurate | Friction, users won't bother |
| **E. Hybrid: Auto + Editable** | Best of both worlds | Slightly more UI complexity |

### Dimension 2: Storage Location

| Location | Pros | Cons |
|----------|------|------|
| **A. localStorage** (keyed by session_id) | No backend changes, instant | Lost on clear, per-device |
| **B. Backend database** (new column/table) | Persistent across devices | Schema changes, API updates |
| **C. Notification metadata** | No new tables | Denormalized, complex updates |
| **D. Derived on-the-fly** (current) | No storage | Not stable, not customizable |

### Dimension 3: Update Timing

| Timing | Pros | Cons |
|--------|------|------|
| **A. Once, from first message** | Simple, stable | May not reflect evolution |
| **B. Periodically updated** | More accurate | Potentially confusing |
| **C. On-demand regeneration** | User control | Requires explicit action |

### Dimension 4: Display Format

```
A. Separate line:
   LUPIN #a1b2c3d4
   JWT token bug fix

B. Inline with separator:
   LUPIN #a1b2c3d4 · JWT token bug fix

C. Name-first (ID on hover):
   LUPIN · JWT token bug fix

D. Current (name after ID):
   LUPIN #a1b2c3d4 JWT token bug fix
```

---

## Recommended Approach: Hybrid Auto + Editable with localStorage

### Why This Approach?

1. **Zero friction** - Auto-generates from first message (existing behavior)
2. **User override** - Click to edit when auto-name isn't helpful
3. **Persistence** - localStorage survives page refresh
4. **No backend changes for core feature** - Frontend-only for persistence/editing
5. **Graceful degradation** - Hex ID always visible as fallback
6. **Optional LLM enhancement** - Gist button for smarter naming on-demand

## Smarter Auto-Naming Algorithm

### Current Algorithm (first 4 words)
```javascript
generateSessionName( firstMessage ) {
    const cleaned = firstMessage.replace( /^\[[A-Z]+\]\s*/, '' );
    const words = cleaned.split( /\s+/ ).slice( 0, 4 );
    return words.join( ' ' ).substring( 0, 30 );
}
```

**Problem**: First 4 words often aren't meaningful:
- "Hello, I need help..." → "Hello, I need help"
- "Can you please fix..." → "Can you please fix"

### Improved Algorithm: Action Verbs + Key Nouns

**Goal**: Extract the core action and subject from the message.

```javascript
generateSessionName( firstMessage ) {
    if ( !firstMessage ) return 'Session';

    // Remove common prefixes like "[LUPIN] "
    const cleaned = firstMessage.replace( /^\[[A-Z]+\]\s*/, '' );

    // Skip words: pronouns, articles, common verbs, filler words
    const skipWords = new Set( [
        // Pronouns
        'i', 'you', 'we', 'they', 'it', 'me', 'my', 'your', 'our',
        // Articles
        'a', 'an', 'the',
        // Common verbs (non-action)
        'am', 'is', 'are', 'was', 'were', 'be', 'been', 'being',
        'have', 'has', 'had', 'do', 'does', 'did', 'can', 'could',
        'would', 'should', 'will', 'shall', 'may', 'might', 'must',
        // Filler words
        'please', 'just', 'really', 'very', 'actually', 'basically',
        'need', 'want', 'like', 'know', 'think', 'help', 'trying',
        // Question words (keep for context)
        // 'what', 'how', 'why', 'when', 'where' - these can stay
    ] );

    // Action verbs to prioritize (keep these!)
    const actionVerbs = new Set( [
        'add', 'fix', 'update', 'create', 'delete', 'remove', 'change',
        'implement', 'refactor', 'debug', 'test', 'deploy', 'configure',
        'migrate', 'upgrade', 'install', 'build', 'run', 'check', 'verify',
        'enable', 'disable', 'optimize', 'improve', 'review', 'merge'
    ] );

    const words = cleaned.toLowerCase().split( /\s+/ );
    const meaningful = [];

    for ( const word of words ) {
        // Clean punctuation
        const clean = word.replace( /[^a-z0-9]/g, '' );
        if ( !clean ) continue;

        // Always include action verbs
        if ( actionVerbs.has( clean ) ) {
            meaningful.push( clean );
            continue;
        }

        // Skip filler words
        if ( skipWords.has( clean ) ) continue;

        // Include remaining words (likely nouns/subjects)
        meaningful.push( clean );

        // Stop at 4 meaningful words
        if ( meaningful.length >= 4 ) break;
    }

    // Capitalize first letter of each word
    const name = meaningful
        .map( w => w.charAt( 0 ).toUpperCase() + w.slice( 1 ) )
        .join( ' ' );

    return name || 'Session';
}
```

| Input Message | Old (First 4) | New (Action + Nouns) |
|---------------|---------------|----------------------|
| "I'm having trouble with the JWT token expiration" | "I'm having trouble with" | "JWT Token Expiration" |
| "Can you please help me fix the authentication bug" | "Can you please help" | "Fix Authentication Bug" |

editSessionName( sessionId ) {
    const currentName = this.sessionNames[ sessionId ] || '';
    const newName = prompt( 'Enter session name:', currentName );
    if ( newName !== null && newName !== currentName ) {
        this.saveSessionName( sessionId, newName );
        this.refreshSessionNameDisplay( sessionId, newName );
        this.log( `Session ${sessionId} renamed to: ${newName}` );
    }
}

refreshSessionNameDisplay( sessionId, newName ) {
    // Find all sender cards with this session ID and update the name span
    const cards = document.querySelectorAll( `[data-session-id="${sessionId}"]` );
    cards.forEach( card => {
        const nameSpan = card.querySelector( '.sender-session-name' );
        if ( nameSpan ) nameSpan.textContent = newName;
    } );
}

**New gist generation method:**
```javascript
async generateSessionGist( senderId ) {
    const parsed = this.parseSenderId( senderId );
    const sessionId = parsed.sessionId;
    if ( !sessionId ) return;

    const group = this.senderGroups.get( senderId );
    if ( !group?.notifications?.length ) {
        this.log( 'No notifications to generate gist from' );
        return;
    }

    // Collect all messages for this session
    const messages = group.notifications.map( n => n.message ).filter( Boolean );

    try {
        // Call backend API to generate gist
        const response = await fetch( '/api/notifications/generate-gist', {
            method  : 'POST',
            headers : { ...this.getAuthHeaders(), 'Content-Type': 'application/json' },
            body    : JSON.stringify( { messages } )
        } );

        if ( !response.ok ) throw new Error( `API error: ${response.status}` );

        const data = await response.json();
        const gist = data.gist;

        // Save and display the generated gist
        this.saveSessionName( sessionId, gist );
        this.refreshSessionNameDisplay( sessionId, gist );
        this.log( `Generated gist for ${sessionId}: ${gist}` );

    } catch ( error ) {
        this.error( 'Failed to generate gist:', error );
        // Could show a toast/notification to user
    }
}
```

### Step 6: Backend API endpoint

**In `src/cosa/rest/routers/notifications.py`:**
```python
from cosa.memory.gister import Gister

@router.post( "/generate-gist" )
async def generate_session_gist(
    request: dict,
    current_user: dict = Depends( get_current_user )
):
    """
    Generate a 3-4 word gist from a list of conversation messages.

    Requires:
        - messages: list of strings

    Ensures:
        - Returns {"gist": "short summary"}
    """
    messages = request.get( "messages", [] )
    if not messages:
        return { "gist": "Empty session" }

    # Combine messages into single text for gisting
    combined = " ".join( messages[ :10 ] )  # Limit to first 10 messages

    # Use Gister to extract concise summary
    gister = Gister()
    gist = gister.get_gist( combined )

    # Truncate to ~4 words if longer
    words = gist.split()[ :4 ]
    short_gist = " ".join( words )

    return { "gist": short_gist }
```
