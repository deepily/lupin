## Executive Summary

This document outlines the migration plan for moving 3 Claude Agent SDK agents from static dataclass configuration to using the COSA ConfigurationManager, enabling runtime configuration via INI files and environment variable overrides.

---

## Background

### Current State

The Claude Agent SDK agents currently use static `@dataclass` configurations with hardcoded defaults:

| Agent | Config File | Pattern | Field Count |
|-------|-------------|---------|-------------|
| Deep Research | `src/cosa/agents/deep_research/config.py` | `@dataclass ResearchConfig` | ~25 fields |
| Podcast Generator | `src/cosa/agents/podcast_generator/config.py` | `@dataclass PodcastConfig` + nested types | ~25 fields + nested |
| LLM Client Factory | `src/cosa/agents/llm_client_factory.py` | Static dictionaries | ~15 entries |

### Problem Statement

1. **No runtime configuration**: Model names, token limits, and behavior parameters require code changes
2. **Environment-specific settings**: Cannot easily switch between development/production configurations
3. **Inconsistent patterns**: Agent configs don't use the established ConfigurationManager pattern
4. **Testing friction**: Integration tests cannot override config without code modification

### Desired State

- All agent configurations loadable from `lupin-app.ini`
- Environment variable overrides via `LUPIN_CONFIG_MGR_CLI_ARGS`
- Backward compatible - existing `ResearchConfig()` pattern unchanged
- Type safety preserved through dataclass structure

## Recommended Architecture

### Hybrid Dataclass + ConfigManager Pattern

**Core Principle**: Keep dataclasses for type safety, add factory method for config loading.

```python
@dataclass
class ResearchConfig:
    """Configuration for deep research agent."""

    # Dataclass fields provide defaults AND type safety
    lead_model     : str = "claude-opus-4-20250514"
    subagent_model : str = "claude-sonnet-4-20250514"
    max_subagents_simple   : int = 1
    max_subagents_moderate : int = 4
    max_subagents_complex  : int = 10
    # ... etc

    @classmethod
    def from_config(
        cls,
        config_mgr: "ConfigurationManager",
        prefix: str = "deep research",
        debug: bool = False
    ) -> "ResearchConfig":
        """
        Load configuration from ConfigurationManager with fallback to defaults.

        Requires:
            - config_mgr is a valid ConfigurationManager instance
            - prefix identifies the agent configuration keys

        Ensures:
            - Returns ResearchConfig with values loaded from INI
            - Falls back to dataclass defaults for missing keys
            - Preserves type safety with explicit conversions
        """
        defaults = cls()

        def _get(key: str, attr: str, return_type: str = "string"):
            full_key = f"{prefix} {key}"
            default_val = getattr(defaults, attr)
            value = config_mgr.get(full_key, default=default_val,
                                   return_type=return_type, silent=True)
            if debug:
                print(f"  [{full_key}] = {value} (default: {default_val})")
            return value

        return cls(
            lead_model     = _get("lead model", "lead_model"),
            subagent_model = _get("subagent model", "subagent_model"),
            max_subagents_simple   = _get("max subagents simple", "max_subagents_simple", "int"),
            max_subagents_moderate = _get("max subagents moderate", "max_subagents_moderate", "int"),
            max_subagents_complex  = _get("max subagents complex", "max_subagents_complex", "int"),
            # ... etc
        )
```

### Pattern Benefits

| Benefit | Description |
|---------|-------------|
| **Type Safety** | Dataclass fields enforce types; IDE autocomplete works |
| **Backward Compatible** | `ResearchConfig()` still works with hardcoded defaults |
| **Progressive Adoption** | Consumers migrate to `from_config()` incrementally |
| **Testing Friendly** | Tests use `ResearchConfig()` without ConfigManager |
| **Documented Defaults** | Dataclass fields serve as in-code documentation |
| **Environment Override** | ConfigManager supports env var overrides |

## Consumer Update Pattern

### Orchestrator Constructor Enhancement

```python
# Before
def __init__(
    self,
    query: str,
    user_id: str,
    config: Optional[ResearchConfig] = None,
    budget_limit_usd: Optional[float] = None,
    debug: bool = False,
    verbose: bool = False
):
    self.config = config or ResearchConfig()

# After
def __init__(
    self,
    query: str,
    user_id: str,
    config: Optional[ResearchConfig] = None,
    config_mgr: Optional["ConfigurationManager"] = None,  # NEW
    budget_limit_usd: Optional[float] = None,
    debug: bool = False,
    verbose: bool = False
):
    # Config priority: explicit config > config_mgr > defaults
    if config is not None:
        self.config = config
    elif config_mgr is not None:
        self.config = ResearchConfig.from_config(config_mgr, debug=debug)
    else:
        self.config = ResearchConfig()
```

## Risks and Mitigations

| Risk | Impact | Likelihood | Mitigation |
|------|--------|------------|------------|
| Breaking existing code | High | Low | `from_config()` is additive; existing pattern unchanged |
| Type coercion errors | Medium | Medium | Explicit `return_type` + dataclass defaults as fallback |
| Configuration sprawl | Low | High | Consistent prefixes, comment headers, splainer docs |
| Testing complexity | Low | Low | Tests use `ResearchConfig()` without ConfigManager |
| Nested dataclass complexity | Medium | Medium | Flatten with prefixes; factory handles reconstruction |
