# Design: cosa-voice Onboarding Bootstrapper

**Date**: 2026.03.23
**Status**: Early design (think-out-loud session)
**Origin**: Session 366 — user hit the onboarding gap when working in a non-Lupin repo

## Problem

When starting a Claude Code session in a new repo (or any repo that isn't Lupin), there's no easy way to:

1. **Get cosa-voice MCP tools** — No `.mcp.json` exists, so `notify()`, `ask_yes_no()`, etc. are unavailable
2. **Know what's missing** — No clear checklist of required env vars, config files, API keys
3. **Configure the notification recipient** — The email for the CC runtime hooks and listener isn't surfaced
4. **Validate the setup** — No way to test that everything works before starting real work

The user must manually know the config format, file paths, and env vars. This is a bootstrapping problem that grows with each new repo.

## Current Architecture

### What lives where

| Component | Location | Scope |
|-----------|----------|-------|
| cosa-voice MCP server | `$LUPIN_ROOT/src/lupin_mcp/cosa_voice_mcp.py` | Lupin project |
| MCP config | `<project>/.mcp.json` | Per-project (must be copied) |
| CC hooks (SessionStart, Stop, etc.) | `~/.claude/settings.json` | Global (already shared) |
| Hook scripts | `$LUPIN_ROOT/src/lupin_cli/claude_code/hooks/` | Lupin project |
| Notification API | `http://localhost:7999/api/notify` | Lupin FastAPI server |
| Notification recipient config | `~/.lupin/config` | Global user config |
| API key | `$LUPIN_ROOT/src/conf/keys/notification-api-claude-code-dev` | Lupin project |

### What a new repo needs

1. **`.mcp.json`** — Points to Lupin's MCP server with correct `PYTHONPATH`, `LUPIN_ROOT`, `MCP_PROJECT`
2. **`LUPIN_ROOT` env var** — Must be set in shell profile (hooks depend on it)
3. **`~/.lupin/config`** — Must have `global_notification_recipient` set
4. **FastAPI server running** — On port 7999 (the notification API)

### What already works globally

- Hooks in `~/.claude/settings.json` use `$LUPIN_ROOT` — work in any repo IF the env var is set
- The MCP server reads `MCP_PROJECT` env var to customize per-project behavior

## Proposed Solution

### Layer 1: `install-cosa-voice.sh` (Lupin script)

A bootstrapper script at `$LUPIN_ROOT/src/scripts/install-cosa-voice.sh` that:

```
Usage: install-cosa-voice.sh [--project-dir <path>] [--project-name <name>] [--check-only]
```

**Steps:**

1. **Validate prerequisites**:
   - `LUPIN_ROOT` env var is set and points to a valid Lupin installation
   - Python venv exists at `$LUPIN_ROOT/src/cosa/.venv/`
   - FastAPI server is reachable on port 7999
   - `~/.lupin/config` exists with `global_notification_recipient`

2. **Generate `.mcp.json`** in target project dir:
   ```json
   {
     "mcpServers": {
       "cosa-voice": {
         "type": "stdio",
         "command": "$LUPIN_ROOT/src/cosa/.venv/bin/python",
         "args": ["$LUPIN_ROOT/src/lupin_mcp/cosa_voice_mcp.py"],
         "env": {
           "PYTHONPATH": "$LUPIN_ROOT/src",
           "LUPIN_ROOT": "$LUPIN_ROOT",
           "MCP_PROJECT": "<project-name>"
         }
       }
     }
   }
   ```
   (With actual paths expanded, not env var references — `.mcp.json` doesn't expand vars)

3. **Validate hooks** — Check `~/.claude/settings.json` has the 4 hook entries
4. **Test connection** — Send a test `notify()` ping and verify delivery
5. **Print summary** — Green/red checklist of what's configured

**`--check-only` mode**: Just validates and reports, doesn't write anything. Useful for diagnosing "why isn't cosa-voice working in this repo?"

### Layer 2: Diagnostic output on missing config

When the MCP server starts and detects missing configuration, it should print clear diagnostic messages:

```
[cosa-voice] ⚠️ Missing configuration:
  ✗ LUPIN_ROOT not set — hooks will fail
  ✗ ~/.lupin/config missing global_notification_recipient
  ✓ FastAPI server reachable on port 7999
  ✓ Python venv found
```

This could be added to `cosa_voice_mcp.py`'s startup sequence.

### Layer 3: Planning-is-prompting pointer

Add a section to planning-is-prompting's `INSTALLATION-GUIDE.md`:

```markdown
## cosa-voice Notification System

If your project needs voice notifications and interactive prompts:

1. Ensure Lupin is installed and `LUPIN_ROOT` is set
2. Run: `$LUPIN_ROOT/src/scripts/install-cosa-voice.sh --project-dir .`
3. Restart Claude Code in the project
4. Verify: `get_session_info()` should return project metadata
```

## Open Questions

1. **Should `.mcp.json` be gitignored?** It contains absolute paths specific to the machine. Probably yes — each developer generates their own via the bootstrapper.

2. **Global vs per-project MCP?** Could put cosa-voice in `~/.mcp.json` (global) instead of per-project. Pro: one config for all repos. Con: `MCP_PROJECT` would need to be auto-detected (it currently reads from the env var set in `.mcp.json`).

3. **Auto-detect project name?** The `MCP_PROJECT` env var could be derived from the CWD's directory name or a `CLAUDE.md` marker instead of being hardcoded in `.mcp.json`.

4. **Slash command?** Instead of a shell script, this could be a planning-is-prompting slash command: `/install-cosa-voice`. The slash command would be more discoverable but requires the skill to already be installed.

5. **Should hooks be optional?** Some repos might want cosa-voice MCP tools (notify, ask) but NOT the full hook system (SessionStart, Stop, etc.). The bootstrapper could offer tiers: "MCP only" vs "MCP + hooks".
