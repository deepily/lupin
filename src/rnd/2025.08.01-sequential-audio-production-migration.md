# Sequential Audio Production Migration Plan
Date: 2025.08.01

## Executive Summary
This document outlines the production migration strategy for moving the successfully validated SequentialAudioManager from experimental implementation to the production HybridTTS system. The experimental validation confirmed complete elimination of simultaneous audio chunk overlap with zero performance regression.

## Background & Validation

### Experimental Success ✅
- **Location**: `/src/fastapi_app/static/js/test/experimental-tts.js`
- **Validation**: "It works! Not one bit of overlap!"
- **Root Cause Fixed**: Simultaneous audio playback eliminated
- **Approach Validated**: Simple Audio Element Queue with 'ended' event listeners

### Problem Statement
The production HybridTTS system (`/src/fastapi_app/static/js/hybrid-tts.js`) has the same simultaneous playback issue in **instant mode only**. The 'reliable' mode is unaffected as it collects chunks and plays them after completion.

## Architecture Analysis

### HybridTTS Current Structure
```javascript
// PROBLEMATIC: handleWebSocketMessage() in instant mode
if (this.mode === 'instant' && this.useWebAudioAPI && this.audioContext) {
    this.playChunkProgressive(event.data);  // ← SIMULTANEOUS PLAYBACK ISSUE
}

// SAFE: reliable mode collects chunks without immediate playback
this.audioChunks.push(event.data);  // ← NO OVERLAP ISSUE
```

### Integration Strategy
**Target**: Only modify 'instant' mode behavior, preserve 'reliable' mode completely.

**Key Insight**: This surgical approach minimizes risk and maintains backwards compatibility.
