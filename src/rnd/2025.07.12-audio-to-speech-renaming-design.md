# Audio to Speech Renaming Design

**Date**: 2025.07.12  
**Purpose**: Rename misleading "audio" terminology to accurate "speech" terminology for TTS functionality  
**Status**: Design Phase  
**Priority**: High - Should be completed before WebSocket user routing implementation
**Related**: Complements `2025.07.11-websocket-user-routing-architecture.md`

## Executive Summary

### Problem Statement
The current codebase uses "audio" terminology for Text-to-Speech (TTS) functionality, which is misleading since:
- `emit_audio()` only handles speech synthesis, not general audio
- `audio_update` events specifically trigger TTS, not audio playback
- Notification sounds use a completely different system (`notification_sound_update`)
- This confusion makes the codebase harder to understand and maintain

### Solution Overview
**Core Principle**: Use precise terminology that matches actual functionality

Rename all TTS-related components:
- `emit_audio` → `emit_speech`
- `audio_update` → `speech_update`
- `/api/get-audio` → `/api/get-speech`
- `audio.py` router → `speech.py` router
- All related callbacks, parameters, and references

**No backward compatibility** - Complete migration in one session.

### Implementation Benefits
1. **Clarity**: Developers immediately understand these are speech-specific
2. **Consistency**: Unified "speech" terminology throughout the stack
3. **Distinction**: Clear separation from notification sounds and future audio features
4. **Maintainability**: Reduces confusion for new contributors


   - `TodoFifoQueue`: Uses `emit_audio_callback` for agent thinking sounds
   - `RunningFifoQueue`: Uses `emit_audio_callback` for job completion speech
   - `FifoQueue`: Base class with `_emit_audio()` helper method

3. **WebSocket Events**:
   - Event type: `"audio_update"` (actually triggers TTS)
   - Separate: `"notification_sound_update"` (plays .wav files)

4. **Router Module**:
   - `/src/cosa/rest/routers/audio.py` - Misnamed, handles speech synthesis

#### Client-Side Components
1. **Queue JavaScript** (`/src/fastapi_app/static/js/queue.js`):
   ```javascript

   ```

2. **API Endpoints**:
   - `/api/get-audio` - OpenAI TTS endpoint
   - `/api/get-audio-elevenlabs` - ElevenLabs TTS endpoint

## Future Considerations

### Clear Namespace for Future Audio Features
With "speech" clearly defined for TTS, future audio features can use appropriate names:
- `audio_stream_update` - For music/podcast streaming
- `sound_effect_update` - For UI sound effects  
- `voice_call_update` - For real-time voice communication

### Next Steps After This Migration
1. Implement WebSocket user routing with correct "speech" terminology
2. Consider creating separate `sounds.py` router for notification sounds
3. Document the distinction between speech and audio in README
