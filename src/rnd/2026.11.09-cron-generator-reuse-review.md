# Reuse review: cron generator and the shared job command (row 449bf026)

Twelve definitions are new across `lupin_mcp/cron_generate.py`, `lupin_mcp/job_run.py`, `cosa/rest/job_service.py` and `cosa/repo/symindex/librarian_tick.py`. A neutral subagent read the source of each shortlisted candidate and ruled; I then acted on its two extend rulings, one of which (`read_crontab`) is why that function no longer exists.

- `read_crontab` was deleted: `cron_generate` calls `lupin_mcp.host_snapshot.crontab_text`, which gained an optional `cmd` argument.
- `bootstrap_env` re-derived `home` and the planning-is-prompting root with the two lines `paths_of` uses, so those lines became `home_and_pip`, called by both.
- `with_trigger`, `stream_run`, `run_command`, `bootstrap_env`, `managed_jobs`, `lines_for_job`, `generate`, `make_log_folders` and `main` have no existing equivalent; the lines below name the nearest candidate and the difference.
- `install_moved_text` is one shared message that five retired `--install` handlers call, so it removes duplication.
