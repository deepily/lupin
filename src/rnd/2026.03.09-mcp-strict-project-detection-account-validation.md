# cosa-voice MCP: Strict Project Detection + Account Validation

**Serialized from**: `~/.claude/plans/transient-purring-swing.md`
**Date**: 2026-03-09 (Session 332)
**Status**: Planned — not yet implemented

## Context

When Claude Code launches in an unrecognized repo, the MCP server silently falls back to `"unknown"` project. The sender_id becomes `claude.code@unknown.deepily.ai` — useless. Two fixes needed:

1. **Fail loudly** when project can't be identified (no `"unknown"` fallback)
2. **Validate at startup** that a **per-repo Lupin user account** exists and is enabled

### Why per-repo accounts matter

Each repo needs its own first-class Lupin user account (e.g., `claude.code@lupin.deepily.ai`, `claude.code@newrepo.deepily.ai`). This is NOT the generic service account `claude.code@deepily.ai` — it's a repo-specific account because:
- The **CC Notification Listener** authenticates as this user via WebSocket to receive notifications
- The browser UI sends **user-initiated messages** to this account (routed by sender_id)
- Without a valid account, the entire voice I/O pipeline for that repo is dead

**Provisioning a new repo** requires:
1. Create PG account: `python src/scripts/create_service_account_postgres.py --email=claude.code@newrepo.deepily.ai`
2. Add credentials: `[newrepo]` section in `~/.lupin/credentials.ini`
3. The MCP server should validate both at startup and fail loudly if either is missing

### Step 3: Validate service account at startup

**File**: `src/lupin_mcp/cosa_voice_mcp.py`

Add `_validate_repo_account( project: str )` — called at module init. Validates:

1. **Credentials exist**: `~/.lupin/credentials.ini` has a `[{project}]` section
2. **Account is live**: `POST /auth/login` succeeds

**Key design decision: Don't crash — poison the tool results.**

The MCP server runs as a stdio subprocess. stderr logs are buried — the user never sees them. If we `os._exit(1)`, the user gets a generic "MCP server died" error with no actionable info.

Instead: let the server start, but store the validation error. Every tool call checks the error and **returns it as the tool result**. Claude Code sees the error message and relays it to the user in conversation — the one channel they're actually reading.

```python
_repo_account_error: Optional[str] = None  # Set if validation fails

def _validate_repo_account( project: str ) -> None:
    global _repo_account_error
    expected_email = f"claude.code@{project}.deepily.ai"

    try:
        email, password = get_hook_credentials( project )
    except ( FileNotFoundError, ValueError ) as e:
        _repo_account_error = (
            f"COSA-VOICE MCP STARTUP FAILED: No credentials for project '{project}'.\n\n"
            f"{e}\n\n"
            f"To fix:\n"
            f"1. Create the repo account:\n"
            f"   python src/scripts/create_service_account_postgres.py --email={expected_email}\n"
            f"2. Add to ~/.lupin/credentials.ini:\n"
            f"   [{project}]\n"
            f"   email = {expected_email}\n"
            f"   password = <password-from-step-1>\n"
        )
        logger.critical( _repo_account_error )
        return

    try:
        resp = requests.post( f"{SERVER_URL}/auth/login",
                              json={ "email": email, "password": password },
                              timeout=5 )
        if resp.status_code != 200:
            _repo_account_error = (
                f"COSA-VOICE MCP STARTUP FAILED: Login failed for {email} (HTTP {resp.status_code}).\n\n"
                f"The account may not exist or may be disabled.\n\n"
                f"To fix:\n"
                f"1. Create the repo account:\n"
                f"   python src/scripts/create_service_account_postgres.py --email={expected_email}\n"
                f"2. Verify credentials in ~/.lupin/credentials.ini [{project}] section\n"
            )
            logger.critical( _repo_account_error )
            return
    except requests.ConnectionError:
        _repo_account_error = (
            f"COSA-VOICE MCP STARTUP FAILED: Cannot reach Lupin server at {SERVER_URL}.\n\n"
            f"Ensure the FastAPI server is running: src/scripts/run-fastapi-lupin.sh\n"
        )
        logger.critical( _repo_account_error )
        return

    logger.info( f"Repo account validated: {email}" )

def _check_repo_account():
    """Gate for every tool call. Raises RuntimeError if account validation failed."""
    if _repo_account_error:
        raise RuntimeError( _repo_account_error )
```

Every tool function starts with `_check_repo_account()`. If validation failed, the tool returns the setup instructions as the error — visible to Claude Code and the user.
