# API Push Endpoint Migration: GET to POST

**Date**: 2025.08.15  
**Status**: ✅ COMPLETED  
**Priority**: CRITICAL  
**Issue**: Smoke tests failing due to HTTP method mismatch - RESOLVED

## Problem Statement

The `/api/push` endpoint has a critical HTTP method mismatch causing smoke test failures:

- **Current Implementation**: GET method with query parameters
- **Test Expectations**: POST method with JSON body
- **Smoke Test Results**: 405 Method Not Allowed errors
- **Impact**: Audio/TTS (0/9 tests pass), Queue Workflow (3/8 tests pass)

## Root Cause Analysis

### Current Implementation (`queues.py:117`)
```python
@router.get("/push")
async def push(
    question: str = Query(...),
    websocket_id: str = Query(...),
    # ... other dependencies
):
```

### Test Expectations
```python
response = await self.client.http_request("POST", "/api/push", json=data)
```

### Client Code Reality Check
- **queue.js**: Uses GET with query parameters (2 locations)
- **queue-fresh.js**: Uses GET with query parameters (1 location)
- **Firefox Plugin**: No usage found ✅

## Migration Strategy

### Phase 1: Backend Changes ✅ PLANNED
**File**: `src/cosa/rest/routers/queues.py`

**Current Signature**:
```python
@router.get("/push")
async def push(
    question: str = Query(...),
    websocket_id: str = Query(...),
    current_user: dict = Depends(get_current_user),
    todo_queue = Depends(get_todo_queue)
):
```

**Target Signature**:
```python
@router.post("/push")
async def push(
    request: Request,
    current_user: dict = Depends(get_current_user),
    todo_queue = Depends(get_todo_queue)
):
```

**Request Body Schema**:
```json
{
    "question": "string",
    "websocket_id": "string"
}
```

### Phase 2: Frontend Changes ✅ PLANNED

#### 2.1 queue.js Updates
**File**: `src/fastapi_app/static/js/queue.js`

**Location 1** (~line 1120):
```javascript
// FROM:
const url = `/api/push?question=${encodeURIComponent(question)}&websocket_id=${websocketId}`;

    headers: {
        'Authorization': getAuthHeader(),
        'X-Session-ID': sessionId

})

    method: 'POST',
    headers: {
        'Authorization': getAuthHeader(),
        'X-Session-ID': sessionId,
        'Content-Type': 'application/json'

    body: JSON.stringify({
        question: question,
        websocket_id: websocketId
    })
})
```

## Benefits of POST Migration

### 1. RESTful Compliance ✅
- **GET**: Retrieve data (safe, idempotent)
- **POST**: Create resources (correct for job submission)

### 2. Security Improvements ✅
- Question content in request body (not URL logs)
- No query parameter length limitations
- Reduced exposure in access logs

### 3. API Consistency ✅
- Matches test expectations
- Aligns with industry standards
- Better for future extensibility

### 4. Technical Benefits ✅
- JSON schema validation possible
- Easier to add new fields
- Better error handling capabilities
