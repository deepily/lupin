## Objective

Create LORA training datasets to enable intent classification and parameter extraction for three agentic job workflows:
1. **Deep Research** - Research investigation from a query
2. **Podcast Generator** - Audio creation from existing research documents
3. **Research→Podcast** - Combined research + podcast in one workflow

The fine-tuned model will parse natural language voice commands and extract:
- The correct routing command
- Structured parameters (research topic, budget, languages, etc.)

### Existing Training Data Format

Training data uses JSONL with XML-structured inputs and outputs.

**IMPORTANT**: The full JSONL format requires **6 fields** (not 4):

```json
{
  "command": "agent router go to calendar",
  "instruction": "Your job is to discern the intent...",
  "input": "<human><voice-command>...</voice-command></human>",
  "output": "<response><command>...</command><args>...</args></response>",
  "prompt": "### Instruction:\n{instruction}\n\n### Task:\n{input}\n\n### Response:\n{output}",
  "gpt_message": {
    "messages": [
      {"role": "system", "content": "{instruction}"},
      {"role": "user", "content": "{input}"},
      {"role": "assistant", "content": "{output}"}
    ]
  }
}
```

## Design Decisions

### Training Data Format

**XML Output Structure** (matches existing infrastructure):
```xml
<response>
    <command>agent router go to deep research</command>
    <args>research_topic="quantum computing safety" budget=50</args>
</response>
```

### Command Names

| Intent | Command |
|--------|---------|
| Deep Research | `agent router go to deep research` |
| Podcast Generator | `agent router go to podcast generator` |
| Research→Podcast | `agent router go to research to podcast` |

### Args Format

**Space-delimited name-value pairs** (command-line style, NOT URL-style with `&`):
- Quoted strings for multi-word values: `research_topic="AI safety developments"`
- Unquoted for simple values: `budget=50`
- Comma-separated lists: `languages=en,es,fr`

**Examples:**
```
research_topic="quantum computing" budget=50
podcast_source_file="/io/deep-research/user@email/report.md" languages=en,es
research_topic="climate change impacts" budget=25 languages=en,es,fr max_segments=20
```

### Parameters by Intent (Complete)

Based on exploration of all three agentic agents, here are ALL extractable parameters:

#### Deep Research Parameters
| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `research_topic` | string | Yes | The research query/topic to investigate |
| `budget` | float | No | Maximum USD budget (None = unlimited) |
| `target_audience` | enum | No | `beginner`, `general`, `expert`, `academic` (default: expert) |
| `audience_context` | string | No | Custom audience description (e.g., "AI architect familiar with LLMs") |

#### Podcast Generator Parameters
| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `podcast_source_file` | string | Yes | Path or description of research document |
| `languages` | list | No | ISO language codes (default: `en`). Examples: `en`, `en,es-MX`, `es-ES,es-AR` |
| `max_segments` | int | No | Limit TTS to first N segments (cost control) |

#### Research→Podcast Parameters (inherits from both workflows)
| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `research_topic` | string | Yes | The research query/topic to investigate |
| `budget` | float | No | Maximum USD budget for research phase |
| `target_audience` | enum | No | `beginner`, `general`, `expert`, `academic` |
| `audience_context` | string | No | Custom audience description |
| `languages` | list | No | ISO language codes for podcast audio |
| `max_segments` | int | No | Limit TTS segments |

### Args Format Examples

```
# Deep Research - simple

# Deep Research - with budget

# Research→Podcast - simple

# Research→Podcast - full params
research_topic="renewable energy innovations" budget=75 target_audience=general languages=en,es-MX max_segments=15
```

### Missing Parameter Handling

When parameters are missing or ambiguous, the notification system asks blocking clarification questions via `ask_multiple_choice()` or `converse()`. This creates a hybrid approach:
- LORA model handles intent classification and parameter extraction
- Missing/ambiguous parameters get clarified interactively

## Intent Classification Decision Tree

For reference, this is the logic the model should learn:

```
User Intent Classification

1. Does user mention "podcast" or "audio"?
   ├─ NO → Deep Research
   │       Command: agent router go to deep research
   │       Args: research_topic="..." [budget=N]
   │
   └─ YES → Is there a research query (not just document reference)?
             ├─ YES → Research→Podcast Chained
             │        Command: agent router go to research to podcast
             │        Args: research_topic="..." [budget=N] [languages=...] [max_segments=N]
             │
             └─ NO → Podcast Generator
                     Command: agent router go to podcast generator
                     Args: podcast_source_file="..." [languages=...] [max_segments=N]
```

**Key Distinguishing Signals:**

| Signal | Deep Research | Podcast Generator | Research→Podcast |
|--------|---------------|-------------------|------------------|
| "research", "investigate", "explore" | ✓ Primary | | ✓ |
| "podcast", "audio", "create audio" | | ✓ Primary | ✓ |
| References existing document | | ✓ | |
| Research query + podcast mention | | | ✓ Primary |
| Budget mentioned | ✓ Optional | | ✓ Optional |
| Languages mentioned | | ✓ Optional | ✓ Optional |
