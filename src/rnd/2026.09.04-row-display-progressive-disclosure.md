## 🔴 A COMPUTED `display` STRING IS NOT EVIDENCE ABOUT A CLAMP — THE GEOMETRY IS

**Two of us reached the same explanation independently, and it was false.**

The two-line clamp was inert on the title cell. The diagnosis both Maya and Pocholo gave,
in that order, was: *"`display` computes to `flow-root`, and `-webkit-line-clamp` only
applies under `display: -webkit-box` — so it never applies."* It reads well, it names a
real CSS rule, and it explained the symptom exactly.

**Pocholo disproved it by measuring the thing that was supposed to be the fix.** The span
that *does* clamp correctly **also computes `flow-root`**. Chrome reports the same string
for both.

| element | computed `display` | does the clamp bind? |
|---|---|---|
| the `td` | `flow-root` | **no** — declared `max-height: 39px`, **rendered 90px** |
| a `span` inside it | `flow-root` | **yes** — bounds at 39px against 78px of content, clipped |

⇒ **The display value was constant across the two cases and the behaviour was not, so it
could never have been the discriminator.** It was a plausible story wearing the clothes of
a mechanism.

**What actually discriminates, and it was available the whole time:**

```
clientHeight == scrollHeight   ->  NOTHING was clamped   (51 / 51, the defect)
clientHeight <  scrollHeight   ->  something was clamped (39 / 78, the fix)
```

⚠️ **THE CONCLUSION SURVIVED AND THE RECEIPT WAS ALWAYS THE RIGHT RECEIPT.** *"The clamp is
inert on the cell"* was true. *"A span fixes it"* was true. The `51/51` reading was the
correct evidence and was quoted from the start. **Only the sentence in between was wrong** —
which is the hardest kind to catch, because everything around it checks out.

⇒ **This is § *THE OVERCLAIM HIDES IN THE JOIN* in CLAUDE.md, arriving through CSS.** Two
measured ends — *the clamp does not fire* and *the cell computes flow-root* — welded with a
*because* that nobody tested.

🔴 **AND IT IS WORSE THAN A WRONG NUMBER, BY THIS REPO'S OWN RANKING.** A wrong figure gets
re-derived by the next reader. **A wrong mechanism sends them into innocent code** — here,
hunting a `display` value that was never involved. It was one commit away from living in a
docstring, where it would have been read for years by people who never saw the retraction.

**How it was closed**: the retraction is in the **artifact**, not the thread —
`notifications.js` at the title field and arm 3c of
`the_row_is_one_shape_in_all_three_panes.test.ts` both now lead with the geometry and carry
an explicit ⚠️ naming the `flow-root` story as false. *A retraction has to reach the artifact,
not just the conversation.*

⚠️ **What this does NOT establish**: it says nothing about *why* the cell refuses. The honest
statement is that the declarations reach the cell and do nothing there, and bind on a span —
measured both ways. Nobody has established the underlying rule, and this entry deliberately
does not guess at one.

## 🔴 HIT-TESTING A CONTROL LIES IN THREE WAYS, AND ALL THREE READ AS "UNREACHABLE"

The question *"can the operator actually reach this button?"* is the one this whole epic
exists to answer — an editor that rendered **108px outside a 916px pane** cost an evening
because *absent* and *off-screen* look identical from a chair. So the hit-test is the
instrument that matters most, and it produced **three false readings in a row** before it
produced a true one.

| # | what happened | what it returned | what it looks like |
|---|---|---|---|
| 1 | the button was scrolled **off-viewport** | `elementFromPoint` → **null** | unreachable |
| 2 | the button sat **under the fixed nav** (`.lupin-nav`, `position: fixed`, `z-index: 9999`) | `.lupin-nav-inner` | **something is covering it** |
| 3 | the node was **detached by a background re-render** between capture and measurement | rect all zeros → *"1226.5px outside the pane"* | **wildly** unreachable |

🔴 **THE THIRD IS THE DANGEROUS ONE AND IT IS INVISIBLE.** The panes poll and repaint. A node
captured before a `scrollIntoView` can be gone by the time it is measured, and a detached
node's `getBoundingClientRect()` is all zeros — which arithmetic then renders as an enormous
displacement. Nothing in the output says *"this element is no longer in the document."* It
had this reviewer one message from reporting a reachability defect **that did not exist**, in
the exact pane where the opposite mistake had already cost the evening.

**The guard shape that survives all three** — each clause is there because one of them fired:

```js
for (let i = 0; i < n; i++) {
  let btns = [...document.querySelector(tsel).querySelectorAll(SEL)];   // RE-QUERY per index
  if (i >= btns.length)                    { skip("re-rendered, fewer rows"); continue; }
  if (btns[i].getBoundingClientRect().width === 0) { skip("collapsed group"); continue; }

  btns[i].scrollIntoView({ block: "center" });
  await settle(180);

  btns = [...document.querySelector(tsel).querySelectorAll(SEL)];       // RE-QUERY AGAIN
  if (i >= btns.length || !document.contains(btns[i])) { skip("detached mid-measure"); continue; }

  const r = btns[i].getBoundingClientRect(), cy = (r.top + r.bottom) / 2;
  if (!(cy > 60 && cy < innerHeight - 10))  { skip("could not clear the fixed nav"); continue; }

  judge({ insidePane: r.right <= paneRect.right + 0.5,
          hitIsToggle: document.elementFromPoint(cx, cy)?.classList.contains(TOGGLE) });
}
// A SKIPPED node is never a pass and never a failure.
if (judged.length === 0) return "NO JUDGEABLE TOGGLE — refusing to report";
```

**The five rules, and each one is a receipt:**

1. **Re-query by index immediately before measuring** — never hold a node across an `await`.
2. **Assert `document.contains()`** — a detached node answers every geometric question with a
   confident lie.
3. **Require the point clear of fixed overlays** (60px here) — a nav at `z-index: 9999` wins
   every hit-test under it.
4. **Report SKIPPED as SKIPPED.** Collapsed-group rows have zero width and would satisfy
   every per-cell assertion trivially; counting one as a pass is how a loop over nothing
   reports success.
5. **Refuse to return a verdict when nothing was judgeable.** *"All toggles reachable"* over
   an empty judged set is the emptiest true sentence in this repo.

⚠️ **This is § *AN EMPTY RESULT IS TWO DIFFERENT FAILURES WEARING ONE FACE* reaching the DOM.**
An unreachable control and an unmeasurable one return the same shape. The only defence is an
instrument that says which one it is — and one that declines rather than guessing.

⇒ **And note the direction of the error.** In this epic the famous failure was reporting a
present-but-off-screen control as **absent**. The hit-test's failure mode is the mirror:
reporting a **reachable** control as unreachable. Both come from an instrument that cannot
tell "I did not see it" from "it is not there."

## The smaller ones, recorded without ceremony

- **`--cov`-style blindness has a DOM equivalent.** `happy-dom` has **no layout engine**:
  every geometry value is `0` while computed styles read back fine (`display "flow-root"`,
  `width "3.71%"` returned verbatim, never resolved). That is exactly how **574 green tests
  sat over a visibly broken page** all evening. A unit guard here can pin **declarations** and
  never **geometry** — and arm 3c says so on its own face rather than implying more than it
  can prove.
- **A stamped asset is `immutable` for a year.** Twice tonight the bytes on disk were correct
  and the `?v=` stamp naming them was not, so the change was shipped, served, and invisible.
  No bounce fixes it; a reload does not either. **Two files changed means two stamps bumped.**
  The stamps are hand-maintained, which is why it happened twice — deriving them from a
  content hash would remove the step entirely, and that is worth filing rather than
  remembering.
- **A rule can outlive the element it was written for and still match something.** The sticky
  pin on `.task-col-actions` survived the column's removal and now silently applies to the
  actions block inside the disclosed row. It measures clean. It is a booby trap, filed as
  `7bacb4ab`.
