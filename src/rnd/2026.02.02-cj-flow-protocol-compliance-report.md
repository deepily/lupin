## Protocol Definition

**Location**: `src/cosa/rest/queue_protocol.py`

The QueueableJob protocol is a Python `@runtime_checkable` Protocol that defines the unified interface for all jobs flowing through the COSA queue system. It was formalized on 2025-01-22 to enable consistent queue handling without fragile `getattr()` chains.

## Task Type Analysis

### BOUNDED Mode (Fire-and-Forget)

- **Implementation**: Uses `claude` CLI in print mode (`claude -p`)
- **Execution Model**: Runs to natural completion
- **Control**: No bidirectional communication after launch
- **Best For**: CI/CD pipelines, scheduled jobs, bounded tasks
- **Protocol Compliance**: ✅ Full

### INTERACTIVE Mode (Bidirectional/Unbounded)

- **Implementation**: Uses Claude Agent SDK (`claude-agent-sdk`)
- **Execution Model**: Session with injection/interruption capability
- **Control**: Can inject messages or interrupt during execution
- **Best For**: Open-ended sessions requiring human guidance
- **Protocol Compliance**: ✅ Full

Both modes use the same `ClaudeCodeJob` class with different `task_type` parameter values.

### Programmatic Protocol Check

```python
from cosa.rest.queue_protocol import is_queueable_job
from cosa.agents.claude_code.job import ClaudeCodeJob

# Create BOUNDED job
bounded_job = ClaudeCodeJob(
    prompt     = "Run the tests",
    project    = "lupin",
    user_id    = "test_user",
    user_email = "test@test.com",
    session_id = "test_session",
    task_type  = "BOUNDED"
)

# Create INTERACTIVE job
interactive_job = ClaudeCodeJob(
    prompt     = "Help me refactor the auth module",
    project    = "lupin",
    user_id    = "test_user",
    user_email = "test@test.com",
    session_id = "test_session",
    task_type  = "INTERACTIVE"
)

# Verify both implement protocol
assert is_queueable_job( bounded_job ), "BOUNDED job should implement QueueableJob"
assert is_queueable_job( interactive_job ), "INTERACTIVE job should implement QueueableJob"

print( "✓ Both job types implement QueueableJob protocol" )
```
