Extend the existing `POST /api/test-suite/submit` endpoint + `TestSuiteJob` agentic job so Claude can schedule **every** Lupin test tier via a single uniform mechanism. Enable user commands like:

- "Run all the tests at midnight"

### Why Two Smoke Runners?

Tests in `src/tests/smoke/` have **two invocation conventions**:

1. **Pytest-style** (`smoke` runner): `def test_X():` + `assert quick_smoke_test()` — pytest discovers
2. **Python-main-style** (`smoke_direct` runner): `if __name__ == "__main__":` with custom argparse (`--auto-proxy`, `--cost-cap-usd`, `--group`, etc.) — pytest cannot parse these custom flags

**Examples requiring `smoke_direct`**:
- `test_presentation_live_smoke.py` (--auto-proxy, --cost-cap-usd)
- `test_proxy_integration.py` (--group, --auto-proxy, --no-confirm)
- `test_notification_proxy_script_matching.py` (--script, --tier, --scenarios)

**Alternative (future)**: port custom flags to pytest's `conftest.py` `pytest_addoption` hooks, then `smoke_direct` becomes unnecessary. Tracked as Phase 3.

## "All" Suite Orchestration

### Sequencing (test-pyramid order: cheapest → costliest)

```
1. unit       (~30-60s)   — No server dependency
2. smoke      (~2 min)    — Mostly server-dependent
3. websocket  (~1-2 min)  — Server + WS endpoints
4. integration (~5-10 min) — Server + DB + auth (hot-swaps config)
5. e2e        (~17 min)   — Playwright + browser (hot-swaps config)
─────────────────────────
   TOTAL     (~25-35 min) — When all pass
```

### Failure Handling

**Default: fail-fast** (abort at first failing suite). Rationale:
- Unit failures → don't waste 30 min on E2E that definitely won't work
- Fast feedback loop

**Override via flag**: `pytest_args="--continue-on-failure"` → run every suite, aggregate failures. Useful for nightly regression reports where you want full visibility.

### Output Aggregation

`run-all-tests.sh` produces:
- Per-suite logs: `/tmp/{type}-latest.log` (unchanged)
- Combined log: `/tmp/all-tests-latest.log`
- Summary footer: `X passed, Y failed across N suites`
- JSON stats file: `/tmp/all-tests-summary.json` (for programmatic consumption)

### 4. `src/tests/run-all-tests.sh` (NEW)

```bash
#!/bin/bash
# Sequentially runs all test suites in pyramid order
# Supports --continue-on-failure flag
set -o pipefail
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
PROJECT_ROOT="$(cd "$SCRIPT_DIR/.." && pwd)"
COMBINED_LOG="/tmp/all-tests-latest.log"
SUMMARY_JSON="/tmp/all-tests-summary.json"
CONTINUE_ON_FAIL=0

# Parse flags
for arg in "$@"; do
    [ "$arg" = "--continue-on-failure" ] && CONTINUE_ON_FAIL=1
done

# Suite sequence + runner scripts
declare -a SUITES=( "unit" "smoke" "websocket" "integration" "e2e" )
declare -A SCRIPTS=(
    [unit]="src/tests/run-unit-tests.sh"
    [smoke]="src/tests/run-smoke-tests.sh"
    [websocket]="src/scripts/run-websocket-smoke-tests.sh"
    [integration]="src/tests/run-integration-tests.sh"
    [e2e]="src/scripts/run-e2e-ui-tests.sh"
)

declare -A RESULTS
OVERALL_EXIT=0

echo "=" > "$COMBINED_LOG"
for suite in "${SUITES[@]}"; do
    echo "=== Running $suite ===" | tee -a "$COMBINED_LOG"
    START=$(date +%s)
    bash "$PROJECT_ROOT/${SCRIPTS[$suite]}" 2>&1 | tee -a "$COMBINED_LOG"
    EXIT=${PIPESTATUS[0]}
    END=$(date +%s)
    DUR=$((END - START))
    RESULTS[$suite]="exit=$EXIT duration=${DUR}s"

    if [ $EXIT -ne 0 ]; then
        OVERALL_EXIT=$EXIT
        if [ $CONTINUE_ON_FAIL -eq 0 ]; then
            echo "ABORT: $suite failed (exit=$EXIT). Skipping remaining suites." | tee -a "$COMBINED_LOG"
            break
        fi
        echo "WARNING: $suite failed (exit=$EXIT). Continuing per flag." | tee -a "$COMBINED_LOG"
    fi
done

# Generate JSON summary
python3 -c "
import json
results = {k.split('=')[0] + '=' + k.split('=')[1].split()[0]: k.split('=')[2] for k in ['${RESULTS[unit]:-skipped}', '${RESULTS[smoke]:-skipped}'] }
json.dump(results, open('$SUMMARY_JSON', 'w'), indent=2)
" 2>/dev/null || echo '{}' > "$SUMMARY_JSON"

echo "=== Summary ===" | tee -a "$COMBINED_LOG"
for suite in "${SUITES[@]}"; do
    echo "  $suite: ${RESULTS[$suite]:-SKIPPED}" | tee -a "$COMBINED_LOG"
done
exit $OVERALL_EXIT
```

## `--bg` Flag Handling (CRITICAL)

**The rule**: `--bg` detaches a script into the background — useful when Claude invokes directly via Bash tool (10-min timeout), useless/harmful when TestSuiteJob invokes via `subprocess.Popen` (no timeout, needs to track the process).

**Implementation**:
- Runner scripts **accept** `--bg` but should no-op when called as a subprocess
- TestSuiteJob **must not pass** `--bg` to scripts
- Currently: `cmd = [ "bash", script_path ] + self.pytest_args` — user-supplied `pytest_args` could include `--bg`
- **Fix**: Strip `--bg` and warn when TestSuiteJob sees it in pytest_args

Code change in `job.py:485`:
```python
# Strip --bg flag (harmful when running as subprocess)
sanitized_args = [ arg for arg in self.pytest_args if arg != "--bg" ]
if len(sanitized_args) < len(self.pytest_args):
    logger.warning("--bg flag stripped (TestSuiteJob runs subprocess synchronously)")
cmd = [ "bash", script_path ] + sanitized_args
```

## Risks & Decisions

| Risk | Mitigation | Decision Owner |
|---|---|---|
| `all` suite takes 35+ min; server restart mid-run breaks things | `monopolize=True` enforced by TestSuiteJob; document server stability expectation | User (accept) |
| Hot-swap collision: `integration` and `e2e` both hot-swap config | Sequential via `all` script (no parallel); each suite's hot-swap is reversed before next starts | Already handled by existing scripts |
| pytest_args applies to ALL suites uniformly (multi-type request) | Document; user can submit separate requests for different args per suite | User (accept) |
| `--bg` flag in pytest_args causes script detachment | Strip in TestSuiteJob + warn | Me (implement) |
| Test credentials hardcoded to `LUPIN_TEST_INTERACTIVE_MOCK_JOBS_*` | Keep; already CLAUDE.md standard | Already standard |
| `all` suite fail-fast vs continue-on-failure default | **Default: fail-fast.** Override: `--continue-on-failure` flag | Me (default fail-fast) |
| Timeouts too aggressive or too loose | Start with proposed values; tune based on first 5-10 runs | Me (initial) |
| Server may not have INI timeout keys; falls back to defaults | Ship with splainer entries so operators know | Me (implement) |
