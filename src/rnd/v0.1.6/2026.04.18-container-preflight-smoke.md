# Container Preflight Smoke — Design

**Filed**: 2026-04-18, Session be57a252
**Precipitating event**: TFE Resume `tfe-93fb4cf2` died 21 seconds into Phase 3 with `fatal: not a git repository (or any of the parent directories): .git` — the exact Bug 9a symptom — on a test container whose mount set predated yesterday's Bug 9a compose edit.
**Status**: design complete; implementation in progress.

---

## Problem

Bug 9a's `docker-compose.yml` edit adds `.git` + `~/.claude/.credentials.json` + `~/.lora_env` to the `lupin-rest-test` bind-mount set. The fix lives in the compose file — but a `docker restart` does NOT re-read the compose file; only `docker rm -f` + `docker compose up -d` picks up new mounts. Containers created before the compose edit run in production-drift without any in-code signal until Phase 3 reaches `git worktree add` and crashes.

Existing test coverage does not catch this drift:

- **Host-run unit tests** (`test_worktree_context.py`, 9 tests) use `tempfile.TemporaryDirectory` + real `git init`. They verify `WorktreeContext` itself works. They cannot see inside a container.
- **Mocked BFE/TFE git tests** (28 tests across `test_bfe_git_ops.py` + `test_tfe_phase5_git.py`) assert command construction and success/failure handling. The subprocess is mocked — no real `.git` is ever touched.
- **Live E2E drivers** (`run-tfe-live-e2e.sh`, `run-bfe-live-e2e.sh`) submit jobs and observe queue transitions. They would CATCH this class of failure, but only at the cost of a multi-minute live run reaching Phase 3.

The missing tier is a **container preflight** — a host-run test that probes the running container's actual mount set and exercises the minimum git surface TFE/BFE require.

## Non-goals

- **No docker-in-docker**. The preflight runs from the host against an already-running `lupin-rest-test` container. If the container is not running, the preflight fails fast — it does not try to start one.
- **No speculative `~/.config/gh` mount**. `gh auth status` is probed WARN-only; a failing probe emits a warning so it's visible before Phase 5 trips on it, but does not fail the preflight. We'll add the mount only when a real Phase 5 run actually asks for auth and fails.
- **No CoSA code changes**. The failure message from `WorktreeContext` is already clear ("not a git repository"); the postmortem explicitly declined a defensive `enabled=False` fallback in favor of keeping deployment errors loud.
- **No replacement for existing unit tests**. The 9 `test_worktree_context.py` tests stay — they validate the context-manager logic. Preflight is additive and validates the deployment.

## Design

### Artifacts

1. `src/scripts/preflight-test-container.sh` — bash script, host-runnable, exits non-zero on any fail.
2. `src/tests/smoke/test_container_preflight.py` — pytest wrapper that runs each probe as its own test so failures are diagnostic-specific.
3. One-liner wiring in `CLAUDE.md` and `.claude/skills/testing-patterns/SKILL.md`.

### Probe list (5 blocking + 1 WARN)

| # | Probe | What it validates | On fail |
|---|---|---|---|
| 1 | `docker ps` filter → `lupin-rest-test` running | Container exists and is up | Fail with remedy: start the container |
| 2 | `docker inspect` mount list contains `./.git:/var/lupin/.git` | Compose-file mount is actually applied to this container | Fail with remedy: `docker rm -f` + `compose up -d` |
| 3 | `docker exec lupin-rest-test git rev-parse --is-inside-work-tree` → `true` | `.git` mount is accessible AND git sees a valid worktree | Fail with remedy: as above |
| 4 | `docker exec lupin-rest-test git worktree add /tmp/preflight-smoke HEAD && git worktree remove /tmp/preflight-smoke` | TFE/BFE Phase 3's exact operation works end-to-end | Fail with remedy: as above |
| 5 | `docker exec lupin-rest-test test -f /home/rruiz/.claude/.credentials.json` | Claude Agent SDK credentials mount is active | Fail with remedy: as above |
| 6 | `docker exec lupin-rest-test gh auth status` (WARN-only) | `gh` CLI has a valid GitHub token for Phase 5 | Warn + note: Phase 5 `gh pr create` will fail; mount `~/.config/gh` when ready |

### Contract

- Script exits `0` on all blocking probes green, `1` otherwise. WARN-only probe cannot change exit code.
- Script emits one line per probe — `[OK]`, `[FAIL]`, or `[WARN]` — followed by the remedy if non-OK.
- pytest test file mirrors the probe list 1:1; a failing test on probe N explicitly names the probe.

### Host vs. container port convention

Host → test container: `:8000` (per reference memory). The preflight targets the container directly via `docker exec`, not the HTTP port — no port choice needed. `/health` polling after a recreate uses `:8000`.

## Why a new smoke tier

Existing smoke tests live in `src/tests/smoke/` and test Python modules directly (usually via `quick_smoke_test()` entry points). Container preflight is the first test of the **deployment** rather than the code. Placing it in `src/tests/smoke/` as a peer is the lowest-friction option:

- pytest discovery picks it up automatically.
- Slow (~5-10s) but still within the smoke tier's "seconds, not minutes" budget.
- Name prefix `test_container_*` makes it skippable via `pytest -k` when you're debugging non-container issues.

## Implementation order (per plan)

1. Write both R&D docs (this + execution log). [docs-first]
2. Write `src/scripts/preflight-test-container.sh`.
3. Write `src/tests/smoke/test_container_preflight.py`.
4. Wire one-liners into `CLAUDE.md` + `testing-patterns/SKILL.md`.
5. User runs `docker rm -f lupin-rest-test && docker compose up -d lupin-rest-test`.
6. Run preflight + pytest smoke against freshly-recreated container.
7. Deliberately regress + restore to prove the preflight catches the drift.
8. User re-clicks Resume on the stalled TFE; observe Phase 3 writes into `/var/lupin/.claude/worktrees/<job>/`.

## Acceptance criteria

- [ ] `src/scripts/preflight-test-container.sh` exists, is executable, exits 0 against a freshly-recreated container.
- [ ] `src/tests/smoke/test_container_preflight.py` exists, 5 blocking tests + 1 WARN test pass / warn correctly.
- [ ] `py_compile` passes on the new Python file.
- [ ] CLAUDE.md + testing-patterns skill mention preflight.
- [ ] Regression probe (remove `.git` mount → restart → run preflight) fails as expected.
