# Plan: LanceDB Test Isolation for UPE E2E Tests

## Context

Cold-start E2E prediction engine tests fail because the production LanceDB table (`prediction_decisions`) has accumulated real decisions from live usage. The `PredictionEngine` singleton, initialized at server startup, reads from the production table even after the integration test runner hot-swaps to `[Lupin: Testing]` config. Result: cold-start tests get `cbr_majority_vote` instead of the expected `cold_start`.

This is the **Phase 2 blocker** for the Prediction System Validation Campaign (Item A), which in turn blocks the Trust & Prediction Documentation Update (Item B).

**Session 373b** diagnosed the root cause and designed a 4-change fix plan at `src/rnd/2026.03.25-upe-lancedb-test-isolation.md`. This session implements it with additional discoveries.

---

## Implementation Summary

### Discoveries During Implementation

1. **Server is a separate process**: `PredictionEngine.reset()` in the test process is meaningless — the server runs as a separate Docker process on port 7999. All resets must happen server-side via HTTP endpoints.

2. **LanceDB files owned by root**: The server (Docker) creates LanceDB tables as `root:root`. The test process (running as `rruiz`) gets `Permission denied` when trying to drop tables. Table drops must happen server-side.

3. **`/api/init` is too heavy for per-test use**: Calling `/api/init` before each test triggers DB swaps and re-logins, causing 429 rate limiting. A dedicated lightweight endpoint was needed.

### Warm Test Fix: API Key Trailing Newline

All 11 `TestPredictionEngineWarm` failures caused by `ValueError: Invalid header value` — trailing `\n` in the API key file `src/conf/keys/notification-api-claude-code-dev`.

**Root cause**: `get_api_key()` in `util.py:661` returns `get_file_as_string(path)` without stripping. The key file has a trailing newline (common for text files). HTTP headers reject newline characters.

**Fix**: Add `.strip()` to `get_api_key()` return value at `util.py:661`. This is a system boundary — normalize at the source, not at every consumer.

**Additional fix**: Warm tests used `X-API-Key` header for embedding endpoint, but API key isn't seeded in test DB (`lupin_db_test`). Switched to JWT Bearer auth (already available from `ws_connection` fixture). Also updated warm test `setup_prediction_engine` fixture to use server-side `/api/prediction-engine/reset` endpoint (same permission issue as cold-start tests).
