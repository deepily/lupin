# Implementation Plan: TestSuiteJob (Pattern A — Queue-Level Monopolize)

## Context

Long-running test suites (integration ~15 min, E2E ~19 min) are currently kicked off manually via shell scripts and babysat to completion. This plan encapsulates them as a first-class AgenticJob in CJ Flow, enabling scheduled unattended execution with monopolize mode. This is the highest-ROI step toward Claude Code self-scheduling its own test verification.

PEFT training orchestrator (Pattern B) is deferred — it requires OS-level service lifecycle management that will be planned separately.

## Scope

Audited against the **agentic-voice-workflow** skill (v1.3) compliance checklist. All mandatory items are covered.

- `TestSuiteJob` class (AgenticJobBase subclass) with voice_io integration
- Config classmethod (`from_config`) + INI keys
- Factory integration (`agentic_job_factory.py`)
- Agent registry entry (`agent_registry.py`)
- Mode map + metadata entries (`todo_fifo_queue.py`)
- REST endpoint for programmatic submission (`routers/test_suite.py`)
- Voice routing training data (PEFT utterance templates)
- Notification Proxy Q&A script for automated testing
- Automated smoke test (LivePipelineTestBase)
- Unit tests + mode management test updates

## Phase 1: TestSuiteJob Class

**New files:**
- `src/cosa/agents/test_suite/__init__.py`
- `src/cosa/agents/test_suite/job.py`

**Class design:**
```
TestSuiteJob(AgenticJobBase)
    JOB_TYPE   = "test_suite"
    JOB_PREFIX = "ts"

    __init__(
        test_types: list,         # ["integration", "e2e"] or subset
        user_id, user_email, session_id,
        scheduled_at=None,
        pytest_args=None,         # Optional extra args list ["-v", "-k", "test_auth"]
        dry_run=False,
        debug=False, verbose=False
    )
    → super().__init__(..., monopolize=True)  # Always monopolize (DB hot-swap is exclusive)

    last_question_asked → "[Tests] integration, e2e"

    do_all() → standard pattern: RUNNING → asyncio.run(_execute()) → COMPLETED/FAILED

    _execute():
        voice_io.set_job_id( self.id_hash )           # MANDATORY: job card routing
        try:
            results = {}
            for suite in self.test_types:
                if self._cancel_requested: break
                await voice_io.notify( f"Starting {suite} tests...", priority="low", queue_name="run" )
                result = self._run_suite( suite )
                results[suite] = result
                await voice_io.notify(
                    f"{suite}: {result['passed']} passed, {result['failed']} failed",
                    priority="low", queue_name="run"
                )

            # Build summary + populate artifacts
            self.artifacts["cost_summary"] = { "suites_run": len(results), ... }
            await voice_io.notify( "All test suites complete", priority="medium", queue_name="run" )
            return conversational_summary
        finally:
            voice_io.clear_job_id()                    # MANDATORY: cleanup

    _execute_dry_run():                                # MANDATORY: separate method
        voice_io.set_job_id( self.id_hash )
        try:
            for suite in self.test_types:
                await voice_io.notify(
                    f"[DRY RUN] Would run {suite} tests",
                    priority="low", queue_name="run", job_id=self.id_hash
                )
            self.artifacts["cost_summary"] = { "mode": "dry_run", "suites": self.test_types }
            await voice_io.notify(
                "Dry run complete", priority="medium", queue_name="run",
                abstract="**Dry Run Summary**\n- Suites: ..."
            )
            return "Dry run: would have run ..."
        finally:
            voice_io.clear_job_id()

    _run_suite(suite_type) → dict:
        # Map suite → script path (using cu.get_project_root())
        scripts = {
            "integration" : f"{project_root}/src/tests/run-integration-tests.sh",
            "e2e"         : f"{project_root}/src/scripts/run-e2e-ui-tests.sh",
        }
        # subprocess.Popen (NOT run) for cancellation support
        # NO --bg flag (the job IS the background runner)
        # Poll loop checks self._cancel_requested, calls process.terminate() if set
        # Parse pytest output for pass/fail/skip/error counts
        # Return { "passed": N, "failed": N, "skipped": N, "errors": N, "exit_code": N, "log_path": str }

    _parse_pytest_output(stdout) → dict:
        # Regex on pytest summary line: "X passed, Y failed, Z skipped in Ns"
        # Also capture: "X error" lines
```

**Key decisions:**
- Uses `subprocess.Popen` + poll loop (not `subprocess.run`) to support cancellation via `process.terminate()`
- Does NOT use `--bg` flag on scripts — the AgenticJob is already the background execution context
- Always runs both suites regardless of individual failures (user preference)
- `monopolize=True` hardcoded in `super().__init__()` — DB hot-swap is always exclusive
- Stores log file paths in `self.artifacts` for UI access
- `voice_io.set_job_id()` / `clear_job_id()` in try/finally (mandatory per skill checklist)
- ALL `notify()` calls include `queue_name="run"` (mandatory per skill checklist)
- `_execute_dry_run()` is a separate method (mandatory per skill checklist)

**Reuse:** `cu.get_project_root()` from `cosa.utils.util` for script paths.

## Phase 4: REST Endpoint

**New file:** `src/cosa/rest/routers/test_suite.py`

Follow the pattern from `routers/deep_research.py`:
- `POST /api/test-suite/submit`
- Form fields: `test_types` (default "integration,e2e"), `pytest_args` (optional JSON list), `scheduled_at` (optional ISO datetime), `dry_run` (optional bool)
- Authentication required (JWT)
- Creates TestSuiteJob via factory, pushes to todo queue
- Returns JSON: `{ "job_id": "ts-...", "scheduled_at": "...", "message": "..." }`
