## Problem

During overnight `ts-79829a75` (2026-04-15 21:05 EDT), `tfe-7e8d3888` dispatched and generated **21 proposals across 8 clusters**. At 21:41 EDT the Phase 2 voice gate fired. Operator was offline. MCP's `/api/notify` returned HTTP 503 "User is offline and no default response provided". Dispatcher exception handlers swallowed the error and returned empty-answers to the orchestrator, which treated the empty dict as a valid "user selected nothing" response and finalized the job as `status=completed` (0 fixed) instead of `status=stalled`.

**Impact**: the 21 proposals are sitting in the TFE report markdown, but the UI ⏸ Resume button was never activated. Bug 11 (STALLED first-class state + UI Resume button) is bypassed for every offline overnight scenario until Bug 12 lands.

## Root cause

`src/cosa/agents/utils/agent_notification_dispatcher.py` has three blocking voice-gate methods:

| Method | exit_code=0 path | exit_code=2 path | **exit_code=1 path (HTTP 503)** |
|---|---|---|---|
| `present_choices` | Parse JSON, Bug-7 empty-answer normalization | Raises `VoiceGateTimeoutError` | ✅ Catch-all at line 453-457 raises `VoiceGateTimeoutError` (added by commit `49c238d` as Bug 7 side-effect) |
| `ask_confirmation` | Return boolean | Raises `VoiceGateTimeoutError` | ❌ Line 300: `return default == "yes"` — silently applies default |
| `get_feedback` | Return string | (No exit_code=2 branch) | ❌ Line 355: `return None` — silently returns None |

`_notify_user_sync` does NOT raise on HTTP 503. It catches the 503 and returns `NotificationResponse(exit_code=1, status="http_error_503")` (see `src/lupin_cli/notifications/notify_user_sync.py:228-236`). The dispatcher methods receive this structured response but two of them don't distinguish "user explicitly declined" from "user was unavailable."

## Critical discovery (not in forensics doc)

Commit `49c238d` (Session f01fdc2f, 2026-04-15 22:42 EDT) **already fixed** `present_choices` as a side-effect of the Bug 7 empty-answers normalization. The forensics doc was authored on 2026-04-16 morning, based on the overnight failure (pre-`49c238d` code), and didn't account for this. Bug 12's actual remaining scope is narrower than the forensics doc implies: **only `ask_confirmation` and `get_feedback` need the fix**.

## Fix

In `agent_notification_dispatcher.py`:

### `ask_confirmation` (lines 241-309)

Replace line 300 `return default == "yes"` with a catch-all raise matching the existing exit_code=2 pattern:

```python
# Catch-all: any other non-0 exit code (HTTP 503, connection errors, etc.)
# is "no answer received" — raise so the orchestrator can checkpoint-and-stall
# instead of silently applying the default.
from cosa.agents.test_fix_expediter.state import VoiceGateTimeoutError
raise VoiceGateTimeoutError(
    phase   = "confirmation",
    message = f"ask_confirmation received no answer (exit_code={response.exit_code}, status={response.status}) after {timeout}s"
)
```

Outer `except Exception as e` at lines 302-309 already re-raises `VoiceGateTimeoutError` — no change needed there.

### `get_feedback` (lines 311-359)

Same pattern: replace line 355 `return None` with the catch-all raise. Additionally, add the `isinstance(e, VoiceGateTimeoutError): raise` guard to the outer except handler (lines 357-359 currently lacks it — copy the pattern from `ask_confirmation`).

### `present_choices` — no change

Lines 453-457 already raise via the `49c238d` catch-all. Regression test will guard against future removal.

## Blast-radius analysis

`ask_confirmation` and `get_feedback` are used by BFE, SWE Team, Deep Research, Podcast Generator, Presentation Generator, and Claude Code agents (via the shared dispatcher). Post-fix, their 503-offline paths will propagate an uncaught exception instead of silently applying default/None.

| Caller | Files | Current behavior on 503 | Post-fix behavior |
|---|---|---|---|
| TFE `_per_cluster_voice_gate` | `test_fix_expediter/orchestrator.py:1085` | Returns default=yes → fix auto-applied | Raises → stall |
| BFE PlanWriter review gates | `bug_fix_expediter/orchestrator.py:880, 908, 992, 1056` | Returns default/None | Raises → propagates past BFE's isinstance check (see follow-up) |
| Other agents | Various `cosa_interface.py` | Returns default/None | Raises → propagates |

The trade-off (fails loud vs. silent wrong behavior) is acceptable. See follow-up.

## Architectural follow-up (out of scope this session)

`VoiceGateTimeoutError` is **duplicated** in two modules:
- `src/cosa/agents/test_fix_expediter/state.py:247`
- `src/cosa/agents/bug_fix_expediter/state.py` (separate class with same name)

The dispatcher imports from TFE's version only. BFE's orchestrator (e.g., `bug_fix_expediter/orchestrator.py:892`) does `isinstance(e, VoiceGateTimeoutError)` against its OWN class — which never matches TFE's raised exception. So BFE's "gate timeout" handling is subtly broken for present_choices today, and will be affected by the Bug 12 fix in the same way.

**Proposed unification**:
- Move canonical `VoiceGateTimeoutError` to `src/cosa/agents/utils/voice_errors.py`
- Re-export from both TFE and BFE `state.py` for backward compatibility
- Update dispatcher to import from the shared location

**Scope**: 3-4 files, ~40 lines; adds 1 new file. **Not this session** — flagged as follow-up TODO.
