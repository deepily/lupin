# Plan: Notification Admin Filter Toggle — "Not My Jobs" Mode

## Context

1001 SWE Team dry-run notification artifacts (`st-*` sender IDs) pollute the personal notification feed because `global_notification_recipient` points to `ricardo.felipe.ruiz@gmail.com`. The user wants to:
1. Create an admin account to redirect future test notifications
2. Add a "Not My Jobs" filter to isolate/manage foreign notifications
3. Scope bulk-delete to respect the active filter
4. Clean up existing test artifacts

## Phase 3: Backend — Notification Sender Filtering

### Ownership Model (Decided)

All notifications have `recipient_id = current_user`. Ownership is determined by `job_id`:

| `job_id` value | Ownership | Reasoning |
|----------------|-----------|-----------|
| Matches user's registered jobs (via UserJobTracker) | **Mine** | Job I submitted triggered this notification |
| Does NOT match user's jobs | **Others** | Someone else's job triggered this notification |
| `NULL` (no job_id) | **Mine** | Direct notification addressed to me — it's mine |

**Mechanism**: Option A — UserJobTracker lookup. No schema changes needed.

### `src/cosa/rest/routers/notifications.py` — `get_visible_senders`
- Add optional `exclude_own_jobs=true` query param
- When set, look up current user's job IDs from UserJobTracker across all queues
- Exclude senders whose notifications ALL have matching `job_id` values OR `job_id IS NULL`
- Only show senders with at least one notification whose `job_id` does NOT belong to current user

### `src/cosa/rest/db/repositories/notification_repository.py`
- Add `exclude_job_ids` param to `get_sender_last_activities_visible()`
- SQL: `WHERE job_id IS NOT NULL AND job_id NOT IN (:user_job_ids)`
- Note: `job_id IS NULL` notifications are excluded from "others" view (they're "mine")

## Phase 4: Backend — Scoped Bulk Delete

### `src/cosa/rest/routers/notifications.py` — Bulk delete endpoint

### `src/cosa/rest/db/repositories/notification_repository.py`
