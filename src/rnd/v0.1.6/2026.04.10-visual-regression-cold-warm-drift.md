# Visual Regression Cold/Warm Baseline Drift — Plan & Fix

**Date**: 2026-04-10
**Branch**: wip-v0.1.6-2026.03.12-cjflow-upe-and-playwrite
**Surfaced by**: Session 85b05d1d, full e2e run after #3 artifact relocation
**Status**: Plan written + minimal-invasive fix (file rename) implemented 2026-04-10. Validation requires a full 335-test e2e run.

---

## Context

After fixing the display bug (#1 in the session) and the container config bug (pytest.ini bind mount) and refreshing two stale baselines (Session 85b05d1d earlier work), a clean surgical run `./src/scripts/run-e2e-ui-tests.sh --bg -v -k visual` passes **12/12** in 37 seconds. The identical baselines, run as part of the full 335-test e2e suite, produce **12 errors** with message `"Snapshots DO NOT match!"` on pages including `login`, `register`, `change-password`, `profile`, `notifications`, and the 6 admin pages. The 10 pages that pass cleanly in isolated mode fail in the full-suite mode.

Diff PNGs from the failing full-suite run showed only faint subpixel yellow speckles in text areas (titles, labels, button text) — no structural differences, no layout shifts, no content changes. Icons, borders, cards, and form fields were pixel-clean. This rules out DB state contamination, dynamic content, and CSS layout drift as root causes.

**Hypothesis**: Chromium's font/render cache warms up over the course of 323 prior tests in the full e2e suite. By the time the visual regression tests fire (alphabetical position 28 of 31 test files), the headless Chromium process has accumulated enough font-cache state, GPU memory layout, and rendering pipeline warmth that subpixel anti-aliasing produces slightly different pixel output than a freshly-started Chromium. The baselines were captured in the cold state (during the surgical `-k visual` run which starts Chromium fresh), so the warm-state renders exceed the 0.1 pixelmatch threshold on anti-aliased text regions.

## Options Considered

### Option A — Re-baseline inside the full e2e via `--update-snapshots` full run

Run `./src/scripts/run-e2e-ui-tests.sh --bg --update-snapshots` once against the full 335-test suite, capturing baselines in the "warm" state. Subsequent full e2e runs would compare against warm baselines and pass.

**Rejected**: Trades cold-baseline-warm-fail for warm-baseline-cold-fail. The next `-k visual` surgical run would fail because Chromium starts cold. Also burns ~17 min every time we need to refresh and the state drifts further (browser updates, OS updates, etc.). This moves the problem instead of solving it.

### Option B — Raise the 0.1 pixelmatch threshold

Edit `pytest.ini`:
```ini
playwright_visual_snapshot_threshold = 0.2  # or 0.3
```

**Rejected** (as primary fix): Weakens the signal. A threshold high enough to tolerate cold/warm subpixel drift would also tolerate real visual regressions on small UI elements (button text changes, label updates). The plugin's threshold is a per-pixel matching tolerance, not a "percentage of pixels that can differ", so raising it reduces the SIGNAL strength globally. Acceptable as a fallback if Option D doesn't fix the problem.

### Option C — Run visual regression as a standalone scheduled suite

Exclude `test_visual_regression.py` from the main e2e suite (via `collect_ignore` in `conftest.py` or a pytest marker filter), and run it as a separate scheduled test suite. Pro: always cold Chromium. Con: adds a new schedulable test type (`visual`) that doesn't currently exist in the test_suite job's `SUITE_TIMEOUTS_SECONDS` dict or the `/api/test-suite/submit` validation; requires scaffolding in `src/cosa/agents/test_suite/job.py` (a CoSA submodule edit).

**Rejected**: Over-engineered for the problem. Adds a new suite type, new scheduler wiring, new CI paths, and doubles the visual-test maintenance surface. Reserve this as a long-term option if the problem recurs.

### Option D — Force visual regression to run FIRST in the e2e suite  ✅ RECOMMENDED

Use `pytest_collection_modifyitems` in `src/tests/e2e_ui/conftest.py` to reorder items after collection so all visual regression tests run before any other e2e test. Chromium is in its COLD state when visual tests run — matching the state where baselines were captured.

**Why this works**:
- Before hook: visual tests run after ~323 prior tests warm Chromium → subpixel drift
- After hook: visual tests run FIRST, before any test warms Chromium → pixel-identical to `-k visual` state
- Baselines stay valid (they're the cold-state captures already)
- The 323 other tests still run after visual regression and are unaffected by visual testing

**Why the conftest hook is better than a file rename**:
- The `pytest-playwright-visual-snapshot` plugin derives the baseline directory from `test_file_name_without_extension`. Renaming `test_visual_regression.py` → `test_00_visual_regression.py` would invalidate the baseline directory `io/test-suite/visual-baselines/test_visual_regression/...` — we'd have to rename both. Fragile.
- The conftest hook keeps the filename stable, keeps baseline paths stable, and makes the intent explicit via code + comment (not via naming convention).
- Still zero new dependencies — `pytest_collection_modifyitems` is a built-in pytest hook.
- Same reversibility: delete the function to revert.

**Why it's the minimum viable fix**:
- One conftest.py function addition
- Zero test code changes
- Zero new dependencies
- Zero changes to filesystem layout
- Trivially reversible: delete the hook function

## Implementation

### The conftest hook

Added to `src/tests/e2e_ui/conftest.py`:

```python
def pytest_collection_modifyitems( config, items ):
    """
    Reorder collected tests so visual regression runs before everything else.
    ...
    """
    visual = [ i for i in items if "test_visual_regression" in str( i.fspath ) ]
    other  = [ i for i in items if "test_visual_regression" not in str( i.fspath ) ]
    items[ : ] = visual + other
```

The full docstring explains the cold/warm hypothesis and links back to this plan doc. Works for any pytest invocation: full e2e (reorders 335 items), `-k visual` (only collects 12, hook is a no-op), specific file (only collects that file's items, hook is a no-op).

## Risk Assessment

| Risk | Severity | Mitigation |
|------|----------|-----------|
| Other tests depend on visual regression running later (fixture cleanup, etc.) | Low | Quick grep for cross-file dependencies; visual regression uses only standard fixtures (`clean_test_db`, `admin_page`, `logged_in_page`) which don't share state |
| Rename breaks test discovery elsewhere (CI workflows, docs, references) | Low | grep for `test_visual_regression` references; update any hardcoded paths |
| The `_00_` convention isn't enforced by pytest — some future refactor might re-order | Low | Add an explanatory comment at the top of the file; if drift recurs, escalate to Option C (standalone suite) |
| Chromium cache isn't the real root cause | Medium | If this fix doesn't work, the warm-path check will fail and we have diagnostic data for the next hypothesis |

## Out of Scope

- Raising the pixelmatch threshold globally (Option B — reserved as fallback)
- Splitting visual regression into its own scheduled suite type (Option C — reserved as long-term option)
- Re-baselining anything (current baselines are correct for the cold-state path)
- Server-side changes to the test_suite job
- Any investigation into why Chromium's cache warms up (it just does; that's normal)
