## Outcome

Dev (`lupin-rest-dev`) and test (`lupin-rest-test`) containers now run as **UID 1001 (rruiz)**. All files written to bind-mounted host paths (LanceDB, io/) land owned by rruiz — eliminating the root-file regrowth that broke backups.

## Hurdles encountered

### 1. Silent `docker compose build` exit-0

Initial `docker compose build lupin-rest-dev lupin-rest-test` returned exit 0 with empty stdout/stderr while the image remained 5 days old. Direct `docker build` surfaced the real error (build context permission denial). Suspect: compose swallowed BuildKit progress when invoked non-TTY.

### 2. Build context: `postgresql-dev-data` mode 700

Directory owned by postgres container UID 70, mode 700. BuildKit walks the full FS before applying `.dockerignore`, so it hit "permission denied" on this dir despite being excluded. **Fix**: `sudo chmod -R g+rX` on the directory (postgres still owns it; group rruiz now has traversal-only access).

### 3. Build context: `io/` + other bind-mount dirs

`io/` (presentation outputs) and similar runtime-only bind-mount dirs weren't in `.dockerignore` and contained container-written root-owned files. **Fix**: expanded `.dockerignore` to exclude `io/`, `src/rnd/`, `src/tests/`, `src/ephemera/`, `src/lupin-plugin-firefox/`, `src/lupin-mobile/`. These paths are never `COPY`'d by the Dockerfile.

### 4. Root-file regrowth between Option B and container stop

User ran Option B (`sudo chown -R rruiz:rruiz lupin.lancedb/`) earlier in the day. Container kept running and accumulated 1,663 new root-owned files before I stopped it. **Fix**: second round of `sudo chown -R rruiz:rruiz lupin.lancedb io/` after `docker compose down`.

### 5. HuggingFace cache path mismatch (anticipated, mitigated)

First pass Dockerfile change only added `ENV HOME=/home/rruiz`. Docker layer cache could reuse earlier HF pre-download RUN commands (cache keyed by command string, not env), leaving models at `/root/.cache/huggingface`. UID 1001 can't enter `/root` (mode 700). **Preemptive mitigation** added before build:
- `ENV HF_HOME=/home/rruiz/.cache/huggingface` (explicit, not `$HOME`-dependent)
- Late-stage RUN to `cp -an /root/.cache/. /home/rruiz/.cache/ && rm -rf /root/.cache` (no-op when fresh build, saves a `--no-cache` rebuild when layers are reused)

Final image rebuild was full (useradd invalidated everything), so the relocation RUN was a no-op, but the guard remains for future incremental builds.

### 6. marp CLI coordination

A parallel session added `@marp-team/marp-cli v4.3.1` install to the Dockerfile before my rebuild. I paused my build so both changes landed in one image instead of back-to-back full rebuilds.

## Addendum — post-verification additions

Two follow-on changes landed in the same session after Option C verified green:

### `CHROME_PATH` env on both services

Orchestrator's marp subprocess needs an explicit Chromium path because HF_HOME/Playwright's autodiscovery doesn't find the `ms-playwright` cache under `/home/rruiz`. Added to both `lupin-rest-dev` and `lupin-rest-test` in `docker-compose.yml`:

```
CHROME_PATH: /home/rruiz/.cache/ms-playwright/chromium-1208/chrome-linux64/chrome
```

Verified post-bounce on both containers: `docker exec lupin-rest-{dev,test} printenv CHROME_PATH` returns the expected path; `/health` on :7999 + :8000 both HTTP 200.
