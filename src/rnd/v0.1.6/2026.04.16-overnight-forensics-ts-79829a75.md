## The status=completed anomaly → **Bug 12** (new)

**Expected**: voice gate fires → ricardo offline → MCP 503 → dispatcher converts to `VoiceGateTimeoutError` → orchestrator saves checkpoint → `StalledException` → `job.state=STALLED` → row persists as `stalled` → UI ⏸ badge + Resume button.

**Actual**: MCP returned 503 → dispatcher's `_notify_user_sync()` raised an HTTP exception → caught in `present_choices`'s generic `except Exception as e` block → logged + returned `{"answers": {}}` (empty dict) → orchestrator treats as "empty selection" (valid user response) → finalizes with `status=completed`, 0 fixed.

**Why Bug 7 didn't catch this**: Bug 7 normalizes **empty answers from a 200 response** as timeout. It doesn't convert **503 HTTP exceptions** to timeouts. The exception path and the empty-payload path are distinct.

**Fix locus**: `src/cosa/agents/utils/agent_notification_dispatcher.py` — the final `except Exception as e` in `present_choices` / `ask_confirmation` / `get_feedback`. When the exception is an HTTP 503 with body `"User is offline"`, raise `VoiceGateTimeoutError` so the orchestrator can stall + checkpoint. Anything else (real network errors, 500s) should still be logged and return default.

**Impact on overnight result**: the 21 proposals aren't lost — they're in the report markdown. But because `status != 'stalled'`, the UI doesn't show a Resume button for `tfe-7e8d3888`. To act on the proposals today you'd either:
1. Read the report, pick 1-3 proposals, and apply manually.
2. After Bug 12 lands, re-run a fresh TFE against the same remediation snapshot (`2026.04.15-at-21:05-EDT-all-remediation.json`) — re-cluster + re-diagnose cost ≈ $0.30, and this time the 503 will properly stall.
3. Manually flip `tfe-7e8d3888`'s DB row to `status=stalled` + inject the checkpoint + re-resume through the UI (same pattern we used yesterday afternoon for the synthetic smoke).

Option 2 is cleanest; Option 1 is fastest; Option 3 recovers the existing Sonnet spend.
