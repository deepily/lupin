## The one remaining gap

**BFE's end-of-run abstract (`src/cosa/agents/bug_fix_expediter/job.py:371-397`) does not surface `fix_result.last_stderr`** when a fix was auto-rejected after max attempts. TFE's end-of-run abstract now includes a "Failed fix diagnostics" section with stderr tails (added in Part 1 Item C). The user's "work like TFE" directive implies BFE should do the same — at first glance triviality, but it's the difference between *knowing why the fix failed* from the completion notification vs. digging through worktree logs.

---

## Proposed edit (exact shape)

**File**: `src/cosa/agents/bug_fix_expediter/job.py`

**Site**: after the existing `Duration` line (line 384) and before the worktree artifacts block.

**Insert**:

```python
            # Failed-fix diagnostics — last_stderr retained by FixExecutor's
            # auto-reject path (Part 1 Item A + C). Mirrors TFE's job.py parity.
            # BFE runs one fix at a time, so no top-N cap needed — embed the tail directly.
            if ( not fix_applied
                 and getattr( fix_result, "last_stderr", None )
                 and getattr( fix_result, "attempts", 0 ) > 0 ):
                lines.append( "" )
                lines.append(
                    f"**Failed fix diagnostics** ({fix_result.attempts} attempt(s)):"
                )
                lines.append( "```" )
                lines.append( fix_result.last_stderr )
                lines.append( "```" )
```

**Why `getattr`**: `FixResult` is the shared Pydantic model (BFE's `state.py` — Part 1 added the fields), so these attributes always exist. The `getattr(...)` calls are defensive *for the old BFEState dict-shaped fix_result in the "no selected fix" branch at `job.py:322-323`*, where a minimal FixResult is constructed that may not go through FixExecutor. Without `getattr`, that branch raises AttributeError if Pydantic's default-value defaults ever drift.

Actually — this might violate the user's feedback "Fix at source, not consumer" (`feedback_no_defensive_programming`). The proper fix is to rely on Pydantic defaults (`attempts: int = 0`, `last_stderr: Optional[str] = None`) and write:

```python
            if not fix_applied and fix_result.last_stderr and fix_result.attempts > 0:
                lines.append( "" )
                lines.append(
                    f"**Failed fix diagnostics** ({fix_result.attempts} attempt(s)):"
                )
                lines.append( "```" )
                lines.append( fix_result.last_stderr )
                lines.append( "```" )
```

Decision: **drop the `getattr`**. The Pydantic defaults guarantee the attributes exist; "no selected fix" branch's `FixResult(applied=False, success=False, details="No fix selected")` will have `attempts=0` and `last_stderr=None`, which cleanly evaluates to False and skips the block.
