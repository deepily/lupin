# CJ Flow History — Manual Testing Rubric for Delete & Retry

## Context

Delete and retry buttons are fully implemented in the CJ Flow accordion history section (Session 371). Automated tests cover API-level auth/validation and basic E2E visibility, but **no automated test actually clicks the retry button** and verifies the full flow. Manual testing is needed to confirm the end-to-end user experience works correctly.

### Key Implementation Details

- **Delete**: Hard deletes from PostgreSQL. No undo. Original record permanently removed.
- **Retry**: Creates a **new** job in the todo queue using the original `question_text`. Original job record is **not** updated (stays `failed`/`interrupted`). No database link between original and retried job.
- **Retry visible on**: `failed` and `interrupted` jobs only
- **Delete visible on**: All history jobs

## Prerequisites

1. FastAPI server running on port 7999
2. Logged in as a regular user (not admin) in the Lupin UI
3. At least one completed job and one failed/interrupted job in the history section
   - If no jobs exist, submit a deep_research or podcast job and let it complete/fail
4. Browser dev tools open (Network tab + Console)
