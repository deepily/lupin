## Problem

Flat 20-turn budget across all TFE Phase 3 fix attempts is too tight for everything. Today's 11 selected fixes varied wildly in scope:

| Proposal | fix_type | files | likely turns needed |
|---|---|---|---|
| C2: Add PRODUCT_NAMES entry | `code_patch` | 1 | ~10 |
| C4: Add resume_from to all_agents | `code_patch` | 1 | ~10 |
| C3: Fix `== 9` → `== 10` | `test_patch` | 3 | ~20-30 |
| C1: Re-capture 12 visual baselines | `test_patch` | 5 | 60+ |
| C8: stop.py + notifications.js | `code_patch` | 2 | ~30 |

Single flat cap either wastes budget on trivial fixes or starves complex ones.

## Non-goals

- **No mid-flight turn extension**. `claude-agent-sdk`'s `max_turns` is set at `sdk_query()` call time and is not live-extensible — that's Option B, queued in `TODO.md` as a follow-up if Option A proves insufficient.
- **No operator picks tier at voice gate**. Adds friction across N proposals. Auto-derive from proposal metadata instead; operator can still override via Option B or a future refinement.
- **No BFE parity in this pass**. BFE's `_build_coder_options` at `bug_fix_expediter/orchestrator.py:1544` has the same pattern but wasn't hit in today's incident. Parity work deferred unless a BFE run trips on it.

## Design

### Tier rule (auto-derive from proposal metadata)

```python
def _derive_budget_tier( proposed ) -> str:
    """
    small  — single-file test/config tweak (≤1 file, test_patch or config_change)
    large  — multi-file change (≥4 files) — visual baselines, broad refactors
    medium — everything else (single-file code_patch, 2-3 file anythings, retries)
    """
    n_files = len( proposed.changes ) if proposed.changes else 0
    ft      = proposed.fix_type
    if n_files == 1 and ft in ( "test_patch", "config_change" ):
        return "small"
    if n_files >= 4:
        return "large"
    return "medium"
```

Applied to today's 11 fixes, this would have assigned:
- **small** (30 turns): C3 minimal scope, C7 minimal — trivial test flips
- **medium** (50 turns): C2 PRODUCT_NAMES, C4 resume_from, C3 full 3-site flip, C8 stop.py+notifications.js
- **large** (80 turns): C1 visual baselines (5 files)

### Orchestrator wiring (CoSA side — `orchestrator.py`)

Three surgical edits:

**1. `__init__`**: add side-channel attribute

```python
# Per-fix budget tier (set by Phase 3 loop, read by _build_tfe_coder_options).
# Sequential Phase 3 execution makes this single-writer safe.
self._current_budget_tier : str = "medium"
```

**2. Phase 3 loop (before `executor.execute_fix(...)`)**: compute + set tier

```python
self._current_budget_tier = self._derive_budget_tier( proposed )
await self._notify(
    f"Applying fix {i}/{n} for {proposed.cluster_id}: {proposed.title} "
    f"[budget={self._current_budget_tier}]",
    priority="low",
)
```

(replaces the existing `Applying fix N/M` notification; budget tier is added inline so operator can see it mid-run.)

**3. `_build_tfe_coder_options`**: swap `max_turns` source

```python
budget_turns = {
    "small"  : self.config.coder_budget_small_turns,
    "medium" : self.config.coder_budget_medium_turns,
    "large"  : self.config.coder_budget_large_turns,
}[ self._current_budget_tier ]

return ClaudeAgentOptions(
    ...
    max_turns = budget_turns,
    ...
)
```

Drop the old `self.config.max_fix_attempts * 10` formula. `max_fix_attempts` stays as config (used elsewhere for retry semantics, not turn budget).
