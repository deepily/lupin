# Bug-Fix Plan — `all` test-suite aggregation + history-card scroll toggle

## Context

An overnight `all` test-suite run (2026-04-14 00:42 EDT) produced an apparently empty report despite roughly a dozen job cards showing completed sub-tasks in the done-queue history UI. Two separate bugs were surfaced:

1. **Aggregation black hole**: `io/test-suite/2026.04.14-at-00:42-EDT-all-*.{json,md}` report `0 passed, 0 failed, 1 error, 0 skipped`, `failures: []`, and no per-suite output. The 4661.7s duration is the smoking gun — this is the per-suite timeout tripping, and the timeout return path discards all captured output and fails to synthesize a failure record, so `TestSuiteCompletionWatchdog` Gate 3 refuses to dispatch TFE because `len(failures)==0`.
2. **UI regression**: Job cards rendered into the History panel from `/api/job-history` do not expand when the scroll-toggle is clicked; cards created live during the session expand normally.

Fixing both is required for nightly CJ-Flow test runs to produce actionable output and for operators to inspect results.

---

## Root cause analysis

### Bug 1 — `all` suite aggregation

`src/cosa/agents/test_suite/job.py`:

- Line 292 loops `for suite_type in self.test_types`. When `test_types=["all"]`, this is a single iteration that shells out to `src/tests/run-all-tests.sh` (unit → smoke → websocket → integration → e2e, sequentially combined, ~70–80min wall time).
- Lines 682–698 — the **timeout path** — calls `process.terminate()` and returns:
  ```python
  {"passed":0,"failed":0,"skipped":0,"errors":1,"exit_code":-2,
   "log_path":None,"duration":elapsed,"error":f"Timeout: {suite_type} ..."}
  ```
  Notice: **no `failure_details` key**, **no log file written**, stdout already captured in `stdout_lines` is discarded.
- Lines 421–447 build the remediation snapshot by iterating `result.get("failure_details", [])` — which is empty on timeout — producing `failures: []` even though `total_errors==1`.
- `TestSuiteCompletionWatchdog` Gate 3 at `src/cosa/rest/test_suite_completion_watchdog.py:150` requires `len(failures)>0` to dispatch TFE, so no remediation is launched and the 78-minute run goes to waste.

The "~dozen cards in history" are almost certainly **side-effect agentic jobs** (Presentation, DeepResearch, Podcast, etc.) that tests submit to CJ Flow — they are NOT sub-TestSuiteJob entries. `job.py` only ever stores `self.suite_results["all"]` (one bucket), so the parent's view of child state is fundamentally flat.

### Bug 2 — History-card scroll toggle

`src/fastapi_app/static/js/notifications.js`:

- Both live and history cards converge on `renderJobCard()` (line 6744) which emits an inline `onclick="...toggleJobCard('${jobId}','${queueName}')"` and `<div id="job-details-${jobId}">`.
- `renderHistoryCard` (line ~6020–6086) normalizes `job_id = job.id_hash` (line 6039) and maps status→queueName (6066–6073).
- `toggleJobCard` (line 6991–7014) resolves the details pane with `document.getElementById('job-details-${jobId}')` — **not** scoped to the clicked card.

**Hypothesis (needs devtools confirmation)**: when a job appears both in the live Done section AND in the History section of the same page, two elements share `id="job-details-${jobId}"`. `getElementById` returns the first (the Done-section, often hidden), so clicking the History copy's toggle silently flips the Done copy's `.collapsed` class. The History card never visibly moves.

A secondary possibility is that `renderHistoryCard`'s `lastIndexOf('</div>')` splice at line 6078–6083 corrupts card HTML for certain statuses, but the `if (!canRetry) return '';` early-return at 6103 makes this a no-op for most (completed) cards, so this is unlikely to be the general cause.

## Proposed fix

### Step 0 — Confirm Bug 2 root cause in-browser (≤ 5 min)

Before editing JS, open the done-queue page, load enough history that at least one job appears in both Done and History, and in devtools Console run:
```js
document.querySelectorAll('[id^="job-details-"]').length
  vs
new Set([...document.querySelectorAll('[id^="job-details-"]')].map(e=>e.id)).size
```
If the two numbers differ, ID collision is confirmed. If not, instrument `toggleJobCard` with a `console.log` temporarily to see whether it's firing and what element it resolves. Record the finding in the session notes before writing the fix.

### Step 1 — Bug 1A: timeout path must preserve evidence

**File**: `src/cosa/agents/test_suite/job.py`

Modify the timeout branch at lines 682–698 to:
1. Read any remaining buffered stdout via `process.stdout.read()` before `terminate()`.
2. Write the captured stdout to `/tmp/{suite_type}-{timestamp}.log` and symlink (reuse the logic at lines 714–734 — refactor into a helper `_write_log(suite_type, stdout_text)`).
3. Set the returned dict's `log_path` to the written file.
4. Populate a synthetic `failure_details` entry so the watchdog can see the timeout:
   ```python
   "failure_details": [{
       "classname": f"TestSuiteJob.{suite_type}",
       "name"     : "timeout",
       "time"     : f"{elapsed:.1f}",
       "type"     : "ERROR",
       "message"  : f"Subprocess killed after {timeout_secs}s",
       "traceback": "".join(stdout_lines[-40:]).strip(),
   }]
   ```
5. Apply the same treatment to the generic `except Exception` path at lines 760–771 (currently returns `errors:0` — a bug in its own right; should be `errors:1` with a failure_details entry describing the exception).

This converts "silent timeout with 0-failure snapshot" into "surfaced timeout with a real failure record the watchdog can route to TFE".

### Step 2 — Bug 1B: expand `"all"` into component suites

**File**: `src/cosa/agents/test_suite/job.py`

When `"all"` is present in `self.test_types`, expand it at the top of `run_task()` into the underlying component list (`unit`, `smoke`, `websocket`, `integration`, `e2e`) and run each as its own `self.suite_results[component]` entry, using each component's own timeout. This:
- Gives per-suite cards in the report (matches what the user expected).
- Prevents one slow suite from vaporizing the others' results.
- Aligns the persisted `suite_results` structure with the UI's mental model.

Keep `run-all-tests.sh` available for CLI use but stop invoking it from the agent.

Add/update the timeout configuration in `src/conf/lupin-app.ini` with per-component values (plus matching `[Lupin: Baseline]` explanations in `lupin-app-splainer.ini` — project convention). Suggested starting values: unit 300s, smoke 600s, websocket 600s, integration 900s, e2e 1500s (total ~65min vs. current single `all` budget of ~77min).

### Step 3 — Bug 2 fix (contingent on Step 0)

**File**: `src/fastapi_app/static/js/notifications.js`

Most likely fix (if ID collision is confirmed in Step 0): make `toggleJobCard` scope the details lookup to the clicked card instead of the document:

```js
toggleJobCard( jobId, queueName ) {
    const card    = document.getElementById( `job-card-${jobId}` ) ||
                    event?.currentTarget?.closest( '.job-card' );
    if ( !card ) { this.error( `Job card not found: ${jobId}` ); return; }
    const details = card.querySelector( `#job-details-${jobId}, .job-details` );
    // ... rest unchanged
}
```

Better still, namespace the DOM IDs by section at render time so a job never has two cards with the same ID:
- `renderJobCard(job, queueName)` already has `queueName` — prefix IDs as `job-card-${queueName}-${jobId}` / `job-details-${queueName}-${jobId}` and update the inline `onclick` to match.
- `renderHistoryCard` passes a history-specific queueName (e.g. `history`) so its IDs can't collide with live Done cards.
- `toggleJobCard` signature becomes `(jobId, queueName)` resolving `job-details-${queueName}-${jobId}`.

Prefer the second approach — it eliminates the collision class of bug rather than papering over one symptom. It's a local rename in three places (renderJobCard, renderHistoryCard, toggleJobCard) plus any other sites calling `getElementById('job-details-...')`.

### Step 4 — Tests

- **Unit** (`src/tests/unit/`): add a `TestSuiteJob` test that stubs `subprocess.Popen` to simulate timeout, asserts the returned dict has `failure_details` with one ERROR entry, `errors==1`, and a non-null `log_path`.
- **Integration** (`src/tests/integration/`): add a short-timeout run (e.g. synthetic 5s-budget on a deliberately-slow fake suite) and assert `remediation.json.failures` has exactly one entry with `type: "ERROR"` and `name: "timeout"`.
- **E2E UI** (`src/tests/e2e_ui/`): add a Playwright test that loads a page with both a live Done card and a History card for the same job_id (or two distinct jobs), clicks each toggle, and asserts each `job-details-*` element independently transitions between `collapsed` and expanded. Cover both paths — don't just test the new ID scheme in isolation.
- **Voice-routing training data**: not applicable — no new agent introduced.

Run the full pre-merge gate per CLAUDE.md:
```
pytest src/tests/unit/ -v
./src/scripts/run-websocket-smoke-tests.sh
./src/scripts/run-e2e-ui-tests.sh --bg -v
./src/tests/run-integration-tests.sh --bg -v
```
E2E and integration must use `--bg`; wait for E2E to complete before launching integration (final gate). Integration tests are scheduled via `/schedule-tests` per the project's skill, not hand-rolled.

### Step 5 — Verification

1. Manually kick off a test-suite run against a deliberately short timeout to trigger the timeout branch; confirm `failures: [...]` is populated and the markdown report contains the captured stdout tail.
2. Trigger a normal `all` run (or schedule one); confirm the report now shows five `## unit`, `## smoke`, `## websocket`, `## integration`, `## e2e` sections with independent counts.
3. Reload the queue UI, expand Done and History, confirm every card's scroll toggle independently expands/collapses.
4. Confirm `TestSuiteCompletionWatchdog` dispatches TFE on the failed run (check logs for Gate-3 dispatch).
