# Plan: OpenAPI-to-Markdown Automation Script

## Context

The Lupin project has two auto-generated API doc files in `src/docs/fastapi/` — `api.json` (raw OpenAPI spec, 118KB minified) and `api.md` (3,321-line Markdown). Both were last generated on 2026-03-23 with **no visible automation script**. Meanwhile, 26 router files define endpoints and the hand-maintained `rest-api-reference.md` quick reference stays separate (and should remain hand-maintained).

The `openapi-to-markdown` CLI (v0.1.0b2) is already installed in `src/cosa/.venv/` with entry points `openapi-to-markdown` and `api2md`. It supports `--input_file`, `--curl_url`, `--output_file`, `--filter-paths`, and `-t/--templates-dir`.

**Goal**: Create a shell script to regenerate `api.json` + `api.md` from the live FastAPI server's `/openapi.json` endpoint, and document it.

---

## Implementation

### Step 1: Create `src/scripts/generate-api-docs.sh`

A bash script that:

1. **Validates** `$LUPIN_ROOT` is set
2. **Supports two modes**:
   - Default: fetch from live server (port 7999) and generate both files
   - `--offline`: regenerate `api.md` from existing `api.json` (no server required)
3. **Server health check** (default mode): curl the `/openapi.json` endpoint with a 5s timeout; error gracefully if server not running
4. **Fetch + pretty-print JSON**: `curl -s /openapi.json | python3 -m json.tool > api.json` — makes diffs meaningful (currently a single 118KB line)
5. **Generate Markdown**: `openapi-to-markdown --input_file api.json --output_file api.md`
6. **Inject timestamp footer**: append `_Auto-generated on YYYY.MM.DD HH:MM:SS by src/scripts/generate-api-docs.sh_`
7. **Summary output**: report line counts for both files

**Key paths** (all via `$LUPIN_ROOT`):
- Output: `$LUPIN_ROOT/src/docs/fastapi/api.json`, `$LUPIN_ROOT/src/docs/fastapi/api.md`
- Venv python: `$LUPIN_ROOT/src/cosa/.venv/bin/python3`
- CLI tool: `$LUPIN_ROOT/src/cosa/.venv/bin/openapi-to-markdown`

### Step 2: Update `CLAUDE.md`

Add under `## COMMANDS`:
```
- Regenerate API docs: `src/scripts/generate-api-docs.sh` (requires server on port 7999)
```

Update the `## DOCUMENTATION TOUCHPOINTS` table to note that when routers change, run `generate-api-docs.sh` to update `src/docs/fastapi/`.

### Step 3: Test

1. Run with live server: `./src/scripts/generate-api-docs.sh` — verify both files regenerated
2. Run offline: `./src/scripts/generate-api-docs.sh --offline` — verify `api.md` regenerated from saved JSON
3. Spot-check: compare `api.md` line count and endpoint coverage against the 26 known routers

## Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| `rest-api-reference.md` | Stay hand-maintained | It's a curated quick reference with auth annotations; auto-generation would lose curation |
| Two-step (fetch JSON then convert) | Yes | Saves both artifacts; enables `--offline` mode |
| Pre-commit hook | No | Requires live server at commit time — too fragile |
| Custom Jinja2 templates | No | Default templates match existing `api.md` output (emoji headings etc.) |
| Pretty-print JSON | Yes | Current 118KB single-line blob is useless for diffing |
