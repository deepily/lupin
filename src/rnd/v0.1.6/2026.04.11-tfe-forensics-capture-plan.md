## Context

A real TFE job (`tfe-d9e6b50f`, launched by `TestSuiteCompletionWatchdog` after test suite
`ts-f199de94::0cf47e2d-d5a1-4cd4-addf-79810fd32b15` failed) ran for ~267 seconds, reached
**Phase 2** of the pipeline, successfully wrote a complete diagnosis + fix proposal plan to disk,
and then died at the Phase 2 voice gate with the UI showing only the literal string
`"Unknown error"`. Investigation this session reconstructed the full failure trail from docker
logs + filesystem artifacts and cataloged **six independent bugs** that collaborate to destroy
the forensic signal whenever a TFE dies. The underlying trigger (`present_choices` failing to
resolve `target_user`) is actually a seventh bug — and even after it's fixed, the other six will
continue dropping data on every future TFE failure for any reason.

**Goal**: Make a dead TFE job capture and surface enough forensic data that a user can diagnose
the failure without SSH'ing into the server and grepping docker logs. Specifically:
- Every TFE failure captures a full Python traceback into `self.error`
- Every TFE failure persists a row in `job_history` with the traceback in `metadata_json.stack_trace`
- Every TFE failure emits an urgent voice notification with the real error message (not "Unknown error")
- TFE's voice-notification plumbing stops flooding the log with hundreds of harmless kwarg errors
- The specific `present_choices` target_user bug that triggered THIS failure is fixed
- The dead-queue UI card surfaces the path to the partial plan file when one exists, so users
  can recover the diagnosis + proposed fixes that TFE computed before dying

**Non-goals**:
- A full TFE live E2E test (that's separate, already tracked as a TODO)
- Any GPU-touching work (user-run only)
- Investigating or modifying the TFE parallel session's in-flight scope

### Fix 2 — Rewrite TFE `do_all()` to match the BFE pattern

**File**: `src/cosa/agents/test_fix_expediter/job.py:119-148` (**CoSA submodule**)

Replace the current block with the BFE-aligned pattern. Key changes:

1. **Use `self.state` (enum) throughout** — delete `self.status = "running" | "completed" | "failed"`. Replace with `self.state = JobState.RUNNING | COMPLETED | FAILED`. The `self.status` string was a dead attribute that no consumer reads.
2. **Capture full traceback into `self.error`** — replicate `tb_str = traceback.format_exc()` + `self.error = f"{e}\n\n{tb_str}"` from BFE.
3. **Set `self.completed_at`** on both success and failure paths.
4. **Unconditional stdout print** of `f"[TestFixExpediterJob] Failed: {e}"` and `tb_str` — NOT gated behind `self.debug`. Production tracebacks must hit stdout unconditionally so they land in `docker logs lupin-rest` regardless of the job's debug flag.
5. **Keep `self.answer_conversational`** set to `f"TFE failed: {str(e)}"` for UI display.

Target final shape (CoSA-side edit — exact form):

```python
def do_all( self ) -> str:
    if self.debug:
        print( f"[TestFixExpediterJob] Starting do_all() for: {self.source_test_suite_job_id}" )

    self.state      = JobState.RUNNING
    self.started_at = cu.get_current_datetime_iso()

    try:
        result = asyncio.run( self._execute() )

        if self._cancel_requested:
            self.state                 = JobState.CANCELLED
            self.completed_at          = cu.get_current_datetime_iso()
            self.error                 = "Cancelled by user request"
            self.answer_conversational = result or "TFE was cancelled by the user."
            return self.answer_conversational

        self.state        = JobState.COMPLETED
        self.completed_at = cu.get_current_datetime_iso()
        self.result       = result
        self.answer_conversational = result
        return result

    except Exception as e:
        import traceback
        tb_str = traceback.format_exc()

        self.state        = JobState.FAILED
        self.completed_at = cu.get_current_datetime_iso()
        self.error        = f"{e}\n\n{tb_str}"

        print( f"[TestFixExpediterJob] Failed: {e}" )
        print( tb_str )

        self.answer_conversational = f"TFE failed: {str( e )}"
        return self.answer_conversational
```

Mirrors BFE `do_all` at `bug_fix_expediter/job.py:107-157` exactly.

### Fix 3 — Wrap TFE `_execute()` phases in outer try/except with urgent voice notification

**File**: `src/cosa/agents/test_fix_expediter/job.py:149-218` (**CoSA submodule**)

Add a top-level `try/except` around the orchestrator phase invocations:

```python
async def _execute( self ) -> str:
    from cosa.agents.test_fix_expediter import voice_io, cosa_interface
    voice_io.reconfigure()

    # Fix 7 — set sender/target before anything else
    cosa_interface.SENDER_ID   = cosa_interface._get_sender_id( suffix=self.base_id )
    cosa_interface.TARGET_USER = self.user_email
    voice_io.set_job_id( self.id_hash )

    try:
        # ... existing Phase 0-6 orchestration ...
        return result

    except Exception as e:
        await voice_io.notify(
            f"Test Fix Expediter error: {str( e )[ :100 ]}",
            priority="urgent", job_id=self.id_hash, queue_name="run"
        )
        raise

    finally:
        voice_io.clear_job_id()
```

Mirrors BFE `_execute` at `bug_fix_expediter/job.py:186-300`. Critical nuances:

- The `try` must wrap the **entire** phase pipeline, including snapshot loading (which currently
  has its own inner try/except that swallows errors — see `job.py:174-184`; that inner handler
  should now re-raise so the outer handler notifies the user).
- The urgent notify is fire-and-forget; it must NEVER swallow its own exception (which is why
  we bury it in a separate try/except if needed — but generally `voice_io.notify` is already
  safe).
- `raise` (bare re-raise) is essential — do NOT swallow. The exception must propagate to
  `do_all()` so that Fix 2's traceback capture runs.
