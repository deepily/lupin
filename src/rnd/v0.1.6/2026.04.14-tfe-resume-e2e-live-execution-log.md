### 1.2 Inject `LUPIN_TEST_BASE_URL` for subprocess runners

**File**: `src/cosa/agents/test_suite/job.py` (CoSA submodule)
**Site**: `subprocess.Popen(...)` inside `_run_suite_subprocess()` at line 697.

**Edit**: added `LUPIN_TEST_BASE_URL` to the `env` dict, defaulting to `http://localhost:$PORT` (7999 inside container). Honors any caller-set value first:

```python
"LUPIN_TEST_BASE_URL" : os.environ.get(
    "LUPIN_TEST_BASE_URL",
    f"http://localhost:{os.environ.get( 'PORT', '7999' )}"
),
```

**Why this matters**: when `lupin-rest-test` runs a scheduled `pytest_direct` or `integration` suite via the test-suite endpoint, the runner subprocess is spawned INSIDE the container. Container-internal port 7999 is where the server lives; host-side :8000 is unreachable. Without this env var, every `requests.get( BASE_URL/health )` in `conftest.py` hit `localhost:8000` inside the container → `ConnectionError`. That's exactly what killed last night's 21:00 and tonight's 21:39 scheduled runs.

### 2.1 Env-var override for `feedback_timeout_seconds`

**File**: `src/cosa/agents/test_fix_expediter/config.py` (CoSA submodule)

Added `import os` and an env-var override block at the end of `TestFixExpediterConfig.from_config()` — AFTER the INI-driven `kwargs` are populated, BEFORE `cls( **kwargs )` is called. If `TFE_FEEDBACK_TIMEOUT_SECONDS_OVERRIDE` is set and parseable as an int, it replaces the INI value for `feedback_timeout_seconds`. Malformed values are ignored (fall back to INI).

**Why env var on the config, not the orchestrator**: `TFEOrchestrator` reads `self.config.feedback_timeout_seconds` in two places (`orchestrator.py:1002, 1038`). Overriding at the config level makes both call sites work without changing either one.

## Design notes for next session

- **Option (a) submit endpoint**: The plan's "direct TFE submit via factory" fallback requires the FastAPI app's DI context, not available from pytest. A proper fix is to add `POST /api/agentic-jobs/submit` (generic agentic job submitter) so tests can construct arbitrary job types without the watchdog path.
- **Checkpoint hygiene**: The happy-path test may find stale stalled jobs from prior sessions. Consider adding a `cleanup_stale_stalled_jobs` cron or test-fixture teardown.
- **INI mutation at runtime**: A more flexible alternative to env vars would be an admin endpoint (`POST /api/config/override`) that accepts a subset of INI keys for live mutation. Avoids the need to bounce containers for test config.
