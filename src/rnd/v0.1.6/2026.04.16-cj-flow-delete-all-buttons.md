# Plan: CJ Flow — Delete All Button for 5 Queue Panes

## Context

Manually clearing CJ flow queues (todo, running, done, dead, history) currently requires
deleting jobs one at a time. This is tedious during development and debugging. We need a
"Delete All" (🗑️) button in the header of each of the five queue panes, providing one-click
bulk deletion with a confirmation prompt.

**Authorization model** (per user answers):
- Any authenticated user can delete their own jobs from any queue
- Admins calling the endpoint delete the entire queue
- Matches existing single-job delete behavior

**History scope** (per user answers):
- History Delete All respects the active time-window filter (1/7/14/30 days or All)

## Phase 1 — Backend: Two New Endpoints

### Endpoint 1: Bulk delete a live queue
```
DELETE /api/queue/{queue_name}/all
```
- `queue_name`: `todo`, `run`, `done`, or `dead`
- Non-admin: iterates user's jobs via `queue.get_jobs_for_user(user_id)`, calls `queue.delete_by_id_hash()` for each
- Admin: calls `queue.clear()` directly (emits WebSocket update)
- For `run` queue: call `job.request_cancel()` on each job before removal (mirrors existing single-delete behavior in `DELETE /api/queue/{queue_name}/{job_id}` lines 1058–1170)
- Returns: `{ status, queue_name, items_deleted, timestamp }`
- Reuse existing queue Depends: `get_todo_queue`, `get_running_queue`, `get_done_queue`, `get_dead_queue`

### Endpoint 2: Bulk delete job history
```
DELETE /api/job-history/all?days={N|all}
```
- `days`: optional query param, matches current time-window selector values (1, 7, 14, 30, "all"); defaults to "all"
- Non-admin: adds `user_id` filter; admin: no user filter
- Calls `job_persistence.delete_job_history_bulk(user_id, days)` — **new function** to add in `job_persistence.py`
- Returns: `{ status, items_deleted, days_filter, timestamp }`

## Phase 3 — Frontend JS: `deleteAllQueueJobs()` Method

Add to `notifications.js` near `deleteQueueJob()` (line ~6149):

```javascript
async deleteAllQueueJobs( queueName ) {
    // For live queues: count from queueCategoryState
    // For history: count from queueCategoryState.history.total
    // Confirm with user (include running-jobs cancellation warning for 'run')
    // Call DELETE /api/queue/{queueName}/all  OR  DELETE /api/job-history/all?days=N
    // On success: clear local state, reload cards, update count badge
}
```

**Confirmation messages:**
- `todo/done/dead`: `"Remove all N jobs from the [queue] queue?"`
- `run`: `"Cancel and remove all N running jobs? This will interrupt active jobs."`
- `history`: `"Delete all N history entries from the last [time-window] days?"`

**History endpoint call**: reads current value of `#history-time-window` select, passes as `?days=N`.

**After success**: call `this.loadQueueJobCards(queueName)` (live queues) or `this.loadJobHistory()` (history) to refresh UI — same as post-single-delete pattern.

Wire up event listeners in `setupEventListeners()` (near the `clear-all-notifications` wiring at line ~1476) — add listeners for all 5 buttons.
