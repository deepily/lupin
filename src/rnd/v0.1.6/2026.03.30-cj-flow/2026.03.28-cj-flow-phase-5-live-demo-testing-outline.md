## Test 1: Scheduled Badge — Submit Timed Job

**Goal**: Verify future-scheduled jobs show the purple clock badge.

1. Open DevTools console and run:
   ```javascript
   const token = localStorage.getItem( "lupin_access_token" );
   const future = new Date( Date.now() + 3600000 ).toISOString();
   fetch( "/api/mock-job/submit", {
       method: "POST",
       headers: { "Authorization": `Bearer ${token}`, "Content-Type": "application/json" },
       body: JSON.stringify({ fixed_iterations: 1, fixed_sleep: 25, scheduled_at: future, description: "Scheduled demo job" })
   }).then( r => r.json() ).then( d => console.log( "Job ID:", d.job_id ) );
   ```
2. Expand the **Todo** queue section
3. **Expected**: Job card appears with:
   - Purple `🕐 Mar 28 HH:MM` badge (scheduled time)
   - Standard agent badge, cancel button, pause button
   - Job stays in todo (consumer skips it — scheduled time not reached)

**Pass criteria**: Purple scheduled badge visible with correct date/time format.

## Test 2: Monopolize Badge — Submit Exclusive Job

   fetch( "/api/mock-job/submit", {

3. **Expected**: Job card has:

   - Purple `🕐` scheduled badge (both visible together)

**Pass criteria**: Lock badge visible alongside scheduled badge.

## Test 3: Pause Button — Click to Pause

**Goal**: Verify the ⏸ button pauses a job and updates the card in real-time via WebSocket.

1. Find a job card in the Todo queue (from Tests 1 or 2)
2. Click the **⏸** button on the card
3. **Expected immediate UI changes**:
   - Button shows "..." briefly (optimistic update)
   - Card fades to ~65% opacity (`.job-paused` class)
   - Amber `⏸ Paused` badge appears
   - Button changes to **▶** (resume icon)
   - Button gains amber background (`.is-paused` class)
4. Check DevTools WS tab:
   - **Expected**: `job_paused` event received with `{ job_id, paused: true, timestamp }`

**Pass criteria**: Card visually muted, paused badge + resume button visible, WS event received.

## Test 4: Resume Button — Click to Resume

**Goal**: Verify the ▶ button resumes a paused job and clears the visual state.

1. Find the paused job card from Test 3
2. Click the **▶** button
3. **Expected immediate UI changes**:
   - Card opacity returns to 100%
   - Amber `⏸ Paused` badge removed
   - Button changes back to **⏸** (pause icon)
   - Button loses amber background
4. Check DevTools WS tab:
   - **Expected**: `job_resumed` event received with `{ job_id, paused: false, timestamp }`

**Pass criteria**: Card returns to normal, no paused badge, pause button restored, WS event received.

## Test 5: Pause + Scheduled — Combined States

**Goal**: Verify a paused scheduled job shows both badges.

1. Use a scheduled job from Test 1 (or submit a new one)
2. Click ⏸ to pause it
3. **Expected**:
   - Card is muted (opacity 0.65)
   - Both `⏸ Paused` (amber) and `🕐 date time` (purple) badges visible

4. Click ▶ to resume
5. **Expected**: Only scheduled badge remains, card is no longer muted

**Pass criteria**: Multiple badges coexist correctly, pause/resume toggles only the paused state.
