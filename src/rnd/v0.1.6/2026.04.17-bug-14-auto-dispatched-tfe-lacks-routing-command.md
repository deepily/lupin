# Bug 14 — Auto-dispatched TFE jobs can't be resumed (missing `routing_command` + `original_args`)

**Discovered**: 2026-04-17 morning, Session 44581b8c
**Severity**: High — blocks Resume validation for every TFE job the `TestSuiteCompletionWatchdog` auto-dispatches. Every attempt returns HTTP 404 from `/api/jobs/{id}/resume-from-checkpoint`.
**Status**: Root-caused, not fixed. User declined remediation pending review.

## Symptom

Clicking "▶ Resume from Checkpoint" on `tfe-3436c5b8` (confirmed `status=stalled` on `:8000`) returns:

```
POST http://localhost:8000/api/jobs/tfe-3436c5b8/resume-from-checkpoint 404 (Not Found)
[Notifications ERROR] [JOB-RESUME] Failed to resume tfe-3436c5b8:
    Error: Job tfe-3436c5b8 not found, not stalled, or has no checkpoint

Server log:

```

INFO:     172.19.0.1:47378 - "POST /api/jobs/tfe-3436c5b8/resume-from-checkpoint HTTP/1.1" 404 Not Found

## Root cause

Direct DB evidence (from `lupin_db_test.job_history`, queried via `docker exec lupin-postgres psql -U lupin_dev -d lupin_db_test`):

```
 id_hash       | routing_command | user_email                              | status
---------------+-----------------+-----------------------------------------+---------
 tfe-3436c5b8  |                 | interactive.job.tester@lupin.deepily.ai | stalled
```

- `routing_command` column is **empty**.
- `metadata_json` top-level keys: `['agent_type', 'checkpoint', 'monopolize', 'report_link', 'response_text']` — no `original_args` key.

In `src/cosa/rest/agentic_job_factory.py:347-392`, `resume_job()` requires both:

```python
job_info = get_original_args_for_job( job_id_hash )
if not job_info or not job_info.get( "routing_command" ):
    print( f"[agentic_job_factory] No original args found for {job_id_hash}" )
    return None
```

So `resume_job()` returns `None` → endpoint raises 404.

### Why the fields are missing

`create_agentic_job( command, args_dict, … )` at `agentic_job_factory.py:101` sets both fields on every constructed job:

```python
job.routing_command = command
job.original_args   = dict( args_dict )
```

Those attrs flow into `persist_job_created_from_metadata` at `job_persistence.py:155` and populate the DB row's `routing_command` column + `metadata_json["original_args"]`.

**But `TestSuiteCompletionWatchdog._dispatch_tfe` bypasses the factory entirely.** At `test_suite_completion_watchdog.py:254-264`, it builds `TestFixExpediterJob` directly:

```python
tfe_job = TestFixExpediterJob(
    remediation_snapshot_path = snapshot_path,
    source_test_suite_job_id  = getattr( completed_job, "id_hash", "unknown" ),
    user_id                   = user_id,
    user_email                = user_email,
    session_id                = session_id,
    original_test_types       = snapshot.get( "suites_run", [] ),
    dry_run                   = False,
    debug                     = self.debug,
    verbose                   = self.verbose,
)
# ...
self.todo_queue.push( tfe_job )
```

No `routing_command` or `original_args` attr on `tfe_job`, so when the push-path persists the row, both end up null/empty. Every auto-dispatched TFE has this problem.

## Forward fix — route dispatch through `create_agentic_job()`

An earlier draft of this doc proposed patching `tfe_job.routing_command` and `tfe_job.original_args` manually after direct construction. That version still bypassed the factory and would silently drift if the TFE constructor gained a new arg. The **correct** structural fix is to route the dispatch through the existing factory.

**File**: `src/cosa/rest/test_suite_completion_watchdog.py` (CoSA submodule — user commits separately)

**Change**: replace the direct `TestFixExpediterJob(...)` construction (and its preceding `TestFixExpediterJob` import) with a `create_agentic_job()` call:

```python
# Route through create_agentic_job() so routing_command + original_args are set
# on the constructed job for Resume capability (Bug 14 fix). The factory is the
# single source of truth for TFE construction; matches the voice-expediter path.
try:
    from cosa.rest.agentic_job_factory import create_agentic_job

    args_dict = {
        "remediation_snapshot_path" : snapshot_path,
        "source_test_suite_job_id"  : getattr( completed_job, "id_hash", "unknown" ),
        "original_test_types"       : snapshot.get( "suites_run", [] ),
        "dry_run"                   : False,
    }

    tfe_job = create_agentic_job(
        command    = "agent router go to test fix expediter",
        args_dict  = args_dict,
        user_id    = user_id,
        user_email = user_email,
        session_id = session_id,
        debug      = self.debug,
        verbose    = self.verbose,
    )

    if tfe_job is None:
        logger.error(
            "[TestSuiteCompletionWatchdog] create_agentic_job returned None for TFE dispatch "
            f"(source job {getattr( completed_job, 'id_hash', 'unknown' )})"
        )
        return None

except Exception as e:
    logger.error(
        f"[TestSuiteCompletionWatchdog] TFE construction via factory failed: {e}"
    )
    return None
```

### Why factory-routed is structurally correct

1. **Single source of truth** for TFE construction — watchdog path == voice-expediter path == any future caller. No drift when the TFE constructor gains a new arg.
2. **`routing_command` + `original_args` set for free** by the factory's trailing lines 342-343 — impossible to forget.
3. **Central arg parsing** — the factory's TFE branch (`agentic_job_factory.py:311-333`) already normalizes `original_test_types` / `original_pytest_args` from comma/space strings and accepts `lead_model_override` / `worker_model_override`. The watchdog inherits these for free.
4. **None-guarded** — the only path that returns `None` from `create_agentic_job()` is an unknown command, which cannot happen here but is cheap to check.

After this lands + container bounce + a fresh test-suite run, any newly-auto-dispatched TFE that stalls will be Resume-capable via `/api/jobs/{id}/resume-from-checkpoint`.
