# Plan: cosa-voice Global MCP Onboarding Bootstrapper

**Date**: 2026.03.23
**Status**: Approved — implementation in progress (Session 367)
**Origin**: Session 366 — user hit the onboarding gap when working in a non-Lupin repo

## Context

When starting Claude Code in a non-Lupin repo, cosa-voice MCP tools are unavailable because there's no `.mcp.json`. Currently both Lupin and planning-is-prompting have nearly identical `.mcp.json` files checked in — the only difference is the `MCP_PROJECT` string. Since the MCP server already auto-detects project from CWD (with basename fallback for unknown projects), we can eliminate per-project configs entirely and register cosa-voice once at **user scope**.

An existing `install-mcp-server.sh` script handles basic setup but uses **local** scope (per-project). This plan replaces it entirely with a full onboarding bootstrapper at global scope, plus a two-part session status display.

## Design Decisions

1. **Global (user scope)** — `claude mcp add --scope user` writes to `~/.claude/settings.json`, works in every repo
2. **No `MCP_PROJECT` env var** — auto-detection via CWD is primary; basename fallback covers unknown projects
3. **Shell script primary** — works without Claude Code running; slash command can wrap it later
4. **Hooks are all-or-nothing** — no "MCP only" tier (hooks share session bridge state with MCP server)
5. **Gitignore `.mcp.json`** — machine-specific paths shouldn't be version-controlled
6. **Delete old script** — no backward compatibility; `install-mcp-server.sh` is removed entirely
7. **Two-part status display** — SessionStart hook shows immediate prereq status; MCP server stderr shows runtime status

## Open Questions (Resolved)

1. **Should `.mcp.json` be gitignored?** → Yes. Machine-specific absolute paths.
2. **Global vs per-project MCP?** → Global (user scope). Only variable was `MCP_PROJECT`, which auto-detection eliminates.
3. **Auto-detect project name from CWD?** → Already implemented in `sender_id.py:detect_project()`. Basename fallback for unknown projects.
4. **Shell script vs slash command?** → Shell script primary. Slash command can wrap it later.
5. **Should hooks be optional?** → No. Hooks and MCP server share session bridge state — all-or-nothing.
