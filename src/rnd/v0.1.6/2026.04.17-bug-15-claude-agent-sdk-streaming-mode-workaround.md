# Bug 15 — `claude-agent-sdk` `can_use_tool` requires AsyncIterable prompt (forced workaround)

**Discovered**: 2026-04-17 afternoon, Session 44581b8c, while validating Bug 9a + Bug 14 end-to-end.
**Severity**: High — every TFE/BFE/SWE Phase 3 Coder + Tester delegation fails silently in the current container SDK. Job reports "applied N fixes" based on iteration count while 0 actually succeeded.
**Status**: Workaround landed this session (helper + 7 call-site swaps + 6 unit tests). Container bounce + Resume retry deferred to tomorrow morning.

## Symptom

TFE `tfe-60431542` (resumed from `tfe-72adc928` checkpoint): voice gate answered cleanly with 11 of 17 proposals selected, Phase 2 complete, Phase 3 worktree created successfully (Bug 9a validated inside container). Then every fix delegation failed identically:

```
Coder delegation failed: can_use_tool callback requires streaming mode.
Please provide prompt as an AsyncIterable instead of a string.
```

The exception is caught at `test_fix_expediter/orchestrator.py:1398`:

```python
except Exception as e:
    logger.error( f"Coder delegation failed: {e}" )
    return ( "", [] )
```

So the orchestrator iterates through all 11 selections, emits "Applying fix N/11" notifications (based on iteration count, not success), and finishes with `Phase 3 complete: 0/11 cluster(s) fixed`. Phase 6 is then skipped ("no successful fixes → no rerun"). The job's final response text:

> TFE complete: 8 clusters, 17 proposed, 11 selected, 0 fixed. No rerun (no successful fixes).

## Root cause

Container SDK: `claude-agent-sdk v0.1.56`. Between `v0.1.36` (in use when the SWE Team integration was first landed) and current, Anthropic added a strict validation in `claude_agent_sdk/client.py::connect()`:

```python
if self.options.can_use_tool:
    # canUseTool callback requires streaming mode (AsyncIterable prompt)
    if isinstance(prompt, str):
        raise ValueError(
            "can_use_tool callback requires streaming mode. "
            "Please provide prompt as an AsyncIterable instead of a string."
        )
```

Every `sdk_query()` call in COSA that wires `can_use_tool` via `build_can_use_tool(...)` passes a plain string prompt, which fails this validation.

## Community state (April 2026)

Open upstream issue tracking this as unresolved design gap:

- **Title**: *Required workaround for Python `can_use_tool` indicates SDK race condition or design flaw*
- **URL**: https://github.com/anthropics/claude-code/issues/18735

Key community observations:

1. **Python-only restriction** — TypeScript SDK accepts string prompt with `can_use_tool` set. The Python SDK enforces streaming-mode explicitly.
2. **Race concern** — the validation exists because without streaming the SDK/CLI bridge closes the connection before the `can_use_tool` callback can be invoked.
3. **Dummy-hook alternative** — some community workarounds use a `PreToolUse` hook returning `{"continue_": True}` to keep the stream open. That targets a different symptom (stream closing mid-callback) — not our symptom. Our fix is simpler: satisfy the validation by wrapping the prompt.
4. **Long-term fix planned but not landed** — upstream intent is to handle stream persistence internally when `can_use_tool` is set, eliminating the need for the wrap. No timeline as of v0.1.56.

## Fix — `wrap_prompt_for_streaming()` helper + 7 call-site swaps

### Helper (new)

`src/cosa/agents/swe_team/hooks.py` (CoSA submodule — user commits from inside `src/cosa/`):

```python
async def wrap_prompt_for_streaming( prompt, session_id=None ):
    """
    Wrap a string prompt as the single-message AsyncIterable shape that
    claude-agent-sdk >= 0.1.36 requires whenever options.can_use_tool is set.

    WORKAROUND for upstream bug — the Python SDK raises
    ValueError("can_use_tool callback requires streaming mode. ...") if a plain
    string is passed while can_use_tool is set. TypeScript SDK has no such
    restriction — this is Python-only.

    Upstream tracker (unresolved as of 2026-04-17):
        https://github.com/anthropics/claude-code/issues/18735

    Remove this helper and revert every call site once upstream lands the fix.
    """
    import uuid
    effective_session_id = session_id or str( uuid.uuid4() )
    yield {
        "type"               : "user",
        "message"            : { "role": "user", "content": prompt },
        "parent_tool_use_id" : None,
        "session_id"         : effective_session_id,
    }
```

Shape derived from reading the SDK source at https://github.com/anthropics/claude-agent-sdk-python/blob/main/src/claude_agent_sdk/client.py — the internal `query()` path builds the same dict when a string prompt is handled successfully.

Exported from `src/cosa/agents/swe_team/__init__.py` (two single-line edits).

### Unit test (new)

`src/tests/unit/test_wrap_prompt_for_streaming.py` — 6 tests covering:

1. Yields exactly one message.
2. Message shape matches the SDK contract (`type`, `message.role`, `message.content`, `parent_tool_use_id`, `session_id`).
3. Default `session_id` is a UUID4 (36 chars, 4 hyphens).
4. Explicit `session_id` override is respected.
5. Two invocations get distinct default UUIDs.
6. Long multi-line prompts (> 3000 chars) round-trip intact — guards against any accidental truncation if a future helper variant tries to optimize.
