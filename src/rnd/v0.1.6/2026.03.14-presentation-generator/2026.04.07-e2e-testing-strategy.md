**Date**: 2026-04-07

## Problem Statement

Presentation generation is a long-running, expensive agentic process (~8 min, ~$0.46-$2.43 per run). It cannot be tested interactively during development. The user codes during the day and needs to schedule full regression runs for after hours when the server can be monopolized. This document defines the permanent testing infrastructure for the Presentation Generator and its render-only and research-to-presentation variants.

---

## Testing Pyramid

```
                    ┌─────────────────────┐
                    │  Tier 5: R2P Chain   │  ~$5-10, ~30min
                    │  (weekly/pre-merge)  │  Research → Presentation
                    ├─────────────────────┤
                    │  Tier 4: Opus Full   │  ~$2.43, ~8min
                    │  (pre-merge only)    │  Production quality gate
                ┌───┴─────────────────────┴───┐
                │   Tier 3: Sonnet Full        │  ~$0.46, ~8min
                │   (nightly default)          │  Quality + cost validation
            ┌───┴─────────────────────────────┴───┐
            │   Tier 2: Render-Only Live           │  ~$0, ~60s
            │   (after render pipeline changes)    │  Visual pipeline validation
        ┌───┴─────────────────────────────────────┴───┐
        │   Tier 1: Dry-Run Smoke                      │  $0, ~30s
        │   (during development, always safe)           │  Infrastructure validation
    ┌───┴─────────────────────────────────────────────┴───┐
    │   Tier 0: Unit Tests                                 │  $0, ~5s
    │   (during development, always safe)                  │  Function-level validation
    └──────────────────────────────────────────────────────┘
```

| Tier | Test File | Cost | Duration | When to Run | What It Validates |
|------|-----------|------|----------|-------------|-------------------|
| 0 | `pytest src/tests/unit/test_presentation_*.py` | $0 | ~5s | Every edit | YAML parse, slug gen, cost math, config |

## Artifacts to Create

### 1. Render-Only Smoke Test (Tier 2)

**File**: `src/tests/smoke/test_presentation_render_only_smoke.py`

**Purpose**: Validate the render-only pipeline (Phases 6-8) works end-to-end with a pre-existing YAML intermediate. Zero LLM cost — tests only the rendering infrastructure.

**Pattern**: Extends `InteractiveSmokeTest` (same as Phase D live test). Proxy needed because Gate 4 (rendered output review) still fires.

**Source YAML Resolution Strategy**:
- Primary: `--yaml-path` CLI arg (explicit path)
- Fallback: Find the latest `.yaml` in `io/presentations/{test_user_email}/` sorted by mtime
- If no YAML exists: skip with `pytest.skip("No YAML fixture found — run Tier 3 first")`

**Scenario Matrix** (1 scenario, 6 sub-checks):

```python
RENDER_ONLY_SCENARIOS = [
    {
        "id"          : "PR_RENDER_ONLY_FAST",
        "render_only" : True,
        "dry_run"     : False,
        "check"       : "render_quality",
    },
]
```

**Sub-checks**:

| # | Check | Assertion | Why |
|---|-------|-----------|-----|
| 1 | `job_id_prefix` | Starts with `pr-` | Correct job type |
| 2 | `agent_type` | `== "presentation"` | Correct routing |
| 3 | `fast_completion` | `duration_seconds < 120` | Render should be fast |
| 4 | `low_cost` | `total_cost_usd < 0.10` | No LLM calls expected |
| 5 | `slide_count` | `> 0` | YAML had slides, Marp should too |
| 6 | `no_stack_trace` | No error in job record | Clean completion |

**CLI Invocations**:

```bash

python src/tests/smoke/test_presentation_render_only_smoke.py --auto-proxy

# Explicit YAML path
python src/tests/smoke/test_presentation_render_only_smoke.py --auto-proxy \
  --yaml-path io/presentations/interactive.job.tester@lupin.deepily.ai/2026.04.07-at-16:33-EST-strategy-and-design.yaml

# Via test-suite endpoint (scheduled)
POST /api/test-suite/submit
{
    "test_types"  : "smoke",
    "pytest_args" : "src/tests/smoke/test_presentation_render_only_smoke.py --auto-proxy",
    "scheduled_at": "2026-04-07T22:00:00-04:00"
}
```

**Cost envelope**: `$0.10` cap (rendering only — Mermaid CLI is free, Matplotlib is local, D2 is local). If NanoBanana/Veo renderers fire, Gemini API costs could be non-zero.

### 4. Presentation Regression Runner Script

**File**: `src/tests/run-presentation-regression.sh`

Sequential pyramid orchestrator — runs tiers cheapest-first with continue-on-failure:

```bash
#!/bin/bash
# Presentation Generator Regression Suite
#
# Usage:
#   ./src/tests/run-presentation-regression.sh              # Default: render + sonnet
#   ./src/tests/run-presentation-regression.sh --include-opus
#   ./src/tests/run-presentation-regression.sh --include-r2p
#   ./src/tests/run-presentation-regression.sh --all
#
# Scheduling:
#   POST /api/test-suite/submit
#   {"test_types": "presentation", "scheduled_at": "2026-04-07T22:00:00-04:00"}

set -o pipefail
SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
cd "$SCRIPT_DIR/../.."  # Project root

INCLUDE_OPUS=false
INCLUDE_R2P=false

# Parse flags
for arg in "$@"; do
    case "$arg" in
        --include-opus) INCLUDE_OPUS=true ;;
        --include-r2p)  INCLUDE_R2P=true ;;
        --all)          INCLUDE_OPUS=true; INCLUDE_R2P=true ;;
        --bg)           ;; # Stripped by test-suite job
    esac
done

TOTAL=0; PASSED=0; FAILED=0
LOG_FILE="/tmp/presentation-regression-latest.log"

run_tier() {
    local name="$1"
    local cmd="$2"
    local timeout="$3"

    echo "═══════════════════════════════════════════════"
    echo "  TIER: $name"
    echo "═══════════════════════════════════════════════"

    TOTAL=$((TOTAL + 1))
    if timeout "$timeout" bash -c "$cmd" >> "$LOG_FILE" 2>&1; then
        echo "  ✓ PASS: $name"
        PASSED=$((PASSED + 1))
    else
        echo "  ✗ FAIL: $name (exit code $?)"
        FAILED=$((FAILED + 1))
    fi
    echo ""
}

echo "Presentation Regression Suite — $(date)" | tee "$LOG_FILE"
echo ""

# Tier 2: Render-only (~60s, $0)
run_tier "render-only" \
    "pytest src/tests/smoke/test_presentation_render_only_smoke.py --auto-proxy -v" \
    120

# Tier 3: Sonnet full (~8min, $0.46)
run_tier "sonnet-full" \
    "pytest src/tests/smoke/test_presentation_live_smoke.py --auto-proxy --content-model claude-sonnet-4-6 --cost-cap-usd 2.00 -v" \
    900

# Tier 4: Opus full (optional, ~8min, $2.43)
if [ "$INCLUDE_OPUS" = "true" ]; then
    run_tier "opus-full" \
        "pytest src/tests/smoke/test_presentation_live_smoke.py --auto-proxy --cost-cap-usd 5.00 -v" \
        900
fi

# Tier 5: R2P chain (optional, ~30min, $5-10)
if [ "$INCLUDE_R2P" = "true" ]; then
    run_tier "r2p-chain" \
        "pytest src/tests/smoke/test_research_to_presentation_live_smoke.py --auto-proxy --cost-cap-usd 10.00 -v" \
        2400
fi

echo "═══════════════════════════════════════════════"
echo "  RESULTS: $PASSED/$TOTAL passed, $FAILED failed"
echo "═══════════════════════════════════════════════"
echo ""

[ "$FAILED" -eq 0 ] && exit 0 || exit 1
```

## Scheduling Workflow

### Daily Development (Daytime)

```
Coding session starts
  → Unit tests run freely (Tier 0, $0)
  → Dry-run smoke after infrastructure changes (Tier 1, $0)
  → Render-only after visual pipeline changes (Tier 2, $0)
  → NEVER run Tiers 3-5 during coding
```

### End of Day — Schedule Nightly Regression

```
User finishes coding, schedules from UI or Claude Code:

  POST /api/test-suite/submit
  {
      "test_types"   : "presentation",
      "scheduled_at" : "2026-04-07T22:00:00-04:00"
  }

Queue consumer sleeps until 22:00, then:

  22:00:00  Tier 2: Render-only starts (monopolized)
  22:01:00  Tier 2: PASS ($0.00, 45s)
  22:01:05  Tier 3: Sonnet starts
  22:09:00  Tier 3: PASS ($0.46, 472s)
  22:09:05  Suite complete → voice notification:
            "Presentation regression: 2/2 PASSED ($0.46)"
```

## YAML Fixture Management

Render-only tests (Tier 2) depend on a pre-existing YAML from a prior Tier 3/4 run. Strategy:

1. **Auto-discovery**: Test finds latest `.yaml` in user's output dir
2. **Seed fixture**: First time, must run Tier 3 to generate the YAML
3. **Staleness**: YAML fixtures are never "stale" — the same YAML can be re-rendered indefinitely. Content doesn't change; only rendering changes.
4. **Version pinning**: For CI, could pin a specific YAML path in the test config. Not needed for nightly regression (always has recent YAMLs from prior runs).
