# D2Renderer — Implementation Plan

**Date**: 2026-04-01
**Phase**: 9B
**Scope**: LLM-generated D2 syntax → d2 CLI → SVG flowcharts and architecture diagrams
**Effort**: 1 session
**Cost**: Free (LLM tokens only)

---

## Context

Mermaid diagrams are functional but visually plain. D2 (Declarative Diagramming) produces significantly prettier SVG output with built-in themes (including sketch/hand-drawn mode), better layout engines (dagre + ELK), and native support for containers, connections, and icons. D2Renderer fills the gap for `flowchart_d2` and `architecture` visual types that currently fall through to PlaceholderRenderer.

D2Renderer is a **file-producing renderer** — unlike MermaidRenderer (which returns inline Mermaid code blocks for Marp to render), D2Renderer writes SVG files to a `visuals/` directory and returns markdown image references (`![title](visuals/diagram-001.svg)`). This requires a small orchestrator change to pass `output_dir` and `slide_index` kwargs.

**Note**: MatplotlibRenderer (Phase 9A) is being built in a parallel session and needs the same orchestrator kwargs. The orchestrator change is designed to be additive (new kwargs via `**kwargs` catch-all) to minimize merge conflict risk.

---

## Design Decisions (Open Questions Resolved)

| Question | Decision | Rationale |
|----------|----------|-----------|
| Theme mapping | Default theme (0) via constructor param | Future Phase 11 will wire presentation theme → D2 theme; for now keep simple |
| SVG size limits | None — Marp CSS handles display sizing | Adding dimensions would be premature; `width: 100%` in Marp handles it |
| Fallback if d2 missing | PlaceholderRenderer (NOT Mermaid) | Mermaid can't render `architecture` type; honest TODO marker is better |
| CLI check timing | Lazy at render time, cached | Avoids failing at construction when no D2 visuals exist in the presentation |

### Step 4: Create `renderers/d2_renderer.py` (~130 lines)

**File**: `src/cosa/agents/presentation_generator/renderers/d2_renderer.py`

```
class D2Renderer( VisualRenderer ):
    SUPPORTED_TYPES = [ "flowchart_d2", "architecture" ]
```

**Constructor**: `__init__( self, debug=False, verbose=False, d2_theme=0 )`
- Stores debug, verbose, d2_theme
- `_d2_available = None` (lazy cache)

**`render()` flow**:
1. Check d2 CLI available (lazy, cached via `shutil.which("d2")`)
2. Get `api_client`, `slide_title`, `output_dir`, `slide_index` from kwargs
3. If no api_client or no output_dir → return None
4. Call `api_client.call_for_d2()` with D2 prompt
5. Extract D2 code via `_extract_d2_code()` static method
6. Ensure output_dir exists (`os.makedirs( output_dir, exist_ok=True )`)
7. Render via `_render_d2()` → SVG file
8. Return `![slide_title](visuals/diagram-NNN.svg)` or None

**`_extract_d2_code( response_content )`** static method:
- Try fenced ` ```d2 ` block first
- Try bare fenced ` ``` ` block
- Try bare D2 (starts with known patterns: node names with `->`, `{`, etc.)
- Return None if nothing found

**`_render_d2( d2_code, output_path, theme )`** async method:
- `asyncio.get_event_loop().run_in_executor()` wrapping `subprocess.run()`
- Command: `[ "d2", "--theme", str(theme), "-", output_path ]`
- Input: d2_code via stdin
- Timeout: 30 seconds
- Returns bool (success/failure)
- Logs warning on failure with first 200 chars of stderr

**`quick_smoke_test()`** at bottom.

## Parallel Session Conflict Mitigation

The MatplotlibRenderer session may also modify the orchestrator's `_render_visuals_async()` to add `output_dir`/`slide_index` kwargs. To minimize conflicts:
- Our orchestrator change is purely additive (2 new kwargs, 3 new lines in registry builder)
- If the other session lands first, we just add D2 registration — the kwargs will already be there
- If we land first, the other session just adds Matplotlib registration — same pattern
- Worst case: a simple merge conflict in `_build_visual_registry()` (adjacent `registry.register()` lines)
