## Context

The Presentation Generator's visual pipeline handles structural diagrams (MermaidRenderer) and text-only placeholders (PlaceholderRenderer). Slides with `visual_type: chart`, `plot`, `graph`, or `data_viz` fall through to PlaceholderRenderer, producing `[TODO: chart]` markers.

MatplotlibRenderer closes this gap: the LLM generates Python plotting code from the slide's `visual_description`, we execute it in a sandboxed subprocess, capture the PNG, and return a Marp-compatible markdown image reference.

**Key design issue**: MermaidRenderer currently claims `SUPPORTED_TYPES = ["diagram", "chart"]`. The "chart" type must move to MatplotlibRenderer. Mermaid keeps "diagram" only.

**Dependency check**: `matplotlib==3.10.3` already in requirements.txt and installed. `seaborn` NOT installed — must be added to requirements.txt, installed locally, and pinned in Dockerfile.

### Step 1: Install seaborn + pin rendering deps in Dockerfile
**Why**: seaborn provides cleaner chart aesthetics out of the box (whitegrid theme, better color palettes). The LLM-generated code benefits from having seaborn available for `sns.set_theme()` calls. Dependencies must be pinned at the END of the Dockerfile to avoid invalidating earlier cached layers.

**1a**: Install locally:
```bash
pip install seaborn
```

**1b**: Add to `src/cosa/requirements.txt` — pin the installed version (e.g., `seaborn==0.13.2`)

**1c**: Add to `docker/lupin/Dockerfile` — append BEFORE the Playwright section (after line 131, the `pydub` install), as a new rendering dependencies block:
```dockerfile
# ============================================================================
# VISUAL RENDERING DEPENDENCIES (Phase 9A, v0.1.6)
# ============================================================================
# Matplotlib is already installed as a transitive dep. Pin seaborn explicitly
# for presentation generator chart rendering (MatplotlibRenderer).
# Placed late in Dockerfile to avoid invalidating earlier cached layers.
RUN pip install --no-cache-dir seaborn==0.13.2
```

**Note**: `matplotlib==3.10.3` is already pulled in as a transitive dependency and listed in requirements.txt — no Dockerfile change needed for it. Only seaborn is new.

### Step 3: Create `renderers/matplotlib_renderer.py`
**File**: `src/cosa/agents/presentation_generator/renderers/matplotlib_renderer.py` (NEW, ~170 lines)

Following MermaidRenderer pattern:
- `SUPPORTED_TYPES = ["chart", "plot", "graph", "data_viz"]`
- `__init__(self, debug, verbose)` — same as MermaidRenderer
- `async render()` flow:
  1. Get `api_client`, `slide_title`, `output_dir`, `slide_index` from kwargs
  2. Guard: return None if `api_client` or `output_dir` is None
  3. Call `api_client.call_for_matplotlib()` with system prompt + built prompt
  4. Extract Python code via `_extract_python_code()` (fenced ```python blocks, bare code)
  5. Inject `plt.savefig(output_path, dpi=150, bbox_inches='tight')` + `plt.close('all')` via `_inject_savefig()`
  6. Strip any `plt.show()` calls
  7. Execute in subprocess with 30s timeout via `_execute_code()`
  8. Verify output PNG exists
  9. Return `![slide_title](visuals/chart-NNN.png)` (relative path for Marp)

Static/helper methods:
- `_extract_python_code(response_content) -> Optional[str]` — regex extraction
- `_inject_savefig(code, output_path) -> str` — append savefig, strip plt.show()
- `_execute_code(code) -> dict` — write to tempfile, run `python3` subprocess, 30s timeout
- `quick_smoke_test()` — 6 tests (extraction, injection, SUPPORTED_TYPES, etc.)

## Open Questions Resolved

1. **Chart type dispatch**: LLM chooses chart type, with keyword hints as suggestions in prompt (same pattern as Mermaid)
2. **Data generation**: LLM invents representative data when description lacks numbers (explicit instruction in system prompt)
3. **Style injection**: Minimal — seaborn `whitegrid` theme for clean defaults (no presentation-theme color injection yet, future Phase 9B)
4. **SVG vs PNG**: PNG at 150 DPI (simpler, reliable with Marp, good slide quality)
5. **seaborn**: Install + pin in requirements.txt and Dockerfile. System prompt encourages `sns.set_theme()` for clean chart aesthetics. Dockerfile pin placed late to preserve cached layers.
