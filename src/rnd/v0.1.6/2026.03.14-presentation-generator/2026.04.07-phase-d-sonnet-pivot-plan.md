### Step 5: Interrupted job re-enqueue mechanism

**Problem**: `mark_interrupted_jobs()` (`job_persistence.py:313-343`) bulk-updates pending/running → interrupted at startup but never re-enqueues. Long-running jobs (presentation generation ~8min, deep research ~15min) are lost on server restart.

**Proposed design**:

#### 5a. Persist constructor args at job creation time

**File**: `src/cosa/rest/job_persistence.py` — `persist_job_created_from_metadata()`

Add `constructor_args` to `metadata_json` at creation time. Each agentic job factory call already has the `args_dict` — store it alongside existing metadata so reconstruction is possible.

#### 5b. Add `requeue_interrupted_jobs()` function

**File**: `src/cosa/rest/job_persistence.py`

New function called after `mark_interrupted_jobs()` at startup:
1. Query all jobs with status='interrupted' that were in RUNNING state (have `started_at` set)
2. For each: extract `job_type`, `routing_command`, `constructor_args` from metadata_json
3. Call `create_agentic_job(routing_command, constructor_args, user_id, user_email, session_id)`
4. Push reconstructed job to todo queue
5. Update original interrupted row with `retry_job_id` reference
6. Track retry count to prevent infinite restart loops (max 1-2 retries)

#### 5c. Add INTERRUPTED → QUEUED transition

**File**: `src/cosa/rest/job_state.py`

Currently INTERRUPTED is terminal. Add `INTERRUPTED → QUEUED` to `VALID_TRANSITIONS` for the re-enqueue path.

#### 5d. Wire into startup sequence

**File**: `src/fastapi_app/main.py` (~line 499)

After `mark_interrupted_jobs()`, call `requeue_interrupted_jobs()` with reference to `todo_queue`.

#### 5e. Configuration

**File**: `src/conf/lupin-app.ini`

Add keys:
- `requeue interrupted jobs = true` (enable/disable)
- `requeue max retries = 1` (prevent infinite loops)
