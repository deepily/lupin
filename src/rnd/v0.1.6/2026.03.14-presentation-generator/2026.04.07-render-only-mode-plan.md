# Render-Only Mode for Presentation Generator

## Context

After Phase D testing, the Opus run produced a high-quality YAML intermediate with 15 slides but the Marp output looks "vanilla" — `[TODO: ...]` placeholders where Matplotlib/D2/NanoBanana visuals should be, plus the plain `default` theme. The content generation (Phases 1-5, ~$2.43) doesn't need to re-run; only the rendering pipeline (Phases 6-8, free) needs to execute with real visual renderers active.

The YAML intermediate format was deliberately designed as a content/rendering boundary. This feature closes that loop.

**Three entry points requested:**
1. CLI invocation — `python -m` or smoke test style
2. Notifications UI — "Re-render" button on completed presentation job cards
3. Voice/text routing — detect YAML input vs raw document automatically

**Follow-up**: Cross-cutting theme integration (Phase 11) comes after this is working.

---

## Architecture

```
Existing:   Source Doc → [Phases 1-5] → YAML → [Phases 6-8] → Marp + Visuals
                          ~$2.43                  free

New:        YAML File  → [skip 1-5]  →        → [Phases 6-8] → Marp + Visuals
                          $0.00                   free
```

The orchestrator already has separable phase methods:
- `_render_text_async(presentation)` — Phase 6
- `_render_visuals_async(presentation)` — Phase 7  
- `_deliver_async(presentation)` — Phase 8

All three accept a `PresentationModel` which can be loaded from YAML via `PresentationModel.from_yaml()`.

---

## Implementation Steps

### Step 1: Orchestrator — add `render_from_yaml()` method

**File**: `src/cosa/agents/presentation_generator/orchestrator.py`

Add a new public method that loads YAML and runs Phases 6-8 only:

```python
async def render_from_yaml_async( self, yaml_path: str ) -> PresentationModel:
    """
    Render-only mode: load existing YAML intermediate, run Phases 6-8.
    Skips content generation (Phases 1-5) and gates 1-3.
    Gate 4 (rendered output review) still fires.
    """
    # Load YAML
    presentation = PresentationModel.from_yaml( yaml_content )
    
    # Populate state needed by rendering phases
    self._presentation_state[ "yaml_path" ] = yaml_path
    
    # Run rendering pipeline
    await self._render_text_async( presentation )    # Phase 6
    await self._render_visuals_async( presentation ) # Phase 7
    # Gate 4 fires here (rendered output review)
    await self._deliver_async( presentation )        # Phase 8
    
    return presentation
```

**Key**: Reuses existing phase methods — no duplication.

### Step 2: Job — add `render_only` flag

**File**: `src/cosa/agents/presentation_generator/job.py`

- Add `render_only: bool = False` constructor parameter
- In `_execute()`, branch based on flag:
  - `render_only=True` + source is YAML → call `orchestrator.render_from_yaml_async()`
  - `render_only=False` → existing `orchestrator.do_all_async()` path

### Step 3: Submit endpoint — add `render_only` parameter

**File**: `src/cosa/rest/routers/presentation_generator.py`

- Add `render_only: bool = False` to `PresentationSubmitRequest`
- Validate: if `render_only=True`, source_path must end in `.yaml`/`.yml`
- Pass through to `args_dict` → factory → job

### Step 4: Factory — wire `render_only` arg

**File**: `src/cosa/rest/agentic_job_factory.py`

- Pass `render_only = _parse_boolean( args_dict.get( "render_only" ) )` to `PresentationGeneratorJob`

### Step 5: YAML detection in voice routing

**File**: `src/cosa/agents/runtime_argument_expeditor/agent_registry.py`

- In the presentation generator registry entry, add `render_only` to arg_mapping
- In `fuzzy_file_match` handler: when resolved file ends in `.yaml`/`.yml`, auto-set `render_only=True` in args_dict

This means: user says "re-render the YAML file about quantum computing" → fuzzy match finds `.yaml` → `render_only` auto-enabled.

### Step 6: Notifications UI — "Re-render" button on done cards

**File**: `src/fastapi_app/static/js/notifications.js`

On completed presentation job cards (status=done, agent_type=presentation):
- Add "Re-render" button next to existing "View Presentation" link
- Button calls `POST /api/presentation-generator/submit` with:
  - `source_path` = the job's `yaml_path` from artifacts
  - `render_only` = true
  - `theme` = (optional: let user pick from dropdown)
- Creates a new queue job that runs Phases 6-8 only

**File**: `src/fastapi_app/static/html/notifications.html`

- Add re-render button to the presentation job card template

### Step 6b: "Generate Presentation" pane — smart YAML detection

**File**: `src/fastapi_app/static/html/notifications.html` + `notifications.js`

The existing "Generate Presentation from Document" submission pane already has a source file input. Enhance it:
- When user types/pastes a path or uses the smart input to describe a file, the `fuzzy_file_match` resolution should search BOTH `.md` and `.yaml`/`.yml` files
- If the resolved file is a `.yaml`/`.yml`, auto-check a "Render only" toggle and show a notice: "YAML detected — will render Phases 6-8 only (no content regeneration)"
- If the resolved file is `.md`/`.txt`, leave "Render only" unchecked (full pipeline)
- User can override either way

This means the same pane handles both use cases:
- "Create a presentation from my quantum computing research" → finds `.md` → full pipeline
- "Re-render the presentation YAML about strategy and design" → finds `.yaml` → render only

### Step 8: Fix output filename convention

**File**: `src/cosa/agents/presentation_generator/orchestrator.py`

Current filenames: `20260407-163334-presentation-generator-agent.yaml` — ugly bare timestamp.

Change to project convention: `YYYY.MM.DD-at-HH:MM-EST-{descriptive-slug}.yaml`

Example: `2026.04.07-at-16:33-EST-strategy-and-design-slides.yaml`

- Descriptive slug derived from presentation title, sanitized to lowercase-hyphenated, 4-5 words max
- Timezone from server locale (EST/EDT)
- Apply to both YAML and Marp output filenames
- Also update any path references that depend on the old format

### Step 7: Voice routing training data

**File**: PEFT training data for presentation generator

Add utterance patterns where "render" (not just "create/make/generate") triggers the presentation generator route. The word "render" should be a first-class trigger alongside existing patterns:
- "render the presentation from [YAML file]"
- "render slides from the existing YAML"
- "render [file description]"
- "re-render the presentation about [topic]"
- "render visuals for [presentation YAML]"

The LORA model needs to learn that "render" → `presentation_generator` route, and the `render_only` flag gets set when the resolved file is `.yaml`/`.yml`.
