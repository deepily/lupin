# Plan: LanceDB Test Isolation for UPE E2E Tests

**Date**: 2026-03-25 | **Session**: 373 | **Status**: Planned (not yet implemented)

---

## Context

The WebSocket fixture (implemented Session 373) unblocked the prediction engine hooks — `prediction_log` entries are now created during E2E tests. However, cold-start tests fail because the **production LanceDB table** (`prediction_decisions`) has accumulated decisions from real usage. The prediction engine returns `cbr_majority_vote` instead of the expected `cold_start`.

The test file already defines `TEST_LANCEDB_TABLE = "prediction_decisions_test"` (line 34) and the warm test class has cleanup infrastructure, but the prediction engine has never been configured to use the test table.

## Root Cause

The `[Lupin: Testing]` config block doesn't override `prediction engine lancedb table`. When the server hot-swaps to Testing mode, it still reads from the production `prediction_decisions` table.

Additionally, the `PredictionEngine` singleton is initialized once at server startup. After hot-swap, the config changes but the singleton's `self.lancedb_table` attribute doesn't update because it was set at construction time.

## Fix: 4 Small Changes

### Step 1: Add config key to Testing block

In `src/conf/lupin-app.ini`, under `[Lupin: Testing]`:

```ini
prediction engine lancedb table                       = prediction_decisions_test
```

And matching splainer entry in `src/conf/lupin-app-splainer.ini`:

```ini
prediction engine lancedb table                       = LanceDB table name for prediction engine CBR storage. Overridden in Testing block to isolate test data from production decisions.
```

### Step 2: Reset PredictionEngine on hot-swap

Add `PredictionEngine.reset()` to `/api/init` endpoint in `src/cosa/rest/routers/system.py` so the singleton is recreated with the new config after hot-swap. One line of code.

### Step 3: Add LanceDB cleanup to TestPredictionEngineE2E

The warm test class (`TestPredictionEngineWarm`) already has `setup_prediction_engine` that resets the singleton and drops the test table. Add equivalent `clean_lancedb` fixture to `TestPredictionEngineE2E`:

```python
@pytest.fixture( autouse=True )
def clean_lancedb( self ):
    """Drop test LanceDB table before each cold-start test for true cold start."""
    import lancedb
    lancedb_path = cu.get_project_root() + "/src/conf/long-term-memory/lupin.lancedb"
    try:
        db = lancedb.connect( lancedb_path )
        if TEST_LANCEDB_TABLE in db.table_names():
            db.drop_table( TEST_LANCEDB_TABLE )
    except Exception:
        pass
    yield
```
