# Feature: Marp CLI PPTX Export for Presentation Generator

**Date**: 2026-04-13
**Session**: 248e740e
**Status**: Implementation in progress

## Context

The presentation generator pipeline currently outputs Marp Markdown (`.md`) with a YAML intermediate. The user wants PowerPoint (`.pptx`) as a final deliverable. Marp CLI has native `--pptx` export that preserves theme styling, slide breaks, and embedded images. The Docker image already has Playwright Chromium installed (used for E2E tests), which Marp CLI can reuse for its headless rendering.

## Approach: Marp CLI Standalone Binary (v4.3.1)

Marp CLI distributes a standalone binary (no Node.js required) via GitHub releases. The Linux tarball contains a single `marp` binary. This avoids adding the entire Node.js runtime to the Docker image.

## Implementation Summary

### Dockerfile (`docker/lupin/Dockerfile`)
- New layer added after Playwright section, before non-root runtime section
- Downloads `marp-cli-v4.3.1-linux.tar.gz` and installs to `/usr/local/bin/marp`
- No existing cached layers disturbed

### Pipeline Phase 8.5: PPTX Export (`orchestrator.py`)
- New `_export_pptx_async()` method runs after Phase 8 (deliver)
- Uses `asyncio.create_subprocess_exec` to call `marp --pptx --allow-local-files`
- `cwd` set to the `.md` file's directory so relative `visuals/` paths resolve
- Non-fatal: if Marp CLI is missing or fails, MD + YAML still delivered
- Respects `pptx_export_enabled` INI toggle and `dry_run` flag

### Config (`config.py` + `lupin-app.ini`)
- New field `pptx_export_enabled: bool = True`
- INI key: `presentation generator pptx export enabled = true`

### Job Artifacts (`job.py`)
- `pptx_path` extracted from orchestrator state and stored in artifacts
- Completion abstract includes "Download PPTX" link
- Relative path stored for persistence

### Persistence (`job_persistence.py` + `running_fifo_queue.py`)
- `pptx_path` added to `rich_fields` whitelist and done-transition metadata
