## Problem

`FixExecutor` (Phase 3) currently writes code changes directly into the live working tree, and `GitStrategist` (Phase 5) runs `git checkout -b <slug>` on whatever branch the operator is currently on. Two failure modes:

1. **Branch contamination**: operator's uncommitted changes get pulled into the fix PR when GitStrategist creates its branch off HEAD.
2. **Development disruption**: the operator's working tree is mutated by the agent mid-session; their own edits and the agent's edits become entangled.

This is acceptable for today's "dry-run" usage but **blocks Doc 18 D2** (full attended TFE live run with real commits + PR). It also makes scheduled overnight Resume-to-apply dangerous — the user can't click Resume on a stalled TFE without risking branch contamination.

## Goal

Give TFE/BFE an isolated sandbox (via `git worktree`) for Phases 3 + 5 so agent edits are confined to a dedicated working tree and never touch the operator's current branch. The operator can resume a stalled TFE job without fear of trampling in-progress work.

## Design

### Config — `[cosa_worktree]` in `lupin-app.ini`

```ini
[cosa_worktree]
enabled              = false
sandbox_root         = .claude/worktrees
base_ref             = origin/main
auto_cleanup         = true
cleanup_timeout_secs = 30
```

Default `enabled=false` — opt-in to preserve existing behavior. Callers (or INI overrides for test server) flip to `true` when isolation is wanted. Matching explainers added to `lupin-app-splainer.ini`.

### New helper — `src/cosa/agents/shared/worktree_context.py`

Async context manager (Python `async with`) with these responsibilities:

```python
class WorktreeContext:
    async def __aenter__(self) -> "WorktreeContext":
        # 1. Load config via ConfigurationManager (LUPIN_CONFIG_MGR_CLI_ARGS)
        # 2. Resolve sandbox path: cu.get_project_root() + / + sandbox_root + / + job_id
        # 3. Ensure sandbox_root exists (mkdir -p)
        # 4. Check for collision: if target path exists, raise WorktreeCollisionError
        # 5. Validate base_ref exists (git rev-parse --verify <ref>); fallback to HEAD with warning
        # 6. git worktree add <path> <base_ref>
        # 7. self.path = resolved absolute path
        return self

    async def __aexit__(self, exc_type, exc, tb) -> bool:
        # If not auto_cleanup: return (preserve for debugging)
        # Else: git worktree remove <path> with timeout
        # If remove fails: log warning, run git worktree prune as fallback
        # NEVER mask the primary exception — return False to let it propagate
        return False
```

Public API:
- `WorktreeContext(job_id, config_mgr=None, enabled=None)` — constructor; `enabled` override lets tests force on/off without INI
- `async with WorktreeContext(...) as wt: ... wt.path` — primary usage
- Class attribute `wt.enabled` tells callers whether isolation is actually active (caller uses `wt.path if wt.enabled else cu.get_project_root()`)

### FixExecutor — accept `worktree_cwd`

`src/cosa/agents/shared/fix_executor.py`:
- `__init__`: add `worktree_cwd: Optional[str] = None`; store as `self.worktree_cwd`
- `execute_fix()`: pass `worktree_cwd=self.worktree_cwd` to the callback functions (`delegate_to_coder_fn`, `verify_fix_fn`)

### BFE orchestrator — thread cwd_override + wrap in WorktreeContext

`src/cosa/agents/bug_fix_expediter/orchestrator.py`:
- `_build_coder_options()` / `_build_tester_options()`: accept `cwd_override: Optional[str] = None`; line 1456 becomes `cwd = cwd_override or cu.get_project_root()`
- `_delegate_to_coder()` and verify callbacks: accept and thread `worktree_cwd` down to `_build_coder_options(cwd_override=worktree_cwd)`
- `run_fix()` and `run_git_strategy()` entry points: when `cosa_worktree.enabled`, wrap in a single `WorktreeContext` that spans both phases:

```python
async with WorktreeContext(self.job_id) as wt:
    if wt.enabled:
        executor = FixExecutor(..., worktree_cwd=wt.path)
    else:
        executor = FixExecutor(...)
    await executor.execute_fix(...)
    git_ops = GitOps(cwd=wt.path if wt.enabled else cu.get_project_root(), ...)
    # ... Phase 5 work ...
```

The context spans Phase 3 + Phase 5 so the branch created by GitStrategist lives in the same worktree FixExecutor wrote to.

### TFE orchestrator — parity

`src/cosa/agents/test_fix_expediter/orchestrator.py`: same pattern. TFE reuses the shared `FixExecutor` and `GitStrategist` classes, so the plumbing mirrors BFE exactly.

### GitOps — no change

`src/cosa/agents/bug_fix_expediter/git_ops.py` already accepts `cwd` in `__init__` (line 36) and uses it in `_run_cmd` (line 65). `GitStrategist` inherits via its GitOps instance. The orchestrator just needs to pass the right `cwd` — no structural changes to GitOps itself.

### Runtime safety guard (enabled=false path)

When `cosa_worktree.enabled=false`, `run_fix()` calls `git status --porcelain` and if non-empty, emits a visible WARNING in logs:

> ⚠️ Worktree isolation is disabled AND current working tree has uncommitted changes. TFE/BFE fixes will mutate this tree and may contaminate your PR. Consider enabling `[cosa_worktree] enabled=true` or committing/stashing first.

This does NOT block execution — just surfaces the risk the user opted into.

## Edge cases

| Case | Handling |
|---|---|
| Sandbox dir doesn't exist | `mkdir -p` in `__aenter__` |
| Target worktree path already exists | Raise `WorktreeCollisionError` with clear message |
| Two concurrent jobs collide on `job_id` | `job_id`s are hash-based (astronomically unlikely), but collision error is clear |
| Base ref doesn't exist | Log warning, fall back to HEAD (with ref validated via `git rev-parse --verify`) |
| Cleanup fails (permissions, locked files) | Log warning, try `git worktree prune` as recovery, don't mask primary exception |
| Process crash mid-job | Orphaned worktree left behind; operator runs `git worktree prune` (documented in follow-up maintenance section) |
| Permission denied on sandbox_root | Raise cleanly at `__aenter__` |
