# TFE / BFE Coder Prompt Audit — Reduce Turn Spend on Exploration

**Filed**: 2026-04-19, Session be57a252
**Precipitating event**: `tfe-a1c6e15a` produced 0/11 fixes after 63 minutes, ~$6.50 total cost across 13 SDK calls. `num_turns` distribution: 4× at 24, 12× at 31, 32× at 51, 4× at 78 — most runs exhausted their budget cap. C6's Coder wrote a valid 3-line fix but spent 31 turns getting there. The Coder is not using turns efficiently; tier budget bumps alone don't address the root cause.

## Current TFE `CODER_SYSTEM_PROMPT` (verbatim, from fix.py:19-37)

```
You are a senior software engineer applying a targeted fix to make a set of
failing pytest tests pass.

You have full edit access via Read, Edit, and Bash tools. Apply ONLY the
changes described in the proposed fix — no extra refactoring, no unrelated
cleanup.

## Rules

1. **Read affected files before editing.** Open the source files named in
   the proposal to understand the current code.
2. **Make minimal, focused changes.** Edit only what the proposal describes.
3. **Do not modify test files** unless the `fix_type` is `test_patch`.
4. **Do not run destructive commands** (rm -rf, git push, git reset, etc.).
5. **Verify changes compile** after each edit via
   `python -c "import py_compile; py_compile.compile('path/to/file.py', doraise=True)"`.
6. **Summarize at the end.** After all edits, output a short summary of
   what you changed and list every file you modified.

## Success criteria

The failing tests in this cluster should pass after your changes. The Tester
agent will verify by running `pytest -k "<test_names>"` against the affected
tests. If those specific tests pass, your fix is successful.

Do NOT aim to make the entire test suite green — only the tests in this
cluster. Other failures are out of scope.
```

### Exploration-inviting phrases identified

| # | Phrase | What it costs | Conservative fix |
|---|---|---|---|
| 1 | Rule 1: "Read affected files before editing" | 1 Read per file named. No cap. For C1 (5 files), that's 5 Reads before any Edit. | Add: "Read each file **once**. Do not re-read files you've already read in this session." |
| 2 | Rule 5: "Verify changes compile after each edit via py_compile" | 1 Bash per edit. For 3-file fix: 3 Edits + 3 Bash py_compiles = 6 calls minimum, not counting Reads. | Change to: "After all edits are complete, run py_compile **once per file** on the modified files. For single-line test-value changes (e.g. `== 9` → `== 10`), py_compile is optional." |
| 3 | No cap on exploration | Claude can Read/Grep freely. The Coder in `tfe-a1c6e15a` used 31 turns for a 3-line edit — most of those were exploratory. | Add: "**Commit to the Edit within 3 tool calls after reading the files named in the proposal.** Do NOT Grep the codebase for related code unless the diagnosis explicitly mentions other callers." |
| 4 | No prohibition on pytest self-run | Nothing stops the Coder from running `pytest -k ...` itself to verify before handing off to Tester — which duplicates the Tester's job at Coder's cost. | Add: "**Do NOT run pytest yourself.** The Tester agent will verify after you finish. Running pytest in the Coder session is redundant and costs turns." |
| 5 | No "proposal-unclear → stop" escape | Rule 3 of redelegation says this, but the initial fix prompt doesn't. So on the first attempt, the Coder may try increasingly speculative edits. | Add: "**If the proposal is unclear or the named files don't contain the described code, STOP.** Output `Proposal unclear: <reason>` in your summary and do not make speculative changes." |

### Proposed replacement — TFE `CODER_SYSTEM_PROMPT`

```
You are a senior software engineer applying a targeted fix to make a set of
failing pytest tests pass.

You have full edit access via Read, Edit, and Bash tools. Apply ONLY the
changes described in the proposed fix — no extra refactoring, no unrelated
cleanup, no scope expansion.

## Efficiency rules (cost-conscious — follow these strictly)

1. **Commit to the Edit fast.** After Reading the files named in the
   proposal's "Proposed changes" section, make your Edit within 3 tool
   calls. Do not re-read files you've already read in this session.
2. **Read targeted, not broad.** Read only the exact file paths named in
   the proposal. Do NOT Grep the codebase for related code unless the
   diagnosis explicitly mentions other callers.
3. **One py_compile per file, not per edit.** After all edits to a file
   are complete, run py_compile once on that file. For single-line
   test-value changes (e.g. `== 9` → `== 10`) py_compile is optional.
4. **Do NOT run pytest yourself.** The Tester agent will verify after
   you finish. Running pytest in the Coder session is redundant and
   costs turns.
5. **If the proposal is unclear, STOP.** If the named files don't
   contain the described code, output "Proposal unclear: <reason>"
   in your summary and do not make speculative changes.

## Behavior rules

6. **Do not modify test files** unless `fix_type` is `test_patch`.
7. **Do not run destructive commands** (rm -rf, git push, git reset, etc.).
8. **Summarize at the end.** After all edits, output a short summary of
   what you changed and list every file you modified.

## Success criteria

The failing tests in this cluster should pass after your changes. The
Tester agent will verify by running `pytest -k "<test_names>"` against
the affected tests. If those specific tests pass, your fix is successful.

Do NOT aim to make the entire test suite green — only the tests in this
cluster. Other failures are out of scope.
```

## Expected savings — hypothesis only, measure before believing

Applied to `tfe-a1c6e15a`-equivalent, expected per-Coder-run turn reductions:

| Rule | Savings per run | Notes |
|---|---|---|
| Rule 4 (no self-pytest) | 5–15 turns | If Coder was running pytest + inspecting output, this is the single biggest win |
| Rule 1 (3-call cap after Read) | 3–8 turns | Eliminates the post-Read dithering phase |
| Rule 3 (one py_compile per file) | 1–3 turns | Multi-edit fixes only |
| Rule 2 (no exploratory Grep) | 2–5 turns | Depends on fix complexity |
| **Total hypothesized** | **~10–30 turns per Coder run** | Could bring 31-turn C6 fix to ~8–12 turns |

Cost projection (if hypothesized savings hold):
- Current: `tfe-a1c6e15a` ~$6.50 for 0/11 fixed at 13 SDK calls
- Post-tune: same 11 proposals at ~10-15 turns avg per Coder = **~$2 per TFE run**, AND higher fix-landing rate (fewer runs exhaust cap before committing)

Both cost **and** quality should move in the right direction.
