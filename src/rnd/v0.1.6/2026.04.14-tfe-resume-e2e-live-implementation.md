#### 2.2 Implement `test_live_stall_and_resume` body

**File**: `src/tests/integration/test_tfe_resume_e2e.py` (Lupin)

Replace the `pytest.skip()` at lines 212-215 with:

```python
def test_live_stall_and_resume( auth_headers ):
    """Full live validation: submit TFE → force stall → resume → verify completion."""
    # 1. Set the timeout override BEFORE job submission
    #    (orchestrator reads env var at __init__)
    os.environ[ "TFE_FEEDBACK_TIMEOUT_SECONDS_OVERRIDE" ] = "3"
    try:
        # 2. Submit a minimal TFE job via direct orchestrator construction
        #    (no TFE submit endpoint exists — go through helper)
        tfe_job_id = _submit_test_tfe_job( auth_headers )

        # 3. Poll until STALLED (up to 15s — voice gate will time out at 3s
        #    the first time a confirmation is requested)
        stalled_at = _poll_until_state( tfe_job_id, "stalled", auth_headers, timeout_s=15 )
        assert stalled_at is not None, "TFE job did not stall within 15s"

        # 4. Call resume-from-checkpoint
        resume_resp = requests.post(
            f"{BASE_URL}/api/jobs/{tfe_job_id}/resume-from-checkpoint",
            headers = auth_headers,
            timeout = 10,
        )
        assert resume_resp.status_code == 200
        resumed = resume_resp.json()
        resumed_id = resumed[ "resumed_job_id" ]
        assert resumed[ "resume_count" ] == 1

        # 5. Clear the override so the resumed job doesn't re-stall
        os.environ.pop( "TFE_FEEDBACK_TIMEOUT_SECONDS_OVERRIDE", None )

        # 6. Poll resumed job to completion (up to 60s)
        final_state = _poll_until_state( resumed_id, ( "completed", "done" ), auth_headers, timeout_s=60 )
        assert final_state in ( "completed", "done" )
    finally:
        os.environ.pop( "TFE_FEEDBACK_TIMEOUT_SECONDS_OVERRIDE", None )
```

**Helper: `_submit_test_tfe_job()`** — creates and pushes a minimal TFE job. Since no direct REST endpoint exists, the helper either:
- (a) imports TFE job factory directly and calls `todo_queue.push()`, OR
- (b) POSTs to a new test-only endpoint added in this phase.

Prefer **(a)** — zero API surface change, lives entirely in test code. Uses `cosa.rest.agentic_job_factory.create_agentic_job("agent router go to test fix expediter", ...)`.

**Helper: `_poll_until_state()`** — GETs `/api/job-history/{id}`, checks `status`, sleeps 1s, retries up to timeout.

## Risks & Mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| TFE orchestrator re-reads INI per-run → env override ignored | Low | Read once in `__init__` is typical; if not, cache at class-level with override precedence |
| Test framework sets env vars too late (after orchestrator `__init__`) | Medium | Set env var BEFORE submitting the job, not just before the assertion |
| Job factory unavailable from test context (no FastAPI app) | Medium | Fall back to Phase 2.2 plan option (b) — add test-only submit endpoint. Execution log flags this if hit. |
| CoSA edits diverge from eventual committed state | Low | Execution log explicitly lists each CoSA edit for user review |
| Resumed job re-stalls because override still set | Low | Test explicitly pops the env var before polling resumed job (step 5) |
