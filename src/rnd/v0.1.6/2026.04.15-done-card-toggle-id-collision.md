# Bug Fix — Done-card toggle silently no-ops (ID collision)

## Context

User reports two Done cards in the CJ Flow panel whose headers won't toggle open when clicked — `bug_fix_expediter` and `test_fix_expediter` from 12:56 AM on 2026-04-15. No console errors.

This is **Bug 2** deferred from yesterday's plan `src/rnd/v0.1.6/2026.04.14-all-suite-aggregation-and-history-card-toggle.md` (Step 3), which was postponed until the user was at the keyboard for in-browser verification.

**Hypothesis (confirmed by code read)**: `notifications.js:6995` resolves card details via unscoped `document.getElementById('job-details-${jobId}')`. Both live Done rendering (`renderJobCard`, line 6895) and history rendering (`renderHistoryCard` → `renderJobCard`) emit the same ID. When a completed job appears in both the live Done section and the History section, `getElementById` returns the first match (typically the hidden Done-section copy), so clicking the visible History card's toggle silently flips the hidden one's `.collapsed` class — zero visible effect, zero errors.

The two cards the user is clicking are almost certainly the History copies being clobbered by hidden Done-section duplicates.

Bug 1 (`all`-suite aggregation black hole) is a separate item in the same deferred doc; **out of scope for this session** unless user elects otherwise.

## Step 1 — Fix: namespace DOM IDs by queue section

**File**: `src/fastapi_app/static/js/notifications.js`

Prefer the structural fix over a scoped-lookup patch — it eliminates the collision class of bug.

Edit sites (all self-contained to this one file):

1. **`renderJobCard( job, queueName )` (line ~6887)** — change emitted IDs:
   - `id="job-card-${jobId}"` → `id="job-card-${queueName}-${jobId}"`
   - `id="job-details-${jobId}"` → `id="job-details-${queueName}-${jobId}"`
   - inline `onclick="...toggleJobCard('${jobId}','${queueName}')"` — already passes `queueName`, no signature change needed at call site.
   - Also namespace the `id="interactions-content-${jobId}"` at line ~6981 → `id="interactions-content-${queueName}-${jobId}"` and any other `*-${jobId}` IDs inside the card template. Audit via grep below.

2. **`toggleJobCard( jobId, queueName )` (line ~6991)** — resolve via namespaced IDs:
   ```js
   const details = document.getElementById( `job-details-${queueName}-${jobId}` );
   const card    = document.getElementById( `job-card-${queueName}-${jobId}` );
   ```
   Keep the `expandedJobCards` Set key as `${queueName}-${jobId}` so a job expanded in Done doesn't silently affect its History twin.

3. **`renderHistoryCard( job )` (line 6023)** — history cards always render into their own namespace, never sharing with any live queue. Replace the `statusToQueue` map's usage for ID purposes: pass `queueName = 'history'` unconditionally into `renderJobCard` so every history card's IDs become `job-details-history-*` / `job-card-history-*`. Status-driven styling (success/failure colors) continues to use the status map, but **decoupled from the ID scheme** — pass status separately (e.g. as a CSS class on the outer card) rather than overloading `queueName`. Under this rule a job in live Done (`job-details-done-X`) and the same job in History (`job-details-history-X`) can never collide.

4. **Audit all other call sites** that construct or look up these IDs. Grep the file for:
   - `job-details-\$\{`, `job-card-\$\{`, `interactions-content-\$\{`
   - `getElementById\(\s*[\`'"]job-(details|card)-`
   - `#job-details-`, `#job-card-` (CSS selectors in JS)
   - `expandedJobCards\.(has|add|delete)\(` — update keying scheme
   - `job-msg-input-\$\{`, `job-msg-urgent-\$\{` (send-message form at line ~7020) — decide whether to namespace these too; they're scoped inside one card so collision symptoms will be similar.

   Update each to use the `${queueName}-${jobId}` compound key. Missing a site = regression.

5. **CSS** (`src/fastapi_app/static/css/notifications.css` if selectors use these IDs) — grep for `#job-details-` / `#job-card-` attribute selectors. Likely none (class-based styling dominates) but verify.
