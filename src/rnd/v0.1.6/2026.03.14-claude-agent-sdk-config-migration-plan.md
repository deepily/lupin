# Claude Agent SDK Config Migration — Revised Plan (No Backward Compat)

**Date**: 2026-03-14
**Supersedes**: `src/rnd/2026.01.27-claude-agent-sdk-config-migration-plan.md`
**Key Change**: Drop backward compatibility — `from_config()` becomes the only path

---

## Context

Three Claude Agent SDK agents use hardcoded `@dataclass` configs. Model names, token limits, scaling heuristics, and behavior settings require code changes to modify. This migration moves all config to COSA ConfigurationManager (INI files + env var overrides).

**Existing INI keys found**: Some keys already exist (storage backend, audience, voice IDs, timeouts). The LLM Client Factory already uses ConfigManager for VLLM/local models via a `key` + `key_params` pattern. The migration adds the remaining fields and wires everything through ConfigManager.

## Resolved Decisions

- **Voice key naming**: Keep `podcast voice female/male *` (existing). Renaming would break TTS voice routing in `tts_client.py`.
- **Backward compatibility**: Dropped. No dual-path config loading. `from_config()` is the only path.
- **Model registry** (Phase 3): Move to INI. Same restart required either way, and INI enables env var overrides.
