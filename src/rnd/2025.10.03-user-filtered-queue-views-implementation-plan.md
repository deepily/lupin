# User-Filtered Queue Views Implementation Plan

**Date:** 2025-10-03
**Status:** Approved - Phase 1 Implementation
**Author:** Claude Code Assistant
**Priority:** High - Core Multi-Tenant Feature

## Executive Summary

### Problem Statement

The Fresh Queue UI currently displays **all jobs from all users** to every authenticated user, violating multi-tenant isolation principles. This creates:
- **Security Risk:** Users can see other users' private queries and results
- **UX Confusion:** Queue displays contain irrelevant jobs from other users
- **Scalability Issues:** Queue views become cluttered in multi-user scenarios

### Solution

Implement **role-based user-filtered queue views** with:
- **Regular Users:** See only their own jobs (default behavior)
- **Admin Users:** Can view own jobs, specific user's jobs, or all users' jobs
- **Backward Compatible:** Phased migration preserves current functionality during transition
- **Comprehensive Testing:** 4-layer test strategy ensures correctness and security

### Phasing Strategy

**Phase 1 (Current Work):** Backend infrastructure + testing (NO client changes)
**Phase 2 (Future PR):** Admin UI enhancement with "View All" toggle
**Phase 3 (Optional):** Default migration to most secure behavior

**File:** `src/cosa/rest/fifo_queue.py`

**New Methods:**
```python
def get_jobs_for_user(self, user_id: str) -> List[Any]:
    """
    Get raw job objects for specific user (NO authorization, NO formatting).

    Requires:
        - user_id is a valid user identifier

    Ensures:
        - Returns list of job objects matching user's job IDs
        - Returns empty list if user has no jobs
        - NO HTML formatting (returns raw objects)
        - NO authorization checks (pure data access)
    """
    user_job_ids = self.user_job_tracker.get_jobs_for_user(user_id)

    filtered_jobs = [
        job for job in self.queue_list
        if hasattr(job, 'id_hash') and job.id_hash in user_job_ids
    ]

    return filtered_jobs

def get_all_jobs(self) -> List[Any]:
    """
    Get ALL raw job objects (NO authorization, NO formatting).

    Ensures:
        - Returns complete queue_list
        - NO filtering by user
        - NO HTML formatting
        - NO authorization checks
    """
    return self.queue_list.copy()
```

**Design Rationale:**
- **Single Responsibility:** Data access only, no business logic
- **Testability:** Can be tested in isolation with mock jobs
- **Reusability:** Used by all queue types (todo, run, done, dead)

#### **Layer 2: Authorization Helper** (NEW module)

**File:** `src/cosa/rest/queue_auth.py`

**Purpose:** Queue-specific authorization logic using centralized auth utilities

```python
"""
Queue Authorization Helper

Provides role-based authorization for queue filtering operations.
Uses centralized auth utilities from auth_middleware.py.
"""

from fastapi import HTTPException
from typing import Optional
from cosa.rest.auth_middleware import is_admin


def authorize_queue_filter(
    current_user: dict,
    filter_user_id: Optional[str]
) -> str:
    """
    Determine authorized user filter based on roles.

    Requires:
        - current_user is authenticated user dict from get_current_user dependency
        - filter_user_id is query parameter (None/"*"/specific_id)

    Ensures:
        - Returns authorized filter value ("*" or specific user_id)
        - Raises 403 if unauthorized access attempted
        - Uses centralized is_admin() from auth_middleware
        - Regular users ALWAYS get their own user_id
        - Admin users get their requested filter

    Raises:
        - HTTPException(403) if regular user attempts admin operations

    Returns:
        str: Authorized user_id to filter by ("*" for all, or specific user_id)

    Authorization Matrix:
        | Role    | filter_user_id | Returns          | Status |
        |---------|----------------|------------------|--------|
        | User    | None           | current_user_id  | ✓      |
        | User    | "*"            | HTTPException    | 403    |
        | User    | other_id       | HTTPException    | 403    |
        | User    | own_id         | current_user_id  | ✓      |
        | Admin   | None           | current_user_id  | ✓      |
        | Admin   | "*"            | "*"              | ✓      |
        | Admin   | other_id       | other_id         | ✓      |
    """
    requesting_user_id = current_user["uid"]

    # Use centralized auth check from auth_middleware
    user_is_admin = is_admin(current_user)

    # Case 1: No filter specified → default to requesting user's own jobs
    if filter_user_id is None:
        return requesting_user_id

    # Case 2: Wildcard "*" → all users' jobs (admin only)
    if filter_user_id == "*":
        if not user_is_admin:
            raise HTTPException(
                status_code=403,
                detail="Only admin users can query all jobs. Regular users can only view their own jobs."
            )
        return "*"  # Authorized wildcard

    # Case 3: Specific user_id requested (different from self)
    if filter_user_id != requesting_user_id:
        if not user_is_admin:
            raise HTTPException(
                status_code=403,
                detail=f"Cannot access other users' jobs. Regular users can only view their own jobs."
            )

    # Admin requesting specific user, or user requesting their own
    return filter_user_id
```

**Design Rationale:**
- **Centralized Logic:** Uses `is_admin()` from `auth_middleware.py` (single source of truth)
- **Clear Errors:** Specific 403 messages guide users and admins
- **Extensibility:** Easy to add new roles or permissions

#### **Layer 3: API Orchestration** (Updated endpoint)

**File:** `src/cosa/rest/routers/queues.py`

**Changes to `/api/get-queue/{queue_name}` endpoint:**

```python
from fastapi import Query
from typing import Optional
from cosa.rest.queue_auth import authorize_queue_filter
from cosa.rest.auth_middleware import is_admin

@router.get("/get-queue/{queue_name}")
async def get_queue(
    queue_name: str,
    current_user: dict = Depends(get_current_user),
    user_filter: Optional[str] = Query(
        None,
        description="User filter: omit for self, '*' for all (admin), or specific user_id (admin)",
        example="ricardo_felipe_ruiz_6bdc"
    ),
    todo_queue = Depends(get_todo_queue),
    running_queue = Depends(get_running_queue),
    done_queue = Depends(get_done_queue),
    dead_queue = Depends(get_dead_queue)
):
    """
    Retrieve jobs from queue with role-based user filtering.

    **NEW:** Phase 1 implementation with backward-compatible defaults

    Authorization Rules:
    - Regular users: Can ONLY query their own jobs (user_filter ignored or must match self)
    - Admin users: Can query own, specific user's, or all users' jobs

    Query Parameters:
        - user_filter: Optional[str]
            - None (omit): Current user's jobs (default for all users)
            - "*": ALL users' jobs (admin only)
            - "user_id_xyz": Specific user's jobs (admin only)

    Returns:
        - {queue_name}_jobs: List of HTML job representations
        - filtered_by: Which user_id was used for filtering
        - is_admin_view: Boolean indicating if admin override was used
        - total_jobs: Count of jobs returned
    """

    # Step 1: Authorize the filter request
    try:
        authorized_filter = authorize_queue_filter(
            current_user=current_user,
            filter_user_id=user_filter
        )
    except HTTPException:
        raise  # Re-raise authorization failures

    # Step 2: Map queue name to queue object
    queue_map = {
        "todo": todo_queue,
        "run": running_queue,
        "done": done_queue,
        "dead": dead_queue
    }

    if queue_name not in queue_map:
        raise HTTPException(status_code=400, detail=f"Invalid queue name: {queue_name}")

    queue = queue_map[queue_name]

    # Step 3: Retrieve jobs based on authorized filter
    if authorized_filter == "*":
        # Admin requesting ALL users' jobs
        jobs = queue.get_all_jobs()
    else:
        # Specific user's jobs (could be self or other for admin)
        jobs = queue.get_jobs_for_user(authorized_filter)

    # Step 4: Apply queue-specific sorting
    descending = queue_name in ["todo", "done", "dead"]
    if descending:
        jobs.reverse()

    # Step 5: Format as HTML
    html_list = [job.get_html() for job in jobs]

    # Step 6: Return with metadata
    is_admin_override = is_admin(current_user) and (user_filter is not None)

    return {
        f"{queue_name}_jobs": html_list,
        "filtered_by": authorized_filter,
        "is_admin_view": is_admin_override,
        "total_jobs": len(html_list)
    }
```

**Backward Compatibility Notes:**
- `user_filter` parameter is **optional** (defaults to None)
- When None, returns user's own jobs (new correct behavior)
- JavaScript clients need NO changes (parameter omission is valid)
- Response format unchanged (adds metadata fields but keeps `{queue_name}_jobs`)

**Goal:** Add filtering capability without breaking existing clients

**Implementation:**
- Add optional `user_filter` query parameter
- Default behavior: Return user's own jobs when parameter omitted
- Preserve response structure (add metadata, don't change core fields)

- JavaScript clients continue calling `/api/get-queue/{queue_name}` (no parameters)
- Parameter is optional, so omission is valid
- Response includes same `{queue_name}_jobs` array as before

**Trade-off:**
- Current behavior (all users see all jobs) WILL change
- New behavior (users see own jobs) is MORE correct
- Admins temporarily lose "view all" until Phase 2 UI added

## Risk Assessment

### Identified Risks

#### **Risk 1: Breaking Change for Admins**

**Description:** Admins currently see all jobs, will see only own jobs after Phase 1

**Likelihood:** High
**Impact:** Medium (admin UX degraded until Phase 2)

**Mitigation:**
- Option A: Use role-aware default (admins keep seeing all temporarily)
- Option B: Fast-track Phase 2 admin UI
- Option C: Document behavior change in release notes

**Recommended:** Option A (role-aware default) for smooth transition

---

#### **Risk 2: UserJobTracker State Persistence**

**Description:** UserJobTracker is in-memory singleton, loses associations on restart

**Likelihood:** High (every server restart)
**Impact:** Medium (jobs lose user association)

**Mitigation:**
- Phase 1: Accept limitation (jobs created before restart unfiltered)
- Future: Add `user_id` field to `SolutionSnapshot` for persistence
- Future: Migrate UserJobTracker to database-backed storage

**Recommended:** Document limitation, plan Phase 4 for persistence

---

#### **Risk 3: JavaScript Client Compatibility**

**Description:** Response format changes could break client parsing

**Likelihood:** Low (we're adding fields, not removing)
**Impact:** High (UI breaks)

**Mitigation:**
- Preserve existing response fields (`{queue_name}_jobs`)
- Add new fields as optional metadata
- Test with existing client code before deployment

**Recommended:** Maintain backward-compatible response structure

---

#### **Risk 4: Performance with Large User Counts**

**Description:** Filtering jobs in Python list comprehension may be slow

**Likelihood:** Low (typical queues < 100 jobs)
**Impact:** Medium (slow API responses)

**Mitigation:**
- Current implementation: O(n) filtering acceptable for small queues
- Future optimization: Add index to queue_dict by user_id
- Future optimization: Database-backed queues with SQL filtering

**Recommended:** Monitor performance, optimize if needed
