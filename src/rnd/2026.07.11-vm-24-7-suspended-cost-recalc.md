## 1. Exact reconfig diff (for the owning terraform implementer — NOT applied by me)

**File:** `google/terraforming-vms/.vm-state/lupin-host-test/terraform/vm.tfvars`
```diff
-enable_overnight_pause = true
+enable_overnight_pause = false
```
**Why it gives "24/7 suspended by default":** `enable_overnight_pause=true` provisions `google_compute_resource_policy.vm_schedule` (`schedules.tf:5-6`, attached `compute.tf:101-102`) with a **daily 08:00 auto-START** (`start_time="0 8 * * *"`). Flipping to `false` → policy `count=0` → **nothing auto-resumes the VM** (this closes the F-A1 audit finding at the source).

**Operational steps (gcloud auth / real-money — Rick's console or the implementer):**
1. `gcloud compute instances suspend lupin-host-test --zone=us-central1-a` (one-time → suspended steady state). Terraform cannot declare a VM as created-suspended (`desired_status` only accepts `RUNNING`/`TERMINATED`), so the suspend is operational — same pattern as the repo's VM-stop / Cloud-SQL-`NEVER` default-paused model (`lupin/src/rnd/2026.06.30-gpu-model-server-cloud-run-split/05-default-paused-terraform-plan.md:25`).
2. `terraform apply` the `false` diff to remove the live auto-start resource policy.

**Caveat:** `vm.tfvars` is "Auto-generated by vm-manager" — if it's regenerated from an upstream input, the durable fix must flow through that input too.

## 2. Monthly cost — 24/7 suspended `lupin-host-test`, Postgres bundled on disk

**Machine (from vm.tfvars):** `e2-standard-8` (8 vCPU / 32 GB RAM); boot **100 GB pd-ssd**; data **200 GB pd-ssd** (Postgres lives here — bundled); **no external IP** (`compute.tf` has no `access_config`).

**Suspended billing model (GCP):** no vCPU/RAM charge; you pay only for **stored instance memory** + **persistent disks** + any static IPs. Preserved state is billed at Persistent-Disk rates, prorated per second.

**Rates — us-central1, retrieved 2026-07-11:** pd-ssd **$0.17**/GB·mo · pd-balanced $0.10 · pd-standard **$0.04**.

| Line item | Qty | Rate | $/mo |
|---|---|---|---|
| vCPU + RAM compute (suspended) | 8 vCPU / 32 GB | — | **$0.00** |
| Boot disk (pd-ssd) | 100 GB | $0.17 | **$17.00** |
| Data disk / Postgres bundled (pd-ssd) | 200 GB | $0.17 | **$34.00** |
| Suspended instance memory (PD-priced; pd-standard SKU) | 32 GB | $0.04 | **$1.28** |
| External IP | none | — | $0.00 |
| Cloud NAT (idle — suspended = 0 active VMs) | — | — | $0.00 |
| **TOTAL** | | | **≈ $52.28 / month** |

- If GCP bills the suspended 32 GB memory at the **pd-ssd** rate: memory = $5.44 → **≈ $56.44/mo**. Realistic band: **$52–56/month**.
- **Entirely dominated by the 300 GB of pd-ssd disk = $51/mo.** Compute is genuinely $0 while suspended. Postgres bundled on the 200 GB data disk → **no separate Cloud SQL charge**.

### Optional cost-reduction lever (Rick's call — NOT applied)
300 GB is provisioned as pd-ssd; a mostly-suspended dev VM rarely needs SSD IOPS:
- pd-ssd → **pd-balanced** ($0.10): disks $30/mo → **total ≈ $31/mo** (~40% cut; fine Postgres perf when resumed) — **recommended if cost matters**.
- pd-ssd → **pd-standard** ($0.04): disks $12/mo → **total ≈ $13/mo**, but slow for Postgres under load.
(Disk-type change on a data disk isn't in-place trivial — snapshot→recreate; owning implementer's call.)

### Reconciliation vs the old floor
The 2026-07-01 `05-default-paused-terraform-plan.md` floor (~$10–20/mo) assumed a **20 GB pd-standard boot + separate Cloud SQL**. The ACTUAL current config (post 2026-07-08 e2 downgrade) is **300 GB pd-ssd** with Postgres **bundled** on the 200 GB data disk → real suspended cost **~$52/mo**, higher because disks were under-counted in the old floor.
