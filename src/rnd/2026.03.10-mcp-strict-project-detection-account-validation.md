# cosa-voice MCP: Strict Project Detection + Account Validation

**Serialized from**: `~/.claude/plans/eager-sprouting-sun.md`

**Updated**: 2026-03-10 (Session 337) — revised after source code review

## Context

When Claude Code launches in an unrecognized repo, the MCP server silently falls back to `"unknown"` project (line 154 of `cosa_voice_mcp.py`). The sender_id becomes `claude.code@unknown.deepily.ai` — useless for notification routing. Two fixes needed:
1. Fail loudly when project can't be identified
2. Validate per-repo Lupin service account at startup

### Why per-repo accounts matter

Each repo needs its own first-class Lupin user account (e.g., `claude.code@lupin.deepily.ai`, `claude.code@newrepo.deepily.ai`). This is NOT the generic service account `claude.code@deepily.ai` — it's a repo-specific account because:
- The **CC Notification Listener** authenticates as this user via WebSocket to receive notifications
- The browser UI sends **user-initiated messages** to this account (routed by sender_id)
- Without a valid account, the entire voice I/O pipeline for that repo is dead

**Provisioning a new repo** requires:
1. Create PG account: `python src/scripts/create_service_account_postgres.py --email=claude.code@newrepo.deepily.ai`
2. Add credentials: `[newrepo]` section in `~/.lupin/credentials.ini`
3. The MCP server should validate both at startup and fail loudly if either is missing

### Design decision (revised Session 337)

On validation failure, send a **one-time urgent notification** via synthetic `claude.code@errors.deepily.ai` sender. The user hears a TTS alert with setup instructions. Tools continue working in degraded mode — no tool-result poisoning.

**Pattern precedent**: `_die_no_session_id()` (lines 305-332) already sends error notifications on startup failure — follow this pattern.

### Step 3: Validate service account at startup

**File**: `src/lupin_mcp/cosa_voice_mcp.py`

Add `_validate_repo_account( project: str ) -> None` — called after `SENDER_ID` is set (line 189) but before session watcher thread starts (line 297).

Validation checks:
1. `get_hook_credentials( project )` — credentials exist in `~/.lupin/credentials.ini`
2. `POST /auth/login` with those credentials — account is live

**On failure**: Send one urgent notification, then log and return (don't crash):

```python
from lupin_cli.notifications.notify_user_async import notify_user_async
from lupin_cli.notifications.notification_models import (
    AsyncNotificationRequest, NotificationType, NotificationPriority
)
from lupin_cli.claude_code.hooks.lib.hook_credentials import get_hook_credentials

ERROR_SENDER_ID = "claude.code@errors.deepily.ai"

def _validate_repo_account( project: str ) -> None:
    expected_email = f"claude.code@{project}.deepily.ai"
    try:
        email, password = get_hook_credentials( project )
    except ( FileNotFoundError, ValueError ) as e:
        _send_validation_error(
            f"No credentials for project '{project}'.\n{e}\n\n"
            f"To fix:\n"
            f"1. Create account: python src/scripts/create_service_account_postgres.py --email={expected_email}\n"
            f"2. Add to ~/.lupin/credentials.ini:\n"
            f"   [{project}]\n"
            f"   email = {expected_email}\n"
            f"   password = <password>"
        )
        return

    try:
        resp = requests.post( f"{SERVER_URL}/auth/login",
                              json={ "email": email, "password": password },
                              timeout=5 )
        if resp.status_code != 200:
            _send_validation_error(
                f"Login failed for {email} (HTTP {resp.status_code}).\n"
                f"Account may not exist or may be disabled."
            )
            return
    except requests.ConnectionError:
        _send_validation_error(
            f"Cannot reach Lupin server at {SERVER_URL}.\n"
            f"Ensure FastAPI is running: src/scripts/run-fastapi-lupin.sh"
        )
        return

    logger.info( f"Repo account validated: {email}" )

def _send_validation_error( detail: str ) -> None:
    msg = f"COSA-VOICE MCP VALIDATION FAILED\n\n{detail}"
    logger.critical( msg )
    try:
        request = AsyncNotificationRequest(
            message=msg,
            notification_type=NotificationType.TASK,
            priority=NotificationPriority( "urgent" ),
            sender_id=ERROR_SENDER_ID
        )
        notify_user_async( request=request, debug=False )
    except Exception as e:
        logger.warning( f"Could not send validation error notification: {e}" )
```

**Key detail**: `notify_user_async()` uses `get_api_config()` + `load_api_key()` for auth — needs a running Lupin server. If the server is down, the notification silently fails (caught in the try/except), but the critical log persists.
