## Item 1 — Single-source roster env file

### Problem

`COSA_VOICE_MANAGERS__LUPIN="Mr. Radio, Tiberius"` exists today only as an
`Environment=` literal inside the arbiter's systemd drop-in
(`~/.config/systemd/user/lupin-arbiter-app.service.d/override.conf`). Interactive
CC sessions never see it, and the value lives outside the repo. Rick wants ONE
definition, two readers.

### The file: `src/conf/fleet-roster.env`

- **Location**: `src/conf/` — config home, beside `lupin-app.ini`.
- **Name**: dashes per file-naming convention; `.env` extension signals the
  format. `.gitignore` does not match it (only `src/scripts/cloud-run.env` is
  ignored, by exact path) — verified trackable.
- **Format**: plain `KEY="value"` lines + `#` comments — the intersection of
  what `bash source` and systemd `EnvironmentFile=` both parse. No `export`
  keyword (systemd rejects it), no variable expansion (systemd doesn't expand).
- **Content**: the roster line, with a header comment explaining what the file
  is, who reads it, ordering semantics (roster head = declared fallback
  manager → **Mr. Radio first**, per Rick), and how to apply changes
  (interactive: next tmux-launched session picks it up automatically, or
  re-source; arbiter: `systemctl --user daemon-reload && systemctl --user
  restart lupin-arbiter-app`). `LUPIN_DEV_EMAIL` is explicitly NOT here —
  user-specific, stays a drop-in literal (Rick's carve-out).

### Reader (a): `src/scripts/start-cc-with-tmux.sh`

After `LUPIN_ROOT` resolution (line ~67), source with auto-export so the
variable is visible both to the script and to anything it execs:

```bash
FLEET_ROSTER_ENV="$LUPIN_ROOT/src/conf/fleet-roster.env"
if [[ -f "$FLEET_ROSTER_ENV" ]]; then
    set -a; source "$FLEET_ROSTER_ENV"; set +a
fi
```

Then forward across the tmux boundary the same way the persona chains travel
(existing pattern at lines 96–121): every `COSA_VOICE_MANAGERS__*` variable is
appended to `PERSONA_ENV_FLAGS` via `-e`. Generic glob (via `compgen -A
variable`) rather than a hardcoded `__LUPIN` key, so a future
`COSA_VOICE_MANAGERS__PLAN` line needs zero script edits. tmux does not inherit
arbitrary parent env — without the `-e` forward the SessionStart hook never sees
the roster (the same boundary that ate `persona_preference`, one engagement ago).

Sessions started OUTSIDE this script (bare `claude` in a terminal) see the
roster only if that shell sourced the file — the header comment notes the
optional `~/.bashrc` one-liner for that coverage. Spawned (headless) children DO
get it: `session_spawner` launches through this same script.

### Reader (b): the systemd drop-in — exact replacement text (Tiberius applies)

The drop-in lives outside the repo; this section IS the deliverable for it.
Replace the current `Environment="COSA_VOICE_MANAGERS__LUPIN=..."` line (and its

  survives intact; identical parse result to the bash source.
- Apply: edit drop-in → `systemctl --user daemon-reload` → `systemctl --user
  restart lupin-arbiter-app`.

## Item 2 — Reserve-from-random: declared managers leave the random pool

### Semantics (Rick's ruling, restated as invariants)

| Allocation path | Declared-manager names |
|---|---|
| Random (`allocate_persona_for_session`, no-param allocate) | **SKIPPED** |
| Chain wildcard `*` ("then take anything free") | **SKIPPED** |
| Explicit strict request (`requested_persona_name`, `request_persona` MCP tool) | claimable — unchanged |
| NAMED chain element (`"Mr. Radio,Tiberius,*"` named hops) | claimable — unchanged (this is how managers get their names) |
| Pool emptied by the exclusion | existing Sam/Arnold-overflow semantics, byte-unchanged |

The overflow persona is NOT subject to reservation: it is the exhaustion
fallback of last resort, not a "candidate for random selection" — if the roster
ever named the overflow persona, the overflow path would still hand it out.

### Transport: the hook carries the roster to the server

The allocate endpoint runs on `:7999` inside Docker, which has no
`COSA_VOICE_MANAGERS__*` in its env and no project context of its own. The
roster therefore travels the SAME corridor the persona chain already travels:

```
fleet-roster.env → start-cc-with-tmux.sh (source + tmux -e)
  → session env → SessionStart hook (register_session.py)
      reads COSA_VOICE_MANAGERS__<PROJECT> for ITS project
  → query param `declared_managers=<csv>` on POST .../allocate
  → router → allocation helpers (exclusion applied)
```

This is per-project by construction (the hook reads its own project's key) and
needs no docker-compose / server-env changes. Accepted scope consequence: a
session whose environment declares no roster (foreign project, bare-terminal
launch without the bashrc source) applies no exclusion. Rosters are per-project
advisory reservations, not server-global locks.

### Code changes (one name everywhere: `declared_managers`)

1. **Relocate `pick_declared_managers_from_env`** from
   `cosa/agents/heartbeat_arbiter/manager_resolver.py` →
   `cosa/rest/voice_persona_helpers.py`. Justification under the one-name rule:
   - It is the structural sibling of `pick_persona_chain_from_env` (same
     `__<PROJECT>` normalization, same CSV parse, same never-raise contract) —
     they belong in one module.
   - Its consumer set now spans the arbiter (`lupin_arbiter_app/app.py`) AND
     the allocation corridor (the LIVE SessionStart hook). The hook already
     imports `voice_persona_helpers` (stdlib-only); importing
     `manager_resolver` instead would drag `lupin_mcp.session_spawner` (its
     module-top import) into the live hook's import chain.
   - Single definition, NO re-export shim left behind in `manager_resolver`
     (a shim is an alias — prohibited). `app.py:242` import updated to the new
     home; tests move with it.
   - Internal split: extract `parse_declared_managers( raw_csv ) -> list[str]`
     (strip / case-insensitive dedup / drop `*`) so the router can parse the
     query param with the SAME parser the env reader uses — no second parser.

2. **`pick_unallocated_persona(..., declared_manager_names=None)`**
   (`voice_persona_helpers.py:374`): new optional set of POOL-KEY names;
   `free = pool − occupied − declared_manager_names`. The exhaustion branch
   (overflow → Extra-N → legacy borrow) is untouched — emptying `free` via the
   exclusion lands in the existing overflow path with `occupied_names`
   unchanged.

3. **`allocate_persona_for_session(..., declared_managers=None)`**
   (`voice_persona_helpers.py:461`): resolves roster names → pool-key names via
   the EXISTING `_find_persona_in_pool` (case-insensitive on pool key form AND
   `display_name_for` rendering — so `"Mr. Radio"`, `"mr radio"`, `"MR. RADIO"`
   all resolve to pool entry `mr radio`). Unknown roster names resolve to
   nothing and constrain nothing (a typo can't brick allocation). Passes the
   resolved set into `pick_unallocated_persona`.

4. **`allocate_persona_chain_for_session(..., declared_managers=None)`**
   (`voice_persona_helpers.py:865`): threads the roster into the wildcard
   branch's `allocate_persona_for_session` call ONLY. Named chain elements go
   through the strict requested path and stay reservation-blind by design.

5. **Router** (`routers/voice_persona.py:187`): new optional query param
   `declared_managers` (CSV, `max_length=256`), parsed with
   `parse_declared_managers`, threaded into both the random branch (line ~423)
   and the chain branch (line ~353). Strict `requested_persona_name` path: no
   change. `available` lists in 409/422 bodies intentionally still mean
   "pool − occupied" — reserved names ARE available to explicit requests.

6. **Hook** (`register_session.py` — LIVE hook, edited in this worktree only):
   `_allocate_voice_persona_via_http` gains `declared_managers=None`; appends
   the CSV query param when non-empty. Call site adds one resolution line
   (`pick_declared_managers_from_env( project, os.environ )`) next to the
   existing chain resolution at `:1053`. Minimal-delta discipline per the
   hook-coverage interim ruling; the logic lives in unit-tested helpers.
