## 2. Design decisions (deltas vs. the report's sketch)

### 2.1 New shared lib module: `lib/listener_processes.py`

F1 (SessionStart) and F2 (SessionEnd) both need "find live listeners serving hash H",
and F1 + F4 both need an exclusive-flock primitive. One canonical implementation, one
descriptive name each (no per-hook copies):

- `find_live_listener_pids( session_hash )` — `pgrep -f "cc_notification_listener.*--session-id <hash>"`,
  returns sorted PID list, excludes own PID, never raises.
- `exclusive_flock( lock_path )` — context manager; blocking `LOCK_EX`; yields a bool
  (`True` = lock held). **Fail-open**: any `OSError` during acquisition yields `False`
  and the caller proceeds unlocked — listener spawn / tmux injection must never be
  blocked by lock infrastructure. Matches the hook layer's pervasive never-raise contract.
- `listener_spawn_lock( session_hash )` / `tmux_injection_lock( tmux_session )` — named
  wrappers binding the lock-file path conventions
  (`~/.claude/sessions/cc-listener-{hash}.spawn-lock`, `tmux-inject-{sanitized}.lock`).
- `SESSION_DIR` module constant (same pattern as `cc_notification_listener.py`) —
  monkeypatchable for filesystem-isolated tests.

### 2.2 F1 — why flock + pgrep, not a PID file

The documented `--continue` double-fire runs two SessionStart hooks **concurrently**;
a check-then-spawn without mutual exclusion just narrows the race. The blocking flock
serializes the (pgrep → Popen → liveness-check) critical section (~0.5 s bounded), so
hook B enters after hook A's listener is alive and pgrep-visible. A PID file alone has
both a write-race and a staleness problem; pgrep-by-cmdline is ground truth.

When the guard finds an existing listener it records that PID into the bridge
(same write as the spawn path) and returns it — so SessionEnd still has a kill target
even when this hook never spawned.

On /clear, `_cleanup_old_listener` kills the old listener (synchronously, before
Phase 5.5), so the guard does not wrongly preserve a stale-`accepted_ids` listener;
the guard only short-circuits when the live listener already serves the same hash set
(the duplicate case).

### 2.3 F2 — reap by cmdline union, bridge PID as a member not the authority

`_find_all_listener_pids( session_id )` = bridge `listener_pid` (if any) ∪
`find_live_listener_pids( h )` for every hash associated with the session
(`session_id`, `stable_session_id`, each entry of `session_ids[]` — the listener's
`--session-id` is the **stable** hash, while SessionEnd receives the transient ID;
the old single-PID code already had that mismatch latent). `_find_listener_pid` is
deleted — one name, no alias (`_find_all_listener_pids` is the contract now).

### 2.4 F3 — contract break, not a parallel function

`filter_and_project_sessions` now returns `( included, filtered_out )`. All ~31 call
sites (3 production, 2 unit-test trees) updated — we own every consumer, so the
contract breaks cleanly rather than growing a `_with_receipts` alias.

`filtered_out[]` entry shape: `{ "session_id", "reason" }` plus `"age_seconds"` +
`"threshold_seconds"` for the mtime gate. Reasons: `bridge_unreadable`,
`owner_mismatch`, `stale_bridge_mtime`, `bridge_vanished` (TOCTOU stat failure),
`originator_excluded` (intentional, reported for receipt completeness).

`execute_broadcast` includes `filtered_out` in **both** 200 shapes — the
zero-recipient response especially, since that is the silent-miss case the receipts
exist for. Additive key for HTTP/MCP consumers; `broadcast-panel.js` appends a
filtered-out summary to the submit status line and `console.debug`s the full list.

### 2.5 F4 — flock spans the whole 2-step injection

`_inject_via_tmux` wraps (send-keys -l text → 250 ms sleep → send-keys Enter) in
`tmux_injection_lock( tmux_session )`. Serializes any two injectors that both honor
the lock — both duplicate listeners (until F1/F2 kill the class) and any future
in-repo injector that adopts the same primitive. Server-side injectors (e.g. the
register-question tmux push) are out of scope here, per the report.

  `execute_broadcast` carries `filtered_out` in both 200 shapes.

  one listener instance with recorded subprocess order → no interleave
  (text·Enter pairs stay atomic); lock fail-open still injects.

Venue: all :7999-discretionary (no DB, no server, /tmp + mocked subprocess only;
live-process tests use throwaway children with fake hashes).

## 4. Deployment note

This is live hook-family code. The fix is **inert until each session's next
SessionStart** (hooks execute the working tree): running sessions keep their current
listeners; F1/F2 take effect on their next start/end cycle, F4 when their listener
process is next restarted. No live listener processes are touched by landing this.
