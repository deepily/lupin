# External-sender card gap — root cause (Rick's 2026-06-11 ~19:50 EDT bug report)

**Author:** Clayton 😎 (for Tiberius 👑) · **Date:** 2026-06-11 evening (EDT)
**Symptom (Rick, verbatim):** "there's no card established for notifications that arrive from
outside the system." Concrete: the arbiter's stall warning (sender `lupin-arbiter-app-8001`-class,
no CC bridge, no persona) was spoken via the Sam TTS fallback but left no reviewable card.

## Verdict: the multiplexer has NO notifications-pane history hydration — cards are live-event-only

The bug is **not** external-sender-specific and **not** server-side. Reproduced end-to-end on
`:7999` with the test user (receipts below):

| Leg | Finding | Evidence |
|---|---|---|
| Server persist | ✅ INNOCENT — `/api/notify` fire-and-forget persists **unconditionally**, even when the user is offline (`notifications.py` step 1, `_persist_notification_sync`) | Repro POST with `sender_id=lupin-arbiter-app-8001` returned `user_not_available` yet the row landed |
| Server hydration data | ✅ INNOCENT — `GET /api/notifications/senders-visible/{email}` returns external senders unfiltered (`voice_persona: null` stamped, no format/persona gate) | Repro: arbiter sender present with `count:1, new_count:1` |
| JS classic cold load | ✅ **CARDS IT** — `loadConversationHistory()` iterates ALL visible senders → `conversation-by-date` → card; persona-less senders get the gray personaless treatment (existing tested behavior) | Playwright cold load: **arbiter card = 1** |
| Multiplexer live | ✅ cards external senders fine (any `notification_queue_update` with `sender_id` + parseable timestamp builds a card — no persona/format gate in `SenderStore`) | My `test_multiplexer_session_strip.py` builds cards from bare sender_ids |
| **Multiplexer cold load** | ❌ **THE GAP** — `NotificationStore.hydrate()` restores only the localStorage **unread count**; `boot.ts` hydrates the strip store + jobs history but **never fetches notification history**. Cold load renders **ZERO sender cards** (repro: 0 cards against 102 senders with history) | Playwright cold load: **total sender cards = 0** |

**Why external senders expose it maximally:** CC-session senders re-notify constantly, so their
cards reappear within seconds of any reload and the missing hydration is masked. A one-shot
external advisory (arbiter) never re-fires — its card exists only in a tab that was open at
delivery time, and is gone forever on the next load. With the Saturday cutover making the
multiplexer the default surface, every "while you were away" notification loses its record.

**Discrepancy to close with Rick's eyes:** my repro shows the JS classic client DOES card the
external sender on cold load. Rick reported no card in *either* client — likely he checked the
multiplexer (or the JS client's `historyWindowHours` window had moved past it). Not reproduced;
flagged, not assumed.

## Fix shape (pending design ruling)

Mux notifications-pane cold-load hydration mirroring the JS client and the established mux
hydration precedents (`JobStore.hydrateHistory`, `SessionStripStore.hydrate`):
`senders-visible` + `conversation-by-date` → seed `SenderStore` + `NotificationStore` → one
"hydrated" emission → cards paint on boot.

**Design decisions needed (Tiberius/Rick):**
1. **Hydration window** — JS classic uses `historyWindowHours` ("today"-anchored); the mux has no
   window selector. Adopt the same default silently, or add the selector now?
2. **External-sender card anatomy** — mux cards already render persona-less; ruling wanted on a
   distinguishing chip/icon for non-CC senders (JS classic precedent: gray personaless gradient).
3. **Staffing** — net-new feature lane (store seeding + renderer reconcile + unit 100% + e2e);
   bigger than a patch. Fresh worker vs. Clayton continuing — manager's call.
