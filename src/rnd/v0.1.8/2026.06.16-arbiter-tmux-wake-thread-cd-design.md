## 1. Investigation (C) — why the arbiter poke doesn't wake a dormant session

### 1.1 The arbiter ALREADY has a wake hop

Contrary to the initial "the arbiter never invokes the wake path" hypothesis, the arbiter's
`_emit_dm` (`src/cosa/agents/heartbeat_arbiter/arbiter_job.py:881`) already calls a `dm_push_fn`
seam (the "§3.3 manager wake hop"). In production (`:8001`) that seam is `make_dm_push_fn`
(`src/lupin_arbiter_app/arbiter_live_notify.py:334`), which does:

```
dm_push(persona, thread_id, body) → POST :7999/api/notify-peer (body INLINE)
    → notify-peer resolves persona → active session → dispatches a
      direction='ai_to_ai' notification → recipient's cc_notification_listener
```

So the arbiter DOES reach the listener. The break is **in the listener**, not the arbiter.

### 1.2 The break: the listener's buffer-vs-inject gate keyed on `EVENT_IDLE`

`cc_notification_listener._deliver_peer_dm` (`cc_notification_listener.py:292`) routes an inbound
`ai_to_ai` DM by the recipient session's liveness:

| `_recipient_is_idle()` | route | effect |
|---|---|---|
| **True**  | `_handle_peer_dm` → `_inject_via_tmux(wrap=False)` | **WAKES** the dormant pane |
| **False** | `_buffer_message` | sits in the voice buffer, **drained only by the NEXT injecting hook** (PreToolUse/PostToolUse/Stop) |

`_recipient_is_idle()` (`cc_notification_listener.py:319`) returns True **only** when the
session's last heartbeat outcome `== EVENT_IDLE`. `EVENT_IDLE` is emitted by
`stop.py:_emit_genuine_idle` (`stop.py:989`) **only on the transition into genuine idle**
(`not_owed` AND an empty Task* set).

### 1.3 Two distinct non-wake paths (both real)

A dormant session whose buffer nothing drains never wakes. The buffer is reached whenever
`last_outcome != EVENT_IDLE`, which happens in (at least) **two** ways:

1. **Stale-stopped-with-owed** — a stale manager (the arbiter's target, silent ≥ ~45 min) stopped
   with work owed → last outcome is `OUTCOME_POKE` (self-poked) or `OUTCOME_CAP_REACHED`
   (poke-capped). Neither is `EVENT_IDLE` → buffered → no wake.

2. **Idle-but-`EVENT_IDLE`-never-emitted** — Mr. Radio's residual probe (Problem A) found
   `poke_count = 0`: his self-poke NEVER fired (he was `not_owed`, so the heartbeat never emitted
   `OUTCOME_POKE`). If the genuine-idle transition also didn't fire (e.g. de-dup already consumed
   it, or the not_owed Stop carried a non-empty Task* set), `last_outcome != EVENT_IDLE` → buffered
   → no wake **even though the session is genuinely idle and waiting at a prompt**.

**Conclusion**: the `EVENT_IDLE`-keyed gate is the bug surface. Any fix that still routes through
`_deliver_peer_dm` inherits both failure modes.

### 1.4 Why Rick's broadcasts DO wake

`_handle_broadcast_received` (`cc_notification_listener.py:445`) hands `handle_broadcast` an
`inject_fn = lambda text: self._inject_via_tmux(text, wrap=False)` and injects **unconditionally**
for the addressed personas — no `_recipient_is_idle()` gate. That is exactly the asymmetry: the
broadcast path bypasses the buffer gate; the peer-DM path does not.

## 2. Design (D) — runtime-configurable poke surface, default TMUX (Approach B)

### 2.1 Chosen approach: host-side direct tmux (Approach B)

The arbiter app runs **host-side** (systemd `--user`, uid 1001, same user as the CC tmux server;
`run-lupin-arbiter-app.sh` does `cd $LUPIN_ROOT/src` + sets PYTHONPATH). So it can reach the
user-scoped tmux socket directly via `tmux send-keys -t <session-name>`, exactly the mechanism
broadcasts already use. We reuse the existing host-side primitive
`hook_common.inject_qualifier_via_tmux(session_id, text, wrap=False)` — which resolves the tmux
session from the bridge and `send-keys` **unconditionally** (no idle gate), waking a dormant pane.

This **bypasses `_deliver_peer_dm`'s `EVENT_IDLE` gate entirely**, covering BOTH non-wake paths
from §1.3.

**Approach A (rejected)**: thread a `force_tmux` flag through `/api/notify-peer` →
`NotificationItem` → WS dict → listener to bypass the idle gate. More surface across server +
listener, less self-contained. Mr. Radio's NOD: "Approach A's server-threading is needless surface."

### 2.2 The seam: `tmux_push_fn(session_id, thread_id, body) → outcome`

A new optional seam on `ArbiterConsumerJob`, sibling to `dm_push_fn`. The arbiter already holds
the dark session's `session_id` at poke time (`_check_manager_staleness` passes `session_id=sid`
into `_emit_dm`, `arbiter_job.py:1804`; the comment there even reads "the poke targets a DARK
session (it may have no self-wake)").

Production wiring `arbiter_live_notify.make_tmux_push_fn` (seam-injected for tests):

```
tmux_push(session_id, thread_id, body):
    resolve = resolve_fn(session_id)            # find_session_by_id — read-only bridge probe
    if not resolve or not resolve.tmux_session: # degrade-safe signal
        return {channel: dm_push, outcome: push_unavailable, detail: ...}
    framed = reminder_fn(body, persona=..., msg_id=thread_id, thread_id=thread_id)
    inject_fn(session_id, framed, wrap=False)    # inject_qualifier_via_tmux — never raises
    return {channel: dm_push, outcome: dispatched}
    # any exception → push_unavailable (never raises)
```

The pre-check on `find_session_by_id` lets `_emit_dm` **fall back to `dm_push_fn`** when tmux/bridge
is unavailable — without that signal `inject_qualifier_via_tmux` swallows errors silently and we
could never tell delivery failed.

### 2.3 `_emit_dm` mechanism branch (degrade-safe — rider a + b)

```
# (b) durable board write — UNCONDITIONAL, both mechanisms, runs FIRST (poke never lost)
self._commons.send_to(persona, body, metadata={... question_id=qid ...})
log dm-channel outcome (posted | post_error)

# push hop — mechanism-selected
push_outcome = None
if self._poke_wake_mechanism == "tmux" and self._tmux_push_fn and session_id:
    push_outcome = self._tmux_push_fn(session_id, qid, body)       # never raises
    if push_outcome.outcome == "push_unavailable" and self._dm_push_fn:
        push_outcome = self._dm_push_fn(persona, qid, body)        # (a) fall back to DM
if push_outcome is None:                                           # mechanism=dm, or no tmux fn/session_id
    push_outcome = self._dm_push_fn(persona, qid, body) if self._dm_push_fn \
                   else {channel: dm_push, outcome: disabled}
log push-channel outcome
```

Invariants honored:
- **(a) degrade-safe**: `tmux_push_fn` never raises; `push_unavailable` → DM fallback; the board
  write already happened so the poke is durable regardless.
- **(b) board write in both paths**: it is unconditional and precedes the push-hop selection.
- **(c) unconditional inject**: the WAKE target is stale-by-definition; no idle pre-check.

### 2.4 Config: `arbiter poke wake mechanism = tmux | dm` (default **tmux**)

- Read in `app.assemble_app` (with the other `cfg.get` calls), threaded through
  `build_fleet_arbiter_job_factory(poke_wake_mechanism=...)` → `ArbiterConsumerJob`.
- `ArbiterConsumerJob.__init__` validates the value ∈ `{tmux, dm}`; a malformed value coerces to
  the default `tmux` with a LOUD log line (mirrors `arbiter_bootstrap.submit_arbiter_if_enabled`'s
  bool-coercion pattern — a typo must not silently change wake behavior).
- `tmux_push_fn` built in `_build_arbiter_outreach_hops`, returned alongside the existing hops,
  passed via `assemble_app` → factory → job (same path as `dm_push_fn`).
- **Reversible**: `= dm` restores the prior notify-peer-only behavior; nothing is hard-deleted.

### 2.5 Splainer (rider F)

`lupin-app-splainer.ini` gets a paired explanation for `arbiter poke wake mechanism` (every new
`lupin-app.ini` key requires its splainer twin).
