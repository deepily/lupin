## 1. Current shape (what exists today)

- **Envelope**: `PresentationOrchestratorAgent` drives `PresentationAPIClient` through up to 7 content-synthesis calls (analysis → outline → elaboration, plus on-demand mermaid/matplotlib/d2 diagram-code generation, plus a structured `call_with_json_output`), all `content_model` (Anthropic), all firewalled-key, all funnelling to one `messages.create` (L529).
- **Gemini path (SEPARATE, non-Anthropic)**: `GeminiImageClient` drives NanoBanana (images) + Veo (video) renderers. Independent client, independent key. **Out of scope.**
- **Non-LLM phase**: parsed slide dicts → theme/templates → Marp/pptx assembly + diagram/image/video renderers → final deck. Stays.

## 2. Migration boundary (what changes vs what stays)

| **`gemini_client.py` + NanoBanana/Veo renderers (non-Anthropic)** — UNTOUCHED | The firewalled-key dependency for the content phase (drop unused refs) |

## 4. Output parsers = D6 STRICT (structured content consumed downstream)

Per ratified **D6=STRICT for Presentation**: bounded CC returns a single completion that may carry chatty prose, but the result feeds pptx rendering where a malformed/empty deck is a real failure.

For `parse_analysis_response` / `parse_outline_response` / `parse_elaboration_response` AND `call_with_json_output`:
- **Robustly recover** the JSON object from chatty output (fence-strip + last-balanced-`{…}` extraction — needed because bounded CC is chattier than `messages.create`). Reuse the `extract_json_object` brace-matcher pattern (port from Podcast/BFE).
- **STRICT failure posture** (the change from today's `return []`):
  - Unrecoverable JSON → **raise** `ValueError` (fail-loud), NOT `return []`.
  - Recovered but the expected list (`sections`/`outline`/`slides`) is **missing or empty** → **raise** (zero structured content = real defect).
  - Per-entry validation (skip non-dict entries) stays as-is.
- **⚠ Orchestrator implication (must handle in this lane)**: callers at `orchestrator.py:630/760/879/976` currently receive `[]` on failure. Making parsers raise means those call sites (and any retry/revision loop) must surface the failure loudly (propagate or notify+fail the job) rather than silently building an empty deck. Audit each call site; add explicit fail-loud handling. This is the one orchestrator-touching part of an otherwise client-only migration — call it out for the reviewer.
- `call_with_json_output` already raises `ValueError` on bad JSON today — extend it with the prose-recovery step (keep the raise).
