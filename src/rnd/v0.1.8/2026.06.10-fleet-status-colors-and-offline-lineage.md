(`src/lupin_app/static/js/notifications.js`) and is fed by the heartbeat arbiter's published
snapshot (`src/cosa/agents/heartbeat_arbiter/`). Two improvements were requested:

1. **TASK 1 — color-coding** (client only): make liveness verdict and context-window pressure

degrade-safe throughout. The color scheme is documented here so the multiplexer's Fleet-Status
port (Lane E) can inherit it verbatim.

## TASK 1 — Liveness + Context-Pressure Color-Coding

### Where

- Row builder: `notifications.js` `_renderFleetRow()` (`~8757–8799`) + two new pure helpers.
- Styles: `src/lupin_app/static/css/notifications.css` Fleet-Status section (`~5806–5962`).
- Tests: `src/tests/unit/notifications_js/fleet_status_panel.test.ts`.

### Accessibility principle

Color is **always redundant** with a text label already present in the cell — the verdict word
(`LIVE`/`quiet 6m`/`stale 12m`/`offline`) and the numeric `%`. Color therefore *reinforces*,
never *replaces*, the signal (WCAG 1.4.1 "Use of Color"). Dot colors sit ≥3:1 against the white
row; heat-tints are low-alpha so the dark numeric text keeps ≥4.5:1 contrast.

### (a) Verdict → liveness color

A **status dot** leads the verdict word in the Liveness cell; a **3px left-edge accent** on the
row reinforces it. A single verdict class on the `<tr>` drives both via CSS — one source of truth.

| Verdict band | `<tr>` class | Color (CSS var) | Hex | Meaning |
|---|---|---|---|---|
| `LIVE` | `fleet-verdict-live` | `--fleet-live` | `#2e7d32` green | fresh signal within the live window (≤60s) |
| `quiet Nm` | `fleet-verdict-quiet` | `--fleet-quiet` | `#1565c0` blue | recently active, within the alive window (≤10m) |
| `stale Nm` | `fleet-verdict-stale` | `--fleet-stale` | `#f57f17` amber | aging, still within the ~1h decay window |
| `offline` | `fleet-verdict-offline` | `--fleet-offline` | `#9e9e9e` grey | no recent signal / reaped / dead |
| _(no liveness)_ | `fleet-verdict-unknown` | `--fleet-unknown` | `#bdbdbd` l.grey | no liveness data at all |

Verdict colors are deliberately **disjoint from the existing `fleet-row-stuck` red background**
(`rgba(220,53,69,.06)`) — stuck is an orthogonal axis (a LIVE row can be stuck). The left accent
is a `box-shadow: inset` so it never fights the stuck background nor shifts layout.

JS helper `_fleetVerdictClass( verdict )` matches the first whitespace-delimited token,
case-insensitively (`"stale 12m"` → `stale`), defaulting to `unknown`.

### (b) % Window consumption heat-tint

On the `<td class="fleet-col-window-pct">` cell, keyed by `consumption_pct_of_window`:

| Range | `<td>` class | Tint |
|---|---|---|
| `< 50%` | `fleet-pct-low` | green `rgba(46,125,50,.12)` |
| `50% – 79%` | `fleet-pct-mid` | amber `rgba(245,127,23,.16)` |
| `≥ 80%` | `fleet-pct-high` | red `rgba(198,40,40,.16)` + bold |
| unmeasured (`—`) | _(no class)_ | no tint |

Breakpoints documented as CSS-class thresholds. A measured `0%` tints green (low = healthy);
`null`/`undefined`/non-numeric/`NaN` → no class (the `—` cell stays untinted).

JS helper `_fleetPctClass( pct )` returns `fleet-pct-low|mid|high` or `""`.

### Final color scheme (for the Lane-E multiplexer port)

```
verdict→color:  LIVE=#2e7d32  quiet=#1565c0  stale=#f57f17  offline=#9e9e9e  unknown=#bdbdbd
%window heat:   low(<50)=green#2e7d32@12%  mid(50–79)=amber#f57f17@16%  high(≥80)=red#c62828@16%+bold
markers:        liveness status-dot (8px) + row inset 3px left-accent;  pct = cell bg tint
redundancy:     color is ALWAYS paired with the verdict word / numeric % (WCAG 1.4.1)
```

## TASK 2 — Offline-Lineage Retention (the "Unmanaged" bug)

### Repro (observed 2026-06-10)

Sam (`baa28090`) + Clayton (`a9ec3dd0`) were reaped ~14:33 UTC. Their bridges were deleted and
they dropped to the **Unmanaged** group in the fleet table — while still inside their ~1h decay
window — even though they were Tiberius-managed (the focus-bar badge, event-sourced at spawn and
client-cached, still showed it).

### Root cause

`build_snapshot()` sets a row's `manager` **only** when `resolve_manager_fn(sid).source ==
"lineage"` (degrade-safe: never show a guessed manager). `manager_resolver.resolve_manager()`
has exactly two lineage sources, and **both die at reap in the same instant**
(`session_spawner.dismiss_sessions`):

1. **PRIMARY** — `bridge.spawned_by` (the manager's real session id). The bridge file is
   `unlink()`ed on reap.
2. **FALLBACK** — manifest-name scan over `spawned-<mgr>.json`. The reaped session's manifest
   entry is dropped (and the file unlinked if it empties).

So the very next poll after reap, both paths miss → `SOURCE_UNRESOLVED` → `manager=None` →
the row lands in **Unmanaged**, even though the session lingers in `stale Nm` (published, not yet
`offline`-pruned) for up to ~1h. The table thus contradicts the focus-bar badge.

### Fix: carry forward last-known lineage until row eviction

A new **pure** function `carry_forward_lineage( snapshot, prior_lineage )` in `fleet_render.py`,
threaded across polls by a caller-owned `self._manager_lineage` dict on `ArbiterConsumerJob`,
applied in `_publish_fleet_snapshot()` right after `build_snapshot()`.

Per published row:
- `manager` is **not None** (fresh lineage this poll) → **refresh** `next_lineage[sid]`; row untouched.
- `manager` is **None** but `sid` ∈ `prior_lineage` → **fill** `row["manager"] = prior_lineage[sid]`,
  set `row["manager_retained"] = True` (honest transparency flag), keep carrying it.
- `manager` is **None** and `sid` ∉ `prior_lineage` → genuinely **Unmanaged** (no carry, no invention).
- `next_lineage` is **pruned to the snapshot's current sids** → a row that evicts (goes `offline`
  → pruned from the published snapshot) **forgets** its lineage. Bounded; matches "until row eviction".

### Why this source (vs alternatives)

- **Snapshot-carry of the prior poll's resolution** (chosen): zero new persistence surface, no
  schema/file, no dependency on reap-ordering. The arbiter already threads cross-poll state
  (`self._acc`, `self._last_frame_sig`, …); one more dict fits the established pattern. The carry
  function stays pure + 100%-testable with fakes.
- **Durable lineage record (file)** (rejected): heavier — a new on-disk artifact to write, read,
  prune, and reconcile with reap. Over-engineered for "remember the last value until the row leaves".
- **Resolve-before-delete at reap time** (rejected): couples the arbiter's view to
  `dismiss_sessions` ordering and races the very deletion we're compensating for.

### Degrade-safety invariants (Rick's redline)

- **Never invents lineage** — only ever replays a persona *this fleet actually resolved before*.
- **Never raises** — a malformed snapshot/row degrades to `(snapshot, {})` / a skipped row.
- `manager_retained` is purely additive metadata; the frontend's existing grouping reads `manager`
  unchanged. `frame_signature` does not include `manager`, so the carry causes **no** spurious
  table re-render (it keeps the frame stable across the reap, which is the correct behavior).

### Where

- `src/cosa/agents/heartbeat_arbiter/fleet_render.py` — new `carry_forward_lineage()`.
- `src/cosa/agents/heartbeat_arbiter/arbiter_job.py` — `self._manager_lineage = {}` state +
  one carry call in `_publish_fleet_snapshot()` + import.
- Tests: `src/tests/unit/test_fleet_render.py` (pure-function branches) +
  `src/tests/unit/test_arbiter_fleet_snapshot.py` (cross-poll retention through a simulated reap).
