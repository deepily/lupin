## 3. Tail the arbiter logs yourself — cheat sheet

The arbiter runs as a **user systemd service** (`lupin-arbiter-app`, :8001) and logs structured JSON lines to journald. All commands run as your normal user (no sudo).

```bash
# 1. Live tail, everything (Ctrl-C to stop)
journalctl --user -u lupin-arbiter-app -f

# 2. Live tail, OUTREACH ONLY — "is it attempting to reach out?" (your original ask)
journalctl --user -u lupin-arbiter-app -f -o cat | grep --line-buffered arbiter_outreach

# 3. Live tail, human-readable one-liners (time, kind, who)
journalctl --user -u lupin-arbiter-app -f -o cat \
  | jq -r 'select(.event=="arbiter_outreach") | "\(.ts) \(.kind) → \(.recipients|join(",")) | \(.summary[0:90])"'

# 4. Replay a time window (journalctl --since/--until take LOCAL time = EDT)
journalctl --user -u lupin-arbiter-app --since "11:30" --until "12:05" -o cat | grep arbiter_outreach

# 5. Why is it NOT poking someone? (gate-evaluation trail; dumps hourly + on change)
journalctl --user -u lupin-arbiter-app -f -o cat | grep --line-buffered arbiter_poke_gate

# 6. Event census for a window (what kinds of activity happened at all)
journalctl --user -u lupin-arbiter-app --since "today" -o cat \
  | grep -oE '"event": "[a-z_]+"' | sort | uniq -c | sort -rn
```

**Gotchas**:
- The `ts` field INSIDE each JSON line is **UTC** (+00:00); the journalctl line prefix (in default output, without `-o cat`) is local EDT. Subtract 4h from `ts` or trust the prefix.
- `grep` in a live pipe needs `--line-buffered` or matches sit invisible in the buffer.
- `-o cat` strips the journal prefix so each line is pure JSON (what `jq` wants).

**Event vocabulary** (post-game build, 2026-06-11): `arbiter_outreach` (every outbound communication: kinds `ping`, `tap`, `stuck_poke`, `manager_stale_poke`, `manager_stale_advisory`, `fleet_dark`, `reap_rec`, `manager_down`, `decision`, `stall`, …) · `arbiter_poke_gate` (why-not-poked vectors) · `arbiter_poll_activity` (counters, only on nonzero polls) · `fleet_arbiter_render` (the table) · `health_obs` (container health) · `context_pressure_written`.
