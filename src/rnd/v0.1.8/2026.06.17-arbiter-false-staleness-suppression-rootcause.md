## 1. ROOT CAUSE — what "last signal" measures (deliverable 1)

**"last signal" = `now − freshest_age_s`**, computed in `fleet_render.compute_liveness()`. `freshest_age_s` is the **minimum (freshest) age across the up-to-5-signal union**:

| Signal | Source | Bumped by |
|---|---|---|
| `bridge_age_s` | bridge-file mtime | every PreToolUse (Read/Edit/Bash/MCP tool call) |
| `event_age_s` | last STOP / non-idle_prompt event | a completed assistant turn |
| `commons_age_s` | last `commons_who` activity | posting/reading commons |
| `idle_prompt_age_s` | last `kind=idle_prompt` beacon | the idle-prompt hook |
| `dm_age_s` *(toggle `count_dm`, default on)* | last SENT `ai_to_ai` DM | `dm_send` to any peer |

It does **NOT** read tmux-pane content, and it does **NOT** read the heartbeat-hold file (the hold file gates the Stop-hook poke, not the arbiter's staleness check — confirmed; see `reference_heartbeat_hold_uses_harness_session_id`).

**Why §4's 06-12 episodes saw "last signal" timestamps that didn't match Mr Radio's commons activity:** the 06-12 arbiter predated the Part-7 / DM-as-liveness 5-signal union — the OLD `compute_liveness` saw only `{bridge, event}` (its own docstring records this as the false WHOLE-FLEET-STALL bug). So commons posts genuinely weren't in the union then. **Current HEAD already folds in `commons_age` + `dm_age`**, so an *acking* manager (posting threaded ACKs / DMing) now freshens — this **already substantially closes class (d)** by construction. (Caveat: only if the running `:8001` arbiter is on current HEAD — see §4 deploy note.)

**The residual, un-closed false positive (the live one Tiberius hit this session):** an interactive manager working directly with Rick, **no `/loop`**, emits **none of the 5 signals** during a long human-away gap — no tool calls (waiting on Rick → no bridge bump), no completed turns, no commons, no DM, no idle beacon. After 45 min (`manager_stale_poke_threshold_seconds = 2700`) **all five ages legitimately exceed threshold → `freshest_age_s ≥ 2700` → MANAGER-STALE fires.** The manager is perfectly healthy; it is *correctly blocked on the human*. No liveness-signal enrichment can fix this — a session genuinely produces no signal while idle-waiting. The honest discriminator is **not** "is there a signal?" but **"does this manager actually OWE non-Rick-gated work?"**

## 2. THE CODE GAP — `_check_manager_staleness` is the one detector L1 left store-blind

The L1 store-awareness work (2026-06-17) added a per-poll store classification, `_classify_owed()`, that buckets each manager:

- `CLASS_DONE` ⇔ zero non-terminal owed items
- `CLASS_BLOCKED_ON_USER` ⇔ ≥1 owed item AND **every** owed item is Rick-gated
- `CLASS_ACTIVE` ⇔ ≥1 owed item that is NOT Rick-gated
- `CLASS_UNKNOWN` ⇔ seam unwired / store hiccup / persona absent → **fail-SAFE (escalate as today)**

L1 threaded `owed_class` into **`_check_manager_acks`** (#9 manager-down) and **`_check_fleet_stall`** (#11 fleet-dark), so those two suppress BLOCKED_ON_USER → case 16 (MANAGER-AWAITING-USER) and DONE → case 17 (MANAGER-DONE), each at most once, instead of the repeating escalation.

**But `_check_manager_staleness` (#F2, case 14) was NOT given `owed_class`** — line 800 of `arbiter_job.py`:

```python
manager_stale_pokes = self._check_manager_staleness( self._last_full_snapshot, now, active_managers )
#                                                     ^^ no owed_class — fires on raw freshest_age_s ≥ 2700
```

So the *exact* false-positive class L1 closed for manager-down/fleet-dark is **still open** for manager-staleness. This is the single highest-leverage fix and it **reuses cases 16/17 that already exist and already route `TIER_RICK_AND_MANAGERS`.**

## 4. PROPOSED DESIGN (for Tiberius's approval — NOT yet built)

**Primary fix (store-aware staleness, mirrors L1 cases 16/17):**
1. Thread `owed_class` into `_check_manager_staleness` (the `eval_personas` set already includes tapped managers; ensure staleness-eligible managers are classified in the same single per-poll read).
2. For an eligible (age ∈ [threshold, max_age]) manager:
   - `CLASS_BLOCKED_ON_USER` → **suppress** the repeating case-14 poke; emit **at most ONE** case-16 (MANAGER-AWAITING-USER) advisory per episode (or none, if 16 already fired via the acks path — de-dupe).
   - `CLASS_DONE` → suppress case-14; emit **at most ONE** case-17 (MANAGER-DONE / consider-reaping) advisory per episode.
   - `CLASS_ACTIVE` / `CLASS_UNKNOWN` → **today's behavior** (case-14 poke + advisory). UNKNOWN = fail-safe.
3. Episode state (`_mgr_stale_since` / `_mgr_poke_count` / `_mgr_advised`) clears on freshen/declassify exactly as today, so the cap + advisory re-arm.

**Secondary suppressors (explicit markers — belt-and-suspenders for what the store can't express):**
- **(a) human-gated presence marker w/ TTL** — a manager writes a machine-readable marker (`fleet_state=human_gated`, expiry ts). Staleness suppressed while the marker is unexpired. TTL prevents a forgotten marker from masking a genuinely-dead manager. (Mr Radio literally posted this at 06:31 and was ignored.)
- **(b) post-ritual standby** — manifest status `committed` + published roster 0 → terminal quiet, suppress. (Derivable from `CLASS_DONE` + roster count; marker optional.)
- **(c) zero-workers + queued/running :8000 job** — needs a signal of an in-flight test-suite job; suppress staleness for the waiting manager.

**Addendum #14 (Mr Radio — quota-freeze correlation + "covers-metadata retry bug"):** the 1 TP was a fleet-wide quota freeze (ALL sessions silent at once). Correlating simultaneous staleness across managers → recognize a **systemic** freeze → emit ONE whole-fleet advisory rather than N per-manager pokes. **I do not yet have the verbatim addendum-#14 text** (the top-7 doc only references it; "covers-metadata retry bug" is unresolved). → **OPEN QUESTION for Tiberius** (see §6).
