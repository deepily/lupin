## 1. Context

The notifications page shows a **"N missed while away"** indicator (the AFK-inbox / "Lever D"
badge) in the System Status accordion. It is a **live query** recomputed on every WebSocket
reconnect — `count_undelivered_for_recipient()` counts notification rows in state
`created`/`queued`, `is_hidden=False`, created within the last 24h (storm-guard cap added
after the 2026-06-03 stale-replay incident).

**Gap Rick hit:** the badge was "sticky." Viewing notifications did not clear it, reconnecting
only recomputed/displayed it, and there was **no user-facing affordance** to acknowledge/dismiss.
The count only decayed as rows aged past the 24h window. Rick asked for a **reset button** beside
the indicator.

## 2. Design decision — soft-dismiss (chosen via ask_multiple_choice)

Three ways to drop rows out of the badge's count query were considered:

| Option | Mechanism | Verdict |
|---|---|---|
| **A — Soft-dismiss (CHOSEN)** | `is_hidden=True` | Uses the column the count query already filters on (zero schema change). Preserves the honest audit trail (state stays `created`/`queued` = never actually delivered). Reversible. Also clears the `/undelivered` pull inbox. |
| B — Mark delivered | `state→delivered` | Rejected: semantically lies (claims delivery that never happened); pollutes `delivered_at` analytics. |
| C — New `acknowledged` state | enum addition | Rejected: larger blast radius (every state-machine consumer + count query must learn it) for a one-button feature. |

Rick selected **A (soft-dismiss)**.

## 3. Implementation

### Backend
- **`NotificationRepository.dismiss_undelivered_for_recipient(recipient_id, max_age_hours=None) -> int`**
  (`src/cosa/rest/db/repositories/notification_repository.py`) — bulk `is_hidden=True` update over
  the SAME filter as `count_undelivered_for_recipient` (incl. the 24h cap), so post-call the count
  is 0. State untouched (audit trail). Returns rowcount; flushes.
- **`POST /api/notifications/undelivered/dismiss`** (`src/cosa/rest/routers/notifications.py`) —
  JWT/API-key auth. Returns `{ status, dismissed_count, undelivered_count, timestamp }` where
  `undelivered_count` is the post-dismiss count (0 on success). 400 on bad UUID, 500 on failure.
  Auto-appears in FastAPI `/docs` (authoritative API reference; no hand-written doc tracks the
  AFK-inbox family).

### Frontend (`src/fastapi_app/static/`)
- **HTML** (`html/notifications.html`) — a `Reset` button (`#missed-reset-button`,
  `data-testid="notifications-missed-reset-btn"`) beside `#missed-status`. Hidden by default;
  shown only when the count is non-zero.
- **JS** (`js/notifications.js`) —
  - `_surfaceMissedNotifications(count)` now also toggles the Reset button's visibility with the badge.
  - New `resetMissedNotifications()` (async, on `NotificationsUI`): `POST`s to the dismiss
    endpoint via `authedFetch`, then re-surfaces the returned count (0) to zero the badge live.
    Error-handled with `this.error` + alert. **No confirm prompt** (removed per Rick
    2026-06-03): the reset is non-destructive (soft-dismiss, state preserved, reversible),
    so a one-click clear is appropriate — the confirm dialog stood between Rick and a
    zero-cost action.

## 4. Bug found & fixed during this work (inline-onclick wrong global)

The first wiring used `onclick="window.freshQueueUI.resetMissedNotifications()"` — copied from the
adjacent logout button. **`freshQueueUI` is never assigned anywhere** in the codebase; the real
global is **`window.notificationsUI`** (`NotificationsUI` instance, `notifications.js:18391/18394`).
Clicking threw `Cannot read properties of undefined (reading 'resetMissedNotifications')`.

- The **pre-existing logout button** (`window.freshQueueUI.logout()`) had the identical latent bug.
- It was never caught because `test_logout_redirects_to_login` asserts `"/login" in url OR "/app"
  in url`; a throwing click stays on `/app/notifications` (contains `/app`) → **false-pass**.

**Fix:** both buttons repointed to `window.notificationsUI.*`. Sweep confirmed 0 remaining
`freshQueueUI` references. Lesson captured in auto-memory
`feedback_verify_inline_onclick_global_resolves.md`.
