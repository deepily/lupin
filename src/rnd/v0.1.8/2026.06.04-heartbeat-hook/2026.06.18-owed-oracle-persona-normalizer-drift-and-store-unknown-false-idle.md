## Facet 1 — persona-normalizer DRIFT between the owed READ seam and the WRITE seam

### Symptom
A manager whose voice persona name carries an accent or punctuation
(**María**, **Mr. Radio**) false-idles while genuinely owing work; clean-ASCII
personas (Tiberius, Clayton) do not. Tiberius's empirical store probe:

| query `owner_persona=` | rows |
|---|---|
| `"maria"`  | 22 |
| `"maría"`  | 0  |
| `"mr radio"` | 54 |
| `"mr. radio"` | 0 |

### Root cause
The owed READ seam, `stop.py::_owed_count_from_store`, computed the query key as
a **bare `.lower()`** of the persona name:

```python
persona_lower = ( persona.get( "name" ) or "unknown" ).lower()
ok, count = query_owed( settings, api_key, persona_lower, ... )
```

The store's `owner_persona` rows, however, are stamped in the **voice-pool
canonical form** — accent-stripped, punctuation-stripped, lowercased, **internal
spaces kept** (display `"María"` → `"maria"`, `"Mr. Radio"` → `"mr radio"`; the
pool defines `voice_persona.name` directly in this form). For an accented/
punctuated persona whose name reaches the read seam in display form, `.lower()`
yields `"maría"` / `"mr. radio"` — which match **zero** rows → false "nothing
owed". Clean ASCII names normalize to themselves under `.lower()`, so they match
by luck — exactly why those managers don't false-idle.

This is **Sam's project-alias false-idle bug-class (`07622b34`) on the PERSONA
axis**: read-side and write-side normalizers disagreed.

### The 3-way drift (strategic — for the bug-tracker)
There are currently **three different persona normalizers** in the tree, none
shared:

1. **READ seam** (`stop.py`, pre-fix): `.lower()` only → `"maría"`, `"mr. radio"`.
2. **WRITE form** (voice pool / MCP `task_create` stamping): accent+punct-stripped,
   lowercased, **spaces kept** → `"maria"`, `"mr radio"`.
3. **`follow_through_escalation_watcher._norm_persona`**: NFKD + drop-combining +
   lowercase + `re.sub(r"[^a-z0-9]","")` — strips **spaces too** → `"mrradio"`.
   This would ALSO miss the store rows; it must **not** be substituted for the
   read seam.

Killing this drift class strategically = collapse all three onto ONE shared
function (one-name-at-both-seams). This change introduces that function on the
read side; **adopting it at the write seam + retiring `_norm_persona` is the
follow-up** (broader blast radius — server + config).

### Fix
New `session_bridge.canonical_persona_key( name )` — the canonical key the READ
seam now routes through. NFKD-decompose, drop combining marks, lowercase, reduce
to `[a-z0-9 ]` (**spaces kept**), collapse whitespace, trim. It is **IDEMPOTENT**:
`key("María") == key("maria") == "maria"`, so it is regression-safe whether the
bridge holds the display form or the already-normalized pool form (the live
bridges currently hold the latter).

`_owed_count_from_store` now calls `canonical_persona_key(...)` instead of
`.lower()`.

### Reproduction (flips)
- `test_accented_persona_queries_canonical_key_FLIP`: persona `"María"` →
  query key `"maria"` (was `"maría"`).
- `test_punctuated_persona_keeps_internal_space_FLIP`: `"Mr. Radio"` →
  `"mr radio"` (guards against the space-stripping `_norm_persona`).
- `test_already_normalized_pool_name_is_idempotent`: `"mr radio"` → `"mr radio"`.
- Dedicated `test_session_bridge_persona_key.py` covers the normalizer directly.

## Facet 2 — store-UNREACHABLE conflated with genuine NOT-OWED (the whole-fleet false-idle)

### Symptom
All three managers false-idled **at once**, correlated with the `:7999` outage —
NOT with per-session task state. The beacon said "idle — nothing owed" while the
store was simply down.

### Root cause
`stop.py::_run_heartbeat`, when `owed_source_from_store` is ON and
`_owed_count_from_store` returns `store_ok=False` (timeout / ConnectionReset),
correctly fails safe by setting `owed_items = []` so the §C fail-safe **suppresses
the POKE**. BUT the verdict then renders identically to genuine idle → the
`idle_announce` beacon emits **"Heartbeat: idle — nothing owed."** This conflates
**UNKNOWN** (store down — owed status unknowable) with **NOT-OWED** (store
answered, count 0). Gating only the poke, not the MESSAGE, was the gap.

### Fix — a THREE-state verdict
`_run_heartbeat` now returns `( hook_output, owed_unknown )`. `owed_unknown` is
True iff the store source was ON and the read FAILED. `main()` threads it into
`_announce_idle( ..., owed_unknown=owed_unknown )`, which renders:

- `owed_unknown=False` → `"Heartbeat: idle — nothing owed."` (unchanged)
- `owed_unknown=True`  → `"Heartbeat: owed status unknown (task store
  unreachable) — NOT idle; verify manually."` + spoken `"Owed status unknown."`

The poke remains suppressed exactly as before (§C fail-safe untouched); only the
beacon MESSAGE is now gated on the three-state distinction.

### Reproduction (flips)
- `test_flag_on_store_unreachable_no_local_signals_no_poke`: returns
  `owed_unknown=True` (was implicitly idle).
- `test_flag_on_store_zero_idles`: store ANSWERED, count 0 → `owed_unknown=False`
  (the contrast — genuine idle still says "nothing owed").
- `_idle_sentence` / `_announce_idle` unknown-beacon tests assert the abstract
  never contains "nothing owed" and does contain "unknown" + "verify manually".
- `test_store_unreachable_threads_owed_unknown_to_announce`: end-to-end through
  `main()`.
