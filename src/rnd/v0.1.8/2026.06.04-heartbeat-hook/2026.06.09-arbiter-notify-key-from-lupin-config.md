## 1. TL;DR

The arbiter's live-push-to-Rick hop (`POST :7999/api/notify`) authenticates with an `X-API-Key`. Today that key is read from the raw env var `LUPIN_ARBITER_NOTIFY_API_KEY`, which was never provisioned → live push is OFF (degrades safe to commons-only). **Change the source:** read the key from `~/.lupin/config`, section `[development]`, key `api_key_file` (a path), then read that file — reusing the canonical `cosa.utils.config_loader`. This makes live push light up with zero secret-in-env and zero new mechanism, because the file already exists and already holds a valid `ck_live_…` key.

## 2. Why this source

`~/.lupin/config` (INI) already defines per-environment notify credentials. `[development]`:

```ini
[development]
api_url      = http://localhost:7999
api_key_file = /mnt/DATA01/.../src/conf/keys/notification-api-claude-code-dev
global_notification_recipient = admin@lupin.deepily.ai
```

The pointed-to file holds a valid `ck_live_…` key (73 bytes, format matches `load_api_key`'s regex). This is the **same credential** the cc-notification-listener, hooks, and `notify_user_*` already use — so the arbiter joins the existing, working auth path instead of inventing a parallel env-var path.

## 3. Reuse — do NOT reinvent

`src/cosa/utils/config_loader.py` already provides exactly what we need:

- `get_api_config( env="development" )` → returns `{ "api_url", "api_key_file", ... }`, honoring env-var overrides (`LUPIN_API_URL`/`LUPIN_API_KEY_FILE`/`LUPIN_API_KEY`) ABOVE the file, then `[development]` from `~/.lupin/config`.
- `load_api_key( api_key_file )` → reads + strips + validates the `ck_live_…` format; also honors a direct `LUPIN_API_KEY` env override.

The arbiter app **already imports cosa** inside its production-construction boundary (`app.py:284-285`, `create_production_app`), so importing `config_loader` there is consistent and adds no new dependency surface.

## 4. The change (single function, already pragma'd)

**File:** `src/lupin_arbiter_app/app.py` — `_build_live_notify_fn( cfg )` (currently `# pragma: no cover - literal external IO boundary`).

Replace the key acquisition block (current `app.py:252-255`):

```python
api_key = os.environ.get( "LUPIN_ARBITER_NOTIFY_API_KEY" )
if not api_key:
    _default_log_fn( "live_notify_disabled", reason="LUPIN_ARBITER_NOTIFY_API_KEY not set" )
    return None
```

with a config-file read that stays **degrade-safe** (any failure → log + `return None`, never crash arbiter startup):

```python
from cosa.utils.config_loader import get_api_config, load_api_key

config_env = cfg.get( "arbiter live notify config env", default="development" ) or "development"
try:
    api_cfg = get_api_config( env=config_env )
    api_key = load_api_key( api_cfg[ "api_key_file" ] )
except ( FileNotFoundError, ValueError, KeyError ) as e:
    _default_log_fn( "live_notify_disabled",
                     reason=f"could not load api key from ~/.lupin/config [{config_env}]: {e}" )
    return None
```

**Invariants preserved:**
- The `arbiter live notify enabled` gate still fires first (unchanged).
- Degrade-safe: missing config / missing file / bad format → `None` → escalations stay durable on the `fleet-escalations` commons topic; never a storm of failed POSTs and never a startup crash.
- The whole function remains the pragma'd no-cover IO boundary; `build_notify_request` + `make_live_notify_fn` (the tested pure seams) are untouched.
