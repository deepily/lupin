# Fleet-Status: spawned worker shows "Unmanaged" — diagnosis + fix proposal

---

## 1. Symptom (empirically reproduced)

`resolve_manager("6acfa341")` returns `{manager_session_id: None, manager_persona: None, source: "unresolved"}`
→ `build_snapshot` shows `manager = None` (degrade-safe: never guess)
→ `groupFleetByManager()` files the row under **"Unmanaged"**, not under Tiberius.

The live arbiter (`:8001`, restarted 2026-06-09 20:24 EDT, PID 1775929) uses this exact resolver, so the panel renders the same.

## 2. The lineage join (as built)

`manager_resolver.resolve_manager(sid)` (`src/cosa/agents/heartbeat_arbiter/manager_resolver.py`) is a multi-hop join:

```
sid → bridge.tmux_session            (find_session_by_id)
    → manifest record session_name match  across ~/.claude/sessions/spawned-*.json
    → manager_session_id             (parsed from the manifest FILENAME)
    → manager_persona                (get_voice_persona)
```
`source="lineage"` requires ALL hops to succeed; any miss/ambiguity → `unresolved` → `manager=None`.

## 3. Where it breaks — HOP 2 (manifest scan), via the COLLISION GUARD

Per-hop trace for `6acfa341`:

| Hop | Result |
|---|---|
| 1. `bridge.tmux_session` | ✅ `'cc-reviewer-tiberius-1'` |
| 2. `find_manager_session_id('cc-reviewer-tiberius-1')` | ❌ **`None`** |
| 3. persona | (not reached) |

`find_manager_session_id` enforces a **multi-match guard** ("if the child's `session_name` resolves to MORE THAN ONE manager-id → return None; escalate-don't-guess"). The child name `cc-reviewer-tiberius-1` is present in **THREE** manifests:

- `spawned-7b76ad86-….json` — **mine** (current Tiberius), 1 record
- `spawned-1647c17c-….json` — a **prior** Tiberius session (stale), contains `cc-reviewer-tiberius-1`
- `spawned-b8a9f332-….json` — another **prior** Tiberius session (stale), contains `cc-reviewer-tiberius-1`

Three managers "claim" the same child name → collision guard fires → `None`. (The round-trip filename guard is fine — verified `True` for my id.)

## 4. Root cause

The manifest **join key is the child tmux `session_name`, which is persona-indexed and reused** — `cc-<role>-<persona>-<N>` (e.g. `cc-reviewer-tiberius-1`). Every Tiberius-personated manager session that spawns a reviewer #1 produces the **identical** name. Combined with **stale manifests** from dead prior-Tiberius sessions that still live in `~/.claude/sessions/`, the same name legitimately appears in several manifests → the join is structurally ambiguous → escalate-don't-guess → "Unmanaged".

Two contributing factors:
1. **Non-unique join key** — the child name embeds the *persona*, not the *manager session id*, so it is not globally unique across time.
2. **Stale-manifest accumulation** — `dismiss_sessions` prunes reaped *children* from the *live* manager's manifest, but a dead manager's *whole* manifest lingers. Those linger-manifests are what create the phantom collision.

## 5. The fix (proposed) — prefer the authoritative `spawned_by`

The child's **bridge already records `spawned_by`** = the manager's real session id, globally unique, collision-proof. Verified for Mr. Radio:

```
find_session_by_id("6acfa341")["spawned_by"] == "7b76ad86-7cf3-4d45-b2a7-a93da7b64f71"
get_voice_persona("7b76ad86-7cf3-4d45-b2a7-a93da7b64f71")["name"] == "Tiberius"
```

**Change `resolve_manager` to use `bridge.spawned_by` as the PRIMARY lineage source**, resolving persona directly from it. Keep the existing `tmux_session → manifest-name scan` ONLY as a fallback for older bridges that predate `spawned_by`.

```
bridge = bridge_lookup(sid)
manager_id = bridge.get("spawned_by")                 # NEW: authoritative, unique
if not manager_id:                                    # fallback (legacy bridges)
    manager_id = manifest_scan(bridge.get("tmux_session"), session_dir)
if manager_id:
    name = persona_lookup(manager_id).get("name")
    if name: return {..., source: "lineage"}
# else declared / unresolved (unchanged)
```

Why this is right (matches the codebase's authoritative-source philosophy):
- **Unique & collision-proof**: a real session id, not a reusable persona-indexed name. The 3-manifest collision simply cannot arise.
- **Stale manifests become irrelevant** to the primary path.
- **Degrade-safe preserved**: no `spawned_by` and no unambiguous manifest hit → still `declared`/`unresolved` (never a guessed manager).
- **`list_managers_fn` (the role=manager set)** still uses manifest ownership — fine, unchanged; a manager is still "a session that owns a manifest."

### Secondary remediation (hygiene, non-blocking)
Prune `spawned-<id>.json` manifests whose manager session is dead (e.g. `1647c17c`, `b8a9f332`). Reduces collision surface for the fallback path and keeps `list_manager_session_ids` honest. Candidate: a host-side prune at SessionStart (mirrors the existing dead-bridge prune) or a `dismiss_sessions`-time manager-manifest GC.
