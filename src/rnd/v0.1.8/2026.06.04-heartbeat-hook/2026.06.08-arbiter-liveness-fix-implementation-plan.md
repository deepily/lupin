## TL;DR

The arbiter's fleet roster is built from a **single frozen source** — the STOP-hook outcome log (`events_by_session`) — so it tracks ~20 dead historical sessions and is **blind to the live fleet** (every live worker reads `offline`). This produced a **false WHOLE-FLEET-STALL** escalation. The fix: **rebuild the roster as the UNION of four liveness signals** (process bridge+PID, commons-recency, `idle_prompt`, stop-event), with the **arbiter as the integrator** and the **`context_pressure` leaf staying a pure process primitive**. Liveness biases toward ALIVE; ACTIVITY (working/stuck/holding) demotes to a separate axis. This is **build-step 1 of 3** (routing rework + loop rename = step 2; probe tier = step 3).

### Step 1.3 — `idle_prompt` emits a fleet event (Decision #4, the 4th signal)

## Risks & mitigations

1. **CLI-pid (`ppid`) resolution fragility** (`_resolve_cc_pid` falls back to `hook_ppid` on error). → `None`/wrong-pid is None-safe in the OR; the other three signals backstop it; never treat `None` as dead.
2. **Bridge-discovery cost** (`find_active_voice_persona_sessions` stats every bridge). → already applies a coarse 12h filter; runs once per ~60s poll; acceptable. Measure if the fleet grows large.
3. **Double-counting across id forms** (short 8-char event ids vs full-uuid bridge/commons ids — review N3). → canonicalize id form at union time reusing the existing prefix-match logic BEFORE dedup; one VIEW per canonical session.
4. **Pre-`ppid` bridges** (older than the field) → `None` → not-checkable, not dead (Step 1.1 acceptance). Most/all current bridges already have `ppid`.
5. **Four-age verdict regression risk** (review B1) — the ages must be threaded into `fleet_render.compute_liveness`, not just added to the view; a miss here = the fix silently no-ops at `/state`. → ACs assert a live-by-commons-only and a live-by-idle_prompt-only session BOTH read LIVE in `build_snapshot` output.
6. **`/state` consumer coupling** → the locked freshness-gated leaf-direct fallback (Decision #1) covers unreachable/stale `/state`; `generated_at` already present enables it.
