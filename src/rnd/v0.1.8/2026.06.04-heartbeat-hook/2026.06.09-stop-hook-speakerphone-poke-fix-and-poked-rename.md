## 1. Rick's reframe (the design — NOT an AFK gate)

The native heartbeat self-poke does NOT fire for speakerphone sessions (every manager). Rick's corrected design:

1. **No AFK gate.** The poke should ALWAYS fire when a worker has *stopped with work owed* — the Stop-hook + the existing work-owed oracle ARE the gate. "Am I at the console" is irrelevant: a worker actively in dialogue with Rick has no owed-and-stopped state, so the oracle simply won't fire; a worker that genuinely stopped with owed Task work gets poked. Drop the AFK-predicate idea entirely.
2. **No stand-down.** The `stop.py` poke is the **permanent first line of defense** (catches a worker the instant it stops). The `:8001` arbiter is the **second line** for *escalated / persistent* cases. Both stay forever — no make-before-break retirement, no enable/disable flag tied to the arbiter.
3. **Breadcrumb to Rick's card.** When the hook catches a stopped-with-owed worker (poke fires) — and on idle — drop a low-priority notify on Rick's notification card ("Krishna stopped — 2 owed Task items, poked").

## 2. Root cause (confirmed at the line)

`src/lupin_cli/claude_code/hooks/stop.py` `main()`:

```python
# line ~990
if get_speakerphone( session_id ):
    log_to_stream( "stop", {}, extra={ "phase": "speakerphone_skip", "session_id": session_id } )
    emit_json( {} )
    sys.exit( 0 )          # ← BAILS OUT here
...
# line ~1065 (75 lines downstream — never reached for speakerphone sessions)
heartbeat_output = _run_heartbeat( session_id, payload.get( "transcript_path" ) )
```

The `:990` early-exit was meant narrowly — skip the noisy *"Anything else?"* blocking ask in speakerphone — but it short-circuits the entire downstream path, taking the heartbeat poke down as collateral. Every speakerphone session exits at 990 and never reaches the poke at 1065.

## 3. The fix (relocate, don't gate)

- **Run the heartbeat self-poke for speakerphone sessions too.** Relocate `_run_heartbeat` so it executes BEFORE (or independent of) the `:990` speakerphone early-exit. Its own work-owed oracle (`evaluate_work_owed` over the session's Task* replay) is the real gate — unchanged.
- **Keep skipping ONLY the blocking ask** in speakerphone (that part of the `:990` intent is correct — don't fire the interactive "Anything else?" ask via TTS in speakerphone). I.e. split the current all-or-nothing early-exit: speakerphone still suppresses the *blocking ask*, but NOT the *poke* and NOT the *breadcrumb*.
- **Loop-guard invariant preserved:** the poke still only fires downstream of the `stop_hook_active` re-fire guard and only in Branch C (voice always wins). Do not poke on a re-fire.
- **Confirm no double-speak** (María Q2): the poke rides the Stop-hook `reason` field (`decision:block`) — a silent re-prompt, not a TTS utterance. Verify it composes with the chorus/auto-narrate path without speaking twice.

## 4. Breadcrumb to Rick's card

- On **OUTCOME_POKED** (worker stopped with owed work → poked) AND on **idle**, fire a low-priority `AsyncNotificationRequest` to Rick's card. The `_announce_idle` / `idle_announce` path (`stop.py:289`) already does this for non-speakerphone idle — extend it so (a) the **poke** event breadcrumbs too ("<persona> stopped — <specifics>, poked"), and (b) speakerphone no longer suppresses the breadcrumb (it's a card notify, not a blocking ask).
- Keep it low-priority + deduped (the per-Stop cost is already cheap); reuse the existing notify plumbing.

## 6. HARD build constraint — worktree-safe (NON-NEGOTIABLE)

`stop.py` (and the `heartbeat_decision` / `heartbeat_events` modules it imports) is the **LIVE, ENABLED hook** — it executes on every Stop trigger of every session. Editing it in the live working tree runs **uncommitted, unreviewed code in production on the next trigger** (this footgun bit the original Heartbeat Hook build). Therefore:

- **The implementer builds in a dedicated git worktree** (`git worktree add /tmp/stophook-wt-<id> <branch>`), edits + tests + commits there. NEVER the live working tree. (Worktrees in `/tmp` can be pruned mid-flight — if it vanishes, regenerate the diff via `git diff`.)
- Re-enable / land only AFTER reviewed + committed.
- The interim keep-alives — the manual cascade-poker AND Tiberius's `/loop` — are unaffected (no stand-down; §1.2).
