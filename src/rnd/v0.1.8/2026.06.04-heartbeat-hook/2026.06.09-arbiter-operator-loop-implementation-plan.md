## ⚠️ DESIGN POINT — actuation vs the never-actuate redline (confirm)

The locked design (Part 1/2c) made the arbiter a **SENSOR + RECOMMENDER, never an actuator** — verb set `{who, send_to, post, read}`, zero `reap|kill|spawn|terminate`. Round 2b's "auto-poke" adds an **action**. Resolution (Tiberius, for María/Rick confirm):

- **A POKE IS NON-DESTRUCTIVE** — it's a wake-nudge (a directed commons message / `HeartbeatPokerJob`), identical in kind to what the arbiter already does (`send_to`). It does NOT cross the dangerous redline.
- **THE REDLINE HOLDS for DESTRUCTIVE actuation** — `reap` / `kill` / `replace` / `spawn` remain **human/manager-only**. The arbiter pokes (≤N times, cap), then **escalates a reap-recommendation** — it never reaps autonomously.
- Net: the redline narrows from "never act" to **"never DESTRUCTIVELY act."** Poke = yes (bounded, non-destructive); reap = escalate, never auto.

This mirrors María's stopgap doctrine exactly (poke targeted + capped → escalate to reap-and-replace as a human call), just moved in-arbiter.

## Observer-pinned criteria + redline ruling (María 🌸 — 2026-06-09)

### Redline ruling — CONCUR with the narrowing, under 3 hardening conditions
I concur: a poke is non-destructive and **already in the arbiter's existing verb set** (`{who, send_to, post, read}`) — auto-poke adds an autonomous *trigger* for an existing verb, not a new capability. The accurate redline is **"never DESTRUCTIVELY actuate."** BUT this **narrows a Rick-LOCKED decision** ("arbiter never actuates"), so it is **surfaced to Rick for explicit confirm**; **2b-3's arming is gated on Rick's yes.** 2b-1/2b-2 do NOT cross the redline → proceed regardless. Three conditions make the narrowing safe:
1. **Structural enforcement, not convention — a STANDING redline test.** The original verification ("no `reap|kill|dismiss|spawn|terminate|replace` in the arbiter loop; only `os.kill(pid,0)` liveness") becomes a PERMANENT test asserting the arbiter module contains/calls no destructive primitive. Re-run at every 2b gate so a future edit can't silently re-cross.
2. **Anti-storm (FM-20) — the ≤N cap PERSISTS across ticks**, per stall-episode, not per poll. A persistently-stuck session gets ≤N pokes TOTAL → ONE escalate-reap-recommendation → silence; never a per-tick re-poke. Test: many ticks over a stuck session → ≤N pokes + 1 escalation, no storm.
3. **Escalation is a recommendation to a HUMAN/manager** (Part 6: Rick + active managers) — the arbiter emits the non-destructive escalation and STOPS; reap/replace stay human/manager. The arbiter never executes a reap.

### Cross-phase HARD GATE — calibration precedes BOTH push and poke
