# Stop-hook poke-abstract receipts enrichment

**Date:** 2026-06-10 · **Author:** Tiffany 💍 (for Tiberius 👑, Rick-directed) · **Status:** held (worktree `wt-poke-abstract`, off HEAD `7500079`)

## Problem

When a worker hits **Stop** with work owed, the §4 breadcrumb fires a low-pri card
notify whose **abstract** said only the generic line:

> `Heartbeat: stopped with work owed — self-poke fired.`

Rick wants the abstract to carry the **receipts**: (a) WHAT work is owed — the
oracle's fired signals with their **actual referents**, and (b) the **verbatim
poke text** injected into the worker. The spoken `message` stays short (TTS
rule); all detail rides the abstract (card-only, never spoken).

A known cosmetic (Mr. Radio filed): the breadcrumb counted only Task items, so a
**delegation-only** poke (0 Task items, ≥1 live worker) mis-read as the
zero-count *"work owed (self-declared)"* wording.

## Design

Two pure helpers + a degrade-safe wrapper, composed in the existing
`_run_heartbeat` poke branch. **The oracle (`heartbeat_work_owed.py`) is
untouched and stays pure** (no IO added).

1. **`heartbeat_task_state.replay_task_subjects(transcript_path)`** *(new, pure)*
   — `{ taskId: subject }` by the SAME sequential-ordinal model as
   `replay_task_state`, so ids align 1:1. Lets the breadcrumb name owed Task
   items by subject **without changing `replay_task_state`'s shape** (and thus
   without touching its consumers or the oracle). Never raises.

2. **`stop._compose_poke_abstract(verdict, owed_task_subjects, delegations, open_inbound, poke_text)`** *(new, pure)*
   — builds the receipts abstract:
   - `Signals (strongest first): …` (the oracle's fired signal list)
   - `Owed Task items:` — bulleted subjects
   - `Outstanding delegations (live workers):` — bulleted session names
   - `Unanswered inbound questions:` — `from <sender> (qid <short>)`
   - `Poke text injected into the worker:` — the verbatim reason
   - Per-list cap **8 items** → `…+N more`; whole abstract capped **~4 KB**.

3. **`stop._build_poke_abstract_safe(...)`** *(new, degrade-safe shell)* —
   resolves owed Task* subjects (replays subjects ONLY when ≥1 owed task; missing
   subject → `task <id>` fallback) and composes. **ANY failure ⇒ `None`** → the
   breadcrumb falls back to the generic line. **Never raises** (the never-block-Stop
   invariant).

### Cosmetic fix

`_poke_sentence` now counts the **total owed referents** across all signals
(`len(owed_items) + len(delegations) + len(open_inbound)`) and reads
`"N owed item(s)"` (generalized from `"Task item"`); `"work owed
(self-declared)"` remains only for the genuine hold-declared, zero-referent case.

### Supporting change

`_gather_unanswered_inbound_questions` now also returns `sender`
(`sender_session_id`) per entry — for the inbound receipt. It never affects the
oracle verdict (only list length matters there).

## Degrade-safe invariant (above all)

Every new path is failure-isolated: the subject replay never raises, the compose
is wrapped, and `_announce_poke`'s existing try/except still guards the notify.
Worst case = today's generic line. The poke itself is never blocked or broken.
