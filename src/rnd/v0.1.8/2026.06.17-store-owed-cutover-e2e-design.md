## 1. Why this test exists (the gap)

The store-canonical cutover (2026-06-17) flipped `heartbeat.owed_source_from_store=True` so the
Stop-hook owed-work oracle reads the **unified task store**, not transcript replay. But **every
existing proof MOCKS the seam**:

| Existing test | What it mocks (the gap) |
|---|---|
| `test_stop_hook_heartbeat.py` | patches `replay_task_state`; flag hardcoded `False` |
| `test_task_store_client.py::query_owed` | patches `urllib.request.urlopen` (no real HTTP/SQL) |
| `test_tasks_router.py` (count_only) | `TaskRepository` is a `MagicMock`; no real Postgres |
| `test_task_store_drain.py` (parity) | `_query`/`_create` patched; parity proven vs canned results |
| `test_task_store_integration.py` | real server+DB, but **no `count_only`, no owed-source disagreement** |

The "parity 4/4" at cutover was a manual `drain --apply` run. **Nothing proves which source was
actually read** end-to-end through real HTTP → router → repo → SQL `COUNT(*)`.

## 2. The empirical doctrine (Rick): a test that AGREES proves nothing

We **engineer a disagreement** between the two candidate sources so the test can only pass if the
RIGHT source was read. If store and transcript agreed, a green test would be silent about which one
the oracle consulted.

## 3. Seam under test (kept 100% real — NO mocks)

```
stop._run_heartbeat( flag=owed_source_from_store )
  └─ if flag: _owed_count_from_store(session)
        └─ query_owed()                    ← real stdlib urllib (real socket)
             └─ GET /api/tasks?owner_persona=&status=&count_only=true   ← real HTTP
                  └─ routers/tasks.py count_only branch                  ← real router
                       └─ TaskRepository.count_tasks()                   ← real repo
                            └─ SELECT COUNT(task_items.id) WHERE …       ← real SQL on lupin_db_test
  └─ else: owed_items_from_state( replay_task_state(transcript) )        ← real transcript replay
```

`query_owed` sums `count_only=true` COUNTs across `STORE_OWED_STATUSES = (queued, in_progress)` —
a **true `COUNT(*)`** (cannot saturate at the page `limit`).

## 4. Harness (Option A — self-contained, venue-portable)

The seam's `urllib` needs a **real bound socket** → a real server bound to `lupin_db_test`.
The running `:7999` dev server is bound to `lupin_db_DEV`, so it cannot back a `lupin_db_test`
test. We therefore **own the server lifecycle**:

- `swap_database("testing")` → module engine binds `lupin_db_test`.
- A **minimal FastAPI app** mounting ONLY `routers/tasks.py`, run by `uvicorn` in a background
  thread on an **ephemeral port** (full Lupin app is GPU-heavy at import — avoided).
- Auth (`require_api_key_or_jwt`) is **dependency-overridden** to accept — auth is NOT the seam
  under test; the `X-API-Key` still flows over real HTTP, only its *validation* is bypassed.
- Rows seeded via the **real repo** (`create_item` → real INSERT/commit) into `lupin_db_test`.
- Transcripts are **real JSONL files** on disk (`TaskCreate`/`TaskUpdate` blocks the real
  `transcript_reader` parses).

### Controlled INPUTS vs the SEAM
Monkeypatched (session-identity glue + config — INPUTS to the seam, not the seam): `get_voice_persona`,
`resolve_project_name`, `load_heartbeat_settings` (the flag), `load_task_store_settings` (the URL).
Neutralized (non-seam side-effects): poke-cap FS writes, `emit_outcome`, tmux inject, `_announce_poke`,
genuine-idle beacon, and the two LOCAL owed signals (`_gather_outstanding_delegations`,
`_gather_unanswered_inbound_questions` → empty, so the verdict reflects ONLY the owed-items source).

### Assertion target (drive level)
Drive the **full `_run_heartbeat`** and read the `heartbeat_oracle` log line it emits every Stop
(`owed_items` count + `work_owed`) — the authoritative oracle readout. The flag-branch,
`_synthesize_owed_items`, and `evaluate_work_owed` all run real.

### Receipts
- **HTTP**: a server-side middleware records every inbound request's `(method, path, query)` —
  proves `count_only=true` + the `owner_persona`/`status`/`project` filters AS RECEIVED.
- **SQL**: a SQLAlchemy `before_cursor_execute` listener captures each `COUNT` statement + params.
- Per-scenario table: flag · project · persona · store-seeded · transcript-owed · expected · actual ·
  work_owed · PASS/FAIL.
