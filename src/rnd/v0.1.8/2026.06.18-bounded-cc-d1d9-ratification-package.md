### D6 — Output-parser fallback strategy

**Question:** "Bounded CC returns a single completion string (minor formatting variance possible) — strict, lenient, or hybrid parsing?"

| Option | Pros | Cons |
|---|---|---|
| **A — Strict, fail-loud [RECOMMENDED: Presentation, Deep Research]** | Catches drift early before downstream consumers; forces consistent prompt-engineering. | Brittle — one stray newline can fail a job; bounded CC has no native structured-output enforcement. |
| **B — Lenient, best-effort [RECOMMENDED: Podcast]** | Resilient to drift; users get a result not an error. | Bugs hide in "almost-correct" output; harder to debug silent degradation. |
| **C — Hybrid: strict happy-path + retry-with-stricter-prompt on failure** | Best of both; self-healing under transient variance. | More effort; retry doubles latency on failure; can mask slow drift. |

**Flip-condition:** Strict → lenient/hybrid if observed variance > ~5% of runs (fail-loud becomes user-hostile).
**Recommendation:** **Per-migration** — Podcast = B (TTS is tolerant); Presentation = A (pptx assembly is fragile); Deep Research = A initially, escalate to C if variance > 5%.

## 2.3 **D-DR1 — the invocation-surface sub-decision (new, must answer before coding)**

The cost-model doc and the BFE/TFE reference disagree on HOW bounded CC is invoked. Deep Research must pick one:

| Option | What it is | Pros | Cons |

## 2.4 D-DR2 — the `max_turns` cap

Deep Research is currently effectively unbounded; bounded CC **requires** an explicit cap. Add INI key `deep research max research turns` (+ splainer entry per the config mandate), default **20**, tune from observation. Submit-route bound is 1–500 (`claude_code_queue.py:46`). Define the **cap-hit failure UX**: if the cap is reached before synthesis, return a clearly-marked partial result ("research truncated at N turns") rather than silently presenting incomplete findings (risk #2 in the source register, HIGH impact).

## 2.5 `scheduled_at` post-midnight default (D2 applied)

Non-interactive DR runs (scheduled sweeps, batch) default `scheduled_at` to the next post-midnight slot (12 AM–9 AM EDT optimal window). User-clicked synchronous research **omits** `scheduled_at` and fires immediately. The field is already first-class on the submission request.
