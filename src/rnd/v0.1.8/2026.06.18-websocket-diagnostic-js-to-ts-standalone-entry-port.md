## 3. APPROVED port-time bug-fix — composed connect handlers

**Latent bug in the legacy** (`createMonitoredWebSocket`): it installed metrics
handlers on `websocket.onopen`/`onerror` (lines 157–181), then **reassigned**
`onopen = resolve` / `onerror = reject` (lines 194–195) for the connect-promise.
The last assignment wins, so the metrics `onopen`/`onerror` were **dead** —
`activeConnections` never incremented, "✅ WebSocket connected" never logged.

**Why a fix was required** (not optional): faithfully preserving the dead handlers
would ship uncoverable code, making the mandated `c8 --100` impossible *honestly*
(pragma-ing them would abuse the pragma discipline — pragma is for unreachable
*defensive* code, not reachable-killed-by-a-bug). Mr. Radio APPROVED the fix
(2026-06-18, dev-only tool, low blast radius).

**The fix**: the handlers are **composed** — one `onopen` does its metrics work
AND resolves; one `onerror` logs AND rejects — gated by a one-shot `settled` latch.
This preserves the **exact** connect-promise contract (resolve-on-open /
reject-on-error / reject-on-timeout) while reviving the previously-dead metrics.
Documented at the fix site (inline comment), in the module header, and in the
commit message. **This is an approved intentional deviation, not a parity regression.**

Also preserved verbatim (out of scope): the pre-existing hardcoded dev bearer
token in `sendTTSRequest`.
