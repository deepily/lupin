## 1. The Bug

A Claude Code session whose cwd is a **git worktree** (e.g. `/tmp/wt-delegation-signal`)
mis-detects its project as the **worktree directory basename** instead of the real
registered project (`lupin`).

`detect_project()` walks up from cwd to the first ancestor containing a `.git` entry
and returns that directory's basename:

```python
for candidate in [ cwd, *cwd.parents ]:
    if ( candidate / ".git" ).exists():
        name = candidate.name.lower()
        return _PROJECT_ALIASES.get( name, name )
```

`( candidate / ".git" ).exists()` is `True` for BOTH a normal repo (`.git` is a
**directory**) AND a worktree (`.git` is a **file** — a "gitlink" pointing at the main
repo). For a worktree the walk-up stops at the worktree root and returns its basename
(`wt-delegation-signal`), never reaching the real project identity.

### Downstream blast radius

The MCP server (`src/lupin_mcp/cosa_voice_mcp.py`) feeds this into
`_validate_repo_account( project )`, which looks up `~/.lupin/config` for a
`[wt-delegation-signal]` section, finds none, and fires a recurring **URGENT** TTS
notification: `No credentials for project 'wt-delegation-signal'`. Because worktree
crews are now the norm for every parallel build, this spam fires on every worktree
session. Diagnosed 2026-06-09 (TODO.md 🌙 LATE block, item 1).

## 2. Why a Worktree Looks Like a Submodule (but must resolve differently)

Both worktrees and submodules store `.git` as a **file** (gitlink) rather than a
directory. They are distinguished by where the gitlink points:

| cwd kind      | `.git` form | gitlink target                         | desired project |
|---------------|-------------|----------------------------------------|-----------------|
| normal repo   | directory   | (n/a)                                  | dir basename    |
| **worktree**  | file        | `<main>/.git/worktrees/<name>`         | **MAIN repo basename** |
| submodule     | file        | `<main>/.git/modules/<name>`           | submodule basename (unchanged) |
| non-git       | absent      | (n/a)                                  | cwd basename (fallback) |

The existing behavior for submodules (return the inner name, e.g. `cosa`) MUST be
preserved — only the worktree case is wrong.

---

## 3. The Fix — `git rev-parse --git-common-dir`

When (and only when) the resolved `.git` entry is a **file**, ask git for the
**common** git directory. Git reports the shared main-repo `.git` for a worktree, and
the per-submodule `.git/modules/<name>` for a submodule — which lets us tell them apart
by the basename of the reported common dir:

```
worktree   → git rev-parse --git-common-dir → <main>/.git        (basename == ".git")
submodule  → git rev-parse --git-common-dir → <main>/.git/modules/<name>  (basename != ".git")
normal     → (.git is a DIRECTORY → fast path, git never invoked)
```

### Empirically confirmed (2026-06-10, real `git worktree add`)

```
$ cat /tmp/wt-probe-link/.git
gitdir: /tmp/wt-probe-main/.git/worktrees/wt-probe-link
$ cd /tmp/wt-probe-link && git rev-parse --git-common-dir
/tmp/wt-probe-main/.git                    # basename ".git" → main root = /tmp/wt-probe-main
$ # dir with a fake empty .git parent:
$ git rev-parse --git-common-dir ; echo rc=$?
fatal: not a git repository ...           # rc=128 → fall back to existing behavior
```

### Algorithm (additive — fast path unchanged)

```
for candidate in [ cwd, *cwd.parents ]:
    git_entry = candidate / ".git"
    if git_entry.exists():
        if git_entry.is_file():                       # gitlink (worktree OR submodule)
            owner = _worktree_owner_basename( candidate )
            if owner is not None:                     # confirmed worktree → MAIN repo
                return alias( owner )
            # else: submodule / unresolvable → fall through to existing behavior
        return alias( candidate.name.lower() )        # normal repo OR submodule inner name
return alias( cwd.name.lower() )                       # non-git fallback
```

`_worktree_owner_basename( candidate )`:
1. `subprocess.run( ["git","rev-parse","--git-common-dir"], cwd=candidate, timeout=5 )`.
2. On any failure (`OSError`/`SubprocessError`/non-zero return/empty stdout) → return
   `None` (fail toward existing behavior — the ratified safety requirement).
3. Resolve the reported path (relative → absolute against `candidate`).
4. If its basename is **not** `.git` → submodule (`.git/modules/...`) → return `None`.
5. Else → worktree → return `common_dir.parent.name.lower()` (the MAIN repo basename).

### Design choices

- **Subprocess fires ONLY for gitlink files**, never for normal repos (`.git` dir →
  `is_file()` is `False`). The overwhelmingly-common case keeps a zero-subprocess path.
- **Authoritative**: delegates worktree/submodule disambiguation to git itself rather
  than re-implementing gitlink/`commondir` parsing across git versions.
- **Fail-safe**: every git failure path returns `None` → caller uses the pre-existing
  basename behavior. A worktree session degrades to the OLD (buggy-but-survivable)
  behavior rather than crashing if git is somehow unavailable.
- `_PROJECT_ALIASES` is applied to the resolved owner too (a worktree of
  `planning-is-prompting` still maps to `plan`).
