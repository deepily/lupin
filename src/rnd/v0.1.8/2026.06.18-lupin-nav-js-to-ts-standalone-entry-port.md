## 1. Summary

Ported the legacy `src/lupin_app/static/js/lupin-nav.js` (206-line self-contained IIFE
top nav bar, loaded by 16 pages) to a strict TypeScript module **and** established the
project's first **standalone (non-multiplexer) esbuild build pattern**. Behaviour-preserving;
100% c8 (lines/branches/funcs); additive and parallel-safe — the legacy `.js` stays the live
script until the `.ts` bundle is wired in and proven on the pages.

## 2. Why a new build entry was needed (architectural finding)

The TS toolchain was **multiplexer-bundle-only**:
- `tsconfig.json` `include` = `multiplexer/**/*.ts`; `rootDir`/`outDir` scoped to the mux tree.
- `build-multiplexer.sh` has a single esbuild entry `multiplexer/boot.ts` → `dist/multiplexer/boot.js`.

`lupin-nav.js` is a **global** module (loaded by 16 non-mux pages via a plain `<script>` tag),
so it cannot ride the mux bundle the way Rio's `SequentialAudioManager.ts` did (his port went
*in-bundle* under `multiplexer/audio/`, needing zero build change — only valid for mux-loaded
modules). A standalone module needs its own entry. Per Mr. Radio's Option-A guardrails this was
done **additively** — the mux `boot.ts` bundle and its single-entry config are untouched.

## 3. What landed (all additive)

| File | Role |
|---|---|
| `src/lupin_app/static/js/nav/lupinNav.ts` | The port. All logic; every side-effecting seam (storage / pathname / navigate) injected for deterministic testing. |
| `src/lupin_app/static/js/nav/boot.ts` | Composition root (esbuild entry) — binds seams to real `document`/`window`/`localStorage` + schedules the mount. No logic of its own. |
| `tsconfig.nav.json` | Standalone TS config — `extends ./tsconfig.json` (inherits strict opts), re-scopes `rootDir`/`outDir`/`include` to `nav/`. Does **not** touch `tsconfig.json`. |
| `src/scripts/build-nav.sh` | Standalone esbuild driver mirroring `build-multiplexer.sh` (minify + sourcemap + content-hash + manifest). New file. |
| `package.json` | Added `build:nav`, `build:nav:watch`, `typecheck:nav` script keys (additive). |
| `src/tests/unit/nav/lupin_nav_port.test.ts` | 23 unit cases (happy-dom, injected seams). |
| `src/tests/unit/nav/lupin_nav_boot.test.ts` | 1 case — composition-root coverage. |

`dist/nav/**` output is gitignored (matches the mux `dist/` convention) — not committed.

## 4. Behaviour parity + intentional type-driven cleanups

- Auth helpers, active-page detection, visibility filter, HTML render, logout + hamburger
  wiring, and DOM-ready scheduling all reproduce the IIFE's behaviour exactly.
- The legacy `ICONS[item.icon] || ""` defensive fallback was **dropped**: `IconName` is
  `keyof typeof ICONS`, so the lookup is provably non-undefined at compile time. Removing the
  dead `|| ""` keeps branch coverage honest (no unreachable branch) with identical runtime output.
- Seams are injected (not read from globals inside the logic) so every branch is reachable from
  tests — mirrors the multiplexer port convention.

## 6. Not done (deliberately — guardrail #2)

The 16 pages still load the **legacy** `lupin-nav.js`. Wiring them to the new
`dist/nav/lupin-nav.js` `<script type="module">` is a **follow-up** (post fresh-critical review),
keeping this slice behaviour-neutral and rollback-free.

## 7. Reusable pattern

`tsconfig.nav.json` + `build-nav.sh` are the template future non-mux standalone slices
(`websocket-diagnostic.js`, etc.) can copy — a self-contained `.ts` tree → its own `dist`
output, loadable by any page independent of the mux bundle.
