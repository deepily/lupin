**Why the persona drifts at all (the (c) nuance)**: `build_fleet_view` prefers
the BRIDGE persona, but a session whose bridge is gone/stale surfaces its
EVENT-sourced persona (`last_activity.persona` from the stop-hook heartbeat
events), which records the normalized lowercase form — same poll shows
bridge-sourced `Tiberius`/`Rio` beside event-sourced `mr radio`/`maria`. The
drift is structural across signal sources; exact-string comparison anywhere in
the role path is therefore wrong by construction.

**Also checked**: the `session_reaped` event (`_default_emit_reap`) POSTs to the
:7999 notification rail (UI focus-bar/badge wiring) only — the arbiter's
events-tail never sees a reap, so no existing durable signal can rebuild
lineage after a restart.

## 2. Design

Two arbiter-local fixes + one carried nit. **No shared spawn-infra edits**: a
manifest-tombstone alternative (keep reaped records flagged `reaped_at` instead
of dropping them) was considered and REJECTED — the manifest is load-bearing for
the spawn-cap name-collision set, `remaining`, and `list_spawned_sessions`;
changing its semantics has multi-consumer blast radius for a problem the
arbiter can solve locally. (Accepted residual edge, documented: a worker
spawned AND reaped entirely while the arbiter is down never enters the carry —
nothing observed, nothing carried.)

### F-A (leads a+b) — file-backed lineage carry

Persist `self._manager_lineage` so the carry survives restarts exactly like the
outreach pending-ledger survives them:

- **NEW** `src/cosa/agents/heartbeat_arbiter/lineage_carry.py` — `read_carry(path) -> dict`
  / `write_carry(path, mapping)`; degrade-safe reads (any error ⇒ `{}`), atomic
  tmp-write+rename, non-string values skipped. Mirrors `outreach_ledger`'s
  idioms line-for-line (same file family, same `io/arbiter/` home).
- `ArbiterConsumerJob` gains `lineage_carry_path=None` (None ⇒ today's volatile
  behavior — in-pool/test default unchanged): at construction, seed
  `self._manager_lineage` from the file; in `_publish_fleet_snapshot`, after
  `carry_forward_lineage` returns the pruned mapping, **write-on-change** (skip
  the write when the mapping is unchanged — one tiny write only when lineage
  actually moves). A write failure journals `lineage_carry_error` (the §1.5
  no-silent-drops doctrine) and never breaks the poll.
- Pruning semantics are UNCHANGED and now persistent: `carry_forward_lineage`
  already prunes to the current full-snapshot sids, so the file tracks exactly
  the decay-window population — it cannot grow unbounded, and a row that
  evicts from the snapshot evicts from the file on the same poll.
- INI: `arbiter lineage carry path = /io/arbiter/lineage-carry.json` (+ splainer),
  threaded `app.assemble_app → build_fleet_arbiter_job_factory → constructor`
  via `cu.get_project_root()` + relative value (PATH MANAGEMENT), exactly like
  the pending ledger.

### F-B (lead c) — punct/case-tolerant declared matching, ONE normalizer

Reuse the allocation/DM path's own primitive — `_normalize_for_match` from
`lupin_mcp.commons_persona_matcher` ("Mr. Radio" / "mr radio" / "MR.RADIO" →
"mrradio"; `re.UNICODE`) — as the single owner of persona-string equivalence
(one-name rule: no second normalizer, no inline regex copies). `lupin_mcp` is
already an established import for this layer (`manager_resolver` imports
`session_spawner`). Applied at every declared-roster compare:

1. `fleet_render.build_snapshot` — `declared_lower` set + `is_declared` check
   (the role badge + the F2 staleness tier's `role == "manager"` gate both
   derive from this).
2. `manager_resolver.resolve_active_managers` — the declared set (line 249) and
   the live-bridge persona check (line 272), so a declared manager whose bridge
   persona drifts in punctuation still fans out.
3. `manager_resolver.pick_declared_managers_from_env` — the case-insensitive
   dedup key becomes normalize-keyed ("Mr. Radio, mr radio" declares ONE
   manager). Emitted names stay verbatim (display surfaces keep the
   user's casing — normalization is for COMPARISON only, never display).
