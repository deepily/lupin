## 1. The Motivating Case Study — 2026-06-10 Silent Stall (forensics by Rick + Tiberius, 2026-06-11 AM)

From `journalctl --user -u lupin-arbiter-app` (journal times UTC; shown here converted to EDT):

| Window (EDT) | What happened | What the arbiter did |
|---|---|---|
| 10:45–11:03 | Manager session (Tiberius `4f7a7ab8`) quiet #1 — verdict decayed to **stale 27m** | Rendered the verdict. Nothing else. |
| 13:58–14:43 | Manager quiet #2 — **stale 34m** (Rick's "45 minutes" episode) | Rendered the verdict. Nothing else. |
| 15:58 onward | Manager quiet #3 — stale 30m+ by 16:28 | Rendered the verdict. Nothing else. |
| 16:30–17:05 | Entire fleet roster decayed **4 → 3 → 2 → 1 → 0** (each session crossing the 1h offline-prune) | Rendered each shrink, then ticked **"no changes · 0 session(s)"** happily for **6+ hours** |

In the **entire day's journal** exactly three event types appear: `health_obs`, `context_pressure_written`, `fleet_arbiter_render`. **Zero** poke events, **zero** escalation events, **zero** advisories to Rick. The fleet died in slow motion in front of a healthy, 100%-covered, all-tests-green observer that is *specifically chartered* to notice this.

### Root causes (verified in source, 2026-06-11)

**RC-1 — Calibration gap.** `_pokeable_sessions` (`src/cosa/agents/heartbeat_arbiter/arbiter_job.py:996-1016`) requires `alive is True AND stuck is True`. "Stuck" = repeated `cap_reached` + owed work. A stale-but-idle **manager** (the renders showed `state=working`, `holding=none`, `stuck=False`, verdict `stale 34m`) is **never pokeable** — María's quiet≠stall doctrine, which correctly protects heads-down workers, also makes the exact scenario Rick cares about (manager dark 45m+) structurally unreachable by any poke or advisory. Compounding gates:
- The D3 fleet-stall detector (`_check_fleet_stall`, `:945`) requires **live owed work** (`_has_live_owed_work`, `:916`); its own docstring states a dead/empty roster can **never** stall-escalate. Full-fleet death = silence **by design**.
- The D4 manager-down detector (`_check_manager_acks`, `:792`) only arms **after a tap**, and taps require attention-needing workers (`_attention_workers`). No stuck workers → no tap → D4 never armed. The detector chain embeds an unstated assumption: *"a dark manager only matters if workers are stuck."* 2026-06-10 falsified it.

**RC-2 — Observability gap.** `_auto_poke` (`:1084`) calls `self._commons.send_to(...)` with **no log event on fire** and **no log event on gate evaluation**. `pokes_fired` lands in the `_poll_once` summary dict (`:414-426`) which is **returned and discarded** — it never reaches the journal. When the arbiter is silent, there is no way to distinguish "evaluated and correctly declined" from "never evaluated" from "fired and delivery failed."

## 2. Deliverable (a) — Test-Thoroughness Audit

### 2.1 What the suite contains

Audited: `src/tests/unit/test_arbiter_auto_poke.py`, `test_arbiter_escalation.py`, `test_lupin_arbiter_app_fleet_arbiter_loop.py`, `test_lupin_arbiter_app_app.py`, plus the sibling arbiter unit files (`test_arbiter_manager_tap.py`, `test_arbiter_redline.py`, `test_heartbeat_arbiter_job.py`, …). The suite is genuinely strong **at the contract level**: anti-storm episode caps, calibration receipts (dead-roster suppression), redline (AST-level no-actuation), routing-table cell-for-cell checks, Krishna anchors. Coverage is a real 100% line+branch.

### 2.2 Does any test encode the operational requirement?

**No.** Worse than absent — the suite **actively ratifies the failure**. `test_arbiter_auto_poke.py::test_stall_not_quiet_these_are_never_poked` parametrizes:

```python
( _view( "s", state="working", stuck=False, alive=True ), "busy/working alive" ),
```

and asserts **zero pokes across 5 polls spanning any threshold**. The 2026-06-10 manager (`state=working, stuck=False, alive=True`, stale 34m) is *literally this parametrized case*. The observed silence wasn't an untested path — it was a **tested-and-asserted-correct** path whose requirement-level calibration was wrong. Every test in the suite asks "does the code do what the code intends?"; none asks "does the system do what the operator needs?"

### 2.3 The missing class, named precisely

**Operational-requirement acceptance tests (scenario tier)** — tests whose *given* is an operator-level situation (a realistic fleet timeline) and whose *then* is an operator-observable outcome (a DM fired, a Rick advisory landed, a journal event exists), driven through the **composed** poll path (`_poll_once`), not a single detector's branch.

The structural lesson (generalizes beyond the arbiter): **coverage measures code reachability, not requirement reachability.** A requirement with no implementing code contributes zero uncovered lines — 100% line/branch is *vacuously* satisfiable against it. Contract-level unit tests inherit the implementation's blind spots because they are derived from the implementation's predicates ("stuck", "owed work") rather than from the operator's predicates ("my manager has been dark for 45 minutes"). When a calibration assumption is wrong, contract tests *enshrine* the wrong calibration. Only tests written from the requirement side — before/independently of the predicate vocabulary — can catch a predicate that is mis-scoped.

A second, smaller absent class: **observability invariants** — no test anywhere asserts that an outbound communication produces a journal event, because no such logging exists. "Silence is diagnosable" was never stated as a testable property.

## 3. Deliverable (b) — Fix Design

Three additive features. No existing detector's behavior changes; the published `/state` snapshot contract is unchanged. All new outbound text destined for Rick formats timestamps in **EDT** (`America/New_York`), labeled.

### 3.1 F1 — Outreach logging (RC-2; Rick's verbatim ask)

New injectable seam on `ArbiterConsumerJob`: `log_fn( event, **fields )` (default: module-level JSON-line printer mirroring the app's `_default_log_fn` shape; `build_fleet_arbiter_job_factory` injects the app's `log_fn` so events land in journald with `service`/`loop` fields).

**Events:**

1. **`arbiter_outreach`** — emitted at EVERY outbound communication, no exceptions. Fields: `{ kind: stuck_poke|ping|tap|reap_rec|deadlock|manager_down|decision|decision_cc|stall|manager_stale_poke|manager_stale_advisory|fleet_dark|orphan_worker|poll_error_escalation, case, tier, via, recipients: [...], session_id?, persona?, summary: <first 160 chars> }`. (Implementation note: the stuck-tier kind is `stuck_poke`, never the bare four-letter literal — the poked-rename one-name sweep, `test_poked_rename_consistency.py`, bans quoted bare-poke literals on production surfaces.) Implemented **centrally in `_route`** (covers cases 4/5/7/8/9/10/11/13 + new 14/15) plus the three direct `send_to` sites (`_auto_poke`'s wake-nudge, `_blocker_manager_cc` cc, `_cc_decision_manager` cc) and the F2 staleness poke.

2. **`arbiter_poke_gate`** — gate-evaluation visibility ("why-not-poked"). Each poll, compute per-session gate vector: `{ session_id, persona, role, pokeable: bool, why_not: subset of [disabled, not_alive, not_stuck, below_threshold, capped, already_escalated], stuck_since?, poke_count? }`. Emit **on change** of a session's vector (including appearance/disappearance), plus a **periodic full dump every 60 polls** (hourly at the 60s default) so a long silence is still self-explaining. Same event covers the F2 manager-staleness gate (`why_not` gains `not_manager`, `not_stale`).

3. **`arbiter_poll_activity`** — the `_poll_once` summary dict, promoted to a journal line **whenever any outreach counter is nonzero** (pings/taps/pokes/managers_down/decisions/stalled/staleness/dark). Zero-activity polls stay un-logged (the render tick already proves liveness) — no journal spam.

### 3.2 F2 — Manager-staleness poke tier (RC-1)

A **second, role-gated pokeable criterion** — additive to, never replacing, the stuck-tier. Workers are untouched (quiet≠stall preserved); the gate is `role == "manager"`.

- **Config**: new INI key `arbiter manager stale poke threshold seconds = 2700` (45 min; `0` disables the tier), in `[Lupin: Baseline]` + splainer entry, threaded `assemble_app` → `build_fleet_arbiter_job_factory` → constructor param `manager_stale_poke_threshold_seconds` (validated ≥ 0).
- **Signal**: `liveness.freshest_age_s` from the snapshot row — the min over the Round-1 union (bridge ∪ stop-event ∪ commons ∪ idle_prompt). This is exactly the age behind the `stale 34m` verdicts in the forensics, so the threshold means what Rick means by "dark 45 minutes."
- **Role source**: snapshot `role` (manager-manifest via `list_managers_fn`, prefix-tolerant — already wired in `build_snapshot`).
- **Detection input**: `_publish_fleet_snapshot` builds the snapshot with `include_offline=True` for **internal detection**, then derives the published view through a new pure `fleet_render.prune_offline_rows( snapshot )` helper (recount included) — published bytes, frame signature, and render are **bit-identical to today**. Detection sees offline managers; consumers don't (D6/§5.2 intact). The full snapshot is handed to the new detectors in `_poll_once`.
- **Detector** `_check_manager_staleness( full_snapshot, now, active_managers )`, run each poll:
  - Eligible: rows with `role == "manager"` AND `freshest_age_s >= threshold` (an offline-verdict manager remains eligible — offline is *maximal* staleness, not an exit).
  - **Episode machinery mirrors `_auto_poke`** (per-persona `_mgr_stale_since` / `_mgr_poke_count` / `_mgr_escalated`; clear-on-recovery when freshness returns below threshold → cap re-arms): bounded pokes (`poke_max_per_episode` reused, no new knob), direct `send_to( manager_persona, nudge )`.
  - **Rick advisory fires on the FIRST threshold crossing, same poll as poke #1** — case 14, `TIER_RICK_AND_MANAGERS` — NOT after poke exhaustion. Yesterday's lesson: the pokes are best-effort (a dark manager may have no self-wake); the advisory to Rick is the load-bearing output. Once per episode. Body: `"MANAGER-STALE: {persona} silent {Nm} (last signal HH:MM EDT, threshold 45m) — poking (bounded); no action taken beyond outreach."`
  - Composition with existing detectors is clean: D4 = manager **gone after a tap**; D3-stall = manager **present-but-not-acting on owed work**; **F2 = manager dark regardless of worker state** — the case both existing detectors structurally excluded.

### 3.2.1 F2 amendment — the corpse ceiling (same-day calibration fix, 2026-06-11 PM)

**The bug the deploy exposed (10:52 EDT, within ONE minute of the first boot)**: the tier poked **yesterday's dead Tiberius session `4f7a7ab8`** ("silent 1134m") and advised Rick — a CORPSE row resurfaced by the `include_offline=True` detection snapshot (43 scanned rows vs 13 live roster) matched `role == "manager"` + `age >= threshold`. Bounded (≤3 pokes + 1 advisory per corpse sid per process) but wrong, and **re-bursting on every :8001 restart** (episode state is in-memory; multiple Tiberius corpses exist on disk). Spec ratified via Tiberius's review-thread DM (14:54 UTC).

**The fix** (built by Cheech 🌿 successor session `66f07d5f`, held commit `c87eccf2` on `cheech/arbiter-corpse-ceiling-2026.06.11`, based on `c2156762`):

1. **Staleness CEILING** — eligible iff `threshold <= freshest_age_s <= max_age`. New INI key `arbiter manager stale poke max age seconds = 7200` (+ splainer), threaded `app.py → build_fleet_arbiter_job_factory → constructor`. An empty `[threshold, max_age]` window (ceiling ≤ threshold while the tier is enabled) raises `ValueError` at construction — same config-dead fail-fast class as the `quiet < alive` invariant. Rationale: **F2 means "this manager went dark RECENTLY", not "a corpse exists".**
2. **None-age FLIP** — `freshest_age_s` None = no signal EVER = corpse/malformed row → **NOT eligible** (was: "None = maximally stale = eligible" — §3.2's original choice, which §3.2.1 retires by decision). Documented in `_check_manager_staleness`'s docstring; the old `test_offline_manager_age_none_stays_eligible` is replaced by `test_corpse_manager_age_none_not_eligible`, called out as a deliberate assertion flip.
3. **Gate vocabulary** — `stale_why_not` gains `no_signal` (None age) + `beyond_max_age` (past the ceiling), so the journal explains every corpse silence.
4. **S6 scenario** (`test_arbiter_scenarios.py`) — boot over a ≥20h corpse manager row → ZERO staleness pokes/advisories, while a 50-min-dark LIVE manager in the same snapshot still fires; the corpse's gate vector reads `beyond_max_age`. Unit tier adds: inclusive ceiling boundary (7200 fires / 7201 doesn't), the 1134m corpse pin, mid-episode aging-past-ceiling clears the episode, empty-window raise, max-age-irrelevant-when-disabled.

### 3.3 F3 — Empty-roster / full-fleet-dark advisory (RC-1, decay-to-zero arm)

- Track across polls (state on the job): last nonzero published roster count + the most-recently-seen manager `(persona, last_signal_at)` harvested from the full snapshot.
- On the transition **count > 0 → count == 0**, fire **once** (case 15, `TIER_RICK_ONLY` — by definition no managers remain to fan to): `"FLEET-DARK: roster decayed {N}→0; last manager signal {persona} at HH:MM EDT. The arbiter keeps watching; this fires once per dark episode."`
- Re-arm when the roster repopulates (count > 0). Bounded by construction: one advisory per dark episode. The 6-hour "no changes · 0 session(s)" tick-parade becomes one loud line + a diagnosable journal.

**Restart-while-dark (Tiberius review NIT-1, resolved 2026-06-11)**: a pure edge trigger loses its state on a service restart — the arbiter would boot into `count == 0` with no `>0 → 0` edge and go silent again. Persisting the edge in the :8001-local store does **not** fix this (`LocalSnapshotStore` is in-memory; it dies with the process). Resolution: **hybrid trigger**.

- *Primary (edge)*: the `>0 → 0` transition, as above.
- *Recovery (state, evaluated only while no edge has been seen this process — i.e. after a boot/recycle straight into an empty roster)*: fire iff published `count == 0` AND the FULL snapshot contains ≥1 session whose `freshest_age_s ≤ DARK_LOOKBACK_SECONDS` (constant, `7200` = 2h). "The fleet *just* died" leaves recent corpses; a cold morning boot over a roster reaped the previous evening has no signal younger than 2h → **no fire** (this is what prevents the page-Rick-every-morning failure mode Tiberius flagged). The 120s warm-up suppressor additionally guards boot-time noise.
- Both paths share the once-per-dark-episode flag (re-armed on `count > 0`), so a restart mid-dark re-fires **at most once per process** — bounded, and only when the darkness is fresh enough to still be actionable.

### 3.6 Acceptance criteria

1. Every outbound `send_to`/`notify_fn` from the arbiter produces exactly one `arbiter_outreach` journal event (S3 invariant test).
2. A `role=manager` session with `freshest_age_s ≥ 2700` receives a bounded poke AND Rick receives one advisory per episode, **even with zero stuck workers** (S1).
3. A `role=worker` session equally stale, not stuck, receives **nothing** from the staleness tier (S5 — quiet≠stall intact).
4. Roster decay to zero produces exactly one fleet-dark advisory naming the last manager seen, EDT-labeled (S2).
5. The S4 replay of the 2026-06-10 timeline is loud: ≥2 staleness escalations + 1 fleet-dark + gate events explaining every silent poll.
6. **100% lines AND branches AND functions** on all touched files (`pytest --cov --cov-fail-under=100`); redline AST test green; published `/state` snapshot byte-identical for the no-new-events case.
7. All existing arbiter tests pass unmodified EXCEPT where they assert the absence of the new behavior — those are updated deliberately and called out in review. **Named explicitly (Tiberius review NIT-2)**: `test_arbiter_auto_poke.py::test_stall_not_quiet_these_are_never_poked` — the test that ratified the failure — is **SPLIT**, not silently edited: (i) the worker-role cases (busy/working, declared-holding, idle, dead-but-stuck) keep their zero-poke assertions verbatim — quiet≠stall stands; (ii) a NEW manager-role companion case (`role=manager`, `state=working`, `stuck=False`, `alive=True`, stale ≥ threshold) asserts the OPPOSITE outcome via the staleness tier (poke + Rick advisory). The split is called out in the implementation review notes so the deliberate calibration flip is auditable — the old assertion is retired by decision, never by drift.
