# Expeditor Default Values — Design Document

**Date**: 2026-02-09
**Status**: IMPLEMENTED
**Session**: 157 (continuation of 156)

## Problem

When the RuntimeArgumentExpeditor asks users for missing arguments via `ask_open_ended_batch`, all text inputs start empty. Users must manually type default answers (like "no limit", "academic", "none") every time they launch a job, even though these values rarely change.

## Solution

Pre-populate batch question text inputs with sensible default values. Users can accept defaults by hitting Submit All, or modify any value before submitting.

## Data Flow

```
agent_registry.py          Config INI override        Frontend
fallback_defaults  ─────>  _resolve_default()  ─────> text input value=""
  (hardcoded)           (config > registry > None)     (pre-filled)
```

### Override Chain

1. **Config INI** (`lupin-app.ini`): `expeditor default value for <agent> <arg>` — highest priority
2. **Agent Registry** (`agent_registry.py`): `fallback_defaults` dict — hardcoded baseline
3. **None**: No default, text input starts empty (current behavior)

## Design Decisions

1. **Parallel `fallback_defaults` dict** — preserves backward compatibility, follows existing registry pattern
2. **`default_value` as optional key** — any caller of `ask_open_ended_batch` can provide defaults
3. **`value` attribute, not `placeholder`** — placeholder disappears on focus, defeating "hit Enter to accept"
4. **TTS ignores defaults** — pre-fills are visual-only, not spoken
5. **Config keys commented out by default** — active defaults come from registry; config is override mechanism
6. **Languages config keys enabled** — always generate English + Mexican Spanish podcasts per user preference
7. **ISO codes for defaults, full names in questions** — defaults use `en,es-MX` (what CLI consumes), questions mention both formats
