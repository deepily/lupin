## Context

### Why this change

`TestSuiteJob` emits a machine-readable remediation snapshot JSON
(`io/test-suite/{ts}-{suites}-remediation.json`, schema v1.0) on any test run
with failures. Per-failure records carry `classname`, `name`, `type`, `message`,
`traceback`, `suite`. Nothing consumes it today — TODO.md line 20 is the
explicit design gap.

BFE is code-complete through Phase 6 (58 unit tests passing, live E2E in
progress in a separate console — not blocked by this plan). BFE assumes **one
crashed job → one root cause → one fix → retry that job**. Test failures
violate that on every axis: cardinality (N failures, usually K≤5 clusters),
shape (flat traceback list vs single stack trace), validation semantics
(rerun tests vs retry job), and prompts (BFE hard-codes dead-job fields).

### The outcome

A new `TestFixExpediterJob` (`tfe-` prefix) handles test-shaped problems
natively: Phase 0 clustering, test-aware diagnose/propose, delegated Phase 3
fix (shared with BFE), shared Phase 5 trust/git, Phase 6 rerun validation. BFE
stays untouched on its proven dead-job path. A new
`TestSuiteCompletionWatchdog` dispatches TFE automatically when a
TestSuiteJob finishes with `summary.all_passed == false`.

### CoSA submodule rule (MUST FOLLOW)

Most files edited by this plan live inside `src/cosa/`, which is a separate
git repository. **From the Lupin parent context**: edit those files, but NEVER
run git there, NEVER investigate submodule state, NEVER propose cross-submodule
commit ordering, NEVER offer to commit CoSA. CoSA commit coordination is
explicitly out of scope.

Mandated voice/notification patterns TFE will honor:
- **Session topic**: `voice_io.set_session_topic()` called at phase entry
  (`"TFE Phase 0: Clustering"`, `"TFE Phase 1: Diagnose"`, etc.)
- **Breadcrumbs**: `notify(priority="low")` every 10+ seconds in long loops
  (per-cluster diagnose, per-fix execution). Breadcrumbs MUST fire in dry-run
  too — in dry-run they're the only visible output.
- **Voice gates**: `ask_yes_no()` / `ask_multiple_choice()` via voice_io
  wrapper, `priority="high"`, 5-minute timeout, explicit default answer.
- **Errors**: `notify(priority="urgent")` before raising, with error summary
  in abstract.
- **Completion**: `notify(priority="medium")` with result summary + duration.
- **Job-scoped routing**: every voice call includes `job_id=self.id_hash` for
  WebSocket routing to the job card.
- **Mock client**: `api_client.py` supports a mock mode for unit tests
  (returns canned responses matching real Anthropic API shape).
- **Dry-run mode**: `job.py` accepts `dry_run=True`; orchestrator emits
  breadcrumbs but makes zero real API calls, `cost_summary["total_usd"] == 0`.
- **Artifacts**: `self.artifacts` dict populated with
  `{remediation_snapshot_path, clusters, proposed_fixes, fix_results,
  validation_run_job_id, plan_path, cost_summary}`.
- **WebSocket**: do NOT emit WS events manually. `RunningFifoQueue` handles
  this via `emit_job_state_transition()` based on `self.status`.

## Architecture at a glance

```
TestSuiteJob completes → TestSuiteCompletionWatchdog
  └─ eligible? → TestFixExpediterJob (tfe-*)
       ├─ Phase 0: Cluster N failures → K clusters (heuristic seed + LLM refine)
       ├─ Phase 1: Diagnose per cluster (Opus, read-only SDK tools)
       ├─ [Aggregate voice gate: proceed to proposal?]
       ├─ Phase 2: Propose fixes (single plan doc, multi-select gate)
       ├─ [Aggregate voice gate: select subset of fixes to apply]
       ├─ Phase 3: Fix → shared FixExecutor (per selected cluster, serial)
       ├─ Phase 5: shared GitStrategist → one branch, N commits, one PR
       └─ Phase 6: async resubmit TestSuiteJob targeting affected suites
                    (metadata["triggered_by_tfe"]=<id> recursion guard)
```

## Voice gate default — elaboration

The `test fix expediter voice gate mode` key defaults to `aggregate`. What
that means in the UX, concretely:

### Aggregate mode (default) — 2 voice gates per run

After Phase 1 Diagnose completes (all K clusters analyzed):
```
ask_yes_no(
  f"Diagnosis complete. {K} clusters analyzed. Proceed to proposal phase?",
  default="yes", priority="high",
  abstract=<cluster summaries in markdown>
)
```

After Phase 2 Propose produces K proposed fixes:
```
ask_multiple_choice(
  questions=[{
    "question": f"Select fixes to apply ({K} proposals):",
    "header": "Fixes",
    "multiSelect": True,
    "options": [
      {"label": f"Cluster {i+1}: {fix.title}",
       "description": f"{fix.confidence:.0%} confidence, {fix.risk_level}"}
      for i, fix in enumerate(proposed_fixes)
    ]
  }],
  priority="high",
  abstract=<full plan doc link + per-cluster rationale>
)
```
User checks any subset (or all, or none). Total interactive gates per TFE
run: **2**.

### Per-cluster mode — 2K voice gates per run

Each cluster diagnosis fires its own `ask_yes_no()`. Each proposed fix fires
its own `ask_yes_no()`. With K=5 that's 10 interactive gates per run.

### Why aggregate is the default

Decision fatigue is real. Real-world batches cluster at K=3-8. The
multi-select UX already exists (`ask_multiple_choice` with `multiSelect=True`)
and lets users accept any subset cleanly. Aggregate matches the BFE UX (one
diagnosis gate + one proposal gate) and scales without user burden. The
config key provides an escape hatch for high-trust automation (set to
`none` — but that requires active-mode trust proxy) or single-cluster runs.

## Extraction design (FixExecutor + GitStrategist)

### `shared/fix_executor.py` public API

```python
class FixContext(BaseModel):
    user_email           : str
    root_cause           : str
    error_category       : str
    affected_components  : list[str]
    origin_label         : str   # "dead_job: dr-abc" or "test_cluster: C2"
    origin_details       : dict
    prompt_builder_key   : str   # "bfe" | "tfe"

    @classmethod
    def from_dead_job(cls, ctx: DeadJobContext, diagnosis: DiagnosisResult)
        -> "FixContext": ...

    @classmethod
    def from_test_cluster(cls, cluster: FailureCluster,
                          diagnosis: TestDiagnosisResult,
                          user_email: str) -> "FixContext": ...

class FixExecutor:
    def __init__(self, config, session_id, job_id, voice_io_module,
                 cosa_interface_module, cancel_check, on_notify,
                 debug=False, verbose=False): ...

    async def execute_fix(
        self,
        proposed_fix : ProposedFix,
        fix_context  : FixContext,
        plan_path    : str
    ) -> tuple[FixResult, list[str]]:   # (result, files_changed)
        ...
```

Polymorphic prompt registry (populated at import time):
```python
FIX_PROMPT_BUILDERS: dict[str, tuple[Callable, Callable, Callable]] = {}
# bfe/prompts/fix.py registers "bfe"
# tfe/prompts/fix.py registers "tfe"
```

### BFE shim (zero behavior change guarantee)

BFE `run_fix()` becomes ~20 lines: constructs a `FixContext.from_dead_job()`,
calls `self._fix_executor.execute_fix()`, returns. All existing BFE Phase 3
tests exercise the same codepath through the shim. **This is the riskiest
commit in the sequence.** Regression gate:
`pytest src/tests/unit/ -v --tb=no -q` totals must not degrade.

### `shared/git_strategist.py`

Exposes:
- `commit_and_pr_single(files, fix, plan_path, trust_level)` — BFE path
- `commit_and_pr_multi(files_by_cluster, cluster_titles, plan_path,
  trust_level)` — TFE path: one branch, one commit per cluster, one PR

BFE `run_git_strategy()` becomes a shim calling `commit_and_pr_single()`.

## TFE orchestrator phases

### Phase 0 — Cluster (heuristic + LLM)

- **Input**: parsed remediation snapshot via `snapshot_loader.py` (validates
  `schema_version == "1.0"`, strips PII, returns `TestRemediationContext`)
- **Heuristic seed** (`cluster.py::heuristic_seed()`): group by
  `(classname, first_non_pytest_traceback_frame)`. Handles ~80% of realworld
  cases cheaply, no LLM cost.
- **LLM refinement**: Opus with read-only SDK tools (`Read` only), sees
  snapshot + heuristic seeds, returns JSON with final cluster assignments.
  Capped at `max_clusters` (default 8).
- **Output**: `list[FailureCluster]` with `cluster_id, failure_indices,
  shared_error_signature, hypothesis, affected_files_guess, confidence`
- **Voice**: breadcrumb `notify("Clustering N failures...", priority="low")`.
  No gate — clusters are shown in the proposal gate.

### Phase 1 — Diagnose (per cluster, serial in MVP)

- **LLM**: Opus, read-only SDK tools (Grep, Read, Bash). Iteration pattern
  matches BFE: max iterations = 4 (config), min confidence = 0.65 (config).
- **Prompts** differ from BFE: must teach the agent to parse
  `classname::name[param]` into `src/tests/...py::ClassName::test_name[param]`,
  open test file first, trace test → tested module, recognize fixture vs
  assertion vs collection error modes.
- **Output**: `TestDiagnosisResult` per cluster (extends BFE
  `DiagnosisResult` with `cluster_id` and `test_symptoms: list[str]`)
- **Voice**: breadcrumb per cluster (`"Diagnosing cluster i of K..."`). One
  aggregate `ask_yes_no()` gate after all K complete (see voice gate section).
- **Future optimization**: parallel diagnose via `asyncio.gather()` with a
  semaphore. MVP is serial to keep SDK client lifecycle simple.

### Phase 2 — Propose (aggregated)

- **LLM**: Opus, read-only.
- **Output**: `list[ProposedFix]` (reuses BFE model with new `cluster_id`).
  One plan doc covering all K clusters with `## Cluster N: <title>` sections,
  written via shared `PlanWriter`. Path:
  `src/rnd/{date}-tfe-{suite_hash}-{short_slug}.md` (Lupin parent).
- **Voice gate**: one aggregate `ask_multiple_choice(multiSelect=True)` — see
  voice gate section.

### Phase 3 — Fix (delegated)

- Iterates selected fixes serially. For each:
  ```python
  fix_context = FixContext.from_test_cluster(cluster, diagnosis, user_email)
  result, files_changed = await self.fix_executor.execute_fix(
      proposed_fix=fix, fix_context=fix_context, plan_path=plan_path
  )
  ```
- **Continue-on-cluster-failure** (default `true`): cluster failures don't
  abort remaining clusters. Final outcome aggregates across clusters.
- **Final state**: `fixed` (all succeeded) | `partial` (some succeeded) |
  `failed` (none succeeded).

### Phase 5 — Trust + Git

- Reuses `shared/git_strategist.py::commit_and_pr_multi()`.
- **One branch, N commits (one per cluster), one PR** (confirmed strategy).
- Branch slug: `fix/YYYY-MM-DD-tfe-{suite_abbrev}-{K}-clusters`.
- Trust-level resolution reuses BFE's trust-proxy wiring via the shared
  module; `test fix expediter trust mode = inherit` (default) reads the
  global SWE proxy config.

### Phase 6 — Validate (async resubmit)

- Guard: only if `any(fix.success)`.
- Construct a new `TestSuiteJob` via `create_agentic_job(command="agent
  router go to test suite", args_dict={"test_types": ",".join(
  ctx.original_test_types), ...}, ...)`.
- **Recursion guard**: set `metadata["triggered_by_tfe"] = self.id_hash` on
  the validation TestSuiteJob. `TestSuiteCompletionWatchdog` honors this
  flag and refuses to re-trigger.
- TFE does NOT wait on the validation run. It completes with
  `artifacts["validation_run_job_id"]` for UI lineage. The follow-up
  TestSuiteJob is a peer job observable in the queue UI.
- **Default rerun scope** = `affected` suites (confirmed). Config key
  `test fix expediter rerun scope = affected | full` allows override.

## Watchdog routing

### Why a new watchdog is needed

TestSuiteJobs complete **successfully** when tests fail — the job returned
a result object, tests just weren't green. They land in the done queue, NOT
the dead queue. The existing `DeadQueueWatchdog` is the wrong hook.

### Implementation

`src/cosa/rest/test_suite_completion_watchdog.py` —
`TestSuiteCompletionWatchdog`, parallel to `DeadQueueWatchdog`. Called from
`running_fifo_queue.py` in the done-queue push path (~line 540).

Eligibility gates (all must pass):
1. `self.enabled` (INI `test fix expediter auto fix enabled`, default `false`)
2. `completed_job.JOB_TYPE == "test_suite"`
3. Remediation snapshot present, schema valid, `summary.all_passed == false`,
   `failures` non-empty
4. **Recursion guard**: `completed_job.metadata.get("triggered_by_tfe") is None`
5. `len(failures) <= max_cluster_seed_failures` (default 50 — beyond that,
   defer to human)
6. Reuse `RepairAttemptTracker` (cost/iteration/wall-clock) keyed by
   `(test_suite_job_id, sorted(suites))`
7. Not currently in circuit-breaker state

Dispatch: constructs `TestFixExpediterJob` and pushes to `jobs_todo_queue`
with the original user's identity.

Initialization in `main.py` alongside the existing `DeadQueueWatchdog` singleton.
