# Reuse review: podcast auto-play in the multiplexer and the legacy page

Twenty-two definitions are new in the podcast auto-play commit. Seven sit in the multiplexer render and shared modules, and fifteen sit in the wire file and the legacy page.
I read the source of the shortlisted candidates and the nearest definitions each search named. Most candidates are unrelated; the rest are listed with the reason.

The legacy page is plain JavaScript and loads no TypeScript module. The multiplexer module podcastLinks.ts already ports legacy functions, so the two clients keep parallel copies by precedent.
Each cross-client twin below is marked related for that reason. It is the same job in a runtime that cannot call the other copy.

Review found two misses, both fixed in the code. The helper playHereTitle now calls podcastUrlTitle from podcastLinks.ts and adds only the fallback.
The helper firstPlayHereLink now calls isEmbeddedAudioHref for the embed-flag test. The legacy twin keeps its own copy, because that page loads no TypeScript module.
The nested handler onMessage has no index entry in the reuse tools, so it has no receipt of its own. Its lines cite the receipt of the enclosing wire function.
