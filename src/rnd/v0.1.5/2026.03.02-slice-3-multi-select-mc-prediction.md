# Slice 3: Multi-Select (Inclusive) Multiple Choice Prediction

**Status**: IN-PROGRESS
**Date**: 2026-03-02
**Context**: Extending PredictionEngine to handle `multiSelect: true` from cosa-voice `ask_multiple_choice()`

---

## Problem

When multi-select responses (`{"answers": {"Header": ["A", "B"]}}`) flow through the current vote-tallying code, using a **list as a dict key** causes `TypeError: unhashable type: 'list'`. Additionally, `get_comparator()` always dispatches to `compare_multiple_choice_single` regardless of whether the data is multi-select.

## What Already Works

- `compare_multiple_choice_multi()` exists in `accuracy_comparators.py:114-170` (Jaccard similarity with 0.50 threshold)
- `_parse_mc_decision_value()` handles list values in answers (returns parsed JSON as-is)
- `_store_decision()` serializes dict answers via `json.dumps()`
- `PredictionResult._wrap_predicted_value()` passes dicts through unchanged

## Implementation Steps

1. **Add `_tally_multi_select_votes()`** — option frequency counting with >= 50% threshold
2. **Make vote loop type-aware** — detect `isinstance(option, list)`, branch to multi-select path
3. **Rename** `_predict_multiple_choice_single` → `_predict_multiple_choice`
4. **Update `get_comparator()`** — data-driven dispatch via optional `actual_value` param
5. **Update `record_outcome()`** — pass `actual_dict` to `get_comparator()`
6. **Unit tests** — ~10 new tests for multi-select vote logic + comparator dispatch
7. **E2E warm tests** — 2 new scenarios for multi-select prediction + accuracy
8. **Smoke test** — data-driven `get_comparator()` dispatch test
