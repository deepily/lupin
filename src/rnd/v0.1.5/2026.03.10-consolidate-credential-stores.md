# Plan: Consolidate Three Credential Stores into `~/.lupin/config`

## Context

Three separate INI files serve overlapping Lupin configuration needs:

| File | Purpose | Permissions |
|------|---------|-------------|
| `~/.lupin/credentials.ini` | CC hook auth (email/password) | `600` |
| `~/.notifications/config` | API config — CURRENT (api_url, api_key_file, recipient) | `664` |
| `~/.lupin/config` | API config — DEPRECATED fallback (same as above) | `664` |

The `~/.notifications/config` migration (Session 267) moved config OUT of `~/.lupin/`, but credentials stayed behind. This created a split: two directories, two files, for one project. The deprecated `~/.lupin/config` still exists on disk with stale data.

**Goal**: Merge everything into `~/.lupin/config` — one file, one directory, `chmod 600`.

## Backward Compatibility Matrix

| Scenario | Behavior |
|----------|----------|
| Only `~/.lupin/config` (unified) | Primary path — everything works |
| Only `~/.notifications/config` + `~/.lupin/credentials.ini` | Legacy paths with deprecation warnings |
| `~/.lupin/config` (no credentials) + `~/.lupin/credentials.ini` | API from unified, credentials fallback to `.ini` with warning |
| All three files exist | `~/.lupin/config` wins for both |
| No files exist | Hardcoded defaults for API config; FileNotFoundError for credentials |

## File Permissions

After consolidation, `~/.lupin/config` MUST be `chmod 600` (currently `664`). The `cmd_migrate()` and `cmd_init()` commands enforce this.
