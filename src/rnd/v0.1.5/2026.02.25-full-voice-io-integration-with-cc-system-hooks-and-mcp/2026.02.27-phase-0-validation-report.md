```json

  "ppid": 1186724,
  "payload": { ... }
```

| Field | Type | Required | Notes |
|-------|------|----------|-------|

## 4. Surprises / Deviations from Research

### 4.1 `model` field in SessionStart (NOT predicted)

The `model` field appeared in 50% (13/26) of SessionStart payloads with value `"claude-opus-4-6"`. This was not mentioned in the research document. Useful for multi-model routing if hooks need to adjust behavior per model.

**Impact**: Low — informational field, no action needed.

### 4.2 `source` field in SessionStart (NOT predicted)

The `source` field indicates WHY the session started: `startup` (fresh start), `clear` (context window cleared), `compact` (context compressed). This enables hooks to differentiate between fresh sessions and context-continuation events.

**Impact**: Medium — useful for session bridge: don't overwrite bridge file on `clear`/`compact` since the logical session continues.

### 4.3 Notification with alternate schema (1 anomaly)

File `notification-20260227T034710_850340.json` had a different schema:
```json
{"type": "permission_prompt", "message": "Allow Write to /tmp/test.py?", "title": "Permission Required"}
```
Missing: `session_id`, `hook_event_name`, `cwd`, `transcript_path`. Uses `type` instead of `notification_type`.

**Cause**: This was from a manual stdin test during initial hook development (Session 276). Not a real CC payload.

### 4.4 `stop_hook_active` always `false`

Never observed `stop_hook_active: true` because the test hooks never return a blocking `decision: "block"` response. The `true` case will only appear when a production Stop hook actively blocks — to be validated in Phase 4.

### 4.5 MCP tool responses are strings, not dicts

Built-in tools (Read, Bash, Edit, etc.) return structured dict responses. MCP tools return plain JSON-encoded strings. Hook code that processes `tool_response` must handle both types.

### 4.6 PostToolUse count < PreToolUse count (delta: 66)

66 more PreToolUse events than PostToolUse events. Possible causes:
- Tool calls interrupted by user (Ctrl+C)
- Session terminated mid-tool-call
- Tool call errored before post-hook could fire

**Impact**: Hooks should not assume 1:1 pre/post pairing.

### 4.7 `last_assistant_message` can be very long

Stop hook `last_assistant_message` contains Claude's full response text — including markdown tables, code blocks, and multi-paragraph summaries. Some messages exceed 2,000 characters. Voice drain code should truncate or summarize before TTS.

## 7. Recommendations for Phase 1+

1. **Filter noisy tools from TTS** (Phase 3): Read (35.5%), Grep (7.3%), and Glob (6.4%) should be excluded from PostToolUse TTS announcements — together they're 49.2% of all tool calls
2. **Handle both dict and string `tool_response`** (Phase 2): Built-in tools return dicts, MCP tools return strings
3. **Truncate `last_assistant_message`** (Phase 4): Stop hook messages can be very long — summarize before TTS
4. **Respect `source` in SessionStart** (Phase 2): Don't overwrite session bridge on `clear`/`compact` events
5. **Don't assume pre/post pairing** (Phase 2): 66-event delta means some tool calls lack a post-hook event
6. **Leverage `model` field** (future): SessionStart provides model name — could enable model-specific hook behavior
