# Plan: Preference Learning Seed Data Generator

**Created**: 2026-02-24
**Status**: Implemented
**Script**: `src/scripts/seed_proxy_decisions.py`

**Scope**: This plan covers seed data for Phases 0-1 (current). The same script and scenario catalog will serve as the foundation for Phases 2-3 testing when Thompson Sampling, GP/BALD, and Conformal Prediction are implemented — those phases build on top of the same case base and ratification data.

## Context

Phases 0 and 1 of the preference learning system are implemented:
- **Phase 0**: LanceDB `proxy_decisions` table with 768-dim embeddings via `ProxyDecisionEmbeddings`
- **Phase 1**: CBR engine via `CBRDecisionStore` + Beta-Bernoulli trust levels

The system has **0 observations**. CBR returns `verdict=None, confidence=0.0` for every query. To bootstrap the case base, we need to seed ~50 realistic decision scenarios across all 6 engineering categories, then ratify them (approve/reject) to create training signal.

## Deliverable

**One self-contained script**: `src/scripts/seed_proxy_decisions.py`

Contains both the scenario catalog (50 scenarios) and the seeding/ratification logic. No new files or directories needed beyond this script.

## Scenario Catalog Design (50 scenarios)

| Category | Count | Approve | Reject | Rationale |
|----------|-------|---------|--------|-----------|
| `deployment` | 9 | 3 | 6 | High-risk, cap L3 — mostly requires human review |
| `testing` | 9 | 7 | 2 | Low-risk, cap L5 — mostly safe to auto-approve |
| `deps` | 8 | 5 | 3 | Low-risk but risky upgrades exist |
| `architecture` | 9 | 3 | 6 | High-risk, cap L3 — design decisions need oversight |
| `destructive` | 9 | 2 | 7 | Highest-risk — heavily reject |
| `general` | 6 | 5 | 1 | Catch-all, mostly benign |

### Design principles

1. **Keyword coverage**: Each question contains 1-2 keywords from `engineering_categories.py` so the classifier can correctly route them
2. **Semantic clusters**: 2-3 pairs of semantically similar questions per category (e.g., "run full pytest regression suite" vs "execute complete test suite as pre-merge gate") — tests CBR embedding similarity
3. **Cross-category edge cases**: 3-4 questions with keywords from multiple categories (e.g., "delete old integration test fixtures" = destructive + testing)
4. **Sender rotation**: Distributed across `swe.lead@`, `swe.coder@`, `swe.tester@lupin.deepily.ai`

## Script Architecture

```
src/scripts/seed_proxy_decisions.py
│
├── LUPIN_ROOT bootstrap (sys.path setup)
├── SCENARIO_CATALOG = [ ... ]          # 50 scenario dicts
│
├── seed_decisions( scenarios, dry_run )
│   ├── For each scenario:
│   │   ├── ProxyDecisionRepository.log_decision()    → PostgreSQL
│   │   ├── EmbeddingProvider.generate_embedding()     → 768-dim vector
│   │   └── ProxyDecisionEmbeddings.add_decision()     → LanceDB
│   └── Returns list of ( pg_uuid, scenario_id )
│
├── ratify_suggested( user_email )
│   ├── For each seed decision (metadata_json.seed_data == True):
│   │   ├── ProxyDecisionRepository.ratify()           → PostgreSQL
│   │   ├── ProxyDecisionEmbeddings.update_ratification_state() → LanceDB
│   │   └── (TrustState update optional — skip for seed data)
│   └── Summary table of approve/reject counts
│
├── verify()
│   ├── Count PostgreSQL pending/ratified decisions
│   ├── Test LanceDB similarity search with known query
│   ├── Test semantic pair cosine similarity > 0.80
│   └── Test CBR prediction returns non-None verdict
│
├── clean_seed_data()
│   └── Delete records where metadata_json.seed_data == True
│
└── __main__
    └── argparse: --dry-run, --ratify, --verify, --clean, --category, --user-email
```

## Usage Workflow

```bash
# Step 1: Preview scenarios (no writes)
python src/scripts/seed_proxy_decisions.py --dry-run

# Step 2: Seed 50 decisions into PostgreSQL + LanceDB
python src/scripts/seed_proxy_decisions.py

# Step 3: Optionally review a few in Trust Dashboard UI

# Step 4: Batch-ratify all using suggested approve/reject values
python src/scripts/seed_proxy_decisions.py --ratify --user-email your@email.com

# Step 5: Verify CBR case base is populated
python src/scripts/seed_proxy_decisions.py --verify

# Cleanup: Remove seed data if needed
python src/scripts/seed_proxy_decisions.py --clean
```

## Verification Criteria

1. `--dry-run` prints category distribution table (no side effects)
2. After seeding: PostgreSQL has 50 pending seed decisions
3. After ratifying: LanceDB `find_similar()` returns results with correct ratification states
4. After ratifying: `CBRDecisionStore.predict( "Should I run the pytest suite?", "testing", embedding )` returns `verdict` with `confidence > 0.0`
5. Semantic pair verification: cosine similarity between "run full pytest regression suite" and "execute complete test suite as pre-merge gate" > 0.80

## Bootstrap & Testing Infrastructure

This script is a **required step** for bootstrapping the preference learning system in any new environment (fresh install, CI, or after `--clean`). Without seed data, the CBR engine returns empty predictions and the trust system has no training signal.

### Prerequisites

```bash
# Required environment variables
export LUPIN_ROOT=/path/to/lupin
export LUPIN_CONFIG_MGR_CLI_ARGS='{"config_path": "/src/conf/lupin-app.ini", ...}'

# Required services
# - PostgreSQL with proxy_decisions table (via Alembic migrations)
# - LanceDB database directory (auto-created on first use)
# - Embedding engine (OpenAI or local — per config)
```

### Complete Bootstrap Sequence

```bash
# 1. Verify prerequisites
python src/scripts/seed_proxy_decisions.py --dry-run

# 2. Seed the case base (50 decisions → PG + LanceDB)
python src/scripts/seed_proxy_decisions.py

# 3. Ratify all using curated approve/reject values
python src/scripts/seed_proxy_decisions.py --ratify --user-email your@email.com

# 4. Verify end-to-end (PG counts, LanceDB search, CBR prediction)
python src/scripts/seed_proxy_decisions.py --verify
```

### CLI Reference

| Flag | Description | Requires |
|------|-------------|----------|
| `--dry-run` | Print scenario catalog, no database writes | — |
| (no flags) | Seed 50 decisions into PostgreSQL + LanceDB | DB access |
| `--ratify` | Batch-ratify all seed decisions | `--user-email` |
| `--verify` | Run verification checks (PG, LanceDB, CBR) | Seeded data |
| `--clean` | Delete all seed data (metadata_json.seed_data=True) | Seeded data |
| `--category X` | Filter to one category (e.g., `testing`) | — |
| `--user-email E` | Email for ratification audit trail | `--ratify` |

### Cleanup / Reset

```bash
# Remove all seed data and start fresh
python src/scripts/seed_proxy_decisions.py --clean

# Then re-seed
python src/scripts/seed_proxy_decisions.py
python src/scripts/seed_proxy_decisions.py --ratify --user-email your@email.com
```

### Seed Data Identification

All seed records are tagged with `metadata_json.seed_data = True` and `metadata_json.seed_id = "seed-<cat>-NNN"`. This makes them:
- **Identifiable**: Easy to query/filter in the Trust Dashboard
- **Cleanable**: `--clean` removes only seed records, preserving organic decisions
- **Auditable**: Each record traces back to a specific scenario in `SCENARIO_CATALOG`
