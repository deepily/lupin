## Context

The Universal Prediction Engine (Slices 0–5) computes predictions server-side and attaches them as `prediction_hint` on `NotificationItem`. The WebSocket delivers this dict to the browser. But `notifications.js` → `renderActionRequiredNotification()` never reads `notification.prediction_hint`. This means:

- You can't see what the engine predicted
- You can't validate predictions visually during live E2E testing
- The "full stack per type (predict + **UI hint** + track)" architecture decision remains incomplete

**This slice closes the gap**: render prediction hints inside response-required notification cards.

---

## Data Flow (already working)

```
PredictionEngine.predict()
  → PredictionResult.to_hint_dict()
    → NotificationItem.prediction_hint = hint_dict
      → NotificationItem.to_dict() serializes it
        → WebSocket pushes to browser
          → notification.prediction_hint available in JS ← WE ARE HERE
```

### Step 1: Add `buildPredictionHintSection()` helper method

**File**: `src/fastapi_app/static/js/notifications.js`
**Location**: After `renderOpenEndedBatchUI()` (line ~10856), add a new method.

This method takes `notification` and returns an HTML string (empty string if no hint).

```javascript
buildPredictionHintSection( notification ) {
    const hint = notification.prediction_hint;
    if ( !hint ) return '';  // Cold start — no hint

    const confidence   = Math.round( hint.confidence * 100 );
    const strategy     = this.formatStrategyLabel( hint.strategy );
    const responseType = notification.response_type;

    let predictedText = '';

    if ( responseType === 'yes_no' ) {
        const value = typeof hint.predicted_value === 'string'
            ? hint.predicted_value.charAt( 0 ).toUpperCase() + hint.predicted_value.slice( 1 )
            : hint.predicted_value;
        predictedText = hint.predicted_qualifier
            ? `Predicted: ${value} — "${hint.predicted_qualifier}" (${confidence}%)`
            : `Predicted: ${value} (${confidence}%)`;

    } else if ( responseType === 'multiple_choice' ) {
        const answers = hint.predicted_value?.answers;
        if ( answers ) {
            const parts = Object.entries( answers ).map( ( [ header, val ] ) => {
                return Array.isArray( val ) ? `${header}: [${val.join( ', ' )}]` : `${header}: ${val}`;
            } );
            predictedText = `Predicted: ${parts.join( '; ' )} (${confidence}%)`;
        }

    } else if ( responseType === 'open_ended' ) {
        const value = typeof hint.predicted_value === 'string'
            ? hint.predicted_value
            : JSON.stringify( hint.predicted_value );
        predictedText = `Predicted: "${value}" (${confidence}%)`;

    } else if ( responseType === 'open_ended_batch' ) {
        const answers = hint.predicted_value?.answers;
        if ( answers ) {
            const parts = Object.entries( answers ).map( ( [ header, val ] ) =>
                `${header}: "${val}"`
            );
            predictedText = `Predicted: ${parts.join( '; ' )} (${confidence}%)`;
        }
    }

    if ( !predictedText ) return '';

    return `
        <div class="prediction-hint">
            <div class="prediction-hint-label">${predictedText}</div>
            <div class="prediction-hint-strategy">${strategy}</div>
        </div>
    `;
}
```

### Step 2: Add `formatStrategyLabel()` helper method

**File**: `src/fastapi_app/static/js/notifications.js`
**Location**: Adjacent to `buildPredictionHintSection()`.

Maps internal strategy constants to human-readable labels.

```javascript
formatStrategyLabel( strategy ) {
    const labels = {
        'cbr_majority_vote'      : 'Based on majority vote',
        'cbr_retrieval'          : 'Based on exact match retrieval',
        'llm_synthesis'          : 'Based on LLM synthesis',
        'option_embedding_scoring': 'Based on option scoring',
        'cold_start'             : 'No prediction data'
    };
    return labels[ strategy ] || strategy;
}
```

### Step 4: Add CSS styling for `.prediction-hint`

**File**: `src/fastapi_app/static/css/notifications.css`
**Location**: After `.action-required-abstract` styles (after line ~752), before `.action-required-progress-bar` (line 754).

Follow the established abstract section pattern (gray background, border-left, padding) but with a distinct color to visually separate "context" from "prediction":

```css
/* Prediction engine hint section */
.prediction-hint {
    font-size: 0.85em;
    color: #5a4e8c;
    margin-top: 4px;
    margin-bottom: 12px;
    padding: 8px 12px;
    background: #f3f0ff;
    border-left: 3px solid #7c6bc4;
    border-radius: 4px;
    line-height: 1.5;
}

.prediction-hint-label {
    font-weight: 600;
    margin-bottom: 2px;
}

.prediction-hint-strategy {
    font-size: 0.9em;
    color: #7c6bc4;
    font-style: italic;
}
```

**Design rationale**:
- Purple tones (`#5a4e8c`, `#f3f0ff`, `#7c6bc4`) distinguish predictions from the gray abstract section
- Smaller font (0.85em) and italic strategy label keep the hint subordinate to main content
- Same border-left + padding pattern as abstract for visual consistency
- No interactivity — purely informational, doesn't bias the user's response
