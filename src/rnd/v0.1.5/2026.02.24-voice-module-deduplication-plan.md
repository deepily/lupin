# Voice Module Audit: cosa_interface.py vs voice_io.py vs lupin_mcp Redundancy

## Context

The voice/notification system has grown organically across 4 layers and 19 files totaling ~7,261 lines. The MCP server (`src/lupin_mcp/`) was the reference implementation for wrapping notification interactions. Over time, the same patterns were copy-pasted into each agent's `cosa_interface.py` and `voice_io.py`, creating significant redundancy. This audit identifies refactoring opportunities to reduce ~2,200 lines of duplicated code while preserving backward compatibility.

## Architecture Summary

```
Layer 1: cosa.cli (Foundation — CLEAN, no changes needed)
  notification_models.py, notify_user_sync.py, notify_user_async.py, notification_utils.py

Layer 2: cosa_interface.py (6 per-agent files — MAJOR DUPLICATION)
  deep_research (492 lines), podcast_generator (400), swe_team (491),
  claude_code (219), decision_proxy (13), notification_proxy (10)

Layer 3: voice_io.py (7 per-agent files — MAJOR DUPLICATION)
  utils/voice_io.py CORE (840), deep_research (440), podcast_generator (452),
  swe_team (269), claude_code (16), decision_proxy (82), notification_proxy (79)

Layer 4: lupin_mcp/cosa_voice_mcp.py (703 lines — PARALLEL IMPLEMENTATION)
```

## Findings: What's Redundant vs Complementary

### Complementary (different purposes, keep separate)
- **cosa_interface.py**: Async wrappers (`asyncio.to_thread`) for agents running in event loops
- **voice_io.py core**: Voice-first layer with CLI fallback on top of cosa_interface
- **lupin_mcp**: MCP protocol adapter for Claude Code (sync, standalone process)

### Redundant (copy-paste across agents)
1. **`_get_sender_id()` project detection** — 5 identical copies (DR, PG, CC, SWE, MCP), only agent prefix differs
2. **`notify_progress()` body** — 4 near-identical copies
3. **`ask_confirmation()` body** — 4 near-identical copies
4. **`get_feedback()` body** — 3 identical copies
5. **`present_choices()` body** — 3 identical copies
6. **`is_approval()` / `is_rejection()`** — 3 character-for-character identical copies
7. **voice_io wrappers** — DR (440) and PG (452) are ~95% identical re-export boilerplate
8. **`inspect.signature()` hacks** in core voice_io.py to handle differing cosa_interface signatures

## Refactoring Plan (5 Phases, Incremental)

### Phase 1: Extract Shared Utilities (Low Risk, ~1 hour)

**New file: `src/cosa/agents/utils/sender_id.py`** (~35 lines)
- `detect_project()` — single copy of cwd-based project detection
- `build_sender_id( agent_type, project=None, session_suffix=None )` — constructs sender_id string
- Replaces 5 copies of `_get_sender_id()` across DR, PG, CC, SWE, MCP

**New file: `src/cosa/agents/utils/feedback_analysis.py`** (~50 lines)
- `APPROVAL_SIGNALS`, `REJECTION_SIGNALS` — shared signal lists
- `is_approval( feedback )`, `is_rejection( feedback )` — shared analysis
- `extract_feedback_intent( feedback )` — currently DR-only, promote to shared
- Replaces 3 identical copies across DR, PG, SWE

**Update each agent's cosa_interface.py** (to be renamed in Phase 2) to import from shared modules:
```python
from cosa.agents.utils.sender_id import build_sender_id
SENDER_ID = build_sender_id( "deep.research" )
```

**Runtime mutation preserved**: `_get_sender_id()` still exposed for `job.py` callers that do:
```python
notification_profile.SENDER_ID = notification_profile._get_sender_id() + f"#{self.id_hash}"
```

**Files modified**: 4 cosa_interface.py files (DR, PG, CC, SWE) + MCP server
**Savings**: ~180 lines

### Phase 2: Create `AgentNotificationDispatcher` + Rename to `notification_profile.py` (Medium Risk, ~3-4 hours)

**New file: `src/cosa/agents/utils/agent_notification_dispatcher.py`** (~250 lines)
- Class `AgentNotificationDispatcher` — encapsulates the shared async wrapper + notification dispatch pattern
- Configurable via constructor: `agent_type`, `default_priority`, `supports_role`
- Provides: `notify_progress()`, `ask_confirmation()`, `get_feedback()`, `present_choices()`
- All methods use `asyncio.to_thread()` internally, accept optional `role`, `job_id`, `queue_name`, `progress_group_id` params

**Rename `cosa_interface.py` -> `notification_profile.py`** across all 6 agents.
No re-export boilerplate — just identity + dispatcher instance:

```python
# deep_research/notification_profile.py (~10 lines)
from cosa.agents.utils.agent_notification_dispatcher import AgentNotificationDispatcher
from cosa.agents.utils.feedback_analysis import is_approval, is_rejection, extract_feedback_intent

dispatcher = AgentNotificationDispatcher( agent_type="deep.research" )
```

```python
# swe_team/notification_profile.py (~10 lines, role-aware)
from cosa.agents.utils.agent_notification_dispatcher import AgentNotificationDispatcher
from cosa.agents.utils.feedback_analysis import is_approval, is_rejection

dispatcher = AgentNotificationDispatcher( agent_type="swe", default_priority="high", supports_role=True )
```

**Update ~15 consumer files** (job.py, orchestrator.py, cli.py) to use dispatcher directly:
```python
# Before:
from . import cosa_interface
cosa_interface.SENDER_ID = cosa_interface._get_sender_id() + f"#{self.id_hash}"
await cosa_interface.notify_progress( "Starting..." )

# After:
from . import notification_profile
notification_profile.dispatcher.sender_id = notification_profile.dispatcher.build_sender_id() + f"#{self.id_hash}"
await notification_profile.dispatcher.notify_progress( "Starting..." )
```

**Files renamed**: 6 cosa_interface.py -> notification_profile.py
**Files created**: 1 new dispatcher class
**Consumer files updated**: ~15 import statements
**Savings**: ~1,100 lines (consolidation + no re-export boilerplate)

### Phase 3: Consolidate voice_io Wrappers (Medium Risk, ~1-2 hours)

**Depends on**: Phase 2 (unified cosa_interface signatures)

**Remove `inspect.signature()` hacks** from `utils/voice_io.py`:
- Lines 237-248: notify() introspection -> direct call
- Lines 547-553: present_choices() introspection -> direct call

**Reduce DR, PG, SWE voice_io wrappers** to thin re-export modules (~25 lines each):
```python
from cosa.agents.utils import voice_io as _core_voice_io
from . import notification_profile as _notification_profile
_core_voice_io.configure( _notification_profile )
from cosa.agents.utils.voice_io import notify, ask_yes_no, get_input, choose, present_choices
```

**Files modified**: 4 voice_io.py files (core + DR + PG + SWE)
**Savings**: ~1,050 lines

### Phase 4: Proxy Agent Alignment (Low Risk, ~30 min)

**New file: `src/cosa/agents/utils/sync_notify.py`** (~30 lines)
- Shared synchronous REST notify helper for proxy agents
- Handles API key loading, request construction, error handling

**Reduce**: decision_proxy/voice_io.py (82 -> ~15) and notification_proxy/voice_io.py (79 -> ~15)

**Files modified**: 2 voice_io.py files
**Files created**: 1 shared helper
**Savings**: ~100 lines

### Phase 5: MCP Server Cleanup (Low Risk, ~30 min)

**Update `src/lupin_mcp/cosa_voice_mcp.py`**:
- Import `detect_project()`, `build_sender_id()` from `sender_id.py`
- Move `_normalize_abstract()` to `cosa/utils/notification_utils.py`
- Keep MCP-specific tool definitions and FastMCP decorators as-is

**Rationale for NOT sharing more**: MCP server is sync (no asyncio.to_thread), standalone process, different protocol (MCP vs Python calls). Forced sharing would add complexity.

**Files modified**: 1 MCP server + 1 notification_utils
**Savings**: ~15 lines (but eliminates the 5th copy of project detection)

## Estimated Total Impact

| Phase | Lines Before | Lines After | Savings |
|-------|-------------|-------------|---------|
| Phase 1: Shared utilities | ~300 (across 5 files) | ~120 (2 new + imports) | ~180 |
| Phase 2: AgentNotificationDispatcher + rename | ~1,625 (6 cosa_interface) | ~310 (dispatcher + 6 profiles) | ~1,315 |
| Phase 3: voice_io consolidation | ~1,161 (3 wrappers + introspection) | ~105 (3 thin re-exports) | ~1,056 |
| Phase 4: Proxy alignment | ~161 (2 proxy voice_io) | ~60 (2 thin + helper) | ~101 |
| Phase 5: MCP cleanup | ~703 | ~688 | ~15 |
| **Total** | **~3,927 affected** | **~1,258** | **~2,669** |

**~37% reduction** in the voice/notification module footprint.

## Critical Files

| File | Role in refactoring |
|------|---------------------|
| `src/cosa/agents/utils/voice_io.py` | Core to simplify (remove inspect.signature hacks) |
| `src/cosa/agents/deep_research/cosa_interface.py` | Template for AgentNotificationDispatcher extraction; renamed to `notification_profile.py` |
| `src/cosa/agents/swe_team/cosa_interface.py` | Tests role-aware flexibility of dispatcher; renamed to `notification_profile.py` |
| `src/cosa/agents/deep_research/voice_io.py` | Biggest single-file savings (440 -> ~25) |
| `src/cosa/agents/deep_research/job.py` | Key consumer — mutates SENDER_ID at runtime (import update needed) |
| `src/lupin_mcp/cosa_voice_mcp.py` | MCP server — minimal changes (Phase 5) |

## Verification Plan

After each phase:
1. Run agent smoke tests: `python -m cosa.agents.deep_research.cosa_interface` (etc.)
2. Run voice_io smoke tests: `python -m cosa.agents.deep_research.voice_io` (etc.)
3. Run MCP smoke test: `pytest src/tests/smoke/test_mcp_smoke.py -v`
4. Run unit tests: `pytest src/tests/unit/ -v`
5. Manual E2E: Submit a Deep Research job and verify notifications arrive correctly

## Risk Mitigations

- **All phases are independently deployable** — no phase requires another
- **Clean break, no re-export boilerplate** — consumers updated directly in Phase 2
- **Runtime sender_id mutation preserved** — `dispatcher.sender_id` is a mutable attribute
- **No circular import risk** — new utils depend only on cosa.cli (lower in graph)
- **Smoke tests validate each step** — existing tests cover all agents
