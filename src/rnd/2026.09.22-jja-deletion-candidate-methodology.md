## 3. The methodology — five gates, in this order

Order is load-bearing. Running the cheap tests first means the expensive one (reading files)
is paid on 46 documents instead of 341.

### Gate 0 — LOAD-BEARING. Runs first, overrides every later verdict.

Does any code or test name this path? If yes the file is **never bare-deleted**. Two exits only:

- **PROMOTE** — grant it authorization, add frontmatter, keep it.
- **RETARGET** — move the content, re-point the citation, *then* delete. One commit, in that order.

This is María's Rule 0. My September finding is what put it there: her first draft said non-`.md`
deletes by rule, no judgment, and that rule would have reddened the suite.

**Instrument**: fixed-string search of each basename across `git ls-files 'src'` filtered to
code and test extensions. **Never a regex** — a character class under-reports silently.

### Gate 1 — DURABLE CITATION.

Cited from `CLAUDE.md`, `CLAUDE.local.md`, `TODO.md`, `history.md`, `history/`, `src/docs/`,
or `src/workflow/`? Keep.

🔴 **`src/rnd/README.md` is excluded from the haystack.** It is the index entry every worker is
instructed to add. An index that lists its own directory makes every file in it "cited," and the
signal reads green while measuring nothing.

### Gate 2 — OPERATOR AUTHORIZATION. *(the gate I skipped in September)*

Does the document's own text name Rick as the ordering authority — `(Rick, P0)`, *asked for by
Rick*, *by Rick's voice ruling*, *Rick's broadcast*? Keep.

⚠️ **I published this as part of a six-signal discriminator and then did not run it.** Adding it
afterwards found 12 keepers in September and 20 in the pre-September set, including the deliverable
of row `645a7da5` — a P0 Rick ordered, still in progress. *A signal reported as run and not run is
worse than a signal never claimed*, because it spends the trust the other five earned.

### Gate 3 — CLASS.

Is this a research document at all? Logs, probe rigs, receipts, screenshots, `.failset`/`.meta`
files and shell scripts are **transient by class** and never belonged here. **41 of the 341** carry
receipt-shaped names.

⚠️ Gate 0 still wins: `harvest.sh` is a shell script *and* test-cited.

### Gate 4 — UNMINTED FINDING. The only gate that needs a human.

Of what survives Gates 0–3, does the document name **any store row**? A document that cites a row
is a narrative duplicate of durable work — the finding outlives the file. A document citing **no**
row may hold a finding that exists nowhere else.

**Only 46 of 341 name no row.** Those 46 get read. For each: mint a row for any real finding, then
delete.

In September this test was exact — **1 of 71** named no row (`2026.09.06-the-orphan-tick-is-built-and-not-installed.md`),
it did hold a genuine unminted finding, and it is now row `18ec288d`.

⚠️ **Naming a row is not proof the finding is minted.** A doc can cite the row it was written *for*
while containing a *second*, never-filed finding. The 46-file read catches the clear cases; it does
not make the other 295 provably safe. **Say which you mean:** this is "I looked and found one,"
not "there can only be one."

## 4. Execution plan

| phase | action | output | gate |
|---|---|---|---|
| **P1** | Run Gates 0–3 mechanically over all 341 | a candidate list with a per-file reason | none — read-only |
| **P2** | Positive control: plant a known-cited doc, confirm Gate 0 catches it; restore | a receipt | none |
| **P3** | Read the ~46 Gate-4 files; mint rows for real findings | new store rows | none |
| **P4** | **Present the cut to Rick** with per-file reasons and the keep list | one decision ask | 🔴 **Rick rules** |
| **P5** | `git rm` the ruled set; strip `README.md` index entries; annotate dead cross-links | a commit | — |
| **P6** | Full merge pyramid before the commit is pushed | green tiers | 🔴 **Rick pushes** |

**P4 is the only place a file becomes deletable.** Everything before it is measurement.

### Controls that must actually run

- **Positive control before trusting any zero.** A negative result is worth nothing until the same
  search has been watched returning a positive.
- **Delinking is not line deletion.** In September, a naive `grep -vF` over `README.md` would have
  removed the *only* index entry for a **surviving** doc, because one line linked both a deleted and
  a kept file. Check removed-lines-against-survivors *before* applying.
- **Read the exit code with the summary line.** My first September tier printed `25683 passed` and
  `EXIT=124` — a `SIGTERM` at 99%. The passing count looked exactly like success.
- **Never `git add .`.** `src/conf/lupin-app.ini` was dirty from another session throughout this work.
