## Why a human is doing this at all

🔴 **The guard proves a class REACHES a linked sheet. It cannot prove the rule LOOKS right.**

That is not a gap in the guard — it is the boundary of what a static check can claim. It parses
`multiplexer.html`'s `<link>` tags, collects the class names those sheets define, and asserts the
five names below are among them. **A rule that reached the page and painted the wrong thing passes
it.** Nothing in this repo renders the page and compares pixels for these five, so the last step is
a person's eyes.

⚠️ **Five checks, not twenty-three.** The census found 23 emitted classes that no sheet defines.
Eighteen **must stay unstyled** — 13 because the legacy card emits them and styles them nowhere
(Rick's "look exactly like legacy"), 3 because their wrapper already handles them, 1 because it is
a wrapper whose variants carry the look, 1 because the unaccented badge *is* the default's look.
**Styling those would be the regression, not the fix.** Full derivation:
`src/rnd/2026.09.06-accordion-wiring-census.md`.

## Setup

1. Sign in, then open **`http://localhost:7999/app/multiplexer`**.
2. You need the **Holding Area**, **Epic Board** and **Task List** panes visible.
3. Hard-reload once (**Ctrl-Shift-R**) — these sheets are cache-busted with `?v=`, and a stale
   sheet is the single most likely reason a check below fails for a reason that is not the CSS.

## The five

### 1 · `.holding-area-refresh` — the Holding Area ⟳ button

| | |
|---|---|
| **Where** | Holding Area section header, the **⟳** glyph beside the title |
| **Look for** | a **button that reads as a button** |
| **Correct** | light grey fill, a thin grey rounded border (~6px radius), snug padding. Hovering **darkens the fill**. Tabbing to it shows a **grey focus ring offset a couple of px outside** the border |
| **Wrong** | a raw browser button (chunky bevelled grey, square corners) — the rule did not reach it. Or **no hover change at all** |
| **Compare against** | the Task List's own ⟳ — **they must be indistinguishable.** That is the whole intent: one column, one button language |

### 2 · `.epic-board-refresh` — the Epic Board ⟳ button

Same rule, same selector block, different pane. **Check it separately** — it is a second class name
and could be dropped from the selector list without the first one noticing.

| | |
|---|---|
| **Correct** | identical to items 1 and the Task List ⟳ — **all three the same** |
| **Wrong** | this one alone looks like a default browser button |

### 3 · `.holding-area-updated` — the "updated HH:MM:SS" stamp

| | |
|---|---|
| **Where** | Holding Area header, after a refresh has completed |
| **Look for** | where it sits, and how loud it is |
| **Correct** | **pushed hard to the RIGHT edge** of the header row; small (~11px), **pale grey**, digits evenly spaced (tabular) so the time does not jitter as it ticks |
| **Wrong** | sitting **next to the title** instead of at the right edge — that is `margin-left: auto` not landing, the one declaration that is copied rather than approximated. Or full-size / full-contrast text competing with the title |

🔴 **DO NOT REPORT THE EPIC BOARD'S STAMP AS A BUG.** `.epic-board-updated` is **deliberately
unstyled** — the legacy card emits it and styles it nowhere, so giving it a rule would make the
multiplexer *differ* from legacy. **The two stamps looking different is the intended state.** It is
in the guard's `CHROME_PARITY_EXCLUSIONS` for exactly this reason.

### 4 · `.holding-area-sentinel` — the store-unreachable banner

| | |
|---|---|
| **Where** | fills the Holding Area body, replacing the rows |
| **How to reach it** | it is the **pre-first-poll state**, so it is often visible for a moment on a cold load. To hold it: open DevTools → Network → **Offline**, then click the Holding Area **⟳**. Set Online again and ⟳ to leave |
| **Text** | *"Task store unreachable — last known state not shown."* |
| **Correct** | a **centred amber banner** — pale yellow fill, darker amber border, brown-ish text, rounded ~6px, generous padding, a small gap below it. It should read like the **same warning language** as the Task List's own unreachable banner |
| **Wrong** | unstyled centred text with no box; or a **red** box (that is the sign-in language, a different meaning) |

⚠️ **Then check the SIBLING state, because this rule was written narrowly to protect it.** Empty the
Holding Area (or watch it when nothing is held) — **"Nothing waiting on triage."** must still render
**dim, italic, tight** (legacy's `.holding-area-empty`). **If the empty state has turned into an
amber box too, this rule leaked onto the shared `.holding-area-message` base and broke a legacy look
this work is supposed to preserve.** That is the specific failure the rule is scoped to avoid.

### 5 · `.task-col-blocked` — the "Blocked by" field wraps

| | |
|---|---|
| **Where** | Task List, second line of a **disclosed** row |
| **How to reach it** | find a row whose status is **blocked** and that has **more than one blocker** (row `96cf5cec` qualifies today — two blockers). Click the **⋯** glyph at the right end of its title line ("Show row controls") |
| **Look for** | the **"Blocked by"** field on line 2 |
| **Correct** | the blocker list **wraps onto a second line inside its own field**, staying within the row |
| **Wrong** | the list runs **off the right edge**, or **shoves the fields beside it out of the row**. That is the `white-space: nowrap` it inherits from `.task-disclosed-field` still winning |

⚠️ **This is the only one of the five that OVERRIDES an inherited legacy value**, so it is the only
one where the cascade order matters — this sheet is linked after the legacy pair and wins at equal
specificity. **A single-blocker row cannot show you anything**: one token fits either way, so it
looks correct under both the working rule and the broken one. **You need a multi-blocker row or the
check is vacuous.**

## Reporting

For each item say **PASS**, **FAIL**, or **COULD NOT REACH THE STATE** — and treat the third as its
own answer, not a pass. Four of the five need a state to be produced (a completed refresh, an
outage, a multi-blocker row), and *"I could not get the pane into that state"* and *"it looked
right"* are different facts.

If something fails, the useful report is **what you saw**, not what you think is missing — a
screenshot beats a diagnosis. Describing damage in terms of what is *absent* means comparing the
page against your idea of it, and the idea is the part that can be wrong.
