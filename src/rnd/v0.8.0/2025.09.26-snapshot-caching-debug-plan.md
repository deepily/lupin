# Snapshot Caching Debug Plan - 2025.09.26

## Problem Statement

The snapshot caching system is not working as expected. When asking the same question twice (e.g., "What is the square root of 100?"), the second request should retrieve the cached result instead of regenerating the solution, but this cache-hit optimization is not happening.

## Expected Behavior

### First Execution (Cache Miss)
1. User asks: "What is the square root of 100?"
2. System searches LanceDB for matching snapshot → Not found
3. Math Agent generates code → Executes → Gets answer: 10.0
4. **Snapshot stored** with:
   - Question/query text
   - Generated code
   - Result/answer
   - Timestamp
   - Vector embedding for similarity search
5. Answer returned to user

### Second Execution (Cache Hit - CURRENTLY BROKEN)
1. User asks: "What is the square root of 100?" (exact same question)
2. System searches LanceDB for matching snapshot → **SHOULD FIND IT**
3. Retrieve cached snapshot
4. Replay cached code WITHOUT regenerating (saves LLM costs)
5. Answer returned to user (fast response)

## 🎯 ROOT CAUSE IDENTIFIED

### Summary
**The snapshot caching infrastructure is 100% functional, but the queue system never searches for existing snapshots before creating new agent jobs.**

### Detailed Findings

#### ✅ What Works (Confirmed)
1. **Storage Pipeline**: Snapshots are correctly saved to LanceDB after job completion
2. **Database**: 45 snapshots exist in `solution_snapshots` table including our test question
3. **Search Functionality**: `manager.get_snapshots_by_question()` finds exact matches
4. **Configuration**: LanceDB manager properly initialized with correct paths
5. **Infrastructure**: All components (LanceDBSolutionManager, Factory, etc.) functional

#### ❌ What's Missing (Root Cause)
1. **Cache Check Logic**: No code searches for existing snapshots before agent execution
2. **Queue Integration**: RunningFifoQueue only saves snapshots, never retrieves them
3. **Workflow Gap**: Agent creation bypasses any cache lookup entirely

### Evidence
- **Timing Test**: Both executions took ~5.1 seconds (no cache speedup)
- **Database Inspection**: Found exact match for "what is the square root of 100"
- **Code Analysis**: Zero search/find/cache methods in agent or queue classes
- **Manager Test**: `get_snapshots_by_question()` successfully returns cached result

### The Missing Logic
The system should work like this:
```python
# MISSING LOGIC - Should happen before agent creation
cached_result = snapshot_mgr.get_snapshots_by_question(question)
if cached_result:
    return cached_result  # Skip agent creation entirely
else:
    create_agent_and_run()  # Current behavior
```
