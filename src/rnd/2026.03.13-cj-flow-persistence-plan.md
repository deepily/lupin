# CJ Flow Persistence — Implementation Plan

## Context

CJ Flow is Lupin's unified work queue system (todo → running → done/dead). Currently, **all queue state is ephemeral** — lost on server restart. Long-running agentic jobs (DeepResearch 10-30min, PodcastGenerator 5-15min, ClaudeCode 1-60min) are the most impacted: if the server restarts mid-execution, users have no visibility into what happened.

**Goal**: Durable PostgreSQL-backed persistence for AgenticJobBase jobs. Job state survives restarts, enables job history queries, and marks interrupted jobs.

**Scope**: AgenticJobBase subclasses only (DeepResearch, PodcastGenerator, ClaudeCode, SweTeam, ResearchToPodcast). Sync agents (Math, Calendar, etc.) are already cached as SolutionSnapshots in LanceDB and execute in 1-5s — not worth the write overhead.

**Future footnote**: Once persistence is in place, queue management operations (delete/remove from done/dead queues) will be needed for ALL job types. The schema and API should be designed to accommodate this expansion.

---

## Architecture Decision: Central Write-Through

Persistence writes happen inside `emit_job_state_transition()` in `queue_util.py` — the single function already called at every state transition. This avoids touching ~10 handler sites in `running_fifo_queue.py`.

**Filter**: Only persist when the job is an `AgenticJobBase` instance (checked via `job_type` in metadata using `is_agentic_job_type()` from `job_persistence.py`).

**Done/dead queues remain in-memory** for the current session. Historical jobs are served from PostgreSQL via a new `/api/job-history` endpoint. No reload into memory on restart.

## Phase 1: Schema + Model (Foundation) ✅

**Status**: Completed in Session 360 (2026-03-14).

### 1.1 PostgreSQL Table

Standalone migration `src/scripts/sql/add-job-history.sql` and appended to `src/scripts/sql/schema.sql`:

```sql
CREATE TABLE IF NOT EXISTS job_history (
    id_hash             VARCHAR(255)    PRIMARY KEY,
    job_type            VARCHAR(100)    NOT NULL,
    user_id             VARCHAR(255)    NOT NULL,
    user_email          VARCHAR(255),
    session_id          VARCHAR(255),
    routing_command     VARCHAR(255),
    status              VARCHAR(50)     NOT NULL DEFAULT 'pending',
    question_text       TEXT,
    error               TEXT,
    is_cache_hit        BOOLEAN         DEFAULT FALSE,
    duration_seconds    FLOAT,
    metadata_json       JSONB,
    created_at          TIMESTAMPTZ     NOT NULL DEFAULT NOW(),
    started_at          TIMESTAMPTZ,
    completed_at        TIMESTAMPTZ,
    updated_at          TIMESTAMPTZ     NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_job_history_user_id ON job_history( user_id );
CREATE INDEX IF NOT EXISTS idx_job_history_status ON job_history( status );
CREATE INDEX IF NOT EXISTS idx_job_history_job_type ON job_history( job_type );
CREATE INDEX IF NOT EXISTS idx_job_history_created_at ON job_history( created_at DESC );
CREATE INDEX IF NOT EXISTS idx_job_history_user_status ON job_history( user_id, status );
```

**Design notes**:
- `id_hash` is PK (the scoped `{hash}::{user_id}` string from CJ Flow)
- `user_id` is VARCHAR (JWT uid string like `ricardo_felipe_ruiz_6bdc`), not UUID FK
- `user_email` is nullable (not `NOT NULL` as originally planned — enrichment happens in Phase 3)
- `metadata_json` JSONB stores: response_text, abstract, report_link, cost_summary, artifacts, answer_conversational, push_counter, agent_type
- Status values: `pending`, `running`, `completed`, `failed`, `interrupted`

**Implementation deviation**: `user_email` changed from `NOT NULL` to nullable because the persistence functions take metadata dicts (not job objects), and user_email may not be available at the pending→todo transition. Enrichment will happen in Phase 3 when metadata completeness is verified.

## Phase 2: Persistence Service ✅

**Status**: Completed in Session 360 (2026-03-14).

### 2.1 New Module

**File**: `src/cosa/rest/job_persistence.py` (NEW)

Stateless service module (functions, no class) following `queue_util.py` pattern.

**Agentic type filter**:
```python
AGENTIC_JOB_TYPES = frozenset( {
    "deep_research", "podcast", "claude_code",
    "swe_team", "research_to_podcast"
} )
```

**Core functions** (all fire-and-forget except `mark_interrupted_jobs`):

| Function | Action | Transition |
|----------|--------|------------|
| `persist_job_created_from_metadata( job_id, user_id, metadata )` | INSERT status='pending' | pending→todo |
| `persist_job_started_from_metadata( job_id, metadata )` | UPDATE status='running', started_at | todo→run |
| `persist_job_completed_from_metadata( job_id, metadata )` | UPDATE status='completed', metadata_json | run→done |
| `persist_job_failed_from_metadata( job_id, metadata )` | UPDATE status='failed', error | run→dead |
| `mark_interrupted_jobs() -> int` | Bulk UPDATE status='interrupted' | Startup recovery |
| `get_active_job_ids_by_user() -> dict` | Query pending/running by user | Startup recovery |
| `query_job_history( ... ) -> dict` | Paginated filtered query | API endpoint |
| `get_job_by_id_hash( id_hash ) -> dict` | Single row lookup | API endpoint |

**Implementation notes**:
- Functions take metadata dicts (not job objects) — matches `emit_job_state_transition` signature
- `_from_metadata` suffix distinguishes from future `_from_job()` variants if needed
- `_build_metadata_json( metadata )` helper extracts 8 rich fields into JSONB
- `_is_persistence_enabled()` checks config flag via ConfigurationManager, defaults to `True`
- All timestamps use `datetime.now( timezone.utc )` for timezone-aware datetimes (critical: PostgreSQL stores TIMESTAMPTZ, so naive datetimes cause `can't subtract offset-naive and offset-aware datetimes` errors in duration calculation)
- `query_job_history()` caps limit at 100 for safety
- `get_job_by_id_hash()` and `query_job_history()` serialize datetime fields to ISO format strings

### 3.1 Hook into emit_job_state_transition

**File**: `src/cosa/rest/queue_util.py`

Add persistence calls at the end of `emit_job_state_transition()`:

```python
# After WebSocket emit, persist terminal transitions for agentic jobs
if metadata and is_agentic_job_type( metadata.get( 'agent_type' ) ):
    if to_queue == 'todo':
        persist_job_created_from_metadata( job_id, user_id, metadata )
    elif to_queue == 'run' and from_queue == 'todo':
        persist_job_started_from_metadata( job_id, metadata )
    elif to_queue == 'done':
        persist_job_completed_from_metadata( job_id, metadata )
    elif to_queue == 'dead':
        persist_job_failed_from_metadata( job_id, metadata )
```
