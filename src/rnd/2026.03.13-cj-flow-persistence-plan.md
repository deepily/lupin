# CJ Flow Persistence — Implementation Plan

## Context

CJ Flow is Lupin's unified work queue system (todo → running → done/dead). Currently, **all queue state is ephemeral** — lost on server restart. Long-running agentic jobs (DeepResearch 10-30min, PodcastGenerator 5-15min, ClaudeCode 1-60min) are the most impacted: if the server restarts mid-execution, users have no visibility into what happened.

**Goal**: Durable PostgreSQL-backed persistence for AgenticJobBase jobs. Job state survives restarts, enables job history queries, and marks interrupted jobs.

**Scope**: AgenticJobBase subclasses only (DeepResearch, PodcastGenerator, ClaudeCode, SweTeam). Sync agents (Math, Calendar, etc.) are already cached as SolutionSnapshots in LanceDB and execute in 1-5s — not worth the write overhead.

**Future footnote**: Once persistence is in place, queue management operations (delete/remove from done/dead queues) will be needed for ALL job types. The schema and API should be designed to accommodate this expansion.

---

## Architecture Decision: Central Write-Through

Persistence writes happen inside `emit_job_state_transition()` in `queue_util.py` — the single function already called at every state transition. This avoids touching ~10 handler sites in `running_fifo_queue.py`.

**Filter**: Only persist when the job is an `AgenticJobBase` instance (checked via `job_type` in metadata or a new `is_agentic` flag).

**Done/dead queues remain in-memory** for the current session. Historical jobs are served from PostgreSQL via a new `/api/job-history` endpoint. No reload into memory on restart.

## Phase 1: Schema + Model (Foundation)

### 1.1 PostgreSQL Table

Add to `src/scripts/sql/schema.sql` and create standalone `src/scripts/sql/add-job-history.sql`:

```sql
CREATE TABLE IF NOT EXISTS job_history (
    id_hash             VARCHAR(255)    PRIMARY KEY,
    job_type            VARCHAR(100)    NOT NULL,
    user_id             VARCHAR(255)    NOT NULL,
    user_email          VARCHAR(255)    NOT NULL,
    session_id          VARCHAR(255),
    routing_command     VARCHAR(255),
    status              VARCHAR(50)     NOT NULL DEFAULT 'pending',
    question_text       TEXT,
    error               TEXT,
    is_cache_hit        BOOLEAN         DEFAULT FALSE,
    duration_seconds    FLOAT,
    metadata_json       JSONB,
    created_at          TIMESTAMPTZ     NOT NULL DEFAULT NOW(),
    started_at          TIMESTAMPTZ,
    completed_at        TIMESTAMPTZ,
    updated_at          TIMESTAMPTZ     NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_job_history_user_id ON job_history( user_id );
CREATE INDEX IF NOT EXISTS idx_job_history_status ON job_history( status );
CREATE INDEX IF NOT EXISTS idx_job_history_job_type ON job_history( job_type );
CREATE INDEX IF NOT EXISTS idx_job_history_created_at ON job_history( created_at DESC );
CREATE INDEX IF NOT EXISTS idx_job_history_user_status ON job_history( user_id, status );
```

**Design notes**:
- `id_hash` is PK (the scoped `{hash}::{user_id}` string from CJ Flow)
- `user_id` is VARCHAR (JWT uid string like `ricardo_felipe_ruiz_6bdc`), not UUID FK
- `metadata_json` JSONB stores: answer_conversational, artifacts dict, cost_summary, abstract, push_counter
- Status values: `pending`, `running`, `completed`, `failed`, `interrupted`

## Phase 2: Persistence Service

### 2.1 New Module

**File**: `src/cosa/rest/job_persistence.py` (NEW)

Stateless service module (follows `queue_util.py` pattern):

```python
def persist_job_created( job )         # INSERT with status='pending'
def persist_job_started( job )         # UPDATE status='running', started_at
def persist_job_completed( job )       # UPDATE status='completed', completed_at, metadata_json
def persist_job_failed( job, error )   # UPDATE status='failed', error, completed_at
def mark_interrupted_jobs() -> int     # UPDATE status='interrupted' WHERE status IN ('pending','running')
def get_active_job_ids_by_user()       # For UserJobTracker rebuild
def query_job_history( ... )           # Paginated query with filters
def get_job_by_id_hash( id_hash )      # Single job lookup
```

**Critical**: All `persist_*` functions are **fire-and-forget** — catch and log exceptions, never break the queue pipeline.

**Agentic filter**: Check `is_agentic_job_type( job_type )` helper that returns True for known agentic types (`deep_research`, `podcast`, `claude_code`, `swe_team`, `research_to_podcast`).

Uses `get_db()` from `src/cosa/rest/db/database.py` for session management.

## Phase 3: Central Write-Through Integration

### 3.1 Hook into emit_job_state_transition

**File**: `src/cosa/rest/queue_util.py`

Add persistence calls at the end of `emit_job_state_transition()`:

```python
# After WebSocket emit, persist terminal transitions for agentic jobs
if metadata and is_agentic_job_type( metadata.get( 'agent_type' ) ):
    if to_queue == 'todo':
        persist_job_created_from_metadata( job_id, user_id, metadata )
    elif to_queue == 'run' and from_queue == 'todo':
        persist_job_started_from_metadata( job_id, metadata )
    elif to_queue == 'done':
        persist_job_completed_from_metadata( job_id, metadata )
    elif to_queue == 'dead':
        persist_job_failed_from_metadata( job_id, metadata )
```
