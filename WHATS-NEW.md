## What's New in v0.2.2 — a code wiki, a reuse check on every merge, and measurements that say what they found

v0.2.2 ran from 30 September to 3 November 2026, on `wip-v0.2.2-2026.09.30-code-wiki-and-jev-for-reuse-planning-review`. It set out to answer one question: **before a seat writes a new function, can it find out whether the code base already has one**? The branch is about 4,000 commits, more than 300 of them merges. It built a wiki of the code, lookup tools that search it, and a merge gate that holds seats to using them. It also measured how well the checker works, and some of those results were negative.

**The standouts**

- **A wiki of the code, written from the code**. About 674 capability pages under `src/docs/wiki/`, none of which existed on main, now describe what each package does and how its parts fit together. Each page pins the symbols it describes, and `symindex lint` fails when a pin goes stale or a public symbol has no page. By 15 October every package's unpinned symbols had a page (for example `cosa.utils` went from 257 unpinned symbols to 0). The reuse lookup tools read these pages, so a seat gets a sentence about what a function is for, not just its name.
- **The reuse check runs on every merge, and it is switched on**. Every new function, method or class a branch adds now needs a `REUSE-OUTCOME` line. That is a short record naming the lookup receipt, the text search that was run and the ruling. The ruling is duplicate, extend an existing symbol, or distinct and why. The `reuse` gate, fourth in the merge pyramid, checks each line against the call log and refuses a missing or unbacked one. It makes no model call and takes seconds, as Rick ruled. Enforcement was turned on at 11:30 on 3 November (`cc5d00e49`), and the merges after it passed under it.
- **A daily duplicate check that files what it finds**. A new job judges each day's new definitions against the rest of the tree, under a fixed call cap. It files each finding as a task row at priority 5. It queues an audit when it can tie the finding to the lookup that missed it. Its first full pass by hand, on 3 November, covered 73 commits and judged 100 definitions. It returned 41 findings in about 11 minutes, and 4 were real duplicates, fixed and merged the same afternoon. From the night of 3 November it runs at each night's Last Call. That run files one triage row listing every finding, with one fixed-format verdict line per finding. Two weeks of results can then be counted.
- **Coverage reached 100% across the whole frame**. On 26 October the coverage gate read 100.00% over 102,293 statements, up from 97.82% on 10 October. Getting there meant moving the server's start-up code into a testable function. The gate was also changed to refuse a run when one parallel worker's coverage data is lost. On that date the 100% mandate in CLAUDE.md was a measured state, not just a target.
- **The docstring sweep, and a gate that keeps it swept**. The [documentation rewrite plan](src/rnd/v0.2.2/2026.09.30-lupin-af-documentation-rewrite-plan/2026.09.30-lupin-af-documentation-rewrite-plan.md) explains why. It measured how often older Claude models packed rhetorical markers into the text, per 1,000 words, and showed six bad patterns with real examples. It also rewrote one 113-line docstring into 20 lines as the model to follow. Six review trains rewrote 3,485 docstrings across 74 packages and directories. The 859 swept files went from 29,838 documentation lint findings to 0. A check of 40,100 claims in the rewritten docstrings found no real loss of meaning in the final sort. The new `doclint` gate, third in the pyramid, and a pre-push hook refuse any change that brings a finding back into a swept file. Both have been live since 7 October.
- **Any document becomes a podcast, in one click**. Since 9 October the doc viewer has had a "Make a podcast" button with an in-page confirmation, in both clients. Rick uses it to turn each explainer a seat writes into a narrated episode, so the repo and its plans can be followed by ear. The `io/podcast-proxy/` folder holds 24 episodes made that way between 9 October and 2 November. Files can also be uploaded into the viewer, and a finished episode plays or downloads from its card. From 1 November its Script and Original links open in the doc viewer, for their owner only.
- **Copy-pasted code merged into shared helpers**. On Rick's request, the twin refactor replaced near-identical copies with one shared body each, landed in five batches on 18 and 19 October. Exact clone groups went from 129 to 34, and their members from 306 to 77. Each batch passed the full unit tier before it landed.

**The rest of the reuse review**

- **Lookup tools that seats call before writing code**. `check_exists`, `fetch_similar`, `read_capability` and `record_search` run from the cosa-voice MCP server, the voice and tools server every seat loads. They search an index of every symbol in the tree. They ask Jev, an outside judging model (TypeSafe's System One), which candidates do the same job. On 24 October the "write new" verdict was retired: an empty shortlist now tells the seat to read the source. `record_search` runs and records a plain text search, and a "distinct" ruling is refused unless one stands behind it.
- **Fast lookups, sized to a measured worst case**. Lookups now send candidates to the judge in packs of 50 rather than one full sweep. Full sweeps had been stopping at their 9,000-call cap since 26 October and leaving entries unasked. Each lookup has a token ceiling of 64,000, which is the worst fast lookup measured (42,360 tokens) times 1.5, rounded up. Both values are set in the seats' cosa-voice configuration, and the install script keeps them when it is re-run. On 3 November every live seat's tools server was checked and found carrying the pack size of 50.
- **A search stage built on the code's own vectors**. The model server gained an embeddings role. The reuse index now holds one vector per entry it can return, a set of 8,615 that matches the index exactly. The verdict threshold was fitted to 0.3 on held-out negatives, for a false-reuse rate of 0.047 against a target of 0.05. A daily cron job refreshes the vectors.
- **Shadow audits, with budgets read only from the configuration file**. About 1 in 100 live lookups is queued for a slower full audit, and findings from the daily check are audited first. On 3 November the budgets moved into `lupin-app.ini` with no code fallback. They are a 100,000,000-token lifetime limit (Rick's ruling), 5,000,000 tokens per drain, 4 audits a week, and an on/off switch. The drain stops before it spends past the lifetime limit. An unreadable switch value is reported as an error, never treated as off. The first real audit, on 3 November, cost 3,324,735 tokens.
- **A weekly fleet page for the reuse checker**. One page per Monday-to-Sunday week counts lookups, audits, outcome lines by kind and refusals by reason, with no seat named, as Rick ruled. A table added on 3 November gives one line per daily duplicate check, with findings, real against not real, and precision. It is written by a cron job at 18:00 each day, which skips the run when that week's page is already saved.
- **The first duplicate-check triage**. The 41 findings from 3 November were triaged that afternoon. Every ruling is recorded on its own task row: 4 real duplicates and 37 distinct. The real ones were merged as two consolidations: the Newcombe interval arithmetic now lives in one place, and two identical test stand-ins became one helper. The same day fixed a refile bug that had filed 17 duplicate rows, because the check for an existing row could not see held rows.

**What the measurements found**

- **A labelling page, and every pair labelled**. `/app/pair-labelling` lets a person mark two definitions as "same job" or "not" without the page jumping ahead. Rick used it to label all 125 proof pairs, and then all 222 once the trial runs added flags. Unofficial trial run 3 found 86.5% of the known duplicates and passed that bar. Only 74.9% of its flags were correct, which fails the 0.80 bar. The checker was not retuned on the same set, so that the set stays a fair test.
- **The purpose line decides whether a duplicate is found at all**. In the first-thousand trial, some planted rewrites carried a one-line statement of purpose. Those reached the 128-candidate shortlist 12 times out of 13. Without it they reached it 5 times. Expanding each need into fuller wording raised the correct answers reaching the shortlist from 80 to 110 of 119. The team also caught its own error: the plants had reached the judge without their purpose line. So those judge figures were suspended and the input was fixed.
- **The judge, measured alone on real pairs, is weak**. On 97 of 157 real labelled pairs, the judge's ranking scored an AUC of 0.682 (95% range 0.552 to 0.799). AUC is the chance that a real duplicate ranks above a non-duplicate, where 0.5 is a coin toss and 1.0 is perfect. At the 0.30 line it accepted 41% of pairs that were not the same job. It was read as "weak but usable", and nothing was adopted on the strength of it.
- **Inside a real pack, the judge does not separate same from not-same**. On 3 November a planted candidate was asked among the 127 real places of one pack, in two arms with two repeats each. Without the plant's purpose line the judge accepted 6 and 5 of 13 same-job pairs, but also 3 of 4 not-same pairs in both repeats. With the line it accepted all 13 same-job pairs and all 4 not-same pairs both times. The sample is small (4 not-same pairs, 136 calls), but it is a measured negative result. In neither arm did acceptance track whether the pair really was the same job.
- **Two model choices settled by measurement**. Gemini was tried as a docstring writer and checker. It caught all 28 planted losses as a checker. As a writer it left 18 lint findings where Claude left 0, and 100 claims judged absent where Claude had 38. Rick ruled it out. A judge with thinking turned off missed every known real loss (0 of 4), so thinking stays on.

**Quality and test gates**

- **Three new steps in the merge pyramid**. `doclint` (third), `reuse` (fourth) and `docker_smoke` were added on this branch. `docker_smoke` runs the three Docker smoke files on the host and counts a skip as a failure. `typecheck` and `stylelint` were already on main. The test container reports the host-only steps as "not run here" instead of refusing.
- **The unit tier runs in parallel, in its own memory budget**. The unit tier now runs on four workers under pytest-xdist, inside a cgroup capped at 16 GB. It needs about 12 GB, and a seat has 8 GiB. An out-of-memory kill exits 72 and is reported as such. The full tier passed 43,182 tests at a 12.17 GB peak on 2 November, against 27,670 unit tests on 30 September.
- **Census guards and GPU-free unit tests**. A census guard counts something across the whole tree, so new code can turn one red without touching its files. `src/tests/run-census-guards.sh` runs them all before review. It ran 385 tests when it landed on 9 October and 1,592 on 3 November's merges. Rick ruled that no unit test may need a free GPU, so the fine-tuning trainer's tests now mock the graphics calls. A guard fails any test that reaches a real one, with "unit test touched the real GPU".

**Approvals, the browser clients and podcasts**

- **One click approves a held row, or a whole list**. Action cards now carry an "approve ☐" link that turns into a greyed "approved ✅" once used. A 📋 link shows the row's contents first, so an approval is never blind. From 3 November one link approves or drops a whole list of held rows. A network error on one row shows on that row alone.
- **Keep place keeps your place**. Turning on 📌 Keep place now holds the scroll inside each card's notification history, as well as the page. This works in both the legacy page and the TypeScript client. The cause was that it guarded only the page scroll, so a card that moved or was redrawn reset its history to the top. The Focus, All and Keep place toggles now sit on their own row and match the persona badges in height. They share the Active toggle's on and hover colours.
- **The clients stay in step with the server**. Both clients send an utterance id with each speech request and drop a finished or error frame that names another one. So audio can no longer play for the wrong request. Three review passes each found a real bug first, and each now has a test. The server also pushes a `task_store_changed` event. The Task List, Holding Area and Finished Tasks panes re-read on it instead of waiting for their next poll. Fleet Status keeps polling, by Rick's ruling.
- **Skeleton crew is a switch on the fleet status panel**. Rick can turn skeleton crew on and off from both web clients, and the fleet size cap can be changed only by an admin login. Rick used the switch twice on 3 November.

- **Podcasts publish to Google Drive, and runs survive a bad step**. Publishing is off by default, and the setting `podcast drive upload users` (default: the owner) decides whose podcasts go to Drive. It was proven end to end on 1 November, when job `rp-f4e44cc2` uploaded its 20 MB audio file and the source document to Rick's Drive. A list route and a stream route for the phone app were also built. A research topic that runs out of turns now becomes a named gap, and the run goes on. An unreadable podcast script is saved in full and retried once. The Play Here player gained a small bare-player view, and a card's Script and Original links open in the doc viewer for their owner only.

**Platform and servers**

- **Both servers on one image, then the new agent SDK**. On 2 November :7999, :8000 and the test VM moved to one rebuilt image, `lupin:1.1.6-candidate`. On 3 November, with Rick's go, :7999 and :8000 moved to `lupin:1.1.7-candidate`. It carries claude-agent-sdk 0.2.177 and Claude Code 2.1.317, the host's own version, in place of the 2.1.161 it had bundled. The rollback is 1.1.6.
- **The app logs in to the database with its own role and no password in its environment**. All 27 tables in both databases are now owned by `lupin_app`, and Postgres listens on 127.0.0.1 only. Grants are applied by a script and checked after every bounce. A one-command installer sets up the database login files on a new host.
- **The test VM runs on Vertex Model Garden**. The cloud test VM now calls Claude through Google's Vertex service. By Rick's ruling it runs its quick summaries on Gemini Flash-Lite there, and it passed its post-deploy checks with nothing blocking.
- **The time zone comes only from configuration**. Every code default for the time zone was removed. Web pages show the server's zone or a labelled UTC time, and two census guards keep it that way.
- **Guards against cross-tree and cross-user damage**. The kill guard refuses a `pkill`, `killall` or `pgrep` pattern that would reach a process the caller did not start. It was added after one seat's `pkill` stopped another seat's unit tier. The answer route returns 403 and writes nothing when the caller is not the card's addressee. Resume-job resumes only the caller's own job, and two debug routes now require an admin. Every job builder refuses bad input, and the dev and test containers run Docker's init process, which took leftover zombie processes from 48 to 0.
